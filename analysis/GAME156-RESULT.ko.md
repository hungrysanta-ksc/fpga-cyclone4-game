# NES156 — 음원 활성화 가설과 버튼 읽기 이력

PR97 머지에서 시작했다. 사용자는 Select 효과음과 스테이지 사운드 시작이 실패 시점과 겹친다고 제안했다.155의 최초 실패는 PPU 기한 오류2였고, 실제 Select 비트나 직전 APU/DMC 활동은 기록되지 않았다. 사용자 관찰은 유효한 재현 가설이며 원인 확정은 아니다.

## 확인한 구현과 참조 결과

155는 외부 DAC 핀을0으로 고정했지만 내부 APU·DMC를 실행했다. 따라서 TV가 무음이었다는 사실로 내부 사운드 처리를 배제할 수 없다. 단순 믹서 음소거로는 DMC 메모리 요청을 차단할 수 없다.

같은 SMB3(J)의 Mesen 참조를240프레임씩 비교했다. 모든 경우 첫 Start는30~44프레임, 두 번째 조작은90~104프레임이었다.

| 두 번째 조작 | APU 쓰기 수¹ | `$4015`의 DMC 활성화 쓰기 | 해석 |
|---|---:|---|---|
| 없음 | 688 | 없음 | 비교 기준 |
| Select | 698 | 없음 | pulse1 효과음 레지스터 쓰기와2PLAYER 화살표 확인 |
| Start | 1084 | 157/193/223/229프레임 | 이후 DMC 활성화 있음 |

¹ `$4000..$4017` 쓰기에서OAM `$4014`와패드 `$4016` 제외. Select 직후91프레임에 `$4002=2A`, `$4003=08`, `$4001=7F`, `$4000=97`을 관찰했다. 참조 에뮬레이터 결과이며 실제 FPGA의 동일 실행을 증명하지 않는다. DMC 하나만으로 두 입력의 실패를 설명하기는 어렵지만 다른 음원 활동이나 사운드 코드가 늘린 메모리 접근은 조사 대상이다.

## 시험판의 변경

실제 NES의 APU 인스턴스에서 음원 채널 쓰기를 차단한다. 읽기와 `$4017` 쓰기는 유지하고 전체 APU 리셋을 추가하지 않는다. 원래 APU가 제공하던 get/put 신호와 화면 OAM DMA도 유지한다. 음원 상태와 DMC 요청이 달라지는 비교판이며 최종 호환성 수정이 아니다. ROM·PPU·MMC3·메모리 서비스·읽기 기한·클록·화면 전송 결정은155와 같다.

사용자 요청에 따라 게임이 패드8비트를 읽은 값을 관찰한다. 상태 변화만최근16건과 NES 클록 시각으로 저장하고, 최초 오류/STOP 뒤65/DF 식별의 SPI 응답으로 회수한다. 기존 패드 전송식·시프트 결정을 바꾸지 않는다. TXT에는 버튼 이름과 비트값을 함께 남긴다. 손의 물리적 클릭·불완전 읽기·DMA 동안 놓친 입력까지 기록하는 것은 아니다.

## 검증과 남은 작업

수치·선택 산출물·원본 해시는 [검증 기록](game156-verification.json)을 따른다. 짧은 시험은 실제 APU/DMA와 실제 연결에서 추출한 차단식, 원본155 패드와256가지 입력 대조, 실제 SPI 관측기의 최근16건/종료 후 보존, 실제 MCU RUN/STOP와 TXT 포맷을 확인한다. 전체 게임 부팅이나 같은155 PPU 충돌 시험을 반복하지 않는다.

테스트벤치 초기의 APU 파라미터 누락·패키지 import 누락·DMC 강제 입력의 연결선 전파 문제는 수정 후 대조 요청 발생까지 확인했다. 초기 ARM 빌드는 들여쓰기 경고를 오류로 처리하여 중단했고 포맷 소스의 문장 배치를 수정했다. 원본 실패 증거도 보존한다. 라이선스 부족이나 실제 게임 실패로 분류하지 않는다.

이력 저장의 최초 배치는 같은 클록setup -0.437ns여서 배포하지 않았다. 저장소를640비트 레지스터에서M9K로 옮기고 SPI 응답에2개 소스 클록 준비 시간을 두었다. 이후에도 -0.093/-0.038/-0.614ns 배치는 모두 제외했다. 최종 이력은 시각을256 NES 클록 단위로 내림해512비트·1개M9K에 담는다.16건과32비트 시각 표기는 유지한다. 마지막 기능 시험은 실제 명목 NES 클록·SPI 속도도 확인했으며, 최초 명목 클록 시험의 너무 짧은 오류 주입 펄스는 클록에 맞춰 수정했다.

fit06의setup -0.092ns와조건부PSRAM -0.096ns도 제외했다. fit07은CHECK 비교 경로5.5ns·CE/OE 출력12ns의 **배치 최적화 예산**을 추가했고, 기존 매핑을 재사용했다. 이 추가5.5ns목표 자체는 -0.010ns로 미달이며 이를 통과로 바꾸지 않았다. 같은 배선DB를 **기존155와 바이트가 같은 실제 클록SDC**로 별도 분석한 결과setup **+0.246ns**,hold **+0.153ns**,조건부PSRAM **+4.571ns**,SNES전송범위 **201.453ns < 270ns**다. 실제 클록 주기·false path·multicycle을 완화하지 않았다. 두 분석을 모두 보존한다. 선택 배치13,593LE/4,994레지스터/53M9K/122실핀/0가상핀/1PLL,ARM187,952바이트다. 전체 외부IO·MTBF 승인과는 구분한다.

복사된 이전 분석JSON은 최신 결과로 재사용하지 않았다. STA 재분석으로 갱신되는IO 시뮬레이션 캐시는 배선DB와 구분하여 검증하고, 소스·제약·실제 배선 입력 해시가 그대로인지 확인했다. 강화된 예산은 유지된 상태로 조립했으며, 기능상 바뀌지 않은 코어 전체나SD전체 적재 모델을 다시 실행하지 않았다.
