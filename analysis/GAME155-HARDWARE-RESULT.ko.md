# NES155 실기 — 선택 화면의 Select에서도 PPU 읽기 기한 오류

**155의 일반 배경 선행 읽기로 실제 정지를 해결하지 못했다.** 첫 Start로 선택 화면에 들어간 뒤 Select를 누르자, 두 번째 항목으로 화살표가 이동하는 대신 종료 후 메뉴로 복귀했다는 사용자 관찰이다. 이번 실패 입력은 이전154의 두 번째 Start와 구분한다. 스테이지 진입을 거치지 않는 선택 화면 조작도 조사 대상이 됐다.

## 확인한 결과

- 기대/실제 보드64,관측부DE로155 조합이 실행됐다.
- ROM393216바이트 적재·전체 비교·검증 통과. 진행 기록104개512바이트,seq0~103 연속이며 기록 시간 역전이 없다.
- `run_passed=0`, `run_rom_error=2`: PPU가 데이터를 소비할 때 해당 주소의 유효한 값이 없었다. `run_error=1`은 MCU 실행 오류 분류이며 CPU ROM 오류1이라는 의미가 아니다.
- `stop_ok=1`, `run_stop_error=0`, `base_restored=1`, `safe_to_reload=1`. 카운터14220446이 STOP 뒤 유지됐고 최종 TXT741바이트가 저장됐다. 사용자는 실제 메뉴 복귀도 확인했다.

## 이전 오류와 비교

| 항목 | 154 실기 | 155 실기 |
|---|---|---|
| 사용자 입력 경로 | 선택 화면에서 두 번째 Start | 선택 화면에서 Select |
| 최초 ROM 오류 | PPU 기한 오류2 | PPU 기한 오류2 |
| PPU line / dot | 193 / 6 | 193 / 8 |
| 배경 패턴 단계 | 하위 비트면 | 상위 비트면 |
| PPU 논리 주소 | `0x0A10` | `0x0A18` |
| 대기/실제 물리 주소 | 모두 `0x217A10` | 모두 `0x217A18` |
| 대기 age | 1 | 1 |
| 응답 / PPU 유효 데이터 | 0 / 0 | 0 / 0 |
| 현재 `$2007` 읽기/쓰기 파이프 | 0 / 0 | 0 / 0 |

155 주소 문맥은 `e200c2f4:30217a18`,PPU 상태는 `60820800:28606060`이다. 렌더링1/스프라이트구간0/배경테이블0,ALE0,address_valid0,주소래치·버스핀은 모두0x18이다. dot8은 일반 배경 상위 패턴 소비 단계다.155의 일반 선행 읽기 힌트는 dot3~6에만 켜므로 dot8의 hint0 자체는 결함 증거가 아니다. 이전 dot5~6에서 실제 예측·요청이 있었는지는 이 상태만으로 알 수 없다.

두 주소는 같은 타일 행의 하위·상위 비트면에 해당하는8바이트 차이다. 따라서 배경 읽기의 공통 경계가 여전히 우선 조사 대상이다. 다만 사용자 입력 경로가 다르므로 **155가154의 dot6 오류를 해결해 두 dot 더 진행했다고 판정하지 않는다.** 반환 바이트 손상이 아니라 샘플 시점의 유효값 부재이며,PSRAM 고장·선행 읽기 미발행·캐시 교체 중 하나로 단정할 수도 없다.

## 입력 문제 가설의 위치

사용자 관찰은 중요하다. **“첫 입력 이후 다른 버튼에서 문제가 생긴다”는 가설을 추가하고, 스테이지 로딩에만 원인을 한정한 접근을 수정한다.** 그러나 모든 버튼을 시험한 것은 아니므로 두 번째 이후의 모든 입력이 실패한다고 일반화하지 않는다.

현재 패드 모듈은 SNES 버튼을 보존해 NES 직렬 입력으로 전달한다. Select/Start는 서로 다른 비트이며 패드 수신부가 직접 ROM 오류2를 만드는 연결은 없다. 실제 오류2는 ROM 서비스의 `ppu_sample && ppu_rom && !ppu_valid` 조건에서 발생한다. 그렇더라도 잘못 전달된 입력이 다른 게임 실행 경로를 유발했을 가능성까지 배제되지는 않는다. 최종 로그에는 실제 패드 바이트·strobe/read 이력·CPU 실행 경로가 없어 Select 매핑 정상 여부도 아직 미확인이다.

구분할 두 경로는 다음과 같다.

1. 버튼 값·반복·래치/시프트 전달이 잘못되어 게임이 의도하지 않은 경로를 실행하는 경우.
2. 입력은 정상이나, 게임의 선택 표시나 화면 갱신·매퍼/PPU 처리에서 공유 ROM 읽기 기한 문제가 드러나는 경우.

로그상 직접 정지 원인은 두 번째 경로와 가까운 PPU 기한 오류지만, 정확한 촉발 원인은 미확정이다.155의 주기적 CPU 점유·고정 뱅크·합성 타일 모델 통과를 실제 Select 경로 통과로 확대하지 않는다.

## 다음 작업

최소 재현 기준을 **선택 화면의 Start 대 Select**로 바꾼다. 실제 패드의 버튼 바이트·strobe·shift 소비를 먼저 대조하고, 같은 경계의 BG dot5~8 예측주소/실제주소/MMC3 물리태그/요청승인/응답·캐시 교체 순서를 연결해 확인한다. 현재 모델이 고정한 PPU·매퍼 주변 상태에 의존해 또 통과 판정하지 않는다. 기존 자료로 원인을 좁히지 못할 때만 필요한 최소 직전 이력을 추가한다.

같은155 재시험,044/GBC 복원,A/B 패턴,변경 없는 장시간 전체 부팅은 요구하지 않는다. 기한 검사를 삭제하거나 무조건 캐시를 확대하지 않는다. 원인에 맞는 변경 경계 검증 후 같은 SMB3 실기로 돌아간다.

펌웨어 기록상 DISPLAY_NEXT232.670초→DISPLAY_STOPPED237.640초는4.970초,이후 메뉴 준비240.800초까지3.160초다. 실제 Select 입력·첫 화면 시각을 측정한 값은 아니다. `screen_frames=9`와 `screen_telemetry_trusted=0`을 FPS나 화면 정상 증거로 해석하지 않는다. 새 영상은 없으며 선택 화면 조작·메뉴 복귀는 사용자 관찰이다.

이번 PR97 추가 커밋은 실기 결과와 다음 작업 인계만 반영한다.155 펌웨어·FPGA·ZIP·동결 증거·공개 도구 고정값은 보존했다. 새 구현·빌드·설치 패키지는 만들지 않았다. [원본 해시·전체 진행 기록·해석](game155-hardware-verification.json)에 근거를 남겼다.
