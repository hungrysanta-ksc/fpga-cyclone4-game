# SDREPORT084 실기 저장·재읽기 통과

사용자 제공 HW084001.TXT와 IMG_3642.MOV를 대조해 **이번 보고서 저장·재읽기·결과 화면은 실기 통과**로 기록한다. 새 firmware나 FPGA를 빌드하지 않았다.

| --- | --- |
| TXT 크기 | 3072바이트, 기대값과 일치 |
| TXT 전체 비교 | 모든 바이트 일치, 불일치0 |
| TXT SHA256 | `1621997c9acc8f90588da273fbdbfdf18459eb380d749b98cec4622f55b2679e` |
| 영상6초 | `STEP 1C FIND SPACE` |
| 영상10초 | `STEP 8 CLOSE READ` |
| 영상15.43초 | `TXT SAVED + READBACK OK`, `/HW084001.TXT`, `Save code: 0` |
| 화면 여백 | 검토 프레임에서 제목·진행·파일명·결과·복원 안내가 화면 안에 표시됨 |
| 정상044 복원·메뉴/GBC | 사용자 직접 확인: 복원 후 메뉴·GBC 모두 정상 |

영상은15.93초이며2초 간격과15.43초 프레임을 추출했다. 위 세 프레임을 직접 확인했다. 전체 프레임이나 모든 단계의 정확한 전환 시각을 측정했다고 주장하지 않는다. 화면 파일명과 전달 TXT 이름도 일치한다. 원본영상5542993바이트 SHA256 `28413b4999dc79381d1b5ba3394df2b2aea248fdb4edb33454fedd983470189f`.

## TXT의 뜻

이 파일은 사람이 읽는 상세 상태 로그가 아니라 **SD 저장 검사용 데이터**다. `SDREPORT084-NATIVE077`은 진단 버전과 native 경로의 식별자다. 뒤의 반복 알파벳·줄바꿈은 정해진 시험 패턴이며, 잘못 쓴 바이트나 누락을 전체 비교로 찾아낸다. 깨진 글자나 에러 메시지가 아니다.

`STORAGE PAYLOAD; FILE ALONE DOES NOT PROVE SUCCESS`는 파일만 있다고 전체 시험을 성공으로 판정하지 말라는 뜻이다. 이번에는 PC의 전체파일비교와 실기 최종성공화면이 모두 일치한다. 화면 `Save code: 0`은 오류 없이 완료했다는 뜻이다. `001`은 새 파일 이름의 번호이며 오류코드가 아니다. 전달되지 않은000파일의 내용이나 결과는 추정하지 않는다.

## 범위와 다음 확인

083의0바이트/STEP3정지가084의이번실행에서재현되지않고저장·재읽기가완료됐다. 앞선FAT탐색가설을지지하지만083당시실제FAT/hint/최초fault를회수한것은아니므로원인까지직접증명한것은아니다. 다른SD배치·반복내구성·NES/CF68전체실기성공으로확대하지않는다.

사용자는 정상044 firmware 복원 후 메뉴와GBC가 모두 정상이라고 직접 확인했다. 복원 결과는 사용자 보고이며 별도 복원 영상은 받지 않았다. 이번 보고서 진단의 저장·결과화면·복귀 경계는 완료됐다. 같은저장시험이나부품/LED/분해/PCUSB/기존파일수집을반복할필요는없다. 다음에는별도CF68의P2외부조건/P3최종쌍및P4진단진입조건을다시점검한다. 전체준비도4완료7부분1미완료는범위가더넓으므로유지한다.

원본TXT/영상·검사로그·프레임·SHA는별도개인증거에보존했다. 기존084빌드증거와공개소스핀,083실패기록은수정하지않는다. 시험전메타데이터의hardware_verified=false는당시빌드범위기록이며,이번후속판정은 [실기검증메타데이터](report084-hardware-verification.json)를따른다.
