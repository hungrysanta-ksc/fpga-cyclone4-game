# NES159 — 매퍼 쓰기 구간의 불필요한 ROM 읽기 차단

**158 실패 이력과 같은 요청 순서를 만드는 조건을 재현했고, 조기 CPU 읽기 자격에 실제 읽기 조건을 추가해 해당 모델을 통과했다.159 실기 패키지가 준비됐으며 실제 SMB3 스테이지 진입은 확인 대기다.** PR100 머지 `3ef0a0714fd803bdfdfeb0c7208b4f8a84a127c5`를 기준으로 작업했다.

## 문제와 변경

[158 실기](GAME158-HARDWARE-RESULT.ko.md)에서 새 CHR주소217A18은 오류15클록 전부터 예측됐지만, 낮은 비트면 응답 직후 CPU03C001 읽기가 먼저 발행됐다. CPU 읽기가 끝날 때 예측 유효 구간은 닫혔고, 옛205A18을 읽은 뒤 새217A18 읽기를 시작해 dot8 샘플 기한을 놓쳤다.

기존 조기 읽기 자격은 `prg_addr[15] && prg_allow`였다. 실제 CPU가 매퍼에 쓰고 있어도 `cart_pre` 이전에는 `prg_write=0`, MMC3 `prg_allow=1`이므로 불필요한 ROM 읽기를 발행할 수 있었다.159는 `mr_int && prg_addr[15] && prg_allow`로 바꾼다. `mr_int`는 실제 CPU/DMA 선택 뒤의 읽기 신호다. 선택한 MMC3 어댑터의 버스 충돌 요구는0이다. 다른 매퍼의 버스 충돌 계약을 검증한 것으로 확대하지 않는다.

기능 RTL 변경은 이 식 하나다.158의 예정된 MMC3 쓰기 예측, 실제 매퍼 상태·IRQ·PPU·공유 메모리 서비스·물리 reader·캐시·샘플 기한·클록·화면·패드·오류 회수는 유지한다. ARM과 나머지 FPGA 차이는159/68/E2 식별뿐이다.156의 APU 채널 쓰기 차단은 유지하며 정상 오디오 완료로 표시하지 않는다.

## 변경 경계 검증

선택 `test04`는 실제 NES의 CPU/DMA 출력 버스와 분주 위상, PPU 렌더링 위치를 구동한다. raw mux, mr_int/mw_int, cart_pre/cart_ce, MMC3 쓰기와 allow, 조기 자격, cpumem_read와 실제 ROM 샘플 결선은 살아 있다. 실제 PPU/service/READ16 및70ns 메모리 모델에 지정 SMB3 데이터를 사용한다. CPU 명령 실행이나 전체 DMA 컨트롤러 재생은 아니다.

- 쓰기 시작12위상과 관측 이력 경계1종 × 메모리 위상0/3.5/5.5ns: 수정판39건 모두 PPU 낮은/높은 비트면 정확, 오류0, 쓰기 구간 ROM 읽기0.
- 조기 자격만158 식으로 되돌린 대조39건 모두 불필요한 읽기1회. 이 중18건은 PPU 오류2. 모든 불필요한 읽기가 반드시 기한 실패를 만드는 것은 아니다.
- 각 실행의 CPU/DMA × 읽기/쓰기 ×12분주 위상48조건, 실제 CPU6/DMA6 샘플의 PRG 바이트 비교 통과.6실행 합계288조건/72샘플이며 별개의288종 자극으로 부풀리지 않는다.
- 관측 경계 재현은 초기 reader 사용 가능 시점과 이전 낮은 비트면 캐시를 설정했다. PRG bank6=1E, CHR bank1=16과5E 쓰기를 사용해 물리03C001/205A10/205A18/217A18 순서를 맞췄다. 기록 창 이전의 실제 명령·캐시 형성 원인까지 재현한 것은 아니다.

| 재현 단계 | 기존 자격 | 수정 자격 |
|---|---|---|
|19, 낮은 비트면 응답|CPU03C001 요청|미래 CHR217A18 요청|
|24, 응답·예측 유효 종료|CPU 응답, 옛205A18 요청|217A18 응답 보관, 옛205A18 요청|
|26, 실제 뱅크 변경|새 주소 데이터 없음|새 주소 데이터 유효|
|29, 옛 주소 응답|217A18 요청 시작|정상 CPU03C001 읽기 처리|
|31, dot8 샘플|오류2|정상 데이터 수신|

실기 이력에는 raw R/W가 없으므로 기존 실기의03C001 요청이 실제로 쓰기 중 발생했다는 확정은 아직 아니다. 이번 검증은 구체적인 원인 후보의 결선 오류와 같은 실패 순서를 확인한 것이다. 새 임의 예측이나 우선순위 변경을 더하기 전에159 실기로 판별한다.

## 빌드와 보존 범위

- `arm01/armcheck01`:188604바이트, 강한 NMI15stores/0calls, transport 일치. 호스트13개 회수 사례/256포맷 마스크 통과. 실제 ARM 실행 검증은 실기 대기다.
- `reuse01`: 기능 식 한 곳 외 FPGA 변화는 식별뿐, ARM도 식별·파일명뿐임을158의 동결 입력과 비교했다. 게이트 등가성 검사는 아니다.
- `fit01/asm01`:13670LE/5005레지스터/122물리핀/가상핀0/PLL1/56M9K. 이력용 RAM을 포함해56/56이므로 추가 여유로 계산하지 않는다.
- 추가5.5ns **배치 유도 예산은-0.036ns로 실패**했다. 같은 배치를 기존155 명목 SDC로 재검사해 setup+0.095ns/hold+0.160ns, 조건부 PSRAM+3.035ns, SNES202.2ns<270ns를 확인했다. 실제 클록/false path/multicycle을 바꾸지 않았으며 무변경 재배치하지 않았다. 두 결과를 모두 보존한다.
- PCB2ns 가정, 비동기 reset release 입력의 음수 recovery, 전체 외부IO와MTBF 미완료는 기존과 같다. 전체 타이밍 승인이나 전기적 실측 완료가 아니다.

초기 `test01`은 reset 중 CPU분주를1에 고정해 해제에 필요한 cpu_ce를 막은 시험대 오류로 watchdog 종료했다. `test02`는12위상 범위, `test03`은 캐시 경계를 추가했으나 CPU 물리주소000001이었다. 최종 `test04`에서03C001과 뒤따르는 정상 CPU읽기까지 맞췄다. 앞선 시도·원시 로그는 보존하고 최종 통계에 섞지 않는다. 기존 FLOAT 실행을 사용했으며 라이선스 교체는 없었다.

## 다음 실기와 의미

[159 안내](../docs/nes-game159-instructions.ko.md)에 따라 실제 SMB3 첫 Start →1PLAYER Start 한 번 후 떼기 → 진행되면 방향키/A·B를 확인한다. 두159 TXT와 메뉴 복귀 결과를 받는다. 정상 플레이가 되면 짧은 영상, 같은 실패라면 추가 영상은 필수가 아니다.044/GBC 복원, 이전158, A/B 화면, 무변경 전체 부팅 시험은 반복하지 않는다.

이번 변경은 **실제 코어의 메모리 읽기 자격 결선을 고쳐 스테이지 진입을 가능하게 하려는 작업**이다. 진단 틀이나 매퍼 수를 늘린 작업이 아니다. 아직 스테이지 플레이·전체 입력·속도·오디오·저장은 미완료다.159에서도 실패하면 최초 오류와 마지막16클록을 비교하고 정당한 CPU 읽기와 충돌하는지부터 본다. 관측 없이 PPU 우선순위나 캐시를 확대하지 않는다. 진행되면 이동·점프·스크롤을 먼저 확인하고, 원인 해결 후 임시 이력 RAM 축소 및 음원 차단 해제로 넘어간다.
