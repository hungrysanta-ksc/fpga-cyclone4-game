# NES H1 SAMPLING 044 검증 결과

2026-10-06. **제한된 실기 진단 시험용 MCU/FPGA 쌍을 준비했다. 실기 성공과 전기적 타이밍 검증은 아직 아니다.** 마지막 실제 관측은041의 자동 메뉴 복귀 실패이며 그대로 보존한다.

## 변경과 근거

043에서 입력을 연속 두 번 확인하고 오류 판정과 최초 기록이 같은 등록 이벤트를 쓰도록 바꿨다. 044는 이 구조를 유지하면서 주소 변경 판정을 이진 논리상 동등한 식으로 정리했다. 정상 읽기 종료 시 현재 주소만 X인 경우, 이전 주소와 저장 주소가 같은데도 기존 비교식의 재결합 때문에 오류가 X로 오염되는 현상을 재현했다. 4비트 주소 조합4096개에서 이진 동등성을 확인했으며 실제 오류 판정 조건을 완화하지 않았다. 프로토콜·기록 태그는0x44다.

최적화 후 실제 남은 dffeas q 출력을 추적했다. 043의 실패 경로는40805A 종료 시 addr_meta[12]의641373597ps hold notifier → 주소 샘플 → 오류 이벤트 → sticky 오류였다. 044 원래 SDF의 실패는40807E 시작 시654444998ps의 rd_sync[0] notifier에서 읽기 상태로 전파됐다. 두 번째 현상에는 서로 다른 합법적인0/1 해소 이력이 가능하다. 논리 수정만 반복해 모든 X를 제거하는 것을 검증 목표로 삼지 않았다. 배치 후 RD/ROMSEL 관련 q는 소스와 반전된 극성이므로 원시 핀 값으로 읽지 않았다.

별도 해소 모델은 테스트벤치에서35개 첫단 q만 다룬다(주소24, 데이터8, RD/WR/ROMSEL 각1). notifier 후1ns에 이전 값/현재 입력/교대 선택의 이진 값으로 결정하고 다음 클록+2ns에 force를 해제한다. 입력이 부동·불확정이면 이전 값을 쓴다. 타이밍 검사와 notifier는 끄지 않았다. 후단 상태·오류·ROM·payload를 강제로 고치지 않았다. 이는 **정해진 시간 안에 첫단 값이 해소된다는 가정의 실험**이며 아날로그 준안정성 확률, 모든 지연 조합, 원래 SDF 통과를 뜻하지 않는다.

외부 입력38포트/725경로, 출력11포트/965경로는 여전히 미제약이다. 실제 보드 파형과 버스 전환 시간은 미측정이다. 내부 STA 성공으로 외부 IO를 검증했다고 주장하지 않는다. 043과044의 원래 SDF 실패를 모두 보존하고, 조건을 달리한 실험을 별도로 기록했다.

## 실기 진입과 후속 판단

패키지의 READ-ME.ko.md에 따라 기존041 쌍을 백업하고 firmware.stm과 fpga_nh1.bi3를 **둘 다** 교체한다. NES H1 037.nh1을 그대로 실행하며 화면 제목 NES H1 034는 유지된다. LINK SCREEN1→2→3→1 순환, RESET 복귀와 재진입을 확인하고 sd2snes/nes-h1-last-044.txt를 보존한다. 설치 파일 해시와 복원 절차는 안내에 있다.

자동 복귀가 반복되면044 프로토콜/태그와 단일 이벤트의 주소·직전 샘플·소비 위치·오류 마스크를 먼저 확인한다. 비트 원인을 확정하기 전 추가 타이밍 수정을 추측으로 반복하지 않는다. 통과하면 GBC 시작/메뉴 복귀를 확인하고 이후에 장시간 반복 시험과 실제 NES 생산자 통합으로 진행한다. 현재 패키지는 NES 게임 코어·오디오·저장 지원 완료가 아니다.

보호된 GBC 소스·릴리스와 H0 실제 관측을 유지한다. 원본 로그·넷리스트·SDF·빌드 산출물은 ignored local-h1-sampling-044에, 공개 검증 결과와 해시 목록은 h1-sampling-verification.json 및 h1-sampling-artifacts.json에 기록한다.
