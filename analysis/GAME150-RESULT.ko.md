# NES150 실제 게임 화면·패드 연결

## 작업 목표

149의 실제 SMB3 적재·대조와148의 게임 코어를 물리 보드에 연결하고, 실제 게임 화면·패드를 시험할 SD 패키지를 만든다. PR91은 9f97bb7ae4c6a96b57d19ac2b250679edd3d3a0b로 머지됐다. 변경 없는30프레임·전체 적재·A/B·044 시험은 반복하지 않았다.

## 작업 내용

NCR1의 고정 배경/팔레트/CHR atlas 제한을 없애기 위해 최종 PPU 색 인덱스를 한 프레임 저장한다. 256×224, 원본 위·아래8줄 제외, 6비트 인덱스 보존이다. 스프라이트·스크롤·맵퍼 전환은 기존 PPU가 합성한 결과를 사용한다. 게임 로직을 SNES용 타일 엔진으로 다시 구현하지 않는다.

세 픽셀을18비트로 묶어38개의512×18 M9K에 저장한다. 완성된 프레임만 공개하고 SNES가 DMA를 마치기 전까지 덮어쓰지 않는다. 전송 중 지나가는 게임 프레임은 버리며 게임 CPU/PPU 클록은 멈추지 않는다. 호스트에서 SNES 8bpp 타일 순서로 읽는다. READ가 계속 낮은 DMA에서도 주소 변화를 처리하고, raw READ/reset/주소 소유권으로 출력을 차단한다.

2KiB SNES 프로그램은 WRAM으로 이동해 실행하며, 전체57344바이트를 forced blank 중 VRAM으로 복사한다. 다음 vblank에서 표시하고 버퍼를 반환한다. 따라서 **검정 구간과 낮은 표시 갱신률이 예상되는 첫 게임 확인 경로**다. 60fps 완성 주장은 하지 않는다. 색 강조·오디오·저장 지속성은 미구현이다.

SNES auto-joy 결과를 승인 응답이 있는 고정 데이터로 NES에 전달한다. A/B/Select/Start/위/아래/왼쪽/오른쪽을 매핑하고, NES read clock이 내려간 뒤 직렬 비트를 이동한다. 새 식별60/DA를 엄격히 사용한다. MCU는149 동작 그대로 식별·파일명만 변경하며60초 유한 RUN, 오류 조기 종료, 진행TXT, STOP/base/menu 복귀를 유지한다.

fit01은 새 주소 나눗셈·덧셈 경로의 -2.816ns로 채택하지 않았다. 열 주소를32항목 상수 조회로 바꾸고 행/열 합산을 한 단계 나눴다. 새 호스트 상태의 reset도 해당 클록에서 해제한다. fit02만 패키지에 사용한다. 원래 같은 클록 검사를 통과했다고 raw CDC/reset 음수를 모두 통과 처리하지 않았다.

초기 외부 계산은 주소·CE·OE에 모두16클록을 적용해 -0.864ns였다. 실제 기존reader는 주소를 IDLE→SETUP,CE/OE를 SETUP→ACTIVE에서 내보내므로 캡처까지 각각17/16클록이다. 변경 없는 동일 배치의 경로 표를 재사용해 이를 나눴다. 70ns 접근·기존 배선/설정 여유를 줄이거나 읽기를 연장한 것이 아니다. 원래 실패 계산도 보존하며, 최종0.78ns는 여전히 작은 조건부 여유다.

보존한 실행 문제: 최초 Quartus 출력 지연을 정지로 잘못 판단해 중단했으며 같은fit01을 재실행했다. Mesen 최초2회는 잘못 선택한 실행 위치의 사용자 경로/DLL 문제였고 기존137 portable runtime으로 해결했다. client03 최초 판정은239줄 출력 캔버스와5→8비트 색 확장을 잘못 가정한 검사기 실패였으며 같은 캡처를 올바른7/8줄 검정 테두리·비트 복제 기준으로 재검사했다. ARM 준비01의 전역 역치환 검사가 이미 존재한 명령0x60까지 바꾸는 오류를 수정했다. 이 문제들을 RTL 실패나 라이선스 부족으로 해석하지 않는다.

## 작업 의미

이번 변경은 **실제 게임 출력·입력 배선 구현**이다. 기존 진단 화면만 표시하던 한계를 넘고 실제 SMB3의 이동·스크롤을 관찰할 수 있는 시험 경로를 만들었다. 실기 구동 목표는 아직 완료가 아니다. 다음 작업은150 실기 로그·영상에서 게임 표시,Start/이동/점프,오류/메뉴 복귀,적재 시간을 확인하는 것이다. 이후 관찰 결과에 따라 첫 차단 오류 또는 화면 전송 비용을 개선한다. 추가 패턴 시험이나 표시60fps 최적화를 실기 첫 실행의 선행 조건으로 삼지 않는다.

ROM/바이너리/영상/라이선스는 공개하지 않는다. 기존GBC152/NES334와 모든 이전 공개 pin·frozen archive는 보존한다. [실기 안내](../docs/nes-game150-instructions.ko.md) · [인계](../cores/nes/HANDOFF.ko.md).
