# NES151 실기 — 게임 화면 출력 성공, PPU 읽기 오류로 조기 종료

**SMB3의 제목·캐릭터와 화면 갱신, 적재·전량 대조·STOP·실제 메뉴 복귀를 확인했다. RUN은 PPU 읽기 기한 오류로 중단됐으며 정상 게임 플레이와 전체 버튼 입력은 미완료다.** 이번에는 결과 기록만 추가하고 기존151 펌웨어·RTL·패키지를 변경하지 않는다.

## 영상과 시간

사용자는 실행까지 약3분50초, 화면 시작2~3초 뒤 촬영, 약35~40초 플레이 후 복귀를 보고했다. 실제 제공 영상은23.90초다.2Hz로48개 프레임을 추출하고1초 간격24개 및 제목 화면 확대를 확인했다. 초반 캐릭터와 바닥 무늬, 약3초의 제목 등장, 약5초 이후 `1 PLAYER GAME / 2 PLAYER GAME` 선택 화면과 캐릭터 갱신, 약20초의 메뉴 복귀를 식별했다. 영상에 월드맵이나 실제 스테이지 진입은 보이지 않는다. CRT 대각선 띠는 촬영 간섭으로 제외한다.

진행104기록의 ENTRY→DISPLAY_NEXT는233010ms(3분53.010초)여서 사용자의 시작 대기 측정과 대체로 맞는다. DISPLAY_NEXT→DISPLAY_STOPPED는233010→252280ms, **19.270초**다. MENU_PREPARED는255510ms다. 영상과 로그는 정확히 같은 시작점을 쓰지 않지만 둘 다60초 완주보다 짧은 실행을 보여준다.35~40초는 사용자 추정으로 보존하고 코드의 타이머 오류 근거로 쓰지 않는다.150의 철회된5~6분 체감도 다시 사용하지 않는다.

## 종료 원인

61/DB 식별,loaded/compared=393216,verified/end_accepted=1은 통과했다. 반면 `run_passed=0`, `run_error=1`, `run_first_error=1`, **`run_rom_error=2`**다. 실제151 `nes_rom_service.sv`에서2는 PPU가 ROM 값을 샘플해야 하는 시점에 `ppu_valid=0`인 경우다. MCU의1은 관측된 실행 오류 분류이며 CPU 읽기 오류1과 혼동하지 않는다. `nes_run136.inc`는 이 오류를 관측하면60초 반복을 채우지 않고 조기 종료한다. 따라서 이번 복귀는 정상 제한시간 종료가 아니라 **오류를 감지한 뒤 안전하게 복귀한 것**이다.

최초 문맥 `6200c2f4:3003f887`을 실제 사용된64비트 배치로 해석하면 다음과 같다.

| 필드 | 값 | 의미·한계 |
| --- | --- | --- |
| busy / pending_ppu | 1 / 1 | 처리 중인 요청이 PPU용 |
| pending_address | 0x217A18 | 처리 중인 물리 ROM 주소. 오류 순간 PPU가 요구한 주소와 같다는 증명은 아님 |
| age | 1 NES 클록 | 요청 후 경과 카운터.255클록 장기 타임아웃이 아님 |
| ppu_sample / ppu_valid | 1 / 0 | PPU 샘플 시점에 유효 데이터 없음 |
| rom_response / rom_ready | 0 / 0 | 응답 없음·백엔드 새 요청 준비 안 됨 |
| cpu_sample / cpu_valid | 0 / 0 | 이 순간 CPU 샘플은 아님 |
| cpumem_addr | 0x03F887 | 코어가 내보낸 물리 CPU 메모리 주소. CPU PC로 해석하지 않음 |

이 문맥은 PPU 요청 시점·중재·선행 읽기·캐시 경계의 확인에 유용하다. 실제 요구 `ppumem_addr`, PPU scanline/cycle, 과거 요청 순서는 저장되지 않았으므로 원인을 특정 맵퍼 전환이나 PSRAM 물리 고장으로 확정하지 않는다. 기존 모델30프레임 통과는 이번 약19초 구간까지 보장하지 않는다.

run_first=148922,run_last=run_stopped=55258010이며 STOP 후 오류와 카운터를 보존했다. stop_ok/base_restored=1,run_stop_error=0이고 사용자·영상 모두 실제 메뉴 복귀를 확인했다. flags=3은 STOP 이후 reset+sticky fault 표식이며 RUN 시작부터 reset에 묶였다는 뜻이 아니다.

## 화면·입력 판정

150의 밝은 균일 화면에서151의 식별 가능한 제목·캐릭터로 개선됐다.151 전체 후보의 표시 개선은 실기로 확인했지만 쓰기 종료 수신과30vblank 유지가 함께 바뀌었으므로 한 원인만 독립적으로 증명했다고 표현하지 않는다. screen_stage=6,screen_frames=34는 새 프로그램의 표시 단계와 부합한다. 그래도 `screen_telemetry_trusted=0`을 유지하며34를 FPS나 원본 NES 프레임 수로 쓰지 않는다.

Start 반응은 사용자 관찰로 기록한다. 버튼 시각이 동기 기록되지 않아 영상의 제목 진행이 Start 때문인지 자동 진행인지 단독 확정할 수 없다. 이후 A·Start로 다음 장면에 못 갔다는 관찰도 보존한다. 현재 패드는 약0.5초마다 스냅샷을 수집하므로 짧은 눌림을 놓칠 수 있으며, PPU 오류가 발생한 뒤에는 게임 진행도 멈춘다. 어느 이유가 개별 입력 실패를 설명하는지는 아직 미확인이다. 모든 버튼이 정상 또는 고장이라고 판정하지 않는다.

## 다음 작업

우선 같은 SMB3와 기록된 PPU 오류 문맥을 대상으로 최초 잘못된 요청/응답 경계를 재현한다. 제목·Start 이후 경로를 포함하고, 이미 통과한 초기30프레임만 무변경 반복하지 않는다. 현재 문맥으로 부족한 실제 PPU 요구 주소·시점은 재현 추적에서 먼저 확보하고 필요한 경우에만 최소 실기 관측을 추가한다. 기한 검사 제거·무조건 캐시 확대·PSRAM 고장 단정으로 통과시키지 않는다.

그다음 입력을 표시 유지 루프와 분리해 짧은 누름을 놓치는 제한을 줄이고 실제 Start·방향·A/B를 확인한다. 이번에는 같은151 재시험·044 복원을 요구하지 않는다. 새 구현은 별도 다음 작업이며 PR93에는 이 실기 결과까지만 반영한다. 원본 TXT/영상은 비공개,파일명·해시·원시 로그와 문맥 해석은 [메타데이터](game151-hardware-verification.json)에 보존한다. [인계](../cores/nes/HANDOFF.ko.md).
