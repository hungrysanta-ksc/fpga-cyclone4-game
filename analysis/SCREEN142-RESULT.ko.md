# NES142 결과 — SNES 화면 실행 단계의 실기 구분

## 작업 목표

141의 ROM 활동·오류0과 실제 글리치가 공존하는 이유를 좁히기 위해 SNES 화면 프로그램이 어디까지 실행했는지 회수한다. PR87 머지112fd8b를 기준으로 변경했다. **새 실기 후보와 변경 경계 검증은 완료, 글리치 원인 확정·정상 영상 달성은 아직 미완료다.**

## 현재 증상의 해석

사용자는 무음이며 약10초 중1~2회만 조금 변하는 글리치를 보고했다. 사진의 대각선 띠는 카메라와CRT 주사 차이로 설명했고 오류 분석에서 제외한다. 정지 사진에서 추정했던 신호 동기 이상을 근거로 삼지 않는다.

141 두 실행 모두 적재·대조81,920바이트, RUN/STOP 통과, 기록된 ROM·최초·STOP 오류0이다. 읽기 관측은 약16만에서3,075만으로 증가했다. 이 카운터는 유효 읽기 활동이며 명령어 수·프레임 수·정상 NES 프로그램 동작의 보증이 아니다. 현재 근거로 전체 실행 정지보다는 **SNES 화면 프로그램 부팅/WRAM 이행 또는 패킷→VRAM 경로 실패**를 우선한다.

|가설|현재 근거와 구분 방법|
|---|---|
|SNES 프로그램이 부팅하지 못하거나 WRAM 복사 중 잘못 실행|FPGA 내부 NES 읽기는 계속될 수 있다. 프로그램 ROM·RESET·카트리지 버스와 초기 PPU 설정을 stage0~2로 구분한다.|
|프로그램은 실행하지만 패킷 획득·DMA·소비가 막힘|일부 화면 변화와 양립한다. 이전 에뮬레이터는 MMIO를 모델링했으므로 실기 버스 성공을 입증하지 않았다. stage3~5와 최초 오류를 확인한다.|
|VRAM/팔레트/표시 설정의 실기 문제|stage6 횟수가 증가하는데도 깨진 화면이면 이 경로 또는 전달 데이터 정확성을 우선한다. 소프트웨어 전송 완료 자체는 정상 픽셀 증거가 아니다.|
|실제 NES 프레임 생성이 느리거나 정지|현재 읽기 카운터만으로 배제할 수 없지만1~2회 움직임만으로 저프레임률을 확정할 수도 없다. 먼저 화면 전송 진행과 구분한다.|

단순한 실행 실패가 항상 글리치를 만드는 것은 아니다. SNES PPU가 초기화되지 않았거나 잘못된VRAM/팔레트 상태로 표시되면 NES 실행 상태와 별개로 깨진 그림이 남을 수 있다. 이는 후보 설명이지 이번 실기의 확정 원인이 아니다. 오디오 핀은 현재0으로 고정되어 무음이 예상되며, CPU 실패 근거로 사용하지 않는다.

## 작업 내용

SNES 프로그램은 부팅 초기 force-blank/NMI·HDMA 정리 후 WRAM 복사, WRAM 진입, PPU 초기화, 패킷DMA, 검증·소비, VRAM·팔레트 전송마다 카트리지007000에1~6을 쓴다. 최초 오류는007001, 오류stage255다. 첫 패킷 대기에는 파란 배경, 검출한 오류에는 빨간 배경을 의도한다. VRAM 전송 전 force-blank를 명시하고 완료 뒤 표시를 켠다. 044의 성공한 WRAM 복사 방식을 참고했으며, 프로그램 ROM 공급 방식이 달라 같은 부트 코드의 재사용만으로 실기 성공을 가정하지 않았다.

새 host84MHz 상태 회로는 쓰기를 안정된 주소·데이터와 동기화한 제어로 인정하고 단계·최초 오류·stage6 횟수를 보존한다. SPI73은 D9/단계/오류/벡터·프로그램 읽기flags/횟수16비트/스키마1을 고정 스냅샷으로 돌려준다. raw read flags는 보조 관측이며 신호 미관측을 실행 부재로 단정하지 않는다. RUN 활성화는2단 동기화하고 raw 버스 격리는 즉시 적용한다.

MCU는 strict5E/D9로 식별하고 STOP 후 상태를 회수하여 기존 TXT에5개 필드를 추가한다. 알 수 없는stage/error도 보존하며 잘못된ID/스키마/예약비트는 거부한다. RUN 중 SD 쓰기는 추가하지 않았다. 메뉴 예산 복구, bounded RUN/STOP, base 복원, 강한NMI는 유지했다. NES CPU/PPU·ROM reader/service/cache는141과 동일하며 다시 전체 프레임/적재 시험을 반복하지 않았다.

## 다음 실기와 작업 의미

[142 실행 안내](../docs/nes-screen142-instructions.ko.md)에 따라 한 번 시험한다. 약9분 적재 후10초 표시, 전체10분 관찰 기준은 같다. 변경된 화면 경계의 결과를 얻는 시험이며 같은141 재시험은 아니다. 다음에는stage/오류/횟수와 화면 관찰로 첫 실패 구간을 고쳐 정상 화면을 우선한다. 일반 디버그 기능 확대·044/GBC 반복은 하지 않는다.

이 변경은 실기 화면의 부팅·전송 경계를 실제 배선에 연결하고 초기 표시를 명시한 작업이다. 전체 게임 완료나 글리치 해결 선언은 아니다. SMB3(J),mapper4/PRG256KiB+CHR128KiB·패드·오디오는 다음 단계다.141 ACK16ns 실패, E1/E2·8µs·양클록정지 CE9µs·source-lock4·124격리는 그대로 보류한다.
