# 127 로더·검증 후 RUN·클록 감시의 실제 코어 통합

PR72 병합 `cd6325e7f2980dc26a7ff9c6d492003ee6c3cbd2`에서 시작했다. **배선 통합과 기능 시험·FPGA 배치는 완료했지만, 168MHz 내부 타이밍은 미완료다. 실기 실행용 산출물은 아니다.**

## 작업 목표

126 읽기 전용 코어 후보에 실제 로더, CHECK 후 RUN 소유권, 클록 감시를 연결한다. 8MHz 로더의 쓰기 시간을 보존하고 실제 배치로 자원·타이밍 가능성을 확인한다. 실기 RUN에 필요한 최소 안정성 확보는 아직 달성하지 못했다.

## 작업 내용

- 동결126 fit02의 코어·READ16 reader·PLL84/168MHz·bridge8개 QSF 설정을 유지한다. 동결086 로더/검증 래퍼를 새 진단 후보로 생성하며 원래 공개 소스와 과거 증거는 수정하지 않는다.
- 로더 준비/쓰기/유지/해제를 22/64/22/22클록으로 설정한다. 5.952ns 모델에서 130.944/380.928/130.944/130.944ns로 기존 125/375/125/125ns 최소값을 보존한다. 이는 RTL 모델 시간이며 실제 출력핀의 전기적 시간 보증이 아니다.
- 전 바이트 CHECK/ACK/FINISH가 완료되어 `verified`가 설정된 경우만 START를 허용한다. `nes_spi_boot`의 차단된 START 배선을 연결하고 외부 `ext_arm`의 메모리 RUN 우회를 제거했다. `ext_arm`은 기존 영상 흐름용 입력으로 남아 있다. 이미지 형식은 여전히 진단용64KiB PRG+16/32KiB CHR다.
- CHECK와 RUN은 같은 reader를 독점 사용한다. 프로토콜 오류는 RUN과 읽기를 취소하지만 이미 시작한 쓰기는 완료한다. 원시 reset/클록 오류의 비동기 취소는 이 쓰기 완료 보장과 별도다.
- 메모리 heartbeat를21분주하고 반대 클록 감시 한도를672클록으로 바꿨다. startup은33603클록으로200µs 이상이다. 둘 중 한 클록이 살아 있어야 정지를 감지할 수 있고, 두 클록 모두 멈추는 반례는 남는다.
- 첫 배치의 CHECK 비교→판정 병목을 줄이기 위해 세 가지 CHECK 비교 결과를 레지스터에 미리 계산한다. CHECK index는 명령 종료 때만 바뀌고 length는 CHECK 동안 고정이며 offset은8바이트 프레임 중3번째 주소 바이트에서 완성된다. DATA의 실시간 length/ready 비교는 그대로 둔다. 검증 시 명령 종료 순간 선행 계산값과 원래 조건의 일치를 확인한다.

첫 fit01은959LAB/14,169LE이며 `check_next[0]→check_done`이 −2.508ns였다. 세 비교를 분리한 fit02는954LAB로 감소했지만 전체 memory168 최악값은 개선되지 않았다. 새 최악 경로는 `clock_guard|mem_fault→loader_boot|control|check_next[15]`(85°C,−2.647ns), 다른 slow corner에서는 `checked_data[2]→fault`(0°C,−2.258ns)다. 따라서 비교 분리만으로 문제를 해결했다고 하지 않는다.

unit02의 loader/boot/reader/guard와 최종 decoder02/fit02는 해당 RTL 해시가 일치한다. 변경한 decoder만 추가 시험했고 같은 전체 로더 시험을 다시 반복하지 않았다. 실제 전체 SPI→코어 동작, 최종 SNES 소비자, ARM/ASM, 설치 패키지와 새 실기 검증은 수행하지 않았다. 기존126의372 데이터쌍/10제어·reset체인 검증은 hierarchy와 배치가 달라져 이번 후보의 승인으로 재사용하지 않는다.

실패도 보존했다. unit01의 WRITE63 부정 시험은 RAM 모델이 먼저 거부했는데 검사기가 다른 monitor 문구를 기대하여 실패했다. unit02에서 기대 문구를 바로잡았다. 초기 보고서 파서는 `Total LABs` 실제 제목을 잘못 예상했으며 같은 원시 보고서로 수정 검증했다. 라이선스 문제나 새 라이선스 요청은 없었다.

동결1,171파일 manifest: `c2a31d101697953dcc1d02fc3ef82036ff24d16a134a144b0eb74749aa99a6c8`. 완료 finalizer나 동결 파일은 다시 수정하지 않는다. 동결 notes의 next에 있는 `140ns-class` 문구는 부정확한 초안 표기이며, 실제 계약과 공개 메타의 최소값은 **125/375/125/125ns**다.

## 작업 의미와 다음 작업

이번 변경은 **실기 코어 동작을 위한 로더·메모리 배선 구현과 통합 검증**이다. 단순 문서/디버깅 기반만의 작업은 아니지만 게임 기능·MMC3 호환성·실기 RUN 완성을 의미하지 않는다. 첫 목표 SMB3(J), mapper4, PRG256KiB+CHR128KiB는 유지한다.

1. fit02 소스를 기준으로 SPI 명령 판정과 진단 reset 경로를 분리한다. 과거124 로컬 reset 해제 원칙을 새 loader/decoder까지 대조하고 raw reset의 조합 논리 우회 및 높은 fanout을 확인한다. 오류 검출/RESET 취소를 느슨하게 만들지 않는다.
2. 영향을 받는 명령 경계·오류/정지 시험을 한 뒤 새 fit/타이밍을 확인한다. 검증되지 않은 false path나 multicycle을 추가하지 않는다. 가상 디버그 포트를 포함한 현재9LAB을 최종 여유로 보지 않는다.
3. 새 hierarchy의 CDC/외부 IO, 실제 SNES 소비자와 관측 가능한 종료 경로를 확인하고 최소 RUN+044 독립 복원 실기로 넘어간다. 변경 없는119 전체80KiB·BASE·ENTRY·전체 코어 프레임 반복은 피한다.

E1/E2, 전체 MTBF·외부 IO,8µs 보증, 양쪽 클록 정지/CE9µs 반례는 계속 미해결이다. 제한 진단 준비도6완료/5부분/1미완료는 게임 완성률과 별도다.
