# NES139 실기 결과 — 같은 주소의 CPU 읽기 응답 대기 중 마감 실패

사용자는 두 TXT 작성과 정상 펌웨어 복원에 성공했으며, 글리치가 보였는지는 불확실하다고 보고했다. **최초 오류 수집과 조기 종료 경로는 확인됐지만 NES 실행은 실패했다.** 화면 성공, 이번 실행의 메뉴 복귀 육안 확인 및 GBC 플레이는 별도로 확인되지 않았다.

## 확인된 결과

| 구간 | 결과 |
| --- | --- |
| 후보 식별 | FPGA5B / observerD6 일치 |
| 적재·전체 대조 | 81920바이트 완료, verified=1, 오류0 |
| 실행 | run_passed=0, ROM 오류1, 최초 실행 오류1 |
| 유효 CPU ROM 샘플 | 최초·마지막·STOP 후 모두123028; 이전138과 같음 |
| 최초 상태 | CPU 주소와 pending 주소 모두0xE184, CPU 요청 진행 중, age3 |
| 소비 시점 | cpu_sample=1, cpu_valid=0, rom_response=0, rom_ready=0 |
| 종료 | run_stop_error=0, stop_ok=1, 기본FPGA 복원·메뉴 준비 완료 |
| 사용자 확인 | TXT 작성·정상 펌웨어 복원 성공, 화면 변화 불확실 |

원본 진행 파일은 순서·경과시간이 일치하는47개512바이트 기록이다. DISPLAY_NEXT=524890ms(8분44.890초), DISPLAY_STOPPED=524970ms, MENU_PREPARED=528100ms(8분48.100초)다. 표시 단계의 두 체크포인트 차이는80ms로, 이전138의10340ms에서 줄었다. 이 값은 MCU 처리 시간을 포함하며 실제 화면 표시 시간이나 정확한 오류 발생 시각은 아니다. 짧게 지나가 화면 변화를 알아보기 어려웠다는 관찰과 모순되지 않는다.

## 새로 좁혀진 원인 범위

`fault_context_hi=440181c3`, `fault_context_lo=0800e184`, valid=1이다. 최초 오류 에지에서 서비스는 **CPU가 필요로 하는 바로 그 주소의 읽기를 이미 요청한 상태**였으나 유효한 캐시 또는 완료 응답이 없었다. 그 순간 미완료 요청의 소유자는 PPU가 아니라 CPU이며, 서비스 age는3이다. age는 NES 마스터 클록 카운터이고 CPU 사이클 수나 ns가 아니다. 주소는 외부 ROM 매핑 주소이며 CPU PC로 단정하지 않는다.

이는 CPU 읽기 요청 시작부터 응답 전달까지의 시간과 소비 시점의 관계를 우선 조사할 근거다. 이전 PPU 요청이 CPU 요청 시작을 늦췄는지, 주소 유효 신호·캐시 갱신·요청/ACK 동기화가 영향을 줬는지는 이 단일 상태만으로 확정할 수 없다. PSRAM 칩 불량이나 데이터 값 오류도 입증하지 않는다. `rom_ready=0`은 미완료 읽기 동안 가능한 정상 busy 상태다.

138과139에서 오류1과 유효 샘플 수123028이 반복됐다. 같은 실행 경계를 우선 재현할 가치가 있지만, 같은 프로그램 명령에서 실패했다는 증명은 아니다. 마지막 flags3은 STOP 후 reset 유지+sticky ROM 오류이며 RUN 도중 reset의 증거가 아니다. 이번에는 최초 오류1과 STOP 오류0이 분리되어 이전의 오류 덮어쓰기 문제가 해소됐다.

## 다음 작업

1. 현재139 RTL·동일 진단 ROM에서0xE184/샘플123028 부근의 CPU 주소 유효화, 이전 CPU/PPU 요청, 요청 수락, reader 응답/ACK, 소비 에지를 집중 대조한다. 모델 위상과 실제 클록 조건의 차이를 확인한다.
2. 원인이 확인된 요청·응답 경계만 수정한다. 근거 없이 PSRAM 읽기 시간을 줄이거나 deadline 검사를 제거하지 않는다. 기존 저장·부품·전체 적재·무변경 fit을 반복하지 않는다.
3. 관련 경계와 복원 경로를 확인한 다음 수정 후보를 실기에 전달한다. 동일139 재시험이나 추가 영상은 이번 판정에 필요하지 않다. 이번 응답 확인에서는 새 펌웨어를 만들지 않았다.

원본 TXT는 기존139 동결 증거 밖의 별도 관측 폴더에 보존했다. 공개 [관측 메타](screen139-hardware-observation.json)에 원본 해시와 해석값을 기록한다. [139 제작 결과](FAULT139-RESULT.ko.md)와 패키지·고정 소스는 변경하지 않는다.
