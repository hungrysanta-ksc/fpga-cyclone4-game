# NES105 최종 파일 조합과 실기 판정 경계

ARM104·CF86의097 ASM·정확044 복원 조합을11개 파일의 역할과 SHA256으로 고정했다. 이름이 같은 구형 파일, 진단/복원본 혼동, 설치 승인 플래그 변조를 오프라인에서 거부한다.

PR54 병합 `93feb9f3262cf2ce01db3105602ac74ffaf497d0` 및 head `80c161525cced4640d596088c0bd01f0b108c951` 포함 확인. 이번 목표인 **최종 파일 조합 고정·거부 검사·관측 해석 정리**는 완료했다. 외부 IO·공통고장 조건이 해결되지 않아 실기 배포 승인은 미완료다.

## 작업 의미

실기 디버깅 기반의 검증·배포 준비다. 같은 검증 파일 조합을 다시 선택하고 잘못된 조합을 걸러낼 수 있게 됐다. CPU/PPU/APU/mapper 배선이나 SMB3 실행 기능을 추가한 작업은 아니다. 전체 목표 중 '검증된 MCU/FPGA와 복원본을 구분해 실기 진단에 넘기는 준비'가 진전됐다. 게임 구동 진척도나 새로운 하드웨어 PASS로 계산하지 않는다.

## 파일 조합

[입력 manifest](pair105-inputs.json)는11개 파일의 크기·SHA·역할·장래 SD 경로를 지정한다. 실제 로컬 출력은 `files/` 아래 평면 검토 자료이며 SD 설치 구조나 ZIP을 만들지 않았다. 설치/복원 명령은 없다.

|역할|고정 입력|근거|
|---|---|---|
|진단 MCU|CF86-IRQ104,182640바이트|104 최종 ARM과 동일 SHA7f0601cc…|
|진단 FPGA|CF86, packed219453 / raw510856|097 동일086 fit ASM;071 형식으로 새 재생성 없이 전체 decode 대조|
|base/menu|받은base packed168440/raw214981, menu65536|097 실제 C decode/104 통합 입력과 동일; 받은base의 legacy EOF 패딩 보존|
|합성 입력|80/96KiB 데이터와 iNES 헤더|104 main/FAT32 시험의 exact fixture; 상용 ROM 아님|
|선택 표식|NES VERIFY 094 80.nh1 / 96.nh1|104 소스 및 바이너리에 실제 존재하는 이름,0바이트 표식|
|수동 복원|정확044,169056바이트|091 보존 ZIP 전체 SHA를 검사한 뒤 원본 member SHA1c3b40a3… 대조|

복원본은 진단 펌웨어와 동일 SD 대상명이라도 역할이 다르다. 두 파일을 동시에 같은 대상으로 복사하는 계획을 만들지 않는다. base/menu 경로는 기존 기준 파일을 뜻하며 새파일로 자동 덮어쓰는 허가가 아니다. 사용자 SD가 현재 같은 내용이라는 증거도 아니다.

manifest SHA `bba0316dc6160c107edab5a41b6ea32e11b74e3fc227f23b69e967a79dbc797a`. 검토기 입력 digest는 manifest 밖에서 제공하며, digest를 다시 계산해도 고정된 파일 역할/해시/정책과 다르면 거부한다. 신뢰 기준은 검토된 도구·공개 메타데이터·동결 증거다. 전자서명이나 공격자가 저장소까지 바꾼 경우의 인증 체계는 아니다.

## 검사 결과

정상1·거부23, 총24건 통과.11개 파일 각각의 바이트 변조(빈 표식은1바이트 추가), 누락, 추가 구형 파일,044→104 잘못 교체, 오래된 manifest digest, 역할 변경,069 표식,6개 승인/보호 플래그 변경을 검사했다. 알려진 파일 전체 SHA와11역할 목록이 일치해야 통과한다.

CF86 압축을510856바이트 전체 해제해 동일 RBF와 비교했다. 기존 base의 다른 EOF 패딩은071 decoder로 임의 재인코딩하지 않는다. 이 base의 실제 C 해제 근거는097에서 재사용하며 이번에 새 C 실행을 했다고 쓰지 않는다.104 동결 manifest와 선택한 원본 파일 해시도 대조했다.

선택 파일명·FPGA/ROM 경로·보고 파일명·두 메뉴 상태 문자열8개가 실제 소스와 ARM 바이너리에 존재함을 확인했다. 이는104 호출 검증을 대체하는 새 실행 증거가 아니다. 제품 C/RTL 변경, ARM/fit/STA/ASM/Questa 재실행, 실기 시험은 없다.

## 관측 해석에서 확인한 제약

펌웨어 VERSION은104지만 선택 파일명·로그 이름과 TXT candidate는094로 유지되어 있다. 이름이나 candidate만 보고104 실행을 확정하지 않는다. 전달 시 펌웨어 SHA를 확인해야 한다.

제품은 `/sd2snes/nes-verify-last-094.txt`를 PREPARED_RESET_HELD 단계에서 저장한다. RETURN_READY_RESET_RELEASED는 UART 출력만 하므로 TXT가 있다는 것만으로 RESET 해제/메뉴 표시/게임 정상까지 증명하지 않는다. 저장 실패가 공유 오류로 이어지지 않는 경로도 있어 '메뉴 복귀와 TXT 저장 성공'은 각각 확인해야 한다. 이전 TXT가 남을 수 있으므로 향후 실기 절차에는 이전 파일 보존·분리와 새 파일/화면 관측을 함께 넣어야 한다.

오류 뒤 추가 SD/UART/화면 IO를 강제할 수 없다. 검은 화면·오래된 TXT·0바이트만으로 특정 원인을 단정하지 않는다. LED는 외부에서 보이지 않는다는 사용자 관측을 유지한다. 정상044 수동 복원 절차는 보존하며 이번에 다시 시험을 요청하지 않는다.
