# NES157 — 실제 게임의 첫 PPU 오류 직전16클록 보존

**156의 Start 실패를 고쳤다는 판정은 아직 없다.** 같은 SMB3에서 정지 직전 요청 경계를 회수할157 시험판을 준비했다. 기존156의 오류 순간만으로 원인을 고를 수 없다는 점을 실제 ROM 서비스의 짧은 합성 시험으로 확인하고, 필요한 관측만 추가했다.

## 이번 변경이 필요한 이유

156은 Select 커서 이동·버튼 수신·메뉴 복귀가 통과했지만 Start 이후155와 같은 `e200c2f4:30217a18`, PPU line193/dot8/주소0x217A18 오류가 났다. APU 채널 쓰기를 차단해도 남아 사운드만을 유일 원인으로 삼을 수 없다. 이전155의 타일·뱅크를 고정한 충돌 시험은 실제 입력 후의 주소 변화 순서를 포괄하지 않는다.

새 짧은 시험은 실제 ROM 서비스에 두 합법적인 입력·백엔드 순서를 준다.

1. 먼저 CPU 읽기가 점유하고, 그동안 등장한 PPU 요청이 CPU 응답까지 기다리는 경우.
2. 앞선 CPU 점유는 없고, PPU 주소 자체가 뒤늦게 등장하는 경우.

둘 다 PPU 요청 후 두 클록 뒤 샘플하게 하면 실제156과 같은 최종 문맥·오류2가 나온다. 새 이력에는 첫 경우의 CPU 요청/점유/응답과 둘째 경우의 유휴·늦은 주소가 다르게 남는다. **이는 최종 스냅샷의 모호성과 새 관측의 구분 능력을 증명하는 합성 시험이지, 실제 실기 원인 재현이나 둘 중 하나로의 확정은 아니다.** 매퍼 변경·선행 읽기·캐시 교체 등 다른 실제 원인도 열려 있다.

## 변경과 보존 범위

NES 클록마다96비트를16칸 링 메모리에 저장하고 최초 오류 클록을 포함해 고정한다. line9/dot9/상태12/전송주소22/예측주소22/현재PPU주소22 순이다. 상태는 request,response,ready,busy,pending_ppu,cpu_need,cpu_sample,ppu_sample,ppu_valid,hint_valid,use_prefetch,prefetch_hit다. 전송주소는 새 요청이 있으면 그 주소, 없으면 현재 대기 주소다. 응답과 새 요청이 같은 클록이면 새 주소가 표시되므로 응답 주소는 앞선 요청과 함께 해석한다. 반환 데이터·CPU PC·직접 매퍼 레지스터·창 이전 이력은 포함하지 않는다.

SPI77 헤더와 A0~BF의 두48비트 페이지를 STOP 후 읽어 오래된 순서로 TXT에 쓴다. 헤더의 fault_seen이1인 경우 마지막 항목이 첫 오류 클록이다. 정상 STOP은 마지막 실행 구간이며 오류라고 해석하지 않는다.16클록은 명목21MHz대 기준 약0.75µs의 짧은 창이다. 전체 게임·버튼 시각 기록과 다른 용도다.

ROM 서비스·코어 결선은 새 출력 전용 관측선을 제거하면156 소스와 정확히 같다. CPU/PPU/APU/MMC3/reader/loader/화면·패드 전달/클록·타이밍 제약은 유지했다.156의 진단 APU 채널 차단도 유지하며 정상 오디오 완성으로 보지 않는다. board66/observerE0를 엄격히 사용한다. 과거 ID를 무조건 허용하지 않는다.

MCU는 기존 STOP 검증 뒤 이력을 읽는다. RUN 중 SD쓰기는 없다. 보조 헤더·페이지가 잘못되면 valid0으로 남기고 기존 복귀를 계속한다. TXT 버퍼는3072→4096바이트로 늘렸고 버튼16건과 이력16건을 함께 채운 경계 포맷을 확인했다. 물리 SPI·클록 실패까지 항상 복구된다는 뜻은 아니다.

## 검증 결과

- 선택 test04: 실제 SPI 관측부로 링 순환·오래된 순서·첫 오류 포함·STOP 유지·재설정·부분 기록·미기록 슬롯·이전 문맥/패드 응답 통과. 실제 ROM 서비스의 위 두 합성 경로는 같은 오류 문맥과 다른 이력을 남겼다.
- host02: 실제 MCU RUN/STOP·디코더를 합성 SPI에 연결해 정상1+잘못된 응답12조건에서 STOP·체크포인트·복귀 유지. 버튼256마스크와 최대 버튼 시각·최대16이력 결합 포맷, 작은 버퍼 거부 통과. 전체 FatFS·실제 MCU 실행 시험은 아니다.
- reuse01: 관측 출력 제거 후 서비스·실제 중간/상위 결선이156과 같고 나머지 기능 입력도 보존됨을 확인했다. 배치 후 게이트 등가 증명은 아니다.
- ARM02/armcheck02:188604바이트, strong NMI15저장/0호출과 기존 오류 복귀·새 식별자 확인. asm01은 선택fit02 배선을 그대로 사용했다.
- fit02:13763LE,5005레지스터,122실제핀/0가상핀,PLL1,**M9K56/56개**. 이력은 임시로3개를 추가했다. 논리적 미사용 비트가 있어도 추가 M9K 여유로 계산하지 않는다. 원인 확인 뒤 축소·제거할 관측이다.
- 같은155 실제 클록 SDC에서 setup **+0.055ns**, hold **+0.128ns**, 조건부 PSRAM **+3.763ns**, SNES 경계199.238ns<270ns.156부터 쓰는 별도 배치 개선 목표5.5ns는 **-0.042ns 미달**로 별도 보존했다. 실제 클록 주기·false path·multicycle을 완화하지 않았다.303개 라우팅/소스 입력을 유지한 같은 배치의 STA 재분석이다. PCB 허용치 가정·전체 IO·MTBF·clock-halt 한계는 여전히 미완료다.

초기fit01/arm01은 materializer의 상위 모듈 위치·문자열 개수 단언 오류로 빌드 전 중단했고 수정 후fit02/arm02를 선택했다. test02는 시험 코드의 예약어context 컴파일 오류, test03은 합성 CPU 캐시 상태가 실제 오류 문맥과 달라 단언 실패했고 각각 수정 후test04가 통과했다. 실패 근거는 따로 보존했다. 샌드박스의 임시 드라이브·DLL·호스트 식별 제한은 기존 호스트 실행으로 해결했으며 새 라이선스를 요구하지 않았다.

## 다음 실기와 종료 조건

[157 안내](../docs/nes-game157-instructions.ko.md)에 따라 같은 SMB3에서 첫 Start→1PLAYER에서 Start→가능하면 이동·점프를 확인한다. 같은 오류라면 두 TXT와 메뉴 복귀 여부만 있으면 된다. 이번 기록으로 PPU 예측/현재 주소 변화, CPU 점유, 요청 승인·응답, 캐시 유효화 중 실제로 먼저 어긋난 경계를 선택해 다음 수정에 연결한다. 창이 부족할 경우에도 범위를 근거 없이 확장하지 않고 누락된 경계만 보완한다.

같은156/044/GBC/A-B·변경 없는 전체 부팅은 반복하지 않았다. 실제 게임 플레이·오디오·저장·정상 표시 속도는 미완료다. 이 PR은 원인 구분에 필요한 최소 실기 관측을 갖춘 진전이며 게임 정지 해결 완료가 아니다.
