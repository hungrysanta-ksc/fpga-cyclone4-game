# 113 — 무로그 실패 재현과 SD 읽기 인계 수정

## 작업 목표

112의10분 이상 로딩·로그 없음 실패에서 첫 기록 이전의 중단 원인을 찾고, 긴 시험 대신 진입 구간만 실기에서 확인할 패키지를 만든다. 사용자 복원 정상 확인은 기록하되 별도GBC 결과를 추정하지 않는다.

## 작업 내용

일반 native `read_block`은 CMD18 읽기 완료 뒤 `TRANS_READ`를 유지할 수 있다.112는 첫 로그보다 앞의 `nes_cf86_enter094`에서 모든 `during_blocktrans!=0`을 고장 처리했다. 실제 C 경로에 그 상태를 넣으면 SD 명령0회·로그0·고정RESET으로 재현된다. 실기의 실제 상태를 읽은 결과는 아니므로 물리 원인 확정은 아니다.

113은 USB IRQ 차단·RESET 유지·진단 활성화 상태에서 종료된 일반 읽기만 CMD12로 정리한다. 기존 bounded native 응답·CRC·상태·busy 검사에 성공한 뒤에만 TRANS_NONE으로 전환한다. WRITE/MID/offload·불확실한 응답은 거절하고 재시도/후속쓰기하지 않는다. 유휴 상태에서는 CMD12를 보내지 않는다. 기존 CF86 소유권 검사를 완화하지 않는다.

첫 로그 `ENTRY_SD_READY`를 CSS 검사 앞으로 옮기고 진입 시 transfer 상태를 기록한다. CSS 거절 시 `CSS_CHECK_NEXT`까지만 남는다. 고장 뒤 SD 쓰기는 없다. 새 `NES ENTRY 113.nh1`은 진입 검사만 마치고 메뉴로 돌아간다. CF86 구성·ROM 입력·적재·비교·게임RUN은 실행하지 않으며 메뉴 SRAM 재적재는 수행한다.

## 작업 의미

실기 디버깅 기반의 메뉴→진단 진입과 최초 로그 공백을 수정한 작업이다. NES 코어 배선·게임 호환성 구현이 진전한 것은 아니다. 전체준비도4완료/7부분/1미완료와 SMB3(J) mapper4/384KiB 첫 목표를 유지한다. 외부 전기조건E1/공통원인E2/8µs 보장, 양클록정지lockedHIGH CE9µs 반례는 미해결이다.
