# NES111 제한 실기 패키지 발행

PR60 병합 커밋 `b49f9e2c8ea50ad15cf914d404011b0f1aad2be3`에 head `c13e79108f5b064e38f708366d3506005549e90a`가 포함됨을 확인했다. 사용자가 2026-10-09 직접 “실기 시험으로 가자”라고 선택했다. 110의 선택 대기를 해소하는 새 결정이며, 완료된 110 기록이나 109 파일 조합의 정책을 소급 수정하지 않았다.

## 결과

실행용 `NES111-80KiB-TRIAL-and-RESTORE044.zip`을 만들었다. 588,031바이트, SHA-256 `a63d464e19b013f0b69d71d89cd742ce26defb21d7282ab4788defb05fa915a6`이다. 시험 폴더 6역할과 복원 폴더 3역할, 사용 안내·사용자 결정·manifest를 합해 12항목이다. 패키지 각 바이트를 고정된 109 원본과 대조하며 ZIP 내부의 역할별 해시도 별도로 확인한다. 96KiB 표식과 입력은 없다.

ARM108/CF86/정확044는 재사용했다. 새 C/RTL 수정, ARM 빌드, fit/STA/ASM/Questa 실행은 없다. 이번 파일 대조는 전달 무결성 검사이며 기존 108/109 펌웨어 시험 건수를 늘리지 않는다. SD 복사와 실기 실행은 사용자가 외부 실기에서 수행하므로 아직 실기 결과는 없다.

**완료:** 선택 기록, 승인 범위가 표시된 시험 패키지, 복원 파일, 사용자 절차, 향후 실기 우선 작업 원칙. **미완료:** 실제 80KiB 적재·비교·메뉴 복귀 및 이번 복원 관측. E1/E2 전기 조건·8µs 차단 상한·전체 NES 게임 실행은 계속 미완료다. 전체 준비도 4완료/7부분/1미완료는 유지한다.

## 다음 관측과 분기

사용자는 정상 전원에서 `NES VERIFY 094 80.nh1`을 한 번 선택한다. 최대 600초 안에 메뉴가 돌아오는지 관측한 다음 TXT를 보존하고 정상044로 복원한다. 상세 복사 위치와 보고 항목은 [실기 안내](../docs/nes-trial111-instructions.ko.md)에 있다.

- 새 TXT와 실제 메뉴 복귀, 복원 후 메뉴·GBC를 별도 판정한다. `PREPARED_RESET_HELD`만으로 메뉴 복귀를 확정하지 않는다.
- 파일 없음·0바이트·메뉴 미복귀도 유효한 실기 증거다. 동일 시험을 반복 요청하지 않고 관측된 실패 경계부터 조사한다.
- 성공하면 실기 적재·비교·반환 경로를 기준선으로 고정하고, 다음 기능 통합에 필요한 최소 실험을 정한다. 80KiB 성공을 96KiB·384KiB SMB3·게임 RUN 성공으로 확대하지 않는다.

## 작업 의미와 운영 변경

이 단계는 검토 후보를 사용자 실행 패키지로 전달하는 **실기 검증·배포 준비**다. 코어 배선이나 게임 호환성 구현은 아니다. 사용자의 추가 지시에 따라 기본 보호 동작, 파일 조합, 관측 방법, 독립 복원이 준비되면 제한 실기에서 데이터를 얻는 것을 우선한다. 실기 데이터로만 판단 가능한 항목을 동일한 문서·모형 검사로 반복해서 미루지 않는다. 이미 승인된 범위는 재승인을 요구하지 않으며, 새 범위·위험이 생기면 차이를 먼저 판단한다.

109 조합의 역사적 승인 false, 110 검토 ZIP의 설치 금지 표시는 그대로다. 현재 제한 시험에만 [111 결정](../docs/nes-trial111-decision.json)의 승인 true를 적용한다. 8µs 보장과 전기적 signoff는 false이며, 기존 양클록 정지·locked HIGH·CE LOW 9µs 반례와 정상084/092 관측을 보존한다.
