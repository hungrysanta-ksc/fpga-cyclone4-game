# NES-H1-FIRMWARE-035 결과

2026-10-06. **실제 STM32용 전체 ARM 펌웨어 빌드와 호스트 바인딩 시험11개 통과.**
034 H1 FPGA를 설정하고 진입·RESET 종료·기본 FPGA/메뉴로 복귀하는 코드를 연결했다.
실물 MCU/콘솔 실행 또는 외부 I/O 타이밍 통과를 뜻하지 않는다.

- 전체 ARM GNU 13.3.rel1 빌드: 경고0, 바이너리168,288 bytes.
- 최종 ELF의 main에 H1 실행 호출3개와 확장자 검사4개가 존재한다.
- 호스트에서 생산 C 코드 그대로 실행: 정상 복귀·재진입·이미지 누락·잘못된 ID·응답 없음·SPI busy·실행 중 fault·base 누락·base 토큰 오류·USB IRQ 보존·확장자 경계 총11조건.
- 정상 경로 SCK224개 상승 edge에 mode0/최소 시간/명령·RESET 순서를 검사했다.
- 034 기록194개와 GBC C44 소스152개 해시 보존. 기존 FPGA/세션 소스와 C44 빌드 도구는 변경하지 않았다.

새 바인딩은 H1에만 GPIO SPI를 사용한다. SPI1의 기본 분주로는 250kHz 이하를 만들 수 없다.
GPIO/SPI 설정을 복원한 뒤 기본 FPGA 토큰을 확인한다.
USB IRQ에서 stock SPI를 호출할 수 있는 실제 upstream 경로도 발견해 H1 동안 해당 IRQ를 보호했다.
복구 실패 시 RESET을 유지하고 정지한다. .nh1 자동 부팅은 NACK 처리한다.
