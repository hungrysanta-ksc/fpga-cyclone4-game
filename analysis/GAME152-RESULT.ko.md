# NES152 입력 갱신과 PPU 요구 주소 기록

## 작업 목표

PR93 머지9b26d7b6a8375ff2cc10e8a6774bf5cced39d2d2를 기준으로 같은 SMB3의 조작과 조기 종료를 좁힌다. **입력 갱신 개선과 다음 실기 패키지는 완료했지만,151 PPU 오류의 실제 게임 재현·원인 수정은 미완료다.** 기존19초 오류를 해결했다고 표시하지 않는다.

## 작업 내용

SNES 프로그램이 게임 화면을 유지하는30 vblank 동안 매 vblank 자동 패드 수집 완료를 기다린 뒤4218/4219를6002/6003으로 전달한다. 기존에는 표시 한 번에 한 번만 보냈다. 표시 유지 시간·전체 화면 DMA·NES CPU/PPU 실행 속도·패드 비트 배선은 바꾸지 않았다. DMA와 다음 프레임 대기에는 여전히 수집 공백이 있다. 완전한 입력 독립화나60fps 표시 완성은 아니다.

151 오류 문맥에는 처리 중 PPU 주소0x217A18과 CPU 물리 주소만 있었다. 실제 PPU 요구 주소가 없어 요청이 늦었는지 요청 이후 주소가 바뀌었는지 구분할 수 없었다.152는 기존64비트 문맥에 형식 태그를 추가한다. bit63=1이면 하위25비트는 `{3'b000,ppumem_addr}`,0이면 기존CPU 물리 주소다. 처리 중 요청 주소bits46:25와 age·상태 필드는 유지한다. 태그는 **주소 종류**이며 오류 우선순위나 원인 코드가 아니다. 원인 코드는 별도run_rom_error로 판정한다.

서비스의 문맥 배선 외 코드가151과 정확히 같은지 확인했다. 기한 검사·중재·캐시·선행 읽기·PSRAM reader는 그대로다. 새62/DC 식별로 기존 문맥 형식을 혼동하지 않도록 했다. MCU는 후보명·엄격한 식별만 변경하며 RUN 최대60초·오류 조기 종료·STOP·메뉴 복귀·SD 기록은 기존 경로다.

변경 없는 초기30프레임이나19초 전체 핀 모델을 다시 실행하지 않았다. 기존30프레임(~0.498초) 모델은 약11분 걸렸으며19초를 단순 비례하면 수시간이다. 이는 비용 추정일 뿐 새 실행 결과가 아니다. 실제 게임의 부족한 요구 주소를 작은 문맥 변경으로 받고 조작 개선도 함께 확인하는 편이 현재 사용자의 실기 우선 원칙에 맞는다. 아직 필요한 실제 요구 주소·입력 경로를 추측으로 채워 캐시를 늘리거나 오류 검사를 제거하지 않는다.

## 작업 의미

실제 게임 조작을 전달하는 SNES 소프트웨어 개선과, 현재 조기 종료 원인을 구분하기 위한 최소 오류 기록 변경이다. 일반 진단 체계 확장이 아니다. 정상 플레이 목표는 아직 미달이며 다음 한 번의 SMB3 시험으로 제목→월드맵/스테이지와 입력을 확인한다. 오류가 반복되면 pending/actual demand·age를 비교해 선행 읽기·주소 변화·응답 지연 중 해당 경계를 좁힌다.
