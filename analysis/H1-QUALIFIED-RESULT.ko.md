# NES H1 043 구현·검증 결과

043은 입력 샘플링과 오류 기록 구조를 실제로 수정하고 MCU/FPGA 빌드까지 완료했다.
정상 동작과 실제 오류의 RTL 회귀는 통과했지만, SDF 적용 검사에서91바이트 뒤
불확정값이 남아 있다. **실기 배포는 보류한다.041 재시험도 요청하지 않는다.**
041의 실기 실패 원인이 해결됐다고 판단하지 않는다.

## 변경한 동작

- 주소·ROMSEL이 연속된 두 활성 샘플에서 같고 WR이 해제돼 있을 때 읽기를 시작한다.
  원시 핀은 최초 샘플링과 외부 버스의 즉시 해제에만 사용한다.
- 하나의 등록된 오류 이벤트를 sticky 오류와 최초 기록이 함께 소비한다.
  진단은 실제 판단에 쓴 샘플 주소와 이전 샘플, 래치 주소, 위치, 오류 매핑을 기록한다.
  041의 raw-strobe 카운터를 없앴고 프로토콜은43으로 분리했다.
- 응답 전에 RD가 해제된 경우는 정렬된 응답 준비 표식으로 계속 검출한다.
  처음부터 거부한 요청에는 조기 종료 오류를 중복해서 붙이지 않는다.
- 안정적으로 받은 쓰기는 WR의 안정된 해제를 확인해 한 번만 완료한다.
  한 번뿐인 상승 에지에 의존했던 대조군은 불확정 샘플 뒤 요청을 놓쳤다.

입력 폭·상대 지연·미검증 범위와 D0..DF 정의는
[입력/진단 계약](../docs/nes-h1-qualified-contract.md)에 명시했다.

## 아직 실패하는 검사

동일한 최종 netlist와 동일한 입력에서 SDF 적용은91바이트 뒤40805B에서
기대00 대신XX가 나왔다. 타이밍 위반612건은 ROM 주소 샘플링575건,
주소/데이터 첫 단계33건, ROMSEL 첫 단계4건이다. 오류 레지스터에 직접
원시 입력이 연결된 이전 구조는 제거됐지만, 첫 단계의 불확정값이
논리로 전달되는 문제는 여전히 분리해서 검증해야 한다.

SDF만 제거한 대조군은512바이트/오류0건을 통과했다. 이것은 타이밍 통과가 아니다.
게이트 내부 snapshot 버스의 최적화된 Z 비트를 실제 SPI 로그로 해석하지 않았다.
043은 정상 RD 해제 때 주소·ROMSEL도 바꾸므로,042의227바이트와 이번91바이트를
동일 조건의 개선/악화 수치로 비교하지 않는다. 실기 원인 확정도 아니다.

중간 실패도 보존했다: 초기 RTL의 거부 요청 중복 오류, 초기 게이트의300초
acquisition 대기 종료, 버퍼 채움보다 짧았던20us 검사 한도. 최종 대기 한도는1ms다.
초기 게이트 종료 때의 license-process fatal은 부모 타임아웃에 따른 종료 메시지이며,
라이선스 부족이 아니다. 모든 실행은 기존 Starter FLOAT 경로를 사용했다.
