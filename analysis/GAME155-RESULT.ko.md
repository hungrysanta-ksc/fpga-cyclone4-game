# NES155 — 일반 배경 선행 읽기와 다음 SMB3 실기

## 작업 목표

154에서 두 번째 Start 후 발생한 PPU 읽기 기한 오류를 줄이고 같은 SMB3(J)로 다음 실기 시험을 진행한다. 진입 정지 해결과 실제 이동·점프는 아직 실기로 확인하지 않았다.

## 작업 내용

154 실기 문맥은 line193/dot6의 일반 배경 읽기이며 요구·대기 주소가 모두0x217a10,age1,응답·유효값0이었다. 현재 read/write2007 파이프는0이었다. 이는 데이터가 필요할 때 아직 준비되지 않았다는 증거이며, PSRAM 불량이나 직전 CPU 점유까지 확정하지는 않는다.

155는 dot2에서 타일 번호가 확정된 후 dot3~4의 속성 읽기 구간에서 배경 하위 패턴을, dot5~6에서 상위 패턴을 준비한다. 실제 MMC3의 같은 뱅크 레지스터로 물리주소를 계산한다. 기존 서비스의 현재 요구 우선·빈 슬롯 선행 읽기·물리주소 캐시 태그를 그대로 사용한다. 기존 PPUDATA 중첩 예측이 우선하며 스프라이트 구간, 렌더링 꺼짐,2007 읽기·쓰기 파이프가 있는 일반 예측은 제한한다.

ROM 서비스/캐시 크기/READ16/클록/샘플 기한/IRQ 입력/게임 표시·패드 결정은 그대로다. 회수·메뉴 복귀의 MCU 동작과 관측기는154와 식별자·이름을 제외하고 같음을 비교했다. 새 조합은64/DE, 실행 표식은 `NES GAME 155.nh1`이다. PPU 상태 형식은 같고 hint 비트는 일반 선행 읽기도 포함한다.

## 작업 결과

- 실제 PPU 주소 생성·MMC3·ROM 서비스·READ16/168MHz·70ns 메모리 모델을 연결한 짧은 시험에서4타일 연속 읽기와12가지 CPU 상대 시점,3가지 메모리 위상을 확인했다. 후보36조건에서 오류 없이 샘플 데이터가 대상 ROM과 일치했다.
- 같은 소스에서 새 일반 선행 읽기만 끈 대조 시험은 각 위상에서 PPU 오류를 다시 발생시켰다. 기존 PPUDATA 예측은 켜 둔 대조다. 렌더링·스프라이트·2007 파이프·라인 끝의 활성 조건과 기존 중첩 주소식도 확인했다.
- 이는 합성 초기 상태와 주기적 CPU 점유 모델이다.154 실기의 직전 요청 이력을 재현한 것이 아니며 정확한 실기 원인은 미확정이다. 전체 게임 부팅을 다시 돌리지 않았다.
- 배치13709LE/5054레지스터/122실제핀/가상핀0/PLL1. 같은 클록 setup +0.015ns,hold +0.178ns. 기존 조건부 PSRAM 여유 +2.736ns,SNES 응답 예산203.311<270ns. 전체 외부IO·MTBF 검증 완료는 아니다.
- ARM187124바이트, 강한 NMI와 STOP 연결 검사 통과. 새 MCU 응답 해독960정상·10비정상 통과.154 회수/관측기 검증은 정확한 식별자 정규화 비교를 근거로 재사용했다. 새 전체 FatFS/SD 모델 실행이나 새 관측기 시뮬레이션을 했다는 뜻은 아니다.
- 초기 탐색01/03~05의 미설정 값은 코어의 내부 리셋 해제까지 기다리지 않은 시험 설정 문제였다.02는 소스 줄바꿈 매칭 실패,재사용 검사01은 명령0x64까지 치환한 검사기 오류였다. 이를 고친 선택 결과와 실패 원본을 보존했다.

설치 ZIP은 준비됐으며 [실기 안내](../docs/nes-game155-instructions.ko.md)를 따른다. 기존 ROM·기본 FPGA·메뉴·044 복원 파일의 내용은 보존했다. 실기 판정 전에는 정상 플레이나 기존 정지 해결을 완료로 표시하지 않는다. 표시 속도, DMA 입력 공백, 소리, 저장은 남아 있다.

## 작업 의미

일반 배경 데이터의 메모리 대기를 앞당기는 실제 실행 경로 수정이다. 추가 로그만 확장하는 단계가 아니다. 최소 변경 경계와 배치를 확인했으므로 다음은 SMB3에서 두 번째 Start 이후 진행·이동·점프를 확인하는 실기 한 번이다.154·044·A/B 패턴·변경 없는 전체 부팅은 반복하지 않는다.
