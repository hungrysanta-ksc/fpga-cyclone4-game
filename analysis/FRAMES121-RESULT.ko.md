# 121 — 70ns 실제 코어의 전체 프레임과 클록 위상 검증

## 작업 목표

PR66 병합 `ac3baaaf10168e9574e2bed8e02c027e021e48f7`을 확인했다.120에서 선정한 READ_CYCLES=8,70ns 후보가 초기 PPU 구간을 넘어 완전한 화면을 생성하는지 검사한다.119의 전체80KiB 적재·복구 실기 성공은 기준선으로 유지한다.

## 작업 내용

공개052 manifest와 일치하는 실제 CPU·PPU·선행 요청 서비스·CDC 소스와 자체 fine_x(80KiB),banks32(96KiB) 입력을 사용했다. 테스트벤치만 읽기8클록,접근70ns,메모리 시작 위상 매개변수로 바꿨다.120의 조기 종료 관측기는 사용하지 않았다. 정상 NES 클록,60ms 부팅 뒤 캡처,150ms watchdog,기존 데이터·기한 검사를 유지했다.

3.5ns(기존 위상),0ns,11.25ns 시작 위상에서 각각 두 입력의4프레임을 실행했다. 입력은 배경 전용·불변 CHR 진단으로,일반 게임의 스프라이트·가변 CHR 동작을 포함하지 않는다. 모든 픽셀,시각 필드를 제외한 패킷,PPU S/E/F/D 이벤트를 핀된052 기준과 비교하고 시각 차이는 사례 내 상수인지 확인했다. 기존 consumer는 테스트벤치 SNES 버스 자극이다.

## 작업 의미

**정상 속도 코어의 메모리 배선 후보가 화면 생성까지 이어짐을 확인한 단계**다.120의 부팅·PPU128샘플에서 전체 프레임으로 범위를 넓혔다. 실기 게임 동작이나 SMB3 호환성 완료는 아니다. 제한 진단 체크리스트6완료/5부분/1미완료는 그대로이며 게임 완성률과 구분한다.

다음은 CF86의 등록형 SETUP/ACTIVE/HOLD/RELEASE 보호 reader를 정상 속도 경로와 연결했을 때 추가 지연을 실제 코어가 감당하는지 확인한다. 실패하면 서비스·캐시·선행 읽기를 고치며 NES 감속이나 프레임 버림으로 숨기지 않는다. 이어 클록/리셋/독점 소유권과 같은 후보의 보드 fit을 묶는다. 기존 guard는8MHz/20–22MHz용이므로84MHz에 그대로 연결하지 않는다.059의959/963LAB(가상핀/PLL0)은 최종 물리 보드 여유가 아니며 진단191LAB를 단순 합산하지 않는다. 실제 SNES 소비자/DMA/표시 기한도 남아 있다.

119의 같은80KiB·BASE·ENTRY는 다시 시험하지 않는다. 최소 RUN 후보의 새 관측·오류 종료·044복원 경로가 준비되면 실기로 넘어간다. SMB3(J) mapper4/384KiB 첫 목표,외부 E1/E2·8µs·양 클록 정지 lockedHIGH CE9µs 반례는 유지한다.
