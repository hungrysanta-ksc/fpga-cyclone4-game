# NES 058 — 실행 전 공유 메모리 읽기 포트

후보 **NES-READBACK-PORT-058**. END 뒤 코어를 reset에 둔 채 기존052 PSRAM reader를 CHECK가 공유하도록 생성 경로를 추가했다. 원본052–057·MCU056·실기044는 유지한다. [계약과 재현](../docs/nes-rom-readback-port-contract.md).

| 검증 | 결과 |
| --- | --- |
| 핀 모델 단위 | 1,919,161 검사. 재적재를 포함한 실제 핀 쓰기835,585바이트 |
| 실행 전 읽기 | 80/96KiB 전 영역을 포함한180,238회, 수락한 주소 tag·반환 바이트 검사 |
| RUN 재전환 | 두 형상 각각512회, 총1,024회 읽기 |
| 취소/오류 | 취소10회, 불법 요청/명령10경우, PRG/CHR 손상4회 검출. 오류 중 수락된 쓰기 펄스 유지 |
| 원본052와 RUN 차등 | 양쪽 클록 edge161,207회 비교,4,096요청=4,053응답+43리셋 취소 |
| 잘못된 연결 대조 | chip/lane/CHR 주소를 바꾸면 정확히 반환 주소 검사에서 실패. 예상 실패 확인 |
| 공동 진단 fit | 13,946LE,949/963LAB,5,160레지스터,26M9K.14LAB 여유 |

CHECK는 메모리 클록에서 직접 기존 FSM을 사용하므로 두 번째 읽기 제어기나 새 CDC 요청 왕복을 추가하지 않는다. 주소·chip/lane·데이터도 기존 레지스터를 재사용한다. SPI가 장시간 보존할 완료 응답은 아직 없다. 읽기 요청마다 응답을 한 클록 안에 소비해야 한다.

057 대비 레지스터는2개, 조합 함수는25개 증가했지만 배치가 달라져 LE30개·LAB5개 감소했다. 이는 FPGA에 기능을 추가하면 항상 자원이 줄어든다는 뜻이 아니다. 가상 핀도288→335로 바뀌었다. **14LAB은 이 외부 CHECK 포트 시험의 여유이며 다음 SPI 연결 비용을 포함하지 않는다.** 실제 보드 클록/PLL/핀/소비자/STA는 미완료다.

첫 fit 준비는 중첩 소스 폴더를 만들지 않아 파일 복사 단계에서 실패했다. 디렉터리 생성을 수정한 뒤 같은 RTL로 map/fit가 통과했다. 초기 diff의 미연결 CHECK 출력 경고5개는 빈 출력 연결을 명시하여 제거했고 같은 비교 횟수로 다시 통과했다. 첫 unit 통과 후 쓰기 펄스 유지 시험을 추가한 최종 unit도 통과했다. 원시 실패/초기 결과를 보존했다. 라이선스 오류는 없었다.

**SPI opcode/MCU 비교·CRC/완료 mailbox/검증 성공 START gate는 미구현이다.** 이번에는 전체 NES 코어를 재실행하지 않았다.057의8프레임 근거는 과거 상태로 유지하며058의 RUN reader 차등 검증과 구분한다. 실기 읽기 검증·새 SD 이미지·새 GBC 실기 회귀를 주장하지 않는다. GBC152개와 원래 NES334개 파일의 해시는 보존했다.

다음은 CHECK 요청·완료 응답을 SPI/MCU에 연결하고, 전체 바이트 비교·tag/timeout 거부·실제 C GPIO 파형을 검증하는 단계다. 이후 실제 코어 회귀와 새 공동 fit를 수행한다. [현재 인계](../cores/nes/HANDOFF.ko.md), [검증 요약·해시](rom-readback-port-verification.json).
