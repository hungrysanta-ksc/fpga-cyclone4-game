# NES142 실기 결과 — 화면 프로그램 진행 확인, 그림 정확성 실패

**143 후속 정정:** 기존 진단 ROM의 정상 에뮬레이터 RGB도 잡음형 무늬다. 아래 기록의 사용자 글리치 관측은 유지하되, 그 외형만으로 정상 영상 실패를 확정했던 해석은 철회한다. 실제 픽셀 정상도 아직 확정하지 않는다. [143 비교 시험](SCREEN143-RESULT.ko.md)을 기준으로 판정한다.

사용자는141과 동일한 글리치를 보고했다. **새 로그는 화면 프로그램이 전혀 실행되지 않았다는 가설의 우선순위를 크게 낮춘다.** SNES 프로그램의 전송 완료 지점을72회 관측했으나 정상 그림은 표시되지 않았다. 같은142 재시험은 필요 없다.

47개512바이트 진행 레코드의 순서·시간 증가를 확인했다. 표시 단계는525,210→535,550ms(10.34초), 기본FPGA 복구536,430ms, MENU_PREPARED538,750ms다. 표식 횟수를 이 MCU 구간으로 단순 나누면 약6.96회/초지만 SNES 프레임의 정확한 측정 구간이나 정상 TV 프레임률로 쓰지 않는다. 앞서 보였다는1~2회 움직임과도 구분한다.

## 이번 결과로 좁힌 범위

생성기의stage6는 패킷 획득, 길이·일부 헤더 검사, WRAM DMA, 패킷 소비 확인, VRAM·팔레트 전송과 표시 설정 뒤에만 기록한다. 반복72회는 **SNES 부팅과 WRAM 코드 진입 후 화면 처리 루프가 진행했다는 강한 근거**다. 이전에 우선 의심했던 부팅 자체 정지를 계속 첫 가설로 두지 않는다. NES 읽기 카운터만 보고 판단했던141보다 구체적인 결과다.

그러나 코드에는 그림 본문 전체의 체크섬이나 VRAM 읽기 대조가 없다. 전송 명령을 마쳤다는 표식은 올바른 내용이 저장됐다는 보증이 아니다. 현재 우선순위는 다음과 같다.

1. **ROM atlas → SNES VRAM 전송 내용:** 부트 코드 읽기는 성공해도 별도 bank01:8000의16KiB 그림 데이터 DMA가 정확하다는 검사는 없었다. program-ROM의 bank/주소/읽기 타이밍과 실제 VRAM 내용을 확인한다. 아직 특정 DMA 결함을 확정하지 않는다.
2. **패킷 본문 → 타일맵·팔레트:** 길이·헤더 통과는 본문1,988바이트 전체의 정확성을 증명하지 않는다. 잘못된 타일 번호나 그림 데이터가 반복 전송되면 계속 깨진 화면일 수 있다.
3. **SNES 표시 설정과 실제 데이터의 조합:** 전송 데이터와 VRAM이 맞으면 타일맵/문자 베이스·증분·팔레트·표시 모드를 확인한다. 에뮬레이터 정상3프레임은 소프트웨어 알고리즘 근거이며 실제 카트리지 버스 검증은 아니었다.

패킷의 서로 다른 내용을72회 받았는지, NES가 목표 속도로 프레임을 만들었는지도 아직 입증하지 않았다. 따라서 단순히7FPS로 돌고 있다고 결론내리지 않는다. 앞서 보고된 무음은 오디오 미구현과 일치하고, 대각선 띠는 사용자 설명에 따라 카메라/CRT 현상으로 제외한다.

## 다음 작업

일반 진단 체계를 늘리거나 같은142의9분 적재를 다시 요청하지 않는다. 이미 통과한 부팅·상태 회수·RUN/STOP은 재사용한다. 기존044 성공 경로와 비교하면서 내부에서 생성한 단순 타일·색상 표시를 먼저 대조하고, ROM atlas DMA와 실시간 패킷 본문을 붙여 최초로 그림이 깨지는 경계를 확인한다. 가능한 한 긴 NES 적재 이전의 짧은 표시 시험으로 나누되, 그 성공을 실제 NES 게임 성공으로 대체하지 않는다.

이번 작업은 새 실기 증거의 판정·기록과 계획 변경이다. 새 펌웨어·FPGA 배치·시뮬레이션·패키지는 만들지 않았다.142 동결 제작 자료와 ZIP,141의ACK16ns 실패 및 기존 전기적 보류를 보존한다.044/GBC 복원 반복은 생략한다. 정상 영상·SMB3 mapper4/384KiB·패드·오디오는 여전히 미완료다.
