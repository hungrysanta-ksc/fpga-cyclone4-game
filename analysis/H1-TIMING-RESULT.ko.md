# H1 042 조사 — 041 실기 실패와 배치 지연 대조 검사

**041도 실기 실패다. 새042 실기 이미지나 설치 묶음은 만들지 않았다.**
이번에는 로그의 오류 분류가 서로 맞지 않아 원인 판독을 바로잡고, 실제041 배치 결과로 지연 포함/제외 검사를 실행했다.

## 실제041 로그

F2_STATUS/07,start/stop0,base복구1,polls21,elapsed450ms. 식별A5/프로토콜0x41과 계측태그0x41이 확인돼 이번041 진단 쌍 실행은 확인된다.
집계 최초 오류는 frontend=1(읽기 중단/주소/선택 변경),stage0,producer0이다.
반면 별도 최초 원인 캡처는0x20(순서/ready 검사)으로, 이상적인 RTL에서는 frontend bit1=2를 설정하는 조건이다.
같은 최초 원인을 설명해야 할 두 기록이 다른 오류 종류를 가리킨다.

원인 캡처의 ready=1,raw주소40:81A0,기존 래치주소40:819F,position416(0x1A0),pending0,
RD낮음,WR높음,ROMSEL낮음이다. raw주소는 기대되는 다음 위치와 일치한다.
하지만 실제 순서 검사에 쓰인 addr_sync 값은041에서 직접 저장하지 않았으므로,
raw주소 일치만으로 그 비교가 정상이라고 증명하거나 잘못된 바이트가 정확히 몇 개였다고 단정하지 않는다.
카운터 low1/previous_low18/previous_high13도 비동기 raw 입력을 직접 사용하므로 물리 타이밍 측정값으로 신뢰하지 않는다.

새 판독 검사에서 이 기록을 'different_first_error_bits'로 분류하도록 했다.
실제 첨부의 불일치,합성 일치,이전stage오류가 먼저였던 합성 사례3개로 검사했다.
041 상세원인0x20만 보고 payload 순서 오류라고 확정하지 않는다.

## 실제 배치 결과로 추가 실행

041 fit 사본에서 Quartus EDA로 EP4CE15F17C8 타이밍 넷리스트와 Slow1200mV85C SDF를 생성했다.
HDL·SDC·핀·RBF는041과 같고 사본 QSF에는 EDA 출력 메타데이터4줄만 추가됐다.
기존 무료 Starter FLOAT로 실제 Questa 실행했다. 라이선스나 전역 서비스 설정을 바꾸지 않았다.

동일512바이트 시험대와 동일 primitive 연결에서 SDF 적용 여부만 비교했다.
8MHz 보드 입력과 실제 PLL 모델,MCU SPI 진입,레지스터 acquire와 payload 읽기를 포함한다.
합성 외부 입력은 주소setup30ns,RD low214ns,release 뒤125ns+다음setup30ns이며 데이터는low180ns에서 읽는다.
실제 보드에서 계측한 파형의 재생은 아니다.

|실행|결과|
|---|---|
|실제배치 지연 적용(gate03)|227바이트까지 일치 후40:80E3에서Z 출력,기대00. 타이밍 위반617건|
|지연 미적용 대조(gate05)|512바이트 일치,frontend0,타이밍 오류0|

617건은 제어 입력 첫단6,주소/데이터 첫단262,ROM 주소 샘플277,raw 읽기 카운터72건이다.
타이밍 notifier와검사는 끄지 않았다. 다만 첫단 비동기 샘플의 timing violation/X 전파는 vendor 모델의 동작이므로,
이 실패를 실기에서 같은 원인이 확인된 것으로 주장하지 않는다.
지연 없는 논리 검사만으로 현재 버스 입력·계측 회로를 실기 검증했다고 볼 수 없다는 검증 공백을 확인한 결과다.

배치된 내부 debug 벡터는 상수 최적화로 일부 비트가연결되지 않아 통과대조에서도Z가 보인다.
이 별칭 벡터를 SPI로 읽은 실제041 텍스트처럼 해석하지 않는다. frontend/실제핀 데이터 비교와 그 한계를 분리했다.

Slow85C 경로 inventory: raw입력→sticky오류 최대10.522ns,raw입력→별도캡처 최대12.731ns,
rawRD→첫동기화플립플롭5.101ns. 서로 다른 경로의 최댓값 차이를 특정 핀의 실제경합 시간으로 단정하지 않는다.
이 값들은 기존38입력/11출력 미제약을 대신하는 IO signoff가 아니다.

## 실패한 조사 실행도 보존

- gate01: vendor dffeas 라이브러리 연결 누락으로 elaboration1101오류. 기존altera 라이브러리 추가 후 재실행했다.
- gate02: 긴SPI덤프가300초 제한을 넘었다.75바이트 뒤Z/상태0X와타이밍128오류를 보존했다. 종료 중 license process 메시지는 타임아웃으로 프로세스 연결이끊긴 결과이며 새 라이선스 필요 문제가 아니다.
- gate04: 지연 미적용 대조를 시도했지만 생성넷리스트의 initial $sdf_annotate가 SDF를 다시 적용했다. 무효 대조로 보존했다.
- gate05: 원본넷리스트를 별도보존하고 자동annotation 한줄만 제거했다. driver가 SDF 적용 여부를 로그로검증한다. primitive/연결은변경하지 않았다.
- gate03의 중복annotation과 gate04의 자동annotation은 동일SDF값을 쓴다.34652개 triplet 모두 min/typ/max동일임도 확인했다.
