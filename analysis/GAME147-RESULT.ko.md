# NES147 실제 SMB3 ROM 경로 확장 — 실기 배포 전

146 실기 결과는 PR90에서 마무리했다. 이 변경은 별도 게임 작업이며 아직 설치 가능한 펌웨어가 아니다. A/B 패턴 시험을 추가하지 않고 사용자가 지정한 Super Mario Bros. 3 (J)를 기존 CPU·PPU·MMC3와 PSRAM 읽기 경로로 실행했다.

## 완료한 범위

- 정확한 ROM 해시를 검사하고 PRG256KiB·CHR128KiB를 사용한다. ROM 데이터와 화면 캡처는 공개하지 않는다.
- 물리 주소 범위와 PRG/CHR 캐시 태그를 함께 확장했다. 적재·CHECK·SPI 계수는 19비트이며 새 식별5F와 BEGIN 인수2로 기존 작은 진단 호출을 구분한다. 아직 실기 top·MCU에 연결하지 않았다.
- 변경 경계 시험은 98검사, 실제 쓰기8회·CHECK 읽기6회·오류6경우를 통과했다. 카운터는 시험 전용으로 경계값을 주입했다. 전체384KiB 적재 통과를 뜻하지 않는다. PRG 태그를 다시 줄인 대조군은 두 번째 뱅크 검사에서 거부됐다.
- 실제 ROM 실행의 20번째 출력에서 61,440픽셀의 커튼·바닥 그림을 확인했다. 이는 RTL 시뮬레이션의 초기 장면이며 독립 에뮬레이터의 픽셀 일치나 실기 출력·게임 플레이 통과는 아니다.

## 실제 게임에서 발견한 미완료 문제

30프레임을 요청한 기본 실행 core02는 24번째 프레임,193줄,231도트에서 PPU 주소 `0x21e1ff`의 유효 데이터가 샘플 시점까지 준비되지 않아 실패했다. 시뮬레이션 시간은 약0.395초다. 실제 PC 계산에 걸린 분 단위 시간과 게임 실행 시간을 혼동하지 않는다.

CPU의 `$2007` 읽기가 렌더링의 주소 래치와 겹치면 직전 PPU 버스 데이터가 다음 주소의 하위 바이트가 될 수 있다. 이때 요청이 늦게 확정되며 현재 외부 읽기 왕복 시간이 마감 안에 들어오지 못했다. 검증된 주소에서 잘못된 캐시 데이터를 반환한 경우와 구분한다.

`--prefetch` 실험은 유휴 슬롯에서 이 주소를 미리 읽는다. 실제 요청을 우선하고 전체 물리 주소 태그와 기존 마감 검사를 유지한다. 첫 실패 경계의 짧은 재현은 두 위상에서 성공했고, 미리 읽기를 끄면 PPU 오류2가 다시 발생했다. 그러나 실제 ROM core03은 26번째 프레임,193줄,237도트의 `0x21e100`에서 다시 실패했다. **부분 수정이지 게임 실행 성공이 아니다.** 직전 접근이 내부 네임테이블 RAM이고 다음 접근이 CHR인 경우를 현재 예측이 처리하지 못하는 것으로 추정한다.

현재 생성기가 core03의 입력 소스26개를 같은 해시로 재현함을 확인했다. 선택된 경계 시험은 unit04/prefetch01이며 core02/core03의 원본 실패, unit01 컴파일 실패와 unit02 BEGIN 거부도 비공개 증거에 보존했다. 독립 에뮬레이터 시도는 결과를 얻지 못했으므로 통과 근거에서 제외했다.

## 다음 작업

1. 내부 RAM→CHR 전환에서도 실제 MMC3 뱅크를 반영해 늦은 PPU 요청을 처리한다. 첫 실패 경계를 수정한 뒤 실제 ROM 실행으로 돌아간다. 오류 숨김·코어 클록 감속으로 통과시키지 않는다.
2. MCU384KiB 적재·전량 검증을 연결하고 로딩을 줄인다. 146의80KiB 적재·대조518.99초를 단순 비례하면 약41.5분이므로 기존 바이트 전송을 그대로 실기 배포하지 않는다. 이 수치는 추정이며 게임 로딩 실측이 아니다.
3. 게임의 스프라이트·스크롤·CHR 전환을 표현할 SNES 출력과 패드를 연결한다. 고정 팔레트·배경 전용 NCR1을 게임 화면으로 간주하지 않는다.
4. 변경된 자원·타이밍·유한 종료 경계를 확인한 뒤 실기 패키지를 제공한다. 실기에서는 마리오 이동·스크롤·프레임 끊김을 중심으로 판단한다. 동일044 복원과 A/B-only 시험을 다시 요구하지 않는다.

오디오와 다른 맵퍼 확장은 별도 미완료다. 기존146 RTL·배치·패키지는 변경하지 않았다. 이 작업의 의미는 실제 목표 게임의 메모리 경로를 구현하고 첫 실행 장애를 재현한 것이며 실기 게임 구동 완료가 아니다.
