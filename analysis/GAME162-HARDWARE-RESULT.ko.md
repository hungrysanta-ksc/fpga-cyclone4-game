# NES162 실기 결과 — 첫 레벨·정상 복귀 통과, 사운드 무음

사용자가 첫 레벨 진입·정상 플레이·약60초 뒤 메뉴 복귀를 확인했다. 두 TXT도 정상이며, 실행 중 ROM 오류는0이다. **APU 차단을 해제한 뒤에도 이번 플레이는 정상적으로 끝났지만, 사운드 목표는 달성하지 못했다.** 소리가 나지 않았다는 사용자 보고를 실패로 기록한다.

[제작 당시 검증](GAME162-RESULT.ko.md) · [이번 로그 분석](game162-hardware-verification.json) · [현재 인계](../cores/nes/HANDOFF.ko.md)

## 로그 판정

| 항목 | 결과 |
| --- | --- |
| 실행 식별 | NES-GAME-162 / FPGA6B / observerE5 일치 |
| ROM 적재·비교 | 각각393216바이트, load/file/verify 오류0 |
| 실행·정지 | run_passed=1, run/ROM/first/stop 오류0, fault_context_valid=0 |
| 실행 구간 | DISPLAY_NEXT233960 → DISPLAY_STOPPED294620ms, **60.660초** |
| 메뉴 준비 | MENU_PREPARED297860ms, 정지 이후3.240초; 실제 복귀는 사용자 확인 |
| 진행 기록 | 512바이트×104레코드, seq0..103 연속, 경과 시각 단조 증가 |
| 사운드 | 사용자 확인: 무음. 음원 생성·DAC 핀·본체 음소거 상태는 로그에 없음 |

60.660초는 제목·선택·월드맵을 포함한 펌웨어 실행 구간이며 첫 레벨 안에서만60초가 아니다. `apu_channel_writes_blocked=0`은 제작 설정을 적은 상수이므로 실제 APU 쓰기나 음원 출력의 측정값으로 해석하지 않는다. 복원은 실행 종료 시 base/menu 복귀이며 별도의044 재시험을 요구하지 않는다.

입력 변화231건 중 마지막16건만 남고215건은 덮어써졌다. A/B/방향 조합이 기록되어 있지만 물리 버튼 상태를 측정하지 않았으므로 지속 입력 문제 해결로 판정하지 않는다. `ppu_history_flags=1`은 정상 말단 기록이다. `screen_frames=365`는 `screen_telemetry_trusted=0`이어서 FPS나 연속 화면 성공의 근거가 아니다. 이번에는 영상·음성 파일이 없으며 무음과 플레이 판정은 사용자 보고에 따른다.

## 무음 조사 — 확인한 코드 차이와 남은 가설

162는 APU 전체 쓰기와 `out_sample → nes_dac162 → DAC 핀`을 연결했다. 반면 SNES에서 실행하는 `game-program.hex`는161과 해시가 같다. 생성기 `tools/build_nes_game161.py`에는 SPC 통신 포트 접근이나 사운드 초기화 호출이 없다.

기존 GBC 기반 코드 `src/renderer/base/g9_snes_io.py`에는 별도의 SPC700 업로드와 DSP FLG를0x20으로 설정하는 절차, 완료 토큰과 FLG 읽기 확인이 있다. **FPGA 출력 연결에 집중하면서 본체 쪽 사운드 초기화 차이를162의 검증 범위에 포함하지 못했다.** 이것이 다음에 먼저 확인할 구체적인 누락이다. 다만 이번 실기에서는 DSP FLG나 DAC 활동을 읽지 않았으므로, 본체 음소거가 실제 원인이라고 확정하지 않는다. APU 출력이0이거나 출력 경로에 다른 문제가 있을 가능성도 남는다.

기존 APU 시험과 DAC 시험은 각각 자극을 넣어 확인했으며 실제 SMB3의 CPU 쓰기부터 본체 아날로그 출력까지 연결한 실기 검증은 아니었다. 그 시험 통과를 실제 소리 성공으로 확대하지 않는다.

## 다음 작업

PR104 머지 후 GBC의 유한 SPC 초기화·FLG 읽기 절차를 NES 클라이언트에 맞춰 검토한다. WRAM 주소·호출 ABI·제한시간을 확인하고 초기화 결과를 기존 종료 로그에 남겨, 대기 실패가 게임·메뉴 회수를 막지 않도록 한다. 필요할 때만 최소 음원 활동 관측을 추가한다. 이미 여유가 LAB3/M9K0이므로 범용 이력 회로부터 늘리지 않는다.

최소 확인 후 실제 SMB3로 음악·효과음과 첫 레벨·메뉴 복귀를 검증한다. 이어 연속 화면을 개선하며, 사운드·화면 확인 후60초 제한 해제와 오류/본체 리셋 로그, 장시간 입력 유지 평가 순서를 유지한다. 동일162 무변경 재시험·044/GBC 복원·전체 적재 시뮬레이션 반복은 하지 않는다.

이번 커밋은 결과와 인계만 갱신한다. 펌웨어·FPGA·실기 ZIP·동결162 및 기존 공개 소스 핀은 변경하지 않았다.
