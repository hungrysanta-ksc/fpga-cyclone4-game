# NES095: CF86 전체 전송과 고장 취소 파형

094의 실제 C로 캡처한 80/96KiB 전체 전송을 CF86 SPI·메모리 RTL에 재생했다. 정상 클록 조건에서 총180224바이트,901152프레임,50464224응답 비트를 비교했고, 원시 PLL lock 상실 두 경우의 취소 파형과 대조3개를 확인했다. 정상 전체 실행은 독립 클록 감시 회로의34비트 반복 상태를 이용한 조건부 분리 검증이다.

PR44 병합 `e2a11912f1799c75de33a7a34969cddc8c9b6183`에서 시작했다. [조건과 재현](../docs/nes-replay095-contract.md), [검증 메타데이터](replay095-verification.json)를 함께 읽는다.

## 완료된 범위

| 경우 | 적재·재읽기·ACK 각각 | 프레임 | 비교한 응답 비트 |
| --- | ---: | ---: | ---: |
| 80KiB | 81920 | 409616 | 22938352 |
| 96KiB | 98304 | 491536 | 27525872 |

두 경우 모두 실제 MOSI로 RAM을 채웠으며 사전 적재하지 않았다. 쓰기 주소와 바이트 lane, 16비트 읽기 enable, 모든 바이트, 마지막 ACK·FINISH·STOP, 종료 핀 상태를 검사했다. RUN은 없고 FPGA 재구성·메뉴 복귀는 이 파형 재생 구간 밖이다.

새 C의 RDY 검사에 매회250ns의 **가정한 비용**을 더했다. GPIO 상승/하강, CS, MOSI 변화와 C 샘플 위치를 검사하고 시각·송수신 비트를 압축 기록했다. C 모델 시간은80KiB127.185087초,96KiB152.621247초다. 실제 STM32 실행 시간이나 상한이 아니다. capture03의 MOSI 검사 추가 후 두 trace는 capture02와 같았다.

CF 식별 중과 첫 DATA 중 raw lock 상실에 해당하는 C 취소 trace를 별도로 실제 guard와 대조했다. 106은45 GPIO 기록,101은1023기록/192응답 비트다. 두 경우0 writes, CS 비활성/SCK LOW·메모리 및 MISO 차단, lock 복귀 후 빈 이미지가 확인됐다. C의 FAILED 유지/재진입 차단도 같은 실행에서 확인했다. 실제 C와 RTL을 실시간으로 연결한 co-simulation은 아니다. ref-only halt·늦은 CHECK 중 고장은 별도086/094 근거이며 이번 두 경우로 확대 해석하지 않는다.

대조는 응답 비트 변조, 반복 상태 비교값 변조, 예정된 raw lock 고장을 제거하는 세 가지다. 모두 예상한 검사에서 거부됐다.

## 정상 클록 회로의 분리 검증

직접 실행은 SPI와 무관한20MHz 감시 회로 계산에 큰 비용이 들었다. 무분리1024프레임을 보존하고 첫 전체 실행은 의도적으로 중단했다. 이후 같은 guard의 모든14레지스터/34비트와8MHz·20MHz 클록 위상이4µs 뒤 같음을 확인했다. guard는 두 클록과 reset만 입력으로 받으며 SPI 입력이 없다. 동일한 이상적 주기 입력과 reset 불변을 전제로 한 결정적 상태 반복 논증이다.

정상 파형의 처음1024프레임까지 실제 guard를 실행하고, 그 뒤 guard의 두 입력 클록만 정지시켜 이미 확인한 allow=1을 유지한다. 생산 소스는 변경하지 않으며 시뮬레이션 사본의 guard 포트 표현식을 분리한다. **SPI·PSRAM의8MHz는 계속 동작한다.** 기존처럼 RESET-held H1 포트와 사용하지 않는84MHz legacy 도메인도 별도 정지한다. 무분리1024와 분리8192프레임, 상태 변조 대조가 통과했다. 고장 파형에는 guard 분리를 적용하지 않는다.

이는 전체 기간에 감시 회로를 직접 실행한 결과가 아니며, 임의 클록 위상/주파수/중단, CDC 메타안정성, 아날로그 PLL, SDF 또는 전기 승인에 해당하지 않는다. 관련 전제·분리 위치를 숨기지 않고 결과에 기록한다.

## 보존 및 남은 범위

새 생산 C/RTL·ARM·fit·STA·ASM은 없다. 핵심 C9개는094 ARM과 같고, RTL16개는086 fit03과 같다. 094 ARM180928바이트를 재사용하며 재빌드 성공으로 세지 않는다. 093 SDF와084/092 실기 결과는 기존 범위에서 유지한다.

capture01의 helper 인수 오류, fault01의 SV 예약어 오류, 의도적으로 중단한 full80-01과 launcher EOF/종료 로그를 보존했다. 취소 뒤 FLOAT wrapper가 서버를 종료했고 라이선스 경로를 바꾸지 않았다. 이번 원인은 라이선스 자격 오류가 아니다.

실제077 SD/FatFS·FPGA 구성·공유 오류·시간/핀 소유권을094 세션과 연결해 검증한 뒤, 동일086 fit의 ASM/최종 ARM/044 복원 쌍을 만든다. 외부 IO와 공통 클록 고장 조건을 해결하거나 승인 범위를 명확히 하기 전에는 설치하지 않는다.

정상 클록 전제의 전체 SPI 비교 및 두 취소 파형 목표는 달성했다. 실제 native SD/config/전체 복구와 실기 쌍은 미완료이며 설치 승인은 false, 전체 준비도4완료/7부분/1미완료다. SMB3(J), mapper4·PRG256KiB/CHR128KiB 첫 게임 목표는 유지한다.80/96KiB 진단은384KiB 게임 지원이 아니다.
