# NES 메모리 패킷 생산기045

2026-10-06. **완성된 영상 패킷을 가변 응답시간 메모리에서 읽어044 전송부로 넘기는 원본 RTL을 구현·검증했다.** 실제 NES 실행 중 화면을 만드는 인코더와 물리 메모리 컨트롤러는 아직 연결하지 않았다. 실기 기준044와 배포 이미지는 그대로 유지한다.

| 검증 | 실제 결과 |
|---|---|
| 입력 출처 |021 원본 NES 참조 실행의 banks32/fine-X 각4프레임.025 패킷을 다시 구성하고 전체 참조 화면과 비교 |
| 실제 전송 |NCR1 패킷8개×2008바이트가044 큐/CDC/호스트/MMIO 경로에서 일치 |
| 회귀 |세 가지 클록 조합마다17항목 통과. 각19153바이트, 총57459바이트 비교 |
| 소유권 |두 슬롯 포화 시 새 메모리 읽기 정지, 미완성 패킷 비공개, 빈 acquire 재시도 |
| 실패·복구 |길이/세대/순서/주소 범위, 요청·응답 시간초과, 주소 불일치, 부분 읽기 뒤 서비스 오류, RESET 뒤 오래된 응답 검사 |
| 최종 단독 map/fit |416LE,155레지스터,0M9K,전체61LAB,266가상핀. 최종 시뮬레이션과 소스 해시 일치 |

첫 두2008바이트 패킷의 descriptor 수락부터 완료 관측까지는46.56ns 큐 클록에서 약0.868ms였다. 포화 대기가 포함된 세 번째는 약2.13ms였다. 이는 합성 메모리 모델과 이미 완성된 입력을 사용한 측정이다. NES 실제 패킷 도착 시점이나 VBlank 마감 충족으로 해석하지 않는다.

초기 테스트벤치가 길이 레지스터6006 대신 소비량6008을 읽었고, 빈 acquire 응답 뒤 재시도를 누락했다. 두 실패 로그와 수정 전 벤치를 보존했다. 이후 RTL 회귀는 통과했지만 초기 합성에서 가변 epoch의 비동기 RESET 대입이 래치로 추론됐다. 큐와 같은 동기식 RESET 캡처로 수정해 최종 회귀와 재배치를 완료했고10240/335093/332060 경고가 사라졌다. 상수 출력·클록핀 미지정·주기 절삭·IO 관련 경고는 보존했다. 389LE 초기 수치는 최종 비용이 아니다.

외부 요청은 RESET 즉시 차단하며 새 세대는 큐 클록에서 저장한다. 세대가 오래된 응답은 버리고, 현재 세대의 잘못된 응답은 오류로 정지한다. 응답은 같은 큐 클록 도메인에서 요청당 정확히 한 번 와야 한다. 실제 메모리 서비스의 CDC와 이 보장은 이후 검증 대상이다.

## 다음 통합 순서

1. 실제 NES fetch→NCR1 인코더와 원본 패킷 버퍼의 완료/소유권 계약을 구현한다. 지금의 이력 패킷 입력을 실시간 구현이라고 부르지 않는다.
2. 보드 메모리 서비스의 지연·중재·RESET과 클록 관계를 연결하고044+045+NES 공동 배치를 다시 측정한다. 단독61LAB와 기존 잔여40LAB를 단순 합산해 성공/실패를 단정하지 않는다.
3. SNES의 NCR1 런타임 소비자와 표시 정책을 연결한 뒤 MCU 파형·동일 소스 fit/STA·복구 검사를 거쳐 다음 실기 쌍을 만든다.

044 화면 순환/RESET 복구 및 GBC 플레이의 실기 성공 기록은 유지된다. H1 재진입·장시간 반복, 외부 전기 타이밍, 실제 NES 게임/음향/저장 지원은 여전히 별도 항목이다. 이번 단계는 새 실기 패키지가 없으므로 SD 교체가 필요하지 않다.
