# NES144 실기 결과 — 문자·메뉴 통과, 갱신 일관성 미완료

두 TXT와 연속 사진, 사용자 육안 관찰을 받았다. `NES 144` 글자·A/B 변화·실제 메뉴 복귀는 확인했다. 81,920바이트 적재·전량 대조, RUN/STOP, base 복원이 통과했고 기록된 오류는0이다.

사용자는 화면 전체가 한 번에 바뀌지 않고 글자 일부가 따로 갱신된다고 확실히 관찰했다. 위·아래 A/B 혼합과 일부 글자 혼합을 미해결로 남긴다. 대각선 밝기 띠만 카메라/CRT 효과로 제외하며 부분 갱신까지 촬영 탓으로 돌리지 않는다. 현재 코드의 짧은 forceblank는 눈에 보이지 않을 수 있으므로, 검정이 안 보였다는 사실만으로 미실행을 단정하지 않는다.

전체 패킷을 받았다는 사실과 패킷 안 데이터가 같은 NES 프레임에 속한다는 사실은 별개다. 실제 주사 중 VRAM 쓰기인지, 이미 섞인 패킷인지 아직 확정하지 않았다. stage112/frame161/mask8은 `screen_telemetry_trusted=0`이며 FPS나 정상 프레임 수로 환산하지 않는다.

펌웨어 경과시간 기준 적재207.660초, 대조311.310초, 표시31.710초, 메뉴 준비556.050초다. 9분 전부가 SD 쓰기는 아니다. GPIO 비트별 SPI와 바이트별 DATA/상태조회·READ/STATUS/ACK 비용이 크며, NES 본래 요구시간이 아니다. 현재 검증 완료가 START 조건이므로 단순히 대조를 건너뛰지 않는다.

다음은 [145](SCREEN145-RESULT.ko.md)의 긴 검정과 고정 그림을 한 번 촬영해 섞임이 언제 남는지 판별한다. 동일144/044 반복은 요구하지 않는다.
