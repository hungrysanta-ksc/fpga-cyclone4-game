# 124 — 코어·reader·영상 경로의 도메인별 reset 해제

## 작업 목표

PR69 병합 `befb91f2746f202fff9a08dd021a85c0b19ec3c9` 확인 후,123에서 드러난 초기화 완료 신호의 도메인 간 reset 직결을 수정했다. 도메인별 reset 배선 구현과 그 기능·배치 검증은 달성했다. 전체 CDC·외부 IO 타이밍과 실기 RUN 코어는 아직 미완료다.

## 작업 내용

`nes_domain_reset124`은 공통 reset을 비동기로 걸고, 대상 클록의 두 상승 에지를 거쳐 해제한다. 클록이 멈추면 해제되지 않는다. 로컬 RAM 초기화는 RUN/외부 reset/PLL lock 조건으로만 시작하며, `memory_ready`를 기다리는 코어 reset과 분리해 초기화 교착을 피한다.

reader의 기존 source_reset/memory_reset을 실제 상태·동기화 레지스터의 reset에 연결하고 원시 reset의 조합 우회를 제거했다. 영상 bridge의 상태도 q_up/h_up을 통해 해제한다. host stage와 SNES frontend에는 별도의 host 도메인 reset을 연결했다. 모든 도메인은 같은 원시 reset을 공유하며 독립 reset은 지원하지 않는다.

과거 해시가 고정된 제품 모듈은 바꾸지 않았다. `nes_reset124.py`가 정확한 원문 일치를 확인해 새 작업 디렉터리에만 진단용 RTL 변형을 생성한다. 이 변형은 실제 CPU/PPU/APU/메모리 서비스/영상 전달 회로의 기능 시험과 Quartus 배치에 사용됐다. 문서만 정리한 작업이 아니다. loader/CHECK·guard·실제 SNES 프로그램은 이번 읽기 전용 통합 범위에 포함되지 않는다.

코어 프레임·패킷은 내용이 같고 기록된 tick은 모두 기준보다4 작다. reset 시작/해제 위상 변경에 따른 일정한 기준 이동이며,이벤트 순서·각 이벤트 간 tick 차이·픽셀은 동일하다. 절대 tick이0차이라고 기록하지 않는다. 122의24프레임 전체를 반복하지 않고 변경된 연결에 대해 한 입력의4프레임을 확인했다.

세 corner의 클록쌍별 setup/hold/recovery/removal 최악 경로72개를 추출했다. 동일 클록 경로는 모두 양수다. `init_done`에서 시작하는1,272개 경로 중 비동기 reset36개(6종착점×2종류×3corner)는 core/host/reader의 release 레지스터에만 연결된다. 나머지 setup/hold는 로컬 메모리와 같은 NES 도메인의 CPU/PPU 데이터 경로다. 기존에 다른 도메인의 host 상태·RAM주소·reader 데이터 레지스터로 직접 가던 초기화 reset 경로는 이번 배치에서 제거됐다. 합성은 같은 조건의 source/q/host release 회로 일부를 병합했다.

이 결과는 비동기 reset 입력 자체의 recovery/removal이나 metastability/MTBF 검증 완료가 아니다. 원시 reset→해제 레지스터의 검사와 묶음 데이터 CDC 위반을 그대로 남겼으며 false-path/clock-group 면제는 추가하지 않았다. 이번 논리 펄스 시험의0.1ns는 실물 reset 최소 펄스 규격을 보장하지 않는다. PSRAM의 PCB/패드 지연·전압·부하·외부 IO 제약도 남는다. 남은30LAB는 로더·guard·최종 소비자가 빠진 값으로 최종 여유가 아니다.

## 작업 의미

**실기 코어 동작을 위한 reset 배선 구현과 기능·물리 배치 검증**이다. 코어 초기화 뒤 서로 다른 클록의 회로가 제각기 reset에서 풀릴 수 있는 경로를 줄였다. 게임 호환성이나 최종 설치 이미지 완성을 뜻하지 않는다.

다음은 같은124 배치에서 reader의 address_hold/data_hold 및 request/ack,영상 bridge의 req/reply 데이터를 대상으로 안정 유지 구간과 실제 최대 지연을 대응시키고 정확한 제약을 검증하는 것이다. 다음 단계에서 변경 없는 fit/전체 프레임을 반복하지 않는다. 이어 로더 쓰기375ns·guard·독점 소유권·전체 자원·실제 SNES 소비자,진행 관측·오류 종료·독립044복원을 묶어 최소 RUN 실기로 간다.8MHz WRITE3를168MHz에 그대로 옮기는 것은 금지한다.
