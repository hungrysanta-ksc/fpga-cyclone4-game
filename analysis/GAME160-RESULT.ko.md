# NES160 — 렌더링 재개 시 실제 주소를 미리 읽는 실기 시험판

**159의 첫 레벨 진입 오류와 같은 주소·시점·읽기 순서를 실제 PPU 렌더링 재개 경로로 재현했다.160은 그 전환에 필요한 주소를 한 PPU 주기 먼저 예측해 경계 시험을 통과했다. 첫 레벨 플레이 성공은 실기 확인 대기다.** PR101 머지 `7f93ac599a958d9073eb571468cc7dd8d6459ed3` 기준이며,159에서 확인한 월드맵 진입·이동 성과를 유지한다.

## 확인한 원인 후보와 수정

[159 실기](GAME159-HARDWARE-RESULT.ko.md)는 line193/dot336에서217000을 샘플3클록 전에 요청해 오류2로 종료했다. CPU읽기는 이미 끝났고 reader가 비어 있었다. 이전 dot8의 불필요한 CPU읽기와는 다른 경계다.

새 시험은 PPU2001 쓰기를 실제 레지스터에 전달하고 `re_sr` 렌더링 지연 파이프라인·ALE·하위주소래치를 그대로 실행했다. 렌더링이 dot336 같은 짝수 패턴 읽기 구간에 켜지면 직전 ALE가 없어 옛 하위래치00이 남는다. 일반 배경 예측217078/217070 대신 실제 주소217000이 필요한 상태가 만들어졌다.2001 쓰기 이전의 스크롤·이름 바이트·하위래치와 CPU출력버스·PPU 위치는 시험대에서 설정했다. 실기159는 이전 렌더링 파이프라인을 기록하지 않아 이 원인 후보가 물리적으로 확정된 것은 아니다.

160은 `re_sr[1]=1`, `re_sr[2]=0`인 한 PPU 주기 앞의 재개 구간에서, 다음 짝수 배경 패턴 읽기가 사용할 **상위 배경 주소와 보존된 하위주소래치**를 예측한다. 가시 scanline, 비스프라이트, 해당 패턴 위상, PPUDATA 읽기·쓰기 파이프라인이 비어 있는 범위로 제한한다. 이 주소가 현재 데이터 유효 조건에 막히지 않도록 재개 예측 신호를 서비스 입구까지 연결했다.

실제 PPU 레지스터·주소·래치·읽기 의미, 매퍼 상태·IRQ,159의 CPU/DMA raw읽기 자격, 공유 service/physical reader/캐시/기한/클록은 그대로다. 실제 수요 우선과 완료 전 읽기 취소 금지도 유지한다. 일반 힌트 조건을 일괄 해제하지 않는다. ARM 변경은160/69/E3 식별·파일명뿐이며 기존60초 상한·오류 회수·버튼/16클록 이력·APU 채널 차단을 유지했다.

## 변경 경계 시험

선택 `test05`는 실제 PPU/매퍼/service/READ16과70ns 메모리 모델, 지정 SMB3 데이터로 실행했다.

- 재개 목표dot334/336 × 이전 하위래치00/5A × 메모리위상0/3.5/5.5ns: 수정12건 모두 올바른 PPU 바이트와 샘플 기한 통과.
- 재개 예측만 끈 대조12건 모두 오류2. 기존 일반 힌트/읽기 자격은 그대로여서 변경의 영향을 구분한다.
- 기존159 경계 시험도 같은 제품 RTL에 적용해 수정39건 통과, 불필요읽기 대조39건 중18건 오류를 보존했다. 각 실행의 CPU/DMA48자격조건과12정상샘플을6회 확인했다. 기존 시험대는 새 미사용 출력 선언만 추가한 사본이며 원본은 보존했다.
- 시험 전 실제 PPUDATA 파이프라인을8회 활성화해 미정 값을 없앴다. 전환 동안 요청·응답·현재주소·유효·샘플·오류·힌트의 미정 값을 명시적으로 거부한다.

대표 dot336/래치00/위상0에서 기존 조건은 실제와 같은 CPU03F86E→217000 요청을 보였다. 수정판은 dot335의 재개 예정 신호에서217000을 예측하고, CPU 응답과 같은 클록(오류 기준-6)에 요청했다. 응답은 샘플1클록 전에 도달했고 dot336에서 정상 수신했다. 낮은 주소가5A일 때도21705A로 비교했다. 00을 하드코딩한 우회가 아니다.

이는 특정 전환 경계의 기능 시험이며 전체 CPU 명령 실행·게임 재생·모든 스캔라인/PPUDATA 겹침/매퍼 변경 위상의 보장은 아니다. 같은 실기 재시험이나 전체 부팅 반복 대신 이 최소 검증 후 첫 레벨 실기로 돌아간다.

## 배치와 펌웨어

첫 `fit01`은 명목 클록 setup-0.170ns로 실패해 배포 대상에서 제외했다. 경로는 SPI byte_count→miso_hold 및 적재 state→loaded_bytes였다. 두 경로에 더 엄격한5.3ns 배치 지침을 추가해 `fit02`를 새로 배치했다. 실제 클록·false path·multicycle을 완화하지 않았다. 실패 배치와 원시 결과를 보존한다.

선택 `fit02/asm01`:13725LE/5005레지스터/122물리핀/가상핀0/PLL1/56M9K. 추가 배치 예산 setup+0.076ns, 기존155 명목 SDC 기준 setup+0.207ns/hold+0.138ns. 조건부 PSRAM 여유+3.026ns, SNES199.984ns<270ns. 기능 RTL은 test05와 정확히 동일하고 배치 지침만 바뀌었으므로 동일 시험을 반복하지 않았다.56/56M9K는 임시 이력을 포함하며 추가 여유가 아니다. PCB2ns 가정, reset release 입력의 음수 recovery, 전체 외부IO·MTBF 미완료 한계는 유지한다.

ARM188604바이트, NMI15stores/0calls와 transport 호출 확인. 호스트 회수13사례/포맷256마스크 통과.159 frozen 입력과 비교해 지정된 예측·신호 연결·배치 지침·식별 변경 외의 차이가 없음을 확인했다. 실기 ARM 실행·게임 성공이나 게이트 등가성 검증으로 확대하지 않는다. 패키지는 이전의 지정 ROM·044 복원 파일을 보존하고 새 MCU·FPGA만 교체했다.

조사 시도도 보존한다. `test01`은 시험대에 존재하지 않는 PPU 신호명을 참조해 elaboration 실패, `test02`는 기존159로 오류 재현, `test03`은 수정된 단일 경계 통과다. `test04`는 확대 사례가 통과했지만 초기 PPUDATA 파이프라인에 미정 값이 있어 최종 근거에서 제외했고, 이를 제거하고 거부 검사를 넣은 `test05`를 선택했다. 최초 materializer Python 구문 오류는 빌드 전에 수정됐다. 새 라이선스 문제는 없었으며 기존 FLOAT를 사용했다.

## 다음 실기와 작업 의미

[160 안내](../docs/nes-game160-instructions.ko.md)에 따라 월드맵에서 첫 레벨로 이동한 뒤 A로 진입하고, 레벨 내부가 나오면 이동·점프를 확인한다. 두160 TXT·메뉴 복귀 결과, 플레이가 되면 짧은 영상을 받는다. 이번 오류는 시간제한이 아니므로 상한만 늘리지 않았다.044/GBC 복원·159 재시험·A/B 화면은 반복하지 않는다.

이번은 **화면 전환 때 실제 PPU가 사용할 주소를 메모리 경로에 제때 공급하는 이식 결선 수정**이다. 진단 체계나 매퍼 종류를 늘리는 작업이 아니다. 첫 레벨 플레이·전체 입력·스크롤·속도·오디오·저장은 아직 미완료다. 새 실기도 실패하면 처음 오류와16클록을 이번 재개 모델과 비교해 원시 재개 신호·주소의 일치 여부부터 확인한다. 진행되면 실제 이동·점프·스크롤을 우선하고 이후 임시 이력 축소 및 음원 차단 해제로 간다.
