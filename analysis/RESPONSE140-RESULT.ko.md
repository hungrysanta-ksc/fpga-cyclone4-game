# NES140 — 핀 해제 시점에 읽기 완료 응답 통지

139 실기는 오류1, CPU/pending 주소0xE184,age3,유효 샘플123028에서 멈췄다.140은 **읽기를 마친 뒤 응답을 알리기까지 한 메모리 클록 더 기다리던 부분을 줄인 실기 수정 후보**다. 실기에서 정상 화면이 나오는지는 아직 확인하지 않았다. [실행 안내](../docs/nes-response140-instructions.ko.md)를 따른다.

## 재현 근거

- 같은139 실제 코어·진단 ROM을 사용한 무지연 모델에서도 샘플123028/0xE184 경계를 찾았다. PPU201FF2 요청이 CPU 주소 변경 직전에 시작되고, 완료된 에지에 CPU0xE184 요청이 이어졌다. CPU가 소비하는 에지에 응답이 간신히 도착했다. 이때age4이며 실기age3과 한 클록 차이다.
-139 배치 보고서의 요청/ACK 첫 동기화 단계 전달 지연과 클록 skew를 조사했다. 이 값만으로 특정 보드 지연을 확정할 수 없으므로 요청5ns/ACK8ns라는 명시적인 시험 여유를 적용했다. 지연 없는 모델이나 보고서에서 계산한 한 조건만으로는 실패하지 않았다.
- 지연 모델의 기존 회로는 **실기와 동일한 샘플123028 및64비트 최초 상태440181c30800e184**로 실패했다. 같은 조건에서140 응답 위치를 적용하면 이 경계를 통과하고198527샘플,67.161ms까지 오류 없이 진행했다.
- 집중 경계의12개 메모리 위상에서 기존 회로는10개 실패, 새 회로는0개 실패였다. 실제 코어 모델은 한 위상이며 SDF·아날로그 metastability·실측 보드의 재현이 아니다. 물리적인 최초 원인 전체가 확정됐다고 주장하지 않는다.

## 구현 변경

`nes_rom_physical`은 ACTIVE 마지막 에지에서 데이터를 잡고, 다음 HOLD 에지에서 CE/OE를 해제한다. 기존에는 그다음 RELEASE 에지에서 RUN ACK를 발행했다.140은 **HOLD의 핀 해제 에지에서 RUN ACK를 발행**한다. RELEASE/IDLE,READ16/168MHz,95.232ns 읽기 창,post-sample HOLD,주소/데이터 레지스터와 기존2단 동기화기는 유지한다. CHECK 모드의 응답은 기존 RELEASE 에지에 유지한다. 새 요청을 받는 source의2단 동기화 경로도 우회하지 않는다.

기존/수정 reader의 기능 차이는 이 ACK 위치 하나다. ROM 서비스·CPU·PPU·mapper·SNES 소비자와 fixture는 그대로다. 후보 혼동 방지를 위해 loader5C/observerD7,`NES SCREEN 140.nh1`로 구분한다. MCU는139의 오류 수집·조기 복귀·보호/저장 로직을 유지하며 식별자와 파일명만 바꾼다.

## 확인과 한계

- 실제140 reader에서16위상,8400개 완료 읽기·208취소,주소/데이터 안정 구간·핀 SETUP/HOLD·클록 정지/리셋을 확인했다.110ns 메모리와 HOLD 제거 반례는 거부했다. CHECK 소유권 전체 적재 검증은 바뀌지 않은 기존 계약을 재사용했다.
- 지연 모델의 수정 코어가 출력한 한 프레임61440픽셀은 무지연139 모델과 파일 내용이 완전히 같다. 이것은 SNES 실제 표시 성공이나 다중 프레임·모든 위상 승인이 아니다. 전체 영상/소비자 근거는137을 재사용했다.
- MCU/FatFs20사례와 실제 TXT 재읽기,ARM 보호 루틴·호출·생산 소스 일치를 확인했다. 마지막 ROM 오류와 STOP 오류는 별도 기록하며 RUN 중 SD 쓰기는 금지한다.
- fit01은13640LE/932LAB/5184레지스터/50M9K/PLL1,실핀122/가상0이다. 같은 클록 setup+0.199ns/hold+0.179ns다.363 held-data쌍과17체인의 현재 배치를 확인했다. raw setup·MTBF·외부 타이밍 전체 승인은 아니다.
- PSRAM 읽기 여유는PCB 왕복2ns 및 setup/불확실성2ns를 가정하면 **+0.430ns**다.139의+2.478ns보다 줄었고 실측 보증이 아니다. 읽기 활성 시간을 줄여 확보한 응답 개선이 아님을 구분한다. 실제 화면·메뉴·복원 결과를 받아야 한다.
-140 배치의 첫 단계 유효 전달 지연(data delay−clock skew) 최댓값은 요청3.896ns/ACK4.385ns이며5/8ns 시험 범위 안이다. 이 비교는 단순 지연 모델의 범위 확인이며 MTBF나 모든 클록 위상의 증명이 아니다.

테스트 모델은 조건부 EARLY_ACK를 접으면 생산 reader와 주석/공백을 제외한 내용이 같음을 확인했다. 실제 코어 모델은139 식별자를 사용했고140의 식별 상수만 별도다. 성공을 만들기 위해 ROM 데이터를 강제로 바꾸거나 deadline 검사를 제거하지 않았다. 최초 단위 테스트의SystemVerilog 예약어 이름 충돌은 별도 실패 기록으로 남겼다. 앞선 ACTIVE 에지 ACK 실험은 채택하지 않았으며, 선택본은 HOLD 에지 ACK다.

## 다음 작업

140 실기의 두 TXT와 화면/메뉴/044 복원 결과를 받는다. 정상 RUN이어도 화면은 사용자 관찰로 판정한다. 같은 실패면 최초 상태와 샘플 수를139와 비교해 남은 경계를 좁힌다. 결과 없이 같은 배치·전체 적재·부품/저장 시험을 반복하지 않는다. 정상 화면을 확보한 뒤 패드·SMB3(J) mapper4/384KiB·오디오로 진행한다. 기존 동결 자료와 E1/E2·8µs/양클록 정지CE9µs·124격리·source-lock4는 유지한다.
