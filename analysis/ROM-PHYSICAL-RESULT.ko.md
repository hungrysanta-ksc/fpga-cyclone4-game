# NES052 PSRAM 읽기·클록 경계 연결 결과

NES 코어와 독립된 빠른 메모리 클록 사이에 요청·응답 전달 회로를 넣고, **읽기 전용 PSRAM 핀 제어기**까지 연결했다. 실제 보드에 올리기 전 RTL 검증 단계다.

- 실제 NES 코어 2종 ROM·8프레임 통과. 491520픽셀·16064패킷 바이트·전체 진행 기록이051과 일치했다.
- 16가지 시작 위상에서 최종 단위 검사 203392개 통과. 8400건 읽기 완료와208건 리셋 취소를 확인했다. 완료한 읽기의 왕복 지연은 NES 클록4주기였다.
- 칩·바이트 선택, 읽기 펄스3메모리 클록, 해제 구간, 주소 유지, 새 요청과 이전 응답의 동시 처리, 읽기 중 리셋, 메모리 클록 정지 후 복귀를 검사했다.
- 25ns 접근을 가정한 핀 모델에서는 통과하고, 60ns 모델에서는 데이터 검사가 실패했다. 실제 PSRAM 부품 사양을 확인한 결과는 아니다.

최종 공동 배치는 **13547LE /925LAB /26M9K**, LAB 여유38개다.051보다 논리는 늘었지만 배치 방식에 따라 LAB 사용은 줄었다. 아직 실제 핀·PLL·로더·SNES 소비자까지 합친 결과는 아니다.

처음에는 Quartus가 동기화 속성을 인식하지 않아 지정 방식을 보완했고, 카운터 상수 폭도 명시했다. 전체 NES 실행은 보완 전 소스이며, 두 소스가 이 표기 변경만 다른지 검증했다. 최종 소스로는 강화한 전체 단위 검사와 합성·배치를 완료했다. 최초 기록도 보존했다.

다음은044 보드 경계에 실제 클록·리셋·메모리 소유권과 진단 ROM 로더를 붙이고, SNES 패킷 소비자 및 오류 복구를 함께 연결하는 작업이다. 실제 부품 접근 시간과 클록 경계의 배선 지연을 검증한 뒤 새 실기 패키지를 만든다. **현재 새 SD 이미지는 없으며044·GBC는 유지했다.**
