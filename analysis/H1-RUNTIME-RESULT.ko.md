# H1 038: 화면1 뒤 자동 메뉴 복귀 원인 기록

사용자가037 실행 후 LINK SCREEN1을 보고 조작 없이 파일 선택 메뉴로 돌아온다고 확인했다.
037 H1 실기 결과는 **실행됨, 순환 실패, 원인 미분류**다. 이전 H0 육안 통과와 구분한다.
제공 경로 IMG_3630.MOV의 실제 해시는 이전 H0 파일과 같아 새 H1 영상 증거로 사용하지 않았다.

[038 시험 안내](../docs/nes-h1-runtime-test.ko.md), 패키지 (로컬 비공개 자료: `local-h1-runtime-038/NES-H1-RUNTIME-038.zip`).
이번 변경은 원인 식별용이다. 화면 순환 문제가 고쳐졌다고 주장하지 않는다.
035 MCU는 RESET 입력 감지 또는 SPI F2가03 이외일 때 모두 STOP/기본 메뉴 복귀를 수행했다.
038은 그 동작을 유지하고 종료 사유와 응답·시간·세대를 기록한다.

- 전체 ARM 빌드:168820바이트, 컴파일 경고0. 원본035와 별도 파생 빌드다.
- 생산 C 호스트15조건: RESET/F2 종료 구분,기존11조건,로그 open/write/short-write/close 실패의 복구 유지.
- 실제 Questa:038 C 파형224읽기/유효88비트/942행 통과. 파형은036 실행 기록과 바이트까지 같다.
- 파일시스템8조건:실제035/038 MCU 및036 FPGA로 교체/복원/중단/손상·변경 거부 시험.
- 브라우저 실제 scan_dir 호스트 시험은035와 C44 각8조건.035는 .nh1 표시,C44는 미표시.

기록은 로컬 FIL 핸들로 /sd2snes/nes-h1-last-038.txt에 쓴다.
STOP→GPIO/SPI 복원→base FPGA 설정/token 검증 뒤, RESET 유지·USB IRQ 차단 상태에서만 기록한다.
경과시간은100Hz getticks 차이이며 설정 시작을 포함한다. 기록 실패는 메뉴 복구를 막지 않는다.
기본 FPGA 복원 전 panic이면 새 기록이 없을 수 있다. 성공 기록의 base_restored=1은
그 실행에서 base token 검증까지 끝났다는 뜻이다. 게임·세이브는 쓰지 않는다.

F2_STATUS/07은 통합 오류 bit를 의미하며 bus/frontend/producer의 하위 원인은 아직 분리하지 않는다.
RESET_ASSERTED는 실제 읽은 RESET 신호이고 사용자 버튼 조작으로 단정하지 않는다.
하위 원인 구분 또는 파형 계측은 새 기록 결과에 따라 진행한다. 오류 판정을 완화하거나 무시하지 않았다.

FPGA036·ROM034·SPI 루프·기존 GBC 구현은 불변이다. 재배치/STA/Mesen은 새로 수행하지 않았다.
038 installer는 기존037의 MCU035를 확인하고 한 파일만 교체한다. STM32 메뉴 요구 파일은
실제 config의 m3nu.bin으로 검사한다(037 도구는 menu.bin 존재를 검사했음; 화면1 종료 원인으로 판정하지 않음).
처음 SPI 실행기 생성은 중복 UTF-8 BOM으로 PowerShell에서 실패했고 서버 시작 전 수정했다.
실패 실행기와 최종 원시 로그를 보존했다.

다음: 기존 .nh1을 한 번 실행→자동 복귀→새 텍스트 로그 회수. 실기038 성공/원인 해결은 아직 아니다.
