# NES 059 — SPI 전체 읽기 검증과 실행 허용

후보 **NES-SPI-READBACK-059**, 2026-10-07.058의 공유 CHECK reader에 단일 SPI 요청·완료 보존·순서별 ACK를 연결하고, 모든 바이트를 확인하기 전 START를 거부한다. MCU가 승인 원본 callback과 반환 바이트를 비교한다. [프로토콜 계약](../docs/nes-spi-readback-contract.md) · [기계 판독 근거](spi-readback-verification.json).

## 실패와 모델 경계

초기 파형 시험은32비트 범위를 넘는 watchdog literal에서 컴파일 실패했다. real literal로 고쳤다. 첫 live는 host/queue reset 중 불필요한 동작을 줄이기 위해 적재 도중 수동 종료했다. 다음 컴파일의 run_enable 선언 순서 오류를 수정하고 생성기에 순서 검사를 넣었다. 최종 시험은 oscillator 위상을 유지하면서 reset-held 클록만 마스킹한다. RUN 이후 클록·응답 마감·픽셀 비교는 유지한다. 이 클록 처리는 testbench에만 있다.

Make3.81 최초 dependency 실패와 재시도 성공,초기146검사와 최종149검사,모든 실행 소스/원시 로그를 별도 로컬 archive에 보존했다. 생산 RTL은 unit/wave/live/fit에서 같은 해시다. 과거044–058 근거와 GBC152/기존NES334 공개 소스는 바꾸지 않았다.

## 다음 단계

SD 승인 입력 callback을59 프로토콜 검증에 연결하고 실제 load→verify→STOP/복구 흐름을 검사한다. 예상 추가 검증 시간80KiB 약68.3초/96KiB 약82.0초에 맞춰 진행·취소·실패 이유를 설계한다. 현재056 호출 경로는54이므로 새 함수가 자동 적용된다고 간주하면 안 된다.

실기 진입은 먼저 CPU/PPU를 실행하지 않는 **SD→SPI→PSRAM load/verify→STOP/메뉴 복구 진단**으로 좁힌다. 자체 작성 모듈과044 기반으로 해당 진단의 실제 핀·클록·타이밍·복구를 검증한 새 MCU/FPGA 쌍을 준비한다. 이 제한된 진단은 NES 전체 소비자나 일반 게임 정확도 완료를 기다릴 필요가 없지만, 그 결과를 전체 NES 구동 성공으로 부르지 않는다.

전체 코어 경로는 별도로 보드의 클록·핀·소비자 자원/CDC/STA를 닫는다.4LAB 여유 때문에 비용을 측정하기 전에 기능을 계속 누적하지 않는다.044 복구 기준선을 유지하며 현재059에는 새 SD 이미지가 없다.
