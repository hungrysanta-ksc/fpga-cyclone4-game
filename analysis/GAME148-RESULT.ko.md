# NES148 실제 마리오 초기 실행의 PPU 읽기 지연 수정

147에서 실패한 실제 SMB3(J)의 24·26프레임 PPU 읽기 지점을 지나 **30프레임 RTL 실행을 통과**했다. 실기 게임 패키지는 아직 아니다. 이번 변경과 결과는 게임 작업용 PR91에 이어서 기록하며, 머지된 PR90의146 결과는 변경하지 않는다.

## 수정 내용

147의 미리 읽기는 현재 CHR 물리 주소의 상위 비트와 현재 ROM 데이터만 이용했다. 따라서 직전 접근이 네임테이블 내부 RAM이고 다음 접근이 CHR일 때 예측이 유효하지 않았다.

148은 PPU의 다음 배경 패턴 주소 상위 비트와 현재 PPU 버스 데이터를 조합하고, 기존 MMC3 뱅크 레지스터로 물리 주소를 계산한다. 이 별도 조회는 기존 맵퍼 주소·읽기·IRQ 입력을 움직이지 않는다. 배경 패턴으로 넘어가는 `$2007` 중첩 구간에 한정하며 실제 요청·전체 물리 태그·읽기 마감 검사는 그대로다. 예측이 빗나가도 잘못된 주소의 바이트를 실제 요청의 응답으로 인정하지 않는다.

변경은 PPU·NES/probe 연결·맵퍼 조회·시험 연결의5개 생성 소스다. CPU·외부 메모리 서비스/READ16·적재/CHECK/SPI는147과 같은 소스이며, 코어 클록을 느리게 하거나 오류 검사를 해제하지 않았다.

## 확인한 결과와 한계

선택 core03은 실제 목표 ROM을 메모리에 미리 채운 상태에서70ns PSRAM 모형으로 실행했다. 30프레임, CPU ROM 샘플1,425,678회·PPU384,638회·맵퍼 쓰기 관측468회, 오류0으로 끝났다. 기존147의1·2·10·20번째 출력과 각각61,440픽셀이 바이트 단위로 같았다. 이 비교는 초기 출력 보존 근거이며 독립 에뮬레이터의 정확성 판정은 아니다.

시뮬레이션 시간은 약0.498초다. PC에서 계산한11분을 게임 속도나 실기 로딩 시간으로 해석하지 않는다. 초기 미정 값 변환 경고40개는 그대로 남겼다. 첫 core01의 wire 선언 순서 컴파일 실패와 core02의 생성기 문자열 일치 실패도 보존했다. 최종 생성 소스26개는 사전 생성 결과와 같은 해시다.

새 MCU 적재, 실기 SNES 게임 화면·패드·오디오, 새 배치/타이밍, 실제 플레이는 아직 확인하지 않았다. 미리 읽기는 일반적인 모든 PPU 접근·모든 게임의 해결책이라고 주장하지 않는다. 기존147의 경계 시험과146의 실기 근거를 재사용하며 변경 없는 전체 적재·A/B·복원을 반복하지 않았다.

## 다음 작업

다음 산출물은 실제 ROM을 실행할 최소 MCU 적재·검증과 게임 화면·입력 경로다. 기존 바이트별 적재·대조를384KiB로 단순 확장하면 약41.5분이라는 추정이 나오므로 먼저 전송 경로를 줄인다. 동시에 고정 팔레트·배경 전용 진단 출력을 게임의 스프라이트·스크롤·CHR 전환에 맞게 연결한다.

변경된 경계와 필요한 자원·타이밍만 확인한 뒤 실기 ROM 패키지를 제공한다. 마리오 이동·스크롤로 다음 문제를 판단한다. 추가 진단 체계 완성이나 같은30프레임 재실행을 선행 조건으로 삼지 않는다. [모든 코어에 적용할 공통 원칙](../docs/development/MILESTONE-WORKFLOW.ko.md)을 따른다.

## 재현

기존 FLOAT wrapper의 자식 작업에서 `nes_game147.py` 대신 `nes_game148.py`를 사용하고 나머지 인수는 유지한다. `--frames 30 --prefetch`가 선택된 실행이다. 새 ASCII 출력 디렉터리와 정확한 사용자 ROM을 사용한다. [147 재현 안내](../docs/nes-game147-reproduction.ko.md)의147 실패 결과는 과거 기준으로 보존한다.

`tools/verify_nes_game148.py --baseline <probes>`는 완료 증거·소스 해시와 기존 읽기 경로 보존을 확인한다. ROM·원시 프레임·개인 경로는 공개 저장소에 포함하지 않는다. [결과 메타데이터](game148-verification.json)
