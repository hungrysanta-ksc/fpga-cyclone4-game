# NES154 실기 — 배경 타일 읽기 기한 오류, PPU 상태·메뉴 복귀 성공

**154의 추가 PPU 상태 수집과 오류 후 복귀는 실기 통과했다. 게임 진행은 실패했다.** 사용자 관찰은 첫 Start에서 선택 화면, 두 번째 Start에서 다음 장면으로 넘어가는 순간 정지 후 자동 메뉴 복귀다. 두 단계 입력을 중복 입력 문제로 분류하지 않는다. 실제 스테이지 조작과 다른 버튼 동작은 아직 확인하지 못했다.

## 확인한 결과

- 기대/실제 보드63, 관측부DD로154 조합이 실행됐다.
- ROM393216바이트 적재·전체 읽기 비교와 검증을 통과했다.
- 최초 ROM 오류는2(PPU 샘플 기한), `run_passed=0`이다. `run_error=1`은 MCU의 실행 오류 분류이며 CPU ROM 오류1과 혼동하지 않는다.
- `stop_ok=1`, `run_stop_error=0`, `base_restored=1`, `safe_to_reload=1`. 샘플 카운터26849988이 STOP 뒤 유지됐다. 최종 메뉴 준비 로그와 사용자의 실제 메뉴 복귀 관찰이 일치한다.
- 512바이트 진행 기록104개,seq0~103이 연속이며 경과 시간이 역전되지 않았다. 최종 TXT742바이트에 새 `ppu_state_valid=1`과 상태64비트가 저장됐다.

## 새로 좁혀진 실패 구간

주소 문맥은 `e200c2f4:20217a10`으로 **153과 완전히 같다**. 실제 요구 주소와 처리 중 주소가 모두`0x217A10`,busy/pending_ppu=1,age=1이다. 값을 소비하는 순간에 ppu_valid/rom_response/rom_ready는0이었다. 필요한 데이터를 기한 내 공급하지 못했다는 의미이며, 반환된 바이트가 손상됐다는 판정은 아니다.

새 PPU 원시 상태는 `60818800:28404040`이다.

| 항목 | 실제 관측 | 코드와 대조한 의미 |
|---|---:|---|
| scanline / dot | 193 / 6 | 화면 내부의 배경 패턴 읽기 구간 |
| 렌더링 / 스프라이트 구간 | 1 / 0 | 스프라이트 읽기 구간이 아님 |
| 배경 패턴 테이블 | 0 | 선택된 배경 패턴 테이블 |
| VRAM 논리 주소 | `0x0A10` | MMC3 매핑 전 PPU 주소 |
| 주소 래치 / 버스 핀 | `0x10` / `0x10` | 캡처된 값. 핀 값 자체가 올바른 ROM 응답이라는 뜻은 아님 |
| `$2007` 읽기 / 쓰기 파이프 | 0 / 0 | 오류 순간에는 해당 지연 동작이 남아 있지 않음 |
| ALE / address_valid | 0 / 0 | dot6 읽기 단계의 정상적인 주소 래치 비활성 상태와 맞음 |
| 특별 선행 읽기 힌트 | 0 | 현재 힌트는 `$2007` 겹침 조건에 한정되어 있으므로 이 순간0은 예상되는 값 |

판독 근거는 동결154의 `rtl/ppu.sv`에서 dot의 홀짝으로 ALE/읽기를 나누는 부분, `vram_a` 배경 패턴 주소 선택,64비트 관측 연결, `nes_rom_service.sv`의 유효값·오류2·age 로직이다. `ALE=0`, `address_valid=0`, `hint=0`을 그 자체로 결함으로 분류하지 않는다.

이제 다음 재현의 우선 대상은 **일반 배경 타일 읽기에서 주소가 유효해지는 시점→공유 ROM 요청 승인→응답→dot6 샘플**이다. 이전 `$2007` 겹침 전용 선행 읽기만 확대하면 해결된다고 가정하지 않는다. 단, 파이프0은 그 순간의 관측이므로 더 앞선 `$2007` 동작의 영향까지 배제하지는 않는다.

현재 가설은 요청 선행 시간 부족, 직전 CPU/PPU 요청 점유, 샘플 직전 논리/매퍼 주소 변경, 백엔드 응답 지연이다. 직전 이력이 없으므로 어느 하나를 확정할 수 없다. 두 판에서 같은 문맥이 반복된 것은 특정 게임 경로의 재현 가능한 조건을 의심할 근거지만 PSRAM 정상/고장을 증명하지 않는다.

## 시간과 판정 한계

펌웨어 기록상 DISPLAY_NEXT232.670초→DISPLAY_STOPPED242.030초는9.360초, 이후 메뉴 준비245.210초까지3.180초다. 첫 게임 화면과 실제 오류 발생 시각을 직접 측정한 수치는 아니다. `screen_frames=17`, `screen_stage=6`, `screen_telemetry_trusted=0`을 FPS나 게임 진행 성공으로 해석하지 않는다. 이번 영상은 없으며 장면 전환과 메뉴 복귀는 사용자 관찰로 기록한다.

## 다음 작업

154 관측 목표는 달성했으므로 같은154·044/GBC·A/B 시험을 다시 요구하지 않는다. line193/dot5→6 배경 읽기를 기준으로 실제 PPU 주소 생성과 서비스 중재를 짧게 재현하고 직전 요청 점유·MMC3 주소 변경·응답 위상을 각각 대조한다. 인위적 지연 모델은 가설 검증이며 실기 원인 확정으로 승격하지 않는다. 첫 어긋난 경계를 수정하고 최소 변경 검증 후 같은 SMB3로 돌아간다. 초기110/240프레임을 근거 없이 처음부터 반복하거나 오류 검사를 없애지 않는다.

이 PR96 업데이트는 결과와 인계만 변경한다.154 펌웨어·FPGA·ZIP·동결 증거·공개 도구 해시는 유지한다. 새 구현은 후속 작업이며 정상 플레이·표시 속도·입력 공백·오디오·저장은 미완료다.

원본 TXT는 비공개 증거로 보존했다. 파일 크기·SHA-256·전체 진행 기록·해석은 [검증 메타데이터](game154-hardware-verification.json)에 있다.
