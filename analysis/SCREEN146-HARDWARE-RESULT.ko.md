# NES146 실기 결과와 게임 전환

146은 80KiB 적재·전량 대조, 유한 RUN·STOP, 로그 저장 및 실제 메뉴 복귀에 성공했다. 영상에서 읽을 수 있는 NES144 A/B 화면이 출력되며 145의 반복되는 긴 검정 구간은 확인되지 않았다. 동일 ROM을 재사용하므로 화면의144 표식은 정상이다.

두 로그에서 loaded/compared=81920, verified=1, run_passed=1, run_error/rom_error/first_error/stop_error=0, stop_ok/base_restored=1이다. 진행47기록의 LOAD207.670초, CHECK311.320초, 표시 구간63.380초, MENU_PREPARED587.800초이며 영상 약66초에 실제 메뉴를 확인했다. firmware elapsed와 영상 촬영 시작 시점은 서로 다르다.

빠른 구간의 A/B 혼합은 맨눈에서도 보였다는 사용자 관찰을 보존한다. 그러나 빠른 교대와 CRT의 주사·잔상·시각적 적분을 분리하지 않은 관찰만으로 VRAM/전송 오류라고 단정했던 판정은 철회한다. 반대로 전체 프레임의 정확성이 증명된 것도 아니다. **연속 화면 정합성은 판정 보류**다. screen_stage=112/frames=117/mask=0은 telemetry_trusted=0인 값이며 실제FPS나 성공 근거로 쓰지 않는다.

사용자는 추가 A/B 시험을 생략하고 Super Mario Bros. 3 (J)의 실제 이동·스크롤·프레임 끊김을 확인하도록 지시했다. 이 지시를 다음 작업의 우선순위로 삼는다. 같은146·044 복원 시험을 다시 요구하지 않는다. 실제 게임 화면 경로를 구현할 때 필요한 변경 검증은 계속한다.

첫 목표 ROM은 mapper4, PRG256KiB+CHR128KiB, SHA256 `dbb1cb5e18b091ca9101b1c2f5a5d6bdbeaa4a30ae1a504251310f6765cabb49`다. 현재80KiB 진단 적재와 고정 팔레트·스크롤·배경 전용 NCR1을 그대로 게임 지원으로 간주하지 않는다. 384KiB 적재/대조, 물리 뱅크 주소·캐시 태그, 스프라이트·스크롤·CHR 전환, 실제 입력의 연결이 필요하다. 오디오는 별도 미완료다.

원본 로그·영상은 비공개 보존하며 공개 JSON에는 파일명·크기·해시와 판정을 기록한다. 기존146 빌드 증거·패키지·public pin은 변경하지 않았다.
