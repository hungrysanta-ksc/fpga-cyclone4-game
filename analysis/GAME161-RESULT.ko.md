# NES161 — 사용 중인 그래픽 바이트 보존과 표시 대기 단축

**160의 응답 직후 데이터 소실을 기존 service에서 재현했고,수정판은 현재 필요한 바이트를 유지했다. 화면 유지 시간도30에서6 vblank로 줄인 실기판을 준비했다. 첫 레벨 플레이·실기 표시 개선은 확인 대기다.** PR102 머지3100e5c78286ff93ea68168ff587512adb58b1b6 기준이다.

## 수정 근거와 범위

[160 실기](GAME160-HARDWARE-RESULT.ko.md)는 line193/dot6에서205FF0을 샘플하기 직전에 실패했다. 현재 데이터는217FF8 응답 전까지 유효했지만 응답 직후 무효해졌고,같은 응답 클록에217FF8을 다시 요청했다.60초 제한이나 마지막A 입력 누락은 아니었다.

기존 service의 두 PPU 캐시는 응답마다 FIFO처럼 회전한다. 현재205FF0이 이전 슬롯에 있고 첫 슬롯에 다른 바이트가 있는 경우,미래217FF8의 응답이205FF0을 버린다. 새161은 **이전 슬롯이 실제 현재 CHR주소에 맞으면 그 슬롯을 유지**하고 새 응답을 첫 슬롯에 넣는다. 현재 요구가 첫 슬롯에 있으면 종전처럼 이전 슬롯으로 옮겨 보존한다. 태그·데이터 의미나 샘플 기한을 바꾸거나 추가 RAM을 쓰지 않는다.

또한 처리 중인PPU 주소와 같은 힌트는 다시 요청하지 않는다. 기존pending 검사와 실제 수요 우선순위는 유지하며,다른 힌트는 응답과 같은 클록에도 요청할 수 있다. 실제 PPU/매퍼/IRQ/물리reader/클록,159 raw읽기 조건과160 재개예측은 그대로다. 내부 캐시 태그를160에서 관측한 것은 아니므로 실제 원인의 완전한 확정은 실기 결과로 판단한다.

## 화면과 입력

152 표시 프로그램에서 **화면 유지 카운터만30→6**으로 바꾸고161 제목·체크섬을 갱신했다. 기존 매vblank 패드 수집·전체57344바이트 DMA·강제 소거·프레임 반환 순서는 유지했다. 의도적 유지 구간은60Hz 기준 약0.5→0.1초지만 전송·캡처·대기가 추가되므로10fps나60fps를 의미하지 않는다.

대기 전체 삭제는 피했다. 이전보다 자주 화면이 갱신되는 대신 전체 전송의 소거가 더 자주 보일 수 있다. 실제 CRT의 점멸·조작 체감은 이번 영상으로 확인한다. DMA/프레임 대기의 입력 공백도 남아 있고,연속 표시와 완전한 입력 독립화는 미완료다. 이미152에서 수행한 패드 갱신 개선을 새 성과로 중복 계산하지 않는다.

## 검증 결과

- `cache01`: 실제 service에 정상 요청/응답으로 두 슬롯을 채우고 관측된205FF0→미래217FF8 순서를 실행했다. 내부 캐시 강제 설정 없이 기존160은 데이터 소실·중복 요청·오류2를 재현했고,161은15검사 통과. 현재 바이트 보존,8회 반복 선행 응답,다른 힌트의 같은클록 허용,실제 수요 우선,샘플클록 응답우회,reset 무효화,PPU/CPU 기한 및 비정상 응답 오류 유지 포함. 백엔드 응답 시각은 모델이 공급하며 전체게임 재생은 아니다.
- `regression01`: 새service와 실제PPU/READ16/70ns모델에서160의12재개 사례·12예측차단 대조,159의39정상 사례·39대조(18오류)를 그대로 통과. 초기값·위상을 설정한 경계 시험이라는 기존 한계 유지.
- `client01`: 실제SNES CPU/DMA/PPU 모델에서256×224 두 화면114688픽셀 RGB가 기대와 일치. 매유지프레임6회씩과표시전2회=14패드전달,각전달 프레임에 맞는 버튼 비트 확인. 모델은자동패드 레지스터를공급하며 실기버튼이나NES소비까지검증한것은아니다.
- `reuse01`: 지정된service두식·표시프로그램·식별 외160 입력 소스 모두 동일. MCU는161/6A/E4 식별·파일명만 변경. ARM188604바이트,NMI15stores/0calls,호스트회수13사례/포맷256마스크 통과.

56/56M9K는 임시이력을 포함하며 추가여유가 아니다. PCB2ns 가정·비동기reset release 음수recovery·전체IO·MTBF 한계는 유지한다. 첫ARM검증은 샌드박스의 구형도구 DLL 로딩 WinError623으로 실패했으며 제품 문제가 아니다. 호스트 실행armcheck02 통과;기존FLOAT 시험도 정상 종료했다.
