# NES 055 — SPI로 적재한 ROM의 실제 코어 실행

2026-10-06 후보 **NES-R1-SPI-LIVE-055**. 054 SPI 적재와053 실제 코어 실행 사이의 연결을 검증했다. 제품 RTL 변경 없이 진단2종을 SPI로 전부 적재한 뒤 실행했다.

053 대비 release tick 및 모든 S/E/F/D 시각 차이는 `banks32: [8, 8, 8, 8]`, `fine_x: [1, 1, 1, 1]`이다. 프레임마다 같을 뿐 아니라 모든 이벤트에도 같은 상수 차이를 요구했다. 적재 중에도 코어 분주 클록은 계속 돌기 때문에 RUN 해제 위상이 달라질 수 있다. 시각까지 바이트 단위로 같다고 표시하지 않는다.

핀 모델은 미초기화 상태에서 시작하고 실제 쓰기 펄스로만 채워졌다. 매 DATA 완료 count·16KiB마다 직렬 STATUS·전체 메모리 내용과 END/START 분리를 확인했다. CPU/PPU 읽기 값·마감,049 메모리 초기화,패킷 소비 검사를 유지했다. 기존 라이선스 경로에서 컴파일 오류0,명시적 PASS 및 Fatal/Error 부재를 확인했다. upstream의 기존 elaboration/time0 경고는 원시 로그에 남긴다.

첫 실행은98304바이트 적재 뒤 새 시험이 ready=1을 기대해 중단됐다. 로더는 전체 길이에 도달하면 추가 DATA를 막으므로 END 전 상태는ready=0/loaded=0이다. 시험의 마지막 STATUS 기대값만 수정하고 전체를 재실행했다. 제품 RTL 수정은 없으며 실패 로그·실행 소스와 최종 결과를 따로 보존했다. 비교기는 전체+7클록을 허용하되 개별 이벤트1클록 또는 픽셀1개 변조를 거부하는 대조 검사를 통과했다. 이 합성 자료 검사는 새 RTL 실행으로 계산하지 않는다.

## 해석과 다음 단계

이번 SPI 자극은 반주기60ns인 가속 디지털 시험이다. 실제 C callback의250kHz 파형과044 공유 SPI 검증은054 근거이며,055가 새 STM32 펌웨어 실행을 의미하지 않는다. PSRAM25ns 읽기 모델은 가정이고 전체 메모리 비교도 시험벤치 관측이다. 제품용 물리 readback 검사기는 아직 없다.

다음은 materialized044의 GPIO/SPI 소유권·USB IRQ 보호 안에서 실제 C 로더를 호출하고 SD/iNES 및 실패/복구 경로를 연결하는 일이다. 시험에서는 별도 `chr_32k` 입력을 SPI BEGIN 길이와 코어 CHR 마스크에 함께 사용했다. 실제 보드는 승인된 ROM 형상을 한곳에 고정해 두 경로가 같은 값을 사용하게 해야 한다. 그다음 보드 클록·SNES 소비자와 마감/복구를 남은15LAB 안에 통합해야 한다. 실제 핀/PLL 공동 fit와 외부 IO/CDC/STA가 끝나기 전 새 실기 이미지를 만들지 않는다.

실기 기준044와 GBC는 그대로이며 새 SD 이미지·일반 NES 게임 실기 통과 주장은 없다. 재현은 [계약](../docs/nes-spi-live-contract.md), 해시는 [검증 요약](spi-live-verification.json), 다음 작업은 [인계](../cores/nes/HANDOFF.ko.md)를 따른다. 전체 코어 시험은 해시 고정 private053 export가 필요하다.
