# NES154 — SMB3 진입 오류 순간의 PPU 상태 회수

## 작업 목표

153에서 확인한 실제 SMB3(J) 진입 오류 `run_rom_error=2`의 조건을 좁힌다. 153은 오류 로그와 자동 메뉴 복귀에 성공했지만 게임 진행은 실패했다. 실제 요구 주소와 대기 주소는 모두 `0x217a10`, 대기 나이는1이었다. 이 정보만으로 선행 읽기 누락·주소 생성 시점·직전 요청 점유·응답 지연 중 원인을 확정할 수 없다.

154는 해당 순간의 PPU 상태64비트를 추가로 회수하는 실기 후보다. **게임 정지 원인을 고친 판이 아니며 정상 플레이 목표는 미완료다.**

## 작업 내용

- 첫 오류가 발생하는 바로 그 NES 클록 에지에서 기존 주소 문맥과 함께 PPU 상태를 보존한다. 화면 줄9비트, dot9비트, 배경 패턴 선택·스프라이트 구간·렌더링·ALE 각1비트, `$2007` 읽기/쓰기 파이프 각5비트, VRAM 주소14비트, 주소 래치8비트, 데이터 핀8비트, 선행 읽기 힌트·주소 유효성 각1비트다.
- 새 SPI 명령74/75로64비트를 나누어 읽는다. 처음 저장한 값은 이후 오류·코어 STOP으로 지워지지 않고 관측부 reset에서만 초기화한다. 기존 오류 원인/주소 문맥과 별도로 기록한다.
- MCU는 기존 STOP와 유지 상태 검사를 통과한 뒤 보조 상태를 읽는다. 잘못된 식별·유효성·오류 번호·버전이면 보조 값은 무효로 남기고 기존 로그·메뉴 복귀를 계속한다. 전송·클록 보호 검사는 유지한다. RUN 중 SD 쓰기는 추가하지 않는다.
- 새로운 펌웨어와 FPGA는63/DD 식별로 짝을 고정한다. 기존152/153의62/DC를 임의로 허용하지 않는다. `ppu_state_valid`, `ppu_state_hi`, `ppu_state_lo`가 최종 TXT에 추가된다.
- ROM 서비스, 캐시, 요청 우선순위, 샘플 기한, CPU/PPU 상태 결정, MMC3 매핑, 게임 프레임 전송·입력 경로는 변경하지 않는다. 새 관측 연결에 따른 배치와 타이밍은 다시 확인한다.

## 작업 결과

선택 결과와 원시 증거의 해시는 [검증 기록](game154-verification.json)에 남긴다.

공개 전 검사에서 빌드 검사·비트스트림 조립 도구 두 파일의 마지막 빈 줄을 정리했다. 실행 당시 바이트와 동결 증거는 보존하고 공개본의 형식 차이와 양쪽 해시를 별도로 기록했다. 실행 로직이나 펌웨어·FPGA·ZIP은 바뀌지 않았다.

| 확인 항목 | 결과와 한계 |
|---|---|
| 실제 관측부 RTL | 오류 에지·두 SPI 페이지·STOP 후 보존·최초 오류 유지·reset 초기화41건 통과 |
| 실제 C 보조 응답 해독 | 64개 비트×15개 오류 번호960건, 잘못된 응답/전송 실패10건 통과 |
| 실제 MCU/FatFS/메뉴 모델 | 384KiB 적재·비교와 합성 PPU 오류 후 STOP→기본 FPGA→TXT→메뉴 통과. 정상 보조 응답과 잘못된 ID 응답 각각 확인 |
| ARM | 187124바이트, 강한 NMI 경로 및 기존 전송 소스 검사 통과 |
| FPGA 배치 | 13678 LE,924 LAB,5054레지스터,52 M9K,1 PLL,실제122핀·가상0핀 |
| 관련 타이밍 | 같은 클록 setup +0.084ns/hold +0.173ns, SNES201.543ns<270ns, 조건부 PSRAM 여유 +3.257ns |
| 실기 | 154 실행 전. 원인 수정·스테이지 플레이·다른 버튼 동작 미확인 |

소프트웨어 모델은 SD·GPIO·SPI 전송·FPGA 응답을 모사하므로 실제 ARM/전기 동작 증거가 아니다. 조건부 타이밍 통과를 전체 외부 IO/MTBF 검증 완료로 바꾸지 않는다. 합성 PPU 상태와 실제153 로그 값을 혼동하지 않는다.

별도 원인 조사에서는 실제152 코어·매퍼·같은 게임과 입력 모듈을 연결하고 추상5 NES 클록 응답 모델을 사용했다. 프레임30~44/90~104에 Start를 넣었다. **110프레임 진행 기록까지 오류가 재현되지 않았으며, 실기 상태 수집으로 전환하기 위해 의도적으로 중단했다.** 목표240프레임 완료·원인 재현·게임 정상 동작 통과로 기록하지 않는다. ROM 조회 최적화용 DPI의393216바이트는 원본과 대조했다. 초기 선언 순서 오류와 설정 변경을 위한 중단 기록을 보존했다. 종료 시 EOF/라이선스 프로세스 종료 메시지는 의도적 중단의 결과이며 라이선스 부족이 아니다.

사용자 정정: 현재 `1 PLAYER GAME / 2 PLAYER GAME` 선택 화면에서는 **Start 한 번**으로 WORLD1 쪽으로 넘어간다. 초기 연출에서 선택 화면으로 가는 입력과 구분한다. 앞선 참조 에뮬레이터 화면만 보고 첫 입력이 무시됐다고 추정한 것은 철회한다. 시작부터 두 번 연타하도록 안내하지 않는다. 참조 에뮬레이터의 장면 진행은 실제 FPGA 동작 검증이 아니다.

## 작업 의미

이번 작업은 **이미 실행되는 실제 게임이 멈춘 조건을 실기에서 한 번 더 구분하기 위한 최소 관측 추가**다. 신규 코어 기능 완성이나 게임 정지 수정으로 계산하지 않는다. 목표는 로그에서 실제 실패 줄/dot·읽기 파이프·주소 래치 관계를 확보한 뒤 해당 경계만 수정하여 같은 SMB3에서 진행 여부를 확인하는 것이다.

다음 실기는 [설치·진행 안내](../docs/nes-game154-instructions.ko.md)에 따라 한 번 실행하고 두 TXT와 메뉴 복귀 여부를 받는다. 같은 증상이면 영상은 생략할 수 있다. 실제 플레이가 진행되면 방향키·A·B를 확인한다. 같은153·044/GBC 복원·A/B 패턴·변경 없는 초기30프레임을 반복하지 않는다. 기존 화면 유지30vblank, DMA 중 입력 공백, 무음·저장 미구현은 그대로다.
