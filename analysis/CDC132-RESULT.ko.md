# 132 현재 배치의 CDC·reset 경로 재검증

PR77 병합 `1d2257d0398348cdff66928f97899ce87c5f7c81`에서 시작했다. **131fit05의 같은 배치에서 데이터 전달371쌍과16개 동기화·reset 해제 체인을 검증했다.** CHR 설정·RUN/오류 경로 및 외부IO까지 모두 승인한 결과는 아니다.

## 작업 목표

131의 같은 클록 setup·hold 통과 이후 새 loader/reader 계층에 과거125/126의 CDC 결과를 잘못 상속하지 않고, 현재 회로의 실제 경로를 확인한다. 통과한 배치를 재사용해 불필요한 합성·배치·전체 쓰기 반복을 줄인다.

## 작업 내용

선택131fit05의 모든 입력 해시를 확인하고 별도 복사본에서 STA만 수행했다. 원본은 변경하지 않았다. 복사본에서는 `db/live.taw.rdb`와 `db/live.cycloneive_io_sim_cache.31um_ss_1200mv_85c_slow.hsd` 두 STA 캐시만 달라졌고 나머지 기존 배치·소스·QSF·SDC 입력은 모두 동일하다. 새MAP/FIT 또는 생산RTL 변경이 없다.

서로 다른 클록의 보고 경로는3,426행/677개 시작·끝 쌍이다. 데이터371쌍, 첫 단계 제어8쌍, CHR 용량 설정183쌍, RUN/오류 관련115쌍으로 분류했다. 이는 설정한 수집 한도 안에서 보고된 setup 경로 목록이며 모든 아날로그·조합 글리치의 완전한 증명이 아니다. 보고 한도 도달·알 수 없는 경로·없는/중복 레지스터는 오류로 중단한다.

데이터에만 정확한 시작·끝 레지스터별 제약을 적용했다. 데이터 자체 지연 예산4/40/40/10ns와 클록망을 포함하는 `set_max_delay` 5.952/45.454/45.454/11.904ns는 서로 다른 검사다. 두 단계 전달 후 캡처하고 캡처 뒤에도 값을 유지한다는 조건에서 도출했다. 클록 전체false path·clock group 예외는 없다. 현재 fitted reader 주소21쌍을 사용하며 과거22쌍 이름을 그대로 옮기지 않았다.

131의 실제 reader RTL을125의 해시가 확인된70ns RAM 모델·시험·보유 시간 감시기에 연결했다. 위상0/3.5ns에서 동작하며 READ16, memory168MHz/NES22MHz 모델이다. bridge RTL2개와125 프로토콜 결과는 해시가 같아 재사용했고 불필요하게 재실행하지 않았다. 이 시험은 고정RUN reader 전송·취소 범위이며 전체 loader의 CHR 변경·RUN 시작 경로 계약을 대신하지 않는다.

reset 해제 하류는6,492보고행이다. 음수107행/10끝점은 **모두 다른reset 해제 체인의 비동기 입력**이며 최솟값−4.601ns는memory_release→reader source_reset이다. 전체 중reset 체인 입력을 제외한6,168행은최소+0.498ns다. 따라서 음수값만 보고 기능 하류reset 회로를 무조건 수정하지 않는다. 반대로 체인 첫·둘째 단계의 비동기 입력이라는 이유만으로 pulse 폭·해제 순서·재수렴·metastability 조건을 검증한 것으로 처리하지도 않는다. 입력 체인324보고행은 별도 계약 검토 대상으로 남긴다.

미완료 항목은 다음과 같다.

- **CHR 설정183쌍**: loader `chr32`가 CPU/PPU 주소·reader·encoder로 전달된다. 적재 시작 때 변경되고RUN동안 유지된다는 상태 조건과 실제reset 해제 순서를 대조해야 한다. 일반 데이터371쌍 예산을 적용하지 않았다.
- **RUN/오류 제어115쌍**: `state.RUN`, `fault`, loader/diagnostic reset 해제, `check_failed`가 reader 요청·busy·주소 레지스터로 이어진다. 공통reset, source/memory local reset, 최초 요청, STOP/오류 취소 사이의 계약을 실제 상위 결선에서 확인해야 한다. 원시 조합RUN을 단순 동기화해 오류 취소를 늦추는 수정은 하지 않는다.
- **외부IO**: 입력83·출력227포트의 setup/hold 제약이 없고 가상 포트를 포함한다. PSRAM·SPI·SNES 외부 연결의 수치·소유권 계약은 별도다. 이 숫자는 실제 보드310핀이라는 뜻이 아니다.

131의14,078LE/954LAB/5,320regs/26M9K/PLL1와 같은 클록memory+0.041ns는 그대로다. 원시clock-pair−10.408ns를 숨기지 않았고 새 분류와 조건부 데이터 제약으로 구분했다. 새ARM/ASM/패키지/실기 시험 없음. 전체MTBF/E1E2/8µs/양클록정지CE9µs 반례 및 설치 승인은 미해결이다.

초기 준비 검사에서124 manifest가 공개 핀과 불일치해 해당 입력을 거부했다. 기대값은`60a57739bcc05057e36898864041fff8d2665b5ea92112042a6cd610f2f10015`, 관측값은`4e0d6d510c7adde847831b7a77f5ebac7bd197e27f4778f64c174bbe2a5339d3`다. 원인은 미확정이며 과거 보관본을 수정하지 않았다. 대신 독립적으로 해시가 일치하는125 프로토콜 보관본을 사용했다. 따라서124 전체 무결성을 이번에 재검증했다고 주장하지 않는다. 실패 로그·관측manifest도132에 보존했다. 최초 sandbox 하위PowerShell은 시험 실행 전 종료됐고 기존 임시FLOAT 경로를 허용된 호스트에서 실행했다. 실제 라이선스 오류나 승인 검토 거부는 없었다.

## 작업 의미

**실기 코어 동작을 위한 클록 간 전달·reset 결선 검증**이다. 131에서 내부 타이밍을 통과한 회로가 다른 클록으로 데이터를 전달하는 조건을 확인하고, 실제RUN으로 넘어가기 전에 남은298설정·제어 쌍의 검토 대상을 좁혔다. 게임/MMC3 기능 추가나 로그 기반 마련 작업은 아니다.

다음 작업: 131fit05와132 경로 목록을 재사용해 CHR 설정 안정 구간과 RUN/STOP/오류→core/reader reset 해제 계약을 실제 결선에서 검증한다. 비동기 reset 체인 입력107음수행은 기능 하류와 구분하고 pulse/release 조건을 확인한다. 이어 실제 외부IO·SNES 소비자·관측 가능한 최소 RUN+044 복원으로 진행한다. 변경 없는 MAP/FIT/전체쓰기/371쌍 재검증은 반복하지 않는다.

119의 전체80KiB 적재·검증·STOP·메뉴·044복원 실기 통과, 첫 게임SMB3(J)/mapper4/PRG256KiB+CHR128KiB, 제한 진단 준비도6완료/5부분/1미완료를 유지한다. 최소 안정성 확보 뒤에는 실제 실행 자료를 얻는 방향으로 진행한다.
