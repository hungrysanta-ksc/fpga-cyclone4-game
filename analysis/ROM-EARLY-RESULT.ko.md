# NES051 조기 ROM 읽기 결과

실제 CPU·PPU가 주소를 먼저 내보내는 구간에서 ROM 읽기를 시작하도록 개선했다. **050에서 실패했던2클록 응답뿐 아니라3·4클록 응답에서도 정상 실행을 확인했다.** 미래 데이터나 참조 화면을 미리 넣지 않았고, NES 속도를 늦추지 않았다.

- 2·3·4클록 조건 각각2종 ROM·8프레임 검증.각각491520픽셀·16064패킷 바이트·전체 진행 기록이050과 정확히 일치했다.
- 각 조건624788건 요청.050보다170건 늘어 증가량은 약0.027%다.
- 단위시험4168검사 통과.실제 읽기와 조기 읽기의 우선순위, 주소 변경 후 오래된 응답 거부, 캐시·RESET·기존6종 오류를 확인했다.
- 기존050의2클록 실패를 재현했고, 새 회로도8클록 응답에서는 실패한다.실패 직전16클록의 입력 기록과 오류를 보존했다.

합성·배치는 통과했지만 LAB 여유는 줄었다. 실제 보드 전체가 들어간 결과가 아니므로, 다음 메모리/클록 연결에서도 자원을 공동 측정해야 한다.

첫 실패 기록 수집에서는 Fatal이 먼저 실행되어 기록이 출력되지 않았다. 출력 순서만 보완해 실제 오류 결정 직전16클록을 확보했다. 당시 드라이버와 최초 실행을 보존했으며, 정상2클록 시험·최종3클록 시험·fit의 생산 회로는 같다. 일부 테스트 관찰 코드만 달라졌다.

4클록 탐색은 실패를 예상한 실행이었지만 첫 ROM이 통과했다. 그 예상 조건 때문에 중단된 원본 기록은 보존하고, 완료된 결과를 재검증한 뒤 같은 소스로 나머지 ROM을 실행했다. 시험 실행기의 종료 코드만으로 회로나 라이선스 오류라고 판단하지 않는다.5–7클록 조건은 아직 측정하지 않았다.

현재 메모리는 여전히 **동기식 시험 모델**이다.2·3·4클록 통과와8클록 실패는 이번 진단의 측정 결과이며, 실제 PSRAM의 접근 시간이나 클록 경계 안전성을 보증하지 않는다. 다음은 물리 메모리 제어기와 빠른 메모리 클록/CDC를 연결해 전체 지연을 맞추는 작업이다. 보드 오류 복구, 로더, SNES 소비자, 실제 핀·PLL·전체 STA를 거쳐 새 실기 패키지를 준비한다.

044 성공본·GBC·이전044–050증거를 유지했고 SD에는 쓰지 않았다. 지금 교체할 SD 이미지는 없다.
