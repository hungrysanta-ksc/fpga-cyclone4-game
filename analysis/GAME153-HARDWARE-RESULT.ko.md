# NES153 실기 — 오류 문맥 회수·메뉴 복귀 성공, PPU 읽기 기한 오류 지속

**153의 목표였던 새 PPU 오류 표식 수신·최종 TXT 저장·자동 메뉴 복귀가 실기에서 통과했다. 게임 실행은 PPU 읽기 기한 오류로 조기 중단됐으며, 정상 스테이지 플레이는 아직 확인되지 않았다.** 이번에는 결과만 기록하고 펌웨어·FPGA·기존 패키지는 변경하지 않는다.

## 확인된 실행 결과

사용자는 이전과 비슷한 스테이지 시작 지점에서 멈춘 듯 보였고 곧바로 메뉴로 복귀했다고 보고했다. 이번 실행에서 Start가 중복 입력되지 않은 것도 확인했다. 다른 버튼은 아직 미확인이다. 새 영상은 제공하지 않았으므로 정확한 게임 장면·버튼 시각을 독립 판독했다고 기록하지 않는다. 이전152 영상은 WORLD1 시작 안내였으며, 이번 관찰을 실제 스테이지 내부 플레이 성공으로 승격하지 않는다. 현재 로그 분석을 위해 같은 실행의 영상을 다시 요구할 필요는 없다.

| 항목 | 결과 |
|---|---|
| MCU/FPGA 식별 | NES-GAME-153,62/DC 일치 |
| ROM 적재·읽기 대조 | 각각393,216바이트,verified=1,verify_error=0 |
| RUN | run_passed=0,run_first_error=1,run_rom_error=2 |
| 오류 문맥 | valid=1,`e200c2f4:20217a10` |
| STOP | stop_ok=1,run_stop_error=0,run_last=run_stopped=26,415,116 |
| 기본 FPGA·메뉴 | base_restored=1,safe_to_reload=1,진행 로그MENU_PREPARED 도달,사용자 실제 메뉴 복귀 확인 |
| 입력 | 이번 실행 Start 중복 없음(사용자 확인). 다른 버튼·장시간 중복 여부 미확인 |

`run_error=1`은 MCU의 첫 실행 오류 분류다. CPU ROM 오류1을 뜻하지 않는다. 실제 코어 원인은 **`run_rom_error=2`**이며, 사용된 [서비스 RTL](../src/nes/diagnostic/nes_rom_service152.sv)의 `ppu_sample && ppu_rom && !ppu_valid` 조건이다. 따라서60초 제한시간 종료나 정상 게임 종료가 아니라, 오류를 감지하고 조기 복귀한 결과다.

`menu_state=PREPARED_RESET_HELD`는 최종 TXT를 저장한 순간의 상태다. 실제 메뉴 복귀는 그 뒤 이루어지고 사용자가 확인했다. `run_flags=3`도 STOP 이후의 reset+sticky fault 상태이며 처음부터 실행되지 않았다는 뜻이 아니다. 화면 관측 `stage=6,frames=17`은 `screen_telemetry_trusted=0`이므로 FPS·실제 NES 프레임 수·정상 화면 판정으로 사용하지 않는다.

## 최초 오류 문맥

현재152 FPGA의64비트 배치로 해석했다.153은 같은 FPGA 바이트를 사용한다.

| 필드 | 값 | 해석 |
|---|---|---|
| bit63 주소 표식 | 1 | 하위25비트는 오류 순간의 실제 PPU 요구 주소 |
| 실제 요구 주소 | `0x217A10` | CHR ROM 범위의 물리 주소 |
| 처리 중 주소 | `0x217A10` | **실제 요구와 일치** |
| busy / pending_ppu | 1 / 1 | 해당 PPU 읽기 요청이 진행 중 |
| age | 1 | 요청 경과 카운터1. CPU 명령 수·벽시계 시간으로 바꾸지 않음 |
| ppu_sample / ppu_valid | 1 / 0 | 값을 사용해야 할 시점에 캐시/응답의 유효 데이터 없음 |
| rom_response / rom_ready | 0 / 0 | 그 순간 응답이 없고 백엔드가 새 요청을 받을 준비도 안 됨 |
| cpu_sample / cpu_valid | 0 / 0 | 그 순간 CPU 샘플 오류는 아님 |

151의 처리 중 주소는`0x217A18`,age도1이었다.153은 그보다8바이트 앞선`0x217A10`이다. 두 주소가 가까워 같은 CHR 패턴 주변의 요청 시점·캐시·선행 읽기를 우선 볼 근거는 있지만, **151에는 실제 PPU 요구 주소가 없었으므로 동일 원인이라고 단정하지 않는다.** 이전 모델에서 주입한`e200c2f4:30217a19`는 합성 값이며 이번 실제 관측과 구분한다.

## 원인 범위를 어떻게 좁혔나

오류 순간에 다른 주소의 읽기만 진행 중이었던 경우는 이번 문맥과 맞지 않는다. 올바른 주소의 요청은 받아들여졌지만 사용할 때까지 응답이 없었다. 캐시에서 즉시 공급할 수도 없었다. **필요한 요청이 너무 늦게 시작되었는지, 앞선 요청 때문에 지연됐는지, 응답 전달이 늦었는지**가 다음 확인 대상이다. age=1은 장기255카운터 타임아웃6과 구분되며 요청 선행 시점이 부족했을 가능성을 뒷받침한다.

순간 문맥에는 직전 요청/응답 순서, PPU scanline/cycle, 논리 주소, MMC3 레지스터와 캐시 교체 이력이 없다. 따라서 이번 값만으로 선행 읽기 오예측·캐시 교체·맵퍼 전환·PSRAM/CDC 지연 중 하나를 확정할 수 없다. 전량 대조 통과는 적재된 데이터 무결성의 근거이지 실행 중의 빠른 읽기 타이밍 전체를 보증하지 않는다. 응답 주소 오류4·백엔드 오류5가 보고된 것도 아니다.

## 로그 시간

진행 TXT는512바이트 단위104기록이며seq0~103 누락·역전이 없다. 아래 시간은 펌웨어 경과 시간으로, 영상 기반 실측은 아니다.

| 단계 | 경과 시간 |
|---|---:|
| 전체 적재 완료 | 95.290초 |
| 전체 읽기 대조 완료 | 233.010초 |
| DISPLAY_NEXT | 233.020초 |
| DISPLAY_STOPPED | 242.230초 |
| 기본 FPGA 복원 완료 | 243.090초 |
| 메뉴 준비 완료 | 245.380초 |

DISPLAY_NEXT→DISPLAY_STOPPED는 **9.210초**,STOP 표시→메뉴 준비는3.150초다. 첫 화면 표시 시점이나 오류 발생의 정확한 순간은 이 두 기록과 같다고 단정하지 않는다. 사용자 설명의 ‘그 즉시 복귀’는 화면 정지 후 자동 복귀 관찰로 보존한다.

## 다음 작업

153 복귀·기록 수정은 실기 수용 완료로 처리한다. 같은153·044·A/B 시험을 반복하지 않는다. 다음 구현은 실제 SMB3의 Start 이후 경로에서`0x217A10` 주변 요청의 발행→응답→PPU 샘플 순서를 좁혀, 선행 읽기·캐시·중재와 백엔드 전달 기한 중 첫 어긋난 경계를 수정한다. 이미 통과한 초기30프레임만 반복하거나 오류 검사를 제거해 진행시키지 않는다. 현재 정보로 재현이 안 될 때만 필요한 최소 추가 관측을 검토한다.

Start 중복 문제는 이번 실행에서 관찰되지 않았다. 별도 입력 수정을 먼저 추가하지 않고 PPU 오류를 해결하여 실제 스테이지 조작을 확인한 뒤 다른 버튼을 판정한다. 전체 게임·60fps·입력 공백·오디오·저장은 여전히 미완료다. 이 결과는 PR95에 반영하며 새 구현·패키지는 다음 작업이다.

원본 TXT는 비공개로 보존하고 파일 크기·SHA-256·전체 진행 기록·해석은 [검증 메타데이터](game153-hardware-verification.json)에 남겼다.
