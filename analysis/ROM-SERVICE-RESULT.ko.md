# NES050 공유 ROM 경로 결과

CPU와 PPU의 ROM 요청을 **하나의 메모리 포트로 중재**하고, 실제 읽기 시점에 데이터가 준비됐는지 감시하는 회로를 연결했다. 새로운 실기 이미지는 아직 없으며044 성공본을 유지한다.

- 정상 지연 조건:624618건의 ROM 요청 처리.2종 진단 ROM의8프레임·491520픽셀·16064전송 바이트와 전체 진행 기록이049와 정확히 일치했다.
- 지연 증가 조건:응답을1클록에서2클록으로 늦추면 두 ROM 모두 **PPU 읽기 마감 초과(error2)** 를 검출했다. 실패 로그를 그대로 보존했다.
- 단위시험:4148검사 통과.동시 요청의 PPU 우선 처리, 다른 요청으로 이어받기, 캐시 재사용, RESET, 응답 주소/오류/시간 초과와 CPU·PPU 마감을 확인했다.
- 공동 합성·배치:13538LE,928/963LAB,4895레지스터,26M9K.진단 구성에서 LAB35개가 남는다.

이전049보다 LE61개·LAB8개·레지스터84개가 늘었다. 가상 핀282개·미지정 물리 핀5개·PLL0의 조건으로, 실제 보드 전체가 맞는다는 증거는 아니다. GBC 보호152파일과044–049의 기존 결과를 보존했다.

이번 ROM backend는 NES master clock을 공유하는 **동기식 시험 모델**이다.1클록 응답은 요청 수락 다음 클록에 응답이 등록되는 조건이며, 모델에서 한 클록은 약46.56ns다. 이 결과를 실제 PSRAM의 허용 접근 시간으로 그대로 환산해서는 안 된다. 실제 메모리 제어기·클록 경계·버스 전환까지 합쳐 같은 읽기 시점을 만족해야 한다.

2클록 모델은 실행 약40.083ms에서 실패했다. `slow/result.json`의 passed는 의도한 실패 검출에 성공했다는 뜻이다. 그 경로가 정상 실행됐다는 뜻이 아니다. 에러 로그의 주소는 감지 다음 클록의 관찰 값이며 원인 주소 스냅샷으로 해석하지 않는다.

회로는 오류를 유지하고 새 ROM 요청을 중단한다. 실제 보드에서 오류 프레임을 폐기하고 메뉴로 복구하는 처리는 다음 통합 대상이다. 현재 시험은 오류 직후 중단한다. ROM은 RESET 사이에 바뀌지 않아야 하며, 로더·세대 번호·다른 클록의 응답을 그대로 연결할 수 없다. CPU/PPU별1바이트 캐시와 현재 물리 주소만 사용하며 NES를 늦추거나 프레임을 버리지 않았다.

다음은 **실제 외부 메모리 응답·클록 경계가 이 마감을 만족하도록 구현하는 작업**이다. 필요하면 현재 코어 주소에서 요청을 더 일찍 내는 방법을 검증한다. 이후 로더·SNES 화면 소비자·물리 fit/STA를 묶어 복원 가능한 실기 패키지를 준비한다. SD 교체는 아직 필요하지 않다.
