# NES162 — 사운드 복원 실기판

161 첫 레벨 플레이 성공 이후, 사용자가 지정한 **사운드·연속 화면 우선** 계획 중 사운드 경로를 먼저 구현했다. APU 채널 쓰기를 복원하고 카트리지 DAC에 연결한162 시험판을 준비했다. 실제 음악·효과음은 사용자 실기에서 확인해야 한다. **연속 화면은 아직 미완료이며 다음 구현 우선순위다.**

[실기 안내](../docs/nes-game162-instructions.ko.md) · [검증 수치](game162-verification.json) · [161 실기 성공](GAME161-HARDWARE-RESULT.ko.md)

## 구현과 검증

- 기존156의 APU 채널 쓰기 차단을 해제했다. DMC도 포함하며 실제 APU·DMA 동작을 복원한다. 코어가 이미 제공하는 내부 mono mix를 사용하고 확장 매퍼 음원은 추가하지 않는다.
- 512 NES 클록 평균, DC 성분 제거, 절반 크기 변환, 응답을 받기 전까지 샘플을 보존하는 CDC를 거쳐 출력한다. nominal NTSC 약21.477MHz에서 새 평균 샘플은 약41.95kHz다. DAC 전송 클록은 기존 GBC와 동일한84MHz 기반이며 LRCK164.0625kHz/MCLK10.5MHz다. 같은 mono 샘플을 좌우 슬롯에 넣는다. 반복 DAC 샘플 전송률과 새 음원 샘플률을 구분한다.
- GBC의 DAC 직렬 전송 부분을 독립 참조로 추출해 핀 파형을 비교했다. 서로 다른 두 클록 조건에서 평균/DC 수치,38회 전달, 비동기 STOP의 무음화·재시작을 확인했다. 데이터는 수신 응답 전 덮어쓰지 않는다. 기존 GBC 코드 자체는 변경하지 않았다. 신규 PSRAM 오디오 쓰기·지연 RAM·PLL은 없다.
- 실제 APU/DMA 모듈에서32개 주소 읽기·쓰기, OAM256읽기+256쓰기, DMC17바이트 요청/완료, pulse 음원 변화를 확인했다. DMC 응답 바이트는 모델이며 실제 SMB3의 PSRAM 경쟁·아날로그 음질·게임 전체 실행을 증명하는 시험은 아니다.
- 새 APU 결선을 포함한 실제 PPU/service/reader 경계에서160 재개12사례·기존실패12대조와159 읽기39정상·39대조(18오류)를 유지했다.161 캐시·프레임·패드·DMA 클라이언트·PPU·매퍼·reader·클록 파일은 바이트 단위로 보존해 변경 없는 전체 화면 시험을 반복하지 않았다.
- 새 MCU는162/6B/E5 식별과 로그의 `apu_channel_writes_blocked=0`을 반영했다. RUN/STOP 경로·진행 TXT·약60초 실행 상한은 유지했다. 실제 ELF188604바이트, NMI15 stores/0 calls, 호스트 회수13사례·출력256마스크가 통과했다.

## 실제 배치 결과와 범위

단일 MAP/FIT 배치가14711LE,5572 registers,960/963LAB,56/56M9K,122실제핀/가상핀0,PLL1로 완료됐다. 추가 배치 지침과 기존 명목 클록 모두 최소setup **+0.121ns**, hold **+0.177ns**로 통과했다. 배치 seed 재시도나 클록 완화는 하지 않았다. 메모리 공간을 추가하지 않았으나 여유 LAB은3개뿐이므로 이후 연속 화면 구현에서는 임시 관측 회로의 축소·자원 재배치를 고려해야 한다.

기존 조건부 PSRAM 여유는+2.341ns, SNES 응답 상한은199.003ns로270ns 샘플보다 짧다. 새16비트 음원 mailbox 경로는3코너에서 최대1.287ns, DAC 핀 출력 전파는최대5.220ns로 각각84MHz 한 주기11.904ns 이내다. 이 검사는 안정 데이터 전달과 핀 전파 조건의 확인이며 전체 외부IO·PCB2ns 가정·MTBF·reset recovery 및 아날로그 DAC 규격 전체 승인은 아니다.

## 이번 시험과 이후 우선순위

162에서 먼저 실제 SMB3 음악·효과음, 음원을 켠 상태의 월드맵·첫 레벨 진행, 두 TXT와 메뉴 복귀를 확인한다. 사운드 쓰기 복원이 DMC/ROM 요청을 늘리므로 실기에서 오류가 재발하면 기존 최초 오류·입력 이력으로 구분한다. 듣기 전부터 사운드 완료로 기록하지 않는다.

다음 구현은 연속 화면 전송이다. 현재161과 동일한57344바이트 전체 DMA/강제 소거/hold6이 남아 있다. hold를0으로 바꾸는 것만으로 연속 화면이라고 부르지 않는다. SNES 전송 대역·표시 중 VRAM 갱신 제약과 기존 GBC 출력 경로를 대조해 실제 게임의 움직임으로 확인한다. 고정된 오디오 지연 RAM을 지금 추가하지 않고 표시 경로의 지연이 정해진 뒤 동기 문제를 판단한다. 이번 시험은 소리와 화면의 지연 일치까지 보장하지 않는다.

사운드·화면 확인 후 고정60초 종료를 해제하고 오류/본체 리셋을 계기로 상태 보존 → 안전 정지 → TXT 저장 → 메뉴 복귀를 구현한다. 그 환경에서 지속 DOWN·동시 입력·점프·대시를 충분히 확인한다. 기존 DOWN/NONE 문제는 미해결로 남는다. 오류·통신 감시는 계속 유한하게 유지하며, 현재 시험판에 리셋 로그 기능이 구현됐다고 안내하지 않는다.

## 재현과 보존

`tools/nes_game162.py`는 동결161 manifest와 개별 소스 해시를 확인한 뒤 별도 ASCII 경로에 후보를 생성한다. `--arm`은 MCU 소스만 생성한다. `tools/test_nes_game162_audio.py`와 기존 `tools/test_nes_game160.py`를 등록된 Starter FLOAT wrapper로 실행한다. 라이선스 파일을 변경하거나 새 라이선스를 요구하지 않는다.

Quartus25.1std에서 생성된 `board`의 MAP/FIT/STA를 실행한 뒤 `check_nes_game150_timing.py`, `check_nes_game160_timing.py`, `check_nes_game162_audio_timing.py` 순으로 같은 배치를 검증한다. ARM은 기존 `build_nes_run136_arm.ps1`, 검증은 `check_nes_game162_arm.py`·`test_nes_game162_host.py`다. `assemble_nes_game162.py`·`release_nes_game162.py`가 검증된 결과만 포장하고 `verify_nes_game162.py`가 동결 근거·공개 소스·패키지를 읽기 전용으로 확인한다. 각 도구의 `--help`에 입력 경로 인자가 있다. 동결된 생성/완료 스크립트는 재실행하지 않는다.

제한 환경에서 FLOAT wrapper의 호스트 식별 확인과 ARM 임시 드라이브 매핑, 호스트GCC의 구형DLL 로딩이 실패해 기존 호스트 실행 방식으로 진행했다. 실제 FLOAT 시험과 빌드·검증은 통과했다. 초기 타이밍 후처리 순서 오류는 원본 배치 변경 없이 선행 표를 생성해 해결했다. 이러한 실행 환경·후처리 오류를 RTL 실패나 새 라이선스 요구로 기록하지 않는다. 원시 결과와 실패 흔적은 로컬에 보존한다.

161 및 이전 동결 근거·공개 소스 핀·GBC152파일·원본NES334파일·044 복원본·사용자 SMB3 ROM은 보존한다. ROM·바이너리·영상·라이선스·개인 경로는 Git에 올리지 않는다. 같은161/044/GBC/A-B/무변경 전체 부팅을 다시 요구하지 않는다.
