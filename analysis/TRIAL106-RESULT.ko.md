# NES106 외부 지연 한계와 제한 실기 판정

CF86의 외부 지연 예산을 원시3168경로에서 재계산하고, 최소 조건이 CE 비활성 간격임을 확인했다. 실기 미결 조건을 외부 전기적 범위와 공통고장 처리 두 항목으로 좁히고 관측·종료 절차를 구체화했다.

PR55 병합 `4558aedab3feedc79e553756fe60486009c0dbed`와 head0314bdf6127fcc8348231af6ecafe9286492df2b 포함 확인. **분석·판정 기준 작성은 완료, 실제 허용 조건의 근거 확보와 실기 승인은 미완료**다. 105 최종 파일 조합을 그대로 사용한다.

## 작업 의미

실기 디버깅 기반의 진입 조건 분석이다. 필요한 외부 근거의 수치와 관측 판정 기준이 명확해졌다. 새로운 코어 배선·게임 기능·실기 PASS를 추가한 작업은 아니다. 이전의 막연한 '외부IO 미확인'을 어떤 항목과 얼마의 여유를 확인해야 하는지로 바꿨다. 다만 계산 도구 통과를 실제 PCB·전압 측정으로 대체하지 않았다.

## 원시 근거에서 재계산한 경계

086 동결 manifest와 io-paths.tsv SHA를 검사하고3개 코너/3168경로의 기존 계산을 다시 실행했다.20ns/60ns leg 가정 결과가 저장된086 budget과 **전체 JSON 동일**함을 확인했다. 새 Quartus route/STA/fit/ASM은 실행하지 않았다.

두 동일 leg 비용과 추가 불확실성을 모든16경계에 보수적으로 빼는 기존 식을 유지했다. 계산 해상도1ps에서 양수인 최대 동일leg 값은52.282ns다. **이 값은 물리 설계 권장 한계가 아니며,1ps 잔여로 실제 보드를 승인할 수 없다.** 원본 경로 값의 표시 정밀도와 기존 극값 합산식 안에서의 산술 경계다. 읽기 access70ns만 검토하면 가장 좁은 CE 비활성 간격을 놓친다.

네 시나리오와 음수·NaN·무한대 등 잘못된 가정4개 거부를 확인했다. 새로운8건의 회로 시뮬레이션이 아니라 기존 경로에 대한 계산 검사다. 본래 source/hash/3corner/동적핀 존재 검사를 유지했다. 관측된 실물 PCB 지연·전압·부하는 여전히 없다.

## 제조사 범위와 공통고장

[ISSI EBLL Rev.D3 공식 자료](https://www.issi.com/WW/pdf/66-67WVE4M16EALL-BLL-CLL.pdf)의 비동기 모드 설명에서 읽기 tCEM 예외는 T계열이며 사용자 E계열에 적용하지 않는다. WE LOW 시간도 tCEM 제한을 받는다. 이번 직접 PDF 요청은403이었고 공식 도메인의 검색 색인에서 해당 설명을 확인했다. 상세 수치·판본 대조는 이미 고정된 [부품 가이드](../docs/development/FXPAK-HARDWARE-REFERENCE.ko.md)를 재사용하며 다른 판매처의 스펙을 새 근거로 쓰지 않았다.

086의 두클록정지/lockedHIGH CE LOW9µs 반례는 그대로다.093의 최대23.699ns는 감지 레지스터 Q 이후 전파 분석이므로 감지 지연이나 두클록정지까지 보장하지 않는다.092에서 확인한 한 실행의 reference 활동도 공통고장 독립성 증명은 아니다. 의도적 고장 주입을 하지 않는 시험 범위와 고장에 안전한 회로는 서로 다른 주장이다.

## 관측·종료 절차의 의미

[106 관측 가이드](../docs/nes-trial106-observation.ko.md)에 신규TXT와 화면의 역할을 분리했다. 선택 직후부터 최대600초(10분)는 **사람이 무응답을 계속 기다리지 않기 위한 운영상 관측 한도**다. 정상 완료에600초가 필요하다거나 그 안의 MCU 완료/차단을 보장한다는 뜻이 아니다. 기존 wire113/136초 하한·메뉴60초 예산을 합성해 만든 WCET도 아니다. 한도 도달은 원인 미확정 종료이며 타이머 오류 확정이 아니다.

소프트웨어로 자동 전원 차단하거나 오류 뒤 TXT를 강제하지 않는다. 이 절차는 조건 충족 후 사용할 초안이며 현재 실행 요청이 아니다. 이전 파일/로그의 보존·새 TXT·메뉴 관측·수동044복원을 분리한다. 메뉴가 돌아와도 TXT가 없으면 저장 성공으로 쓰지 않고 TXT가 준비 상태여도 메뉴가 없으면 반환 성공으로 쓰지 않는다.
