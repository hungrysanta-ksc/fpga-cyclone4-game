# NES 057 — 승인된 ROM 크기를 코어에 연결

후보 **NES-ROM-GEOMETRY-057**. SPI BEGIN과 별도 코어 입력으로 나뉘었던 CHR 크기를 로더의 기존 승인 레지스터 하나에 연결했다. 원본053/054 파일은 그대로 두고 생성된3모듈에 출력 배선만 추가했다. 코어의 외부 크기 입력과 가상 핀은 제거했다.

| 항목 | 결과 |
| --- | --- |
| SPI 형상 | 14검사,5프로토콜 오류 경우. 거부된 BEGIN이 승인 형상을 바꾸지 않음 |
| 직접 로더 | 360470검사,두 형상180224바이트. 입력 인자 변조·END/RUN/STOP/재진입·RUN 중 BEGIN 거부 |
| 잘못된 구현 대조 | 승인값 대신 SPI 인자 latch를 연결하면 정확히3번째 검사에서 실패. 기능 통과가 아닌 예상 실패 확인 |
| 실제 코어 | 96/80KiB 전체 SPI 적재,2ROM/8프레임/491520픽셀. BEGIN 뒤 기존 시험 인자를 반대로 바꿔도 승인값으로 실행 |
| 055와 비교 | 패킷16064바이트 및 전체 S/E/F/D 이벤트 동일. release tick·모든 이벤트 시각 차이0 |
| 읽기 | 요청624788/응답624786,왕복4NES클록. 각 시험 끝에서 조기 읽기1건 미완료인 기존 범위 유지 |
| 새 공동 fit | 13976LE,954/963LAB,5158레지스터,26M9K. **LAB9개 여유** |

SPI decoder 인자 latch는 프레임이 정상이면 갱신되지만, loader는 자신의 상태에 따라 BEGIN을 거부할 수 있다. 코어가 그 인자를 바로 사용하면 거부된 명령이 형상을 바꾸는 문제가 생긴다.057은 실제 길이를 결정하는 loader의 chr32만 사용한다. 별도의 설정 복제 레지스터는 추가하지 않았다.

054 대비 레지스터 수는5158개 그대로, 조합 함수는12213→12212개지만 패킹이 달라져 LE가110개,LAB이6개 증가했다. 조합+레지스터 동시 사용 LE는3505→3394,레지스터 전용 LE는1653→1764다. 새 자원을 측정했으므로 과거15LAB 여유를 계속 사용하지 않는다. 물리 보드 핀/PLL/전체 소비자/STA는 빠진 공동 진단 fit이며 완성 보드 통과가 아니다.

정상 unit/live/fit는 첫 실행에 통과했다. mutation은 의도적으로 잘못 연결한 대조이며 `Geometry check3 expected1 got0` 실패를 원시 자료에 보존했다. 실제 코어의 기존 초기화 경고는055와 같은 순서/개수이며 신규 Fatal/Error는 없다. 기존 Starter FLOAT 경로를 순차 사용했다.

다음 물리 검증은 FPGA CRC 회로 추가보다 기존052 읽기 경로를 MCU가 CHECK 상태에서 공유하는 방식을 우선 평가한다. 실제 readback·비교·RUN 허가·읽기 취소는 아직 구현하지 않았다. 작은 기능이라도 남은9LAB에 들어가는지 초기 공동 fit에서 확인해야 한다. [후속 설계](../docs/nes-rom-readback-plan.md)에 현재 RUN 전용 reader의 reset/소유권 변경과 손상 대조 시험을 정리했다.

056 MCU·GBC152파일·원래 NES334파일·실기044는 그대로다. **새 MCU 실행 결과·물리 메모리 무결성 통과·새 SD 이미지는 없다.** [재현 계약](../docs/nes-rom-geometry-contract.md), [검증 해시](rom-geometry-verification.json), [현재 인계](../cores/nes/HANDOFF.ko.md).
