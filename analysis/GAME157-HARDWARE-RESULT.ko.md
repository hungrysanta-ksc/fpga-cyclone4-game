# NES157 실기 — 샘플 직전 CHR 물리주소 변경과 PPU 기한 오류

**게임 진입은 실패했지만, 최초 오류 직전의 주소·요청·응답 경계를 회수했다.** 사용자는 Start로 스테이지 진입을 시도하면 종료되고 메뉴로 복귀했다고 보고했다. 이번157은 원인 구분용 관측판이며 게임 정지 수정판이 아니다. 같은157 재시험이나 추가 영상은 필요하지 않다.

## 확인된 결과

- 66/E0 식별, 전체393216바이트 적재·읽기 비교, verified1/오류0. 진행104개512바이트 레코드의 순번·시간 단조성과 최종TXT를 확인했다.
- RUN은 PPU기한 오류2로 실패했다. 최초오류 문맥 `e30042f4:30217a18`: 실제·진행중 주소 모두 `0x217A18`, 요청 age0, PPU샘플1/유효0/응답0, CPU유효1.156의 `e200c2f4`는 CPU유효0/age1이므로 **문맥 전체가 동일한 것은 아니다**.
- PPU `60820800:28606060`은156과 같으며 line193/dot8, 일반 배경 상위 비트면, 논리주소 `0x0A18`, read/write2007 파이프0이다. 이 시점의 hint0은 정상 예측 구간 밖이라는 뜻으로, 선행 읽기 부재의 증거가 아니다.
- STOP 뒤 카운터22584470 유지, stop_error0, 기본FPGA 복원·TXT·안전한 메뉴 준비 통과. 실제 메뉴 복귀는 사용자도 확인했다. 게임 플레이·이동·점프는 미완료다.
- 패드 이력5건은 `NONE → START → NONE → START → NONE`. 두 구분된 Start 수신·해제 구간을 확인했다. 물리 클릭 계측이나 다른 버튼의 동작 증명은 아니다.

## 정지 직전16클록의 의미

상대클록0은 최초 오류를 포함한 마지막 NES클록이다. 아래 주소는 CPU PC가 아닌 서비스의 **물리 메모리 주소**다.

| 상대클록 | 관측 | 판정 |
|---|---|---|
| -13 | 상위 비트면 `205A18` 선행 요청, 이전 `205A10` 응답 | 선행 읽기를 실제로 발행함 |
| -8 | PPU 선행 응답, 동시에 CPU `03C001` 새 요청 | 이전 PPU 읽기 완료. 이 행의 전송주소는 새 CPU 요청임 |
| -7~-4 | 현재 PPU `205A18`, 유효1, 선행 캐시 일치 | 필요한 기존 주소 데이터 확보 |
| -3 | CPU 응답, 현재 PPU 유효1 | 직전 CPU 읽기도 완료 |
| -2 | busy0/ready1, PPU `205A18` 유효1 | 공유 읽기 경로가 비어 있음 |
| -1 | 실제 PPU `205A18 → 217A18`, 예측 `205A10 → 217A10`, 유효0, 즉시 새 요청 | 물리주소 변경으로 기존 캐시 불일치. CPU 점유로 발행이 밀린 장면은 아님 |
| 0 | `217A18` PPU샘플, 응답0/유효0 | 새 요청 후 한 NES클록 만에 샘플하여 오류2 |

이 창의 완료된 PPU/CPU 요청은 각각 요청부터 응답까지5클록이다. 이는 이 두 관측의 지연이며 일반 최악 지연이나 외부 타이밍 보증이 아니다. 새 주소는 샘플까지 한 클록만 남아 같은 경로의 응답을 받지 못했다. 기존 응답을 놓친 문제나 선행 읽기가 전혀 없었던 문제와 구분된다.

## 원인 후보와 증거의 한계

현재 소스의 `cart_nrom.sv`는 실제 PPU 주소와 예측 주소를 **같은 MMC3 뱅크 레지스터로 조합 변환**한다. CPU의 bank-select/invert 쓰기와 bank-data 쓰기가 변환 결과를 바꿀 수 있다. 실제 주소와 예측 주소 모두 하위10비트 오프셋을 유지한 채 상위 뱅크 부분이 함께 바뀌었으므로 **MMC3 매핑 전환과 PPU 읽기 시점의 충돌**을 우선 조사한다.

다만16클록 이력에는 과거 논리 PPU주소·매퍼 쓰기 주소/값·레지스터·CPU PC가 없다. 특정 레지스터를 실제로 썼다거나 MMC3 쓰기가 확정 원인이라고 단정하지 않는다. 논리주소 상위 비트 전환도 구분해야 한다. 이 문서는 확인된 물리주소 변화와 그 원인 후보를 분리한다. 최종 오류 순간의 논리주소만으로 창 전체의 논리주소가 같았다고 가정하지 않는다.

APU 채널 쓰기 차단은 유지됐다. 소리만을 유일 원인으로 보기는 어렵지만, 사운드 드라이버의 CPU 실행·매퍼 접근 영향까지 배제한 것은 아니다. 진단용 음원 차단을 정상 오디오 수정으로 취급하지 않는다. screen_frames15/trusted0은 정상 FPS 근거가 아니다.

펌웨어 진행 시각은 DISPLAY232880→240780ms(7.900초), MENU244020ms(오류 후3.240초)다. 사용자 독립 실측·정확한 버튼 시각·영상 재생 시간으로 해석하지 않는다.

## 다음 작업

1. 실제 MMC3·PPU·서비스·reader를 사용한 짧은 시험에서 dot8 직전 매핑 변경을 재현한다. bank-data, bank-select/invert 전환을 비교하고 논리주소 변경 대조군으로 원인을 구분한다. 고정 뱅크 선행 읽기 시험만 반복하지 않는다.
2. 주소 전환부터 샘플까지의 데이터 확보를 수정한다. 오래된 뱅크 데이터 대입, PPU 기한 검사 삭제, 근거 없는 캐시 확대로 통과시키지 않는다. 실제 NES의 매퍼 전환 의미와 일치하는지 확인한다.
3. 변경된 경계만 검증한 뒤 같은 SMB3의 스테이지 진입·이동·점프 실기로 돌아간다. 원인 확인 후 임시3M9K 이력을 축소·제거한다. 현재56/56M9K이므로 추가 메모리 여유는 없다.
