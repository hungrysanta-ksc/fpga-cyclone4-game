# 123 — 실제 PSRAM 핀과 PLL을 포함한 코어 배치·타이밍 조사

## 작업 목표

PR68 병합 `878c8ce71a9bcae70a3c69ba652292d1e00559e3` 확인 후,122의 READ16/168MHz 보호 reader가 실제 FPGA의 PLL·핀 배치에서 구현 가능한지 확인했다. 기존059는 가상 핀과 PLL0 자원 검사여서 이 판단에 그대로 사용할 수 없었다.

## 작업 내용

공개059 해시와 일치하는 실제 CPU·PPU·APU·메모리 서비스·영상 패킷 회로를 사용하고, 기존 CF86 reader를 READ16으로 연결했다.122와 공통 입력을 비교해 사용한 코어/reader 소스가 같음을 확인했다. 서로 다른 두 파일은 이번 합성에서 사용하지 않는 테스트벤치와 메모리 모델이다.

기존8MHz→84MHz PLL의 별도 출력에168MHz를 추가했다. 코어는 실제 SNES_SYSCLK 핀을 사용하며 STA는 최대22MHz 가정(45.454ns),기존122 기능 시험은 정상21.477MHz 조건이다. CLKIN과 SNES_SYSCLK 및 PSRAM 주소/데이터/제어46개 핀은 저장소 보드 핀표에 맞췄다. 읽기 전용이므로 SPI 로더/CHECK·guard·실제 SNES 프로그램은 제외했다. RUN/리셋/입력/영상 관측 등 나머지264개 포트는 가상 핀이다. 전체 실기 코어를 완성한 빌드가 아니다.

첫 fit01에서 직접 연결한 PPU 주소 관측 신호3개가 실제 핀으로 합쳐져 미지정 핀 경고가 발생했다. fit02에서는 기능 경로 밖의 보존 레지스터에 관측 주소를 한 클록 늦춰 저장했다. 코어·reader RTL은 그대로다. 두 배치와 실패 경고를 모두 남겼다.

## 작업 결과

최종 fit02는 Quartus25.1std Build1129의 map/fit/STA 실행을 마쳤다. **배치 성공과 전체 타이밍 통과는 다르며, 전체 타이밍은 실패 상태다.**

| 항목 | 최종 결과 |
| --- | --- |
| 장치 | EP4CE15F17C8 |
| 논리 요소 / LAB | 13,558 / 15,408 · 938 / 963 LAB |
| 이번 범위의 남은 LAB | 25개; 로더/guard/최종 소비자 포함 여유가 아님 |
| 메모리 / PLL | 26 / 56 M9K · 1 / 4 PLL |
| 핀 | 물리46개 모두 지정 위치 일치 · 가상264개 |
| 파생 클록 | PLL84MHz 및168MHz, 도구 표시 주기11.904/5.952ns |
| 동일 클록 내 setup 최솟값,3corner | NES +9.014ns · host84 +2.885ns · reader168 +1.432ns |
| 전체 원시 최악 slack | −8.104ns; 교차 클록 경로 |

세 동작 corner에서 클록쌍·setup/hold/recovery/removal의 최악 경로60개를 별도로 추출했다. 같은 클록 내부 경로는 모두 비음수다. **168MHz reader 내부 회로가 이 배치에서 동작할 가능성은 확인했지만, 비동기 데이터 전달과 reset 경로가 검증되지 않아 코어 전체 타이밍 통과를 선언할 수 없다.**

위반에는 reader의 `data_hold`에서 CPU로 가는 데이터 경로, 영상 패킷 bridge의 묶음 데이터, NES 도메인의 `local_memory.init_done`에서 다른 도메인의 데이터/비동기 reset 입력으로 가는 경로가 포함된다. 비동기 핸드셰이크 경로를 보통의 단일 클록 setup 수치로만 판정할 수도 없고, 그렇다고 통째로 false-path 처리할 수도 없다. 안정 유지 구간·제어 동기화·reset 해제를 실제 구조와 연결해 증명하고 정확한 제약을 추가해야 한다. 이번에는 false-path/clock-group 면제를 추가하지 않았다.

외부 입력·출력 지연 제약은 미설정 상태로 원시 보고서에 남겼다. 따라서 +1.432ns는 PSRAM70ns나 PCB/패드의 전기적 여유가 아니다. 실제 보드 배선의 연속성이나 전압·부하도 측정하지 않았다. 실제 SNES 데이터버스·영상 소비자의 물리 통합은 남는다.25 LAB를 이후 로더·guard 추가 가능 수치로 보장하거나059/086의 자원을 단순 합산하지 않는다.

원시 map/fit/STA 로그·라우팅 DB·소스·핀표·60경로·클록·미제약 보고서를 755파일로 동결했다. manifest `774f4e60a36bfe0dc045c46beb84428c4ba19b2680e85faeff58742978043279`. [검증 메타](clock123-verification.json)와 `verify_nes_clock123.py`가 해시·핀 배치·클록·위반 보존을 확인한다. fit01의 첫 audit 경로 오류와 성공한 두 번째 실행도 보존했다. 보고서 degree 문자 때문에 초기 검증기의UTF8읽기가 실패한 것은 latin1읽기로 수정했으며 원문은 바꾸지 않았다. 제품 RTL/C/ARM 변경,ASM/실기용 이미지,Questa 실행은 없다.

## 작업 의미

**실기 코어의 메모리 배선을 위한 물리 구현 가능성·자원·타이밍 검증**이다. 가상 클록의 기능 시험에서 실제 PLL과 PSRAM 핀을 포함하는 배치로 전진했다. 목표 중 물리 핀·PLL·reader 내부 타이밍 조사까지 달성했고, 전체 통합 타이밍과 설치 가능한 RUN 코어는 미완료다.

다음은 `init_done`을 포함한 reset 조건을 각 도메인에서 안전하게 해제하도록 연결하고, reader/영상 bridge의 묶음 데이터 핸드셰이크와 실제 최대 지연을 대응시키는 작업이다. 원시 위반은 유지한 채 정확한 대상만 검증한다. 이후8MHz 로더 WRITE3=375ns를 유지할 도메인/카운터 설계,guard·소유권과 전체 자원,실제 SNES 소비자를 연결한다.168MHz에 기존 쓰기3클록을 그대로 적용하면17.856ns로 짧아지므로 금지한다.

최소 RUN의 진행 관측·오류 종료·독립044복원 경로가 준비되면 실기를 우선한다.119의 전체80KiB·메뉴·044복원과122의24프레임 결과는 유지하며,변경 없는 같은 시험은 반복하지 않는다. E1/E2·8µs·양 클록 정지 lockedHIGH CE9µs 반례,113 정지 원인 미확정,119 GBC 플레이 미보고는 유지한다. 제한 진단6완료/5부분/1미완료는 게임 완성률이 아니다. 첫 게임 SMB3(J),mapper4/384KiB 목표와 입력·음성·일반 영상·호환성 작업은 남아 있다.
