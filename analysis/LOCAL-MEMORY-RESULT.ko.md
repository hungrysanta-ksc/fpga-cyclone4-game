# NES049 내부 RAM 통합 결과

실제 코어 시험과 FPGA 자원 측정에 **같은12KiB RAM 구현**을 연결했다. 이전의 이상적인 로컬 배열과 별도 자원 측정용 RAM 간 차이를 해소했고, 시작 시 RAM을 실제 회로로 초기화한다. **새 실기 이미지는 아직 없으며 정상 동작한044를 유지한다.**

- CPU RAM2KiB, CIRAM2KiB, PRG RAM8KiB. 초기화8192클록, NES 기준 약0.381ms. 완료 전 코어·패킷 경로 RESET 유지.
- 단위시험153604검사 통과. 모든 주소 쓰기/읽기·이전 값 읽기·동시 접근·주소 경계·초기화 중 재시작·RESET 중 쓰기를 확인했다.
- 실제 코어의2종 진단 ROM, 총8프레임:131104 BG fetch,16064전송 바이트,491520픽셀 검증 통과. 이전048과 모든 픽셀 및 영상 패킷 본문이 같다.
- 초기화 후 시작 위상 때문에 패킷 release tick과 S/E/F/D 기록은 일관되게4클록 이동했다. 패킷 전체 바이트/시각 기록까지 동일하다고 주장하지 않는다.

초기화 회로가 추가되어 LE194개·레지스터14개가 늘었다. LAB 감소는 이번 배치 결과이며 완성 보드 자원 여유를 보증하지 않는다. RAM12KiB는 실제 M9K12개로 추론되었고, 생성된 파라미터의 OLD_DATA 동작을 확인했다. 전체26M9K에는 전송·인코더 메모리 등이 포함된다. 새로운 래치/사용하지 않는 신호 경고10036/10240은 없다. 기존RAM 경고276020/276027과 시뮬레이션 시작 경고는 원본 로그에 남겼다.

처음 실제 코어 실행은 생성된HDL의 혼합 net 선언 문법 때문에 컴파일되지 않았다. 문법을 수정한 최종 실행이 통과했으며 실패 로그와 당시 생성 소스를 보존했다. 라이선스 오류는 없었고 기존 Starter FLOAT를 사용했다.

이 구현은 진단용으로 매 RESET마다 PRG RAM을 지운다. 게임 저장 데이터 보존 정책, OAM 초기화, 외부 PSRAM 응답/중재, 로더, 실제 보드 클록/RESET/epoch, SNES 런타임 소비자와 VBlank 기한은 남아 있다. 시뮬레이션의 외부 ROM은 아직 이상적이며 fit는237가상 핀·5미지정 핀·PLL0의 진단 조건이다. 전체 보드 STA나 실기 통과가 아니다.

다음 단계는 외부 ROM 서비스의 읽기 마감 시점과 중재를 실제 코어에 연결하는 것이다. 이후 보드 클록·로더·SNES 소비자를 묶어 fit/STA와 복구 가능한 실기 패키지를 준비한다. GBC 보호152파일 및044 성공 이미지·기존044–048증거를 유지했다. SD에는 쓰지 않았다.
