# NES141 실기 결과 — ROM 실행·메뉴 복귀 통과, 화면 관찰 대기

사용자는 메뉴 자동 복귀와 두 TXT 저장 성공을 확인했다. 추가 질문에는 **진단 화면은 확인하지 못했다**고 답했다. 따라서 정상 영상 출력을 완료로 기록하지 않는다.

| 항목 | 이번 결과 |
|---|---|
| 후보 식별 | NES-SCREEN-141, loader5D / observerD8 |
| ROM 적재·대조 | 각각81,920바이트, verified=1, 오류0 |
| 실행 | run_passed=1, run_error=0 |
| ROM·최초·STOP 오류 | 모두0, fault_context_valid=0 |
| CPU 유효 읽기 관측 수 | 160,862 → 30,748,980 → STOP 후30,756,038 |
| STOP·기본FPGA 복원 | 성공 |
| 자동 메뉴 복귀·TXT | 사용자 확인 성공 |
| 실제 진단 그림 | 미관찰, 정상 여부 미확정 |
| 044/GBC 복원 재시험 | 사용자 정책에 따라 생략 |

CPU 관측 수는 명령어 수·프레임 수가 아니다. 이전140은123,028에서 멈추고 CPU ROM deadline 오류1이 남았지만, 이번에는 관측 수가 계속 증가하며 오류가 없었다. **이번 한 번의 진단 ROM 실행에서 ROM 오류와 메뉴 복귀 실패가 재현되지 않았다.** 모든 게임·지연 조건의 해결이나 여러 수정 중 단일 원인 확정을 의미하지 않는다. ACK16ns 스트레스 실패, 보드 지연/MTBF 및 기존 전기적 보류는 그대로다.

## 로그에 있는 표시 기록과 없는 정보

- DISPLAY_NEXT: 523,040ms, 약8분43.04초
- DISPLAY_STOPPED: 533,370ms, 약8분53.37초
- BASE_DONE: 534,240ms
- MENU_PREPARED: 536,550ms, 약8분56.55초

표시 구간의 MCU 처리 간격은10.33초다. 현재 로그는 표시 단계 실행과 ROM 읽기/오류를 확인하며 실제 TV 픽셀, 프레임 수신 완료 또는 정상 그림 판정은 기록하지 않는다. MENU_PREPARED는 마지막 SD 기록이고, 이번 실제 메뉴 복귀 성공은 사용자 관찰을 함께 근거로 삼는다.

## 필요한 재확인

사용자가 재시험 의사를 밝혔으므로 **같은141로 화면만 한 번 확인**한다. 실행 후8분30초부터 화면을 관찰하고, 진단 그림이 보이면 사진 한 장이나 짧은 영상을 남긴다. 정상·검정·깨짐 여부와 메뉴 복귀를 알려주면 된다. 기존 안내의 전체10분 관찰 기준은 유지한다. 새 패키지/무변경 빌드/동일044 복원 반복은 불필요하다. 로그 내용만으로 화면 성공을 추정하거나 같은 저장·부품 검증을 반복하지 않는다.

원본 두 파일은 별도 실기 자료 디렉터리에 바이트 그대로 보관했고, [관측 메타](screen141-hardware-observation.json)에 SHA-256과 판정을 기록했다.141 제작 동결 증거·패키지·고정 실행 안내는 수정하지 않았다. 첫 게임 목표 SMB3(J)/mapper4/384KiB와 입력·오디오 미완료 상태는 유지한다.
