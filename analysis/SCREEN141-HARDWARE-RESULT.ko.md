# NES141 실기 결과 — ROM 실행 통과, 정상 영상 출력 실패

첫 시험에서는 자동 메뉴 복귀와 TXT 저장 성공을 확인했고 화면은 미관찰이었다. **재실행의 두 TXT와 사진 세 장으로 정상 영상 출력 실패를 확인했다.** 사진의 색 잡음은 실제 증상이다. 대각선 띠는 사용자가 카메라·CRT 주사 차이라고 확인했으므로 FPGA 오류 분석에서 제외한다. 정상 진단 그림은 보이지 않는다. 같은141의 추가 재실행은 필요 없다.

|---|---|---|
| 후보·식별 | NES-SCREEN-141 / 5D·D8 | 동일 |
| 적재·대조 | 각각81,920바이트, verified=1 | 동일 |
| RUN·STOP | 통과 | 통과 |
| ROM·최초·STOP 오류 | 모두0 | 모두0 |
| CPU 유효 읽기 관측 수 | 160,862 → 30,748,980 → 30,756,038 | 160,878 → 30,749,002 → 30,756,064 |
| STOP·기본FPGA 복원 | 로그상 성공 | 로그상 성공 |
| 자동 메뉴 복귀 | 사용자 확인 성공 | 이번 메시지에는 별도 보고 없음; MENU_PREPARED까지 기록 |

두 시험 모두 표시 단계의 MCU 기록은523,040→533,370ms, 간격10.33초다. 기본 FPGA 복원은534,240ms, 마지막 MENU_PREPARED는 첫 시험536,550ms/재실행536,540ms다. 재실행47개512바이트 기록의 순서·시간 증가를 확인했다. 최종 TXT는 읽기 관측값 세 필드만 달라졌고, 오류·판정·식별은 동일하다. 원본 파일과 사진은 별도 로컬 증거에 보관하고 [관측 메타](screen141-hardware-observation.json)에 해시를 남겼다.

## 확정한 것과 남은 것

현재 진단 ROM의 적재·대조와 관측한 RUN·STOP은 두 번 통과했다. CPU 관측 수는 명령어 수나 화면 프레임 수가 아니며, 오류0도 ROM 데이터 전체의 실행 중 정확성이나 정상 그림을 보증하지 않는다. 첫 시험의 메뉴 복귀 성공을 이번 재실행의 직접 관찰로 바꾸어 기록하지 않는다.

사진의 글리치와 예전 증상이 닮았다는 이유만으로 같은 원인, 신호 동기 불량, DMA 실패 또는 TV 불량을 확정하지 않는다. 현재 TXT에는 SNES 표시 프로그램 부팅 완료·패킷 수신 완료·VRAM 반영을 판정할 필드가 없다. 따라서 **NES 실행 경로 통과와 TV 정상 영상 실패를 분리**한다. ACK16ns 확장 스트레스 실패·보드 지연/MTBF·기존 전기적 보류도 유지한다.

## 다음 작업

1. 이미 화면 순환에 성공한044와141의 SNES 프로그램 ROM 응답·RESET 해제·WRAM 이행·초기 PPU 설정을 비교한다. 기존044를 사용자에게 다시 시험시키지 않는다.
2. 부팅 → 화면 패킷 수신 → VRAM·팔레트 DMA의 최초 실패 지점을 구분한다. 현재 생성기는 WRAM의0x1FF0/0x1FE6/0x1FE8에 상태를 쓰지만 이번 MCU TXT가 이를 회수했다는 근거는 없다. 필요하면 해당 경계만 최소 관측으로 연결하고 기존 STOP 뒤 로그 저장을 재사용한다. RUN 중 SD 쓰기나 일반 추적 프레임워크를 추가하지 않는다.
3. 긴 NES 적재 이전에 확인 가능한 정적 표시를 짧게 분리할 수 있는지 검토한다. 정적 표시 성공은 SNES 표시 경로의 근거이며 실제 NES 패킷/게임 화면 성공과 구분한다. 변경된 경계 검증 후 수정 후보를 실기에 전달한다.

이번에는 결과 분석과 계획 갱신만 수행했다. 새로운 수정 펌웨어·빌드·시뮬레이션은 없다. 같은141의9분 시험, 변경 없는 전체 배치·저장·부품 검사,044/GBC 복원은 반복하지 않는다. 정상 영상이 확인되기 전 패드·SMB3 mapper4/384KiB·오디오 완료로 넘어가지 않는다. 동결141 제작 증거·설치 ZIP·과거 성공/실패 자료는 보존한다.

**추가 사용자 관측:** 무음이며약10초중1~2번정도만조금변하는글리치였다. 실제FPS측정은아니다. 현재오디오출력은미구현이므로무음은예상된다. 이후수정및판정은[142 결과](SCREEN142-RESULT.ko.md)를따른다.
