# 실기 관측 반영 및 눈으로 판정할 수 있는 진단030
2026-10-06. 후보 NES-H0-VISUAL-030. NES core014/CPU017/자원018/trace replay025/인터페이스029 유지.

사용자는029 top/fine/bottom 모두 차이를 느낄 수 없는 글리치 화면이며 떨리지는 않았고,
세 ROM별 체크가 무의미하다고 보고했다. 이 결과는 **실기 실행됨, 정상 출력 판정 불가**다.
029 패턴은 자동 바이트/화소 비교를 위한 난수형 도안이어서 수동 실기 판정용으로 부적절했다.
진단 설계 문제를 인정하며029 실기 통과나 하드웨어 고장으로 기록하지 않는다.
첨부 사진의 대각선 어두운 영역은 사진만으로 원인을 특정하지 않는다. 사진/사용자 원문은 ignored 로컬 증거에 보존했다.

## 교체한 진단
SNES ROM 하나에서 큰 제목 NES H0 030, 화면 번호와 GRID/BARS/CROSS 도형을 보여준다.
1→2→3→1로60 NTSC프레임마다 반복하여 멈춤과 페이지 전환을 육안으로 구별한다.
검정/흰색/노랑/청록, 넓은 여백과 큰 도형을 사용했다.
자체224줄 SNES 진단이며 NES fetch 재생이나240줄 제품 정책 변경이 아니다.
초기 forced blank에서 palette512B 및 CHR3×14,336B를 적재한다.
이후 각 페이지에서 VBlank에 map2,048B DMA와 CHR base 전환을 수행한다. 반복 forced blank는 없다.
한 ROM으로 확인하며029 ROM3개의 재시험은 요청하지 않는다.

## 실제 검증
Mesen 실제 실행1회, emulation frame2/32/62/92/122/152/182의7개 화면 검사.
페이지와 중간 유지 화면을 포함하여1,1,2,2,3,3,1 순서,전환 간격60프레임을 확인했다.
활성401,408화소와 캡처 여백을 포함한428,288화소가 모두 일치했다.
4개 페이지 commit의 DMA2,048B는VBlank 내 발생했고 최소 잔여32,722 master clocks였다.
이는 독립 SNES 진단의 에뮬레이터 관측이며 실제 FPGA/버스 timing 통과를 의미하지 않는다.

최초 auditor는 getScreenSize가224높이라고 잘못 가정하여 실패했다.
실제 Mesen 캡처는239높이이며 활성224줄 위7줄/아래8줄 검은 여백이 포함됨을 원본으로 확인했다.
검증기는 여백까지 전체 exact 비교하도록 수정했다. ROM/observer는 변경하지 않았고 같은 원시 실행을 재검증했다.
초기 검증기·실패 설명·전체 원시 로그를 보존했으며 실패가 없었다고 표시하지 않는다.
새 Questa/Quartus 실행이나 NES 코어 수정은 없다.
