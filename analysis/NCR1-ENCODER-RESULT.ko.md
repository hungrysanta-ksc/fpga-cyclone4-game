# NES 순차 NCR1 인코더046

2026-10-06. **시간 순서대로 들어온 NES 배경 fetch에서 패킷을 생성해045→044로 전송하는 RTL을 구현했다.** 완성 패킷을 입력하던045 시험에서 한 단계 진행했다. 입력은 과거 NES 참조 실행 기록이며, 실행 중인 NES 코어의 PPU 신호는 아직 직접 연결하지 않았다.

| 항목 | 실제 확인 |
|---|---|
| 순차 입력 |원본021의 banks32/fine-X 각4프레임,131104개 fetch. 원래 tick 간격으로 입력 |
| 생성·전송 |프레임 종료 검사 후 NCR1 공개.045 메모리 생산기와044 버스를 통해 전체 바이트 비교 |
| RTL 회귀 |16항목, RESET 뒤 재생성 포함18072바이트 일치 |
| 오류 검사 |지원 밖 모드·누락/순서·타일 행/속성·셀 내부 변경·혼합 창·미완성 프레임·원본 버퍼 소유권 |
| 최종 map/fit |672LE,292레지스터,2M9K,10890메모리 비트,전체118LAB. 가상핀338개인 인코더 단독 결과 |
| 배치 넷리스트 기능 검사 |창0/1·fineX1·헤더ID1/2를 포함한3프레임,6024바이트 일치. SDF 없는 기능 시험 |

수집 단계의 타일 비교와 완성 후 패킷 읽기가 서로 겹치지 않는 점을 이용해 RAM 읽기 포트를 공유했다. 초기4M9K를2M9K로 줄였고 동일 RTL 회귀를 반복했다. 헤더 함수의 전역 참조를 명시적 입력으로 바꿔 미사용 경고를 없앤 뒤, 실제 배치 넷리스트에서도 헤더·타일·팔레트 바이트가 유지됨을 확인했다. 최초 소스와 결과는 보존했다.

Quartus276027 RAM 경고와 상수 출력·핀/주기 경고는 남겨 두었다. 첫 행 쓰기의 이전 RAM 값을 소비하지 않는 구조이며, 검사한 기능 경로는 넷리스트에서도 통과했다. Questa vendor model의 vopt-13162 경고1건도 보존했다. 어느 결과도 외부 전기 타이밍이나 전체 NES 공동 배치 통과로 확대하지 않는다.

현재 범위는 불변16/32KiB CHR, 제한된 BG 모드, 프레임당 한16KiB 창이다. live PPU fetch 구분·매퍼 물리주소·속성·지원 모드 감시와 팔레트 변환은 입력 계약으로 남아 있다. 현재처럼 이미 확인된 참조 입력에서 통과했다는 사실만으로 일반 게임 화면을 지원한다고 주장하지 않는다. 프레임이 더 빨리 도착하거나 소비가 늦어 버퍼 소유권이 겹치면 명시적으로 실패하며, 프레임을 버리거나 NES를 감속하지 않는다.

## 다음 순서

1. 실제 PPU/매퍼 신호에 fetch·속성·모드 감시를 연결하고, 실제 실행 데이터를 같은 인코더로 검증한다.
2. NES+046+045+044를 함께 배치해 자원 여유와 메모리/클록 관계를 측정한다. 단독118LAB를 기존 잔여40LAB와 단순 합산해 판단하지 않는다.
3. SNES NCR1 런타임 소비자·표시 정책·기동/복구를 통합한 뒤 다음 실기 후보를 만든다.
