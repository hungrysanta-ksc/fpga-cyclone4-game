# NES101 SPI 전송 완료 순서 검증

SPI 진단 경로의 TXE→BSY 종료 순서를 수정했다. 지연 시작·위상·오류336경우와 기존 하위 통합34경우, 보호 제거4개·원본 반례2개 및 같은 ARM 검사에 통과했다. 강제 중단과 핀 차단은 미완료다.

PR50 병합 `6977f6c8fdd30f1f09d1fffc9357e9f7731e0b84`와 이전 head 포함을 확인했다. 정상 종료 순서를 수정하는 범위는 완료했고, 당초 예정한 강제 중단/모든 주변장치 통합은 완료하지 않았다.

## 문제와 수정

100의 `spi_tx_sync`는 BSY만 확인했다. 데이터 레지스터를 쓴 직후 아직 전송이 시작되지 않은 상태를 유휴로 판단할 수 있는 검사 순서다. 같은 위험이 수신 교환 시작에도 있었다. 실제100 함수와 지연 시작 모델을 연결하니 CS가 대기 바이트를 남긴 채 올라가는 경우와 새 바이트 대신 이전 바이트의 응답을 소비하는 경우가 각각 실패했다. 이 반례는 상태 모델이며, 최종 ARM 명령 지연으로 실기에서 같은 창에 들어간다는 증거가 아니다.

[ST RM0368 Rev6](https://www.st.com/resource/en/reference_manual/rm0368-stm32f401xbc-and-stm32f401xde-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)의 20.3.8(p580)과 DMA 설명(p581)은 송신 완료 확인에서 TXE를 먼저 확인하고 BSY를 확인하도록 설명한다. DR 쓰기와 BSY 설정 사이 지연 때문에 순서가 필요하다. 2026-10-08 공식 문서를 대조했다.

진단 `spi_tx_sync`와 `nes_return_spi_exchange`를 TXE=1→BSY=0 순서로 변경했다. 첫 대기가 실패하면 다음 대기를 실행하지 않는다. 교환 경로는 전송 소유권 아래 DR에 다시 쓰기 전까지 TXE를 중복 확인하지 않는다. 기존 공유 예산/최초 오류/개별25tick·1Mpoll을 유지했다. 두 단계의 합을 단일25tick 상한으로 주장하지 않는다. SPI를 동시에 사용하는 인터럽트/DMA가 없다는 진단 소유권 가정은 계속 필요하다.

생산 변경은 `stm32f4xx/spi.c`의 두 함수와 VERSION `CF86-SPI101`뿐이다. 진단 비활성 레거시 함수 본문, RTC099/main/load/실제SD/FatFS/CS 매크로/플랫폼은 그대로다. GBC의 새 실기나 사이클 동일성 검사는 아니다.

## 남은 오류 종료 경계

실제 `nes_diag_blocked` 본문은 USB IRQ 차단·SNES RESET 유지·상태 표시 뒤 CPU 루프에 들어간다. SPI SPE 해제나 GPIO AF 분리 명령은 없다. 오류 후 새 DR 접근/CS LOW 차단과 선택 해제는 기존100 보호로 유지되지만 이미 시작됐거나 대기 중인 하드웨어 전송 취소는 증명하지 못한다. phase04 test12에서 이 미완료 상태를 명시적으로 관찰했다. 정상 TXE→BSY 순서를 BSY 고착 상황의 강제 중단 방법으로 사용하지 않는다.

101 ARM/097 이미지를 기준으로 실제 오류 경로의 SPI 강제 중단·CS/SPE/SCK/GPIO 상태를 구현·검증하고, UART/printf·타이머·CIC·RESET 연결을 확인한다. 이후 최종 파일 쌍·044 복원·외부IO/공통고장·관측 가능한 제한 실기를 확정한다. 전기적 취소시간·외부IO·두 클록 정지/locked HIGH CE9us 반례는 여전히 별도다. 새 RTL/fit/STA/ASM/Questa/실기/설치 패키지는 없다. 준비도4완료/7부분/1미완료·설치false, 084/092실기 기준과 SMB3(J) mapper4/384KiB 목표를 유지한다.

## 실패 이력과 재현

phase01은 샌드박스 MinGW CreateProcess의 WinError623으로 컴파일을 시작하지 못했다. 적정 범위 실행으로 진행했고 자동 승인 거절은 없었다. phase02/03은 초기 ARM01 소스의 위상 시험 통과다. 초기 main01은 중복 TXE 검사로 보고 후 SRAM 검사248회 부근에서 공유 오류16을 냈다. 상한을 늘리는 대신 중복 검사를 제거한 ARM02로 전체 회귀를 통과했다. 첫 negative-sync01은 mutation 문자열이 두 곳에 걸려 추출 단계에서 거부됐고, 대상을 줄 경계로 한정한 negative-*02가 최종이다. 초기 파일과 Make 최초 의존성 실패/재시도 로그를 보존했다.

빌드는 고정100 도구를 재사용하여 출력 디렉터리와 보조 파일 이름에100이 남지만 실제 VERSION과 해시는101이다. 기존100 ARM 검사와 신규101 순서 검사를 모두 실행했다. 공개 도구와 실행 기록의 연결은 [재현 계약](../docs/nes-spi101-contract.md), [검증 메타데이터](spi101-verification.json)를 따른다. 로컬 동결 증거가 필요한 verifier를 공개 clone만으로 재현 가능하다고 주장하지 않는다.
