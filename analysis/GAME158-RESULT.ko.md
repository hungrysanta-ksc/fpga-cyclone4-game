# NES158 — MMC3 쓰기 전환의 선행 읽기와 실기 시험 준비

PR99 머지 `289674a14407459a0823b154ab425e9f731f62c9` 기준. **변경 경계의 기능 시험과 배치 검증을 통과하고158 실기 패키지를 준비했다. 실제 스테이지 진입 성공은 아직 확인하지 않았다.**

[실기 안내](../docs/nes-game158-instructions.ko.md) · [검증 기록](game158-verification.json) · [이식 참고 자료](../docs/nes-porting-reference-guide.ko.md)

## 문제와 수정

157 실기는 이전 CHR주소 `205A18`의 읽기가 끝난 뒤 CPU 읽기가 처리되고, PPU가 샘플하기 한 클록 전에 주소가 `217A18`로 바뀌었다. 새 요청은 즉시 승인됐지만 샘플까지 데이터가 도착하지 않아 오류2로 종료했다. CPU 요청만 앞당겨 끝내는 것으로 해결된다는 근거는 없다. 이 기록에는 매퍼 레지스터 쓰기나 이전 논리 PPU주소가 없어, **MMC3 쓰기가 실제 원인인지는 미확정**이다.

158은 원본 CPU 버스의 쓰기 신호 `mw_int`가 매퍼 갱신보다 먼저 제시되는 구간을 사용한다. 새 입력 `game158_preview_write`를 통해 MMC3의 선행 조회에만 예정된 `$8000` CHR모드 또는 `$8001` CHR뱅크 값을 적용한다. 실제 CHR주소와 레지스터는 기존 `cart_ce`에서 변경한다. R0/R1의 2KiB 정렬과 R2~R5 배치도 원래 규칙을 따른다.

실제 PPU주소·매퍼 상태·IRQ 입력·읽기 서비스·물리주소 태그 검사·샘플 기한·게임 클록은 변경하지 않았다. 예측이 빗나가도 다른 뱅크의 데이터를 정상 응답으로 통과시키지 않는다. ARM은 식별과 파일명만158로 변경했다. 기존 화면·패드·버튼 이력·오류 직전16클록 이력·STOP 및 메뉴 복귀 경로와156의 진단용 APU 채널 쓰기 차단을 유지했다. **오디오는 여전히 미완료**다.

경계 시험은 line193/dot8 충돌을 합성하고 CPU 버스와 매퍼 strobe를 직접 구동했다. CPU 쓰기를 commit9클록 전에 제시하는 고정 관계를 사용했다. 앞선 CPU읽기 위치12종은 **모든 CPU/PPU 쓰기 위상 검사나 실제 CPU의 게임 실행 재현이 아니다**. 실제 목표 ROM의 CHR바이트를 대조했지만 전체 게임을 시뮬레이션하지 않았다. `test01/02`의 앞선 좁은 범위 결과도 따로 보존했다. 매퍼536건의 소스/로그는 별도 해시로 고정했으며 `test03/result.json`의 기존 `sources` 목록에는 전환 시험 소스만 들어 있다는 차이를 기록한다.

## 배치와 패키지

선택 `fit02/asm01`: EP4CE15F17C8, 13731LE, 5005레지스터, 물리핀122/가상핀0, PLL1, **M9K56/56**, 메모리466864비트. 같은 클록 setup **+0.099ns**, hold **+0.171ns**, 조건부 PSRAM 여유 **+2.997ns**, SNES 데이터 경로 **200.492ns < 270ns**. 추가5.5ns 배치 예산도+0.099ns로 통과했다. 기존155 SDC와 클록·예외를 그대로 사용했으며 재배치 없이 명목 제약으로 다시 검사했다.

이는 전체 전기적 검증 완료가 아니다. 기존 비동기 reset recovery 음수 경로, PCB2ns 가정, 미계산 MTBF, 전체 외부IO 및 clock-halt 조건은 기존 제한으로 남는다. 임시 이력이 포함된 M9K56/56은 추가 코어 기능의 여유가 아니다. 원인이 확인되면 이력을 축소하거나 제거한다.

엄격한 MCU/FPGA 식별은 **67/E1**. `NES158-SMB3-CHR-PREVIEW.zip`은 새 ARM·FPGA, 동일 SMB3 ROM/표식, 변경 없는044 복원 파일을 포함한다. ZIP SHA256은 `ae825628138ba735991a52975e4bdb8447ee14ce1073743baa2e39b6867dbe62`. 배포물은 로컬 전용이며 ROM·바이너리는 Git에 넣지 않는다.

초기 materializer의 인스턴스 공백 단언 실패와 재사용 검사에서 식별67이 기존 SPI opcode67과 충돌한 정규화 실패는 도구 문제로 구분했다. 명시적 전방 변경 대조로 수정했다. 샌드박스의 호스트 DLL/라이선스 hostID 제한은 기존 허가된 호스트 실행으로 해결했으며 새 라이선스가 필요한 문제가 아니었다. 해당 초기 산출물과 최종 선택 결과를 구분해 보존했다.

## 다음 작업과 의미

이번은 단순 관측 추가가 아니라 **실제 게임의 CHR 공급 지연을 줄이는 이식 경로 수정**이다. 다음은 동일 SMB3에서 첫 Start → 1PLAYER Start 한 번 후 떼기 → 진행되면 이동·점프를 확인하고158 TXT 두 개를 받는 것이다.044/GBC 복원이나 고정 뱅크·전체 부팅 시뮬레이션을 반복하지 않는다.

다시 실패하면 기존16클록 이력으로 늦은 매퍼 쓰기와 PPU 논리주소 전환을 구분할 최소 근거를 확보한다. 추정만으로 예측 예외를 계속 추가하지 않는다. 게임이 진행되면 조작·스크롤을 먼저 확인한 후 음원 차단 해제로 간다. 원본 MiSTer의 분리된 SDRAM 요청 채널과 우리 공유 PSRAM 경로의 시간 계약을 우선 비교하는 기준을 [참고 가이드](../docs/nes-porting-reference-guide.ko.md)에 남겼다.
