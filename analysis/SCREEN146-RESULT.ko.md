# NES146 결과 — 긴 검정을 제거한 연속 표시 시험판

145는 긴 검정·고정 그림과 실제 메뉴 복귀를 통과했다.146은 같은 NES ROM·FPGA 회로를 유지하면서 첫12개 패킷을30 TV프레임씩 표시하고, 이후에는2 TV프레임 고정 후 다음 패킷을 요청한다. **시험판 제작과 로컬 검증은 완료했으며146 실기 결과는 대기 중이다.**

## 변경과 의미

전체2008바이트 패킷 수신·헤더 검사·COMMIT 후 수직 블랭크를 기다려1988바이트의 타일맵·열·팔레트를 전송한다.145의90프레임 검정과180프레임 고정을 제거했다. 전송 뒤 블랭크 상태를 확인하고, 이미 끝났다면 강제 블랭크를 유지한 채 다음 수직 블랭크까지 기다린 후 켠다. 정상 구간에서는 전송 시작과 화면 켜기가 같은 블랭크 안에 있다.

144와 달리 전송 종료 시점의 블랭크 확인·늦은 경우 대기와30→2프레임 속도 비교가 있다. 이것으로144의 원인이 확정되거나 실기 부분 갱신이 해결됐다고 주장하지 않는다. 단지 긴 대기로 확보한145 기준에서 연속 표시로 전진하는 실제 표시 코드 변경이다.

MCU는145의60초 관측·소유권·GPIO SPI·전량 대조·NMI·STOP·메뉴 복귀를 보존하고 파일/표식 이름만146으로 변경했다. 화면 글자NES144,80KiB 진단 ROM과CRC, 식별5E/D9는 그대로다. 기존142/144/145 배치의 ROM/MIF24576바이트만 바꾸고 ASM/CPF를 수행했다. 새MAP/FIT/STA·전체 NES 프레임 시뮬레이션은 반복하지 않았다.

## 검증 결과

| 검사 | 결과와 범위 |
|---|---|
| 실제 SNES CPU/PPU/DMA 정상 입력 | 30패킷/60,240바이트,395개 완전한 화면RGB 일치 |
| 의도적 혼합 패킷 | 같은395개 화면이 혼합된 입력과 정확히 일치; 소비자가 혼합을 임의로 숨기지 않음 |
| 표시 간격 | 처음12개30 TV프레임, 다음18개2프레임; 고정 중PPU/DMA/새패킷 쓰기 없음 |
| 정상 전송 구간 | 18,390~18,406 master clocks; 첫 프레임225→238줄, 이후240→253줄; 같은 블랭크 내 켜기 |
| 늦음 분기 주입 | 13번째 전송 뒤 블랭크 판독을 한 번0으로 주입; 다음 블랭크까지 유지 후 켜기,395개RGB 일치 |
| 인과 대조 | 테스트 전용ROM의 보호 분기 한 바이트를 무조건 분기로 변경하면30패킷 실행 후 대기 시점 검사에서 거부 |
| 잘못된 길이/헤더 | 각각 오류2/7로 거부 |
| MCU/ARM | 호스트21사례,186,792바이트ARM, 호스트 소스 일치 및NMI15store/0call/3DSB/2ISB 보존 |
| ROM·배치·패키지 | 전체65,536주소 대응,생성MIF전량 일치,기존RTL/QSF/SDC/배치·타이밍 보고서 해시 보존,ZIP13항목 검증 |

늦음 시험은 **블랭크 판독값을 주입한 분기 검증**이며 실제 보드에서DMA가 지연됐다는 증거가 아니다. 정상 전송 시간 역시 에뮬레이터 수치다. 실제 FPGA와SNES를 동시에 실행한 모형·아날로그 타이밍·물리적 갱신률까지 검증한 것은 아니다. 기존 전체IO/MTBF·E1/E2·8µs·양클록 정지CE9µs·ACK16ns실패·source-lock4·124격리를 유지한다.

## 보존한 초기 실패

첫 검사는 블랭크 시작 줄을240으로 고정해 실패했다. 실제 첫 전환은225줄, 이후는240줄이었고RGB는 일치했다. 실제 관측 범위와 같은 블랭크 안의 종료를 검사하도록 수정해normal02를 채택했다.

첫 보호분기 변이 생성은 공통 명령열5개가 일치해ROM 쓰기 전 거부됐다. 이어진negative01의ROM누락 실행 실패는 인과 대조 성공으로 세지 않았다. 유일한 문맥을 지정한negative02에서 실제30패킷 완료 후 정확히 대기 시점 조건이 실패한 것을 확인했다. 초기 자료는 함께 보존했다.

## 실기 시험과 다음 경계

[146 실행 안내](../docs/nes-screen146-instructions.ko.md)에 따라 한 번 적재한 뒤 표시 시작부터 메뉴까지 촬영하고두TXT를 받는다. 같은145/044/GBC를 반복하지 않는다. 실제A/B 교대 순서는 보장하지 않으며30/2프레임 대기는 실제 게임FPS가 아니다. 정상 경로에서 긴 검정이 사라졌는지, 빠른 구간에서 부분 갱신·혼합·깜빡임이 생기는지 확인한다.

약9분 적재·대조 단축, 실제 입력·SMB3(J) mapper4/384KiB·오디오·게임 호환성은 남아 있다.146 실기 통과 전 정상 속도 화면 완료로 승격하지 않는다. 다음에는 받은 실기 결과에서 처음 실패한 경계만 수정하거나, 통과하면 입력·첫 게임 방향으로 전진한다.

재현 소스·선택 결과·해시는 [검증 메타데이터](screen146-verification.json)에 있다. 기존145 제작 증거와 실기 기준은 수정하지 않았다.
