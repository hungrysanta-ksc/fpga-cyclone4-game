# NES149 마리오 적재·대조와 하드웨어 SPI 연결

실제 SMB3(J)의 PRG256KiB+CHR128KiB를 MCU가 적재하고 전부 대조할 수 있도록 연결했다. 종전 GPIO 비트 전송은 게임 경로에서 SPI1 하드웨어 전송으로 교체했다. **MCU 빌드와 변경 경계 시험은 완료했지만, 게임 화면·패드·새 FPGA top 통합이 남아 있어 설치용 패키지는 아직 없다.** PR91 초안에147~149를 함께 유지한다.

## 변경과 의미

- 게임 경로는393,216바이트, FPGA 식별5F, BEGIN 인수2만 허용한다. 실제 목표 ROM의 헤더·전체 길이·CRC32 `5a04eed7`을 확인하고, 원본 재읽기·전량 대조·마지막 읽기와 닫기 성공 후 FINISH·검증 후 START를 유지했다. CRC는 우발적 변경 검출용이다. 로컬 준비기는 기존 SHA256으로 목표 ROM도 확인한다.
- GPIO로 각 비트를 출력하던8바이트 명령을 SPI1 모드0·APB2/32로 전송한다. 기존84MHz 설정에서 명목2.625MHz다. FPGA의 명령·CRC·ACK 규약은 바꾸지 않았고 DMA와 새 대용량 프로토콜도 도입하지 않았다.
- 기존 GPIO 소유 구간 안에서 프레임 동안만 AF5로 전환한다. 매 상태 확인에서 CF86 공유 오류/RDY/DONE/소유권을 검사하며 TXE/RXNE/BSY 대기는 각각512회로 제한한다. 정상 완료는 TXE와 BSY 해제까지 확인하고 원래 비활성 SPI/GPIO 상태로 돌아간다. 오류는 CS 해제·SPI 비활성화 후 지속 오류로 남기며 해당 명령을 재전송하지 않는다.
- 하드웨어는 한 바이트를 자동 전송하므로 종전 비트별 검사와는 다르다. 명목 바이트 시간은 약3.05µs지만 실제 전체 보호 반응 시간8µs를 입증한 것은 아니다. 기존 CSS/NMI의 SPI 비활성화·주변장치 리셋 경로는 그대로 유지했다. 완료 순서는 [ST RM0368의 SPI 설명](https://www.st.com/resource/en/reference_manual/DM00096844.pdf)을 따른다.

기존80KiB 적재·대조518.99초를384KiB로 단순 확대하면 약41.5분이다. 새 경로는 바이트마다 반복하던 GPIO 지연을 제거한다. 명목 전송선 시간과 프레임당8µs만 계산한 바닥값은 약64초지만, 소프트웨어 검사·인터럽트·SD·설정 시간이 빠져 있다. **실기 로딩 시간이나 목표 시간으로 사용하지 않는다.** 다음 실기 로그의 적재/대조 구간으로 측정한다.

선택 결과는 arm04/armcheck02/host02/spi01이다. arm01 준비기의 중복 헤더 일치, arm02 선언 순서, arm03 긴 버전 문자열 빌드 실패를 보존했다. 호스트 도구의 제한 환경 DLL 오류는 별도이며 RTL·라이선스 실패로 분류하지 않는다. 최종 버전 표시는 `NES-GAME149-DEV`다.

148의 실제 ROM30프레임 근거는 재사용했다. CPU/PPU/맵퍼/PSRAM RTL과 기존147 적재 프로토콜은 변경하지 않았으며 같은30프레임·A/B·044 복원은 반복하지 않았다. ROM·바이너리·사용자 자료는 Git에 넣지 않는다.

## 남은 작업과 다음 순서

1. 147/148 코어·19비트 적재·5F 식별을 실제 보드 top에 연결한다.149 MCU는 이 조합을 기다리는 빌드 후보이며 기존146 FPGA와 짝지어 설치하면 안 된다.
2. 고정 팔레트·스크롤0·스프라이트 없는 NCR1 진단 표시를 실제 게임의 스크롤·CHR 전환·스프라이트가 나오는 출력으로 연결하고 패드를 붙인다. 현재 관측 페이지D9와 유한 RUN/STOP 골격은146에서 이어왔으며 게임 화면 구현 완료를 뜻하지 않는다.
3. 바뀐 경계와 필요한 배치/타이밍을 확인해 실제 SMB3 시험 패키지를 만든다. 목표는 마리오 화면·이동·스크롤과 실측 로딩 시간이다. 추가 진단 체계나 unchanged 전체 시험을 선행 조건으로 넣지 않는다.

게임 저장·오디오·다른 맵퍼는 후속이다. 전체IO/MTBF/E1E2/8µs/양 클록 정지CE9µs/ACK16ns/124격리/source-lock4의 기존 미완료 항목도 유지한다. 이 변경은 디버그 항목 확장보다 **실제 게임 ROM을 적재하는 실행 경로와 긴 로딩 해소**에 해당한다.

## 재현

`tools/nes_game149.py --baseline <private probes> --rom <target local NES> --out <new ARM directory>`로 frozen146에서 소스를 만든다. `build_nes_game149_arm.ps1`은 기존 ARM/host 도구와 해시 검증한 mini 이미지를 받는다. `test_nes_game149_host.py`는 같은 ARM 소스로 두 호스트 시험을 실행하고, `check_nes_game149_arm.py`는 링크된 바이너리를 확인한다. `test_nes_game149_spi.py`는 frozen148/core03을 `--prepared`로 받고 기존 FLOAT 래퍼에서 실행한다. 완료된 증거 확인은 `verify_nes_game149.py --baseline <private probes>`만 사용한다.
