# NES143 결과 — 표시 경로 비교와 기존 영상 판정 정정

## 먼저 정정할 판단

**141/142의 사진 외형만으로 정상 영상 실패를 확정했던 판단을 철회한다.** 기존 진단 ROM의 정상 에뮬레이터 결과도 작은 점이 빽빽한 잡음 모양이다. 143의 기존 NES 표시 3프레임은 동결된 142의 정상 RGB 3프레임과 바이트 단위로 동일하다. 기존 자료만으로는 사용자가 본 화면과 예상 진단 무늬를 구별할 수 없다. 사용자 관측은 그대로 유지하며, 실기 픽셀이 정상이라고 반대로 확정하는 것도 아니다.

142의 stage6/error0/flags7/완료72회는 SNES 화면 프로그램이 진행했다는 근거다. 화면이 거의 움직이지 않았다는 관측도 유지한다. 대각선 띠는 사용자 설명에 따라 카메라/CRT 현상으로 제외하며, 무음은 오디오 미구현 상태와 구분한다.

## 변경과 작업 의미

PR88 머지 `47460aa`를 기준으로 한 번의 실행에서 네 경로를 비교한다.

| 단계 | 표시 | 비교 목적 |
|---|---|---|
| A | 파란 배경 | 타일·패킷 없이 배경색과 표시 설정 확인 |
| B | 왼쪽 빨강·오른쪽 청록 | SNES CPU가 직접 작성한 타일·타일맵·팔레트 확인 |
| C | 촘촘한 반복 무늬 | B의 맵·팔레트를 유지하고 타일만 기존 ROM DMA로 교체 |
| D | 기존 NES 진단 무늬 | 기존 패킷→WRAM→VRAM 경로와 정상 기준 비교 |

A~C는 각각 180회 수직 귀선을 기다린다(약 3~3.6초). MCU의 전체 표시 대기는 600회×50ms, 명목 30초다. RUN 중 기존 SPI73 상태를 읽어 A/B/C/D 비트 1/2/4/8을 누적한다. STOP 이후 TXT에 기록하는 `screen_phase_mask`가 15면 네 단계가 모두 관측된 것이다. D 완료의 stage99는 143 프로그램 표식이고, 전송 완료 횟수는 기존 stage6에서 센다. 이 값은 실제 TV FPS나 올바른 픽셀 수가 아니다.

142의 회로·배치·ID 5E/D9·CPU/PPU/reader/cache는 그대로다. 바뀐 표시 프로그램 HEX와 생성 MIF 24,576바이트를 대조하고 ASM만 실행했다. 새 143 파일명·펌웨어·해시로 조합을 구분한다. FPGA ID를 여러 개 무조건 허용하지 않는다. 오류 종료·STOP·메뉴 복귀 경로를 유지하며 RUN 중 SD 쓰기는 하지 않는다.

적재 전 짧은 표시도 검토했으나, 현재 SNES 응답은 검증된 RUN에서만 열린다. 빠른 표시를 위해 loader 검증 상태나 reset 보호를 우회하지 않았다. 이번에는 기존 약 9분 적재를 한 번 수행한 뒤 네 경로를 비교한다.

## 검증 결과

- 실제 65816/PPU/DMA 에뮬레이터에서 A/B/C 각 256×239픽셀을 독립 예상값과 정확히 대조했다. D의 정상 3프레임도 기존 142 RGB와 동일하며, 길이·헤더 오류 2사례를 검출했다. MMIO는 Lua 모델이며 실기 버스와 동시 시뮬레이션은 아니다.
- 실제 MCU 소스의 호스트 21사례가 통과했다. 정상 30초/600관측·mask15/stage99, 오류 시 조기 종료·최초 오류 보존·STOP·base/menu 예산 복원을 확인했다. 초기 host01~03 실패는 과거 모형의 RUN 명령 상한·203관측·20,000count 기대값이 남았기 때문이며 보존했다. 최종 host04의 공통 MCU 소스는 ARM과 동일하다.
- 실제 decoder 12사례로 단계 비트 누적, 알 수 없는 stage/error 보존, 잘못된 ID·스키마 거부를 검사했다. 새 ROM 전체 64KiB의 프로그램·atlas·벡터 버스 대응을 Questa로 확인했다.
- ARM 186,764바이트, 강한 NMI의 15store/0call, 호스트 소스 일치를 확인했다. 142 배치의 같은 클록 setup +0.185/hold +0.150ns 및 조건부 IO 근거를 재사용한다. 보드 실측·전체 IO·MTBF 승인으로 확대하지 않는다.
- ZIP 13개 구성 항목, 압축 FPGA 역변환, 조합 해시를 검증했다. 실제 에뮬레이터 RGB에서 만든 `EXPECTED-SCREENS.png`를 동봉했다. 새 실기 결과는 대기 중이다.

변경 없는 CPU 전체 프레임·fullwrite·상태 RTL 40검사·MAP/FIT/STA는 반복하지 않았다. 최초 동결 시도는 제외된 생성 DB의 Verilog 파일을 ASM 보관본에서도 찾는 목록 검사에서 중단됐다. 부분 보관본을 유지하고 DB 생성 파일을 입력 목록에서 제외한 `evidence-final`을 완성했다. 이는 회로나 시험 실패가 아니다.

## 다음 시험과 완료 범위

[실행 안내](../docs/nes-screen143-instructions.ko.md)에 따라 143을 한 번 실행하고 두 TXT, A/B/C/D 관찰, 자동 메뉴 복귀 여부를 받는다. A/B가 정상이고 C/D가 기준과 비슷하면 잡음형 이미지를 고장으로 다루던 가설부터 수정하고, 명확한 NES 패턴과 입력·게임 연결로 전진한다. 차이가 있으면 처음 갈라지는 경계만 수정한다.

비교 시험판과 필요한 로컬 검증은 완료했다. 정상 실기 표시 확정, SMB3(J) mapper4/384KiB 구동, 패드, 오디오는 미완료다. 동일 142/044/GBC 시험은 반복하지 않는다. 141의 ACK16ns 실패, E1/E2, 8µs, 양 클록 정지 CE9µs, source-lock4, 124 격리 사항은 보존한다.
