# NES CHR 상주·사전 적재 결과 — NES-P1-RESIDENT-004

2026-10-05. SPDX-License-Identifier: MIT.

**준비된 8개 CHR 뱅크를 한 프레임 경계에서 함께 전환했다. 진단 OFF/ON 각각
128프레임·15회 전체 전환에서 화소 차이와 전송 기한 초과가 없었다. 단, 이 시험은
다음 CHR 집합의 데이터가 미리 주어진 합성 입력이다. 실제 게임의 예고 없는
뱅크 변경을 모두 처리했다는 뜻은 아니다.**

[이전 캐시 결과](CACHE-RESULT.ko.md), [계약·재현](../docs/nes-resident-contract.md),
[원시 감사](resident-verification.json), [소스·증거 목록](resident-artifacts.json).

## 필요한 타일과 구현한 방식

32개 합성 상태의 전체 256×240 좌표에서 BG 타일 키를 계산했다. 각 상태는
8개 창마다 32타일, 합계 256개의 서로 다른 CHR 타일을 참조한다. 원본 2bpp
데이터로 4,096B다. 이 데이터가 전부 새로 필요해 현 전송 경로로 한꺼번에
적재하면 DMA만 32,768 clocks가 든다. 239줄 출력의 blank 22줄은 30,008 raw
clocks이므로 CPU·팔레트·부분 패치를 제외해도 들어가지 않는다. NES PPU의 실제
fetch를 수집한 결과나 모든 렌더링 방식의 불가능 증명은 아니다.

이번 구현은 BG CHR에 16KB를 배정해 표시용·준비용 8KB 집합을 유지한다. 각 집합은
8개 1KB 창이다. 한 프레임에 준비용 창 하나씩 채우고 8개가 모두 완료되면
BG3 타일 기준 주소를 바꿔 전체 집합을 전환한다. 지도·타일 번호를 대량 갱신할
필요가 없다. 한 창의 사용하지 않는 타일도 전송하므로, 4KB working set을 촘촘히
배치한 타일 단위 캐시는 아직 아니다.

4개 논리 집합은 banks 0..7/gen0, 8..15/gen0, 0..7/gen1, 8..15/gen1이다.
8프레임마다 전환하며 두 물리 영역을 계속 재사용한다. 화면은 매 프레임 스크롤,
스프라이트 위치, dot 팔레트 부분 패치를 갱신한다. 색·프레임·게임 속도를 줄이는
정책은 넣지 않았다.

## 소유권과 시간 배치

새 패킷은 이전 화면이 표시되는 동안 읽기 전용으로 검사한다. 캐시 완료 마스크와
집합 번호, 반대쪽 준비 영역, 순차 적재 마스크, 키·길이·범위를 검사하고 VBlank를
기다린다. 이 시험의 공급원은 변경되지 않는 ROM이므로 검사 후 내용이 바뀌지 않는다.
실제 FPGA 패킷에도 같은 소유권/불변성이 필요하지만 아직 구현하지 않았다.

VBlank에는 비표시 부분 패치를 stage하고, 취소 검사 후 CGRAM/OAM/스크롤/지도 및
BG3 기준 주소를 확정한다. 그 뒤 **새로 표시하지 않는 CHR 영역**에 다음 집합의
1KB를 적재한다. 전환 프레임에도 이전 영역을 먼저 덮어쓰지 않는다. 완료 비트는
DMA 뒤에 기록한다. 원시 추적에서 표시 기준 주소·영역·전송 위치·순서를 검사했다.

## 결과

| 시험 | 캡처 | 결과 |
| --- | ---: | --- |
| OFF | 128 | 128 commit, 15회 전체 전환, 화소 차이 0 |
| ON | 128 | 동일; OFF와 모든 화면 해시 일치 |
| 전환 프레임 8의 stage 뒤 reset 요청 | 64 | 63 commit/1 cancel; 이전 화면과 두 캐시 영역의 키 보존, 같은 요청 재시도 |
| 미리 적재하지 않은 집합 요청 | 32 | 프레임 8 E5, 해당 요청 DMA 0B, 이전 화면 유지 |
| 마지막 준비 완료 비트 누락 | 32 | 프레임 8 E5, 해당 요청 DMA 0B, 이전 화면 유지 |
| 올바른 키에 이전 집합 데이터 적재 | 64 | 16프레임, 총 79,588화소 오류 검출 |
| 준비용 DMA를 표시 영역으로 잘못 전송 | 64 | 2회 소유권 위반과 26프레임/136,408화소 오류 검출 |

마지막 네 항목은 실패 원인이 기대와 일치해야 감사가 통과한다. 오래된 데이터와
잘못된 주소의 화면 오류는 RGB 비교에서 검출했다. 런타임 CRC로 내용을 거부한
것이 아니다. 에뮬레이터 자체 frame skipping은 비활성화했고 관측 Lua는 PPU나
메모리에 쓰지 않는다.

| 측정 | OFF | ON | reset 포함 |
| --- | ---: | ---: | ---: |
| 최장 VBlank 작업 | 21,496 | 22,288 | 21,606 |
| 최소 deadline 여유 | 8,400 | 7,606 | 8,288 |

단위는 SNES master clocks다. 읽기 전용 사전 검사는 별도로 최대 2,816 clocks이며
실제 활성 표시 구간에서 수행된 것을 확인했다. VBlank 수치에서 그 작업을 숨긴
것이 아니라, DMA 없는 별도 단계로 원시 시각과 함께 기록한다.

매 프레임 전송량은 CHR 준비 1,024 + 부분 패치 544 + 지도 64 + CGRAM 384 +
OAM 60 = **2,076B**다. 초기 forced blank 전송은 별도 33,792B다. DMA 비용에
CPU/설정 5,120 및 진단 768 clocks를 예약한 모델은 22,496 clocks로, 기존 모델의
80% 목표 23,299.2 이내다. 외부 SRAM/MCU 지연은 포함하지 않는다.

미적재 영역을 초기화하지 않은 첫 부정 시험은 실행마다 오류 화소 수가 달랐다.
최종 후보는 준비 영역도 set 0의 바이트로 초기화하되 키/완료 마스크는 무효 상태로
유지한다. 초기 전송이 8KB 늘었으며 정상 반복 비용은 같다. 소유권 오류 시험을
다시 실행해 64개 화면 해시가 전부 일치하는 것을 확인했다. 이전 실행은 보존했다.

## 사전 적재 조건과 미해결 사항

- 이번 일정은 첫 적재를 전환 8프레임 전에 시작한다. ROM에 이미 컴파일된 미래
  CHR 데이터와 전환 순서를 사용한다. 실제 게임에서 그 정보를 이 시점에 얻을 수
  있는지는 입증하지 않았다. 특히 CHR RAM의 미래 쓰기를 예측한 것이 아니다.
- 미적재 집합 요청 때 E5로 정지하는 것은 개발 중 오류 경로다. 게임을 멈추거나
  프레임을 생략해 정상 지원으로 간주하는 제품 정책이 아니다.
- reset 주입은 불변 공급원의 같은 요청을 취소·재시도하는 시험이다. 실제 생산자가
  reset으로 데이터를 바꿀 때 준비된 캐시를 어떻게 무효화할지, commit 중 reset,
  비동기 reset/CDC/MCU ack는 미완료다.
- 256×239 화면만 비교했다. 원본 마지막 줄의 출력 정책은 아직 승인되지 않았다.
- OBJ CHR는 고정이다. 일반 fetch working set, scanline/dot bank 전환, mapper IRQ,
  강조색, 실제 NES CPU/PPU, 전체 fit/STA 및 SMB3 실기는 아직 미완료다.
- 프레임 번호 wrap·장기 실행은 이 128프레임 시험으로 검증하지 않았다.

다음 판단에는 실제 fetch 시점의 물리 CHR 주소·변경 시점과 사용 집합이 필요하다.
현재의 합성 사전 적재 성공을 근거로 P1 전체를 통과시키지 않는다. 주소 추적을
얻을 수 있는 기능 시뮬레이션 경로를 먼저 정리하고, 사전 적재 없이 이미 상주한
타일만으로 처리 가능한 비율과 미적재 burst를 측정하는 것이 다음 과제다.

기존 P1/STREAM-002/CACHE-003 소스·증거와 실험 초안은 보존했다. GBC 기준 소스
152개 및 Quartus 입력/packed boot 검사를 통과했다. 공통 FPGA/MCU 변경이나
상용 ROM 복사·패키징·SD 배포는 수행하지 않았다.
