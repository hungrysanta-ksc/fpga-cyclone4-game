# NES 다음 작업 인계 — 053 이후

완료 기준은 [현재 상태](README.md)와 [053 결과](../../analysis/ROM-BOOT-RESULT.ko.md)다. 이번 공개 정리는 001–053의 자체 작성 코드·계약·요약과 공개 메모리 시험을 기록한다. 054 MCU SPI 연결 구현은 아직 시작 전이며 완료로 표시하지 않는다.

## 다음 구현: MCU SPI 적재·상태 연결

1. `tools/nes_h1_sampling.py`로 생성하는 044의 SPI/버스 경계에서 출발한다. 오래된 034 기반 HDL과 035 MCU를 직접 조합하지 않는다. 실제 C가 SCK 상승 후 +2µs에 읽는 MISO를 유지하는 036 이후 수정이 필요하다.
2. BEGIN(고정 PRG64KiB + CHR16/32KiB), DATA, END, START, STOP과 상태 읽기를 정의한다. 명령 길이·부분 SS 종료·중복/누락·busy·오버플로·고장 후 복구를 먼저 명시한다. 적재 길이와 ROM 무결성 검증을 별도 상태로 취급한다.
3. 053 `nes_rom_loader`의 완료/ready 신호와 연결한다. 쓰기 중 오류에는 펄스와 hold를 마치고 정지한다. MCU/FPGA의 하나의 소유자만 PSRAM을 구동한다. 실패한 이미지는 실행하지 않는다.
4. 실제 MCU C GPIO 파형을 캡처해 같은 RTL에 재생한다. 정상 명령뿐 아니라 CS 중단·잘못된 순서·실행 중 쓰기·STOP/RESET을 검증한다. 독립 C mock 통과만으로 경계 연결을 승인하지 않는다.
5. 공통 reset 및 코어/캐시/패킷 초기화를 정의한다. 049 RAM scrub 완료 전 코어를 실행하지 않는다. STOP 보존과 RESET 무효화를 혼동하지 않는다.

## 이어지는 보드 관문

- 실제 NES/메모리 클록·reset: SNES_SYSCLK/PIN_A9는 후보일 뿐 주파수·지역·라우팅 미확인이다. 84MHz/4를 NES 기준 클록이라고 가정하지 않는다.
- 실제 SNES NCR1 소비자, frame deadline/backpressure, 오류 복구를 연결한다. 게임 코어를 임의로 늦추거나 프레임을 버려 통과시키지 않는다.
- 전체 핀/PLL/로더/소비자를 넣은 공동 fit, 외부 IO와 CDC의 실제 제약을 확인한다. 053의 LAB 여유 34개는 완성 보드 여유가 아니다.
- 후보 ID·페이지 진행·로그·중단/복구를 갖춘 새 MCU/FPGA 쌍을 검증한 뒤에만 실기 패키지를 준비한다. 현재 실기 기준은 044이며 반복 플래시를 요구하지 않는다.

## 유지할 증거

044 사용자 보고와 로그, 041 실패, 043/044 원래 SDF 실패, 050 지연 실패, 051 지연 범위, 053 초기 실패와 최종 통과를 보존한다. 과거 원본 파일/manifest는 로컬에서 불변이다. 공개용 현재 문서의 갱신을 기존 체크포인트의 재검증 결과라고 부르지 않는다.
