# 현재 NES 인계

**902 · 최종 ACK 확인 주기 대조 완료.** MMC897에서 네 입력 블록마다 E0를 확인해 재생 최장 대기를 9.58→1.78ms로 줄였으나 네 조건 모두 표시 간격 합은 같았고 EA까지의 다음 입력이 16→8블록으로 줄었다. 실기 기준은 MMC897을 유지한다. 다음은 MMC901 세대 1001 유형의 마지막 타일을 token별로 FPGA 준비·E8·E1·65816 수락까지 실기에서 연결하는 일이다. [실기·재생 비교](../../docs/nes-ack902-results.ko.md)

**MMC900·901 실기 완료.** 무입력 60초·STOP·메뉴 복귀 모두 통과했다. 데모는 17.97→16.23 FPS였다. 두 BIN에서 작업량이 연속 일치한 뒤 구간 9장은 18→21 VBlank였고, 마지막 tile 수락 전 지연과 직전 ACK의 ARM 확인 후 다음 입력이 늦어진 사례를 구분했다. 다음은 타일 준비→E8과 직전 ACK→다음 입력의 거래를 분리 재생하는 일이다. [실기 결과·해석 범위](../../docs/nes-hardware900-901-results.ko.md)

**MMC900·901 · MMC872·897 화면별 실기 계측판 준비.** 같은 세대의 입력 완료부터 최종 ACK까지 30–35초와 55–60초에 기록한다. 최종 링크 재생에서 MMC901은 두 위상의 두 구간 표시 간격을 유지했고 MMC900은 일부 구간에서 1 VBlank가 추가됐다. 다음은 두 실기 BIN을 세대·뱅크·작업량으로 대응시키고 이 계측 영향을 감안해 첫 지연 단계를 찾는 일이다. [설치·분석 순서](../../docs/nes-mmc900-901-trial.ko.md) · [최종 링크·보드 검증](../../analysis/frame900-901-package.json)

**899 · OAM 재사용 순서 대조 완료.** MMC897에서 1970·3470의 OAM 발행은 2.20–2.62ms 앞당겨졌으나 두 시작 위상 모두 표시 간격은 2 VBlank였다. 다음은 MMC897 실기에서 한 VBlank를 잃은 세대와 마지막 map·tile 수락부터 공개까지의 시각을 식별하는 작업이다. [결과와 재현](../../docs/nes-oam899-results.ko.md)

**898 · MMC897 후반 출력 지연 비교.** 같은 화면 작업량에서 897은 1970·3470의 OAM 재사용 명령을 두 section 5 패킷 뒤에 발행했다. SEAL 발행이 0.46–0.96ms 늦었지만 두 시작 위상의 표시 간격 합은 같은 구간의 872와 같았다. 다음은 이 순서만 바꾼 대조와 실기 세대별 마감 계측이다. [두 실기 구간과 같은 화면 재생](../../docs/nes-latency898-results.ko.md)

**MMC897 · 일반 실행 60초·메뉴 복귀 실기 통과.** 오프닝 531장(18.31 FPS), 데모 502장(16.73 FPS)으로 MMC872보다 각각 12장 증가·21장 감소했다. 다음은 SRAM 송신을 유지한 채 30–35초와 55–60초에서 비슷한 map·OBJ·BG 작업량의 수신 및 출력·최종 ACK 지연을 대조하는 일이다. [실기 결과](../../docs/progress/pr-170.md#mmc897-무입력-60초-실기-결과)

**MMC896 · SRAM에서 첫 입력 제안 확인, STOP·메뉴 복귀 성공.** 같은 설치의 Flash 실행은 START 직전 기록 뒤 검은 화면에서 멈췄다. SRAM은 D0를 1,248회 조회했고 입력 CRC 오류는 0이었다. 다음 검증은 일반 실행의 네 D0 송신 지점을 SRAM으로 통일하고 D1·D2, 첫 화면 최종 ACK, 메뉴 복귀까지 확인하는 것이다. [실기 결과](../../docs/progress/pr-170.md#mmc896-sramflash-실기-결과)

**MMC892 · 첫 벡터 공급 수정, 실기 부팅 진단 통과.** MMC891의 `03`을 실제 RAM 초기화와 브리지 회로로 재현했다. ARM은 첫 E0가 무응답일 때 SPI73의 현재 active를 확인한 뒤 RESET을 해제한다. 네 위상에서 두 벡터와 첫 stage 쓰기를 확인했다. 전체 FIT·STA와 STOP·메뉴 경로를 통과했다. NES BOOT 892 실기 1회에서 약 240ms에 stage 3에 도달했고 STOP·base 복구·메뉴 복귀를 확인했다. 일반 실행은 222,470ms의 DISPLAY_NEXT에서 기록이 끊겼고 검은 화면에서 본체 RESET으로 메뉴 복귀하지 못했다. 다음은 실제 ARM 첫 프레임과 STOP 경계 확인이다. [검증 결과](../../docs/nes-reset892-results.ko.md) · [설치 순서](../../docs/nes-mmc892-trial.ko.md)

**MMC891 · 실기에서 벡터 읽기 주소만 관측.** NES BOOT 891은 384KiB 검증·START 뒤 stage 0, 누적 `03`으로 5초 뒤 종료했다. STOP·base·실제 메뉴 복귀가 성공했다. 다음은 두 벡터 스트로브에서 세션 해제·주소 tag·ROM 출력 허가를 대조하는 작업이다. 실기 FPS 기준은 MMC872다. [실기 판독과 대조 조건](../../docs/nes-boot891-results.ko.md#nes-boot-891-실기-결과)

NES BOOT 890도 stage 0에서 5초 시간 초과 후 메뉴로 복귀했다. 다음은 RESET 해제·벡터 읽기부터 첫 $7000 쓰기까지의 검증이다.
