## 현재 위치와 바로 다음 작업

**MCU 적재·대조 연결까지 완료했으며 다음은 실제 게임 보드 top·화면·패드다.** 모든 코어에서 최소 필수 구현 확인 뒤 실제 목표 ROM 실기를 우선한다. 사용자는 A/B만 보는 시험을 끝내고 마리오 이동·스크롤로 판단하도록 했다. 같은30프레임·A/B·044 복원이나 변경 없는 전체 적재 시험을 반복하지 않는다. 공통 기준은 docs/development/MILESTONE-WORKFLOW.ko.md다.

PR90은 c38bad708988e301df336c227f4ea78cdad77b69로 머지됐다. 게임 작업 PR91은 master 기준 초안이며147~149를 이어간다. GitHub는 hungrysanta-ksc 인증과 저장소 개인 작성자 설정을 사용한다. 선택 창이 뜨거나 인증이 실패해도 퇴사 계정으로 전환하지 않는다. 사용자가 머지한다.

1. 147/148의 코어·전체 캐시 태그·19비트 적재/검증·5F 식별을 실제 보드 top에 연결한다.149 MCU를 재사용하며 식별을 무조건 여러 개 허용하지 않는다.
2. 고정 팔레트·스크롤0·스프라이트off인 NCR1 진단 출력을 게임의 스크롤·CHR 전환·스프라이트가 나오는 출력으로 연결하고 패드를 붙인다. 현재의146 계승D9 관측·유한 RUN/STOP 골격을 게임 영상 완료로 해석하지 않는다.
3. 바뀐 경계와 필요한 배치/타이밍을 확인해 SMB3 실기 패키지로 간다. 첫 목표는 실제 마리오 표시·이동·스크롤, 적재/대조 시간 실측이다. 새 대용량 프로토콜이나 추가 진단 체계 완성을 선행 조건으로 만들지 않는다.

설치 가능한 새SD패키지는 없다. **149 MCU와 기존146 FPGA를 짝지어 배포하지 않는다.** 새 전체보드 fit/게임 화면/패드/오디오는 아직 미완료이며 실제게임 속도도 측정하지 않았다. 저장·오디오·다른 맵퍼는 후속이다.

## 재사용할 완료 근거

149 arm04: 실제 SMB3(J) PRG256KiB+CHR128KiB, 총393216바이트, 식별5F/BEGIN2를 MCU에 연결했다. 헤더/파일크기/CRC와 전량 대조, 마지막 재읽기·닫기 성공 후 FINISH·검증 후 START를 유지한다. 바이트 명령 자체는 기존147 규약이며 새 벌크 명령은 없다. GPIO 비트 전송을 SPI1 모드0 APB2/32 명목2.625MHz로 바꿨다. 프레임 동안만 AF5로 전환하고 원래 비활성 SPI/GPIO로 복귀한다. 오류는 지속 오류로 남기고 재전송하지 않는다.
