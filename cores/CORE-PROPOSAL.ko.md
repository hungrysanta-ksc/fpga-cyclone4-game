# 새 코어 제안서 양식

## 식별과 범위

- core ID / 내부 후보:
- 담당 작업·관련 이슈:
- 첫 제품 목표 범위 / 제외할 확장 기능:
- 지원 보드와 필요한 입력 장치:
- 입력 파일 형식·판별·코어 파일 이름:

## 원본과 재현

- upstream URL / 고정 commit:
- 저작권·라이선스·고지·필수 생성 소스:
- 도구와 독립 빌드 방법:
- 공개 가능한 자작 fixture / 로컬 전용 시험 구분:

## 예산과 통합

- LE / M9K 블록 / PLL / 외부 RAM: 측정값 또는 미측정.
- 코어 클록·reset·CDC·I/O 요구:
- 최대 프레임·음향 처리량과 출력 변환 정책:
- 메모리 맵·버스 소유권·타임아웃:
- 배터리 저장·RTC·상태 파일 스키마 및 core ID 구분:
- 공통 MCU/renderer 변경과 기존 코어 회귀 범위:

## 진입·중단 기준

- 다음 한 번의 실험이 판정할 질문:
- 최소 성공 조건 / 결과 파일·소스 해시:
- 실패 시 축소·중단 조건:
- 독립 합성 → 통합 → 실기 → 제품 편입의 남은 항목:
- 제품 버전은 편입 시 결정. 아직 검증하지 않은 지원을 표기하지 않기.
