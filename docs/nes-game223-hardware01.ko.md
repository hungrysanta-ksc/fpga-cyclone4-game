# NES223 실기 결과: 60초 플레이와 메뉴 복귀 통과, 전송량 감소 확인

PR122 `codex/nes-geometry-ingress-223`. 이 결과가223 시험판 준비/실기 미수집 기록보다 우선한다. 파일223은 ARM223과 FPGA224/source02를 짝지은 시험판이다. 이번에는 결과만 기록했고 펌웨어·RTL·패키지를 변경하지 않았다.

## 작업 의미

geometry 묶음 전송의 효과가 실제 SMB3 실행에서 관측됐다. 사용자가 게임·사운드·메뉴 복귀 정상과 추가 프레임 개선을 보고했고, 로그의 화면 완료 증가와 완료당 D1 전송량 감소도 같은 방향이다. **60fps 달성은 아직 아니다.** 이번 결과로 다음 구현을 스크롤 맵의 반복 처리·전송 감소에 집중할 근거를 확보했다.

## 실행·종료 판정

- ROM393216B load/compare 전부 통과. RUN/ROM/STOP 오류0, plan/sink/video/window 오류0, 전송 실패0.
- DISPLAY_NEXT230510ms → DISPLAY_STOPPED290570ms: **60.06초**. 메뉴 준비293760ms, 영상62초부터 카트리지 메뉴가 확인된다. 사용자도 복귀 정상 확인.
- BEGIN417/END416/COMMIT416/ABORT0. 실제 표시 완료416회, 마지막59.99초/gen597. 다음gen598 수신 중 deadline1로 종료. window12242송신=12242회수.
- `native_receiver_error=24`는 D2 POP의 전송 callback 실패 **또는** 응답 status 불일치 코드다. 실제 transfer는 I/O 전후 guard로60초 제한을 검사하며, 첫 종료 원인 deadline1을 보존한다. 이번60.06초/다음 프레임 부분 진행/실제 전송 실패0은 의도한 시간 종료와 일치한다. 원시 D2 응답은 없으므로 별도 ACK 고장이나 status 정상 자체를 실측했다고 단정하지 않는다.
- `screen_frames=0`은 untrusted 구필드다. `screen_error=169/A9`는 SPC 초기화 결과이며 화면 오류가 아니다. SPC unmute1, 사용자 사운드 정상. 영상 오디오는 별도 청음하지 않았다.
- pad_trace는 변경된8bit 읽기121회 중 마지막16개를 보존한다. 물리 버튼121번 클릭이라는 뜻이 아니다. 이번 자료만으로 입력 지연·유지 품질의 전부를 인증하지 않는다.
- 시작 경로는 pre6/all00 → post1/빈F7 CRC → READY428poll/4tick(40ms).222의 해제 후 확인 경로가 다시 사용됐다. RESET/DONE/RDY 표본이며 물리 /WR 파형이나 보편적 안정성을 입증하지 않는다.

## 다음 작업

1. **스크롤 맵의 반복 생성·전송을 줄이는 작업을 우선한다.** 현행 E0/E1의 map·command·poll 구성을 실제 소스와 비용 모델로 분리하고, 두bank의 기준/coverage를 보존하면서 필요한 부분만 갱신한다. `mapdirty=6293`은 직전 표시 대비64B block 수이며 inactive-bank의 실제 누적 union upload는 아니다.
2. 수신·계획·SEAL을 함께16.67ms 안에 넣는 설계로 진행한다. D1만도 현재 평균17.91ms, 계측 공유SPI 전체는52.69ms/완료다. 현재 반복 작업량을 그대로 둔 채 한 구간만 빠르게 하는 것으로는 부족하다. 압축 가능한 표현·종료 미완료분을 포함한 관측 평균이므로 NES의 불변 대역폭 하한으로 해석하지 않는다.
3. 최소한의 실제 경계 검증 후 첫 레벨 스크롤로 확인한다. 같은223/044 재시험, 시작 절차 진단 반복, polling-only 최적화나 새 FIT 반복을 먼저 하지 않는다. D0를 모두 없애도 계측 순수전송 약1.11초/session이다.

ARM1912B·FPGA159LE/2LAB/9M9K 여유를 구별해 지킨다. 큰cache를 무작정 늘리지 않고 저장SRAM/GBC164/기존 봉인 자료를 보존한다. physical CHR tag/row-alt/mask/epoch/active-bank 보호/최종displayACK를 유지하며 MMC4/5의 fetch-time 상태와 향후 저장·로드를 훼손하는 무조건 재사용은 피한다.

## 재현·한계

`tools/analyze_nes_game223.py --archive <probes/nes-game223-hardware01>`로 원본 해시·100단계·12bin 합계·실제 종료 소스·222 비교를 검증한다. 봉인 후 덮어쓰기를 거부한다. [분석 JSON](../analysis/game223-hardware01-verification.json)에 원시 필드·bin·소스 해시를 보존했다.

FRAME_START bin은 장면 기준이 아니고 마지막bin에는 미완료 작업이 포함된다. wire에는 별도 서비스/오디오와 parallel aperture DMA가 빠져 있다. source read/SNES VBlank는 미측정이다. 따라서 평균6.93완료/초는 TV 주사율이나 통제된 스크롤FPS가 아니며,60fps·전체mapper·장기 안정성을 입증하지 않는다.
