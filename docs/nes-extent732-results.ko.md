# NES732 연속 map 구간과 다음 BG 마감

## 목표

727을 기준으로952·957의 남은 map DMA 묶음,956 선행 DMA,다음 BG의 ROM 공급 마감을 함께 보존할 OBJ·ordinary 발행 조건을 정한다. 정상 Flash212,992B,독립 검사·STOP·최종 ACK·메뉴 복귀를 유지하고 두 시작 위상의 전체 간격·마지막 ACK를 확인한다.

## 작업내용

731은192B 두 패킷을 보존했지만,952·957의 offset2048..3583 연속1,536B를 쪼갰다. 732에서는 쌍이 아니라 **실제 주소가 연속된 변경 행 구간 전체**가 끝난 뒤에만 ordinary를 발행하도록 구현했다. 구간 안의 producer 조회·checked-empty grant·192B 쌍·E1 credit는727 그대로다.

최종 prepared/serial/generation/bank/used/dirty 검사를 통과한 뒤 첫 구간을 발행한다. 다음 변경 구간이 있으면 그 주소 공백에서 확정 palette/OAM을 한 번 보내고 나머지 map을 발행한다. 더 남은 map이 없으면727의 유한 DMA 대기를 먼저 거친 후 ordinary를 보낸다. ordinary의 기존 실제 bulk descriptor·receipt·CRC·STOP 검사를 우회하지 않는다. 마지막 map 뒤에도 원래 대기 조건을 적용한다.

`map_next`를 재사용하며 새 상주 RAM·상태 비트는 없다. B는 반복64비트 가변 주소 복원과 추가 gap scan을 하나의 지역 mask cursor로 대체했다. 원래 변경 마스크는 수정하지 않고,shift64 경계도 차단한다. C는 앞뒤 대기 본체를 함수로 공유하고,D는 두 단계 pass 제어를 직접 완료 분기로 바꿨다. 기존 source/planner/FPGA/65816은 변경하지 않았다.

E0 bit8은 기존 ABI에서 **DMA 한 번 완료**이지 남은 map 전체 완료가 아니다. 따라서 이 비트만으로 다음 ordinary를 허가하거나 모든 DMA가 끝났다고 간주하지 않는다.728C의 전체 큐 완료 공개는 이전 미채택 후보이며 이번에 몰래 포함하지 않았다. 연속 발행을 보존해도 실제 DMA·다음 ROM 마감까지 보장됐다는 뜻은 아니며,전체 재생으로 따로 확인해야 한다.

## 성과

**가장 작은 B도 정상 Flash가28B 초과해 미채택이다. 새 두 위상 전체 일정은 실행하지 않았으며,732의 표시 간격·마지막 ACK 개선 여부는 미검증이다.** 실제 선택707D·기존 ARM/65816과727을 유지한다.

|전체 링크|Flash|한도 초과|같은 전체 함수 경계|
|---|---:|---:|---:|
|727|212,992B|0B|4,966B|
|A 구간·두 단계 발행|213,096B|104B|5,072B|
|B 단일 mask cursor|213,020B|**28B**|4,994B|
|C 대기 본체 공유|213,080B|88B|5,050B|
|D 직접 완료 분기|213,036B|44B|5,010B|

함수 경계 한도4,970B에도 B는24B 초과다. C의 새 `mapwait732` 비용을 합계에 포함했다. 기존 span188B/cost82B는 양쪽 모두 포함한다. 정적 `.data1048/.ahbram8992/.bss19548B`,sink992/resident6032/runtime1408B는 같다. 새 전체 stack 관측·장시간판 링크는 하지 않았고,정적RAM 불변을 stack 불변으로 표현하지 않는다.

B의 실제 링크 ELF로13개 구간/ordinary/오류,9개 prepared·부분 전송·최종 ACK,32개 원본 모드0..3 대조,76개 span·8개 OAM 동등성을 통과했다. cold4096B·zero·sparse·bit63·중간 cursor·짧은 범위·sequence 소진·STOP·CRC·generation·모호한 E1 실패를 포함한다. 기존35개 수락/행/status,10개 진행/소유권,7개 END,9개 credit,17개 마감/expiry,7개60초 종료,9개 메뉴 경계도 통과했다. 준비 데이터·clock·transport는 단위 시험의 fixture이며 실제 DMA 시간 검증이 아니다.

초기 guard 묶음은 장시간용693 시험을 정상판에 잘못 연결해 `limit=0` 초기화에서 실패했다. 원본727 정상판도 같은 위치에서 거부했고 정상판 코드는 `!limit`를 금지한다. 양쪽 실패 로그를 보존하고 정상판용692의7경계와704 메뉴 시험으로 바로잡았다. 이를 제품 회귀나 장시간 시험 통과로 기록하지 않는다.

### 두 위상에서 고정한 관측 기준

아래는 새732 시간이 아니라 **기존727의 해시 고정 재생**이다. 두 위상은 시작7288416/7467100,ROM 위상0이다.

|보호할 구간|위상1|위상2|
|---|---:|---:|
|952 마지막 map 수락 / ACK|31.862 / 32.445ms|31.753 / 32.335ms|
|952의1,536B DMA 시작|237선|236선|
|957 마지막 map 수락 / ACK|30.947 / 31.531ms|31.047 / 31.631ms|
|957의1,536B DMA 시작|237선|236선|
|956 선행 map|1,024B|1,024B|

map 수락/ACK 시간은 해당 직전 표시 기준이다. 주사선은 관측 시점이며 새 하드코딩 마감이 아니다. E9 여유는 뒤따르는 생산·ROM중재 비용을 제외한 여유로,충분한 DMA 안전 예산이나 새 후보의 개선량이 아니다.

731에서 이 원래 ROM 구간을 놓친 BG는32읽기 중8회였고,E9가53.735/592.279µs 늦었다. 그때953 ordinary는 놓친 구간 뒤6.886/7.210ms에 시작하므로 직접 선행 원인으로 오인하지 않는다. 직전952의 늦어진 표시·다음 입력·plan 공급까지 연결해야 한다. 이 기록도732 결과가 아니다.

이번에는 ARM 정상판4회 링크와 단위 경계·기존 두 위상 예산 분석만 수행했다. 정상 Flash gate 실패로 장시간판·새106화면 재생·새 전체 FIT/STA·설치본은 진행하지 않았다. FPGA·65816·SDC는707D 그대로이며 기존 비용15,322LE·962/963LAB·56/56M9K와 기존 제약 STA 기록 범위를 보존한다. 회로 절감이나 새 실기 승인 주장은 없다.

## 후속작업

1. B의 두 단계 발행·남은 구간 종료 판단과 기존 packet/span 완료 제어에서 **전체 Flash 최소28B,같은 함수 경계 최소24B**를 실제로 삭제한다. 검사·STOP·cold 복구를 제거해 맞추지 않는다. A/C/D의 동일 제어 분배·함수 공유 변형은 반복하지 않는다.
2. 정상/장시간 전체 링크가 모두 한도 안에 들어오면 같은 후보로 두 시작 위상106화면을 실행한다. 952·957의 offset2048..3583 DMA1,536B,956 선행1,024B,953 BG 원래ROM 구간,908·911·951·952·957 및7입력 블록을 함께 비교한다. 구간 발행 단위시험 통과를 실제 DMA 보존으로 대신하지 않는다.
3. 두 위상952–957 및951–955 밀집 간격과957 마지막 ACK를 함께 줄일 때만 채택한다. 프레임 번호 특례·고정 대기·위상 상수·새 검사 생략은 추가하지 않는다. 현재 새 시간 개선 주장은 보류한다.
