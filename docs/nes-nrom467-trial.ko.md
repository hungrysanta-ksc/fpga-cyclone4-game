# NROM467 제한 실기 시험 전달본

기존 방식대로 이 파일을 사용자가 SD에 설치해 보드에서 확인한다. FPGA457·ARM418·자체 제작 NROM428을 고정한 실험용 짝이다. 60fps 시험 전의 설정·기본 표시·STOP·메뉴 복구 확인용이며 전체 timing/CDC·IO 보증은 없다. 새466은 sink reset 5개를 고쳤지만 다른 동기 setup −0.091ns로 보류하여 포함하지 않았다. 457은 제한 관련 setup +0.226ns/hold +0.151ns이고 raw setup −7.040ns/recovery −9.659ns, 미제약 input54/output56과 직접 reset 상태 검토가 남는다. 이 한계를 포함한 첫 실물 관찰용이다.

## 설치 전

전원을 끄고 SD의 기존 sd2snes 폴더와 세이브를 PC에 백업한다. `01-NROM-SD-ROOT` 안의 내용을 SD 루트에 복사한다. firmware.stm·fpga_nrom16.bi3는 반드시 전달본 짝으로 사용한다. base/menu는 보존164/227과 동일한 해시다. 기존 게임·세이브를 삭제할 필요는 없다. 자체 ROM만 포함하며 상용 게임 ROM은 포함하지 않는다. manifest.json은 전달 파일의 해시 목록이다. marker 이름은 기존 진입 코드 때문에 `NES GAME 227.nh1`을 사용하지만 이번에는 NROM 자체 테스트 ROM이 실행된다.

## 한 번의 시험

1. 부팅 후 메뉴가 표시되는지 확인하고 `NES GAME 227.nh1`을 실행한다. 화면이 바뀌는 시점과 정지/오류 문구를 기록한다. 384KiB 적재와 독립 readback을 먼저 수행하므로 기다리는 시간도 기록한다. 이 적재 시간은 게임 FPS가 아니다.
2. 표시되면 체크무늬와 색을 확인한다. 방향키·A/B를 짧게 눌러 입력에 따른 색/패턴 반응을 기록한다. 자체 fixture의 음성 출력은 합격 조건이 아니다. 현재 FPGA/ARM의 실물 첫 조합이므로 화면이 나온다고 지속 60fps로 판단하지 않는다.
3. 원래 진단 세션의 자동 STOP·메뉴 복귀까지 관찰한다. 기존 227은 약60초 세션이었지만 이번 전체 적재·복귀 시간은 실측 전이므로 정확한 종료 시한으로 사용하지 않는다. 멈추거나 오류가 표시되면 상태·경과 시간을 남긴다. BLOCKED_RESET_HELD가 나오면 보호 차단을 해제하거나 강제 재진입하지 않는다.
4. 메뉴에 정상 복귀했으면 같은 항목을 한 번 더 실행해 재시작 여부를 확인한다. 이어 전원을 껐다 켜 메뉴 부팅이 유지되는지 확인한다.

## 돌려줄 결과

가능하면 부팅부터 실행·자동 복귀까지 영상과 아래 파일을 복사해 전달한다. `sd2snes/nes-progress-227.txt`, `sd2snes/nes-game-last-227.txt`, `sd2snes/nes-budget-227.txt`. 파일이 없으면 없다고 알려주고 오류 문구/마지막 화면·경과 시간·사용 보드 모델을 함께 전달한다. 로그에는 STOP·base_restored·safe_to_reload·menu_state 등 복구 상태를 확인한다. 파일이 없는 상태도 결과이므로 반복 설치만으로 덮어쓰지 않는다.

## 복원

전원을 끄고 `02-RESTORE164-SD-ROOT` 안의 내용을 SD 루트에 복사하면 보존164 firmware/FPGA·base/menu로 돌아간다. 다른 기존 구성을 사용했다면 설치 전 백업이 우선이다. 복원용 상용 ROM은 넣지 않았으며 기존 게임 파일과 저장 자료를 유지한다. 새 파일을 지우려고 전체 SD를 포맷하지 않는다.
