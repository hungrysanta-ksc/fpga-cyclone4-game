# MMC529 SMB3 실기 결과

사용자는 MMC524 때와 비슷한 동선으로 플레이했고 실행과 메뉴 복귀를 확인했다. 384KiB 적재와 전체 readback, START, STOP, base 복원, MENU_PREPARED가 기록됐다. 전송 실패와 CRC 오류는 0건이었다.

| 표시 완료 기준 | MMC524 | MMC529 |
|---|---:|---:|
| 1초 이상 40초 미만 | 480회 · 12.31fps | 461회 · 11.82fps |
| 40초 이상 60초 미만 | 220회 · 11.00fps | 232회 · 11.60fps |
| 전체 | 715회 / 60.08초 · 11.90fps | 708회 / 60.07초 · 11.79fps |

후반은 12회 더 표시했지만 전반은 19회 줄었다. 전체 평균 표시 간격은 84.03→84.84ms였다. 완료 카운터와 별개로, 아래 5초 집계는 프레임이 시작된 시각에 귀속한다. 마지막 구간은 종료 시점까지 포함한다.

| 구간 | 표시 수 524 → 529 | 최대 표시 간격 | 출력·최종 ACK 구간/표시 |
|---|---:|---:|---:|
| 40–45초 | 62 → 50 | 100 → 180ms | 46.29 → 59.40ms |
| 45–50초 | 47 → 64 | 160 → 100ms | 65.11 → 44.22ms |
| 50–55초 | 55 → 63 | 210 → 100ms | 54.18 → 45.56ms |
| 55초 이후 | 55 → 54 | 120 → 120ms | 54.73 → 55.00ms |

45–55초에는 긴 표시 간격이 줄었고, 40–45초에는 오히려 늘었다. 45–50초의 OBJ 타일 공급 계획은 표시당 17.60→3.45건으로 달랐다. 적의 수를 기록하는 지표는 아니며 같은 장면·입력으로 동기화된 실행도 아니다. 두 위상에서 952·954가 한 VBlank 빨라진 시뮬레이션 결과를 전체 실기 fps 개선으로 환산할 수 없다. [동일 입력 검증](nes-flash529-results.ko.md)

전체 DWT 비용을 완료된 표시 수로 나누면 수신 19.94→20.00ms, 계획·공급 15.42→16.06ms, 출력·최종 ACK 48.02→48.10ms다. 출력 구간에는 DMA·검사·대기가 함께 들어 있다. 다음 비교에서는 같은 map·OBJ 공급량에서 SEAL의 raw·tile DMA와 최종 VBlank 대기를 분리한다.

입력 commit 709회 중 최종 EA는 708회였다. 마지막 완료 시각은 59.91초이고 제한 시간 종료 때 큐 1건이 남았다. 마지막 미완료 건은 표시 수에서 제외했다. 원본 세 로그는 저장소 부모의 `probes/nes-hardware530/run01`에 보관했다. 재현 명령은 `python tools/analyze_nes_hardware521.py --trial 529 --raw <로그 폴더> --out <결과.json>`이다.
