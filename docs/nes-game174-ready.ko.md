# NES174 — 연속 영상 개선 실기 시험

타일 간 비트평면 수집 수정과 패턴 묶음 전송을 함께 시험한다. FPGA 내부 실제 클록 타이밍과 기존 외부 인터페이스 조건 검사를 통과했다. **화면 정지 해결과60fps는 아직 실기에서 확인하지 않았다.** 이번에는 MCU와 FPGA가 모두 바뀌므로 반드시 폴더 전체를 적용한다.

1. `NES174-SMB3-VIDEO-BATCH.zip`의 `01-GAME174-SD-ROOT` 안 내용을 SD 루트에 덮어쓴다. 기존173의 firmware나 FPGA와 섞지 않는다.
2. 메뉴에서 `NES GAME 174.nh1`을 한 번 실행한다. ROM 적재·검사 절차는 유지하여 로딩은 여전히 수분 걸릴 수 있다. 이번 변경은 로딩 시간 단축이 아니라 실행 중 영상 정지와 전송 비용 개선이다.
3. 게임 화면이 나오면 스타트로 진행하고 가능하면 첫 레벨에서 이동·점프한다. 화면이 계속 갱신되는지, 뚝뚝 끊기는 정도가 줄었는지, 음악·버튼 반응이 유지되는지 확인한다. 표시 준비 후 약60초에 메뉴로 복귀하는 기존 한도는 유지한다.
4. 가능하면 **게임 화면이 보인 때부터 메뉴 복귀까지 영상**을 촬영한다. 로딩 구간은 촬영하지 않아도 된다. 화면이 다시 멈춰도 소리·버튼 반응이 남는지 알려준다.
5. 메뉴 복귀 후 `sd2snes/nes-progress-174.txt`와 `sd2snes/nes-game-last-174.txt`를 전달한다. 화면 지속 여부·끊김·사운드·메뉴 복귀 여부도 함께 알려준다.

메뉴 실행부터6분이 지나도 복귀하지 않으면 전원을 끄고 남은 로그를 복사한다. 기존044 복원 시험은 반복하지 않는다. 정상 사용으로 돌아갈 때는 포함된 `02-RESTORE164-SD-ROOT`를 사용한다.

실행 중 SD 쓰기는 없고 정지·메뉴 복구 뒤 로그를 작성한다. 세이브 SRAM은 영상 버퍼로 사용하지 않는다. 게임·164 복원 파일은 이전173 패키지와 동일 바이트로 보존했다.

로그의 시간 측정 필드는 기존173 형식이다. 수신 대기 시간을 그대로 화면 처리 시간으로 보거나,60초 전체에 표시 횟수를 나눠 정상 FPS라고 해석하지 않는다. 이번 결과로 연속 표시와 실제 처리 시간을 함께 판단한다.
