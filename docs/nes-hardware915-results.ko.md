# MMC915 실기 결과 · 모험도 4 무입력 60초

MMC907과 MMC915 각 1회에서 실제 표시가 끝난 화면을 셌다. MMC915는 393,216B ROM 비교를 통과했고 마지막 표시는 59.98초였다. 전송 실패와 실행 중 ROM 오류는 0건이었다. STOP과 base 복구가 완료됐고 사용자가 메뉴 복귀를 확인했다.

| 표시 구간 | MMC907 | MMC915 | 변화 |
|---|---:|---:|---:|
| 1–30초 오프닝 | 597장 · 20.59 FPS | 627장 · 21.62 FPS | +5.03% |
| 30–60초 데모 | 592장 · 19.73 FPS | 646장 · 21.53 FPS | +9.12% |
| 55–60초 데모 부분 구간 | 92장 · 18.40 FPS | 103장 · 20.60 FPS | +11.96% |

55–60초에 시작 시각이 10ms 눈금까지 같고 BG·OBJ·변경 map 수, 타일 수, 묶음 수, 마지막 묶음의 종류·크기·offset이 모두 일치한 7쌍을 대조했다. 입력 완료부터 ARM의 첫 유효 최종 ACK까지 7쌍 모두 줄었고 평균은 53.91→42.45ms였다. 첫 E9부터 마지막 OBJ 준비까지는 OBJ로 끝난 6쌍 중 5쌍에서 오히려 늘었다. 이 화면들의 요약만으로 ROM 선행 읽기가 단축한 시간을 분리하기는 어렵다.

ROM 허가를 낱개로 기록한 상세 화면은 MMC907의 56.46초(타일 9개·4묶음·64회)와 MMC915의 56.17초(4개·3묶음·16회)였다. 두 화면의 작업량이 달라 ROM 경쟁 감소량은 미확정이다. MMC915 상세 화면의 COMMIT D2 반환은 가장 가까운 캡처 기회보다 2.431–5.549ms 앞선 것으로 추정된다. MMC907의 같은 기준 여유는 기록 분해능과 COMMIT 시각 부재로 확정할 수 없다.

재현 명령은 `python tools/compare_nes_trial915.py <MMC907 로그 폴더> <MMC915 로그 폴더>`다.
