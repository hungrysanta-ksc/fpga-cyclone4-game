# MMC520 SMB3 실기 결과

사용자는 게임 실행과 메뉴 복귀가 정상이고 이전보다 초반은 확실히 부드러웠으며 후반 체감은 비슷했다고 보고했다. 384KiB 적재·readback, START, STOP, base 복원, 메뉴 준비까지 확인했다. 실기 세 로그는 상위 작업 폴더의 `probes/nes-hardware521/run01`에 보관했다. 파일 해시·계산 결과는 [측정 기록](../analysis/hardware521-mmc520.json)에 있다.

## 표시율

| ARM이 최종 표시를 확인한 시각 | 횟수 | 관측 시간 | 표시율 |
|---|---:|---:|---:|
| 1초 이상~40초 미만 | 471 | 39초 | 12.08fps |
| 40초 이상~60초 미만 | 232 | 20초 | 11.60fps |
| 전체 | 718 | 60.07초 | 11.95fps |

첫 1초에 15회가 포함됐고 마지막 표시는 59.95초였다. 전체는 DISPLAY_NEXT부터 DISPLAY_STOPPED까지로 계산한다. 이전 MMC516은 같은 60.07초에 660회(10.99fps)였다. 이번 실행은 58회 더 표시해 전체 관측 평균이 8.79% 높다. 같은 게임과 유사한 동선으로 진행한 별도의 플레이여서 장면과 입력이 정확히 대응하지 않는다. MMC516에는 1초·40초 경계의 완료 카운터가 없다.

두 빌드에 공통인 **프레임 시작 기준** 5초 카운터로 구간을 비교하면 다음과 같다. 완료 카운터와는 경계를 넘는 화면의 귀속이 다르다. 마지막 bin은 55초 이후를 함께 담으므로 5초로 나눈 값은 근사다.

| 시작 기준 구간 | MMC516 표시 수 | MMC520 표시 수 | 의미 |
|---|---:|---:|---|
| 5–40초 | 401 | 418 | 같은 35초 기준으로 약 11.46→11.94fps |
| 40초 이후 | 196 | 231 | 약 9.8→11.55fps |
| 그중 45–50초 | 30 | 65 | 약 6.0→13.0fps. OBJ 계획은 30.07→9.42개/표시 |
| 그중 50–55초 | 56 | 65 | 약 11.2→13.0fps |
| 그중 55초 이후 | 52 | 40 | 약 10.4→8.0fps. OBJ 계획은 9.25→22.90개/표시 |

초반 체감과 공통 구간의 표시 수는 같은 방향이다. 후반 전체 표시 수가 늘었지만, 이번에는 마지막 5초에 가장 긴 처리 시간이 몰렸다. 기록된 OBJ 수는 새로 공급한 타일 계획을 뜻한다. 두 실행에서 같은 적 또는 같은 장면이 나타난 시각은 확인할 수 없다.

## 처리 비용과 다음 작업

| 표시 1회당 비용 | MMC516 전체 | MMC520 전체 | MMC520 마지막 5초 |
|---|---:|---:|---:|
| 수신 | 19.85ms | 19.99ms | 22.00ms |
| 계획·공급 | 16.45ms | 15.51ms | 23.50ms |
| 출력·최종 ACK | 54.10ms | 47.54ms | 78.25ms |

전체는 84MHz DWT 누적 비용, 마지막 구간은 10ms 틱을 표시 수로 나눈 근사치다. 마지막 구간은 916개의 OBJ 계획을 공급했고 최대 표시 간격이 180ms였다. END 추가·flush 약 8ms는 계획·공급에 이미 들어 있다. 전체 평균 표시 간격은 83.66ms이며, 60fps의 16.67ms 예산과는 약 67.0ms 차이가 있다.

다음 비교는 MMC520을 기준으로 OBJ 부하가 큰 동일 입력에서 **마지막 OBJ 공급·소비 완료 → SEAL 진입 → VBlank 대기 → 최종 표시 ACK**를 나누어 측정한다. 실기 후반의 78.25ms는 여러 출력 작업의 합계다. 현재 로그만으로 이 시간을 ROM, 65816 DMA, VBlank 각각에 배분하거나 원작의 게임 로직 지연을 확정할 수 없다. [520의 동일 입력 기준](nes-order520-results.ko.md)

## 종료 해석

입력 commit 719회와 EA 718회가 기록됐다. 60초 제한 결과(`native_result=1`)로 종료할 때 마지막 한 화면은 열려 있었고, 전송 창의 sent 19,805와 retired 19,803 사이에 2건이 남아 있었다. 이 화면은 표시 수에서 제외했다. 종료 시 plan/window/sink 코드는 5/3/5다. 실행 중 계측한 CRC 오류·전송 실패·전송 중단은 모두 0이고, STOP과 base 복구가 성공했다. 종료 직전의 정확한 명령은 재생하지 않았다. 보존된 캡처 이력에는 거부·회복 각 3건, 해당 fetch 오류 0건이 있다. 이 이력은 전체 실행의 캡처 누락률을 제공하지 않는다.
