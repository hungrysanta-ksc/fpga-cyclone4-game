# 921 · 세대 908 첫 팔레트와 OBJ 수락 순서

## 920에서 처음 늦어진 경계

MMC915와 920의 전체 ARM 링크에 실행 주소 관측점을 붙여 팔레트 범위 계산 진입, 첫 패킷 조립, 큐 제출, 실제 E1 시작·종료를 기록했다. 65816에서 같은 세대·offset 0의 팔레트 머리글을 처음 읽은 클록을 수락으로 잡았다. 계측을 붙인 두 대조군의 공개 간격과 최종 ACK는 기존 재생과 일치했다. 아래는 기존 캐시에서 920이 MMC915보다 늦어진 시간이다.

| 908 첫 팔레트 수락까지 | 위상 1 | 위상 2 |
|---|---:|---:|
| ARM이 팔레트 범위 계산에 진입하기까지 | +0.301ms | +0.366ms |
| 범위 계산 진입부터 E1 시작까지 | 약 0ms | 약 0ms |
| 32B 팔레트 E1 전송 시간 차이 | 약 0ms | 약 0ms |
| E1 종료부터 65816 수락까지 | +0.466ms | +0.480ms |
| **총 수락 지연** | **+0.767ms** | **+0.846ms** |

두 링크 모두 범위 분할과 첫 패킷 조립 함수 진입 사이에 9,565클록을 썼고 첫 팔레트 E1은 약 4,409클록이었다. MMC915의 큐에서는 64B OBJ 뒤에 첫 팔레트, 그 뒤에 544B OBJ가 섰다. 920에서는 544B OBJ까지 팔레트보다 앞에 섰다. 실제 SPI 발행과 65816 수락 간격이 이 순서에 따라 늘었다. 팔레트 비용 계산만 생략한 대조군은 해당 ARM 구간을 약 0.41ms 줄였지만 OBJ 반환을 기다리면서 첫 팔레트 수락이 920보다 오히려 늦어졌다.

## 발행 조건과 검사

첫 팔레트는 이미 CRC·세대·token 검사를 마친 OBJ가 직전 발행이고 해당 반환을 추적할 수 있을 때 기존 DATA 발행 경로로 보냈다. 후속 범위를 겹치는 후보에서는 발행 건수와 마지막 bulk 반환 대상 사이의 거리를 제한해 4개 머리글 창 안에 해당 반환을 보존했다. 32·96·232·152B 고정 분할도 512B 전부를 현재 CGRAM에서 읽고 실제 바이트가 반복될 때만 압축한다. STOP과 SEAL, 최종 표시 ACK는 원래 소비자가 처리했다.

계획 생성 중 큰 OBJ가 끝나기 전에 팔레트 32B를 일반 FINISH 경로로 보낸 초기 두 후보는 세대 907에서 거부됐다. 당시 END가 발행되기 전이어서 `nes_plan200_progress`의 진입 조건을 충족하지 못했다. 이 실패도 결과 JSON에 보존했다. 큐에 직접 넣은 후보와 END 이후에 순서를 바꾼 후보는 별도로 재생했다.

## 최종 링크와 표시 결과

가장 작은 후보 `compact`에서 원래 범위 비용 함수를 없애고 같은 발행 루프로 네 팔레트 범위를 처리했다. 직전 OBJ가 반환 추적 대상이면 첫 팔레트를 먼저 보내고, 128B 이후에는 미반환 bulk 뒤에 발행한 일반 머리글이 3개 미만일 때만 같은 credit을 이용했다. 65816의 독립 검사와 표시 마감 조건은 920과 같다. ARM 이미지는 **212,912B**, 한도까지 80B이고 920보다 96B 작다.

| MMC915 → compact | 위상 1 | 위상 2 |
|---|---:|---:|
| 기존 캐시 첫 팔레트 수락 단축 | 0.901ms | 0.789ms |
| 기존 캐시 64B / 544B OBJ 유효 E8 단축 | 0.840 / 1.424ms | 0.754 / 1.124ms |
| 기존 캐시 908 공개 VBlank | 39 → **38** | 40 → **39** |
| 기존 캐시 906→912 여섯 간격 합 | 14 → 14 | 14 → 14 |
| 기존 캐시 912 최종 ACK 변화 | 220클록 늦음 (0.010ms) | 같은 클록 |
| 빈 캐시 912 선행 DMA | 같은 주소 496B | 같은 주소 496B |
| 빈 캐시 여섯 간격 합 / ACK 지연 | 16 → 17 / 16.638ms | 16 → 17 / 16.645ms |

920과 직접 비교하면 첫 팔레트가 1.668 / 1.635ms 빨리 수락됐다. 64B OBJ 응답은 네 번째를 유지하며 0.015 / 0.036ms 늦었고 544B는 다섯 번째를 유지하며 0.206 / 0.186ms 빨랐다. 진행 조회 이득을 얻은 뒤에도 실제 65816이 수락 가능한 순서로 팔레트를 전달해야 공개가 앞당겨졌다.

기존 캐시에서 908과 910은 각각 한 VBlank 앞당겨졌다. 909와 911은 MMC915와 같은 VBlank에 공개되어 그 이득을 이어가지 못했다. 빈 캐시에서는 911까지 모든 공개 VBlank가 기준과 일치했다. 912의 SEAL 수락은 기준의 VBlank 49·50에서 후보의 50·51로 밀렸다. 두 위상 모두 이미 SEAL 수락 전에 한 주기가 밀려 있었고 실제 선행 DMA의 목적지와 크기는 유지됐다.

## 판정과 후속 작업

실기 기준은 MMC915를 유지한다. 다음 비교에서는 기존 캐시의 908→909와 910→911에 대해 직전 공개, 다음 입력의 마지막 D2, SEAL 수락, 잔여 DMA를 같은 클록에서 대조한다. 빈 캐시에서는 911→912의 입력·ROM 공급부터 SEAL 이전에 잃은 한 주기를 추적한다. 채택 기준은 908의 공개 이득과 빈 캐시 496B를 보존하면서 여섯 간격 합과 912 최종 ACK가 두 위상 모두 개선되는 것이다.

905–912의 RGB·map·팔레트 바이트, tile 목적지별 데이터, E9 묶음과 section 5 해시를 대조했다. 후보의 마지막 타일 복사 바이트에서 STOP을 넣으면 미완료 token을 반환하지 않고 0xE4로 종료했다. 잘못된 descriptor·중복 타일·잘못된 SEAL은 0xE0으로 거부했고 표시 대기 중 STOP도 통과했다. 최종 ARM에서 SRAM D0 송신 네 곳, 잘못된 입력 CRC 거부, 타이머 STOP, base 및 메뉴 복구를 확인했다. 시간은 동일 입력과 ROM 공급 모형을 사용한 ARM·65816 공동 재생 결과다.
