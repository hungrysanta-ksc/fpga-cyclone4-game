# FF3 저장 워드와 전체 보드 배치 1040

1039와 같은 FF3 전용 보드, Cyclone IV E EP4CE15F17C8, Quartus Lite 25.1에서 비교했다. 보드가 제공하는 963 LAB 중 최종 후보는 1,015개를 요구한다. 부족분은 62개에서 52개로 줄었다.

| 전체 보드 | 필요 LAB | LE | 조합 함수 | 레지스터 | M9K |
|---|---:|---:|---:|---:|---:|
| 1039 | 1,025 | 16,172 | 15,090 | 8,695 | 56 |
| 1040 중앙 워드 선택 | 1,022 | 16,195 | 15,395 | 8,294 | 56 |
| 1040 소유 회로에서 워드 선택 및 cold 초기화 | 1,015 | 16,131 | 15,312 | 8,294 | 56 |

### 실제 변경 범위

저장 파일의 64비트 레지스터 워드 주소와 비트 배치는 1039와 같다. T65 세 워드, PPU 본체·버스 감쇠 카운터 두 워드, APU 본체·DMC·프레임 카운터 네 워드는 코어를 멈춘 상태에서 해당 워드의 쓰기 펄스에 직접 복원한다. 저장 때는 워드 소유 회로가 주소를 확인해 현재 값을 반환한다. PPU 카운터를 포함해 한 워드를 한 번에 읽는다. 1039의 팔레트·매퍼 바이트 경로는 그대로 사용한다.

복원 도중 cold 리셋을 받으면 이 아홉 워드가 사용하는 실제 레지스터에도 초기값을 적용한다. PPU의 clear는 기존 reset 동작 설정을 따른다. 나머지 PPU 클록·OAM 평가·VRAM 주소 생성과 코어 최상위의 이력에는 복원 사본이 있다. MAP 결과상 네 사본은 각각 30·53·37·25 레지스터다.

### FF3 복원과 STOP

첨부한 FF3 ROM을 실행한 혼합언어 RTL에서 저장 스트림의 아홉 워드를 각 소유 회로의 현재 값과 대조했다. 파일 배치에서 예약한 비트는 비교에서 제외했다. CPU·PPU·APU에 서로 구별되는 값을 넣어 부분 복원한 뒤 STOP으로 중단했다. CPU 첫 워드 뒤, PPU 두 워드 뒤, APU 프레임 카운터 직전을 포함한 일곱 경계에서 변경된 레지스터, 리셋 뒤 초기값, 콜드 부팅의 첫 64개 CPU 명령 경계 및 이전 요청의 소멸을 확인했다.

완전 복원 시험에서는 2,658워드와 8,192바이트의 배터리 RAM을 검사했다. 재개 후 첫 64개 CPU 명령 경계와 연속 두 화면의 122,880픽셀이 중단 없이 실행한 결과와 일치했다. 이 장면의 색 수는 3개다. SPI CRC·워드 순서·에코·재시도·STOP, 부팅 전 배터리 접근, 저장 파일 손상 시 이전 세대 복구, CHR RAM 스냅샷에서 BG·OBJ에 이르는 바이트 순서 시험도 통과했다. 로그는 `probes/nes-ff3-1040/leaf-checkpoint.log`, `state-spi-sim.log`, `display-sim.log`, `savefile-host.log`에 보관했다. 실물 SD에서 FF3를 다시 선택해 부하 장면으로 복귀하는 시험은 보드 배치가 남아 있다.

### 면적 해석과 다음 작업

1039 대비 레지스터 401개와 전체 LE 41개를 줄였다. 일부 절감이 쓰기 값 선택 회로로 옮겨가면서 조합 함수는 222개 증가했다. 같은 MAP 계층에서 T65는 조합 함수 151개 증가·레지스터 164개 감소, PPU는 28개 증가·102개 감소, APU는 34개 증가·135개 감소다. 하위 계층과 상위 계층의 값을 중복해 더하지 않는다. 레지스터만 사용하는 LE는 1,082개에서 819개로 줄었다.

다음 면적 실험은 T65의 일반 실행·리셋·복원 쓰기에 중복되는 값 선택과 64비트 반환 경로를 우선한다. 남은 네 사본의 합은 145레지스터이고 현재 전체 LE 초과량은 723개다. 이 숫자를 서로 상쇄할 수 있다고 가정하지 않는다. 배치 성공 뒤 같은 소스의 전체 STA, 코어 메뉴, SD 재선택·장면 복귀 순으로 검증한다.

### 재현 위치

- 보드 생성 진입점은 `tools/prepare_ff3_display1037.py`, CPU·PPU·APU 변환은 `tools/prepare_ff3_core1040.py`다. 최종 소스로 재생성한 보드 파일 99개가 FIT 입력과 바이트 단위로 일치했다.
- 원시 MAP·FIT 보고서는 작업 루트의 `probes/nes-ff3-1040/lite-words/`, `lite-leaf/`에 있다. 두 보드 모두 FIT의 오류 170012에서 종료했다. 배치 후 STA·프로그래밍 이미지·실기 설치 ZIP은 생성되지 않았다.
- 코어 시험은 `tools/check_ff3_checkpoint_rtl.ps1`, 저장 파일·전송 시험은 `tools/check_nes_savefile1036.py`를 사용한다.
