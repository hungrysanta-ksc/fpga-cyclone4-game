# 887 · 최종 ACK 조회와 다음 캡처

## 886의 위상 2에서 마감을 놓친 구간

65816이 최종 ACK를 쓰는 순간 진행 중이던 E0에는 SPI 거래 시작 때의 상태가 들어 있었다. 밀집 947에서는 그 거래가 ACK 779클록 전에 시작해 1,564클록 뒤에 끝났다. 오프닝 918에서는 659클록 전에 시작해 1,683클록 뒤에 끝났다. ARM은 두 응답 모두 이전 상태로 처리했다. 다음 E0에서 CRC와 전체 표시 identity가 일치한 뒤 EA와 E8 재무장을 거쳐 다음 입력을 진행했다.

| 위상 2, 마스터클록 | 밀집 947 (883 → 886) | 오프닝 918 (883 → 886) |
|---|---:|---:|
| 이전 최종 ACK → 첫 유효 E0 완료 | 4,957 → 6,346 | 3,048 → 7,125 |
| 유효 E0 완료 → 마지막 D2 완료 | 13,027 → 13,026 | 24,759 → 24,759 |
| 마지막 D2의 캡처선 여유 | +1,128 → −36 | +3,657 → −254 |

E0 이후 경로의 소요 시간은 1클록 이내로 일치했다. 886에서 늦어진 구간은 실제 ACK 공개와 ARM의 다음 조회가 만나는 지점이다. 같은 상태를 더 자주 확인하면 다른 세대의 SPI 점유와 시작 시각도 바뀌므로 해당 세대만 바꾼 대조와 정적 링크를 모두 실행했다.

## 시험 조건

887은 SEAL의 최종 identity를 기다릴 때 진전이 없으면 다음 조회까지 48µs를 기다린다. 886의 대기는 입력 완료 때 96µs, 그 밖에는 128µs다. 일반 큐 credit 대기와 입력 수신 예산은 두 링크가 같다. STOP 확인, E0 응답 CRC와 identity, EA 뒤 E8 재무장 확인, COMMIT 순서는 같은 코드를 실행한다.

세대 한정 대조는 원래 886을 부팅한다. 밀집 945 또는 오프닝 916의 해당 함수 호출에만 48µs 인자를 전달하고 복귀 시 되돌린다. 945의 최종 ACK가 946의 COMMIT을 허용하고 그 마지막 D2가 947 캡처선을 결정한다. 오프닝도 916→917→918의 같은 관계다. 정적 후보에는 세대 번호 조건이 없다. 65816은 886 정적 ROM, FPGA는 기존 회로를 사용한다. ARM Flash는 212,960→212,952B로 줄어 한도까지 40B가 남고 BSS는 20,908B다.

## 전체 부팅 결과

위상 2에서 이전 일정과 최종 ACK 시각을 고정하고 한 세대만 바꾸면 밀집 947의 ACK→유효 E0는 6,346→2,448클록, 오프닝 918은 7,125→3,937클록이다. 이후 마지막 D2까지의 13,026 / 24,759클록은 각각 동일했다. 캡처 여유는 −36→+3,862 / −254→+2,934클록으로 바뀌어 두 캡처 모두 한 주기 빨라졌다. 이 대조에서 밀집 간격은 139→138회, 오프닝은 122→121회다.

| 지표 (위상 1 / 위상 2) | 886 | 887 정적 링크 |
|---|---:|---:|
| 밀집 데모 60간격 합 | 138 / 139 | 138 / 138 |
| 데모 마지막 65816 ACK (마스터클록) | 63,944,966 / 64,659,938 | 63,946,008 / 64,302,242 |
| 데모 E0 조회 수 | 3,135 / 3,244 | 3,561 / 3,548 |
| 오프닝 60간격 합 | 121 / 122 | 122 / 120 |
| 오프닝 703 공개 (VBlank·선) | 59·231 / 59·231 | 59·231 / 60·231 |
| 전환 간격 합 | 119 / 119 | 119 / 119 |

정적 후보의 밀집 947은 위상 2에서 VBlank 136→135로 이동했다. 밀집 959는 두 위상 모두 225선 전에 대기에 들어갔고(221 / 222선) 최종 DMA를 239 / 240선에서 허가했다. 768B 선행 map DMA는 원본 WRAM 주소부터 VRAM 주소·포트·값·순서까지 두 위상 모두 일치했다. 밀집 마지막 ACK는 위상 2에서 16.655ms 빨라졌고 위상 1에서는 0.049ms 늦어졌다. E0의 추가 SPI 전송량은 각각 8,520 / 6,080B다.

오프닝 위상 2는 905 공개부터 한 VBlank 늦어져 703 마감도 한 번 놓쳤다. 917→918 간격은 3→2회로 줄었지만 918 공개는 두 링크 모두 VBlank 78이다. 위상 1은 917에서 처음 한 번 늦어졌다. 전체 부팅 결과를 기준으로 48µs 정책을 보류하고 실기판은 MMC872를 유지한다.

다음 시험은 886 조회 주기를 유지하고 유효 E0 거래 완료부터 EA 발행까지 걸린 1,049 / 1,293클록(밀집 947 / 오프닝 918)을 ARM 함수별로 계측한다. 대상 뱅크 이력 확정과 표시 집계에 드는 비용을 나눠 보고, 같은 입력·부팅에서 E0 거래를 늘리지 않고 36 / 254클록 이상 줄일 수 있는지 확인한다. 이전 표시의 성공 집계, EA 전 STOP, E8 재무장 후 COMMIT을 각각 검사한다.

## 재현

세 장면의 세대별 활성 RGB·map과 최종 ACK→EA→COMMIT 순서를 대조했다. 밀집 데모는 세대별 BG·OBJ·map 작업량도 일치했다. 새 ARM 링크에서 retire 19조건과 메뉴 복귀 경로를 통과했고, 65816에서 부분 수신·STOP·cold 재시작을 포함한 12조건을 통과했다. 결과는 실제 ARM·65816 코드를 같은 SPI·ROM 일정으로 실행한 결합 재생이다. 887의 실기 FPS는 측정하지 않았다.

1. `prepare_nes_deadline887.py`로 입력 소스와 886 ROM을 준비하고 `build_nes_mmc479_arm.ps1`로 883 공유 링크에서 ARM 전체를 링크한다.
2. `replay_nes_strip869.py TEMP PHASE WORK 887-seal CLIP`으로 dense·opening·transition을 두 위상에서 실행한다. `replay_nes_deadline887_control.py TEMP SCENE`은 dense와 opening의 위상 2에서 각각 한 세대의 대기만 교체한다.
3. `test_nes_mapwait880.py TEMP PHASE --generation 959 --audit 887-seal`로 VRAM 쓰기를 기록한다. ARM 메뉴(`check_nes_menu533.py --trial 872`)·retire 가드와 65816 소비·취소·cold 재시작 가드를 실행한 후 `check_nes_deadline887.py TEMP analysis/deadline887-results.json`으로 대조한다. [측정 결과](../analysis/deadline887-results.json)
