# 605 · 첫 BG를 위해 미리 읽을 수 있는 값과 마감

**현재 입력의 map과 직전 표시 ACK로 확정한 뱅크 이력만 사용해 첫 BG에서 실제 읽는 세 타일을 952·954 모두 골랐다.** 후보는 목적 슬롯을 정하지 않고 물리 CHR 48 B만 임시 보관한다. 두 시작 위상에서 첫 묶음의 데이터 준비는 5.62–6.42 ms 앞당길 수 있지만, 후속 BG·OBJ 읽기까지 포함한 낙관 일정의 단축은 0.121–0.145 ms였다. 실기 선택은 MMC577이다.

## 값이 확정되는 위치

604와 같은 ARM ELF, 입력 핀 RTL, 이전 표시 뱅크 이력을 사용했다. D1 파서가 끝난 뒤 보내는 D2와 D0의 반환 token을 기록하고, 수신 함수가 성공으로 돌아온 지점에서 사용을 허용했다. 최종 표시 ACK와 EA는 604의 출력 모델에서 끝까지 확인했다. 두 위상의 ARM 명령·드라이버 조건과 첫 E9 해시·완료 시각이 같아 수신 추적은 세대별 한 번 실행하고 ROM 달력은 위상별로 적용했다.

| 세대 | 첫 세 물리 tag | 처음 나타난 map 인덱스 | D1 token · 블록 내 레코드 바이트 위치 | 이후 ARM이 실제로 정한 슬롯 · 발행 시각 |
|---|---|---|---|---|
| 952 | 6542, 6558, 6574 | 528, 561, 594 | 5 · 83, 163, 243 | 119, 120, 121 · 24.942–25.853 ms |
| 954 | 6156, 6157, 6158 | 557, 558, 559 | 5 · 153, 163, 163 | 123, 124, 125 · 25.307–25.513 ms |

시간 원점은 각 입력 시작이다. 두 세대 모두 여섯 번째 D1 블록까지 검사하면 약 9.06 ms에 세 tag가 있다. 첫 E9에는 ROM을 읽지 않는 슬롯 0의 지우기 명령도 포함된다. 슬롯은 행 분할·예외·현재 프레임에서 이미 쓴 슬롯·목적 뱅크의 유효 상태에 의존한다. 앞의 map 레코드만으로 이를 예약하면 이후의 정식 계획과 충돌할 수 있다.

비교 대조군인 ‘첫 블록의 서로 다른 tag 세 개’는 두 장면에서 모두 0/3이었다. 후보 ARM 코드는 입력 시작 시 **다음 표시 대상 뱅크**에 이미 있는 일반 BG tag를 1,024 B 비트맵에 표시한다. 이후 성공적으로 수신한 map에서 아직 표시하지 않은 세 tag만 고른다. 해당 슬롯이 나중에 바뀌거나 hint가 빗나가면 정식 계획은 원래 ROM 경로를 쓴다.

## 비용과 표시 마감

Cortex-M4로 컴파일해 실행한 선택·중복 제거·요청 CRC까지 952는 13,365명령, 954는 12,980명령이었다. 실험용 17 B 요청은 epoch·generation·세 tag·CRC를 담는다. 84 MHz, CPI 2와 2.625 MHz SPI, E9 드라이버의 측정 평균을 대입해 추가 직렬 비용 전체를 기존 입력·첫 E9에 더했다. 952는 0.419 ms, 954는 0.410 ms다. 이 요청용 보드 드라이버와 FPGA 수신기는 아직 모델이다.

| 세대 · 위상 | 임시 48 B 채움 완료 | 첫 BG 묶음 데이터 준비 대조→후보 | 모든 필수 ROM 읽기 완료 대조→후보 | 60 Hz 마감 전 ROM에서 가능한 최대 바이트 / 필요량 |
|---|---:|---:|---:|---:|
| 952 · 1 | 15.844 ms | 32.483→26.675 ms | 32.839→32.694 ms | 179 / 208 B |
| 952 · 2 | 15.654 ms | 32.294→26.675 ms | 32.650→32.505 ms | 195 / 208 B |
| 954 · 1 | 16.065 ms | 32.705→26.326 ms | 33.216→33.095 ms | 8 / 272 B |
| 954 · 2 | 16.102 ms | 32.741→26.326 ms | 33.252→33.132 ms | 8 / 272 B |

첫 세 열은 동일 509 ROM 중재 기록에서 48 B를 먼저 읽고, 정식 E9 이후의 cache hit은 즉시 사용할 수 있으며 나머지 요청도 즉시 제출할 수 있게 한 민감도 비교다. 이 표에서는 실제 65816 DMA·VBlank·최종 ACK를 실행하지 않았다. 첫 묶음의 읽기는 전체 읽기 시간에 포함된다. 마지막 열은 별도 상한이다. 나중에 실제로 필요한 주소를 미리 알고, 해당 tag가 현 입력에서 검증되는 즉시 공짜로 요청하며 무제한으로 보관할 수 있다고 뒀다. 기한은 **직전 표시 + 16.667 ms**다. 따라서 이 시작 시각과 중재 조건에서 954는 현재 입력을 받은 뒤 ROM만 읽는 방식으로는 최소 **264 B**가 부족하다.

ARM 선택기는 단독 text 400 B, 상태 1,040 B, 송신 버퍼 17 B, 자체 최대 stack 24 B다. FPGA에는 원본 48 B 외에도 tag·identity·채움 상태와 중단 중 응답 처리 비용이 필요하다. 이 비용을 보드 전체 FIT나 순 Flash 증가량으로 환산하지 않았다. 604 전체 링크가 이미 112 B 초과다.

## 복구와 검증 범위

실제 선택기는 이력이 없는 cold 상태에서 요청을 만들지 않았다. 참조 수신기에서 잘린 요청 0–16 B, 각 바이트 1비트 손상, epoch·generation 불일치를 검사했다. 15 B만 채운 행과 입력 COMMIT 전 데이터는 소비할 수 없었다. 읽기 도중 STOP을 걸면 임시 상태를 폐기하고 마지막 응답을 배출할 때까지 같은 identity 재시작도 막았다. 실제 주소와 값은 601의 고정 demand·원본 CHR과 대조했다. 새 캐시가 보드의 슬롯·receipt·표시 ACK를 쓰는 경로는 추가하지 않았다. 실제 IRQ, 새 요청과 입력 사이에서 달라질 수 있는 D0 busy 횟수, 새 FPGA·65816 통합, 보드 STA와 실기 메뉴 복귀는 미검증이다.

## 다음 판정

**3-tag 캐시를 보드에 추가하는 일은 보류한다.** 현재 일정에서는 입력 COMMIT 확인 자체가 60 Hz 표시 마감보다 약 1.69–1.85 ms 늦고, 첫 E9도 약 9.97–10.30 ms 늦다. 다음은 954를 기준으로 입력 블록·계획·출력 작업 중 어느 부분을 직전 표시와 겹칠 수 있는지, 이전 표시 ACK를 지켜야 하는 부분은 어디인지 같은 시각축에 올리는 일이다. ROM 쪽은 601에서 현재 PPU 캡처에 실제로 있던 272 B 가운데 적어도 264 B를 제때 제공할 수 있어야 한다. 두 조건을 함께 만족시키는 구조에만 전체 보드·65816 비용을 투입한다.
