# 597 · 페이지 묶음의 실제 SPI 비용과 source 교체 예산

**페이지 묶음은 유지하고 595 source의 국소 최적화는 여기서 마친다.** 594 ARM과 연결한 595 SPI 핀에서 905·906 각각 698 B와 97거래를 줄였다. NES 값 경로·헤더와 host SPI 응답까지 줄인 결합 MAP은 2,625 LE였다. 선별 상한 1,816 LE까지 809 LE가 남는다. [측정 결과와 재현 해시](../analysis/region597-verification.json)

## 같은 입력에서 달라진 전송

실제 594 ARM ELF가 cold 905와 warm 906을 연속 수신했다. 원래 595와 묶음 회로는 같은 collector 캡처, query 응답 지연, host/NES 클록, 2.625 MHz SPI 핀, 단일 페이지 및 원래 135비트 명령 CDC를 사용했다. 기존 블록 형식과 단계 끝 표식을 보존하고, 최대 literal 길이가 남은 공간 안에 들어갈 때만 그 페이지에서 다음 블록을 쓴다. 블록이 압축되면 실제 끝 위치부터 이어 쓴다. [RTL 변경 생성기와 공동 실행](../tools/budget_nes_region597.py)

| 전체 입력 | 595 대조군 | 597 묶음 | 감소 |
|---|---:|---:|---:|
| cold 905 | 47패킷 · 202거래 · 4,402 B | 21패킷 · 105거래 · 3,704 B | 97거래 · 698 B |
| warm 906 | 39패킷 · 172거래 · 2,692 B | 13패킷 · 75거래 · 1,994 B | 97거래 · 698 B |

두 입력 모두 nonmap 데이터 32페이지가 6페이지로 줄었다. 596에서 계산한 D1·D2·D0 반환 확인의 고정 절감 78거래·546 B에 더해, 나머지 D0 조회가 순감 19회·152 B였다. D0 응답을 다시 기록하니 반환·요청·PREPARE 직후의 확인을 제외한 ready 응답은 905에서 44→18회, 906에서 36→10회였다. 같은 분류에서 ready=0 응답은 두 입력 모두 11→18회였다. 따라서 26회 절약에서 7회 추가 대기를 빼면 19회다. SPI 점유 절감은 입력당 2.127 ms다. ARM의 계산, ROM 중재, IRQ, 65816 DMA·VBlank가 같은 시간만큼 앞당겨진다는 뜻은 아니다. [596 전송 예산](nes-pages596-budget.ko.md)

| NONMAP 진입 → 데이터 페이지 봉인 · NES 클록 | 595 | 묶음 |
|---|---:|---:|
| 첫 metadata · 905/906 | 229 | 1,599 |
| 첫 raw · 905/906 | 229 | 3,650 |
| 데이터 페이지 생산 구간의 합 · 905 | 8,609 | 8,563 |
| 데이터 페이지 생산 구간의 합 · 906 | 8,583 | 8,537 |

45.454 ns 클록에서 첫 metadata는 10.41→72.68 µs, 첫 raw는 10.41→165.91 µs였다. 첫 페이지를 더 오래 기다렸지만 모든 페이지의 생산 구간 합은 입력당 46클록(2.09 µs) 줄었다. 합에는 봉인 후 host가 D1/D2를 마칠 때까지의 대기가 들어가지 않는다. 별도 SPI 점유와 합산해 전체 프레임 시간으로 쓰지 않는다.

## 같은 Quartus Lite 경계의 삭제 비용

NES에서는 현재 값 하나를 다음 query 응답까지 보존해 이전 값과 비교하고, 고정된 값을 바이트 위치로 선택해 전송한다. 처음 값과 매번 비교하던 반복 판정은 인접한 값이 모두 같은지 누적하는 것으로 바꿨다. linear 판정에는 이전 값의 raster 다음 값을 사용한다. 헤더는 낮은 바이트를 쓸 때 높은 바이트를 보존한다. SPI는 첫 명령 바이트에서 상태를 고정한 뒤 실제 응답 바이트 순으로 CRC8을 계산하고 D1/D4 CRC16 누적기를 공유한다.

| 지역 MAP · RAM 모두 2,048 bit | LE | 조합 | FF |
|---|---:|---:|---:|
| 595 원래 CDC·단일 블록 | 3,041 | 2,308 | 1,278 |
| 595 원래 CDC·묶음 · 핀 시험과 같은 RTL | 3,112 | 2,379 | 1,286 |
| 596 진단 CDC·CRC/주소 공유 | 2,708 | 2,245 | 979 |
| 596 + NES 값·헤더 변경 | 2,589 | 2,190 | 859 |
| 596 + SPI 응답 변경 | 2,694 | 2,231 | 963 |
| 두 변경 결합 · 묶음 전 | 2,554 | 2,155 | 843 |
| 두 변경 결합 · 묶음 포함 | **2,625** | **2,226** | **851** |

892 LE 초과에서 값·헤더와 SPI 변경을 함께 적용해 154 LE를 회수했다. 묶음 제어가 71 LE를 사용해 실제 설명된 순감은 83 LE다. 2,625 LE에는 안전한 bundled-data CDC 보호와 물리 타이밍 여유가 포함되지 않았다. 기능 시험을 거친 묶음 회로는 원래 CDC를 사용한 3,112 LE 행이다.

교체 경계 자체도 확인했다. 헤더/END/행 요약 바이트·SPI 상태 응답 바이트·반복/linear 비교 결과를 18개 외부 입력 핀에서 무상으로 공급하는 진단은 **1,909 LE**였다. 기존 204핀에서 222핀으로 경계를 바꿨고 관측되지 않는 CRC·카운터·선택기도 Quartus가 제거할 수 있다. 상대 생산기와 독립 검사 복원 비용을 포함하기 전부터 상한보다 93 LE 크다. 이 수치는 현재 구조의 특정 삭제 실험이며 다른 구조의 물리적 하한은 아니다. [MAP 및 핀 결과 결합 도구](../tools/analyze_nes_region597.py)

## 검증 범위와 후속 작업

원래 CDC를 유지한 묶음 RTL에서 warm 수신 값·tile tag가 원본과 일치했다. 첫 행 값을 바꾼 cold에서 ARM의 독립 CRC가 REPAIR를 요청하고 29행을 전부 다시 받아 MAP_ACCEPT했다(6,122 B·147거래). warm D1을 3 B에서 끊은 뒤 D2를 시도하자 token 32와 lease를 유지했다. STOP/reset 뒤 전체 905를 정상 cold와 같은 3,704 B에 복구했다. 정상 최종 ACK는 표시 1회·EA 뒤 IDLE, 잘못된 generation은 표시 0회·EA 차단, EA 중 STOP은 표시 1회·COMMITTED였다. 입력 상대는 실제 SPI RTL과 캡처 기반 collector다. 표시·ROM 상대 장치는 모델이다. 53입력 전체 핀 회귀와 새로운 실기 측정은 범위 밖이다.

588에서 580의 밀집 일정 중 입력만 제외하고 다른 항을 고정했을 때도 두 시작 위상에 59.983/59.989 ms가 남았다. 이번 SPI 절감은 그 출력·계획 시간을 줄인 측정으로 셈하지 않는다. [기존 전체 일정의 비용 분리](nes-source588-results.ko.md)

다음 판정은 MMC577의 collector가 행·메타데이터를 확정하는 시점과 기존 source/SPI 페이지의 포트 소유권을 함께 대조하는 것이다. 계산을 옮길 때 실제로 삭제되는 source 본체, collector 쓰기 대역·CRC 이력, cold·부분 수신 뒤 복구, ARM Flash, 출력·최종 ACK까지 남는 시간을 한 비용표에 넣는다. 595 헤더/응답만 재합성하거나 같은 2,625 LE 후보에 전체 FIT·두 위상 시험을 반복하지 않는다. 실기 기준은 MMC577이다.

재현은 `budget_nes_region597.py map <parts>`, `map-combined <combined>`, `map-free <free>` 세 모드로 Quartus Lite 보고서를 만든다. 단일 FLOAT 래퍼에서 `sim <sim-dir> --arm <594 ARM01/src> --archive <581 evidence01.zip>`를 실행한다. 이어서 같은 래퍼에서 `poll <poll-dir>`에 동일한 ARM·archive 인자를 주고 D0 응답을 분류한다. `analyze_nes_region597.py <sim-dir> <parts> <combined> <free> <poll-dir> <result.json>`으로 결합한다. 최초 test01과 map01의 결합 시도에서 page_end 선언 위치와 생성한 블록 종결 오류가 발견돼 수정했다. 최종 선택은 test02·poll01, map01의 개별 두 보고서, map02와 map03이다.
