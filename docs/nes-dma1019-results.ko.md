# MMC1019 — 192B map DMA 시작과 section 5 발행

MMC1012를 실기 기준으로 유지한다. 모험도 4의 23행 화면(원본 3462, 재생 세대 908)에서 map 오프셋 768의 192B를 두 위상 모두 직전 VBlank에 전송했다. 실제 ARM 후보는 DMA 시작을 253선에서 245선으로 앞당겼고 246선에 192B를 끝냈다. 해당 화면 공개는 여전히 다음 VBlank였다.

## 65816이 DMA를 시작하는 순간에 보낸 경우

65816의 실제 MDMAEN 쓰기($420B)에서 세대·map 오프셋·길이·VRAM 포트를 대조했다. 이 시점을 즉시 알 수 있는 실험용 송신기는 이미 전송 중인 map 패킷을 마친 뒤 첫 빈 SPI 구간에 201B, 이어서 240B를 발행했다. 다른 패킷의 순서, 큐 credit, 타일 관측 하한과 65816 검사를 보존했다. 두 위상에서 발행 전의 192B DMA 시작 클록은 원본과 정확히 일치했다. 이 신호는 실험의 비교용 입력이다. MMC1012에서 ARM이 받는 E0의 bit 3은 해당 head의 반환과 idle map DMA **완료**를 확인한다.

원본에서는 두 위상 모두 VBlank 38의 253선에 DMA가 시작됐고 그때 다음 192B map의 SPI 전송이 진행 중이었다. 비선점 전송이 끝날 때까지 0.340 / 0.292ms가 걸렸다. 이후 다른 SPI 점유를 모두 풀어준 낙관 대조에서도 SEAL 수락만 1.207 / 1.084ms 앞당겼고 공개는 VBlank 39의 242선에 머물렀다. 기존 비-E1 거래의 시간대를 그대로 예약한 민감도 실험에서는 두 위상 모두 VBlank 40에 공개됐다. 예약 실험은 ARM의 적응형 polling 일정을 다시 계산하지 않으므로 실기 회귀량으로 사용하지 않는다.

현재 SPI 속도·측정 거래 길이에서 두 패킷은 각각 15,471·18,024 마스터클록을 차지한다. 합계 33,495클록(1.560ms)은 VBlank 첫 225선 시작부터 246선 끝까지의 최대 30,008클록(1.397ms)을 초과한다. DMA를 225선 첫 클록에 시작하고 ARM 통지, 다른 SPI 거래, 수락·검사, SEAL과 잔여 DMA를 모두 0클록으로 두어도 3,487클록(0.162ms)이 부족하다.

## MMC1012의 실제 ARM과 기존 완료 응답

별도 최종 링크에서 대상 192B map을 하나 발행한 뒤 기존 E0 완료 응답을 제한 횟수만큼 기다렸다. 정상 경로의 CRC·identity·credit 검사와 준비된 타일의 우선권을 유지했고, 시간 내에 완료가 확인되지 않으면 나머지 map을 먼저 보낸다. 8개 연속 캡처를 기존 캐시 조회와 ROM 허가 일정으로 ARM·65816에서 재생했다.

| 세대 908 | MMC1012 ① / ② | E0 후보 ① / ② |
|---|---|---|
| 192B map 시작 | VBlank 38, 253 / 253선 | VBlank 38, 245 / 245선 |
| SEAL 수락 변화 | 기준 | 0.094ms 빠름 / 0.199ms 늦음 |
| 잔여 DMA 종료 | VBlank 39, 240 / 240선 | VBlank 39, 239 / 239선 |
| 화면 공개 | VBlank 39, 242 / 242선 | VBlank 39, 241 / 241선 |
| 표시 최종 ACK 변화 | 기준 | 0.029 / 0.027ms 빠름 |

192B의 실제 DMA 시작부터 해당 반환의 유효 E0 수신까지는 0.274 / 0.228ms였다. ARM은 준비된 OBJ의 우선권과 큐 검사를 거쳐 201B의 SPI 발행을 DMA 시작 후 0.940 / 0.894ms, 240B 발행을 2.113 / 2.067ms에 시작했다.

연속 8개 캡처의 마지막 세대 912 ACK는 0.031 / 0.049ms 빨라졌다. 최종 링크는 212,940B(여유 52B)다. 패킷 내용과 타일 token·데이터, 출력 map과 화면 해시는 각 세대에서 기준과 일치했다. 동일한 캐시 조회 기록을 사용했고 배정된 ROM 읽기도 3,136회로 같았다. 마지막 OBJ까지의 실기 적중을 새로 계측한 결과는 아니다.

실험 송신기와 ARM 후보 모두 잘못된 SEAL과 복원 중 STOP에서 직전 화면을 보존했다. ARM의 SRAM 송신·retire와 메뉴·base 복구 경로를 실행했고, 외부 보드 및 프로그래머는 복구 모델을 사용했다. 실기 전달본은 만들지 않았다.
