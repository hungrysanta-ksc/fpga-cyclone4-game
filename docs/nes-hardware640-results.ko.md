# MMC639 실기 2회 — 표시 도중 중단과 첫 표시 준비 시간 초과

두 실행 모두 393,216 B 적재·전체 비교·START를 통과하고 STOP·base 복구와 MENU_PREPARED에 도달했다. 사용자도 두 번 모두 메뉴 복귀를 확인했다. DISPLAY_NEXT→DISPLAY_STOPPED는 각각 1.37초와 5.01초다. 두 실행은 60초 성능 표본에서 제외한다. [6개 원본 해시와 판정 필드](../analysis/hardware640-mmc639.json)

| 항목 | 1차 | 2차 |
|---|---|---|
| 준비 단계 | 310 ms, stage 3 | 5,000 ms, 44,203회 조회 뒤 TIMEOUT |
| 표시 완료 | 20화면, 마지막 generation 31 | 0화면, native 전송 0건 |
| 중단 지점 | generation 32의 plan FINISH에서 E8 flags 오류 | stage 0에서 부팅 준비 미완료 |
| 마지막 준비 응답 | 01fca903 | 01580000 |

1차의 21회 trace commit은 입력 측 기록이고, 최종 표시 수는 native_frames=20이다. E8 응답은 `00d7048000020000000000000000000000000057`이다. 응답 CRC와 수락 개수 2는 맞고, FPGA가 flags=0x80을 반환했다. 선택 RTL의 nes_plan_spi200에서 이 비트는 로컬 fault와 source_fault의 OR이다. source_fault에는 상위 취소 신호가 연결돼 있어 최초 발생 블록은 로그로 구분할 수 없다. 최초 오류를 보존한 채 E9·END 수락 및 bulk 소비·lease 경계를 재현하는 것이 우선이다. 252번 선 DMA 또는 START 버튼이 원인이었다는 증거는 없다.

2차는 MMC551 실패 때와 준비 상태 전이(01480000→01580000)와 제한 시간, 첫 표시 전 중단 지점이 같다. 같은 원인인지는 미확정이다. 이 경로는 별도로 부트 진입·WRAM 복원·첫 준비 응답 경계를 구분해야 한다. 두 실행에서 5–40초와 40–55초를 비교할 수 없다. 성능 기준은 MMC613이다.
