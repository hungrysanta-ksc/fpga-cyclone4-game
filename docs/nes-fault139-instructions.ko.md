# NES139 — 최초 ROM 오류 수집 시험

138에서 적재·전체 대조·메뉴 복귀·복원은 성공했지만 NES 실행 중 ROM 응답 마감 오류가 확인됐습니다. 이번139는 **그 순간의 주소와 읽기 상태를 수집하는 수정판**입니다. 화면 오류 자체가 해결됐다고 판단한 버전은 아닙니다.

## 복사와 실행

1. 전원을 끄고 SD의 현재 `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`을 별도 보관합니다.
2. ZIP의 **`01-SCREEN139-SD-ROOT` 안의 내용**을 SD 최상위에 덮어씁니다. 펌웨어·`fpga_n139.bi3`·`nes/screen139.nes`를 함께 적용합니다.
3. 메뉴에서 **`NES SCREEN 139.nh1`**을 한 번 실행합니다. 선택 파일은 **0바이트가 정상**이며 확장자를 바꾸지 않습니다. 이전138 파일을 실행하지 않습니다.
4. 메뉴로 돌아오면 전원을 끄고 아래 두 TXT를 회수합니다.
5. **`02-RESTORE044-SD-ROOT` 안의 내용**을 SD 최상위에 덮어써 복원합니다. 메뉴와 기존 GBC 동작을 확인합니다.

## 예상 시간과 화면

화면이 바로 나오지 않습니다. 앞의80KiB 적재·전체 대조는 유지하며, 이전138은 화면 단계까지 약8분43초가 걸렸습니다. 이번에도 **실행부터 최대10분**을 관찰 기준으로 삼습니다. 이는 실행시간 보장이 아닙니다.

정상이면 약10초간 표시한 뒤 메뉴로 복귀합니다. ROM 오류가 관측되면 기다리던 표시 구간을 끝내고 오류 정보 수집→RESET 재유지→STOP→메뉴 복귀를 진행합니다. 따라서 같은 오류가 나면 화면이 잠깐 깨지거나 화면을 알아보기 전에 복귀할 수 있습니다. 오류 검출 주기는 명목50ms이며 실제 관측·복귀시간을 보장하는 값은 아닙니다.

10분이 지나도 복귀하지 않으면 전원을 끄고 남은 로그를 회수한 뒤044로 복원합니다. 같은 시험을 연속 반복하거나 리셋 버튼으로 복귀를 시도하지 않습니다. **이번에는 영상이 필수가 아닙니다.** 화면 상태와 메뉴 복귀 여부만 알려주세요.

## 전달할 파일

- `sd2snes/nes-progress-139.txt`
- `sd2snes/nes-screen-last-139.txt`
- 메뉴 복귀 여부, 화면 상태,044 복원 후 메뉴·GBC 동작 여부

로그 내용을 직접 해석할 필요는 없습니다. 새 필드 `run_first_error`와 `run_stop_error`는 실행 오류와 종료 검사 오류를 구분합니다. `fault_context_valid=1`이면 최초 오류 당시 주소·요청 소유자·대기 길이가 `fault_context_hi/lo`에 남습니다. `run_passed=1`도 자동 화면 판정은 아닙니다.

표시/RUN 중 SD 쓰기는 금지합니다. 정보는 FPGA/MCU 메모리에 보관하고 정상 복귀 뒤 TXT로 저장합니다. SPI/RDY 등 공통 고장 시에는 기록을 강행하지 않으므로 최종 TXT가 없을 수 있습니다. 이 경우 진행 TXT와 파일 유무·크기도 알려주세요.

## 범위

139는138과 같은 고정 진단 ROM·READ16/168MHz 읽기 시간을 사용합니다. 화면·패드·오디오·SMB3 플레이 완료가 아니며, 외부 보드 지연·MTBF·모든 고장 안전성의 실측 승인을 뜻하지 않습니다. 기존 E1/E2·8µs·양클록 정지CE9µs 미보장과 source-lock 보류4건은 유지합니다. 새 분해·LED 확인·PC 직접 연결은 필요하지 않습니다.
