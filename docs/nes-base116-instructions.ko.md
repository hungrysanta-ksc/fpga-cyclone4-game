# NES116 — 기본 FPGA 복구만 짧게 확인

113 실기 로그는80KiB 적재·전체 읽기 비교·STOP까지 통과했고,487.45초의 BASE_START 이후 기록이 없었다.116은 그 뒤의 복구 구간만 확인하는 진단이다. 원인이 해결됐다고 주장하는 펌웨어는 아니다.

## 실행할 파일

**이번에는 `NES BASE 116.nh1`만 실행한다.** 이전 `NES VERIFY 094 80.nh1`이나 `NES ENTRY 113.nh1`은 이번 시험 대상이 아니다. 표식 파일은0바이트가 정상이다.

1. 전원을 끈 뒤 ZIP의 `01-BASE-SD-ROOT` 안 내용을 SD 루트에 복사한다. `sd2snes/firmware.stm`, `fpga_n86.bi3`, `fpga_base.bi3`, `m3nu.bin`과 루트의 새 표식이 들어간다.
2. 메뉴에서 **`NES BASE 116.nh1`을 한 번 실행**한다. CF86 구성→빈 상태 STOP→기본 FPGA 복구→메뉴 복귀를 시도한다. NES 데이터 적재·비교와 게임RUN은 생략한다.
3. 메뉴 복귀 여부를 확인한다. **60초가 지나도 복귀하지 않으면 전원을 끈다.** 리셋 버튼이나 같은 표식 재실행으로 반복하지 않는다.60초는 관측 한도이며 MCU 최악 실행시간 보장이 아니다.
4. 전원을 끈 상태에서 `/sd2snes/nes-progress-116.txt`와 `/sd2snes/nes-verify-last-094.txt`를 복사해 전달한다. 최종094 파일은 오래된 파일일 수 있으므로 새116 로그를 우선한다. 없거나0바이트라면 그대로 알려준다. 영상은 필요 없다.
5. 정상 사용으로 돌아가기 전 `02-RESTORE044-SD-ROOT` 내용을 SD 루트에 복사한다. 기존044 복원 파일을 그대로 포함했다. 이번에 확인하지 않은 복원/GBC 결과는 성공으로 추정하지 않는다.

기존SD 파일을 삭제하거나 포맷하지 않는다. 동일 표식을 다시 실행하면116 로그가 덮어써지므로 한 번의 결과를 보존한다.

## 로그에서 구분하는 경계

| 기록 | 뜻 |
| --- | --- |
| EMPTY_STOP_NEXT / STOP_DONE | 빈 CF86에서 STOP 전 / STOP와세션정리 완료 |
| BASE_FILE_OPEN_NEXT / BASE_FILE_OPENED | 기본 이미지 열기 전 / 성공·파일크기 |
| BASE_PINS_READY | nCONFIG·nSTATUS·DONE 초기조건 검사 통과 |
| BASE_STREAM_END | 구성 데이터 전송 루프 종료·출력바이트, total=1이면디코더 완료 |
| BASE_DONE_HIGH / BASE_DONE_TIMEOUT | 구성 뒤DONE 확인 성공 / 시간초과 |
| BASE_PGM_OK / BASE_PGM_REJECT | 구성 함수 성공 / 거절, bytes는진단오류번호 |
| BASE_SPI_STATE_NEXT | SPI BSY/TXE 검사 직전 |
| BASE_TOKEN_NEXT / BASE_TOKEN_RESULT | 기본 FPGA 응답 요청 전 / 수신값과기대값 |
| BASE_DONE / MENU_PREPARED | 기본 FPGA 확인 완료 / 메뉴 준비와로그 저장 완료 |

각 기록의 `spi_sr`와`spi_cr1`은 SPI 레지스터의 관측값이다. 사용자가 직접 해석할 필요 없이 파일을 그대로 전달하면 된다.512바이트 기록에공백이많은것은정상이다. 최종094 보고의 `verified=0`은 이번 복구 전용 시험에서 정상이다.

MENU_PREPARED는 실제 화면 복귀와 별개다. 실패나 공유고장 뒤에는 로그 쓰기를 강행하지 않으므로 마지막 기록은 실패 위치의 범위이며 반드시 그 줄에서 멈췄다는 뜻은 아니다.

## 이번 시험의 한계

긴 적재·비교를 생략하고 단계 기록을 추가했으므로, 장시간 실행 뒤에만 생기는 오류나 기록 추가에 민감한 타이밍 문제가 재현되지 않을 수 있다. 성공하더라도 기존80KiB 전체 경로의 메뉴 복귀를 통과했다고 판단하지 않는다. 후속 판단은 이번 로그와 실제 화면을 함께 사용한다.

기존 CSS/NMI·RESET·USB 차단은 유지한다. SD 공유고장·CSS 고장 뒤 추가SD/FPGA IO를 하지 않는다. 게임 구동·외부 전기조건·공통원인8µs 보장을 확인하는 시험은 아니다.
