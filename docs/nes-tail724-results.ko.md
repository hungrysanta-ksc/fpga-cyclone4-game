# NES724 준비된 bulk 인계·후반 준비 순서 검증

## 목표

723C의 BG ROM 마감 회복·map 연속 DMA를 유지하고, 준비된 OBJ의 발행 대기와 마지막 tile 뒤 SEAL 대기를 함께 줄인다. 같은 작업량과 두 시작 위상에서 952–957 표시 간격·마지막 ACK, 951·911·952·957 보호 조건을 비교한다.

## 작업내용

기존에는 마지막 map 발행 뒤719의 DMA 기회 대기를 먼저 수행하고, 다음 ordinary 패킷을 만들 때에야 producer를 조회했다. 새 후보는 warm map 발행 직후 기존 `nes_plan200_progress(NES_ORDINARY553)`를 호출한다. 준비된 descriptor가 있으면 기존 poll이 CRC·generation·token·STOP을 검사하고 실제 map ACK와 제한된 다음 입력 수신을 거쳐 bulk를 인계한다. 이때 마지막 queue 항목이 tile로 바뀌므로 뒤의 map 전용 대기를 생략한다. 준비된 bulk가 없으면 기존 map 대기가 그대로 남는다. 수락·소비·최종 표시 ACK의 의미는 바꾸지 않았다.

raw CHR의 compact 변환과 팔레트·OAM 재사용 비교를 map 전송 앞에 옮겼다. 원본 CHR은 유지하며, planner 완료 뒤 수명이 끝난 BG key 공간만 기존 방식대로 사용한다. 마지막 ACK 전에는 표시 이력을 확정하지 않는다. 새 버퍼·정적 상태·SPI 명령·대기 상수·세대별 예외가 없다.

A는 위 변경만으로 정상 Flash가36B 초과했다. B는 기존 팔레트 offset128에서 실행하던 반복 drain4회를 함께 제거했다. 실제 queue credit·CRC·identity와 SEAL barrier는 그대로 남는다. 이 반복 대기 삭제가 표시를 지킨다고 가정하지 않고 전체 재생에서911/951을 별도 판정한다.

실제 링크 ARM·65816을 실행하며 CPI2/84MHz, 공유SPI·IRQ 모델과 기존 주기적 ROM 달력을 사용한다. 두 시작 시각7288416/7467100, payload·map·tile·plan은723과 동일하다. 전체 NES/PSRAM RTL 동시실행이나 새 실기 FPS·물리 메뉴 복귀 증명은 아니다.

## 성과

**724B는 기능·자원 검증을 통과했지만, map DMA·BG 마감·종단 시간 조건에서 기각했다.** 두 위상106화면의 map·tile·plan·픽셀은723과같고독립검사·STOP·최종ACK·메뉴경계는통과했다. 그러나준비된OBJ를일찍발행하는것만으로는기존mapDMA기회를유지하지못했다. 현재선택본은707D·기존ARM/65816이며,다음조사의시간기준은723C로유지한다.

### 956은 빨라졌지만 map 기회를 소비했다

준비된첫OBJ bulk 발행은직전표시후33.802/33.649ms에서27.743/27.484ms로앞당겨졌다. 실제시작시각기준마지막OBJ응답은5.755/5.968ms,마지막tile ACK는5.849/5.967ms,SEAL은5.494/5.589ms빨라졌다. 다만마지막tile 뒤SEAL대기는3.059/3.060→3.414/3.438ms로늘었다. 남은후반작업을없앤결과가아니며,선행map896B를잃은비용까지포함하면표시회차는여전히3이다.

### 952의 지연이 다음953의 ROM 마감을 다시 무너뜨렸다

952 표시는238→249선으로늦어져953의직전표시시각이0.700/0.699ms밀렸다. 953 마지막BG E9도동일절대시각에서0.687/0.707ms늦어졌고,마지막BG ROM응답은16.270/15.956ms늦어졌다. 첫BG가사용하는ROM허가구간은같지만마지막BG만다음구간으로넘어갔다. 723의ROM마감회복을유지하지못했다.

953의마지막tile 뒤SEAL간격은5.120/5.350→3.477/3.480ms로짧아졌지만,이미tile ACK가2.694/2.935ms늦어진뒤다. SEAL자체는1.051/1.066ms느려졌다. 이구간차이만뽑아전체가속으로계산하지않는다. 957의SEAL도0.325/0.411ms빨라졌으나최종ACK는오히려위표만큼늦다.

첫분석schedule01은ROM구간번호를직전표시에상대비교하여,표시가약0.70ms늦어ROM구간경계를넘은효과와BG지연이서로상쇄됐다. schedule02는실제첫BG→마지막BG의서비스구간수가0→1로늘어난것을검사한다. 원시실행·타깃은그대로이며잘못된분석도보존했다. inherited720 audit의offset표시는실제로header12..13의payload길이이므로724공개기록에서는wire_payload_B로명명했다. 주소·작업량동일성은별도의실제map복원으로검사했다.

정상/장시간 각각11조건의 실제 linked seal 검사는 producer ready/empty/fault, STOP·잘못된credit·최종ACK·cold·reset, 1/2행 raw 변환과 발행 전 검사를 포함한다. producer와 queue 상태는 이 경계 시험에서 주입하며, 실제 poll의 CRC·token·STOP 및 전체 실행은 별도 검사한다. 기존719 마감17조건·721 gate10조건·bulk24조건·END소유권7조건·수신credit9조건·런타임16조건·CRC16 240길이·정상/장시간 메뉴 각9조건을 실행한다. 변경 없는723 행 공급·CRC8과 slot 검사 근거를 승계한다.

FPGA·65816·SDC가 같으므로 기존707D 전체 Lite FIT15322LE·962/963LAB·56/56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다. 새 합성·회로 절감·외부IO 승인 확대는 없다.

## 후속작업

1. 723C의행완료BG공급·초기묶음·map연속DMA를기준으로돌아간다. 724B의64B절감이나956의5.5ms이득을따로선택본에합치지않는다. 독립분리검증전까지723의정상Flash여유는여전히0B다.
2. ARM의producer-ready만보고map대기를건너뛰는방법은보류한다. 수신완료·첫DMA진행·전체map실행완료는다르며,현재E0진행비트만으로이번선행map손실을막을수있다고가정하지않는다.
3. 다음은실제65816소비경계에서수락된map DMA와다음bulk소비를함께중재할교체범위를정한다. 빈큐가될때까지미루는기존제어를대체할수있는지,현재명령수락/완료·STOP·새패킷우선·VBlank와마지막ACK소유권을먼저확정한다. ARM고정대기상수·세대/시작위상별조건을반복조정하지않는다.

현재ARM검토경계는723의4698B/한도4700B이며724의미채택4634B를무료공간으로쓰지않는다. 새65816제어는기존ROM여유26B와교체삭제량,707D FPGA는86LE·1LAB·0M9K여유를함께검토해야한다. 새로운순삭제입증은없다. 역할변경이필요하면기존idle/완료제어삭제까지포함하고실제전체비용을먼저확인한다.

두위상952–957합계18VBlank미만·밀집평균·957마지막ACK동시개선과기존보호조건을계속채택기준으로삼는다. 새설치본·새실기FPS주장은없다.
