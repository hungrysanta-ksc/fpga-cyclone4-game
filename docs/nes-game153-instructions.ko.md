# NES153 — 오류 로그와 메뉴 복귀 수정판

152에서 새 PPU 오류 표식을 MCU가 잘못 거부하던 결함을 수정했다. **게임을 멈추게 한 PPU 읽기 오류 자체는 아직 해결하지 않았다.** 다시 일찍 멈추더라도 오류 주소를 TXT로 회수하고 메뉴로 돌아오는 것이 이번 확인 목표다. FPGA·게임·입력 처리는152와 같다.

## 설치와 실행

1. 전원을 끄고 SD의 현재 `firmware.stm`을 별도 백업한다.
2. ZIP의 `01-GAME153-SD-ROOT` **안의 내용**을 SD 루트에 복사한다.
3. 메뉴에서 **`NES GAME 153.nh1`**을 실행한다. 0바이트 표식이므로 확장자를 바꾸지 않는다. 실제 ROM은 `sd2snes/nes/game153.nes`다.

펌웨어는153이고, `fpga_n153.bi3`는 검증된152 FPGA와 **바이트가 같다**. 식별62/DC도 유지한다. ZIP에 제공된 이름과 경로를 그대로 사용한다. ROM이 포함된 개인용 ZIP은 공개하지 않는다.

## 한 번의 실기 시험

- 표식 실행 시각과 첫 게임 화면·메뉴 복귀 시각을 기록한다. 로딩은 변경하지 않았으며151 실측은 약3분50초였다. 로딩 전체 영상은 필요 없다.
- 게임 화면부터 메뉴 복귀까지 촬영한다. Start를 약0.2~0.5초 누르고 확실히 뗀다. 진행되면 방향키·A·B를 확인하고 버튼 이름을 말해준다. 화면이 멈추면 계속 연타하지 않고 자동 복귀를 관찰한다.
- RUN은 최대 약60초이며 오류가 감지되면 더 일찍 종료한다. **같은 월드맵 화면에서 곧바로 메뉴로 돌아와도 이번 오류 회수 목적에는 유효한 결과**다. 실제 게임 정상 구동 판정은 별도다.
- 실행 후 총7분이 지나도 메뉴로 돌아오지 않으면 전원을 끄고 남은 로그를 전달한다. 7분은 사용자의 관찰 상한이며 펌웨어의 전체 실행 타임아웃이 아니다.
- 한 번의 결과로 판단한다. 이전152나 변하지 않은044/GBC 복원 시험을 반복할 필요는 없다.

## 전달 자료

전원을 끈 뒤 아래 파일과 영상, 메뉴 복귀 여부·측정 시간을 전달한다.

- `/sd2snes/nes-progress-153.txt`
- `/sd2snes/nes-game-last-153.txt`

로그가 하나만 생기거나 0바이트여도 그대로 알려준다. 사용자가 로그를 해독할 필요는 없다. 최종 로그는 안전하게 STOP하고 기본 FPGA·메뉴를 준비한 뒤 저장한다. RUN 도중 SD 쓰기를 추가한 것은 아니다.

표시는 약0.5초 단위로 유지되어60fps가 아니며, DMA·다음 화면 대기 중 입력 공백이 남아 있다. Start 중복 소비 여부, 모든 버튼, 소리·저장·부드러운 표시도 미완료다. CRT 촬영의 대각선 띠는 판정에서 제외한다.

정상 사용으로 돌아갈 때는 전원을 끄고 `02-RESTORE044-SD-ROOT` 안의 내용을 복사한다. 복원 결과의 반복 보고는 요구하지 않는다.
