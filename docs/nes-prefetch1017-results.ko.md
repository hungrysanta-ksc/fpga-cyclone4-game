# MMC1017 실험 — OBJ 행 선행 읽기와 화면 공개 마감

MMC1012를 실기 기준으로 유지한다. 모험도 4의 59.70초 표본에서 주소는 일찍 알 수 있었다. 같은 타일열의 마지막 출력은 특정 ROM 위상에서 6.24–7.02ms 앞당겼다. 두 시작 위상의 화면 공개를 앞당기는 조건은 충족하지 못했다.

## 주소와 허가

실제 게임의 무입력 dot 0 재생에서 원본 화면 3600의 PPU가 태그 6270의 0행을 처음 읽은 곳은 100선 dot 269였다. 6270·6271의 두 평면 여덟 행은 115선 dot 285까지 모두 관측됐다. 각 값은 로컬 CHR ROM과 대조했다. 확정된 OBJ 레코드 20개에도 이 행이 있었고, 원본 화면 3588·3592·3596에도 같은 0행이 있었다. PPU 관측과 FPGA가 실제로 PSRAM을 사용할 수 있는 시각은 별개다.

MMC1012의 세대 1499·1531에서는 입력 완료가 첫 E9보다 각각 12.44–14.88ms, 12.45–14.88ms 빨랐다. 이 값은 ARM 입력 완료·유효 E0와 FPGA E9·최종 ACK를 연결한 범위로 클록 양자화 오차를 포함한다. MMC1016에서 확인한 11틱 대기에 실제 중재기의 허가 기록을 정렬하면 두 표본 모두 입력 완료의 가장 늦은 경계부터 직전 허가까지 약 4.2ms가 남는다. 실기 로그에는 당시 직전 허가 구간의 절대 시각이 없다. [원본 계측과 재생 조건](../analysis/prefetch1017-results.json)

## FPGA 후보와 대조

기존 geometry query의 종류·세대·hit 검사를 통과한 OBJ 응답에서만 태그와 행 마스크를 받는다. 최대 32개 레코드를 저장하고, 수요 읽기·기존 hint·plan에 우선권을 준다. 원본 PSRAM 허가와 주소가 일치하는 응답만 같은 row RAM에 저장한다. 이미 유효한 엔트리는 덮어쓰지 않는다. STOP과 lease 해제는 남아 있는 조언을 취소한다. 게임·세대·대상 태그에 대한 분기는 없다. [보드 연결](../tools/nes_prefetch1017.py) · [행 선택 회로](../tools/nes_guide1017.svh)

실기의 15개 타일, 112개 행 요청, 기존 적중 96개와 뱅크 재사용 순서를 재생했다. 이전 뱅크 반환은 해당 실기 표본의 가장 늦은 양자화 경계를 적용했다. 원본 MMC1012 RTL과 후보를 비활성화한 결과가 클록 단위로 일치했다. 아래는 나머지 캐시 위치가 비어 있는 경우다.

| 재생 조건 | 첫 미적중 행 대기, 원본 → 후보 | 첫 E9 기준 마지막 타일 완료, 원본 → 후보 | 앞당긴 시간 |
|---|---:|---:|---:|
| 실기 1차 대기와 반환에 정렬 | 8.385 → 0.00014ms | 8.593 → 1.570ms | 7.023ms |
| 실기 2차 대기와 반환에 정렬 | 8.385 → 0.00014ms | 8.593 → 2.350ms | 6.243ms |
| 1차에서 ROM 허가를 고정하고 시작만 178,684클록 이동 | 0.065 → 0.065ms | 1.570 → 1.570ms | 0ms |

앞의 두 조건에서 32회 선행 읽기 중 16회가 실제 수요를 대체했다. 나머지 16회도 ROM 비용에 포함했다. 충돌 위치에 다른 유효 행을 채운 대조군에서는 기존 96개 적중을 보존했고, 원래 16개 수요 요청과 마지막 타일 시각도 그대로였다. 세 번째 조건에서는 입력이 허가 구간 뒤에 준비돼 선행 읽기가 0건이었다. 타일 출력기의 464B를 ROM 원본으로 독립 대조했고 STOP 뒤 지연 응답 폐기·reader 유휴 복귀를 확인했다. MMC1012 ARM의 SRAM 송신·retire·타이머·메뉴 해제 검사도 재실행했다.

## 공개 마감과 다음 실험

실기의 SEAL→공개를 기준으로 직전 VBlank 246선에 도착하려면 SEAL을 적어도 10.95ms·9.00ms 앞당겨야 한다. 이는 이전 공개가 225선 이후이고 한 프레임이 262선이라는 조건에서 DMA 시간을 0으로 놓고 양자화 오차까지 유리하게 준 하한이다. 뱅크 반환을 포함한 타일 절감이 그대로 SEAL까지 이어져도 각각 3.93ms·2.76ms가 더 필요하다. 동일 VBlank 안에서의 공개·최종 ACK 이동은 이번 실험에서 계측되지 않았다. 별도의 8장 재생은 같은 OBJ 장면을 생성했지만 마지막 화면의 변경 map 행이 0개로 실기의 23개와 달라 공개 시각 대조에서 제외했다.

다음 우선순위는 23행 표본의 마지막 OBJ 뱅크 반환 이후에 발행하거나 이미 병행할 수 있는 일반 패킷, SEAL 수락, 남은 DMA를 같은 세대로 연결하는 것이다. 캐시 정책만으로 공개가 앞당겨졌다고 판정하거나 이 회로를 실기판으로 승격하지 않는다. 보드 전체 FIT·STA와 후보 실기 메뉴 복귀는 미검증이다.

## 재현

`tools/nes_prefetch1017.py`의 `capture`, `geometry`, `rtl` 순서로 로컬 ROM과 기존 NES 도구에서 원본 구간을 생성한다. `rtl`은 저장소의 Questa FLOAT 래퍼에서 실행한다. 이어서 `board`, `stimulus`로 MMC1012 소스 사본과 실기 두 회의 해시를 확인한 입력을 준비하고, 같은 래퍼에서 `tools/check_nes_guide1017.ps1`을 실행한다. 마지막으로 `report`를 실행하면 원본 대조와 각 캐시 조건을 포함한 결과 JSON이 생성된다. 게임 ROM과 원본 로그는 로컬에 둔다.
