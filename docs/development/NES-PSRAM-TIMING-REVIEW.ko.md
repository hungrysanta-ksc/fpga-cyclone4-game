## 확정한 입력

[공통 하드웨어 가이드](FXPAK-HARDWARE-REFERENCE.ko.md)에 사진·TXT·공식 자료의 대응을 기록했다. FXPAK Pro Mk.III Rev.D, FPGA EP4CE15F17C8N, MCU STM32F401RCT6, PSRAM IS66WVE4M16EBLL-70BLI 두 개, SRAM IS62WV5128EBLL-45HLI다. 추가 분해·사진·ID 진단을 요청할 이유는 없다.

PSRAM 규격은 EBLL Rev.D3(Sept.2022) -70 열을 사용한다. 실제 보드 전압/지연은 측정하지 않았다. 061 진단은 8MHz(125ns 주기), 읽기/쓰기 활성3클록, 쓰기 후 HOLD1클록이다. 이것은 전체 NES 코어의84MHz 메모리 경로에 적용한 승인이 아니다.

## 실제 RTL을 사용한 지연 대조

현재 공개 생성기로061 RTL을 새 폴더에 만들고, 저장된061 fit의 loader/reader SHA256과 일치함을 확인했다. 실제 Questa Starter FLOAT에서 **쓰기5회·CHECK 읽기1회**를 각 경우에 실행했다. 생산 RTL은 수정하지 않았으며 CPU/PPU·SPI 전체 전송·메모리 내용 검증은 이 시험 범위에 없다.

주소와 CE에 독립 지연을 넣고, CE가 내려온 직후1ps에 요청한 주소가 핀에 이미 나왔는지를 검사했다. 2ns는 원인 대조용 가정이며 실제 라우팅/PCB 측정값이 아니다. zero-delay 경계의 델타 사이클 경합을 피하기 위한1ps 관측 때문에1ps 미만 위반 검사는 하지 않는다.

| 경우 | 주소 지연 / CE 지연 | 쓰기 주소 지연 검출 | 읽기 주소 지연 검출 |
| --- | --- | ---: | ---: |
| 기준 | 0ns / 0ns | 0 | 0 |
| 주소가 늦음 | 2ns / 0ns | 1 | 1 |
| 제어가 늦음 | 0ns / 2ns | 0 | 0 |

세 실행 모두 예상한 횟수와 관측 수를 확인했다. 주소가 늦는 경우의 두 검출은 의도한 반례이며 **현재 실기 고장이나 실제 배선 위반을 관측한 결과가 아니다**. 이 결과로375ns 펄스 하나만 검사하는 모델이 시작 에지 순서를 보증하지 못함을 확인했다. 후속 변경은 이 반례를 단순히 기대값 변경으로 통과시키지 않아야 한다.

사용된 생성 RTL SHA256:

- nes_rom_loader.sv: `0044d3e95cb01df212a016e6b6d2f33ec242a32bb6df9bbc7709767adef9bfc9`
- nes_rom_physical.sv: `718ab345658c228ca27888e39e52a74cbaaafd9a667d35b850df557487128a84`
- 시험 소스: `f06e54c7bd40e89813f4641e267fff4392a31bb2def8a70edb915eee08a8ebc1`

마지막 시험 해시는 아래 공개 요약을 생성할 때 원시 파일과 대조한다. 원본 사진/실행 소스/세 로그는 로컬 `probes/fxpak-hardware-final-005/`에 보존한다. 이 문서만으로 private 원시 근거 검사를 공개 clone에서 재현했다고 주장하지 않는다. 기존061/066 동결 파일·044/GBC는 수정하지 않았다. 새 Quartus fit/STA 또는 ARM 링크는 수행하지 않았다.

## 다음 구현과 검증 순서

1. **진단 전용** 파생 회로에서 주소/byte lane/data를 먼저 준비하고 CE/WE/OE를 나중에 켜는 구간, 읽기 샘플 뒤 CE/OE를 유지하는 구간을 설계한다. 가능하면 각각 한125ns 클록을 사용해 동시 에지 의존을 줄인다. 실제 min/max 예산이 이보다 작다는 근거는 여전히 필요하다. 전체 코어 reader/loader와 기존061 이미지를 직접 바꾸지 않는다.
2. 이번 주소-late 반례, 읽기 샘플 hold, 쓰기/읽기 전환, tCEM·전원 초기화, PLL 상실/클록 정지를 포함한 monitor를 연결한다. 고정2ns 한 점뿐 아니라 허용 min/max 범위와 경계 밖 실패를 대조한다.
3. 실제 핀·같은 소스·같은 SDC의 routed min/max와 외부 예산을 확인한다. SPI 및 SNES 경계도 별도 제약/예외 근거로 정리한다. 기존 미제약 포트 수를 임의 blanket exception으로 없애지 않는다.
4. 이후 변경된 회로로 실제 C GPIO 전체80/96KiB 적재·비교·STOP 회귀와 최종 fit/STA·파일 쌍을 갱신한다. 기존065/066 파일 쌍을 새 회로 검증 결과로 승인하지 않는다.
5. 원래 SD/base/menu의 백업·호환성·복원 근거를 확보한 뒤에만 사용자에게 제한 실기 패키지를 전달한다. 기기를 작업 PC에 USB로 연결하는 방식을 전제로 요구하지 않는다.

현재 H05는 전체 배선 대응, H06은 외부 IO 승인 때문에 각각 부분/미완료를 유지한다. 설치 가능 상태로 승격하지 않는다. 부품 식별 완료와 다음 타이밍 작업의 구체적인 검출 경계를 이번 진전으로 기록한다.

## 068 외부 예산·초기 대기·읽기 활성 유지

새 CF68에 1600클록 초기 대기를 연결하고, 샘플 에지의 CE/OE 활성 제어를 별도 레지스터로 유지했다. 전체 pin 모델 정상4/실패4와 실제 routed FPGA3168경로를 확인했다. 주소→CE 외부 잔여109.498ns, read byte 경계276.658ns 등 16조건을 계산했다. PCB 각 leg20ns/추가5ns는 미측정 가정이다. locked-high 클록 정지의 CE>8µs 반례가 남으므로 외부/고장 승인은 미완료다. [068 계약](../nes-diag-safety-contract.md)을 현재 기준으로 쓴다.
