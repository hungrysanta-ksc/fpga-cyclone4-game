# GBC773 하드웨어 호환성 시험

## 원피스 8 MiB

첨부 한국어판 헤더는 MBC5+RAM+배터리(0x1B), ROM 0x08, RAM 0x02이다. 512개 ROM 뱅크와 8 KiB 저장 RAM을 사용한다. C44 로더는 ROM 크기 0x08을 처리하지 않았고 D1 블록 카운터는 4 MiB에서 멈췄다. 오디오 지연 버퍼도 8 MiB ROM 공간 안에 있었다. GBC773은 실제 파일 크기와 헤더를 대조하고 E6 응답 A8을 확인한 다음 8 MiB를 전송한다. 오디오는 PSRAM 바이트 주소 A00000–A07FFF를 사용한다.

Quartus Lite 전체 FIT는 15,136/15,408 LE, 961/963 LAB이다. 기존 제약의 타이밍 요약 48개 중 최소 여유는 +0.056 ns였다. ARM 파일은 166,932 B이다. Questa에서 원본 ROM을 512 B씩 16,384회 전송했고, 4,194,304개 16비트 쓰기와 각 읽기 반환을 원본과 대조했다. 마지막 D2, 빈 세션, 잘린 패킷도 검사했다. 사용자가 8 MiB 원피스 한국어판의 실기 실행·플레이와 다른 8 MiB ROM의 정상 실행을 확인했다. 저장 후 재실행 결과는 아직 보고되지 않았다.

[재현 빌드](../BUILD-C44.ko.md)에서 GBC773 MCU에는 `-Candidate`, FPGA에는 `--candidate`를 사용한다. 65816은 C44 재현본이다. Questa 시험에는 `gbc_load_words.sv`, `gbc_load_duplex.sv`, `tests/gbc_load_8m_tb.sv`와 `+ROM=<8MiB 파일>`이 필요하다.

SD 루트 ZIP에는 `sd2snes/firmware.stm`, `sd2snes/fpga_egbc.bi3`, `sd2snes/gbc_snes.bin`이 들어 있다. ZIP SHA-256은 `ed27842b50b6c67842a1aa5a12243d8e59ef0eed593c059168d5fc03b3dc0cfa`이다. 원래 파일명의 확장자를 `.egbc`로 바꾼 복사본을 실행한다. NES 시험 재개 시 기존 NES 시험판 파일을 복구한다.

## 원색 출력 재현

갤러가의 두 로고 다음 타이틀은 RGB555 1,214색이다. 원래 캡처 RTL은 사전이 512색으로 찬 뒤 오류 2를 발생시켰다. 해리 포터는 첨부 세이브의 슬롯 1에서 폴리오마기 → 보호 → 괴짜 웬델린으로 재현했다. 387색 화면의 행 49에서 교체 8개가 필요했고 7개를 반영한 뒤 오류 7, 상세 0x3131을 기록했다. 두 결과는 참조 에뮬레이터에서 얻은 픽셀을 실제 제품 RTL에 재생한 값이다. 실기 고장 레지스터는 수집하지 않았다. 화면 준비 대기가 길어지면 65816의 메뉴 입력 검사에도 다시 진입하지 못할 수 있다.

`tools/probe_gbc_rgb773.py INPUT.npy OUTPUT.sfc`는 160×144 RGB555 화면을 SNES Mode 3 BG1 상위 색과 BG2 하위 색으로 나눈다. SNES 색 덧셈으로 빨강 1비트·초록 2비트·파랑 1비트를 복원한다. 두 화면 모두 Snes9x에서 18회 연속 23,040픽셀이 원본과 일치했다. 상위 색만 제품 표시 RTL로 재생해도 갤러가 349,652클록, 웬델린 238,928클록에 23,040픽셀이 일치했다. 이 숫자는 시험 메모리 응답 조건의 처리 클록이다.

갤러가 1,300프레임의 5개 고유 화면과 카드 전환 211프레임의 26개 고유 화면 모두 상위 색을 행당 7회 이하로 배치할 수 있었다. 31개의 고유 화면 각각을 정지 화면 ROM으로 재생해 18프레임 연속으로 RGB555 전체가 일치하는 것도 확인했다. 하위 색 타일은 두 시퀀스 모두 한 화면 전환에 최대 11,520 B가 바뀌었다. 기존 상위 색 17,280 B와 동시에 전체 갱신하려면 28,800 B가 필요하다. 하위 색까지 기록하는 별도 캡처 어댑터는 전체 FIT에서 964/963 LAB였다. 두 번째 구현은 기존 FIFO·픽셀 위치·메모리 수락·응답 상태를 공유한다. 네 픽셀의 하위 색을 한 워드로 같은 캡처 뱅크에 저장한다. 두 번째 구현의 실제 메모리 쓰기와 상위 색 출력을 합쳐 재구성한 결과는 갤러가 349,651클록, 웬델린 238,923클록에 각각 23,040픽셀이 일치했다.

이 실험을 재현하려면 별도 작업 디렉터리에 `src/fpga`를 복사하고, 그 위치에서 `git apply --ignore-space-change <절대경로>/tests/gbc_rgb_capture773.patch`를 적용한다. Questa의 altera_mf_ver 라이브러리를 연결하고 `tests/gbc_rgb_capture773_tb.sv`를 `+VECTORS=<23,040개 RGB555 hex 워드 파일>`로 실행한다. 공유 회로의 첫 전체 보드 배선 시도는 배선 자원 112개가 두 신호 이상에 필요해 배치기로 돌아갔다. 하위 색 전송까지 포함한 실기 설치 기준은 아직 충족하지 않았다. 시험에 `+EXPORT=<접두사>`를 주면 실제 RTL의 타일 워드·팔레트 명령·저장된 하위 색이 나온다. `probe_gbc_rgb773.py INPUT.npy OUTPUT.sfc --hardware <접두사>`로 두 원본 화면을 각각 Snes9x까지 재생했고 18회 연속 전 픽셀이 일치했다. 설치본의 화면 출력은 C44이다. 실시간 출력에는 완성된 두 레이어의 동일 프레임 공개, SRAM 페이지와 VRAM DMA 일정, 새 화면 대기 중 메뉴 입력 검증이 남는다.
