# NES 135 이후 공정 점검 — 실기 실행을 기준으로 재정렬

**140 현재:** 적재·대조·TXT는 성공, 동일 CPU ROM 마감 오류와 검은 화면/메뉴 복귀 실패. [실기 결과](../../analysis/SCREEN140-HARDWARE-RESULT.ko.md)와 현재 HANDOFF를 우선한다. 동일044 반복 복원은 사용자 지시로 생략하며 아래 표의 과거 매회 회귀 요청보다 이 정책이 우선한다.

**137 현재:** A 전달과 B 실기CPU활동/STOP/메뉴/복원 완료. C 실제화면결선·제한영상시험 통과, MCU표시전환/화면실기/입력은미완료. [137 결과](../../analysis/SCREEN137-RESULT.ko.md)를우선하며 아래과거표는이력을유지한다.

2026-10-10. 사용자 요청에 따른 계획 점검이며 구현 마일스톤136이 아니다. 코드·빌드·시뮬레이션·펌웨어·증거 동결을 진행하지 않았다. 아래 순서는135 기술 인계의 세부 사실을 유지하면서 다음 작업의 우선순위를 갱신한다.

## 판단

진전은 있었지만 실기 피드백 주기가 너무 길어졌다.119 이후120–135의16단계 동안 실제 코어의 새 실기 RUN은 확인하지 못했다.122의 CPU 메모리 기한 실패와127–135의 같은 클록 실패 수정은 필요한 구현 작업이었다. 모든 단계를 불필요한 디버그로 분류할 수는 없다. 다만 로더/보호 회로/실제 핀을 순차 통합하면서 앞선 배치·CDC 검토의 일부를 새 배치에서 다시 확인하게 됐고, 세분화된 검증·문서·PR이 사용자에게 전달할 실행물보다 앞서 진행됐다.

이제 다음 산출물은 **짧게 NES CPU를 실행하고 결과 TXT와 복원 경로를 제공하는 실기 패키지**다. 디버그 체계 자체의 완성을 목표로 삼지 않는다. 데이터 전달·reset·외부 핀 중 이 시험에 필요한 검토와 MCU 연결을 하나의 전달 목표로 묶는다.

## A에 반드시 포함할 일

1. **선택135fit03를 고정한다.** 기존 HDL/QSF/라우팅을 복사해 재사용하고 새 실제 경로에 대해서만 held-data 전달·제어 동기화·reset 해제·관측 reset을 점검한다. 사용 중인 PSRAM/SPI와 비활성 SNES 버스의 방향·소유권·타이밍 조건을 구분한다. 구체적인 실패가 있을 때만 수정하고 그 영향 범위만 재검증한다.
2. **MCU 전용 연결을 우선 구현한다.** 기존116의 SD 전이·진행 로그·CSS/NMI·shared-fault·기본FPGA/메뉴 복구를 재사용한다. 새 회로의59/D4와 구형86을 혼용하지 않는다. 이 작업은 영향 검토 전체가 끝날 때까지 대기시킬 이유가 없으며, 하나의 A 산출물 안에서 함께 진행한다.
3. **정상 한 번의 최소 시험을 완성한다.** 자체 합성 진단 하나/현재80KiB 형상 하나, 짧은 RUN 한 번을 우선한다. 전체 세션이 짧다고 약속하지 않는다. 기존119 적재/비교/복구는 펌웨어 시각 약491초였고 새 쌍의 시간은 아직 미측정이다. RUN 지속시간과 전체 적재 대기 상한을 따로 표시한다.
4. **최소 관측과 복원만 갖춘다.** 기존 로그 틀에 후보·단계·RUN 전후 카운터·reset/오류·STOP/복구 결과를 연결한다. RUN 전 기록은 저장을 완료하고, RUN 중 매샘플 SD 쓰기는 하지 않는다. shared fault 뒤 SD/UART 쓰기를 강행하지 않는다. 중단 시 마지막 기록으로 구간을 좁힌다. 복잡한 현장 화면/LED/USB/trace 도구를 추가하지 않는다.
5. **최종 쌍을 한 번 확인해 전달한다.** 실제 MCU 호출→식별→START/관측/STOP 경계, 대표 불일치·timeout·오류 차단,정상 복구를 변경 범위에 맞춰 검사한다. 최종 FPGA ASM/압축과 ARM을 생성해 후보명/선택파일/해시/복사경로/044 복원/종료 안내를 맞춘다. 새 후보의 전체 적재/비교를 생략하자는 뜻은 아니며, 불변 대규모 호스트 시험의 반복을 줄인다는 뜻이다.

새 후보에서 알려진 신호 충돌·필요 타이밍 위반이 확인되면 바로 고친다. 외부E1/E2·MTBF·모든 고장 조건의 포괄적 증명을 A의 끝없는 선행 과제로 만들지 않는다. 정상전원·단일 시험에서 필요한 가정과 제한을 기록하며, 기존 CE9µs 반례나8µs 보장을 지우거나 해결됐다고 선언하지 않는다.135 후보의 실제 배포 가능 판단은 아직 완료되지 않았다.

## 빠져 있거나 약했던 항목

- **최종 MCU↔FPGA 규격 일치:** 새 식별 규격의 실제 메뉴 호출까지 확인할 항목을 A에 명시한다. 개별RTL시험 PASS로 대신할 수 없다.
- **첫 RUN의 시험 의미:** 화면은 없어도 되는B와 실제 화면/게임인C·D를 구분한다. 카운터만 늘었다고 게임 실행을 완료 처리하지 않는다.
- **전체 통합 자원:**135의885LAB는 화면 등이 제거된 셸이다. 화면·H1 programROM·mapper4를 연결할 때 자원/타이밍을 확인한다. 나중에 기능을 더한 뒤 다시 검증하는 것은 필요한 공정이다.
- **사용자 대기 안내:** 전체 시간과 RUN 구간을 구분하고,새 로그 없음/0바이트/마지막단계/메뉴미복귀 각각의 회수 방법을 패키지에 적는다. 기존 선택 파일명·실제 펌웨어 혼동을 재발시키지 않는다.
- **오디오·저장/RAM·입력·메뉴 회귀:**SMB3 제목만 보이면 완료하는 계획을 피한다. 필요 기능을D의 수용 기준에 포함한다.
- **기존 source-lock 보류4건:**없어진 것으로 취급하지 않는다. 실제 채택·전달되는 입력에 적용되는 기록을 패키지/공개 범위와 대조한다. 이는 기존 미결 기록 점검이며, 이번에 새로운 법적 결론이나 별도 무기한 조사 공정을 추가한 것이 아니다.
- **현재 상태와 역사 분리:**계획JSON의059 자원/133 board 상태,061·CF61 기반 현행 안내를 갱신한다. 과거 결과·동결 증거는 그대로 둔다.

## 반복을 막는 진행 규칙

새 검증을 추가할 때 “막으려는 구체적 실패 / 기존 근거로 부족한 이유 / 첫 RUN 전 필수 여부 / 통과하면 바로 할 행동” 네 가지를 짧게 기록한다. 답이 불명확하면 후속 목록으로 이동한다.

새 후보·변경이 없는 한 같은 배치/소스/복원물을 다시 빌드하거나 동결하지 않는다. 첫 실기 결과가 오면 마지막 성공 단계와 첫 실패 단계 사이만 수정하고 가장 짧은 판별 시험을 돌린다. 패키지 전달 후 같은 오프라인 검증을 반복하며 다음 실기를 늦추지 않는다.

다음 개발 요청의 기본 완료 목표는 A 패키지 전달이다. 실질적인 차단 문제가 나오면 그 문제와 근거를 보고하고 필요한 수정을 수행한다. “검증 정리 완료”만으로 목표를 또 쪼개지 않는다. 근거 없는 일정/성공 보장은 하지 않는다.
