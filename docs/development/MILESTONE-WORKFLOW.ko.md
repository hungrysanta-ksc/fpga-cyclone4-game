# 코어별 작업과 주요 진전 기록

각 작업 호출마다 커밋하지 않는다. 기능 경계가 검증되거나, 실기 증거로 판단이 바뀌거나, 다음 통합의 기준이 확정되는 **큰 진전마다** 작업을 정리하고 커밋·push·PR을 만든다. 현재 후보와 실기 기준은 기종별 현황·인계 문서에서 관리한다. 사용자가 요청한 운영 방식이며 별도 반복 승인 요청을 추가하지 않는다. PR 병합·제품 릴리스는 별도 결정이다.

## 현재 계획의 갱신

주요 진전마다 현재 후보·실기 기준·파일 쌍·전체 세션의 버전을 분리하고, 준비도 표와 계획 JSON/기종 등록부/인계의 다음 작업을 함께 맞춘다. 과거 완료 시험은 보존하되 소스가 바뀐 현재 통합까지 완료로 자동 승격하지 않는다. 정보가 기존 입력에서 해결됐으면 실기 수집을 반복하지 않는다. 실기 요청은 판별할 가설·사용 가능한 관측·종료/복원 방법을 먼저 구체화한다. 미확정 실기 원인 자체를 새 관측 시험의 선행 조건으로 두어 순환 의존을 만들지 않는다.

## 자료를 찾는 위치

| 구분 | 위치 | 역할 |
| --- | --- | --- |
| 코어별 현재 상태 | `cores/<id>/README.md`, `cores/registry.json` | 후보·제품·미결 gate·다음 작업 |
| 코어별 재현/관측 | `cores/<id>/`, 후보별 `analysis/*-RESULT*`, `docs/*-contract*` | 검증 수준과 근거·진입 명령 |
| 공통 이식 경험 | `docs/development/`, `docs/PORTING-PLAYBOOK.ko.md` | 다른 코어가 재사용할 경계·실패 예방 |
| 구현 | 등록부의 `source_paths` | 검증된 기존 경로를 보존. 문서 분류를 위해 소스를 이동하지 않음 |
| 로컬 원본 | ignored 출력·원시 로그·증거 | 실패·해시·정확한 실행 소스 보존, 공개와 분리 |

## 주요 진전의 완료 조건

1. 해결한 문제, 실제 수정한 동작, 아직 구현하지 않은 경계를 적는다.
2. 같은 소스로 필요한 시험을 수행하고 실패·negative control·모델 가정을 함께 기록한다. compile, RTL, fit, STA, 보드, 사용자 실기를 구분한다.
3. 현재 코어 진입점과 등록부를 갱신한다. 다른 기종의 상태는 그대로 보존한다. 과거 상태를 현재 상태보다 앞에 반복해서 쌓지 않는다.
4. 다른 코어에 적용할 수 있는 교훈만 공통 문서에 반영한다. GBC의 주파수·NES의 메모리/팔레트 제한을 다른 코어에 그대로 적용하지 않는다.
5. 공개 후보 파일을 명시적으로 검토·stage하고 diff·금지 자산·출처·고지·보호된 기준선 해시를 확인한다. `git add .`, 강제 추가, 전체 로컬 snapshot 업로드는 사용하지 않는다.
6. `codex/` 브랜치에 논리적인 커밋을 만들고 PR에 후보·재현·결과·제약·다음 gate를 적는다. 커밋/PR 링크를 인계 자료에 남긴다. 큰 누적 작업을 다시 미커밋 상태로 계속 쌓지 않는다.

## PR 제목과 본문 작성 규칙

모든 기종의 PR 제목과 본문은 **한국어**로 작성한다. 기술 식별자·파일명·명령어는 원래 표기를 유지할 수 있다. 제목은 기종/단계와 실제 변경 또는 검증한 경계를 구체적으로 적는다. 예: `NES063: 전체 적재·읽기 비교·종료 경로의 보드 핀 모형 검증`.

본문은 아래 세 절을 순서대로 사용한다. 명료하게 작성하고 검토에 필요한 근거만 남긴다.

```markdown
## 작업 목표

이번 PR에서 해결하려는 문제와 완료 조건을 적는다. 전체 개발 목표와 이번 작업 범위를 구분한다.

## 작업 내용

실제로 변경한 내용과 수행한 검증을 적는다. 재사용한 근거는 새로 실행한 시험과 구분한다.

## 작업 결과

이번 목표를 완전히 달성했는지 명시하고 결과·근거를 적는다.
미달성 또는 부분 달성이면 부족한 구현·검증·정보와 그 영향을 구체적으로 적는다.
이번 목표를 달성했어도 전체 개발 또는 실기 진입에 남은 조건을 별도로 적는다.
다음 작업 목표와 완료 조건을 적는다.
```

- “완료”의 범위를 밝힌다. 시뮬레이션·컴파일·fit/STA·실기 결과를 서로 대체하지 않는다.
- 결과에는 필요한 시험 수치·실패/수정 근거·제약을 간결하게 적고, 자세한 내용은 기종별 결과 문서에 연결한다.
- 제목과 본문은 최종 변경에 맞춰 갱신한다. 미구현 기능을 달성한 것으로 쓰거나 과거 시험을 새 실행처럼 쓰지 않는다.
- 게시 전 한국어 제목, 세 절의 순서, 달성 여부, 부족한 점, 다음 목표를 확인한다. 게시 후 실제 PR의 제목·본문도 대조한다.
- 사용자가 PR 수정만 요청하면 제목·본문과 요청한 가이드 문서만 수정한다. 개발·빌드·시뮬레이션·실기 작업을 이어서 수행하지 않는다. 가이드 변경은 해당 PR에 문서 커밋으로 반영하며 새 PR을 만들지 않는다.

## NES에서 재사용할 교훈

- MCU와 FPGA SPI 단독 검사가 각각 통과해도 실제 샘플 시점은 다를 수 있다. 실제 C GPIO 파형을 RTL에 재생하고 펌웨어가 소비한 응답 비트를 비교한다.
- 정상 버스 종료에서도 RD/ROMSEL/주소가 함께 바뀐다. 정상 종료의 상대 위상과 실제 오류를 따로 회귀한다.
- 사람이 판단하는 실기 진단에는 읽을 수 있는 후보/페이지 ID·뚜렷한 화면 차이·진행 표시·종료 이유를 넣는다. 잡음 패턴만으로 정상 판정을 요구하지 않는다.
- 원래 SDF 실패와 가정이 추가된 해소 실험을 분리한다. 실기 성공을 이전 실패의 정확한 물리 원인 증명으로 확대하지 않는다.
- 메모리 쓰기는 소유권과 오류 시 펄스 종료를 포함해 검증한다. 길이 완료 상태는 CRC/읽기 검증과 다르다.
- 논리 요소 수뿐 아니라 실제 LAB packing과 M9K를 공동 fit에서 확인한다. 단독 fit의 합산은 보드 여유 증명이 아니다.
- 라이선스 오류와 HDL/테스트 오류를 구분하고, 확인된 실행 경로를 재사용한다. 원본 라이선스·전역 설정·다른 작업의 서버를 변경하지 않는다.

- 큰 ROM 직렬 적재가 앞에 붙으면 적재 watchdog과 RUN 이후 실행 watchdog을 분리한다. 기존 CPU/PPU 응답 마감은 그대로 유지한다. 시작 위상 차이는 전체 이벤트/패킷에 같은 상수 차이를 요구해 기록하고 프레임 내용 차이를 덮지 않는다.
- 입력 `ready`는 다음 데이터를 받을 수 있다는 뜻이며 적재 완료가 아니다. 마지막 바이트 뒤 추가 입력을 막는 상태와 END 승인, RUN 시작을 별도로 검증한다. 정상적인 ready 해제를 오류로 판정하지 않는다.
- 파일 검증·적재 성공·실행 허용·메뉴 복구 성공은 별도 상태로 보고한다. 응답을 잃은 DATA를 무조건 재전송하지 말고 현재 상태 확인 또는 공통 초기화로 복구한다. 복구 실패 시 RESET과 공유 주변장치 보호를 유지한다.
- GPIO 반환은 원래 출력 latch를 복원할 수 있다. 뒤따르는 독립 SPI 시험은 이전 clock level을 가정하지 않고 자기 mode의 idle을 먼저 설정한다. 호출되지 않는 새 펌웨어 함수를 링크 검사할 때는 section GC에서 유지됐는지도 확인한다.

- 명령 수신 인자와 상태 머신이 승인한 설정을 구분한다. 소비자는 길이/주소를 결정하는 승인 레지스터를 공유해야 한다. 별도 입력을 반대로 바꾸는 대조로 숨은 의존을 확인한다. 레지스터·LUT 수가 거의 같아도 배선 연결로 LAB 패킹이 달라지므로 공동 fit 여유를 다시 측정한다.

- 기존 reader를 실행 전 검사와 공유할 때 소비자 reset과 reader reset을 구분하고 양쪽 CDC 상태를 공통으로 취소한다. 한 클록 완료 pulse를 느린 MCU가 나중에 읽을 응답으로 취급하지 않는다. 보존/ack 경계와 실제 데이터 비교가 연결돼야 무결성 성공을 표시할 수 있다.

- 느린 제어 버스의 명령 수신 레지스터와 보존된 완료 tag를 분리한다. query 반복·중복/누락 ACK·부분 CS·비교 제거 mutation을 시험한다. 완전한 바이트 비교와 실행 허용,오류 뒤 복구를 각각 확인한다.
- 긴 직렬 적재/검사는 데이터 크기뿐 아니라 프레임 수와 전송 지연으로 사용자 대기 시간을 계산한다. testbench 성능 개선은 reset-held 경계에만 적용하고 실행 클록 위상/마감/전체 출력 비교를 유지한다. wire 초기식이 참조하는 신호는 먼저 선언하도록 생성 단계에서 검사한다.

- 비교 원본을 파일에서 다시 읽을 때에도 승인 조건을 유지한다. 마지막 CRC·크기·close가 성공하기 전에 검증 완료를 승인하지 않는다. 입력과 대상이 함께 바뀌는 대조도 검사한다.
- 실행 driver의 해시는 종료 시점의 작업 파일이 아니라 저장한 실행 snapshot에서 구한다. 시뮬레이터가 선언 순서를 요구하는 helper task도 license 시작 전 검사한다.

- 적재 전용 진단 클록과 실제 코어 실행 클록을 분리해 기록한다. 느린 진단 fit를 전체 코어 fit로 대체하지 않는다. 각 클록 영역의 reset 해제 FF를 다른 영역의 일반 데이터 경로로 전달하지 않는다.
- 합성 RAM 구간 수와 실제 M9K 사용량을 구별한다. 배치/STA 도구 exit0이나 시뮬레이터 exit0만으로 성공을 판단하지 말고 slack·미제약 IO·Fatal·완료 marker를 검사한다.

- 검증함수를링크에유지한것과실제제품진입점에서호출하는것을구분한다. 호출source뿐아니라최종ELF의callsite로연결을확인한다. 짧은FPGA후보ID/파일CRC/설치파일SHA의역할을각각기록한다. 표식과승인파일형상이바뀐조합도적재전에거부한다.
- 복구로그의메뉴준비와RESET해제경계는사용자화면관측과구별한다. 복구불가시공유SD/USB접근을금지하고,선택적 파일 API 로그 실패와 native SD/버스/타이머 실패를 구분한다. 후자는 공유 주변장치 안전이 확인되지 않았으므로 RESET/USB 해제를 막는다.
- 사용자에게 하드웨어 정보를 묻기 전에 README·기종 등록부·기존 계약/로그를 확인한다. 알려진 제품·MCU·FPGA를 가이드에 명시하고, 부족한 부품/타이밍 항목만 구체적으로 질문한다. 문서의 개발 대상과 새 물리 관측은 구별한다.

- 긴 GPIO 기록은 압축 기록에서 검사한 시점과 C 템플릿으로 재구성한 전환을 구분한다. 동작하는 decoder/메모리 클록과 실제 샘플 시점은 유지하며, 미사용 영역의 테스트 변경과 원래 클록 대조 범위를 명시한다. 입력 net을 force하면 공유 상위 net까지 영향을 줄 수 있으므로 별도 테스트 연결을 사용한다.
- 쓰기 byte lane과 읽기 word enable을 같은 규칙으로 가정하지 않는다. 기존 물리 인터페이스 계약을 먼저 확인하고 전체 성공 시험 전에 monitor 조건을 점검한다. 실패한 시험의 기대값을 고칠 때 제품 RTL 변경 여부와 대조 시험에 미치는 영향을 따로 기록한다.

- 동기 함수의 바깥 timeout은 내부 busy/panic/UART 대기를 끝내지 못한다. 실제 하위 대기마다 반환 경계·tick 정지 대조·오류 전달·재시도 금지를 확인한다. 관측용 UART 자체가 대기를 만들 수 있으므로 같은 종료 정책을 적용한다.
- 컴파일러가 여러 진입점을 shared call block으로 합치면 source 호출 수와 ELF의 bl 수가 달라질 수 있다. 기대 숫자를 완화하는 대신 실제 분기 목적지와 공통 호출 경계를 확인한다.

- 진단 보호의 수명은 probe 함수 반환이 아니라 메뉴 준비·RESET 해제 후 안정화까지 정의한다. 그 뒤의 로그가 SD/USB 소유권을 다시 얻지 않게 한다.
- SD busy 제한만으로 FatFS의 캐시 hit·빈 클러스터 탐색이 제한되는 것은 아니다. 실제 metadata/cache 방문에도 tick 정지 시 끝나는 누적 한도를 넣고, 한도 소진 뒤 추가 IO와 재시도를 차단한다.
- 복구를 위한 제한 경로에서 목록·저장 등 부가 기능을 생략한다면 사용자에게 보이는 차이를 문서에 명시한다. 버퍼 복사와 모든 byte의 실제 readback을 비교하되 모형/ARM/실기의 범위를 구분한다.

- 이미지 압축은 decoder의 성공만 보지 말고 원본의 길이와 모든 byte를 대조한다. EOF 반복·65535 경계를 검사하고 구형 도구의 추가 padding도 명시한다. 실기 기준 파일을 바꾸지 않고 새 후보 도구를 분리한다.
- FPGA/ARM/준비 패키지의 버전은 각각 기록하며, 인식하는 실제 marker 이름을 유지한다. manifest는 독립 digest로 고정한다. 백업 모형·복원 계획과 실제 SD 백업·복원 실행을 구별하고 후자를 수행하지 않았다면 준비 완료로 쓰지 않는다.

- 모델/담당 작업이 바뀔 때 최신 후보·실기 기준·변경 파일·실행 명령·해시 근거·실패 대조·미확인 가정·다음 완료 조건·다시 실행하면 안 되는 동결 작업을 별도 인계한다. 모델 등급으로 완료 기준을 바꾸지 않는다. PSRAM의 최대 출력 해제 시간은 최소 유지 시간이 아니며, 준비/유지 클록 추가와 가정 지연 대조를 실제 외부 min/max 승인으로 확대하지 않는다.

- IO경로조회에필요한분석전용zero-delay/가상제약을생산SDC또는보드승인으로사용하지않는다.원본fit DB복사본의분석전해시와후변경(report/cache·정확한도구버전행)을기록한다.전원대기는전압센서가아니며locked강제LOW복구시험과lockedHIGH인클록정지반례를구분한다.

- 후보 ID를 연결할 때 programming DONE과 peripheral READY를 구분하고, 실제 ELF의 대기→소유권→ID 검사 순서를 확인한다. 전체 trace 차이는 프레임별 필드·시간을 대조하고 ID 변경만 허용했다고 해서 새 RTL 전체 성공으로 승격하지 않는다. 동결 전 준비 manifest의 확장자 없는 Makefile과 캡처/fixture를 포함한 모든 참조 입력의 존재를 점검한다.

- 전체 재생을 새 후보에 연결할 때 testbench의 파일명·top module·clock expression·시뮬레이터 인자를 함께 확인한다. READY 이전 상태와 캡처 원점의 대기는 MCU 실측과 구분하며 `%t` 출력 단위를 명시한다. 동결 데이터와 생산 해시를 확인한 뒤 마지막 ACK/FINISH/STOP까지 재생한다.

- 기존 DB inventory의 포함 범위를 먼저 확인한다. 기록된 db와 기록되지 않은 incremental_db를 구분하고 독립 고정되지 않은 추가 파일을 새 조립에 몰래 넣지 않는다. 원본 해시·새 복사 입력·조립 후 변화를 따로 남긴다. ARM materializer의 줄바꿈/추가 enum 차이를 해시 동일성으로 가정하지 말고 실제 링크 입력을 고정해 C 검증에 사용한다. 첫 실패 원문을 저장하지 못했으면 터미널 전사라고 명시한다.

## 072 원본 정보 수집의 재사용 원칙

기기를 직접 연결할 수 없으면 기존 검증된 firmware→SD TXT→사용자 반환 경로를 활용한다. 원본 firmware의 교체 전 독립 백업과 수집기 firmware 자체를 구분하고, 입력 읽기 전용/새 보고서 CREATE_NEW/sync/close/all-byte readback을 분리한다. 수집 성공은 메뉴 분류나 실제 복원 성공이 아니다. 마지막 화면 출력까지 공유 peripheral 오류 보호를 유지하며, legacy 부팅의 예산 밖 대기도 명시한다. 공개 재현 도구의 입력 바이트와 실제 ARM 입력을 대조하고 config/VERSION 등 archive 밖 입력은 새로 고정한다. 큰 진전의 한국어 PR에는 수집기 준비 달성과 실제 사용자 TXT/복원 미달성을 함께 적는다.

## 073 상태·권한을 건너는 실제 호출 시험

072의 writer/platform mocks는 SD native의 별도 쓰기 허용 상태를 검사하지 않아 실물 code4/미생성을 놓쳤다. 상태·권한이 여러층을 건너는 변경은 실제 호출자→전체FatFS→native guard/runtime를 연결해 성공·거부·shared fault·종료권한회수를 확인한다. mock 하나씩 통과한 결과를 이 연결의 검증으로 확대하지 않는다. 표시 경로는 생성 시도이며 sync/close/allbyte readback까지 통과해야 저장완료다. 출력파일이 없어도 실패를 읽을 수 있게 첫 FatFS 반환/바이트/위치를 화면 또는 안전한 RAM 관측으로 남긴다. 이미 열린 PR의 같은 목표 오류 수정은 상태 확인 뒤 해당 PR에 반영한다.

- 오류를 확인하려는 화면/로그가 실패한 공유 장치에 의존하면 관측 자체가 차단될 수 있다. 보호를 해제해 출력을 강행하지 않고 독립 MCU LED 등 허용된 경로로 최초 오류와 호출 전 단계를 기록한다. 관측 모듈에서 UART/SD/SPI 재귀 오류가 생기지 않게 한다. 실제 SD 송수신을 RAM 복사로 대신한 시험은 카드 response/data/CRC/busy 검증으로 인용하지 않는다. 관측용 패키지는 근본 원인 수정본과 구분한다.

- 외부 실기 진단을 보내기 전에 결과를 사용자가 케이스를 열지 않고 관측할 수 있는지 확인한다. 질문에 답이 없다는 사실을 가시성 승인으로 취급하지 않는다. 콘솔 전원 램프와 카트리지 진단 LED를 혼동하지 않는다. 관측 불가가 확인되면 같은 테스트·분해를 반복 요구하지 않는다. 먼저 필요한 정보가 기존 파일 사본에서 추출 가능한지 확인하고 실기 의존을 줄인다. 정보 수집과 별도의 하드웨어 오류 규명을 분리한다.

- 정상 동작 펌웨어와 별도 진단 성공 펌웨어를 이름이 아닌 전체 해시/출처/역할로 구분한다. 사용자 실제 메뉴를 분류기에 넣어 승인 조건을 검사하고, 메뉴를 실행하지 않는 저장 수집기 오류와 분리한다. GPIO helper 호출 횟수는 실제 클록 에지 수가 아니다. SET/CLR 중복과 마지막 응답 샘플을 추적하고 데이터 시작까지의 검사를 전체 CRC/busy 검증으로 부풀리지 않는다.

## 선행 PR이 미병합인 후속 작업

사용자가 미병합 상태에서도 계속 진행하도록 허용하면 선행 PR의 고정 head에서 별도 브랜치를 만든다. 후속 PR은 선행 브랜치를 base로 삼아 변경을 분리하고 병합 순서를 명시한다. 선행 PR 병합 후 후속 base를 master로 전환하고 차이를 재확인한다. 자동 병합이나 미병합 커밋을 버리는 rebase/reset을 하지 않는다. GitHub가 불가하면 검증된 로컬 커밋·선행 SHA·게시할 한국어 본문을 보존하고 게시 미완료를 명시한다.

## 병합 대상과 초기화 연결의 재발 방지

- PR이 merged여도 대상이 이전 작업 브랜치면 master에 반영되지 않을 수 있다. 사용자 병합 보고 뒤 base/merge SHA와 master의 실제 파일·도달 관계까지 확인한다. 이미 잘못된 대상에 병합됐다면 원본 커밋을 보존해 master 대상 PR로 회수하고 자동 병합하지 않는다.
- 사용자가 두 PR을 연속 병합하는 흐름에서는 중간 retarget이 빠지지 않도록 후속도 master 대상으로 제출할 수 있다. 그때 선행 변경이 현재 diff에 포함됨과 먼저 병합할 PR을 명시한다. 선행 병합 뒤 후속 diff가 줄었는지 확인한다. 이번 PR30/081은 이 방식이다.
- 카드 초기화 성공만으로 FatFS 첫 mount가 성공한다고 가정하지 않는다. 실제 find_volume의 disk_initialize 호출, weak alias/strong definition 선택, 오류 후 재mount를 시험과 최종ELF에 연결한다. 기존 전역 거부를 제거하거나 fault를 reset해서 통과시키지 않는다.
- 시간 wrap 시험은 예산을 시작하기 전에 시계 원점을 설정한다. 뒤에서 원점을 바꾼 시험 실패를 생산 timeout 결함으로 기록하지 않는다. MCU clock/startup 가정, tick/poll 종료, 실제 벽시계 측정은 구분한다.

## 단일 플랫폼 시험과 논리 오류의 구분

- init·첫mount·native저장·화면을 따로 통과한 결과를 전체 세션으로 합산하지 않는다. 실제 writer/FatFS/native와 초기화/상태전달/부팅을 같은 실행에 연결하고 모델 경계를 명시한다. 디스크 성공 callback을 모형으로 대체하면 native 저장 증거가 아니다.
- 정상CRC readback 내용 불일치는 code7처럼 논리 실패를 반환할 수 있다. 모든 실패를 shared fault로 기대하지 않는다. 실제 계약을 확인해 논리 실패의 종료 문구와 공유고장의 추가IO 금지를 각각 검사한다.
- 검증만 추가하고 생산 소스가 불변이면 같은 해시의 ARM 증거를 재사용하고 새 펌웨어 ID나 실기 성공을 만들지 않는다. 다음 생산 변경 때는 바뀐 경계와 ARM 호출을 다시 검증한다.

## 첫 관측 패키지와 복원본

- 의존 장치가 실패하기 전에 표식을 보이도록 준비한다. 예고 표식, 실제 작업 완료, 물리 원인 코드를 구분한다. startup/표시 자체의 실패는 별도 범위로 기록하고 보호를 풀어 오류 후 출력을 강행하지 않는다.
- 코드·오프라인 패키지가 끝나면 실물 가독성을 같은 호스트 시험으로 반복 증명하려 하지 않는다. 제한된 첫 관측의 목적·마지막 표식/파일 회수표·사용자 관측 종료 시간·정상 복원 파일을 명시해 사용자 실행으로 확인한다. 이를 게임 코어/제품 출시 승인으로 확대하지 않는다.
- 사용자가 제공한 정상 펌웨어를 전체 해시로 확인해 복원 폴더에 동봉한다. 없는 백업 이름을 다시 요구하지 않으며 정상044와 HW002 성공 진단을 혼동하지 않는다. 전체 SD/세이브 백업과 실제 복원 관측은 별도다.
- ZIP의 모든 멤버를 읽어 검증하고 대응 소스를 함께 제공한다. Make의 버전 인수 캐시처럼 의도된 생성 파일 변경은 정확한 예상값을 따로 검사하며 C 소스 해시 검사를 통째로 해제하지 않는다.

## 파일시스템·화면 진단의 재사용 원칙

- 빈 카드 모형 통과만으로 실제 SD의 할당 탐색을 검증했다고 기록하지 않는다. 사용 중인 FAT 앞부분,FSINFO 힌트,조각난 빈 영역,클러스터 크기,root 확장을 구분하고 실제 FatFS/native 경로로 검사한다.
- poll 제한은 SD명령 수와 같지 않다. cache-hit get_fat/move_window도 예산을 차감할 수 있다. 제한 확대에 앞서 재현하고 읽기 전용 준비와 쓰기 구간을 나누되 기존 상한·첫오류 보존을 유지한다.
- RAM 할당 힌트는 FAT 예약이 아니다. directory 확장 등이 힌트를 바꾸는 경계를 공개한다. 재현된 소프트웨어 조건과 사용자의 실제 카드 원인 확정을 구분한다.
- TV 문구는 공통 포맷에서 좌우 여백과 길이를 검사한다. SRAM 문자열 검사와 실제 TV overscan 해결을 같은 증거로 취급하지 않는다. 기존 실기 실패는 성공한 후속모형으로 덮어쓰지 않는다.

- 클록 감시는 실제 독립된 입력과 연결된 핀 동작으로 검증한다. 같은 입력에서 만든 PLL/분주기를 독립 감시자로 부르지 않는다. 단일 고장 차단과 두 클록 동시 정지 반례를 함께 보존하고, 새 클록/비동기 reset 경로에는 새 fit/STA/CDC 근거를 요구한다. 기존 클록 측정 명령도 실제 측정창 주파수를 확인한 뒤 Hz로 해석한다.

- 비동기 fault를 동기 해제 FF에 넣은 뒤 raw fault를 downstream reset 식에 다시 OR하면 영역 경계를 우회할 수 있다. 새 배선에서 일반 제어 data/reset까지 직접 전달되지 않는지 검사한다. CDC 예외는 정확한 첫 FF/clear 경로에만 적용하고 예외를 제거한 전체 경로 목록과 실제 수정 전 반례를 보존한다. 제약된 내부 timing PASS와 외부 IO/비동기 차단/실기 승인을 구분한다.

- 출처가 불명확한 base 명령을 가정하기보다 메모리 비활성 관측 회로와 명확한 응답 계약으로 가정을 수집할 수 있다. READY/측정 완료/클록 정상은 다른 상태로 표시하고 원시count·window·divisor·가정주파수를 함께 보존한다. 시뮬레이터 시간 해상도로 양자화된 stimulus와 이상적인 주파수를 혼동하지 않는다. 측정 중간 갱신은 snapshot으로 차단하고 다음단계 actual MCU/저장/화면 통합을 별도로 완료한다.

- snapshot의구간완료/클록활동/전송오류를분리한다. 읽기모형통과뒤실제C가소비한모든응답bit를RTL에재생하고실행파형동일성을고정한다. 개별bounded작업의합은전체예산에맞는다는뜻이아니므로구성·reader·복귀의실제호출수를계측한다. 제한회피용fault초기화/재시도별예산재시작은금지한다. ARM오브젝트컴파일과main에연결된최종펌웨어링크를구분한다.
