# 작업·PR·진척 기록 규칙

성능 개발은 재개되었다. 문서/PR 정리만 요청한 경우에는 새 구현·합성·실기 실행으로 확대하지 않는다. 이 규칙의 PR 양식은2026-10-29 사용자가 지정한 이름으로 통일했다.

## 문서의 역할

| 위치 | 담을 내용 |
|---|---|
| 루트 README | 멀티 코어 목표·현재 코어 상태·진입 링크만 유지 |
| docs/PROJECT-STATUS.ko.md | 현재 완료/미완료·최신 측정·선택 구성 |
| cores/<id>/README·HANDOFF | 현재 선택·소스·예산·보존 조건·순서 |
| cores/registry.json | 현재 선택과 근거 경로, 과거 세션 전체를 누적하지 않음 |
| docs/progress/pr-NNN.md | 해당 PR의 목표·작업내용·성과·후속작업 |
| docs/progress/archive | 과거 누적 원문. Current/NEXT는 당시 기록 |
| analysis/ 및 상세 계약 | 재현 가능 수치·hash·모델 범위·실패와 상세 설계 |

새 증거가 나오면 현재 상태는 교체한다. 루트 README/AGENTS/인계 앞에 같은 PR·실험 요약을 계속 붙이지 않는다. PR별 기록은 한 PR당 한 파일을 갱신하며 관련 세부 근거로 연결한다. 이전 병합 PR의 GitHub 본문을 이번 양식으로 일괄 수정하지 않는다.

## PR 양식

모든 PR 제목/설명은 한국어를 기본으로 한다. 기술 식별자·파일·명령어는 유지한다. 본문은 아래 네 절만 순서대로 사용한다.

```markdown
## 목표

문제·이번 범위·완료 조건.

## 작업내용

실제 변경과 수행한 검증, 재사용한 근거의 구분.

## 성과

달성 여부·수치·근거·비용·실패/미확인. 전체 목표에서 새로 가능해진 범위.

## 후속작업

남은 조건·다음 순서·완료 기준·중지 사항. 설치/원복·로컬 의존성도 필요한 범위에서 연결.
```

`.github/PULL_REQUEST_TEMPLATE.md`와 progress 기록도 같은 네 이름을 쓴다. 게시 전/후 실제 PR 본문을 대조한다. 사용자 요청으로 이 이름/양식이 바뀌면 template·이 규칙·AGENTS·검사기를 함께 맞춘다.

## 작업과 검증

- 매 호출마다 커밋할 필요는 없다. 기능 경계·실기 판정·다음 통합 기준 등 주요 진전마다 명시한 파일만 커밋/push한다. 브랜치는 `codex/`, 자동 병합/릴리스는 하지 않는다.
- 변경 경계에 필요한 최소 시험을 한다. 변경 없는 적재·합성·복원/GBC 시험, 이미 판별된 진단 패턴을 반복하지 않는다.
- 실제 목표 장면의 실기 데이터를 우선한다. 추가 시험은 어떤 실패/미확인을 판별하고 통과 후 무엇을 실행할지 적는다. 관측 도구의 완성이 실기 진입의 무한 선행 조건이 되지 않게 한다.
- 모델·실제 CPU 실행·MAP·FIT/STA·실기·제품 완료를 구분한다. 카운터 증가를 게임 정상 동작으로, 제한 NROM FPS를 일반 NES/60Hz로 승격하지 않는다.
- source/ABI/스케줄이 바뀌면 같은 후보의 근거인지 확인한다. 다른 구성의 최저 면적·최소 시간을 합하지 않는다. 실패/원시 로그와 동결 산출물은 보존한다.
- 불확실한 I/O·native fault 뒤 SD 기록/복구를 강행하지 않는다. 최초 원인을 보존하고 STOP·최종 ACK·base/menu·반복 진입을 구분한다.

## 재개와 이식성

새 PC/새 담당자는 [재개 안내](RESUME.ko.md)부터 읽는다. 후보·실기 기준·파일 쌍·소스/제약 hash·로컬 자료 의존성·다음 완료 조건을 남긴다. 채팅 기억이나 사용자 홈 경로를 유일한 지침으로 삼지 않는다. 누락 원본을 임의 생성해 과거 PASS를 재현한 것으로 쓰지 않는다.

사용자 병합 보고 뒤 실제 base/merge SHA와 master 도달 관계를 확인하고 새 작업 브랜치/PR을 만든다. 미병합 후속이 허가된 경우 선행 head·base·병합 순서를 명시한다. 사용자 변경을 reset/rebase로 버리지 않는다.

## 공개·보존

다음 NES 시험판부터 RESTORE 폴더를 포함하지 않는다(502 수신 시 사용자 요청,별도 백업 보유). 기존 전달ZIP/백업은 삭제하지 않는다. 후보별 고유 파일명과 설치 안내는 유지하며 실행 중 STOP·최종ACK·base/menu 복구와 이 배포 정책을 혼동하지 않는다.

[CONTRIBUTING](../../CONTRIBUTING.md)·[공개 정책](../REPOSITORY-POLICY.ko.md)의 allowlist와 자산 분리를 지킨다. 상용 ROM/BIOS·개인 save/dump/영상·키/라이선스·도구 캐시는 Git에 넣지 않는다. 검증된 GBC와 원복물을 보호하고 문서 정리만을 위해 source를 이동/수정하지 않는다.

이전 상세 운영·사례 원문은 [archive](../progress/archive/README.md)에 보존했다. 현재 사용자 지시와 현재 코어 인계를 우선하며 특정 과거 경계를 조사할 때만 해당 사례를 읽는다.

README는 의미 있는 진척 변화나 정정이 필요한 때만 갱신한다. 일상 진행은 PR별 기록에 남기며 네 항목 PR 양식은 계속 유지한다.
