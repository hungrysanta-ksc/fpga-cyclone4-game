# 코어별 작업과 주요 진전 기록

각 작업 호출마다 커밋하지 않는다. 기능 경계가 검증되거나, 실기 증거로 판단이 바뀌거나, 다음 통합의 기준이 확정되는 **큰 진전마다** 작업을 정리하고 커밋·push·PR을 만든다. 현재 후보와 실기 기준은 기종별 현황·인계 문서에서 관리한다. 사용자가 요청한 운영 방식이며 별도 반복 승인 요청을 추가하지 않는다. PR 병합·제품 릴리스는 별도 결정이다.

## 자료를 찾는 위치

| 구분 | 위치 | 역할 |
| --- | --- | --- |
| 코어별 현재 상태 | `cores/<id>/README.md`, `cores/registry.json` | 후보·제품·미결 gate·다음 작업 |
| 코어별 재현/관측 | `cores/<id>/`, 후보별 `analysis/*-RESULT*`, `docs/*-contract*` | 검증 수준과 근거·진입 명령 |
| 공통 이식 경험 | `docs/development/`, `docs/PORTING-PLAYBOOK.ko.md` | 다른 코어가 재사용할 경계·실패 예방 |
| 구현 | 등록부의 `source_paths` | 검증된 기존 경로를 보존. 문서 분류를 위해 소스를 이동하지 않음 |
| 로컬 원본 | ignored 출력·원시 로그·증거 | 실패·해시·정확한 실행 소스 보존, 공개와 분리 |

## 주요 진전의 완료 조건

1. 해결한 문제, 실제 수정한 동작, 아직 구현하지 않은 경계를 적는다.
2. 같은 소스로 필요한 시험을 수행하고 실패·negative control·모델 가정을 함께 기록한다. compile, RTL, fit, STA, 보드, 사용자 실기를 구분한다.
3. 현재 코어 진입점과 등록부를 갱신한다. 다른 기종의 상태는 그대로 보존한다. 과거 상태를 현재 상태보다 앞에 반복해서 쌓지 않는다.
4. 다른 코어에 적용할 수 있는 교훈만 공통 문서에 반영한다. GBC의 주파수·NES의 메모리/팔레트 제한을 다른 코어에 그대로 적용하지 않는다.
5. 공개 후보 파일을 명시적으로 검토·stage하고 diff·금지 자산·출처·고지·보호된 기준선 해시를 확인한다. `git add .`, 강제 추가, 전체 로컬 snapshot 업로드는 사용하지 않는다.
6. `codex/` 브랜치에 논리적인 커밋을 만들고 PR에 후보·재현·결과·제약·다음 gate를 적는다. 커밋/PR 링크를 인계 자료에 남긴다. 큰 누적 작업을 다시 미커밋 상태로 계속 쌓지 않는다.

## NES에서 재사용할 교훈

- MCU와 FPGA SPI 단독 검사가 각각 통과해도 실제 샘플 시점은 다를 수 있다. 실제 C GPIO 파형을 RTL에 재생하고 펌웨어가 소비한 응답 비트를 비교한다.
- 정상 버스 종료에서도 RD/ROMSEL/주소가 함께 바뀐다. 정상 종료의 상대 위상과 실제 오류를 따로 회귀한다.
- 사람이 판단하는 실기 진단에는 읽을 수 있는 후보/페이지 ID·뚜렷한 화면 차이·진행 표시·종료 이유를 넣는다. 잡음 패턴만으로 정상 판정을 요구하지 않는다.
- 원래 SDF 실패와 가정이 추가된 해소 실험을 분리한다. 실기 성공을 이전 실패의 정확한 물리 원인 증명으로 확대하지 않는다.
- 메모리 쓰기는 소유권과 오류 시 펄스 종료를 포함해 검증한다. 길이 완료 상태는 CRC/읽기 검증과 다르다.
- 논리 요소 수뿐 아니라 실제 LAB packing과 M9K를 공동 fit에서 확인한다. 단독 fit의 합산은 보드 여유 증명이 아니다.
- 라이선스 오류와 HDL/테스트 오류를 구분하고, 확인된 실행 경로를 재사용한다. 원본 라이선스·전역 설정·다른 작업의 서버를 변경하지 않는다.

- 큰 ROM 직렬 적재가 앞에 붙으면 적재 watchdog과 RUN 이후 실행 watchdog을 분리한다. 기존 CPU/PPU 응답 마감은 그대로 유지한다. 시작 위상 차이는 전체 이벤트/패킷에 같은 상수 차이를 요구해 기록하고 프레임 내용 차이를 덮지 않는다.
- 입력 `ready`는 다음 데이터를 받을 수 있다는 뜻이며 적재 완료가 아니다. 마지막 바이트 뒤 추가 입력을 막는 상태와 END 승인, RUN 시작을 별도로 검증한다. 정상적인 ready 해제를 오류로 판정하지 않는다.
- 파일 검증·적재 성공·실행 허용·메뉴 복구 성공은 별도 상태로 보고한다. 응답을 잃은 DATA를 무조건 재전송하지 말고 현재 상태 확인 또는 공통 초기화로 복구한다. 복구 실패 시 RESET과 공유 주변장치 보호를 유지한다.
- GPIO 반환은 원래 출력 latch를 복원할 수 있다. 뒤따르는 독립 SPI 시험은 이전 clock level을 가정하지 않고 자기 mode의 idle을 먼저 설정한다. 호출되지 않는 새 펌웨어 함수를 링크 검사할 때는 section GC에서 유지됐는지도 확인한다.

- 명령 수신 인자와 상태 머신이 승인한 설정을 구분한다. 소비자는 길이/주소를 결정하는 승인 레지스터를 공유해야 한다. 별도 입력을 반대로 바꾸는 대조로 숨은 의존을 확인한다. 레지스터·LUT 수가 거의 같아도 배선 연결로 LAB 패킹이 달라지므로 공동 fit 여유를 다시 측정한다.

- 기존 reader를 실행 전 검사와 공유할 때 소비자 reset과 reader reset을 구분하고 양쪽 CDC 상태를 공통으로 취소한다. 한 클록 완료 pulse를 느린 MCU가 나중에 읽을 응답으로 취급하지 않는다. 보존/ack 경계와 실제 데이터 비교가 연결돼야 무결성 성공을 표시할 수 있다.

- 느린 제어 버스의 명령 수신 레지스터와 보존된 완료 tag를 분리한다. query 반복·중복/누락 ACK·부분 CS·비교 제거 mutation을 시험한다. 완전한 바이트 비교와 실행 허용,오류 뒤 복구를 각각 확인한다.
- 긴 직렬 적재/검사는 데이터 크기뿐 아니라 프레임 수와 전송 지연으로 사용자 대기 시간을 계산한다. testbench 성능 개선은 reset-held 경계에만 적용하고 실행 클록 위상/마감/전체 출력 비교를 유지한다. wire 초기식이 참조하는 신호는 먼저 선언하도록 생성 단계에서 검사한다.

- 비교 원본을 파일에서 다시 읽을 때에도 승인 조건을 유지한다. 마지막 CRC·크기·close가 성공하기 전에 검증 완료를 승인하지 않는다. 입력과 대상이 함께 바뀌는 대조도 검사한다.
- 실행 driver의 해시는 종료 시점의 작업 파일이 아니라 저장한 실행 snapshot에서 구한다. 시뮬레이터가 선언 순서를 요구하는 helper task도 license 시작 전 검사한다.
