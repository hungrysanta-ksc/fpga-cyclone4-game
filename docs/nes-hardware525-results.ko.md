# MMC524 SMB3 실기 결과

MMC524에서 게임 실행과 약 60초 뒤 메뉴 복귀를 확인했다. 사용자는 적이 여럿 등장하는 장면에서도 속도 저하가 덜 느껴졌다고 보고했다. 같은 ROM의 MMC520 플레이와 비교하면 초반과 마지막 5초의 표시 수가 늘었고, 45–55초에는 줄었다.

| 최종 표시 완료 기준 | MMC520 | MMC524 |
|---|---:|---:|
| 1초 이상~40초 미만 | 471회 / 12.08fps | 480회 / 12.31fps |
| 40초 이상~60초 미만 | 232회 / 11.60fps | 220회 / 11.00fps |
| 전체 | 718회 / 60.07초 / 11.95fps | 715회 / 60.08초 / 11.90fps |

첫 1초는 두 실행 모두 15회였다. 아래 5초 집계는 프레임을 시작한 시각에 귀속한다. 구간 경계를 넘는 화면 때문에 위의 완료 카운터와 합이 다를 수 있다. 마지막 구간은 55초부터 종료까지 포함한다.

| 시작 시각 | 표시 수 520 → 524 | 최대 표시 간격 | OBJ 타일 계획/표시 | 출력·최종 ACK 구간/표시 |
|---|---:|---:|---:|---:|
| 40–45초 | 61 → 62 | 100 → 100ms | 5.11 → 7.73 | 48.20 → 46.29ms |
| 45–50초 | 65 → 47 | 120 → 160ms | 9.42 → 17.60 | 41.85 → 65.11ms |
| 50–55초 | 65 → 55 | 100 → 210ms | 8.28 → 8.16 | 42.00 → 54.18ms |
| 55초 이후 | 40 → 55 | 180 → 120ms | 22.90 → 15.16 | 78.25 → 54.73ms |

마지막 구간은 약 8→11fps로, 표시가 오래 멈춰 있던 시간도 줄었다. 해당 구간에서 타일 공급량 역시 달랐다. OBJ 수치는 새로 공급한 타일 계획 수이며 적의 수나 장면 ID를 기록하지 않는다. 플레이 입력과 장면을 동기화하지 않아 같은 적 배치에서의 개선량은 분리할 수 없다.

전체 84MHz DWT 누적 비용을 표시 횟수로 나누면 수신 19.99→19.94ms, 계획·공급 15.51→15.42ms, 출력·최종 ACK 47.54→48.02ms다. 위 표의 5초별 비용은 10ms 틱 기반 근사다. 다음 작업은 MMC524를 유지하고 같은 입력에서 수락된 map을 64B 단위로 먼저 옮겼을 때, 독립 검사·STOP·head 우선권을 유지하면서 952·954의 최종 표시 검사가 246번 주사선 안에 도달하고 실제 표시 간격도 줄어드는지 확인하는 것이다. [524 동일 입력 검증](nes-idle524-results.ko.md)

384KiB 적재·readback과 START가 성공했고 전송 실패·CRC 오류는 0이었다. 입력 commit 716회 중 최종 EA는 715회다. 마지막 표시는 59.94초였고 제한 시간 종료 때 큐 3건이 남았다. 당시 plan/window/sink 상태 코드는 0/3/2였다. STOP, base 복원, MENU_PREPARED 단계를 거쳤고 사용자가 실제 메뉴 복귀를 확인했다.

원본 세 로그는 상위 작업 폴더의 `probes/nes-hardware525/run01`에 보존했다. 재현 명령은 `python tools/analyze_nes_hardware521.py --trial 524 --raw <로그 폴더> --out <결과.json>`이다. [로그 해시와 측정값](../analysis/hardware525-mmc524.json) · [MMC520 실기 대조군](nes-hardware521-results.ko.md)
