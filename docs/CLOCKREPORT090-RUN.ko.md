# CLOCKREPORT090: 기준 클록 실기 관측

이 시험은 SNES RESET 유지 중 기준 클록을 읽어 사람이 읽을 TXT로 남긴다. 이미 성공한084 저장 시험을 다시 요구하는 것이 아니라, 메모리 보호에 사용할 기준 클록이 그 조건에서도 들어오는지 확인하는 새 관측이다. **SMB3 게임 실행용이 아니다.** 첫 게임 목표는 별도[호환성 계획](development/NES-GAME-COMPATIBILITY.ko.md)에 등록했다.

091 작업에서 전환 검증·패키징만 보강했으므로 펌웨어와 화면의 번호는 **090**이다. 새 버전을 설치한 것처럼 번호를 바꾸지 않았다.

## 실행과 복원

1. 콘솔 전원을 끈다. SD의 게임·세이브를 포함한 독립 백업을 보관한다.
2. `FXPAK-CLOCKREPORT090-TRIAL.zip`을 풀고 **`test/sd2snes/firmware.stm` 한 파일만** SD의 `/sd2snes/firmware.stm`에 복사한다. test/restore를 동시에 복사하지 않는다. 메뉴·base FPGA·게임·세이브 파일은 교체하지 않는다.
3. 전원을 켜기 전부터 TV 전체를 촬영한다. 진단은 자동 실행되며 브라우저에서 ROM이나 별도 진단 파일을 선택하지 않는다. 분해·LED 확인·PC USB 연결은 필요 없다.
4. 처음 `CLOCKREPORT090 CF87` / `STEP 1A OBSERVE CLOCK`가 보인다. 이후 클록 관측·mini 재구성 중에는 화면이 남거나 꺼질 수 있다. 최종 결과가 나오면 촬영하고 전원을 끈다. 결과가 없으면 **전원 후90초까지 한 번 관측하고 끈다.** 자동 메뉴 복귀는 없다.90초는 관측 종료 기준이며 하드웨어 watchdog 보장이 아니다.
5. 전원이 꺼진 상태에서 **`restore/sd2snes/firmware.stm`**을 같은 위치에 복사해 기존 정상044로 복원한다. 이전084 복원/menu/GBC 통과는 이미 기록돼 있다. 이번에도 정상 복원해 사용하고, 이전과 달라진 문제가 있으면 함께 알려준다.
6. 새 SD 루트의 **`HW090000.TXT`–`HW090999.TXT`와 영상 또는 마지막 화면 사진**을 전달한다. 내용은 직접 해석하지 않아도 된다. 파일이0바이트면 그대로 보관하고, 없으면 마지막 화면과 파일 없음만 알려준다. 기존HW084/HW090파일을 삭제하거나 이번 결과로 대체하지 않는다.

| 파일 역할 | 크기 | SHA-256 |
| --- | --- | --- |
| 시험090 | 196248바이트 | 00f757fcd1ca0da08ce0e5564358e06b482071e6119d8827e6c81748fcfddebe |
| 정상044 복원 | 169056바이트 | 1c3b40a3459d24114cb4d91ee9d861d1a08025a670ef25317ef489092203693b |

복원본은 사용자가 전달하고 메뉴/GBC 정상으로 확인한044와 동일하며 HW002 진단 펌웨어가 아니다. 복사 누락·부팅 적용 여부 등 실제 환경은 이번 영상과 TXT로 구분한다.

## 화면·TXT 판정

| 마지막 화면 | 의미와 다음 확인 |
| --- | --- |
| 아무 표식 없음 | firmware 적용·MCU startup·첫 mini 표시 범위. SD/클록 원인을 단정하지 않음 |
| `STEP 1A OBSERVE CLOCK` 후 그대로/꺼짐 | 구성·관측·mini 복귀 구간을 구분할 후속 근거 필요. 공유 오류 시 TXT가 없을 수 있음 |
| `STEP 1B INIT SD` / `1C MOUNT FAT` / `1D FIND SPACE` | 새 클록 관측이 끝났고 각각 SD 초기화/mount/공간 탐색을 시도함 |
| `STEP 2`–`STEP 8` | 기존 생성·쓰기·sync·close·재열기·비교·읽기 close 단계 |
| `TXT SAVED + READBACK OK`, `Save code: 0` | 저장·재읽기 성공. 같은 화면의 파일명을 기준으로 TXT 회수 |
| `TXT SAVE FAILED`, 코드2–7 | 파일시스템/읽기 비교 실패. 코드·파일명·실제 파일 회수 |

클록 결과는 화면10행과 TXT의 RESULT에 나온다. `CLOCK ACTIVE`=관측 구간에 활동 있음, `CLOCK ABSENT`=두 구간에 활동 없음, `CLOCK UNSTABLE`=중단/불연속 등 일관된 판정 불가, `NO CLOCK PROGRESS`=제한 안에 필요한 측정 구간을 얻지 못함이다. **어느 결과든 파일을 전달하면 된다.** ACTIVE를 실제 주파수/외부 메모리 타이밍 승인으로 해석하지 않는다.

TXT는 반복 알파벳이 아니라 원시 snapshot과 해석값이다. 길이는 결과에 따라 달라지며3072바이트보다 작다. FILE 존재만으로 완료를 판단하지 않는다. `tools/check_nes_clock_report090.py`로 raw/decoded 일치를 확인하고 화면·관측 조건을 함께 검토한다.

## 범위

CF87 관측 이미지는 PSRAM 비활성 회로이며 펌웨어에 내장했다. 새 FPGA 파일을 SD에 별도로 복사하지 않는다. 정상044 복원으로 기존 사용으로 돌아간다.090의 전체 세션94·ARM 링크,091의 실제 설정 함수/매크로를 이용한 레지스터 모델과 전환 누락 대조3개, 패키지 전체 멤버 검증은 완료했지만 새 클록 관측의 실기 결과는 아직 없다. MCU/SPI 전기 파형·절대 주파수·CF86 메모리 고장 보호·게임 실행 완료를 주장하지 않는다.

대응 소스는 `FXPAK-CLOCKREPORT090-SOURCE.zip`이다. SD 자동 설치는 하지 않았다.
