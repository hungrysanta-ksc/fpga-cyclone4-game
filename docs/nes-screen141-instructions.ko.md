# NES141 — 메뉴 복귀와 ROM 응답 수정 시험

140은 ROM 오류 뒤 검은 화면에서 메뉴로 돌아오지 못했습니다. 141은 보고서 저장 후 메뉴 통신의 대기 예산을 복구하고, ROM 완료 신호와 실제 데이터 소비 시점의 관계를 수정하고 반복되는 CPU·PPU ROM 읽기를 각각 8바이트·2바이트 캐시에 보관하는 후보입니다. PSRAM 읽기 시간과 읽은 뒤 핀 유지 시간은 줄이지 않았습니다. 실기 해결 여부는 이번 결과로 판정합니다.

## 복사와 실행

1. 전원을 끄고 현재 SD의 `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`을 별도 보관합니다.
2. ZIP의 **`01-SCREEN141-SD-ROOT` 안의 내용**을 SD 최상위에 복사합니다. 펌웨어·`fpga_n141.bi3`·`nes/screen141.nes`를 함께 적용합니다.
3. 메뉴에서 **`NES SCREEN 141.nh1`**을 한 번 실행합니다. 이 선택 파일은 **0바이트가 정상**입니다. 이전 버전 선택 파일을 실행하거나 확장자를 바꾸지 않습니다.
4. 메뉴로 돌아오면 전원을 끄고 아래 두 TXT를 회수합니다.

**같은 044 복원 및 GBC 회귀 시험은 다시 요청하지 않습니다.** ZIP의 `02-RESTORE044-SD-ROOT`는 기존 복원본 그대로이며 필요할 때 사용할 수 있습니다. 이번 후보의 자동 메뉴 복귀 여부는 반드시 구분해서 관찰합니다.

## 시간과 관찰

80KiB 적재·대조에 이전 실기 기준 약 9분이 걸립니다. 정상이라면 이후 약 10초간 진단 화면을 표시하고 메뉴로 복귀하는 것이 목표입니다. 입력과 소리는 아직 시험하지 않습니다.

실행 후 **전체 10분**을 관찰 기준으로 삼습니다. 복귀하지 않으면 더 기다리거나 리셋 버튼을 반복해서 누르지 말고 전원을 끈 뒤 남은 로그를 회수합니다. 전원을 다시 켰을 때 메뉴가 나오는지도 알려주세요. 같은 실패 시험을 반복할 필요는 없습니다.

## 전달할 결과

- `sd2snes/nes-progress-141.txt`
- `sd2snes/nes-screen-last-141.txt`
- 화면이 보였는지, 검은 화면이나 깨짐이 있었는지, 자동 메뉴 복귀 여부

화면이 보이면 사진 한 장이나 짧은 영상이 유용하지만 필수는 아닙니다. 전체 9분 과정을 촬영할 필요는 없습니다. TXT가 없거나 0바이트라면 그 사실을 알려주세요.

`run_passed=1`은 CPU 읽기 활동과 종료 검사 통과이며 정상 영상의 자동 판정이 아닙니다. `MENU_PREPARED`는 SD에 저장하는 마지막 진행 단계로, RESET 해제나 실제 메뉴 표시의 성공을 보증하지 않습니다. RUN 중 SD 쓰기 금지와 최초 오류 보존은 유지합니다.

## 범위

동일한 진단 ROM으로 두 수정의 효과를 확인합니다. 첫 게임 목표는 계속 SMB3(J), mapper4이며 이번 패키지는 게임·패드·오디오 완료가 아닙니다. 보드 지연 실측, MTBF, E1/E2, 8µs 및 양 클록 정지 시 CE 9µs 제한, source-lock 4건은 보류 상태를 유지합니다. 분해·LED 확인·PC 직접 연결·SD 포맷은 필요 없습니다.
