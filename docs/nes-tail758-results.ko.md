# 758 · 마지막 두 map을 먼저 보내면 957 표시가 앞당겨지는가

## 목표

753과 같은 두 시작 위상에서 957 오른쪽 페이지의 마지막 두 범위(3,200·3,392)를 먼저 확정·발행한다. 판정 시점은 여덟 번째로 소비된 map 패킷의 65816 반환이다. 956 공개 뒤 첫 VBlank의 248선 마감과 957 표시 2 VBlank, 951→957 여섯 표시 간격 평균과 리셋→957 최종 ACK의 동시 단축을 확인한다.

## 작업내용

753 ARM의 957에서 범위 3,200의 첫 쓰기부터 마지막 쓰기까지 실제 함수 진입·복귀와 SPI 시작·종료를 기록했다. 중첩 구간은 SPI를 먼저 계상하고 slot·행 쓰기·나머지 ARM을 나눴다. 이 시간창에는 이웃 페이지 셀의 준비와 쓰기도 들어간다. slot 시간은 현재 세대의 resident 탐색·할당 함수 실행 시간이다. 확정 시각 자체는 각 셀이 참조하는 최종 slot의 사용 비트가 처음 설정되는 시각으로 별도 확인했다.

| 753에서 점유한 작업 | 시간 ms (두 위상 동일) | 계측 |
|---|---:|---|
| BG slot 탐색·할당 | 0.357762 | 겹친 함수 호출 59회, SPI 제외 |
| 행 쓰기 함수 | 0.038667 | 겹친 호출 85회, 대상 범위 실제 byte store 114회 |
| tile E8 | 0.109083 | 20B 거래 1회 |
| tile E9 | 0.116502 | 22B 거래 1회 |
| 나머지 ARM 처리 | 0.297452 | 셀·루프 제어 및 계상한 함수 밖의 실행 |
| 합계 | 0.919466 | 첫·마지막 store 사이 경과 시간 |

- 현재 프레임에서 검증한 일반 BG 태그와 slot을 8개까지 보관하고, 같은 태그일 때 재사용했다. 예외 shape와 충돌·miss는 기존 경로로 처리했다. map 셀은 16비트 비교·쓰기로 바꿨다. compact는 기존 두 칸 전 특례를 제거하고 writer 본문을 공유한다. inlining된 후보의 행 쓰기 시간은 나머지 ARM에 포함한다.
- 뒤 두 범위 우선(tail)과 원래 순서대로 완성 범위 발행(burst)은 warm 이력·tile 계획·192B 전체 확정·큐 credit을 확인한다. 기존 형식의 E1 한 건씩 enqueue하고 성공한 범위만 기록한다. 대상 map의 전체 커버리지와 셀 내용을 독립적으로 비교했다.
- 같은 707D 보드 근거와 751 정적 65816 ROM을 사용했다. ARM 전체 링크 명령 실행(CPI 2), 보정한 공유 SPI, IRQ, ROM 경쟁 달력과 65816 CPU·PPU·DMA를 결합해 리셋부터 905–957을 비교했다. 두 시작 클록은 7,288,416 / 7,467,100이다. 실기 측정과 신규 Quartus 빌드는 수행하지 않았다.

## 성과

시간 쌍은 위상 1 / 2다. 248선 지연은 956 공개 뒤 첫 VBlank에서 248선이 끝나는 시각을 기준으로 측정했다(경계 오차 최대 4 master clocks). 최종 ACK 차이는 같은 위상의 753과 비교한 리셋 이후 누적 시간이다.

| ARM 후보 | 페이지 전체 반환의 248선 지연 ms | 957 표시 간격 VBlank | 952–957 밀집 평균 ms | 957 최종 ACK 차이 ms | Flash B |
|---|---:|---:|---:|---:|---:|
| 753 계측 대조 | 14.646 / 14.932 | 3 / 3 | 49.90983 / 49.91245 | 0 / 0 | 212,960 |
| 8태그·16비트 쓰기 | 14.007 / 14.328 | 3 / 3 | 49.91472 / 49.90983 | +0.011 / −16.650 | 213,072 |
| compact | 14.175 / 14.491 | 3 / 3 | 49.90985 / 49.91281 | −16.639 / −16.650 | 212,960 |
| 뒤 두 범위 우선 | 14.691 / 14.928 | 3 / 3 | 49.93707 / 49.93597 | +0.140 / −16.504 | 213,436 |
| 확정 범위 원래 순서 | 13.244 / 13.280 | 3 / 3 | 49.96207 / 49.96559 | +0.313 / −16.326 | 213,436 |

뒤 두 범위 우선에서는 오프셋 3,200 E1 시작이 +12.426 / +12.692ms에서 **−0.562 / −0.518ms**로, 3,392가 +13.322 / +13.588ms에서 **+0.475 / +0.519ms**로 이동했다. 3,392의 65816 반환은 +1.813 / +1.833ms였다. 뒤로 밀린 3,008이 여덟 번째 패킷이 되어 전체 반환은 +14.691 / +14.928ms였다. 952의 선행 DMA도 384+1,152 / 192+192+1,152B로, 957은 두 위상 모두 384+1,152B로 나뉘었다. 원래 순서 후보는 957에서 576+960B로 나뉘었다.

compact는 3,200 구간을 0.919466→0.818609ms로 줄였다. slot은 0.314048ms, 행 쓰기는 0.016929ms였다. Flash 32B 여유, BSS 19,796B, 관측한 스택과 작업공간 간 여유 1,568 / 1,504B였다. 두 1,536B DMA와 E8 마감, 957 OBJ 시작 246 / 247선을 지켰다. 누적 ACK는 앞당겼지만 두 위상의 952–957 각 간격은 모두 3 VBlank였고, 908 간격은 두 위상 모두 2→3으로 늘었다. 전체 후보에서 951 공개 236선·911 표시 2회·957 최종 대기 0회와 957 E8 마감은 유지됐다. Flash 상한 212,992B를 넘은 후보는 보드 설치 대상에서 제외했다.

**남은 비용.** 753에서 3,200의 첫 쓰기부터 마지막 쓰기까지를 통째로 0으로 놓고, 그 뒤 모든 준비를 같은 만큼 당겨도 기존 여덟 거래의 E1 완료가 248선을 **0.075 / 0.129ms** 넘었다. 실제 패킷별 65816 수락→반환 서비스를 SPI와 겹쳐 적용하면 **0.656 / 0.710ms** 늦었다. 위상 1에서는 2,048의 마지막 쓰기 뒤 남은 여덟 E1, 위상 2에서는 3,008 뒤 남은 세 E1이 전송 마감을 결정했다. 이 계산은 기존 192B 순서와 E1별 211B·드라이버 비용을 유지하고 다른 SPI·credit·대기를 제거한 조건부 비교다.

**안전성.** 대조군과 후보 네 개를 각각 두 위상에서 53화면 실행해 753과 map·RGB·작업량을 대조했다. 753 대조 재실행의 map 발행·수락·반환·DMA·표시와 최종 ACK가 기존 기록과 일치했다. 네 ARM 링크에서 손상 receipt·잘못된 credit·STOP·잘못된 최종 ACK·메뉴 복귀 경로를 검사했다. 뒤 두 범위 우선의 실제 첫 384B DMA 직전·수행 중 STOP, 새 head 우선, 오래된 identity를 각각 두 위상에서 주입했다. STOP·손상은 956 화면을 보존하고 957 최종 ACK를 차단했다. 새 head는 DMA보다 먼저 처리되고 53번째 화면이 정상 커밋됐다.

## 후속작업

753을 유지한다. 다음에는 2,048·3,008의 마지막 쓰기와 후속 E1 서비스 시간을 함께 줄일 예산부터 잡는다. 여덟 E1의 드라이버 고정비는 합계 약 0.398ms다. 이를 모두 절감해도 관측된 65816 반환 비용까지 남으므로, 생산·수신을 겹치면서 수신기가 1,536B 전체를 한 번에 DMA할 수 있는 시점을 별도로 대조한다. 처음부터 끝까지 같은 시작 위상에서 908·E8·OBJ 마감과 957 두 번째 VBlank를 함께 판정한다.

## 재현

1. `tools/prepare_nes_tail758.py <753 arm-prefix/src> <새 overlay> word|compact|tail|burst` 후 `tools/build_nes_mmc479_arm.ps1`로 각 ARM을 전체 링크한다. 각 모드는 `../probes/nes-tail758/arm-<모드>`에 둔다.
2. `tools/run_nes_tail758.ps1 -Variant control|word|compact|tail|burst -Phase 1|2 -Game <ROM>`을 각 조합으로 실행한다. word 첫 실행은 계측기가 인라인된 함수 심볼을 찾다 중단되어 수정 후 같은 바이너리로 두 위상을 재실행했다.
3. 계산 전용 후보는 `check_nes_credit752.py`의 mapobj 검사, 발행 후보는 `check_nes_rows757.py`의 tail·page 검사로 각각 `guards-<모드>.json`을 생성한다. 두 tail 추적에 `check_nes_static751.py --source 23680 --size 384 --fault before|during|head|stale`를 적용해 각 출력 폴더를 `nes-tail758-tail<위상>-<fault>`로 지정한다.
4. `tools/analyze_nes_tail758.py --temp <추적 루트> --probe ../probes/nes-tail758 --out analysis/tail758-verification.json`을 실행한다. [두 위상 실측·해시·보호 검사](../analysis/tail758-verification.json)
