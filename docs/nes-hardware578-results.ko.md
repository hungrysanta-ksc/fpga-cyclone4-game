# MMC577 실기 비교

사용자는 실행·메뉴 복귀가 정상이며 프레임 개선을 느꼈다고 보고했다. 첨부된 세 로그는 한 실행이다. MMC558의 저장된 한 실행과 비교한다.

| 표시 완료 구간 | MMC558 | MMC577 | 변화 |
|---|---:|---:|---:|
| 5–40초 | 478회 · 13.66fps | 482회 · 13.77fps | +0.84% |
| 40–55초 | 208회 · 13.87fps | 211회 · 14.07fps | +1.44% |
| 5–55초 | 686회 · 13.72fps | 693회 · 13.86fps | +1.02% |
| 전체 60.08초 | 842회 · 14.01fps | 838회 · 13.95fps | −0.48% |

첫·마지막 5초를 제외한 주 비교에서는 양 구간 모두 소폭 증가했다. 제외 구간의 표시 수는 156→145회여서 전체 평균은 약간 낮다. 한 번씩의 비동기 플레이이므로 위 비율을 코드 변경만의 인과적 가속률로 확정하지 않는다.

## 구간의 부하와 체감

프레임 시작 시각으로 묶은 5초 bin에서 후반 표시 수는 40–45초 48→69회, 45–50초 69→72회, 50–55초 91→70회다. 이전의 40–45초 집중 저하가 이번에는 덜 보이며 후반 분포가 더 고르다. 해당 구간의 최대 표시 간격 카운터도 각각 150→140ms, 110→100ms, 270→100ms다. 이는 10ms 단위 최대치이며 p95나 동일 장면의 결과는 아니다.

후반 전체에서 표시당 변경 map 행은 8.93→10.94개, E1 전송량은 2,001→2,497B로 늘었지만 출력 tick 비용은 38.27→36.73ms였다. 특히 50–55초 map 행은 4.30→10.60개로 크게 다르다. 영상·장면별 기록이 없어 적의 수나 플레이 위치를 동일하게 맞춘 결과로 해석할 수 없다. 시작 bin과 표시 완료 window의 정의도 구분한다.

## 남은 비용

전체 DWT 누적 시간을 완료 표시 수로 나눈 값이다. 수신·계획에는 마지막 미완료 작업 일부도 포함된다. IRQ·대기가 포함되며 하위 SPI/poll 비용을 다시 더하지 않는다.

| ms/표시 | MMC558 | MMC577 |
|---|---:|---:|
| 수신 | 19.79 | 19.89 |
| 계획·공급 | 14.31 | 14.83 |
| 출력·최종 ACK | 36.63 | 36.37 |

가장 큰 비용은 여전히 출력·최종 ACK다. 이번 로그만으로 DMA와 마지막 VBlank 대기를 분리할 수 없다. 전체 평균 71.69ms는 60fps의 16.67ms보다 약 55.03ms 길다. 5–55초 완료 빈도 13.86fps의 역수는 약 72.15ms이며 전체 평균과 서로 다른 집계다.

## 정상 종료와 미완료 작업

384KiB 적재·readback·CRC, START/RUN, STOP, base 복구와 메뉴 준비가 완료됐다. 사용자도 메뉴 복귀를 확인했다. CRC 오류·실패 전송·abort·ROM/고장 문맥 오류는 기록상 0이다. 838개의 표시 완료와 EA 횟수가 일치한다.

입력 BEGIN/END/commit은 839회다. 839번째 ordinary section 2 전송 중 종료됐으며 큐 발행/retire는 23,528/23,527, 마지막 표시 시각은 59.96초다. native_result=1, sink_window_error=3, native_sink_error=2는 시간 제한 중 전송 경계에서 종료된 서명과 일치한다. 실제 ARM577 소스의 guard→transfer→post-guard와 window 전송 실패 경로를 확인했다. 물리적인 실패 명령 시각은 로그에 없어 재현 완료나 모든 error=3의 무해함을 주장하지 않는다. 이 미완료 입력은 FPS에 넣지 않았다.

screen_error=169는 이 로그의 명시적 역할대로 SPC 초기화 결과이며 화면 오류 횟수가 아니다. screen_telemetry_trusted=0이므로 screen_frames=0을 표시 수로 사용하지 않는다.

## 다음 순서와 보존

MMC577을 새 실기 기준으로 고정한다. 다음은 출력·최종 ACK 약 36.37ms를 같은 작업량·두 시작 위상에서 수락 전 공급, 실제 DMA, SEAL 이후 VBlank로 나누고 가장 큰 잔여 대기 하나를 선택한다. STOP·독립 검사·최종 ACK·메뉴 복귀와 5–40/40–55초 집계를 유지한다. 양수 timer/epoch 배치·seed 반복은 재개하지 않는다. 내부 CDC/STA 검증과 이번 정상 실기는 외부 IO 전체 sign-off나 capture 무손실·60fps 달성 증거가 아니다.

새 firmware·FPGA 합성·전달 ZIP은 만들지 않았다. [선택 전달본](../analysis/trial577-package.json)과 [577 검증](nes-gate577-results.ko.md)은 변경하지 않는다. 원본 세 로그는 probes/nes-hardware578/run01에 바이트 그대로 복사했고 다운로드 원본과 SHA256을 대조했다. [측정값·해시](../analysis/hardware578-mmc577.json) · [재현 도구](../tools/analyze_nes_hardware578.py)
