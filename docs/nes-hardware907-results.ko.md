# MMC907 실기 결과 · 모험도 4 무입력 60초

MMC905와 MMC907을 각각 한 번 실행한 기록이다. MMC907은 ROM 393,216B 전체 비교를 통과했고 전송 실패, 캡처 abort, 실행 ROM 오류와 STOP 오류가 모두 0이었다. 마지막 표시는 59.95초였고 STOP 완료, base 복구 및 MENU_PREPARED까지 사용자가 확인한 메뉴 복귀와 일치한다. 종료 시점에는 미반환 큐 항목 하나와 sink 오류값 2가 남았다. 해당 스냅샷에는 발생 시각이 없다.

| 표시 완료 구간 | MMC905 | MMC907 | 차이 |
|---|---:|---:|---:|
| 1–30초 오프닝 | 531장 · 18.31 FPS | 597장 · 20.59 FPS | +2.28 FPS |
| 30–60초 데모 | 504장 · 16.80 FPS | 592장 · 19.73 FPS | +2.93 FPS |
| 55–60초 데모 | 78–79장 · 15.6–15.8 FPS | 92장 · 18.40 FPS | +2.6–2.8 FPS |

55–60초는 데모에 포함된다. MMC905는 이 구간에 시작해 완료한 78장과 55초 경계 전부터 진행 중이었을 수 있는 한 장으로 범위를 계산했다. MMC907은 시작 91장과 별도로 표시 완료 92장을 셌다. 두 판 모두 상세 계측 버퍼 누락은 0이었다.

## 같은 작업량에서 확인되는 변화

MMC905 세대 1079(56.74초)의 BG 528·OBJ 45·변경 map 0 조합은 MMC907 후반 요약 91장에 없었다. 선택된 세대 1212(56.46초)는 BG 529·OBJ 14·변경 map 9로, 총 9타일·4묶음이었다. 첫 E9→마지막 OBJ 준비는 18.725ms, 입력 완료→ARM 첫 유효 최종 ACK는 57.094ms, ROM 허가는 64회였다. MMC905 세대 1079는 31타일·8묶음에 각각 109.227ms, 131.176ms, 316회였다. 세대 1212에는 기준의 608B OBJ 묶음이 없어 해당 묶음의 실기 절감량은 미확정이다.

별도로 두 BIN에서 시작 tick이 정확히 같고 BG·OBJ·변경 map·타일 수·묶음 수·마지막 묶음 종류·크기·offset이 모두 일치하는 화면은 8쌍이었다. 입력 완료→최종 ACK가 빨라진 화면은 3쌍, 늦어진 화면은 5쌍이었다. 57.67초는 표시 뱅크까지 같았고 첫 E9→마지막 OBJ 준비가 44.861→19.505ms, 입력 완료→최종 ACK가 66.267→58.453ms로 줄었다. 56.30초 역시 표시 뱅크까지 같았지만 각각 26.526→29.257ms와 50.036→61.349ms로 늘었다. 이 요약 행에는 모든 묶음의 개별 ROM 허가 수가 없다.

다음 비교의 실기 기준은 MMC907로 둔다. 같은 시각·작업량에서도 ACK 방향이 갈린 두 화면의 ROM 공급 이후 DMA와 VBlank 경계를 대조하고, 608B 묶음의 가설은 실제로 그 크기가 반환된 화면에서 확인한다. 구간 FPS 비교는 기존 무입력 1–30초·30–60초 기준을 유지한다. 두 판의 작업량 선택과 계측 비용 차이까지 포함한 이번 한 번의 결과로는 보드 변경만의 기여도를 분리할 수 없다.

재현 명령은 `python tools/compare_nes_trial907.py <905 로그 폴더> <907 로그 폴더>`다. 요약 행 대조에는 같은 도구가 사용하는 `read_nes_supply905.decode`의 `rows`를 사용했다.
