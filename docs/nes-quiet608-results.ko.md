# 608 · E8 조회와 957의 마지막 DMA

MMC577에서 계획기만 바꾼 607의 두 슬롯 ARM을 대조군으로 썼다. 이전 단계에서 951은 한 VBlank 빨라졌지만 952·954는 첫 E9 이후 같은 ROM 허가를 기다렸고, 957은 표시 직전 246번 검사선을 넘었다. 이번에는 ARM 조회 간격과 SNES 팔레트 수신 비용을 별개로 변경했다.

## 607에서 실제로 기다린 대상

- 952의 E8은 두 위상 모두 59회, 954는 60 / 59회였다. 마지막 일반 E1 뒤부터 마지막 OBJ ROM 응답 전까지 bulk가 비어 있다고 응답한 횟수는 952에서 11 / 11회, 954에서 19 / 18회였다. 앞쪽의 빈 응답 사이에는 map·팔레트·OAM·HDMA 발행이 실제로 진행됐다. 그 조회들을 전부 없앨 수 있는 시간으로 계산하지 않았다.
- E8은 명령 수신 시점에 응답을 고정한다. 각 응답의 CRC, accepted count, flags, bulk token을 기록하고 실제 ROM 응답 시각과 맞췄다. E0에서 읽은 sent/retired도 해당 거래 시작까지 실제 PUSH·65816 ACK 수와 대조했다. SPI 응답이 연속으로 같았다는 것만으로 그동안 상태 변화가 불가능했다고 가정하지 않는다.
- 957의 이전 대조군은 SEAL 앞에서 512 B map 두 건을 보냈다. 607은 두 위상 모두 128 B map 한 건만 미리 보냈고, SEAL이 1,536 B map 명령 하나를 맡았다. final credit은 480 B였고 빔 검사 위치는 두 위상 모두 248번 선이었다.
- 607의 패킷 도착을 그대로 주고 65816을 독립 재생했다. 마지막 기회의 head는 16 B 타일, tail은 이미 수락한 1,536 B map이었다. 선택기는 작은 타일을 골랐지만 최종 STOP·head 재검사 때 1674번 팔레트 패킷이 먼저 도착했다. DMA가 양보한 시점에는 16 B 전송조차 시작할 수 없었다. 두 독립 재생 모두 53화면의 원래 이벤트 시각과 RGB가 일치했다.

## 두 변경의 범위

**ARM 조회**. 일반 패킷 발행이 모두 끝난 FINAL 단계에서 E8이 빈 descriptor를 반환하면 기존 128 µs 대기 함수를 한 번 더 호출한다. 대기 중에도 기존 deadline·STOP·service guard를 돌린다. 이미 관측한 bulk는 즉시 소비하고, ordinary·credit·E9 발행 경로는 원래 순서를 유지한다. 다음에 발생하는 FPGA 상태를 늦게 읽을 가능성은 두 위상의 종단 시각에 청구한다. 두 대기 각각에 STOP을 넣었을 때 다음 SPI 거래 없이 중단했다. 재개 후 첫 응답의 CRC가 틀리면 완료를 거부했고, 정상 END 상태만으로는 EA가 허용되지 않았다. ARM은 212,980 B로 Flash가 12 B 남는다.

**65816 팔레트 수신**. 1674번은 같은 값 152 B를 palette WRAM에 쓰는 명령이었다. 두 바이트가 같은 64 B 이상 반복은 기존 고정 source DMA로 복원한다. 목적지는 비활성 뱅크의 palette WRAM이며, 실제 CGRAM 표시는 기존 VBlank 경로가 맡는다. 64 B마다 STOP을 확인하고 마지막 조각까지 검사한 경우에만 ACK한다. section 3은 section 5의 raw 이력을 발행하는 코드를 건너뛴다. 프로그램 본체는 4,931→4,949 B, 할당은 5,120 B 그대로다. FPGA 내장 ROM 초기값은 바뀐다.

정상 실행에서는 각 고정 DMA의 소스·길이·조각 간 서비스와 ACK 시점의 palette WRAM을 받은 패킷에 대조했다. 별도로 906의 152 B를 0·64·128·152 B에서, 반대 뱅크인 907의 96 B를 0·64·96 B에서 취소했다. 7건 모두 완료한 prefix 밖의 바이트를 유지하고 오류 ACK 0xe4로 끝났으며 이전 표시 RGB가 남았다. ## SEAL을 10 ms 앞당기려면

607의 직전 표시를 원점으로 잡고 기존 SEAL보다 10 ms 이른 시점에서 ROM 응답을 잘랐다. 952와 954 모두 두 위상에서 OBJ 11슬롯의 96 B가 남았다. mapper가 확정한 tag·행·plane으로 다시 계산해도 96개는 서로 다른 주소이고 그 세대에서 마감 전에 읽은 OBJ 주소와 겹치는 바이트는 0개였다. 이 11슬롯의 계획은 모두 마감 전에 이미 FPGA가 수락했다.

| 607 장면 | 첫 지연 슬롯 | 이전 표시 → plan 수락, 위상 1 / 2 | 첫 요청 → 허가, 위상 1 / 2 | 마지막 ROM 응답 → SEAL, 위상 1 / 2 |
|---|---:|---:|---:|---:|
| 952 | 40 | 39.01 / 38.95 ms | 50.38→65.88 / 50.32→65.88 ms | 2.998 / 2.933 ms |
| 954 | 60 | 34.77 / 34.72 ms | 52.28→66.53 / 52.26→66.55 ms | 2.994 / 2.917 ms |

첫 요청 뒤 14.25–15.56 ms 동안 기록된 중재 일정에서 허가를 얻지 못했다. ROM 이후의 모든 비용을 0으로 두어도 10 ms 목표 중 **7.002–7.083 ms**는 그 앞에서 확보해야 한다. 다음 시험은 해당 96개 주소를 같은 캡처의 mapper 확정 PPU 읽기에 맞추고, 실제 읽기 포트·세대 취소·두 bulk 슬롯까지 포함해 앞선 허가 구간에서 공급할 수 있는지 판정한다. 이 수치는 주기적으로 재생한 ROM 허가 일정에 한정된다.

## 재현

607 문서의 동일 입력·fixture·53화면 연속 실행 환경을 사용한다. ARM은 `prepare_nes_quiet608.py`에 recent577 프로젝트를 주고 `build_nes_trial577.ps1`로 전체 링크한다. client는 `nes_quiet608_client.py --out`으로 만든다. 원본 client에는 기존 `test_nes_close561.py`, 새 client에는 팔레트 검사기가 연결된 `test_nes_quiet608.py`를 사용한다. 시작 클록은 3000000 / 3178684다. `guard_nes_quiet608.py`와 `test_nes_repeat545_stop.py --palette`는 취소·오류 경계를 검사한다. `replay_nes_quiet608.py`는 607 두 위상의 selector를 관측하며 `analyze_nes_quiet608.py`는 원본 해시와 관측 결과를 대조한다. Windows 임시 디렉터리의 원시 trace는 이전 단계와 동일하게 별도 입력이다.
