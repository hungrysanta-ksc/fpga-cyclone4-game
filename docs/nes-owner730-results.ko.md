# NES730 첫 OBJ 소비와 map DMA 대기 순서

## 목표

727의384B 연속 DMA·BG 마감을 유지하고953의 첫 OBJ 소비·뱅크 반환을 앞당겨 후속 OBJ 생산 공백을 줄인다. Flash·STOP·독립 검사·최종 ACK·메뉴 경계와908/911/951/952/957·입력7블록을 보호하며 두 시작 위상의 전체 밀집 표시 간격·957 마지막 ACK를 비교한다.

## 작업내용

기준727의953 OBJ112회는 모두 `OBJ_capture` 적중이다. 최대 demand 공백은9.216/9.117ms지만 **뱅크 반환 뒤9ms가 더 걸린다는 뜻이 아니다.** 첫 OBJ64B가 수락·소비되기를 기다리는 동안 두 bulk 뱅크가 차 있어 후속 생산이 멈춘다. 기존 재생 모델은 실제65816의 token 소비 쓰기를 받고 뱅크를 반환하며,queue ACK와 표시 ACK를 구분한다. 생산은 첫 packet ACK 약43.35µs 전에 이미 재개한다.

첫 OBJ가 준비된 뒤 SPI 발행까지는 두 위상 모두9.772ms다. 마지막 map ACK 뒤에도 첫 OBJ 발행까지5.927/5.908ms가 남고,마지막 map 발행과 첫 OBJ 발행 사이 `through` 호출은23회다. 이 중719의 map DMA 기회 대기에서 새로운 producer를 조회하지 않는다. 외부PSRAM 대기나 반환 이후 제어 지연으로 잘못 분류하지 않는다.

730A는 map 전체 발행이 끝나고719의 기존 유한 DMA 대기 조건을 통과했을 때,기존 `nes_plan200_progress(NES_ORDINARY553)`를 한 번 먼저 호출한다. 정상 E8 CRC·identity·token 검사와 실제 E1 credit·STOP 경로로 준비된 bulk를 넘긴다. 이어지는 기존 drain은 그 실제 bulk 소비까지 포함하며,원래 ACK-relative 마감은 재시작하지 않는다. 새 ordinal/세대 예외·고정 poll 수·새 SPI ABI·조기 receipt는 없다. 기존 map 연속 발행·BG 생산·FPGA·65816·SDC는 유지한다.

A는 첫 뱅크를 일찍 반환해도 이어지는 descriptor 확인이 늦어 이득을 대부분 잃었다.730B는 같은 호출 위치에서 기존 `NES_HDMA554` 정책을 사용한다. 준비된 bulk를 실제 receipt까지 처리하고 다음 descriptor를 조회하며,생산기가 비면 즉시 반환한다. 미래 ROM을 기다리는 `NES_FINAL553`과 다르고,END가 남아 있으면 기존 guarded E9 경로로 끝낸다. 새 고정 반복 수를 만들지 않고 기존 poll 상한·STOP·완료 소유권을 재사용한다.

공간은729에서 독립 동등성을 검사한 span/OAM 비용 공유만 분리해 확보했다.729의 cached-credit ordinary 우회는 가져오지 않는다. 모든 새 응답을 기존 전체 검사로 처리한다. 실제 변경 파일은 정상/장시간 모두 `nes_native_sink165.c` 하나다.

## 성과

### B: 준비된 bulk 연속 소비

**두 후보 모두 미채택이다.** B도106화면의 같은 map·tile·plan·픽셀·최종 ACK를 통과했다. 첫 생산 공백은 약3.75ms로 줄었고,마지막 descriptor 확인은1.899/1.918ms로 A의5.883/6.156ms보다 짧아졌다. 그러나 ordinary를 뒤로 미룬 비용과956의 선행 DMA 감소로 전체 일정은 빨라지지 않았다. 선택707D·기존 ARM/65816과727 연구 기준을 유지한다.

### 다음 마감과 전송 예산

B의953 마지막tile ACK 뒤에E1 916B가 남는다. 이 바이트를 그대로 전송하면2.625MHz 모델의 순수 wire만2.792ms,실측 드라이버 비용을 적용한 SPI 점유는3.389ms다. 반면 이전246선 끝까지 남은 시간은2.055/2.123ms다. **bulk를 모두 끝낸 뒤 ordinary를 시작하는 순서로는,동일 전송량에서 이 마감에 들어갈 수 없다.** 이 결론은 현재 바이트·클록·시작 일정에 한정하며 프로토콜 전체의 불가능성을 뜻하지 않는다.

현재 SEAL 자체는 이전246선 끝보다5.612/5.549ms 늦다. 이는기존357368-masterclock 달력과실제선/수평클록 anchor로계산한 최소필요선행량이며,독립 검사·잔여DMA·공개비용을0으로둔 필요조건일뿐 충분한 마감 예산이아니다. 실제로필요한선행량은더크다. 전체 데이터가 같아도 마지막tile ACK가 빨라지면 그뒤로 분류되는 ordinary 바이트가 늘 수 있으므로,후반7.67ms 증가를새작업량으로잘못해석하지않는다.

## 후속작업

1. 선택707D·기존 ARM/65816과727을 유지한다. A의단일bulk 서비스와B의ready-chain 선행을제품에합치지않는다. 같은719 앞단일/연속drain·poll횟수·고정대기변형은 새 상위 공급구조 근거 없이 반복하지 않는다.
2. 다음 검토는map 전체 완료 뒤가아닌,이미보장된384B map 쌍의 경계에서첫 OBJ를 공급하면서 ordinary 일부도겹치는 구조다.192B두패킷사이에삽입하지않으며,953의BG/OBJ 소유권 전환과956의bulk·map DMA를같이포함한다. 실제 삭제할중복제어와Flash·stack 비용부터 산정하고,검증되지않은pair허가·bank여유를무료로가정하지않는다.
3. 목표예산은B 대비SEAL 최소5.612/5.549ms 선행에 독립검사·DMA 비용을더한값이다.916B후반E1의일부를실제확정시각부터앞당기거나같은검사를유지하며전송량을줄여야한다.기존고정source 패딩DMA·64B STOP 검사를다시새최적화로세지않는다.
4. 두위상952–957 평균·각프레임간격·957절대ACK와908/911/951/952/957·956선행DMA를함께판정한다.새설치본은없다.다음전달은고유파일명60초/장시간판·RESTORE제외·5–40초/40–55초집계를유지한다.
