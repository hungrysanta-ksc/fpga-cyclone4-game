# MMC907 · 모험도 4 무입력 60초 실기판

1. 전원을 끄고 ZIP 안의 `MMC907-ADVENTURE-60SEC-SD-ROOT` 폴더 **내용물**을 SD 카드 루트에 복사한다.
2. MMC905에서 사용한 `sd2snes/nes/mmc905.nes`를 같은 폴더에 `mmc907.nes`로 복사한다.
3. SD 메뉴에서 **NES MMC3 907.nh1**을 한 번 실행한다. 아무 버튼도 누르지 않고 오프닝과 스테이지 데모를 지나 60초 후 자동 메뉴 복귀까지 기다린다.
4. 재실행 전에 `sd2snes` 폴더의 `nes-frame-mmc907.bin`, `nes-budget-mmc907.txt`, `nes-progress-mmc907.txt`, `nes-game-last-mmc907.txt`를 보관한다.

## 실기 비교

MMC905의 기준 화면은 무입력 데모 56.74초에 시작한 세대 1079다. 변경 map 0, BG 528, OBJ 45였고 실제 타일 공급은 31개, 8묶음이었다. ROM 허가는 전체 316회, 그중 OBJ 608B에서 204회였다. FPGA가 첫 E9를 받은 뒤 마지막 OBJ가 준비되기까지 109.227ms, ARM의 입력 완료부터 첫 유효 최종 ACK 확인까지 131.176ms였다.

MMC907은 55–60초 안에서 작업량, 타일·묶음 개수, 마지막 OBJ의 크기와 위치, 시작 시각을 보고 상세 기록 한 장을 선택한다. 분석기는 양쪽의 map·OBJ·BG와 8개 묶음 각각의 종류·크기를 확인하고 시작 시각 차이가 0.30초 이내일 때만 허가 수와 지연의 차이를 계산한다. 조건을 벗어나면 실제 차이와 양측 측정값을 표시한다. 추가 SPI 조회는 해당 화면의 ACK 뒤에 실행하며 조회 시간도 남긴다.

FPS는 ARM이 확인한 표시 완료 시각으로 집계한다. MMC905의 1–30초는 18.31 FPS, 30–60초는 16.80 FPS였다. MMC905의 55–60초에는 그 구간에 시작해 표시된 화면이 78장이고 마지막 표시는 59.98초였다. 55초 전에 시작한 화면 한 장이 경계에 걸릴 수 있어 15.6–15.8 FPS 범위로 비교한다. MMC907은 55–60초 표시 완료 수를 별도로 세므로 이 구간도 정확히 집계된다.

## 검증과 재현

906 보드의 Quartus Lite 최종 이미지와 65816 표시 ROM을 확인했다. 전체 FIT는 15,296/15,408 LE, 961/963 LAB, 54/56 M9K이며 최저 setup은 +0.385ns, hold는 +0.171ns다. 기존 외부 I/O 미제약 항목은 검증표에 남겼다. ARM 최종 링크는 212,820/212,992B다. SRAM D0 송신 네 곳, 독립 입력 CRC와 실패 처리, 60초 STOP, base 복구·메뉴 반환을 최종 링크로 재생했다. 실기 성능은 위 네 로그로 판정한다.

최종 ARM·65816 재생에서 두 시작 위상 모두 8장씩 화면 바이트가 기준과 일치했다. 여섯 표시 간격 합은 기존 캐시에서 15 VBlank, OBJ 캐시를 비우면 20 VBlank였다. 같은 906 보드 모형에 이전 계측용 ARM을 연결한 결과와 비교해 마지막 ACK는 위상 1에서 48·160 마스터클록 늦었고 위상 2에서 20·104클록 빨랐다. 이 값에는 계측 SPI 비용이 들어간다.

저장소의 `tools/prepare_nes_trial907.py`가 보드 이미지와 ARM 변경을 준비한다. 최종 링크 후 같은 도구의 `check-arm <게임 ROM> <MMC905 실기 BIN>`, `replay <임시 작업 경로>`를 실행한다. `tools/package_nes_trial907.py`가 최종 링크, 보드 및 두 시작 위상의 재생 증거를 확인하고 ZIP을 생성한다. 실기 비교 명령은 `python tools/compare_nes_trial907.py <MMC905-로그-디렉터리> <MMC907-로그-디렉터리>`다.
