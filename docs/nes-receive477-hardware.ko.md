# NROM477: 476 실기와 시험 장면의 대표성

사용자가476 로그3개와 정상 메뉴 복귀를 회신했다. 원본은 `probes/nes-nrom477/hardware01`에 byte 그대로 보존했다. [분석 JSON](../analysis/receive477-hardware.json), 재현 도구 `tools/analyze_nes_receive477.py`. 이 확인에서는 새 firmware·합성·시뮬레이션을 실행하지 않았다.

## 이 단순 문양 시험은 무엇을 검증하나

자체6502 NROM을 실제 NES core가 실행해 PPU 상태를 만들고, 수신·검사·ARM 계획·FPGA 출력·65816 DMA/표시·최종ACK/복구 경로를 지난다. 단순한 그림이어도 그 경로의 정상 연결과 동일 입력의 변경 전후 비용을 분리하는 데 유효하다.

반면 실제 게임 성능의 대표성은 낮다. 이번 로그는 **OBJ0**, 최초5초 뒤 **mapdirty0**,28개 BG group 중27개 재사용(96.43%)이다. 다양한 타일·sprite·CHR bank 전환·분할 스크롤·IRQ·ROM 경쟁이 있는 게임보다 쉽게 압축되고 계획 재사용도 유리하다. 화면이 정상이고24fps라는 사실을 SMB3의 정상 표시나24fps/60fps로 확장하지 않는다. 6502 게임 내부 속도와 최종 표시 완료율도 별개다.

## SMB3를 바로 넣을 수 없는 이유

SMB3는 MMC3/mapper4·PRG256KiB/CHR128KiB·WRAM8KiB를 사용하는 실제 게임이다. [실물 카트리지 조사 자료](https://nescartdb.com/profile/view/3539/super-mario-bros-3). 현재 선택된471/476 FPGA는 `cart_nrom.sv`의 고정 NROM16/H·CHR-ROM8KiB 구성이고, 실제 ARM loader도 다른 profile을 FPGA 설정 전에 거부한다. ROM 파일만 바꾸거나 검사만 풀어서는 올바른 게임 시험이 되지 않는다.

기존227에서 SMB3를 시험한 기록은 있지만 현재의 NROM/압축/ARM476 경로와 같은 조합이 아니다. 옛 SMB3 약7.74fps와 현재 문양23.84fps를 향상률로 비교하지 않는다. 옛406/407의 MMC3–NROM 면적 차이는 다른 전체 보드의 MAP이므로 현재14740LE에 단순 가산해서 FIT를 예측하지 않는다.

## 수정한 다음 순서

1. **문양은 회귀 fixture로 유지**한다. 이 문양의60fps를 달성할 때까지 같은 종류의 국소 최적화만 반복하지 않는다.
2. **게임 대표 입력과 현재 receiver/planner를 먼저 비교**한다. 기존 SMB3 capture의 다양한 BG/OBJ·split/예외·bank/tag 사례를 쓰되, 기록 재생과 실기 게임 구동을 구분한다. 필요한 최소 고부하 자체 NROM은 mapper와 표시 부하를 분리하는 대조군이다.
3. **실제 MMC3 진입의 소스·예산을 검토**한다. 알려진227 mapper/WRAM·bank/IRQ·PSRAM 배치와 현재 압축/source/query/lease의 교체 범위를 고정하고 전체 Lite 비용/입력 중 ROM 경쟁을 판정한다. 현재668LE 산술 잔여는 배치 보장이 아니다. 이 단계가 실제 게임으로 가는 다음 구조 관문이다.
4. **구동 가능한 같은 조합으로 SMB3를 측정**한다. 시작 화면만이 아니라 월드맵·1-1 이동·sprite·CHR 변경/상태창·음악/효과음과 전환을 포함한다. 같은 게임 장면의 capture/표시 ID·repeat/miss·cadence·최대/p95·입력·STOP/최종ACK/base/menu를 비교한다. 상용 ROM은 Git/전달 ZIP에 포함하지 않는다.

이 우선순위 변경은 계획이며 새 MMC3 회로·FIT·SMB3 설치본을 만든 성과가 아니다. 실제 게임 검증을 현재24fps 문양 시험으로 대체하지 않는다. 지금 평균30fps까지8.614991ms,60Hz까지25.281657ms가 남고, 이는 해당 제한 장면의 평균 격차다.
