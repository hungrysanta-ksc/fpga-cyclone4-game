# 594 ARM Flash와 cold 입력 동시 판정

593 수신기를 담은 전체 이미지가 **212,064 B**로 링크됐다. 한도 212,992 B에서 **928 B**가 남는다. 같은 ELF에서 cold 905의 map 1,914 B를 순서대로 한 번 읽었고 수신에 234,153명령을 썼다. 84 MHz·CPI 2·동일 SPI 모델에서 입력 시간은 17.984 ms로, MMC577의 20.089 ms보다 2.105 ms 짧다. [검증 수치와 해시](../analysis/report594-verification.json)

|---|---:|---:|---:|

| 한도 대비 여유 | 84 B | −148 B | 928 B |
| 입력 I/O | 13.223 ms | 12.408 ms | 12.408 ms |

593 링크 지도에서 종료 보고 함수 세 곳을 확인했다. budget formatter는 456 B, cost appender는 392 B, save_report는 1,360 B였다. 별도 I/O 진단 formatter는 이미 링커가 폐기해 회수량에서 제외했다. 선택한 후보는 종료 보고에 쓰는 16개 서식의 반복 문구를 빌드 때 한 번 사전화한다. 보고서를 쓸 때만 원래 서식을 스택에 복원해 기존 vsnprintf를 호출한다. SD에 서식 파일을 추가할 필요가 없다.

서식 본문 3,205 B는 인코딩 1,441 B와 사전 564 B가 됐다. 복원 함수의 링크 크기는 92 B다. 호출부·종단 문자·사전 정렬까지 포함한 **전체 이미지 순절감은 1,076 B**다. 할당 섹션을 비교한 77개 object 중 달라진 것은 NES 종료 보고 함수가 들어 있는 3개뿐이었다. BSS는 18,592 B다. [생성기](../tools/prepare_nes_report594.py) · [복원 함수](../tools/nes_report594.inc)

| 실제 ARM 종료 보고 경로 | 593 → 594 실행 명령 | 관측 스택 깊이 | 바이트 비교 |
|---|---:|---:|---|
| 복구 실패, UART 보고 | 51,443 → 63,697 | 7,000 → 7,744 B | 게임 로그 1,900 B 일치 |
| 정상 복구, SD 보고 | 368,371 → 399,510 | 7,072 → 7,816 B | 게임 3,197 B·budget 5,022 B 일치 |

실패 시에는 SD 쓰기가 0회인 것도 확인했다. 두 경로를 합쳐 16개 서식을 모두 실행했다. 성공·실패 각각 budget 출력 버퍼 크기 0, 32, 결과 길이, 결과 길이+1에서 반환값과 버퍼 뒤의 보호 바이트를 확인했다. 성공 경로의 추가 31,139명령과 744 B 스택은 게임 세션이 끝난 뒤 발생한다. save_report는 실행 루프가 돌아온 뒤 호출되며, 복원 함수의 컴파일러 스택 프레임은 752 B다. UART·FatFS 경계는 모델을 사용했다. IRQ가 중첩되는 실기의 최대 스택과 메뉴 복귀 시간은 이번 측정 범위 밖이다. [보고 비교 시험](../tools/check_nes_report594.py)

ARM01의 수신 시험 53입력·27조건은 593과 프레임별 명령·wire·응답·복구 결과가 같았다. 같은 ELF에서 정상 최종 ACK는 표시 1회·EA 후 IDLE, 틀린 generation의 ACK는 표시 0회·EA 차단, 정상 ACK 뒤 EA 처리 중 STOP은 표시 1회·후속 입력 차단이었다. 입력과 출력의 상대 장치는 모델이다. 실기 기준은 MMC577이다.

다음 단일 판정은 594 ARM의 D4 HELLO/REQUEST/MAP_ACCEPT/REPAIR와 고정 행·nonmap 공급을 실제 FPGA의 단일 패킷 소유권 및 CRC에 연결하는 것이다. cold·부분 수신·STOP 복구와 Quartus Lite 동일 경계 비용을 확인한다. 이 경계를 통과하면 전체 보드와 두 시작 위상의 첫 BG~최종 ACK를 검증한다.

선택 근거는 ARM01/test01/ack01/reports04다. prepare_nes_report594.py에 593 ARM04 트리를 전달하고, 새 트리에서 build_nes_trial577.ps1을 실행한다. 수신·표시 검사는 기존 check_nes_receiver593.py 및 check_nes_ack593.py를 그대로 사용한다. check_nes_report594.py로 원본과 새 바이너리를 비교한 뒤 analyze_nes_report594.py로 ELF 해시를 대조한다. 비교 시험을 준비하면서 기준 바이너리에도 영향을 준 메모리 쓰기 훅을 제거하고 SP 직접 관측으로 바꿨으며, 시간 카운터 시험값은 실제 ELF 심볼의 전체 크기만큼 두 바이너리에 동일하게 주입했다.
