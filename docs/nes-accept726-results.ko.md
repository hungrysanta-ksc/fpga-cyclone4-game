# NES726 BG 완료 map의 생산·credit·수락 경계 검증

## 목표

723C의 BG ROM 마감과 map 연속 DMA를 유지하며 확정 map을 목표 VBlank 전에 수락시킨다. 실제 ARM·SPI·credit·65816 비용, Flash·ROM 한도와951/911/952/957·STOP·독립 검사·최종 ACK·메뉴 경계를 함께 검사한다.

## 작업내용

**A는 warm BG 완료 시 기존 credit·producer 검사를 통과한 최대192B map 한 패킷을 OBJ 계산 전에 발행한다.** 723의 행 중간 BG flush·첫 BG 쌍·cold 경로는 그대로다. 기존 `offer527`은 완료 시 직전 map에 인접한 경우만 허용했는데, 완료된 warm map에는 기존 `nes_plan527_map_credit` 경계를 적용했다. 준비된 tile이 있으면 tile이 우선하며, 여유 queue credit가 없으면 map을 밀어 넣지 않는다. generation·CRC·token·실제 bulk 완료·최종 표시 ACK 의미는 유지했다.

원시 기록의 `bg_map_frozen`은 첫 OAM memset에서 관측되므로 BG 완료 콜백의 대기까지 포함한다. 이번 분석은 마지막 BG 완료 콜백 진입의 map hash가 frozen hash와 같은지 확인하고, 그 진입을 생산 완료 경계로 사용한다. 진입·복귀·잔여 planner·resident prepare·END·출력 preflight를 분리했다. 각 map은 packet 함수 진입→E0 credit/receipt 조회→E8 producer 조회→기타 ARM/callback→E1 전송→65816 load→packet ACK로 분해한다. 패킷별 구간은 정확히 합쳐지지만 여러 패킷 구간은 서로 겹칠 수 있으므로 그 합을 프레임 시간으로 부르지 않는다.

723C와 같은 링크 ARM·기존694 65816, 시작7288416/7467100·ROM 위상0·CPI2/84MHz·공유SPI·IRQ 모델로 두 위상53화면씩106화면을 실행했다. 같은 map·tile·plan·픽셀을 확인했다. 실제 명령 실행과 기존 ROM 허가 달력을 포함하지만 전체 NES/PSRAM RTL 동시실행·실기 FPS·물리 메뉴 시험은 아니다.

**첫 map의 수락 대기를 줄였지만 연속 DMA·BG 마감·종단 시간 조건을 함께 만족하지 못했다. A는 미채택이며, 선택본707D·기존 ARM/65816과723C 시간 비교 기준을 유지한다.**

### 첫 패킷과 후속 패킷 사이에 tile이 끼었다

952의 원본 순서는 `map1024/192B → map1216/192B`다. A에서는 두 위상 모두 `map1024/192B → BG1904/48B → OBJ864/32B → map1216/192B`가 됐다. 원본은 offset1024에서384B DMA를 수행했지만 A는192B만 선행 처리했다. offset2048의1536B는 유지돼 총 선행량이192B 줄었다. “첫 map을 일찍 수락”과 “연속 map을 같은 VBlank에 DMA”는 별도 조건이다.

952 공개는238→240선으로 늦어졌고,위상2의953 BG 첫/마지막 허가 구간은170/170→170/171이 됐다. 보호 판정은 구간 수뿐 아니라 같은 시작 시각에서 마지막 구간이 더 늦어지지 않는지도 확인한다. 첫 수락 개선을 전체 표시 이득으로 합산하지 않았다.

### 인접 쌍 수정안의 자원 한도

B는 기존 helper를 두 번 사용해 새 checked-empty 첫192B 뒤 기존 인접192B 완료 경계를 같은 callback에 연결했다. C는 내부 mode1/2/3으로 첫 행·기존 인접 완료·warm 완료 쌍을 구분하고 기존 `map527` 순회에서 최대 두 개의 정확한192B 인접 packet을 처리한다. 공통 SPI ABI·새 persistent RAM은 없고, gap/짧은 범위는 두 번째 발행을 허용하지 않는다.

A의 `offer527`은46→36B이며 alignment를 포함한 전체 Flash는8B 감소했다. B는 helper 반복으로66B, C는 callback54B·`map527`364→380B가 된다. 공통 실행이라는 이름만으로 코드가 줄었다고 계산하지 않는다. **B/C는 정상판 Flash와 같은 전체 경계 예산에서 탈락했으므로 장시간판 전체 링크·두 위상 시간을 실행하지 않았다.** A의 여유8B를 B/C의 비용과 따로 합치지 않는다.

C는 정상 링크 코드의 독립 경계35조건에서 정확한 인접 쌍, gap/짧은 범위·cold/복구·credit wrap·ready tile·CRC·STOP·첫 map 뒤 STOP을 검사했다. 이 기능 검사는 자원·전체 일정 통과가 아니다. C의 기능 결과만으로 연속 DMA나 BG 마감 회복을 주장하지 않는다.

A 정상/장시간 각34새경계,기존DMA gate10·마감17·END 소유권7·입력credit9·runtime16·bulk/STOP 대조24·메뉴 각9조건을 통과했다. 전체106화면에서도 독립 수락/내용/coverage·최종ACK와 두 슬롯 한도를 통과했다. 정적RAM과 관측 stack low는 동일하다. ARM 명령은두위상+28049/+34275,전체SPI는+36/−28B라 일관된 전송량 절감도 아니다. 기존 CRC·65816 복원/종료 근거는 변경 없는 구현에서 승계한다.

FPGA·65816 ROM·SDC가 그대로라707D의전체Lite FIT15322LE·962/963LAB·56/56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 같은 범위로 승계한다. 새 합성·회로 절감·외부IO 승인 확대는 없다. 첫 정상 빌드의 sandbox `subst` 실패와 C 준비기의 header prototype 매칭 실패도 보존했고,실제 전체 빌드/원시 로그와 구분한다.

## 후속작업

1. 723C의 BG ROM 마감·map 연속 DMA를 유지한다. A의 한 패킷 선행만 선택본에 합치지 않는다. 725의 무조건 소비기 검사,무조건 OBJ 우선·고정 대기 상수·세대/위상별 예외도 재시도하지 않는다.
2. 다음 교체 단위는 **checked-empty grant 아래 정확한 인접192B 쌍의 준비·수락**이다. 첫 패킷 뒤 producer를 새로 조회해 BG/OBJ를 끼우지 않되,실제 credit·STOP·첫 패킷만 수락된 실패·cold 복원·최종ACK를 유지해야 한다. C에서 추가한 mode 분기와 기존 pair/진행 제어의 중복을 실제로 삭제할 범위를 먼저 확정한다. 현재 입증된 추가 회수량은0B이며,C는최소24B Flash와22B 같은 경계 삭제가 필요하다.
3. 자원 통과 후보에서만 두 위상을 재생한다. 목표는952의offset1024/1216을384B 선행 DMA로 복구하고953 BG를 원래 ROM 구간에 유지하는 동시에,952–957 합계·평균·밀집 평균·957 마지막ACK를 개선하는 것이다. 수락 시각만 개선되고 최종ACK가 늦어지는 후보는 기각한다.
4. 새실기 전달본은 없다. 다음 전달 시 새 파일명60초/장시간판·RESTORE 제외·5–40초/40–55초 집계 정책을 유지한다.
