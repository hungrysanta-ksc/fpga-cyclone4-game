# 912 OAM 복원과 화면 공개

## 목표

978의 첫 OAM 152B와 4B 원본을 360B로 복원하는 후속 패킷에서 검사·복원·큐 반환 비용을 나눈다. 두 슬롯과 공유 SPI를 사용해 VBlank 46 시작 전 그룹 준비, 같은 VBlank 246선 이내 공개, 최종 ACK 단축을 함께 확인한다.

## 작업내용

세대 905부터 912까지 두 시작 위상에서 실제 65816 명령을 실행했다. 978과 같은 시각에 패킷이 도착하는 대조군, 978 링크 ARM과 65816이 큐 상태를 다시 주고받는 실행, SPI와 큐 credit을 청구하며 준비된 타일 또는 일반 패킷을 우선하는 발행 모델을 각각 측정했다. 수신 코드 후보는 부팅 영향 분리를 위해 912 BEGIN에서 WRAM에 설치했다.

기존 반복 복사는 4B seed DMA 뒤에 겹치는 WRAM 범위를 MVN으로 복사한다. 첫 후보는 ROM의 반복 패턴 24B 전체를 수신한 두 단어와 대조하고, 일치하면 24B씩 DMA한다. 두 번째 후보는 임의의 4B seed를 그대로 써서 앞쪽 나머지를 MVN으로 복사한 뒤 64B씩 16비트 store로 쓴다. 각 묶음에서 기존 STOP 서비스를 호출한다. 원래 identity·범위·coverage·SEAL 검사를 통과하며, 시험 도구가 수락 시점의 비활성 WRAM 전체를 패킷 원본과 대조한다.

## 성과

아래는 SNES 마스터클록이다. 각 칸은 위상 1 / 2 순서다. 검사 열에는 패킷 취득부터 헤더·범위·목적지 결정까지, 복원 열에는 DMA 설정·WRAM 쓰기·STOP 확인까지 포함한다. 반환은 수락 처리 진입부터 큐 ACK까지다.

| 수신 경로 | 검사·주소 | 복원·서비스 | 반환 | 합계 |
|---|---:|---:|---:|---:|
| 978 첫 OAM 152B | 4,162 / 4,210 | 2,112 / 2,112 | 1,182 / 1,182 | 7,456 / 7,504 |
| 978 반복 OAM 360B | 4,996 / 5,038 | 21,278 / 21,288 | 1,190 / 1,182 | 27,464 / 27,508 |
| 64B씩 쓰는 반복 OAM, 링크 ARM | 4,996 / 5,038 | 16,334 / 16,324 | 1,184 / 1,182 | 22,514 / 22,544 |

360B 수신은 4,950 / 4,964클록(각 약 0.231ms) 단축됐다. 24B DMA 후보가 줄인 수신 시간은 약 0.047ms였다. 링크 ARM에서 section 5 마지막 큐 반환부터 SEAL을 읽기 시작하기까지의 대기는 758 / 758클록에서 6,068 / 6,076클록으로 늘었다. 두 위상 모두 SEAL의 실제 SPI 송신 시작·끝과 ARM 최종 E0·EA 시각은 978과 같았다.

| 일정 | VB46 시작 대비 그룹 준비 지연 | 912 공개 | 978 대비 65816 최종 ACK |
|---|---:|---|---:|
| 978 | 9.446 / 9.444ms | VB47 242 / 242선 | 기준 |
| 링크 ARM + 64B 쓰기 | 9.464 / 9.463ms | VB47 242 / 242선 | 330 / 392클록 지연 |
| 일반 패킷 우선 + 1001 DMA 사전 설정 + 64B 쓰기 | 5.974 / 5.968ms | VB47 244 / 244선 | 3,252 / 3,324클록 지연 |

일반 패킷 우선 일정에서는 반복 OAM을 VB45에서 이미 반환했다. VB46 시작 후에도 section 5의 마지막 패킷과 뒤의 타일 패킷 다섯 개를 수락해야 했다. 수신 최적화가 가장 효과적인 이 일정에서도 246선 마감은 다음 VBlank에서만 지켰다.

두 위상에서 908 공개·909 선행 DMA 624B·910 마지막 D2 시각을 확인했고, 정상 실행의 905–912 RGB가 978과 일치했다. 범위 초과·SEAL 세대 손상·복원 도중 STOP은 912 최종 성공 ACK를 막고 911 화면을 보존했다. 원래 패턴과 다른 4B 값으로도 360B 전부 복원됐고, ROM 패턴이 손상된 DMA 후보에서는 기존 복사 경로가 실행됐다. 64B 쓰기 단독의 정적 패킹은 예약 공간을 118B 초과했고, DMA 사전 설정과 결합하면 233B 초과했다. 실기 전달본은 발행하지 않았다. ## 후속작업

978을 유지한다. 다음 비교는 일반 패킷을 앞당겼을 때 뒤로 밀린 다섯 타일의 첫 수락과 마지막 section 5의 SPI 슬롯을 기준으로 한다. 두 슬롯 중 하나를 타일에 예약할 때와 기존 발행의 마지막 유효 credit으로 SEAL을 더 일찍 송신할 때를 분리해, 수신 단축이 실제 그룹 준비와 공개 마감까지 전달되는지 판단한다.

재현은 978·1001·1002 자료가 있는 TEMP에서 `tools/nes_oam1003.py TEMP PHASE MODE VARIANT`를 사용한다. 위상 1·2 각각 reference에 stock·dma·words·fallback, arb에 dma·words, tail에 dma와 `words --stage`를 실행한다. `reference words --joint`는 링크 ARM 실행이다. `tail words --stage --fault`로 bad_range·mid_stop·bad_seal·alt_stop을 각각 실행한 뒤 `tools/check_nes_oam1003.py TEMP analysis/oam1003-results.json`으로 검증한다.
