# MMC1010 모험도 4 무입력 실기 2회

## 실행과 표시 FPS

두 실행 모두 ROM 393,216B 검증, 60초 종료, STOP, base 복구와 메뉴 준비가 기록됐다. 사용자가 메뉴 복귀를 확인했다. 실행 오류·전송 실패·화면 abort는 두 번 모두 0이다. 종료 스냅샷의 발행/반환 카운터는 1차 17,276/17,272, 2차 16,697/16,697이다. 1차 종료 시점에 남은 네 항목은 55–60초 공개 기록의 누락 수와 별개다.

| 무입력 실행 | 1–30초 오프닝 표시 수 / FPS | 30–60초 데모 표시 수 / FPS | 55–60초 실제 공개 수 / 유효 BIN 행 |
|---|---:|---:|---:|
| MMC966 기준 | 706 / 24.34 | 746 / 24.87 | 124 / 123 |
| MMC1010 1차 | 705 / 24.31 | 739 / 24.63 | 123 / 122 |
| MMC1010 2차 | 676 / 23.31 | 719 / 23.97 | 120 / 119 |

오프닝은 첫 1초를 제외한 29초, 데모는 30초다. MMC1010 두 번의 평균은 23.81 / 24.30 FPS로 MMC966 한 번보다 0.53 / 0.57 FPS 낮다. 설치판의 상세 타일 조회가 없어지고 일반 조회가 16→32B로 바뀌었으며 같은 MMC1010에서도 결과가 달라졌다. 이 표만으로 계측 변경의 성능 비용을 추정할 수 없다.

## 화면이 공개되기까지

BIN의 세대·descriptor·token·완료 플래그·footer를 확인했다. 두 실행의 241행 모두 유효했고 버퍼 초과는 0이었다. BIN은 프레임 시작 시각, 공개 수는 공개 시각으로 구간을 나눈다. 연속된 모든 행에서 직전 공개와 이전 행의 현재 공개가 일치했다. 계측 눈금은 0.390ms다.

MMC966과 양방향으로 유일한 대응을 찾을 때 시작 시각 ±0.30초 안에서 BG·OBJ·변경 map·타일 수·묶음 수·마지막 종류·길이·offset을 모두 맞췄다. 1차 37쌍, 2차 23쌍이다. 아래는 1009에서 미리 고른 빠른 타일 공급 대조군이다. 범위는 해당 두 관측의 최솟값·최댓값이다.

| MMC966 세대 / 변경 map | 1010 세대 1차 / 2차 | 마지막 타일→SEAL 헤더 | SEAL 헤더→마지막 DMA 쓰기 | 마지막 타일→공개 | 공개 간격 |
|---|---|---:|---:|---:|---:|
| 1411 / 23 | 1403 / 1357 | 11.70–12.09ms | 9.75–10.53ms | 21.85–22.63ms | 2 VBlank |
| 1443 / 23 | 1433 / 1387 | 10.53ms | 10.92ms | 21.46–21.85ms | 2 VBlank |
| 1453 / 9 | 1444 / 1398 | 8.58–8.97ms | 14.04ms | 22.63–23.02ms | 2 VBlank |
| 1511 / 0 | 대응 없음 / 1453 | 10.92ms | 13.65ms | 24.58ms | 2 VBlank |

이 일곱 관측의 마지막 DMA→공개는 0–0.39ms, FPGA 최종 ACK→ARM 첫 유효 E0의 보수적 상한은 1.54ms 이하다. 56.36초 ROM 대조군(966 세대 1452)도 별도로 일치했다. MMC1010에서는 첫 E9→마지막 타일이 두 번 모두 3.12ms, SEAL→마지막 DMA가 14.43ms였다. 이 보드에서는 개별 ROM 허가를 기록하지 않는다.

전체 행에서 타일 공급의 상한이 2ms 미만이면서 마지막 타일→공개의 하한이 한 주기를 넘긴 화면은 1차 31장, 2차 38장이다. 1차의 93/122장과 2차의 85/119장은 공개 간격 자체가 2 VBlank였다. 반면 공개 간격 4 VBlank인 행들의 타일 공급 중앙값은 각각 40.18 / 39.79ms였다. 공급과 공개 뒤 ACK를 모든 화면에 일괄 적용하는 최적화는 이 차이를 놓친다.

## 55.45초 부근의 반복 정체

같은 BG 529·OBJ 18·변경 map 33 화면에서 최장 공개 간격이 반복됐다. 1차는 1410→1424 세대, 266.44ms(16 VBlank), 2차는 1364→1377 세대, 249.66ms(15 VBlank)였다. MMC966에서도 55.42초의 같은 BG·OBJ·map 화면에서 세대가 15 증가했다. MMC966에는 같은 공개 시각 계측이 없다.

MMC1010 두 번 모두 직전 공개→첫 E9가 각각 250.44 / 233.67ms였다. ARM의 입력 완료 표식까지로 좁히면 직전 공개 후 약 227.6–230.0 / 207.4–209.9ms다. 해당 화면의 마지막 타일→공개는 12.48 / 15.60ms였다. 입력이 없었던 시간, 캡처가 부적합해서 건너뛴 시간, D1/D2 전송을 기다린 시간은 이 BIN만으로 더 나눌 수 없다.

## 후속작업

- 큰 끊김은 같은 33행 전환을 골라 실제 캡처 유효 여부·건너뛴 세대 사유, 첫 입력 준비·D1·마지막 D2 시각을 확인한다.
- 지속 FPS는 9행과 23행의 반복 화면에서 실제 SEAL 전 마지막 패킷 반환, SEAL 뒤 첫 DMA와 남은 VBlank 시간을 확인한다. 마지막 DMA 시각 하나로 바이트 복사 시간과 VBlank 진입 대기를 분리할 수 없다.
