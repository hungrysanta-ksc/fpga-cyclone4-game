# 886 · 959의 SEAL 독립 검사와 VBlank 대기 진입

## 바꾼 경로

883 위상 1의 959는 SEAL 검사와 DMA 묶음 준비를 거쳐 226선에 `wait169`에 진입했다. 위상 2는 225선이었다. 두 경우 모두 다음 VBlank까지 기다렸다. 이때 SEAL의 타일 요구 비트맵 72단어 가운데 62단어가 0이었다.

886은 같은 144바이트를 16비트씩 전부 읽는다. 요구 단어가 0이면 다음 단어로 간다. 하나라도 요구하면 대상 뱅크의 독립 수신 비트맵을 읽고 `(~요구 | 수신) == 0xffff`를 검사한다. 빠진 비트가 하나라도 있으면 기존 오류 경로로 간다. 두 뱅크의 이력, map의 별도 coverage 검사, 길이 검사, DMA 허가와 246선 검사 코드는 그대로다. 이 변경에는 ARM 발행 조건이나 세대 번호 조건이 없다.

기존 65816 본체 안에서 루프를 6단어 단위로 바꿨다. 본체 크기는 6,380B, 물리 ROM은 5,120B다. 압축 부분은 4,079→4,074B, 물리 ROM 여유는 17→22B다. 추가 WRAM은 0B다. 독립 부팅 재생에서는 새 이미지가 9,430 마스터클록 먼저 진입했으므로, 959의 코드만 바꾼 대조와 새 이미지의 전체 부팅을 따로 측정했다.

## 두 위상의 결과

각 칸은 위상 1 / 위상 2 순서다. 959만 교체한 재생은 883과 같은 시각에 같은 SEAL을 수락했다. 검사 시작부터 업로드 진입까지 3,294 / 3,348클록(153 / 156µs)을 절약해 225선 전에 VBlank 대기에 도착했다.

| 같은 입력의 밀집 데모 | 883 공유 링크 | 959에서만 교체 | 886 정적 ROM 부팅 |
|---|---:|---:|---:|
| 959 대기 진입선 | 226 / 225 | 223 / 223 | 219 / 224 |
| 959 표시 간격 (VBlank) | 3 / 3 | 2 / 2 | 2 / 2 |
| 961 캡처 준비가 883보다 앞선 VBlank 수 | 0 / 0 | 1 / 1 | 1 / 0 |
| 밀집 60개 표시 간격 합 | 139 / 139 | 138 / 138 | 138 / 139 |
| 883 대비 마지막 65816 ACK 절감 (ms) | — | 16.596 / 16.640 | 16.645 / −0.005 |

정적 ROM에서 959의 768B 선행 map DMA는 두 위상 모두 WRAM 원본 주소, VRAM 목적 주소 24,576–25,343, PPU 포트, 순서와 값이 883과 일치했다. 위상 1은 다른 범위 16B도 선행 전송했다. 두 위상 모두 최종 DMA 허가 검사는 240선에서 통과했다. 실제 공개는 249 / 250선이었다. 246선은 최종 DMA의 허가 마감이다.

전체 부팅에서 오프닝 60간격은 883의 122 / 120에서 121 / 122로 바뀌었다. 703 공개는 두 위상 모두 VBlank 59의 231선, 759는 173 / 174회였다. 전환 48간격은 119 / 119, 빈 화면 보존은 두 위상 모두 16회다. MMC872의 밀집 141 / 141과 비교하면 정적 886의 마지막 ACK는 49.93 / 33.54ms 빨랐다. 최근 구현 대조군인 883과 비교하면 위상 2의 마지막 ACK는 106클록, ARM의 첫 유효 E0는 1,587클록 늦었다.

위상 2 밀집에서 처음 간격이 늘어난 947의 캡처선은 46,815,208클록이다. 883은 마지막 D2를 46,814,080에 끝냈고 886은 46,815,244에 끝내 36클록 늦었다. 앞선 표시의 최종 ACK는 886이 224클록 빨랐지만 ARM의 첫 유효 E0 확인은 1,165클록 늦었다. 오프닝 918에서도 D2가 캡처선을 254클록 넘었다. 다음 시험은 이 두 지점의 최종 ACK부터 E0·EA·D2까지를 같은 부팅 조건에서 비교한다. 959만 교체한 결과는 검사 자체의 효과를 분리하기 위한 진단이다. 실기 기준은 MMC872로 유지한다.

## 검증과 재현

부팅 이미지 정상·손상 시험, 기존 수신·중단·복구 12조건, 여섯 위치의 수신 비트 누락 검출, ARM 메뉴 복귀 경로를 통과했다. 세 장면에서 이전과 같은 세대의 활성 RGB와 map을 대조했고, 최종 ACK·EA·다음 COMMIT 순서를 확인했다. 새 실기판 배포나 FPS 측정은 이번 단계에 포함하지 않았다.

1. `nes_coverage886.py`로 883 공유 링크의 검증된 65816 본체에서 새 정적 ROM을 만든다. 두 이미지의 부팅·복사 검사는 `check_nes_longrun694_boot.py`로 정상 및 손상 입력을 각각 실행한다.
2. `replay_nes_coverage886.py TEMP PHASE dense --local`은 883으로 부팅해 959 SEAL에서만 WRAM 검사 루프를 교체하고 960 SEAL에서 되돌린다. 같은 입력의 전체 정적 ROM은 `--local` 없이 dense·transition·opening을 두 위상에서 실행한다. ARM·SPI 비용과 ROM 허가표는 각 대조군과 같다.
3. `guard_nes_coverage886.py TEMP`는 새 ROM의 12개 소비·중단·재시작 조건을 실행한다. 별도로 실제 SEAL에 요구 비트를 넣고 해당 뱅크의 수신 비트를 지우는 시험으로 루프의 여섯 위치, 양쪽 뱅크, 첫·마지막 단어를 포함한다. 오류 분기에 도달했는지, 이전 공개 화면이 유지됐는지 확인한다.
4. `check_nes_coverage886.py TEMP analysis/coverage886-results.json`은 RGB·map·작업량·DMA·최종 ACK 순서와 위상별 마감을 대조한다. 클록·주사선·프레임 번호는 결합 재생 값이다. [재생과 오류 주입 결과](../analysis/coverage886-results.json)
