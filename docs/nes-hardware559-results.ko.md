# MMC558 실기 비교

사용자는 두 번 모두 실행·메뉴 복귀에 성공했고 프레임 체감은 비슷했다고 보고했다. 첨부된 같은 이름의 세 로그는 한 실행의 기록이다. 비교 대상은 MMC551의 성공 실행이다.

| 표시 완료 구간 | MMC551 | MMC558 | FPS 변화 |
|---|---:|---:|---:|
| 5–40초 | 458회 · 13.09 | 478회 · 13.66 | +4.4% |
| 40–55초 | 214회 · 14.27 | 208회 · 13.87 | −2.8% |
| 5–55초 | 672회 · 13.44 | 686회 · 13.72 | +2.1% |
| 전체 60.08초 | 822회 · 13.68 | 842회 · 14.01 | +2.4% |

후반을 프레임 **시작** 시각 기준 5초 bin으로 보면 40–45초는 70→48회, 45–50초는 69→69회, 50–55초는 75→91회였다. 40–45초에는 화면당 변경 map 행이 9.20→16.75개, E1 전송량이 2,364→3,015B, 출력 비용이 약 39.14→66.46ms였다. 50–55초에는 출력 비용이 31.47→22.42ms로 줄었다. 구간별 장면과 적의 수를 기록하지 않아 같은 부하에서의 변화량은 알 수 없다. 53화면 시뮬레이션의 밀집 구간과 실기 40–55초도 서로 다른 표본이다.

전체 DWT 비용을 완료 화면당 ms로 환산하면 수신은 19.95→19.79, 계획·공급은 14.53→14.31, 출력·최종 ACK는 37.98→36.63이다. 출력에서 1.36ms가 줄었고 여전히 가장 크다. 이 DWT 수치는 전체 실행 평균이다. 5초 bin의 단계 카운터는 프레임 시작 기준의 10ms tick이다.

842개의 END·commit·EA와 21,535개의 queue 발행·retire가 일치한다. CRC 오류·실패 전송·표시 abort는 0회였고 STOP·base 복구·메뉴 준비가 완료됐다. 종료 시 BEGIN은 한 건 더 있고 native_result=1(시간 제한), receiver_error=27(D2 뒤 D0 상태·token 확인)이 기록됐다. 27만으로 D0 전송·상태·token 중 어느 검사가 종료됐는지는 구별할 수 없다. 이전 MMC551의 첫 표시 전 준비 실패와는 시점이 다르다. 시작 실패는 자연 재발 시 별도 로그로 수집한다.
