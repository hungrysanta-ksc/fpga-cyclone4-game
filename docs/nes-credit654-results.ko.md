## ARM 발행 정책 비교

- **service**는 조립·CRC를 마친 END 단독 명령을 출력 서비스가 소유할 수 있게 한다. 새 tile을 먼저 제출한 뒤 실제 큐 미반환 수가 2개 이하일 때 일반 명령 한 개를 허용한다. SEAL은 END 발행과 실제 tile 소비를 기다린다. 따라서 END 함수의 반환과 실제 E9 발행을 따로 기록했다.
- **batch**는 warm 두 번째 plan에 일곱 BG 다음의 확정된 여덟 번째 BG까지 포함한다. 다음 record가 OBJ이면 일곱 BG를 먼저 발행한다. 혼합 묶음을 임의로 재정렬하지 않는다. 955의 묶음 크기는 기존 2·7·15·1에서 2·8·15가 되어 마지막 14개 OBJ와 END가 한 번에 전송된다.
- **combined**는 위 두 변경을 결합한다. **front**는 대조용으로 첫 두 plan이 발행될 때까지 선택적인 선행 map 기회를 넘긴다. 남은 map은 같은 cursor에서 출력한다. 네 정책 모두 세대 번호를 검사해 동작을 고르는 분기가 없다.

## FPGA 교체와 전체 보드 비용

기존 0–255 원본/256–511 출력 두 페이지를 하나로 합쳤다. SPI는 0–255에서만 읽고 직접 수락한 셀은 256–511에 저장한다. 헤더를 복사하는 단계와 SPI 읽기 페이지 선택을 삭제했다. 원본 4셀 복구는 RAM에서 읽은 15비트를 기존 96비트 serializer로 모아 ordinary와 같은 쓰기 포트·CRC16으로 출력한다. 압축 출력 CRC와 독립 셀 CRC도 같은 CRC16 데이터 경로를 사용한다. 직렬 SPI의 요청 CRC8과 응답 CRC8은 각각 실제 수신·송신 비트에서 갱신한다. 길이·opcode·token·상보 인자·CRC·마지막 바이트 검사를 거친 뒤에만 D2/D3를 반영한다.

| Quartus Lite 25.1 · EP4CE15F17C8 | 653 | 654 | 한도 |
|---|---:|---:|---:|
| 전체 LE | 15,880 | 15,837 | 15,408 |
| 필요한 LAB | 1,004 | 999 | 963 |
| 조합 논리 / 전용 레지스터 | 15,039 / 8,688 | 14,866 / 8,673 | — |
| M9K / 논리적 RAM 비트 | 56 / 309,360 | 56 / 305,264 | 56 M9K |

전체 보드에서 **43 LE·5 LAB**를 회수했다. 남은 부족분은 **429 LE·36 LAB**다. Quartus Lite의 전체 컴파일은 FIT에서 중단돼 배치 후 STA와 SOF가 생성되지 않았다.

## 검사와 재현

1. `prepare_nes_credit654.py <652 ARM 빌드> <출력> service|batch|combined|front`로 실제 ARM을 생성하고 `build_nes_trial577.ps1`로 전체 링크한다.
2. `prepare_nes_serial654.py <653 최종 보드> <출력>`으로 해당 serializer를 보드 SPI 인스턴스에 연결한다. 같은 설정으로 `quartus_sh --flow compile board`를 실행한다.
3. 기존 한 좌석 FLOAT wrapper에서 `check_nes_serial654.py`를 일반·`--guards` 모드로 순차 실행한다. 901개 D1의 바이트·CRC가 653과 일치한다. 99셀 원본 복구, 짧은 D1, 오래된 D2, 준비 중 D0, 미완료 map의 E002, 원본 출력 중 STOP, 잘못된 D3 prefix·인자·상보·CRC·tail·길이를 검사한다.
4. 653과 같은 `test_nes_direct653.py --geometry650 --commit-pop-bound --keep-run`에 각 ELF와 각 실제 RTL의 `sender.json`을 공급한다. 637 client01, 시작 클록 7,288,416 / 7,467,100, ARM CPI 2·IRQ·공유 SPI 드라이버·ROM 달력과 두 staging 슬롯을 고정한다. `analyze_nes_credit654.py`로 D1 전 준비 완료, 53화면의 독립 map·영상·표시 ACK와 이전 ACK→EA→다음 COMMIT을 대조한다. 시각은 이 연결 일정의 측정이며 실제 보드 FPS는 MMC643이 기준이다.
5. 실제 ELF의 geometry·END·queue·SEAL·menu 및 base 복귀를 실행한다. END가 보류된 상태와 타일 제출 직후의 STOP, 잘못된 CRC·세대·반복 descriptor·모호한 발행 실패도 포함한다.
