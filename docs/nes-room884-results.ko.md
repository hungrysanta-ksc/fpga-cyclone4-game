# 884 · 962의 출력 큐를 기다리는 동안 963 입력 수신

실기 기준은 MMC872다. 883에서 독립 검사를 공유한 ARM 링크를 구현 대조군으로 두었다. 884는 마지막 타일 FINISH를 확인하고 팔레트·OAM·section 5의 큐 credit을 기다릴 때 준비된 다음 입력 한 블록을 수신한다. 전송 전후 STOP 확인, D1 복원과 D2 확인을 수행한다. 이전 출력의 최종 ACK·EA 이후에 다음 COMMIT을 허용한다.

## 수신 준비와 실제 발행

위상 1에서 963 캡처는 60,365,184클록에 준비됐다. 60,391,476클록의 D0에서는 962의 tile 작업이 아직 남아 있었다. 입력 패킷은 모두 소비했고 END도 받았지만 두 세대가 공유하는 타일 공급 경로는 해제 전이었다. 위상 2에서도 같은 조건을 확인했다. 작업 해제 후 ordinary credit 대기를 이용한 D0는 두 위상 모두 입력을 받았다.

| 실제 ARM·65816 결합 재생 | 위상 1 | 위상 2 |
|---|---:|---:|
| 963 첫 D1 시작, 883→884 | 60,591,135→60,471,705 | 60,947,207→60,832,355 |
| 963 두 번째 D1 시작, 883→884 | 60,602,575→60,602,484 | 60,958,647→60,963,089 |
| 962의 마지막 240B 테이블 발행, 884 | 60,567,173 | 60,927,778 |
| 962 SEAL 발행, 884 | 60,588,942 | 60,949,547 |
| 963 SEAL 수락선, 883→884 | 171·213→171·218 | 172·212→172·223 |

첫 D1은 5.561 / 5.348ms 앞당겼다. 두 번째 D1은 원래 발행 시각 부근으로 돌아왔다. ARM은 한 블록 뒤 962의 테이블과 SEAL 발행으로 복귀했다. 884의 963 업로드 진입은 각각 VBlank 172·243선과 173·248선이었고, 실제 공개는 173·249선과 174·250선이었다.

## 962의 분기만 바꾼 대조

같은 펌웨어에서 962의 새 분기만 억제했다. 최초 분기까지 완료된 SPI 거래 8,955 / 8,989건과 961의 공개 클록이 각각 일치했고, 962의 E1 패킷 바이트와 순서도 같았다. 분기를 켜면 첫 D1은 119,327 / 119,282클록(5.556 / 5.554ms) 빨라진다. 반면 962 SEAL은 13,114 / 13,115클록 늦어지고, 963 두 번째 D1은 두 위상 모두 12클록 늦어진다. 이전 최종 ACK 전에 완료된 D1은 켬·끔 모두 13개다. 첫 입력을 앞당긴 시간이 두 번째 블록과 다음 표시까지 전달되지 않은 지점이 여기다.

950은 두 위상 모두 1,472B와 64B 두 범위를 선행 DMA해 3 VBlank, 952는 2 VBlank에 표시했다. 오프닝 703은 884 위상 1 / 2에서 각각 59·249선 / 59·231선에 공개됐다. 759는 174·229선 / 174·229선이다. 전체 ARM은 212,980B로 883보다 20B 늘었고 12B 여유다. 같은 65816·보드와 ROM 허가 일정을 사용했다.

883에 비해 884의 밀집 마지막 ACK는 818 / 404클록 늦었다. 962의 분기만 끈 대조군에 비해서도 위상 1은 392클록 늦고 위상 2는 240클록 빨랐다. 두 위상의 동시 개선 조건은 미달이다. 950의 선행 DMA 1,536바이트는 883과 WRAM 주소·VRAM 주소·PPU 포트·값이 모두 일치했다. ARM STOP·retire·메뉴 경로와 65816 독립 검사·cold·부분 수신·STOP·재시작 12조건을 통과했다.

실기 기준 MMC872와 구현 대조군 883을 유지한다. 다음 시험은 962의 마지막 OBJ 반환~240B 테이블 발행 사이에 963 두 번째 D1/D2도 끝낼 여유가 있는지 같은 바이너리에서 검증한다. 첫 D1, 두 번째 D2, 962 SEAL, 963 업로드와 마지막 ACK를 함께 기록한다. 테이블과 SEAL이 밀리거나 963 공개가 그대로면 해당 변경을 실기판에서 제외한다.

## 검증과 재현

1. `prepare_nes_room884.py BASE/src PATCH`의 BASE는 883 공유 링크다. `build_nes_mmc479_arm.ps1`로 전체 ARM을 링크하고 883의 client02를 사용한다.
2. 위상 1과 2에서 `replay_nes_strip869.py TEMP PHASE WORK 884-room CLIP`으로 opening·transition을 실행한다. 밀집은 `replay_nes_room884.py TEMP PHASE WORK 884-room`을 실행한다. 동일 바이너리 대조는 태그를 `884-late962`로 바꾸고 `--late962`를 붙인다. 이 대조는 962에서 해당 credit 분기만 억제한다.
3. `guard_nes_room884.py SRC OUT`으로 ordinary credit 14조건과 기존 테이블 12조건을 검사한다. 기존 입력·retire·메뉴 가드, `test_nes_mapwait880.py --audit 884-room`의 PPU 포트 쓰기, `check_nes_strip869.py guards`의 독립 수신·STOP·cold 가드를 이어서 실행한다.
4. `check_nes_room884.py TEMP WORK analysis/room884-results.json`은 활성 RGB·map과 세대별 공개·ACK·EA·재무장·COMMIT 순서, SPI 접두부, 링크 해시와 DMA를 대조한다. [측정값과 가드 결과](../analysis/room884-results.json)

이 수치는 고정 ROM 경쟁 조건과 실제 두 CPU 바이너리를 사용한 재생 결과다. MMC872 이후의 실기 FPS는 미측정이다.
