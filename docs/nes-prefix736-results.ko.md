# NES736 · 957의 마지막 OBJ와 240B 테이블 발행

**727을 유지한다.** 두 후보 모두 957에서 scroll·패딩, 마지막 OBJ 소비 ACK, 240B 테이블 전송을 앞당겼다. 두 위상 모두 952와 957에서 1,536B map 선행 DMA 기회를 잃었고 957 최종 ACK는 늦어졌다.

## 같은 화면에서 바꾼 순서

기존 707D FPGA와 65816을 사용했다. 각 후보의 링크된 장시간판 ARM과 65816을 905–957 연속 53화면, 시작 클록 7,288,416 / 7,467,100에서 각각 실행했다. 아래 수치는 M4 CPI2·공유 SPI·IRQ·주기적 ROM 경쟁을 적용한 재생 결과다. 두 후보의 212개 화면은 727과 픽셀, 복원된 map·tile·section 5 바이트, 팔레트·OAM 명령 및 plan이 일치했다.

ARM은 두 뱅크 이력이 준비되고 재사용할 색 정보, 확정된 patch, 변경 OBJ, 하나로 이어진 잔여 map 구간이 있을 때 scroll과 패딩을 먼저 발행한다. A는 raw·240B 테이블·9B 꼬리를 보낸 다음 map을 보낸다. B는 scroll·패딩 다음에 map을 보내고 raw·테이블·꼬리를 이어 보낸다. 둘 다 기존 bulk와 credit 중재를 거친다. 실제 957에서는 scroll과 패딩 사이에 준비된 OBJ가 수락됐다. 앞당긴 순서가 실행된 세대는 두 위상 모두 948·949·951·952·957이었다. 나머지 세대는 727의 패킷 순서를 따르며 색 이력 비교와 raw 준비 시점, span·cursor 실행 비용은 바뀐다.

## 957의 소비·전송 시각

직전 화면 공개부터의 ms다. 각 셀은 위상 1 / 위상 2 순서다. 240B 테이블은 헤더를 포함해 259B이고 아래 시작 시각부터 두 위상 모두 0.839ms 동안 다른 SPI 거래와 겹치지 않았다.

| 실제 사건 | 727 | A · 테이블 다음 map | B · map 다음 테이블 |
|---|---:|---:|---:|
| scroll 소비 ACK | 35.717 / 35.486 | 25.466 / 25.530 | 25.496 / 25.536 |
| 마지막 OBJ 소비 ACK | 34.606 / 34.546 | 26.849 / 26.911 | 26.878 / 26.917 |
| 1,100B 패딩 소비 ACK | 37.246 / 37.012 | 28.380 / 28.437 | 28.406 / 28.448 |
| 테이블 SPI 시작 | 38.172 / 37.988 | 29.358 / 29.394 | 36.842 / 36.856 |
| 65816 SEAL 수락 | 40.047 / 39.811 | 38.996 / 39.007 | 39.869 / 39.906 |
| 화면 공개 | 49.795 / 49.794 | 50.523 / 65.887 | 50.530 / 50.511 |

A의 새 테이블 전송 구간에서 727은 E1 발행에 0.671 / 0.693ms, E0 조회에 각각 0.109ms를 쓰고 있었다. A는 여기에 테이블을 넣어 전송을 8.815 / 8.594ms 앞당겼지만 957의 첫 192B map 패킷도 뒤로 밀었다.

## 연속 표시와 DMA 마감

727 대비 변화량이며 양수는 지연이다. 마지막 ACK는 같은 시작 클록에서 잰 절대 완료 시각이다.

| 지표 | A 위상 1 / 2 | B 위상 1 / 2 |
|---|---:|---:|
| 951–955 평균 표시 간격 변화 | −0.005 / −0.004ms | −0.005 / +0.002ms |
| 952–957 평균 표시 간격 변화 | +0.031 / +2.591ms | +0.125 / +0.121ms |
| 957 마지막 ACK 변화 | +0.738 / +16.095ms | +0.739 / +0.724ms |
| 952–957 합계 VBlank | 18 / 19 | 18 / 18 |

956의 선행 map 1,024B와 tile 64B, 마지막 map 384B가 후속 OBJ보다 먼저 DMA되는 순서는 모두 유지됐다. 911 마감·951 공개선·952 표시 3회·7블록 수신도 통과했다. 두 후보 모두 953의 BG가 727보다 늦은 ROM 구간으로 밀렸다. A 위상 2는 957 최종 대기 0회도 잃어 3→4 VBlank가 됐다. B는 양쪽 모두 957 최종 대기 0회를 지켰다.

직전 공개를 맞춘 뒤 727의 **1,536B map DMA 시작 시각에서 해당 묶음의 마지막 map 소비 ACK를 뺀 값**이다. 음수는 그 시각에 마지막 map이 준비되지 않았음을 뜻한다.

| 세대 | 727 여유 | A 여유 | B 여유 |
|---|---:|---:|---:|
| 952 | +0.874 / +0.958ms | −8.525 / −8.530ms | −2.612 / −2.440ms |
| 957 | +1.578 / +1.419ms | −4.429 / −4.504ms | −1.261 / −1.361ms |

다음 비교는 727의 952 map 발행과 953의 첫 BG ROM 허가를 고정한다. 957은 B의 map 꼬리를 **최소 1.261 / 1.361ms** 앞당길 공급 구간을 먼저 찾는다. 마지막 map 수락 뒤 큐가 비어 DMA가 실제 시작되는 것까지 확인해야 한다. 727에서 이 DMA는 직전 표시 후 33.109 / 33.050ms에 시작해 33.701 / 33.642ms에 마지막 PPU 쓰기를 마쳤다. 이 구간과 OBJ·section 5의 수신을 겹칠 여지가 있는지 비교하되 65816의 DMA 실행 중에는 같은 CPU의 패킷 소비를 중복 계산하지 않는다.

## 자원·중단·복귀

정상판 / 장시간판 각각 두 후보 모두 전체 Flash 212,980 / 212,936B이며 한도까지 12 / 56B가 남았다. 첫 정상판 링크는 40B, span 공유 뒤에는 8B 초과했다. 기존 map 진행 마스크를 지역 cursor로 소비해 최종 링크가 통과했다. 두 후보 모두 733의 패딩 상수 238B 절감을 유지했다. 전체 Flash는 727 대비 12B 감소, 733 대비 188B 증가했다. 정적 RAM과 기존 문맥 크기는 727과 같다.

두 후보 각각 새 ARM 순서·오류 경계 13조건, 기존 credit·수락·최종 ACK·런타임·메뉴 복귀 검사, 패딩과 map cursor 동등성 검사를 통과했다. 실제 65816에서는 907과 선행 순서가 적용된 948에서 1,100B 패딩의 64B 및 1,088B 뒤 STOP을 주입했다. 8회 모두 상태 0xE4로 종료했고 쓰기는 지정된 경계까지만 진행됐다. 실패 세대는 공개되지 않았고 이전 표시의 RGB가 일치했다. 메뉴 복귀는 링크된 ARM 경로에서 확인했다. FPGA와 65816은 그대로이며 새 Quartus 합성·실기 FPS 측정·설치본은 없다.
