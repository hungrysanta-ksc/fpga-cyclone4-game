# 712 확정 map·tile 공동 공급 경계와 삭제 예산

## 목표

707D·기존694/704 ARM·기존65816을 유지한다. 확정 map의 생산→발행→수락과 tile의 계획→ROM 공급을 같은 일정에서 추적하고,951 이후 연속 표시와957 최종 ACK를 함께 줄일 교체 경계를 정한다. [계측·예산](../analysis/ready712-budget.json) · [원시 근거](../analysis/ready712-archive.json)

## 작업내용

실제 링크 ARM에 읽기 전용 계측을 추가했다. `nes_planner211.c:184`의 공통 `row549_done` 명령에서 논리행 완료를 기록하고,같은 행이 쓰는 왼쪽/오른쪽 물리행과 packet을 연결했다. 마지막 메모리 쓰기를 행 확정으로 추정하지 않았다. 발행한 map 바이트가 해당 planner 종료 전 다시 바뀌지 않는지도 검사했다. BG 완료·OBJ 계산·map 조립·producer service·검사된 queue credit·SPI·65816 수락/소비를 나눴다. plan slot/bank 경계와 실제 ROM 요청/허가/응답을 같이 기록했다.

최종 두 위상905–957,106화면의 ARM 명령 수·모든 SPI 바이트·출력 사건 시각·최종 ACK·픽셀은 원래707D 재생과 정확히 같다. 초기 관찰용106화면도 별도로 보존했다. 새 packet을 미리 주입하거나 실제 생산보다 앞선 도착을 가정하지 않았다. 초기 도구 오류3건(import·event 이름·bytes 이름 충돌)도 원시 로그로 보존했다.

범위는 실제 M4/65816 실행,공유SPI 2.625Mbps·실측 driver 비용·IRQ·4credit·2bulk와 반복 ROM 허용 달력이다. M4 CPI2/84MHz는 보수적 배분이며 게임 실행 중 NES/PSRAM 전체 RTL 공동 시뮬레이션·실기 FPS는 아니다. ROM tag가 반복될 수 있으므로 tile별 마지막 동일 tag 응답은 진단값이고,정확한 소유권은 plan index/slot/bank로 판단한다.

## 성과

**map 행은 늦게 만들어지는 것보다 늦게 발행되는 부분이 크다. 그러나 기존 대기 틈에 끼우기만 해서는 필요한 전송시간을 확보하지 못한다.** 제품 변경은 없고 속도 개선을 달성했다고 판정하지 않는다.

마지막 열은 **현재 동기 emit/flush 호출·행 완료·외부 ROM 대기·SPI 유휴의 교집합을 합친 상한**이다. 연속 구간이나 queue 허가를 보장하지 않으며,다른 생산 순서의 모든 가능성을 부정하는 값도 아니다. 동일192B map 패킷의211B E1+driver만0.692830ms여서 현재 구간에 한 개도 온전히 숨길 수 없다. 조립/검사 약0.049690ms와 tile/credit service는 별도다.

954·955의 물리 ROM 대기 합계13.84–13.99/12.90–13.07ms를 ARM 유휴로 계산하면 안 된다. 상당 부분은 기존 계산·전송과 이미 겹친다. BG 완료→END의 SPI 빈 시간3.293/3.310ms도 ARM이 OBJ를 계산하는 시간이다. 여기에 동기 SPI를 넣으면 그만큼 OBJ 생산이 늦어질 수 있다. 순수 `map527` 제어 비용은 packet 자식 호출을 제외하면952/954/955/957 각각0.019310/0.036333/0.035357/0.015714ms다. 제어 함수 통합만으로 수 ms를 얻는다는 근거는 없다.

### 확정한 교체 범위와 자원 상한

현재 한 개 `map_next`는 왼쪽 물리 페이지를 먼저 순회하고 오른쪽 페이지를 뒤로 미룬다. planner의 조기 callback도 왼쪽 dirty 행과3행 간격에 묶여 있다. 검토할 구조는 **논리행 완료 frontier와 두 페이지 cursor가 확정된 행을 고르고,기존 plan 공급·map 허가·최종 quiet callback을 한 실행 경로로 대체하는 것**이다. 기존 배열을 참조하며 새 packet buffer·입력 재읽기·새 ABI를 만들지 않는다.

| 삭제/교체 조사 경계 | 현재 링크 크기(B) |
|---|---:|
| `map527` | 364 |
| `nes_sink527_early` | 104 |
| `nes_plan527_map_credit` | 70 |
| `offer527` / `quiet528` | 16 / 56 |
| `drive554` / `nes_plan200_progress` | 236 / 262 |

이 합계는 통째로 회수할 여유가 아니다. 새 실행기도 이 기능을 제공해야 한다. **현재 입증한 순삭제는0B**다. 정상판 Flash 여유8B를 포함한 새 경계 상한은1,116B,우선 목표는1,108B 이하로 확정한다. long 여유52B만 보고 정상판 한도를 넘기지 않는다. 추가RAM은 frontier/cursor/정렬 포함4B 이하를 조사 상한으로 두며 전체 링크·stack으로 입증해야 한다.

`poll`의 CRC/identity/counter 검사,실제 `bulk_until` 소비 완료,`flush`의 plan CRC,packet 검증·STOP,SEAL coverage·최종 표시 ACK·EA는 삭제 예산에서 제외한다. E9 발행 허가와 이미 소유한 tile을 먼저 처리하고,queue 한 칸 예약을 보존한다. 저장 credit와 최종 ACK는 합치지 않는다. cold/STOP/부분 전송은 frontier·이력을 무효화하고 전체 복구해야 한다. 기존 boot용 blocking SPI DMA를 새 비동기 NES 전송기로 공짜 재사용한다고 가정하지 않는다.

FPGA·65816 변경 예산은 우선0이다. 선택707D의 전체 FIT는15,322LE·962LAB·56M9K,여유86LE/1LAB/0M9K다. setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다.65816 물리ROM 여유는26B다(코드 body 상한의380B와 다름). 타깃이 같으므로 새 합성/FIT/STA는 실행하지 않았다. 전체 외부IO sign-off는 여전히 미완료다.

## 후속작업

1. **기존 대기 삽입 단독 후보는 예산 미달로 보류한다.** 다음 제한 구현은 위 공동 경계 안에서 행 완료와 두 페이지 발행을 연결하되,957의576B 이상을 실제로 앞당긴 비용과 tile 생산 지연을 함께 측정한다. 필요한 실제 여유가 없으면 즉시 기각한다. 해소하지 못한 부족분을 조건부 성공으로 넘기지 않는다.
2. 954/955는 map 전송을 먼저 끼우기 전에 BG 생산 자체가 이전 ROM 창에 들어갈 수 있어야 한다. 각1.624/0.347ms 이상의 생산 선행에 E8/E9·decode·ROM 허가 비용을 더해 예산을 지급한다. 단순 마지막 flush·첫 pair 크기·고정 위상 조정은 반복하지 않는다. 이 예산을 현 경계에서 만들 수 없으면 입력 복원→BG 계산의 준비 순서까지 재설계하며,이를 이미 확정한 절감으로 계산하지 않는다.
3. 실제 ARM 전체 링크와 동일 두 위상 연속 재생에서 새로운 발행·D1/D2·SPI·IRQ·2bulk·ROM 경쟁을 다시 지급한다.951–955 평균과957 마지막ACK가 모두 줄고 **952–957 합계18VBlank도 감소**해야 채택한다.911/951/952/957·7블록·STOP·독립검사·cold 복구·메뉴 경계를 모두 유지한다. 시작 시각만 한 번 이동하는 효과는 지속 개선으로 인정하지 않는다.

707D·기존ARM/65816이 계속 선택본이다. 이번에는 새 설치본을 만들지 않는다. 다음 실기본은60초/장시간·새 파일명·RESTORE 제외,5–40초/40–55초 집계 정책을 유지한다.
