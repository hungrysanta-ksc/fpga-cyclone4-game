# NES H0: 지금 시작할 수 있는 SNES 화면 경로 실기 시험

이 묶음은 자체 제작 SNES 진단 ROM 3개다. 기존025 Mesen 검증본의 바이트를 그대로 사용했다.
NES FPGA/게임 실행 시험이 아니며, 새 펌웨어나 FPGA 이미지를 설치하지 않는다.
대상은 NTSC SNES와 현재 정상 사용하는 FXPAK/sd2snes의 일반 SNES ROM 실행 경로다.
H0 결과를 받은 뒤 실제 보드 차이를 다음 연결 작업에 반영한다.

## 준비와 실행
1. PC에서 압축을 새 폴더에 풀고 PowerShell로 ./Verify-Package.ps1 을 실행해 PASS를 확인한다.
   압축 파일 자체의 SHA-256은 개발 결과 보고의 기록과 비교한다.
2. 콘솔 전원을 끈 상태에서 SD에 NES-H0-029 라는 새 ROM 폴더를 만들고 .sfc 3개만 복사한다.
   기존 sd2snes 시스템 폴더, 펌웨어와 세이브는 교체하지 않는다.
3. SD를 넣고 기존 메뉴에서 nes-h0-top.sfc 를 일반 SNES 게임처럼 실행한다.
   초기 4프레임 전송 뒤 고정된 무늬 화면이 남는 것이 정상이다. 애니메이션·소리·버튼 반응·PASS 글자는 없다.
   약 30초 동안 화면이 안정적인지 보고 expected-top.png 와 무늬를 비교한다.
4. 평소 사용하는 RESET/메뉴 복귀 방법으로 돌아온다. 같은 ROM을 다시 실행해 warm 시작도 확인한다.
   이후 bottom, fine_x도 같은 방식으로 각 1회 확인한다. 각 ROM의 대응 PNG가 비교 기준이다.
5. results.tsv에 결과를 적는다. 콘솔 모델/지역, 카트리지 리비전, 현재 설치 버전,
   TV 또는 캡처 연결, 화면 사진과 메뉴 복귀 결과를 함께 기록한다.
   검은 화면·깨짐·정지 시 ROM 이름과 cold/warm 여부를 기록하고 추가 반복을 중단한다.
   평소 복귀가 안 되면 이 ROM은 저장을 하지 않으므로 전원을 끄고 시험 ROM 폴더를 제거해 원래 실행 경로로 돌아갈 수 있다.

## 관찰 범위
최종 화면은 의도적인 합성 패턴이다. TV 색감과 확대 필터는 PNG와 다를 수 있다.
top과 bottom은 240줄 원본의 서로 다른239줄 진단 viewport다. 제품의 자르기 정책 승인이 아니다.
네 번의 갱신은 매우 빨라 육안으로 각각 판별하기 어렵다. 마지막 화면만 같아도 중간 DMA와 모든 frame deadline이 입증되는 것은 아니다.
음향·입력·NES CPU/APU·실제 패킷 생산자·FPGA CDC·외부 메모리는 이번 실기 시험 대상이 아니다.
H0 통과 뒤에도 전체 NES 실기 성공으로 표시하지 않는다.

## 다음 실기 후보 H1
원본 자체 패턴 생산기 → 큐/CDC/준비 버퍼 → 실제 SNES 주소 디코더/데이터 버스 → PPU DMA 경로를 연결한다.
동일 후보의 핀·클록·리셋·IO 제약과 fit/STA, 데이터 버스 구동 방향/경합,
DMA 연속 주소와 read-strobe 중복 방지를 검사하고 loader 및 복귀 경로를 준비한다.
별도 설치 묶음에는 정확한 파일명/해시/기준판 백업·복원 절차와 눈으로 읽을 수 있는 sequence/error 표시를 넣는다.
이 조건이 충족되면 전체 SMB3나 DMC 정확도 완료를 기다리지 않고 H1 진단 실기에 들어간다.
H1은 현재 준비 중이며 이 묶음에는 FPGA 비트스트림이 없다.
