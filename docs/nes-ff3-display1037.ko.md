# FF3 ROM 선택·가변 CHR 표시·저장 복원

SD 메뉴에서 선택한 파일의 전체 경로를 다시 열어 헤더, 길이, 내용 CRC를 검사한다. 대소문자가 다른 확장자와 다른 폴더의 파일을 포함해 실제 ARM 최종 링크로 8가지 경우를 시험했다. FF3는 512 KiB PRG와 8 KiB CHR RAM을 가진 수평 미러링 MMC3 프로필이다. Kirby는 독립된 CHR ROM 프로필을 사용한다. 프로필의 나머지 조건은 [브라우저 계약](nes-browser1036.ko.md)에 있다.

## CHR 쓰기와 화면 세대

PPU는 보드 내부의 8 KiB CHR RAM을 읽고 쓴다. 스냅샷 회로는 카트리지 SRAM 상단 8 KiB에 안정된 사본을 만들고 화면 세대가 소유하는 동안 이를 보존한다. 수집 중 화면의 패턴이 바뀌면 해당 캡처를 폐기한다. 타일 공급기는 수락한 세대의 주소와 응답을 검사한다. ARM은 CHR RAM 프로필에서 다음 세대가 같은 타일 번호를 사용할 때 대상 뱅크에 다시 올린다.

첨부 ROM에서 주소가 같은 타일의 변경 전후 패턴을 추출했다. Questa에서 실제 타일 공급기와 외부 SRAM 모델을 연결한 시험은 프레임 9의 1번 타일에 대해 이전 세대와 다음 세대의 BG 및 OBJ 바이트 순서가 각각 일치했다. 보유 중 쓰기, 잘못된 세대 반납, STOP, cold 재수집도 시험했다. 실제 TV의 SNES 픽셀과 SRAM 핀 타이밍은 배치와 실기 확인이 필요하다.

## 저장 경로

- 일반 세이브는 ROM 내용과 크기로 식별한 배터리 RAM 8,192 B를 사용한다. 시작 시 배터리 파일 읽기와 바이트별 기록·재읽기가 끝날 때까지 CPU를 리셋 상태로 유지한다. 파일이 없으면 초기 상태로 시작하고 손상된 사본만 남아 있으면 기존 오류 복귀 경로를 탄다.
- 상태 슬롯 1–4에는 헤더를 포함한 2,658개의 64비트 워드를 보관한다. ARM은 정지·배출 확인 후에만 전송하며 CRC, 반환 인덱스, 마지막 완료 응답을 확인한다. 파일을 저장할 때는 번갈아 사용하는 두 사본 중 새 사본을 동기화하고 다시 읽어서 확인한다. 저장·복원 도중 STOP하면 미완료 워드와 쓰기 요청이 다음 실행으로 넘어가지 않아야 한다.
- 개발 중 첫 명령값 `0xA6`은 기존 보드의 `0xA0–0xBF` 이력 조회 범위와 겹쳤다. 두 장치가 함께 선택되면 보드 최상위 회로는 MISO를 해제한다. ARM과 코어의 저장 명령을 `0x59`로 옮겼다. SPI 시험은 기존 이력 조회 회로도 함께 인스턴스화해 두 선택선과 실제 응답 CRC를 확인한다.
- 호스트 시험은 실제 파일 처리 및 ARM 전송 코드를 독립 SPI 상대와 실행했다. 게임·슬롯 격리, 재실행, 이전 사본 복구, CRC나 워드 순서가 잘못된 응답 차단을 확인했다. 이 시험은 실물 SD·패드 입력을 포함하지 않는다.

첨부 FF3를 실행한 혼합언어 RTL 시험에서는 한 프레임에 서로 다른 색이 3개 나타날 때까지 기다린 뒤 정지했다. 시험용 비균일 배터리 데이터 8,192 B를 기록·확인하고 코어 상태를 저장했다. 콜드 초기화 후 복원한 첫 64개 CPU 명령 경계의 주소·데이터와 이어지는 두 화면의 PPU 픽셀 122,880개가 저장 지점에서 그대로 진행한 대조 실행과 일치했다. 저장·불러오기 각각에서 워드 응답을 보류한 채 STOP한 경우에도 재시작 후 잔여 쓰기가 발생하지 않았다. 이 결과는 시험한 3색 장면에 한정되며 플레이 중 고른 부하 장면과 SNES 최종 출력은 별도로 확인해야 한다. 원시 결과는 작업 루트의 `probes/nes-ff3-checkpoint/vsim-checkpoint.log`에 있다.

## 후속 순서

1. 정지 중에만 쓰는 상태 저장 주소·워드 조립을 ARM 및 기존 포트로 옮길 수 있는지 비교한다. 합성에서 상태 순회기는 조합 논리 603개, SPI 저장 장치는 337개였다. 둘의 합은 장치 전체 비용이며 대체 회로도 예산에 포함한다. 기존 CPU·PPU 상태, 독립 검사, STOP 시험에 같은 입력을 사용한다.
2. GBC에서 쓰는 L+R+START 조작으로 NES를 정지하고, 일반 세이브와 슬롯 저장·불러오기를 선택하는 65816 메뉴를 연결한다. 상태 불러오기 직후 ARM과 SNES의 표시 이력을 무효화하고, 첫 완전한 화면을 수락한 뒤 입력을 재개한다. 실제 펌웨어를 다시 링크해 Flash, 스택과 메뉴 공간을 검증한다.
3. 전체 FIT·STA, 부팅, 일반 저장과 재실행, 강제 저장 후 종료·재선택·같은 장면 복원, 전송 중 STOP 및 base 메뉴 복귀를 순서대로 확인한다. 이 결과로 실기 설치본을 판정한다.
