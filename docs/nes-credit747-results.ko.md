# 747 · 마지막 map의 실제 credit 반환과 OBJ 발행

## 707D에서 읽을 수 있는 신호

727과 같은 707D 보드의 SPI endpoint는 SNES의 ACK 공개 뒤 map 헤더와 identity를 비교한다. 독립 검사가 끝난 호스트 클록 에지에서만 retired가 증가한다. E0 명령 바이트의 마지막 상승 에지를 동기화할 때 accepted·retired·ACK를 한꺼번에 잡고, 그 snapshot의 CRC8을 보낸다. 반환과 snapshot이 같은 클록이면 응답에는 이전 값이 들어간다. 보드의 MCU_RDY는 external_memory_ready에 연결되고 SNES_IRQ는 0에 연결된다. ARM의 100Hz SysTick도 map 반환을 알리는 인터럽트로 쓸 수 없다.

Questa Starter에서 84MHz 호스트와 2.625MHz SPI로 두 시작 위상에 41개씩 ACK 쓰기 시각을 바꿨다. 각 위상에서 현재 E0가 새 반환을 본 경우는 19개, 다음 E0에서 처음 본 경우는 22개였다. ACK 공개부터 검사 완료까지 18클록(214.272ns)이었다. 전체 응답 CRC와 반환 identity를 검증했다. 최초 벤치 생성은 중복 문자열 치환으로 중단됐고, 첫 실행의 좁은 지연 범위는 한 위상에서 이전 값만 관측했다. 표에는 범위를 넓힌 최종 실행을 사용한다.

## ARM 재조회와 독립 검사

마지막 map 뒤 48B BG 소유권이 반환되고 E8에서 준비된 OBJ descriptor를 확인하면, 별도 ARM 실험 코드가 기존 E0 경로에서 반환을 기다린다. 비교한 두 방법은 STOP 검사 직후 재조회하는 방법과, 직전 E0 교환·검사에 든 DWT 시간을 기준으로 대기한 뒤 조회하는 방법이다. 후자는 최대 21,504 ARM 클록으로 제한했다. 두 방법 모두 기존 poll 상한과 STOP guard를 거친다. credit을 사용할 때는 응답의 CRC8, 누적 카운터, 마지막 map identity·서명을 확인한다. reason 4 입력 서비스는 큐를 실제로 비운 뒤 수행하고 OBJ 발행에는 별도의 E1 CRC16을 쓴다.

마지막 계산 비용을 분리하려고 accepted와 retired가 같은 응답에서 CRC8 다항식 0x07을 조회표 없이 계산하는 후보도 실행했다. 같은 카운터 값은 계산 방식만 선택한다. 헤더부터 ACK 서명까지 18B 전체를 검사한다. Thumb 계산의 CRC 상태·다음 바이트 조합 65,536개를 원본 다항식과 대조했다. 각 링크 ARM의 마지막 응답에서 보호 비트 152개를 하나씩 뒤집은 시험은 전부 실패로 처리됐고 credit은 반환되지 않았다.

마지막 후보는 map credit을 완전히 확인한 뒤 OBJ와 준비된 OAM을 연속 발행한다. 그때 미룬 reason 4 입력 조회 한 번은 OAM의 실제 반환과 identity를 검증한 뒤 원래 콜백에서 수행한다. 검사 실패·STOP으로 송신을 중단하면 정상 완료를 공개하지 않는다. 이 경로의 실행 자료에는 OAM 뒤 재조회와 추가 입력 확인 시간도 포함한다.

## 952–957 연속 표시와 957 최종 ACK

밀집 간격은 951 공개부터 957 공개까지 걸린 시간을 여섯 표시 간격으로 나눈 값이다. 시각 변화는 동일 시작 위상의 727과 비교했다. OBJ 시작은 65816이 957의 288B 중 첫 64B에 대해 MDMAEN을 쓴 위치다.

727 부팅·발행 시각을 고정했을 때 마지막 map 반환부터 OBJ 발행까지 위상 1은 43,599→6,563클록, 위상 2는 37,497→5,815클록이었다. E0 재조회와 CRC만 바꾸면 위상 2의 DMA 시작은 258선 H496에 머물렀다. 반환 확인 뒤 입력 조회를 미루면 OBJ와 OAM이 먼저 큐에 들어간다. 실제 OAM 반환 identity를 확인하고 빈 큐에서 D0를 발행한 뒤에도 957 최종 ACK는 두 위상에서 각각 154·178클록 앞당겨졌다. 전체 VBlank 하나를 줄인 결과는 아니다.

전체 링크에서는 첫 SNES 패킷 조회와 부팅 ROM 시각이 같았지만 905의 첫 map부터 62클록 늦었고, 521개 map 발행 시각이 모두 달라졌다. 위상 1에서 951 공개가 384클록 빨라진 데 비해 957 공개는 154클록 빨라져, 여섯 간격 합계가 230클록 늘었다. 위상 2에서는 951이 112클록 늦고 957이 500클록 빨라졌다. 두 위상 모두 952·957 map 1,536B, 908·911 표시 2회, 951 공개 236선, 952 표시 3회, 957 최종 대기 0회를 확인했다. 기준 53화면의 RGB·map WRAM/VRAM과 packet 작업량도 일치했다.

최종 후보의 STOP 직전·64B 전송 중 취소는 각각 OBJ 전송 0B·64B에서 956 표시를 보존했다. 준비된 새 패킷을 넣으면 section 5를 먼저 처리한 뒤 OBJ를 전송했고 오래된 OAM identity는 거부했다. 메뉴·base 복구 다섯 경로는 실제 ARM 함수에서 확인했다. 실기 실행은 이번 측정에 포함되지 않았다.

## 측정 범위와 자원

고정 시각 시험은 727 ARM과 694 ROM으로 부팅하고 957의 마지막 map 뒤부터 실제 Thumb와 WRAM의 65816 코드를 실행한다. 일반 C 전체 링크는 부팅부터 분기와 메모리 접근 비용을 모두 지불한다. 고정 시각 시험의 대기 기준은 E0 검사 진입부터 대기 루틴의 첫 STOP 검사 직전까지, C 링크의 기준은 status 함수 반환까지다. 두 구현의 차이는 표에 따로 표시한다.

장시간판 / 60초판 ARM 크기는 재조회 변경이 213,200 / 213,244B, CRC 변경을 합치면 213,276 / 213,320B다. 212,992B 한도를 각각 208 / 252B, 284 / 328B 넘는다. 입력 조회까지 옮긴 최종 후보는 213,360 / 213,404B로 368 / 412B 초과했다. 이전 746 대비 정적 RAM 증가는 없으며 측정용 stamp는 실행 중인 OAM 작업의 스택에 둔다. 65816 재생에 쓴 745 본체는 같은 부팅 prefix로 저장할 경우 여전히 ROM 279B를 초과한다. FPGA 제품 RTL은 변경하지 않았다.

ARM·65816 연속 시험은 실제 명령과 53화면의 동일 작업량·RGB·map WRAM/VRAM을 확인하며 SPI 드라이버 비용·IRQ·ROM 경쟁은 기존 달력을 사용한다. 이 모델은 E0의 시작 시각으로 snapshot을 잡는다. RTL 시험은 명령 바이트 끝의 핀 동작을 별도로 확인한다. 실기의 SPI 첫 에지까지 걸린 시간이나 게임 FPS는 이번에 측정하지 않았다.

## 재현

1. `tools/check_nes_credit747_rtl.py`를 기존 Starter FLOAT 래퍼에서 707D 보드 소스로 실행한다. 공개 시각·검사 완료·snapshot·반환값의 82개 원시 행은 검증 JSON에 있다.
2. `tools/build_nes_oam746_probe.ps1`과 `tools/build_nes_credit747_probe.ps1`로 고정 prefix 시험용 ELF를 만든다. `tools/prepare_nes_credit747.py`로 727 장시간판·60초판 패치를 만들고, CRC 변경을 합치는 경우 `--fold`, OBJ·OAM 뒤 입력을 확인하는 경우 `--debt`를 지정한다. 고정 시각의 후자에는 probe 빌드의 `-Debt`도 실행한다. `tools/build_nes_mmc479_arm.ps1`로 각 펌웨어를 전체 링크한다.
3. `tools/run_nes_credit747.ps1`로 각 후보의 위상 1·2를 실행한다. 이전 ROM 경쟁 달력과 사용자 보유 MMC3 ROM이 필요하다. `tools/check_nes_credit747.py`는 링크별 반환·CRC·STOP을 검사한다. `tools/check_nes_fold747.py`는 실제 Thumb CRC를 전수 대조한다. 메뉴·오류 복귀는 기존 menu533, deadline719, bg745 경로에서 확인한다.
4. 해당 실행의 65816 trace로 STOP·오래된 OAM identity 및 OBJ 시작 경계의 새 패킷을 재생한다. [비교 코드](../tools/analyze_nes_credit747.py) · [검증 JSON](../analysis/credit747-verification.json)
