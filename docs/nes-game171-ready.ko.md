# NES171 실기 — 그래픽 읽기와 전송 대기 분리

170은13회 표시 뒤 다음 화면의 그래픽 데이터 수집 제한에 걸려 화면이 멈췄다.171은 FPGA 내부에256바이트 데이터와 타일 정보를 담는 FIFO를 추가한다. 화면 공백 구간에 허용된 읽기를 먼저 진행하고 MCU가 준비되면 순서대로 전송한다. 코어의 메모리 우선권, 응답 제한, 전체 수집 제한, 사운드·입력·60초 종료는 유지한다. **연속 화면 개선의 실기 확인은 아직 필요하다.**

1. ZIP의 `01-GAME171-SD-ROOT` 안 내용을 SD 루트에 적용한다. 기존170과 새171의 펌웨어/FPGA를 섞지 않는다. ROM과164 복원 파일은 이전 패키지와 동일하다.
2. 메뉴에서 `NES GAME 171.nh1`을 실행한다. 초기 ROM 적재·검증은 기존과 같아 약4분이 걸릴 수 있다. 이번 변경은 게임 화면 갱신 경로이며 초기 적재 시간 단축은 아니다.
3. 화면이 나오면 스타트로 선택 화면→맵에 진입하고 첫 레벨에서 이동·점프한다. 이번에는 **몇 장 뒤 정지하던 화면이 계속 갱신되는지와 음악 유지**를 우선 확인한다. 실행은 기존처럼 약60초 후 끝난다.
4. `nes-progress-171.txt`, `nes-game-last-171.txt`와 화면·사운드·메뉴 복귀 결과를 전달한다. 가능하면 첫 화면부터20~30초 영상을 찍는다. 화면이 아예 없거나170과 똑같이 멈추면 두 TXT와 증상 설명만으로 충분하다.

총6분을 넘겨도 복귀하지 않으면 더 기다리지 말고 전원을 끈 뒤 남은 TXT를 복사한다. 이는 관찰 종료 기준이며 펌웨어의 강제 복귀 보장이 아니다. 복원이 필요하면 `02-RESTORE164-SD-ROOT`를 사용한다. 동일044/GBC 복원 시험을 반복할 필요는 없다.

로그의 `native_frames`는 SNES 표시 완료 ACK 횟수다. `trace_first_abort_reason`/`trace_last_abort_reason`52는 이전의 전체 수집 시간 초과다. 결과가 개선돼도 이 카운터만으로60fps나 입력 유지 품질을 확정하지 않는다. CRT 촬영 색 차이·대각선 띠는 판단에서 제외한다.
