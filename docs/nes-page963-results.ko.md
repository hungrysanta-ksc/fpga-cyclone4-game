# 963 · 입력에서 찾은 OBJ 묶음의 선행 읽기

Flash·STA 수정과 실제 E8 응답 재생 결과는 [964 검증](nes-mail964-results.ko.md)에 기록했다.

## 목표

962의 세대 909에서 직전 ROM 허가를 활용하되, 세대 912에서도 SEAL 전 496B DMA와 911 공개 전 입력 17블록을 유지한다. 실기 기준은 MMC955이고, 963의 표시 시간은 세대 905–912의 연속 재생 값이다.

## 작업내용

MMC955 ARM의 입력 COMMIT 뒤, planner 진입 시 복원된 CHR 디렉터리와 OBJ 조각에서 행 마스크가 모두 찬 8개 태그를 찾았다. 화면 슬롯 할당은 기존 planner가 맡는다. ARM은 기존 SRAM 송신 함수로 세대·시작 태그·CRC8·종료 표식을 담은 7B EB 명령을 보낸다. 두 위상 모두 907에서 3136, 909에서 3072를 발행했다. 909 전송 완료와 직전 구간의 마지막 ROM 허가는 각각 13,841,110→13,933,212와 14,197,428→14,290,572 마스터클록이었다. 재생에는 같은 길이 EA의 SPI 드라이버 부대 비용도 반영했다.

보드에서 기존 EA 수신 필드를 공유하고 26비트 메일박스로 NES 클록에 전달했다. 빈 캡처에서만 유휴 포트로 지정한 8개 타일을 읽고, 같은 16타일 페이지의 나머지 8개를 이어 읽는다. 기존 태그 RAM과 실제 물리 응답 쓰기 포트를 재사용했다. plan·일반 요청에 우선권을 주고 STOP에서 취소한다. 정상 표시 경로는 기존 독립 검사를 거친다.

## 성과

| 빈 캐시, 같은 링크 ARM | 909에서 선행 공급한 행 | 밀집 여섯 간격 합 (위상 1 / 2) | 912 직전 VBlank DMA | 912 최종 ACK, 마스터클록 (위상 1 / 2) |
|---|---:|---:|---:|---:|
| EB 송신, 공급 끔 | 0 | 14 / 14 | 496B / 496B | 17,129,766 / 17,486,866 |
| 지정한 8타일 | 64 | 13 / 13 | 176B / 176B | 16,776,082 / 17,133,582 |
| 인접 묶음까지 16타일 | 128 | 13 / 13 | 496B / 496B | 16,772,126 / 17,129,674 |

8타일만 읽으면 912에서 태그 3084의 첫 행이 ROM 허가를 79,220·79,068클록 기다린다. 16타일 조건에서는 이 읽기가 캐시에서 해결된다. 288B OBJ의 65816 수락이 256·255선에서 양쪽 모두 212선으로, 뒤따르는 32B도 다음 프레임 14·13선에서 직전 프레임 233선으로 이동했다. 같은 ARM의 공급 끔 대비 912 최종 ACK는 **16.652·16.631ms** 빨랐다. 기존 캐시에서는 두 설정 모두 13회이며 최종 ACK 시각도 같았다. 기존 961 ARM과 비교하면 기존 캐시 위상 2에서 4.3µs 늦었다.

각 경우에 RGB 8장, map·팔레트·section 5·tile 작업량, VBlank 내 출력과 최종 ACK를 대조했다. 두 위상에서 908 SEAL의 identity 손상과 STOP을 주입해 907의 화면이 유지됨을 확인했다. 링크 ARM의 메뉴 준비·해제와 base 복구도 I/O 모형에서 통과했다. 단일 Questa 시험에서는 실제 EB 바이트를 SPI 핀에 보내 CRC 오류·부분 전송·다른 세대의 거절, CDC 전달, 실제 128개 행 주소, 두 색면의 재읽기, ROM 허가 대기, plan 우선, STOP 뒤 다른 ROM 데이터를 확인했다. 연속 재생의 ROM 허가·E8 응답은 모델 값이며 새 RTL의 전 세대 E8을 ARM에 되먹이는 비교는 남았다.

## 후속작업

1. 기존 클록 간 전달 및 리셋 해제 회로를 재사용하거나, 수신 측에서 문맥을 먼저 등록해 행 순회와 분리한다. 비동기 STOP 직후의 요청 차단, 양 클록 해제 순서, 세대 재사용을 확인한 뒤 전체 STA를 다시 비교한다.
2. 입력 검사 중 이미 순회하는 OBJ 태그·행 마스크를 재사용해 ARM의 별도 탐색을 줄인다. 페이지 경계를 건너는 불연속 태그, 부분 마스크, 빈 캡처도 포함해 검사한다. 전체 링크에서 최소 240B를 회수하고 동일 바이너리로 시간 이득을 재검증한다.
3. 실제 ROM 포트에서 발생한 세대별 E8을 ARM에 되먹여 기존·빈 캐시의 두 위상을 검증한다. 회로·Flash·표시 조건을 함께 통과한 뒤 MMC955와 1–30초·30–60초 실기를 비교한다.

재현 순서는 `nes_page963.py prepare`, 기존 `build_nes_trial577.ps1`로 `nes-page963/link` 빌드, `nes_board963.py TEMP --fit`, `nes_page963.py replay --temp TEMP --phase P`이다. 재생 시 공급 끔·지정 8타일·인접 포함은 각각 기본값·`--enabled`·`--neighbor`로 선택한다. 기존 캐시는 `--cache warm`을 더한다. FLOAT 래퍼로 `check_nes_page963.ps1`을 실행한다. 각 위상의 오류 주입은 `nes_tail961.guards(TEMP,P,'963bnes-page963both')`, base 복구는 `check_nes_transfer512_recovery.py --arm ../probes/nes-page963/link/src --trial 955 --fault none --out ../probes/nes-page963/proof/base`를 사용한다.
