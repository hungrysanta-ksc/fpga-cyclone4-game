# NES169 실기 — 큰 화면 변경 후 플레이 지속 확인

168은8번째 화면 갱신에서 전송 예산 초과(E3)로 종료됐다.169는 큰 변경을 SNES의 비표시 영상 메모리에 나누어 준비한 뒤 화면을 전환한다. 작은 변경은 기존 방식이다. **이번 목표는 첫 화면 이후 종료가 없어지고 게임 진행이 이어지는지 확인하는 것이다.60fps 개선 완료판은 아니다.**

## 적용·실행

1. 전원을 끄고 ZIP의 `01-GAME169-SD-ROOT` 안 내용을 SD 루트에 복사한다. `sd2snes/firmware.stm`, `fpga_n169.bi3`, `sd2snes/nes/game169.nes`와0바이트 표식 `NES GAME 169.nh1`이 함께 있어야 한다.
2. 정상 메뉴에서 `NES GAME 169.nh1`을 실행한다. 기존 적재·비교 경로는 동일하다.168 진행 로그 기준 초기 준비는 약3분52초였으며 펌웨어 tick이므로 실제 대기시간과 다를 수 있다.
3. 화면이 나오면 스타트로 플레이어 선택→스타트로 월드맵→A로 첫 레벨에 진입해 이동·점프·사운드를 확인한다. 가능하면 첫 화면부터 메뉴 복귀까지 촬영한다.
4. 화면이 검게 꺼지는지, 이전·새 화면이 섞이는지, 잠시 멈춰 보이더라도 플레이가 계속되는지를 알려준다. 큰 변경의 준비 중에는 이전 화면을 잠깐 유지할 수 있다.
5. 기존 약60초 시험 제한 뒤 메뉴로 복귀해야 한다. 화면이 나온 뒤2분 이상 메뉴 복귀가 없으면 더 오래 기다리지 말고 전원을 끈 뒤 로그를 전달한다.

## 전달 자료

- SD의 `nes-progress-169.txt`, `nes-game-last-169.txt`.
- 화면·사운드·조작·메뉴 복귀 결과. 영상이 있으면 함께 전달한다.
- 이전과 같은 즉시 종료라면 마지막 오류 응답은 기존 `sink_trace_*` 필드에 남는다. 같은 상황을 여러 번 반복할 필요는 없다.

RUN 도중 SD 로그는 쓰지 않는다. 정상 종료나 오류 정지 후 TXT를 저장한다. 본체 리셋으로 로그를 보장하는 장기 실행 모드는 아직 구현하지 않았다. 기존 `02-RESTORE164-SD-ROOT`를 포함했지만 반복 복원 시험은 요청하지 않는다. 세이브 SRAM·GBC·164 복원 파일은 보존한다.
