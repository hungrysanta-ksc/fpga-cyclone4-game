# 685: 마지막 map384B 선행 DMA와 다음 입력 마감

685는 수락된 map1536B를 VBlank 잔여 시간 안에서 한 번에 끝내957의 마지막384B를 선행 DMA했다. SEAL 뒤 중복 E0도 줄여 두 위상 모두 밀집 평균−0.038571/−0.049764ms,957 마지막ACK−0.183357/−0.396326ms로 MMC666보다 빨라졌다. 952 표시3회·957 최종대기0회와 보호조건은 유지했지만 위상2의7번째 입력 검사 완료가955 ACK보다0.081864ms 늦어 전체 채택은 보류한다. 실기 기준은MMC666이다.

## 실제 교체 경계

684의 BG 완료 map 발행과1024→1216→BG48B 순서를 유지했다. 기존65816의1152B 부분 DMA 뒤 남던384B는 다음 OBJ 수락으로 빈 큐 기회를 잃었다. fresh beam이248선 이내이며 이미 독립 수락된 선택 범위 전체가1536B 이하면 한 DMA로 끝낸다.249–252선이거나 범위가 더 크면 기존1152B 한도를 유지한다. 전체 범위만 확대하므로 부분 retire 계산은 그대로1152B다. tile 선택과246번 표시 검사선은 바꾸지 않는다.

MDMAEN 직전에 STOP·새 패킷을 다시 확인한다. DMA 자체는 비선점이며 완료 뒤 STOP이면 후속 ACK·표시를 막는다. 기존wait169가SEAL 뒤FFFF로 재초기화하는103E lowbyte를SEAL 이전 beam 저장에 재사용했고, 새WRAM은 없다. 두 수명은 겹치지 않는다.

추가 ARM 후보는 SEAL 대기에서 이전 패킷 retire가 진행됐더라도 중복 E0를 기다리지 않고 최대7개 입력을 수신한다. 일반 출력 credit 우선권은 그대로다. 입력 예산은 CRC 확인·D2/D0 반환 확인 뒤에만 줄이며, 입력 수신이 최종 표시 ACK나 새 COMMIT을 대신하지 않는다.

실제 링크M4·65816을 실행했지만 SPI·IRQ 비용과 반복boot ROM 허용 달력은 모델이다. 실시간NES/PSRAM 전체 공동 실행이나 실제 보드 재시험이 아니다. MMC666 실기 출력·최종ACK26.84ms에 이 비율을 곱하지 않는다.

## 7블록 마감이 남은 이유

CPU 단독에서 위상2 SEAL 수락은 약0.391ms 늦고955 ACK는약0.084ms 빨라졌다. 첫D1→7번째D0 비용은4.035271ms로 동일했다. 단지 표시가 빨라졌기 때문이라는 설명만으로는 부족하다. ARM 변경으로 중복E0 약0.151ms를 없앴지만 연속 일정에서SEAL 발행도 달라져 순 마감 개선은약0.051ms였다.

최종 후보 위상2에서 SEAL SPI 종료65,638,675.282, 첫poll65,641,991.140,7번째 검사 반환65,731,140.210,955 ACK65,729,382다. SEAL 종료→입력poll의0.154389ms에는 첫20B E0와CRC/credit 처리가 남는다. poll부터7블록 검사 완료까지4.150856ms이며, 마감까지 추가0.081864ms를 앞당겨야 한다. 모든 입력은 이후 정상 완료했지만 **요청한 ACK 전7블록 조건은 미달**이다. ACK를 늦추거나 검사 완료 정의를 바꿔 통과시키지 않는다.

## 보호 시험과 비용

- 실제65816 범위·STOP·새 패킷·cold 복구·manifest 독립 검사·최종ACK 취소23개, 늦은252/253선 경계3개와 기존tile 경합/late 검사를 통과했다.
- full1536B는248선h1162에beam을읽고250선h476에DMA를시작해259선h920에끝났다. late1152B는252선h1146 latch 뒤261선h160에끝났다. 새전체106화면의모든idleDMA도같은VBlank의262선전에끝났다.
- STOP 첫쓰기→quiet 최악은15562 masterclocks(약0.725ms)다. 비선점DMA의응답비용이며 즉시 중단이라고 주장하지 않는다. DMA 시작 전 STOP·head 우선과 DMA 후 최종ACK 차단은 유지했다.
- 최종ARM의 수신/CRC/STOP/credit56개, BG/map33개, 메뉴/base5개와marker4개를 통과했다.154개C/H는 생성기로 새 후보 소스를 바이트 그대로 재현했고,7개DWARF 구조체는684와 동일했다. 새실기 메뉴 복귀 시험은 아니다.
- ARM 전체 Flash212988B/free4B, data10040B/BSS19544B. wait634 stack40B·poll560B로 동일하다. CPU body5984B/free0, packed5120B/free13, prefix512B다.

7블록 선행 수신 게이트가 미달이므로 새 Quartus Lite MAP/FIT/STA와 설치본은 만들지 않았다. RTL680과 새685 ROM을 묶은 보드 입력은 준비·해시 고정만 했다. 기존 MMC666 보드의15324LE/962LAB/56M9K와STA를 새 후보 통과로 옮겨 쓰지 않는다.

## 다음 순서

685의 BG 완료 map·큰 묶음·1536B 완료 DMA를 보존한다. 다음은 SEAL E1 성공 뒤 첫 E0보다 먼저 bounded7 입력을 시작하는 소유권 경계 하나를 검토한다. 측정된 첫 E0와 진입 비용0.154389ms 대비 필요한 선행량은 위상2 0.081864ms다. 이 차이는 가능 예산이며 성공 시간이 아니다. E1 수락 오류·STOP·부분 입력·CRC/POP 실패 때 입력 중단과 cold 복구를 유지하고, 이전 최종ACK 전체 identity를 확인하기 전 새 COMMIT/EA/표시 공개를 금지한다. 일반 출력 credit 우선권은 그대로 두고 Flash4B 안에서 기존 대기 제어를 대체한다. 두 시작 위상106화면에서7블록·첫BG ROM창·911/951/952/957과 밀집/마지막ACK를 다시 함께 통과해야 한다. 그 뒤에만 전체 Lite FIT/STA·새 전달을 진행한다. 고정 지연·위상 상수·DMA 크기 반복 탐색은 하지 않는다.
