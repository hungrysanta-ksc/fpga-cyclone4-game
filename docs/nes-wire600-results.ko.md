# 600 · MMC577 입력 압축을 유지한 952·954 SPI 예산

**추가 절감 목표는 두 장면 모두 달성했다. 60 Hz 예산은 두 위상 모두 미달이다.** 512에서 시험했던 블록별 generation 공유를 MMC577 입력에 이식했다. 원래 압축 tag와 값은 그대로 보내고, FPGA가 블록마다 버전과 generation을 한 번 기록한다. ARM은 블록 문맥·길이·토큰·CRC와 원래의 레코드 의미를 검사한다. 599의 nonmap 상속 CRC 재검사는 사용하지 않았다. [상속 검사 비용](nes-output599-results.ko.md)

## 실제 전송과 ARM 수신

동일 입력을 MMC577 보드의 직렬화기와 변경 직렬화기에 차례로 넣었다. 단일 Questa FLOAT 라이선스로 D0/D1/D2/D3 핀 시험을 실행했다. 길이와 CRC를 확인한 D1 패킷을 각각의 전체 링크 ARM 수신기에 전달했다. ARM은 두 방식 모두 map·row·object·exception·raster·palette·raw를 캡처와 동일하게 복원했다. D1 결과는 핀 측정, D0 횟수는 sealed 상태를 재사용하는 실제 ARM이 추가 busy 대기 없이 발행한 수치다. 원본 ARM의 opcode별 바이트는 두 위상의 원래 기록과 정확히 일치했다.

| 항목 | 952 | 954 |
|---|---:|---:|
| D1 패킷 | 16 → 15 | 16 → 15 |
| D1 전체 wire | 3,462 → 2,916 B | 3,450 → 2,908 B |
| D0 / D2 / D3 호출 | 20/16/1 → 19/15/1 | 20/16/1 → 19/15/1 |
| 입력 순절약 / 목표 | **562 / 429 B** | **558 / 518 B** |
| ARM 수신 명령 수 | 298,300 → 289,721 | 297,818 → 289,263 |
| 8 B map 적용 뒤 기존 부분합 → 새 부분합 | 5,897 → **5,335 B** | 5,986 → **5,428 B** |

부분합에는 D0–D3, E1, E9, EA가 있다. 8 B map은 582·599에서 검증한 레코드와 마스크 선언의 전송 비용이다. E0·E8·observer는 이 부분합 밖에 있다. ARM 전체 링크는 212,908 → 212,916 B로 Flash 여유 76 B다. 이번 빌드는 수신 변경만 포함한다. 599의 독립 map 커널이나 새 보드 전체 FIT·STA를 포함한 설치본은 없다. 512의 다른 보드 배치에서 관련 setup이 음수였던 기록 역시 남아 있다. [512 결과](nes-transfer512-results.ko.md)

## 조회를 어디까지 줄일 수 있나

- 952의 E1은 기존 38개 중 map 10개를 새 3개로 바꾸면 31개다. 954는 35개 중 12개를 4개로 바꾸면 27개다. 현재 ARM은 E0에서만 retired 수를 갱신하고, 마지막 SEAL의 성공·identity까지 확인한다. 한 번에 최대 4개를 반환해도 E0가 각각 최소 8회와 7회 필요하다.
- EA 전 E8 상태 확인 한 번만 더하고, 나머지 plan·bulk 조회, 재무장 조회, observer, 드라이버 시간을 모두 0으로 둔 하한이 **5,515 / 5,588 B**다. 2.625 MHz의 60 Hz 한도 5,468.75 B보다 각각 최소 47 / 120 B 더 줄여야 한다. E0/E8을 없애려면 실제 응답의 소유권을 옮겨야 하며 중복 스냅숏을 무료로 받을 수 있다고 가정하지 않았다. [584 응답 비용](nes-transport584-results.ko.md)

|---|---:|---:|---:|---:|
| 1 · 952 | 89/42 | 16.808 ms | 24.341 / 34.872 ms | 83.362 / 83.360 ms |
| 2 · 952 | 86/44 | 16.808 ms | 24.280 / 34.763 ms | 83.240 / 83.240 ms |
| 1 · 954 | 84/45 | 17.030 ms | 24.454 / 34.690 ms | 83.582 / 83.582 ms |
| 2 · 954 | 84/43 | 17.030 ms | 24.381 / 34.520 ms | 83.362 / 83.364 ms |

기존 조회 횟수 시나리오는 관측 observer 바이트와 503의 opcode별 평균 드라이버 시간을 포함한다. observer의 별도 호출 지연은 제외했다. 표의 마지막 열은 기준 65816의 실제 명령을 실행한 기존 공동 일정이다. 새 ARM·8 B map의 표시 간격 또는 실기 FPS로 사용하지 않는다.

## ROM과 VBlank를 같은 시각축에서 비교

시작 3,000,000 / 3,178,684 master clock의 577 기록에서 이전 표시·ACK와 이번 입력 시작을 고정했다. 84 MHz·CPI 2, 수신 명령 수, 동기 SPI와 호출별 평균 드라이버 비용을 한 번씩 과금하면 새 수신 완료는 입력 시작 후 **19.124 / 19.089 ms**다. 두 세대 모두 수신 단계에서 이미 한 주기를 넘는다.

새 일정은 첫 E9 전송이 끝나는 즉시 나머지 BG·OBJ 주소까지 전부 준비됐다고 두었다. 실제 ROM 읽기 208 / 272개를 원래와 같은 8프레임 부팅 ROM 중재 기록에 다시 배치했다. 원래 요청을 넣으면 원래 grant와 응답 시각이 모두 재현된다. 새 요청은 겹칠 수 있는 나머지 SPI와 병렬로 진행하고 두 경로 중 늦은 쪽을 택했다. 표시 전 SPI에서 최종 E0·E8·EA를 빼고, 검증·DMA·planner·추가 IRQ 비용을 0으로 두고도 VBlank 중에만 화면을 바꿀 수 있게 했다. NTSC 위상은 기존 두 65816 추적의 scanline·hclock과 대조했다.

| 위상 · 세대 | 기준 ROM 대기 / SEAL 구간 VBlank 대기 | 새 ROM 대기 | ROM·버스 완료 후 추가 VBlank 대기 | 이전 표시부터 가장 이른 표시 시나리오 |
|---|---:|---:|---:|---:|
| 1 · 952 | 27.627 / 7.266 ms | 13.520 ms | 0 ms | 33.404 ms |
| 2 · 952 | 28.010 / 8.329 ms | 13.331 ms | 0 ms | 33.366 ms |
| 1 · 954 | 26.305 / 9.048 ms | 13.917 ms | 0 ms | 33.972 ms |
| 2 · 954 | 26.091 / 9.336 ms | 13.953 ms | 0 ms | 33.977 ms |

추가 VBlank 대기가 0인 이유는 마지막 ROM 응답이 이미 표시 가능한 구간에 있기 때문이다. 실제 65816의 검사·DMA가 그 구간 안에 끝난다는 뜻은 아니다. 기존 네 경우의 최종 대기 횟수도 0이지만 SEAL 처리 중 VBlank 대기는 있었다. 기준 ROM 대기는 다른 작업과 겹치므로 기준 ACK 간격에 더하지 않았다.

**다음 판정은 타일 ROM 읽기의 마감 시각이다.** 이전 표시에서 16.667 ms 뒤를 기한으로 역산하면, 입력 시작 순간에 모든 주소를 알아도 952는 두 위상에서 179/195번, 954는 11/22번만 읽을 수 있다. 954에서는 272회 중 최소 261/250회가 입력 시작 전 안전하게 준비돼 있거나, 캐시 적중 등으로 이번 읽기에서 제외돼야 한다. 현재 입력 시작·ROM 허용 구간을 유지할 때의 조건이다. 실제 tile tag·mapper 상태·이전 표시의 확정 이력을 대조해 이만큼의 안전한 재사용이 가능한지를 먼저 확인한다. 읽기 수·SPI·CPU 조건을 함께 만족하는 후보가 생기기 전까지 MMC577을 실기 기준으로 유지한다.

## 보호 경로와 재현

SPI 핀에서 혼합 generation, 잘못된 POP·CRC, 짧은 D1, reset 뒤 잔여 블록을 검사했다. 연결한 ARM에서도 D1 CRC 실패 뒤 POP 차단, ABORT 뒤 늦은 COMMIT, 잘못된 generation·token 거절을 확인했다. 별도 ARM runtime 시험은 같은 핀 payload와 한 개의 sealed 입력 슬롯, 기존 출력 명령과 모델 소비자를 사용한다. 성공 최종 ACK만 EA·retire를 허용하고, generation이 틀린 ACK는 표시 집계·EA를 막으며, EA 시점 STOP은 추가 진행을 막는다. 이번 두 위상의 ROM은 실제 첫 레벨 카트 버스 계측 대신 기존 부팅 기록을 재생한 것이다. 새 제품 최종 ACK 시각·메뉴 실기·FPS는 측정하지 않았다.

`check_nes_wire600.py prepare`로 577 원본 해시와 캡처를 확인하고 독립 작업 경로를 만든다. `build_nes_trial577.ps1`로 그 ARM을 링크하고, 단일 FLOAT 래퍼에서 `check_nes_wire600.py sim`을 실행한다. `analyze_nes_wire600.py`에는 두 위상 원본 trace, 509 ROM calendar, 생성한 핀 추적과 연결 ARM을 지정한다. [선택 결과·핀 해시](../analysis/wire600-verification.json)
