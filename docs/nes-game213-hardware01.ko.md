# NES213 실기: 첫 화면 전송 전 시작 실패

사용자 보고: “아에 실행에 실패했어.” 세 TXT를 원본 그대로 `probes/nes-game213-hardware01/raw`에 보존하고 SHA256을 검증했다. [기계 분석](../analysis/game213-hardware01-verification.json). **213은 실기 시작 실패이며 기존 READY 기록을 실기 통과로 해석하지 않는다.** 기존 빌드·패키지·시험 archive는 수정하지 않았다.

## 확인된 결과

| 단계 | 결과 |
|---|---|
| ROM 적재/전체 비교 | 393216바이트 일치, verified=1, verify_error=0 |
| FPGA START | 전송됨, NES observer 카운터 진행, ROM 오류 0 |
| SNES 준비 응답 | stage=0, flags=0; READY=3에 도달하지 못함 |
| 시작 대기 | DISPLAY_NEXT 231150ms → DISPLAY_STOPPED 236170ms, 5020ms |
| 오류 | run_first_error=6, native_result=2(SERVICE) |
| 첫 프레임 | BEGIN/계획/표시/전송 모두 0; 12개 budget bin 모두 0 |
| 종료 | STOP/base 복원/메뉴 준비 성공. 실제 메뉴가 보였는지는 이번 보고에 없음 |

`native_boot172`는 500tick(5초) 또는 제한된 poll 수까지 준비 상태를 기다린다. 이 함수가 실패하면 resident 초기화와 `nes_runtime165_begin` 전에 반환한다. 따라서 **이번 실패를 변경 타일 캐시, 스크롤 부하 또는 60fps 실패로 진단할 수 없다.** 5.02초는 준비 대기 제한과 일치한다. 다만 서비스/SPI 실패도 같은 오류6을 쓰므로 마지막 분기를 로그만으로 단정하지 않는다.

`screen_flags`의 bit0/1은 SNES 리셋 벡터 하위/상위 읽기, bit2는 프로그램 읽기 관찰이다. 세 비트가 모두 0이고 첫 소프트웨어 단계1도 기록되지 않았다. 이 상태는 STOP에서 지워지는 것이 아니라 FPGA 재구성/전원 초기화까지 유지된다. 따라서 초기 리셋 해제, 버스 허용, 실제 ROM 응답, 상태 감지 조건을 우선 조사해야 한다. **실제 버스 파형이 없으므로 CPU가 전혀 읽지 않았다고 확정하지 않는다.**

## 소스 대조와 검증 공백

210과213의 `nes_boot172.inc`는 동일하다. 기존207 ROM과 새213 compact ROM은 리셋 벡터 `$8000` 및 첫 단계1 기록까지의 39바이트가 같다. 새 dirty 소비 코드 및 확장 메타데이터 초기화는 그 뒤에 실행된다. 초기화 누락 하나를 이번 원인으로 확정할 근거가 없으며, 대기 시간만 늘릴 이유도 없다.

213 결합 시험은 실제 C/RTL/65816 소비 경로를 검사했지만, Mesen은 독립 LoROM으로 부팅했다. 실제 FPGA의 compact ROM 응답을 통한 리셋 벡터 읽기부터 생산 ARM의 리셋 해제·READY 판정까지 연결한 시험은 없었다. post-fit ROM 4096바이트 일치는 이미지 내용 검증이지 실물 부팅 검증이 아니다. 이번 실기 결과는 그 공백을 드러냈다. 전체 실기 FPGA 이미지 식별도 공통 board ID74만으로 증명할 수 없다.

## 작업 의미와 다음 순서

이번 작업은 성능 개선을 추가하는 작업이 아니라 **새 출력 경로의 실기 시작 실패 위치를 좁히는 작업**이다. 211/212의 성능 설계를 폐기하거나 60fps를 포기할 근거는 아직 없다.

1. 정상210과 실패213의 실제 패키지 시작 경로를 비교한다. compact ROM/리셋 벡터→board 버스 허용·응답/상태 감지→ARM 준비 대기를 하나의 최소 경계로 검증한다.
2. 재현된 원인을 수정한다. 로컬에서 재현되지 않으면 다음 판에 최초 시작 오류와 활동 상태를 보존해 서비스 실패와 준비 시간 초과를 구분한다. 무조건 재시도나 시간 제한 확대는 하지 않는다.
3. 시작 복구 뒤 같은 resident/dirty 구현으로 첫 레벨 스크롤 실기 측정을 재개한다. zero budget에 성능 의미를 부여하지 않는다.

동일213/044 재시험·추가 영상은 지금 요청하지 않는다. 새 firmware/FIT/ZIP 없음. 저장 SRAM/GBC164/기존 패키지/완료 archive는 그대로 유지한다. 이번 분석으로 시작 문제가 수정되었다고 주장하지 않는다.
