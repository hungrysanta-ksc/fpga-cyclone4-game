# NES734 수락된 map 꼬리와 OBJ 발행 경계

## 목표

733의 Flash 절감을 유지하며956의 수락된 마지막384B map DMA가 후속 OBJ보다 먼저 실행되도록 ARM 발행 조건을 조정한다. STOP·새 패킷 우선·독립 검사·최종 ACK·메뉴 복귀,952/957의1536B와 다음 BG ROM 마감을 유지하고 두 위상의 밀집 간격·마지막 ACK를727과 비교한다.

## 작업내용

733에서는956 마지막384B의 수락이128B DMA보다3.523/3.595ms 빨랐는데도,위상1에서240선의 OBJ가 빈 큐 기회를 먼저 사용했다. map 수락 부족과 구분한다.

734는732B/733의 두 단계 map 발행 중 **ordinary를 사이에 두고 후속 map 구간까지 발행한 경우**에만 기존719 대기 해제 조건을 바꾼다. E0 bit8 한 번으로 대기를 끝내지 않고,기존 최종 ACK timestamp로 계산한 유한 마감까지 checked drain과 입력 callback을 계속한다. 마감 만료·poll 한도·callback 부재는 기존처럼 발행을 재개한다. 한 구간만 발행했을 때와 cold·만료 이력·현재 SEAL 예산이 남은 경우의 기존 조건은 유지한다.

새 주기/지연 상수·프레임 번호·상주 상태·명령·FPGA/65816 변경은 없다. ARM이 다음 패킷을 아직 보내지 않는 기회를 확보하는 것이며,수신된 새 패킷이나 STOP의 우선권은 바꾸지 않는다. E0를 전체 map 완료로 해석하거나 이 대기만으로 실제 DMA 완료를 단정하지 않는다. 실제 완료는 두 위상의65816 DMA 이벤트로 판정한다.

A의 실제 재생에서956은 회복했지만 위상2의 다음953 BG ROM 구간을 놓쳤다. B는 첫 구간 뒤 cursor와 불변 변경 마스크로 **남은 범위의 폭**을 계산해384B 이하일 때만 추가 대기를 적용한다. 선행0비트를 제거한 마스크가6비트 이내인지 확인하며,0/64 shift 경계를 차단한다. 작은 행 사이 공백은 포함하고7행 이상·큰1536B 꼬리는 원래 진행 해제 조건을 유지한다. 새 global/heap은 없고,이 분기·64비트 지역 계산의 코드와 실제 실행 비용을 포함한다.

## 성과

### 자원·기능

정상 Flash212800B(192B여유),장시간212756B(236B여유)로 전체 링크를 통과했다.733보다8B 증가,727보다192B 감소다. 같은 함수+패딩 경계는5012B(727은5206B)다. 함수만의 종전4970B 부분 예산 통과로 표현하지 않는다.

B는 정상212948B(44B여유),장시간212904B(88B여유),함수+패딩5160B다. A보다148B 추가되며733의 영점 상수 제거는 그대로다. 전체 링크는727보다44B 작다.

정적 `.data1048/.ahbram8992B`, `.bss` 정상19548/장시간19556B와 sink992/resident6032/runtime1408B는 같다.733의240→2B 상수 절감·wire 동등성을 유지한다. FPGA707D·65816은 그대로이므로 동일 FIT/STA를 다시 실행하지 않았다. 기존 전체 FIT/STA 근거와 물리IO 검증 한계는733과 같다.

새 split-map 조건19개(진행 비트가 이미 있음/나중에 설정,마감 경계,만료,정지 시계/poll 한도,STOP(진행 비트 뒤 포함),잘못된 credit(진행 비트 뒤 포함)·최종 ACK,cold,이력 만료·wrap,callback 부재)를 실제 링크 ELF로 검사했다. 기존 한 구간 조건17개도 별도로 대조한다. 초기 시험의 최대 반복 횟수20은 종전 짧은 마감 fixture의 범위를 그대로 복사한 것이어서 가장 긴 기존672000cycle 경계에서38회가 나왔다. 새 조건의 유한 마감에 맞게 시험 상한을80으로 정정했고,제품의 마감·poll 상수는 바꾸지 않았다. 초기 실패 로그는 보존한다.

### 전체 일정

A의 두 위상106화면은 동일 map·tile·plan·픽셀로 완료됐다.956의 마지막384B는 모두241선 DMA→후속OBJ253선 수락으로 회복했고,선행 map1024B/tile128B를 확보했다.952/9571536B·951공개선·911/952표시·957최종대기0회·7블록도 유지했다. 그러나 위상2의953 BG32읽기 마지막 구간이61105529→61462889로 넘어갔다.727 대비952–957 평균+0.001738/+0.002592ms,951–955 밀집평균+0.021567/+0.021269ms,957ACK는0/+0.015551ms로 미채택이다. 범위 구분 없이 마감까지 보류하는 A를 선택하지 않는다.

B도 두 위상106화면을 동일 map·tile·plan·최종 픽셀로 완료했다. A+B 총212화면이다. 시작7288416/7467100,ROM 위상0,각905..957의53화면이다. 실제 링크 M4·65816 실행이며 CPI2/84MHz·SPI/IRQ·반복 ROM 달력은 모델이다. 전체 NES/PSRAM RTL 동시 실행 또는 실기 FPS가 아니다. B는 A의19개 안전 경계에 긴 꼬리·짧은 공백·넓은 공백·bit63·단일구간·빈구간6개를 추가한25개 실제 링크 시험도 통과했다.

## 후속작업

선택707D·기존 ARM/65816과 연구 대조군727을 유지한다.733 Flash 절감과734B의 짧은 map 꼬리 보호는 재사용 가능한 근거로 보존하지만 전체 발행 후보는 채택하지 않는다.

같은 마감·고정 대기·범위 임계값의 반복 조정은 보류한다. 다음은957의 마지막 OBJ 소비부터 raw/table/SEAL 수락까지5.439/5.519ms를 실제 준비·SPI·credit·65816 검사로 나누고,이전 VBlank를 쓰려면 각 발행을 얼마나 앞당겨야 하는지 예산부터 정한다. 수락된 map의 DMA 회복만으로60fps나 VBlank 감소를 주장하지 않는다.9561024B·952/9571536B·다음BG 원래ROM 구간·STOP·새 패킷 우선·독립검사·최종ACK·메뉴·Flash 한도를 함께 유지한다. 새 실기 전달본은 없다.
