# NES173 — 초기 화면 갱신 비용 측정

이번 시험은 172와 **같은 FPGA·SNES 표시 코드**에 MCU 시간 측정만 추가한다. 화면 정지나 끊김을 고쳤다는 시험판은 아니다. 처음부터 느렸던 화면의 수신 대기·변환 및 전송·표시 확인 비용을 실제 게임에서 구분한다.

1. `NES173-SMB3-VIDEO-PROFILE.zip`의 `01-GAME173-SD-ROOT` 안 내용을 SD 루트에 덮어쓴다. 파일 이름 연결을 위해 폴더 전체를 적용한다.
2. `NES GAME 173.nh1`을 한 번 실행한다. ROM 적재·비교 시간과 표시 준비 후 약60초 실행 한도는 그대로다.
3. 가능하면 기존처럼 스타트로 게임을 진행한다. 같은 화면 정지라면 추가 영상이나 정확한 수동 시간 측정은 필요 없다.
4. 메뉴 복귀 후 `sd2snes/nes-progress-173.txt`, `sd2snes/nes-game-last-173.txt`를 전달한다. 화면·소리·메뉴 복귀가 172와 달라졌다면 그 차이도 알려준다.

메뉴 실행부터6분이 지나도 복귀하지 않으면 전원을 끄고 남은 로그를 복사한다. 기존044 복원 시험은 반복하지 않는다. 정상 사용으로 되돌릴 때는 포함된 `02-RESTORE164-SD-ROOT`를 사용한다.

실행 중 SD 쓰기는 없고 정지·메뉴 복구 뒤 로그를 작성한다. GBC·세이브 SRAM·164 복원본은 보존한다. [측정 범위와 다음 판단](nes-profile173-contract.ko.md).
