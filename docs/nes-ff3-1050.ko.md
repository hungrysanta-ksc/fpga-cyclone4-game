# FF3 1050 · 전투 경계와 연사

ZIP의 `sd2snes` 폴더를 SD 루트에 병합하고 전원을 껐다 켠다. 기존 FF3 한글판과 저장 슬롯을 그대로 사용한다. 전투 상태창 바로 위와 보스방 입장·퇴장 중 움직이는 경계를 확인한다. 플레이 중 X를 누르고 있으면 A, Y를 누르고 있으면 B가 약 초당 15회 반복된다. 둘을 함께 누를 수 있고 직접 누른 A·B는 계속 눌린 상태를 유지한다. L+R+START 메뉴에서는 기존 A로 선택하고 B로 돌아간다. 종료 후 `nes-progress-ff31050.txt`, `nes-game-last-ff31050.txt`, `nes-frame-ff31050.bin`이 생성된다. 이번 변경의 대상은 FF3용 CHR RAM 보드의 65816 클라이언트다.

## 점선 재현과 확인

혼합 표시 경계의 한두 줄은 NES의 최종 픽셀 색을 캡처해 SNES 8비트 타일로 복원한다. 팔레트 64–127을 쓰려면 비트플레인 6의 한 바이트가 FF여야 한다. 이전 고정 소스 DMA 주소 $00:97BE에는 퀵메뉴 추가 후 명령 바이트 10이 들어갔다. 그 결과 8픽셀 중 7픽셀이 하위 팔레트로 넘어갔다. 전투와 보스방은 같은 루틴을 거친다.

1050은 메뉴 ROM의 마지막 바이트 $00:9BFF를 FF로 예약하고 최종 보드용 HEX와 CPU 시험 ROM 양쪽에서 검사한다. 같은 전투 캡처 64장과 방 전환 캡처 7장을 두 VRAM 뱅크에서 재생했다. 실제 클라이언트의 압축 해제·검증을 거쳐 65816 DMA가 쓴 51,712픽셀의 팔레트 번호를 캡처 원본과 대조했다. 불일치가 45,248개에서 0개로 줄었다. 실기 화면은 다음 실행에서 확인한다.

연사 위상은 SNES 자동 조이패드 읽기가 완료된 필드에서 진행한다. 연속 148개 필드 시험에서 X·Y 동시 입력, X와 방향키, 직접 누른 A·B, Y 단독, 버튼 해제를 검사했다. 이어 메뉴 표시·슬롯 요청·재개·종료, ARM의 슬롯 4개와 STOP 뒤 base 복구를 검사했다. 1048의 배치배선 복사본에서 ROM 초기값을 교체해 Quartus Lite로 다시 조립했다. FIT·STA 보고서와 핀 파일이 원본과 동일하다.

## 속도와 다음 실험

| 실기판과 장면 | 55–60초 표시 수 | 표시 FPS |
|---|---:|---:|
| FF3 1048 사용자 플레이 | 70 | 14.0 |
| FF3 1049 사용자 플레이 | 100 | 20.0 |
| MMC955 모험도 4 무입력 데모 | 121 | 24.2 |

1049 마지막 실행의 DISPLAY_NEXT부터 DISPLAY_STOPPED까지는 759.14초이고 마지막 실행에서 확인한 표시 완료는 10,540장이다. 퀵메뉴에 머문 시간까지 포함하는 경과 시간으로 나누면 약 13.88 FPS다. 55–60초의 20.0 FPS는 이 장시간 플레이 중 한 구간의 값이다.

1049는 입력 첫 블록부터 완료까지의 경과 시간 중앙값이 8.51ms, 입력 완료부터 ARM이 유효한 최종 ACK를 확인할 때까지 20.20ms였다(같은 세대 75개). 1048은 각각 8.62ms와 38.03ms(57개)였다. 마지막 구간에는 계획·공유 SPI·65816 소비·VBlank 대기가 포함된다. FF3 두 실행은 장면과 입력이 고정되지 않았다. 모험도는 55–60초에 시작한 120장의 수신 구간 누적치가 330ms(화면당 평균 2.75ms)였다. 이 평균과 FF3의 첫 블록부터 마지막 반환까지의 중앙값은 집계 경계가 다르다.

1. 인카운터를 끈 같은 슬롯에서 마을·여관·필드 동선과 입력을 재생한다. 세대별 CHR 변경 페이지, 첫 블록 준비와 D1/D2 반환, 타일 재공급량, 마지막 DMA·공개 시각을 맞춘다. 움직임이 적어도 CHR RAM을 다시 쓰면 같은 태그의 내용이 바뀔 수 있다.
2. 변경 페이지 안에서 실제로 다시 요구된 타일의 바이트와 전송을 센다. 페이지 전체의 재공급이 지연을 설명하면 변경 타일만 무효화하는 비용과 이득을 비교한다. STOP·LOAD 뒤에는 cold 복원을 검증한다.
3. ARM의 map 계획·공유 SPI·65816 수락에 양쪽 게임의 공통 지연이 확인되면 같은 변경을 켜고 꺼서 시험한다. 모험도는 기존 무입력 1–30초·30–60초 기준으로 재측정한다. FF3의 CHR RAM 쓰기 추적만으로 모험도의 FPS 상승을 예측할 수 없다.
