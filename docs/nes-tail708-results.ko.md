# 708 후반 발행·credit 비교

**새 속도 후보는 채택하지 않았다.** 707D BG 수정 보드와 기존 ARM·65816을 유지한다. 후반 데이터를 먼저 보내는 두 후보는 다른 화면의 DMA 기회를 잃었고, 패킷 초기화 제거는 일관된 종단 이득과 정상판 Flash 한도를 통과하지 못했다. [검증·다음 경계](../analysis/tail708-verification.json) · [원시 근거 보존](../analysis/tail708-archive.json)

## 후반 선행이 실패한 이유

707의 **17패킷·2,351B는 소비 ACK 미완료량**이다. 마지막 tile ACK 때 map 한 패킷211B는 이미 SPI 전송을 끝냈다. 실제 미발행량은 두 위상 모두 **16패킷·2,140B**이며 그 시각 전송 중인 E1은 없다. 과거 원시 기록은 보존하고 의미를 정정했다.

951 데이터 확정→마지막 tile ACK는4.348/4.339ms지만, 그 안의 SPI 비점유 시간은1.282/1.273ms이고 가장 긴 공백도0.336ms다. 이 공백은 ARM 계산·credit 대기를 포함하므로 전부 재사용 가능한 시간이 아니다. 패딩 선행 후보의1,100B 복원은 마지막 tile ACK보다약35µs 늦게 시작해약1.50ms를 소비했다. tile 작업 아래로 숨겨지지 않고 마지막 map을 뒤로 밀었다. 951 선행 map DMA가448→1,792B로 늘어도 다른 화면의 VBlank를 놓쳐 전체 마지막 ACK가 늦었다. 국소 DMA 증가를 전체 성과로 채택하지 않는다.

짧은 scroll만 먼저 보내도911 업로드가217/218선으로 늦어졌다(기준≤214선). 두 선행 후보는 compact raw 준비 계산도 map 앞으로 이동하므로 그 비용까지 실제 재생에 포함했다. 같은 순서 변경·상수 지연·위상별 예외 변형은 새 근거 전까지 반복하지 않는다.

## 다음 작업의 경계와 순서

다음 가설은 **기존 E1 전송 응답에 기존 E0 상태를 함께 실어 별도 credit 조회를 줄이는 것**이다. 아직 구현이나 시간 절감으로 선택하지 않았다.

| 별도 E0 credit 조회 비용 | 위상1 | 위상2 |
|---|---:|---:|
| 951 enqueue 내부 | 5회 /100B /0.545ms | 6회 /120B /0.654ms |
| 957 enqueue 내부 | 6회 /120B /0.654ms | 7회 /140B /0.763ms |

이는 현재 조회의 비용이며 삭제 가능한 수나 종단 절감 보장이 아니다. 예를 들어951의 through 내부49/47회는 소비·최종 ACK 확인을 포함하므로 위 절감 대상으로 더하지 않는다. 새 응답은 이전 snapshot이므로 모든 대기를 없앨 수 없다.

1. `nes_sink_spi165.sv`는 E1에서도17B snapshot과CRC8을 이미 계산하지만 응답·회전은 E0에서만 공개한다. 두 번째 snapshot/RAM을 추가하지 않고 기존 응답 경로를 공유할 범위를 정한다. ARM은 기존 status 검사를 분리·공유해 중복 parser를 만들지 않는다.
2. snapshot은 현재 E1의 SS 해제·accepted 증가보다 앞선다. ARM의 sent 증가 전에 **이전 수락·소비 수와 이전 identity**를 검사한다. 이것이 현재 E1 성공이나 최종 표시 완료를 증명한다고 취급하지 않는다. fault·CRC·counter wrap·STOP·stale 응답·수신 중 ACK 변경을 검증한다. E1은 최소19B여서20B 응답이 안 들어가는 명령은 E0 fallback을 유지한다.
3. 먼저 실제 삭제 가능한 조회 수와 응답 지연을 대조한다. Flash 정상판8B/장시간52B, 회로86LE/1LAB/0M9K 안에서 기존 제어를 교체해야 한다. 추정 절감만으로 FIT/긴 일정 시험을 반복하지 않는다.
4. 유효한 후보 한 개만 기존 두 위상에 연결한다. 911 마감·951 공개≤246선·952 표시3회·957 최종대기0회·7블록 선행 수신,독립 검사·STOP·최종 ACK·메뉴 복귀를 유지하고 밀집 평균과 마지막 ACK가 함께 빨라져야 채택한다.

배경 CHR707D는 시뮬레이션·FIT 통과이며 아직 실기 미확인이다. 스페이드는 사용자 실기 해결로 인정한다. 반복 화면 깨짐·stage0 timeout은 관찰로 남기며 속도 작업을 막거나 속도 개선으로 해결됐다고 단정하지 않는다. 새 설치본은 없고, 다음 전달은 새 이름의60초/장시간판·RESTORE 제외·5–40초/40–55초 집계를 유지한다.

## 재현과 실패 보존

`prepare_nes_tail708.py`는694 원본 firmware SHA를 검사해 flat patch를 만든다. `build_nes_mmc479_arm.ps1`로 전체 링크한다. `test_nes_longrun694.py`의 기존 replay에 새 ARM만 연결하고 `analyze_nes_tail708.py`로 같은 작업량·바이트·보호 조건·종단 시간을 대조한다. 패킷 초기화의 바이트 정의 검사는 `check_nes_tail708.py`에서 별도로 실행한다. `summarize_nes_tail708.py`는 세 비교·두 추가 링크·원시 실패를 보존하고 다음 조회 예산을 집계한다. 정확한 인수는 private evidence의 replay 스크립트에 있으며 입력 firmware/자료는707/694 기존 보관본에 의존한다. clean clone 전체 재현이 새로 완성된 것은 아니다.

처음 추가한 메모리 쓰기 관찰 harness는 import 순서 오류 뒤 SysTick 복귀 오류가 나서 시간 근거에서 제외했다. 같은 후보의 **기존 무수정 harness 두 위상 재생**과 별도29개 바이트 검사를 사용했다. 초기 subst 권한 실패도 원시 로그로 보존한다. 이 실패를 제품 오류나 라이선스 오류로 분류하지 않는다. 원시 로그·후보 소스·ELF/map/firmware·선택 해시를 private ZIP에 보존하며 게임 ROM·PRG/CHR·라이선스는 제외한다.
