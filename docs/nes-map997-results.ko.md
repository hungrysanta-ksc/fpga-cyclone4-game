# 997 · 907의 map 선행 DMA와 첫 OBJ ROM 허가

## 목표

978에서 907의 첫 VBlank에 수락된 map을 얼마나 더 보낼 수 있는지 측정하고, 908 공개·909 선행 DMA 624B·910 캡처를 보존하면서 여섯 표시 간격과 912 최종 ACK를 함께 앞당기는지 확인했다.

## 작업내용

기존 65816은 16B BG descriptor 앞뒤의 연속 map을 두 번에 나누어 DMA했다. 후보는 두 descriptor가 모두 미소비 상태이고 BG 목적지가 map과 분리된 경우, 기존 source·destination 연속성 검사와 길이 한도를 그대로 거쳐 앞의 map에 새 범위를 합친다. ARM·SPI 패킷 순서·STOP·SEAL은 978과 같다. 관측기는 descriptor가 가리키는 BG와 map의 목적지 분리, 모든 map 읽기의 수락 범위·중복, 실제 화면 RGB를 확인한다.

비교군은 978, 부팅과 906까지 동일하게 재생하고 907에서만 수신기를 바꾼 경우, 바뀐 수신기로 처음부터 부팅한 경우다. 각 경우 두 시작 위상에서 실제 ARM·65816 명령을 실행했다. ROM 허가에는 기존의 주기적 보드 트레이스 모델을 사용했다.

978에서 offset 768·960은 첫 768B DMA 시작보다 각각 약 0.86·0.18ms 먼저 반환됐다. 그 사이에 들어간 16B BG descriptor 때문에 다음 VBlank로 밀렸던 384B를 옮길 수 있었다. offset 1,152·1,344는 첫 DMA 시작보다 약 0.94·1.47ms 뒤에 반환됐다. 후보는 이 두 범위를 다음 VBlank에 320B로 전송했다. BG와 448B OBJ, raw·팔레트·OAM의 전송량과 905–912의 화면 RGB는 기준과 일치한다.

**직전 VBlank 공개를 막는 시각은 OBJ 공급에서 이미 확인된다.** 978의 907 OBJ 첫 실수요 요청은 두 위상에서 각각 12,376,504 / 12,377,939클록이다. 첫 ROM 허가는 모두 12,486,636클록으로 요청 후 5.128 / 5.061ms가 걸렸다. 총 22회 읽기의 마지막 응답은 12,490,613, 448B OBJ 준비는 12,493,547클록이다. VBlank 35의 246선 종료는 두 위상 모두 12,487,352클록으로, OBJ 준비만으로 이미 0.288ms 늦다. ARM의 첫 유효 E8은 그보다 215 / 593클록 뒤다. 이 순서에서 E8이나 map만 앞당겨서는 35회 공개에 도달할 수 없다.

ROM 허가 일정상 직전 슬롯은 12,146,376클록에서 닫혔다. ARM planner 진입도 그보다 1.772 / 1.838ms 늦다. 이 슬롯은 다른 사용자와의 경쟁을 차감하기 전의 가장 낙관적인 시각이다. 계획 완료 뒤 E9의 발행 순서만 바꾸는 방식으로는 해당 구간의 읽기를 시작할 수 없다.

부팅판 두 위상에서 1,152B 선행 DMA 후 STOP을 주입하면 0xE4, SEAL identity를 손상시키면 0xE0로 종료했다. 네 경우 모두 907 최종 ACK가 차단되고 마지막 906 화면 RGB가 유지됐다. 실기 메뉴 복귀와 보드 FIT·STA는 이번 실험 범위 밖이다. 저장 ROM은 5,096→5,157B로 5,120B 한도를 37B 초과한다. 실기판은 만들지 않았다. [위상별 절대 클록·DMA·오류 주입 결과](../analysis/map997-results.json)

## 후속작업

978을 유지한다. 다음에는 907에서 첫 요청을 일으키는 실제 CHR 주소를 906 표시 대기 중의 입력 블록·mapper 상태와 대조한다. 주소가 직전 ROM 허가 전에 확정되는 바이트에 한해 기존 캐시에 공급하고, 사용 중인 포트·다른 타일·STOP 때 취소되는 요청까지 포함해 비교한다. 완전한 공개에는 OBJ 외에 남은 map·SEAL·팔레트·OAM 비용도 들어가므로, 먼저 전체 일정을 재생해 35회 공개가 가능한지 판정한다.

재현은 `tools/nes_map997.py build` 후 `matched`와 `static`에 기존 임시 작업 경로와 위상 1·2를 각각 전달한다. 이어 `tools/check_nes_map997.py`로 위상별 `--guard stop_decode`와 `--guard bad_seal`을 실행하고 `--out analysis/map997-results.json`으로 비교 결과를 생성한다.
