# NES161 — 첫 레벨 진입과 화면 갱신 개선 시험

160에서 현재 필요한 그래픽 데이터가 다음 데이터의 응답 직후 사라지는 경계를 확인했다.161은 사용 중인 바이트를 보존하고 같은 주소의 중복 선행 읽기를 막는다. 실제 첫 레벨 플레이 성공은 이번 시험으로 확인한다.

화면 유지 시간을30프레임에서6프레임으로 줄였다.60Hz 기준 의도적인 대기는 약0.5초에서0.1초가 되지만,전송·캡처 시간이 더해지므로10fps나60fps를 의미하지 않는다. 화면 전송 중 짧은 소거·점멸과 입력 수집 공백은 남아 있다. 소리는 계속 차단돼 있다.

1. ZIP의 `01-GAME161-SD-ROOT` **안의 내용**을 SD 루트에 덮어쓴다. MCU·FPGA·ROM을 같은 세트로 적용한다.
2. **`NES GAME 161.nh1`**를 실행한다.0바이트 표식이 정상이며 확장자는 바꾸지 않는다.
3. 첫 Start →1PLAYER에서 Start 한 번 후 떼기 →월드맵 첫 레벨에서 **A로 진입**한다. 기존 실행 상한 약60초 안에 진행하도록 월드맵에서 오래 기다리지 않는다.
4. 레벨 내부가 나오면 이동·점프를 확인한다. 이번에는 화면이 덜 끊기는지,점멸이 심해졌는지도 볼 수 있도록 짧은 영상을 찍는다.
5. 메뉴 복귀 후 `sd2snes/nes-progress-161.txt`, `sd2snes/nes-game-last-161.txt`와 메뉴 복귀 여부를 전달한다.

적재 방식은 이전과 같고 약3분50초는 기존 실측 참고치이며161 실측은 아니다. 전체7분 이상 무반응이면 기다림을 끝내고 남은 TXT와 상태를 전달한다. 160 종료는60초 제한이 아닌 PPU오류였다.

044/GBC 복원 시험은 반복하지 않는다. 정상 사용으로 돌아갈 때 동봉 `02-RESTORE044-SD-ROOT`를 사용한다. 첫 레벨 플레이·연속 화면·속도·오디오·저장은 아직 완료되지 않았다.
