# MMC704 60초판 / MMC705 장시간판

두 판 모두 **703B의 CPU·CHR 연속 ROM 읽기 수정**을 포함합니다. 기존 MMC700/701의 실행·표시 코드를 유지하고 설치·로그 파일명을 갱신했습니다. 이번 시험의 우선 목표는 스페이드 보너스 진입, 일회성 타일 깨짐, 장시간 안정성 확인입니다. FPS 향상을 전제로 한 전달본은 아닙니다.

## 설치

1. 전원을 끄고 ZIP에서 원하는 **한 폴더의 내용만** SD 루트로 복사합니다.
   - `01-MMC704-60SEC-SD-ROOT`: 약 60초 뒤 자동 메뉴 복귀.
   - `02-MMC705-LONG-SD-ROOT`: 고정 플레이 시간 제한 없음.
2. 기존에 사용한 SMB3(J) ROM의 내용을 바꾸지 말고 다음 이름으로 복사합니다.
   - 60초판: `sd2snes/nes/mmc704.nes`
   - 장시간판: `sd2snes/nes/mmc705.nes`
   - MMC700/701에서 사용한 ROM과 같은 파일입니다. payload CRC32는 `5a04eed7`입니다.
3. `NES MMC3 704.nh1` 또는 `NES MMC3 705.nh1` 중 설치한 판의 메뉴 항목을 실행합니다.
4. 판을 바꿀 때도 전원을 끄고 해당 폴더의 `firmware.stm`, FPGA 파일, 메뉴 파일을 함께 교체합니다. 두 설치 폴더를 동시에 덮어쓰지 않습니다.

RESTORE·이전 펌웨어 복구본·게임 ROM·세이브는 포함하지 않습니다. 동봉된 `fpga_base.bi3`와 `m3nu.bin`은 실행 후 STOP·메뉴 복귀에 필요한 기본 구성입니다. 기존 백업·세이브는 그대로 둡니다.

## 시험 순서

1. **MMC704:** 이전과 비슷한 첫 레벨 동선으로 플레이합니다. 타일이 밀리거나 잠시 깨지는 현상이 있는지 보고, 약 60초 뒤 자동으로 메뉴에 돌아오는지 확인합니다. 프레임 비교는 기존처럼 **5–40초 / 40–55초**입니다.
2. **MMC705:** 월드1 레벨1·2를 클리어하고 아래쪽 **스페이드 보너스 게임**으로 들어갑니다. 안내 화면뿐 아니라 슬롯 회전·결과·월드 맵 복귀까지 확인합니다. 치트나 자동 진입 코드는 넣지 않았습니다.
3. 장시간판으로 다른 스테이지를 계속 플레이합니다. 가능하면 이전 실패 시점인 약 14분 11초보다 오래 진행합니다. 시간 제한은 없지만 기존 오류 검사는 계속 작동합니다.
4. **장시간판 수동 종료:** `L + R + Start + Select`를 동시에 길게 누릅니다. 기존 STOP → base 복구 → 메뉴 복귀가 실행됩니다. 종료 조합의 실기 동작도 이번 확인 항목입니다. 60초판은 자동 종료를 확인합니다.

타일 깨짐이 다시 보이면 **대략적인 경과 시간, 스테이지·장면, 잠깐 뒤 정상으로 돌아왔는지**를 기록해 주세요. 가능하면 사진·짧은 영상도 남기면 도움이 됩니다. 이 현상은 아직 703B로 해결됐다고 확인하지 않았습니다. 예기치 않게 메뉴로 돌아오거나 실행에 실패해도 해당 회차 로그를 보관합니다.

## 로그 보관

메뉴 복귀 뒤 `sd2snes` 폴더에서 아래 세 파일을 복사합니다. 같은 판을 재실행하면 덮어써지므로 **재실행 전에 회차를 붙여 따로 보관**해 주세요.

| 판 | 로그 파일 |
|---|---|
| MMC704 | `nes-progress-mmc704.txt`, `nes-budget-mmc704.txt`, `nes-game-last-mmc704.txt` |
| MMC705 | `nes-progress-mmc705.txt`, `nes-budget-mmc705.txt`, `nes-game-last-mmc705.txt` |

로그와 함께 스페이드 진입 성공 여부, 타일 깨짐 여부, 대략적인 플레이 시간, 자동 종료·종료 조합·예기치 않은 복귀 중 어느 경우인지 알려주세요. 전원 차단으로 끝내면 종료 로그가 남지 않을 수 있습니다.

장시간판도 첫 5–40/40–55초 집계를 유지합니다. 상세 5초 bin은 약 60초 epoch마다 재사용하므로 전체 플레이의 모든 5초 기록이 남는 방식은 아닙니다. RUN 중 SD 기록은 추가하지 않았습니다.

## 검증 범위

703B는 실기 MMC701과 같은 CPU 오류 문맥을 재현한 뒤, 실제 T65·PSRAM 모델에서 두 스프라이트까지의 읽기 36조건·중간 STOP 36조건을 통과했습니다. 독립 데이터·주소 검사와 최종 ACK를 유지했고, 두 시작 위상의 기존 ARM·65816 일정은 동일했습니다. 전체 FIT·기존 제약 STA는 통과했지만 외부 IO 전체 sign-off와 수정 후 실기 안정성은 확인이 남습니다.

전달본은 두 ARM 전체 링크·함수 바이트 동일성, 판별 표시 ROM·FPGA 구성, 프로그래머·설치 marker·로그·ROM bus·STOP/base/menu를 검증합니다. 검증 결과와 해시는 ZIP의 `manifest.json`에 들어 있습니다.
