# 687: 인접 map의 조회 소유권과 bulk 우선권

687은 인접 map의 조회를 두 패킷 단위로 공유하되 준비된 bulk의 완료 처리를 우선했다. 955 마지막 map 검사 완료를 위상1/2에서 593.930/1043.522µs 앞당겨 두 위상 모두 1152B 선행 DMA를 회복했다. 7블록 수신·957 마지막384B 선행·952 표시3회·957 최종대기0회를 유지했고, MMC666 대비 밀집 평균은 −0.044959/−0.001378ms, 마지막ACK는 −0.167340/−0.407501ms다. 그러나 위상1의951 공개가247선으로 기존246선 제한을 넘어서 후보 채택은 보류하고 실기 기준MMC666을 유지한다.

## 구현한 경계

686의 SEAL 성공→입력 인계와 최대7블록 수신,685의실제beam 기반 map 완료DMA를 유지했다. ARM의 `map527`에서 warm 대상 뱅크의 확정된192B map 두 개가 연속일 때 첫 패킷의 실제 producer 진행 확인을 두 번째 패킷까지 재사용한다. 다음 쌍은 다시 조회한다. gap·짧은 tail·cold에서는 기존 검사를 유지하고, BG/행 선행 callback은 기존 한 패킷만 발행한다. 패킷별 STOP·credit·wire CRC·sequence와 최종 ACK identity는 생략하지 않는다.

처음에는 함수 진입 때의 map head만 허가에 사용했다.955는 직전tile 때문에 이 조건이 거짓이어서 조회가15회 그대로였고,위상1 마지막map ACK가 오히려16.762µs 늦었다. 전송 완료 후 소유권 갱신으로 수정하자 위상1은611.065µs 빨라져1152B DMA를 회복했지만,위상2 951→952 일정이 바뀌어952가4VBlank가됐다. 이 후보도 채택하지 않았다.

마지막 후보는 새로운 묶음 허가를 만들 때 `bulk_pending`을 확인한다. 이미 제출한tile의 소비 완료가 남아 있으면 다음map을 기존producer/receipt 경로로 보낸다. 준비된bulk의우선권을지키며,이미 제출한 bulk의 완료가 남지 않았을 때 다음 인접 map의 조회 왕복을 줄인다. 새로 준비될 tile까지 미리 알 수 있다는 뜻은 아니다. 별도순서표·frame번호·시작위상상수·고정지연은 추가하지 않는다.

## 독립 검사와 자원

- 최종 ARM으로 map/credit/CRC/중간STOP/readybulk42개,SEAL·최종ACK23개,입력·credit56개,메뉴/base5개와marker4개를검증했다. 마지막42개에는두패킷뒤E8 CRC오류와이미소유한bulk의완료우선권이포함된다.

- 처음별도next커서를둔ARM01은213000B로8B초과해재생하지않았다. 기존gap순회를공유한ARM02는212968B,완료문맥을갱신한ARM03은212972B,bulk우선ARM04는212988B다. 빌드와실패결과는모두보존했다.
