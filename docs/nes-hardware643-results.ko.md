# 스테이지 선택 전환 중 MMC642 종료

사용자가 START로 스테이지 선택에 들어가면서 메뉴로 복귀했다. 384 KiB 적재·비교와 부팅(310 ms, stage 3)은 성공했다. 패드 기록에 START 입력 두 번과 각각의 해제가 있다. 85화면을 표시했고 마지막 표시 시각은 4.03초, DISPLAY_NEXT부터 DISPLAY_STOPPED까지는 4.40초다. STOP·base 복구·MENU_PREPARED를 확인했다. 5–55초 성능 표본에서 제외한다. [원본 해시·판독 결과](../analysis/hardware643-mmc642.json)

| 관측 | 이번 MMC642 | MMC639 1차 | NES215 스테이지 선택 2회 |
|---|---|---|---|
| 마지막 표시 → 실패 세대 | 96 → 97 | 31 → 32 | 78 → 79 / 115 → 116 |
| ARM이 오류를 읽은 곳 | FINISH, E9 수락 2 | FINISH, E9 수락 2 | FLUSH, E9 수락 1 |
| 다음 캡처 | 98 거부 | 33 거부 | 당시 원회로에 642 마스크 없음 |
| 판정 | E8 byte 14/15 = 00/24 | 다음 거부 기록과 중단 순서 일치, 최초 회로 미확정 | 216에서 정상 대기를 tile watchdog이 고장으로 오판하는 경로 재현 |

MMC639 2차 및 MMC551 실패는 첫 표시 전 부팅 시간 초과로 따로 둔다. NES215에서 같은 화면 전환에 실패했던 사용자의 관찰은 당시 실기 기록과 일치한다. [215 실기 기록](../analysis/game215-hardware01-verification.json) · [216 재현 범위](nes-wait216-contract.ko.md)

**이번 FPGA의 최초 NES 증거는 lease 오류다.** 0x24의 bit 2는 NES 도메인의 lease 검사, bit 5는 host가 관측한 같은 lease 신호다. host 자체 오류 마스크는 0이다. FINISH 응답 CRC가 맞고 ROM·입력 수신·전송 CRC 오류는 0이었다. 다음 캡처의 REJECT는 두 실기 모두 224행, BG 그룹·팔레트·OBJ·예외 0, 표시 마스크 0, fetch/compact/raster 오류 0이었다. 이는 기록된 **다음 캡처**의 상태다. 전환 전후 각 화면의 타일 수나 실제 PPU 쓰기 시점은 기록되지 않았다. 5초 누계만으로 실패 세대의 타일 증가량을 추정하지 않는다.

**재현된 결함**은 이전 화면의 표시 권한이 남아 있을 때 다음 입력을 먼저 검사하는 경로에 있다. END가 닫히고 reader가 비면 다음 캡처를 내보낼 수 있다. 이때 BG 그룹·팔레트가 0인 다음 캡처를 exporter가 error 2로 거부하면서 release를 보낸다. 소유권 검사기는 이전 화면의 반환을 기다리는 중이므로 그 release에서 fault를 세운다. 입력 폐기가 진행 중인 표시까지 중단시키는 경로다. 실기에는 이 release 자체의 파형이 없다.

**643 수정**은 거부 대상에 대한 release만 이전 표시 권한이 반환될 때까지 보류한다. 유효 입력의 선행 처리, 독립적인 세대·소유권 검사, 최종 ACK 뒤 EA, STOP에는 기존 제어를 사용한다. 지연되는 동안 다음 입력 하나가 collector를 점유하므로 그 구간에서 새 캡처 기회를 놓칠 수 있다.

선택한 보드의 exporter·lease·plan SPI·bulk RTL에 실기 두 쌍의 세대와 거부 조건을 주었다. 정상 타일은 blank+BG 32 B, ROM은 주소 대응 시험 응답, SNES 소비와 최종 승인 후 EA는 버스 자극이다. 전체 게임이나 전환 화면을 재생한 시험과 구분한다. 원본 24조건(두 세대 × host 위상 12개) 모두 lease fault로 중단됐고 위상 8 ns에서 MMC642 E8 **20 B 전체가 일치**했다. 다른 위상은 host가 lease를 관측한 00/20이었다. 수정본 24조건 모두 앞 화면의 32 B 읽기·소비와 EA 반환, 다음 거부 입력의 1회 폐기, 그 다음 유효 입력의 export 시작, STOP을 통과했다. [48개 로그 해시와 전달 검증](../analysis/reject643-package.json)

643 보드 전체는 15,354 LE(642 대비 +9), 14,301 조합 논리(−7), 8,500 FF, 56 M9K다. Quartus Lite 최저 setup/hold는 0.333/0.144 ns, recovery/removal은 1.256/0.496 ns, ROM_OE 여유는 1.463 ns다. ARM 798개 함수 기계어 동일, 파일명 갱신 후 Flash 여유 60 B다. 기존 fault·부팅·STOP 회귀, 메뉴/base 복구, ROM 5,120 B 및 최종 이미지 프로그래머 시험을 통과했다. 실기 전환 통과와 60초 플레이는 다음 외부 확인 대상이다. [MMC643 실기 안내](nes-mmc643-trial.ko.md)
