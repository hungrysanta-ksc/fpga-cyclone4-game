# NES110 제한 실기 선택안 — 현재 실행 지시 아님

권장 선택은 **미측정 전기 조건을 남긴 정상 전원·80KiB 자체 진단 1회**다. 사용자의 시험 우선 개발 목표,109의 실제C 통합과 정확044 복원 파일을 근거로 한 개발 방식 제안이다. 제품 규격 보증이나 안전성 인증이 아니다. 전기 조건과 8µs 차단이 입증됐다는 의미로 E1/E2를 닫지 않는다.

## 지금 선택이 필요한 이유

기존106/107은 E1/E2가 열린 상태에서 실행을 승인하지 않았다.108/109는 고장 종료 소프트웨어를 검증했지만 실측을 대체하지 못한다. 이번 선택은 그 미확인을 명시한 기능 시험으로 진입 기준을 바꾸는 것이므로, 일반적인 ‘계속’이나 PR 병합을 시험 동의로 간주하지 않는다. 자동 승인 검토나 도구 권한 문제가 아니라 작업 범위에 관한 판단이다.

- **제한 시험 선택:** 정상 전원에서 자체80KiB를 한 번 적재·전체 비교·STOP·기본FPGA/메뉴 복구. 전기적 보증·고장내성은 주장하지 않는다. 선택을 기록한 다음 실행용 패키지를 제공한다.
- **실기 보류 선택:** 현 후보를 실행하지 않고 보드 설계/계측 근거를 확보한다. 추가 TXT·사진·정상GBC 플레이만으로 전압/부하/CE 파형의 상한을 대신할 수 없다.

고장 주입을 제외해도 우발적 고장이 없어지지는 않는다. tCEM을 넘겨도 하드웨어 손상이 절대 없다는 보장은 하지 않는다. 규격 밖 동작의 결과를 자료 없이 단정하지 않는다. 백업은 데이터 복구 수단이며 전기 조건을 보증하지 않는다.

## 실행용 패키지 발행 후 사용할 절차 초안

1. 별도 매체에 현재 SD 내용, 특히 정상 sd2snes 폴더·저장 데이터를 보존한다. 전원이 꺼진 상태에서만 SD를 분리/복사한다. 과거 nes-verify-last-094.txt도 별도로 옮겨 이번 결과와 구분한다.
2. trial 폴더 내용만 SD 루트에 적용한다. restore 폴더를 동시에 덮어쓰지 않는다. 파일 해시/역할표로 ARM108과정확044를 구분한다. PC와실기 직접 연결은 필요 없다.
3. 정상 메뉴가 나온 경우 `NES VERIFY 094 80.nh1`을 한 번 선택하고 그때부터 시간을 잰다. 메뉴가 나오지 않으면 표식을 실행했다고 가정하지 말고 관측을 기록한 뒤 복원한다.
4. 정상 메뉴가 돌아오면 추가 반복 없이 종료한다. 최대600초에도 돌아오지 않으면 마지막 화면/시간을 기록하고 전원을 끈다.600초는 사람이 기다리는 한도이며 MCU 완료·SD flush·8µs 보장이 아니다. NMI/공유고장 뒤 새TXT를 강제로 만들거나 자동복구하지 않는다.
5. 전원을 끈 뒤SD에서 새TXT를 보존한다. 없음/0바이트도 결과다. restore의정확044/base/menu로 수동 복원하고 메뉴·GBC가 정상인지 별도로 기록한다. 원래 SD의 개인 설정과 저장 데이터는 독립 보존본으로 복구한다.

반환할 자료는 새TXT(없으면없음), 실제메뉴복귀 여부, 선택부터 경과시간, 마지막화면, 수동복원 결과다. 저장TXT의 PREPARED_RESET_HELD는 RESET 해제 전 상태다. 새 TXT와 메뉴 복귀가 모두 있어야 이번 진단 준비와 반환을 함께 확인하며, 어느 쪽이 없으면 부분 관측으로 남긴다. 과거084/092 PASS를 이번 성공으로 기록하지 않는다.

현재 검토 ZIP은 DO-NOT-INSTALL 표시와 review-only 하위폴더를 갖고 있으며 실행 승인=false다. 이번 PR을 병합해도 이 표시는 해제하지 않는다. [판정 상태](nes-trial110-decision.json) · [110 근거](../analysis/TRIAL110-RESULT.ko.md).
