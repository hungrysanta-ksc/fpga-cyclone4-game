# 599 · 952·954의 출력 재사용과 최종 ACK 기한

MMC577 입력을 고정했다. 582의 출력 형식 중 대상 뱅크의 8 B map 변경분, 팔레트·OAM·HDMA의 동일 범위 선언을 Cortex-M4 코드로 생성하고 이 바이트를 Mesen의 65816 코드에 전달했다. **매 화면 상속 범위를 읽어 CRC를 다시 만드는 방식은 제외한다.** 두 위상 모두 map DMA를 시작하기도 전에 MMC577이 이미 해당 화면의 표시와 최종 ACK를 마쳤다.

## 같은 작업에서 무엇을 줄였나

| 세대 | ARM 명령 수 | map 순절약 | nonmap 순절약 | nonmap SPI 시간 절약 | 65816 상속 읽기 |
|---|---:|---:|---:|---:|---:|
| 952 | 291,969 | 1,683 B | 724 B | 2.206 ms | 2,551 B · 6범위 |
| 954 | 290,645 | 1,526 B | 696 B | 2.121 ms | 2,359 B · 4범위 |

순절약은 582와 동일한 E1 헤더·검사 선언을 과금한 전송량 차이다. 2.625 MHz wire 시간에 드라이버·조회 대기는 포함하지 않았다. ARM은 실제 577 일정에 발행된 패킷에서 복원한 현재 값과 해당 뱅크에서 마지막으로 승인된 값을 정확히 비교한다. 이전 표시 뒤 생긴 변경도 양쪽 뱅크의 stale 마스크에 누적했다. ARM이 생성한 30/52개 map 그룹과 CRC를 독립 참조와 대조했다. 두 위상의 결과가 같았다.

ARM 수치는 독립 링크한 Thumb 코드의 실행 명령 수다. 코드·상수 596 B, 컴파일러 정적 스택 72 B다. MMC577 Flash 여유 84 B보다 단독 코드가 512 B 크며, 기존 함수 교체 후 순증은 미측정이다. 검사에서는 최대 4,474 B의 nonmap 뱅크 이력과 4,518 B의 전체 출력 버퍼를 별도 확보했다. 이력을 양쪽 뱅크에 같은 방식으로 두면 8,948 B가 필요하다. 이 시험 버퍼를 제품 RAM 여유로 계산하지 않았다.

## 65816 실행 시간

각 위상의 기록된 ARM 출력 진입 시각에 소비를 허용했다. 해당 세대의 모든 레코드가 이미 WRAM에 있는 유리한 조건이다. 시작 오차는 91–161 master clock이다. 65816은 이전 뱅크 데이터를 직접 읽어 전달된 범위 CRC와 비교하고, map 스트림 CRC와 행 마스크·범위를 확인했다. 이어 연속 8 B 그룹을 묶어 실제 DMA 레지스터를 구동하고 225–245선을 확인한 뒤 전송을 시작했다. 검사와 DMA가 끝난 시각은 첫 완료 이벤트에서 한 번만 기록했다.

| 위상 · 세대 | 상속 CRC | map CRC | 행 검사·VBlank 대기·DMA | 상속 CRC 완료가 기준 최종 ACK보다 늦은 시간 |
|---|---:|---:|---:|---:|
| 1 · 952 | 57.310 ms | 6.716 ms | 59.533 ms | 15.723 ms |
| 2 · 952 | 57.310 ms | 6.716 ms | 59.343 ms | 15.995 ms |
| 1 · 954 | 52.894 ms | 10.643 ms | 75.423 ms | 12.077 ms |
| 2 · 954 | 52.894 ms | 10.641 ms | 75.464 ms | 12.261 ms |

마지막 열은 같은 세대·위상의 실제 기준 ACK 클록과 새 코드의 상속 검사 종료 클록 차이다. 이 직렬 소비 순서로는 기준보다 앞선 표시와 최종 ACK가 불가능하다. 마지막 세 작업을 모두 합쳐 제품 ACK 시간으로 쓰지 않는다. 새 SPI 큐·credit·IRQ·ROM 중재, SEAL, 최종 ACK와 연속 표시 간격은 재실행하지 않았다. 제품 경로의 변경, 새 FIT·STA 또는 실기 결과도 없다.

## 독립 검사와 복구

- 두 위상 네 경우 모두 DMA 뒤 4,096 B VRAM이 예상 map과 일치했다. 이전 세대의 SEAL → 표시 → 성공 ACK 및 다음 출력 발행 순서를 원본 기록에서 확인한 뒤에만 뱅크 이력을 제공했다.
- 상속 데이터 손상, map 값 손상, 선언 마스크 불일치, 주소 넘침, 중복 범위, CRC 도중 STOP은 거절했고 VRAM은 이전 화면과 일치했다.
- 실제 VRAM 값이 바뀐 뒤 STOP을 넣자 부분 map 상태에서 거절했다. 이 VRAM을 다음 시험의 초기값으로 넘기고 이력 유효 길이를 0으로, stale를 전체로 설정했다. ARM은 상속 선언 없이 64행 전체를 만들었고 65816은 4,096 B를 모두 복구했다.
- 새 코드가 내는 완료는 map 작업의 성공·실패다. cold 시험의 이력 폐기는 시험기가 명시했고 새 제품 STOP 제어·nonmap 전체 재전송·최종 ACK·메뉴 복구는 별도로 실행하지 않았다. 실기 기준은 MMC577이다.
