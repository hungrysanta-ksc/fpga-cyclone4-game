# 626 · 955에서 선행 map DMA로 옮길 수 있는 바이트

## 비교 방법

대조군은 625의 tables-bg ARM과 624 소비기다. 시작 master clock 3,000,000 / 3,178,684에서 같은 입력 905–957을 사용했다. 먼저 각 위상의 실제 PUSH 시각을 고정한 재생에서 두 요인을 교차했다. 이어서 실제 링크한 ARM과 65816을 SPI·IRQ·ROM 허가·큐 소비에 다시 연결해 앞 화면의 변경이 다음 화면에 미치는 효과까지 포함했다.

- **발행 순서**는 두 번째 map 페이지의 첫 여섯 행이 모두 필요하고 3행 묶음으로 나뉘는 경우, 두 192B 패킷의 주소와 데이터를 함께 바꾼다. 스캔 커서·패킷 순번·뱅크는 원래 순서를 따른다. 955에서 오프셋 2,240을 2,048보다 먼저 보냈다. 고정 재생은 이 두 패킷만 교체하며 크기·도착 시각·중간 tile을 보존한다.
- **DMA 시작 주소**는 한 번에 보낼 수 있는 1,152B보다 큰 수락 범위의 끝에서 전송한다. 부분 DMA가 끝나면 남은 앞부분의 길이만 줄인다. 중단·새 head 확인은 MDMAEN 직전에 수행한다. 실제 PPU 주소·데이터와 독립 수락 비트맵으로 관측했다.
- **1,344B 전송**은 별도 실험이다. 정확히 1,344B가 이미 수락됐고 빔을 247번 선까지 읽은 경우에만 전부 보낸다. 248번 선부터 기존 1,152B 한도를 적용한다. 이 변경은 유휴 DMA에만 적용되며 최종 표시의 246번 검사선은 기존 코드를 사용한다.

## 고정 도착에서 분리한 효과

955에서 필요한 map은 1,856B다. 기존 ARM과 소비기는 1,344B를 먼저 보내고 512B를 SEAL 뒤에 보냈다. 발행 순서만, 시작 주소만, 두 가지 모두를 바꿔도 이 합계는 같았다. 1,152B 전송의 시작점만 2,240에서 2,432로 이동했다. 후반 3,392–3,583을 먼저 보낸 만큼 앞쪽 2,240–2,431이 나중으로 이동했다. 두 위상에서 수락·선행·잔여 행의 합집합과 중복 여부를 실제 DMA로 확인했다.

| 변경 | 955 ACK 차이 (위상 1 / 2, ms) | 957 마지막 ACK 차이 (위상 1 / 2, ms) |
|---|---:|---:|
| 발행 순서만 | −0.004 / −0.025 | −0.024 / −0.011 |
| DMA 시작 주소만 | −0.047 / −0.012 | −0.001 / +0.156 |
| 두 가지 모두 | −0.053 / −0.021 | −0.011 / +0.179 |
| 1,344B 전송 | −0.153 / −0.107 | −0.001 / +0.168 |
| tile 대체 선택을 끝낸 뒤 1,344B 판정 | −0.147 / −0.118 | −0.016 / +0.156 |

두 원본 재생은 53화면의 CPU 관측 이벤트까지 원래 기록과 일치했다. 모든 고정 재생은 표시된 RGB와 map 검사를 거친다. 이 표의 마지막 ACK는 원래 미래 입력 시각을 사용하므로 채택 판정은 연속 실행 결과로 한다.

고정 도착에서 1,344B 후보는 두 위상 모두 오프셋 2,240부터 3,583까지 한 번에 썼다. 전체 선행 전송량이 1,344→1,536B, SEAL 뒤 실제 map DMA가 512→320B가 됐다. 955 최종 검사 진입도 238 / 237→235 / 235번 선으로 앞당겨졌지만 표시는 같은 VBlank였다.

## ARM과 65816을 다시 연결한 결과

같은 시작 클록의 625 tables-bg가 대조군이다. 아래 각 칸은 위상 1 / 위상 2다. 양수는 후보의 마지막 표시 ACK가 늦다는 뜻이다.

| 후보 | 955 후반 384B 중 선행 (B) | 955 SEAL 뒤 map (B) | 922 표시 VBlank | 밀집 951–955 합계 | 957 마지막 ACK 차이 (ms) |
|---|---:|---:|---:|---:|---:|
| 625 tables-bg | 192 / 192 | 512 / 512 | 92 / 92 | 20 / 20 | 0 / 0 |
| 발행 순서만 | 384 / 384 | 512 / 512 | 92 / 92 | 20 / 20 | +0.024 / +0.187 |
| DMA 시작 주소만 | 384 / 384 | 512 / 512 | 92 / 93 | 20 / 20 | −0.019 / +16.808 |
| 두 가지 모두 | 384 / 384 | 512 / 512 | 92 / 92 | 20 / 20 | −0.073 / +0.199 |
| 1,344B 전송 | 384 / 192 | 320 / 512 | 92 / 92 | 20 / 20 | −0.011 / +0.169 |
| 최종 선택 뒤 1,344B 판정 | 384 / 384 | 320 / 320 | 92 / 92 | 20 / 20 | −0.006 / +0.173 |

모든 후보가 두 위상에서 952·954·955 표시 간격 4회, 957 최종 대기 0회, 954의 첫 허가 구간 ROM 읽기 96회와 전체 53화면의 최종 ACK를 지켰다. 끝 주소 후보만 위상 2에서 923 첫 ROM 응답이 16.640ms 늦었다. 1,344B 후보는 957의 tile 16·48B와 오프셋 2,048의 map 1,152B를 두 위상에서 모두 같은 VBlank에 끝냈다. 53화면 중 1,344B 허가는 각각 5 / 4건이었다.

길이 판정 위치도 분리했다. 1,344B 후보에서 위상 1은 246번 선에 map을 직접 골랐다. 위상 2는 244번 선에 1,344B를 이미 수락했으나, 늦은 tile을 map으로 교체하는 과정에서 기존 1,152B 한도를 다시 적용했다. 동일 클록 재생에서 실제 fallback 실행과 선택된 descriptor 길이를 함께 관측했다. 후속 후보는 원래 빔 값을 스택에 보존하고 최종 X·Y 선택 뒤에 길이를 판정한다. 두 종료 경로 모두 스택을 복구한다.

후속 후보(5,364B)는 두 위상 모두 1,344B를 일곱 번씩 허가했다. 변경된 연속 일정에서 955 자체는 246 / 245번 선에 map을 직접 골랐고, 926에서는 두 위상 모두 tile을 map으로 대체한 뒤 실제로 1,344B를 보냈다(241 / 240번 선). 955의 선행 map 합계는 1,536B, 잔여 map은 320B였다. 955의 표시 ACK는 625 대비 0.169 / 0.108ms 빨랐다. 922의 표시, 923의 첫 ROM 응답과 957의 세 전송이 같은 VBlank에 끝나는 조건까지 만족했지만, 위상 2의 957 ACK는 0.173ms 늦었다. 247번 선 h=1,274 경계에서 1,344B 전송을 257번 선에 끝냈고, 별도의 두 뱅크 거부·STOP·최종 ACK 취소 시험도 통과했다.

**다음 병목은 SEAL 발행 시각이다.** 625의 955 SEAL 발행은 직전 VBlank의 246번 선이 끝난 뒤 9.84 / 9.80ms에 시작했다. 따라서 잔여 map을 192B 더 일찍 보내도 직전 VBlank에 표시하려면 ARM 발행부터 그만큼 이상 앞당겨야 한다. 951은 같은 차이가 5.86 / 6.62ms로 측정한 밀집 구간에서 가장 짧다. 두 위상 모두 마감 뒤 남은 E1은 섹션 5 일곱 건(506B)과 SEAL 한 건(187B)이었다. 이 시각은 실제 OAM DMA의 빔 위치에서 이전 VBlank 마감까지 역산했으며 검사·DMA에 필요한 시간은 별도다.

626은 채택하지 않는다. 기준은 621, 다음 시간 대조군은 625 tables-bg다. 다음 단계는 951의 일곱 패킷 각각에서 데이터 확정, ARM 준비 시작, 실제 발행, 65816 수락을 대조한다. 확정된 부분을 tile·credit 대기와 겹칠 수 있는지 시험하고, 922·923과 952·954·955·957부터 마지막 ACK까지 두 위상에서 다시 확인한다.

## 자원과 보호 경계

단순 교환을 추가한 전체 ARM은 213,004B로 Flash 한도를 12B 넘었다. 같은 3행 스캔에서 한 번 이동한 마스크의 하위 세 비트로 길이를 구한 ARM은 212,940B로 52B가 남았다. 625 대비 Flash 36B가 줄었고 .data 10,040B, .bss 18,592B였다. 실제 Thumb의 642개 마스크에서 모든 행과 바이트를 검사했다. enqueue 실패 시 첫 커서는 0을 지켰고 재초기화 뒤 두 패킷을 순서대로 복구했다.

65816 본체는 624의 5,323B에서 끝 주소 방식 5,331B, 1,344B 방식 5,352B가 됐다. 1,344B 후보의 경계 시험에서는 247번 선 h=1,274에서 허가해 257번 선에 전송을 끝냈다. 같은 1,344B를 수락해 둔 상태에서 248번 선에는 1,152B만 허가했다. 끝 주소 후보는 252번 선 h=1,272에서 1,152B를 허가해 261번 선에 마쳤고, 남은 앞쪽 192B의 주소와 길이도 확인했다. 두 후보 모두 새 head나 STOP과 새 head가 함께 들어온 경우는 허가 0회였다.

## 재현

1. `tools/prepare_nes_map626.py`에 625 tables-bg 링크를 주고 원형과 `--compact`를 각각 `tools/build_nes_trial577.ps1`로 빌드한다. `tools/check_nes_map626.py`로 compact의 실제 스캔을 검사한다. `tools/nes_map626.py` 기본과 `--whole`로 두 65816 이미지를 생성한다.
2. [625 연결 조건](nes-seal625-results.ko.md)으로 기존 소비기에는 `tools/test_nes_board611.py`, 끝 주소 소비기에는 `tools/test_nes_map626.py`, 1,344B 소비기에는 같은 도구의 `--whole`을 사용한다. `tools/nes_map626.py --after-selection`이 최종 선택 뒤 판정하는 이미지를 생성한다. 각 연결 실행이 생성한 관측 스크립트를 `tools/replay_nes_map626.py`에 지정해 기존 tables-bg의 PUSH를 재생한다. 발행만 바꾸는 재생은 `--swap`, 실제 연결 기록의 선택 경로 대조는 `--beam-log`다.
3. 각 새 소비기에서 `tools/test_nes_map616_edges.py`, `tools/test_nes_seal538_stop.py`, `tools/test_nes_raw624_stop.py`를 실행하고, 1,344B 후보에는 `tools/check_nes_map626_beam.py`도 실행한다. `tools/analyze_nes_map626.py`가 같은 map·tile 작업, 53장 RGB, STOP, 최종 ACK와 ROM 위상을 대조한다. [기계 판독 결과](../analysis/map626-verification.json)

측정 범위는 연결 시뮬레이션이다. ROM 허가는 8부트 프레임 기록을 반복하고 MCU IRQ는 명령·전송 경계에서 처리한다. 변경은 ARM·65816에 한정했고 이번 단계에서는 Quartus 재합성과 실기 시험을 수행하지 않았다. 실기 성능과 메뉴 복귀의 기준은 MMC613이다.
