# 911의 팔레트 재사용과 246선 공개 마감

## 목표

978에서 대상 뱅크의 최종 ACK로 팔레트만 재사용하면, 908의 공개·909 선행 DMA 624B·910 캡처를 유지하면서 911을 1 VBlank에 표시하고 912 최종 ACK도 앞당길 수 있는지 확인했다.

## 작업내용

첫 32B 팔레트 발행은 원래 시각에 유지했다. 이 시점에는 뒤쪽 raw 색상표가 아직 완성되지 않았다. ARM은 팔레트 512B가 확정된 뒤, 직전 두 번의 최종 ACK에서 같은 팔레트를 확정했고 이번에도 바이트가 같을 때만 남은 세 패킷을 대상 뱅크의 serial을 담은 명령 하나로 교체한다. OAM과 section 5는 따로 전송한다. 65816은 비활성 뱅크·serial·명령 크기와 선행 32B 수락을 확인한다. SEAL에서 대상과 표시 중인 뱅크의 팔레트를 16비트 단위로 전부 대조하고 64B마다 STOP을 확인한다. 통과한 화면도 실제 CGRAM 512B와 OAM 544B를 갱신한다.

원본 978, 새 ROM에 978 ARM을 연결한 대조군, 새 ROM·새 ARM 후보를 같은 입력·계측량으로 비교했다. 전체 ARM 링크와 Mesen 65816을 공유 SPI·ROM 공급 모델에 연결해 각 위상에서 905–912까지 실행했다. 진단 ROM은 실제 보드 용량을 넘으므로 아래 시간은 시뮬레이션 결과다.

## 성과

표는 위상 1 / 2 순이다. 시간 변화는 978 대비이며 음수가 앞당겨진 시각이다.

| 911 측정 항목 | 결과 |
|---|---:|
| 팔레트 SPI 전송 | 4패킷 344B → 2패킷 74B (78.5% 감소) |
| 팔레트 SPI 점유 | 1.248ms → 0.325ms (양쪽) |
| 마지막 팔레트 반환 변화 | −2.137 / −2.318ms |
| SEAL 진입 변화 | −1.029 / −1.167ms |
| 두 WRAM 뱅크의 512B 대조 | 2.717 / 2.719ms |
| 독립 검사 뒤 업로드 진입 변화 | +1.743 / +1.601ms |
| 911 공개 / 밀집 여섯 표시 간격 | 양쪽 VBlank 45의 244선 / 13회 |
| 912 최종 ACK 변화 | +0.004 / 0.000ms |

같은 ROM 대조군과 비교해도 후보의 SEAL은 1.014 / 1.064ms 일찍 시작했고 업로드 진입은 1.750 / 1.697ms 늦었다. 원본 대비 908 공개는 두 위상 모두 VBlank 38의 245선, 909 선행 전송은 624B, 910 캡처 여유는 0.209 / 0.142ms였다. 911 타일 432B는 두 위상 모두 VBlank 45에서 전송됐다. 905–912의 RGB와 map·타일 plan, 최종 CGRAM을 대조했다.

246선까지 부족한 이유는 대조 비용만으로 설명되지 않는다. **팔레트 대조 시간을 전부 제거해도** 측정된 업로드 진입 시각부터 VBlank 44의 246선 끝까지 0.080 / 0.169ms만 남는다. CGRAM 전송도 전부 생략한다고 가정해도 타일 432B·raw 192B·OAM 544B에 바이트 전송만 최소 0.435ms가 든다. 설정·공개 시간을 모두 0으로 둬도 두 위상에서 0.356 / 0.266ms가 부족하다. 이 계산은 911에서 관측한 DMA 순서를 기준으로 한다.

두 위상에서 잘못된 대상 serial, 30B만 수락된 팔레트, 명령 수락 뒤의 대상 WRAM 마지막 바이트 손상, 64B 대조 후 STOP을 주입했다. 실패 시 최종 ACK 이력 무효화와 910 화면 보존을 확인했다. STOP 실행의 두 팔레트 뱅크와 이력 영역을 초기값으로 사용하고 팔레트 바이트까지 뒤집은 재부팅에서는 cold 905·906의 전체 전송으로 화면을 복구하는지 대조했다. 메뉴 복귀는 링크한 ARM에서 정상 해제와 네 실패 분기를 시험했다. ARM은 213,068B로 한도를 76B 초과했고, 65816의 로더·압축 프로그램·벡터는 5,197B로 보드 ROM을 77B 초과했다. [위상별 시각·DMA·검사 결과](../analysis/palette987-results.json)

부분 패킷 시험의 최초 재생은 예상한 거부 이후에도 정상 실행에서 기록한 PUSH를 계속 발행해 시험 큐가 넘쳤다. 거부된 명령으로 입력을 끝낸 재생에서 두 위상 모두 30B 부분 패킷의 정상 수락, 재사용 명령의 0xE0 거부, 910 화면 보존을 확인했다.

## 후속작업

실기 기준은 MMC966, 개발 기준은 978을 유지한다. 팔레트 전송 절감만을 위한 ROM 축소는 여기서 마친다. 다음 비교는 전체 512B 대조를 표시 직전에서 제거해도 이득을 낼 수 있는지부터 계산한다. 985에서 확인한 타일 432B 선행 DMA 구간과, 마지막 OAM·201B·240B 반환을 포함한 SEAL 시각을 같은 실행에 놓는다. 확정 팔레트를 원본 입력으로 재구성하거나 수신 중 검사를 진행할 때는 후속 쓰기·손상·STOP을 검출하는 비용을 포함해야 한다. 두 위상의 246선 여유가 양수인 구조부터 ARM·65816에 연결한다.

재현 순서는 `nes_palette987.py arm`, 978과 같은 ARM 전체 빌드, `rom`, 위상별 `control`·`run`이다. `check_nes_palette987.py`의 위상별 `--fault stop` 다음에 `recover`를 실행한다. `damage`, `partial`, `owner`, `timing`을 포함해 완료한 뒤 `--out analysis/palette987-results.json`으로 집계한다.
