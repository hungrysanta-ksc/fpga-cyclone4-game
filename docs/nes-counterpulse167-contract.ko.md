# NES167 카운터 경로 개선 — 두 후보 미채택

NES167 정상 대기 수정은 기능 검증을 통과했으나 실기 ZIP은 여전히 보류다. CHECK 갱신 펄스화는 해당 경로를+0.581ns로 개선했지만 적재 카운터가-0.349ns였다. 적재 카운터 갱신·산술 분리 후 해당 경로는+0.338ns, CHECK는-0.144ns여서 두 후보 모두 미채택이다. 승인 FPGA는boundary165/map02, 다음 분석 기준은pacing167/map04(-0.003ns)를 유지한다.

## 변경과 판단

첫 후보는 기존 C1 명령 판정에서 CHECK 초기화·증가를 한 클록 펄스로 만든다. 펄스가 있으면 pending도 있다는 순차 불변식을 이용해 C2의 중복 pending 판정을 제거한다. 잘못된 응답 주소는 계속 같은 edge의 live 값으로 검사한다. 외부 명령 지연·SPI ID74·상태 snapshot·오류 우선순위는 바꾸지 않는다.

첫 배치의 최악 경로는 READY 상태→적재 수 loaded_bytes였다. 갱신 조건이 덧셈 입력까지 이어져6개 논리 단계를 거쳤다. 두 번째 후보는 첫 수정에 더해 적재 수의 갱신 허용과 산술을 분리한다.19비트 prefix XOR 증가, clear 우선순위, 레지스터 enable을 사용하며 게이트 클록은 없다. count_complete의 계산 edge도 그대로다.

|후보|LE / LAB / M9K|CHECK 카운터|적재 카운터|전체 setup|
|---|---|---:|---:|---:|
|map01 갱신 펄스|14995 / 961 /35|+0.581ns|-0.349ns|-0.349ns|
|map02 + 적재 갱신 분리|14995 / 960 /35|-0.144ns|+0.338ns|-0.144ns|

두 후보 모두 용량과 기능 시험은 통과했으나 실제 클록 setup은 실패했다. 기존 분석 기준-0.003ns보다 나빠 채택하지 않는다. 국소 경로 개선과 전체 배치 통과를 구분한다. seed1, Standard Fit, SDC·클록·false-path는 바꾸지 않았다. 각 후보는 근거 있는 변경 후 한 번만 전체 배치했고 재현 입력은 배치 없이 바이트 비교했다.60/59개 입력은 pacing167/map04와 같다.

## 필요한 경계 검증

- CHECK의 전체19비트 카운터 값과 idle/pending·오류·응답·reset·명령 조합1048576조건에서 같은 edge 효과가 일치했다.
- 실제 SPI219프레임,1125909관측 edge에서100읽기/7ACK/19응답 비트 오류/72취소/2겹침을 검증했다. 매 edge 펄스와 pending 관계 및 기존 레지스터 효과를 비교했다. 한 클록 뒤 펄스가 남는 잘못된 회로도 검출했다.
- 적재 카운터 변경은294912조건/1056연속 쓰기·중단 시나리오와 모든524288카운터 값에서 통과했다. STOP clear를 빠뜨린 회로는 거부했다.
- 두 변경을 합친 map02에 실제 SPI 시험을 새로 실행했다. CHECK 단독1048576조건은 동일 SPI 바이트로 재사용했다. 로더 ready/적재 수 일부를 시험용으로 주입하므로 전체 ROM 적재나 게임 실기는 아니다.
- 첫 연결 시험은 이전 벤치가 이제 wire인 loader.state를 쓰려 해 컴파일 실패했다. 현재 저장소인 phase에 READY를 주입하도록 고친 test02가 통과했다. test01 원본과 실행 도구를 보존했다.
- 앞서 통과한167 fill/export·ARM·SNES 코드는 변경하지 않았다. 새 IO/reset·ASM/CPF·실기 패키지는 실행하지 않았다. GBC·164 복원·세이브 SRAM은 보존했다.

## 다음 작업

같은 클록 카운터 식·seed·설정으로 전체 FIT를 다시 반복하지 않는다. MCU의 기존2us SS 간격 안에서 오류 판정(C2)과 CHECK 카운터 반영(C3)을 분리할 수 있는지 먼저 계약을 정한다. fault/STOP/reset 우선순위, 응답과 명령 겹침, 주소·상태 snapshot이 관측 가능한 edge, SPI ID/MCU 호환성을 명시한다. 같은 edge 등가로 주장하거나 false path로 완화하지 않는다. 가능하면 변경 경계만 검증한 뒤 한 번 배치한다. 불가하면 근거와 함께 영역 배치 보존을 검토한다. 내부 타이밍과 조건부 IO/reset 통과 후167 MCU·미변경 SNES 근거를 재사용해 패키지와 SMB3 실기로 간다.166·044 재시험은 요청하지 않는다.

이 작업은 실기 영상 구현을 막는 FPGA 내부 타이밍을 개선하는 작업이다. 화면 복구나60fps를 달성한 것으로 평가하지 않는다. 현재 추가 실기 시험은 필요 없다.
