# 536. MMC533의 map 발행·credit 반환·유휴 DMA

기준은 실기 MMC533의 ARM과 128B map 소비기다. 입력이 시작된 시각을 각 세대의 0ms로 삼았다. 910은 마지막 선행 전송 직후의 map 바이트 오프셋 1,216, 951은 2,560을 추적했다. 양쪽 모두 대상 뱅크의 64B 행 경계다.

## 계측 경계

- ARM의 `packet_wire` 진입, bulk 우선 처리를 거친 `nes_window184_enqueue` 진입, 실제 E1 SPI 시작, FPGA 큐 PUSH, 65816 head 읽기, 검사를 마친 버스 ACK, 그 ACK를 포함한 첫 E0 응답 완료를 순서대로 대조했다. E0 응답이 보고한 누적 sent·retired는 각 SPI 시작 시각까지의 PUSH·버스 ACK 개수와 대조했다. 버스 ACK에서 반환된 credit을 ARM이 다음 E0를 읽기까지 모르고 있을 수 있다. 큐 credit 반환은 최종 표시 ACK와 별개의 이벤트다.
- VBlank는 실제 PPU DMA의 빔 좌표와 프레임 번호에서 복원했다. 225번부터 map 시작을 허용하는 마지막 254번까지, 열린 트랜잭션에서 SEAL 발행 전만 포함했다. 큐가 비었던 시간, 실제 selector 진입, 빈 목록 반환, STOP·새 head 재확인, DMA grant를 따로 기록했다. 폴링과 DMA 설정 시간 때문에 빈 구간 전체를 전송에 쓸 수 있는 것은 아니다.

**910.** 30.7–32.8ms 부근의 VBlank에서는 앞의 192B를 모두 옮긴 뒤 빈 명령 목록을 22/25회 확인했다. 다음 패킷을 만드는 호출은 36.71ms에야 시작됐다. 이어 기존 bulk 우선 처리(E8·bulk E1·E0)를 거쳐 38.17ms에 enqueue했다. 이때 큐 점유는 실제·캐시 모두 0이었다. 이후 마지막 VBlank에서는 그 행을 이미 수락했지만 작은 BG tile 16B가 우선됐고, map의 재확인 시점에 새 head가 위상별 2/1회 먼저 들어왔다.

**951.** 오프셋 2,560을 담은 패킷은 44.30ms의 enqueue에서 캐시 점유 4, 실제 점유 1이었다. 발행에 필요한 credit은 이미 29.22/29.02ms에 반환됐고 E0 조회는 양쪽 모두 44.307–44.416ms였다. 행은 46.26/46.24ms에 수락돼 47.32/47.33ms의 map 허용 구간을 앞섰다. 여기서 두 위상 모두 네 번에 512B를 옮겼다. 다음 약 63.96–65.88ms 구간은 시작 점유가 3이었고 section 5의 RLE·DATA 서비스 중 큐가 비지 않아 selector 진입이 0회였다.

## 두 변경의 분리 검증

첫 후보는 BG 계획 중 최대 두 번 map을 제안한다. 두 번째 제안은 첫 패킷이 실제 발행됐고 다음 패킷의 최대 세 행까지 값이 확정된 뒤에만 가능하다. 첫 제안 이후 최소 세 그룹을 더 처리하고, 다음 dirty/stale 비트가 확정된 하위 행에 있는지 확인한다. BG 처리가 전부 끝난 경우에는 전체 행이 안정적이다. 반환 credit을 확인해 한 슬롯을 남기고, ready bulk 및 유효한 이전 bulk 완료 검사를 우선한다. 65816 수신 코드·map 패킷 경계는 MMC533과 같다.

두 번째 후보는 같은 map 발행기를 사용하되 최대 384B의 compact raw CHR만 최대 240B DATA 패킷으로 나눈다. 패킷 전체가 같은 단어인 경우에는 기존 RLE를 유지한다. 일부 반복 바이트를 리터럴로 보내는 만큼 늘어난 공유 SPI 비용과 줄어든 패킷 처리 시간을 함께 계산했다. 모든 세대에서 section 5를 독립 복원해 바이트별 주소와 값을 비교했고, 그 외 패킷은 sequence를 제외한 내용과 개수가 같아야 통과한다.

910에서 두 번째 map 선행만으로도 대상 행 수락은 39.96ms에서 33.39/33.42ms로 앞당겨졌다. 첫 위상의 당시 map 허용 구간에는 들어왔고, 둘째 위상에서는 구간이 먼저 닫혔다. compact raw까지 묶은 경우에는 두 위상 모두 910의 최종 대기가 0회가 됐다. 951의 마지막 구간에서도 128B씩 실제 전송됐으나 최종 대기는 각각 한 번 남았다.

53화면의 E1 패킷은 1,689→1,543개, E1 전송량은 171,401→182,479B였다. 긴 반복 구간을 리터럴로 보낸 추가 비용이 포함된다. ARM Flash는 기준 212,420B, 선행만 212,548B, 결합 212,616B이고 남은 여유는 각각 572/444/376B다. BSS는 모두 18,592B다. 533의 FPGA와 65816을 그대로 사용했다.

**판정.** 결합 후보의 957 ACK는 두 위상 모두 약 33.27ms 빨랐다. 그러나 951–955는 31→33 VBlank로 늘어 실기 기준은 MMC533을 유지한다. 추가된 두 VBlank는 각 위상에서 954·955가 하나씩 차지했다. 두 화면 모두 직전 표시부터 SEAL head를 읽기까지가 5→6 VBlank였고 SEAL 읽기부터 표시까지는 1 VBlank 그대로였다. 다음에는 이 두 화면의 SEAL 도착 전 시간을 입력 시작 위상·ROM 공급·출력 발행으로 나눠, 이른 map 제안이나 compact raw 묶음을 적용할 조건을 검증한다.

## 검증 범위

두 시작 클록 3,000,000과 3,178,684에서 각각 905–957을 연속 실행했다. MMC533 기준의 표시·ACK 이벤트는 PR146의 선택 trace와 일치해야 한다. 동일한 65816에서 각 후보의 실제 ARM 명령, SysTick IRQ, 공유 SPI와 ROM 허용 일정을 사용했다. 독립 재생으로 53화면의 소비 이벤트 시각과 RGB 및 선행 tile 기록을 확인했다. 두 후보 각각 링크된 ARM의 두 번째 제안 11건, 기존 첫 제안 9건과 END credit 경계 6건을 검증했다. 별도로 양 뱅크의 STOP·새 head 우선, DMA 중 STOP, cold 복구, 독립 검증 실패 등 22건을 각 후보가 생성한 패킷으로 시험했다. FPGA와 65816은 MMC533 전달본과 같으며, 새 실기 FPS는 측정하지 않았다.
