# 912 후속 타일·section 5 수신 비용

## 목표

978의 두 슬롯·공유 SPI 일정에서 후속 OBJ 다섯 개와 section 5의 201B·240B 패킷을 함께 조사했다. 목표는 912 그룹을 VBlank 46 시작 전에 준비하고 246선 안에 공개해 최종 ACK까지 앞당기는 것이다.

## 작업내용

공통 대조군은 1004의 일반 패킷 우선 두 슬롯 스케줄러와 978의 65816이다. 912 BEGIN에서 수신 코드만 WRAM에 설치해 타일만, section 5만, 둘 다 적용한 경우를 분리했다. 905부터 두 시작 위상을 각각 재생했다.

- OBJ 수신은 2–9개의 연속 32B 단위가 차지하는 비트를 1–2바이트 마스크로 검사하고 두 bitmap에 기록한다. 이미 세워진 비트가 있으면 쓰기 전에 원래 루프로 돌아가 부분 기록과 거부 순서까지 보존한다. 다른 크기는 원래 루프로 처리한다.
- section 5의 뒤쪽 리터럴은 원래 패킷 길이·identity 검사 후 조밀한 범위에 전용 경로를 사용한다. 기존 끝 위치, 영 길이, 덧셈 넘침, section 상한을 확인해 같은 inactive WRAM 목적지로 DMA한다. 원래 수락·SEAL·STOP 경로를 계속 사용한다.
- 별도의 계산에서 SPI와 65816을 동시에 동작시키며 타일·팔레트·OAM·section 5 내부 순서를 지키는 모든 교차 발행 순서를 비교했다. CPU는 1002에서 계측한 패킷별 비용의 낙관적 추정치, 선로는 2.625MHz E1 전송 바이트만 청구했다. 모든 타일이 첫 E9에서 준비되고 다른 SPI 거래·조회·그룹 설정 비용은 0으로 두었다. 두 슬롯도 전송 완료 시점에만 확보하면 된다. 이 계산은 다른 ABI나 실제 보드의 하한 보증에 사용할 수 없다.

## 성과

위상 1 / 2 순서이며 시간은 SNES 마스터클록이다. 후속 타일 다섯 개의 978 수신 시간 65,254 / 65,226 중 범위 검사·마스크 준비까지 23,020 / 23,024, 마스크·주소 처리에서 descriptor 등록 진입까지 19,446 / 19,270, 나머지 등록·복사·반환에 22,788 / 22,932가 들었다. 단일 패킷으로는 288B OBJ(token 35)가 17,444 / 17,408로 가장 컸다. section 5 두 패킷의 합은 15,792 / 15,794였고, 그중 범위 처리와 WRAM 복사에 8,284 / 8,278이 들었다.

결합 후보에서 token 35는 14,312 / 14,304클록으로 줄었다. 32B OBJ에서는 새 분기 비용이 생겼다. 전체 일곱 패킷에서는 4,726 / 4,764클록(0.220 / 0.222ms)을 절감했다. 그룹 준비를 0.212 / 0.157ms 앞당겼으나 공개 VBlank는 같았다. 원래 978 ARM 발행 기록의 912 ACK와 비교해도 결합 후보가 6,380 / 6,468클록 늦었다. 새 발행 정책의 실기 FPS는 측정하지 않았다.

낙관적 SPI·CPU 계산에서 기존 수신 비용으로는 SEAL 검사 후 업로드 진입조차 VB46 시작보다 26,263 / 25,975클록 늦었다. 일곱 패킷의 모델 CPU 비용만 같은 비율로 줄일 경우 57.8 / 58.3% 이하로 남겨야 업로드 진입이 VB46 시작보다 빨라진다(0.1% 단위). 일곱 비용을 전부 0으로 두면 20,392 / 20,680클록의 여유가 나온다. 여기에는 실제 E0·E8·그룹 준비 비용이 추가된다. 이번 실측 5.83 / 5.88%와 모델의 비율은 각각 실측 수신 시간과 낙관적 CPU 추정치를 분모로 사용한다.

두 위상에서 908 공개, 909 선행 DMA 624B, 910 마지막 D2 및 905–911 수신 이벤트를 보존했다. 정상 재생 8건의 905–912 RGB는 978과 일치했다. 중복 비트·불연속 section 5·잘못된 SEAL·디코드 중 STOP에서 912 성공 ACK와 공개가 차단되고 911 화면을 유지했다. 중복 비트는 stock과 후보 모두 token 35의 본문을 읽거나 뱅크를 반환하기 전에 거부했다. 최초 중복 주입에서는 시험 도구가 모든 타일 응답에 성공을 요구해 중단됐다. 해당 오류 주입에서만 E0 오류와 읽기 0B·소비 토큰 없음 조건을 적용해 재검증했다. 계측 주입 LUT에 대한 Mesen 초기화 추적 경고가 있어, 수정한 중복 시험은 65816이 lookup 경로에 진입할 때 WRAM의 열 개 마스크 값을 원본과 대조한다. 코드와 표를 실제 포맷으로 압축하면 결합 후보는 정적 ROM 공간을 165B 초과한다. ## 후속작업

978을 유지한다. 같은 일곱 패킷의 범위 검사만 더 다듬기보다, tile descriptor마다 반복되는 헤더·identity 처리와 마지막 section 5의 전송을 어느 정도 함께 없애야 하는지부터 계산한다. 첫 비교는 연속 타일 descriptor를 하나의 헤더로 받되 각 token의 뱅크 반환과 독립 범위 검사를 유지하는 경우다. 앞 타일의 반환을 늦춰 다음 타일 생산을 막는 비용, 실제 E0·E8, section 5 송신을 함께 청구한 뒤 구현 여부를 결정한다.

재현은 978·1002·1004 TEMP 자료에서 `tools/nes_receive1005.py TEMP PHASE MODE`로 stock·tile·section·both를 위상 1·2에 각각 실행한다. both에는 `--fault duplicate|offset|bad_seal|stop_decode`, stock에는 duplicate를 각각 적용한다. `tools/check_nes_receive1005.py TEMP analysis/receive1005-results.json`이 재생·패킹·낙관적 일정 계산을 대조한다.
