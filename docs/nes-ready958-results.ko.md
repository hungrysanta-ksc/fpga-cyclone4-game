# MMC955의 OBJ 행 확정과 ROM·표시 마감 (958)

## 목표

MMC956 실기의 576B OBJ 묶음에서 관찰한 허가 대기가 E9 선행 발행으로 줄어들고, 그 이득이 최종 표시까지 이어지는지 조사했다. 실기 기준은 MMC955다.

## 작업내용

모험도 4 무입력 데모 후반에서 OBJ 18개가 한 묶음(576B)을 이루는 원본 화면 3412(재생 세대 906)를 골랐다. MMC956 실기 세대 1410의 원본 프레임 번호와 개별 CHR 태그는 BIN에 없다. 재생의 네 번째·열한 번째 OBJ는 952 RTL에서 각각 81클록에 끝났고 그동안 공유 ROM 허가는 0회였다. 실기에서는 각각 9회·8회였다.

두 시작 위상에서 MMC955 최종 ARM의 `nes_plan200_emit` 진입 시 완성된 행·슬롯·태그를 읽어 실제 E9 전송 내용과 대조했다. 계측 전후 SPI 이벤트·65816 소비 기록·타일 생산 기록은 바이트 단위로 같았다. 이전 세대 905부터 952 RTL의 캐시를 이어서 재생했고, 906의 대상 E9는 SPI 바이트별 시각·쓰기 허가·CRC·수락 개수를 확인했다. 여덟 화면의 RGB 값과 22,512B의 VRAM DMA 총량도 대조했다.

## 성과

여섯 번째 E9에 든 네 번째 OBJ(tag 3582)와 열한 번째 OBJ(tag 3576)는 두 위상 모두 각각 실제 E9 발행 **12.973ms, 12.603ms 전**에 완성됐다. 이 시각은 완성된 descriptor를 ARM에서 직접 관측한 시점이다. 보드의 수신 허가부터 ROM 구간 끝까지는 0.464ms였다. 기존 E8 확인부터 127B E9 수락까지의 실측 재생 비용을 적용하면, 허가가 열린 즉시 E8을 표본화해도 양쪽 모두 약 92µs 부족했다. 실제 수락은 마감보다 0.252 / 0.293ms 늦었다.

| 같은 ROM·동일 작업의 변경 | 위상 1 | 위상 2 |
|---|---:|---:|
| OBJ 혼합 묶음을 15→12개로 제한한 ARM. 576B 묶음의 RTL 준비 시각 변화 | 0.000ms | +0.009ms |
| 같은 후보의 912 최종 ACK 변화 | +0.352ms | +0.173ms |
| 952 RTL의 실제 수신 허가를 ARM에 반영. 일곱 번째 E9의 발행 변화 | −16.269ms | −15.141ms |
| 같은 대조의 576B OBJ 준비 변화 (RTL) | −16.493ms | −16.484ms |
| 같은 대조의 마지막 64B OBJ 준비 변화 (RTL) | −13.456ms | −13.564ms |
| 같은 대조의 906 SEAL 수락 / 화면 공개 변화 (65816) | −7.389 / +15.946ms | −6.845 / +15.958ms |
| 같은 대조의 밀집 여섯 표시 간격 합 / 912 최종 ACK 변화 | 14→14 VBlank / +16.649ms | 14→15 VBlank / +33.629ms |

변화량은 같은 공급 모델의 MMC955 대조군 대비이며 음수가 빠르다. 12개 후보는 여섯 번째 E9를 127→103B, 일곱 번째를 83→107B로 바꿨다. 합계는 210B였다. ARM Flash는 212,980→212,988B로 한도까지 4B가 남았다. 표시 간격 합은 양쪽 모두 14회였고 최종 ACK는 늦어져 후보를 채택하지 않았다.

기존 보드가 이미 내는 E8의 쓰기 허가를 재생에 반영하자, 동일한 ARM이 동일한 일곱 번째 E9를 더 일찍 발행했다. 이 묶음에 든 17번째 OBJ(tag 6264)가 먼저 공급됐다. 두 위상 모두 보드 RTL에서 75B 본문 전체의 CRC·수락과 576B 타일 출력을 확인했다. 마지막 E8 차이까지 반영한 뒤 세대 906의 응답은 위상별 173개·172개 모두 일치했다. 마지막 보정은 DMA·공개·최종 ACK 시각에 영향을 주지 않았다. 이 시간 차이는 재생 모델 보정으로 얻은 값이다.

**공개를 늦춘 지점은 SEAL 뒤 첫 VBlank 대기였다.** 65816은 위상 1의 33번째 VBlank 226선, 위상 2의 34번째 VBlank 239선에 업로드 대기 루틴으로 들어갔다. 이미 열린 해당 VBlank의 PPU DMA는 0B였다. 대조군은 같은 구간에서 각각 2,176B를 보냈다. 보정 후에는 다음 225선부터 전송했고 253선에서 다시 기다려, 906 공개가 두 위상 모두 한 VBlank 늦어졌다. [재생 수치 및 DMA 목록](../analysis/ready958-results.json)

## 후속작업

959에서 남은 VBlank에 1,920B map을 보내고 세대 912의 최종 ACK까지 추적했다. [단일 DMA와 정적 ROM 비교](nes-blank959-results.ko.md)

실제 65816의 VBlank 대기 진입에서 빔 위치, 수락된 DMA 길이, 설정 비용과 독립 검사 완료를 함께 확인한다. 226선·239선에 남은 시간 안에 비활성 VRAM으로 완결 가능한 범위만 보내는 대조를 우선한다. 두 위상의 DMA 마지막 쓰기·공개·912 최종 ACK, STOP·새 패킷 우선과 메뉴 복귀를 함께 확인한 뒤 실기판을 결정한다.

재현할 때는 `tools/nes_ready958.py TEMP PHASE`로 읽기 전용 계측 대조군을 생성한다. `--policy prepare` 후 기존 `build_nes_trial577.ps1`으로 `probes/nes-ready958-short/link`를 링크하고 두 위상에서 `--policy control`과 `--policy short`를 실행한다. FLOAT 래퍼에서 `tools/check_nes_ready958.ps1`을 `NES_958_RTL=mark`와 `short`로 각각 실행한다. 이어 `credit`과 `closed`를 순서대로 각각 ARM의 `--policy`와 RTL의 `NES_958_RTL`에 적용하고 `analyze_nes_ready958.py TEMP MMC956_BIN`으로 집계한다.
