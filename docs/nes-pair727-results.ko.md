# NES727 인접 map 수락·진행 제어 통합

## 목표

726C의 인접192B 두 패킷을 유지하면서 정상판 Flash24B 초과를 해소하고,723C의384B 연속 DMA·BG ROM 마감을 회복한다. STOP·독립 검사·최종 ACK·메뉴 경계와951/911/952/957 보호 조건,두 시작 위상의952–957 표시 간격·마지막 ACK를 함께 비교한다.

## 작업내용

단독 호출되는 `nes_sink527_early`를 삭제하고 그 cursor·credit·producer 검사를 실제 소유자인 runtime의 `offer527`에 통합했다. runtime 초기화는 `sink.plan=&plan`을 묶으므로 다른 소유자의 상태를 대체하는 변경이 아니다. `map527`의 기존 진행 제어가 쌍의 다음 패킷 허가도 한 번에 계산하고,중복 pair 갱신을 제거한다. 기존 mode0 출력·mode1 행 offer·mode2 인접 완료와 mode3 warm 완료 쌍을 유지한다.

처음에는 checked-empty producer 응답과 queue 여유가 필요하다. 이후 정확히 인접한192B 두 패킷에만 같은 허가를 쓰며,각 E1의 실제 queue credit·CRC·STOP 검사는 그대로다. gap·짧은 범위는 쌍을 늘리지 않고,첫 패킷 뒤 STOP/실패가 나면 두 번째 발행과 최종 ACK를 허용하지 않는다. cold·부분 전송 복구·BG 행 flush·ROM 공급 코드는 유지한다. 새 persistent RAM·SPI ABI·FPGA·65816 수정은 없다.

723C와 같은 시작7288416/7467100,ROM 위상0,CPI2/84MHz,공유SPI·IRQ·기존 ROM 허가 달력으로 실제 링크 M4와 Mesen65816을53화면씩 실행했다. 두 위상106화면의 map·tile·plan·픽셀이 같고 각114352B VRAM DMA를 완료했다. 실제 명령 실행을 포함한 일정 모델이며,전체 NES/PSRAM RTL 동시실행·실기 FPS·물리 메뉴 시험은 아니다.

## 성과

**Flash24B 초과와384B DMA·BG 마감 회복은 달성했다. 요청한952–957 평균과 마지막 ACK도 두 위상에서 조금 빨라졌다. 그러나 VBlank 수는 줄지 않았고,개별 표시 간격과 기존951–955 집계에는 회귀가 있어 성능 채택은 보류한다.** 선택707D·기존 ARM/65816과723C 시간 대조군을 유지하고727을 자원 통과 연구 후보로 보존한다.

723C의 정상/장시간 Flash212992/212948B와 같고,같은 함수 경계4698B보다2B 작다. alignment를 포함한 전체 Flash와 함수 크기의 차이를 별도로 계산했다. `.data1048B/.ahbram8992B/.bss19548B(정상)·19556B(장시간)`와 관측 stack low `0x2000f814`도 동일하다. 같은 이름의 다른 static `status` 함수를 섞지 않고 기존278B 함수를 비용 경계에 포함한다.

FPGA·SDC는707D와 같으므로 기존 전체 Lite FIT15322LE·962/963LAB·56/56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 같은 검증 범위로 승계한다. 새 FIT·STA·회로 절감·외부IO 승인 확대는 없다.

### 두 위상 시간

아래 변화는 모두 **723C 대비**다. µs 수준 모델 변화로 실기 가속이나 처리 여유를 보장하지 않는다.

| 항목 |위상1|위상2|
|---|---:|---:|
|952–957 각 표시 간격(VBlank)|3/3/3/3/3/3 유지|3/3/3/3/3/3 유지|
|952–957 합계|18→18|18→18|
|952–957 평균 간격 변화|−0.006689ms|−0.002313ms|
|957 마지막 ACK 변화|−0.018531ms|−0.000559ms|
|기존951–955 평균 변화|+0.003259ms|+0.004377ms|
|952 선행 map DMA|1920B 유지|1920B 유지|
|953 BG 첫/마지막 ROM 허가 구간|169/169 유지|170/170 유지|

951은236선·3VBlank,911은242선·2VBlank,952는3VBlank,957 최종대기는0회다. 기존908/934/940/943 표시2회와 다음 입력7블록도 유지했다. 952의offset1024/1216 두192B가 실제384B DMA로 합쳐졌고,후속offset2048의1536B도 유지했다. 956/957 선행 map1024/2048B도 유지한다.

952의 두 번째 map ACK는 직전 표시 기준25.721→20.229ms/25.694→20.348ms로 약5.49/5.35ms 앞당겨졌다. 하지만952 자체 표시 간격은+0.025981/+0.023932ms이며,위상2의953은+0.133443ms다. **평균 감소가 모든 프레임의 감소를 뜻하지 않는다.** 957 마지막 ACK의 위상2 차이는 약0.56µs뿐이며 실제 MCU·IRQ 오차 여유로 취급하지 않는다.

ARM 명령은−22905/−21529이지만 SPI 총량은+164/+88B다. 데이터 작업량은 같고 진행 조회 횟수·시각이 바뀌었으므로,명령 감소만 전체 처리량 개선으로 계산하지 않는다. 기계 판정은 요청한952–957 평균/ACK 조건과 기존951–955 채택 조건을 별도로 기록한다. 전자는 두 위상 통과,후자는 미통과다.

### 남은 병목: 이미 수락된 map과 후속 OBJ의 빈 큐 기회

위상2의953에서offset3072/3264 map 두 패킷은 각각124/136선에 수락됐다(723C는111/124선). 따라서 이384B의 병목은 목표 VBlank 전에 전혀 도착하지 못한 것이 아니다.

723C는172번째 프레임240선에 해당384B DMA를 시작한 뒤245선에 OBJ64B를 수락했다. 727은240선에 OBJ64B를 먼저 수락해 새 패킷 우선 규칙을 지켰고,그384B는 최종 업로드로 남았다. 실제 기록은 다음과 같다.

|위상2·953|723C|727|
|---|---:|---:|
|3072/384B idle DMA 요청|61438014 clock·240선|없음|
|후속 OBJ64B load|61444846 clock·245선|61437792 clock·240선|
|선행 map 합계|832B|448B|
|SEAL load|121선|117선|
|최종 공개|237선|240선|

727은 SEAL이 더 일찍 수락됐어도 최종 DMA가 늘어 공개가 늦었다. BG ROM은 같은 구간에서 끝나므로 이 현상을 BG 마감 실패로 분류하지 않는다. 수신 시각만 앞당기는 수정도 이 빈 큐 소비 경쟁을 해결하지 못한다. 모델 내 인과 추적이며 실기 화면 깨짐의 원인 주장도 아니다.

### 검증과 보존

정상/장시간 각35수락 경계,기존DMA gate10·마감17·END 소유권7·입력credit9·runtime16·bulk/STOP 대조24·메뉴 각9조건을 통과했다. 별도로726C와32개의 linked map 순회 조건을 대조해 모드0/1/2/3,빈 mask·gap·짧은 두 번째 범위·32/64비트 경계의 패킷·CRC·cursor·pair·sequence가 일치했다. 독립 peer가 실제 payload와4credit를 검사한다. 전체106화면에서도 독립 수락·내용·coverage·최종 ACK·두 슬롯 한도를 통과했다. 기존 CRC·cold 복원·메뉴 코드의 미변경 근거를 승계하며 물리 메뉴 성공을 새로 주장하지 않는다.

정상/장시간 전체 빌드와 원시 로그,준비 recipe,32조건 비교,106화면 기록과 source diff를 보관했다. 이전726 실패 산출물과 정상 선택본은 덮지 않았다.

## 후속작업

1. 727의 자원 통과 쌍 발행·723C 마감 대조를 보존한다. Flash 여유0B·같은 경계 여유4B·새RAM0B·ROM 여유26B 안에서 다음 변경도 실제 삭제와 함께 계산한다. 이번µs 차이만으로 실기 성능판을 만들지 않는다.
2. 다음 대상은953의 수락 완료 map384B와 후속 OBJ64B 사이 실제 DMA 진행·queue credit 경계다. 두 패킷의 생산/수락을 다시 앞당기는 대신,이미 완료된 map의 빈 큐 DMA 기회를 소비하는 발행을 구분한다. STOP·새 패킷 우선은 유지하며,고정 지연·세대/위상별 예외·무조건 OBJ 우선·725 소비기 반복 poll은 재시도하지 않는다.
3. 남은 map이 있을 때 실제 진행 응답과 후속 발행을 결합할 수 있는지 먼저 원시 시각으로 예산을 잡는다. 목표는953의 선행832B 회복과 실제 공개/VBlank 감소이며,952의384B·BG ROM 구간·951/911/952/957·7블록을 함께 보호한다. 부분 평균만 선택하지 않는다.
4. 새 설치본은 없다. 다음 실기 전달 때 새 파일명60초/장시간판,RESTORE 제외,5–40초/40–55초 집계를 유지한다.
