# NES185 실기 결과 — 입력 유지 개선, 평균 표시율은 비슷함

사용자는 **사운드 정상, 버튼 길게 누르기도 고쳐진 것 같음, 프레임 소폭 향상**을 보고했다. 체감 개선은 그대로 기록한다. 전체 표시 완료율에서는 향상이 확인되지 않았으며, 같은 장면·입력을 재생한 통제 비교도 아니다. 새 영상은 없다.

원본 두 TXT는 private `probes/nes-game185-hardware01/raw`에 바이트 그대로 보관했다. [검증 JSON](../analysis/game185-hardware01-verification.json)은 원본 해시·100개 진행 단계·상태·비교 계산을 포함한다. 기존185 배포판과 완료 증거는 변경하지 않았다.

## 표시와 처리 비용

| 항목 | NES184 | NES185 |
|---|---:|---:|
| DISPLAY 구간 | 60,060ms | 60,060ms |
| 최종 표시 완료 | 183회 | 180회 |
| 전체 평균 표시 완료율 | 3.047회/s | 2.997회/s |
| 수신 누적 | 26.87s | 28.19s |
| 변환·CHR 전송 누적 | 7.22s | 7.76s |
| 나머지 전송·표시 완료 대기 누적 | 25.53s | 23.53s |
| SPI 거래 수 | 247,955 | 269,524 |
| SPI clocked bytes | 7,867,303 | 7,514,384 |
| 표시 큐 전송·소비 패킷 | 9,051 | 14,333 |

표시 완료율은 약1.64% 낮고 두 시험 모두 약3회/s다. 이는 CRT 주사율이나 특정 장면의 순간 FPS가 아니다. 사용자가 느낀 국소적 개선을 부정하거나 평균 수치만으로 성능 퇴행을 확정하지 않는다. 평균 약333.7ms/표시 완료라 목표16.7ms와는 여전히 차이가 크다.

clocked bytes는 약4.49% 감소했고 후반 전송·표시 대기는2초 줄었다. 반면 표시 큐 패킷은58.36%, 전체 SPI 거래는8.70% 늘었다. **64바이트마다 COPY 요청을 보내는 처리 비용이 데이터 절약 효과를 일부 상쇄했을 가능성**이 있다. 다만 누적 시간에는 장면 변화와 작업량이 섞이고, COPY별 시간·개수나 순수 map payload가 기록되지 않아 원인을 확정하지 않는다. clocked bytes는 폴링·헤더도 포함한다. 앞선 보관 map3952→1214바이트는 실제 플레이 전체 비용의 감소율이 아니었다.

현재 계측의 receive에는 수신 대기·읽기·prepare, build에는 변환과 CHR 전송, seal에는 나머지 데이터 전송과 최종 표시 완료 대기가 포함된다. 수신 누적28.19초도 크므로 SNES 복사 명령만 최적화하면60fps가 된다고 보지 않는다. 실패한 마지막 작업·guard·측정 경계와10ms 해상도 때문에 세 구간 합59.48초와 DISPLAY60.06초는 같지 않다.

## 종료·사운드·입력

BEGIN181 / END180 / COMMIT180 / ABORT0. 마지막 표시 generation306,59.93초이고 다음 generation307 처리 중 제한 시간이 종료됐다. `native_result=1`은60초 deadline이며, 수신 중 guard가 중단되면서 receiver21이 남은 기존 경로와 일치한다. 로그에 CRC 원인이 별도로 기록된 것은 아니다.

ROM/검증/STOP/sink/video/window 오류0. 큐 sent=retired=14333, flags2/최종ACK1. 마지막으로 확인한 큐 상태이며 모든 순간의 추적은 아니다. STOP·기본 코어 복원·295680ms MENU_PREPARED까지 기록됐다. 로그는 reset-held 준비 단계에서 끝나므로 실제 파일 메뉴가 보였는지는 별도 사용자 보고 없이 확정하지 않는다.

SPC A9/unmute1과 사용자 청취가 함께 있어 이번 시험의 사운드는 정상으로 기록한다. 입력 유지 수정은 실기에서 개선된 것으로 보인다는 사용자 관측을 얻었다. 마지막16개 변경 입력에는 A/RIGHT의 누름·해제와 마지막 DOWN이 있으며, 마지막 DOWN 이후 해제 항목은 없다. 물리 누름 시간과 동기화된 기록이 없어 유지 시간을 계산하거나 모든 버튼의 입력 품질까지 승인하지 않는다. 같은 시험을 입력만을 위해 다시 요청할 필요는 없다.

## 다음 작업

사운드·입력 수정을 유지하고, **연속된 미변경 구간을 여러64바이트 COPY 요청 대신 묶어서 전달하는 방법**을 우선 검토한다. 실행 중 STOP·시간·패드 service의 최대 지연을 유지해야 하므로 긴 무조건 복사로 바꾸지 않는다. SNES body3776/3776과 ARM 잔여1204바이트 안에서 구현 가능성·실제 요청 수·전체 처리 비용을 함께 평가한다.

이후 receive/build/seal 전체에서 CHR 중복 전송과 capture·수신·표시의 직렬 수명을 줄이는 방향을 이어간다. 기존 RLE·4패킷 큐·로컬 VRAM 차등을 다시 구현하지 않고, 세대/소유권·완성 화면 ACK를 보존한다. 새 관측기나 같은185/044·불변 FIT 시험을 추가하지 않는다. 이번 턴은 결과 기록이며 새 펌웨어/FPGA/ZIP은 없다. GBC164·세이브 SRAM·MMC4/5/state/mute/frameskip 요구와 AV60fps→장기플레이/오류·reset로그→입력품질 우선순위를 유지한다.
