# 618 · OAM 발행 시각과 SEAL 검사 후 같은 VBlank의 DMA

두 시작 클록은 3,000,000 / 3,178,684다. 실기 MMC613 이후의 일정 기준인 616B와 같은 입력 905–957, 같은 ROM 허용 구간, CPI 2, SPI 드라이버 실측 비용, 실제 SysTick·ARM·65816 코드 및 두 bulk 슬롯을 사용했다. 표시 간격은 연속한 951–955 다섯 구간의 평균이고, 마지막 ACK는 957의 표시 완료다.

**618의 조건부 발행 후보에서 두 위상 모두 밀집 평균 간격과 마지막 ACK가 줄었다.** 밀집 구간의 평균 절감은 0.032 / 0.007 ms였고 VBlank 합계는 22 / 22였다. 954·955도 계속 각각 5 VBlank였다. 시간 이득과 두 DMA 기회를 재현한 연결 일정 후보로 보존하고, 실기 준비의 기준은 616B로 둔다.

| 두 위상의 연속 일정 | 616B | ARM 준비 순서만 | 검사 후 DMA 추가 | 검사 후 DMA + 조건부 OAM 발행 |
|---|---:|---:|---:|---:|
| 955 첫 기회 map(B) | 64 / 64 | 192 / 192 | 192 / 192 | 192 / 192 |
| 955 마지막 384B 중 선행 DMA(B) | 384 / 384 | 0 / 0 | 0 / 0 | **384 / 384** |
| 954 검사 뒤 같은 VBlank의 일반 DMA(B) | 0 / 0 | 0 / 0 | 736 / 352 | **192 / 192** |
| 밀집 평균 간격(ms) | 73.147 / 73.144 | 73.196 / 73.195 | 73.059 / 73.117 | **73.115 / 73.138** |
| 마지막 ACK 차이(ms) | 기준 | −49.543 / −32.955 | −66.167 / −32.971 | **−50.027 / −33.461** |

모든 구성에서 952 표시 간격은 4 / 4 VBlank, 957 최종 대기는 0 / 0회였다. 최종 후보는 955의 1,152B DMA가 끝나고 0.441 / 0.439 ms 뒤에 첫 OAM이 큐에 들어왔다. 두 위상 모두 240번 라인에서 다음 map 384B의 실제 DMA를 시작했다. 최종 후보의 누적 ACK 이득은 주로 밀집 구간 전에 생겼다. 위상 1에서는 920·931·947이 한 VBlank씩 짧아졌고, 위상 2에서는 922·931·947이 짧아지고 923이 한 번 늘었다.

954는 최종 후보에서 두 위상 모두 업로드 진입이 245번 라인이었다. 같은 VBlank에 128+64B를 쓴 뒤 256번에서 대기에 들어갔다. 다음 VBlank에 일반 544B와 raw 192B, 마지막 팔레트·OAM 1,056B를 수행해 246번에 표시했다. 업로드 대기 자체는 616B의 14.627 / 14.133 ms에서 14.684 / 14.687 ms가 됐다. **다음은 954의 검사 완료를 앞당기거나 대기 뒤 일반 544B를 SEAL 전에 처리할 수 있는지 검증하는 일이다.** OAM 발행 지연과 빔 상한은 이 비교값에 고정한다.

## 955 · OAM 앞의 빈 구간

616B는 955의 마지막 384B를 두 위상 모두 선행 전송했다. 617에서는 첫 기회에 추가 128B를 전송했지만, 다음 VBlank에서 1,152B DMA가 끝난 직후 첫 OAM이 도착해 마지막 384B가 SEAL로 넘어갔다. 양쪽 이득을 동시에 보존하는 것을 목표로 했다.

먼저 617의 고정 패킷 도착 기록에서 첫 OAM과 이후 패킷 전체를 5,500 master clock(0.256 ms) 뒤로 옮겼다. 패킷 순서와 간격을 보존했고, 선행 DMA 1,152B의 마지막 쓰기까지 소비 이벤트와 시각이 원본과 일치했다. 같은 65816이 242 / 243번 라인에서 384B를 추가 전송했다. 955 ACK가 0.220 / 0.247 ms 빨라졌다. 이 실험의 변경 지점은 도착 시각이며 실제 ARM 대기 비용은 아래 연속 일정에서 따로 측정했다.

ARM 후보는 만료된 BG scratch에 compact CHR을 채우는 기존 계산을 팔레트 발행과 OAM 발행 사이로 이동했다. 패킷 순서와 payload는 동일하다. 두 번째 ARM 후보는 오른쪽 map 페이지의 첫 19개 행이 연속으로 필요할 때만 기존 128µs 대기 함수를 두 번 호출한다. 18행이 1,152B 한 번의 최대 선행 전송량이다. 각 대기는 서비스·STOP을 확인하고 OAM 발행 전에 반환한다. 어느 세대도 하드코딩하지 않았다.

## 954 · 검사 후 빔과 DMA 한도

65816은 SEAL 검증과 raw 준비가 완료된 뒤, 이미 수락된 비활성 VRAM의 일반 descriptor 한 개를 검사한다. 길이 384B 이하, 새로 읽은 실제 빔 225–252번, VBlank 상태와 STOP 재확인을 모두 통과해야 DMA를 시작한다. 한 명령 뒤에는 다시 빔을 읽고 판정한다. raw 복원에는 기존 배치 경로를 사용하고, 부분 전송에는 다음 표시를 허용하는 잔여 credit을 부여하지 않는다. 최종 246번 검사선과 기존 빈 큐의 새 head 우선 중재를 그대로 사용했다. SEAL 실행 중에는 그 head가 최종 ACK까지 큐를 소유한다.

OAM 준비 순서 변경과 이 65816을 연결한 954의 고정 도착 시험에서는 독립 검사 완료까지 9,818 / 9,827개 CPU 이벤트와 시각이 같았다. 그 시점에서만 빔 분기를 꺼 비교했다. 분기를 켰을 때 다음 VBlank를 기다리기 전에 각각 **736B**(128+64+144+16+384)와 **352B**(128+64+144+16)를 썼다. 같은 954 ACK가 각각 0.430 / 0.263 ms 앞당겨졌다.

별도 경계 fixture는 검사를 통과한 일반 명령에서 384B 구간을 골라 실제 PPU 빔에 맞춰 실행하고 표시 전에 STOP을 주입했다. 252번 H=1144 샘플에서 첫 쓰기는 253번, 마지막 쓰기는 256번이었다. 253번 H=1170에서는 0B, 252번 빔 확인 직후 STOP에서도 0B였다. 384B는 이 후보가 허용하고 검증한 단일 명령 한도다.

## 비용과 재현

- ARM 전체 링크는 준비 순서 변경이 212,912B, 19행 조건부 대기를 포함하면 212,992B다. BSS는 18,592B다. 페이지 위치와 무관하게 dirty 행 수를 세던 중간 후보는 Flash 한도를 28B 초과해 일정 비교에서 제외했다.
- 65816 본체는 4,949→5,068B다. 기존 5KiB 배치의 본체 한도 4,960B를 108B 초과해 연속 시험에는 6KiB 진단 ROM을 사용했다. 첫 확장본은 고정 DMA의 0xff 소스가 이전 주소를 가리켜 cold 905 raw VRAM 비교에 실패했다. 소스를 ROM 끝의 검증된 0xff 바이트로 옮긴 뒤 처음부터 다시 실행했다. 기본 5KiB 설정으로 재생성한 616B ROM은 원본과 SHA-256이 같다. 6KiB 구성의 보드 FIT·STA 및 실기 메뉴 복귀는 이번 시험 범위 밖이다.
- 65816의 새 패킷 우선·STOP과 독립 누락·중복 검사는 616 경계 시험으로 확인했다. 954의 팔레트·OAM·HDMA 수락 직후 STOP 세 건 모두 0xe4와 직전 표시를 유지했다. ARM 18행/19행과 첫째·둘째 대기에서의 STOP도 분리 검사했다.
- 새 구성 세 개의 두 위상에서 각각 53장의 RGB·map, 일반 payload·tile 및 VRAM DMA 총 114,352B가 기준과 일치했다. warm DMA의 첫 쓰기와 마지막 쓰기는 같은 VBlank에 있었다.
