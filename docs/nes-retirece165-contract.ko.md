# NES165 CHECK 카운터 갱신 허용 경로

165 영상 경로 진척: CHECK 카운터의 오류 차단을 전용 갱신 허용 입력으로 분리하고 로더 상태별 명령 판정과 결합했습니다. 전체 타이밍 개선이 없어 기존 개발 기준을 유지합니다. 선택 phaseguard165/map01/reproduce01; 마지막 후보 15048LE/962LAB/35M9K, 실제 클록 최악 setup-1.974ns. 전체IO·CDC·MCU·실기는 미완료, 설치164와 세이브 SRAM 보존, 새SD 없음.

[수치와 검증 해시](../analysis/retirece165-verification.json) · [현재 인계](../cores/nes/HANDOFF.ko.md).

## 구조와 근거

기존 CHECK 카운터는 갱신 허용 자동 인식을 끈 상태여서 같은 클록의 오류 판정이 각 비트의 데이터 선택 논리를 거쳤다. 새 후보는 카운터19비트에만 AUTO_CLOCK_ENABLE_RECOGNITION을 켜고, 기존 counter_retire_ok와 저장된 clear/inc를 결합한 갱신 허용 신호를 만든다. clear 우선순위, 잘못된 응답·오류의 같은 클록 차단, reset과 명령 완료 시점을 보존한다. 게이트 클록·새 파이프라인 지연·조기 길이 샘플링을 추가하지 않는다.

[Cyclone IV 공식 핸드북](https://cdrdv2-public.intel.com/653974/cyclone4-handbook.pdf)의 LE/LAB clock enable 구조와 [Quartus 공식 설명](https://resources.altera.com/quartushelp/17.0/comp/comp_tab_fitting.htm)의 Auto Clock Enable Replacement를 참고했다. 구현 효과는 문서만으로 추정하지 않고, MAP의19개 ON 설정과 배치된19개 check_next 레지스터의 ena 경로로 확인했다. 소스의 IMPLEMENT_AS_CLOCK_ENABLE 힌트는 MAP 설정 행에 나타나지 않았으므로 그 힌트가 적용됐다는 주장은 하지 않는다.

map01은 지난번 확인한 숫자 keep 길이 비교를 함께 적용하고 로더는 그대로 둔다. map02는 map01에 검증된 상태별 명령 판정을 결합한다. map03은 오류 코드 저장을 별도 always 블록으로 옮겨 상태가 갱신 여부를, 명령 우선순위가 코드 값을 결정하게 한다. fault·데이터·타이머·상태 처리와 오류 코드의 같은 클록 결과는 유지한다. SPI와 로더 외59개 입력, QSF·클록·SDC는 최초 기준과 같다. 각 단계의 독립 재생성 바이트도 같다. map02 로더는 length165/loader03 바이트와 같아294912조건/1056시나리오를 재사용하며, map03 로더는 같은 시험을 새로 실행한다.

## 검증

- 카운터 전체19비트 값524288개와 오류·응답·reset·명령 조합262144개, 합계786432조건에서 같은 클록 결과를 비교했다.
- 저장/다음 처리 클록393741조건과 길이 경계·비트 반전·저장 후 live length 변경을 비교했다. 오류 차단을 제거한 회로는 음성 대조군에서 검출됐다.
- 세 후보 각각 실제 SPI·boot·READ16 연결에서1026691클록/100읽기/7ACK/19응답 오류/72중단/2겹침을 통과했다. map02/03은 SPI와 로더 변경이 동시에 들어간 상태로 새 연결 시험을 실행했다. map03은294912조건/1056연속 쓰기 시나리오와 잘못된 STOP·오류 코드 음성 대조군도 새로 통과했다.
- 이 연결 시험은 loader READY/적재 수 일부를 주입한다. 전체 ROM 적재·게임·MCU/SNES 실기 실행은 아니다. 로더 부품 동등성 시험 전체를 새로 반복했다는 뜻도 아니다.
- 새 배치마다 영상 지역 리셋 해제4레지스터, 첫 단계fanout1,12개 setup/hold 경로를 확인했다.

더 엄격한 추가 배치 목표와 실제 클록 조건을 구분한다. 외부 입력54개/출력57개 미제약, 혼합 클록·전체 reset/CDC·MTBF·MCU 연결은 아직 승인하지 않았다. 내부 경로 개선은60fps 실기 성공을 뜻하지 않는다.

## 다음 작업과 의미

선택 phaseguard165/map01/reproduce01을 유지한다. 개별 조합식 수정→전체 재배치만 반복하는 방식은 중단한다. 다음에는 실제 MCU SPI 프레임 간격과 SS/SCK 겹침·응답·ACK·STOP/reset 계약을 먼저 확인해, 명령 캡처와 실행 자격 판정을 명시적인 여러 클록 단계로 나눌 수 있는지 검토한다. 이것은 기존 같은 클록 처리 계약을 바꾸는 설계이므로 단순한 동등성 주장이나 false path로 넘기지 않는다. 외부 응답 지연 한도, queued 명령 중 오류·STOP 우선순위, 새 프레임의 fail-closed 처리와 식별 버전/MCU 호환성을 정의하고 변경 경계 시험을 통과한 구조만 한 번 배치한다. 추가 지연을 허용할 수 없다는 근거가 나오면 그 결과를 남기고 공통 오류 신호의 지역화 대안을 선택한다. 이번3후보·이전 length165/STOP 분리·무변경 fit/전체ROM 쓰기는 반복하지 않는다. 내부 타이밍 이후 필요한 외부IO/영상CDC/reset와 MCU E6/version2 상태73·E5 관측70·E0/F6 수신/변환/ACK·사운드·입력·STOP·경과시간을 연결해 SMB3 첫 레벨 실기로 진행한다. 설치164/GBC와 세이브 SRAM은 보존한다.

연속 게임 화면을 위한 FPGA 제어·배선 속도 확보 작업이다. 설치164 사운드·입력·메뉴와 세이브 SRAM을 보존하고, 필요한 연결 후 SMB3 첫 레벨 실기로 판단한다. 새 실기 패키지는 없다.
