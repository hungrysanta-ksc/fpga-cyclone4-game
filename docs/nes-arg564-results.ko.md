# 564 · SPI 인자 수신 경로

563에서 168MHz 메모리 클록의 `byte_count[2] → arg[7]` setup은 −0.333ns였다. 564에서는 바이트 위치 4의 일곱 번째 SCK 상승 에지에서 쓰기 허가를 저장하고, 여덟 번째 에지에 마지막 MOSI 비트까지 포함한 인자 값을 캡처한다. 동기화된 SS 해제 또는 reset이 쓰기 허가를 지운다. MMC558 보드 입력 73개를 기준으로 563과 564 사이에 달라진 파일은 `nes_rom_spi.sv` 하나다. [563 결과](nes-guard563-results.ko.md)

## 수신 동작

Questa 한 좌석에서 기존·후보 수신기에 같은 SPI 입력을 동시에 주었다. 168MHz 내부 클록과 2.625MHz SPI의 두 시작 위상에서 각각 1,429,799개 클록 샘플의 출력과 내부 인자 값을 비교했다. 별도 검사기가 비트·바이트 번호와 MOSI로 인자 캡처를 재구성했다.

- 위상마다 256가지 DATA 인자를 모두 전송했다. 외부 명령 중단·reset 뒤 이어진 전송까지 포함해 정상 쓰기는 266회였다.
- 소유 명령을 8–63비트의 모든 길이에서 끊은 56경우, 80비트 초과 프레임, 잘못된 보수·CRC·tail·opcode는 쓰기 없이 오류가 됐다. 외부 명령의 인자 부근 9개 위치에서 SS를 해제한 뒤 reset 없이 유효한 명령을 전송했다. 39번째 비트 직후에는 실제 쓰기 허가가 올라와 있음을 먼저 검사했다.
- SS 해제 전 비동기 reset, CHECK 읽기와 데이터 불일치 ACK 거부, 일치 ACK 뒤 START와 STOP을 확인했다. CHECK의 메모리 응답은 시험벤치가 제공했다. 예비 독립 검사기의 reset 에지를 보정하고 최종 벡터에 CHECK·START·STOP을 추가했다.

563에서 직접 이어졌던 count→arg 경로는 세 코너 모두에서 사라졌다. Slow 85°C에서 count→쓰기 허가는 +2.881ns, 허가→arg는 +3.005ns였다. 다른 두 코너도 양수다. 새 대상 최악 경로는 `ss_sync[1] → snapshot[45]`이며 구현·nominal 분석에서 모두 +0.415ns다.

기존 음수 항목의 회귀는 168MHz setup 3개, NES setup 3개, 84MHz recovery 3개, ROM_OE 출력 예산 1개다. 미제약 항목 수는 그대로다. 다음 설계에서 따로 확인할 경로는 다음과 같다.

- Slow 85°C에서 `core_release.release_reset[1] → bulk.hcancel.release_reset[0]`의 recovery는 −8.877ns로 MMC558보다 0.397ns 낮다. 이 경계는 타일 뱅크 조기 공개 중 취소에 관여한다.
- 같은 코너의 `reading_active → ROM_OE`는 12ns 출력 제약에서 −0.606ns로 MMC558보다 0.394ns 낮다. 내부 주소가 요청보다 충분히 먼저 도착하는 것과 별도로 점검해야 할 외부 핀 경로다.
- 564의 실제 배치에서 563의 전체 주소 분석을 반복했다. 가장 이른 토글과 가장 늦은 주소를 서로 다른 코너에서 취한 캡처 여유는 8.435ns였다. ROM 주소 프로토콜은 유지됐다. [경로별 측정값과 전체 판정](../analysis/arg564-verification.json)

## 표시와 다음 결정

같은 ARM·SPI·IRQ·ROM 도착 기록으로 65816 소비를 두 위상에서 다시 실행했다. 각각 53개 RGB·ACK 추적이 일치했고, 위상별 대조 이벤트는 9,464개와 9,462개였다. 952는 5 VBlank, 밀집 5화면은 합계 25 VBlank(평균 83.157 / 83.121ms), 957 최종 검사 뒤 추가 대기는 0회였다. 이번 비교는 부트 SPI의 차등 RTL 시험과 기존 도착 일정의 65816 재생을 별도로 실행한 결과다.

**실기 기준은 MMC558을 유지한다.** SPI 인자 쓰기 허가는 검증된 후보로 보존한다. 다음 단계는 ROM_OE의 launch부터 PSRAM 데이터 샘플까지의 시간과 host 취소 reset의 해제 순서를 실측·배치 근거로 분리하는 것이다. 로컬 SPI setup을 다시 조정하기 전에 외부 핀·reset이 동시에 충족해야 하는 예산을 확정한다.

## 재현

1. `prepare_nes_arg564.py`로 MMC558 보드에서 563을 재구성한 뒤 SPI 변경을 적용한다. 전체 보드에 기존 `quartus_sh --flow compile board`와 `timing506.tcl`을 실행한다.
2. 563·564 보드에서 각각 `report_nes_arg564.tcl`을 실행한다. 564에서 기존 `report_nes_owner562.tcl`과 `report_nes_capture563.tcl`도 실행해 같은 제약과 주소 캡처 기준으로 비교한다.
3. FLOAT wrapper에서 `check_nes_arg564.py`를 실행한다. 선택된 보드는 board01, 시험은 rtl03이다. 각 위상의 562 도착 추적을 `replay_nes_close561.py`로 재생한 후 `analyze_nes_arg564.py`로 RTL·표시·보드 결과를 합친다.
