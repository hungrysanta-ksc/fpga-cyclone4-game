# MMC866에서 23행 map 전송을 줄이는 비용

MMC866까지의 로컬 네 커밋을 PR169 병합점 기반 브랜치에 반영했다. 기준은 모험도 4 MMC866 무입력 실기 오프닝 17.90 FPS, 데모 16.90 FPS다. sd2snes+ 실기 구간 FPS 비교는 작업 순서에서 뺐다. 상류에서만 확인할 수 있는 구조나 동작이 있을 때 해당 실험을 진행한다.

## 같은 화면에서 비교한 세 가지 수신 방식

MMC866 최종 링크의 두 시작 위상에서 35–40초 부근 원본 2120–2364를 4장 간격으로 재생한 기록을 사용했다. 처음 두 장으로 두 뱅크를 채우고 이후 60장을 비교했다. 이 중 42장에서 연속 23행이 바뀐 페이지가 43개였다. 세대 950은 두 페이지에 해당한다. 25개 페이지는 한 열, 18개는 인접한 두 열이었다. 좌우 두 페이지에 모두 나타났다. 각 행에서 목적 뱅크 또는 직전 표시 뱅크와 다른 단어의 합집합으로 계산했다. 기존 853/854의 명령은 오른쪽 페이지·단일 열·0인 후반부 등 추가 조건을 요구한다. MMC866의 이 표본에서 실제 op9 발행은 0회였다.

| 43개 페이지의 해당 23행만 합산 | 기존 MMC866 | 단어마다 주소·값 | 공통 열 번호와 23행 값 |
|---|---:|---:|---:|
| map E1 거래 | 344 | 43 | 43 |
| map E1 바이트 | 68,312 | 6,773 | 3,967 |
| 65816 수신 비용, 위상 1 합계 | 206.17ms | 267.77ms | 215.11ms |
| 65816 수신 비용, 위상 2 합계 | 205.70ms | 267.77ms | 215.11ms |

기존 값은 같은 패킷의 실제 65816 load부터 큐 반환까지의 경과 시각이다. 후보는 Mesen에서 실행한 독립 수신 루틴의 서비스 시작부터 결과 반환까지다. 새 패킷의 큐 배차·coverage 등록·SEAL·DMA 비용은 합산하지 않았다. 43개 페이지 밖의 거래 및 23행 밖의 7거래·901B는 기존 경로를 쓴다. 따라서 측정 표본 전체 map E1은 **351→50거래, 69,213→4,868B**로 계산된다. 새 형식의 SPI 거래 길이는 구성한 실제 payload와 기존 외피로 산출했다. [단어 수신 측정](../analysis/map868-cost.json) · [열 수신 측정](../analysis/map868-strip.json)

열 수신기는 명시한 1–2개 열을 대상 WRAM에 쓰고 다시 읽는다. 생략한 모든 단어는 두 물리 뱅크에서 각각 읽어 비교한다. ARM이 두 뱅크에서 모두 원하는 값과 일치한 경우에만 생략한다. 두 뱅크의 같은 위치가 똑같이 손상된 경우까지 검출하는 방식은 아니다. 65816은 열마다 STOP을 확인하고, 실패하면 이력 유효 표시를 지운다. 두 형식 각각 43개의 정상 결과 전체 1,472B와 peer 보존을 대조했다. 생략 단어의 대상·peer 단독 손상, cold 이력, 잘린 길이, 세대 불일치, 잘못된 범위/중복, 세 중단 위치 등 9개 오류 조건도 각각 통과했다. cold 전체 복구·실제 큐 반환·최종 ACK·메뉴는 후보를 제품에 연결한 뒤 재검증한다. [65816 코드와 시험](../tools/probe_nes_map868.py)

## ARM 이력과 발행 마감

기존 ARM의 column_map은 두 뱅크 합계 1,368B다. 두 페이지 23행을 두 뱅크에 그대로 저장하면 5,888B가 든다. 페이지·뱅크 간에 같은 열과 16비트 값을 공유하고, 모든 열에서 직전 행을 반복하는 행을 표시하면, 이 표본의 연속된 두 map 이력 61쌍은 각각 641–1,130B에 들어갔다. 모든 단어를 다시 풀어 원본과 대조했고 용량 초과 시 fallback을 검사했다. 전체 이력을 만드는 코드는 현재 호스트에 있다. ARM에서 최종 ACK 때 사전을 갱신하는 시간과 이력이 교체되는 동안의 최대 메모리는 별도 측정이 필요하다.

압축 이력을 직접 읽는 Cortex-M4 생산 함수를 빌드하고 Unicorn에서 실행했다. 43개 페이지 모두 65816 시험과 바이트 단위로 같은 payload를 발행했다. 화면당 12,268–12,548명령, 함수 본체 294B다. 원본 두 뱅크 배열을 직접 읽은 대조군은 9,207–9,285명령·178B였다. 866의 Flash 여유는 4B라서 기존 코드와 교체하는 전체 링크가 필요하다. 독립 65816 시험 ROM의 457B에는 부팅·시험 제어도 들어 있으며 제품 ROM 증가량으로 쓰지 않는다. [ARM 생산 함수](../tools/nes_strip868.c) · [비용과 입력 해시](../analysis/map868-producer.json)

43개 페이지 합계에서 866의 E1 보정값을 적용한 SPI 절감은 211.09ms다. 열 단위 독립 검사로 수신 시간이 8.94/9.42ms 늘고 ARM에 CPI 2를 적용하면 생산에 12.73ms가 든다. 세 항목의 직렬 차이는 189.42/188.94ms다. 실제 SPI와 65816은 겹쳐 실행되고 map 이력 생성도 필요하므로 이 합계를 표시 시간 절감으로 환산할 수 없다.

원래 여덟 번째 map 전송을 시작하던 시각에 전체 묶음을 만들기 시작하면 **두 위상 모두 43개 페이지 전체가 기존 마지막 map 반환을 놓친다**. SPI와 CPU를 즉시 쓸 수 있다고 가정해도 위상 1은 3.48–4.81ms, 위상 2는 3.49–4.81ms 늦다. 원래 첫 map 시각에 모든 행이 확정되어 있었다고 가정하면 43개 페이지 모두 기존 반환 전에 수락을 끝낼 계산 여유가 있다. 최소 여유는 0.686/0.715ms다. 두 시각은 마감 판단의 경계이고 실제 마지막 행 확정 시각은 이 계측에 포함되지 않았다. 비교 대상인 MMC866 최종 링크는 밀집 60개 표시 간격 145/144 VBlank, 마지막 65816 ACK는 각각 66,446,426 master clocks였다. [세대별 마감 계산](../tools/cost_nes_strip868.py)

## 다음 작업 순서

1. MMC866의 실제 planner에서 두 페이지의 마지막 변경 가능한 행 쓰기와 BG 슬롯 확정을 계측한다. 868의 세대별 마지막 발행 가능 시각과 대조하고, 이력이 아직 확정되지 않은 행에는 기존 전송을 유지한다.
2. 마감에 들어올 수 있는 화면을 대상으로 기존 column_map 공간에서 ACK 시 이력 교체·STOP·용량 초과 뒤 cold 복구를 구현한다. ARM 전체 링크와 부분 갱신 중 최대 메모리를 확인한다. 마지막 행이 너무 늦으면 조기 확정된 행만 나눠 보내는 안과 남는 credit·검사 비용을 비교한다.
3. 같은 제품 링크에서 묶음 켬/끔, 두 시작 위상의 밀집 60장 표시 간격과 마지막 ACK, 오프닝과 전환을 검증한다. 공개 지연을 줄이는 후보만 MMC866과 같은 60초 실기 시험으로 보낸다. 실기의 60 FPS 예산은 표시당 16.67ms다.

재현할 때는 probe_nes_map868.py에 기존 MMC866 재생 temp 루트, Mesen 실행 파일, 새 작업 폴더와 결과 JSON을 전달한다. 기본 방식과 --strip을 각각 실행한 뒤 cost_nes_strip868.py에 같은 temp 루트, 새 작업 폴더, 열 방식 결과(--measure), 출력 JSON을 전달한다. 이번 단계는 ARM·65816 비용 시험이며 보드 RTL·설치본은 MMC866을 유지한다.
