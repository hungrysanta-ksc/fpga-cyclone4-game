# NES150 — 실제 마리오 화면·패드 첫 실기 시험

이번에는 `Super Mario Bros 3 (J).nes`의 실제 PPU 화면을 표시한다. 진단 A/B 패턴이 아니다. 게임 화면과 Start·방향키·점프 입력, 오류 없는 메뉴 복귀를 확인하는 시험판이다.

## 설치와 실행

1. 전원을 끄고 SD의 현재 `sd2snes/firmware.stm`을 별도 백업한다.
2. ZIP의 `01-GAME150-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. 폴더 자체를 복사하지 않는다. 이번 펌웨어와 `fpga_n150.bi3`는 60/DA 식별로 짝지어져 있다. 이전 FPGA와 섞지 않는다.
3. 메뉴에서 **`NES GAME 150.nh1`**을 실행한다. 0바이트 표식이 정상이며 확장자를 변경하지 않는다. 실제 게임은 패키지 내부 `sd2snes/nes/game150.nes`에 있다. 사용자 제공 ROM을 담은 개인용 패키지이므로 GitHub에 업로드하지 않는다.
4. 적재·전체 대조 후 화면이 나오면 Start를 누르고 방향키, A/B를 조작한다. **게임 표시 구간은 약 60초 후 자동 종료**하고 메뉴로 돌아간다. 오류를 감지하면 더 일찍 종료할 수 있다.
5. 전원을 끄고 `/sd2snes/nes-progress-150.txt`, `/sd2snes/nes-game-last-150.txt`와 촬영 영상을 전달한다. 두 TXT의 단계 시각으로 새 적재 시간을 측정한다.

로딩 시간은 아직 실측하지 않았다. 기존 GPIO 전송 대신 검증한 하드웨어 SPI를 사용하며 9분 대기는 요구하지 않는다. 이번 첫 시험에서는 **실행 후 5분 동안 게임 화면·메뉴 복귀 모두 없으면 종료하고 남은 로그를 전달**한다. 이는 관찰 상한이며 정상 로딩 시간이나 펌웨어 자동 타임아웃을 뜻하지 않는다. 화면이 나온 시점부터 약 60초간 촬영하면 된다.

## 이번 화면에서 예상되는 제한

- 원본 256×240 중 위·아래 8줄을 제외한 256×224를 표시한다. PPU가 합성한 픽셀이므로 스프라이트·스크롤·CHR 뱅크 변경이 포함된다.
- 완성된 화면 하나를 고정하고 SNES VRAM으로 전체 복사한다. **복사 중 검정 화면과 낮은 화면 갱신률이 예상된다.** 이 방식은 60fps 출력이 아니며, 이번 영상의 끊김을 곧바로 NES CPU 속도 오류로 판정하지 않는다. 실기에서 게임과 입력 경로를 먼저 확인한 뒤 전송량·표시 속도를 개선한다.
- 소리는 아직 출력하지 않는다. NES 색 강조 비트, 저장 유지 기능도 미구현이다. 일반 64색 인덱스는 보존한다.
- 화면 로그의 stage/frames는 SNES 프로그램의 진행 표식이다. TV 출력 정상이나 실제 FPS를 증명하지 않는다.

## 전달할 관찰과 복원

게임 제목/캐릭터가 식별되는지, Start·방향키·A/B가 반응하는지, 메뉴로 복귀했는지를 알려준다. 보이는 검정 구간·게임 진행 속도는 영상으로 확인한다. CRT 촬영 대각선 띠는 기존 안내대로 판정에서 제외한다.

정상 사용으로 돌아가려면 전원을 끈 뒤 `02-RESTORE044-SD-ROOT`의 내용을 SD 루트에 복사한다. 기존 검증본 그대로이며 **동일한 044 복원·GBC 재시험 보고는 요구하지 않는다.**

이 패키지는 실험판이다. 같은 클록 setup/hold와 조건부 외부 읽기 계산을 통과했지만 PSRAM 계산 여유가 약 0.78ns로 작다. 실제 보드 배선 지연·MTBF·기존 양 클록 정지 보호 항목을 새로 실측한 것은 아니다.
