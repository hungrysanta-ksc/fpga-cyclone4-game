## 처음 늦어진 화면

오프닝에서 MMC866보다 처음 늦게 공개된 화면은 원본 728(재생 세대 935), 전환에서는 원본 1572(세대 952)였다. 두 화면 모두 양쪽 링크에서 map 패킷을 발행하지 않았다. 따라서 해당 세대의 map 반환 대기는 0건이다. 직전 입력의 마지막 D2가 캡처 시작선을 넘으면 다음 캡처 준비가 정확히 357,368 마스터클록 늦어진다.

## 수신 변경과 확인 범위

기존 ARM은 D3 뒤 D0로 유효한 COMMIT head를 확인한 다음, 다음 수신 함수에서 같은 D0를 다시 보냈다. 후보는 CRC를 통과한 긍정 응답의 길이·token만 기존 8B 저장소에서 재사용한다. 아직 head가 없으면 다음 수신에서 다시 조회한다. COMMIT payload와 generation은 D1에서 검사하고 D2 뒤 D0로 token 반환을 확인한다. 두 조회를 줄이는 대조군에서는 마지막 데이터 D2의 반환 응답에 END가 서 있는 경우에만 PREPARE 앞의 D0도 재사용한다.

검증에는 동일 시작 클록·ROM 위상, dot 0 보정 입력, 실기 로그로 보정한 SPI 비용, CPI 2 ARM 명령 실행, Mesen 65816 실행을 사용한다. 오프닝 62장·전환 50장·밀집 62장의 같은 세대 활성 영상을 위상별로 MMC866과 비교한다. 개별 COMMIT 오류·STOP·cold 복구·메뉴 복귀도 최종 링크에 연결해 확인한다. 이 결과는 실기 60초 FPS를 대신하지 않는다.

수신 오류 주입 16조건에 END 지연, END·head 상태 CRC 손상, D1 CRC·세대·token 불일치, D2 미반환, STOP, OBJ 초과 뒤 ABORT 확인을 포함했다. 65816은 잘못된 범위·생략 열 손상·부분 전송 후 STOP과 두 뱅크 cold 복구를 검사했다. 메뉴 복귀는 링크된 ARM 해제 함수의 정상·오류 분기로 확인했다. 이번 변경은 ARM 수신기에 한정돼 870G의 보드와 65816을 재사용했다.

처음부터 두 응답을 재사용한 `ready_both_frame`은 전환을 119/119로 회복했지만 위상 2의 오프닝 703 공개가 60으로 늦었다. 첫 화면 뒤 D3의 응답만 재사용한 `warm_clean`은 703을 지켰지만 오프닝 125/127, 전환 120/119였다. `wire`는 Flash를 4B 초과했다. 추가 링크 중 `warm`은 Flash를 44B 초과했고 `banks`와 `ready_frame`에서는 703의 위상 2 마감을 놓쳤다. 이 세 링크는 여섯 재생을 모두 끝내지 않아 구간 합 대조에서 제외했다.
