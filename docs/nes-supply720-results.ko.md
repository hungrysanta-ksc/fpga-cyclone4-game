# NES720 BG 완료 공급·OBJ bulk 진행 검증

## 목표

719의 951 공개선·911 표시2회와 716B·717 계산 절감을 유지하면서, 953의 마지막 BG 공급과 956의 OBJ capture/bulk 해제를 앞당긴다. 같은 입력·map·OBJ 작업량, 두 시작 위상에서 밀집 표시 간격과 마지막 ACK를 함께 비교한다.

## 작업내용

- warm의 BG 탐색 도중 map 선행 발행은 한 번만 허용한다. 대상 뱅크의 최종 ACK로 확정된 resident slot0 비트로 cold/warm을 구분한다. cold 두 뱅크 채움·STOP 뒤 무효화는 기존 경로를 유지한다.
- 선행 행 발행이 있었던 프레임은 BG 완료 callback에서 남은 BG를 기존 E8/E9 검사를 거쳐 공급한 뒤 OBJ 계산을 진행한다. 선행 행 발행이 없으면 원래 fallback을 유지한다. 세대·시작 위상별 분기는 없다.
- map 뒤의 receipt-only 조기 반환을 삭제해 실제 producer를 조회한다. 새 OBJ가 준비됐으면 기존 bulk 완료·CRC·identity 확인 뒤 수락하고, 준비되지 않았으면 map 발행을 이어간다. bank 해제·DMA 완료·최종 표시 ACK를 합치지 않는다.
- 719의 ACK 기반 대기 허용 조건과 8ms 예산, OAM 대기, STOP·새 패킷 우선, 독립 검사·최종 ACK·메뉴 경로는 유지한다. FPGA·65816 소스와 제약은 변경하지 않았다.

실제 링크 ARM/65816을 실행하지만 CPI2·SPI/IRQ 비용·반복 ROM 달력은 모델이다. 실제 NES/PSRAM 전체 RTL의 동시 실행이나 실기 FPS·외부 IO 승인을 뜻하지 않는다. OBJ_capture 응답 간격을 외부 ROM 경쟁 시간으로 계산하지 않는다.

## 성과

**720은 자원·기능·보호조건을 통과했지만 시간의 동시 개선에 실패해 미채택이다.** 707D·기존694/704 ARM·기존65816 선택을 유지하며, 716B·717·719와720 원시 근거를 보존한다.

음수는 단축이다. 원본707D ARM 기준의 밀집 평균은 여전히+0.038273/+0.075056ms, 마지막ACK는−82.977764/−83.107017ms다. 마지막 ACK의 큰 단축은719에서 보존한 cold/앞쪽 화면 효과를 포함하며 지속FPS 상승이 아니다.

953의 직전 표시가0.751/0.696ms 늦어졌으므로, 그 표시를 기준으로 한 ROM 응답 단축을 공급 성과로 계산하면 안 된다. 동일 시작 시각에서 마지막 ROM 응답은 정확히 그대로다. E9 수락은 빨라졌어도 직전 ROM창 종료보다2.114416/1.990960ms 늦어 같은 다음 창을 기다렸다. 같은 기준의953 SEAL은+0.090607/−0.008753ms다.

956의80회 OBJ_capture 읽기 완료는 실제로 앞당겼다. 그러나 선행map이1024→704B,952는1920→576B,957은2048→1664/1856B로 줄었다. 준비된 tile을 더 빨리 공급한 일정이 map 선행DMA와 경쟁했고,952 공개는239→250선,956은239→242선,957은238→242/240선으로 밀렸다. `957 최종대기0`이 유지돼도 같은 VBlank 안의 작업 완료 지연은 남는다. 이 결합시험만으로 세 변경 각각의 모든 기여를 분리했다고 주장하지 않는다.

전체 SPI는719보다1,240/1,336B 감소했다. E8 −1,060B, E9 +200B, D0 −400/−416B, E0 +20/−60B이며 D1·E1 데이터는 동일하다. 거래량 감소만으로 표시·ACK 개선을 보장하지 않는다.

두 위상106화면의 map·tile·plan·픽셀은719와 동일하고, 951 공개236선·911 표시2회/242·241선·952 표시3회·957 최종대기0·7블록과908/934/940/943의2회를 모두 유지했다. 관측stack 추가0B다. 실제 링크 ARM의 deadline17·slot18·tail24·plan7·credit9·runtime16·메뉴18·새query/fence19조건과65816 STOP4조건을 통과했다. 변경 없는65816 종료12조건은 hash가 같은 기존 근거를 승계하며 새 실기 메뉴 시험으로 표시하지 않는다. query01은 시험 fixture의 wait callback 누락으로 실패했으며 수정한query02/03과 함께 보존했다.

원본 대비 719에서 추가한 ACK 시각4B는 남는다. `nes_plan200_progress` 262→208B, `nes_sink527_early` 104→128B이며 전체 링크에서16B 감소했다. 패딩·링크 배치 때문에 함수 크기 합을 그대로 전체 Flash 절감으로 쓰지 않는다. 중간 arm03/normal03은 cold 구분을 추가한 뒤 정상판이16B 초과했다. 별도 warm 변수를 유지하지 않고 기존 행 진행 상태를 재사용한 arm04/normal04를 시간 검증에 사용했다. 중간 빌드·실패 로그는 보존한다.

## 후속작업

1. 719의 map 연속 공급을 대조군으로 유지하고,720의 새 producer 조회와 BG 완료 flush를 분리한다. 952의선행map1920B,956의1024B,957의2048B를 잃지 않는 tile 수락 경계부터 검증한다. 준비된 tile을 무조건 먼저 넣는 정책은 보류한다.
2. 953은 마지막 BG E9가 직전 ROM창보다최소1.991–2.114ms 더 빨라야 한다. 실제 생산·E8/E9·map 준비를 함께 과금한다. 직전 표시 이동을 ROM 가속으로 계산하지 않는다.
3. 956은 현재 SEAL에서도 직전 VBlank의246선 끝까지 최소6.534–6.539ms가 부족하다. 이 값은 잔여 검사/DMA를0으로 둔 낙관적 하한이며 실제 필요량은 더 크다. 단독 bulk 해제·빈 polling 조정만으로 해결했다고 판정하지 않는다.
4. 전체Flash≤212992B·추가정적RAM≤4B(원본대비)·공동경계≤1116B와 두위상 보호조건을 유지한다. 720 자체여유16B/공동경계1078B는 미채택후보 비용이다. 신규 FPGA 상태공개는 실제 삭제·포트·CDC 비용을 먼저 정한다.

선택본 변경은 밀집·952–957 연속간격·마지막ACK를 함께 개선한 뒤 판단한다. 새FIT/STA·설치본은 만들지 않았다. 다음 실기 전달은 새파일명60초/장시간판·RESTORE제외·5–40초/40–55초 집계를 유지한다.
