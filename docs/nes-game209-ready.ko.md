# NES209 직접 타일 전송 실기 시험

FPGA가 만든 타일을 SNES가 직접 읽는 첫 실기판이다. 기존186의 픽셀 데이터 SPI→MCU→SPI 왕복을 줄였다. 사운드·입력 유지 코드는 보존했다. **60fps 달성 여부는 아직 모른다.** 초기 ROM 로딩 절차와 약60초 실행 제한은 유지한다.

## 실행

1. 현재 SD 파일을 백업하고 ZIP의 `01-GAME209-SD-ROOT` **안의 내용**을 SD 최상위에 복사한다. `firmware.stm`과 `fpga_n209.bi3`는 반드시 함께 사용한다. 이전186 펌웨어/FPGA와 섞지 않는다.
2. 메뉴에서 `NES GAME 209.nh1`을 실행한다. 스타트로 플레이어 선택·월드맵에 들어가 숫자 **1** 타일에서 **A**로 첫 레벨에 진입한다.
3. 첫 레벨에서 **오른쪽+B를 누른 채 A를 반복해서 눌렀다 떼며** 달린다. 실제 카메라 스크롤 구간의 끊김을 확인한다. 가능하면 첫 레벨 진입부터20~30초 영상을 촬영한다. 오프닝·정지 장면으로 성능을 판단하지 않는다.
4. 음악·조작이 유지되는지, 약60초 후 파일 메뉴로 복귀하는지 확인하고 아래 로그 두 개를 전달한다. 첫 화면이 나타나기까지 걸린 시간과 실제 게임 실행 시간은 구분한다.

- `sd2snes/nes-progress-209.txt`
- `sd2snes/nes-game-last-209.txt`

첫 게임 화면 이후90초가 지나도 복귀하지 않으면 더 기다리지 말고 증상과 남은 로그를 알려준다. 화면만 멈췄다면 소리와 버튼 반응도 기록하면 된다. 같은044 복원 시험을 반복할 필요는 없다. `02-RESTORE164-SD-ROOT`는 필요할 때만 사용한다.

종료 로그에 `plan_error`, `plan_sent`, `plan_end`를 추가했다. 이는 마지막 계획 전송 상태이며 전체 표시 프레임 수가 아니다. 종료 제한에 걸린 미완료 전송의 오류와 그 전에 발생한 오류는 함께 분석한다. 로그는 기존처럼 STOP·기본 코어 복원 이후에 쓰며 프레임마다 SD에 쓰지 않는다. 장기 플레이/실기 reset 로그 정책은 이번 변경에 포함하지 않는다.

세이브 SRAM은 작업 공간으로 사용하지 않는다. 제공된 게임 ROM·메뉴·기본 코어·복원 파일은186 패키지와 바이트가 같다. 이번 시험에서는 새 전송 경로의 실제 동작과 스크롤 부하를 우선 확인하며 별도 입력 유지 반복시험은 요구하지 않는다.
