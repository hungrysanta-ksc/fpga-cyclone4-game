# NES 영상 호환성 — 게임·매퍼·PPU 기능을 나눠 관리하기

이번에 재현한 화면 정지는 **SMB3 또는 MMC3만의 기능 오류가 아니라 NES 공통 표시 설정을 출력 변환기가 지원하지 못한 문제**다. 왼쪽 8픽셀을 숨기는 설정은 다른 게임·매퍼에서도 사용할 수 있다. 다만178은 수정 후보이며 실기 해결을 아직 확인하지 않았다. 같은 증상의 모든 게임이 같은 원인이라고 단정하지 않는다.

## 무엇에 따라 달라지는가

| 구분 | 역할과 이번 문제와의 관계 | 확인할 근거 |
| --- | --- | --- |
| 게임·장면 | 언제 화면을 끄고 켜는지, 왼쪽을 가리는지, 스크롤·팔레트·패턴을 얼마나 바꾸는지 결정 | 해당 ROM·지역판·장면·입력 순서와 실제 PPU 상태 |
| NES 공통 PPU | `$2001`의 배경/스프라이트 표시, 독립적인 왼쪽8픽셀 표시, 회색조·색 강조 | 기능과 변경 시점. 이번1e→18은 여기에 속함 |
| 매퍼·서브매퍼 | PRG/CHR 뱅크, 미러링, IRQ 등. 같은 번호 안에도 차이가 있음 | 실제 물리 CHR 주소와 쓰기, IRQ 조건·종류, 장면 중 변경 |
| 현재 출력 변환 경로 | 정상 PPU 화면을 수집·표현하고 SNES로 전송할 수 있는 범위 | fetch/compact/raster 거부, 개수·용량, BEGIN/COMMIT/표시ACK, 전송 시간 |

PPUMASK는 배경과 스프라이트의 왼쪽 표시를 별도 비트로 제어한다. 따라서 한 기능을 구현할 때 두 레이어를 같은 것으로 취급하면 또 다른 정상 조합을 놓친다. [NESdev PPU 레지스터 설명](https://www.nesdev.org/wiki/PPU_programmer_reference)

매퍼와 PPU가 완전히 독립적이라는 뜻은 아니다. MMC3 IRQ는 PPU 주소 A12의 변화에 의존한다. MMC3 계열도 서브매퍼에 따라 IRQ 방식이 달라, 게임명이나 매퍼4라는 정보만으로 호환성을 보증할 수 없다. [MMC3](https://www.nesdev.org/wiki/MMC3), [서브매퍼](https://www.nesdev.org/wiki/NES_2.0_submappers)

## 현재 지원표

이 표는 NES 코어 전체의 기능표가 아니라 **새 네이티브 수집·SNES 출력 경로**의 범위다. 기존 경로의 실기 성공을 새 경로의 성공으로 옮겨 적지 않는다.

| 화면 패턴 | 177 배포 경로 | 178 후보 | 후속 대응 |
| --- | --- | --- | --- |
| 한 화면 전체1e: 두 레이어와 왼쪽 모두 표시 | 허용, 도입부 실기 표시. 끊김 있음 | 기존 동작 보존, 기능 시험 통과 | 실제 게임 연속 표시·속도 측정 |
| 한 화면 전체18: 두 레이어 표시, 왼쪽 둘 다 숨김 | 정상 화면을 지속 거부 | 최종 vblank에서 BG1/OBJ window 적용, 픽셀 시험 통과 | SMB3 선택→월드맵→첫 레벨 실기 확인 |
| 한 화면 전체1a: 왼쪽 배경만 표시 | 미지원 | 미지원, 명시적으로 거부 | SNES OBJ만 마스킹; 양 레이어가 겹친 독립 픽셀 기준 필요 |
| 한 화면 전체1c: 왼쪽 스프라이트만 표시 | 미지원 | 미지원, 명시적으로 거부 | SNES BG1만 마스킹; 뒤쪽 레이어가 드러나는 경우 포함 |
| 배경만·스프라이트만 표시 | 미지원 | 미지원 | 수집 완료 조건과 레이어 투명도 함께 구현 |
| 렌더링 꺼짐·다시 켜짐 | 전환 후보를 거부하고 이전 화면 유지 | 같은 제한 | 장기 blank를 정지와 구분하고 배경색/재시작 표현 검토 |
| 회색조·색 강조 | 미지원 | 미지원 | 팔레트 변환·지역별 색 의미 및 갱신 비용 확인 |
| 행 사이 표시 설정 변경 | mask는1e만 | 프레임 전체1e/18만 허용 | 실제 게임 필요 시 행별 마스킹/전송 설계 |
| 행 도중 표시·팔레트·패턴 모드 변경 | 표현 제한, 거부 조건 존재 | 동일 | 행별 상태만으로 표현 불가; 별도 표현/출력 경로 검토 |
| 스크롤·CHR 뱅크·팔레트 분할 | 수집·예외·묶음 수의 제한 안에서 처리 | 기존 범위 보존 | 매퍼 이벤트와 실제 수집 주소를 대조; 용량 초과를 매퍼 오류로 오인하지 않음 |

1a/1c는 정상 NES 설정이지만 현재 출력 후보가 지원하지 않는다. 이를 거부하는 시험의 통과는 **미지원 입력이 잘못 표시되지 않는다는 뜻**이며 해당 기능의 지원 완료가 아니다. 구현 시 화면 오른쪽·왼쪽, 배경·객체 겹침과 우선순위를 함께 비교해야 한다. 두 레이어를 모두 backdrop으로 바꾸는18의 기준 영상을 그대로 사용할 수 없다.

렌더링 비활성은 항상 검정 화면이 아니다. 팔레트 주소 상태에 따라 다른 색이 출력될 수 있고 색 효과도 남는다. 단순히 모든 mask를 허용하거나 blank를 모두 검정으로 치환하면 새 오류를 만든다. [PPU의 렌더링 비활성 동작](https://www.nesdev.org/wiki/PPU_rendering)

현재 용량도 별도 한계다.177 변환기는 묶음32·객체128·예외128·팔레트 최대2시점 등의 범위를 검사한다. 이런 수치는 NES 자체의 한계가 아니라 현 출력 표현의 한계이며, 같은 매퍼의 다른 게임이나 같은 게임의 다른 장면에서 초과할 수 있다. 수집 RAM에 더 많은 공간이 보인다는 이유만으로 변환기·전송기까지 지원한다고 판단하지 않는다.

## 앞으로 적용할 원칙과 순서

1. **178 실기까지 우선 완료한다.** 기존1e/18 후보의 패킷·ARM·필수 FIT/IO 확인 후 SMB3로 전환 화면과 플레이를 확인한다. 모든 게임 지원을 먼저 구현하거나 무입력 도입부를 다시 길게 실행하지 않는다.
2. 같은 화면 거부를 게임명 예외로 우회하지 않는다. `mapper/submapper + 실제 PPU 기능 + 변경 시점 + 표현 용량`으로 원인을 기록한다. ROM 해시는 재현 식별용이며 허용 조건을 바꾸는 키로 쓰지 않는다.
3. 가장 가까운 확장 단위는1a/1c를 포함한 **왼쪽 독립 클리핑4조합**이다. 이후 레이어 on/off·blank 회복, 색 효과, 행별/행중 효과를 실제 목표 ROM 필요에 따라 추가한다. 현재 작업에서 모두 지원한 것으로 기록하지 않는다.
4. 허용 비트만 늘리는 수정은 금지한다. FPGA 수집, MCU 변환·계획, 패킷, SNES 최종 표시를 함께 바꾸고 작은 기능 기준으로 검증한 뒤 실제 ROM을 실행한다. IRQ·sprite0 hit 같은 게임 내부 PPU 동작은 SNES 윈도우로 대체하지 않는다.
5. 앞으로 새 거부 조건을 추가할 때는 최초 이유·generation·mask와 해당 개수/한계를 기존 종료 로그에 남길 최소 경로를 함께 정한다. 일시 전환의 회복과 지속 미지원을 구분하며, 실제 원인 기록 없이 타임아웃만 늘리거나 정상처럼 무한히 이전 화면을 유지하지 않는다. 이 관측 개선은 아직 설계 항목이고178에 추가된 기능이 아니다. 정상 blank를 무조건 오류 종료시키는 공통 짧은 제한도 도입하지 않는다.
6. **정지 해소와60fps를 따로 합격 처리한다.** 반복되는 전체 테이블 전송을 줄이는 base/target generation·최종ACK 기반 차분 전송은 다음 성능 작업이다. 생산·수신/폴링·변환·SNES 완료의 비용과 유효 전송량을 측정하고16.7ms 목표와 비교한다. 표시ACK 개수/전체 시험 시간만으로 FPS를 주장하지 않는다.
7. 새 게임은 부팅만으로 통과시키지 않는다. 타이틀→메뉴→실제 플레이→큰 화면 전환 중 최소 경로, AV·입력·메뉴 복귀를 확인한다. 이미 입증된 공통 기능의 긴 재시험 대신 새 기능과 실제 실패 경계에 필요한 시험을 선택한다.

지원 판단은 `구현 후보 / 모델 검증 / 해당 실기 장면 확인 / 지속 속도 확인`을 구분한다. 이번 결과는 전환 후 mask18 거부의 재현과 후보 기능 검증까지이며, 모든 MMC3 게임·다른 매퍼·지속60fps를 보증하지 않는다. GBC·164 복원·세이브 SRAM은 보존한다.
