# 683: 선행 map과 최종 출력 사이의 병합 경계

683은 planner에서 선행 발행한192B map의 경계를 최종 출력으로 넘겨, 두 위상 모두956·957의 map1024→map1216→BG48B 순서를 구현했다. 입력7블록·첫BG ROM창·952 표시3회·957 최종대기0회·보호조건은 유지했다. 그러나 밀집 평균은MMC666 대비−0.011845/−0.036634ms,957 마지막ACK는+0.485257/−0.009405ms로 동시 개선에 실패했다. 실기 선택본은MMC666이다.

## 구현한 경계

682 read ARM·681 client02·680 RTL을 기준으로 했다. 실제 호출 추적에서 map1024/192B는 BG planner의 offer에서, map1216/192B는 planner가 끝난 최종 출력에서 발행된다. 그 사이 ready BG48B가 들어가 append212의 직전 descriptor 병합을 끊었다. 첫 map 시점에 다음 세 행이 아직 확정됐다는 보장은 없으므로 planner가 보내는 최대 세 행을 늘리지 않는다.

최종 ARM04는 선행 map이 정확히192B였다는 한 번짜리 경계를 `map_pair683`에 저장한다. 다음 출력 호출은 재사용 뱅크·직전 literal map head·인접192B를 모두 확인한 경우에만 기존 내부24번 제출 경로로 먼저 보낸다. 다른 tile/ordinary head·불연속·짧은 범위·cold에서는 기존 producer 중재를 수행한다. 경계는 사용 전에 소모하고 BEGIN/reset에서 초기화한다. 기존 E1 CRC·credit·STOP 검사와 실제 SNES 수락·독립 검사·DMA·최종 표시 ACK는 그대로다.

일반 출력 루프 내부만 묶은 ARM01은 목표 경계에 도달하지 못했고 위상2의952가3→4회로 회귀했다. END callback만 묶은 ARM03도 실제 목표가 planner 안에 있어 병합을 회복하지 못했다. 중간 ARM02는 링크만 했고 재생하지 않았다. 세 가설의 실제 실행과 미실행을 구분하며 원시 실패를 보존한다. 이후에는 기존 `call673`의 부모 호출·immutable·END 시각부터 확인하고, 다른 경계의 단독 변경을 전체 재생으로 반복하지 않는다.

682 대비956 선행map은두위상512→128B,957은1472→512/1280B로 줄었다. 956의 기존248/253번 선 DMA 시각에683은section5 offset21의1100B 반복 패킷을 소비 중이었다. 그 ACK는 기존 첫 DMA 시각보다0.680/0.386ms 늦다. 957 위상1의 기존243번 선1152B DMA 시각에는마지막map3392를소비 중이며ACK가0.192ms 늦다. 새 후보는384B를248번 선에실행했지만기존1152B 선행기회를잃었다. 위상2의238번 선에서는1152B를실행했고,뒤의384B는최종업로드에남았다. 이는같은masterclock의실제load→ACK와DMA기록비교이며,관측하지않은selector분기나모든빈큐구간의원인을단정하지않는다.

957 마지막ACK는682보다0.369693/0.111467ms 늦다. 위상1은직전956표시+0.228521ms와957자체간격+0.139310ms,작은ACK꼬리차로분해된다. map 두패킷의준비시각은거의같지만BG48B 발행이뒤로밀려후속소비가VBlank와겹쳤다. 단순히384B 병합만회복해도전체시간이줄어든다는가정은기각한다. 모델결과를실기FPS로환산하지않는다.

시작 masterclock7288416/7467100, 같은53입력·map/OBJ 작업량·plan 큰 묶음·픽셀을 대조했다. 실제 링크 M4와65816을 실행하고 SPI/IRQ 비용과 포화 boot ROM 허용 달력을 반복 적용했다. 실시간 NES/PSRAM 전체 공동 실행이나 실기 FPS 측정은 아니다. 실기26.84ms에 모델 개선 비율을 곱하지 않는다.

## 보호 조건과 비용

최종 후보의22개 map 인계/credit/STOP/CRC/identity 검사,50개 수신/부분 전송/STOP/반환 검사,메뉴/base5개·marker4개 검사를 통과했다. planner에서는 한 패킷만 보내고, 이후 출력에서만 인접 패킷을 앞당기는 실제 호출 두 개를 함께 검사한다. full ACK identity는 credit 수치가 아니라 기존 drain/through 경계에서 검사하며, 최초 단위 검사의 잘못된 기대는 고친 뒤 재실행했다. 해당 실패 로그도 남겼다. 7블록 완료는 D1 도착이 아니라 D2/D0 반환·CRC/identity 검사 후 poll의 성공 반환 시각으로 계산한다.

전체 ARM Flash212,944B/여유48B, data10,040B/BSS19,544B다. `nes_native_sink165`의 기존 padding offset34에1B를 사용하며 크기988B·ack635 offset36과 이후 필드는 같다. map527 stack은64→56B, 수신poll560B·wait634 40B다. 새 구조체 공간·정적 RAM은 없다. source 생성 재현과 전체 링크 바이너리 hash를 시작/종료 모두 확인한다.

65816/FPGA는682와 동일하다. 기존681 독립 검사·늦은DMA/STOP·최종 ACK 근거를 hash로 연결하며 새로운 RTL 절감으로 세지 않는다. 두 위상 종단 시간 게이트 실패로 새 Quartus Lite 합성/FIT/STA와 설치본은 만들지 않았다. 680 RTL·681 client02가 같다는 사실을 전체 보드 배치/타이밍 통과로 대신하지 않는다. 기존MMC666 실기·GBC·save·ZIP은 유지한다.

## 다음 순서

683의경계기록은검증된비교후보로보존하되실기기준은MMC666을유지한다. 다음은BG loop 완료 직후,OBJ 계산 전에map1216의실제최종쓰기·발행가능시각을계측한다. planner 도중아직확정되지않은행을보내지않고,확정된후속map을앞당겨두map의연속발행을지키면서BG48B와후속ordinary 소비를VBlank보다앞에놓을수있는지비교한다. 956의1100B padding 소비ACK를기존첫선행DMA보다0.680/0.386ms,957 위상1의마지막map3392 ACK를기존1152B DMA시각보다0.192ms 앞당길예산이필요하다. 고정대기·위상·DMA크기변형을반복하지않는다. 두위상의7블록(현재최소여유75µs)·첫BG ROM창·큰묶음·9523회·957최종대기0회·독립검사·STOP·최종ACK·메뉴복귀를유지하고,Flash48B/packedROM0B안에서실제삭제예산을먼저확인한다. 기존call673의부모호출·immutable·END시각으로수정경계가실제목표패킷에적용됨을확인한후종단재생한다. 밀집평균과957마지막ACK가두위상모두개선된뒤에만전체Lite FIT/STA와새실기전달을진행한다.
