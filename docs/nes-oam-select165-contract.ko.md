# NES165 면적 합성과 OAM 축소 시도 결과

PR108의 [실제 보드 연결](nes-sink-board165-contract.ko.md) 이후 작업이다. **동일 RTL의 조합 논리를794개 줄였지만, 실제 배치는 여전히 실패했다.** 선택 결과는 area07이며 설치 후보164와 사용자 세이브는 그대로다. [검증 기록](../analysis/oam-select165-verification.json).

## 채택한 변경

`nes_oam_select165.py`의 기본 `area` 변형은 검증된 board03을 복사하고 QSF에 `CYCLONEII_OPTIMIZATION_TECHNIQUE AREA` 한 줄을 추가한다. RTL·SDC·ROM 등60개 파일의 바이트는 동일하다. 입력에는 QSF 명시 파일뿐 아니라 Quartus가 같은 디렉터리에서 자동 탐색하는 모듈도 포함한다. 최종 공개 도구로 별도 재생성한 결과가 실제 합성 입력과 모두 같은지 확인했다.

일반 이름 `OPTIMIZATION_TECHNIQUE`만 넣은 초기 시도에서는 보고서가 계속 Balanced였다. Cyclone IV용 이름을 사용한 area07에서 **보고서의 실제 적용값 Area**를 확인했다. 설치된 Quartus의 Cyclone IV DSE 설정에도 이 이름이 사용된다. 앞으로 QSF 문자열만 보고 설정 적용을 승인하지 않는다. 면적 최적화와 물리 배치·타이밍 검증은 별개다. [Altera Cyclone IV 설계 지침 AN592](https://cdrdv2-public.intel.com/654795/an592.pdf).

| 항목 | 기존 board03 | 선택 area07 |
| --- | ---: | ---: |
| 합성 추정 LE | 21,442 | 21,070 |
| 조합 논리 | 16,441 | 15,647 |
| 레지스터 | 8,294 | 8,294 |
| 메모리 비트 | 197,104 | 197,104 |
| 실제/가상 핀 | 122/0 | 122/0 |
| PLL | 1 | 1 |
| Fitter | 실패 | 실패 |

조합 논리는794개, 약4.8% 감소했다. 그러나 실제 Fitter170011/171000은15,647개가 칩 한도15,408개보다239개 많아 거부했다. **239개만 줄이면 배치가 보장된다는 뜻은 아니다.** 합성 추정LE, 실제 배치LE, 레지스터와 LAB 포장 조건은 다르다. 배선과 STA는 아직 통과하지 않았다.

## 채택하지 않은 OAM 변경

OAM의 클록·처리 시점·배열 내용을 그대로 두고 두 구조를 비교했다.

1. `onehot-read`: 행 비교값으로 데이터를 마스킹해 읽기 선택을 공유. 전체 조합 논리16,440개, OAMEval5664개. 기존과 사실상 같아 채택하지 않았다.
2. `row-writer`: 쓰기 데이터를 공유하고 행별 쓰기 허가와 CPU/상태 저장 충돌 우선순위를 명시. 전체 조합 논리16,441개, OAMEval5664개로 감소가 없어 채택하지 않았다.

두 변형 모두 실제 banked OAM과 매 클록 출력·native 관측·256바이트 primary/64바이트 secondary OAM·평가 상태를 비교했다. 각각216,362클록, 행 복사2426회, CPU 쓰기3111회, 상태 저장 쓰기10473회, 충돌2012회에서 일치했다. 초기 미정 상태, 지시된 충돌, 난수 입력, NTSC/PAL 전체 주사 순서를 포함한다. 이는 시뮬레이션 비교이며 형식적 등가 증명이나 새게임 실행 증거는 아니다.

기능 시험의 의미는 **두 변경이 잘못된 동작 때문에 탈락한 것이 아니라 자원 절감 효과가 없어 탈락했다**는 것이다. 그 RTL을 활성 후보에 넣지 않는다. area07의 활성 RTL은 board03과 동일하므로 기존 test04·SMB3 기록 재생 근거를 재사용하고 같은 부팅을 반복하지 않았다. 새 배치의 타이밍 승인을 재사용하지는 않는다.

실패·중간 결과도 보존했다: map01 자동 탐색 CIRAM 파일 누락, map03 명시적 generate 구문 필요, prepare05 줄바꿈 때문에 바이트 보존 검사 거부, area06 지원 대상이 다른 설정 이름으로 Balanced 유지. 이들은 선택 결과와 구분한다. 이후 archive와 완료 record/audit를 덮어쓰거나 다시 실행하지 않는다.

## 다음 작업의 구체적 기준

- AREA 결과를 자원 기준으로 사용한다. onehot 선택식·행별 쓰기·같은 AREA 재배치를 무변경 반복하지 않는다.
- 가장 큰 OAMEval은 여전히5663개다. 단순 표현 변경이 같은 회로로 합성된 만큼, 다음 후보는 실제 OAM 읽기 포트·행 복사·저장 구조의 비용을 줄이는 변경이어야 한다.
- 내부 RAM과 사전 읽기를 이용하려면 원래 CPU/PPU의 CE·데이터 소비 시점을 먼저 명시한다. 추가 읽기 지연을 숨겨 붙이거나 CPU/PPU를 느리게 하지 않는다. 행 복사와 동일 주소 쓰기 우선순위도 유지한다. 기존 주기별 비교는 구조가 맞는 범위에서 재사용하고, 시점이 달라지는 변경에는 실제 SMB3 코어의 소비 시점·영상 비교를 추가한다.
- 자원 기준을 만족한 뒤 전체 Fitter·변경된 타이밍을 확인한다. 이어 MCU RUN의 수신→변환→ACK와 실제 경과시간·오디오·입력·STOP 서비스, 전체 링크·중첩 스택을 연결해 SMB3 첫 레벨 실기로 간다.

카트리지 SRAM·세이브·자동 저장·복구 영역은 영상 저장소로 사용하지 않는다. 사운드·입력을 빼서 공간을 만들거나 타이밍 제약을 완화하지 않는다. 새SD·정상 플레이·60fps 완료로 표시하지 않는다. 최소 안정성 이후 실기 데이터를 우선하고 일반 진단 증설과 동일 boot/A-B/044 시험은 생략한다.
