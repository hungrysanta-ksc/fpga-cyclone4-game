# NES168 — 화면 갱신 중단 응답 확인

167에서 첫 화면은 출력됐으나8번째 영상 처리 중 응답 검사 오류로 메뉴에 복귀했다.168은 **그때 받은 응답 원문을 남기는 MCU 변경판**이다. 영상 오류를 고쳤다고 주장하는 판은 아니며, 같은 지점에서 종료될 수 있다.167의 FPGA·SNES 코드·사운드·60초 제한은 그대로다.

1. ZIP의 `01-GAME168-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. `sd2snes/firmware.stm`, `sd2snes/fpga_n168.bi3`, 게임 파일과 표식을 함께 적용한다. FPGA 파일명은 바뀌지만 내용은167과 같다.
2. 메뉴에서 `NES GAME 168.nh1`을 실행한다.0바이트 표식이 정상이다. ROM 적재·전체 비교는 약4분 걸릴 수 있다.
3. 화면이 잠깐 나오고 메뉴로 돌아와도 그대로 두고 아래 TXT 두 개를 전달한다. 먼저 버튼을 누르지 않아도 된다. 계속 실행되면 평소처럼 스타트→첫 레벨로 진행하며 화면·소리를 확인한다. RUN은 최대 약60초이고 오류가 나면 먼저 종료한다.
4. `sd2snes/nes-progress-168.txt`와 `sd2snes/nes-game-last-168.txt`를 전달한다. 마지막 로그가 없으면 진행 로그와 마지막 화면 상태만 알려준다. 같은 짧은 화면이라면 영상은 필요 없다.

표식 선택부터 전체7분 이상 무반응이면 추가 대기를 끝내고 상태를 알려준다. 자동 종료되기 전에 임의로 전원을 끄지 않는다. 새 응답 기록은 RUN 중 메모리에만 보관하고 안전 정지·기본 코어 복구 뒤 TXT에 쓴다.

044/GBC 복원 반복 시험은 필요 없다. 기존 상태로 돌아가야 하면 `02-RESTORE164-SD-ROOT` 안의 내용을 복사한다. 세이브 파일·별도 카트리지 SRAM은 영상이나 로그 임시 공간으로 사용하지 않는다.

실기 결과에서는 화면 갱신 실패 원인을 우선 판정한다. 원인을 확인한 뒤 해당 경로를 수정하고, 연속 화면·사운드→장기 플레이와 오류/본체 리셋 로그→입력 유지 순서로 진행한다.
