# 688: 실제 빈 조회의 소유권과 951 공개선 회복

688은 687의 추정 `bulk_pending` 조건을 실제 E8 빈 응답을 검증한 경로의 허가로 교체했다. 951 공개는 위상1에서 247→236선, 위상2에서 236선을 유지해 246선 제한을 통과했다. 955 선행 DMA·최종 ACK 전 7블록 수신·952 표시 3회·957 최종 대기 0회를 유지했다. 같은 작업량에서 MMC666보다 두 위상의 밀집 평균과 마지막 ACK가 모두 빨라졌다. 모델 개선이며 실기 기준은 MMC666이다.

## 교체한 경계

`nes_plan200_progress`가 실제 E8의 CRC·상태·descriptor를 검사하고 빈 응답을 받은 경우에만 기존 `map_pair683` 비트에 다음 인접 map의 조회 허가를 넘긴다. 이미 소유한 tile의 receipt만 처리하는 빠른 경로, ready descriptor, DONE에서는 허가를 만들지 않는다. `map527`은 허가를 한 번 소비하고 지운다. 전송 실패·STOP에서도 지우며, 이전의 cold·gap·짧은 tail·BG 선행 callback 제한과 패킷별 credit·sequence·CRC 검사는 유지했다. 새 COMMIT·EA는 이전 최종 ACK의 전체 identity 확인 뒤에만 허용한다.

687은 receipt-only 경로에서도 다음 조회를 건너뛸 수 있어 tile 완료·credit·빈 큐 DMA의 순서가 바뀌었다. 688은 이미 저렴한 완료 경로를 조회 절감으로 취급하지 않는다. 프레임 번호·시작 위상·고정 지연을 실행 코드에 넣거나 246 공개선·248/252 DMA 허용선을 완화하지 않았다.

처음 ARM01은 실패한 packet 뒤에 임시 허가가 남는 guard 실패를 발견했다. ARM02에서 실패 경로도 명시적으로 지웠다. ARM01은 전체 재생하지 않았고 실패 로그·소스를 보존했다.

## 두 위상의 같은 작업량

시작 clock 7288416/7467100에서 각각 53화면(905–957)을 연속 실행했다. 실제 링크 M4·동일 685 65816을 사용하고 map·OBJ 작업량, tile payload·최종 이미지, 큰 E9 묶음·두 슬롯, 입력 CRC/POP와 전체 ACK identity를 독립 대조했다.

| 항목 | 위상1 | 위상2 |
|---|---:|---:|
| 951 공개선, 687→688 | 247→236 | 236→236 |
| 951 선행 map DMA, 687→688 | 256→1792B | 1792→1792B |
| 955 큰 선행 DMA | 1536B | 1152B |
| 955 전체 선행 map DMA | 1728B | 1344B |
| 955 최종 ACK 전 7블록 검사완료 여유 | 1.452186ms | 1.503415ms |
| 952 표시 간격 | 3 VBlank | 3 VBlank |
| 957 최종 대기 | 0회 | 0회 |
| 밀집 평균 변화 / MMC666 | −0.051906ms | −0.001248ms |
| 957 마지막 ACK 변화 / MMC666 | −0.188944ms | −0.385896ms |

951 위상1은 SEAL 수락이 오히려 21,608 master clock 늦었지만 선행 map이 1536B 늘어 최종 DMA가 줄었다. 공개는 61089954→61074478로 15,476 clock 빨라졌다. 따라서 SEAL을 일찍 보내는 것만으로 공개선 회복을 설명하지 않는다. 위상2는 같은 공개 clock 61432364를 유지했다. 전체 구간에서 표시 VBlank 수 증가나 최종 대기 추가는 없다.

955 마지막 map ACK는 65016502/65380296이며 위상1의 기존 마감 65025724보다 앞선다. 위상1은 245선 h760에 전체 1536B 범위를 허가해 687의 1152B보다 많이 선행했다. 위상2는 250선 h326에 1152B를 허가했다. 실제 DMA 시작·마지막 byte가 같은 VBlank의 225–261선 안에 있음을 확인했다. 첫 BG의 ROM 허용 구간, 1024/1216 map의 연속 발행, 957의 마지막 384B를 포함한 1536B DMA도 유지했다.

687 대비로는 밀집 평균 변화가 −0.006947/+0.000130ms, 마지막 ACK가 −0.021604/+0.021604ms다. 두 위상 모두 MMC666보다 개선됐지만 모든 값이 687보다 빨라진 것은 아니다. 특히 위상2 밀집 개선은 약 1.25µs로 작고 실기 체감 향상이나 60fps 달성으로 환산하지 않는다.

## 검사와 자원

- 실제 ARM map/CRC/credit/STOP 41개와 조회 소유권 6개를 통과했다. 빈 응답·receipt-only·DONE·ready descriptor·E8 CRC 오류·STOP을 구분했다.
- SEAL/최종 ACK 23개, 입력/credit/STOP 56개, 메뉴/base 복귀 5개·marker 4개를 통과했다. 실물 보드의 메뉴 복귀를 새로 시험한 것은 아니다.
- 두 실제 재생 모두 observer 연결을 첫 호출부터 확인했다. 핵심 화면의 57개 progress 반환 중 11개가 빈 조회 허가였고, 모든 허가에 실제 E8 빈 응답과 성공 반환·pending 없음이 대응했다. 계측은 읽기 전용이며 시간을 할당하거나 코드를 패치하지 않는다.
- 전체 Flash 212984B / 한도 212992B, 여유 8B. data 10040B·BSS 19544B, 새 정적 RAM 0B. 154개 C/H 재현 및 7개 DWARF 구조체가 일치했다. map stack 64B·packet 320B·poll 560B·wait 40B·barrier 24B는 687과 같다.
- 변경된 C 파일은 `nes_native_sink165.c`, `nes_plan_service200.c` 두 개다. firmware SHA256은 `6685fdaea7b0bccad4d0a9303eb881bd76dea47831e4cb82981208f89b851148`이다. 65816은 685의 동일 바이너리(body 5984B/free0, packed free13B)이며 기존 beam/STOP/cold/최종 ACK 취소 검사에 같은 hash로 연결했다.

## 보드와 후속 순서

보호조건·시간 검사를 모두 통과한 뒤, 680의 E0 DMA 진행 RTL과 685의 CPU ROM을 실제 보드에 묶어 Quartus Lite 25.1 전체 컴파일을 한 번 실행했다. 기존 핀·클록·제약·seed는 바꾸지 않았다. 665/MMC666 입력 해시를 모두 대조했으며 변경은 sink bus/SPI/bridge 3개와 CPU hex뿐이다.

| 전체 보드 | MMC666 | 688 결합 후보 |
|---|---:|---:|
| LE | 15324 | 15321 |
| 조합 논리 | 14418 | 14390 |
| FF | 8386 | 8389 |
| M9K | 56/56 | 56/56 |
| LAB | 962/963, 배치 성공 | 969 필요 / 963, 실패 |
| FIT / STA | 기존 통과 | FIT 실패 / STA 미실행 |

총 LE가 87개 남는 산술값은 사용 가능한 배치 여유가 아니다. 6 LAB 부족으로 실제 배치가 실패했으며 새 SOF·설치 ZIP은 없다. 이것을 ARM 변경의 회로 증가나 E0 한 비트만의 비용으로 귀속하지 않는다. 새 RTL을 수정하지 않고 seed/FIT 반복으로 넘기지 않았다. 원래 보드가 가진 1 LAB 여유로는 누적 제어·ROM 결합을 수용하지 못했다. [전체 보드 근거](../analysis/owner688-board.json)

다음은 688 ARM과 685 CPU의 통과 바이너리를 고정하고, 680 E0 진행 공개에 추가된 bus 주소 비교·ack/stop 무효화·SPI flags 선택을 기존 601C 최종 ACK/queue 상태 판정과 공동 처리할 수 있는지 검토한다. 삭제할 비교기·상태 조건과 CDC 소유권을 먼저 특정하고 최소 6 LAB의 전체 배치 부족을 없애야 한다. LE 단독 감소를 성공 기준으로 삼지 않는다. 새 패킷/STOP 우선·실제 DMA 완료 뒤에만 진행 공개·기존 최종 ACK identity를 유지한다. 구조 변경 뒤 해당 RTL guard와 두 위상 전체 일정, 한 번의 전체 FIT·STA 순으로 검증한다. 8B Flash와 packed ROM 13B 여유를 비용 없이 쓰지 않는다. 회로 경계 변경이 불필요하다면 통과 ARM/CPU를 다시 미세 조정하지 않는다.

실기 기준 MMC666과 5–40초·40–55초 비교, RESTORE 제외 방침은 유지한다. 전체 보드가 통과한 뒤에만 새 파일명 전달본을 준비한다.
