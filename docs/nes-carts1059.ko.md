# NES 1059 실기판

디버그판이나 배포판 ZIP 하나를 SD 루트에 풀고 기존 한글판 .nes를 선택한다. 디버그판은 1059 이름으로 계측 로그를 남긴다. 배포판은 시간 제한 없이 플레이하며 퀵메뉴의 EXIT TO MENU로 종료한다. 이전 FF3 슬롯과 SRAM 파일을 그대로 사용할 수 있다.

| 게임 | 일반 저장 | 강제 저장 |
|---|---|---|
| 드래곤퀘스트 IV | 게임에서 모험의 서를 기록하고 퀵메뉴에서 WRITE SRAM. 같은 ROM을 다시 선택하면 8 KiB SRAM이 복원된다. | 슬롯 1–4. 1 KiB ExRAM과 MMC5 은행·보호 레지스터도 복원한다. |
| 와이와이월드 2 | 카트리지의 8 KiB 작업 RAM을 WRITE SRAM으로 백업할 수 있다. 일반 게임 진행 위치는 강제 저장 슬롯으로 보존한다. | 슬롯 1–4. VRC4의 PRG·CHR 뱅크, 미러링, IRQ 카운터와 프리스케일러를 함께 저장한다. |
| 배틀토드 | 이 AxROM 카트리지에는 배터리 SRAM이 없다. | 슬롯 1–4. CHR RAM과 PRG·네임테이블 선택 래치를 복원한다. |

**실기 확인 순서**
게임 장면에서 L+R+START를 누르고 슬롯을 골라 SAVE STATE를 실행한다. 다른 위치로 이동한 뒤 같은 슬롯의 LOAD STATE를 실행해 위치·배경·조작을 확인한다. EXIT TO MENU로 나갔다가 같은 ROM을 다시 골라 한 번 더 LOAD STATE를 실행하면 SD에 보관된 슬롯으로 복귀하는지도 확인할 수 있다. 저장 파일은 ROM CRC·크기와 슬롯별로 구분한다.

## 1058 실기 기준

| 게임 | 1–30초 표시 FPS | 30–60초 표시 FPS | 55–60초 공개 수 | 55–60초 입력→유효 ACK 중앙값 |
|---|---:|---:|---:|---:|
| 와이와이월드 2 | 25.14 | 21.53 | 108 | 46.57 ms (73개 표본) |
| 배틀토드 | 15.10 | 9.00 | 40 | 79.70 ms (40개 표본) |
| 드래곤퀘스트 IV | 18.07 | 19.30 | 84 | 18.27 ms (68개 표본) |

각 게임 1회이며 구간 길이는 각각 29초와 30초다. 사용자가 와이와이월드 2의 첫 스테이지와 드래곤퀘스트 IV의 필드 진입을 확인했다. 세 로그에 STOP과 base 복귀가 기록됐다. 배틀토드의 이전 1057 실행은 16.17 / 6.07 FPS, 마지막 5초에 25화면이었다. 게임 진행과 입력 시점이 달라 성능 차이에는 장면 차이가 포함된다.

## 변경과 검증 범위

- 배틀토드는 마지막 5초의 유효 ACK 표본 40개 중 30개에서 dirty map 행 수가 0이었다. 실제 첫 스테이지의 패턴 RAM 쓰기 그룹 0–2, 47, 48에 맞춰 미러 갱신 단위를 1 KiB에서 512 B로 줄였다. 같은 쓰기에서 SRAM 핀에 나온 쓰기가 3,072→1,536바이트로 줄었다. 65816이 소비하는 데이터와 ARM의 페이지 무효화 기준은 유지했다. 이 값은 한 패턴의 미러 쓰기량이다. 새 판의 표시 FPS는 실기 비교가 필요하다.
- 와이와이월드 2는 체크포인트와 기존 전체 CHR 캐시를 함께 배치할 때 FPGA 용량을 초과했다. 저장 지원 보드는 기존 수집기의 map·OBJ 메모리를 공유하고, 타일 공급은 실제 소비 요청에 맞춰 ROM 포트를 사용한다. CPU 우선권·주소·세대 검사와 STOP 시 미결 읽기 회수를 유지한다. 선행 캐시를 쓰던 1058과 속도가 달라질 수 있어 첫 스테이지의 같은 동선으로 비교한다.
- 드래곤퀘스트 IV는 같은 CPU·PPU·APU 체크포인트에 ExRAM 전체를 추가했다. 기존 FF3 저장 크기는 21,264 B, 드래곤퀘스트 IV는 22,280 B다. 잘못된 크기·ROM과 불완전한 저장 파일은 기존 저널 검사에서 걸러진다.
- 세 ROM으로 CPU를 실행해 저장하고 리셋 후 복원해 이어지는 명령 fetch 64개를 대조했다. 드래곤퀘스트 IV에서는 ExRAM 1,024바이트를 덮어쓴 뒤 독립적으로 대조했다. 별도 시험에서 최종 ARM과 FatFS를 실행해 새 인스턴스가 같은 SD 이미지에서 배터리·슬롯을 읽는지 확인했다. 전체 보드 FIT·STA, PSRAM 핀 타이밍, 프로그래머 변환과 ZIP 구성은 패키징 검사에 포함된다.
- 실기에서는 게임마다 실행 후 nes-game-last-debug1059.txt, nes-progress-debug1059.txt, nes-frame-debug1059.bin, nes-stop-debug1059.bin을 따로 보관하면 비교할 수 있다.
