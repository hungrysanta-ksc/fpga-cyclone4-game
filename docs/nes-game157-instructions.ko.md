# NES157 — 실제 SMB3 정지 직전 읽기 이력 수집

이번157은 **156의 정지 원인을 구분하기 위한 실기 시험판**이다. 게임을 고쳤다고 판정한 버전은 아니다. 다른 장면이나 패턴 시험 없이 같은 SMB3를 실행한다. 기존 음원 채널 차단·화면·패드 전달·ROM 서비스 동작은 유지했다.

## 설치와 실행

1. 정상 메뉴용 SD 백업을 유지한다. ZIP의 `01-GAME157-SD-ROOT` 안의 파일과 폴더를 SD 루트에 덮어쓴다. 최상위 폴더 자체를 복사하는 방식은 아니다.
2. 새 `firmware.stm`, `sd2snes/fpga_n157.bi3`, `sd2snes/nes/game157.nes`가 함께 적용되어야 한다. 루트의 **`NES GAME 157.nh1`**를 실행한다. 이 표식은0바이트가 정상이며 확장자를 바꾸지 않는다.
3. 첫 Start로 선택 화면에 진입한다. **1PLAYER 상태에서 Start를 한 번 눌렀다가 떼고** 다음 장면을 기다린다. Select를 반복할 필요는 없다. 스테이지가 열리면 이동·A/B 점프도 확인한다.
4. 이전처럼 종료되면 메뉴 복귀를 확인하고 SD의 다음 두 파일을 전달한다.
   - `sd2snes/nes-progress-157.txt`
   - `sd2snes/nes-game-last-157.txt`

로딩은 기존384KiB 전체 적재·비교 경로 그대로다. 이전 실측 약3분50초를 참고하되 이번 버전의 시간을 실측했다고 보지는 않는다. 이번 이력 추가로 전체 ROM을 한 번 더 쓰거나 읽지는 않는다. 게임 시작 후 실행 상한은 기존 약60초이며 오류가 감지되면 일찍 메뉴로 돌아온다. 전체7분을 넘겨도 반응이 없으면 더 기다릴 필요 없이 관찰한 상태와 생성된 TXT를 전달한다.

같은 정지와 메뉴 복귀라면 영상은 생략해도 된다. 실제 플레이가 가능해지거나 새 증상이면 짧은 영상이 도움이 된다. 같은044/GBC 복원 확인을 다시 보고할 필요는 없다. 정상 사용으로 돌아갈 때만 동봉 `02-RESTORE044-SD-ROOT`를 사용한다.

## 새 로그의 의미

기존 버튼15~16건 기록에 더해 `ppu_history_*`가 들어간다. 오류 순간을 포함한 **직전16 NES 마스터 클록**을 오래된 순서로 담는다. 매 클록의 PPU line/dot, 실제 주소, 예측주소, 전송 주소, 요청·응답·점유·유효 상태를 기록한다. 유효한 오류 기록이면 마지막 항목이 오류가 난 클록이다. 개별 비트는 개발용 디코더가 해석하므로 사용자가 해독할 필요는 없다.

RUN 중에는 이력을 FPGA 내부 메모리에만 저장한다. 오류/STOP 때 고정하고, STOP 후 MCU가 읽어 기존 안전한 기본FPGA 복귀·TXT 저장 경로를 이용한다. 보조 이력이 잘못되면 valid=0으로 남기며 기존 STOP·메뉴 복귀를 막지 않는다. 실제 전송·클록 고장까지 무조건 복귀를 보장하는 뜻은 아니다.

이번 관측은 임시로 M9K3개를 추가해 전체56/56개를 사용한다. 원인 확인 후 축소·제거할 대상이며, 향후 게임·오디오용 메모리 여유가 확보됐다고 해석하지 않는다. 오디오·저장·정상 속도·전체 외부IO/MTBF는 여전히 미완료다.
