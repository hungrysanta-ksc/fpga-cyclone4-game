# G12S2 실기 기준선: 전원 시작과 RESET 후 재실행

목적은 기존 사용자 실기에서 관찰된 전원 시작과 RESET 후 재실행의 점멸 차이를 같은 게임 경로에서 반복 확인하는 것이다. 대상은 **이미 실기 저장·로드가 성공한 G12S2**이며, 새 G13 FPGA 파일 설치나 하드웨어 개조는 이 시험에 포함되지 않는다. 화면 관찰로 재현 조건을 좁힐 수 있지만 PHI2, SRAM `/WE` 펄스 폭, 270ns 슬롯 또는 전기적 안전성은 판정할 수 없다.

## 시작 조건과 자료 보호

1. 현재 SD에 G12S2가 설치되어 있는지 확인한다. 메뉴의 `G12S` 문구는 G12S2와 이전 판을 구분하지 못한다. 세 파일의 SHA-256은 `firmware.stm` `5eb639a233a6adc26cd2c17ddd450b536e2385e6104dd78846a0775c2d21a4c6`, `fpga_sgb.bi3` `571d0a0b8c5a3b4539ecd78c831489aa7bc73e1fecddb89947f75200752e4442`, `gbc_snes.bin` `9329dfc87dcbe12e18355b46d201cc3c9bab4af30082e690a8d12629097543af`이다. 이 값은 보존된 G12S2 패키지의 manifest 기준이며 화면 표기나 파일명만으로 대신하지 않는다.
2. 전원을 끈 상태에서 SD의 `sd2snes` 폴더와 기존 세이브를 PC의 별도 폴더에 백업한다. 시험 준비와 실행 중 ROM, 펌웨어, FPGA, 세이브를 수동으로 덮어쓰거나 삭제하지 않는다. RESET 때 펌웨어가 시험용 세이브를 기록할 수 있으므로 전후 해시를 비교한다. 중요한 원본 세이브 대신 이전에 검증한 K141 시험용 ROM 이름과 정상 8KiB 세이브의 **복사본**을 사용한다. 준비된 복사본이 없다면 먼저 백업과 복사본을 준비한 뒤 시작한다.
3. ROM 내용과 시험용 `.srm`의 SHA-256을 기록한다. PC의 원본 `.sav`는 변경하지 않는다. 시험용 ROM 이름, 세이브 상태, 컨트롤러, TV 연결과 입력 경로를 전 회차에서 고정한다. 해시는 결과 비교용이며 공개 저장소에 ROM·세이브를 올리지 않는다.

Windows에서는 SD 카드의 실제 드라이브 문자로 `E:`를 바꿔 다음처럼 읽기 전용으로 확인할 수 있다.

```powershell
Get-FileHash 'E:\sd2snes\firmware.stm' -Algorithm SHA256
Get-FileHash 'E:\sd2snes\fpga_sgb.bi3' -Algorithm SHA256
Get-FileHash 'E:\sd2snes\gbc_snes.bin' -Algorithm SHA256
```

## 첫 5쌍의 A/B 시험

한 쌍은 아래 A와 B를 순서대로 시행한다. 각 회차에서 같은 ROM을 선택하고 같은 이어하기 경로로 타이틀 또는 이미 알려진 안전한 초기 플레이 지점까지 간다. 폴리오 상세·오류를 의도적으로 만드는 장면과 게임 내 저장 조작은 피한다.

| 단계 | 조작 | 관찰 |
| --- | --- | --- |
| A: cold | 본체 전원이 완전히 꺼진 상태에서 전원을 켜고 FXPAK 메뉴에서 시험 ROM 실행 | 실행 후 30초 동안 최초 점멸 여부, 시작까지의 시간, 타이틀/플레이 화면, 음향·입력 |
| 경계 | 본체 RESET을 한 번 누르고 FXPAK 메뉴가 **완전히** 돌아올 때까지 기다림 | 저장 오류 LED 교대, 메뉴 복귀 실패, 걸린 시간 |
| B: warm | 전원을 유지한 채 같은 ROM을 메뉴에서 다시 실행 | 같은 30초 구간의 최초 점멸 여부·시점·화면·음향·입력 |
| 종료 | 다시 RESET하여 메뉴 복귀를 기다린 뒤 전원을 끔 | 다음 쌍 전까지 SD 기록이 끝났는지 확인 |

먼저 1쌍을 하고 저장 오류나 메뉴 복귀 문제가 없을 때만 최대 5쌍까지 진행한다. 점멸이나 정지 화면이 나타나면 가능하면 RESET **전에** 화면 전체와 발생 시점을 촬영한다. 60fps 휴대전화 동영상은 화면 증상과 순서 비교에 쓸 수 있으나 버스 파형 측정값은 아니다. 한 쌍 안에서 A와 B의 화면 경로·관찰 시간을 맞춘다. 전원을 게임 실행 중 바로 끄거나 저장/진단 기록 도중 끄지 않는다.

기록 양식(한 행은 A 또는 B 한 회차):

| 쌍 | A/B | ROM·세이브 복사본 ID | 실행→첫 화면 시간 | 30초 내 점멸 횟수·첫 시점 | 화면/오류 문구 | 음향·입력 | RESET→메뉴 결과 | 영상 ID |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | A | | | | | | | |
| 1 | B | | | | | | | |

시험 뒤 전원을 끄고 SD를 PC에 연결해 시험용 `.srm`과 `.srm.gbc-prev`가 있다면 모두 별도 폴더에 복사하고 SHA-256을 기록한다. 시험 전후 세이브 내용이 달라졌다면 이를 표시한다. 내용이 달라진 회차는 동일 초기 상태의 cold/warm 비교로 단정하지 않는다. 영상이나 오류 사진에는 개인 정보가 있으면 공유 전에 가린다. ROM·세이브·진단 dump는 공개 이슈/PR에 첨부하지 않는다.

## 중단과 해석

- LED가 번갈아 점멸하거나 RESET 뒤 메뉴 복귀가 안 되거나, 저장이 손상된 듯하면 반복하지 않는다. 전원을 바로 차단하지 말고 현재 화면을 촬영해 상태를 알린다. 복귀 후 관련 `.srm`, `.srm.gbc-prev`, `.srm.gbc-tmp`를 보존한다.
- A와 B의 차이가 반복되면 콘솔 전원 시작과 MCU의 메뉴 재실행 경계, 외부 메모리/세이브/시작 위상 조건을 좁히는 근거가 된다. 어느 회로가 원인인지는 이 관찰만으로 확정하지 않는다. 차이가 없더라도 간헐적 결함이나 G13의 안전성을 통과시킨 것은 아니다.
- 현재 설치판이 G12D나 다른 판이면 이 절차를 그대로 시작하지 않는다. G12D는 RESET 때 별도 진단 파일을 쓸 수 있다. 설치판을 확인한 뒤 그 판에 맞는 짧은 절차로 조정한다.
