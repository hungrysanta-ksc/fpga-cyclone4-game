# 커비 MMC1025 후반의 마지막 OBJ 공개 지연

## 실기에서 확인한 경계

57.61초의 세대 1657과 57.62초의 세대 1619를 각 BIN의 패킷 시각과 CRC·세대·토큰을 통과한 FPGA 헤더로 대조했다. 두 화면은 BG 661개로 같지만 각각 24타일·3묶음과 22타일·7묶음이다. 마지막 OBJ는 각각 512B와 96B다. 관찰한 차이에는 작업량 차이도 포함된다. [두 회차 실측](../analysis/kirby1025-hardware.json)

| 구간 | 1차 1657 | 2차 1619 | 2차 − 1차 |
|---|---:|---:|---:|
| 직전 공개 → 첫 E9 | 10.53ms | 14.43ms | +3.90ms |
| 첫 E9 → 마지막 FPGA 타일 묶음 공개 | 28.48ms | 44.86ms | +16.38ms |
| 마지막 묶음 공개 → SEAL 헤더 수락 | 2.34ms | 2.73ms | +0.39ms |
| SEAL 수락 → 화면 공개 | 8.58ms | 4.29ms | −4.29ms |
| 표시 간격 | 49.93ms | 66.32ms | +1 VBlank |

세대 1619의 마지막 토큰은 3135다. 두 뱅크는 공개·소비 순서대로 교대한다. 마지막 뱅크를 먼저 사용한 토큰 3133이 반환돼야 그 다음 토큰 3134가 읽기 헤드에 나타난다. ARM의 `poll()`은 E8 응답의 CRC·descriptor를 확인한 뒤 op7을 조립한다. 일곱 번째 묶음 직전 op7의 조립 시각에 한 ARM 눈금을 더해도 BEGIN 후 **37.626ms**다. 따라서 그 시각까지 토큰 3133은 반환됐다. 누적 credit의 관측 시각을 실물 반환 시각과 동일하게 두지 않았다. 토큰 3134 패킷의 누적 credit도 **38.583ms**까지 관측됐다.

마지막 묶음의 FPGA 공개는 ARM/FPGA 시계 정렬 오차를 포함해 **49.932–51.944ms**다. 상한은 마지막 op7 조립이 유효 descriptor 관측 뒤라는 제약과 교차했다. 마지막 뱅크의 이전 소유권은 공개 최소 **12.306ms** 전에 끝났고, 공개 뒤 op7 발행 대기는 최대 **2.018ms**다. 앞 단계에서 발생한 backpressure가 이후 일정을 밀었을 가능성은 남는다. NTSC VBlank 주기 16.639ms, 길이 상한 2.45ms, FPGA 시각차 오차 ±0.3901ms를 적용하면, 묶음 공개는 직전 VBlank의 가능한 마지막 시각보다 최소 **6.777ms** 늦었다. SEAL 수락은 최소 **9.508ms** 늦었다. 두 수치는 겹치는 마감 하한이다.

## RTL 분리 시험

MMC1025와 동일한 보드 소스의 `nes_source_tile192`, 실제 캐시·ROM 중재, 타일 mailbox, `nes_tile_bulk206` 및 두 뱅크 aperture를 연결했다. 실기에서 읽은 22타일·7묶음의 종류·시작 슬롯·토큰 순서와 마지막 96B를 사용했다. 앞 여섯 묶음의 길이와 14비트 태그, 메모리 응답, 소비자 타이밍은 통제한 시험 입력이다. 포트의 읽기 시각을 움직인 시험은 ARM의 실제 SPI 재생 대신 외부 소비자가 descriptor를 관측하는 경계만 검사한다.

| 개별 주입 | ROM 요청 대기 (NES 클록) | 뱅크 OPEN 대기 (host 클록) | FPGA 마지막 공개 변화 (host 클록) | 처음 관측된 영향 |
|---|---:|---:|---:|---|
| 대조군 | 0 | 0 | 0 | 마지막 3타일 소비용 ROM 허가 24회 |
| 소비용 ROM 허가 보류 | 800 | 0 | +3,129 | 마지막 타일 완료 지연 |
| 재사용할 뱅크의 반환 보류 | 0 | 801 | +802 | OPEN 대기 후 마지막 타일 완료 지연 |
| 마지막 타일 뒤 END 보류 | 0 | 0 | +3,055 | 마지막 타일 완료 시각 동일, END 수락 지연 |
| descriptor 관측 보류 | 0 | 0 | 0 | 관측만 +801 host 클록 |

다섯 경우 모두 7개 descriptor, 640B 저장 내용과 생산 바이트의 일치, 정상 토큰 반환 및 STOP 뒤 출력 해제를 확인했다. 이 시험은 지연 경계의 구별 가능성을 검증했다. 실기 세대 1619에서 실제 ROM 요청·허가 또는 END가 발생한 시각은 MMC1025에 기록되지 않았다. ## 다음 실기에서 구분할 항목

먼저 마지막 OBJ의 실제 plan 수락 → 소비용 ROM 요청·허가 → 마지막 `tile_done` → bulk의 END 수락 → writer 공개를 같은 세대로 결합한다. `OPEN && !begin_ready` 구간과 E8에서 현재 토큰이 처음 유효해진 시각은 별도로 둔다. 같은 묶음 안에서 겹친 대기는 합산하지 않는다. 타일 완료가 늦고 소비용 요청이 대기한 화면에서만 ROM 공급 일정을 바꾸고, 완료 후 END가 늦으면 마지막 plan·END 공급을 조정한다.

MMC1016의 진단 회로는 타일 태그 13비트·주소 17비트이고 뱅크 반환은 처음 세 건만 저장한다. 그 해석기도 15타일·3묶음으로 고정되어 있어 커비의 14비트 태그·7묶음에 적용할 때 상위 비트, 마지막 반환, 종료 뒤 유효성 보존을 다시 검증해야 한다. 이번 회차는 실기 MMC1024 기준과 배포 비트스트림을 유지했다.

재현은 기존 FLOAT 래퍼에 `tools/check_nes_kirby1026.ps1`의 절대 경로를 넘긴 뒤, `python tools/analyze_nes_kirby1026.py <1차 BIN> <2차 BIN> ../probes/nes-kirby1026 analysis/kirby1026-boundaries.json`을 실행한다.
