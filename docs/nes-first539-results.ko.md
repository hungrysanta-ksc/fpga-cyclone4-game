# 539. 913의 첫 BG 공급과 951 표시를 같은 일정에서 검증

## 놓친 구간

시작 클록 3,178,684에서 912의 실제 표시를 0으로 맞췄다. 두 실행에서 첫 E9 앞에 보낸 출력 패킷은 BEGIN 31B 한 건이었다.

| 913의 구간 | 실기 기준 MMC533 | MMC533 ARM + 538 소비기 |
|---|---:|---:|
| 직전 표시 → 입력 시작 | 0.610ms | 0.778ms |
| 입력 시작 → BEGIN E1 완료 | 20.805ms | 21.020ms |
| BEGIN 완료 → planner 진입 | 0.997ms | 0.998ms |
| planner 진입 → 첫 E9 전송 시작 | 10.746ms | 10.746ms |
| 첫 E9 전송 | 0.104ms | 0.104ms |
| 직전 표시 → 첫 BG ROM 요청 | 33.267ms | 33.649ms |
| 요청 → 첫 grant | 0.0002ms | 15.716ms |

912의 최종 ACK는 표시 뒤 약 0.135ms에 발생했다. 첫 E0 상태 읽기가 시작된 시각은 −0.079ms에서 +0.089ms로 바뀌었지만 두 경우 모두 아직 수락 266·완료 265를 돌려줬다. 완료 266과 표시 상태 1을 관측한 두 번째 읽기도 같은 만큼 밀렸다. E8·EA까지 마친 뒤 다음 입력을 시작하는 순서를 유지하고, ACK 대기 비용과 planner 작업을 따로 실험했다.

## 변경과 검증 기준

- **행 주소 비교**는 같은 COMMITTED 입력에서 두 줄이 같은 33-word map 행을 참조하면 66B 비교를 생략한다. 이 판정은 286의 분할 planner에도 쓰인 것으로, 이번에는 실기 MMC533 planner에만 이식했다. 서로 다른 행은 마지막 word까지 기존 내용 비교를 수행한다. 913 입력에서 원래 비교에 도달하는 193건은 모두 같은 주소였다.
- **행 주소·fine Y 재사용**은 직전 일반 줄에서 구한 fine Y도 재사용한다. 패치 줄 바로 뒤의 일반 줄에서는 원래 조건대로 이전 fine Y를 참조하지 않는다. 추가 프레임 버퍼나 프레임 간 이력을 두지 않는다.
- **최종 ACK 폴링**은 진척이 없고 마지막 명령이 SEAL인 동안의 목표 휴지를 128→64µs로 줄인다. credit·일반 drain 휴지는 128µs다. CRC·완료 개수·ACK identity·STOP·EA 검사는 기존 절차를 실행한다. E0 SPI가 늘면 그 비용도 연속 일정에 포함한다.
- **결합**은 행 주소·fine Y 재사용과 64µs 최종 ACK 폴링을 함께 적용한다. 네 정책 모두 해시가 같은 538의 65816 소비기를 사용한다.

같은 geometry·raw 입력과 ROM 허용표를 사용해 905–957을 시작 클록 3,000,000과 3,178,684에서 실행했다. 통과 조건은 두 실행 모두 첫 BG가 있는 30개 화면의 상대 ROM 구간이 MMC533보다 늦어지지 않고, 951의 SEAL 수락 후 표시가 한 VBlank이며, 952·954의 최종 대기가 0회인 것이다. 동시에 951–955의 표시 간격과 VBlank 합, 957의 절대 최종 ACK가 MMC533보다 줄어야 한다. 이 숫자는 ARM 명령·공유 SPI·IRQ·두 tile bank·65816을 연결한 시뮬레이션 결과다.

## 결과와 선택

| 정책 | 951–955 평균 간격(ms), 위상 1 / 2 | 밀집 VBlank 합 | 957 ACK 차이(ms) | 913 ROM 여유(ms) |
|---|---:|---:|---:|---:|
| MMC533 | 103.109 / 103.115 | 31 / 31 | 기준 | 0.037 / 0.242 |
| MMC533 ARM · 538 소비기 | 99.789 / 99.813 | 30 / 30 | −66.554 / −49.918 | 0.244 / −0.126 |
| 행 주소 비교 | 99.870 / 99.870 | 30 / 30 | −183.037 / −166.375 | 1.115 / 1.276 |
| 행 주소·fine Y 재사용 | 99.874 / 99.869 | 30 / 30 | −183.037 / −166.369 | 1.449 / 1.367 |
| 최종 ACK 64µs | 99.789 / 99.809 | 30 / 30 | −99.841 / −83.191 | 0.064 / −0.003 |
| 결합 | 99.876 / 99.874 | 30 / 30 | −199.679 / −166.373 | 1.696 / 1.368 |

음수 ACK 차이는 MMC533보다 빠르다는 뜻이다. ROM 여유는 MMC533과 같은 상대 구간의 마지막 grant까지 남은 시간이다. 폴링 단독은 두 번째 위상에서 913을 약 3µs 놓쳤고 최종 수락 조건을 통과하지 못했다. 나머지 세 정책은 두 위상의 30개 첫 BG 구간, 951의 SEAL 후 한 VBlank 표시, 952·954 최종 대기 0회와 밀집·마지막 ACK 조건을 모두 통과했다.

**행 주소 비교만 적용한 ARM을 선택했다.** 913의 planner 진입→첫 E9 시작이 10.746→9.593ms가 됐다. 최종 ACK 휴지는 128µs를 유지한다. 53화면의 E0 전송량은 105,620 / 106,000B로 결합의 122,940 / 124,380B보다 작고, 두 번째 위상의 마지막 ACK는 결합과 사실상 같았다. E1은 모든 정책에서 171,401B였다. fine Y 재사용만 추가해도 밀집 VBlank나 마지막 ACK가 더 줄지 않았다.

선택 ARM Flash는 212,428B(여유 564B)로 MMC533보다 8B 증가했고 BSS는 18,592B로 같다. 538의 소비 ROM·4,949B 본체·기존 246행 검사를 그대로 사용한다. 서로 다른 주소의 같은 내용, 마지막 word 차이, 예외·패치 경계 및 실패 입력의 linked-M4 video/plan 대조가 모두 같았다. 네 후보의 여덟 연속 실행은 각 53장 RGB, 실제 소비된 map·tile, ROM 읽기 5,616회, VRAM DMA 125,488B와 독립 재생을 통과했다.

실기 전달 식별자는 MMC540으로 분리한다. 동일 함수 코드·새 설치/로그 경로·메뉴/base 복구 검사와 Quartus Lite 전체 보드 FIT·STA를 연결한다. [MMC540 설치 및 회수할 로그](nes-mmc540-trial.ko.md)
