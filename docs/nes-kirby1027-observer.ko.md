# 커비의 마지막 OBJ 지연을 구분하는 32B 계측

MMC1025의 57.62초 화면에서는 첫 E9에서 마지막 writer 공개까지 44.86ms가 걸렸다. 마지막 뱅크의 이전 소유자는 공개 최소 12.306ms 전에 반환됐다. 1027은 마지막 연속 슬롯의 첫 plan 수락, 소비용 CHR 첫 요청·첫 허가, 마지막 타일 완료, END 수락, writer 공개, 최종 토큰의 첫 E8 스냅샷을 같은 표시 세대에 기록한다. ROM 선행 읽기 자체는 소비용 요청을 발생시키지 않는다. [실기에서 이미 확인한 범위](nes-kirby1026-boundaries.ko.md)

## 시각과 유효성

NES 도메인에서 등록한 단일 비트 사건을 84MHz 쪽 두 단계 동기화기를 통해 관측한다. req/grant의 근거는 `foreground`와 `foreground && shared_ready`다. 뱅크의 첫 유효 E8은 헤드가 준비된 순간의 실제 SPI 명령 스냅샷이다. 같은 헤드의 재조회로 덮어쓰지 않고 반환 뒤 다음 토큰에 대해 다시 기록한다. 실제 ARM의 검증 완료 시각은 55–60초 두 상세 표본의 op7 준비 시각으로 상한을 구한다.

기존 32B 헤더에서 6–8번 바이트에 첫 E9·조회·마지막 writer 시각의 하위 8비트를 저장한다. 9번 바이트에는 세 시각의 상위 2비트씩과 첫 요청·허가 유효 비트를 저장한다. 10–11번은 요청·허가, 26–29번은 plan·마지막 완료·END·첫 E8의 하위 8비트다. 세대와 최종 토큰, SEAL·마지막 DMA·화면 공개·최종 ACK 필드는 기존 위치를 쓴다. 충돌하거나 END·마지막 E8이 빠진 묶음은 유효 footer를 받을 수 없다. STOP은 읽기 권한을 취소한다. 빈 화면은 이전 묶음의 잔류 필드를 해석하지 않는다.

한 눈금은 84MHz의 32,768클록(0.390095ms)이다. 동기화 지연과 겹친 E8 저장의 한 host 클록은 이보다 작지만 경계에서 한 눈금 차이가 날 수 있다. 입력에서 조회까지 255눈금 이상인 표본은 하위 8비트 해석에서 제외한다. MMC1025의 두 BIN에 이 기준을 적용하면 회차별 유효 타일 표본 각 74개가 모두 범위 안이며, 세대 1657·1619의 보수적 관측 길이는 51.85·67.50ms다. 첫 허가 이후의 행별 ROM 경쟁 또는 앞선 묶음의 공급 지연까지 이 값으로 역산할 수는 없다.

## 재현

- 보드와 ARM을 각각 `tools/prepare_nes_kirby1027.py board` 및 `arm`으로 생성한다. 입력은 1023 보드와 1025 링크이며, 출력은 `probes/nes-kirby1027/board-tag` 및 `link`다.
- 기존 FLOAT 래퍼로 `tools/check_nes_kirby1027.ps1`을 실행하고 `tools/check_nes_kirby1027_header.py`로 실제 직렬화 바이트를 판독한다. 다섯 지연 조건과 E8 또는 END 관측을 하나씩 누락시킨 두 조건을 포함한다.
- 22타일·7묶음·640B 시험의 마지막 토큰은 3135다. 주소 상위 비트가 있는 통제 입력을 쓰며 실제 게임 ROM의 시각은 물리 로그로 판정한다. ROM 허가 보류는 첫 허가와 타일 완료를 밀고, END 보류는 완료 시각을 보존하며 END와 공개를 민다. 헤드 관측 보류는 writer를 보존하며 E8만 민다.
- `tools/fit_nes_kirby1027.ps1 -Board <생성한 보드> -Out <새 결과 폴더>`로 Lite 전체 컴파일과 PSRAM 핀 지연을 측정한다. ARM은 기존 `build_nes_trial577.ps1`로 링크한 뒤 `check_nes_kirby1023_release.py`의 guards·run·base를 1027에 실행한다. 실기 배포는 최종 빌드의 전체 FIT·STA와 핀 여유, 프로그램 바이트 왕복 확인 뒤에만 가능하다.

## 버스 회귀 검사

기존 화면 상태 회로의 동기화가 끝난 주소·데이터를 두 소비자가 공유한다. 구성 리셋 또는 PLL lock 손실은 코어와 sink 세션을 닫고, 새 세션은 두 동기화 클록과 host 준비를 거친다. 세션을 다시 열 때 첫 두 클록은 기존 sink와 같이 0으로 채운다. ROM 태그의 직전 주소를 재사용할 때도 같은 조건으로 마스킹한다. SPI73은 요청 시점에 상태를 동결한 뒤 기존 byte/bit 카운터로 직렬화한다.

구형·신형 RTL을 같은 클록에서 10,966회 대조해 ROM·패킷 읽기, ACK, 진행 공개, 비동기 리셋·세션 재시작 및 STOP을 검사했다. SPI73은 실제 응답 중 stage와 frame 수가 변하는 경우, 부분 요청·리셋, 끝을 지나 읽는 경우까지 346비트를 대조했다. ARM 60초 타이머·SRAM D0·손상 CRC 거부·최종 ACK·base 복구·메뉴 해제는 링크 실행 시험을 통과했다.

## 전체 보드 결과

검사 플래그를 포함해 시각을 레지스터에 보관한 후보는 970 LAB을 요구했다. 시각 M9K 분리, 직전·현재 공개의 RAM 교대 저장, SPI73 고정 응답의 비트 인덱싱 후보는 각각 966 LAB을 요구했다. 두 번째 주소·데이터 동기화 단계를 공유하면 964 LAB이었다. 같은 주소를 보유하던 ROM 태그를 재사용한 최종 후보는 **15,357/15,408 LE, 963/963 LAB, 56/56 M9K**로 배치됐다. 어느 후보도 배치 seed를 변경하지 않았다.

Quartus Lite 25.1 전체 STA 57개 항목은 최소 slack +0.072ns, TNS 모두 0이다. 70ns PSRAM과 PCB 지연 4ns 가정의 최저 핀 여유는 주소 3.521ns, CE/OE 3.777ns다. 기존 보드와 같은 외부 I/O 미제약 수(입력 63/63, 출력 54/55)가 남는다. 최종 ARM은 212,936B로 56B가 남고, 75회 × 32B 채집과 최종 BI3의 프로그래머 바이트 왕복을 확인했다. ## 커비 실기 두 회

두 회차 모두 786,432B 대조, 약 60초 실행, STOP, base 복구와 메뉴 복귀를 확인했다. 전송 실패와 캡처 abort는 모두 0이다. 1–30초와 30–60초에 공개한 화면 수는 각각 739/783장과 733/782장이다. 두 회 평균은 25.38/26.08 FPS다. MMC1024의 같은 평균은 26.09/27.32, 같은 계측량의 MMC1025는 27.24/28.37 FPS다. MMC1027 각 회에서 75개 표본 중 74개의 헤더와 사건 순서를 판독했다. 30–60초 프레임 시작 기준 출력·최종 ACK는 27.69/27.66ms로 MMC1025의 24.15/24.75ms보다 길었다.

57.63초에 두 회 모두 BG 661, OBJ 16, 변경 map 6, 타일 23개·4묶음이며 마지막 OBJ는 128B다. 첫 E9를 기준으로 마지막 묶음의 소비용 ROM 요청은 8.19/7.02ms, 첫 허가는 23.41/22.63ms, 타일 완료·END·writer 공개·첫 E8 관측은 23.80/23.02ms다. 첫 요청에서 허가까지 15.21/15.60ms이며, 이후 소비 완료까지는 각 한 눈금이었다. 두 회 모두 표시 간격은 49.93ms다. 관측 단위는 0.390ms이며 같은 눈금 안의 사건 사이에도 지연이 있을 수 있다.

같은 400ms 구간에서 다섯 작업량 수치가 일치한 54쌍 중 51쌍은 표시 VBlank 수가 같았다. 32.42초와 48.03초 부근에는 2차 첫 ROM 허가 대기가 각각 7.80ms 늘면서 표시 간격도 한 VBlank 늘었다. 37.22초 부근에는 소비용 ROM 요청 없이 2차가 한 VBlank 빨랐다. 2차 59.63초에는 첫 허가 뒤 타일 완료까지 16.38ms가 걸려 첫 허가만 앞당겨서는 설명되지 않는 사례도 있다. 두 버전의 같은 400ms 구간·작업량을 교차 대조한 네 회차 조합에서는 31–52쌍 중 각각 7–9쌍이 MMC1027에서 한 VBlank 더 걸렸다. 이 집계로 계측 회로 자체의 인과 효과나 CHR 주소·캐시 내용의 동일성을 보장하지 않는다.

다음 대조 시험은 두 게임에서 공통으로 적용 가능한 계획 확정 시점과 ROM 허가 구간을 맞춘다. 57.63초 사례의 첫 요청과 59.63초 사례의 후속 요청을 구분하고, 독립 검사·STOP을 유지한 상태에서 화면 공개와 최종 ACK가 같이 앞당겨지는지 본다. [회차별 원본 해시·계측값·표시 간격 대조](../analysis/kirby1027-hardware.json)
