# MMC899 실험 · OAM 재사용 발행 순서

MMC897의 ARM에서 대상 뱅크 이력을 확인하는 OAM 재사용 명령을 section 5의 마지막 두 패킷 앞으로 옮겼다. 1970·3470 모두 OAM을 일찍 받았지만 잔여 DMA와 화면 공개는 같은 VBlank에 머물렀다. 실기 기준은 MMC897이다.

## 같은 화면의 재생 결과

898에서 보존한 30–35초와 55–60초 무입력 캡처를 사용했다. 구간별 첫 두 장으로 양쪽 뱅크를 준비한 뒤 여섯 표시 간격을 측정했다. 대응하는 24쌍에서 변경 map 행·OBJ·BG, D1 개수·바이트, 일반 패킷의 주소·내용, map과 표시 RGB를 대조했다. 897과 후보의 65816 바이너리·입력·시작 시각·SPI 비용·ROM 허가 일정이 같다. 수치는 연결 재생에서 얻었으며 실기 FPS는 MMC897의 기존 측정치가 기준이다.

¹ 각 링크의 같은 화면 planner 진입 기준. ² 같은 부팅 시각 기준. OAM은 헤더 포함 132B, 두 section 5 패킷은 217B·256B였다. 패킷 순서와 실제 65816 수락을 모두 확인했다.

1970에는 SEAL 수락 뒤 1,954B가 남았다. 1,472B map DMA가 다음 VBlank 225선에서 시작했다. 3470에는 768B map을 미리 보냈고 잔여 DMA 1,346B가 다음 VBlank 225선에서 시작했다. 후보의 SEAL은 직전 공개 마감인 246선이 지난 뒤에 도달했다. 1970은 두 위상에서 각각 **최소 6.443·6.522ms**, 3470은 **최소 7.061·7.063ms** 늦었다. 이 하한은 실제 기록된 직전 VBlank의 247·253·254선 이벤트에서 SEAL 수락까지의 시간이다. SEAL 이후 독립 검사와 DMA에 쓸 시간은 추가로 필요하다.

## 보호 조건과 판단

실제 ARM 시작 코드가 D0의 8B를 SRAM `0x20000320`에 복사했고 네 송신 지점에서 이를 사용했다. 첫 화면의 정상 수신은 D1·D2 각 33회, 최종 ACK·EA 뒤 STOP으로 끝났다. D1 CRC 오류와 1,247회 빈 제안도 검사했다. 65816에는 1970의 OAM 재사용 패킷에서 최종 ACK 뱅크 일련번호만 손상시켰다. 상태 `0xE0`로 거부했고 앞서 공개한 다섯 번째 화면의 RGB와 표시 identity가 보존됐다. STOP·base 복구·메뉴 준비와 RESET 해제는 연결 ARM과 모델 주변장치에서 확인했다.

최종 후보 ARM은 213,000B로 212,992B 한도를 8B 넘었다. 원본은 212,988B였다. 순서 변경으로 표시 마감을 넘긴 사례가 없어 실기판으로 채택하지 않았다. 다음 비교는 MMC897 실기 두 구간에서 같은 세대의 입력 완료, 마지막 map·tile 수락, SEAL 수락, 마지막 DMA·공개와 유효 E0를 연결해 실제로 한 VBlank를 잃은 화면을 특정하는 것이다.
