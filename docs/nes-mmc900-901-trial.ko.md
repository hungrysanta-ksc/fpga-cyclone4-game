# 모험도 4 · MMC872와 MMC897의 화면별 VBlank 비교

MMC900은 실기 기준 MMC872의 ARM·65816을, MMC901은 MMC897의 ARM·65816을 사용한다. 두 설치본은 같은 방식으로 이벤트를 기록한다. 두 판에서 같은 일본판 모험도 4 ROM으로 각 60초 동안 버튼을 누르지 않는다.

| 순서 | SD 루트에 복사할 폴더의 내용물 | SD에 넣을 사용자 ROM | 선택할 메뉴 |
|---|---|---|---|
| 1 | `MMC900-ADVENTURE-60SEC-SD-ROOT` | `sd2snes/nes/mmc900.nes` | `NES MMC3 900.nh1` |
| 2 | `MMC901-ADVENTURE-60SEC-SD-ROOT` | `sd2snes/nes/mmc901.nes` | `NES MMC3 901.nh1` |

판을 바꿀 때 전원을 끄고 ZIP 속 해당 폴더의 **내용물**을 SD 루트에 복사한다. MMC897 때 썼던 `mmc897.nes`를 표의 이름으로 복사해 사용한다. 오프닝, 무입력 플레이 데모와 60초 뒤 자동 메뉴 복귀를 확인한다.

메뉴 복귀 뒤 SD의 `sd2snes`에서 아래 네 파일을 판별로 보관한다. MMC901에서는 네 이름의 숫자가 모두 `901`이다.

- `nes-frame-mmc900.bin` — 화면별 이벤트
- `nes-budget-mmc900.txt` — 5초 구간 작업량과 오프닝·데모 표시 수
- `nes-progress-mmc900.txt` — 실행·STOP·메뉴 복구 경과
- `nes-game-last-mmc900.txt` — 마지막 세션 상태

**먼저 각 판의 기본 실행 한 번씩이면 된다.** 추가 대조가 필요하면 기존 로그를 PC에 복사한 뒤 같은 설치의 `NES-DIAG/NES CONTROL 900.nh1` 또는 `901`을 실행한다. CONTROL은 동일 ARM에서 화면별 SPI 조회만 생략한다. `EARLY`·`LATE` 메뉴는 기본 기록이 포화됐을 때 각각 30–35초와 55–60초에 기록 공간을 전부 쓴다. 추가 실행은 같은 판의 네 로그를 덮어쓴다.

## 로그 해석

최종 링크 재생에서 MMC901은 두 구간·두 시작 위상 모두 원래 표시 간격을 유지했다. MMC900에서는 앞 구간의 한 위상과 뒤 구간의 두 위상이 여섯 화면 합계에서 각각 1 VBlank 늘었다. MMC900 CONTROL도 앞 구간의 다른 위상에서 1 VBlank 늘었다. 두 계측판이 한 번 차이 날 때는 이 영향을 함께 확인한다.

60초 타이머의 화면 **시작** 틱이 [30,35)초 또는 [55,60)초에 속하는 세대를 기록한다. 표시가 시간 경계를 넘어도 시작 구간에 남는다. 각 행은 세대·대상 뱅크·변경 map 행·OBJ·BG, 마지막 D2가 반환됐음을 확인한 ARM 시각을 담는다. 앞 화면 표시 중 다음 입력이 완료되는 경우에 대비해 최근 두 입력 완료를 세대 번호로 찾는다. 양쪽 세대가 같은 홀짝이어도 구분한다.

FPGA는 마지막 map·tile 패킷의 65816 헤더 읽기와 독립 검사 후 큐 반환을 별도로 기록한다. SEAL은 헤더 읽기, DMA 종료는 7F WRAM에서 VRAM·팔레트·OAM 포트로 전송한 마지막 바이트, 화면 공개는 SEAL 이후 밝기 포트 쓰기다. 최종 ACK는 FPGA가 65816의 표시 ACK를 검증해 큐에서 반환한 시점이다. ARM이 같은 identity의 유효 E0를 처음 확인한 시점도 남긴다. map 또는 tile 패킷이 없던 화면은 해당 이벤트가 비어 있다. 뱅크 이력 재사용은 실제 발생한 패킷 종류대로 집계한다.

FPGA 시간 해상도는 약 6.10µs다. ARM과 FPGA 시간은 26B 조회의 시작과 종료 사이에서 맞추므로 분석기는 ARM 이벤트를 시간 범위로 표시한다. 직전 공개부터 이번 공개까지의 시간으로 표시 간격을 센다. 246선 근처처럼 물리 VBlank의 어느 쪽인지 단정하기 어려운 단계는 가능한 양쪽을 남긴다. 오류·세대 불일치·포화는 별도 표시한다. SD 쓰기는 안전한 메뉴 복구 단계에서 수행한다.

두 BIN을 `python tools/read_nes_frame900.py nes-frame-mmc900.bin nes-frame-mmc901.bin` 순서로 읽는다. `pairs`는 시간 구간·세대·대상 뱅크·map/OBJ/BG가 모두 일치한 화면이다. `VBlanks`는 두 판의 표시 간격, `definitely_later`는 이전 공개를 기준으로 가능한 VBlank 범위를 비교해 확실히 뒤로 간 단계다. `unique_workload_only`는 세대가 달라도 작업량이 유일하게 일치한 참고 표본이다. 세대 카운터와 작업량만으로 픽셀까지 동일함을 증명할 수는 없다. 측정판에서 생긴 대기와 원래 실행의 대기를 구분하기 위해 기존 두 판의 실기 집계 및 필요시 CONTROL 결과와 함께 읽는다.
