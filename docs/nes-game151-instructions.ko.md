# NES151 — 실제 마리오 화면 갱신 재시험

150에서 발견한 쓰기 데이터 수신 시점을 수정했다. 프레임 반환 명령을 놓쳐 첫 화면만 반복할 수 있는 문제를 모델에서 재현하고 고쳤다. 실제 보드의 원인이었는지는 이번 시험으로 확인한다. 같은 SMB3 ROM을 사용하며 별도 패턴 시험이 아니다.

## 설치

1. 전원을 끄고 SD의 현재 firmware.stm을 별도 백업한다.
2. ZIP의 `01-GAME151-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. firmware.stm과 fpga_n151.bi3는 **61/DB 식별**의 한 쌍이다.150의 파일과 혼용하지 않는다.
3. 메뉴에서 **`NES GAME 151.nh1`**을 실행한다. 0바이트 표식이며 확장자는 바꾸지 않는다. 실제 ROM은 `sd2snes/nes/game151.nes`에 있다. ROM 포함 개인용 ZIP을 공개 저장소에 올리지 않는다.

## 관찰·시간 측정

- 표식 실행 시 초시계를 시작하고 **첫 화면 변화 시각과 메뉴 복귀 시각**을 기록한다.150 때의 체감5~6분은 사용자가 철회했으므로 비교 기준으로 쓰지 않는다.
- 적재 방식은150과 같다.150 로그상 ENTRY→표시 시작은 약3분53초였지만 이는 외부 실측 보장이 아니다. **실행 후 총7분이 지나도록 메뉴로 돌아오지 않으면 전원을 끄고 남은 로그를 전달**한다.7분은 관찰 상한이며 자동 타임아웃이 아니다.
- 게임 표시 구간은 약60초다. 오류를 감지하면 일찍 종료할 수 있다. 화면이 나오면 메뉴 복귀까지 촬영한다. 로딩 전체 영상은 필요 없다.
- 이번에는 **실제 게임 한 화면을30 vblank, 약0.5초 유지**한 뒤 다음 화면으로 넘어간다. 그 사이 NES 게임 로직은 계속 진행한다. 짧은 검정 구간과 약2회/초 수준의 거친 표시를 예상한다. 부드러운 움직임이나60fps 시험이 아니다.
- 커튼·제목·캐릭터 등 게임 그림이 보이는지 먼저 확인한다. 보이면 Start를 약1초 누르고, 방향키·A/B도 각각1초 정도 유지한다. 입력 수집도 화면 갱신에 묶여 있어 짧은 누름을 놓칠 수 있다. 그림이 안 보여도 같은 시험을 반복하지 말고 영상과 로그를 보낸다.

## 전달할 파일

전원을 끈 뒤 `/sd2snes/nes-progress-151.txt`, `/sd2snes/nes-game-last-151.txt`와 영상, 위 두 실측 시각을 전달한다. 메뉴 복귀 여부도 함께 알려준다. 화면 단계·frames는 진행 표식이며 실제 FPS가 아니다. 자동 로그의 신뢰 불가 표시도 아직 유지한다.

소리는 여전히 미구현이다. CRT 촬영 대각선 띠는 판정에서 제외한다. 정상 사용으로 돌아갈 때는 전원을 끄고 `02-RESTORE044-SD-ROOT` 안의 내용을 복사한다. 기존044/GBC 재시험 보고는 요구하지 않는다.

새 배치의 같은 클록 setup/hold 및 조건부 외부 읽기 계산은 통과했지만 물리 배선·MTBF의 전체 실측 승인은 아니다. 이번 목적은 실제 게임 그림과 갱신·입력 여부를 확인하는 것이다.
