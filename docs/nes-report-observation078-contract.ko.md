# 보고서 전용 진단의 관측·시간 계약 초안 — 078

081 후속: 초기화·mount가 보호 경로 안으로 들어왔다. 실제FatFS mount의 sector는 모형이며 전체native/화면 단일실행은 남는다. 초기화/mini 실패의 외부 관측과044복원 자료까지 준비해야 설치를 판단한다. [최신 결과](../analysis/REPORT-INIT081-RESULT.ko.md).

상태: 설계 방향과 다음 구현 완료 조건. **아직 설치 가능한 구현이나 화면 검증 결과가 아니다.** [078 통합 시험](../analysis/REPORT-SESSION078-RESULT.ko.md)과 [P1 계획](development/NES-077-PROCESS-REVIEW.ko.md)을 따른다.0바이트 원인은 미확정이다.

## 선택한 방향

외부 LED·PC USB·기판 분해를 사용하지 않는다. 실패 후 공유 오류를 지워 SD/SPI로 결과를 출력하지도 않는다. 보고서 전용 경로에서 **다음 작업의 단계 표식을 먼저 화면에 표시하고, RESET을 유지한 상태에서 그 단계만 실행**하는 방식을 먼저 검증한다. 사용자는 화면 영상의 마지막 단계와 TXT 유무/크기를 반환한다. 마지막 단계는 첫 native 오류 코드 자체가 아니며, 모형 실패 위치 표와 대조하여 가설을 좁힌다.

기존074의 `snes_bootprint_center`는 최초 호출에서 embedded mini FPGA/boot ROM을 준비하고 SRAM에 문자열을 쓴다. 이후에는 문자열만 쓴다. 화면 경로도 FPGA SPI/UART/시간 경로를 사용하므로 독립 오류 출력이라고 부를 수 없다. **오류가 없는 작업 전 경계에서만** 사용하고, 화면 자체의 실패도 표시 단계 실패로 취급한다. 소스상 실행 가능성만 확인했으며 실물에서 읽힌다는 승인은 아니다.

## 제안 상태 순서

1. embedded mini/기준 ID·단계표 준비. USB 비활성·offload 금지·NES START 차단을 유지한다. 초기 legacy 부팅의 무한 대기와 호출 순서를 먼저 감사한다.
2. SD 전송 중이 아니고 shared fault가 없는 경계에서 단계 번호와 다음 동작을 쓴다. SRAM 전체 비교, bounded SPI/UART/timer 성공 확인 후에만 mini 화면을 일시 실행한다. 문구가 소비되는 데 필요한 대기와 RESET 재진입을 확인한다.
3. 화면 대기는 별도 명시한 총 예산 안에서 처리한다. 기존1000tick 보고서 예산에 표시 대기를 몰래 추가하거나 임의로 타임아웃을 늘리지 않는다. 실제 SD 예산/표시 예산/전체 예산과 검사 지점을 구분한다.
4. RESET 재유지 확인 후 해당 FatFS 단계를 실행한다. 실패하면 최초 RAM 원인/단계를 유지하고 USB/RESET 보호로 종료한다. 이후 SD·SPI·화면·close를 시도하지 않는다. 표시 성공을 파일 성공으로 기록하지 않는다.
5. 성공한 경우에만 다음 표식으로 이동한다. 전체 sync/close/재열기/크기/전 바이트 비교 후 최종 완료 화면을 보여 준다. 이 전용 진단의 종료는 전원 끄기와 정상044 복원이며 자동 게임/메뉴 실행은 범위 밖이다.

| 마지막으로 읽힌 단계 | 다음에 시도할 작업 | 실패 시 확보할 정보 |
| --- | --- | --- |
| 준비 | 부팅/보고서 생성/쓰기 권한 진입 | 준비 화면 자체의 유무·후속 진입 여부 |
| 2 생성 | CREATE_NEW | 새 이름/파일 유무, 마지막 영상 표식 |
| 3 내용 쓰기 | 256바이트 분할쓰기·클러스터 할당 | TXT 크기, 마지막 표식.0바이트는 이 단계만의 고유 증거가 아님 |
| 4 동기화 | 잔여 데이터·FAT·디렉터리·CTRL_SYNC | TXT 크기/내용과 표식; 쓰기가 반영됐을 가능성 때문에 재시도 금지 |

검은 화면 전에 표식이 읽히지 않으면 시험은 관측 목적을 달성하지 못한다. 현재074를 반복하거나 “LED를 다시 보라”고 하지 않는다. 정상 경로의 마지막 표식과 대기 간격이 실제로 보이도록 준비되지 않으면 패키지를 보내지 않는다. 준비 화면조차 나오지 않는 부팅 실패는 보고서 원인과 분리한다.

## 다음 구현의 완료 조건

- 별도 SD 전용 후보에만 적용하며076/077 NES 메뉴 진단의 RESET 계약과 GBC 동작을 전역 변경하지 않는다.
- 실제 단계 callback/플랫폼/RESET/USB/소유권을 연결한 모형으로 정상 순서, 각 단계의 표시 실패, SD 실패 이후 추가IO 없음, frozen/wrap 시간과 중간 복귀를 검증한다.
- 실제 boot ROM의 화면 갱신·RESET 후 재시작·mailbox 소비를 확인한다. 소스의200ms 대기만으로 화면 표시 완료를 단정하지 않는다. 효과 없는 RESET 토글만 늘리지 않는다.
- FatFS 파일을 연 채 표시할 때의 SPI/SD offload 소유권과 SD 카드 idle 조건을 검토한다. 표시가 파일/캐시 상태를 바꾸면 이 방식을 그대로 채택하지 않는다.
- 총 표시 횟수와 시간 예산을 고정하고 실제 최종 ARM 호출·mini 입력 해시·정상044 복원 파일을 함께 확인한다. 커스텀 원인 수집용 Flash/RTC/bootloader 쓰기는 도입하지 않는다.
- 이 조건을 통과한 뒤 새 ID·판별할 가설·영상/파일 회수표를 포함한 보고서 전용 패키지를 준비한다. CF68 PSRAM 진단은 별도의 P2/P3 조건을 충족해야 한다.

이 초안은 미확정 원인을 실기 전 확정하라는 요구를 대체하지만, 실제 관측/복구 검증을 생략하는 승인은 아니다. P1은 아직 부분 완료다.
