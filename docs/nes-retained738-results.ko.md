# 738 · 957의 section 5 보존과 변경분 전송

727의 957에서 같은 뱅크의 직전 화면은 955다. 최종 ACK 뒤 WRAM 보존을 확인했다. 변경분 5B를 보낸 시험은 두 시작 위상 모두 표시 기한을 한 번 더 넘겼다. 연구 대조군은 727, 보드 선택은 707D를 유지한다.

## 대상 뱅크 추적

727의 실제 ARM 발행 기록과 원래 65816을 Mesen에서 재생했다. 각 위상에서 905–957의 53개 화면 RGB 및 소비 이벤트 전체가 원래 재생과 일치했다. 일치한 이벤트는 각각 8,721개와 8,717개다. 955 최종 ACK에서 957 첫 section 5 수락까지 직접 WRAM 쓰기, $2180 포트, $420B에서 시작한 WRAM DMA의 목적지를 기록했다.

- 대상은 두 위상 모두 $7F:6500부터 $7F:6BD9까지다. 각 위상에서 다른 범위로 향한 WRAM DMA 58건이 있었고 대상과 겹친 쓰기는 0건이었다.
- 955 최종 ACK, 956 최종 ACK, 957 BEGIN, 957 첫 section 5 직전의 네 덤프는 바이트 단위로 같았다. 이 시점의 내용은 송신 측 955 원본을 별도로 재구성한 값과도 일치했다.
- 이후 727이 957 전체를 복원할 때 포트와 WRAM에서 같은 1,754바이트 쓰기를 각각 관측했다. 두 관찰은 같은 쓰기를 본 것이다. 957 최종 ACK 덤프까지 송신 원본과 일치했다.

| 오프셋 | 955 → 957 |
| --- | --- |
| scroll 1, 6 | 두 곳 모두 0x8C → 0x91 |
| raw 1187 | 0x0F → 0x01 |
| raw 1443, 1444 | 두 곳 모두 0xF0 → 0xFE |

## 실제 소비 비용과 표시

957의 section 5에만 변경분 명령을 대입했다. 명령은 대상 뱅크의 직전 최종 ACK serial 4B, 전체 대상 이미지의 검사값 4B, 오름차순 오프셋과 값 5쌍 15B를 보낸다. 헤더·거래 비용을 포함한 E1은 **8건 552B에서 1건 42B**가 됐다. 수신기는 비활성 뱅크, serial, 현재 패킷 identity, 길이, 순서와 범위를 확인하고 5B를 쓴다. 실제 WRAM의 877개 little-endian 워드로 두 개의 16비트 누적합을 계산해 송신 원본 검사값과 대조한다. STOP을 검사하며 일치한 경우에만 section 5의 전체 길이를 공개한다. 유한한 체크섬이며 모든 다중 손상의 검출을 보장하지 않는다. 기존 SEAL의 독립 의미 검사와 최종 ACK도 실행했다.

| 957 또는 밀집 구간 측정 | 727 위상 1 / 2 | 변경분과 독립 검사 | 전체 재검산 생략 진단 |
| --- | --- | --- | --- |
| section 5 수락부터 ACK까지 합계 (ms) | 4.161 / 4.162 | 17.543 / 17.544 | 0.392 / 0.390 |
| 957 SEAL 수락 시각 변화 (ms) | 기준 | +12.961 / +12.970 | −4.021 / −4.015 |
| 956 → 957 표시 간격 (VBlank) | 3 / 3 | 4 / 4 | 3 / 3 |
| 952–957 여섯 표시 간격 평균 (ms) | 49.932 / 49.932 | 52.727 / 52.727 | 49.954 / 49.953 |
| 957 최종 ACK 시각 변화 (ms) | 기준 | +16.767 / +16.766 | +0.133 / +0.127 |

늦어진 위치는 출력 전송량으로 설명할 수 없다. 957의 마지막 OBJ는 직전 VBlank 248선 / 247선에 수락돼 260선 / 259선에서 소비 ACK가 났다. 후속 OAM 수락은 261선 / 260선이었다. 246번 검사선을 이미 지난 뒤다. 검산을 생략하는 진단에서도 SEAL만 약 4ms 앞당겨졌고 직전 VBlank에는 표시할 수 없었다. 이 진단은 절감 가능성을 분리할 목적으로만 실행했다.

두 위상 모두 952·957의 1,536B map 선행 DMA 시작 클록은 727과 정확히 일치했다. 변경 명령 이전의 모든 65816 이벤트와 최종 53개 화면 RGB도 대조했다. 평균은 951 공개부터 957 공개까지의 차이를 6으로 나눴다.

## 실패와 전체 복원

위상 1에서 확인한 결과다.

| 시험 | 실제 수신 결과 |
| --- | --- |
| cold 이력 없음, 생략된 바이트 1비트 손상, 두 바이트 쓰기 뒤 세 번째 주소 오류 | 각각 0xE0. 커밋 52개, 956 화면 유지 |
| 5B를 썼지만 전체 검산이 끝나기 전 STOP | 0xE4. 커밋 52개, 956 화면 유지 |
| 오염된 1,754B, 부분 중단 덤프, STOP 덤프에서 각각 전체 재전송 | 세 경우 모두 957의 전체 WRAM과 RGB 복원, 최종 ACK 시각이 727과 동일 |

거부된 네 경우 모두 수신기의 뱅크 이력이 무효화됐고 section 5 완료 길이는 0이었다. 복원은 별도 재시작 재생에서 취소된 실제 WRAM 내용을 넣은 뒤 전체 패킷을 받는 방식으로 시험했다. 957 재전송은 8건 552B와 65816 서비스 4.161ms를 다시 사용한다. 최초 cold 905는 10건 594B, 서비스 4.667 / 4.689ms였다. 정상판·장시간판의 기존 링크 ARM으로 메뉴 준비·base 해제·오류 억제 경계 5조건과 파일 식별 4조건을 각각 다시 실행했다.

## 적용 범위와 후속 작업

65816은 282B 명령 처리 코드와 임시 WRAM 8B를 사용했다. 같은 부팅·ROM 위상을 유지하기 위해 예약 명령을 수락할 때 Mesen이 처리 코드를 WRAM에 설치했다. 송신 데이터는 기록된 원본으로 생성했다. 변경 명령의 도착은 기존 첫 scroll 도착에 맞췄고 SEAL은 연속 SPI 전송이 가능한 시점에 공급했다. 추가 ARM 준비·credit 대기에는 0을 배정한 낙관적 시험이다. 실제 ARM 송신기 링크, 보드 ROM 패키징, 실기 FPS 측정은 수행하지 않았다.

다음 시험에서는 957의 마지막 OBJ가 1,536B map DMA를 시작하기 전에 준비됐는지와, 그때 staging·credit이 어느 쪽에 있었는지를 맞춘다. 952·957 map DMA를 유지한 채 OBJ 수락과 후속 OAM 검사를 246선 앞으로 옮길 수 있는지부터 확인한다. 동일 순서에서 section 5의 후반 전송 시간만 줄이는 실험은 보류한다.
