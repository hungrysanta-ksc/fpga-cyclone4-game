# 879 · 951 raster 입력 복원과 950 최종 ACK의 조회 시점

실기 비교 기준은 MMC872다. 878에서 950의 1,088B 선행 DMA와 3회 표시를 보존한 경우 위상 1의 마지막 COMMIT D2는 직전 캡처선보다 3,875클록 늦었고 위상 2는 256클록 빨랐다. 이번에는 동일한 120B D1 전송 뒤 ARM 수신기의 작업과 65816 최종 ACK를 처음 발견하는 시각을 분리했다. 시간 단위는 공동 재생의 SNES 마스터 클록이며 1ms는 약 21,477클록이다.

## 120B D1에서 줄어든 비용

117B payload에는 184행과 39행의 연속 raster, 그 사이의 단독 행, OBJ·팔레트·메타데이터가 들어 있다. ARM은 연속 구간의 세대·범위·종류와 첫 행을 기존 경로로 확인한다. 이후 행은 이미 검사한 첫 행에서 하위 15비트 주소만 갱신해 저장하고 행 수와 레코드 수를 반영한다. D1 전체 CRC와 META_END의 raw 슬롯·coverage 검사는 그대로 실행한다.

| 951의 120B 거래 | 기존 위상 1 / 2 (클록) | 연속 행 복원 위상 1 / 2 (클록) |
|---|---:|---:|
| D1 수신 CRC | 420 / 419 | 420 / 419 |
| 첫 행 검사 이후 나머지 183행 복원 | 9,153 / 9,153 | 1,293 / 1,294 |
| 첫 행 검사 이후 나머지 38행 복원 | 1,905 / 1,906 | 278 / 277 |
| META_END 진입부터 패킷 함수 반환 | 6,188 / 6,188 | 6,188 / 6,188 |
| D1 응답 완료부터 D2 발행 | 20,248 / 20,248 | 10,760 / 10,760 |

범위별 수치는 전체 D1→D2 안에 포함된다. 두 위상 모두 마지막 데이터 블록의 D2도 9,488클록(0.442ms) 일찍 끝났다. 원본과 후보의 패킷 수신기 전체 메모리는 일치했다.

## 공개 시각을 고정한 대조 시험

877 안정 링크에서 878의 검증된 FINISH 재사용을 적용하고 951 대상 블록에만 실제 링크한 ARM 함수를 실행했다. 기준 대조군에는 관측 훅만 걸었다. 950의 1,088B 선행 DMA와 공개 클록 51,081,914 / 51,439,778을 고정하고 CRC·큐 상태·SEAL identity가 맞는 E0만 최종 ACK로 인정했다.

128µs 재조회 대기를 그대로 두면 위상 1은 952가 VBlank 148→147로 빨라지고 캡처 여유가 144클록 생긴다. 위상 2에서는 ARM이 51,441,162클록에 두 번째 E0를 시작했고, 65816이 1,512클록 뒤에 최종 ACK를 공개했다. 해당 거래는 시작할 때의 큐 상태를 반환했다. 세 번째 E0를 기다리면서 마지막 D2가 캡처선보다 1,193클록 늦어져 952 공개는 148→149가 됐다.

END의 D2 반환을 확인한 뒤 기존 E0 재조회 루프만 128→96µs로 줄여 다시 처음부터 재생했다. STOP 검사와 전체 E0 응답 검사를 매번 실행했다. 시각을 고정한 세 시험의 결과는 다음과 같다.

| 950 고정 시험 · 위상 1 / 2 | 878 FINISH 재사용 | 연속 행 복원 | 연속 행 복원 + 96µs |
|---|---:|---:|---:|
| 마지막 COMMIT D2의 캡처 여유 (클록, 양수가 마감 전) | −3,875 / +256 | +144 / −1,193 | **+834 / +188** |
| 952 공개 VBlank | 148 / 148 | 147 / 149 | **147 / 148** |
| 952 표시 간격 | 3 / 2 | 2 / 3 | **2 / 2** |
| 밀집 60개 표시 간격 합 | 141 / 140 | 140 / 141 | **139 / 140** |
| 마지막 65816 ACK (클록) | 65,017,082 / 65,016,842 | 64,659,714 / 65,374,550 | **64,302,102 / 65,016,962** |

결합 대조군은 두 위상 모두 952를 241선에 공개했다. MMC872의 141 / 141 대비 밀집 간격이 2 / 1 VBlank 줄었고 마지막 65816 ACK는 33.301 / 16.913ms 빨라졌다. ARM이 확인한 마지막 유효 E0도 앞당겨졌다. 위상 1에서는 952 이후 달라진 일정에서 963까지 한 번 더 줄었다. 위상 2는 기존에 성공했던 878 분리 대조보다 캡처 여유가 68클록 줄었다. 96µs는 이 두 시작 위상에서 확인한 값이다.

## 처음부터 부팅한 ARM 전체 링크

878 FINISH 링크에 연속 행 복원을 일반 적용한 후보는 212,992B로 Flash 한도에 정확히 들어간다. FPGA와 65816 바이너리는 기존 것을 사용했다.

| 조건 | MMC872 위상 1 / 2 | 879 전체 링크 위상 1 / 2 |
|---|---:|---:|
| 오프닝 60간격 | 125 / 124 | 123 / 122 |
| 오프닝 703 공개선 | 231 / 231 | 248 / 231 |
| 오프닝 759 공개 VBlank | 176 / 176 | 175 / 174 |
| 전환 48간격 | 119 / 119 | 120 / 121 |
| 950 표시 간격 | 4 / 4 | 4 / 4 |
| 밀집 60간격 | 141 / 141 | 141 / 141 |
| 마지막 65816 ACK (클록) | 65,017,306 / 65,380,210 | 65,017,200 / 65,374,338 |

950의 마지막 map은 89 / 93선에 반환됐다. 5,715 / 5,762클록 뒤 ARM이 scroll을 발행하면서 빈 큐에서 1,088B를 먼저 DMA할 기회를 잃었다. 2B 팔레트와 112B OAM이 다음 VBlank로 넘어갔다. 951의 END는 950 공개보다 25.93 / 22.65ms 먼저 검사됐지만 950의 늦은 공개에 묶여 다음 COMMIT이 직전 캡처선을 놓쳤다.

다음 정적 구현에서 단순히 ‘직전 SEAL 발행 후 다음 입력의 raster 수신 중’이라는 조건을 추가해도 951을 따로 다룰 수 없다. 고정 대조군의 두 위상에서 906–966의 61개 입력 모두 이 조건에 맞는 구간이 두 개씩 있었다. 또한 950의 마지막 map 발행부터 첫 scroll 발행까지 관측한 E0 상태는 선행 DMA를 지킨 대조군과 이를 놓친 전체 링크에서 모두 0x03→0x02였다. 이 구간에서 ARM이 받은 응답에는 DMA 진행 비트(0x08)가 올라오지 않았다. 다음 실험은 credit 반환 뒤 실제 DMA 시작을 ARM이 관측할 수 있는 시각과, 그때까지 scroll을 늦추는 비용부터 측정한다.

## 재현과 복구 검사

1. `prepare_nes_raster879.py BASE/src WORK/patch`를 878 FINISH ARM에 적용하고 기존 `build_nes_mmc479_arm.ps1`로 링크한다. SHA-256, 원본 비교와 21개 경계 입력은 `guard_nes_raster875.py`로 확인한다. `guard_nes_raster879.py SENDER WORK OUT`은 951의 데이터 16블록을 END까지 순서대로 적용하고 매번 두 링크의 수신기 전체를 대조한다. 초과 길이·raw 비트·잘못된 메타 개수·잘린 메타를 주입한 뒤 reset과 전체 재수신도 검증한다.
2. `replay_nes_raster879.py TEMP PHASE WORK`로 계측 대조군을, `--fast`로 대상 패킷의 복원 변경을 재생한다. `--fast --short-wait`는 END 완료 뒤 SEAL 응답 대기의 기존 STOP 검사 루프에서 재시도 간격만 96µs로 줄인다. 각 진단은 950을 포함한 밀집 전체를 같은 입력과 비용으로 재생한다.
3. 전체 링크는 `replay_nes_table877.py TEMP PHASE WORK 879-static CLIP`으로 부팅한다. 두 위상에서 오프닝·전환·밀집 총 348개 화면의 활성 RGB와 map, SEAL ACK→EA→재무장 E8→다음 COMMIT 순서를 확인했다. 실제 후보 출력 패킷을 사용한 65816 독립 검사·부분 전송·STOP·cold 복구 12조건과 링크된 ARM의 FINISH·EA 오류 19조건, 메뉴 복귀를 확인했다.
4. 기존 입력·메뉴·큐 guard와 위 재생을 마친 뒤 `check_nes_raster879.py TEMP analysis/raster879-results.json`으로 집계한다. [위상별 입력·상태·화면 공개 측정](../analysis/raster879-results.json)
