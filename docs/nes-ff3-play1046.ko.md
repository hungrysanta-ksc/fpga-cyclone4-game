# FF3 1046 실기판

ZIP의 `sd2snes` 폴더를 SD 루트에 덮어쓴 뒤 전원을 껐다 켜고 평소 사용하던 FF3 한글판 `.nes`를 선택한다. SD에 있는 기존 슬롯과 배터리 세이브를 그대로 읽는다. 이 설치본에는 게임과 세이브 파일이 없다.

1. **L+R+START → STATE SLOT 1 → LOAD STATE**를 선택한다. 선택한 시점부터 저장 장면에 다시 캐릭터가 나타날 때까지 걸린 시간을 확인한다. 처음 SD에서 ROM을 실행하는 시간과 슬롯 불러오기 시간은 따로 측정한다.
2. 첨부했던 슬롯에서 위로 이동해 보스 방에 들어간다. 위아래 검은 띠가 넓어져 방이 닫히고, 다음 방에서 띠가 좁아져 화면이 열리는 두 부분을 확인한다.
3. **L+R+START → EXIT TO MENU**로 종료한다. 이번 판의 로그 이름은 `nes-progress-ff31046.txt`, `nes-game-last-ff31046.txt`, `nes-frame-ff31046.bin`이다.

## 변경 내역

처음 실행할 때는 SD 파일 CRC와 적재한 512 KiB 전체의 PSRAM 읽기 대조를 수행한다. 같은 게임에서 유효한 슬롯을 불러올 때에는 SD 파일 CRC와 슬롯 CRC를 다시 검사하고, FPGA가 보관한 현재 ROM의 대조 완료 상태를 사용한다. 일반 STOP, 새 적재, 검증 오류 또는 리셋 후에는 이 상태로 재시작할 수 없다.

방 전환 때 게임은 배경만 끄고 스프라이트 처리를 계속한다. CHR-RAM 보드는 이 상태의 한 줄에서 최종 256픽셀이 모두 NES 배경색과 일치할 때 그 행을 투명 타일로 표시한다. 경계에서 마스크가 바뀌거나 스프라이트가 한 픽셀이라도 보이면 원본 픽셀 경로로 처리한다. ARM은 해당 화면에서만 왼쪽 map의 31번 행을 예약하고, 이전 뱅크에 남은 타일을 지운 뒤 스크롤 표를 만든다.

화면이 완전히 닫히면 게임은 배경과 스프라이트를 모두 끄고 타일을 읽지 않는다. 이때에도 한 줄의 마지막 픽셀까지 배경색인지 검사한다. 빈 화면은 map 조회가 33개의 0값을 반환하므로 이전 방의 타일을 다시 표시하지 않는다.

## 재현 근거

1045 실기 로그에서 `DISPLAY_STOPPED`는 340,230ms, `DISPLAY_NEXT`는 517,590ms였다. 그 사이 512KiB PSRAM의 첫 `CHECK`부터 마지막으로 기록된 514,304바이트 지점까지 173.97초가 흘렀다. 1046 최종 ARM 링크에서 같은 SD 파일이면 이 재읽기는 0회이고, SD 파일 끝의 한 바이트가 달라지면 START 전에 중단한다. 실기에서 버튼을 누른 뒤 첫 화면까지의 시간은 별도로 측정한다.

첨부한 슬롯 1(저장 순번 3)의 CPU·메모리 상태를 사용해 위로 이동했다. 참조 에뮬레이터에서는 가려진 단색 행이 81→141→201→224개로 늘고 다음 방에서는 193→133→73개로 줄었다. 1045 보드 RTL에서 같은 슬롯을 직접 복원하면 34번 프레임부터 배경을 끈 행만으로 원본 픽셀을 담는 7행 한도를 넘겼다. 세대 충돌과 CHR 쓰기는 그 첫 실패에서 관찰되지 않았다.

1046 최종 RTL에서는 같은 슬롯에서 위로 이동한 115프레임을 연속 재생했다. 검사를 마친 캡처 109개가 모두 유효했다. 65~69번은 NES가 단색 화면에서 다음 방의 CHR를 쓰는 동안 기존 스냅샷 보호가 캡처 시작을 보류했다. 마지막 프레임은 수집 결과 반환 전에 시험이 끝났다. 검은 띠는 224행까지 넓어졌다가 보스 방에서 0행으로 돌아왔다. 최종 ARM 링크로 실제 캡처 9개의 HDMA 스크롤 표와 경계 행의 SNES 타일 비트플레인을 대조했다. 이 수치는 RTL 재생 결과이며 실기 FPS는 별도 측정 대상이다.

Quartus Lite 전체 FIT는 15,188 LE, 961 LAB, 56 M9K를 사용했다. STA 57항목의 최소 여유는 +0.098ns이고 음수 여유 합계는 0이다.
