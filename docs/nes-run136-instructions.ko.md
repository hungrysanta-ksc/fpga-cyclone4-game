# NES136 — 최초 짧은 CPU RUN 실기 시험

이번에는 실제 NES CPU를 잠깐 실행하고 TXT로 확인합니다. **게임 화면·소리·패드 반응은 나오지 않는 시험**입니다. 기존119에서 성공한 SD 적재·검증·복원 경로에 RUN을 연결했습니다. SMB3 실행은 다음 화면/mapper4 단계의 목표입니다.

## SD에 복사

1. 전원을 끈 상태에서 SD의 기존 `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`을 PC에 별도 보관합니다.
2. 압축을 풀고 **`01-RUN136-SD-ROOT` 안의 내용**을 SD 최상위에 덮어씁니다. 폴더 자체를 SD에 넣지 않습니다. 새 펌웨어·`fpga_n136.bi3`·`nes/run136.nes`·빈 선택 파일이 함께 필요합니다.
3. **`02-RESTORE044-SD-ROOT`는 아직 복사하지 않습니다.** 이 폴더는 시험이 끝난 뒤 쓰는 정상044 복원용입니다.
4. 메뉴에서 **`NES RUN 136.nh1`**을 한 번 실행합니다. 이 선택 파일은 **0바이트가 정상**이며 확장자를 바꾸지 않습니다. 이전094/113/116 선택 파일은 이번 시험에 사용하지 않습니다.

## 대기와 종료

실행 후 화면이 로딩 상태나 검은 화면이어도 진행 중일 수 있습니다. 전체 적재/비교는 오래 걸립니다. 이전119 전체 세션은 약8분11초였으며 **이번136의 실기 시간은 아직 미측정**입니다. RUN의 대기 합계16ms와 SPI 관측 시간을 전체 실행시간으로 착각하지 마세요.

**메뉴 복귀까지 기다리되 최대10분을 관찰 기준으로 삼습니다.** 이는 펌웨어의 정확한 실행시간 보장이 아닙니다. 메뉴가 돌아오면 전원을 끄고 로그를 회수합니다. 10분이 지나도 돌아오지 않으면 전원을 끄고 로그를 회수한 뒤044를 복원합니다. 같은 시험을 연속 반복하거나 리셋 버튼으로 복귀시키려 하지 않습니다.

영상은 필수가 아닙니다. 다음 두 파일과 메뉴 복귀 여부만 전달해 주세요.

- `sd2snes/nes-progress-136.txt`: 단계별 진행 기록. 마지막 `RUN_NEXT`는 RUN 진입 직전 저장이 끝났다는 뜻입니다. `RUN_STOPPED`는 STOP와 관측이 끝났다는 뜻입니다. `MENU_PREPARED`는 메뉴 준비 완료 기록이며 실제 화면 복귀는 사용자의 확인이 필요합니다.
- `sd2snes/nes-run-last-136.txt`: 적재/비교, CPU 읽기 카운터, STOP, 기본FPGA와 메뉴 복구 결과입니다. `run_passed=1`은 이번 짧은 활동 시험 통과이며 게임 정상 동작을 뜻하지 않습니다.

로그가 없거나0바이트여도 그 사실과 파일명을 알려주세요. 마지막 단계에서 멈춘 로그도 유용합니다. RUN 중에는 SD에 쓰지 않으며, 공통 고장을 감지한 뒤에는 추가 로그 저장을 강행하지 않습니다.

## 정상044 복원

전원을 끈 후 **`02-RESTORE044-SD-ROOT` 안의 내용**을 SD 최상위에 덮어씁니다. 전원을 다시 켜 메뉴와 기존 GBC 게임을 확인합니다. 시험용 `fpga_n136.bi3`와 선택 파일이 남아 있어도 정상044가 자동으로 실행하지 않지만 혼동 방지를 위해 시험 후 별도 보관해도 됩니다.

## 결과 해석과 범위

`run_first`, `run_last`, `run_stopped`는 유효 CPU ROM 읽기 샘플 수이며 명령 수/프레임 수/PSRAM 실제 접근 수와 다릅니다. 정상 결과는 처음부터 양수이고 실행 중 증가하며 STOP 뒤 유지됩니다. `run_error=2`는 관측된 진행 부족, `1`은 RUN 중 reset/ROM 오류, `3`은 STOP 뒤 상태/카운터/ROM 오류 조건 미충족입니다. 오류 번호만으로 부품 고장을 단정하지 않습니다.

정상 전원에서 한 번 수행하는 제한 실기 진단입니다. 회로135fit03는 그대로이고 전체 전기 타이밍·MTBF·모든 클록 고장 안전성이 승인된 것은 아닙니다. 두 클록 동시 정지 시 CE9µs 반례와8µs 미보장, 외부E1/E2 조건은 남아 있습니다. 새 시험에서 오류가 나오면 그 로그에 따라 다음 수정 범위를 결정합니다.

기존 upstream 고정과 source-lock 보류4건은 유지합니다. 이번 패키지는 사용자 개인 실기용으로 제공하며 ROM·펌웨어·FPGA 바이너리는 Git에 올리지 않습니다. 새 upstream 원본 반입이나 라이선스 보류 해제는 수행하지 않았습니다.
