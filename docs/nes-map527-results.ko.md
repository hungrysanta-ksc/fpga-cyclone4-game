# 527. ARM 첫 map 확정과 SPI 발행 시각

## 비교 조건

526의 map 전용 254번 주사선 소비기와 같은 두 시작 시각을 유지했다. 53화면의 65816 코드, 독립 검사·STOP·최종 ACK, 공유 SPI, 2개 bulk 슬롯, SysTick, 부팅 중 기록한 ROM 허용 구간은 같은 조건이다. 실행한 것은 링크된 Cortex-M4 명령과 Mesen의 실제 65816 명령이다. MCU 시간에는 CPI 2와 실기 SPI 서비스 비용을 적용했다. MMC524가 마지막으로 실기 검증된 빌드다.

같은 ARM 바이너리에서 map 단어 쓰기, BG 종료 시점의 전체 map과 대상 뱅크 마스크, resident 준비와 END 진입, map 패킷 생성·enqueue 진입·SPI 큐 도착을 추적했다. BG 종료는 최종 BG 할당 뒤 544B OAM을 지우는 실제 명령에서 관측했다. 마지막 단어 쓰기 시각은 사후 관측값이다. 선행 발행에 사용하는 안전 조건은 별도로 검사한다.

|---:|---|---:|---:|
| 952 | 오프셋 1,024 · 192B | 49.740 / 50.231ms | 43.224 / 43.286ms |
| 954 | 오프셋 320 · 64B | 30.751 / 30.941ms | 24.833 / 25.022ms |

첫 위상의 END 구간에는 952에서 E8 조회 149회와 bulk E1 5건, 954에서 E8 86회와 bulk E1 2건이 들어 있었다. END 구간은 잔여 plan 버퍼를 비우고 END가 든 E9를 수락시키는 전체 시간이다. enqueue 진입부터 첫 map 큐 도착까지는 양 위상에서 952가 1.009ms, 954가 0.428ms였다.

## 발행 정책

- **첫 OBJ 이후**는 최초로 공급이 필요한 OBJ plan을 현재 plan 버퍼에 제출한 직후 한 번 시도한다. 이때 BG map은 이미 확정됐다. OBJ 공급이 없는 화면은 기존 경로에서 발행한다.
- **행 확정 시점**은 BG 그룹 `g`의 두 물리 행이 `g`와 `g+32`라는 기존 배치를 이용한다. 앞쪽 페이지에서 필요한 행과 그 뒤 두 행까지 끝났으면 기존 오름차순·최대 3행 패킷을 확정할 수 있다. 조건이 성립하지 않으면 전체 BG가 끝난 시점에 한 번 시도한다.
- 두 후보 모두 큐 점유가 3 이상이면 양보한다. 가능한 경우 E8에서 ready bulk를 먼저 처리하고, bulk가 없을 때만 기존 DATA 또는 반복어 RLE 형식의 첫 map 패킷을 보낸다. enqueue 성공 뒤에만 해당 행을 지나도록 커서를 기록한다. 나머지는 기존 SEAL 경로에서 공급한다. 실패 시 재전송과 최종 표시를 차단한다.

양쪽 모두 SEAL 전체에서 두 번 기다렸고 그중 최종 표시에서 한 번 기다렸다. 행 확정 후보도 같은 VBlank를 재사용하는 246번 검사선을 넘겼다. 954 첫 위상에서는 첫 OBJ ROM 요청을 1.406ms 앞당겼는데도 마지막 OBJ ROM 응답은 14.694ms 늦었다. 둘째 위상의 마지막 응답은 1.567ms 빨랐다. MMC524 자체와 비교하면 밀집 평균은 126.457→123.129ms 및 123.130→122.856ms, 957 ACK는 33.284ms 및 0.023ms 빨라졌다. 두 번째 ACK는 사실상 동률이다.

세 경로의 53개 RGB·1,689개 패킷 내용·444개 tile·125,488B VRAM DMA가 일치했다. 두 위상의 526→행 확정 SPI 비용은 536,586→534,506B 및 538,446→532,710B, SysTick은 509→506회 및 511→503회였다. ROM 배정 5,616회, 최대 bulk 2슬롯은 같았다. 행 확정 후보에서 관측한 작업 영역 끝과 최저 스택 주소 사이 간격은 2,424/2,464B였다. 독립 재생은 8,268/8,270개 이벤트의 클록과 두 위상 각각의 53화면 RGB가 일치했다.

**다음 순서.** ① 952·954에서 SEAL에 남은 2.3KiB의 명령별 DMA·설정 비용과 246번 검사선까지 필요한 클록을 분리한다. ② 기존 E8 응답에서 ready bulk·발행 가능한 E9·STOP을 모두 먼저 처리한 뒤 남는 기회에만 다음 확정 행을 공급하는 후보를 같은 두 위상에서 비교한다. 954의 마지막 OBJ ROM 응답도 함께 기록한다. ③ 두 위상에서 최종 대기를 줄인 경우 펌웨어 한도까지 Flash를 회수하고 실기에 전달한다.

## 검증과 비용

두 후보에서 정상 DATA/RLE, 빈 map, 마지막 63번 행, 16비트 credit 랩, bulk 우선권, STOP, 잘못된 E8 CRC와 응답이 불명확한 E1을 연결된 ARM에서 검증했다. 행 확정 후보로 기존 E8 응답 40개도 대조했다. 906의 첫 map E1 뒤 guard 실패 또는 잘못된 OBJ를 주입하면 resident 트랜잭션을 취소하고 두 뱅크의 map 이력을 무효화했다. 마지막 표시 identity는 905였고 906의 SEAL·EA는 없었다. 이 주입 시험은 ARM 취소 경계까지이며 실물 메뉴 복귀 시험은 MMC524의 기록을 사용한다.

MCU Flash는 MMC524와 같은 측정 ARM이 212,992B(여유 0B), OBJ 후보가 213,244B(252B 초과), 행 확정 후보가 213,380B(388B 초과)다. BSS는 모두 18,588B였다. 행 확정 callback으로 resident 구조체는 6,016→6,024B, sink는 기존 패딩을 사용해 36B 그대로였다. 동일한 526 보드 SOF 해시를 대조했다. 해당 Quartus Lite 전체 결과는 15,164 LE·51 M9K, 관련 setup +0.078ns·hold +0.139ns다.

초기 행 확정 공동 실행은 907에서 RPC 응답 형식·큐 오류로 중단됐다. 두 초기 실행은 시간 비교에서 제외했다. 채택 실행은 진행 중인 RPC를 중첩 콜백이 다시 처리하지 않게 하고 첫 콜백 오류를 보존했다. 실제 PUSH 도착·패킷·payload만으로 별도 재생하여 53개 RGB와 전체 소비 이벤트·클록을 두 위상 모두 대조했다.
