# NES170 실기 — 첫 화면 통신 실패 위치 확인

> 실기 결과 수신:13회 표시 뒤 CHR 수집 전체 시간 초과로 화면 갱신이 멈췄다. 연속 AV 미달성. 아래는 시험판 준비 당시 기록이며 동일170 재시험은 필요하지 않다. [170 실기 결과](nes-game170-hardware01.ko.md).

169는 ROM 검증 후 첫 화면 요청의 응답을 받지 못해 종료됐다. 사용자가 시간을 다시 확인해 표시 시도부터 약13~14초, 총 실행 약4분으로 정정했다. 진행 로그의13.49초와 부합한다.

170은 **화면 오류 수정 완료판이 아니라 다음 수정 지점을 정하는 최소 확인판**이다.169의 FPGA·SNES 화면 프로그램을 그대로 사용하고, 통신 실패 위치·폴링 횟수·실제 상태 응답만 기존 TXT에 추가한다. 재시도·대기 횟수·리셋 순서·60초 제한은 변경하지 않았다. 같은 증상이어도 새 기록으로 다음 조치를 구분할 수 있다.

## 실행

1. 전원을 끄고 ZIP의 `01-GAME170-SD-ROOT` 안 내용을 SD 루트에 복사한다. `sd2snes/firmware.stm`, `sd2snes/fpga_n170.bi3`, `sd2snes/nes/game170.nes`, `NES GAME 170.nh1`을 함께 적용한다.
2. 정상 메뉴에서 `NES GAME 170.nh1`을 실행한다. 기존 로딩·검증은 약4분이며 실패 위치가 같으면 그 후 약13~14초에 메뉴로 돌아올 수 있다.60초를 채우지 않아도 된다.
3. 화면이 정상 출력된다면 평소처럼 첫 레벨 진입을 시도한다. 동일한 로딩 화면이면 버튼을 누를 필요 없다. 시작 후 총6분이 지나도 복귀하지 않으면 더 기다리지 말고 전원을 끈 후 상태를 알려준다. 이는 관찰 중단 기준이며 오류 시 로그가 반드시 남는다는 보장은 아니다.
4. SD의 `nes-progress-170.txt`와 `nes-game-last-170.txt`, 화면 출력·메뉴 복귀 여부를 전달한다. **동일 증상이라면 영상은 필요 없다.**

새 `sink_io170` 항목은 분석용이므로 직접 해석하지 않아도 된다.0으로 채워진 상태는 실제 응답이 없을 수 있으며, 오류 코드와 함께 판독한다. 게임 실행 도중 SD에 쓰지 않고 안전 정지 후 로그를 저장한다. `02-RESTORE164-SD-ROOT`는 보존했으며 반복044/164 복원 시험은 요청하지 않는다.
