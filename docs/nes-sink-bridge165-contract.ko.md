# NES165 FPGA 패킷 수신·SNES 완료 응답 접속부

PR107 머지 이후의 별도 FPGA 구현이다. [이전 수신·응답 계약](nes-native-sink165-contract.ko.md)의 MCU→SNES 패킷과 SNES→MCU 응답을 실제 RTL 버스에 연결했다. 새 코어 전체 배치나 실기 패키지는 아직 없으며, 설치 후보는164다. 카트리지 SRAM·세이브·자동 저장·복구 영역은 사용하지 않는다.

## 구현 범위

- `nes_sink_spi165`: 호스트 클록에서 동작하는256바이트 단일 패킷 RAM, SPI 길이·CRC 검사, 불변 패킷 게시, 응답 스냅샷.
- `nes_sink_bus165`: SNES 패킷 읽기 창,12바이트 응답 쓰기와 게시,STOP·패드 레지스터,4KiB 클라이언트 ROM 주소 해석.
- `nes_sink_bridge165`: 위 두 모듈과 공통 reset 해제 회로를 연결한다. raw reset은 외부 SNES 출력 허가를 즉시 해제한다.
- `nes_sink_spi165_exchange`: 기존 C 송신기의 exchange 콜백에 넣을 수 있는 유한 SPI 어댑터. 전송 함수와RUN/오류/STOP/실제 경과시간을 확인하는 guard는 호출자가 제공한다.

이 모듈은 기존151/164의 프레임버퍼용 SNES 버스 소유자를 **대체할 접속부**다. 같은 `$400000` 또는 `$006000` 영역을 두 모듈이 동시에 구동하면 안 된다. 아직 기존 최상위 회로·MCU 게임 루프에 인스턴스화하지 않았다. 기존38M9K 프레임버퍼와 새 경로를 함께 추가해 배치하지 않는다.

## SPI 계약

Mode0, 시험 SCK2.625MHz/호스트 약84MHz. 외부 타이밍·CDC·MTBF 승인이나 최고속도 보장은 아니다.

| 명령 | 전송 길이 | 내용 |
| --- | --- | --- |
| E0 | 16바이트 | 수신0=dummy,1=F6,2=flags,3..14=ACK,15=CRC8 |
| E1 | 패킷 길이+3 | 명령,16..256바이트 패킷,CRC16 상위·하위 |

CRC8은 응답1..14에 poly07/init0,CRC16은 E1 명령과 패킷 전체에 CCITT poly1021/initFFFF를 적용한다. flags bit0=게시된 패킷,bit1=응답 유효,bit7=오류이며 다른 비트는0이다. F6는 새 수신 접속부 식별이다. 기존 D6/E5 또는 그 밖의 식별을 대체 허용하지 않는다.

E1은 완전한 바이트 수, 패킷 헤더의 payload 길이≤240,CRC가 모두 맞고 버퍼가 비어 있어야 CS 해제 후 게시한다. 전송 중에는 SNES에서 보이지 않는다. 게시 중 덮어쓰기는 실제 RAM 쓰기부터 차단하고 오류를 고정한다. 부분 전송·CRC 오류·불완전 ACK 게시도 공통 reset까지 실패 상태다. 오류 후 유효한 다음 패킷으로 자동 복구하지 않는다.

E0는 명령 수신 시 flags와12바이트 ACK를 한 번에 캡처한다. 전송 중 SNES가 새 응답을 게시해도 이미 시작한 E0의 응답과CRC는 변하지 않는다. 다음 E0가 새 상태를 반환한다. ACK 원본은 유지하되 새 패킷 게시 시 유효 비트가 내려간다. C 상위 송신기가 op/sequence/serial/generation/65/9A까지 검사한다. 버스 전달 성공만으로 장면 표시 성공을 선언하지 않는다.

## SNES 계약과 소유권

| 주소 | 동작 |
| --- | --- |
| `$006000` bit0 | 완전하고 유효한 패킷 ready |
| `$006001` bit7 | STOP 또는 접속부 오류 |
| `$006004..6005` | 패킷 길이16..256, little endian |
| `$400000..4000FF` | 읽기 전용 패킷, 길이 바깥은 구동하지 않음 |
| `$006010..601B` |12바이트 ACK 작업 레지스터 |
| `$00601C=A5` |12바이트가 모두 기록된 경우만 ACK 게시·패킷 해제 |
| `$006002..6003` | 패드 low/high,high 쓰기 완료에서 한 번 게시 |

읽기는 동기 RAM 데이터와 주소 태그를 맞춘 뒤 구동한다. `/RD`가 유지된 연속 주소 변경도 시험했다. 쓰기는 동기화된 `/WR` 종료에서 직전 주소·데이터 묶음을 채택해 늦게 안정되는 데이터를 받는다. 실기 최소 setup/hold 보장을 이 디지털 모델에서 추론하지 않는다.

클라이언트 ROM은4KiB다. bank00 `$8000..8FBF`와 `$FFC0..FFFF`에 해당 바이트를 공급하고 나머지 ROM 구멍은FF다. 기존2048바이트 주소 해석으로2651바이트 클라이언트를 실행할 수 없다. SNES WRAM7F 후보 두 개는 기존 계약 그대로이며 이 FPGA 모듈에는 카트리지 SRAM/PSRAM 쓰기 포트가 없다.

## 검증 근거와 한계

[검증 결과](../analysis/sink-bridge165-verification.json)에 원본 해시와 로그 해시를 기록한다. 이전 실제 C/SNES 동시 실행에서 나온 normal137+stop90의227패킷/응답을 재사용했다. 새 ROM 부팅이나 동일 화면 시험은 반복하지 않았다.

두 위상0/3.5ns에서 각227왕복,35,741바이트 검사,42,766 SPI wire바이트가 일치했다. 여기에 전체4KiB ROM·벡터·주소 구멍,연속 읽기,늦은 쓰기 데이터,응답 전송 중 게시,raw release/reset,STOP,CRC 오류,잘린 요청,소유 중 덮어쓰기,불완전 ACK,다른 명령군을 검사했다. C 어댑터는 RTL에서 기록한908전송을 정확히 재현하고17개 IO/guard/CRC/식별/상한 실패를 거부했다.

이번 ACK는 이전 실제 SNES 실행의 응답을 시험대에서 SNES 버스 쓰기로 재생한 것이다. **실제65816과 SPI RTL의 동시 실행 또는 물리 실기 왕복은 아니다.** 새 화면·게임 플레이·FPS 검증으로 계산하지 않는다. 상태 E0 폴링 횟수는 시간이 아니며 실제 guard 연결이 필수다.

ARM 오브젝트는text426B,컨텍스트16B,exchange 직접stack544B,status12B다. 상위 packet 함수304B와콜백·인터럽트의 중첩 stack까지 전체 링크에서 평가해야 한다. 개별 크기만으로64KiB SRAM 여유를 승인하지 않는다.

Cyclone IV EP4CE15F17C8에서 접속부 단독 Analysis & Synthesis로 4KiB ROM과256바이트 simple-dual-port RAM의 M9K 추론을 확인한다. ROM 초기화4096바이트도 원본과 대조한다. 이 결과는 전체 코어 fit·물리 핀·타이밍 승인이 아니다. 초기 합성에서 무시된 `async_reg` 표식을 Quartus 속성으로 교체했으며 속성만으로 CDC/MTBF가 해결되지는 않는다. ROM의 사용하지 않는 쓰기 입력을0으로 정하는10030 경고3개는 유지한다.

## 다음 작업

1. 기존 MCU→코어 SPI와 새 E0/E1의 MISO 배타 선택, 공통 reset/활성/오류/STOP, SNES 패드 게시를 실제 최상위에 연결한다. 기존 framebuffer 버스와38M9K 저장소를 교체하고164 사운드·입력을 보존한다.
2. MCU RUN 루프에 원본 수신→변환→새 sink 어댑터를 연결한다. guard에 실제 시간·오류·STOP과 필요한 서비스를 넣고,수신 대기가 오디오·입력·진행 로그를 막지 않게 한다. 애매한 응답은 재시도하지 않고 공통 복구한다.
3. 전체 SRAM/중첩 stack·클라이언트 공간·fit/변경 I/O 타이밍의 최소 검사를 통과하면 SMB3 첫 레벨 실기로 간다. 같은boot/A-B/044 또는 일반 진단 항목을 늘리지 않는다. SPI39.59ms·SNES 비교29.7ms 병목과60fps는 여전히 미해결이다.

기존 검증164와 모든 이전 해시·아카이브는 보존한다. 이번 소스만으로 새 펌웨어를 SD에 배포하지 않는다.
