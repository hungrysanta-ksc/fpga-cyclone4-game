# 543. map 발행 뒤 기존 큐 완료 확인

[542 비용 분리](nes-dma542-results.ko.md)에서 실제 DMA보다 VBlank 대기가 크며, raw 행 진행 절감만으로 밀집 구간이 줄지 않는 것을 확인했다. MMC540의 ARM·65816을 기준으로 첫 BG 공급 정책과 패킷 바이트를 보존하고, 최종 map 발행 뒤 palette/OAM/HDMA 패킷 앞에 기존 `nes_window184_drain`을 한 번 연결했다.

## 변경 범위

map 변경이 있는 화면에만 적용한다. 기존 accepted/retired counter·CRC·최종 identity 검사와 STOP·deadline 경로를 그대로 사용한다. 큐가 비었다는 응답은 DMA 완료를 뜻하지 않는다. 65816은 실제 선행 DMA 직전 새 head·STOP을 확인하고 기존 비활성 뱅크와 246행 규칙을 지킨다. 새 wire 명령·타이머 sleep·credit 임의 반환·새 RAM을 추가하지 않는다.

ARM은 [541 집계](../analysis/windows541-verification.json)를 기반으로 링크했다. Flash는 212,428→212,460B(+32), 여유 532B, BSS 18,592B로 동일하다. SNES는 MMC540의 538 client04를 그대로 사용한다. 542의 행 진행 후보를 함께 넣지 않아 효과를 분리한다. 아직 전달 이름을 바꾸거나 ZIP을 만들지 않았다.

## 검증 상태

[실제 ARM 경계 시험](../tools/check_nes_drain543.py)은 정상·16비트 counter wrap·변경 map 없음과 CRC/identity/status/counter 오류·STOP·poll 한도 9건을 통과했다. 이 단위 시험은 map 발행을 fixture로 설정하고 첫 palette 준비에서 중단한다. 정상 drain 이후에만 후속 코드에 도달하며 거부 시 최종 확정을 하지 않는 것을 검증한다. 실제 패킷과 표시의 증명은 별도의 연속 실행에서 수행한다.

[집계 경계 검사](../tools/check_nes_windows518.py)는 linked ARM에서 [5,40), [40,55), 초기/종료 제외, 미완료 제외, reset 및 기존 bin 보존을 통과했다. 집계 코드도 ARM 실행 위상에 영향을 줄 수 있으므로 기존 MMC540, 집계만 적용한 대조군, 같은 집계의 drain 후보를 분리했다. 후자의 두 구성은 각각 시작 3,000,000 / 3,178,684에서 905–957을 모두 완료했다. 원본과 집계 대조군의 ELF 실행 함수 788개 중 바뀐 함수는 `nes_budget210_display` 하나뿐이다.

[준비기](../tools/prepare_nes_drain543.py)와 [분석기](../tools/analyze_nes_drain543.py)를 사용한다. 53 RGB·canonical payload·map/tile·ROM 읽기·전체 DMA가 같아야 하며, E0/SPI 증가·ARM 명령·IRQ·map 수락 뒤 비어 있는 구간·선행 DMA·SEAL 잔여 전송·최종 ACK를 기록한다. 실기 승격 조건은 두 위상에서 밀집 구간의 VBlank 수와 마지막 ACK가 모두 줄고 첫 BG ROM 구간 및 952·954 최종 대기 0회가 유지되는 것이다.

## 결과와 기각

| 구성 | 951–955 평균 ms, 위상 1 / 2 | 밀집 VBlank 합 | MMC540 대비 마지막 ACK ms |
|---|---:|---:|---:|
| 원본 MMC540 | 99.870039 / 99.870244 | 30 / 30 | 기준 |
| 5–55초 집계만 변경 | 99.874565 / 103.196123 | 30 / 31 | +16.650346 / +16.626972 |
| 같은 집계 + map 뒤 drain | 99.856015 / 103.200313 | 30 / 31 | +33.296128 / +33.283743 |

**drain은 기각한다.** 같은 집계 대조군보다 마지막 ACK가 16.645783 / 16.656771ms 늦어졌다. 밀집 구간의 blank 수는 줄지 않았다. 첫 BG 30개 상대 ROM 구간과 952·954 최종 대기 0회는 유지했지만 전체 성능을 회복하지 못했다. [검증 JSON](../analysis/drain543-verification.json)

추가 비용은 53장 전체에서 E0 전송 +1,860/+1,800B, 모든 SPI 합 +1,420/+1,316B, ARM 명령 +380,445/+393,195, SysTick 각각 +2회다. 실제 데이터 E1 바이트와 ROM 읽기 5,616회, DMA 125,488B는 같다. E8 등 다른 조회의 순서·횟수도 달라지므로 이 순증가를 새 drain 호출만의 고립 비용으로 해석하지 않는다.

원인은 큐가 빈 시각과 VBlank가 겹치지 않는 데 있다. 957의 마지막 map ACK는 후보에서 121/117행이었다. 뒤 일반 데이터가 도착하기 전 **1.110/1.056ms**의 빈 구간을 확보했지만 여전히 활성 화면이어서 그 구간의 선행 DMA는 0B다. 남은 map 1,664/1,536B와 최종 대기 1회는 집계 대조군과 같았다. 951도 마지막 map ACK가 9/11행으로, 약 4.9ms의 빈 구간에 map DMA가 없었다. 반면 952·954는 기존 대조군에서도 이미 필요한 map 전송을 완료해, 이 drain으로 제거할 최종 map DMA가 없었다.

집계만 바꿔도 한 위상의 밀집 구간에 1 VBlank 차이가 났다. 이는 집계 함수 자체가 16ms를 소비했다는 뜻이 아니라 작은 실행 시각 변화가 이후 공급·ROM 허용 구간·표시 경계로 전파됐다는 뜻이다. 두 위상·고정 부트 ROM 허용표 결과를 실제 게임의 개선 FPS로 환산하지 않는다. 계측 변경과 후보 변경을 한꺼번에 넣어 후자의 성과로 계산하지 않는다.

네 실행 모두 53장 RGB·독립 map/tile 검사·최종 ACK를 통과했다. 독립 재생도 대조군 8,037/8,010, 후보 8,107/8,109 소비 이벤트와 클록이 일치했다. ARM 거부 경계 9건은 fault 이후 재시도까지 차단했고, 메뉴 준비/해제 5조건 및 marker 4조건을 통과했다. 메뉴 I/O는 모델이며 새 실물 메뉴 복귀 증명은 아니다.

FPGA/SNES는 MMC540과 같은 파일이다. 기존 전체 Lite FIT 15,164LE·14,172 조합 함수·8,394FF·264,816 RAM bit·51 M9K 및 관련 setup +0.078ns/hold +0.139ns를 재사용한다. 새 FIT를 돌리거나 회로가 줄었다고 주장하지 않는다. 기존 전체 STA 위반이 남는 제한 실기 기준도 그대로다.

## 다음 작업 순서

1. **현재 제품 기준은 MMC540 유지.** 542의 raw 행 명령 단축과 543의 무조건 post-map drain은 추가 미세 조정 대상에서 제외한다. 다음 전달본에는 5–55초 집계를 유지하되 항상 같은 집계의 대조군을 둔다.
2. 951·957의 마지막 사용 가능한 VBlank에서 수락된 map 행, 큐 head, 실제 consume/credit 반환을 같은 시각표로 고정한다. map 데이터가 아직 없는 경우와 새 패킷 때문에 DMA가 시작되지 못한 경우를 나눈다. 마지막 map 뒤의 고정 지연·추가 polling으로 다시 해결하려 하지 않는다.
3. 수락된 행이 있는 경우에만 **기존 beam/service 정보를 활용한 한 번의 발행 조절**을 비교한다. 새 패킷·STOP 우선과 동기 DMA 완료 뒤 커서 진행을 보존하고, stale 힌트·다른 generation·다음 ROM 공급 지연을 비용/거부 조건에 포함한다. 필요한 추가 정보와 실제 삭제할 제어를 정하기 전에는 새 ABI/FPGA 상태기를 추가하지 않는다. 기존 SNES 본문 여유는 11B, ARM Flash 여유는 564B다. 542 cursor의 15B는 검증된 코드 크기 후보일 뿐 무료 시간 이득으로 합치지 않는다.
4. 두 위상에서 밀집 VBlank 수와 마지막 ACK를 함께 줄인 경우에만 actual ARM 집계·STOP·메뉴 및 변경된 보드 경계의 FIT/STA를 확인하고 새 파일명 전달본을 만든다. 계측만 바꾼 시험판, ROM, RESTORE는 전달하지 않는다.

원시 실행·소스·ARM·단위 시험·독립 재생은 로컬 `probes/nes-drain543/archive01/evidence.zip` 2,108파일을 보존하고 모두 SHA로 재검증했다. ZIP SHA256은 `0ddf189f0a356c3bd9a890b6d63398cefc3e4be3d2cdb901d20d7a96216c31f8`이다. 이전 542 실패 기록도 별도 archive01로 유지한다.
