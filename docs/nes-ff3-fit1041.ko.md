# FF3 CPU 실행·복원 쓰기와 보드 면적 1041

FF3 전용 보드의 T65에서 스택 및 주소 가산기, 프로그램 카운터의 상·하위 바이트 쓰기, A/X/Y와 내부 버스의 실행·복원 데이터 선택을 합쳤다. 보드에 연결된 CPU 모드 `00`을 명령 디코더와 저장 워드 읽기에 그대로 사용한다. 기존 FF3 저장 파일의 비트 배치는 같다. 호스트는 다른 모드의 파일을 PAUSE 전에 거부하고, FPGA도 CRC와 인덱스가 유효한 직접 복원 명령에서 같은 두 비트를 독립 확인한다. 불일치하면 해당 쓰기의 완료를 내보내지 않고 코어를 정지 상태로 유지한다.

### Quartus Lite 전체 보드 결과

Cyclone IV E EP4CE15F17C8, Quartus Lite 25.1, 동일 보드 제약으로 합성·배치를 실행했다. 기기 한도는 15,408 LE, 963 LAB, M9K 56개다.

| 전체 보드 | 요구 LAB | LE | 조합 함수 | 레지스터 |
|---|---:|---:|---:|---:|
| 1040 | 1,015 | 16,131 | 15,312 | 8,294 |
| 1040에 CPU 모드 고정과 복원 검사만 적용 | 1,017 | 16,129 | 15,279 | 8,292 |
| 1041 실행·복원 쓰기 통합 및 CPU 모드 고정 | 1,015 | 16,091 | 15,234 | 8,292 |
| 1041에 ALU 가산기까지 통합 | 1,017 | 16,077 | 15,216 | 8,292 |

채택한 후보에서 T65의 조합 함수는 1,462개에서 1,371개로 줄었다. 전체 LE 감소는 40개이고, 부족분은 683 LE·52 LAB다. M9K 56개를 모두 사용한다. 다른 대조에서는 SPI 송수신의 64비트 버퍼를 합쳐 레지스터를 64개 줄였지만 같은 CPU에서 필요 LAB가 1,017개에서 1,019개로 늘었다. 전체 FIT 오류 170012로 배치 후 STA와 프로그래밍 이미지를 생성할 수 없었다.

### FF3 복원과 STOP 검증

실제 FF3 ROM을 실행한 Questa RTL에서 상태 2,658워드를 저장하고 리셋 뒤 복원했다. 배터리 RAM 8,192바이트를 대조했고, 재개 후 첫 64개 CPU 명령 경계와 연속 두 화면의 122,880픽셀이 계속 실행한 대조군과 일치했다. 해당 장면은 3색이다. 부분 복원 일곱 경계에서 STOP 뒤 콜드 재시작을 확인했다. 이 시험에는 실물 SD 재선택과 코어 메뉴 조작이 포함되지 않는다.

별도 T65 시험은 1040과 43,012클록 동안 외부 주소·데이터·읽기/쓰기 신호와 파일 워드를 대조했다. 복원 쓰기는 1,536워드였다. 이 시험의 CPU 소스 해시는 전체 FIT 입력과 일치한다. CHR RAM 8,192바이트의 BG·OBJ 공급, 팔레트 렌더링 전환 2,048회, 부팅 전 배터리 접근, SPI CRC·워드 순서·재시도, 파일 손상 시 이전 세대 복구도 통과했다. 기능 로그는 `probes/nes-ff3-1041/native-checkpoint.log`, `cpu-sim.log`, `state-spi-sim.log`, `savefile-host.log`에 있다.

### 다음 면적 비교

최종 MAP에서 저장 SPI 엔드포인트는 조합 함수 385개, 코어의 저장 워드 순회기는 284개, 로컬 메모리의 주소·데이터 선택은 211개다. 세 값은 각각 별도 계층의 크기다. 세 블록의 합 880개 중에는 배터리 액세스와 독립 검사 등 필수 회로가 들어 있다. 이 전체를 절감으로 잡지 않는다. 다음에는 코어가 정지하고 표시가 완료된 동안의 워드 인덱스·바이트 순회를 한 소유자가 맡을 때 실제로 삭제되는 주소 선택기와 데이터 사본을 산정한다. 잔여 683 LE 및 LAB 배치 여유에 못 미치는 예산이면 다른 블록을 함께 대체할 범위부터 재검토한다.

### 재현 경로

- 보드 생성기는 `tools/prepare_ff3_display1037.py`, T65 변환기는 `tools/prepare_ff3_alu1041.py`다. 최종 소스로 다시 생성한 보드 파일 99개는 채택한 FIT 입력과 모두 바이트 단위로 일치했다.
- 원시 보고서는 작업 루트의 `probes/nes-ff3-1041/lite-native/`, 구조별 전체 보드 자원 비교는 같은 실험 디렉터리의 `whole-board-costs.json`에 있다.
- CPU 대조는 `tools/check_ff3_cpu1041.ps1`, FF3 전체 코어 복원은 `tools/check_ff3_checkpoint_rtl.ps1`, CHR·팔레트·저장 SPI 시험은 `tools/check_ff3_display1037.ps1`, 저장 파일·호스트 전송 시험은 `tools/check_nes_savefile1036.py`를 사용한다. Questa 작업은 기존 FLOAT 래퍼에서 순차 실행한다.
