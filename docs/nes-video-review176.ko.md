# NES176 영상 회고와 수정된 작업 계획

2026-10-14 사용자 승인: 화면 정지와 약60fps 표시를 함께 목표로 하고, 관계없는 로더 타이밍 미세 수정의 반복을 중단한다. 이 문서의 다음 작업이 이전175 READY/TIMER 문서의 NEXT를 대체한다. 과거 실험과 실패 기록은 그대로 보존한다.

## 이번 작업 결과

- **실제 ROM 모델 확장 완료:**360프레임/모델5.989초, 실제 CPU·PPU·MMC3와174 수집기를 사용했다. 즉시 해제349개,10프레임 보유35개 정상 후보이며 초기11개를 제외한 추가 거부는 없었다. 기존26개 상태 및24·25프레임 픽셀도 일치했다. 컨트롤 입력 없는 도입부 시험이고 이상적 ROM을 쓰므로 실제 공유 PSRAM·fill/export·SNES·첫 레벨·TV FPS까지 통과한 것은 아니다. 마지막 보유 후보는 시험 종료 때 아직 보유 중이며 별도 종료/해제 검증으로 세지 않는다.
- **중재기→exporter 연결6경우/37검사 통과:**시간 초과·백엔드 오류·주소 불일치를 BEGIN 전/후에 주입했다. 기존 오류가 있으면 새 BEGIN/ABORT 없이 후보를 거부하고 코어 읽기는 유지된다. 그러나 진행 중 오류는 먼저 ABORT1을 보낸다. 따라서174의12 COMMIT/ABORT0 정지를 재현·확정한 결과가 아니다.
- **전송량 하한 확인:**기존 두 모델 장면의 전체5,493바이트 대비 실제 차이20바이트를 정확히 재구성했다. 지속 캐시나 차분 프로토콜을 펌웨어에 적용한 상태는 아니다.
- **배포174 유지:**이번에는 모델·분석 도구와 가이드만 변경했다. 새 FPGA 합성/펌웨어/ZIP은 없고 실기 정지·60fps는 미해결이다.

[소스·로그 해시와 검증 범위](../analysis/admission176-verification.json). 새 private evidence56개를 별도 manifest로 고정했으며 상용 ROM/픽셀/라이선스는 Git에 넣지 않는다. 첫 가속 모델은 Verilog 리터럴 뒤 공백 누락으로 컴파일 실패했고 수정본으로 완료했다. 실행 모델은 오류0/경고44이며 원래 코어의 폭·미연결 포트/혼합언어·초기 metavalue 경고를 raw log에 보존했다.

## 판단과 근거

- **실기 기준은174 그대로다.** 12회 표시 완료 뒤 RUN3.81초부터 다음 BEGIN이 없었다. 음악·입력은 계속된다는 보고와 일치한다. 최초 부팅·화면 초기화 전체를 다시 검증할 근거는 부족하다. 후보 반복 거부, 수집기 결합, 소유권 해제/전달을 먼저 구분한다. ABORT0은 BEGIN 이전 거부가 없다는 뜻이 아니다.
- **정지 해결만으로 목표를 달성하지 못한다.**174의 완료 화면당 build+seal 평균167.5ms는 직렬 단계의 계측값이며 TV FPS가 아니다. 목표16.7ms와 큰 차이가 있다. 수신55.24초에는 정지 후 폴링이 포함된다.
- **타일 표시 선택은 유지한다.**164의57344바이트 픽셀 화면은11수직공백에 걸쳐 전송됐다. 이미 구현한 변경분 DMA, VBlank 동기, 비표시 VRAM 준비/전환을 다시 만들지 않는다.
- **차분을 만드는 위치를 앞당긴다.**174 MCU 변환기는 매번 plan을 초기화해 한 화면 안에서 패턴을 중복 제거한다. 지속 캐시는 아니다. map4096+CGRAM512+OAM544=5152바이트 전체와 HDMA를 전송하고 SNES에서 비교한다.2.625MHz SPI에서5152바이트만15.701ms,60Hz당 이상적 총 전송 용량5468.75바이트다. 수신 데이터·패턴·헤더·ACK·대기·계산이 빠진 낙관적 하한이다.
- **검증 범위를 실패 장면에 맞춘다.** 기존 실제 ROM 시험은26프레임까지,175 느린 소비 시험은 합성 PPU 약0.502초까지였다. 실제 약4초 후의 게임 장면·소비 지연을 배제하지 못한다. 소스 해시·모델 픽셀 일치와 실기 원인 확정은 구분한다.
- **타이밍 통과는 배포 조건이다.** 관측 추가 때문에 영상과 관계없는 로더 경로를 계속 고치는 일을 진척 지표로 삼지 않는다. 타이밍 실패 후보를 배포하거나 예외/클록 완화로 숨기지 않는다.

## 실행 순서와 중단 기준

1. **실제 ROM 장면을 늘려 후보 거부를 분리한다.** 기존26프레임 이후를 동일 CPU/PPU/MMC3·174 수집기로 관찰한다. 물리 메모리를 이상적 ROM으로 바꾸는 가속 모델은 앞26개 상태와24·25 픽셀을 원래70ns 모델과 대조한다. 즉시 해제와10프레임 보유를 같은 PPU 입력에 적용한다. 이 모델은 fill/export/SPI/SNES 대기 전체나 실기의 정확한4초 지점을 재현했다고 주장하지 않는다. 원인이 특정되면 해당 표현/결합 조건만 수정한다. 불충분하면 다음 실기에 필요한 최소 생산/거부/해제 관측을 정하고, 광범위 관측·무관한FIT 반복으로 확대하지 않는다.
2. **지속 캐시·변경 명령의 예산을 먼저 고정한다.** 초기화·타이틀·스크롤·레벨 전환을 분리해 패턴/맵/팔레트/OAM/래스터/왕복 바이트와 CPU 시간을 센다. 같은 패턴에 안정된 슬롯을 유지한다. MMC3 물리 주소와 CHR-RAM 내용 세대, 행 재조합 패턴의 실제 내용까지 캐시 키에 반영한다.174의 cross-cell per-frame key를 그대로 지속 캐시 키로 쓰지 않는다.
3. **변경 전송을 한 경계씩 연결한다.** 패턴과 테이블 전체 재전송, 패킷별 왕복, SNES 전체 비교의 비용을 줄인다. 교대 WRAM/VRAM의 base_generation·target_generation·ACK 이후 확정·실패시 폐기/재동기화를 계약으로 정한다. 해시만으로 같은 타일이라고 단정하지 않으며 활성 슬롯을 조기 덮어쓰지 않는다. 두 번째 MCU 전체 화면이나 세이브 SRAM을 추가하지 않는다.
4. **SPI 유지 여부를 수치로 결정한다.** 변경량 감소 후에도 총 직렬 비용이16.7ms를 초과하면 SPI 속도만 올리거나 타임아웃만 늘리지 않는다. FPGA 준비 버퍼→SNES 카트리지 버스 DMA 직결을 비교한다. PSRAM의 명시적 비세이브 영역·중재·버스 응답·세대 소유권 검증이 선행 조건이다. 우회만으로60fps를 보장하지 않는다.
5. **실기 SMB3로 합격 판정한다.** 도입부 뒤 첫 레벨에서 이동/점프/스크롤과 사운드가 함께 유지되고 표시 간격이 개선돼야 한다. 필수 변경 경계 검사 뒤 바로 실기로 간다. 이후 장기 플레이/오류·리셋 로그, 입력 유지 순서다.

## 이번에 좁힌 범위

기존 모델 두 장면(24→25)의 출력6종을 바이트 단위로 비교하고, 이전 장면에 변경 범위를 적용해 다음 장면이 정확히 복원되는지 확인했다. 전체5,493바이트 중 차이는 BG19바이트와 map1바이트, 총20바이트다. 두 도입부 장면의 **전송량 하한 실험**이며 구현된 프로토콜이나 일반 플레이의 압축률이 아니다. DMA 정렬·범위 합치기·명령·ACK·왕복·생산자 데이터는 추가 비용이다. 이전 장면을 잘못 물려받으면 이 결과는 성립하지 않는다.

공유 PSRAM 중재기의 `fault`는 sticky이고 이후 fill 허용과 exporter의 geometry 허용을 차단한다. 반면 소유 중인 요청이 배수된 뒤 코어의 읽기는 계속 가능하다. 기존 ROM 오류0만으로 이 중재기 오류0을 증명할 수 없다. 다만 **이미 BEGIN한 프레임 중 발생한 오류라면 exporter가 ABORT를 보내야 한다.** 짧은 연결 시험에서도 이 차이를 확인했다. 따라서174의 ABORT0을 이 가설의 확정 근거로 삼지 않으며, 오류 감시를 끄거나 제한을 늘리는 수정은 하지 않는다.

후속 최소 관측은 단순 geometry_valid만 읽지 말고 원래 수집 결과와 `rom_fault`/`native_arbiter_fault`를 적용한 최종 허용 조건을 구분해야 한다.175 A5에는 중재기 fault 자체가 없으므로 그대로 재시도하지 않는다. 마지막 COMMIT 뒤 frame_owned·release·export DRAIN·fill busy/idle/abort를 같은 시점에 구분하는 최소 묶음을 정하고, 관련 없는 로더 최적화를 다시 선행 작업으로 만들지 않는다.

성능 계측에서는 build38.3ms를 전부 CPU 변환 시간으로 부르지 않는다. build 안의 패턴 staging 콜백도 SPI 전송을 한다. 변환 계산·유효 전송·폴링·SNES 준비/표시를 분리한 뒤 개선 효과를 판정한다. 수신기의 타일은 tag 오름차순이므로 선형 검색을 줄일 여지도 있지만, 측정 없이 이것만 고쳐60fps 해결이라고 보고하지 않는다.

## 보존 및 인계

174/164 복원/GBC/세이브 SRAM과 완료 evidence는 보존한다. 동일174·044·단색 A/B·변경 없는 ROM 적재 시험을 반복하지 않는다. 실제 코어 시뮬레이션의 frames, 수집 generation, 표시 ACK, TV FPS는 서로 다르다. 새 시험 결과는 별도176 기록으로 남기며, 관측만 통과한 것을 영상 개선 완료로 보고하지 않는다.
