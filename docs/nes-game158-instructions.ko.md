# NES158 — MMC3 전환 전 그래픽 읽기 시험

157에서 읽어 둔 그래픽 주소가 PPU샘플 직전에 바뀌는 것을 확인했다.158은 CPU가 제시한 MMC3 쓰기를 바탕으로 다음 CHR주소를 미리 읽는다. 실제 뱅크 변경 시점·게임 클록·오류 검사·화면·버튼 전달은 유지했다. **합성 재현 시험은 통과했지만 실제 게임 정지 해결은 이번 실기로 확인해야 한다.** 소리는 이전과 같이 진단용으로 차단돼 있다.

1. ZIP의 `01-GAME158-SD-ROOT` **안의 내용**을 SD 루트에 덮어쓴다. `firmware.stm`, `sd2snes/fpga_n158.bi3`, `sd2snes/nes/game158.nes`를 함께 적용한다.
2. 메뉴에서 **`NES GAME 158.nh1`**를 실행한다.0바이트 표식이 정상이므로 확장자를 바꾸지 않는다.
3. 첫 Start로 선택 화면에 들어가고, **1PLAYER에서 Start를 한 번 눌렀다가 뗀다.** 진행되면 이동·A/B 동작을 확인한다. 실제 플레이가 되면 짧은 영상도 부탁한다.
4. 메뉴로 돌아오면 `sd2snes/nes-progress-158.txt`와 `sd2snes/nes-game-last-158.txt`를 전달한다. 같은 정지라면 영상은 생략해도 된다.

로딩 경로는 기존384KiB 전체 적재·비교와 같다. 이전 실측 약3분50초를 참고하며,158에서 새로 실측한 값은 아니다. 게임 실행 상한은 기존 약60초, 오류 시 조기 종료한다. 전체7분이 넘어도 반응이 없으면 더 기다리지 말고 화면 상태와 생성된 TXT를 전달한다.

044/GBC 복원 시험을 다시 보고할 필요는 없다. 정상 사용으로 돌아갈 때 동봉 `02-RESTORE044-SD-ROOT`를 적용한다. 기존 버튼 이력·직전16클록 기록은 유지했으며 사용자가 직접 해독할 필요는 없다.

이번 수정은 MMC3 쓰기 예측에 한정된다. PPU 논리주소 자체의 늦은 변경, 게임 전체 호환성, 정상 표시속도·오디오·저장은 완료되지 않았다. 현재 임시 이력을 포함해 M9K56/56개를 쓰므로, 다음 결과에서 원인이 확인되면 임시 관측을 축소한다.
