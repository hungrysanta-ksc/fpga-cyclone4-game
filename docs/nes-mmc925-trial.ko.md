# MMC925 · 모험도 4 무입력 60초 실기판

1. 전원을 끄고 ZIP의 `MMC925-ADVENTURE-60SEC-SD-ROOT` 폴더 **안의 내용물**을 SD 카드 루트에 복사한다.
2. MMC915에서 사용한 모험도 4 일본판 ROM을 같은 SD 폴더에 `sd2snes/nes/mmc925.nes`로 복사한다.
3. 루트의 **NES MMC3 925.nh1**을 실행한다. 이후 버튼을 누르지 않고 오프닝과 스테이지 데모가 표시되는지, 60초 뒤 자동으로 메뉴에 복귀하는지 확인한다.
4. 실행 직후 SD의 `sd2snes` 폴더에서 `nes-progress-mmc925.txt`, `nes-budget-mmc925.txt`, `nes-game-last-mmc925.txt`, `nes-frame-mmc925.bin`을 보관한다. 재실행하면 같은 이름의 로그가 갱신된다.

## MMC915와 비교하는 기준

| 구간 | 집계 시간 | MMC915 실기 표시 수 | MMC915 표시 FPS |
|---|---:|---:|---:|
| 1–30초 오프닝 | 29초 | 627장 | 21.62 |
| 30–60초 스테이지 데모 | 30초 | 646장 | 21.53 |

집계에는 공개가 끝난 화면만 포함한다. 30초 경계에서 공개된 화면은 데모 구간에 들어간다. 중도 종료되면 로그는 복구 분석에 사용하고 60초 FPS 비교에서는 제외한다. 저장소의 `tools/nes_windows518.py compare`에 두 실행의 `--previous-budget`, `--previous-progress`, `--current-budget`, `--current-progress` 파일을 지정하면 같은 집계식으로 차이를 계산한다.

## 전달 전 검증

925는 924 objheader ARM과 920의 65816 표시 ROM을 사용한다. 914I의 Quartus Lite 배치를 재사용하고 내부 ROM 초기값을 교체해 FPGA 이미지를 다시 조립했다. 보드의 ROM 읽기 경로에서 5,120바이트 전부를 65816 재생에 사용한 ROM과 대조했다. 최종 ARM Flash는 212,940 / 212,992B다.

| 연속 재생 측정 | 위상 1 | 위상 2 |
|---|---:|---:|
| 기존 캐시 910 캡처 여유 | 5.59µs | 23.23µs |
| 기존 캐시 여섯 표시 간격, MMC915→925 | 14→13 VBlank | 14→13 VBlank |
| 기존 캐시 912 최종 ACK 단축 | 16.739ms | 16.688ms |
| 빈 캐시 912 선행 DMA / 여섯 표시 간격 | 496B / 16 VBlank | 496B / 16 VBlank |
| 빈 캐시 912 최종 ACK 단축 | 4.94µs | 12.66µs |

위 시각은 링크된 ARM·65816을 동일한 입력·SPI·IRQ·ROM 경쟁 조건에서 재생한 값이다. MMC925 실기 FPS는 위 두 구간의 로그로 판정한다.
