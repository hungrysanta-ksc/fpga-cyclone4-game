# 716 필요한 경우에만 BG·OBJ descriptor를 만드는 ARM 검증

## 목표

707D·기존694/704 ARM·기존694 65816의 map 행 발행 순서와 큰 plan 묶음을 유지하면서, 이미 확보된 slot에도 반복하는 descriptor 생성을 제거한다. 두 시작 위상에서 952–957 합계18 VBlank 미만·밀집 평균·957 마지막 ACK를 함께 개선하고, 911 마감·951 공개≤246선·952 표시3회·957 최종대기0회·7블록 선행 수신을 보호해야 채택한다. [검증](../analysis/lazy716-verification.json) · [원시 근거](../analysis/lazy716-archive.json)

## 작업내용

기존 hash index와 정확한 key 비교를 유지하고, 일반 BG·OBJ의 40B descriptor 중 header8B를 먼저 만든다. row16B·alt16B는 실제로 필요한 경우에만 초기화한다. 내부 slot 함수에 `rows_ready` 인자4B를 추가했으며 새 SPI 명령·캐시·정적 버퍼는 없다. source tag 검사, epoch/generation·prepared·fault·소유권 검사는 유지한다. 예외 BG와 zero descriptor는 기존처럼 완성한 뒤 전달한다. 미완성 zero는 거부한다.

- **A:** 같은 프레임의 정확한 slot hit이면 32B 초기화를 생략한다. miss에서는 초기화한 뒤 원래 분류·뱅크 이력 검사를 수행한다.
- **B:** header를 검증한 일반 descriptor는 알려진 기본 shape를 만들고 다시 검사하지 않는다. 같은 프레임 hit뿐 아니라 확정된 대상 뱅크의 기존 slot 재사용에도 shape 생성을 생략한다. 실제 write callback이 필요할 때만 공유 `nes_resident716_rows`로 초기화한다. 예외 shape의 독립 검사는 그대로다.

두 후보 각각 정상60초·장시간 ARM을 전체 링크했다. 각 장시간 바이너리로 905–957의53화면×두 위상, 합계212화면을 실행했다. 원본106화면과 시작7288416/7467100·입력·map/OBJ·공유 SPI·IRQ·2bulk·ROM 달력·65816을 맞췄다. 실제 ARM 메모리 접근에서 shape의 모든 읽기가 초기화 뒤인지 확인했고, map·tile·순서 있는 plan·픽셀 일치를 검사했다.

M4·65816의 실제 링크 코드를 실행하지만 CPI2/84MHz 및 공유 SPI·IRQ 모델, 주기적인 측정 ROM 허용 구간을 사용한다. 실기 FPS나 게임 NES CPU·PSRAM 전체 RTL의 동시 실행 결과는 아니다. callback·IRQ를 포함한 planner 비용이며 순수 산술 시간으로 해석하지 않는다.

**두 후보 모두 기능·안전 검사를 통과했으나 채택 조건에는 실패했다. 707D·기존 ARM·65816을 유지한다.** B의 계산 절감은 실증했으며 폐기하지 않고 미채택 후보로 보존한다.

## 후속작업

1. 선택본은707D·기존694/704 ARM·기존69465816이다. 새 설치본은 만들지 않는다. 715 전체 BG-first/2차 map 순회는 보류하고, **716B의 약1ms 계산 절감과 비밀집 네 구간 개선은 재현 가능한 후보로 보존**한다.
2. 먼저716B의951 공개가247/248선으로 밀린 경계와954 마지막 tile 준비·발행·credit·수락·소비를 대조한다. map 발행 순서·큰 묶음·검사선을 고정하고 실제 원인 경계만 수정한다. 특정 위상용 고정 대기나 검사 완화로 맞추지 않는다.
3. 이어 이미 검증된 source의 같은 프레임 exact-key hit에서도 반복되는 tag 탐색·key 비교 비용을 계측한다. 기존 hash를 새 캐시로 중복 구현하지 않는다. source identity·epoch·kind·첫 사용 검사를 보존해야 한다. 제거 가능한 계산량이954의 남은 ROM 구간 차이2.35ms에 의미 있게 기여하는지 먼저 예산화한다.
4. B 정상판은16B 이상 순삭제가 필요하다. 원본 여유8B·공동 발행 경계1116B·추가 정적RAM≤4B·FPGA/65816 증가0을 유지한다. Flash·951 회복만으로 밀집18VB 감소를 달성했다고 하지 않는다. 두 위상의 모든 보호 조건과952–957 합계 감소·밀집 평균·957 ACK 동시 개선 후에만 채택한다.
