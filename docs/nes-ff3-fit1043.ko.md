# FF3 저장 보드 1043

FF3 전용 CHR-RAM 보드가 Cyclone IV EP4CE15F17C8에서 처음으로 전체 FIT, 배선, STA 및 SOF 생성을 마쳤다. 1043은 개발 보드 번호다. 실기 배포와 메뉴를 통한 장면 복귀는 별도로 검증해야 한다.

| Quartus Lite 25.1 전체 보드 | 1042 secondary-final | 1043 rank | 한도 |
|---|---:|---:|---:|
| LE | 15,468 | 15,284 | 15,408 |
| LAB | 976 | 963 | 963 |
| M9K | 56 | 56 | 56 |

1043의 조합 함수는 14,478개, FF는 7,759개, 내장 RAM은 330,640비트다. 분석한 코너 중 최소 슬랙은 setup +0.149ns, hold +0.179ns, recovery +1.846ns, removal +0.501ns, 최소 펄스 폭 +2.627ns다. 외부 SRAM 핀의 배치 후 전파 지연도 따로 추출했다. 주소 출력 2.371–7.055ns, 데이터 출력 2.421–12.770ns, 데이터 입력 1.927–6.426ns, WE 출력 5.559–13.502ns, OE 출력 2.899–8.723ns다. 이 값에서 실제 PCB와 SRAM 부품 지연은 제외했다.

## 무엇을 바꿨는가

추가 스프라이트 평가가 기본 OAM 복사본의 유휴 읽기 포트를 쓴다. CHR·nametable 및 CPU·배터리 RAM은 정지 중에 저장 주소와 쓰기 데이터를 공유한다. 마지막에 스프라이트 순위 8개의 최근 행 번호를 각 fragment RAM 워드의 빈 비트에 넣고 연속된 같은 순위에는 직전 행을 전달했다. 외부로 읽히는 fragment의 예약 비트는 여전히 0이다. 수락과 반환 계측은 같은 에지에 각각 기록할 수 있다. 저장 SPI와 계측 SPI의 클록 경계도 유지했다.

## 확인한 경로

- 순위 8개, 중복·역순 행 및 map 224행을 대조했다. OAM은 두 구현에 같은 179,208도트를 입력해 CPU 주소 변경 43,334회, 추가 스프라이트 8개 행, 동시 쓰기 충돌을 확인했다.
- 실제 FF3 ROM을 실행한 혼합 언어 코어에서 2,658워드를 저장·복원했다. CPU 명령 인출 64회와 PPU의 두 프레임 122,880픽셀이 연속 실행과 같았다. 부분 복원 7곳에서 STOP 후 cold 상태, 배터리 8,192B, 중단된 저장·복원도 검사했다. 이 장면은 세 색 이상이 처음 나타나는 화면이다.
- ARM이 256B씩 FatFS로 쓰고 읽는다. CRC·순서·완료 워드를 검증한 뒤 새 파일 세대를 공개한다. 실제 기기용 SD 드라이버는 FF3 정지 및 소유권을 확인한 저장 구간에만 게임 중 섹터 쓰기를 허용한다.
- 전체 링크는 Flash 211,860/212,992B다. 링크된 ARM·FatFS와 가상 FAT16 카드로 일반 저장 8,192B, 슬롯 저장 21,264B를 기록했다. 같은 카드로 새 ARM 인스턴스를 시작해 두 파일을 온전히 복원했다. 다른 ROM ID의 슬롯은 거부했다. 호출 스택 31,368B를 예약했을 때 시험 중 관측한 최저 여유는 1,304B다. 인터럽트를 포함한 최악치 측정은 남아 있다.
- 같은 바이너리에서 파일명을 바꾼 FF3와 Kirby를 SD 브라우저로 선택했다. 파일 CRC를 계산한 다음 각각 CHR-RAM·CHR-ROM 보드 프로그래머로 진입했다. 미지원 매퍼와 선택 후 바뀐 파일은 거부했다.

## 다음 실기판 조건

L+R+START에서 열린 메뉴가 이전 화면의 최종 ACK까지 소비를 계속하고, 정지 확인 뒤 일반 저장 또는 슬롯 저장·불러오기를 실행해야 한다. 복원 뒤에는 렌더러 이력을 무효화하고 양쪽 뱅크를 새 상태로 채워야 한다. SD에서 FF3를 재선택한 뒤 같은 부하 장면의 CPU 진행·표시·메뉴 복귀까지 대조한 뒤 설치본을 만든다. 현재 65816 부팅 ROM 여유는 24B다.

원본 보고서는 작업 루트의 `probes/nes-ff3-1043/lite-rank/`, 링크 결과는 `arm-drain/`, 계측은 `browser-final.json`과 `sd-final.json`에 있다. 동일 입력을 만드는 도구는 `tools/prepare_ff3_display1037.py`, `tools/prepare_ff3_play1043.py`, `tools/fit_ff3_display1037.ps1`, `tools/check_ff3_display1037.ps1`, `tools/check_ff3_checkpoint_rtl.ps1`, `tools/check_ff3_sd1043.py`다.


## 1044 실기 전달 준비

FF3 메뉴를 포함한 최종 1044 보드는 15,153 LE, 961/963 LAB, 56/56 M9K를 사용한다. Quartus Lite의 3개 코너 57개 검사에서 TNS는 모두 0이다. 최소 setup은 +0.330ns, hold는 +0.168ns다. 기존 PSRAM 접근 예산의 최소 여유는 3.663ns다. 외부 SRAM 핀의 배치 후 전파 지연은 별도로 추출했다. PCB 및 실물 SRAM의 지연은 실기 확인 범위다.

최종 ARM은 212,636바이트로 356바이트가 남았다. 슬롯을 불러오면 STOP 뒤 선택한 파일의 CRC와 PSRAM 전체 524,288바이트를 대조해 새 START를 허용한다. 부팅 정지에서 실제 코어 정지 응답으로 넘기는 동안 다음 캡처를 막는다. 부분 복원 중 STOP은 기존 작업을 취소한다. 네 슬롯에 서로 다른 상태를 남기고 새 ARM에서 4·1·3·2 순서로 불러와 각 슬롯의 내용이 일치하는지 확인했다. 65816 메뉴가 PPU 에뮬레이션에 그린 제목, 슬롯 2의 저장·불러오기 요청, 메뉴 종료 요청, 재개 뒤 글꼴·타일맵·팔레트 복원을 확인했다.

설치와 실기 재현 절차는 [FF3 1044 실기 시험](nes-ff3-play1044.ko.md)에 있다. 최종 경로는 `probes/nes-ff3-1043/lite-timing`, ARM은 `arm-cold`, 메뉴 ROM은 `rom-timing`이다.
