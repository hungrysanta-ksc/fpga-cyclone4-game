# 1008 · 세대 912의 token 36 반환 이후 발행 여유

## 목표

978에서 세대 912의 496B 선행 DMA를 지키면서 팔레트·OAM·section 5 또는 후속 OBJ를 먼저 발행하면 VBlank 46의 246선 안에 공개할 수 있는지 확인했다. 비교 단위는 SNES master clock이며 같은 시작 위상의 978을 기준으로 삼았다.

## 작업내용

- 링크한 ARM을 두 시작 위상에서 다시 실행해 token 36 반환을 확인한 E0와 token 37을 조회한 E8 사이의 호출 위치를 기록했다. 계측 전후 SPI 이벤트, 타일 생산 기록, 패킷, 65816 ROM, 소비 시각 파일이 바이트 단위로 일치했다.
- 첫 실험은 978의 큐 용량과 후속 SPI·SEAL 시각을 고정하고 빈 E0 구간에 E1 하나만 옮겼다. 후속 OBJ는 실제 token 36 반환 응답의 CRC와 세대 확인 뒤 E8과 E1을 모두 지불했다. 두 번째 실험은 token 36까지 같은 입력을 재생하고 이후 2슬롯 credit, E0·E8, ROM 공급, 뱅크 반환, 공유 SPI를 반영해 후속 패킷까지 다시 배치했다. 두 시험 모두 65816에서 실제 명령을 실행했다. 패킷 순서 후보는 스케줄 재생이며 변경한 ARM 펌웨어의 실행 결과는 아니다.
- section 5의 201B는 원본 데이터가 준비된 뒤에도 연속 송신 버퍼 조립을 기다린다. 원래 조립 시각을 적용한 경우와 복사 비용을 0으로 둔 낙관적 대조군을 분리했다.

## 성과

양쪽 위상 모두 token 36 반환을 확인한 뒤 `nes_plan200_progress+0x148`에서 같은 E0 응답을 12번 더 읽었다. E8까지 33,364클록(약 1.55ms)이 지났다. 한 패킷을 옮겨 이 시간을 활용할 수 있었지만 화면 공개는 앞당겨지지 않았다.

| 고정 일정의 변경 | VBlank 46 선행 DMA (위상 1 / 2) | 912 공개 (양쪽) | 최종 ACK 차이 (클록, +는 지연) |
| --- | --- | --- | --- |
| 978 대조군 | 496 / 496B | VB47 242선 | 0 / 0 |
| 팔레트 첫 패킷 | 496 / 496B | VB47 242선 | +316 / 0 |
| OAM 첫 패킷 | 496 / 496B | VB47 242선 | +212 / +272 |
| section 5 첫 패킷, 선조립 가정 | 496 / 496B | VB47 242선 | +316 / +496 |
| 후속 OBJ 먼저 조회 | 464 / 464B | VB47 243선 | +998 / +1,178 |

978에서 496B 전송이 끝난 240선부터 246선 끝까지 남은 시간은 8,196 / 8,276클록이다. 팔레트 512B와 OAM 544B의 데이터 이동만 8,448클록이어서 252 / 172클록이 부족하다. 실제 남은 tile·raw 352B까지 포함하면 최소 부족분은 **3,068 / 2,988클록**이다. 이 하한에는 DMA 설정, 독립 검사, PPU 공개가 포함되지 않는다.

후속 전체를 2슬롯으로 재배치하면 후속 OBJ 우선 후보는 VB46에 528B를 보냈다. 같은 2슬롯 대조군 대비 최종 ACK는 −100 / +132클록이었다. 두 경우 모두 VB48에 공개됐다. 이 재생에서는 원래 SEAL 뒤의 D0 입력 조회 시간도 예약되어 240B 연속 SPI 전송이 밀리므로, VB48은 독립적인 실기 2슬롯 성능값으로 사용할 수 없다.

정상 재생 전체에서 905–912의 여덟 화면이 978과 RGB 단위로 일치했다. 양쪽 위상에서 팔레트 선행 후보에 잘못된 SEAL과 수신 중 STOP을 각각 주입한 결과 7회만 공개됐고 911 화면이 유지됐다. 실기 메뉴 복귀와 FPS는 새로 측정하지 않았다.

## 후속작업

978을 유지한다. 다음 실험에서는 496B의 첫 DMA 설정·마지막 바이트와 남은 tile·raw 352B의 개별 수락·DMA 가능 시각을 나란히 기록한다. 496B 완료를 앞당기거나 잔여 전송을 앞선 공백으로 옮겨, 두 위상에서 데이터 하한과 실제 246선 공개를 순서대로 통과하는 후보만 전체 ARM 일정으로 검증한다.

재현 시 기존 978·1002 입력과 독립된 새 출력 디렉터리를 사용한다. 각 위상에 대해 `nes_drain1008.py TEMP PHASE`, `nes_gap1008.py TEMP PHASE hold palette oam section precopy next_obj`, `nes_gap1008.py TEMP PHASE hold palette oam precopy next_obj --fixed`를 실행한다. 고정 팔레트 시험에 `--fault stop_decode`와 `--fault bad_seal`을 개별 적용한 뒤 `check_nes_gap1008.py TEMP analysis/gap1008-results.json`으로 두 위상을 대조한다. 전체 시각과 DMA별 바이트 수는 [결과 JSON](../analysis/gap1008-results.json)에 있다.
