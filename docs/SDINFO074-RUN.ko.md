# SDINFO074 — 화면이 꺼지는 저장 오류의 LED 진단

073에서 사용자는 **HW004000.TXT 0바이트·화면 없음**을 보고했다. 오류 종류를 아직 확정하지 못했다.074는 SD 드라이버를 추측으로 바꾸는 수정본이 아니라, 같은 실패를 **카트리지 LED로 식별하는 관측용 펌웨어**다. 오류 뒤 추가 SD/SPI/UART 출력·재시도·RESET 해제를 하지 않는다. 기판을 분해하거나 PC에 연결할 필요는 없다.

## 교체와 회수

1. 전원을 끄고 SD를 분리한다. 기존 독립 원본 백업과 `/sd2snes/firmware.before-sdinfo072.stm`을 유지한다. 현재 수집기 펌웨어를 원본 백업에 덮어쓰지 않는다.
2. `FXPAK-SDINFO074-SD.zip`에서 **sd2snes/firmware.stm 하나만** 교체한다.133332바이트, SHA256 `031725700f3e9c58abc1001f9d53cdbe89a1587e5e552a77951434d136953271`. 기본 FPGA·메뉴·게임·세이브는 교체하지 않는다. 대응 소스는 별도 `FXPAK-SDINFO074-SOURCE.zip`이다.
3. 실기에서 실행한다. 화면이 나오면 SDINFO074-BASE069인지 확인한다. 검은 화면이어도 **카트리지 Ready·Read·Write LED 세 개가 보이도록 60초 영상**을 찍는다. LED가 보이지 않는다면 분해하지 말고 보이지 않는다고 알려준다.
4. 전원 켠 뒤2분 안에 완료 화면이 없으면 관측 후 전원을 끈다. 새 루트 `HW005000.TXT`–`HW005999.TXT`가 있으면 크기와 함께 전달한다.0바이트여도 LED 영상이 이번 진단의 주된 결과다. 예전HW004000.TXT는 덮어쓰지 않는다.
5. 진단 후 전원이 꺼진 상태에서 독립 백업의 **원본 firmware**를 복원하고 크기·해시/전체 바이트를 대조한다. 원래 메뉴/GBC 관측은 별도 기록한다. 임의의 펌웨어로 복원하지 않는다.

## LED 읽기

수집 중에는 Ready가 깜빡인다. 공유 오류가 기록되면 아래 순서가 반복된다. 직접 셀 필요 없이 영상으로 전달해도 된다.

**세 LED 동시 점등2초 → 소등1초 → Read가 오류 번호만큼 깜빡임 → 소등2초 → Write가 단계 번호만큼 깜빡임 → 소등3초.** 각 깜빡임은 켜짐0.5초/꺼짐0.5초이며 한 주기는 최대26초다. 첫 오류와 당시 단계를 고정하므로 이후 정리 과정의 오류가 원인을 덮지 않는다.

| Read 횟수 | 오류 종류 | Write 횟수 | 실행 단계 |
| --- | --- | --- | --- |
|1|SD busy 대기 한도|1|입력 수집|
|2|SD 명령 응답/상태 검사|2|새 TXT 열기|
|3|SD 읽기 데이터 대기|3|TXT 내용 쓰기|
|4|SD 데이터 CRC/쓰기 수락 응답|4|동기화|
|5|SD 상태/소유권|5|쓰기 파일 닫기|
|6|파일시스템/처리 한도|6|재읽기 열기|
|7|공유 SPI|7|전체 재읽기 비교|
|8|타이머|8|재읽기 닫기|
|9|기타 또는 기록 없는 차단|9|최종 화면 출력|

LED 원인은 소프트웨어가 처음 기록한 오류 분류이며 전기적 근본 원인 확정은 아니다. 같은 Read4도 카드의 거절과 응답 샘플 문제를 추가 분석해야 한다. 깜빡임이 멈춘 채 고정되는 경우도 그대로 전달한다. 이 표시의 시간은100Hz SysTick에 의존하며, SysTick/CPU가 정지해도 동작하는 독립 감시 장치는 아니다. 기존 초기 부팅/file_init/mini 단계 역시 새 제한 시간의 범위 밖이다.

저장이 완료되면 `TXT SAVED + READBACK OK / Save code: 0` 화면에 머문다. 파일 생성·전체 재읽기 성공은 NES 메뉴 승인·원본 복원·CF68 실기 성공을 의미하지 않는다. 입력4개는 계속 읽기 전용, 새 보고서만 CREATE_NEW로 저장한다.071 NES 쌍 설치 보류는 유지한다.
