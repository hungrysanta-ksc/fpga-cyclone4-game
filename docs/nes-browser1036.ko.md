# MMC1035 실기 분석과 NES 파일 선택판

MMC1035는 두 번 모두 60초를 마치고 메뉴로 복귀했다. 첫 구간은 29초, 둘째 구간은 30초를 분모로 썼다.

| 실기판 | 오프닝 1–30초 FPS | 데모 30–60초 FPS |
|---|---:|---:|
| MMC1034 1회 / 2회 | 27.24 / 25.10 | 28.50 / 26.10 |
| MMC1035 1회 / 2회 | 25.07 / 26.93 | 25.90 / 28.73 |

59.70초의 세대 1550과 1691은 모두 15타일과 입력 17블록(1,849B)을 사용했다. 입력 버퍼 해제→캡처 시작은 13.26 / 3.51ms, 이후 첫 블록 준비는 양쪽 모두 14.04ms였다. 첫 뱅크 반환→둘째 묶음 공개는 9.75 / 7.41ms, 그 공개→반환은 1.17 / 0.78ms였다. 이 카운터에는 한 틱 약 0.39ms의 양자화가 있다. 실제 표시는 4 / 3 VBlank였다.

수락된 출력 레코드와 다음 불변 소스 조회를 겹친 RTL 시험은 캡처 자료의 두 위상에서 마지막 데이터 D2를 3.440 / 3.393µs 당겼다. 18개 실제 블록의 바이트·CRC, STOP, 선행 COMMIT 거부를 대조했다. 이 수치는 실제 화면 공개나 실기 FPS를 당겼다는 근거로 쓸 수 없다. 다음 성능 비교에서는 캡처 시작선이 같은 세대를 우선 짝짓는다.

## SD 브라우저

`tools/prepare_nes_browser1036.py`는 MMC1035 링크에서 NES 파일 유형과 일반 선택, 최근 실행, 즐겨찾기 분기를 연결한다. 사용자는 SD 게임 폴더에 원래 이름으로 둔 파일을 고른다. 확장자 비교는 대소문자를 무시한다. 메뉴의 작업용 파일명 버퍼를 다른 코드가 써도 재검증을 위해 다시 열 경로는 별도로 보관한다.

현재 프로필은 iNES 1.0 mapper 4, 수평 미러링, PRG 512KiB에 CHR ROM 256KiB 또는 CHR RAM 8KiB인 구성이다. 헤더·실제 파일 길이로 프로필을 고르고, 파일 전체 CRC를 이번 세션의 기준으로 삼아 재읽기와 FPGA의 바이트 단위 검사를 수행하도록 했다. 지원 범위를 벗어나는 파일은 RESET 전에 메뉴 오류로 처리한다.

`tools/check_nes_browser1036.py`는 실제 ARM 링크에서 메뉴 판정부터 FPGA 프로그래머 진입까지 실행한다. 혼합 대소문자·폴더·이름 변경·다른 내용의 같은 규격 ROM·잘린 파일·다른 매퍼·이중 확장자를 시험했다. 메뉴 선택 후 다른 프로필의 파일로 바뀐 경우에도 프로그래머에 도달하기 전에 거부했다. 브라우저 링크는 211,504B이다. 실제 FatFS 저장·불러오기 함수를 모두 유지한 개발 링크는 212,464B로 212,992B 한도에서 528B가 남는다. 이 수치에는 미구현 SPI 전송과 메뉴 코드가 포함되지 않는다.

## 저장과 FF3 검증 경계

`src/nes/nes_savefile.c`는 ROM CRC·크기·슬롯으로 배터리와 기계 상태 파일을 구분한다. 배터리는 8,192B, 상태 슬롯 1–4는 현재 엔진 기준 21,264B이다. 저장할 때 다른 사본에 쓰고 동기화와 닫기 후 다시 읽어 확인한다. 실제 C 코드를 호스트 파일로 실행해 이전 사본 복구, 슬롯 격리, 게임 격리를 확인했다. 불러오는 쪽은 CRC를 확인한 임시 버퍼만 코어에 전달해야 한다.

첨부된 FF3의 PRG는 512KiB이고 CHR RAM과 배터리 RAM은 각각 8KiB다. 소프트웨어 기준인 Mesen은 저장 지점을 복원한 뒤 60장의 화면 및 메모리 지문이 일치했다. 전체 보드에서는 가변 CHR의 캡처와 표시 세대를 묶고, SPI 상태 전송과 코어 메뉴, SD 저장 및 복귀를 연결해 검증해야 한다. MMC1035의 기존 FIT는 963 LAB와 55 M9K를 사용하므로 FF3의 가변 CHR 8KiB를 단순히 내부 RAM에 추가한 기능 시험을 전체 보드 FIT로 간주할 수 없다. 이 문서의 ARM 링크는 개발용이다.

FF3 원본 대조에서 첫 600장 중 9장에 걸쳐 16B 패턴 타일의 내용이 바뀌었다. 프레임별 변경 타일 수의 합은 173개, 최대는 한 장에 30개였다. 표시기가 같은 주소의 예전 패턴을 재사용하지 않도록 저장 복원과 CHR 쓰기 양쪽에서 캐시 이력을 처리해야 한다.

Questa 기능 시험은 첨부 ROM으로 CPU를 기동해 CHR 및 이름표 쓰기를 관측하고, 안전한 명령 경계에서 정지해 2,658개의 64비트 워드를 저장한다. 콜드 초기화를 거쳐 복원한 뒤 CHR·이름표·CPU RAM·카트리지 RAM을 저장 파일의 각 오프셋과 비교한다. 복원 전후 처음 64개 명령 경계의 주소·읽기/쓰기·데이터도 대조한다. RAM 비교만으로는 발견되지 않았던 CPU 재개 오류가 두 번째 명령 경계에서 검출됐다.

T65의 2단 리셋 동기화기는 일시정지 중 CPU enable이 없어 복원 리셋을 첫 실행 클록까지 유지했다. 복원 핸드셰이크 동안 동기화기를 해제하도록 수정한 뒤 같은 시험을 처음부터 실행했다. 전체 상태 2,658워드, 배터리 8,192B, 재개 후 64개 명령 경계가 일치했다. 시험 종료 때 PRG 읽기 760,570회, CHR 쓰기 64회, 이름표 쓰기 4,096회를 관측했다. 이 수치는 RTL 시험의 버스 관측 횟수다. 실기에서 메뉴로 저장한 뒤 불러와 같은 부하 장면으로 돌아오는 시험은 남아 있다.
