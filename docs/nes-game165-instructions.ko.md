# NES165 — SMB3 새 영상 전송 경로 실기 시험

이번에는 전체 화면을 잘라 보내던164 대신, NES 영상 정보를 SNES 타일·스프라이트로 변환해 보낸다. **실제 게임에서 화면 속도·그림·소리를 확인하는 첫 시험판**이다. 아직60fps나 모든 장면의 호환성을 보장하지 않는다.

1. ZIP의 `01-GAME165-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. `firmware.stm`과 `fpga_n165.bi3`를 함께 적용한다. 기존 세이브 파일은 건드리지 않는다.
2. `NES GAME 165.nh1`를 실행한다.0바이트 실행 표식이 정상이며 확장자를 바꾸지 않는다. SMB3(J)는 `sd2snes/nes/game165.nes`다.
3. 제목 →1PLAYER →월드맵 →첫 레벨로 진행한다. 첫 레벨에서 이동·점프·대시를 해보고 가능하면 소리와 함께20~30초 촬영한다. **164보다 부드러워졌는지, 배경·마리오·스크롤이 깨지는지, 소리가 정상인지**가 우선 확인 항목이다. 여유가 있으면 아래 방향을2~3초 유지한다.
4. 실행 구간은100Hz tick6000, 명목상60초 후 메뉴로 복귀한다. 첫 화면 준비와 전송 대기도 포함하므로 실제로 보이는 플레이 시간은 더 짧을 수 있다. 오류가 발견되면 일찍 종료할 수 있다. 이는 무제한 플레이판이 아니다.
5. `sd2snes/nes-progress-165.txt`, `sd2snes/nes-game-last-165.txt`와 영상·메뉴 복귀 여부를 전달한다. 마지막 TXT가 없어도 진행 TXT를 전달한다. 실행 표식 선택부터 첫 화면까지의 시간과 첫 화면부터 복귀까지의 시간을 따로 재면 도움이 된다.

ROM 적재 방식은 바꾸지 않았다. 이전 약3분50초는 참고치이며 이번 실측은 아직 없다. **전체7분 이상 무반응이면** 대기를 끝내고 남은 로그와 화면 상태를 전달한다. RUN 중 SD 쓰기와 물리 리셋 로그 기능은 아직 없으므로 리셋을 눌러 로그 생성을 시도할 필요는 없다.

정상 사용으로 돌아갈 때는 `02-RESTORE164-SD-ROOT` 안의 내용을 복사한다. 이전164 파일을 그대로 담았다. 044/GBC 복원 시험은 반복하지 않는다. 이번 시험은 실기 데이터 수집용이며 카트리지 별도 SRAM·세이브 영역을 영상 버퍼로 사용하지 않는다.

`native_frames`는 SNES 표시 완료 응답까지 받은 수다. `native_result=1`은 시간 만료이며, 이것만으로 화면 성공을 뜻하지 않는다. 화면은 보였지만 마지막 응답 시점에 시간이 만료되면 그 프레임은 집계되지 않을 수 있다. CRC/수신/표시 오류와 메뉴 복귀는 로그로 함께 판단한다. 카메라와 CRT 주사율 차이로 생기는 대각선 띠는 기존처럼 판정에서 제외한다.
