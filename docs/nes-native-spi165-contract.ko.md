# NES165 SPI 장면 수신 경로

[논리 호스트 연결](nes-native-host165-contract.ko.md)에 실제 SPI 명령 접속부와 유한 C 수신기를 추가했다. 생성된 부모 RTL은 기존 SPI 핀에 연결되어 컴파일된다. **MCU 게임 실행 루프와 SNES 표시 명령에는 아직 연결하지 않았다.** ARM 수신기 단독 오브젝트 컴파일을 실제 펌웨어 실행으로 해석하지 않는다. 설치 후보는164이며 새165 SD 패키지는 없다.

## 구현과 소유권

- FPGA는 256바이트짜리 버퍼 하나에 레코드를 모은다. 전체 장면이나 픽셀 복사 버퍼를 추가하지 않는다. 이전 ROM 로더·관측·화면 상태 명령을 수정하지 않고 비어 있는 `D0`~`D3`을 사용한다.
- `nes_native_spi165.py`가 기존 host 결선의 논리 포트를 내부 wire로 바꾸고 host84MHz 영역에 접속부를 넣는다. 기존 boot MISO와 native MISO는 배타 선택한다. 바깥쪽 observer/status MISO 선택은 기존 그대로다. 부모는 **컴파일만** 했으며 전체 보드 elaboration/배치/전기적 타이밍을 통과한 것은 아니다.
- SS/SCK/MOSI는 두 단계로 샘플링한다. SPI mode0, 기존 MCU 속도2.625MHz를 사용한다. 두 클록 위상의 디지털 검증이며 모든 위상·메타안정성·배선 지연 보장은 아니다.
- 기존 `nes_game149_spi.inc`에서 함수 이름, 길이 인자/범위, 반복 상한만 바꿔 최대259바이트 bulk 엔진을 생성한다. 원본 파일은 보존한다. CF86 감시,512회 상태 대기 상한, GPIO/AF 소유권, RXNE→TXE/!BSY 완료, 오류시 CS해제/SPI정지, 자동 재시도 금지를 유지한다. 기존 사운드·입력·STOP 코드를 바꾸지 않는다.

## 외부 포맷

각 레코드는 big-endian `tag16(kind3/index13), generation16, payload`다. kind0~7의 payload 길이는 각각 `2,1,7,3,7,1,2,8`바이트다. 레코드를 블록 사이에서 분할하지 않는다. CHR는 현재 한 바이트당 레코드 하나이며, **16바이트 타일 통째 묶기나 장면 간 차분 전송은 아직 아니다.**

버퍼가244바이트를 넘거나 END/ABORT/COMMIT을 넣으면 봉인한다. 최대12바이트 레코드 하나가244바이트 위치에서 시작해도256바이트 안에 들어간다. READ 도중 버퍼는 불변이고 POP 후에만 재사용한다.

| 명령 | 길이 | 의미 |
|---|---:|---|
| D0 STATUS | 8 | 봉인 여부, ACK 수락 가능 여부, sticky 오류, token, 길이 조회 |
| D1 READ | 길이+3 | 첫 dummy 바이트 뒤 payload, CRC16 상·하위 바이트 |
| D2 POP | 8 | 전체 READ를 마친 현재 token의 버퍼 해제 |
| D3 PREPARED | 8 | generation16과 accept0/1을 기존 역방향 mailbox로 전달 |

D0/D2/D3 요청은 기존 형식 `cmd, offset24, arg, ~arg, CRC8, A5`다. offset은 D0=0, D2=token, D3=generation이다. READ 요청의 명령 뒤 바이트는0이다. CRC8은 초기0/poly07, 블록 CRC16은 초기FFFF/poly1021이다.

상태 응답 byte1~7은 `D6, flags, token_hi, token_lo, length_hi, length_lo, CRC8(byte1..6)`이다. flags bit0=봉인, bit1=ACK 슬롯 여유, bit7=sticky 오류다. D2/D3 응답은 **명령 반영 전 상태**이므로 C 코드는 뒤따르는 D0까지 확인한다. POP은 token+1을 확인한다. PREPARED 뒤 ACK가 이미 소비됐을 수 있으므로 ACK 슬롯이 반드시 busy여야 한다고 가정하지 않는다.

요청 CRC/길이/토큰이 잘못되거나 READ가 중단되면 버퍼를 해제하지 않고 오류를 남긴다. 오류 후에는 session을 중단하고 공통 reset으로 복구한다. 같은 명령을 자동 재시도하지 않는다. 독립 endpoint reset은 지원하지 않으며, FPGA reset/STOP과 C 수신 상태 초기화를 함께 연결해야 한다.

## C 수신기와 표시 승인

`nes_native165`는 호출자가 제공하는18,064바이트 저장 공간을 사용한다. 최대32×33 BG 위치,224행,128OBJ,128예외,2팔레트,512물리타일을 수용한다. 필요 타일은8192×2비트로 확인한다. heap이나 전체 픽셀 프레임은 없다. 실제 펌웨어의 기존 전역/스택과 합산한 SRAM 링크 검사는 아직 남아 있다.

호출 순서는 reset → poll 반복 → COMPLETE에서 prepare → poll로 COMMITTED 확인 → SNES 소비 완료 후 consumed다. PREPARED와 COMMIT은 **SNES 업로드/표시 완료 ACK가 아니다.** prepare(false) 또는 오류는 현재 C API에서 FAILED로 끝내며, 재개하려면 세션 중단/공통 reset이 필요하다. 정상 수신 중 ABORT는 임시 장면을 폐기하고 IDLE로 돌아간다.

길이·CRC·token·generation·종류/인덱스 순서·상한·필요 CHR·END 개수를 검사한다. COMMIT 레코드를 받아도 마지막 POP 확인이 실패하면 FAILED로 바뀌며 호출자는 표시하면 안 된다. I/O callback은 기존 bulk 엔진과 실제 게임 실행 루프에 다음 단계에서 연결한다.

새 SPI 부모 결선만 exporter 총4,194,304NES클록, fill 총2,097,152/단계131,072클록의 유한 정책을 사용한다. 대략195/98/6ms이며 기존 공통 모듈 기본값은 보존한다. 직렬 전송을 고려한 **실험 상한이지 WCET나512타일 전부의 처리 보장**이 아니다. 실제 exporter→SPI→MCU 루프와 사운드/입력 스케줄을 함께 실행해 검증해야 한다.

## 검증과 성능의 범위

선택 자료는 `spi04` RTL/부모 컴파일과 `c05` C/ARM 검사다. 기존 host02 실제 SMB3 봉인 frame12의1717레코드를 재사용했다. 전체 게임 부팅은 반복하지 않았다.

- 실제 SPI RTL을 두 시작 위상0/3.5ns에서 구동했다. 각47블록을 읽고, PREPARED 뒤 COMMIT을 받았다. 다른 명령의 비선택, 잘못된 POP, 요청 CRC 오류, 짧은 READ의 해제 금지도 통과했다.
- 캡처한 모든 SPI 요청/응답을 실제 C `poll/prepare`로 재생했다. 호출191회 모두 요청 바이트가 일치하고, 복원된1714데이터 레코드/15타일240CHR바이트가 원본과 완전히 일치했다. 새 픽셀 렌더링 시험은 하지 않았고 기존 픽셀 근거는 재사용한다.
- payload CRC 오류, I/O 실패, COMMIT 후 POP 확인 유실, PREPARED I/O 실패, 잘린 레코드, 잘못된 token을 거부했다. bulk 레지스터 모델1355사례에서 정상1/8/259바이트, 실행된 모든 CF86 감시 위치의 오류,259바이트 각 위치 OVR, 상태 정체/범위 검사를 통과했다.
- Cortex-M4/Thumb/Os 수신기 오브젝트2176바이트, 직접 poll 스택560바이트다. 호출 하위/인터럽트를 포함한 최대 스택이나 전체 펌웨어 크기가 아니다. bulk는 레지스터 모델 검증이며 실제 STM32 주변장치 시험은 아니다.

이 표본은 패킹 레코드11,196바이트, 제어·CRC 포함 전체12,489바이트다. 내부96비트 단순 나열20,604바이트보다 작지만, 기존 위치정보2,226바이트나 SNES 업로드5,493바이트와 서로 다른 구간이다.191회 왕복의 8us CS 간격을 포함한 시험 전송은 약39.59ms다. MCU 연산/인터럽트·장면 생성·SNES 업로드를 제외하므로 **실기 FPS나60fps를 달성했다는 근거가 아니다.** 현재 속도로 매 장면 전체 전송을 하면 직렬 구간만으로도60fps에 부족하다.

초기01 출력 폴더 중복 생성,02 wire 선언 순서,03 MinGW 출력 형식 오류를 보존했다.04 RTL/C는 통과했으나 bulk 시험이 기존8바이트용 전체 poll600회 상한을259바이트에도 적용해 실패했다. wait별512회 구현 상한은 바꾸지 않고,05에서 시험의 전체 누적 상한만 수정하고 C 오류 검사를 보강했다. 통과한 RTL은 변경/재실행하지 않았다.05 최초 sandbox MinGW DLL 시작 오류 뒤 허용된 host 실행에서 통과했다. 라이선스 문제가 아니다.

재현은 기존 FLOAT wrapper로 `tools/test_nes_native_spi165.py --evidence <164 evidence> --records <host02/frame12-mode0.tsv> --out <새 ASCII 경로> --questa-bin <Questa bin> --gcc <host gcc>`를 실행한다. 입력 stream 해시를 기존 공개 검증과 대조한다. ROM·미디어·바이너리·라이선스·원시 실행 자료는 공개 Git에 넣지 않는다.

## 다음 작업

1. C 수신기와 bulk callback을 실제 MCU 실행 루프에 연결하고, 기존 SNES 명령 참조를 유한 저장/증분 갱신 C 코드와 SNES vblank 소비자로 이식한다. 수신/표시 소유권과 오류/STOP 정리를 한 흐름으로 연결한다.
2. 기존38M9K 픽셀 프레임버퍼를 교체한다. 현재56/56M9K에 새 구조를 단순 추가해서 배치하지 않는다. 전체 자원·SRAM 링크·클록/외부SPI/CDC 타이밍과 위 정책 예산을 검사한다.
3. 최소 변경 검사 뒤 실제 SMB3 첫 레벨로 간다. 전송량과 실제 프레임 간격을 계측해 차분/타일 묶기 또는 SPI 속도 변경을 결정한다. 높은 SPI 속도를 타이밍 근거 없이 적용하지 않는다. 같은 부팅·A/B·044 복원을 반복하지 않는다.

164 사운드·입력·STOP/메뉴 복귀를 보존한다. 화면·사운드가 사용 가능해진 뒤60초 제한, 오류/본체 리셋 로그, DOWN 입력 유지 문제로 진행한다.
