# NES138 — 실제 NES 영상 표시 시험

이번에는 실제 NES CPU·PPU가 만든 고정 진단 영상을 SNES에 표시합니다. 게임 실행 시험은 아니며 패드·소리는 아직 연결하지 않았습니다. 이전136의 CPU RUN·메뉴 복귀·복원 성공을 바탕으로 진행합니다.

## 복사와 실행

1. 전원을 끄고 SD의 현재 `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`을 PC에 별도 보관합니다.
2. **`01-SCREEN138-SD-ROOT` 안의 내용**을 SD 최상위에 복사합니다. 폴더 자체를 넣지 않습니다. 펌웨어·`fpga_n138.bi3`·`nes/screen138.nes`·선택 파일을 함께 적용합니다.
3. `02-RESTORE044-SD-ROOT`는 시험 후 복원용이므로 아직 복사하지 않습니다.
4. 메뉴에서 **`NES SCREEN 138.nh1`**을 한 번 실행합니다. 선택 파일은 **0바이트가 정상**이고 확장자를 바꾸지 않습니다. 이전136/094 선택 파일을 사용하지 않습니다.

## 얼마나 기다리나요?

처음에는 로딩 화면이나 검은 화면으로 적재·전체 대조를 진행합니다. 이전136은 이 과정을 포함해 약8분12초가 걸렸습니다. 이번138의 실기 시간은 아직 미측정입니다.

대조가 끝나면 진단 패턴이 **약10초간** 표시되고 메뉴로 돌아오는 것이 목표입니다. 표시 구간은10초 대기와 SPI 관측 시간을 합하므로 정확히10초는 아닙니다. 사진 한 장 또는 짧은 영상이 화면 확인에 도움이 됩니다. 패턴이 보여도 패드 조작·소리는 기대하지 마세요.

**실행 선택부터 최대10분**을 관찰 기준으로 삼습니다. 이는 실행시간 보장이 아닙니다. 메뉴로 돌아오면 전원을 끄고 로그를 회수합니다. 10분이 지나도 복귀하지 않으면 전원을 끄고 로그를 회수한 뒤044를 복원합니다. 리셋 버튼으로 복귀를 시도하거나 같은 시험을 연속 반복하지 않습니다.

## 전달할 결과

- `sd2snes/nes-progress-138.txt`
- `sd2snes/nes-screen-last-138.txt`
- 진단 화면이 보였는지, 깨짐·정지 여부, 메뉴 복귀 여부
- 정상044 복원 후 메뉴·기존 GBC 동작 여부

`DISPLAY_NEXT`는 화면 실행 직전 기록이고 `DISPLAY_STOPPED`는 RESET 재유지·STOP 및 관측 완료입니다. `MENU_PREPARED`는 메뉴 준비 완료이며 실제 화면 복귀는 별도 확인합니다. `run_passed=1`은 CPU 읽기 활동과 STOP 검사 통과를 뜻합니다. **화면이 정상으로 보였다는 자동 판정은 아닙니다.** 화면을 받는 SNES 프로그램의 오류는 현재 MCU TXT에 직접 수집되지 않습니다.

표시/RUN 중에는 SD 기록을 하지 않습니다. 공통 고장 뒤에도 로그 쓰기를 강행하지 않으므로 마지막 단계만 남거나 최종 TXT가 없을 수 있습니다. 파일이 없거나0바이트여도 그 사실을 알려주세요.

## 복원과 시험 범위

전원을 끈 뒤 **`02-RESTORE044-SD-ROOT` 안의 내용**을 SD 최상위에 덮어쓰고 메뉴·GBC를 확인합니다. 시험 파일은 혼동되지 않도록 별도 보관할 수 있습니다. SD 포맷이나 세이브 삭제는 필요 없습니다.

이 패키지는 사용자 개인 보드의 정상 전원에서 수행하는 제한 시험입니다. 동일 클록 타이밍과 조건부 I/O·CDC 검사를 마쳤으나 외부 보드 지연 실측·MTBF·모든 고장 안전성을 보증하지 않습니다. E1/E2·8µs 미보장·양클록 정지 시 CE9µs 반례와 source-lock 보류4건을 유지합니다. SMB3(J)의 전체 mapper4·384KiB·입력·오디오 구현은 다음 단계입니다. 바이너리와 진단 ROM은 Git에 올리지 않습니다.
