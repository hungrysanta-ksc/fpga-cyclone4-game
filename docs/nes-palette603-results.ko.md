# 603. 표시 전에 전송하는 값과 소비 기한

952·954에서 ARM이 받은 NES 색 번호를 65816에 보내고 고정 색상표로 복원하면 E1을 **344 B에서 54 B로** 줄일 수 있다. 같은 512 B가 복원되지만, 독립 CRC 검사까지 실행하면 기존 팔레트 ACK보다 **8.585–8.708 ms 늦다.** MMC577을 실기 기준으로 유지한다. 다음 실험은 SNES 작업을 늘리지 않고 입력 본문 자체를 줄이는 D1 행 번호 전송이다. [블록·명령·클록·검증 결과](../analysis/palette603-verification.json) · [602의 고정 일정](nes-overlap602-results.ko.md)

## 어느 값이 어디서 필요한가

| 기존 MMC577의 실제 SPI wire | 952 | 954 | 값의 출처와 소유권 |
|---|---:|---:|---|
| D1 입력 | 3,462 B | 3,450 B | FPGA 캡처의 map·row·OBJ·raster·palette·raw를 ARM이 복원한다. |
| E1 map / BG·OBJ tile 명령 | 2,110 / 161 B | 2,148 / 92 B | map은 ARM이 배치한 SNES 뱅크 주소와 엔트리다. tile 명령은 FPGA가 별도로 만든 데이터의 slot·token·길이를 지정한다. |
| E1 palette / OAM / HDMA·raw | 344 / 175 / 628 B | 344 / 175 / 586 B | palette는 현재 입력의 색 번호와 고정 LUT에서 전부 재현된다. OAM은 객체 배치, HDMA·raw는 scroll·평면 배치·모드 테이블을 포함한다. |
| E1 BEGIN·SEAL / E9 | 218 / 179 B | 218 / 196 B | E9는 타일 값 대신 배경·객체 slot과 tag, 행·plane 정보를 공급한다. 검증된 plan과 반환될 tile 데이터는 다른 소비자에게 필요하다. |

두 위상의 실제 E1 byte 수를 패킷 본문과 대조하고 E9 세 거래씩을 FPGA plan 뱅크의 seal·첫 decode·release와 맞췄다. E9는 952에서 4/4/13개, 954에서 4/15/5개 plan을 전달했다. D1에서 비슷한 숫자를 찾은 것만으로 map·OAM·tile·E9의 절감을 계산하지 않았다.

두 세대의 원래 D1 핀에서 팔레트 레코드를 직접 해석했다. 600의 공유 generation 형식에서도 같은 색 번호가 12번째 블록까지 들어온다. 원래 공동 일정에서 이전 EA와 다음 source 시작은 같고, 그 후 **19.637–19.852 ms**에야 마지막 색 번호를 담은 D1이 끝난다. 같은 값이 이전 화면에 있었다는 이유로 현재 세대의 색을 확정할 수는 없다. 이번 계산에서 이전 EA 앞으로 이동한 바이트는 0이다.

## 현재 입력만 쓰는 팔레트 패킷

ARM이 보내는 후보 본문은 1 B 형식(32/64색·raw 사용 여부), **기존 ARM 출력 512 B**에 대한 CRC16 2 B, 현재 색 번호 32 B다. 기존 E1의 identity 등 16 B와 SPI 외피 3 B도 포함했다. 65816은 동일한 64색 LUT와 배치표로 비활성 WRAM의 512 B 전체를 새로 쓴 뒤 실제 WRAM에서 CRC를 계산한다. 채우지 않는 자리와 raw용 64색 구간의 초기화까지 검사한다. 뱅크 이력이나 이전 ACK의 색이 필요하지 않다. 검증된 새 section을 게시하는 책임과 최종 SEAL/ACK는 통합 시 기존 소유자에게 남는다.

905–957의 53개 실제 입력에 대해 참조 복원의 512 B가 선택된 ARM CGRAM 파일과 모두 일치했다. 952·954는 두 위상의 기존 E1 네 패킷을 확장한 결과와도 일치했다. Mesen에서 WRAM에 독립 65816 커널을 올리고, 이전 내용은 0xa7로 채웠다. 기존 첫 palette SPI 발행 때 54 B를 보내고 wire가 끝나자마자 커널이 시작할 수 있게 했다. 큐 대기와 드라이버는 무료로 둔 조건이다. 완료 콜백의 첫 실행을 기록했다.

| 세대 · 위상 | 602 가정 + 새 wire의 표시 전 버스 완료 | 같은 시작의 순수 wire 완료 | 복원·CRC 완료가 기존 palette ACK보다 늦은 시간 | 기존 SEAL 수락 전 남은 시간 |
|---|---:|---:|---:|---:|
| 952 · 1 | 20.927 ms | 16.162 ms | 8.708 ms | 3.659 ms |
| 952 · 2 | 21.078 ms | 16.313 ms | 8.637 ms | 3.728 ms |
| 954 · 1 | 21.370 ms | 16.577 ms | 8.609 ms | 2.596 ms |
| 954 · 2 | 21.339 ms | 16.545 ms | 8.585 ms | 2.340 ms |

버스 두 열의 기준점은 이전 표시다. 첫 열은 602의 짧은 D2·두 슬롯 낙관 일정에서 290 B의 wire 시간 **0.884 ms**만 뺐다. 둘째 열은 입력 CPU·드라이버까지 0으로 둔 한계다. 최소 조회를 유지한 정상상태 wire도 952에서 5,455→5,165 B, 954에서 5,528→5,238 B로 내려간다. 3개 E1 감소에 따른 추가 credit 조회 절감은 계상하지 않았다.

**실행한 65816 커널은 네 경우 모두 258,030 master clock, 12.014 ms**가 걸렸다. 재구성은 2.381–2.383 ms이고 나머지 약 9.63 ms가 검증과 완료 처리다. 커널이 기존 SEAL 시각보다 먼저 끝나기는 하지만 후속 OAM·HDMA·tile도 같은 CPU가 소비한다. 기존 palette ACK를 그대로 유지할 수 없고, 첫 열조차 60 Hz보다 **4.260–4.703 ms** 늦다. 새 종단 ACK나 실기 FPS 이득은 확인되지 않았다.

- 실제 네 경우 외에도 두 palette epoch·raw 비활성 복원을 확인했다. 잘못된 길이·예약 비트·색 ID·두 epoch 배경색 불일치, CRC 직전 WRAM 손상, 검증 도중 STOP은 성공 상태를 게시하지 않았다. 커널은 진입과 CRC의 매 64 B 및 성공 직전에 STOP을 확인한다. 초기화·색 배치 중 들어온 STOP은 첫 CRC 구간에서 처리되므로 해당 구간의 즉시 중단은 검증 범위 밖이다. 커널 코드는 235 B, 색상표 128 B, 목적지표 128 B, CRC표 512 B다. 기존 표를 공유할 경우의 순 비용은 전체 링크 전까지 확정하지 않았다.
- 새 소비자는 WRAM 재구성·검사까지 실행했다. 입력 패킷 수락, CRC 생성의 ARM 비용, 뒤따르는 큐·DMA·VBlank·최종 ACK와 메뉴 복귀는 새 종단에서 실행하지 않았다. 후보 본문 길이는 실제 입력에서 생성해 계산했다. 새 포맷의 SPI 핀 시험이나 보드 합성을 한 단계는 아니다.

## 다음 후보를 고른 근거

두 장면 모두 D1의 224개 row 값은 **7부터 185개, 0 한 개, 0 한 개, 193부터 37개**의 연속 구간으로 복원된다. 마지막 값은 229다. 기존 공유 형식의 8개씩 묶은 레코드 28개가 280 B다. 새 버전에서 4 B 레코드에 시작값과 개수를 넣으면 네 레코드 **16 B**가 된다. 이전 화면이나 LUT를 사용하지 않는다.

53개 입력에 같은 규칙을 적용해 원래 224 B를 대조하고 실제 600의 블록 봉인 임계값, END 분리와 CRC·credit 바이트로 다시 묶었다. 952·954는 각각 **15→14블록**, 602의 짧은 D2를 기준으로 **282 B 절감**이다. 레코드 264 B와 사라지는 한 블록의 공통 헤더·D1 외피·D2·D0 18 B를 포함한다. 577의 8 B D2를 600의 공유 형식에 그대로 쓰는 경우라면 같은 한 블록에서 4 B를 더 줄인다. 이 수치는 독립적인 대안이며 팔레트 후보와 합산하지 않았다. 53개 중 51개는 282 B, 나머지 두 개는 300 B 절감이다. 실제 D0 busy 횟수와 생산 지연은 아직 미확정이다.

다음은 **row 구간의 FPGA 생성과 ARM의 독립 복원**을 실제로 연결하는 일이다. 진행 중인 구간 때문에 첫 블록 봉인이나 첫 BG 공급이 늦어지는지, 잘못된 시작값·개수와 부분 전송·STOP이 다음 세대로 넘어가지 않는지부터 확인한다. 기존 행 순서·개수·map 범위 검사를 유지하고, 이전 EA·최종 ACK를 고정한 두 위상에서 175/261 B와 시간 부족을 다시 비교한다. 602의 미배포 4 B D2를 전제로 보드에 올리지 않는다.
