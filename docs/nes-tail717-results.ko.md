# 717 패딩 완료 대기·951 DMA 기회·탐색 비용 분리

## 목표

716B의 약1ms planner 절감을 보존하면서951 공개선 회귀와954 마지막 tile의 준비·발행·credit·수락·소비를 분리한다. 원본707D·694/704 ARM·69465816을 선택본으로 유지하고, 두 위상에서911 마감·951 공개≤246선·952 표시3회·957 최종대기0회·7블록 수신과 독립 검사·STOP·최종 ACK·메뉴를 보호한다. 채택하려면952–957 합계18 VBlank 미만·밀집 평균·957 마지막 ACK도 함께 개선해야 한다. [검증](../analysis/tail717-verification.json) · [원시 근거](../analysis/tail717-archive.json)

## 작업내용

716B에 최소 변경 하나를 적용했다. 새 tile descriptor가 준비됐을 때, 직전에 발행한 **ordinary 패딩 전체가 끝나기를 기다리는 drain만 제거**했다. map 뒤 drain과 bounded input, 이전 bulk의 실제 receipt 확인, 새 패킷의 정상 queue admission·CRC·identity·STOP 검사, 최종 표시 ACK는 유지했다. `nes_plan_service200.c`만 바뀌며 새 ABI·RAM·RTL·65816 변경은 없다.

정상60초·장시간 ARM을 각각 전체 링크했다. 후보53화면×두 위상106화면과 관측기 대조군106화면, 합계212화면의 실제 링크 M4/65816을 실행했다. 시작7288416/7467100·동일 map/OBJ·공유 SPI·IRQ·2bulk·ROM 허용 달력을 유지한다. CPI2/84MHz 및 측정 기반 driver/ROM 모델의 비교이며 실기 FPS·전체 게임 CPU/PSRAM RTL 동시 실행은 아니다.

### 관측기 실패와 대조

첫 재생은cold905에서 `UC_ERR_FETCH_UNMAPPED`로 중단됐다. 변경한 warm 패딩 정책이 적용되기 전이며 같은 바이너리의 slot18조건은 통과했다. 원시 명령·PC/SP/XPSR·메모리 callback 추적을 보존했다. broad video write 관측에서 조건부 저장 뒤 비정상 분기/stack 복귀가 관측됐으나, Unicorn 내부 원인을 확정했다고 주장하지 않는다.

673 관측기는 원래부터 OAM·CGRAM·HDMA·patch의 마지막 쓰기만 기록하고 나머지 메타데이터 쓰기는 무시했다. native memory hook도 **이 선언된 payload 범위에만 설치**하도록 좁혔다. 검사 대상 payload·값·불변성 assertion은 같고 타깃 코드·레지스터·클록·IRQ 정책은 바꾸지 않았다. 이 관측기로 기존716B를 다시106화면 실행해 `window.csv`·`seal528.csv`·`tile532.csv`·`packets.jsonl`의 전체 SHA와 ARM 명령 수·SPI 바이트·frame 결과·stack이 기존과 정확히 같음을 확인했다. 이후 후보106화면도 통과했다.

넓은 hook 실패와 시도한 dispatcher·IRQ 진단은 실패 근거로 보관하며 성능 데이터로 쓰지 않는다. 관측기 범위를 줄여 임의의 잘못된 타깃 쓰기를 허용한 것이 아니라, 기존 callback이 실제 검사하던 payload 범위를 보존한 것이다.

## 성과

**기능·안전 검사는 통과했으나 시간 보호·Flash 조건 미달로 미채택이다.** 716B 계산 절감과717의 불필요한 패딩 drain 제거는 재현 가능한 후보로 보존한다.

| 지표 | 위상1 | 위상2 |
|---|---:|---:|
| 952–957 합계, 원본→717 | 18→18 VBlank | 18→18 VBlank |
| 밀집951–955 평균, 원본 대비 | −0.032518ms | −0.018866ms |
| 밀집 평균,716B 대비 | −0.001713ms | −0.128303ms |
| 957 마지막 ACK, 원본 대비 | −65.878572ms | −66.372675ms |
| 957 마지막 ACK,716B 대비 | 0ms | −0.484698ms |
| 951 공개선 | 248 | 248 |

911 마감·952 표시3회·957 최종대기0회·7블록 수신은 유지했다. 마지막 ACK의 원본 대비 약66ms 이득은 주로716B의 네 비밀집 구간 단축에서 이어진 것이며,717만으로66ms를 줄였다고 계산하지 않는다. 밀집 구간의 VBlank 개수는 줄지 않았다.

### 954: CPU 대기 제거의 일부가 큐 대기로 이동

모든 시각은954의 직전 표시 기준 ms다. 마지막 tile은 OBJ offset1888의384B로 동일하다.

| 경계 | 716B 위상1 /2 | 717 위상1 /2 |
|---|---:|---:|
| ARM tile 준비 | 39.004238 /38.999161 | 37.400928 /37.369031 |
| SPI 발행 시작 | 39.018143 /39.013066 | 37.414833 /37.382936 |
| 65816 수락 | 39.200696 /39.207121 | 38.641407 /38.663011 |
| tile ACK | 40.153424 /40.159570 | 39.595625 /39.616856 |
| SEAL 수락 | 43.633009 /43.636361 | 43.074465 /43.021479 |
| 전송 후 큐 대기 | 0.062671 /0.074171 | 1.106658 /1.160157 |
| 수락 후 소비 | 0.952728 /0.952449 | 0.954218 /0.953846 |

준비는1.603/1.630ms 빨라졌지만, 이미 수락된 패딩이 앞서 있으므로 약1.04/1.09ms가 큐 대기로 이동했다. 소비 자체는약0.95ms로 그대로다. tile ACK는0.558/0.543ms, SEAL은0.559/0.615ms 빨라졌다. 실제 map 선행1920B·tile 선행16B를 유지했지만 추가 VBlank 감소에는 못 미쳤다. 준비 시각만을 전체 절감으로 보고하지 않는다.

### 951: 빨라진 ordinary가 빈 큐 VBlank를 차지함

원본951의 선행 map/tile DMA는위상1 **448/16B**, 위상2 **1792/16B**였다. 716B에서는두위상 **256/0B**로 감소했다. 마지막 map 수락과 SEAL은 더 빨랐지만, 최종 구간으로 넘어간 DMA 때문에 공개가248/247선으로 밀렸다.717에서도공개248/248선을회복하지못했다.

위상1 원본의 OAM 수락32.672ms 앞에서 tile16B·map192B가32.140/32.367ms에 DMA됐다. 716B는 OAM31.581ms·HDMA32.003ms·패딩32.317ms가 먼저 수락돼 이 빈 큐 기회를 잃었다. 위상2도 원본 OAM33.329ms 전에 map1344B 선행이 있었지만,716B OAM31.885ms·HDMA32.299ms가 먼저 큐를 점유했다. 새 패킷 우선 조건 때문에 뒤로 밀린 DMA를 CPU 계산 감소만으로 되찾을 수 없었다.

이는 느린 계산을 되돌려야 한다는 뜻이 아니다. **실제 map 수락/소비 완료와 DMA 시작을 구분해, 후속 ordinary 발행과 다음 입력 수신을 조율할 경계가 필요하다.** 679에서 이미 확인한 것처럼 E0 진행 비트 조회만 늘린다고 빈 큐가 만들어지지는 않는다. 기존 대형 map drain·reason4 입력 경계를 재사용할 수 있는지 먼저 검증하며 새 mailbox나 고정 지연을 추가하지 않는다.

### 탐색 삭제 예산과 전체 비용

716B의 실제 링크 ARM으로53화면의 tag 이진 탐색과hash-chain 탐색을 별도 계측했다. 즉시 plan callback·128KiB 단위시험 공간을 사용했으며 공유SPI/IRQ 시간을 포함한 통합 성능으로 합산하지 않는다. 관측 대상10화면의 plan 바이트/순서는716B 통합 실행과 같다.

| 마지막 BG까지의 탐색 | 954 | 955 |
|---|---:|---:|
| tag 탐색 명령 | 23128 | 14481 |
| hash 탐색 명령 | 25549 | 16193 |
| 둘을 전부 삭제한다는 낙관적 상한, CPI2/84MHz | 1.158976ms | 0.730333ms |
| 716B에서 놓친 직전 ROM 구간 끝, 위상1 /2 | 2.350/2.354ms | 1.858/1.586ms |

첫 사용·정확한 key 비교·소유권 확인을 실제로 전부 삭제할 수는 없다. 따라서 **탐색 최적화만으로 해당 ROM 공급 마감을 회복한다는 계획은 예산상 부족**하다. 951은새 BG 생산이없어마지막BG prefix는해당없음이며전체탐색비용0이라는뜻이아니다.

717 전체 Flash는장시간 **212956B/36B 여유**, 정상 **213000B/8B 초과**다.716B 대비8B 줄었으나 제품 한도212992B는 통과하지 못했다. 정적RAM·구조체증가0B, 관측stack원본대비−64/+36B이며두위상최저주소는`0x2000f7f0`다. 관측값은stack최악상한증명이아니다. 전체SPI는원본대비−1092/−1192B이며E1/E9 작업량은같다.

보드·SDC·65816을 바꾸지 않아 새 Quartus 실행은 없다.707D 전체 Lite FIT15,322LE·962LAB·56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계하며 외부IO·실기 확인 범위를 확대하지 않는다.

실제 링크 검사: slot18조건, 원본/후보 paired map/fill/tile·STOP·CRC·generation·최종ACK24조건, plan grant7조건, runtime16조건, 메뉴준비/해제5조건·marker4조건을 통과했다. 기존65816에 후보 패킷을 넣은 STOP4조건·사용자 종료2조건도 통과했다. 단위 정책 시험의 last-head·empty window·bounded-input callback은 fixture이며 실제 지연 receipt·최종ACK 의무를 분리해 검사했다. 초기 fixture의10B last 필드에12B를 넣어 초기화 상태를 손상시킨 실패와 setup 전에 STOP을 걸었던 실패는 고친 뒤 로그와 함께 보존했다.

## 후속작업

1. **707D·기존694/704 ARM·기존65816을 유지한다.** 정상Flash와951 보호가실패했으므로설치본은없다.716B 계산절감·717 패딩drain 제거는미채택후보로보존한다.
2. 다음은951의실제map receipt 뒤 다음입력의bounded 수신을수행하면서E0의실제DMA진행을확인하고,후속ordinary를발행하는경계다. capture/plan/source 소유권·7블록한도·두slot·ROM경쟁을먼저검사한다. 입력이없거나이미7블록을받은경우도포함한다. 기존679/680/685의진행조회·map drain을중복구현하거나고정시간/위상대기로맞추지않는다.
3. 954는준비지연이큐의패딩소비로옮겨졌으므로,확정된ordinary의실제수락순서와bulk공급을함께검토한다. 필수검사를보존한tag/hash삭제만으로ROM마감을달성한다는가정은중단한다. 새패킷·STOP우선은유지한다.
4. 정상판8B이상순삭제·정적RAM증가≤4B·FPGA/65816증가0예산과,두위상911/951/952/957·7블록·cold/STOP/최종ACK/메뉴 및밀집18회미만·평균·957ACK동시개선을같은바이너리에서확인한다. 951회복이나Flash통과만으로60fps개선승인을대신하지않는다.
