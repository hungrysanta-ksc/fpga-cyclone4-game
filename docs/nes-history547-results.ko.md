# NES 547 · 최종 표시 ACK에 연결한 raw 행 이력

546은 957의 마지막 빔 판정에서 두 시작 위상 모두 1,463 master clocks가 부족했다. 547은 그때 보내던 여섯 개의 64B 행을 비활성 뱅크에 마지막으로 확정한 내용과 대조한다. 실기 비교 기준은 MMC540, 직접 시뮬레이션 대조군은 546이다. [546 측정](nes-header546-results.ko.md)

## 저장과 복원

65816은 SEAL의 버전·bank·범위·coverage·HDMA 검사를 마친 뒤, 두 행 형식의 세 plane에 대해 384B를 정확히 비교한다. 뱅크별 이력은 SNES WRAM `7E:6961..6AE0`와 `7E:E961..EAE0`에 둔다. 두 영역은 기존 명령 RAM `7E:4000..6607`과 겹치지 않는다. 비교 대상인 이번 입력은 bank 7F의 대응 주소에 있다. 같은 16비트 word 32개를 모두 확인한 행만 생략 후보로 남는다.

첫 이력 쓰기 전에 대상 뱅크의 기존 유효 바이트 `$125A/B`를 지운다. 이미 해석한 `$125C`에 같은 형식의 유효 이력이 있을 때만 생략 마스크를 쓴다. 최종 표시를 마치고 ACK를 만드는 경로에서만 뱅크 유효 바이트를 복구한다. 따라서 중간 STOP 뒤에는 부분적으로 쓴 이력을 사용할 수 없다. 형식이 바뀌거나 cold이면 전체 행을 복원한다. 동일한 행도 기존 행별 STOP 검사를 거치고, 실제 DMA를 생략할 때는 source 포인터를 64B 진행시킨다. 기존 그룹별 VBlank 예산과 246행 검사선을 사용한다. [65816 생성기](../tools/nes_history547.py)

SNES WRAM 비용은 768B다. 마스크는 최종 검사 이후 사용이 끝난 기존 직접 페이지 word `$78`을 재사용한다. 처음 만든 본문은 5,022B로 용량을 초과했다. 기존 DMA 비용 분기를 같은 여섯 값의 표로 바꾸고, 낮은 주소의 scratch 명령과 0 비교·헤더 분기를 줄였다. STOP 검사 호출을 공유한 본문은 4,954B, 서비스 반환 시 STOP 값을 함께 읽는 본문은 4,950B다. 546은 4,952B였고 매핑은 모두 5,120B다. 생성기는 공통 반환의 모든 호출자가 원래 STOP 값을 읽었거나, A와 상태 플래그를 사용하지 않는 정지 루프인지를 검사한다.

## 경계 시험

- 각 후보에서 1·2행 전환과 기존 3행 형식을 같은 뱅크에 번갈아 표시했다. 2행으로 돌아온 첫 화면은 여섯 행을 모두 썼다. 같은 여섯 행은 모두 생략했고, 한 행의 마지막 바이트만 바꾼 경우에는 그 행만 전송했다. 두 후보 각각 8개 RGB가 546과 같았다. [형식 전환 시험](../tools/test_nes_history547_counts.py)
- 양 뱅크에서 비교 도중과 첫 실제 raw DMA 직후에 각각 STOP을 주입했다. 오류 ACK `0xE4`, 이전 표시 RGB, 대상 뱅크의 무효 태그를 확인했다. 중단 당시 이력 384B·실제 VRAM 2,048B·무효 태그를 다음 시험의 대상 뱅크에 그대로 이식하자 여섯 행을 모두 복원하고 최종 표시 ACK를 보냈다. 이 시험은 취소된 물리 메모리 상태의 복원을 재현한다. [중간 취소·복원](../tools/test_nes_history547_recovery.py)
- 각 후보에서 64B fill 관련 STOP 8건, SEAL/표시 STOP 7건, 새 head·누락·중복 등 22건을 통과했다. 같은 집계 ARM의 메뉴 복구 경로는 모델에서 확인했다.

독립 65816 재생은 매 표시 ACK에서 실제 VRAM 행을 저장한다. 다음에 같은 뱅크를 대상으로 할 때 이전 ACK의 VRAM, 현재 실제 VRAM, 이번 WRAM 원본으로 생략 가능 비트를 독립 계산한다. 실제 마스크·행별 실행 분기·전체 raw VRAM·RGB와 표시 ACK를 대조한다. 프레임별 DMA 감소분도 생략 개수 × 64B와 일치해야 한다. [독립 재생](../tools/replay_nes_history547.py) · [비용 대조](../tools/analyze_nes_history547.py)

## 재현

생성기에 `--shared-exit`를 주면 공통 반환 버전, 옵션을 생략하면 중첩 호출 버전을 만든다. 546과 같은 hardware541/ARM02, dense519/fixture01, order520/oracle-compact01, service509-rom03 및 시작 3,000,000/3,178,684 master clocks에서 `test_nes_tile532.py --trace-credit --trace-rom`으로 53화면씩 실행한다. 각 출력에 `replay_nes_history547.py`를 적용한다. 고정 도착 대조는 546의 각 위상 기록에 `test_nes_dma542_fixed.py`를 적용한다. 물리 5–40초·40–55초 집계는 실제 시험판에서 따로 측정한다.

두 후보 모두 957은 bank 0의 마지막 ACK인 955를 재사용했다. 생략한 행 인덱스는 0·2·3·4이며 실제 DMA는 6회에서 2회로 줄었다. 각 위상의 53화면에서 174행, 총 11,136B를 절감해 VRAM DMA는 125,488 → 114,352B였다. 53개 RGB 및 map/tile은 대조군과 일치했고 4회의 독립 재생에서 표시·최종 ACK를 확인했다. 첫 BG의 상대 ROM 허용 구간, ROM 읽기 5,616회, 두 bulk 슬롯, 952/954 최종 대기 0회를 유지했다. 고정 도착 공통 반환 시험에서도 957은 246행 h=1106/620에서 표시를 수락했다. [검증 수치](../analysis/history547-verification.json)

**판정.** 957에서 VBlank 한 번을 줄이는 목표는 두 위상에서 달성했다. 전체 53화면의 마지막 ACK와 밀집 표시 간격을 함께 줄이는 승격 조건은 통과하지 못했다. 실기 기준은 MMC540이며 이번 후보의 FIT/STA나 실기 FPS 측정은 수행하지 않았다.

공통 반환에서 이력 대조에 든 시간은 warm 화면당 평균 1.933ms다. 첫 두 화면 이후 51개 표시 간격을 SEAL 수락 전후로 나누면 546 대비 위상 1은 전 0·후 +1 VBlank, 위상 2는 전 +2·후 0 VBlank였다. 따라서 비교 시간이 그대로 최종 ACK에 직렬로 더해졌다고 단정할 수 없다.

다음 검증은 **이미 수락된 반복 패킷의 값과 범위를 재사용**하는 것이다. 현재와 대상 뱅크의 이전 ACK 양쪽에서, 한 개의 동일 바이트 반복 패킷이 행 전체를 덮고 값도 같았던 행을 원시 패킷으로 대조했다. 이번 53화면에서는 생략한 **174행 전부**가 이 조건에 해당했고 957의 네 행도 포함됐다. 이 결과는 해당 캡처의 오프라인 분류다. 실제 후보에서는 section·offset·length·반복 값과 연속 범위를 수신기가 검사하고, 최종 ACK에서만 뱅크별 증명을 공개해야 한다. 부분 범위·literal·형식 전환·STOP 뒤에는 원본 DMA로 복구한다. 384B 전체 대조를 없앤 뒤 ARM 위상·밀집 간격·전체 ACK까지 재검증한다.

원시 증거는 로컬 `probes/nes-history547/archive01/evidence.zip`의 5,381개 파일을 압축 해제해 SHA256을 대조했다. ZIP SHA256은 `9c132f428751b0896b6814c61ab1383e8751192ff8ccf874816e20fc419d6f13`이다.
