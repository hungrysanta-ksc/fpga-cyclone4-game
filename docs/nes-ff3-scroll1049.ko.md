# FF3 1049 마을·여관·필드 이동 시험

ZIP 안의 `sd2snes` 폴더를 SD 루트에 덮어쓰고 전원을 껐다 켠다. 기존 FF3 한글판을 선택해 **L+R+START → STATE SLOT 1 → LOAD STATE**로 첫 마을 세이브를 불러온다. 게임의 **START → 설정 → 인카운터 회피**를 켠다. 여관에서는 복도를 위로 걸을 수 있다. 필드에서는 마을 남쪽 출구로 나가 숲과 산 사이를 걷는다. **EXIT TO MENU**로 종료하면 `nes-progress-ff31049.txt`, `nes-game-last-ff31049.txt`, `nes-frame-ff31049.bin`이 남는다.

## 실기 기준과 같은 입력의 재생 결과

1048 실기 로그의 55–60초 카운터는 표시 70장(14.0 FPS)이다. 샘플링한 57세대의 입력 수신 구간 중앙값은 8.62ms, 입력 완료부터 ARM이 표시 완료 응답을 확인할 때까지는 38.03ms였다. 후자에는 계획과 전송, 소비, VBlank 대기가 함께 들어간다. 로그에 장소가 기록되지 않아 이 FPS는 세 장소의 개별 기준으로 쓸 수 없다.

슬롯 1 저장 순번 8에서 한글판 게임 메뉴로 인카운터 회피를 켰다. 마을 길, 여관 내부, 필드에서 카메라가 이동하는 구간을 각각 6화면씩 캡처했다. 같은 PPU 입력을 1048 보드의 RTL에 공급하고, 얻어진 화면 정보를 두 최종 ARM 바이너리에 넣었다.

| 이동 구간 | 1048 계획 명령 수 | 1049 계획 명령 수 | 감소 |
|---|---:|---:|---:|
| 마을 길 | 1,232,521 | 1,043,109 | 15.4% |
| 여관 내부 | 1,276,980 | 1,071,034 | 16.1% |
| 필드 | 1,259,485 | 975,159 | 22.6% |

ARM은 BG 계산 중 아직 쓰지 않는 HDMA 테이블 공간에 같은 화면에서 확인한 일반 타일 조회 결과를 최대 256개까지 담는다. 전체 태그가 일치할 때만 슬롯을 재사용하며, BG 계산이 끝나면 실제 HDMA 테이블을 작성한다. 직전 행의 미세 스크롤 결과를 보존해 같은 행을 다시 검색하는 일을 줄였다. 원본 픽셀 행과 배경색 전용 행에서는 이력을 끊는다. 동일한 map 단어의 재쓰기와 표준 타일 명령의 반복 조립도 줄였다.

18화면에서 map·OAM·팔레트·HDMA·사용 타일 정의와 계획된 타일 전송량이 일치했다. 한 화면씩 건너뛰는 경우와 기존 전투 재생도 대조했다. 슬롯 4개, 저장 파일 입출력, 첫 표시 전 기존 슬롯 불러오기, STOP·메뉴 복귀 경로를 최종 링크에서 검사했다. Flash는 212,936/212,992B이고 FPGA와 65816은 1048 설치본과 동일하다. 표의 수치는 ARM 계획 함수에서 실행한 명령어다. 실제 FPS는 보드에서 측정한다.
