# NES168 실기 결과 — 8번째 화면 갱신의 전송 예산 초과 확인

사용자는167과 동일한 짧은 화면 뒤 메뉴 복귀 증상을 보고했다. **이번에는 최초 실패 응답이 기록돼 종료 원인을 E3로 확정했다.** 연속 플레이는 실패지만168의 원인 구분 목적은 달성했다.

## 로그와 구현의 대조

요청 원문은 `03002e00080000001400000012000000`, 응답은 `e3032e00080000001400659a`다. `sink_trace_ack_valid=1`은 하위 exchange가 F6·CRC·상태 검사를 통과한 ACK를 전달했다는 뜻이다. `mismatch=01`을 원문에서 다시 계산했으며 응답 식별값 불일치는 없다. 이 실패는 통신 무응답이나60초 만료가 아니라 **SNES가 명시적으로 반환한 표시 거절**이다.

MCU는 SEAL에5000 예산을 보낸다. SNES 로컬 비교기는 변경 구간 길이의 합에 DMA 명령마다96을 더해 비용을 계산한다. 이전 화면이 표시 중일 때 이 비용이5000을 넘으면 E3를 반환한다. 따라서 단순히 원시 전송량5000바이트를 넘었다는 뜻은 아니다.32명령 상한 초과는 별도 E2이며 이번 응답은 E3다. 실제 변경량·명령 수·전체 비용은 로그에 없어 정확한 수치나 실패 장면의 변경 패턴까지 확정할 수 없다.

DATA 패킷은 후보 WRAM에 도착했지만 E3에서는 후보의 PPU DMA를 실행하지 않고 이전 표시 상태를 유지한다. 현재 MCU는 이 부정 응답을 sink 오류3→DISPLAY 오류5→run_error4로 전달해 안전 정지·메뉴 복귀한다. 게임 자체의 ROM fault가 검출된 기록은 없다. 이 설계가 큰 변경을 지속 처리하지 못하는 것이 현재 수정 대상이다.5000 예산을 실제 하드웨어의 절대 용량이나 검증된 최대 대역폭으로 해석하지 않는다.

진행 기록0~99는 연속이고 시각도 단조 증가한다. DISPLAY_NEXT231660ms→DISPLAY_STOPPED235220ms는3560ms다. 준비·정지가 포함된 펌웨어 tick 구간으로 실제 보인 시간이나 FPS가 아니다. MENU_PREPARED는238390ms다. screen_error169는 SPC A9 초기화 결과이며 오디오 재생 성공 증거가 아니다. 구형 screen_frames0도 FPS로 사용하지 않는다.

168의 응답으로167도 반드시 E3였다고 소급 확정하지 않는다. 이전 raw ACK는 없었고, 이번168에서 같은 외관 증상의 한 원인을 직접 확인한 것이다.

## 다음 작업

다음 구현은 E3를 일으키는 합법적인 큰 화면 변경을 게임 종료 없이 완료하는 경로다. 현재 변경 구간 합계+명령당96 비용과5000 상한,32명령 제한을 기준으로 최소 재현하고 유한 분할/표시 전환 방식을 결정한다. 여러 vblank로 나눌 경우 이전 표시와 갱신 중 VRAM·CGRAM·OAM·HDMA의 일관성, 변경 후보 소유권, 마지막 완료 뒤에만 ACK/세대 갱신, STOP·시간 제한·사운드/입력 서비스를 함께 보장한다. 무조건 상한 증대·검사 제거·성공 ACK 위조·무한 재시도·영구 프레임 폐기는 금지한다. 필요하면 명시적 대체 표시 정책의 시각적 영향을 문서화한다. 해당 경계의 최소 검증 후 바로 SMB3 실기로 간다.168 재시험·추가 영상·044 복원·무변경 FPGA FIT는 불필요하다. 연속 AV→장기 플레이/오류·본체 리셋 로그→입력 유지 순서와 세이브 SRAM/GBC/164 보호를 유지한다.

이번 변경은 결과와 다음 계획의 기록이다. 새 펌웨어·FPGA·ZIP은 만들지 않았다. 같은168 재시험이나 추가 영상은 필요하지 않다. 원본 TXT는 비공개 폴더에 바이트 그대로 보존했다. [전체 필드·해시·응답 해석](../analysis/game168-hardware01-verification.json). 기존168 구현 검증과 이전 완료 기록은 수정하지 않는다.
