# NES165 공통 장면과 유한 CHR 보충

이 문서는 [플레인 분리 수집](nes-native-planes165-contract.ko.md)의 다음 구현이다. 설치 후보는 **NES-GAME-164**이며, 이번 코드는 새 SD 패키지가 아니다. [검증 요약](../analysis/native-frame165-verification.json)과 [현재 인계](../cores/nes/HANDOFF.ko.md)를 함께 읽는다.

## 연결한 부분

`nes_native_frame165.sv`는 수정된 fetch·compact와 새 `nes_native_raster_frame165.sv`를 한 NES 클록 영역에서 연결한다. 7행 dot257에 시작하고 224개 표시행을 수집한다. 물리 타일 집합의 16비트 generation 하나만 외부에 사용한다. 각 구성요소를 따로 해제하거나 raster의 내부 번호와 비교하지 않는다. raster 첫 행 이전에 ROM 오류가 발생해도 PPU CE를 기다리지 않고 실패한 장면을 회수한다.

`owned`는 처리가 끝나 조회할 수 있는 상태라는 뜻이다. **`geometry_valid`는 CHR 공급 완료나 화면 표시 준비 완료가 아니다.** fetch의 모든 쌍, compact의 완전한 224행, raster의 224행이 함께 통과해야 켜진다. 오류 비트는 bit24=공통 ROM 오류, bit23:16=raster, bit15:8=compact, bit7:0=fetch다. 실패 원인이 여러 구성요소에 중복될 수 있다.

이제 실제 평가된 타일·스프라이트를 보존하므로 이전 CIRAM/OAM 스냅샷의 무변경 조건을 중복 요구하지 않는다. `nes_native_frame165.py`는 기존164 입력을 검증한 뒤 새 부모 결선을 생성하며 원본 파일을 수정하지 않는다. 이전 snapshot 인스턴스는 제거하고 사용하지 않는 NT/OAM peek 주소는0으로 둔다. 부모 전체는 컴파일했고, 실제 코어 시험은 동일한 `BINDING`을 CPU/PPU/MMC3 시험 인스턴스에 직접 연결했다. FPGA 기판 부모를 실행하거나 fit한 결과는 아니다.

행별 상태의 지원 범위는 다음과 같다.

- 표시 mask는 `1e`, 팔레트는 최대 **연속된 두 버전**이다. 같은 A→B→A도 세 번째 버전이므로 거부한다. 배경색 변경도 거부한다.
- 표시행 중간의 fine X·팔레트·패턴 모드·mask 변경은 계속 거부한다. 순서 오류·복사 중 충돌·용량 초과도 거부한다.
- v/t 접근 자체는 `scroll_seen`으로 기록한다. 실제 fetch의 셀별 물리 태그·두 플레인과 완전한 압축 결과를 함께 요구하므로, 독립 raster의 기존 오류10을 무조건 무시한 것이 아니다. 새 raster의 valid만으로는 게시하지 않는다.
- 공유 release/reset은 모든 구성요소와 진행 중 조회를 취소한다. generation이 돌아와도 매번8192개의 필요 타일 비트를 지운다. 소유 중 원본 ROM 오류가 생기면 완성 판정도 취소한다.

조회는 NES 클록의 동기식 1단계 응답이다. 요청의 generation이 현재 장면과 같고 `owned && geometry_valid`일 때만 hit가 나온다. 실패·범위 밖·이전 generation은 data0이며, 비동기 호스트가 직접 이 포트를 사용하면 안 된다.

| kind | 내용 | 범위 |
| --- | --- | --- |
| 0 | 압축 BG 셀 | BG 묶음 수 ×33 |
| 1 | BG 행의 묶음 번호·fine Y | 224행 |
| 2 | 평가된 OBJ 조각 | object_count |
| 3 | 두 플레인 행 예외 | exception_count |
| 4 | v/t·fine X·mode·mask·palette 번호 | 224행 |
| 5 | NES 팔레트 색 | palette_count ×32 |
| 6 | 물리 CHR 필요 종류, bit0 BG·bit1 OBJ | 8192타일 |
| 7 | 미사용 | 항상 miss |

## CHR 보충기의 계약과 미연결 부분

`nes_native_fill165.sv`는 위 kind6 조회를 사용한다. 필요한 물리 타일마다16바이트를 순서대로 요청해 소비자에게 보낸다. 주소는 `0x200000 | (tile << 4) | lane`이며 파생 패턴의 가상 번호를 사용하지 않는다. 논리 슬롯 캐시에 남아 있다는 이유만으로 다른 물리 은행의 타일을 재사용하지 않는다. 현재 구현은 필요한 타일의16바이트 전체를 공급하며, 이전 캐시 hit를 이용하는 최적화는 아니다.

- 기본 상한은512타일/8192바이트, 총262144 NES 클록, 단계별 대기1024클록이다. 파라미터는 해당 보드 연결 시 확정할 **정책 한도**이며 PSRAM WCET 증명이 아니다.
- 메모리 읽기는 한 번에 하나만 진행한다. 요청 주소/장면 번호를 유지하고, 같은 주소·generation의 정상 응답만 전달한다. 소비자가 준비되지 않으면 한 바이트만 보관하며 대기 한도를 넘으면 실패한다. 전체 CHR 버퍼는 추가하지 않는다.
- 누락된 조회, 타일 상한, 메모리 오류·잘못된 주소/번호, 예기치 않은 응답, grant/응답/소비자 지연, 총 예산 초과는 `done && !success`다. 이미 전달한 바이트도 임시 데이터이므로 폐기해야 한다.
- 진행 중 읽기를 취소하면 `mem_abort`와 quarantine 상태를 유지한다. `mem_idle`은 단순한 순간 유휴가 아니라 **이전 요청의 미래 응답이 남아 있지 않다는 backend flush 확인**이어야 한다. 그 전에는 새 요청을 시작하지 않는다. reset 후에도 이 확인이 필요하다.
- start는 `!busy && !done && !quarantine && mem_idle`일 때 수락한다. done은 clear까지 유지한다. 보충이 끝난 뒤라도 원래 장면의 소유권·valid·번호가 바뀌면 success를 즉시 막고 취소를 유지한다. clear는 새 전송을 준비하기 위한 해제이며 업로드 성공 ACK가 아니다.
- 호스트가 데이터 전체를 받아 실제 SNES 갱신을 승인하기 전까지 원본 장면을 소유해야 한다. `done && success`와 같은 generation의 유효 장면을 함께 확인한다. host ACK와 화면 게시 상태는 아직 구현하지 않았다.

**이 보충기의 메모리 포트는 실제 PSRAM arbiter에 아직 연결하지 않았다.** 기존 CPU/PPU 요청의 기한을 보존하는 grant/response/flush adapter가 필요하다. 기존 ROM 서비스에 무조건 읽기를 추가하거나 CPU/PPU를 멈춰서는 안 된다. 보충기를 NES 클록에서 더 빠르게 실행했다는 모델 수치를 보드 속도나60fps로 해석하지 않는다.

## 검증과 범위

1. **실제 코어 직접 결선:** 개인 SMB3(J) ROM의 CPU/PPU/MMC3·70ns 메모리 모델로20프레임을 실행했다. 기존 프레임 픽셀20개는 바이트 단위로 동일했다. 표시 비활성1~11프레임은 거부하고12~20프레임은 모두 완전 수집했다. 각7,401이벤트/30BG묶음/2OBJ/2예외로 위치정보2,226바이트다. 새 공통 포트의 압축·행/팔레트·전체8192 필요 타일을 읽어 원본 PPU의 **516,096픽셀과 완전 일치**했다. 이번 표본의 필요 타일은15개/완성 CHR240바이트다. 부팅 표본이며 첫 레벨·매 프레임 최악량 증명이 아니다.
2. **공통 소유권 경계:** 합성 입력으로 첫 raster 행 이전 오류, CE 정지, 다음 generation 회복, 잘못된 장면 번호/범위 조회, release/reset과 조회 겹침, mask/fine X/팔레트·배경색/누락 셀 거부를 확인했다. 실제 공통 조회→보충기도 직접 연결해33타일528개 모델 바이트가 정확히 나왔다. 코어 내부 상태를 강제로 설정하지 않았다.
3. **보충 인터페이스:** 실제 수집한9개의 필요 집합과 개인 ROM 바이트를 모델 backend에 공급했다. 아홉 집합 모두240바이트가 정확했다. 추가15사례로 조회 실패·주소/번호/메모리 오류·단계/전체 시간 제한·타일 상한·취소/번호 변경·늦은 응답·reset·완료 뒤 취소를 확인했다. 메모리 grant와 소비자 backpressure는 합성 조건이다. 기판 PSRAM 중재나 CPU/PPU 기한 검증으로 확대하지 않는다.

재현 도구는 `test_nes_native_frame165.py`, `verify_nes_native_frame165.py`, `test_nes_native_frame_lease165.py`, `test_nes_native_fill165.py`다. 비공개164 입력/ROM과 기존 승인된 FLOAT 래퍼를 사용한다. 선택 실행은 `frame03 / lease04 / fill03 / verify01`이다. 초기 시험벤치 선언 오류(frame01/02), 합성 행 간격을 줄여 복사 중 입력이 된 경우(lease01), 첫 타일과 signed -1을 비교한 검사기 오류(fill01)를 보존했다. lease02/03·fill02 통과도 보존하고, 완료 후 취소 조건을 추가한 최종 시험을 선택했다. 원시 로그·입력·실행 소스는 비공개, 공개 저장소에는 코드·해시·요약만 남긴다.

## 바로 다음 작업

이번 **실제 코어의 공통 장면 결선과 유한 보충 인터페이스**는 완료했다. 영상 끊김 해소·설치 가능한165는 아직 미완료다.

1. 기존 ROM 서비스의 CPU/PPU 우선순위와 실제 비어 있는 처리 구간을 기준으로 보충 grant/응답/flush를 연결한다. 무제한 읽기·새 독립 PSRAM 소유자를 만들지 않는다. 공통 장면→보충→host CDC/업로드 ACK의 흐름을 연결하며 임시 데이터는 완성 전 게시하지 않는다.
2. SNES 실제 소비자·명령 생성과 기존38M9K 픽셀 버퍼 교체를 함께 진행한다. 현재56/56M9K이므로 단순 추가는 불가능하다. PC 참조의 전체 이벤트 그래프·shadow VRAM을 그대로 FPGA에 복사하지 않는다.
3. 변경 경로의 최소 검사와 실제 자원·타이밍 확인 후 SMB3 첫 레벨 실기로 간다. 같은20프레임 수집, 플레인 경계, 합성 A/B,044 복원은 변경 없이 다시 하지 않는다. 첫 레벨의 실제 영상이 다음 품질 판단 기준이다.

164 사운드·STOP/메뉴를 유지한다. 화면과 사운드가 사용 가능한 수준에 도달하면60초 제한 제거, 오류/본체 리셋 시 로그, 장시간 입력 유지 순으로 진행한다. PR107에 추가하고 사용자가 머지한다.
