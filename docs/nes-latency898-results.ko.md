# MMC898 분석 · 모험도 4 실기 두 구간의 첫 지연

PR170 머지 커밋 `823f114`을 기준으로 MMC872와 MMC897 실기 각 1회, 두 구간에서 새로 캡처한 원본 화면의 두 위상 재생을 대조했다. 분석에는 배포한 ARM·65816을 그대로 사용했다. 실기 로그에는 5초 단위 집계가 있고 세대별 SEAL·DMA 시각은 없다.

## 실기 5초 집계

각 시간은 해당 구간에 **시작한 화면 수**로 누적 10ms 틱을 나눈 값이다. 미완료 작업이 경계에 걸릴 수 있다. 표시 완료 시각 기준 FPS와 구별한다.

| 구간·판 | 장수 | 장당 변경 map 행 / OBJ / BG | 수신 ms | 계획 ms | 출력·최종 ACK ms |
|---|---:|---:|---:|---:|---:|
| 30–35초 · 872 | 90 | 6.19 / 19.96 / 501.97 | 0.78 | 9.89 | 43.89 |
| 30–35초 · 897 | 80 | 6.96 / 20.89 / 502.55 | 0.88 | 10.50 | 50.63 |
| 55–60초 · 872 | 89 | 6.52 / 24.31 / 525.55 | 3.03 | 9.78 | 42.47 |
| 55–60초 · 897 | 79 | 8.47 / 20.91 / 525.48 | 4.30 | 10.38 | 47.85 |

30–35초의 수신 합계는 양쪽 모두 70ms다. 이 구간에서 가장 큰 장당 증가는 출력·최종 ACK의 6.74ms다. 55–60초는 수신 합계부터 270→340ms로 증가했고 장당 출력도 5.38ms 늘었다. 후반에는 map 행과 OBJ 작업량도 달라졌다. 이 집계에는 각 65816 DMA가 어느 VBlank에 끝났는지 식별할 정보가 없다.

## 작업량을 일치시킨 화면

동일한 ROM·무입력 실행에서 원본 프레임 1950–1978과 3450–3478을 4장 간격으로 캡처했다. 구간별 첫 2장으로 두 뱅크를 준비한 뒤 6장씩 비교했다. 872와 897에 같은 원본·같은 CHR 태그 이력·같은 시작 위상·ROM 허가·SPI 보정을 사용했다. BG 태그 이력은 구간 평균 수준으로 맞췄으며 초기 VRAM 유효 비트는 비워 두었다. 두 판의 변경 행·OBJ·BG, D1 개수·바이트, map 내용 및 표시 RGB가 각 대응 화면에서 일치했다. 원본 프레임 번호는 실제 두 실기 실행의 캡처 세대와 일대일 대응하지 않는다.

아래는 **planner 진입부터 ARM 발행까지** MMC897에서 추가된 시간이다. 한 구간에서 검사 시각을 일관되게 비교하기 위해 양쪽의 같은 세대를 기준점으로 삼았다.

| 원본 화면 | 변경 map 행 / OBJ / BG | OAM 재사용 명령 발행 지연 (위상 1 / 2) | SEAL 발행 지연 (위상 1 / 2) | 표시 간격 872→897 |
|---|---:|---:|---:|---|
| 1970 | 23 / 36 / 499 | +2.62 / +2.62ms | +0.69 / +0.94ms | 양쪽 모두 2→2 VBlank |
| 3470 | 23 / 31 / 526 | +2.70 / +2.20ms | +0.96 / +0.46ms | 양쪽 모두 2→2 VBlank |

두 화면은 입력의 마지막 D2가 직전 표시 기준으로 두 위상 모두 일찍 끝났다. 처음 공통으로 늦어진 후반 출력 명령은 OAM 112B와 대상 뱅크 이력 4B를 담은 op9이다. 872는 section 5의 두 패킷(217B·256B, 헤더 포함)보다 op9를 먼저 보냈고, 897은 두 패킷 뒤에 보냈다. 3470 위상 1에서는 그보다 앞선 map offset 1152 발행부터 0.25ms 늦었고 위상 2에서는 같은 map이 0.26ms 일렀다. 3470의 768B 선행 DMA는 두 판 모두 VBlank 43에, 나머지 DMA와 표시는 44에 완료됐다. 이 두 화면에서는 OAM·SEAL 발행 지연이 실제 한 VBlank 손실까지 이어지지 않았다.

| 측정 6장 | 간격 합 872 / 897 (위상 1, 위상 2) | 같은 시작에서 마지막 65816 ACK 차이 (897−872) |
|---|---|---|
| 30–35초 표본 | 14 / 14, 14 / 14 | +0.004 / −0.018ms |
| 55–60초 표본 | 13 / 13, 13 / 13 | −0.021 / −0.116ms |

직전 표시만 기준으로 볼 때의 착시도 확인했다. 위상 1에서 1962는 3→2 VBlank였고 직후 1966은 2→3이었다. 1966의 캡처 준비 절대 시각은 같았고 897의 D1 시작은 0.44ms, 최종 ACK는 0.60ms 일렀다. 앞 화면이 약 16ms 일찍 공개돼 다음 표시까지의 간격이 늘었다. 이 사례를 수신 회귀로 집계하면 원인을 잘못 지목한다.

## 판단과 다음 확인

실기 두 구간의 공통 우선순위는 출력이다. 먼저 MMC897에서 op9와 두 section 5 패킷의 순서만 바꿔 SEAL 발행이 앞당겨지는지, 실제 잔여 DMA와 공개가 직전 VBlank로 이동하는지 대조한다. 여덟 재생에서 실기의 구간당 10장 감소는 재현되지 않았다. 실기 최초 지점을 확정하려면 두 시간대에 세대·작업량·D1/D2·SEAL 수락·DMA 종료·공개·유효 ACK를 짝지어 기록해야 한다. 특히 후반 수신 지연과 공개 뒤 ARM이 ACK를 확인하는 시간은 별도로 남긴다. SRAM D0 송신, 독립 검사, STOP과 base·메뉴 복귀의 기준은 실기 통과한 MMC897이다.

## 재현

`compare_nes_latency898.py`에 기존 NES 실험용 TEMP와 동일 ROM을 넘겨 capture, geometry, board, history 순으로 준비한다. board는 기존 Questa FLOAT 래퍼에서 한 좌석으로 실행한다. 이후 replay에 --edition 872/897, --clip early/late, --phase 1/2의 여덟 조합을 사용한다. 두 링크와 65816의 해시는 배포 manifest와 대조한다. `analyze_nes_latency898.py TEMP DOWNLOADS analysis/latency898-results.json`은 원본 실기 로그 해시, 공통 RTL, 동일 작업량·화면을 검증하고 입력부터 ARM의 유효 E0·EA까지 클록을 기록한다. 타이머·SPI 비용·ROM 일정은 재생 모델이며 실기 이벤트 시각은 별도다.
