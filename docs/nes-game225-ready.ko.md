# NES225 실기 시험: 가로 스크롤 맵 재배치

이번 시험은 기존64열 SNES 맵 안에서 타일 위치를 유지하고 스크롤 좌표로 화면을 이동시킨다. 화면 밖 셀을 매번 지우지 않아 스크롤의 맵 갱신을 줄인다. FPGA/SNES 프로그램은223과 동일하고 ARM만 변경했다. 실제60fps나 실기 개선은 아직 미확인이다.

## 설치·실행

1. 전원을 끈 상태에서 `01-GAME225-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. 폴더 자체를 넣지 않는다. 기존 파일 덮어쓰기 시 이번 firmware.stm과 이름이 맞는 fpga_n225.bi3/game225.nes/실행파일을 함께 사용한다.
2. 메뉴에서 `NES GAME 225.nh1`을 실행한다. 초기 ROM 검증·로딩은223과 같은 경로이며 단축한 시험이 아니다.
3. 플레이어 선택 → 월드맵의 숫자1 타일로 이동 → A로 첫 레벨에 들어간다. 오른쪽+B를 유지하고 A를 반복해 스크롤한다. 가능한 범위에서 잠시 왼쪽 이동도 해주면 좋다.
4. 게임 화면 시작 후 약60초가 지나면 메뉴로 돌아온다. 게임이 멈추거나 화면만 정지했다면 그 시점과 소리·조작 반응도 알려준다.

## 전달할 결과

- `/sd2snes/nes-progress-225.txt`
- `/sd2snes/nes-game-last-225.txt`
- `/sd2snes/nes-budget-225.txt`
- 첫 레벨 스크롤의 끊김 정도, 새로 나타난 타일 깨짐/경계선 여부, 소리·조작·메뉴 복귀 상태.

가능하면 게임 화면부터 메뉴 복귀까지 영상도 함께 남긴다. 정확한 조작 재현이 어려워도 첫 레벨의 스크롤 구간이 있으면 된다. budget/startup schema가222인 것은 필드 형식을 유지했기 때문이며 파일225가 맞다.

기존223 또는044 재시험은 필요하지 않다. `02-RESTORE164-SD-ROOT`는 필요할 때 돌아갈 수 있도록 기존 내용을 그대로 포함했다. 정상이면 매번 복원 시험을 반복할 필요는 없다. 저장SRAM은 사용하지 않았다.

## 확인된 범위

- 실제 C353프레임: 표시 픽셀·OBJ 바이트 비교 및 기존11거부 경계 통과. 합성 가로스크롤192프레임에서 맵 업로드689152→348672B, map E1전송761684→385104B. 게임FPS나전체전송 절반을 뜻하지 않는다.
- 실제65816 소비기30프레임1835520픽셀 동일. 잘못된 기준/누락된맵/잘못된표시ACK 거부. RUN9프레임 및6오류 경계 통과.
- ARM209196B/static28020/RUN34984/IRQ508/여유1912B. FPGA는223 이미지와바이트 동일, 추가FIT/ROM조립 없음.
- 장면 급변·임의 스크롤 조건은 항상 빨라지지 않는다. 잔여 수신·계획·SNES 반영 비용이 있어60fps는 별도 실기 확인이 필요하다.
