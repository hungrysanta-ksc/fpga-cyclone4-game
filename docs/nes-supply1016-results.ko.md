# MMC1016 모험도 4 실기 두 회

두 실행 모두 59.98초에 마지막 화면을 표시했다. ROM 393,216B 대조, STOP, base 복구, 메뉴 준비가 성공했다. 사용자가 두 번 모두 실제 메뉴 복귀를 확인했다. 각 BIN에서 59.70초의 15타일 표본을 한 번에 48페이지로 읽었고 누락 카운터는 모두 0이었다. [실기 기록과 원본 파일 해시](../analysis/supply1016-hardware.json)

| 무입력 실행 | 1–30초 표시 수 / FPS | 30–60초 표시 수 / FPS |
|---|---:|---:|
| MMC1012 1차 | 683 / 23.55 | 734 / 24.47 |
| MMC1012 2차 | 699 / 24.10 | 748 / 24.93 |
| MMC1016 1차 | 688 / 23.72 | 738 / 24.60 |
| MMC1016 2차 | 700 / 24.14 | 743 / 24.77 |

세대 1507과 1527은 15개 타일의 태그·행·플레인 순서까지 일치했다. 첫 타일은 CHR 읽기가 없고, 나머지 112건 중 96건은 행 캐시, 16건은 소비용 ROM에서 공급했다. 두 회 모두 여덟 번째 타일인 OBJ 태그 6270의 0행에서 요청 0눈금·첫 허가 11눈금이었다. 나머지 15건의 ROM 요청과 허가는 각각 같은 눈금 안에 들어왔고, 어느 요청에서도 선행 읽기 소유자와 겹친 대기가 잡히지 않았다. NES 시계의 눈금 차이는 약 8.39ms이며 실제 대기의 양자화 범위는 약 7.63–9.15ms다.

host 시계에서 첫 E9부터 마지막 묶음 준비까지 두 회 모두 11눈금(8.58ms)이었다. 16B 뱅크 반환만 1→2눈금으로 달라졌고 384B와 64B는 두 회 모두 각각 12·14눈금에 반환됐다. 첫 뱅크가 반환된 뒤 그 뱅크를 다시 쓰는 묶음이 시작될 때까지 두 회 모두 6ms 이상 남았다. 타일 공급 시각에 회차 차이가 없고, MMC1014 세대 1384의 44.47ms 지연은 재현되지 않았다. [이전 세대 비교](nes-supply1015-results.ko.md)

실기 기준은 MMC1012로 유지한다. 다음 실험은 태그 6270의 0행이 plan에서 확정되는 시점과 직전 ROM 허가 구간을 대조한다. 선행 읽기 기회가 있으면 태그를 고정하지 않는 정책으로 같은 입력에서 첫 허가·마지막 묶음 준비·실제 화면 공개가 함께 앞당겨지는지 확인한다. 예전 44.47ms 지연을 조사하려면 빠른 표본과 함께 장시간 대기가 발생한 표본을 따로 보관해야 한다.
