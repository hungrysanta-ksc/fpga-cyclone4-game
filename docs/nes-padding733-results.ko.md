# NES733 패딩 상수 제거와 연속 map 구간 검증

## 목표

732B 발행 순서를 유지하며 정상 Flash 28B 초과를 해소한다. 727과 같은 map·OBJ 작업량, 두 시작 위상에서 952·957의 1536B map DMA, 956 선행 DMA, 다음 BG ROM 마감과 밀집 표시 간격·마지막 ACK를 함께 확인한다. STOP·독립 검사·최종 ACK·메뉴 복귀를 유지한다.

## 작업내용

패딩용 `zero[240]`을 확장 반복 명령에 필요한 `zero[2]`로 줄였다. 짧은 DATA2 패딩은 기존에 영점 초기화되는 256B 송신 버퍼를 사용한다. 내부 NULL source는 해당 영점 DATA를 뜻하며, 짝수 반복의 탐색·복사를 생략한다. 길이 1·2·3과 홀수 패딩은 기존 literal DATA를 그대로 유지한다. wire 명령·길이·순서·독립 수신 검사에는 변경이 없다. 확장 op5/6/7/8의 NULL source 거부도 유지한다.

732B의 연속 map extent, 실제 주소 공백에서 한 번의 ordinary 발행, 기존 유한 DMA 대기와 producer/credit/receipt 검사를 유지한다. 새 RAM·고정 대기·프레임 번호 조건을 추가하지 않는다. E0 bit8을 전체 map DMA 완료로 해석하지 않는다. FPGA707D와 기존65816은 동일하다.

## 성과

### 전체 링크와 비용

|구성|정상 Flash|장시간 Flash|함수 경계|패딩 상수|함수+패딩|
|---|---:|---:|---:|---:|---:|
|727|212,992B|212,948B|4,966B|240B|5,206B|
|732B|213,020B|미측정|4,994B|240B|5,234B|
|733|**212,792B**|**212,748B**|5,002B|2B|5,004B|

Flash 한도212,992B 안에 정상200B·장시간244B가 남는다. 732B 대비 실제 이미지228B 절감이다. 함수만은8B 증가했으므로 종전 함수 전용4,970B 부분 예산을 통과했다고 하지 않는다. 실제 삭제한 상수238B를 양쪽에 똑같이 포함하면 함수+상수는732B보다230B,727보다202B 감소한다. 최종 파일 정렬까지 포함한 전체 링크를 최종 자원 기준으로 삼았다.

정적 `.data1048/.ahbram8992B`, `.bss` 정상19548/장시간19556B와 sink992/resident6032/runtime1408B는727과 같다. 65816 ROM과 FPGA 변경은 없으므로 같은 Quartus FIT/STA를 반복하지 않았다. 707D의 기존15322LE·962/963LAB·56/56M9K 및 setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns는 상속 근거이며 새 합성이나 전체 외부IO 승인 결과가 아니다.

### 기능·소유권 검사

실제 전체 링크 ELF로 길이1..240 패딩의 wire 바이트를732B와 정확히 대조했다. 홀수 literal·짝수 반복을 독립 복원했고,1122개 호출 offset의 복원 범위와5개 잘못된 길이/확장 NULL source 거부를 확인했다.

732의13개 구간/ordinary/오류,9개 prepared·부분 전송·최종 ACK,32개 원래 모드 대조,76개 span·8개 OAM 동등성을 통과했다. 기존35개 수락/행/status,10개 진행/소유권,7개 END,9개 credit,17개 마감/expiry,정상7개·장시간16개 종료와 두 판의 메뉴 경계도 통과했다. 단위 시험의 준비 데이터·응답은 fixture이며 전체 시간은 별도 재생에서 확인한다.

초기 생성은 이미 복사한 src에 recipe가 새 디렉터리를 만들려다 실패했다. 이때 normal01은 수정되지 않은727 소스로 빌드됐다. 생성 patch를 먼저 만든 뒤 normal02/arm02에 복사하도록 바로잡았고, 초기 실패와 원본 빌드 로그를 보존했다. normal01을733 측정이나 추가 후보로 계산하지 않는다.

### 두 위상 전체 일정

**자원·기능 통과, 시간 및956 보호 조건 미달로 미채택이다.** 시작 클록7288416/7467100,ROM 위상0,세대905..957 각53화면(총106)을 완료했다. 727과 map·tile·plan·최종 픽셀이 같다. 실제 링크 M4·65816 실행이며 CPI2/84MHz·SPI driver·IRQ·반복 ROM 달력은 모델이다. 전체 NES/PSRAM RTL 동시 실행이나 실기 FPS가 아니다.

951..957의 표시 간격은 모두3 VBlank 그대로다. 두 위상의952 map384+1536B,957 map128+384+1536B와 최종 대기0회,956 tile64B,953 BG32회 원래 ROM 구간을 유지했다. 951 공개236선,908·911·934·940·943의 기존2회,7블록 선행 수신도 유지했다. 전체 관측 stack 최저주소는0x2000f814→0x2000f81c로8B 적게 사용했다. 관측 실행의 최댓값이며 전체 stack 상한 증명은 아니다.

### 956에서 사라진384B의 경계

두 위상 모두 마지막 map192B 두 패킷을 보내기 전에116B 재사용 OAM 명령이 끼어들었다. 위상1 마지막 map 수락 ACK는 직전 표시 기준27.434→29.575ms로 늦어졌지만, 실제128B 선행 DMA보다 **3.523ms 먼저 완료**됐다. 위상2도3.595ms 먼저 완료됐다. 따라서 이를 map 미수락이나 데이터 부족 때문이라고 결론내리지 않는다.

위상1에서는128B DMA가236선에 끝난 뒤 새 OBJ가240선에 수락됐고250선에는 HDMA가 이어졌다. 새 패킷 우선 규칙을 지킨 결과 마지막384B는 다음 VBlank의 SEAL 뒤로 넘어갔다. 위상2는384B DMA가241선에 먼저 들어가고 OBJ 수락은244선이라1024B를 보존했다. **주소가 연속된 구간을 보존하는 것만으로 여러 구간의 빈 큐 DMA 기회까지 보장되지는 않는다.**

956 SEAL 수락 자체는43.506→41.029ms /43.306→41.203ms로 빨라졌으나 표시 VBlank는 줄지 않았다. 앞당겨진 후속 공급이 수락된 map의 빈 큐 기회를 소비할 수 있으므로, SEAL 단독 개선이나 SPI 감소를 전체 성과로 채택하지 않는다.

## 후속작업

선택707D·기존 ARM/65816과 연구 대조군727을 유지한다.733의 패딩 상수 제거는 독립적인 자원 절감으로 보존하되,732B의 전체 발행 일정은 채택하지 않는다.

다음은956의 **이미 수락된3072..3455 map384B**와240선 근처 후속 OBJ/HDMA 수락을 기존 DMA 진행·credit 경계에 맞추는 조건을 먼저 정한다. 새 패킷·STOP 우선권을 뒤집지 않고 필요한 빈 큐 구간을 ARM 발행에서 확보해야 한다. 952/9571536B·9561024B·다음953 BG 원래 ROM 구간,911·951·7블록을 함께 보호한다. E0 한 번의 진행을 전체 완료로 바꾸거나 고정 프레임 번호·위상 지연을 추가하지 않는다. 두 밀집 지표와957 마지막 ACK가 양쪽에서 함께 줄어야 채택한다. 실기 설치본·RESTORE는 이번 범위에 포함하지 않는다.
