# 625 · 955의 ROM 공급과 SEAL 수락

## 624에서 955가 한 VBlank를 더 쓴 지점

시간 원점은 각 위상의 954 표시다. 두 위상에서 SEAL 이후 첫 DMA는 동일한 비활성 뱅크 map 오프셋 896의 128B였다. ARM 발행과 PUSH, 해당 패킷의 65816 ACK, 실제 첫 PPU 전송을 목적지·범위로 연결했다.

| 955 사건 | 위상 1 (ms) | 위상 2 (ms) |
|---|---:|---:|
| 마지막 BG ROM 응답 | 49.923 | 34.049 |
| 첫 DMA에 쓰일 map의 E1 발행 | 36.913 | 38.046 |
| 해당 map의 65816 수락 | 37.959 | 39.197 |
| SEAL E1 발행 | 63.746 | 59.596 |
| SEAL PUSH | 64.365 | 60.216 |
| 65816 SEAL 읽기 시작 | 64.430 (212번 선) | 60.217 (146번 선) |
| 독립 검사 후 업로드 진입 | 66.031 (238번 선) | 61.847 (172번 선) |
| 첫 DMA | 66.355 (243번 선) | 65.241 (225번 선) |
| 955 표시 ACK | 82.899 | 66.712 |

위상 1은 두 번째 15개 plan 묶음의 BG 읽기에서 주소 99047 요청이 다음 ROM 허가까지 15.842ms를 기다렸다. 확정된 map과 팔레트 전송이 일부 겹쳤지만 마지막 BG 및 OBJ 세 명령의 수락은 51.32–55.70ms로 밀렸다. 위상 2에서 이 네 명령은 37.39–42.99ms에 수락됐다. 위상 1은 검사 후 같은 VBlank에 128·144·64·64·320B를 전송했고, 255번 선에서 새 VBlank를 기다려 마지막 raw 64B 세 건과 표시를 실행했다.

**도착 시각 대조**에서 위상 2의 마지막 SEAL PUSH만 89,112 master clocks(4.149ms) 늦췄다. 그전 10,025개 관측 이벤트는 정확히 같았다. SEAL 읽기가 146→212번 선, 표시가 224→225번째 VBlank, 955 ACK는 16.178ms 뒤로 이동했다. 지연을 넣지 않은 재생은 905–955의 원래 CPU 이벤트와 일치했다. 이 결과는 955의 표시 마감에 대한 것이며, 957까지의 효과는 아래 연속 일정에서 따로 판정한다.

## 실제 ARM 후보

* **linear**는 기존 64B 반복 탐색을 앞에서부터 한 번 읽도록 바꿨다. 두 칸 전과 같은 바이트가 연속 62개면 64B 반복이고, 첫 위치와 240B 경계는 기존 선택 기준을 따른다.
* **tables**는 81B HDMA 테이블 세 개를 연속된 243B로 같은 전송 함수에 준다. 테이블의 미사용 바이트까지 보존한다. 뒤의 6B 길이는 기존 방식으로 보내며, C 구조체 정렬 패딩은 보내지 않는다.
* **both**는 위 두 변경을 결합했다. **transition**은 여기에 대상 뱅크 이력이 최종 ACK로 확정된 경우, 두 번째 plan 묶음의 일곱 번째 레코드가 첫 compact OBJ이면 기존 CRC·credit 확인을 거쳐 E9를 보낸다. 기존 일곱 BG 발행 조건도 유지한다. 955의 세대 번호나 미래 빔 시각을 판단에 사용하지 않는다.

전체 ARM Flash 한도는 212,992B다. linear / tables / both / transition은 각각 212,992 / 212,960 / 212,964 / 212,980B였다. 실제 Thumb 실행에서 길이 1–4,096B, 62–65B 반복, 홀수 시작, 239–241B 경계를 포함한 362개 입력으로 각 링크의 분할 위치를 대조했다. 팔레트의 정상 credit 반환, CRC·개수·identity 오류, STOP도 시험했다. transition의 가변 레코드는 실제 compact OBJ suffix 길이로 구분한다. 설계 중 검토한 prefix 바이트 수만 보는 초기 링크는 연속 일정 후보에서 제외했다.

**tables-bg**는 기존 반복 탐색을 유지하고 tables에만 같은 E9 조건을 붙였다. 전체 링크는 212,976B였다. 원래 623 T에서 E9 조건만 바꾼 대조군(plan-only)은 213,004B로 12B 초과해 연속 일정 대상에서 제외했다.

## 두 시작 위상의 연속 일정

각 칸은 위상 1 / 위상 2 순서다. 마지막 ACK는 905에서 시작한 뒤 957까지의 절대 시각을 같은 위상의 T + 624와 비교했다. 양수는 지연이다. 밀집 합계는 951–955 다섯 표시 간격의 합이다.

| ARM + 624 소비기 | 922 표시 VBlank | 955 표시 간격 | 밀집 합계 | 955 후반 384B 중 선행 DMA | 마지막 ACK 차이 (ms) |
|---|---:|---:|---:|---:|---:|
| 623 T 기준 | 92 / 92 | 5 / 4 | 21 / 20 | 384 / 384 | 0 / 0 |
| linear | 93 / 92 | 4 / 5 | 20 / 21 | 384 / 384 | +16.628 / +33.292 |
| tables | 92 / 92 | 5 / 5 | 21 / 21 | 384 / 384 | −0.013 / +16.640 |
| both | 93 / 92 | 4 / 5 | 20 / 21 | 384 / 384 | +16.639 / +33.278 |
| transition | 93 / 92 | 4 / 4 | 20 / 20 | 192 / 192 | +16.626 / +16.652 |
| tables-bg | 92 / 92 | 4 / 4 | 20 / 20 | 192 / 192 | −16.628 / −0.156 |

**tables-bg가 전체 시간에서 가장 빨랐다.** 두 위상에서 923의 첫 ROM 응답 클록과 952·954 표시 간격 4회를 지켰다. 955의 마지막 BG 응답은 33.655 / 33.605ms, SEAL 읽기는 모두 150번 선이었다. 955의 HDMA E1 합계는 586→567B였다. 위상 1은 955에서 처음으로 표시 한 회를 아꼈고 위상 2는 53화면 모두 원래 VBlank에 표시했다. 621 대비 마지막 ACK는 66.637 / 16.889ms 빨랐다.

**같은 바이너리 대조군**은 transition에서 955의 추가 E9 한 번만 우회했다. 직전 11,583 / 11,492개 이벤트와 클록이 일치했다. E9를 허용하면 955 두 번째 묶음의 수락이 1.189 / 1.189ms 빨라졌고, 마지막 BG ROM 응답은 33.965→33.618 / 50.054→33.654ms였다. 955 간격은 4→4 / 5→4였고, 전체 마지막 ACK는 각각 0.013 / 16.633ms 앞당겨졌다. 624까지의 누적 이득을 판단할 때에는 표의 원래 T 대조군을 사용한다.

**남은 map의 위치**도 바뀌었다. transition은 두 위상 모두 오프셋 2,240에서 1,152B를 보냈다. 이 DMA는 목표 범위 3,200–3,583 중 앞의 192B까지만 덮었다. 끝난 선은 246 / 249이고, 65816이 바로 다음 247 / 250번 선에 새 팔레트 패킷을 수락했다. 뒤 192B는 이미 수락됐어도 이때 함께 선행 전송되지 않았다. STOP이나 새 head의 우선순위를 낮추지 않고 이 192B까지 포함하려면, ARM의 패킷 순서나 1,152B DMA의 시작 주소가 달라져야 한다.

tables-bg도 두 위상 모두 2,240부터 1,152B를 247–254번 선에 전송하고 255번 선에 팔레트를 읽었다. 957의 최종 대기는 두 위상 모두 0회였다. 위상 2에서는 16B tile을 230번째 VBlank에 미리 보냈고 48B tile·1,152B map은 231번째에 보냈다. 세 전송을 같은 VBlank에 끝내는 기존 판정과, 앞서 보낸 16B 때문에 늘어난 대기가 있는지는 구분해 기록한다.

**판정과 다음 검증.** 다섯 후보 중 955의 후반 384B 선행과 기존 표시 조건을 두 위상에서 모두 지킨 시간 개선 후보는 없었다. 621을 기준으로 유지하고 tables-bg를 다음 대조군으로 보존한다. 다음은 이미 수락된 map 오프셋 3,392–3,583의 192B가 유휴 DMA에 포함되도록 수락 순서와 시작 오프셋을 고정 도착 재생에서 각각 바꿔 본다. 중복·누락과 다른 행의 SEAL 뒤 이월량, 246번 최종 검사선, 957의 표시·ACK를 함께 측정한다. 보드 준비 기준은 616B, 실기 기준은 MMC613이다.

## 재현

1. `tools/prepare_nes_seal625.py`에 623 small-snapshots 원본과 정책을 주고 `tools/build_nes_trial577.ps1`로 전체 링크한다. transition, tables-bg, plan-only는 각각 `both --close-bg`, `tables --close-bg`, `original --close-bg`이다. `tools/check_nes_seal625.py`로 실제 링크의 ARM 경계를 검사한다.
