# NES721 OBJ 조회 분리·map 연속 DMA 비교

## 목표

719의 map 연속 DMA와951·911 회복,716B·717 절감을 유지하면서720의 OBJ 공급 개선만 분리한다. 같은 작업량·두 시작 위상에서952–957 표시 간격과957 마지막ACK를 함께 비교한다.

## 작업내용

721A는719의 `nes_plan_service200.c` 한 파일만 바꾼다. map 뒤 receipt-only 반환을 제거해 기존 CRC·identity·STOP 검사로 실제 producer를 조회한다. 이전 bulk의 실제 완료는 계속 필요하며 최종 표시ACK·EA retire를 대신하지 않는다.

720의 warm 행 발행1회 제한과BG완료 flush는 적용하지 않았다. 719의 planner·sink·runtime·window 소스는 hash로 동일함을 확인한다. 코드가 같아도 tile 삽입 시각이 map DMA에 영향을 줄 수 있으므로952·956·957 선행map 바이트가719보다 줄지 않는 조건도 별도로 검사한다.

실제 링크ARM/65816, CPI2·SPI/IRQ 비용모델, 같은ROM달력·시작7288416/7467100을 사용한다. 전체NES/PSRAM RTL 동시실행이나 실기FPS·물리메뉴 확인은 아니다. 독립검사·STOP·최종ACK·메뉴 경계는 각각 명시된 시험 범위로 검증한다.

## 성과

**721A는 기능·Flash를 통과했지만 map 선행 DMA와 시간 조건을 지키지 못해 미채택이다.** 719의 소스 순서를 보존하는 것만으로 실제 DMA 연속성이 보존되지 않았다. 707D·기존694/704 ARM·기존65816 선택을 유지한다.

| 719 대비, 같은 작업량 | 위상1 | 위상2 |
|---|---:|---:|
| 952–957 VBlank 합계 | 18→19 | 18→18 |
| 952–957 평균 표시 간격 | +2.796708ms | +0.017833ms |
| 957 마지막 ACK | +16.798130ms | +0.131115ms |
| 952 표시 간격 / 공개선 | 4회 / 229선 | 3회 / 250선 |
| 952 선행map | 1920→384B | 1920→576B |
| 956 선행map | 1024→832B | 1024→832B |
| 957 선행map | 2048→1856B | 2048→1856B |

951 공개236선·911 표시2회/242선·957 최종대기0·7블록·716B 네화면2회와동일map/tile/plan/픽셀106화면은 유지했다. 낮은 주사선만 보면952 위상1의 한회차 지연을 놓치므로, VBlank 회차와절대ACK를 함께 확인했다. 관측stack은원본대비−100/0B이며새상주RAM은없다.

위상2의956 OBJ 마지막응답은2.329ms,SEAL은1.647ms앞당겼다. 하지만952의map이먼저밀렸고마지막ACK는개선되지않았다. 위상1은952의추가VBlank때문에956 OBJ응답이절대시각으로14.074ms늦다. 직전표시기준부분단축을전체이득으로계산하지않는다. 720과 비교해도위상1마지막ACK+16.547ms,위상2+0.001304ms다. 전체SPI는719대비+984/−36B로조회추가효과와대기변화가함께반영된다.

A의실제링크query10·deadline17·tail24·plan7·credit9·runtime16·메뉴18조건과65816 STOP4조건을통과했다. slot18·동일65816종료12조건은변경없는소스/hash의기존근거를승계한다. 새실기메뉴확인이나60fps성과는없다.

### map DMA 진행 조건의 자원 검증

A의회귀를보고기존719의map우선을유지한수정안도구현했다. **B/D/E는 검증된E0 DMA진행bit와현재sent==retired가함께맞을때만producer조회를허용**한다. 새E1 뒤옛bit가남더라도counter가달라통과하지못한다. DMA진행은적어도한번의완료이지모든map완료나최종ACK가아니다. 새대기루프·예약·상태RAM을추가하지않았다.

| 후보 | 변화 | 정상Flash / 초과 | 동일전체경계 / 1744B 초과 |
|---|---|---:|---:|
| B | 719우선 + DMA진행·현재counter 조건 | 213012B / 20B | 1758B / 14B |
| C | E1에서진행bit무효화, counter분기대체 | 213016B / 24B | 1762B / 18B |
| D | B + 같음·이전token 분기통합 | 212996B / 4B | 1744B / 0B |
| E | D + 반복token 완료반환통합 | 213008B / 16B | 1756B / 12B |

기존목록1108B에이번변경함수`poll`430B·`send`198B를양쪽모두포함하면719의전체경계는1736B,기존여유8B를더한상한은1744B다. A는1682B,D는1744B다. D의named부분1130B만보고14B초과라한초기계산은`poll`430→416B삭제를빠뜨렸으므로정정했다. 최종D의공동경계는통과하고전체Flash4B초과만남는다. 이전archive01도보존한다.

D의 `new_token<=old_token` 뒤전체12B비교는기존같음검사와이전token거부를함께수행한다. 이전token은내용비교에서반드시다르므로거부한다. 실제normal D에서진행없음·새E1뒤stale·empty·repeat·이전token·동일token내용변조·CRC·세대·STOP의10조건을통과했고최종ACK전재사용은막았다. flags나counter를DMA허가로사용하지않는다.

**B/C/D/E는 자원에서 탈락해 두 위상 전체 시간을 실행하지 않았다.** D의map연속성/표시간격개선은아직미검증이며4B만줄이면성능이해결된다고주장하지않는다. E는동등한반환표현도전체링크에서오히려증가했다. 중간7개전체빌드와실패비용을보존하고동일분기표현의반복튜닝은중단한다.

|---|---:|---:|
| 60초판 Flash | 212,992B | 212,936B / 여유56B |
| 장시간판 Flash | 212,948B | 212,892B / 여유100B |
| 공동 발행 경계 | 1,108B | 1,054B |

719 대비 새 정적RAM0B이며 원본 대비ACK 시각4B는 남는다. 기존707D·65816·SDC가 같으므로 전체Quartus Lite FIT15,322LE·962/963LAB·56/56M9K, setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다. 새합성이나 회로절감 성과가 아니다.

## 후속작업

1. 719의map우선을유지한다. A처럼map마다준비된OBJ를즉시삽입하는경로는기각한다. 기존716B·717·719는보존한다.
2. D의진행·counter조건을현재producer/완료제어와공유할범위부터정한다. **동일전체경계1744B를넘기지않으면서전체정상Flash최소4B감소**가필요하다. helper삭제까지포함한같은경계를비교하고함수별합과링크정렬비용을구분한다. 새RAM/상태공개는추가하지않으며8ms대기상수·세대/위상별분기는변경하지않는다.
3. 자원통과뒤동일시작두위상에서952의1920B·956의1024B·957의2048B선행map과951/911/952/957보호조건을검증한다. 이후952–957연속표시간격·957마지막ACK가함께개선되는지판정한다. DMA진행알림하나가전체map완료를의미하지않는경계를검증해야한다.
