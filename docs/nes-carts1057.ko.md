# NES 1057

디버그판과 배포판 중 하나를 골라 SD 루트에 풀고 기존 sd2snes 설정과 게임 파일을 사용한다. 배포판에는 60초 종료 제한이 없다. CHR-RAM 게임은 기존 퀵메뉴에서 EXIT TO MENU를 선택한다. CHR-ROM 배포판은 게임 실행 중 본체 리셋을 누르면 STOP과 기본 메뉴 복구를 요청한다.

## 실기 확인

- 와이와이월드 2는 캐릭터를 선택하고 첫 스테이지에 들어가 조작한다. 1056 디버그판에서는 250화면을 공개한 뒤 PPU의 CHR 읽기 마감 오류로 중단됐다. 1057은 같은 타일 행의 양쪽 비트플레인을 한 번의 PSRAM 읽기로 확보한다.
- 배틀토드는 첫 스테이지에서 캐릭터와 지형이 함께 표시되고 이동하는지 확인한 뒤 퀵메뉴에서 종료한다. 원본은 상단을 비워 두고 14선까지 패턴을 쓴 뒤 15선 끝에 렌더링을 켠다. 수정 보드는 이 동안의 변경을 반영한다. 렌더링 뒤 패턴이 바뀐 화면과 복사가 끝나지 않은 화면은 거부한다.
- 문제가 재발하면 디버그판 종료 뒤 SD의 `nes-progress-debug1057.txt`, `nes-game-last-debug1057.txt`, `nes-frame-debug1057.bin`, `nes-stop-debug1057.bin`을 게임별로 복사한다. 마지막 파일은 STOP 시점의 주소와 PPU 상태, 캡처 거부 이력을 담는다.

## 검증과 다음 작업

1056 원본 보드·ARM 소스에서 `prepare_cart_stage1057.py`로 두 보드와 두 펌웨어를 만든다. `probe_cart_stage1057.py`는 로컬 ROM으로 첫 스테이지를 재생한다. `test_cart_stage1057.ps1`은 단일 Questa FLOAT 환경에서 첫 스테이지 CHR 읽기와 스냅샷 소유권·오류·STOP을 검사한다. `check_cart_stage1057.py`로 최종 링크의 시간 제한과 에뮬레이션된 SD·기본 메뉴 복구를 확인한다. 전체 FIT·STA와 핀 지연을 통과한 보드만 `package_cart_stage1057.py`로 묶는다.

1056 와이와이월드 2 로그에는 실패한 실제 주소가 없다. 첫 스테이지 읽기 재생과 실기에서 같은 조작을 했을 때의 성공 여부를 구분한다. 다음 배포판도 무제한 실행과 수동 종료를 유지하고, 디버그판의 측정 시간은 별도로 정한다.
