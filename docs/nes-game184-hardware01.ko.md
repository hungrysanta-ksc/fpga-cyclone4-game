# NES184 실기 결과 — 표시 개선, 장면별 부하와 입력 결함

## 관측 결과

사용자는 개선이 확실히 느껴지지만 아직 정상 플레이 수준이 아니며, 검은 배경의 커튼/오프닝보다 첫 레벨에서 표시가 더 느리다고 보고했다. 짧은 누름은 한 번, 길게 누르면 두 번 입력처럼 보인다는 의심도 함께 받았다. 후자는 사용자의 확정 판정으로 기록하지 않는다.

원본 두 TXT와 IMG_3698.MOV를 private `probes/nes-game184-hardware01/raw`에 보존했다. 영상은 66.77초, 약30fps 촬영이다. 4초 간격 개요에서 오프닝→월드맵→첫 레벨 이동/스크롤→64초 무렵 파일 메뉴를 확인했다. 이는 장면 지속과 메뉴 복귀의 증거이며, 정확한 게임 FPS 측정은 아니다. CRT 색띠/카메라 간섭은 화면 결함으로 세지 않는다. 오디오 트랙 존재와 SPC 상태만으로 음질을 승인하지 않는다.

전체 표시 완료율은 약5.78% 증가했지만 같은 입력/장면의 통제 시험이 아니다. 이를 큐의 인과적 향상률이나 순간 FPS라고 부르지 않는다. 패킷 수는 줄고 처리 바이트는 늘었다. 폴링을 포함한 바이트를 필수 픽셀 payload로 해석하지 않는다. 평균 약328.2ms/표시 완료이며 목표16.7ms에는 크게 못 미친다.

## 종료 및 전송 상태

BEGIN184 / END183 / COMMIT183 / ABORT0. 마지막 표시 generation278,59.93초. 마지막 producer generation280 수신 중60초 기한이 끝났다. `native_result=1`이 먼저 보존됐고 receiver21은 기한으로 중단된 수신의 부차 오류로 해석한다. 해당 거래의 raw 응답이 없어 별도 CRC 실패를 단정하지 않는다.

ROM/검증/STOP/sink/video 오류0. window sent=retired=9051, error0, flags2, 최종ACK1. 이는 MCU가 마지막으로 확인한 큐 상태이며 실시간 모든 시점의 완전한 기록은 아니다. STOP/base restore/menu prepared296130ms 및 영상의 파일 메뉴를 확인했다. `screen_error=169`는 기존 정의대로 SPC A9 결과다.

## 장면별 부하 해석과 다음 성능 작업

장면 차이라는 추정은 타당하다. 실제1815 송신기는 동일 word 반복을 압축하고 SNES는 이전 화면과 바이트 비교 후 변경 부분을 복사한다. 반복이 적고 변한 타일/스크롤/스프라이트가 많은 장면은 같은 방식으로 저렴하게 처리되지 않는다. 그러나 현재 누적 계측에는 장면별 payload·raw 행 수·표시 시간이 없으므로 첫 레벨 부하를 특정 mapper나 raw7 하나로 확정하지 않는다.

새 큐의 정상 동작을 바탕으로 **패킷마다 기다리는 미세 조정에서 벗어나, 재전송하는 화면 데이터와 직렬 처리 시간을 줄이는 작업**을 이어간다. 이미 구현된 반복 압축·CHR240/224B 묶음·SNES 로컬 차등·정적 raw map을 다시 구현하지 않는다.

1. 현재 실제 생성물에서 목적 WRAM/VRAM bank와 마지막 표시 세대의 수명을 고정한다. MCU 이전 전체 프레임 캐시는 RUN 여유1232B에 들어가지 않는다. 이미 존재하는 SNES 두 WRAM 이미지 및 FPGA 저장소 활용을 먼저 검토한다.
2. 차등 전송은 기준 세대 일치와 미변경 바이트 상속을 함께 구현한다. 미전송 바이트가 오래된 비활성 bank에 남아 있어도 되는 것으로 가정하지 않는다. 기준 불일치·reset·raw 전환에는 전체 재구축, 실패 시 기존 표시 유지, 최종 SEAL ACK 후 소유권 전환을 유지한다. 해시 일치만으로 픽셀 동등성을 승인하지 않는다.
3. 수신/변환/전송/표시 중 겹칠 수 있는 구간을 실제 소유권 기준으로 분리한다. 현재 `consumed()`는 MCU 상태만 IDLE로 바꾸며 FPGA를 새로 시작시키는 명령이 아니다. 함수 순서만 앞당겨 성능 개선을 주장하지 않는다.
4. 기존 raw7 낙관 wire 하한18.667ms는 CPU·수신·대기 제외에도16.7ms 초과다. 전체 처리 예산과 실제 SMB3 첫 레벨을 기준으로 채택하고, 같은184/044 재시험·새 seed FIT·긴 부팅 모델 반복을 하지 않는다.

## 입력 문제의 구체적 진전

마지막16개 입력 이력에는 `B|UP|LEFT`와 NONE이 반복된다. 물리 버튼 누름 시각이 없으므로 이 로그만으로 고장을 확정할 수는 없다. 하지만 코드 점검 후 실제 SNES 실행 코드와 에뮬레이터 자동 패드 읽기로 같은 종류의 값 누락을 재현했다. [입력 수정 후보와 검증](nes-pad185-contract.ko.md)에 원인·범위·초기 fixture 실패를 구분해 기록했다.

입력 후보는 다음 성능 시험판에 결합할 준비를 하며, 지금 입력만을 위해 별도 실기 재시험을 요청하지 않는다. 우선순위는 여전히 약60fps 연속 화면/사운드→장기 플레이와 오류/실기 reset 로그→실기 입력 유지 품질이다. GBC164·세이브 SRAM·완료 archive 및 MMC4/5/state/mute/frameskip 요구를 보존한다.
