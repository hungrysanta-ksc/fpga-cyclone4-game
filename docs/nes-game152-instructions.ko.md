# NES152 — 버튼 갱신 개선과 PPU 오류 주소 확인

같은 SMB3 게임으로 진행한다. **이번 판은 입력 갱신을 개선하고 PPU 오류의 실제 요구 주소를 추가한 시험판이다.151의 PPU 오류 원인은 아직 해결되지 않았다.** 오류 검사를 유지하므로 다시 조기 종료할 수 있다.

## 설치

1. 전원을 끄고 SD의 현재 `firmware.stm`을 별도 백업한다.
2. ZIP의 `01-GAME152-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. `firmware.stm`과 `fpga_n152.bi3`는 **62/DC 식별**의 한 쌍이다. 이전 파일과 혼용하지 않는다.
3. 메뉴에서 **`NES GAME 152.nh1`**을 실행한다.0바이트 표식이며 확장자를 바꾸지 않는다. 실제 ROM은 `sd2snes/nes/game152.nes`다. ROM 포함 개인용 ZIP을 공개하지 않는다.

## 한 번의 게임 시험

- 표식 실행→첫 게임 화면→메뉴 복귀 시간을 측정한다.151은 첫 화면까지 사용자 약3분50초·로그3분53초였다. 적재 방식은 같으며 이번에 로딩 속도를 개선한 것은 아니다.
- 화면이 나오면 메뉴 복귀까지 촬영한다. 로딩 전체 영상은 필요 없다. 버튼을 누를 때 버튼 이름을 말하면 영상과 입력 관찰을 연결할 수 있다.
- 제목의 플레이어 선택 화면에서 Start를 누르고 뗀다. 월드맵으로 넘어가면 방향키, 스테이지 진입 A, 게임 내 이동·점프 A·B를 차례로 확인한다. 각 버튼은 약0.2~0.5초 누르고 확실히 뗀다. 어느 화면에서 어떤 버튼이 반응했는지 함께 알려준다.
- 화면을 유지하는30 vblank 동안 입력을 매 vblank 전달한다. 기존 약0.5초 입력 간격은 줄었지만 전체 화면 DMA와 다음 프레임 대기 중에는 수집 공백이 남는다. 아주 짧은 탭의 완전한 전달을 보장하지 않는다.
- 화면 자체는 여전히 약0.5초씩 유지한다. 거친 갱신·짧은 검정 구간은 예상되는 제한이며60fps 시험이 아니다. 입력 반응도 다음 표시까지 늦게 보일 수 있다.
- RUN은 최대 약60초이며 PPU 오류가 발생하면 조기 종료한다. 같은 판을 반복하지 말고 최초 결과를 전달한다. 실행 후 **총7분**이 지나도 메뉴로 돌아오지 않으면 전원을 끄고 남은 로그를 전달한다.7분은 관찰 상한이며 자동 타임아웃이 아니다.

## 전달 자료

전원을 끈 뒤 `/sd2snes/nes-progress-152.txt`, `/sd2snes/nes-game-last-152.txt`, 영상, 위 시간과 메뉴 복귀 여부를 전달한다. 새 오류 문맥의 최상위 bit63이1이면 하위25비트는 실제 PPU 요구 주소다. 처리 중 주소는 별도로 유지한다. 사용자가 직접 해독할 필요는 없다.

소리·저장·부드러운 표시·전체 버튼의 실기 정상 여부는 미완료다. CRT 촬영 대각선 띠는 제외한다. 정상 사용으로 돌아갈 때는 전원을 끄고 `02-RESTORE044-SD-ROOT` 안의 내용을 복사한다. 기존044/GBC 재시험 보고는 요구하지 않는다.
