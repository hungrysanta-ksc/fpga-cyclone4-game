# MMC907의 OAM 순서를 보존한 201B 사전 조립

실기 기준은 MMC907을 유지한다. C가 기존 캐시의 두 위상에서 첫 패킷과 SEAL의 절대 시각을 모두 앞당겼지만, 위상 1에서 기존 16B 선행 DMA를 놓쳤고 공개가 한 VBlank 앞당겨진 화면은 없었다.

## 측정 기준

모험도 4 후반 캡처 3408–3436을 MMC907 보드 모형과 기존 65816 표시 ROM으로 재생했다. 마지막 화면은 재생 세대 912다. 두 시작 위상에서 기존 OBJ 캐시와 빈 OBJ 캐시를 각각 비교했다. 화면 906부터 912까지 여섯 표시 간격을 합산하고, 같은 시작 시각에서 마지막 65816 ACK와 ARM의 첫 유효 E0를 각각 비교했다. SPI 시간에는 2.625MHz 전송과 기존 실기 로그에서 구한 드라이버 비용이 포함된다. 이 결과로 새 실기 FPS를 추정하지 않는다.

세 ARM 최종 링크 모두 OAM과 section 5의 기존 발행 순서를 사용한다. A는 기존 441B 작업 버퍼에 201B·240B 본문을 미리 조립한다. B는 201B의 고정 헤더까지 준비하고, 직전 bulk 서비스가 끝난 뒤 실제 시퀀스를 채운다. E1 CRC는 원래 송신 경로에서 계산한다. C는 이미 연속인 CHR 마지막 192B를 그대로 사용한다. compact인 경우에는 그 뒤에 테이블 첫 9B만 붙이고, 원본 CHR인 경우에는 바로 이웃한 9B를 사용한다. 남은 240B는 첫 패킷 발행 뒤 준비한다. 세 링크 모두 플래시 한도는 212,992B다.

## 마지막 240B 수락부터 SEAL 수락까지

MMC907 기준값이다. 시각은 마지막 240B를 65816이 수락한 순간부터 측정했다. 표의 위 세 행은 동일한 시계의 연속 구간이고 아래 두 행은 65816이 그 시간 동안 병행한 작업이다.

| 세대 912 · 기존 캐시 (ms) | 위상 1 | 위상 2 |
|---|---:|---:|
| 240B 수락 → SEAL SPI 시작 | 0.0005 | 0.0351 |
| SEAL 187B SPI 시작 → 큐 도착 | 0.6198 | 0.6198 |
| 큐 도착 → 65816 SEAL 수락 | 0.0238 | 0.0634 |
| **전체** | **0.6440** | **0.7182** |
| 240B 수락 → 해당 패킷 검사·복원·반환 완료 | 0.3770 | 0.3753 |
| 그중 SEAL SPI 전송과 겹친 시간 | 0.3765 | 0.3402 |

SEAL 송신 전 이 구간에 E0 조회는 두 위상 모두 0회였다. SEAL이 큐에 도착했을 때 240B는 이미 반환됐다. 187B 자체의 전송은 약 0.570ms이고 나머지 약 0.050ms는 모델에 반영한 드라이버 비용이다. 65816 명령 관측에서 헤더·범위 확인을 거쳐 literal 복원 경로에 도달한 시각은 +0.1893 / +0.1891ms, WRAM DMA 기동 명령은 +0.2175 / +0.2173ms, 복원 후 accepted 경로는 +0.3238 / +0.3217ms였다. SEAL 패킷의 자체 독립 검사는 **SEAL 수락 이후** 진행된다. 두 실행의 명령 관측 훅이 원본 MMC907의 SPI 시각, DMA 범위, 화면 및 ACK를 바꾸지 않았는지 네 조건에서 대조했다.

빈 캐시에서는 같은 240B가 훨씬 먼저 도착한다. MMC907의 240B 수락 → SEAL 수락은 31.219 / 31.201ms이고, 마지막 OBJ는 240B 수락보다 27.788 / 27.727ms 뒤에 준비됐다. SEAL SPI 전까지 두 위상 모두 E8을 99번 조회했고, 구간에 걸친 E8 버스 점유는 10.809 / 10.785ms였다. E0는 각 22회, 약 2.403ms였다. 이 시간들은 타일 생산과 겹친다.

## 발행 시각과 화면 결과

각 칸은 위상 1 / 2 순서다. 마지막 ACK 차이는 **65816이 쓴 최종 ACK**를 같은 재생 시작 시각에서 비교한 값이며 양수는 늦어진 시간이다.

| ARM 링크 | 기존 캐시 OAM 수락 → 201B 발행 (ms) | 빈 캐시 OAM 수락 → 201B 발행 (ms) | 기존 캐시 마지막 ACK 차이 (ms) | 빈 캐시 마지막 ACK 차이 (ms) |
|---|---:|---:|---:|---:|
| MMC907 | 0.539 / 0.576 | 0.523 / 0.498 | 기준 | 기준 |
| A · 본문 사전 조립 | 0.558 / 0.538 | 0.543 / 0.496 | +0.035 / +0.006 | 0 / −0.018 |
| B · 고정 헤더도 사전 조립 | 0.601 / 0.532 | 0.517 / 0.552 | +0.023 / +0.006 | 0 / +0.005 |
| C · CHR 192B 직접 사용 | 0.576 / 0.545 | 0.540 / 0.555 | +0.023 / −0.010 | −0.007 / −0.018 |

기존 캐시에서 MMC907의 0.539 / 0.576ms 중 E0·E8 공유 SPI 점유는 약 0.219 / 0.222ms다. C의 첫 201B 발행은 공통 시작 기준 0.195 / 0.025ms 앞당겨졌고 SEAL 수락도 0.152 / 0.070ms 앞당겨졌다. 위상 1에서는 OAM 수락이 0.232ms 먼저 일어나 OAM을 기준으로 잰 간격은 오히려 늘었다. 네 링크 모두 여섯 표시 간격 합이 기존 캐시에서 15 / 15, 빈 캐시에서 20 / 20 VBlank였다.

선행 DMA를 세대·목적지·바이트 범위별로 대조했다. 세 후보 모두 기존 캐시 위상 1의 세대 912에서 16B가 SEAL 후 전송으로 밀렸다. B는 위상 2의 세대 907에서 두 캐시 상태 모두 192B가 추가로 밀렸다. 마지막 화면의 빈 캐시 선행 DMA 496B는 세 후보 모두 유지했다. 여덟 화면의 RGB, ordinary와 bulk 각각의 패킷 순서·바이트, WRAM 쓰기 범위와 최종 ACK identity·CRC가 기준과 일치했다. 원본에 PC 관측만 추가한 네 실행은 원본과 시각까지 일치했다.

Flash는 A 212,852B, B 212,900B, C 212,848B였다. 세 링크에서 SRAM D0 송신 네 경로, 입력 CRC 거부, 제한 시간 STOP과 base·메뉴 복귀 경로를 통과했다. 재생 장면의 patch는 1행이어서 별도로 행 수 0–7의 실제 링크 송신을 독립 복원하고 최종 ACK 거부 시 이력 보존도 확인했다.

다음 비교는 빈 캐시에서 240B 수락 뒤 약 27.7ms 남은 마지막 OBJ 공급을 우선한다. 기존 캐시의 SEAL 쪽은 187B 전송과 겹치는 검사를 줄여도 확보할 수 있는 시간이 작다. SEAL 전송 자체를 줄일 때는 독립 coverage·identity와 선행 DMA가 보존되고 실제 공개가 앞당겨지는지가 채택 기준이다.

## 재현

1. `python tools/nes_section910.py patch` 후 MMC907 전체 ARM 빌드 절차로 각 패치를 해당 후보의 `link`에 링크한다.
2. `guards <게임 ROM>` 및 `replay <MMC907 작업 경로> <1|2>`로 최종 링크를 검사한다. A는 기본값, B는 `--framed`, C는 `--direct`를 사용한다. 각 위상에서 `--cold`도 시험한다. `replay --reference`는 원본에 관측만 추가한다.
3. `rows <ref|payload|framed|direct>`로 patch 행 수 0–7과 최종 ACK 거부를 시험한다. `python tools/analyze_nes_section910.py <MMC907 작업 경로> analysis/section910-results.json`으로 동일 작업량·보호 조건·일정을 비교한다. [네 조건의 상세 계측](../analysis/section910-results.json)
