# 601. 같은 화면에서 이미 읽은 CHR 바이트를 다시 쓸 수 있는가

954에서 직전 화면의 실제 요청과 겹치는 바이트는 272개 중 64개다. 반면 같은 화면을 캡처할 때 PPU가 읽은 값을 보관하면 272개 모두 돌려줄 수 있었다. 그래도 입력·출력 버스가 이전 표시 후 약 27 ms까지 필요해, 두 시작 위상 모두 다음 표시 기한을 놓쳤다. 실기 기준은 MMC577이다. [600 시간축](nes-wire600-results.ko.md) · [53세대 결과](../analysis/snoop601-verification.json)

## 어느 시점에 값을 알 수 있는가

905–957의 mapper 적용 후 물리 CHR 주소와 값을 Mesen PPU fetch, collector 입력 strobe, ROM 원본에 맞췄다. 두 시작 위상의 실제 op7 payload와 순서에서 plan의 행 마스크·두 plane·대체 tag를 역추적하고, 패딩까지 포함해 출력 값과 대조했다. 매 세대 두 위상이 같은 바이트를 같은 순서로 요구했다. 952와 954에서는 각각 논리 주소 48개가 서로 다른 물리 주소로 매핑됐다. 재사용 키에는 불변 CHR 내용의 epoch와 물리 주소를 쓴다.

| 요청 바이트 수 | 952 | 954 |
|---|---:|---:|
| 실제 tile ROM 읽기 | 208 | 272 |
| 직전 표시에서 읽은 값 / 905부터 직전까지 표시에서 읽은 값 | 96 / 96 | 64 / 64 |
| 905부터 직전까지 PPU 캡처에서 관측된 값 | 96 | 64 |
| 현재 캡처에서 관측된 값 | 208 | 272 |
| 4 KiB 통합 저장소에서 충돌로 잃는 바이트 | 32 | 16 |
| 같은 용량을 BG·OBJ로 나눴을 때 잃는 바이트 | 0 | 0 |

954의 208 B는 관측된 이전 표시·캡처 이력에 없다. 기존 일정에서 직전 EA와 다음 입력 시작은 같은 시각이다. 직전 최종 ACK 후 EA까지 두 위상에 물리적으로 280/270개의 ROM 기회가 있다고 계산되지만, 그 구간은 아직 이전 소유자에게 속한다. 미래 주소를 아는 것으로 간주하거나 그 슬롯을 선행 읽기 이득으로 계상하지 않았다. 입력 시작부터 60 Hz 마감까지는 11/22회만 가능하다. 이력만 쓰면 197/186회가 더 필요하다. 현재 캡처에서 이미 전송된 데이터를 받아 두는 방식은 추가 ROM 요청이 없다.

## 독립 RTL 시험과 Quartus Lite 비용

NES 클록에서 BG·OBJ 각각 128개 라인에 물리 tile tag, 16개 바이트의 유효 비트, lane별 값을 저장했다. 테스트는 매 세대 시작 때 디렉터리를 비웠다. 53세대의 788,598개 표본, 5,616개 조회에서 RTL은 독립 주소 모델과 일치했다. 적중 4,360개, 미적중 1,256개였다. 905와 906은 각각 1,424개 요청 중 332개가 미적중했고, 957에서도 144개 중 16개가 미적중했다. **전체 대체에는 기존 ROM miss 경로가 필요하다.**

같은 인덱스의 다른 태그, 쓰지 않은 lane, BG·OBJ 분리, STOP 직후 응답 차단, epoch 변경 및 쓰기 도중 불변 자격이 사라지는 경우를 같은 Questa 시험에서 확인했다. STOP 뒤 256클록 동안 디렉터리를 비운 뒤 재개한다. 캡처와 조회는 포트를 나눠 쓰며 한 표본을 저장하는 데 2클록이 든다. 재생한 strobe 간격이 이 조건을 만족했다. 실제 보드에서 물리 주소·plane·ROM 데이터가 같은 strobe에 걸리는지와 miss drain은 연결 전 확인 대상이다. 캐시는 DMA 수락, 독립 검사 또는 최종 ACK를 발행하지 않는다.

Quartus Lite의 EP4CE15F17C8 단독 MAP은 166 LE, 조합 126개, FF 69개, RAM 38,400 bit였다. 4,096×8 데이터와 256×22 디렉터리가 M9K 5개에 해당한다. MMC577 보드 여유는 148 LE와 M9K 5개다. 단순 추가 예산에서 18 LE를 넘고 RAM 여유를 모두 쓴다. 기존 cache192의 로컬 자원에는 ROM 요청·응답과 취소 처리도 들어 있어 그 전체를 순절감으로 빼지 않았다. 전체 보드 FIT·STA와 실제 최종 ACK 개선은 미검증이다.

## 표시 시각과 다음 판정

600과 동일한 입력 시작·이전 표시 및 8프레임 부팅 ROM 중재 기록을 썼다. 두 장면의 모든 조회가 적중하고 조회·검사·추가 DMA 시간이 0일 때, 표시 전 버스 완료와 다음 허용 VBlank를 대조한 낙관 일정이다. 실제 보드 FPS로 환산하지 않는다.

| 세대 · 시작 위상 | 기존 600 표시 간격 | 모두 적중 시 표시 간격 | 이전 표시→버스 완료 | 버스 완료 뒤 VBlank 대기 |
|---|---:|---:|---:|---:|
| 952 · 1 | 33.404 ms | 31.481 ms | 26.613 ms | 4.868 ms |
| 952 · 2 | 33.366 ms | 31.443 ms | 26.764 ms | 4.678 ms |
| 954 · 1 | 33.972 ms | 31.894 ms | 27.017 ms | 4.878 ms |
| 954 · 2 | 33.977 ms | 31.900 ms | 26.985 ms | 4.915 ms |

현재 경계에서 ROM 재읽기를 모두 없애 얻는 표시 차이는 1.92–2.08 ms다. 60 Hz 기한 전에 **버스 완료만** 맞추려 해도 9.946–10.350 ms를 더 줄여야 한다. 필수 조회를 포함한 wire 하한도 952에서 47 B, 954에서 120 B 초과다. 다음은 MMC577·600의 D1 수신, ARM 복원, D2 credit 반환을 같은 호출 순서로 분해하고, 다음 블록 수신을 어느 시점에서 현재 복원과 실제로 겹칠 수 있는지 판정하는 일이다. 조회·반환 비용까지 포함해 두 부족분이 함께 줄어드는 후보가 나오기 전에는 캐시 보드 통합을 보류한다.

## 재현

`tools/check_nes_snoop601.py prepare`에 geometry230의 capture02·stim05 상위 디렉터리, output489의 audit01 plans, 561 두 위상 추적의 상위 디렉터리, 577의 선택 RTL 디렉터리 및 일치하는 개인 ROM을 지정한다. `sim`은 생성된 stim.tsv와 단일 Starter FLOAT, `map`은 Quartus Lite quartus_map을 사용한다. `summarize`는 prepare·sim·map 출력, 561 추적과 service509의 rom03 calendar를 대조한다. ROM·원본 PPU 추적·생성 자극은 배포하지 않으며, 저장소 결과에 입력과 선택 RTL·로그 해시를 기록했다.
