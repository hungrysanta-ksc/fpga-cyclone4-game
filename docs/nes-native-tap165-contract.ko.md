# 실제 PPU와 CHR 재사용 캐시 연결

부드러운 실기 화면을 위한 **수신 데이터 연결 단계**다. [독립 캐시](nes-native-chr165-contract.ko.md)에 실제 CPU/PPU/MMC3 실행 중 읽은 데이터를 넣는다. SNES가 새 방식으로 화면을 그리는 단계까지 완료한 것은 아니다. 설치 후보는164다.

## 연결과 기존 동작 보존

`tools/nes_native_tap165.py`는 동결된164 근거의 manifest 및 입력 파일 해시를 확인한 뒤 별도 폴더를 만든다. 원본은 변경하지 않는다. NES의 `chr_addr`를 관측 출력으로 내보내고 `nes_probe`를 거쳐 `nes_live_joint`의 캐시에 연결한다. 추가 부분을 역으로 제거하면 세 파일의 원래 바이트가 정확히 복원되는지도 검사한다. 기존 CPU/PPU/매퍼/ROM 서비스 제어 로직은 바꾸지 않는다.

| 캐시 입력 | 연결 |
| --- | --- |
| 논리 주소 | PPU의 현재 `chr_addr[13:0]` |
| 물리 주소 | 같은 에지의 `ppumem_addr` |
| 데이터 | PPU에 실제로 전달하는 `ppumem_din` |
| 수신 시점 | `tap_ce && ppumem_read`, 논리 주소가 패턴 영역일 때 |
| 유효성 | `rom_ppu_valid && !rom_fault`, 기존 캐시의 물리 CHR 범위/바이트 오프셋 일치 검사 추가 적용 |
| 리셋 | 기존 코어의 NES 도메인 `reset` |

ROM 서비스의 요청·조기 예측 주소는 아직 받은 데이터가 아니다. 서비스의 현재 주소 태그 일치/응답 우회가 보장하는 valid만 사용한다. 등록된 디버그 출력 `out_ppumem_addr`는 한 클록 늦으므로 현재 데이터와 섞어 쓰지 않는다. 이것이164 글리치의 확정 원인이었다는 뜻은 아니다.

freeze/query/release 및 모든 응답은 **NES 클록 도메인**이다. `nes_live_joint`에는 향후 생산자/전달부를 위한 포트만 추가했다. 기존 보드 top의 SNES 호스트 신호를 직접 꽂으면 안 된다. 호스트 CDC와 전송 세대 관리가 아직 없다. 보드 이미지로 합성하거나 설치할 대상으로 승인하지 않는다.

## 검사 범위

선택한 test03은20프레임 부팅과 동결 조회/해제를 통과했다. 컴파일 오류/경고0, 시뮬레이션 오류0/경고42다. 경고에는 기존 혼합언어 코어의 미연결 관측 포트/폭·시각0 초기화 경고와, 이 벤치에서 사용하지 않는 `history_flags157` 출력 관련2건이 포함된다. 경고 없는 전체 보드 검증으로 표시하지 않는다.

| 관측 | 결과 |
| --- | --- |
| 동결 전 CHR 수신 | 182196건, 같은 에지의 원본 ROM 바이트 일치 |
| 동결된512슬롯 | 완성14·부분1·미수집497 |
| 캐시 조회 | BG16+OBJ32바이트 ×512슬롯 =24576건 일치 |
| 조회까지 실제 코어 읽기 | CPU ROM951470건·PPU ROM184972건, 수신 바이트 불일치/ROM 오류 없음 |
| 이미 수집된 슬롯의 물리 뱅크 교체 | 이 부팅 구간에서는0건. 별도 캐시165의 뱅크 교체 검사 근거를 유지 |

부분 타일1개가 확인됐지만 그것이 실제 표시할 화면에 필요한 타일인지는 아직 필요 집합과 대조하지 않았다.14/512를 화면 완성률로 계산하지 않는다. 첫 시도는 선언 순서 컴파일 오류, 두 번째는24프레임에서24576조회 일치 후 과도한 뱅크교체/완성타일 필수조건에 실패했다. 둘 다 보존했다. 최종 시도는 실제 발생한 읽기와 타일 완성도를 기록한다. 캐시/어댑터 RTL은 시도 사이에 바꾸지 않았다.

[검증 결과](../analysis/native-tap165-verification.json)를 기준으로 한다. 실제164 CPU·PPU·MMC3·ROM 서비스와 READ16/168MHz,70ns 메모리 모델에서 목표 SMB3를 부팅한다. PPU/CPU 상태를 강제로 지정하지 않는다. ROM은 시험벤치가 미리 메모리에 넣으며 MCU 적재·버튼 입력·첫 레벨 플레이는 포함하지 않는다.

캐시의 내부 accept를 그대로 정답으로 쓰지 않고 실제 PPU 주소/수신 바이트에서 별도 태그와16바이트 마스크를 누적한다. 동결 뒤512슬롯의 BG16/OBJ32바이트를 원본 ROM과 대조한다. 조회 중에도 CPU/PPU는 계속 실행한다. 기존 로직 보존은 추가 관측의 역변환 및 연결 방향으로 확인한다. 수신을 끈 전체 부팅 대조 실행 옵션은 있지만 이번에는 실행하지 않았다. 이는 임의 게임/입력/실기 타이밍 전체의 동등성 증명은 아니다.

실행 검사는 `nes_probe`와 동일한 연결문으로 캐시를 붙인 경계다. 생성된 `nes_live_joint`는 컴파일하지만 PLL/MCU/SPI/전체 보드까지 인스턴스화하여 실행하지 않는다. 기존 독립 캐시의 모든 타일/오류 검사를 다시 반복하지 않는다.

## 다음 구현

1. 배경·스프라이트의 실제 필요 타일과 팔레트/OAM/스크롤·래스터 상태를 같은 화면 세대로 묶는다. 현재 캐시 전체 중 완성된 슬롯 수는 **그 화면에 필요한 타일의 준비율이 아니다**.
2. 일부 행만 읽힌 타일과 같은 논리 슬롯의 중간 뱅크 교체를 처리한다. 현재 캐시는 슬롯당 한 물리 태그만 보존한다. 미완성/이전 세대 타일을 준비 완료로 내보내지 않는다. 부족 데이터는 ROM 적재 시 준비 또는 기한이 보장되는 공급 경로로 해결한다.
3. 38M9K 픽셀 버퍼를 대체할 생산자·호스트 CDC·SNES 소비자를 연결한다. 전체56M9K를 이미 사용하는164에 캐시를 단순 추가해 배치하지 않는다. 실제 패킷 크기·VRAM/DMA 예산과 변경 경계만 검사한 뒤 SMB3 플레이로 평가한다.

호스트 연결에서는 현재 단일 NES 클록 조회를 그대로 바이트별 왕복 핸드셰이크로 감싸기 전에 SNES 읽기 응답 기한을 계산한다. 데이터 RAM은 쓰기/읽기 포트를 분리할 수 있지만 메타데이터는 이미 NES 쪽 read-modify-write에 두 포트를 사용한다. 세 번째 호스트 읽기 포트나 읽기 클록의 조합 mux를 당연히 허용되는 것으로 가정하지 않는다. 메타데이터 복제 또는 동결 후 일괄 전달 등 한 가지 구체적인 구조를 선택해 자원·소유권·읽기 기한을 함께 확인한다.

기존 사운드·STOP·메뉴 복귀를 유지한다. 이 연결은 렌더링 속도 개선을 위한 구현이며 FPS 향상이나60fps 달성을 뜻하지 않는다. 영상·사운드가 조작 가능한 수준이 된 다음60초 제한 해제/오류·본체 리셋 시 안전 로그/장시간 입력 유지를 진행한다.
