# 911의 첫 32B OBJ 반환과 공개 마감

## 목표

978 returned와 같은 두 시작 위상에서 911의 첫 BG, 낮은 OBJ 슬롯, 다음 비연속 OBJ 슬롯을 한 번에 발행한다. 908 공개, 909 선행 DMA 624B, 910 캡처를 유지하면서 911 표시 간격을 1 VBlank로 줄이고 912 최종 ACK도 앞당길 수 있는지 확인한다.

## 작업내용

905–912 연속 실행에서 원래 ARM의 슬롯 기록 지점을 계측했다. 계측을 켜도 두 위상의 이벤트, 입력 레코드, 표시 일정, 타일 생산 기록은 978과 바이트 단위로 일치했다. 911 입력에서 OBJ 44개와 raster 224줄을 독립 복원해 각 슬롯이 요구하는 태그와 가시 행 마스크를 확인했다.

- 슬롯 89(태그 6511, 마스크 0x0F)는 OBJ 2·3에서 나타나고, 우선순위 0에서 이미 확정된다. 두 위상 모두 planner 진입 후 3.956ms였다.
- 슬롯 86(태그 6264, 마스크 0xF0)은 OBJ 23의 우선순위 7에서 처음 확정된다. 두 위상 모두 5.750ms였다. 먼저 보낼 수 있는 두 슬롯의 준비 시각은 이 낮은 슬롯이 결정했다.
- 두 슬롯 선행 발행은 첫 E9에 zero BG와 86·89를 넣고 두 번째 E9에 90–100과 END를 넣는다. 89가 비연속 슬롯임을 확인한 FPGA가 86의 뱅크를 닫을 수 있다. 실제 wire는 118B 한 번에서 27B와 99B 두 번으로 늘었다. 기존 CRC·credit 처리를 거치며 타일은 16B BG, 32B OBJ, 384B OBJ로 유지된다. 발행 조건에서 세대나 태그 상수를 사용하지 않는다.
- 대조 후보로 준비된 슬롯 전체를 먼저 보내는 방식, 44개 OBJ의 우선순위 순서를 136B의 재사용 영역에 한 번 작성하는 방식, 우선순위 색인과 두 슬롯 선행 발행을 결합한 방식도 각각 전체 링크했다.

## 성과

같은 캡처에서 실제 ARM과 65816을 실행했다. 표의 수치는 위상 1 / 위상 2 순서다. 첫 수락은 planner 진입부터 보드 RTL이 첫 E9를 수락하기까지이며, 최종 ACK 변화는 부팅부터의 절대 시각을 978과 비교했다.

| 후보 | 첫 E9 수락 (ms) | 909 선행 DMA (B) | 911 간격 (VBlank) | 밀집 여섯 간격 | 912 ACK 변화 (µs) | Flash 초과 (B) |
|---|---:|---:|---:|---:|---:|---:|
| 978 | 6.468 / 6.468 | 624 / 624 | 2 / 2 | 13 / 13 | 기준 | 0 |
| 두 슬롯 선행 발행 | 6.037 / 6.037 | 592 / 624 | 2 / 2 | 13 / 13 | −8.38 / 0 | 160 |
| 준비된 슬롯 전체 발행 | 6.319 / 6.319 | 592 / 624 | 2 / 2 | 13 / 13 | +14.71 / +23.09 | 88 |
| 우선순위 색인 | 6.336 / 6.336 | 592 / 560 | 2 / 2 | 13 / 13 | +14.71 / +8.38 | 84 |
| 색인과 두 슬롯 선행 발행 | 5.915 / 5.915 | 592 / 592 | 2 / 2 | 13 / 13 | −8.38 / 0 | 244 |

두 슬롯 선행 발행은 첫 E9의 실제 RTL 수락을 planner 기준 0.431ms 앞당겼다. 연속 실행에서 32B 뱅크 반환은 0.455 / 0.583ms, 후속 384B 반환은 0.267 / 0.394ms 빨랐다. E9가 1회 늘어 점유 시간은 0.409→0.484ms였다. 911의 SEAL은 VBlank 44의 240 / 241선에서 238 / 238선으로 앞당겨졌지만 업로드 준비는 258 / 259선이었다. 실제 65816은 VBlank 45에서 DMA하고 두 위상 모두 244선에 공개했다. 908은 양쪽 모두 VBlank 38의 245선에 공개했고 910 캡처 여유는 0.097 / 0.228ms였다.

우선순위 색인은 슬롯 86 확정을 5.628ms까지 앞당겼다. 색인만 적용해도 업로드 준비가 양쪽 256선에 도착해 246선 마감을 넘겼다. 네 후보 모두 여덟 화면의 RGB, map 범위·값, plan 레코드 내용, 스크롤 선행 순서를 대조했다. STOP과 잘못된 SEAL을 주입했을 때 마지막 정상 화면이 보존되고 상태 0xE4·0xE0가 반환됐다. 링크된 메뉴 복귀 코드는 별도의 제어 시험으로 확인했다. 실기 기준은 MMC966, 개발 기준은 978 returned로 유지한다.

978과 두 슬롯 후보는 같은 ARM 거래·ROM 허가·뱅크 반환 일정을 보드 RTL에 재생하고 905–911의 CHR RAM을 이어서 확인했다. 911의 두 E9는 실제 바이트별 시점에 수락됐다. RTL에서 첫 32B 준비는 0.438 / 0.458ms 빨라졌고 마지막 384B 준비는 0.361 / 0.323ms 늦어졌다. ARM이 실제 조회한 911의 E8 네 응답은 두 위상 모두 일치했다. 905·906에서는 기준과 후보 모두 모델 응답과 RTL 응답이 달랐고, 978 위상 2는 910에서도 한 건 달랐다. 따라서 912 ACK는 공유 포트 모델을 포함한 연속 실행값으로 비교했다. 이 실험에서는 보드 실측을 하지 않았다.

두 슬롯을 먼저 보낸 경우 SEAL 수락부터 업로드 준비까지 양쪽 모두 1.308ms가 걸렸다. 여기에 타일·팔레트·OAM을 포함한 잔여 DMA 1,680B가 남았고, 실제 다음 VBlank의 첫 DMA 시작부터 공개까지는 1.192 / 1.194ms가 더 걸렸다. 반환에서 얻은 약 0.5ms가 그대로 공개 시각으로 이어질 수 없는 이유다.

## 후속작업

다음 시험은 911에서 슬롯 86 하나를 먼저 발행하는 것보다 SEAL 수락 뒤 업로드 준비까지의 약 20선을 먼저 분해한다. 246선까지 남는 시간에 실제 잔여 DMA까지 들어가는지 상한을 먼저 확인한다. 동시에 909에서 선행 DMA 32B가 빠진 첫 원인을 비교한다. 두 조건을 동시에 만족할 여지가 있을 때만 Flash 한도 212,992B 안에서 구현한다.
