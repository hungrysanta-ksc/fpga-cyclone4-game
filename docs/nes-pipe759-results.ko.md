# 759 · E1 전송 중 다음 map 범위를 쓰는 일정

## 목표

753의 동일 작업량에서 2,048·3,008 범위의 생산과 E1 전송·65816 소비를 겹친다. 두 위상에서 956 공개 뒤 첫 VBlank 248선 안에 여덟 번째 map을 반환하고, 952·957의 SEAL 전 1,536B 단일 DMA와 BG→map→OBJ 순서, 908·E8·OBJ 마감, 957 표시 2 VBlank와 밀집 간격·최종 ACK 단축을 함께 판정했다.

## 작업내용

- 두 192B 범위의 BG slot과 최종 셀 값을 ARM이 기존 순서로 확정한다. OBJ를 만들기 전의 OAM 작업공간 384B에 셀을 담고 실제 E1 SPI DMA 대기 루프에서 한 번에 한 셀씩 map을 쓴다. 이 루프는 셀 사이마다 기존 CF86·DMA 오류를 검사한다. tile 조회·공유 SPI 재진입은 하지 않는다. 보이는 셀만 쓰며 생략 위치는 이전 map 값을 유지한다. 행 재사용은 임시 셀까지 읽고, 해당 범위를 발행할 때와 BG가 끝날 때 남은 쓰기를 완료한다.
- 오른쪽 페이지를 확정한 순서대로 제안하고 각 E1의 queue credit과 tile 우선권, 독립 receipt 검사와 최종 ACK는 기존 경로를 거친다. 직렬 대조군은 같은 생산·발행 변경을 적용하되 DMA 대기 중 셀 쓰기를 끈다. split은 DMA당 최대 32셀을 진행하고 E1 반환 직후 나머지를 써서 65816의 수락→소비 시간도 사용한다. ordered는 같은 분할 쓰기를 원래 페이지 발행 순서와 기존 751 ROM에 연결한다.
- 65816 병합 후보는 빈 큐에서 선택한 DMA descriptor가 대상 map 페이지 시작($5800/$D800)이고 아직 1,536B 미만이면 다음 head를 기다린다. 정식 SEAL 후 남은 sparse map은 기존 최종 업로드로 실행한다. 비교 후보는 기존 751 정적 ROM을 그대로 사용한다.
- 시작 클록 7,288,416 / 7,467,100에서 905–957을 리셋부터 연속 실행했다. ARM 명령 시간은 CPI 2, ROM 경쟁은 고정 달력, 공유 SPI는 2.625MHz와 MMC502 드라이버 보정치를 사용한다. map DATA E1은 링크된 DMA 대기 루프를 실행하고 테스트 모델이 양쪽 NDTR 및 TC를 제공한다. 설정·복구 보정 시간을 wire 앞뒤로 반분하고, DMA가 할 일이 없으면 다음 IRQ 또는 완료까지 대기를 진행한다. 이 모델은 새 실기 주기 측정값이 아니다.

## 성과

각 칸은 위상 1 / 위상 2 순서다. 반환 지연은 첫 VBlank 248선 끝을 기준으로 하고, 마지막 ACK 차이는 같은 시작 위상의 753을 기준으로 한다.

| 후보 | 마지막 map 반환 지연 (ms) | 957 표시 (VBlank) | 952–957 평균 간격 (ms) | 957 최종 ACK 차이 (ms) | ARM Flash (B) |
|---|---:|---:|---:|---:|---:|
| 753 기준 | 14.646 / 14.932 | 3 / 3 | 49.910 / 49.912 | 0.000 / 0.000 | 212,960 |
| 직렬 대조 | 14.402 / 14.496 | 3 / 3 | 49.963 / 49.966 | 50.237 / 16.952 | 213,940 |
| E1 중 쓰기 | 14.425 / 14.377 | 3 / 3 | 49.961 / 49.968 | 33.587 / 0.319 | 213,960 |
| E1 중 쓰기 + 병합 대기 | 14.201 / 14.503 | 4 / 4 | 58.029 / 58.029 | 165.955 / 116.032 | 213,960 |
| 분할 쓰기 + 병합 대기 | 14.356 / 14.623 | 4 / 4 | 58.029 / 58.030 | 165.955 / 99.397 | 214,008 |
| 분할 쓰기 + 기존 발행 순서 | 15.464 / 15.652 | 3 / 3 | 49.912 / 49.912 | 33.289 / 33.274 | 213,536 |

E1 중 쓰기는 위상 1의 2,048 범위와 위상 2의 3,008 범위에서 실제로 쓴 114B 전부를 앞 패킷의 SPI 전송과 겹쳤다. 분할 쓰기에서는 위상 1의 2,048이 E1 중 38B, 앞 패킷의 65816 수락→반환 중 0B였다. 위상 2의 3,008은 각각 38B·64B였다. 직렬 대조에서는 두 범위 모두 SPI 중 0B, 65816 소비 중 114B였다.

오른쪽 페이지의 첫 세 패킷(576B)을 BG 완료 전에 보내면 다음 tile과 왼쪽 페이지 패킷이 나머지 960B 앞에 끼었다. 952와 957 모두 DMA가 두 번으로 나뉘었다. 65816에서 병합을 기다린 두 후보는 오른쪽 페이지 전체가 SEAL 뒤로 밀려 957 최종 대기도 1회가 됐다. 기존 발행 순서를 복원하면 두 프레임의 1,536B 단일 선행 DMA와 957 최종 대기 0회를 지켰고 OBJ DMA는 252 / 255선에 시작했다. 이때 908 표시 간격은 2→3 VBlank, E8은 양쪽 모두 기존 마감을 넘겼다.

모든 ARM 후보가 Flash 한도 212,992B를 544–1,016B 초과했다. BSS는 19,796→19,812B, 새 병합 ROM은 물리 여유 61→34B이고 정상 부팅은 1.659ms 늘었다. FPGA는 기존 707D를 사용했다. 753을 유지한다.

## 마감 예산

753에서 957 planner 진입부터 첫 248선 끝까지 6.631 / 6.580ms가 있다. 기존 제출 순서로 마지막 map 이전에 통과하는 E1·E9 거래는 17건, 2,449B다. E0·E8 조회, ARM 생산, 65816 검사, 다른 모든 대기를 제외해도 2.625MHz 순수 wire가 7.464ms이므로 0.832 / 0.884ms 부족하다. 기존 드라이버 보정과 마지막 패킷 한 건의 실제 수락→반환만 더하면 부족분은 2.259 / 2.311ms다. 후속 tile 거래 순서나 패킷 형식을 바꾸면 예산도 다시 계산해야 한다.

753에서 957의 1,536B MDMAEN부터 288B OBJ MDMAEN까지 두 위상 모두 15,252 master clocks가 걸렸다. 같은 간격으로 OBJ를 256선 끝까지 시작하려면 map MDMAEN이 248선 끝보다 약 0.202ms 빨라야 한다. map 반환 후 실제 MDMAEN까지의 선택·설정 시간도 더 필요하다.

## 보호 검사와 재현

- ARM 링크에서 불완전한 credit, 잘못된 receipt·최종 ACK, STOP 시 커밋 차단, 메뉴·base 복귀 함수를 확인했다. 신규 범위 발행 경로에서는 불완전한 세 행, tile 우선권, enqueue 실패, 중복 발행도 검사했다.
- 비동기 레지스터 모델에 변경한 실제 SPI 드라이버를 연결했다. 활성 DMA 작업 중 CF86 실패를 넣은 477개 위치(32셀 제한 후보는 32개), 드라이버 guard 오류 907건, 바이트 오류 2,590건과 정상·경계 794건을 통과했다. 새 정적 ROM은 정상 부팅과 복원 바이트 손상 거부를 통과했다. 두 위상에서 병합 후보의 실제 선행 128B DMA에 STOP 전·중, 새 head, 오래된 identity를 주입했다. STOP·손상은 956 RGB를 유지하고 최종 ACK를 막았고, 새 head는 DMA에 우선해 53번째 화면까지 커밋했다.
- `tools/prepare_nes_pipe759.py <753 arm-prefix/src> <overlay> [--serial|--split|--ordered]`와 `tools/build_nes_mmc479_arm.ps1`로 ARM 전체를 링크한다. `tools/build_nes_join759.py ../probes/nes-static751/sharedfast ../probes/nes-reuse635/client04 ../probes/nes-pipe759/client-join`으로 결합 ROM을 만든다.
- `tools/run_nes_pipe759.ps1 -Variant pipe|serial|join|split|ordered -Phase 1|2 -Game <ROM>`으로 실행한다. 원본은 758에서 753과 발행·DMA·화면·최종 ACK가 일치한 계측 대조를 사용했다. `tools/check_nes_pipe759.py`의 DMA 오류 검사, `tools/check_nes_rows757.py`의 row 검사(ordered는 `check_nes_credit752.py --policy mapobj`), `check_nes_longrun694_boot.py`와 `check_nes_static751.py --source 20800 --size 128`의 receiver 검사를 수행한다. `tools/analyze_nes_pipe759.py --temp <trace root> --probe ../probes/nes-pipe759 --out analysis/pipe759-verification.json`으로 결과를 비교한다. ## 후속작업

753의 957 planner 진입 이후 첫 248선까지, 기존 거래와 마지막 수락→반환 비용만으로도 2.259 / 2.311ms가 부족하다. 다음에는 오른쪽 페이지 8개 패킷을 독립 검사가 가능한 짧은 전송으로 묶을 때 줄어드는 실제 SPI 시간과 65816 복원 비용을 먼저 계산한다. cold·부분 수신·STOP 뒤 전체 복구와 1,536B 단일 DMA, 908·E8·OBJ 마감을 포함해 두 위상 모두 이 부족분을 넘길 때 연속 일정을 실행한다.
