# SDREPORT084 저장 재시험

083에서 HW083000.TXT가 0바이트이고 STEP 3에 멈춘 실기 결과를 반영했다. 사용 중인 FAT 항목이 많은 모형에서 동일한 현상을 재현했으며, 파일 생성 전에 읽기 전용 공간 탐색을 수행하도록 수정했다. **사용자 SD의 실제 원인이 확정되거나 실기 저장 성공이 확인된 것은 아니다.** 화면 문구도 좌우 최소3글자 여백 안으로 옮겼다.

## 복사와 실행

1. 콘솔 전원을 끄고 SD의 게임·세이브를 포함한 독립 백업을 보관한다.
2. `FXPAK-SDREPORT084-TRIAL.zip`의 **`test/sd2snes/firmware.stm` 하나만** SD의 `/sd2snes/firmware.stm`에 복사한다. test와restore 폴더를 함께 복사하지 않는다. 기본 FPGA·메뉴·게임·세이브는 교체하지 않는다.
3. 전원 직전부터 TV 전체 화면을 촬영한다. 펌웨어가 자동으로 진단을 실행하므로 브라우저에서 별도 파일을 고르지 않는다. 분해·LED 관측·PC USB 연결은 필요 없다.
4. `SDREPORT084 STORAGE TEST`가 표시되는지 확인한다. 최종 결과가 나오면 촬영하고 전원을 끈다. 결과가 없으면 **전원 후90초까지 한 번 관측하고 전원을 끈다.** 이 시간은 사용자 관측 종료 기준이며 CPU/클록 고장까지 자동 종료시키는 watchdog 보장이 아니다. 자동 메뉴 복귀는 없다.
5. 새 `/HW084000.TXT`–`/HW084999.TXT`와 영상을 전달한다. 0바이트도 그대로 보관한다. 파일이 없으면 마지막 표식과 함께 알려준다. 기존 HW083 파일은 삭제하거나 이번 결과로 대신하지 않는다.
6. 전원이 꺼진 상태에서 ZIP의 **`restore/sd2snes/firmware.stm`**을 같은 SD 위치에 복사해 정상044로 복원한다. 메뉴와 GBC 실행 결과도 확인한다.

복원본은 사용자가 준 마지막 정상044와 동일하다. HW002 성공 펌웨어와 구분하며, 없는 `firmware.before-sdinfo072.stm`을 다시 요구하지 않는다. firmware 해시 일치와 실제 복원 성공은 별개다.

## 화면 읽기

| 마지막 표식 | 다음에 시도하는 일 |
| --- | --- |
| 표식 없음 | firmware 적용·MCU 시작·내장mini·표시 범위 |
| `STEP 1A INIT SD` | SD 초기화 |
| `STEP 1B MOUNT FAT` | 첫 FAT mount |
| **`STEP 1C FIND SPACE`** | 읽기 전용 FAT 공간 탐색. 아직 새 TXT를 생성하지 않음 |
| `STEP 2 CREATE TXT` | 새 이름 생성. 디렉터리 확장도 여기 포함 |
| `STEP 3 WRITE CONTENT` | 실제 내용 쓰기 |
| `STEP 4 SYNC` / `STEP 5 CLOSE WRITE` | 반영 / 쓰기 닫기 |
| `STEP 6 OPEN READ` / `STEP 7 VERIFY BYTES` / `STEP 8 CLOSE READ` | 재열기 / 전체 비교 / 읽기 닫기 |
| `TXT SAVED + READBACK OK`, `Save code: 0` | 저장·재읽기 검사 성공. 3072바이트 TXT와 화면을 함께 회수 |
| `TXT SAVE FAILED`, `Save code: 2`–`7` | 파일시스템 또는 내용 검사 실패. 코드·파일명·실제 파일을 함께 회수 |

1A/1B/1C는 각각1초,2–8은 각각0.5초의 표시 기회를 제공한다. 합계6.5초 외에 부팅·SD 접근 시간이 든다. 마지막 표식은 다음 작업의 예고이며 정확한 고장 코드나 작업 완료 증거가 아니다. RESET을 유지하는 동안 화면이 꺼지거나 남아 있을 수 있다. 공유 오류가 발생하면 추가 화면·SD IO를 막으므로 최종 실패 문구가 없을 수 있다.

코드2=생성 실패,3=1000개 이름 모두 사용 중,4=쓰기 실패/짧은 쓰기,5=sync 실패,6=쓰기 close 실패,7=재열기·크기·내용·읽기 close 실패다. 파일만3072바이트여도 최종 화면·복원 성공까지 뜻하지 않는다. `tools/check_sdreport084.py`는 회수 TXT의 전체 기대값을 비교한다.

## 이번 수정의 경계

- 탐색은 기존 부팅/초기화60초·100만poll 예산 안에서 수행한다. writer10초·10000poll과 하위 native timeout은 그대로다. 예산 재시작·오류 초기화·SD 재초기화·불확실한 쓰기 재시도를 추가하지 않았다.
- 3072바이트에 필요한 연속 빈 클러스터와 여유1개를 찾고, 성공한 경우에만 RAM의 할당 시작 힌트를 바꾼다. FAT를 예약하거나 기록하지 않는다. 충분한 총 여유 공간이 있어도 조각난 공간만 있으면1C에서 멈출 수 있다. 이는 카드 전체 용량 부족 판정이 아니다.
- 루트 디렉터리 확장은 별도 FatFS 할당 경로다. 디렉터리가 가득 찬 조건에서는2에서 제한에 걸릴 수 있고, 확장이 힌트를 바꾸면3에서 다시 탐색할 수 있다. 모든 파일시스템 배치의 쓰기 성공을 보장하지 않는다. 이를 구분하는 경계 시험도 보존했다.
- 단일 전체경로809검사·실제1초 timer5·인과대조5·ARM 호출 순서 및 기존13입력 해시를 검증했다. 실제 SD timing·화면 가독성·저장·정상 복원은 이번 사용자 시험으로 확인해야 한다. NES/CF68 설치·게임 구현 완료와는 별개다.

대응 소스는 `FXPAK-SDREPORT084-SOURCE.zip`이다. 바이너리·개인 입력은 공개 Git에 올리지 않으며 SD 자동 설치도 하지 않는다.
