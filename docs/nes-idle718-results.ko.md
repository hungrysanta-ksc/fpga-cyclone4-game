# 718 map DMA 진행·다음 입력·ordinary 발행 경계

## 목표

716B의 지연 descriptor 생성과 717의 패딩 drain 제거를 보존한다. map DMA와 다음 입력 수신에 맞춰 OAM·HDMA를 발행해 951 공개 ≤246선, Flash ≤212,992B, 두 위상의 밀집 표시 간격·957 마지막 ACK 동시 개선을 검증한다. STOP·독립 검사·최종 ACK·메뉴 복귀, 911 마감·952 표시 3회·957 최종 대기 0회·7블록 수신을 유지한다.

## 작업내용

두 후보 모두 기존 717 전체 소스에서 시작했다. BG/OBJ descriptor 계산, plan 발행, 패딩 drain 제거, 압축과 독립 검사는 그대로다. ABI·FPGA·65816·정적 RAM 변경은 없다.

- **A — 유효 입력 작업을 빌리는 방식:** 실제 warm map 꼬리를 drain한 후, 다음 입력을 최대 7블록까지 받으며 매 블록 뒤 E0의 CRC·ACK identity·DMA 진행을 확인한다. 진행이 보이거나 입력이 없거나 7블록을 소진하면 ordinary를 발행한다. 기존 OAM의 반복 drain과 팔레트 뒤 고정 대기를 제거했다.
- **B — 실제 DMA 진행을 기다리는 방식:** 717의 원래 입력 callback과 팔레트 정책은 유지한다. map 꼬리의 실제 DMA 진행 신호가 올 때까지 checked drain과 한 블록 입력 수신을 반복한다. 빈 D0는 DMA 완료로 취급하지 않는다. 기존 poll limit·STOP·guard를 적용하며, 무응답이나 callback 누락은 실패 처리한다. OAM 반복 drain은 제거했다.

A는 `nes_native_runtime165.c`와 `nes_native_sink165.c`, B는 `nes_native_sink165.c`만 바꿨다. 두 후보의 정상판·장시간판을 각각 전체 링크했다. 재생은 같은 시작 시각 7,288,416/7,467,100, 실제 링크 Cortex-M4/65816, CPI2/84MHz, 공유 SPI·IRQ·2bulk·측정 기반 ROM 허용 달력이다. 전체 게임 CPU/PSRAM RTL 공동 실행이나 실기 FPS 측정이 아니다.

## 성과

**두 후보 모두 미채택이다.** 원본 선택은 707D·기존 694/704 ARM·기존 694 65816으로 유지한다. 716B·717의 계산/대기 절감 코드는 후보로 보존한다.

| 전체 링크 | 장시간 Flash / 여유 | 정상 Flash / 여유 | 정적 RAM 증가 |
|---|---:|---:|---:|
| 717 | 212,956 / 36B | 213,000 / 8B 초과 | 0B |
| 718A | 212,808 / 184B | 212,852 / 140B | 0B |
| 718B | 212,848 / 144B | 212,892 / 100B | 0B |

A는 `wait634` +36B, `packet_wire` −100B, `nes_sink212_seal` −84B로 합계 148B를 줄였다. 다만 삭제한 반복 대기가 기존 DMA 기회를 만들던 효과까지 제거하므로 이 공간을 기능적으로 공짜인 회수분으로 취급하지 않는다.

### A: 입력이 없으면 DMA 기회도 생기지 않음

| 원본 대비 | 위상 1 | 위상 2 |
|---|---:|---:|
| 951 공개선 | 248 | 248 |
| 952–957 VBlank 합계 | 18 →18 | 18 →18 |
| 밀집 951–955 평균 변화 | −0.035144ms | −0.019053ms |
| 957 마지막 ACK 변화 | −16.683590ms | −16.015349ms |
| 717 대비 마지막 ACK 변화 | **+49.194982ms** | **+50.357327ms** |

951에서 map 꼬리 앞뒤로 빌린 입력은 모두 빈 D0였다. 약 0.102ms의 조회 동안 READ/POP과 DMA 진행이 없었고, OAM·HDMA는 다시 빈 큐 기회를 차지했다. 수신 credit은 감소시키지 않았지만 유효 입력으로 그 간격을 채우지는 못했다.

원본 대비 약 16ms의 마지막 ACK 이득만으로 채택하지 않는다. 717에서 2 VBlank로 줄었던 908/934/940/943이 다시 늘어났고, cold 906 단축을 제외해도 717보다 끝이 약 49–50ms 늦어졌다. 계산 절감 코드 보존과 전체 일정의 이득 보존은 다르다.

|---|---:|---:|
| 951 공개선, 717→B | 248→236 | 248→236 |
| 951 선행 map / tile DMA, 717→B | 256/0→1,792/16B | 256/0→1,792/16B |
| 951 표시 간격 | 3 VBlank 유지 | 3 VBlank 유지 |
| 952–957 VBlank 합계 | 18→18 | 18→18 |

| 957 마지막 ACK 변화 | −0.033896ms | **+16.574172ms** |
| 717 대비 마지막 ACK 변화 | +65.844675ms | +82.946847ms |

**951의 DMA 기회와 공개선은 회복했다.** 그러나 표시 VBlank 수를 줄이지는 못했다. 이때 다음 입력 callback은 10/11회, 합계 1.017/1.121ms였지만 확인된 새 블록은 0개였다. E0 조회 비용도 별도로 들었다. 입력이 없는 순간에 이를 유효 계산과 겹친 시간으로 계산하지 않는다.

911에서는 원본 2 VBlank가 B에서 **두 위상 모두 3 VBlank**로 늘었다. 직전 표시→SEAL 수락은 원본 28.974/29.234ms에서 39.458/39.348ms로 늦어졌다. 그러나 수락 주사선은 71/69, 업로드 진입은 96/95선이어서 기존의 `load≤189 && upload≤214` 검사만 보면 통과했다. **한 VBlank 늦어진 낮은 주사선 값을 마감 회복으로 세면 안 된다.** 이번 판정은 원본 대비 911의 VBlank 회차도 검사한다. 과거 검증값을 덮어쓰지 않고 새 비교에서 이 빈틈을 보강했다.

### 기능·안전·범위

후보별 53화면×두 위상, **총 212화면**을 완료했다. 원본과 map·tile·plan 순서/바이트·53화면의 최종 픽셀을 대조했다. 두 슬롯, 독립 검사·최종 ACK와 952 표시 3회·957 최종 대기 0회·7블록 수신은 두 후보에서 유지했다. 911은 A에서 유지, B에서 회귀했으며 951 공개 조건은 B만 통과했다.

A의 새로운 입력/E0/CRC/identity/STOP 22조건과 실제 seal 호출 7조건, B의 DMA 신호/빈 입력/STOP/최종 ACK/신호 없음/기존 poll 한도 9조건 및 입력 credit 9조건을 통과했다. 각 바이너리에서 기존 bulk 정책 24조건, slot 18조건, plan grant 7조건, runtime 16조건, 메뉴 준비·해제 5조건과 marker 4조건도 통과했다. 각각의 후보 패킷으로 기존 65816의 STOP 4조건, 같은 65816의 장시간 종료 service 12조건을 실행했다. endpoint·입력·pad 주입 범위의 시험이며 새 실기 메뉴 복귀를 뜻하지 않는다.

전체 SPI는 원본 대비 A **+2,660/+2,616B**, B **+12,836/+13,968B**다. 정적 RAM은 같지만 관측 stack은 A **−84/+116B**, B **−100/0B**로 달랐다. 관측값은 최악 stack 상한 증명이 아니다. 입력·진행 조회를 공짜로 처리하거나 Flash 절감만으로 전체 자원 개선을 주장하지 않는다.

첫 A 빌드는 sandbox의 `subst` 권한에서 중단되어 기존 승인된 빌드 절차로 새 디렉터리에 재실행했다. 초기 STOP 단위시험은 세 번째 READ/POP 직후 STOP이 다음 E0보다 먼저 차단하는 것이 정상인데 E0 3회를 기대했다. 실제 우선순위에 맞게 기대를 2회로 고치고 실패 근거를 보존했다. 정상/장시간 소스 전체가 같다는 임시 검사는 원래의 60초 watchdog 차이 때문에 실패했으며, 각 판본의 원본과 recipe를 따로 대조해 새 변경 범위를 확인했다.

보드와 SDC가 바뀌지 않았으므로 새 Quartus 실행은 없다. 707D의 전체 Lite FIT 15,322LE·962LAB·56M9K, setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다. 외부 IO sign-off·707D의 실기 확인 범위는 확대하지 않는다.

## 후속작업

1. **707D·기존 ARM·65816을 유지한다.** 716B 계산 절감, 717 패딩 drain 제거, B의 실제 map DMA 확인 경계는 재사용 가능한 미채택 후보다. B에서 951만 회복했다고 전체 속도 개선으로 채택하지 않는다.
2. 951과 911을 함께 대조한다. map의 수락/receipt/실제 DMA와 OAM·HDMA의 남은 전송·소비 비용을 같은 VBlank 마감에 배치해, 기다려도 SEAL 마감을 넘기지 않는 조건부터 정한다. 기존 E0는 **DMA를 했다는 이력**이지 **지금 DMA를 시작할 수 있다는 허가**가 아니다. 입력이 없을 때의 무조건 진행 대기와 반복 D0/E0 조회는 일반 정책으로 채택하지 않는다.
3. 908/934/940/943의 716B 이득을 보존해야 한다. 기존 OAM 반복 drain을 지우기만 하면 회귀하므로 실제 DMA 기회를 대체할 때만 삭제한다. B의 정상판 여유 100B는 해당 코드의 기존 100B를 복원하면 소진되는 산술 예산이다. 복원·공유·추가 조건을 한 바이너리로 링크하기 전에는 여유라고 가정하지 않는다. 새 상태 공개가 필요하다면 ARM/65816/FPGA의 교체·삭제 예산을 먼저 확정한다.
4. 주사선과 VBlank 회차를 함께 보호한다. 두 위상 911 원본 2회, 951 ≤246선과 간격 무회귀, 952 3회, 957 최종 대기 0회 및 밀집 18회 미만·평균·마지막 ACK 동시 개선을 유지한다. 고정 지연, generation/시작 위상별 상수, 검사 완화로 맞추지 않는다.

재현은 `prepare_nes_idle718.py`(A) / `prepare_nes_progress718.py`(B), 기존 `build_nes_mmc479_arm.ps1`, `test_nes_observer717.py`, `analyze_nes_idle718.py --variant a|b` 순서다. 정확한 인자는 archive의 `probe/run.ps1`·`probe/run-b.ps1`에 보존한다. 관측기와 실행 정책은 717의 대조 검증된 범위를 유지했다. 원본 게임 ROM·라이선스는 Git/ZIP에서 제외한다.

이번 후보의 설치본은 없다. 다음 실기 전달은 새 파일명의 60초판·장시간판, RESTORE 제외, 5–40초·40–55초 비교 정책을 유지한다.
