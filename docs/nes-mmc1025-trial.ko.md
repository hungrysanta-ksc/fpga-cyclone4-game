# MMC1025 별의 커비 후반 표시 계측판

## 실기 실행

1. ZIP의 `MMC1025-KIRBY-60SEC-SD-ROOT` 폴더 내용을 SD 루트에 복사한다. MMC1024에서 사용한 커비 일본판 ROM을 `sd2snes/nes/mmc1025.nes`로 복사한다.
2. 전원을 켜고 **NES MMC3 1025.nh1**을 선택한다. MMC1024의 두 실기에서 ROM 검증과 표시 진입까지 약 7분 25초가 걸렸다. 게임이 시작되면 무입력으로 60초 자동 종료와 메뉴 복귀를 기다린다.
3. SD의 `sd2snes`에서 아래 네 파일을 PC의 `1차` 폴더에 보관한다. 같은 전원 시작 조건으로 한 번 더 실행하고 두 번째 로그는 `2차`에 보관한다. 중단되면 재실행 전 생성된 파일을 보관한다.

- `nes-progress-mmc1025.txt`
- `nes-budget-mmc1025.txt`
- `nes-game-last-mmc1025.txt`
- `nes-frame-mmc1025.bin`

## 측정과 판독

MMC1024 후반의 화면당 출력·최종 ACK는 1차 24.18ms, 2차 27.62ms였다. 기존 23행 조건을 만족하는 상세 기록은 두 회 모두 0개였다. MMC1025 일반 실행은 게임 시작 후 [30, 60)초를 400ms씩 나누고 각 구간에서 처음 표시가 완료된 입력 화면을 저장한다. 구간 배정에는 해당 화면의 처리 시작 시각을 사용한다. 전체 FPS는 실제 공개 시각으로 [1, 30)초와 [30, 60)초를 집계한다.

각 표본에는 BG·OBJ·변경 map 행 수, tile·묶음 수, 직전 공개·SEAL·마지막 DMA 쓰기·공개·최종 ACK 시각이 있다. 세대·token 검사를 통과한 32B 헤더만 사용한다. 최대 75개 표본을 저장하고 55–57.5초와 57.5–60초에는 조건을 만족한 첫 표본의 ARM 패킷 발행·누적 credit 관측도 보관한다. 32B 조회 위치와 횟수가 바뀌므로 이번 판의 FPS 차이는 계측 영향도 포함한다.

`tools/compare_nes_kirby1025.py 1차.bin 2차.bin`은 같은 400ms 구간끼리 비교한다. 다섯 작업량이 일치하는 쌍과 근접한 쌍(BG ±8, OBJ·map 각각 ±1, 타일·묶음 수 일치)을 구분한다. 결과에는 각 구간의 두 값과 차이가 들어간다. 마지막 DMA 쓰기만으로 DMA 전송과 VBlank 진입 대기를 각각 확정할 수는 없다. 원본 화면의 동일성과 개별 DMA 포트도 이 계측 범위 밖이다.
