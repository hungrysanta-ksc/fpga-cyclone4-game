# NES169 — 큰 화면 변경을 비표시 VRAM에 준비한 뒤 전환

168 실기의 E3는 표시 중인 화면 변경량이 설정 예산5000을 넘었음을 뜻했다.169는 작은 변경의 기존 비교·DMA를 유지하고, E2(32명령 초과) 또는 E3일 때만 비표시 VRAM에 완성된 후보를 준비한다. ROM·CPU·PPU·매퍼 RTL, MCU 응답 검사,60초 제한은 바꾸지 않는다. 실기에서의 연속 화면·소리·플레이 품질은 다음 시험으로 판정한다.

## 소유권과 메모리 배치

단위는 SNES VRAM **바이트 주소**다. 두 슬롯의 최대 사용 영역은 서로 겹치지 않는다.

| 슬롯 | BG 패턴(최대16KiB) | OBJ 패턴(최대4KiB) | BG 맵(4KiB) | BG12NBA / OBSEL / BG1SC |
| --- | --- | --- | --- | --- |
| A | 0000–3FFF | 4000–4FFF | 6000–6FFF | 00 / 01 / 31 |
| B | C000–FFFF | 8000–8FFF | A000–AFFF | 06 / 02 / 51 |

BG 맵의 기존 크기 비트1과 타일 번호는 유지한다. 주소 단위와 레지스터 의미는 [SNES 개발 라이브러리의 레지스터 정의](https://github.com/alekmaul/pvsneslib/blob/master/pvsneslib/include/snes/background.h), [Anomie 레지스터 문서](https://github.com/gilligan/snesdev/blob/master/docs/snes_registers.txt)를 대조했다. 최종 화면은 실제65816 실행 결과로 비교한다.

WRAM7F의 기존32KiB 후보 두 개와 패킷 소유권은 유지한다.1032–103E는 이미 초기화되는 SNES 내부 메타데이터 영역으로 활성 슬롯·대상 슬롯·영역·오프셋·크기·원본 주소·대기 카운터에 사용한다.1072는 주소 계산 임시값이다. MCU RAM과 카트리지 세이브 SRAM은 추가 사용하지 않는다. 저장 데이터·GBC·164 복원본은 그대로 보존한다.

## 전환 절차

1. 기존 비교기에서 먼저 동일한 길이·정렬·후보 소유권을 검사하고 변경 명령을 만든다. 기존 예산5000과32명령 제한을 유지한다.
2. 명령이 준비되면 기존 활성 슬롯에만 작은 변경을 적용한다. E0/E1/E4와 잘못된 패킷은 기존 실패 경로로 종료한다.
3. E2/E3이면 표시하지 않는 슬롯에 BG·OBJ·맵 전체를 채운다. 한 번에 최대4096바이트, 각 청크는 새로운 vblank를 기다린 뒤 전송한다. 최대6청크이며 최초 화면의 큰 전체 적재는 기존 forced-blank 경로다.
4. 이 동안 기존 BG/OBJ/맵과 CGRAM·OAM·HDMA 테이블을 계속 표시한다. 마지막 전환용 CGRAM512바이트·OAM544바이트만 명령 두 개로 준비한다.
5. 다음 vblank에 CGRAM·OAM을 반영하고 BG/OBJ/맵 기준 주소, 스크롤, 후보 HDMA 포인터를 함께 전환한다. 이후에만 표시 완료 상태와 기존 세대·토큰 ACK를 반환한다.

4096+명령 비용96을 수용하지 못하는 작은 예산에서는 fallback을 시작하지 않는다. 최종 CGRAM/OAM 비용은1056+192=1248로 작다.5000을 올리거나 성공 응답을 위조하지 않는다. 새로운 여러 프레임 대기는 각 위상65535회 이하이며 매 반복 STOP·패드를 서비스한다. STOP 또는 대기 만료는 E4로 빠져나간다. 전송 도중 STOP이면 미완성 슬롯을 표시하거나 성공 ACK를 반환하지 않는다. MCU는 기존 guard·전체 시간 제한과 실패 후 정지·로그·메뉴 복귀를 유지한다.

## 검증 범위와 실기 목표

실제 C 생산자와65816 소비자를 파일 mailbox로 연결해 작은 변경·무변경, 큰 변경 후 반대 슬롯 재사용, 전송 중 STOP을 검사한다. 합성 장면은 적재된 타일 번호를 보존하고 우선순위·색상·스프라이트 위치를 변경한다. 이전 전체 업로드 방식으로 만든 독립 기준 화면과 픽셀을 비교하고, 준비 중에는 이전 화면을 유지하는지 검사한다. 이는 실제 SPI 속도·전기적 타이밍·60fps를 보장하지 않는다.

새 코드는 기존4096바이트 SNES 프로그램 ROM 안에 들어간다. 기존167의 배치 데이터 복사본에서 실제 생성 MIF를 변경한 뒤 Quartus CDB/ASM으로 재생성한다. RTL·배치·타이밍 자료는 보존하며 무변경 MAP/FIT를 반복하지 않는다. MCU는168에서169 파일명만 변경하고 전체 링크·RUN/IRQ 스택을 다시 확인한다.

이번 실기 목표는 첫 화면 이후 종료가 사라지고 SMB3 선택 화면·첫 레벨까지 진행되는지, 화면 전환 중 검정 구간이나 혼합이 보이는지, 사운드와 메뉴 복귀가 유지되는지 확인하는 것이다. 큰 변경에는 최대 여러 vblank의 준비 시간이 추가되므로 표시 지연 개선이나60fps를 완료했다고 주장하지 않는다. 장기 플레이와 입력 유지 검증은 연속 AV 확인 뒤 진행한다.

## 완료된 검사

- 정상 E2/E3 전환 각6회, 최대 크기6회, STOP 전 정상3회로 총21개 완료 화면1284864픽셀을 비교했다. 큰 전송 중 이전 화면 유지22프레임을 관측했고 첫 공개 후 forced blank와 vblank 밖 PPU 데이터 쓰기가 없었다.
- 최대 BG16KiB·OBJ4KiB·맵4KiB는6청크, 다시 작은 원래 화면으로 돌아오는 전송은3청크였다. 최대 크기 검사는 적법한 bulk DATA 패킷을 사용한 SNES 경계 시험이며 실제 MCU의 타일 단위 호출 속도 측정은 아니다.
- 전송 중 STOP에서는1청크 이후 E4 응답을 반환하고 완료 화면 수는3에 머물렀다. 후보 화면을 완료 처리하지 않았다.
- SNES 프로그램3154바이트/ROM4096바이트, MCU197308바이트, 추가 MCU 상태0바이트, RUN·IRQ 계산 후 여유1044바이트, 최대 TXT3966/4096바이트를 확인했다.167 RTL·배치·제약·타이밍 관련65개 파일은 동일하다.

실행 기록의 실패도 보존했다. test02는 적재되지 않은 타일 번호를 만들어 기준 픽셀 비교가 무효였으며 test03은 타일 번호를 보존했다. test03의 정상4경우는 통과했고 과거 세대15를 기대하던 STOP 검사만 수정해 stop04로 다시 실행했다. 최대 검사01에서는 PC의15초 대기보다 늦은22.4초에 정상 ACK가 저장됐다. PC 대기만60초로 늘린 maximum02에서 완주했으며 실기 제한은 변경하지 않았다. ARM 검사는 한글 절대 경로 출력 디코딩을 상대 경로로 수정했다. 구형100 빌더 후처리 대신168과 같은149 빌더의 현재 초기화 위치 검사를 적용했고, 결과 펌웨어 바이트는 동일했다. 이전 실패 원문은 덮어쓰지 않았다.
