# 951에서 팔레트·OAM 후반 여섯 패킷을 생략한 결과

**두 시작 위상 모두 목표 VBlank에 빈 큐를 활용한 map DMA가 들어갔다. 951 최종 ACK도 0.687 / 0.647 ms 빨라졌다. 그러나 950→951 표시 간격은 4 / 4 VBlank였다.** SEAL이 수신기에 도달했을 때는 세 번째 VBlank의 246번 검사선이 이미 3.100 / 3.670 ms 지난 뒤였다. 621을 유지한다. [기계 판독 결과](../analysis/bank633-verification.json)

## 무엇을 생략했나

625 tables-bg의 951에서 팔레트 네 패킷과 OAM 후반 두 패킷을 제거했다. 30개였던 head는 24개가 됐다. E1은 각각 344 B와 44 B 줄었다. 바뀐 OAM 앞 112 B는 원래대로 전송했다. 949의 최종 ACK에서 확정된 뱅크가 실제 951의 대상이고, 950의 표시 뱅크와 구분됨을 확인했다. 951 SEAL 수락 직전 대상 WRAM의 팔레트 512 B와 OAM 544 B 전부를 원본 패킷에서 독립 복원한 값과 비교했다.

생략 비용의 상한을 보기 위해 이 바이트들이 일치할 때 재생기가 수신 길이 두 개만 채웠다. 데이터 쓰기, 별도 재사용 명령, 검사에 따른 SNES 클록을 부과하지 않았다. 나머지 head는 순번을 다시 매겨 원래 65816에 넣었다. 네 칸 credit·새 패킷 우선·독립 map 검사·실제 DMA·최종 ACK를 거쳤다. 원래 SNES 바이너리와 STOP 경로를 그대로 사용했다. 부분 재사용의 실사용 인증·STOP 복구 비용은 이 상한에 포함하지 않았다.

## 두 시작 위상에서의 재생

각 칸은 위상 1 / 2 순서다. SEAL 수락은 **목표 VBlank의 246번 검사선 마감**을 0으로 한 ms이며, 음수는 마감 전이다. map 열은 해당 VBlank 안에서 마감까지 **완료된 빈 큐 DMA 명령**의 바이트만 센다. 각 경우에 905–951의 47장 RGB와 map 검사를 통과했다. 대조군은 원래 625의 전체 65816 이벤트와 클록까지 일치했다.

| 951 일정 | 마감까지 완료한 선행 map DMA | SEAL 수락 (ms) | 950→951 표시 간격 (VBlank) | 951 최종 ACK 차이 (ms) |
|---|---:|---:|---:|---:|
| 원래 625 | 0 / 0 B | +6.520 / +7.311 | 4 / 4 | 기준 |
| 여섯 head 생략, 나머지는 원래 도착 시각 | 0 / 0 B | +6.517 / +7.298 | 4 / 4 | 0 / −0.012 |
| 여섯 head의 준비·거래·소비를 모두 생략 | 1,152 / 1,152 B | +3.100 / +3.670 | 4 / 4 | −0.687 / −0.647 |
| 추가로 마지막 OBJ 뒤 남은 head도 E1 wire 시간만 부과 | 0 / 0 B | −1.958 / −1.771 | 4 / 4 | −0.250 / −0.247 |

세 번째 행은 생략한 각 PUSH와 직전 PUSH 사이의 **경과 시간 전체**를 차감했다. 여기에는 당시의 ARM 준비·polling·SPI·credit 대기가 함께 들어간다. 이렇게 3.407 / 3.623 ms를 돌려주고 남은 PUSH 간격을 보존했다. 여섯 head는 실제로 큐에 들어가지 않아 소비·ACK도 발생하지 않았다. 이 방식은 그 시각에 병행하던 일까지 무료로 처리하며, ARM의 준비 코드를 다시 실행한 측정과 구분한다. 네 번째 행에서는 마지막 OBJ 이후 나머지 ARM 준비와 E0·E8 등 비-E1 거래까지 무료로 두었다. 이 경우 큐가 채워져 목표 VBlank에 선행 map 기회가 사라졌다. SEAL을 앞당겼어도 업로드 진입은 마감 전 0.362 / 0.181 ms였고 실제 표시는 다음 VBlank였다.

## 빈 큐에서 실제로 수행한 DMA

세 번째 행에서 선행 map DMA가 시작된 네 번 모두, 그 시각까지 공급한 **모든 951 패킷의 소비 ACK가 이미 반환**돼 있었다. 검사선 직전 시작해 뒤에 끝난 명령은 마감 전 완료량에서 제외했다.

| 위상 | 첫 map DMA 1,152 B | 두 번째 map DMA 384 B | 마감 기준 두 번째 DMA 종료 |
|---|---|---|---:|
| 1 | 231→238번 선 | 246→248번 선 | +0.107 ms |
| 2 | 236→243번 선 | 251→253번 선 | +0.442 ms |

첫 DMA가 시작된 뒤 다음 패킷 공급까지 각각 0.229 / 0.445 ms가 남아 있었다. 앞선 256 B 선행 map DMA는 모든 경우에 한 VBlank 앞에서 동일하게 끝났다. 따라서 이번에 추가로 확보한 기회는 목표 VBlank의 두 DMA다. 1,536 B를 이전 VBlank로 옮긴 덕분에 실제 표시 VBlank에서는 양쪽 모두 242번 선에 화면이 공개됐다. 원래는 양쪽 모두 253번 선이었다.

## 결정 및 재현

여섯 패킷 생략만을 위한 실사용 ABI·FPGA·실기 전달본은 진행하지 않는다. 다음은 950이 표시를 기다리는 동안 951 입력 수신과 첫 BG 준비를 어디까지 겹칠 수 있는지, 950의 표시 뱅크·최종 ACK와 951의 입력 저장 공간을 분리해 검토한다. 3.100 / 3.670 ms는 SEAL **수락**을 마감에 맞추기 위한 최소 선행량이며, 그 뒤 독립 검사와 남은 DMA까지 마감 안에 넣어야 한다. 보드 준비 기준은 616B, 실기 기준은 MMC613이다.

아래에서 `$raw`는 625 원자료 루트이고 `$mesen`은 기존 Mesen 실행 파일이다. 기준 client는 624다.

```powershell
foreach ($phase in 1,2) {
  foreach ($mode in 'control','gap','collapse','wire') {
    python tools/replay_nes_bank633.py --trace "$raw/nes-seal625-tables-bg-$phase" --client ../probes/nes-raw624/client --mesen $mesen --mode $mode --out "$raw/nes-bank633-$mode-${phase}a"
  }
}
python tools/analyze_nes_bank633.py --root $raw --out analysis/bank633-verification.json
```
