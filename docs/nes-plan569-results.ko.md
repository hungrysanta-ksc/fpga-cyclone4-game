# 569 · 16비트 plan descriptor의 소유권과 수신 시점

**568 A와 직접 캡처를 결합하면 문제의 hold와 loader 대상 setup이 함께 양수가 된다.** 두 후보 모두 전체 보드 무회귀 기준에는 미달해 실기는 MMC558, 기존 설계 기준은 567 양방향 후보를 유지한다.

568 A의 85°C hold 위반은 봉인한 plan 배치의 길이 상위 비트를 host `held[14]`에서 NES `received[14]`로 복사할 때 발생했다. NES는 그 뒤 WAIT에서 같은 값을 `batch_length[9]`로 다시 복사했다. 569에서는 16비트 plan 제어 인스턴스에만 직접 캡처를 적용했다. `reader`, `batch_length`, `remaining`이 WAIT에서 값을 받고, mailbox의 요청·동기화·valid·ACK는 기존과 같은 에지에서 움직인다. 다른 mailbox는 기존 수신 형식을 사용한다.

## 언제 다시 쓸 수 있는가

1. host가 payload·CRC·개수·길이를 검사해 봉인한다. mailbox가 받을 수 있는 host 에지에 `{writer,count,plans}`를 `held`에 저장하고 반대 RAM 슬롯을 쓰기 시작한다.
2. NES 쪽은 동기화된 요청을 확인하고 한 에지 뒤 valid를 올린다. WAIT와 valid가 동시에 성립하는 NES 에지에 디코더가 값을 받는다. 이전 타일 실행이 늦으면 WAIT가 늦어져도 host는 같은 `held`를 유지한다.
3. 해당 배치 **마지막 plan의 CHECK**가 형식·길이·lease를 확인한 에지에만 descriptor ACK를 낸다. ACK가 host로 돌아온 후 다음 봉인된 슬롯을 넘길 수 있다. 마지막 타일의 실행 완료는 나중일 수 있다. 이때 타일 실행에 필요한 필드는 이미 디코더에 저장돼 있다.

954의 실제 E9 세 묶음만으로는 문제의 `count[9]`가 1이 되지 않는다. 별도로 32B plan 16개로 첫 슬롯을 정확히 512B 채웠고, 다음 슬롯에는 7B plan을 넣었다. 마지막 CHECK 뒤 첫 슬롯을 3B END로 덮어쓰면서 16번째 타일을 기다리게 했다. 기존 타일의 slot·tag·모든 대체 tag와 다음 plan, END, retire 수락·완료를 각각 확인했다.

두 시작 위상에서 송신 직후·WAIT 수신 직전·마지막 CHECK·ACK 뒤 타일 대기 중에 STOP을 걸었다. 각 지점에서 host·NES 클록을 따로 또는 동시에 멈추는 경우를 포함해 위상당 16건을 실행했다. 새 슬롯 0으로 복구했고 잘못된 CRC·길이/개수·lease도 검출했다. 조기 credit 결함을 넣은 첫 시험에서는 반환 직후의 짧은 구간을 놓쳤다. 마지막 CHECK까지 매 host 에지에서 두 번째 봉인과 첫 슬롯 소유권을 확인하도록 보강했다.

위상 1에서 512B 단어는 host 송신 뒤 228.997ns에 WAIT가 받았다. 마지막 CHECK에서 ACK를 낸 뒤 26.443ns에 다음 host 송신이 일어났다. 다음 7B 단어는 이전 타일이 대기 중이어서 `CAP → WAIT`에 NES 세 클록(139.686ns)이 걸렸다. 위상 2에서도 수락·출력 순서는 같았다. 이 시각은 디지털 시뮬레이션의 두 위상에서 관측한 값이다.

568 A와 비교한 85°C bit 14의 raw hold는 −2.106→+2.459ns이고 같은 비트의 raw setup은 +1.031→−4.196ns다. 16개 비트 전체의 최악 setup은 −4.604→−4.397ns였다. 실제로 WAIT가 늦게 샘플하는 사실과 원래 SDC의 setup·hold 판정은 구분했다. 타이밍 예외는 추가하지 않았다.

## 출력 일정과 검증 범위

실제 SPI endpoint에 954의 E8/E9를 공급했다. 두 기존 ARM 일정의 발행 시각과 ROM 경합에 따른 타일 완료 시각을 사용하고, SPI 종료 시점을 두 방식으로 실행해 응답 CRC·credit·23개 plan 및 END를 검사했다. 이 시험의 타일 완료는 외부 자극이다. 별도로 53개 화면을 실제 65816에서 재생했다. 위상별 9,464 / 9,462개 이벤트, RGB 화면 전체와 마지막 ACK가 568과 같았다. 952·957 모두 표시 간격 5 VBlank, 최종 준비 뒤 추가 대기 0회였다. 밀집 구간 평균은 83.157 / 83.121ms였다. 이 변경의 효과는 합성 비용과 타이밍으로 판정한다. 실기 FPS의 새 측정은 없다.

## 다음 판정

직접 캡처·두 슬롯·반환 시각 시험을 이 경계의 회귀 시험으로 둔다. 다음은 **568 A + 직접 캡처 조합에서 남은 85°C 메모리 setup과 host recovery**를 다룬다. 메모리 시작 허가 `ref_qualified → release_pipe[0]`는 −5.693ns, NES 고장 래치 `nf → plan.hcancel.release_reset[0]`는 −8.534ns다. 정상 허가가 실제로 필요한 첫 메모리 에지와, 클록이 멈춘 상태에서도 보장해야 할 고장 차단을 분리해 같은 배치에서 확인한다. 567 loader 조합은 168MHz 최악 setup 끝점이 reader 주소로 달라지는 대조군이다. loader·descriptor를 다시 바꾸기 전에 이 경로들의 실제 제어 경계와 전체 보드 판정을 확인한다.
