# NES165 장면 전송과 호스트 준비 확인

[공유 reader 보충](nes-native-memory165-contract.ko.md)에 **장면 전송기와 서로 다른 클록 사이의 양방향 mailbox**를 연결했다. 공통 장면의 위치/행/팔레트 조회, 실제 fill 모듈의 CHR 스트림, 호스트 준비 확인을 하나의 수명으로 묶는다. 생성된 부모 결선은 컴파일까지 확인했다. 실제 SPI/MMIO 접속부·MCU 수신 코드·SNES 게시·FPGA 배치·새165 SD 패키지는 아직 없다. 설치 후보는164다.

## 장면 단위 흐름

1. 유효한 공통 장면을 소유하면 BEGIN을 보낸다. 지원 상한은224행,1~32 BG묶음,128OBJ,128플레인 예외,1~2팔레트다. 범위 밖 장면은 해제하고 게시하지 않는다.
2. 기존 조회 kind0~5를 순서대로 읽는다. kind6의8192개 필요 비트는 호스트로 다시 보내지 않고 fill 내부에서만 조회한다.
3. fill을 시작하여 `generation / physical tile / lane / kind / byte`를 전달한다. 한 바이트의 호스트 수락이 늦으면 fill의 ready를 낮춘다. 기존65536클록 대기·262144클록 총 보충 상한을 유지한다.
4. 모든 조회와 CHR 보충이 성공하면 END에 레코드/CHR바이트 개수를 싣는다. 이는 완료된 데이터 묶음이며 **아직 표시 승인이 아니다.**
5. 호스트가 순서·장면 번호·크기·필요 타일·입력 범위를 검사하고 PREPARED 또는 REJECT를 돌려준다. 전송기는 같은 generation의 PREPARED를 받는 시점에도 원본 소유권/valid를 확인한다.
6. 유효하면 COMMIT을 보내고 원본 장면을 해제한다. 호스트는 COMMIT을 받은 임시 묶음만 표시 후보로 넘긴다. REJECT·시간 초과·조회/fill 실패·장면 취소에는 ABORT를 보내 임시 데이터를 폐기한다.

**레코드 수락 ACK, 장면 PREPARED, COMMIT, 실제 SNES 표시 완료는 서로 다르다.** 이번에는 앞의 세 단계를 구현했다. COMMIT 이후 SNES 명령의 업로드·vblank 완료 확인은 다음 연결 대상이다. 게임 오류가 COMMIT 허가 뒤 발생해도 이미 복사 완료한 장면 자체를 소급 취소하지 않는다. reset은 양쪽 mailbox와 수신기의 임시 상태를 함께 지운다.

## 레코드와 메모리

내부 ready/valid 버스의 레코드는96비트다. `[95:93] kind`, `[92:77] generation`, `[76:64] index`, `[63:0] payload` 순서다. FPGA 전송기는 한 레코드만 유지하며 전체 이벤트/CHR/프레임 복사 버퍼를 추가하지 않는다.

| kind/index | payload |
| --- | --- |
|0~5|기존 공통 장면 조회 값; 각 표의 index0부터 순서대로 |
|6 / 물리 타일|bit13:12 필요 종류,11:8 lane,7:0 바이트; 나머지0 |
|7/0 BEGIN|버전1651,6비트 BG수,6비트 팔레트수,8비트 행수/OBJ수/예외수,예약12비트0 |
|7/1 END|하위32비트에16비트 데이터 레코드 수와16비트 CHR바이트 수; 상위0 |
|7/2 ABORT|하위4비트 오류 코드 |
|7/3 COMMIT|0 |

이 부팅 표본은 장면당1717레코드다.96비트를 그대로 외부 직렬화하면20,604바이트이므로, 앞서 계산한 위치정보2,226바이트와 혼동하면 안 된다. **현재 버스는 논리 레코드 연결이며, 외부 SPI 대역폭/FPS가 아니다.** 다음 접속부에서 kind별 유효 폭과 타일 단위 묶음을 활용할 수 있지만, 아직 구현하지 않은 패킹의 이득을 결과로 계산하지 않는다.

## 클록·중단 계약

`nes_native_mailbox165`는 송신 데이터를 요청부터 수신 수락의 회신까지 고정한다. 요청/회신은 각각2단 동기화하고, 수신은 동기화된 요청을 본 다음 한 클록 더 기다려 데이터를 잡는다. 소비자가 준비되지 않으면 같은 값과 valid를 유지한다.96비트 순방향과17비트 PREPARED 역방향은 별도 mailbox다.

공통 비동기 reset과 도메인별 동기 해제만 지원한다. 한쪽만 reset하면 안 된다. 클록 정지는 데이터를 바꾸거나 새 레코드를 수락하지 않으며, 회복 후 이어간다. 동기화 속성은 명시했지만 **실제 배치의 bundled-data 최대 지연·첫 단계 팬아웃·reset·MTBF는 아직 검증하지 않았다.** RTL 위상 시험이 그 승인을 대신하지 않는다.

장면 전체 대기는 기본1048576 NES 클록으로 제한한다. 시험은262144로 낮춰 실제 timeout을 확인했다. 실패 시 원본은 해제하지만 이미 수락된 레코드는 회수하지 않고 뒤따르는 ABORT로 폐기한다. 호스트가 멈춰 ABORT도 받지 못하면 새 장면을 시작하지 않는다. 이 경우 공통 reset/기존 종료 경로로 정리해야 한다. 정책 상한은 보드의 최악 실행시간 보장이 아니다.

## 이번 검증

선택 `host02 / verify02`. [결과와 해시](../analysis/native-host165-verification.json).

- 앞서 수집한 실제 SMB3 frame12/14/16/18/20의 봉인된 조회 표와 ROM 바이트를 재사용했다. 이번에는 게임을 다시 부팅하지 않았다. **실제 fill·전송기·양방향 CDC RTL**을 실행했고 메모리 backend는 주소에 맞는 ROM 바이트를 지연 반환하는 모델이다. 실제 공유 reader/CPU 기한 근거는 직전 memory165 결과를 재사용한다.
- 정상5사례는 서로 다른 호스트 클록 위상, 주기적 역압력, 진행 중 호스트 클록 정지를 포함한다. 각각1714데이터+BEGIN/END/COMMIT을 중복·누락 없이 받았고 CHR240바이트가 정확했다.
- 조회 실패, 호스트 REJECT, PREPARED 미응답 timeout, END 후 원본 취소는 모두 COMMIT0/ABORT1이다. 정상 사례에서도 먼저 보낸 오래된 generation의 ACK는 무시됐다. 전송 도중 공통 reset 후 generation65535의 새 장면만 COMMIT됐다. 추가로 호스트가 멈춘 사이 다음 generation이 이미 봉인된 경우에도 이전 ABORT 뒤 새 장면을 COMMIT하여 복구했다.
- PC 참조 수신기는 중복·순서 오류·다른 generation·누락 CHR·PREPARED 없는 COMMIT5가지를 거부했다. 수신 데이터로 기존 SNES 명령 참조를 실행하고 원본 PPU 픽셀과 비교해 정상286720픽셀, reset 회복57344픽셀, 취소 후 새 장면 복구57344픽셀이 일치했다.
- 해당 부팅5장면은 같은 영상이라 PC 명령 참조는 첫5493바이트/6명령 이후0바이트였다. 움직이는 첫 레벨의 전송량·FPS 근거가 아니다. 이번에 새 SNES 모델 실행은 하지 않았다.

초기 host01/verify01은 보존했다. 최종 검토에서 ABORT 대기 중 다음 장면이 봉인되면 DRAIN이 그 장면 해제를 기다리며 멈추는 조건을 발견했다. 이전 generation의 해제와 새 generation의 소유권을 구분하도록 수정하고, host02의11번째 사례에서 복구를 확인했다.

호스트의 RTL 시험 수신자는 개수·표식과 ACK 흐름을 검사하는 모델이고, 완전한 순서/타일/픽셀 검증은 기록된 호스트 레코드를 PC 수신기로 다시 읽어 수행했다. **PC 참조 수신기가 실시간 MCU에서 실행됐다고 하지 않는다.** ROM·프레임·덤프는 비공개이며 공개 소스/결과 해시만 저장한다.

## 다음 작업

1. 이 ready/valid 접점을 실제 SPI 또는 호스트 레지스터에 연결하고 MCU에 유한 수신 저장·검사·PREPARED/COMMIT 처리를 구현한다. 레코드의 외부 전송량과 실행 예산을 실제 포맷으로 계산한다. 범용 진단 종류를 추가하기보다 이 접속을 먼저 한다.
2. 기존 SNES 명령 소비자와 vblank 게시/완료 확인을 연결하며38M9K 픽셀 버퍼를 제거한다. 현재56/56M9K에 추가만 하지 않는다. PC 전체 이벤트/VRAM 그래프를 FPGA에 복사하지 않는다.
3. 변경 경로의 최소 기능 검사와 실제 자원·타이밍 확인 후 SMB3 첫 레벨 실기로 간다. 동일 부팅·플레인·A/B·044 시험을 반복하지 않는다.164 사운드·STOP/메뉴를 유지하고 영상 개선 뒤60초 제한·오류/본체 reset 로그·입력 유지를 진행한다.
