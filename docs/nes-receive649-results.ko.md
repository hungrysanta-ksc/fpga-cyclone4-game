# 649 · 954 표시 중 955 입력을 먼저 받는 세 가지 일정

두 시작 위상에서 955의 첫 D1을 앞당기고 **954 최종 ACK 전에 7블록을 검증·반환**했다. 954의 표시 간격 3 VBlank까지 함께 유지한 후보는 없었다. 955도 세 후보 모두 4 VBlank였다. 실기 기준은 MMC643으로 유지하고 649는 설치본으로 전달하지 않는다.

## 같은 53화면에서의 비교

## 7블록이 3 VBlank에 들어갔는가

**648의 실제 SPI 시간표.** 954 최종 ACK를 기준으로 955 캡처 준비는 −17.271 / −17.378 ms, ARM이 이전 END를 확인한 E8 응답 완료는 −13.750 / −13.974 ms였다. 이전 마지막 타일의 65816 ACK는 −11.213 / −11.455 ms였지만, 첫 D1은 SEAL 발행 뒤 −4.035 / −4.261 ms에 시작했다. 첫 D1 당시 출력 큐에는 두 위상 모두 미소비 패킷이 하나 있었다. 캡처 준비와 입력을 실제 요청할 기회 사이에 큰 차이가 있었다.

**고정 일정에서의 여유.** 캡처 준비와 양성 END 관측이 모두 끝난 시점부터 기존 954 ACK까지 13.750 / 13.974 ms가 있었다. 그중 입력을 제외한 실제 SPI 서비스가 6.968 / 6.968 ms, 확인까지 일곱 입력 블록의 SPI 서비스 합은 6.881 / 6.881 ms다. 기존 거래를 그대로 두고 겹치지 않게 놓으면 여유는 **−0.099 / +0.125 ms**다. 이 계산에는 거래 사이의 ARM 복원·CRC·다음 패킷 준비가 들어 있지 않다. 거래 순서를 바꾼 세 후보는 별도로 끝까지 실행했다.

**실제 출력 지연.** sealed 후보에서 첫 D1은 953 표시 뒤 36.735 / 37.786 ms로, 648보다 9.615 / 8.214 ms 빨랐다. 이때 955 export가 시작될 때의 이전 타일 token은 양쪽 모두 104·105였다. 그러나 954의 SEAL SPI 시작은 953 표시 뒤 45.320 / 44.970→52.441 / 51.915 ms로 늦어졌다. 65816 수락도 45.997 / 45.633→53.070 / 52.542 ms였다. 일곱 번째 입력 확인을 앞당기는 동안 이전 화면의 마지막 출력 발행이 밀렸다. 이후 955의 SEAL 수락은 직전 표시 기준 49.509 / 48.962→53.658 / 54.057 ms였다. 누적 일정에서도 sealed의 첫 D1과 957 ACK는 648보다 늦었다.

**같은 3 VBlank 기간을 대입한 대조.** 각 후보의 실제 953 표시를 원점으로 하고 648의 953 표시→954 ACK 기간을 적용했다. 일곱 번째 확인은 그 기한을 credit에서 5.190 / 6.152 ms, stream에서 3.734 / 3.596 ms, sealed에서 0.778 / 0.375 ms 넘겼다. 이 차이만 없애도 표시가 당겨진다고 볼 수는 없다. 954의 SEAL 자체를 제때 발행해야 한다.

## 판정과 다음 작업

세 후보 모두 독립 검사와 957 최종 추가 대기 0회를 통과했다. sealed는 951 공개선도 243 / 243으로 지켰다. 전체 링크 Flash는 credit 213,000 B, stream 213,056 B, sealed 213,100 B로 한도 212,992 B를 각각 8 / 64 / 108 B 초과했고 BSS는 모두 19,544 B였다.

다음에는 648의 954 **SEAL 발행 기한**을 먼저 고정하고, 일곱 블록의 전송·복원 비용 자체를 줄이는 대조부터 한다. 우선 첫 일곱 geometry 블록에서 D1 payload, D2와 확인 D0, ARM 복원 시간을 나누고 같은 셀·token·CRC를 유지하는 압축 후보의 절감 상한을 계산한다. 954 출력이 밀리는 세 가지 polling 위치는 동일한 비용 조건에서 재시도하지 않는다. 채택 기준은 951 공개선과 957 최종 추가 대기, 954·955 상대 표시 간격, 밀집 구간과 957 누적 ACK의 동시 개선이다.

## 실험 경계

첫 D1은 실제 ARM이 955 데이터 거래를 시작한 시각이다. 입력 블록은 D1 데이터 CRC·복원, D2 반환, 후속 D0에서 token 증가 확인까지 추적했다. 표의 7블록 판정은 D0까지 954의 65816 최종 ACK 전에 끝났을 때만 통과한다. 648 위상 2는 D2 기준 3개, D0 확인 기준 2개였다. 준비된 입력을 읽는 동안에도 D3와 새 COMMIT은 앞 화면의 최종 ACK 및 EA 뒤에서만 허용한다.

세 후보는 같은 648 출력 ABI·테이블·SEAL 코드와 65816 ROM을 사용한다. 각 후보의 끝까지 링크한 ARM에서 같은 905–957 입력을 재생했다. SPI 거래 비용에는 기존 실기 기반 드라이버 비용을 포함했다. ARM 명령 CPI 2, ROM 중재·입력 블록 공급은 모델이고 65816은 Mesen에서 실행했다. 53화면 각각 map·화면·팔레트·OAM·HDMA, 최종 ACK와 EA→다음 COMMIT 순서를 확인했다. 두 슬롯과 BG 48회 적중·OBJ 1,200회 캡처도 대조했다.

- **credit**은 FINISH 뒤 출력 credit 서비스 시점에 확인한 미반환 패킷이 두 개 이상이면 다음 입력 한 블록을 처리한다.
- **stream**은 FINISH 뒤 section 5 패킷을 발행한 직후 미반환 패킷이 두 개 이상이면 한 블록을 처리한다.
- **sealed**는 CRC·세대·token을 검증한 E8이 END와 새 타일 descriptor를 함께 보고한 구간에서 먼저 이전 타일을 발행하고 입력 수신을 시작한다. 이후 section 5 발행 사이에는 이미 시작한 수신만 이어간다. 세 방법 모두 SEAL 뒤 수신과 같은 7회 예산을 사용한다.

MMC643 보드 RTL의 export 시작 허가는 닫힌 plan과 ROM reader drain을 사용한다. 타일 staging의 소비 완료는 별도 token으로 관리한다. Questa에서 세대 97의 마지막 descriptor를 소비하기 전에 98의 유효 헤더와 데이터가 나왔고, 그 뒤에도 97의 32 B를 읽어 원래 token으로 소비했다. 이 시험은 실제 클록·포트에 합성 입력 및 query 응답을 연결했다. 일곱 블록 전체의 물리적 생성 속도는 이 시험의 측정 범위 밖이다.

기존 공동 일정은 마지막 staging 슬롯이 소비되어야 다음 D0를 허용했다. sealed 시험에서만 양성 E8, 캡처 준비, 작업·ROM 읽기 종료, 불변 staging 슬롯 보존을 모두 확인해 D0를 앞당겼다. MMC643·648의 네 원본 일정에는 이 차이가 영향을 줄 수 있는 시점의 D0가 0개였다. 각 후보의 실제 ARM에 I/O·CRC·D2 직후 서비스 중단·기한 경과, 큐와 최종 ACK 오류, 메뉴·base 정상 복구 및 네 실패 차단을 주입했다. 실제 보드에 새 펌웨어를 설치하지 않았다.
