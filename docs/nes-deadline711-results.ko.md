# 711 마지막 수락 마감과 생산·DMA 공동 예산

## 목표

707D·기존694/704 ARM·기존65816을 유지하고, 마지막 패킷 수락을 얼마나 앞당겨야 이전 VBlank에 표시할 수 있는지 두 시작 위상에서 확인한다. 독립 검사·STOP·최종 ACK·메뉴 복귀,911 마감·951 공개≤246선·952 간격3VBlank·957 최종대기0회를 유지한다. [검증·예산 JSON](../analysis/deadline711-budget.json) · [원시 근거](../analysis/deadline711-archive.json)

## 작업내용

실제 링크 ARM/65816을 실행했던707D의905–957 패킷·map·OBJ 작업량을 고정하고, **변경 없는65816에 도착하는 패킷의 가상 공급 시각만** 앞당겼다. 기준 두 실행은 전체53화면의 CPU 사건 시각이 원래 공동 재생과 클록 단위로 같다. 새 시험22회/1,166화면의 독립 CRC·coverage·수락·DMA·최종 ACK와 화면 픽셀을 확인했다.

공급 시각 시험은 SEAL만, 마지막tile 뒤 후반 전체,951–957 전체 출력의 세 범위다. 전체 출력 선행은8/10/12/14/15/15.5/15.75/16ms를 비교했다. 패킷 바이트·순서와 각E1의 wire+driver 시간,4credit·2bulk 소유자,이전 표시ACK 뒤 다음BEGIN을 유지했다. CPU 명령·검사를 건너뛰거나 VRAM을 직접 고치지 않았다.

**새 ARM 일정이나 FPGA 구현은 아니다.** D1/D2/E0/E9/EA·IRQ·ROM 공급을 후보와 함께 재실행하지 않았다. 기존 producer보다 일찍 제공한 데이터는 미지급 비용으로 별도 집계했다. 기존 7블록 선행 수신을 새 일정에서도 입증한 것으로 간주하지 않는다. STOP·캡처 회복·메뉴/base는 변경 없는 타깃과 기존707/694/704 검증을 승계하며, 이번에는 새 STOP 주입이나 실기 메뉴 시험을 하지 않았다.

4credit·2bulk 제한은 **수신 모델에 실제 넣는 시점**에 적용된다. 미리 계산한 공급 예약이 credit 때문에 지연돼도,credit 반환 후의 새 ARM 조회·SPI 거래 시간을 다시 더하지 않는 낙관적 시험이다. E1 전송시간을 보존했다는 것은 예약 시각의 간격이며,전체 공유SPI에서 실행 가능한 일정이라는 뜻이 아니다. 이 미지급 비용까지 실제 생산기에 연결해야 채택할 수 있다.

## 성과

**마지막 SEAL이나 후반 패킷만 앞당기는 접근은 이번 두 위상에서 표시 VBlank를 줄이지 못했다.**

**이 평균 변화는 지속적인 처리율 개선이 아니다.** 951 간격이3→2VBlank이고 이후952–957은 계속3VBlank다. 전체 열을 한 번 앞당긴 효과가 평균과 마지막ACK에 반영됐다. 따라서 새 구현 성과·실기FPS 향상·60fps 가능성의 증거로 사용하지 않는다. 다음 게이트는951 이후 간격도 따로 집계한다.

가상 공급을 기존 생산 일정에 대입하면 문제가 더 분명하다. 마지막BG 패킷 소비에 필요한 기존 공급 완료를952는7.482/7.980ms,954는13.673/13.473ms,955는14.745/15.127ms 앞당겨야 한다. 마지막OBJ는952에서12.510/12.406ms,954에서13.905/13.800ms,955에서12.316/12.413ms가 부족하다. OBJ 수치는 물리 PSRAM 읽기만의 비용이 아니라 기록된 캐시/공급 응답까지 포함한다.954/955 BG의 물리ROM 거래80/72회도 그대로 남는다. 이 수치는 **현재 공급 일정을 그대로 쓸 수 없다는 증거**이며,ROM 자체를 그만큼 가속해야 한다는 뜻은 아니다.

## 후속작업

선택 구성은707D·기존ARM·65816 그대로다. 새 실기 ZIP과 변경 없는 FIT/STA 재실행은 없다. 다음 구조 검토는 아래 순서로 한정한다.

1. **생산 마감부터 확인한다.** 952·954·955의 각 map 범위와 마지막BG/OBJ에 대해 마지막 쓰기·주소/CHR bank 확정·첫 요청·공급 완료를 같은 ARM/ROM 일정에 연결한다. 기존 BG 완료 선행 발행,7블록 수신,압축,캐시,두 연속192B map 발행은 이미 구현된 기능이므로 새 이득으로 계산하지 않는다. 이미 확정된 행과 실제로 늦게 계산되는 행을 구분한다. 준비 시각을 가정으로 옮기는 시험은 더 진행하지 않는다.
2. **후보 경계는 준비된 map 범위의 생산→발행 소유권과 tile 공급이다.** 기존 map 배열·`map_next`를 사용하고,초기/최종 발행의 준비 상태를 한 진행 경계로 관리하는 대안을 검토한다. 아직 확정되지 않은 행의 전송·collector COMMIT 뒤 재읽기는 금지한다. bulk 우선권과 새패킷/STOP 우선권을 유지하며,무조건 map을 끝까지 drain하는708/이전 실패를 반복하지 않는다. 실제 확정 시각이 늦다면 발행 순서 변경으로 해결할 수 없으므로 입력 복원/계획 계산 경계까지 확대할 근거와 비용을 먼저 제시한다. **새 단일 진행 경계는 아직 미구현·미선택**이다.
3. **추가 자원보다 기존 경로 대체를 우선한다.** 기본안은E1 ABI·보드·65816 변경0이다. 기존 `map527`은이미 초기/최종이 공유하므로함수 두 개를 삭제하는 절감은 없다. 링크의map527 364B·early wrapper104B·map credit70B,합계538B는 조사 경계이며 통째로 회수 가능한 공간이 아니다. 검증·credit·bulk 우선권을 남겨야 하므로 입증된 순삭제는현재0B다. 새 readiness 저장이 필요하면최대8B bitmap을 검토하되,기존dirty mask와혼용하거나해제되지않은scratch를재사용하지 않는다. 실제 소유권·전체링크로 비용을 확정한다.
4. **실제 연속 일정으로 채택한다.** 각 프레임의SEAL 수락·선행DMA·표시를 이전246선 마감과 비교한다. 후보는두 위상 모두911/951/952/957·7블록·독립검사·STOP·최종ACK를 유지해야 한다.951–955 평균과957ACK뿐 아니라 **952–957 합계18VBlank도 줄어야** 지속 개선으로 채택한다. 한 번의 시작 이동이나cold단축만으로 성공 처리하지 않는다. 새 기능 구현 시실제ARM/SPI/IRQ/ROM·두슬롯을다시연결하고STOP/cold/최종ACK·메뉴경계를검사한다.
