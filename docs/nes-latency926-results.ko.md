# MMC925 데모 후반의 타일 공급과 표시 대기

PR #173 머지 커밋 `5df17db`를 기준으로 MMC925 무입력 실기 55–60초와 MMC915·925 최종 ARM/65816 링크의 두 위상 재생을 분석했다. 실기끼리는 같은 판의 같은 대상 뱅크 안에서 비교했고, 재생끼리는 두 판에 같은 입력을 공급했다.

## 실기에서 기다린 구간

MMC925 BIN의 정상 세대 요약은 105개다. BG·OBJ·변경 map 행·뱅크·타일 수·묶음 수·마지막 묶음 종류·크기·offset이 같은 화면을 모으니 두 세대 이상인 그룹이 7개였다. 아래는 입력 완료→ARM 첫 유효 최종 ACK 차이가 큰 세 그룹이다. 표시 세대별 데이터 내용과 이전 프레임의 캐시 상태까지 같다는 조건은 아니다.

| 시작 시각 / 세대 | BG·OBJ·변경 행 | 첫 E9→마지막 타일 준비 | 마지막 타일 준비→ARM ACK | 입력 완료→ARM ACK |
|---|---|---:|---:|---:|
| 55.94초 / 1313 → 56.00초 / 1315 | 529·18·0 | 0.00→0.00ms | 24.50→8.13ms | 36.75→20.01ms |
| 57.57초 / 1349 → 57.65초 / 1351 | 528·10·5 | 11.70→28.09ms | 12.03→12.03ms | 33.57→50.06ms |
| 59.48초 / 1391 → 59.76초 / 1397 | 521·44·0 | 12.87→37.84ms | 12.03→12.42ms | 33.48→64.84ms |

1313·1315는 둘 다 BG 16B 한 묶음이다. 마지막 준비 시각과 첫 E9가 같은 FPGA 계수 눈금에 들어왔고, 그 뒤에 약 한 VBlank의 차이가 났다. 1349·1351은 9타일·3묶음, 마지막 OBJ 32B다. 여기서는 16.49ms의 전체 차이 중 16.384ms가 첫 E9부터 마지막 OBJ 준비 사이에 생겼다. 1391·1397은 마지막 OBJ 416B이며 공급 시간이 24.97ms 늘었다. 준비→ACK는 ARM 조회와 FPGA 시계 사이의 추정치로, 표에서 각 값의 오차 한도는 약 ±0.451ms다. 0.00ms의 FPGA 계수 분해능은 약 0.390ms다.

실기 BIN은 마지막 타일 준비와 최종 E0를 기록한다. 1313·1315의 SEAL 수락, PPU 포트별 DMA, 화면 공개 시각은 저장되지 않아 어느 DMA가 한 번 밀렸는지 이 두 세대에서 확정할 수 없다.

## 실제 최종 링크 재생에서 확인한 DMA

MMC925 세대 912의 기존 캐시 재생에서는 SEAL 수락이 두 위상에서 각각 105·104선이었다. 검사 뒤 VBlank 대기에 들어간 시각부터 225선의 첫 DMA까지 5.809·5.896ms였다. 위상 1에는 VRAM 타일 64·288·32·32·128B가 남았고, 위상 2에는 64B 하나가 더 남았다. 그 뒤 raw CHR 64B 세 번, 팔레트 512B, OAM 544B가 같은 VBlank 안에 끝나 245·246선에 공개됐다. 빈 캐시는 496B를 미리 보내고도 대기 진입→첫 DMA가 10.253·10.191ms였다. 따라서 SEAL 이후의 대기를 우선 줄일 대상은 잔여 타일과 뒤따르는 팔레트·OAM의 **실행 가능 시점**이다. 마지막 OAM이 다음 VBlank로 단독 이월된 사례로 볼 수 없다. 이 재생 세대 번호와 위 실기 세대 번호는 서로 대응하지 않는다.

## 입력 수신 증가의 범위

| 프레임 시작 기준 구간 | MMC915→925 수신 ms/장 | D1 payload B/장 | D0 전송 B/장 | D0–D3 전체 B/장 |
|---|---:|---:|---:|---:|
| 30–60초 | 1.535→2.808 | 1,236.43→1,235.93 | 290.57→292.62 | 1,723.33→1,724.81 |
| 55–60초 | 2.255→3.524 | 1,177.53→1,177.06 | 367.45→373.94 | 1,741.68→1,747.54 |

30–60초의 원계수는 99틱/645장과 187틱/666장이다. 원계수 차이는 +1.273ms/장이고, 기존 표의 반올림한 두 값을 빼면 +1.28ms다. `nes_runtime165_step`의 `B210_RECEIVE`는 전면 수신 구간의 10ms 시스템 틱 차이를 호출별로 누적한다. `wait634`에서 출력 대기 중 미리 수행한 입력은 바깥 계획·SEAL 단계에 들어간다. MMC925에서는 D3 후 다음 블록이 준비됐으면 같은 전면 수신 호출에서 poll까지 실행한다. 이 변경과 틱 경계 모두 귀속에 영향을 줄 수 있다. 물리 로그에는 호출별 D1 시작·종료, 복원 종료, D2 뒤 D0 시각이 없다.

같은 세대 907–912의 첫 D1 발행부터 마지막 D2 뒤 D0 확인까지 구간을 중복 없이 나눈 결과다. 아래 수치는 **기존 캐시 두 시작 위상의 화면당 재생 평균**이다.

| 구간 | MMC915 위상 1 / 2 (ms) | MMC925 위상 1 / 2 (ms) |
|---|---:|---:|
| D1 거래 | 5.469 / 5.469 | 5.469 / 5.469 |
| D1 종료→D2 시작 (CRC·ARM 복원·guard 포함) | 2.237 / 2.245 | 1.856 / 1.855 |
| D2 반환 및 바로 뒤 D0 확인 | 2.783 / 2.783 | 2.783 / 2.784 |
| 같은 구간의 출력 등 다른 SPI 거래 | 1.359 / 1.340 | 0.946 / 0.964 |
| 나머지 입력 SPI (별도 D0·D3) | 0.149 / 0.149 | 0.149 / 0.149 |
| 거래 사이의 나머지 시간 | 2.032 / 2.025 | 1.521 / 1.556 |
| 전체 | 14.027 / 14.010 | 12.723 / 12.776 |

빈 캐시에서도 전체는 13.684→12.614ms, 13.622→12.645ms였다. 재생에는 공유 SPI 드라이버 시간·ROM 경쟁과 ARM CPI 가정이 포함된다. 전면 수신만 합산하는 실기 지표와 이 재생 전체 구간의 차이를 더하거나 빼서 실기의 네 원인별 기여도로 환산할 수 없다. 실기에서 D1 바이트 증가는 관측되지 않았고 재생에서도 복원·다른 SPI 점유는 감소했다. 다음 실기 계측은 같은 세대에서 전면 수신과 출력 중 선행 수신을 나눠 D1·복원·D2/D0에 각각 ARM 사이클을 누적하고, 타일 준비 뒤 대기가 긴 화면에는 SEAL·첫/끝 DMA 포트·공개 VBlank를 함께 남기는 것이 우선이다.
