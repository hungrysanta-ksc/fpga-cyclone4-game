# 751 · 리셋부터 실행한 65816 DMA 선택기

749 page의 Cortex-M4 전체 링크와 707D 보드 인터페이스를 고정하고, 각 정적 ROM을 리셋 벡터에서 부팅해 905–957의 53화면을 두 시작 위상에서 실행했다. 750에서 사용한 957 시점 WRAM 코드 교체는 제거했다. ARM이 실행한 SPI·IRQ·ROM 경쟁 일정과 Mesen의 65816·PPU를 연결했다. 아래 클록은 SNES 마스터클록이다.

## 정적 ROM과 부팅

| 후보 | 선택·설정 방식 | 실행 본문 B | 부팅 prefix B | 물리 ROM 여유 B |
|---|---|---:|---:|---:|
| `tail` | 750 실행 본문 | 6185 | 512 | 78 |
| `shared` | 빔 래치·채널 설정 공유 | 6188 | 512 | 61 |
| `fused` | 일반 선택·설정 경로로 통합 | 6145 | 52 | 6 |
| `fused512` | fused와 같은 본문, 중간 거리 압축 | 6145 | 512 | 91 |
| `sharedfast` | shared와 같은 본문, 부팅 참조 순회 단축 | 6188 | 512 | 61 |
| `fusedfast` | fused512와 같은 본문, 부팅 참조 순회 단축 | 6145 | 512 | 91 |

모든 물리 이미지는 벡터 64B를 포함해 5,120B다. `fused` 계열은 1,536B map 완료 후 수락된 288B descriptor를 기존 빔 검사·DMA 설정에 넘긴다. 48B 완료 후에는 STOP과 새 패킷을 확인하고 map tail을 선택한다. 긴 map 뒤 288B 전송에 대한 확장 허가는 마지막 descriptor의 OBJ 종류를 확인한다. 후보의 일반 경로에서는 큐 끝의 다른 종류 288B를 보류할 수 있어 이 장면 밖의 지연은 별도 검증 대상이다.

`tail`은 750 본문을 정적으로 넣은 대조군이다. `fused`는 750 본문에서 40B를 줄여 기존 압축 형식에 들어간다. 나머지 후보는 256–3,327B 뒤를 가리키는 짧은 참조를 쓴다. `fast`는 압축 참조 한 건을 복사하거나 검증하는 동안 X에 참조 위치를 보존한다. 매 바이트의 WRAM 대조와 입력·출력 경계 검사는 그대로 실행한다. `fused512`와 `fusedfast`는 복원 후 본문 SHA-256이 같다.

## 리셋부터 마지막 ACK까지

아래 E8은 957의 마지막 OBJ descriptor에 대한 749의 실제 SPI 발행 시각과의 차이다. 밀집 간격은 951 공개부터 957 공개까지 여섯 간격의 평균이고, 밀집 간격과 ACK의 비교 기준은 727이다. 각 칸은 위상 1 / 2 순서다. ‘다음’은 1,536B map 전송 때의 VBlank가 끝났다는 뜻이다.

| 정적 후보 | E8 변화 µs | OBJ MDMAEN 선·H | 밀집 간격 변화 µs | 957 최종 ACK 변화 클록 |
|---|---:|---|---:|---:|
| `tail` | +16681.001 / +29.214 | 255 H870 / 255 H1174 | −17.631 / −20.720 | +354580 / −2558 |
| `shared` | +16676.098 / +20.811 | 다음 225 H982 / 256 H1316 | +4.796 / −17.631 | +357590 / −2558 |
| `fused` | +16709.011 / −29.695 | 257 H346 / 257 H366 | −19.866 / −20.301 | +354698 / −3022 |
| `fused512` | +16646.308 / −56.590 | 다음 225 H982 / 256 H1070 | +4.796 / −23.451 | +357590 / −3022 |
| `sharedfast` | −33.377 / +21.496 | 257 H1256 / 256 H1316 | −21.620 / −17.631 | −3010 / −2558 |
| `fusedfast` | −30.820 / −33.388 | 258 H930 / 257 H394 | −21.449 / −24.320 | −2764 / −3022 |

공유 선택기와 빠른 부팅을 결합한 5,120B 정적 ROM은 61B가 남고, 957 OBJ를 257선 H1256 / 256선 H1316에 시작했다. 두 위상의 밀집 간격·최종 ACK는 727보다 줄었지만 749의 E8보다 위상 2가 21.496µs 늦어 비교 기준은 727을 유지한다.

`sharedfast`는 위상 1에서 BG 243선 → map 246선 → OBJ 257선 H1256, 위상 2에서 BG 242선 → map 245선 → OBJ 256선 H1316 순서였다. OBJ 마지막 쓰기는 각각 259 / 258선이다. 두 위상의 957 map 래치는 245 / 244선, 952 래치는 234 / 233선이었다. 밀집 평균은 49.910699 / 49.914673ms이고 952–957은 각각 3 VBlank다. 마지막 ACK는 65,722,508 / 66,080,216클록이다.

부팅에서 첫 패킷을 확인한 시각은 같은 본문의 `shared` 7,987,964 → `sharedfast` 7,184,966클록으로 당겨졌다. 위상 1의 905는 749와 같은 프레임 29에 공개됐다. 957의 E8 시작은 65,198,913 / 65,559,323클록이다. 두 응답의 descriptor 바이트와 전송 길이는 749와 같았다. 위상 2에서는 직전 BG E1이 이미 462클록 늦었고, 이어지는 E0 네 건과 E8에도 같은 차이가 남았다. 956 공개를 기준으로 E8까지 늘어난 시간은 5.665µs다. 공통 선택기로 더 작게 만든 `fusedfast`는 두 위상의 E8을 앞당겼지만 위상 1의 OBJ가 258선 H930에 시작했다.

## 보호 조건과 범위

여섯 후보 각각 두 위상에서 53개 화면의 RGB, 수락 payload와 작업량, map WRAM·VRAM, 마지막 ACK를 대조했다. `sharedfast` 두 위상에서 908·911은 2 VBlank, 951 공개는 236선, 952는 3 VBlank, 957 최종 대기는 0회였다. OBJ 직전 STOP이면 0B, 첫 PPU 쓰기 후 STOP이면 시작한 288B만 완료했고 양쪽 모두 956 화면을 보존하며 957 ACK를 차단했다. 같은 경계에 새 패킷을 넣으면 OAM을 먼저 수락했다. 잘못된 OAM 이력은 0xE0으로 거부했다. 여섯 ROM 모두 정상 부팅에서 본문 전체가 일치했고, WRAM 1바이트 손상 시 0xE1으로 진입을 막았다. ARM의 메뉴·base 복귀 5경로와 표식 4조건을 검사했다.

707D RTL과 ARM 전체 링크는 동일하다. ARM Flash는 212,784B로 208B가 남는다. 새로운 Quartus 합성과 실기 플레이는 수행하지 않았다. 시뮬레이션의 표시 간격으로 실기 fps를 환산하지 않았다.

## 재현과 인계

1. [ROM 생성기](../tools/build_nes_static751.py)에 `--client ../probes/nes-longrun694/client01 --raw ../probes/nes-reuse635/client04 --variant K --prefix P --out <temp>/nes-static751-K`를 준다. P는 표의 prefix 값이다. `sink-program.hex`는 물리 ROM 5,120바이트를 한 줄에 한 바이트씩 저장하며, `sink165.sfc`는 같은 내용과 리셋 벡터를 Mesen 주소 공간에 배치한 파일이다.
2. [공동 실행기](../tools/run_nes_static751.ps1)에 `-Variant K -Phase 1|2 -Game <사용자 SMB3 ROM> -TraceRoot <temp>`를 준다. [749 대조군](nes-obj749-results.ko.md)과 같은 IRQ·ROM 입력 및 기존 probes가 필요하다.
3. [부팅 검사](../tools/check_nes_longrun694_boot.py)는 두 후보를 지정해 정상 복원·손상 거부를 각각 검사한다. [STOP·새 head·stale 검사](../tools/check_nes_static751.py)는 정적 ROM의 공동 실행 trace에 `--fault before|during|head|stale`를 적용한다. `--source`와 `--size`는 주입할 DMA의 실제 source·길이다. [메뉴 검사](../tools/check_nes_menu533.py)는 같은 749 page ARM의 다섯 복귀 경로를 실행한다.
4. [결과 집계기](../tools/analyze_nes_static751.py)의 `--temp`와 `--out`으로 절대 클록, map 래치·MDMAEN·마지막 쓰기, E8 응답과 객체 해시를 다시 대조한다. [측정값과 해시](../analysis/static751-verification.json)

751 sharedfast의 정적 ROM을 기준으로 956 공개와 957의 BG descriptor 준비·E1 발행 사이에서 위상 2의 462클록 차이가 처음 생기는 사건을 찾는다. 두 위상의 E8 마감, 1,536B map 선행과 OBJ 257선 마감을 같은 리셋 실행에서 비교한다.
