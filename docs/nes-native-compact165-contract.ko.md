# NES165 온라인 화면 압축과 실제 SMB3 경계

전체 이벤트를 쌓지 않는 BG/OBJ 압축 RTL을 구현하고 실제 SMB3 부팅20프레임에서 얻은 이벤트 간격으로 재생했다. 완전하게 수집된 두 화면은 압축·복원 후 원본 NES PPU와 일치했고, SNES 모델에서도 같은 그림을 출력했다. **연속 화면 목표는 미완료**다. 나머지 표시 프레임에서 기존 fetch 수집기가 분할 경계의 타일 하나를 거부하는 문제가 먼저 해결되어야 한다.

[검증](../analysis/native-compact165-verification.json) · [RTL](../src/nes/diagnostic/nes_native_compact165.sv) · [이전 참조 명령](nes-native-commands165-contract.ko.md).

## 온라인 생산자

`begin_scene` 뒤 실제 fetch 이벤트를 한 클록씩 받는다. PPU를 정지시키거나 ROM 요청을 추가하지 않는다. 마지막 이벤트가 끝난 뒤 `end_scene`으로 봉인하며, 시작과 같은 클록의 source fault도 PPU 진행 없이 invalid 소유권으로 반환한다. 입력 시작은 begin 다음 클록부터다.

배경은 같은33열의 물리 타일/속성이 이어지는 행을 재사용한다. 현재 행의33셀만 비교용 레지스터에 보관하고, 변경된 행은33클록 동안 제한된 맵 RAM으로 복사한다. 복사 중 새 BG 입력이 오면 오류로 보류하며 게임 클록을 늦추지 않는다. 실제 기록의 원래 이벤트 간격으로 이 조건을 확인했다.

스프라이트는8개 평가 순위마다 직전 X/위쪽 행/물리 타일/속성을 유지하고, 같은 조각의 실제 평가 행 마스크를 누적한다. 순위가 바뀌면 새 조각으로 분리한다. 전체 이벤트를 정렬하거나 그래프를 기판에 보관하지 않는다. 팔레트 변화에 따른 추가 분할과 SNES 행당 객체 한도는 후속 명령 승인에서도 확인해야 한다.

| 저장 영역 | 고정 한도 |
| --- | --- |
| BG 물리 태그13비트+팔레트 속성2비트 | 32그룹×33셀×15비트 |
| 표시 행의 BG그룹/fine Y | 224×8비트 |
| OBJ 조각 | 128×64비트 |
| BG 셀별 fine Y 예외 | 128×17비트 |

데이터 RAM 합계는28000비트이며 작은 현재 행/평가 순위 레지스터는 별도다. **실제 M9K/LAB/타이밍 수치가 아니다.** 아직 합성·배치하지 않았다. 원시 최대73472바이트 이벤트 버퍼는 없다. 조회 시 워드 폭으로 직렬화하면 최대3744바이트이며 팔레트/fine X·CHR·헤더/전송 프로토콜은 이 숫자에 포함하지 않는다.

조회 kind0은 BG맵,1은 표시 행,2는 OBJ,3은 fine Y 예외다. 유효한 소유권과 해당 count 안에서만 hit/data를 반환한다. release/reset 후에는 이전 RAM 바이트가 남아도 조회할 수 없다. 다음 빈 세대가 이전 valid를 물려받지 않는 것도 확인했다. 이 valid는 **압축된 위치/태그의 완전성**이며 CHR/host/최종 frame-ready가 아니다.

OBJ64비트는 하위부터 물리 타일13·signed top9·X8·속성8·행 마스크8·평가순위3·예약15비트다. 예외17비트는 하위부터 실제 fine Y3·열6·표시 행8비트다. 논리 슬롯은 물리 주소가 정해진 뒤 표시 복원에 필요하지 않아 저장하지 않는다.

오류 비트는0:예약/행 범위,1:BG순서/행/열/속성/복사 충돌,2:fine Y예외 용량,3:BG그룹 용량,4:OBJ순위의 중복/역순 행,5:OBJ용량,6:원본 오류,7:불완전 종료다. 오류가 생긴 세대를 부분적으로 게시하지 않는다.

## 실제 게임에서 달라진 가정

SMB3의 표시185행(NES193행)에 행 중간 VRAM 변경이 있다.13번째 화면에서 대부분 셀의 fine Y는1이지만 일부 셀은0이다. 이전 참조의 **한 행 전체가 같은 fine Y**라는 조건은 이 화면을 거부했다. 이제 예외 셀만 기록하고 PC 참조의 `RowConsumer`가 해당 타일의 필요한 행을 SNES 타일 행에 복사한 파생 패턴을 만든다. 테스트 화면에서는 파생 패턴2개면 충분했다. 원본 게임 ROM/PPU는 수정하지 않았다.

파생 패턴의 물리 태그+행 선택표는 승인 전 임시 할당하며 전송 commit 때만 유지 상태를 바꾼다. 실제 보충기는 원본 물리 태그의 바이트를 받아야 하며 PC 참조 내부의 가상 번호를 PSRAM 주소로 쓰면 안 된다. 누락 CHR가 있어 prepare가 실패할 때 기존 할당/게시 상태가 유지되는 것도 확인했다.

기존 raster의 오류`10`은 그래픽 접근 자체를 모두 막는 조건이다. 이번 **PC 참조**는 실제 per-cell 주소와 fine Y 예외가 표현된 경우 이 비트만 별도로 해석해 픽셀을 비교했다. 기존 pinned raster RTL이나 보드의 게시 게이트를 해제한 것이 아니다. 나머지 팔레트/fine X/마스크/순서 오류는 계속 거부한다. 두 실제 화면의 픽셀 일치가 이 제한된 해석을 뒷받침하며, 모든 게임/효과의 승인은 아니다.

## 실제 실행 결과

실제 CPU/PPU/MMC3와70ns PSRAM 모델로 SMB3 부팅20프레임을 실행했다. CPU/PPU 상태를 강제로 바꾸거나 버튼을 주입하지 않았다. ROM은 모델 메모리에 미리 적재했다. 따라서 MCU 적재·첫 레벨 플레이 시험은 아니다.

- 1~11프레임은 화면 표시 비활성 구간이며 완전한 BG 이벤트가 없다.
- 12~20프레임은 표시 마스크1e다.13·17프레임은7401이벤트가 완비되어 두 원본 픽셀 화면과 압축 복원이 정확히 일치했다.
- 나머지7개 표시 프레임은 fetch 오류04와 함께185행의28열 또는30열 BG이벤트 하나가 빠졌다. 세부 비교는 아직 기록하지 않아 저/고 플레인 주소·속성 중 어느 조건이 달랐는지는 확정하지 않았다. 분할 경계의 VRAM 변경과 관련된 것으로 추정되지만 ROM 서비스 오류로 단정하지 않는다. 이7개는 계속 보류한다.

두 완비 화면의 압축은30BG그룹·2OBJ조각·fine Y예외2개로2226바이트다. 이는 **위치/태그 패킷만의 크기**다. 원시7401×8=59208바이트를 기판에 저장하지 않고 같은 표시 정보를 복원했다. 기존 행별 fine X/팔레트와 물리 CHR는 별도다.

PC의 완성 CHR 공급으로 첫 화면을 SNES에 적재한 양은5493바이트/6명령이다.13·17프레임의 픽셀이 같아서 두 번째는0바이트였다. 두 번의256×224, 총114688픽셀이 실제 SNES CPU/DMA/PPU에서도 일치했다. **움직이는 장면의 대역폭이나 FPS 검증으로 해석하지 않는다.** 새 파생 패턴 처리에 대한 정확성 시험이다.

온라인 RTL 시험은 합성 정상1·거부7·실제 이벤트2, 총10사례를 통과했다. 복사 충돌, 시작 시 오류, 빈/불완전 세대, BG/OBJ/예외 용량, 조회 범위, 봉인 후 입력 무시와 release 후 stale 차단을 확인했다. 실제 게임 재실행 없이 저장된 원래 간격으로 압축을 검사했다. 이는 생산자 RTL의 재생 검증이며 **실제 게임 인스턴스와 압축 RTL의 동시 배선 실행은 아직 아니다**.

stream01의 시험기 선언 오류,compact01의 예약어 충돌을 보존했고02를 선택했다. SNES rows01은 같은 화면인데0예산도 거부해야 한다고 잘못 기대한 검사기 실패이며, 누락 CHR 거부 검사로 수정한02가 최종이다. 변경 없는 원본 RTL·앞선 검증은 재사용했다. 새 ARM/배치/SD패키지는 없다.

## 다음 작업 우선순위

1. **185행의 빠진 패턴 쌍을 먼저 해결한다.** 최초 거부의 실제 저/고 주소·논리 주소·설명자를 관측하고 실제 PPU가 사용하는 플레인과 대조한다. 합법적인 서로 다른 플레인 적재라면 제한된 예외로 보존한다. 오류04를 무조건 무시하거나 빠진 타일을 이전 그림으로 채우지 않는다.
2. 완전한 fetch를 새 온라인 생산자에 직접 연결하고 raster의 표현 가능 조건을 실제 파이프라인에서 함께 승인한다. 참조 자료구조/전체 이벤트 버퍼를 기판으로 옮기지 않는다. 예전 CIRAM/OAM 스냅샷의 무변경 조건도 이미 평가된 fetch 경로에 무조건 중복 적용하지 않는다.
3. 그 뒤 물리 CHR 보충·host CDC/ACK·유한 vblank 명령 소비자와38M9K 픽셀 버퍼 교체를 연결한다. 최소 변경·자원/타이밍 검사 후 실제 SMB3 첫 레벨로 간다.164 사운드·STOP/메뉴를 유지한다. 현재 설치 후보는164이며 새 실기 시험 요청은 없다.
