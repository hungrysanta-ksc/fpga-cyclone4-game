# 세대 반환 전 CHR 선행 읽기와 표시 마감

## 목표

모험도 4의 MMC966 빈 캐시 재생에서 906이 ROM 포트를 쓰고 남은 허가로 907의 OBJ를 준비하면 화면 공개와 912 최종 ACK까지 빨라지는지 확인했다.

## 작업내용

MMC966 보드의 원본 RTL에 실제 SPI 페이지 명령을 보냈다. 서로 다른 128행의 두 비트플레인이 적중하는 기존 시험에 더해, 빈 캡처 반환·샘플 한 개를 기록한 캡처 반환·STOP을 각각 실행했다. 반환 직전에는 세 경우 모두 128행이 유효했다. 반환과 무효화 순회가 끝난 뒤에는 각각 **128·0·0행**이 남았다. 세 시험 모두 추가 ROM 요청은 0회였다.

연속 일정은 MMC966의 같은 ARM·65816 링크로 세대 905–912를 처음부터 재생했다. 907 페이지가 확정된 뒤 7B 명령 한 번이 들어갈 첫 SPI 공백을 잡고, 직전 타일과 모든 기존 선행 읽기가 사용한 허가를 제외했다. 남은 허가는 위상별 298·299회였다. 각 변형의 여덟 화면 RGB를 대조군과 비교했고, 대조군의 ARM 거래·타일 생산·65816 이벤트·BIN은 원본과 일치했다.

예약은 시간 상한을 알아보는 모형이다. 906의 마지막 타일 생산 뒤에만 실제 허가 달력에서 행을 배정하고 같은 물리 인덱스의 기존 행을 교체했다. 7B 길이의 SPI 공백은 전송 가능한 가장 이른 시각이다. 별도 ARM 발행 명령·새 CDC·행 복구 시간은 이 수치에서 제외했다. 전체 행 보존은 동일 ROM의 906→907 반환 한 번에만 적용했다.

## 성과

| 906→907 반환 처리 | 추가 ROM 허가 | 907 마지막 OBJ가 빨라진 시간, 위상 1 / 2 | 912 최종 ACK 변화, 위상 1 / 2 |
|---|---:|---:|---:|
| 기존 반환, 페이지 또는 rank 0 두 태그 예약 | 64 / 0 | 0 / 0ms | 0 / 0ms |
| 예약한 8타일 페이지의 행만 보존 | 64 | 0.106 / 0.106ms | 0 / 0ms |
| rank 0 두 태그의 행만 보존 | 0 | 0.009 / 0.009ms | 0 / 0ms |
| 기존 캐시 전체 보존 | 0 | 0.009 / 0.009ms | 0.176 / 0.197ms 늦음 |
| 기존 캐시 전체 보존과 페이지 예약 | 64 | 0.123 / 0.124ms | 0.176 / 0.197ms 늦음 |

태그 3136–3143의 페이지에는 907이 실제 사용할 64행이 있었다. 이 행들만 보존하면 해당 페이지의 첫 비트플레인 실수요가 새로 받은 ROM 허가는 16→0회로 줄지만, 첫 미스인 태그 6511은 페이지 밖이다. 반대로 rank 0 태그 6510·6511의 16행은 이미 캐시에 있었다. 이 행들만 보존하면 첫 미스가 3138로 이동했다.

**일곱 조건 모두 907 SEAL 수락·잔여 DMA 종료·화면 공개·최종 ACK가 위상별 같은 클록이었고, 여덟 화면의 공개 VBlank도 같았다.** 대조군에서 마지막 OBJ 준비→SEAL 로드는 8.362 / 8.158ms, SEAL 검사 후 VBlank 대기 루틴의 진입→반환은 4.860 / 5.059ms였다. 마지막 OBJ가 준비돼도 65816은 일반 출력 패킷을 처리 중이었다. 그중 OAM 재사용 명령 하나의 로드→반환은 1.434 / 1.433ms였다. VBlank 대기 전체를 절감 가능 시간으로 보지는 않는다.

기존 55–60초 실기 BIN에서도 같은 현상을 확인했다. 작업량과 시각으로 양쪽에서 유일한 26쌍 중 타일 준비 단축과 전체 단축 차이가 가장 큰 것은 **59.43 / 59.45초**였다. 두 판 모두 BG 521·OBJ 51·변경 map 0행·타일 4개·묶음 2개였다. MMC955→MMC966에서 첫 E9→마지막 타일 준비는 14.434→0.390ms로 **14.044ms** 줄었고, 입력 완료→ARM 최종 ACK는 33.896→31.884ms로 **2.012ms** 줄었다. 이 실기 요약에는 SEAL·공개 시각이 없어 차액 12.032ms를 특정 DMA에 귀속할 수 없다.

## 후속작업

새 설치본은 만들지 않았다. 다음 후보는 907에서 일반 출력의 발행·수락과 SEAL 검사 시작을 앞당겨 이전 VBlank에서 잔여 DMA를 마칠 수 있는지다. 실기에서는 세대 1531과 작업량이 맞는 화면에서 마지막 타일·SEAL·첫/마지막 DMA·공개·ARM ACK를 함께 기록해 재생과 대조한다. 모험도 4의 실기 기준을 유지하며 다른 MMC3 장면의 첫 비교 대상은 커비다. [세 ROM의 검증 결과](nes-demos968-results.ko.md)

재현은 기존 Starter FLOAT 래퍼에서 환경 변수 `NES_RELEASE969=1`로 `tools/check_nes_obj967.ps1`을 실행한 뒤, `python tools/check_nes_reserve969.py <기존 재생 TEMP> analysis/reserve969-results.json --hardware <BIN 폴더>`로 한다. 재실행은 새 출력 접미사를 `--tag`로 지정한다. 실제 보드 파일과 펌웨어는 MMC966 그대로다. 이번 시험은 보드 RTL 반환·STOP과 빈 캐시 재생을 포함하며 새 FIT·STA 및 실기 메뉴 복귀는 측정하지 않았다.
