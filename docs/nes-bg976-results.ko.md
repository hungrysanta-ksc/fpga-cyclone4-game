# 911의 BG 슬롯 조회와 map 행 처리 비용

## 목표

973의 232B 팔레트 전 OBJ 서비스와 원래의 스크롤 선행 발행을 유지한다. 타일 추가 ROM 허가가 없었던 세대 911에서 ARM의 BG 처리 4.39ms를 줄이면 908 공개를 지키면서 911 표시 간격과 912 최종 ACK가 함께 줄어드는지 시험했다.

## 작업내용

같은 빈 캐시에서 두 시작 위상으로 부팅한 뒤 905–912를 연속 실행했다. 실제 ARM 바이너리와 65816 프로그램을 사용했고 FPGA 공급은 기존 포트 모델, ARM 일정은 이전과 같은 CPI 2 가정이다. 원래 ARM의 컴파일 목록에서 함수 호출과 복귀 주소를 짝지어 시간을 합산했다. 스크롤 테이블 생성은 첫 루프 진입부터 map 발행 함수 진입까지 잰 값이다. 계측을 켠 기준 실행의 SPI·65816 이벤트, 타일 생산 기록, 진단 BIN은 계측을 끈 실행과 바이트 단위로 일치했다.

- **슬롯 후보**는 기존 map 워드에서 슬롯 번호를 읽는다. 원래 타일 태그 검사를 통과하고, 일반 BG 셀이며, 그 슬롯이 현재 화면에서 이미 사용됐고 대상 뱅크에 상주하며 64비트 키도 일치할 때만 슬롯 검색과 descriptor 조립을 건너뛴다. 나머지는 원래 할당기를 거친다.
- **행 후보**는 같은 화면에서 입력이 이미 일치한다고 확인한 두 행의 시작 열과 팔레트까지 같을 때만 시도한다. 실제 map의 33워드를 페이지 경계에서 나누어 비교하고, 모두 같으면 원래 셀 루프를 건너뛴다. 다르면 원래 경로에서 워드별로 비교하고 dirty 비트를 갱신한다. 뱅크 이력만으로 두 행이 같다고 가정하지 않는다.

|---|---:|---:|

| resident 슬롯 함수 173회 | 1.143 | 1.143 |
| map 워드 비교·조건부 쓰기 함수 957회 | 0.456 | 0.456 |
| 나머지 BG 행·셀 처리 및 호출 전후 | 2.367 | 2.367 |
| 스크롤 테이블 생성·발행 함수 진입 | 0.071 | 0.071 |
| 전체 | 4.391 | 4.389 |

173회 조회의 결과는 서로 다른 슬롯 62개였다. 슬롯 후보는 위상 1의 실제 할당기 호출을 173→62회로 줄여 BG 구간을 4.391→3.870ms로 단축했다. map 처리 957회는 그대로였다. 행 후보는 33워드 행 8개에 해당하는 264회 호출을 생략해 693회만 실행했고, BG 구간은 4.155ms였다.

|---|---:|---:|
| 911 SEAL 수락 단축 | 0.653 / 0.540ms | 0.415 / 0.168ms |
| 910→911 표시 간격 | 2 / 2 VBlank | 2 / 2 VBlank |

| 같은 검사·DMA 비용 가정 시 직전 VBlank까지 남은 시간 부족분 | 1.730 / 1.751ms | 1.975 / 2.129ms |
| ARM Flash (한도 212,992B) | 212,936B | 212,964B |

원래 부족분은 2.386 / 2.297ms였다. 둘 다 908 공개 시각을 같은 VBlank에 유지했고 911의 실제 공개도 원래 VBlank에 머물렀다. 변경 조각을 직접 복사하는 별도 행 후보는 213,016B로 Flash를 24B 초과해 연속 실행에서 제외했다. 두 실행 후보는 각 위상의 905–912 RGB 여덟 장, map 패킷 52개의 세대·범위·payload, 전체 E9 묶음과 레코드가 대조군과 일치했다. STOP과 SEAL 세대 오류를 각각 주입했을 때 910 RGB를 유지하며 0xE4·0xE0로 종료했다. 새 실기 FPS·메뉴 복귀·보드 합성은 이번에 측정하지 않았다. [실행별 원시 시각·Flash·오류 결과](../analysis/bg976-results.json)

## 후속작업

MMC966 실기판과 973 대조군을 유지한다. 슬롯 후보를 후속 계산 비교용으로 두고, 2.367ms 잔여 구간 중 33셀의 주소 계산과 descriptor 준비에 쓰는 시간을 먼저 분리한다. 다음 후보는 같은 화면에서 확정된 행의 슬롯·팔레트·열 배치를 이용하되 바뀐 셀, 예외 행, 페이지 경계를 원래 경로와 대조한다. SEAL을 앞당긴 뒤 실제 공개 VBlank와 912 ACK가 함께 바뀌는지 확인한다.

재현은 973 before232 링크와 같은 TEMP를 사용한다. `nes_bg976.py profile TEMP --phase N`으로 기준 실행을 계측한다. `prepare TEMP`의 기본·`--equal`·`--rows`로 후보별 소스를 만들고 각각 `build_nes_trial577.ps1`로 링크한다. 기본·`--equal`은 `run TEMP --phase N`으로 두 위상, `count TEMP`로 위상 1의 호출 수를 측정한다. `check_nes_bg976.py TEMP TEMP/nes-MODE-FAULT --mode MODE --guard FAULT`로 두 모드(976hint·976equal)의 stop_decode·bad_seal을 재생한다. 마지막으로 같은 스크립트에 TEMP와 결과 JSON 경로를 주어 집계한다.
