# 617 · 확정 map의 조기 발행과 954·955의 업로드 대기

**일정 기준은 616B를 유지한다.** 617은 954·955에서 두 번째 map 패킷 128B를 실제로 이전 VBlank에 DMA했다. 그러나 두 화면의 표시는 여전히 각각 5 VBlank였고, 951–955 밖에서 얻은 시간 이득이 마지막 ACK에 반영됐다. 아래 수치는 53화면 연속 공동 시뮬레이션이며, 각 셀은 시작 클록 3,000,000 / 3,178,684 순이다.

발행·수락 시각의 원점은 각 세대의 BEGIN ACK다. 대상은 두 화면 모두 비활성 map의 오프셋 512에서 시작하는 같은 128B다. 두 위상 모두 65816의 수락이 10.54–11.23 ms 앞당겨졌다. 첫 기회의 64B와 추가 128B는 별도 DMA였고, 바이트는 최종 map과 일치했다.

## 업로드 대기가 남은 이유

954의 SEAL 이후 map은 320→192B로 줄었다. 검사 후 업로드 대기 진입은 256 / 2번 라인에서 245 / 243번으로 이동했다. 다음 VBlank 225번에서 업로드를 재개하므로 먼저 도착한 만큼 대기 시간이 오히려 늘었다. 955도 대기 진입이 0 / 0번에서 244 / 248번으로 이동했고 같은 현상이 발생했다. 이 대기는 업로드 도중 서비스한 시간이며 최종 표시 단계의 추가 대기와 분리했다.

955의 다음 VBlank에서는 반대 효과도 확인했다. 오프셋 3,200부터의 마지막 384B는 두 위상 모두 VBlank가 열리기 전에 이미 수락됐다. 첫 1,152B DMA가 239 / 240번 라인에서 끝난 뒤 65816은 242 / 243번에 새 OAM 패킷을 수락하기 시작했고 후속 OAM도 처리했다. 616B에서 선행 처리한 384B가 SEAL로 넘어가, SEAL 뒤 map은 256→512B가 됐다. 이 구간은 ARM의 map 발행을 더 앞당겨도 새 패킷 우선 조건이 그대로 적용된다.

마지막 ACK는 49.522 / 16.371 ms 빨라졌다. 표시 간격이 한 VBlank 짧아진 세대는 위상 1의 920·922·931·947, 위상 2의 922·931·947이었다. 한 번 늘어난 세대는 각각 930과 923·930이었다. 951–955에는 두 위상 모두 VBlank 절감이 없었다.

## 구현과 검증 범위

ARM은 현재 BG 그룹보다 최소 세 행 앞서 확정된 왼쪽 페이지의 dirty/stale 비트를 보고 기존 오름차순 map 패킷을 한 개씩 제안한다. 최대 세 행을 담으므로 다음 제안 시점도 최소 세 그룹 뒤로 보낸다. 첫 제안에서 credit이 부족하면 END 이후 기존 경로가 맡는다. 이후 제안에서는 진행 중인 bulk의 완료 위치와 큐 여유를 확인하고, 수락된 패킷만 행 커서를 전진시킨다. 최초 arm01은 불완전 타입을 참조해 컴파일에 실패했다. 실제 측정한 arm02는 완료 위치 검사를 큐 타입을 소유하는 plan service로 이동했다.

- 전체 ARM 링크는 212,992→212,968B, BSS는 18,592B였다. ARM 코드만 교체해 616B의 65816 프로그램과 FPGA를 그대로 사용했다. 이번 단계에서 새 FIT·STA나 실기 메뉴 복귀는 측정하지 않았다.
- 두 위상에서 각각 53장의 RGB와 map, ordinary payload와 tile 결과가 기준과 일치했다. 총 VRAM DMA 114,352B, 두 bulk 슬롯, BG 적중 48회·OBJ 캡처 적중 1,200회와 VBlank 내 warm DMA를 확인했다. 실제 링크된 ARM·65816 코드에 CPI 2, 실측 SPI 드라이버 비용, SysTick IRQ, 반복 ROM 중재 일정을 적용했다.
- ARM 재발행 경계 7건에서 STOP, 불확실한 E1, 손상된 E8 CRC, credit 및 bulk 우선을 검사했다. 617 패킷으로 65816의 STOP·새 head·빔 경계 및 두 뱅크의 누락·중복 검사 9건을 재실행했다. 954 팔레트·OAM·HDMA 수락 뒤 STOP 3건은 모두 상태 0xe4와 직전 953 표시를 유지했다.

## 다음 작업과 재현

다음 비교에서는 616B를 기준으로 617을 실험 대조군에 둔다. 955에서 1,152B DMA가 끝난 뒤 OAM 패킷이 들어오는 시각과 남은 384B의 DMA 시간을 고정 재생으로 대조한다. 954에서는 SEAL 수락부터 업로드 준비까지 약 2.3 ms인 검사를 포함해, 같은 VBlank에 실행을 시작할 때 246번 최종 검사선·마지막 PPU 쓰기를 지킬 수 있는 작업량을 측정한다. STOP·새 패킷 우선을 유지하고 두 위상의 밀집 표시와 마지막 ACK가 함께 줄어들 때 후보를 선택한다.
