# 951의 24행 고정값 DMA와 팔레트·OAM 마감

**621을 유지한다.** 625와 같은 마지막 OBJ 패킷까지 진행한 뒤, 951의 오른쪽 map 전송을 672B 줄이고 팔레트·OAM을 먼저 수락시켜도 두 시작 위상 모두 4 VBlank였다. 65816은 새 map을 정확하게 복원했지만 소비 시간이 늘었다. 기존 624 수신기에 남은 명령을 전부 즉시 제공한 대조군에서도 SEAL 수락이 세 번째 VBlank의 246번 선을 넘었다. [기계 판독 결과](../analysis/map630-verification.json)

## 비교

원점은 950 표시 뒤 세 번째 VBlank의 246번 선 끝이다. 표는 각 이벤트가 그보다 몇 ms 앞섰거나(−) 늦었는지(+)를 나타낸다. 'SEAL 제공'은 마지막 바이트까지 큐에 제출할 수 있다고 가정한 시각, '수락'은 그 head를 실제 65816이 읽은 시각이다. 네 칸이 차면 앞 명령 소비까지 기다린다. 양쪽 수치는 시작 위상 1 / 2다.

예정 시각을 앞당긴 재생은 ARM·SPI 생산 쪽의 비용 가정이다. 실제로 실행한 부분은 65816의 패킷 처리·DMA·PPU·최종 ACK다. 두 위상에서 905–951의 47개 표시, 독립 map 대조와 RGB 일치를 확인했다. 625의 마지막 OBJ와 그 이전 패킷에는 같은 PUSH 클록을 사용했다. 즉시 제공 대조군은 이 경계 이후 공급을 더 앞당겨서 얻을 수 있는 효과를 **해당 순서와 수신기에서만** 제한한다.

## 바이트와 시간

* ARM 기록에 있는 오른쪽 24행 모두 앞 34B 뒤의 30B가 0이었다. 진단 패킷 하나는 세 행을 담는다. 행별로 길이 34와 고정값 0을 확인한 뒤, 65816이 literal DMA 34B와 고정 source DMA 30B로 비활성 WRAM 전체 행을 쓴다. 세 descriptor·수신 길이·확장 범위·대상 섹션을 검사하고 각 행 전에 STOP을 확인한다. 이력 저장은 필요 없다. 기대 map과 실제 표시 결과를 별도로 비교한다.
* 여덟 E1은 1,688→1,016B로 줄고, 2.625MHz에서 선로 절감은 2.048ms다. 소비는 반대 방향이었다. 같은 즉시 제공 조건에서 여덟 map의 head→ACK 합이 기존 4.565 / 4.562ms에서 6.154 / 6.155ms로 늘었다. 24회 literal과 24회 고정값 DMA의 주소·모드·길이·STOP 처리를 포함한다. 65816 본체는 5,323→5,543B다.
* 팔레트·OAM 순서 변경의 951 최종 표시 ACK는 625보다 0.016 / 0.021ms 늦었다. E1만 연속 공급해도 HDMA 마지막 소비 ACK가 +2.834 / +3.070ms였다. SEAL을 일찍 제공해도 이 앞 명령들이 head를 차례로 소유한다. 각 후보의 마지막 DMA·표시·ACK 클록은 결과 JSON에 있다.
* 기존 624 수신기의 즉시 제공 대조군에서 후반 24개 명령의 head→data 진입은 합계 3.174 / 3.168ms, data→accepted는 8.333 / 8.310ms, accepted→소비 ACK는 1.199 / 1.200ms였다. data 구간에는 실제 메모리 쓰기와 coverage 처리가 포함된다. SEAL 수락 뒤 upload 함수 진입에도 1.630 / 1.631ms가 들었다. 다음 VBlank의 VRAM DMA는 225번 선부터, 팔레트와 OAM은 244·248번 선에 각각 시작했다. 246번 검사선은 최종 표시를 허용하는 판정 시각이다.

## 보호 경계와 다음 순서

잘못된 길이·확장 크기·주소 범위·세 번째 행 고정값을 넣은 네 시험에서 DMA 시작 전에 0xE0을 반환했다. 두 번째 행 직전 STOP에는 첫 행의 두 DMA만 끝내고 0xE4를 반환했으며 직전 950 화면을 보존했다. cold에서 잘못된 패킷도 거부했다. 중단된 두 뱅크의 WRAM·VRAM 16KiB를 복원한 뒤 전체 행으로 cold 905·906을 다시 표시하고 두 번째 최종 ACK까지 확인했다. 처음 STOP 주입이 SEAL 조건 안에 들어간 시험을 제외하고, 실제 행 서비스가 읽는 위치로 옮긴 보호 시험을 사용했다.

다음에는 map 분할 DMA와 팔레트·OAM 순서 변경을 닫고 625의 기존 literal 경로를 쓴다. 마지막 OBJ 뒤 소비에서 **24번 반복되는 header·범위·완료 처리와 OAM 400B·HDMA 1,100B 반복 복원**을 구분해, 여러 명령에서 공유할 수 있는 검사와 반드시 개별 실행할 DMA를 먼저 정한다. 두 위상에서 SEAL 수락 지연과 그 뒤 upload 진입만 합쳐도 2.831 / 3.079ms를 회수해야 한다. 실제 잔여 DMA·빔 판정에 필요한 시간은 별도다. 고정 도착 재생에서 그 예산을 확인한 경우에만 ARM·credit·IRQ·ROM 연속 일정으로 넘어간다. 957의 새 연속 결과, 보드 FIT, 실기 메뉴 복귀는 이번 범위에 포함하지 않았다. 실기 기준은 MMC613이다.
