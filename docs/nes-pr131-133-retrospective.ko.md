# PR131–133 종합 회고와 계획 재설정

검토일: 2026-10-29. PR131은 10/22–10/25, PR132는 10/25–10/28, PR133은 10/28–10/29의 기록이다. 지난 작업이 실제 지속 60fps로 연결됐는가를 기준으로 평가한다.

**그 기준으로는 성과가 부족하다. 기존 보드에서 동작하는 60fps 후보를 전달하지 못했다.** 유효한 국소 개선과 실제 NROM 설정·표시·입력·복구의 진전은 있었지만, 이를 실기 속도 개선과 구분해야 한다.

## 이번 15fps가 의미하는 것

실제 467 전달본은 production227 기반 FPGA457/ARM418/ROM428이다. ARM의 수신·planner·resident·전송·출력 등 9개 파일, FPGA의 캡처·export·mailbox·direct·plan·lease·queue와 65816 HEX 8개를 원본227과 비교했으며 모두 바이트 단위로 같았다. FPGA 파일은 458 전달 산출물의 입력 해시에도 연결했다. mapper·loader·클록/reset 변경은 있으므로 전체 설계가 같다는 뜻은 아니다.

**PR131/132의 고속 연구 경로를 기존 실행 경로 대신 넣어 실기 시험한 것이 아니다.** 따라서 이번 15fps는 모든 최적화를 적용했는데 느려졌다는 증거도, 지난 작업으로 실기 성능이 향상됐다는 증거도 아니다. 이전 465표시/60.06초는 SMB3, 이번 899표시/60.06초는 정적 자체 NROM이다. 서로 다른 장면의 7.74→14.97을 향상률이나 회귀율로 계산하지 않는다.

근거: analysis/pr131-133-retrospective.json. 재현: tools/audit_nes_lineage472.py.

## 진행 방식에서 잘못된 점

- 연구 후보와 실제 보드 경로가 분리된 상태에서 실험이 쌓였다. 국소 성과를 얻어도 제품의 포트·면적·capture 관문을 함께 통과하지 못했다. 앞으로 매 후보의 **연구/선택/설치본 포함** 상태를 표시한다.
- 같은 workload의 실물 기준과 지속 capture 검증을 너무 늦게 고정했다. 131의 source 시작 오류·ROM 부하 누락은 국소 PASS가 제품 연결을 대신하지 못했음을 보여준다.
- 큰 면적 초과가 남은 상황에서 작은 FSM/RAM 공유·ABI 실험을 반복했다. 절감한 만큼 다른 제어·CDC가 늘어 기각되는 일이 반복됐고, 이 방식의 효율은 낮았다.
- 133의 실기 진입은 필요했지만 많은 작은 시뮬레이션 단계와 회고를 거치며 제품 성능과 연구 진척을 명확하게 구분하지 못했다. 추가 라이선스나 하루짜리 전체 시뮬레이션을 계속 선행 조건으로 쌓지 않는다.
- 기존227 marker·로그 이름을 유지해 후보 identity도 흐렸다. 다음 전달본부터 번호·실행 항목·로그·manifest를 함께 바꾼다.

## 회로를 전부 다시 바꿔야 하나

**일부 FPGA 전송 경계 변경은 필요하지만 전체 회로 재설계를 먼저 목표로 삼지 않는다.** 현 2.625MHz에서 D1 payload만 17.578ms/표시, 계수된 전체 wire만 26.627ms다. 바이트 스트림을 유지한 채 ARM/SNES만 조정해서 60fps가 되지는 않는다. 기존 snapshot에서 전송할 레코드를 줄이는 bounded 압축 같은 변경을 먼저 비교해야 한다.

ARM planner는 emit callback을 제외해도 약 10.712ms/표시다. 반복 준비·재해석도 함께 줄여야 한다. E0 상태 응답 wire 5.407ms에는 필요한 credit/최종 ACK가 포함돼 전부 제거할 수 없다. SEAL 15.017ms는 검사·queue·DMA·VBlank·ACK 대기의 혼합이다. 회로를 바꾸기만 하면 60fps가 된다는 근거는 없다.

필요한 것은 **실기에서 동작하는 457 기준으로 전송량·ARM 비용·일정을 함께 줄이는 설치 가능한 후보 하나**다. 131의 ARM/raw-group 개선, bounded source 압축, 독립 read-event 검증은 재사용 후보로 보존한다. 미수용 RTL 전체를 옮기거나 과거 모델 시간을 현재 시간에서 바로 빼지 않는다. 새 포트·serializer·ARM 재링크·같은 소스 FIT에 포함된 효과만 계상한다.

## 새 실행 계획과 중단 기준

1. **실물 기준을 고정한다.** 467 산출물과 이번 T0 정적 NROM을 보존한다. T1은 프레임 변화를 눈으로 확인할 수 있는 결정적 NROM scroll/counter 장면이다. 이후 T2는 기존 SMB3와 동일한 구간·입력·장비로 비교한다. 정적 프레임을 생략해 60fps라고 보고하지 않는다.
2. **다음 구현을 하나의 수직 경로로 끝낸다.** 471에 세부 시간·진행/대기 계측을 연결하고, bounded row/record 압축과 ARM 단일 복원을 실제 송신·수신 경계에서 비교한다. 기존 snapshot/RAM을 우선 사용하되 추가 포트·CDC·decode/CRC 비용도 포함한다. 계측만으로 PR 전체를 쓰거나 이름만 바꾼 smoke를 반복하지 않는다. 계측 전용 설치가 필요하면 그 결과가 어떤 결정을 바꾸는지 먼저 명시한다.
3. **중간 성과도 실기로 판정한다.** wire가 60Hz의 물리 한계 안으로 줄고 ARM 복원 비용을 포함한 일정도 개선돼야 한다. 같은 T0/T1에서 첫 실기 중간 목표는 30표시/초 이상이며 최종 60Hz 합격은 아니다. 변경 RTL의 기능 검사 뒤 같은 후보의 Lite 전체 FIT/관련 timing으로 판정한다. 산술 638LE 여유를 배치 여유로 간주하거나 seed 반복으로 후보를 밀어넣지 않는다.
4. **ARM·일정을 이어서 연결한다.** 변경 그룹 재사용·raster 재해석 감소와 진행 기반 polling을 실제 후보에 연결한다. epoch/serial/표시 이력·cold/STOP 무효화를 검사한다. 다음 capture, plan/DMA 공급, VBlank 공개를 같은 소유권 일정에서 확인한다. wire 8ms/2,625B·ARM 계산 3ms 등 470 예산은 설계 목표이며 새 측정으로 다시 판정한다.
5. **제품 검증을 완료한다.** T1에서 capture/display ID·누락·반복·최대/p95 간격·VBlank 마감을 본다. T2에서 게임 스크롤·음성·입력·STOP·재시작·메뉴 복귀를 확인한다. MMC4/5는 실제 mapper와 ROM 경쟁을 측정하는 후속 관문이며 NROM 성공으로 자동 보장하지 않는다.

최소 수직 후보 **두 개가 연속으로 wire/ARM/whole FIT 관문을 크게 못 넘으면**, 같은 경계의 작은 공유 실험을 중단한다. 실패 원인을 명시하고 한 역할 경계를 바꾼 대안과 현재 장치/지원 범위를 비교한다. 미구현 삭제 예산을 가능성 증명으로 쓰거나 추가 구매를 자동 진행하지 않는다. 유효 후보가 나오면 그 후보를 설치까지 완결한다.

모든 단계에서 독립 CRC/coverage, STOP·stale DONE/ACK 차단, bank/token/epoch, 실제 DMA 소비, VBlank 최종 ACK 후 resident commit/EA retire, base DONE·SPI 유휴·토큰·메뉴 복귀를 유지한다. GBC164/saveSRAM과 복원물도 보존한다. 제한 실물 성공과 전체 IO/CDC 승인은 구분하며 새 실제 고장은 해당 경계를 먼저 조사한다.
