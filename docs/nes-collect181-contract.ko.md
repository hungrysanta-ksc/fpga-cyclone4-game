# NES181 — 부분 행 수집과 다음 행 복구

PR113의 독립 행 RAM을 **후보 fetch·compact·raster 수집기에 연결했다.** 기존180의 fetch 소스 검사는 그대로 사용하며, 완전한256픽셀이 보존된 행만 불완전한 타일 표현을 대신한다. 아직 배포 보드·SPI exporter·MCU·SNES 클라이언트에 연결한 펌웨어는 아니다.180 실기의 첫 레벨 정지 해결과60fps는 미확인이다.

## 구현

- `nes_patch_capture181`: 같은 NES 클록에서 PPU CE 다음 클록에 갱신된 좌표·색을 읽는다. cycle2..257의256픽셀, NES8..231행을 저장한다. CE가 쉬는 동안 같은 픽셀을 중복 기록하지 않는다. 강조색은6비트 색에 들어가지 않으므로 계속 거부한다.
- `nes_native_compact181`: 마지막 BG fetch가 아니라 픽셀 RAM의 행 완료 응답에서 행을 확정한다. BG 열 누락·순서 이탈은 행별 대체 요청으로 모은다. 잘못된 행 번호·필드·복사 중 충돌·객체 순서·자원 초과·source fault는 여전히 전체 후보를 거부한다.
- 대체 행은 기존 map을 참조하지 않는 자리표시자만 기록하고 그 행에서 생긴 fineY/plane 예외를 되돌린다. 다음 행의 기대 번호와 column0을 회복하고, 첫 정상 행은 새 map 그룹으로 만든다. 이전의 불완전한 `previous[]`를 다음 행의 동일 그룹으로 오인하지 않는다. 객체는 기존 순서·rank·마스크 규칙을 유지한다.
- `nes_native_raster181`: 행 시작 상태와 중간 변경을 모아 최종 행 판정에 합친다. 대체 행의 팔레트 변화는 정상 행의 팔레트 epoch를 불필요하게 소비하지 않으며, 다음 정상 행에서 필요하면 새 팔레트를 확정한다. 정상 팔레트2개, BG32그룹, 객체128개, 예외128개 한도는 유지한다.
- `nes_native_frame181`: fetch·compact·raster·픽셀 RAM 네 구성 요소가 모두 유효해야 전체 후보를 공개한다. 시작·release·세대·ROM fault와 query 소유권을 결합한다. 원래180의 수집기와 배포 파일은 수정하지 않는다.

행 대체 요청은 **row_finish에서만** 픽셀 RAM에 넘긴다. 이전 행의 latched raster 판정이 다음 row_start까지 남아 있다는 이유로 다음 행까지 무조건 대체하지 않는다. 다음 행의 prefetch가 실제 누락되면 그 행 자신의 완결성 검사에서 대체한다.193행이나 특정 ROM/매퍼를 구현에 하드코딩하지 않는다.

현재 지원 확대는 **fetch 자체는 정상이고 compact/raster 표현만 불완전한 경우**다. low/high CHR 응답 짝 오류·ROM fault를 픽셀 경로로 숨기지 않는다.180 실기에서 fetch 오류0이었던 근거에 맞춘 범위다.7행을 초과하거나 픽셀이 빠지면 전체 후보를 거부한다.

## 후보 내부 데이터 규격

이 규격은 새 exporter/MCU와 함께 버전을 올려야 하며 기존0x1741 wire header로 내보내면 안 된다.

| 내부 조회 | 내용 |
| --- | --- |
| kind0..6 | 기존 map/행/객체/예외/raster/팔레트/required 조회 |
| kind7 | index10..8=보존 슬롯,7..0=x;6비트 최종 색 |
| raster bit49 | 완성된 원시 픽셀 행 표시 |
| raster52..50 | 보존 슬롯0..6 |
| 대체 행의 나머지 raster 필드 | 0; 일반 mask·map 검증 전에 대체 행으로 분기해야 함 |

슬롯7은 임시 쓰기 공간이므로 읽기를 허용하지 않는다. 전체 후보가 유효하고 세대가 같아야 어떤 kind든 읽을 수 있다. 늦은 ROM fault와 release 후에도 공개하지 않는다. 픽셀 RAM은 이전 작업의7보존+1임시 구조를 재사용하며 세이브 SRAM에 접근하지 않는다.

| 시험 | 결과 |

수집기 시험은 실제 fetch와 새 compact/raster를 결합하지만 **입력 PPU 인터페이스는 합성 파형**이다. 별도 PPU 시험은 수정하지 않은180 PPU, 결정적 외부 VRAM, 실제 PPUMASK 쓰기와 CE 간격을 사용한다. CPU·MMC3·실제 SMB3 실행이나 모든 수집기를 동시에 연결한 시험은 아니다. 둘을 합쳐 전체 게임 실행 통과라고 해석하지 않는다. 이전 SNES114,688픽셀 시험은 변경하지 않은 독립 변환 경로의 기존 근거이며 이번에 재실행하지 않았다.

첫 결합 시험은 fixture가 실제 fetch 구간 뒤 dot337/339에서도 prefetch를 중복 생성해 실패했다. 입력을321..335 구간으로 고친 뒤 통과했으며 실패 로그를 보존했다. 이후 객체·팔레트와 정상 복구 비교를 추가한 최종 시험은 `test04`다. PPU 시험의 경고는 관측하지 않는 출력, 기존 debug 포트 폭 및 사용하지 않는 `extra_bits` 입력이며 출력 픽셀의 X값은 별도로 거부했다. 최종 해시와 근거는 [검증 데이터](../analysis/collect181-verification.json)에 있다.

## 다음 작업 — 이 경계를 반복 시험하지 말고 소비 경로로 이동

1. 새 버전 exporter/MCU 수신 규격에 행 슬롯과 최대1,792색 바이트를 추가한다. 일반 섹션·모든 CHR의 완결성과 missing0/lane0을 확인한 **명시적 CHR 종료 경계 이후** 기존 `required[2048]`를 재사용한다. 이후 CHR 재진입은 거부한다. 아직 구현되지 않았다.
2. MCU 변환에서 대체 행의 map/일반 mask 검증을 생략하고, 기존 OBJ가 해당 행에 다시 그려지지 않게 한다. 앞선 SNES mode3/CGRAM64..127/VRAM공백/3HDMA 구현을 배포 클라이언트 staging·뱅크 전환·최종ACK·STOP에 연결한다.4096바이트 ROM 및 WRAM 충돌을 확인한다.
3. 실제 보드 상위 연결에 color/emphasis와 새 수집기·조회7·버전을 반영한다. 한도 증가는 없이 전체 ARM stack과 FPGA 자원·타이밍/조건부 IO를 승인한 다음 새 SMB3 실기 패키지를 만든다. 현재 기준180은15,061LE/962LAB이며 새 후보 FIT는 아직 없다.
4. 실제 숫자1→A 첫 레벨로 확인한다. 정지 해소와 별도로 차분/base-generation/최종ACK의 지연과 유효 전송량을 개선해 약60fps를 목표로 한다. 그 뒤 장시간 플레이·오류/리셋 로그·입력 유지 검증으로 간다.

새 FW/FPGA/ZIP은 없으며 같은180·044 재시험은 요청하지 않는다. GBC·164 복구판·기존 근거·세이브 SRAM을 유지한다.
