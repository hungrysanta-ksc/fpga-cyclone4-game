# NES145 — 검정 구간과 고정 그림을 영상으로 비교

NES144에서 읽을 수 있는 글자와 메뉴 복귀는 성공했지만, 육안으로 부분 갱신이 보였습니다. 이번에는 받은 그림을 즉시 연속 갱신하지 않고, 검정과 고정 그림을 분명히 나눠 확인합니다. 실기 원인을 확정하거나 수정 완료한 시험판은 아닙니다.

## 실행 방법

1. 전원을 끄고 교체할 SD 파일을 별도 보관합니다.
2. ZIP의 `01-SCREEN145-SD-ROOT` **안의 내용**을 SD 최상위에 복사합니다. `sd2snes/firmware.stm`, `fpga_n145.bi3`, `nes/screen145.nes`를 함께 적용합니다. 동봉된 base/menu도 해당 폴더 구성을 따릅니다.
3. 메뉴에서 **`NES SCREEN 145.nh1`**을 한 번 실행합니다. 이 선택 파일은 0바이트가 정상이며 확장자를 바꾸지 않습니다.
4. 적재·전량 대조는 이번에도 약 9분입니다. 144 실측은 적재 약3분28초+대조 약5분11초였습니다. 이후 약1분 표시하고 자동 메뉴 복귀합니다. 실행부터 **최대11분**, 표시 시작부터 **최대90초**를 관찰 기준으로 삼습니다. 초과하면 전원을 끄고 남은 두 TXT를 회수해 주세요.

## 촬영할 구간과 기대 모습

대기 9분 전체는 촬영할 필요가 없습니다. 실행 후 약8분30초부터 준비해 **그림 표시 시작부터 메뉴 복귀까지** 연속 영상으로 찍어 주세요. 휴대폰을 가능한 한 고정하고 TV 전체가 들어오면 됩니다.

처음 파란 대기 화면이 잠깐 나올 수 있습니다. 이후 다음을 반복합니다.

- **검정 약1.5초**(NTSC90프레임, PAL이면 약1.8초).
- **받은 NES 그림 약3초 고정**(NTSC180프레임, PAL이면 약3.6초).
- 다음 그림을 받아 같은 순서 반복. 전체 표시 구간은 명목60초이며 실제 보호 검사 시간에 따라 조금 길어집니다.

**화면 글자는 의도적으로 `NES 144` 그대로입니다.** 145는 기존 NES 프로그램·그림을 그대로 쓰고 SNES 표시 방식만 바꿉니다. 실행 표식·펌웨어·로그 이름은145입니다. ZIP의 `EXPECTED-SCREENS.png`는 에뮬레이터에서 검증한 A/B 기준 그림입니다. 실제 수송은 프레임을 건너뛸 수 있어 반드시 A→B→A 순서가 된다고 보증하지 않습니다. 위아래 그림이 반복되는 형태는 원래 설계입니다. 무음이며 패드 입력은 아직 없습니다.

특히 **검정 뒤 그림이 완성된 상태로 나타나는지**, **3초 고정 중에도 글자가 부분적으로 계속 바뀌는지**, **위아래 A/B가 섞인 채 그대로 고정되는지**가 중요합니다. 카메라/CRT 대각선 밝기 띠는 고장으로 판정하지 않습니다.

## 보내줄 결과

- 표시 구간의 연속 영상
- `sd2snes/nes-progress-145.txt`
- `sd2snes/nes-screen-last-145.txt`
- 자동 메뉴 복귀 여부

그림이 섞여도 한 번의 시험 결과로 전달하면 됩니다. 같은145 재실행이나 변하지 않은044/GBC 복원 재시험은 요구하지 않습니다. 동봉된 `02-RESTORE044-SD-ROOT`는 필요할 때 쓰는 기존 복원본입니다. 교체·복원은 전원을 끈 상태에서 합니다.

## 시간과 판정의 한계

이번에는 전송 속도·검증 생략을 동시에 바꾸지 않았습니다. 9분은 NES 본래 실행 요구가 아니라 현재 GPIO SPI와 바이트별 적재·전량 대조 비용입니다. 로딩 단축은 미완료이며 다음 별도 개선 항목입니다. 한 번 적재한 뒤 여러 화면 전환을 관찰해 반복 대기를 줄입니다.

FPGA 회로·배치·ID5E/D9, NES ROM, ROM 전량 대조, RUN 중 SD쓰기 금지, 오류 차단·STOP·메뉴 복귀를 유지합니다. 화면 관측값은 `screen_telemetry_trusted=0`이므로 stage/mask/frames만으로 표시 성공이나 FPS를 판정하지 않습니다. 실기 영상의 시간과 그림을 함께 봅니다. SMB3 플레이·입력·오디오 완료를 뜻하지 않습니다.
