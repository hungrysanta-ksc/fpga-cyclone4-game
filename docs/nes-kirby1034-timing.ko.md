# 커비 15타일 화면의 입력과 네 뱅크 반환

PR181 병합 `170a23ec`에서 시작했다. MMC1027 2차의 두 화면은 BG 661·OBJ 16·변경 map 2·타일 15·반환 묶음 4·마지막 OBJ 192B·오프셋 320B가 일치한다. 각 화면에서 **직전 화면을 공개한 순간을 0**으로 잡았다. 음수는 이전 화면의 표시를 기다리는 동안 이미 끝났다는 뜻이다.

| 실기 사건 | 58.03초 · 세대 1526 | 59.63초 · 세대 1561 |
|---|---:|---:|
| 마지막 D2 뒤 다음 토큰을 D0에서 확인한 후의 ARM 입력 완료 | −5.74∼−4.10ms | +7.72∼+9.36ms |
| 첫 E9 명령 바이트 | 11.31ms | 19.50ms |
| 마지막 출력 묶음의 첫 plan 수락 | 14.82ms | 31.21ms |
| 마지막 타일 뱅크 공개 | 31.60ms | 47.59ms |
| 화면 공개 | 49.93ms | 66.32ms |
| 최종 ACK | 50.32ms | 66.32ms |

입력 완료의 차이는 **11.82∼15.09ms**다. 이 가운데 일부가 입력 완료 후 첫 E9까지 회복되어 첫 E9의 차이는 8.19ms다. 이후 마지막 묶음 시작까지 8.19ms가 더 쌓였다. 종료 쪽의 완료→writer는 두 화면 모두 한 눈금 이내였다. 1027은 E9의 명령 바이트를 첫 기준으로 기록한다. 실제 수락은 SPI 거래가 끝나고 FPGA가 패킷 형식 등을 확인한 뒤 발생한다. 한 E9 패킷과 한 출력 뱅크는 개수와 경계가 다를 수 있다.

해당 두 세대에는 첫 블록 준비·첫 D1·개별 D2 응답과 각 E9 수락·뱅크 반환 시각이 없다. 1027의 같은 회차에서 패킷 상세 표본이 남은 세대는 1446·1518이다. 후속 MMC1029–1032의 입력 계측에서 두 세대와 출력 작업량 여덟 항목이 일치한 표본은 0개였다. 소급해서 공급 순서나 SPI 점유를 특정할 수 없다. [원본별 해시·세대·측정 범위](../analysis/kirby1034-timing.json)

## 어디부터 줄일 것인가

MMC1029–1032의 각 회차 안에서 2초 이내, 출력 작업량 8항목과 입력 블록 수·바이트가 일치하고 표시 간격이 약 한 VBlank 이상 다른 화면을 찾았다. 두 쌍 모두 MMC1029에서 나왔다. 첫 D1 시각은 D0 확인 뒤 입력 완료 표식과 실제 수신 소요로 추정한 범위다.

| 세대(느림→빠름) | 작업량 | 첫 D1이 앞당겨진 범위 | 첫 D1→반환 확인 | 표시 간격 | 최종 ACK |
|---|---|---:|---:|---:|---:|
| 1012→1024 | 5타일·17블록·1,756B | 11.61∼14.88ms | 11.453→11.457ms | 49.93→32.77ms | 49.93→33.16ms |
| 1487→1499 | 7타일·17블록·1,774B | 10.24∼13.51ms | 11.515→11.298ms | 49.54→33.16ms | 49.54→33.55ms |

먼저 첫 블록 **준비 시각과 첫 D1 발행 시각**을 비교한다. 준비 시각 자체가 밀리면 이전 캡처·입력 버퍼 반환을, 준비 후 첫 D1이 밀리면 같은 시간의 ARM 발행·공유 SPI를 추적한다. 위 두 쌍은 독립적인 관찰이므로 15타일 화면에 적용했을 때 회복할 VBlank 수는 아직 모른다. 첫 E9 이후에는 마지막 plan 시작까지 각 E9 수락과 토큰별 반환의 선후를 비교한다. 두 사건이 같은 0.390ms 눈금이면 순서를 판정할 수 없다.

## MMC1034 계측과 재현

- MMC1032의 기본 캐시와 첫 블록 준비 계수기를 재사용한다. ARM은 첫 D1 호출 시작·길이, 마지막 검증된 D2 응답, 다음 토큰을 D0로 확인한 시각을 보관한다. 원래 CRC·토큰 검사를 통과해야 기록이 유효하다. FPGA의 첫 D1 명령 시각은 ARM의 첫 SPI 호출 안에 있으므로 준비 시각에는 그 호출 길이와 두 타이머의 오차를 포함한다.
- 추가 SPI 조회 없이 기존 32B 헤더를 쓴다. 네 E9 수락과 네 토큰 반환에는 독립된 쓰기 포트가 있다. 다섯 번째 E9가 있으면 목록 일부만 남았다고 표시하며, 반환이 네 개를 초과하면 묶음별 시각을 해석하지 않는다. 표시 세대·토큰, 마지막 plan 시작, SEAL·공개·최종 ACK를 확인한다. 이전 마지막 DMA 타임스탬프 자리는 재사용하며 DMA 발생 검사는 유지한다.
- 55–57.5초에는 100ms, 57.5–60초에는 50ms 간격으로 최대 75개 화면을 기록한다. 이번 판은 15타일 표본을 다시 포착하기 위한 진단판이다. 다른 계측 빈도로 측정한 FPS를 직접 최적화 성과로 쓰지 않는다.
- 보드 생성은 `tools/prepare_nes_kirby1034.py ../probes/nes-kirby1034/board-shared`, ARM 생성은 같은 도구의 `--arm ../probes/nes-kirby1034/link`를 사용한다. ARM 전체 링크, FLOAT 래퍼의 `tools/check_nes_kirby1034.ps1`, Quartus Lite의 `tools/fit_nes_kirby1027.ps1` 순으로 검증한다. ARM 입력 시험은 `tools/check_nes_kirby1031.py 1034`, base 복구는 `tools/check_nes_kirby1023_release.py base 1034`, 계측·메뉴 시험은 `tools/check_nes_kirby1034.py`, 패키징은 `tools/package_nes_kirby1034.py`다.
- 첫 회로는 966 LAB를 요구해 FIT에 실패했다. 직전 공개 시각을 기존 RAM에서 번갈아 읽도록 바꾼 뒤 전체 FIT·STA를 통과했다. 57개 STA 항목의 최소 여유는 +0.065ns다. [최종 링크·보드·복귀 검증](../analysis/trial1034-package.json)
- 실기 BIN은 `tools/read_nes_kirby1034.py <BIN>`으로 읽는다. 같은 작업량에서 준비·수락이 앞당겨지고 공개와 최종 ACK가 함께 직전 VBlank로 이동했는지가 후속 최적화의 판정 조건이다. [실기 시험 절차](nes-mmc1034-trial.ko.md)
