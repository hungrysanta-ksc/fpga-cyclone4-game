# 665: VBlank 진입 전 DMA 설정과 914 추가 대기 제거

664 all의 section 5 선행 발행을 그대로 두고 65816의 DMA 설정 순서만 바꿨다. **두 시작 위상에서 914는 3 VBlank·최종 추가 대기 0회로 복구됐고, 952의 3 VBlank와 MMC662 대비 밀집 표시·957 마지막 ACK 이득을 유지했다.** ROM을 넣은 전체 Quartus Lite FIT·STA도 통과했다. 새 실기 결과나 60fps 달성 주장은 아니다. [검증 JSON](../analysis/entry665-verification.json) · [이전 비용 분해](nes-output664-results.ko.md) · [PR154](progress/pr-154.md)

## 변경 경계와 원인

664 위상 1의 914는 같은 DMA 작업량에서도 첫 명령 진입이 MMC662보다 238 master clocks 늦었다. 246번 선 경계의 검사를 넘겨 다음 VBlank까지 기다렸다. 최종 검사선을 늦추지 않고 다음 두 비용을 줄였다.

- 독립 검사를 마쳐 불변인 SEAL 명령 그룹의 DMA 채널 0 설정(DMAP/BBAD/A1B)과 명령 cursor 적재를 `wait169` 앞으로 옮겼다. 이 설정 자체는 DMA를 시작하거나 VRAM을 쓰지 않는다. HDMA는 채널 1–3을 사용한다. `service`는 X와 채널 0 설정을 보존하며, STOP 때 이력을 무효화한다.
- VBlank 진입을 확인한 뒤 사용하지 않는 대기 카운터 재설정을 제거했다. 다음 호출 입구와 active→blank 전환의 초기화, 두 단계의 제한 횟수·STOP 검사·carry 반환은 유지했다.

기존 본문의 변경은 5바이트이고 새 설정 경로는 32바이트다. 원래의 선행 DMA 경로는 기존 설정을 계속 사용한다. 독립 identity/coverage/CRC, raw 복원, 최종 246번 검사선, 화면 공개와 최종 ACK, 부분 전송 무효화 코드는 바이트 그대로다. generation이나 시작 위상별 분기는 없다.

## 같은 작업량의 연속 일정

실제 링크 ARM·65816, CPI2/SysTick/SPI 모델, 같은 반복 ROM 허용 달력과 시작 시각 7,288,416 / 7,467,100을 사용했다. 각 905–957의 53화면, 총 106화면이다. 664와 같은 ARM firmware이며 map·OBJ 작업량, 확장 section 5, 화면·CGRAM·OAM·최종 ACK를 대조했다. 시작 handshake 시각도 원본과 같다. 실제 물리 평균 출력 26.51ms를 이 재생의 단계 값으로 환산하지 않는다.

| 지표 | MMC662 위상 1 / 2 | 664 all 위상 1 / 2 | 665 위상 1 / 2 |
|---|---:|---:|---:|
| 914 표시 간격, VBlank | 3 / 3 | 4 / 3 | **3 / 3** |
| 914 최종 추가 대기 | 0 / 0 | 1 / 0 | **0 / 0** |
| 952 표시 간격, VBlank | 4 / 4 | 3 / 3 | **3 / 3** |
| 밀집 951–955 합계, VBlank | 16 / 16 | 15 / 15 | **15 / 15** |
| 밀집 평균 표시 간격, ms | 53.243950 / 53.243671 | 49.919878 / 50.016930 | **49.920847 / 49.916880** |
| 957 최종 ACK, master clocks | 67,879,890 / 68,237,054 | 67,879,322 / 67,879,684 | **67,517,358 / 67,879,420** |

MMC662 대비 밀집 평균은 −3.323104 / −3.326791ms, 마지막 ACK는 **−16.879797 / −16.651742ms**다. 664 대비 마지막 ACK는 −16.853351 / −0.012292ms다. 위상 1의 밀집 평균은 664보다 **0.000968ms 늘었고**, 위상 2는 0.100050ms 줄었다. 따라서 모든 연속 시간 값이 664보다 엄격하게 개선됐다고 주장하지 않는다. 요구한 VBlank 횟수와 MMC662 대비 이득 유지, 마지막 ACK 개선을 각각 판정한다.

914의 664→665 첫 DMA 시각은 위상 1에서 462 clocks(약 21.51µs), 위상 2에서 224 clocks(약 10.43µs) 빨라졌다. 이 값은 명령 절약뿐 아니라 polling 진입 위상·WRAM refresh 차이도 포함한다. 위상 1은 대기 반환이 342 clocks 빨라지고 반환→첫 DMA가 120 clocks 짧아졌다. 최종 검사 진입은 두 위상 모두 245번 선이며, 기존 246번 선 검사 뒤 같은 VBlank의 251번 선에 공개했다. 251번 선 공개를 246번 제한 완화로 해석하지 않는다.

951 공개선 239/239, 954·955 각각 3 VBlank, 957 최종 대기 0회를 유지했다. 전체 52 warm 간격에 새 VBlank 횟수 회귀나 새 최종 대기는 없다. warm 출력·최종 ACK 평균은 28.910226 / 28.930506ms다. 이것은 물리 26.51ms와 모집단·모델이 다른 값이다.

## 안전 조건과 비용

설정 이동 경계·active/blank 대기·두 뱅크의 raw 처리·최종 표시 직전에 STOP을 주입한 8조건을 통과했다. 취소 뒤 추가 DMA와 최종 표시 ACK가 없고 이전 RGB가 유지된다. 두 대기 단계에서 카운터 만료를 주입한 2조건도 통과했다. 독립 검사·최종 검사 코드는 기존 본문과 직접 바이트 대조했다.

ARM은 664 all의 동일 바이너리이므로 수신 IO/CRC/service/deadline, 잘못된 credit·중간 STOP·최종 ACK, 메뉴 4종·base 복구 5종의 기존 실제 링크 검증을 유지한다. 캡처 회복 회로도 동일 HDL이다. 이번 재생은 외부 메뉴 하드웨어나 실제 PSRAM 전체 RTL의 새 실기 시험이 아니다.

| 자원 | MMC662 / 664 | 665 |
|---|---:|---:|
| ARM Flash | 212,508 / 212,496 B | **212,496 B**, 여유 496 B |
| ARM data / BSS | 10,040 / 19,544 B | 동일 |
| 65816 복원 본문 | 5,760 B | 5,792 B, 기존 예약 공간 여유 192 B |
| 물리 ROM | 5,120 B | 동일, 압축 저장 여유 11 B |
| 전체 LE / 조합 / FF | 15,324 / 14,418 / 8,386 | 동일 |
| LAB / M9K | 962 / 56 | 동일, 여유 1 LAB·0 M9K |
| setup / hold, ns | +0.511 / +0.149 | 동일 |
| recovery / removal, ns | +1.828 / +0.393 | 동일 |

보드 입력 82개에서 ROM 내용만 변경됐음을 해시로 확인했다. 동일 제약의 모든 corner TNS=0, unconstrained 항목 수 무회귀, ROM_OE 최소 +2.142ns다. 외부 IO 전체 sign-off는 기존과 같이 미완료다. `timing_gate`와 제한 전달 준비 판정은 true이며, 새 ZIP·실기 설치는 아직 하지 않았다.
