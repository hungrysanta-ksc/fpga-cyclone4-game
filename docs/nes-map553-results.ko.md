# 553. 마지막 tile 소비와 후속 map 발행

PR147의 마지막 커밋 `6f7fae1`이 `origin/master`의 병합 커밋 `2211a80`에 포함됐고 두 tree가 같은 것을 확인했다. 실기 기준은 MMC551이다. 성공 실행에서 5–55초에 672회 표시했고, 별도 실행에서 발생한 SNES 준비 타임아웃은 성능 집계에서 분리했다. [실기 기준](nes-hardware552-results.ko.md)

## 변경한 전송 경계

957에서는 실제 ARM이 BG map을 확정한 시점의 4,096B 해시와 최종 map 해시가 같다. section 2의 offset 3008·3200·3392에서 발행된 192B씩을 그 확정본과 직접 비교했다. 기준 경로는 map 발행 준비 중 새 tile descriptor를 발견하면 bulk를 먼저 큐에 넣고, 그 소비를 확인한 뒤에 map을 넣는다. 단순히 마지막 ACK 뒤에 큐가 비었던 시간을 줄일 수 있는 시간으로 계산하면 이 순서와 map 자체의 전송 비용을 놓친다.

553은 이미 END가 수락되고 출력 검사가 끝난 map 발행 경로에서만 이 순서를 바꾼다. 새 bulk 발행 직후 캐시된 sent−retired가 2 이하이면 이미 확정한 map 하나를 그 뒤에 넣는다. 4칸 큐에 최소 한 칸을 남긴다. 기존 bulk의 토큰과 완료 지점은 유지하며 같은 descriptor가 다시 오면 내용을 대조하고 실제 반환을 기다린다. 다음 bulk, 일반 명령 및 최종 SEAL의 검사와 STOP 경로를 그대로 사용한다. FPGA·65816·전송 형식에는 변경이 없다.

MMC551과 실행 함수가 같은 550 연속 기록, 552 보고 수정만 포함한 ARM, 보고 수정과 이 변경을 결합한 ARM을 구분한다. 같은 입력 905–957·ROM 허용표·두 시작 시각에서 비교하며 실제 실기 FPS는 새로 측정하지 않는다. 링크된 경계 시험은 새 tile 지연, 앞선 일반 패킷 0·1·2개, map 이외 section, STOP, 같은 토큰의 변조된 descriptor, 잘못된 E0 응답을 다룬다.

## 전송 시각과 전체 결과

552 보고 수정만 넣은 대조군은 두 위상 모두 MMC551 기준 실행과 ARM 이벤트·PUSH·65816 소비 시각 파일의 SHA256이 일치했다. 957에서 출력 함수 진입을 0ms로 잡으면 map 확정은 대조군 −5.079 / −4.863ms, 후보 −5.079 / −4.865ms였다. 아래 시각은 **각 실행 자신의 마지막 tile ACK**로부터 map PUSH까지의 차이다. 음수이면 실제 소비 완료보다 먼저 전송됐다.

| 957 map offset | 대조군 위상 1 / 2 (ms) | 553 위상 1 / 2 (ms) |
|---:|---:|---:|
| 3008 | +1.570 / +1.58 | −2.033 / −2.092 |
| 3200 | +2.59 / +2.61 | −0.270 / −0.329 |
| 3392 | +3.61 / +3.63 | +1.48 / +1.70 |

두 번째 map까지 앞당겼다. 세 번째는 직전 map 발행을 마치고 다음 E8·credit 처리를 거쳐야 했다. 예를 들어 위상 1에서 세 번째 map 함수 진입은 약 11.76ms, 마지막 tile ACK는 12.03ms였다. 그 사이 약 0.27ms는 192B map의 E1 전송 한 건(약 1ms)보다 짧았다. 수신·반환과 발행은 별개이며 각 패킷의 실제 65816 head 수락, ACK 및 ARM의 첫 E0 반환 관측 시각을 따로 기록했다.

| 연속 일정 | 대조군 위상 1 / 2 | 553 위상 1 / 2 |
|---|---:|---:|
| 957 마지막 tile ACK → SEAL 수락 | 16.457 / 16.541ms | 14.479 / 14.668ms |
| 953 마지막 tile ACK → SEAL 수락 | 약 1.76 / 1.76ms | 약 1.76 / 1.76ms |
| 밀집 951–955 평균 표시 간격 | 93.2119 / 93.2154ms | 93.2130 / 93.2119ms |
| 밀집 합계 VBlank | 28 / 28 | 28 / 28 |
| 53번째 화면 ACK 차이 | 기준 | −49.914 / −33.297ms |
| 952 직전 표시→SEAL / 957 최종 대기 | 두 위상 5 / 0회 | 두 위상 5 / 0회 |

전체 마지막 ACK의 단축과 957에서 줄어든 약 2ms를 구분했다. 화면별 표시 간격에서 한 VBlank가 줄어든 세대는 위상 1의 912·936·937과 위상 2의 937·946이었다. 952·954의 최종 대기는 0회였고 첫 BG가 더 늦은 상대 ROM 허용 구간으로 밀린 사례는 없었다. **밀집 표시가 빨라지는 조건을 충족하지 못해 실기 전달은 보류한다.** 553은 후속 조합 비교용으로 보존한다.

네 공동 실행에서 각각 기대 RGB 53장, ROM 읽기 5,616회, VRAM DMA 114,352B, 두 bulk 슬롯 및 최종 ACK를 확인했다. 독립 재생도 각 공동 실행의 전체 소비 이벤트·클록·RGB와 일치했다. Flash 212,872B는 보고 수정 대조군보다 72B 많다. 여유는 120B이고 BSS는 18,592B다. 기존 4credit wrap·오류 주입, 이전 비용 무효화, 5–40초·40–55초 집계와 링크된 메뉴 정상/실패 분기도 통과했다. 보드 RTL·ROM은 MMC551과 동일해 Quartus를 다시 실행하지 않았다.

다음은 954의 VBlank 경계다. 두 위상 모두 SEAL은 232행에서 수락됐고, 검사 뒤 업로드 대기 함수 진입은 다음 스캔의 11 / 12행이었다. 마지막 tile ACK 뒤 SEAL까지 map 없이 CGRAM·OAM·HDMA 및 SEAL 18개(1,292B)가 남아 12.76 / 12.84ms 걸렸다. 첫 ordinary payload 준비와 발행을 분리해 이 중 어느 부분을 앞당겨야 이전 VBlank에 들어갈 수 있는지 측정한다. 953을 대조하고 957 두 map의 선행, 독립 검사와 STOP·최종 ACK를 유지한다.
