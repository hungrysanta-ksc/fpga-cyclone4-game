# 715 BG 탐색·slot/plan과 map 쓰기 분리 검증

## 목표

707D·기존694/704 ARM·기존694 65816에서 BG 탐색·slot 확정·plan 발행과 나머지 map 행 쓰기를 분리한다. 추가 계산·SPI·Flash·stack을 포함해 두 시작 위상 모두 **952–957 표시 합계18 VBlank 미만, 밀집 평균 감소,957 마지막 ACK 단축**을 만족해야 채택한다. STOP·독립 검사·최종 ACK·메뉴와911/951/952/957 보호 조건을 유지한다. [검증](../analysis/split715-verification.json) · [원시 근거](../analysis/split715-archive.json)

## 작업내용

실제 ARM 첫 순회에서는 기존 순서대로 tag 검사·exception 해석·정확한 key 비교·slot 예약·plan 생산을 실행한다. map 대신 확정 slot을 임시 저장한다. 같은 프레임의 정확히 같은 행은 canonical 행 번호를 보관한다. 이후 남은 BG 묶음을 실제 E8/E9로 발행하고, 두 번째 순회에서 slot·현재 palette·column을 조합해 기존 map writer와 dirty/stale 검사를 수행한다. 완료 행만 기존 row callback으로 발행한다. slot 예약/plan 수락은 map 완료나 최종 표시 ACK가 아니다.

별도 버퍼를 추가하지 않고 아직 생산하지 않은 OAM·CGRAM·HDMA 영역2177B 중2144B를 빌렸다. slot32×33×2=2112B와 행 참조32B다. 구조체 전체의 byte 표현으로 접근하며, 최대 경계는 정적 assertion으로 확인했다. BG key는 첫 순회 내내 유지하고 이미 사용한 slot은 재할당하지 않는다. map 완료 뒤 OAM544B·CGRAM512B를 모두 지우고 새로 생산한다. HDMA는 실제 발행하는 `hdma_size` 범위를 다시 쓴다. 사용하지 않는 HDMA 꼬리에 남은 scratch는 송신하지 않는다. 오류/STOP 후 resident abort와 cold 전체 복원 정책은 원본 그대로다.

정상60초·장시간 ARM을 각각 전체 링크했다. 장시간 후보 하나로 실제 M4/65816을53화면×두 위상 끝까지 실행했다. 시작7288416/7467100, 입력·map/OBJ 작업·공유SPI·IRQ·2bulk·ROM 달력·65816은 대조군과 같다. 모든 scratch 읽기의 초기화, canonical 참조/slot 범위, 두 페이지33셀의 완료, 발행한 map의 불변성·중복 금지를 실제 실행 중 확인했다.

모든 관측 화면은29개 행이며, canonical 행23/25/26/29개 조건을 포함한다. 32행 최대 조건을 통합 실행했다고 주장하지 않는다. 이는 실제 링크 코드와 모델 일정의 비교이며, 실물 FPS나 게임 NES/PSRAM 전체 RTL의 동시 실행이 아니다.

954의 BG 생산은 약1.60–1.89ms,발행은1.77–2.06ms 빨라졌다. 그러나 마지막 E9는 직전 ROM 허용 구간의 끝보다 **1.355/1.572ms 늦다.** 955도0.318/1.387ms 늦다. ROM 읽기 자체까지 해당 구간 안에 완료하려면 더 많은 선행이 필요하며, 이 차이를 충분한 구현 예산으로 해석하지 않는다.

반면 첫 map 수락은954에서6.130/6.218ms,955에서5.695/5.431ms 늦어졌다. 모든 BG를 탐색한 뒤 map을 쓰는 경계가 기존 조기 발행 기회를 제거했다. 선행 map DMA는952의1536/1920→384/384B,954의320/384→64/192B,957의2048/2048→512/1664B로 감소했다. 955는 위상1에서1472→1856B지만 위상2에서1728→64B여서 한 위상의 국소 이득으로 채택할 수 없다.

**714의 원인 가설도 수정한다.** 당시955의 마지막 BG 뒤 남은 행 작업2.385ms를 map 쓰기와 분리해 보니, 이번에도 BG 예약 완료까지 **2.149ms가 남았다.** 대부분은 map 저장 자체가 아니라 나머지 셀의 탐색·key/slot 확인을 포함한 첫 순회였다. map 쓰기만 뒤로 옮기는 것으로 이 시간을 없앨 수 없었다. 여기에 실제 BG flush0.489ms가 이어진다. 954도 마지막 BG 반환 후0.844ms의 남은 탐색과flush0.532ms를 지급한다.

두 번째 map 순회는954/955에서 callback·SPI를 제외한 잔여 시간이약1.073/1.056ms다. IRQ를 포함하므로 순수 산술 시간으로 단정하지 않는다. BG fence부터 map 완료까지는 callback을 포함해954 2.994/2.780ms,955 2.719/2.722ms다. 원래 행 안에서 하던 일을 별도 순회·저장·읽기로 바꾸어 총비용을 늘린 것이다.

`map_word185`의92B 심볼은 사라졌지만 planner가같은92B 증가했다. 이는 인라인 이동이며 순삭제가 아니다. callback16→28B 때문에 전체 Flash는12B 늘었다. 정상판과 공동 발행 경계가4B 초과했으며 시간도 실패했으므로, 크기만 맞추는 추가 미세 조정은 하지 않았다. 장시간판만 자원 한도 안이라는 사실을 정상판 통과로 대신하지 않는다.

후보 관측stack 최저주소는두위상 모두`0x2000f814`,workspace끝`0x2000f0e0`과1844B 차이다. 이는 관측값이며 전체 stack 최악 상한은 아니다. OAM/CGRAM 재초기화와slot 저장/읽기 비용도 실제 ARM 실행에 포함했다.

53화면 전체 ARM 명령은 **+1,173,023 /+707,505**이며 계산뿐 아니라 조회·대기·IRQ도 포함한다. map E1 바이트는 동일하다. BG/OBJ 분리 flush 때문에 E9가두위상 모두264B(33거래) 증가했다. E0는+900/+440B,E8은−140/−1020B,D0는−24/+80B로,전체 SPI 변화는+1000/−236B다. wire 감소가 있었던 위상2도 최종 표시는 느려졌다.

보드·SDC·65816은 변경하지 않아 새 합성은 실행하지 않았다. 707D 전체 Lite FIT15,322LE·962LAB·56M9K와setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다. 기존 외부IO sign-off 미완료와707D 수정의 실기 확인 범위는 확대하지 않는다.

### 안전·실패 근거

- 실제 링크 M4의7조건: BG fence에서map 미공개,실제plan/bulk완료와표시ACK분리,cold4096B전체복원,STOP,E8 CRC,credit CRC,모호한E1 차단을 확인했다. 단위 endpoint는 SPI 시간/receipt 모델이다.
- runtime16조건과메뉴준비·해제5조건/marker4조건을 통과했다. 실제 게임 실물 메뉴를 새로 실행한 것은 아니다.
- 후보 패킷을 기존65816에 넣어 STOP4조건·사용자종료2조건을 확인했다. 이전표시 보존·최종ACK 취소·종료뒤 DMA/ACK 중단을 유지했다.
- 첫 통합 실행은 인라인된`map_word185` 심볼을 찾는 관측기에서 타깃 실행 전에 실패했다. 실제 메모리 쓰기를 읽는 관측기로 보완했으며 타깃 바이너리는 바꾸지 않았다. 첫단위guard는 잘못된END뒤rowoffer순서를 호출했다. 실제runtime와같은END전순서로고쳤고실패로그/스크립트를보존했다.

## 후속작업

1. **707D·기존694/704 ARM·기존69465816을 유지한다.** 이번 전체프레임 BG-first 분리와714 전체완료 fence,713 행별송신 변형은 새근거전까지 반복하지 않는다. 새설치본은 없다.
2. 다음은 발행 순서를 다시 바꾸기 전에 **일반 BG의 동일프레임 exact-slot hit에서 매번 만드는40B plan과남은tag/key/slot확인 비용**을 원본에서 분리 계측한다. 기존hash index와정확한key비교가있으므로 새캐시라고중복구현하지않는다. hit 판정 전에필요한tag/shape/epoch검사와STOP소유권을유지하고, 실제로 불필요한 descriptor 생성만 제거할 수 있는지 확인한다. 시간절감을아직입증하지않았다.
3. 기존map행완료·SPI순서·큰plan묶음을보존한채 계산량을줄이는후보만진행한다. 추가전처리·2차순회·임시저장·별도flush를공짜로계산하지않는다. 정상원본Flash여유는8B,공동경계상한1116B,추가정적RAM≤4B,FPGA/65816증가0이며 **순삭제입증0B**다.714의여유244B는미채택후보의공간이므로재사용가능제품예산이아니다.
4. 두 위상의911마감·951공개·952표시3회·957대기0·7블록·STOP·독립검사·cold복구·최종ACK·메뉴와,952–957합계18회미만·밀집평균·957ACK동시개선을다시판정한다. 계산감소가이마감을넘기지못하면공급순서상수탐색으로넘어가지않는다.
