# 889 · 959 OBJ 큐 반환과 두 번째 E0

실기 기준은 MMC872다. 889는 888의 ARM과 기존 FPGA를 그대로 쓰고, 65816이 타일 descriptor를 검사하는 동안 정상 패킷이 거치는 분기를 줄였다. 크기·section·DMA 범위·정렬 및 별도로 읽은 descriptor의 여섯 필드를 같은 순서로 검사한다. 실패 분기는 기존 오류 처리로 모인다. ARM의 E0 조회 주기는 그대로다.

## 같은 패킷을 같은 시각에 수락한 대조

밀집 세대 959의 OBJ offset 416 한 패킷만 새 검사기로 처리했다. SPI 도착 시각을 고정한 첫 시험에서 원본을 다시 실행해 959까지의 전체 이벤트가 일치하는지 확인했다. 아래 값은 SNES 마스터클록이다.

| 측정값 | 위상 1 | 위상 2 |
|---|---:|---:|
| 두 검사기의 동일한 진입 시각 | 57,653,982 | 58,011,452 |
| 검사 진입부터 데이터 처리까지, 888 → 889 | 1,292 → 1,230 | 1,292 → 1,238 |
| 큐 반환 시각, 888 → 889 | 57,664,506 → 57,664,424 | 58,021,946 → 58,021,906 |

위상 1에서 두 번째 E0는 57,664,443클록에 시작한다. 888에서는 반환보다 63클록 빨랐고, 한 패킷을 교체하면 반환보다 19클록 늦다. 실제 SPI 응답과 후속 OBJ·SEAL 시각은 아래 연속 실행에서 비교한다.

## 부팅부터 이어서 실행한 결과

왼쪽과 오른쪽은 각각 시작 위상 1과 2다. 밀집 60간격은 워밍업 두 화면 이후의 표시 사이 VBlank 수를 합한 값이다.

| 측정값 | MMC872 최종 링크 | 888 | 889 정적 ROM |
|---|---:|---:|---:|
| 밀집 60간격 합 | 141 / 141 | 139 / 138 | **138 / 138** |
| 밀집 마지막 ACK, 마스터클록 | 65,017,306 / 65,380,210 | 64,303,004 / 64,302,572 | **63,945,204 / 64,306,418** |
| 오프닝 간격 합 | 125 / 124 | 121 / 122 | **121 / 121** |
| 오프닝 703 공개, VBlank·선 | 59·231 / 59·231 | 59·231 / 59·249 | **59·231 / 59·231** |
| 오프닝 759 공개, VBlank·선 | 176·230 / 176·234 | 173·230 / 174·230 | **173·229 / 173·230** |
| 전환 간격 합 | 119 / 119 | 119 / 119 | **119 / 119** |

959의 한 패킷만 교체하고 후속 SPI를 자유롭게 실행한 위상 1에서는 두 번째 E0가 새 credit을 읽었다. 다음 OBJ와 SEAL이 각각 5,439클록 빨라졌고, 대기 진입이 226→222선으로 이동했다. 정적 ROM에서는 같은 두 발행이 각각 3,124·3,125클록 빨라졌다. 223선에 대기에 들어가 959가 VBlank 163→162에 공개됐다. 위상 2에서는 959의 대기 진입이 222선으로 유지됐다. 947과 오프닝 918은 각각 목표 캡처선보다 166,245·1,009클록 앞서 D2를 반환했다.

두 위상 모두 950은 직전 표시부터 3 VBlank, 952는 2 VBlank였다. 950의 선행 map 1,472B와 tile 64B는 기존 883 대조의 WRAM 원본·VRAM 목적지·PPU 포트·값·순서와 일치했다. 959에서도 888과 같은 map 768B가 선행 전송됐다.

**위상 2 마지막 화면에는 336B가 남았다.** 888에서 966은 map 512B와 tile 16B를 미리 전송했다. 889는 직전 965를 VBlank 178→177에 공개했지만, 966의 선행 DMA는 map 192B였다. 남은 map 320B와 tile 16B가 최종 DMA에 들어가 966의 공개가 같은 VBlank 180의 242→245선으로 늦어졌다. 888 대비 최종 ACK는 위상 1에서 16.659ms 빨랐고 위상 2에서 0.179ms 늦었다. 실기 기준 MMC872와 비교하면 각각 49.918·49.997ms 빨랐다. 이 값은 같은 장면을 재생한 결과이며 실기 FPS는 다음 무입력 시험에서 측정한다.

**용량과 검증 범위.** ARM Flash는 212,992B 중 212,956B를 쓴다. 부팅용 5,120B ROM의 여유는 22→12B다. 정상·손상 ROM 부팅, ARM 메뉴 복귀, 활성 RGB와 map, 최종 ACK→EA→다음 COMMIT 순서를 확인했다. cold·부분 수신·STOP·재시작 12건과 타일 헤더·descriptor 손상 12건을 통과했다. 타일 손상 12건은 모두 오류 코드 0xE0를 반환했고, 타일 데이터 소비 0B와 직전 화면 보존을 확인했다. 첫 시험의 관측 코드는 타일의 오류 응답까지 정상 ACK로 검사해 중단됐다. 오류 주입 패킷에만 오류 코드와 소비 0B를 요구하도록 고치고 동일 ROM과 입력으로 다시 실행했다.

**다음 작업.** 889를 최종 링크·보드 검증 후보로 둔다. 새 판명으로 링크한 ARM과 889 ROM을 넣은 Quartus Lite 전체 FIT·STA를 확인하고, 동일 두 위상에서 이번 표시·ACK 결과를 다시 대조한다. 위상 2의 추가 개선은 966에서 map 320B와 tile 16B가 큐에 수락되는 시각을 앞선 VBlank와 대조하는 데 집중한다.

## 재현

1. 888에서 만든 ARM·65816 기준 산출물에 `nes_bulk889.py`를 적용한다. 원본 본문의 SHA-256을 확인한 뒤 실제 ROM을 다시 패킹한다.
2. 각 위상에서 `trace_nes_bulk889.py TEMP PHASE`를 원본과 `--local`로 실행한다. `replay_nes_bulk889.py TEMP PHASE dense --local`은 같은 패킷 한 개만 바꾸되 이후 SPI·IRQ·credit 반응을 허용한다. `--local`은 측정용으로만 쓴다.
3. 정적 ROM은 `replay_nes_bulk889.py TEMP PHASE SCENE`으로 부팅부터 실행한다. SCENE에 `dense`, `opening`, `transition`을 각각 넣는다. 각 위상에서 `test_nes_mapwait880.py TEMP PHASE --generation 959 --audit 889-reader`로 실제 VRAM 포트 쓰기를 기록한다.
4. `guard_nes_bulk889.py TEMP`로 부분 수신·cold·STOP·손상 descriptor를 시험한다. 압축 ROM 부팅·손상 거부 및 ARM 메뉴 복귀 시험 결과와 함께 `check_nes_bulk889.py TEMP analysis/bulk889-results.json`으로 대조한다. [측정 결과](../analysis/bulk889-results.json)
