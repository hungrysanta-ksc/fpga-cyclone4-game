# NES 1054 커비 실기 비교

FF3의 성능 기준은 비공정 실기에서 확인한 1053이다. 커비는 MMC1035의 CHR-ROM 보드와 계측 형식을 기준으로 삼는다. 두 게임의 표시 FPS는 각각 같은 게임끼리 비교한다.

## SD 설치와 실행

전원이 꺼진 상태에서 원하는 ZIP 하나를 SD 루트에 풀고 일곱 파일을 함께 교체한다. 두 ZIP의 펌웨어와 NES 보드는 한 세트다. 기존 게임과 세이브는 그대로 사용한다. SD 파일 메뉴에서 일본판 `Hoshi no Kirby - Yume no Izumi no Monogatari (J).nes`를 직접 선택한다. 전체 파일 CRC32는 `248c7140`이다.

- **디버그판**은 적재 전 검사, PSRAM 읽기 대조, 진행 로그를 사용한다. 커비가 시작된 뒤 60초 동안 입력하지 않는다. 메뉴로 돌아오면 `sd2snes/nes-progress-debug1054.txt`, `nes-game-last-debug1054.txt`, `nes-frame-debug1054.bin` 세 파일을 PC의 회차별 폴더에 복사하고 두 번째 실행을 시작한다.
- **배포판**은 SNES 로딩 화면에 `Loading NES`와 0–100%를 5% 간격으로 표시한다. SD 파일 본문을 한 번 읽어 PSRAM에 복사하고 NES 보드로 전환한다. 헤더와 지원 크기, SD 읽기·닫기 결과, 시작·종료 상태를 확인한다. 같은 읽기에서 계산한 CRC32는 기존 FF3 세이브 식별자에 쓴다. 별도 ROM 검사 순회·PSRAM 대조·진단 로그 기록은 생략한다. 기존 세이브 쓰기는 지원한다.
- **이번 커비 빌드는 양쪽 모두 60초 후 자동 복귀한다.** 배포판에서는 ROM 선택부터 첫 게임 화면까지 걸린 시간, 진행률이 보였는지, 메뉴로 복귀했는지만 기록하면 된다. 디버그판으로 같은 시간을 재면 로딩 단축량을 비교할 수 있다. FF3는 기존 장시간 플레이·퀵 메뉴·네 개 상태 슬롯을 사용한다.

## 비교 방법

`nes-game-last-debug1054.txt`에서 `w1 / 29`가 [1, 30)초, `w2 / 30`이 [30, 60)초의 표시 FPS다. 기준은 ROM 선택이나 로딩 시작이 아니라 게임 실행의 계측 타이머다. 과거 MMC1035 두 실행은 각각 25.07 / 25.90 FPS, 26.93 / 28.73 FPS였다. 한 회차의 최댓값만으로 개선을 판정하지 않는다.

`python tools/read_nes_kirby1034.py <bin> --edition 1054`로 상세 기록을 읽는다. 뱅크별 타일 반환, SEAL 수락, 화면 공개, 최종 ACK는 직전 공개에 상대적인 FPGA tick이다. 앞부분은 15초 구간마다 대표 표본 하나를 남기고 55–60초는 기존 1035와 같은 주기로 촘촘하게 기록한다. 전체 표시 횟수는 이 표본 제한을 받지 않는다. 타일 수·BG·OBJ·map 작업량과 뱅크 토큰이 맞는 표본끼리 비교한다. 세대·토큰·시각이 불완전한 표본은 디코더가 표시한다. 이전 실기의 상세 비교 범위는 55–60초다.

커비 결과를 확인한 다음 모험도 4의 256 KiB PRG + 128 KiB CHR와 미러링에 맞는 보드로 같은 디버그판·배포판을 준비한다. 1054 선택기는 커비 512+256 KiB와 FF3 512 KiB + CHR RAM 배치만 지원한다. ZIP에는 게임, 세이브, RESTORE가 없다.
