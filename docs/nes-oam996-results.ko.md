# 996 · 909 최종 ACK 이력으로 911 OAM 반환 합치기

## 목표

978에서 909가 최종 ACK한 OAM이 같은 뱅크를 사용하는 911까지 보존되는지 측정한다. 재사용 명령을 적용해 908 공개, 909의 624B 선행 DMA, 910 캡처를 유지하면서 두 시작 위상 모두 911을 직전 VBlank 44의 246선 안에 공개하고 912 ACK를 앞당기는 것이 선택 조건이다.

## 작업내용

- 909 최종 ACK에서 대상 뱅크의 OAM 176–543을 저장하고 911 BEGIN과 각 OAM 수락 시점에 비교했다. 두 위상 모두 911 반복 패킷 전까지 이 범위에 쓰기가 없었다. 직접 WRAM 쓰기와 WRAM 포트 주소·데이터 접근을 함께 추적했다. 978의 실제 후속 쓰기가 368개 주소를 모두 지나가는 것도 확인했다. 포트와 backing WRAM 양쪽에 관측된 쓰기는 주소를 기준으로 한 번만 셌다.
- ARM은 고정 숨김 패턴과 32B 상위 속성 전체가 0인 경우만 선택한다. 두 뱅크에 각각 1B로 꼬리 시작을 기록한다. 활성 후보 기록은 최종 표시 ACK와 resident commit 뒤에만 갱신한다. 실패는 해당 실행의 FAULT 상태로 이어지고 reset·새 epoch에서 이력을 비운다. cold 첫 두 세대는 기존 전체 OAM 경로를 사용한다.
- 911에서 기존 op8(4B 패턴)과 op4(2B 단어)를 op8 한 건(6B 본문)으로 합쳤다. E1 헤더·CRC 포함 전송이 44→25B이고 큐 반환은 2→1회다. 65816은 identity·section·범위·누적 coverage를 확인한 뒤 300B 숨김 스프라이트 패턴과 32B 상위 속성을 WRAM에서 직접 대조한다. 한 바이트라도 다르면 오류를 반환한다. 332B가 일치할 때만 176–211의 36B를 쓰고 반환한다. 전송이 중단되면 그 세대의 SEAL과 표시를 허용하지 않는다.
- 검사 순회는 스프라이트 1개(4B)씩 비교하는 코드와 8개(32B)씩 비교하는 코드를 각각 실행했다. 32B 방식도 각 16비트 단어를 대조하고 묶음 사이에 STOP을 확인한다. 매 세대에 적용한 전체 링크와, 978 부팅·앞선 큐 도착을 고정하고 911의 마지막 두 OAM만 합친 대조를 구분했다.

## 성과

아래 값은 위상 1 / 2 순서다. OAM 시간은 911의 첫 반복 패킷 수락부터 마지막 상위 속성까지 큐 반환을 완료한 시간이다. ACK 차이의 양수는 978보다 늦음을 뜻한다.

| 전체 ARM·65816 실행 | OAM 시간(ms) | 909 선행 DMA(B) | 910 캡처 여유(ms) | 911 공개(VBlank·선) | 912 최종 ACK 차이(µs) |
|---|---:|---:|---:|---|---:|
| 978 | 1.732 / 1.728 | 624 / 624 | 0.216 / 0.196 | 45·244 / 45·244 | 기준 |
| 4B 검사 | 1.963 / 1.962 | 560 / 624 | 0.091 / 0.200 | 45·244 / 45·244 | +14.7 / +23.1 |
| 32B 검사 | 1.300 / 1.301 | 464 / 624 | 0.093 / 0.197 | 45·244 / 45·243 | +14.7 / +12.7 |

두 위상 모두 908은 38회 245선, 911 표시 간격은 2 VBlank, 밀집 여섯 간격은 13 VBlank였다. 32B 검사는 OAM을 0.432 / 0.427ms 줄였지만 SEAL 진입은 0.133 / 0.096ms 앞당겼다. 모든 전체 실행에서 905–912의 여덟 화면 RGB를 978과 대조했다.

995와의 결합 가능성도 대조했다. 32B 독립 검사를 실행하고 911의 201B·240B·SEAL wire 시간을 371B만큼 줄이며 압축기·복원기 비용을 0으로 둬도 911은 두 위상 모두 45회 244선에 공개됐다. 912 ACK 차이는 −8.4 / +8.4µs였다. 여기에 911의 OAM 독립 대조·36B 쓰기까지 즉시 완료하는 낙관적 재생에서는 두 위상 모두 44회에 타일 432B를 보냈다. raw 192B·팔레트 512B·OAM 544B는 다음 VBlank에서 전송했다. 911 공개는 두 위상 모두 45회 240선이었다. 이 대조의 SEAL 진입도 잔여 검증과 팔레트·OAM만 고려한 993의 낙관적 마감보다 0.137 / 0.203ms 늦었다.

오류 주입에서 보존 대상 212번 또는 543번 바이트 변조, 잘못된 경계 정렬, 이전 값과 맞지 않는 경계를 각각 검출했다. 위상별 부분 STOP은 바뀐 구간을 뒤에서부터 20B 쓴 시점에 0xE4로 종료했다. 모두 911 최종 ACK를 차단하고 910 RGB를 유지했다. 그때 남은 OAM으로 새 부팅을 재생해 첫 두 세대의 전체 복원과 화면도 확인했다. 실기 STOP·메뉴 복귀와 이번 수신 ROM을 넣은 보드 FIT는 측정하지 않았다.

ARM 전체 링크는 213,240B로 한도보다 248B 크다. 65816 저장 이미지는 978의 5,096B에서 각각 5,317B와 5,397B로 늘었다. 32B 검사판은 5,120B 한도를 277B 초과한다. 측정은 실제 명령을 실행한 ARM·Mesen 공동 시뮬레이션과 기존 공유 SPI·ROM 모델을 사용했다. [패킷별 클록·DMA·오류 주입 원자료](../analysis/oam996-results.json)

## 후속작업

978을 유지하고 911 OAM 검사 루프의 추가 미세 조정을 종료한다. 다음에는 978의 907에서 VBlank 35의 768B DMA와 다음 VBlank로 넘어간 704B·448B DMA를 대조한다. 각 범위의 수락·첫 안전 DMA 가능 시각·마지막 SEAL 의존성을 절대 클록으로 비교해, 해당 구간이 실제로 VBlank 하나를 절약할 수 있는지 먼저 판정한다. 로컬 복사 시간과 함께 두 위상의 연속 표시 간격, 912 최종 ACK, 909의 624B 보호를 선택 조건으로 삼는다.
