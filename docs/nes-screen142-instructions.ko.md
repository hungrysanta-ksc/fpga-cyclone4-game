# NES142 — 화면 프로그램의 실제 진행 위치 확인

141에서는 ROM 읽기·RUN/STOP·첫 시험의 메뉴 복귀가 통과했지만 화면은 깨졌습니다.142는 SNES 화면 프로그램의 부팅→WRAM 진입→패킷 수신→VRAM 전송 단계를 TXT에 남깁니다. 기다리는 동안 파란 배경, 검출한 패킷 오류에는 빨간 배경을 표시하도록 변경했습니다. 글리치의 원인이 해결됐다고 확정한 버전은 아닙니다.

## 실행

1. 전원을 끄고 현재 SD의 펌웨어 등 기존 파일을 보관합니다.
2. ZIP의 **01-SCREEN142-SD-ROOT 안의 내용**을 SD 최상위에 복사합니다. `sd2snes/firmware.stm`, `fpga_n142.bi3`, `nes/screen142.nes`를 함께 적용합니다.
3. 메뉴에서 **NES SCREEN 142.nh1**을 한 번 실행합니다. 선택 파일은 **0바이트가 정상**입니다. 확장자를 바꾸지 않습니다.
4. 적재·대조는 기존 실기 기준 약9분, 이후 표시 구간은 약10초입니다. **전체10분** 안에 자동 메뉴 복귀하는지 관찰합니다. 복귀하지 않으면 전원을 끄고 남은 로그를 회수합니다.

같은044 복원·GBC 회귀 시험은 반복하지 않습니다. ZIP의02-RESTORE044-SD-ROOT는 필요할 때 사용하는 기존 복원본입니다. 분해·LED 확인·PC 직접 연결은 필요 없습니다.

## 전달할 결과

- `sd2snes/nes-progress-142.txt`
- `sd2snes/nes-screen-last-142.txt`
- 화면이 파란색/빨간색/정상 패턴/글리치 중 무엇이었는지와 자동 메뉴 복귀 여부

영상은 선택이며 전체 대기 시간을 촬영할 필요는 없습니다. 무음은 현재 오디오 출력 미구현 상태에서 예상됩니다. 사진의 대각선 띠는 사용자가 확인한 카메라·CRT 주사 차이이므로 FPGA 오류 판정에서 제외합니다.

## 로그 해석

`screen_status_valid=1`은 상태 응답의 식별·형식 확인이지 정상 영상 판정이 아닙니다. `screen_error`는 최초 오류를 보존하고, `screen_flags`의 하위3비트는 리셋 벡터 하위/상위 및 프로그램 ROM 읽기 관측입니다. 비트가0이어도 짧은 외부 신호의 관측 누락 가능성은 있습니다.

|screen_stage|기록된 프로그램 진행|
|---|---|
|0|단계 쓰기 미관측: 부팅/ROM/관측 배선부터 확인|
|1|ROM 부트 코드 도달, WRAM 복사 전|
|2|WRAM 코드 진입|
|3|PPU 초기화 후 패킷 대기; 파란 배경 의도|
|4|패킷의 WRAM DMA 종료|
|5|패킷 검사·소비 완료, 화면 전송 전|
|6|VRAM·팔레트 전송 및 표시 설정 완료|
|255|소프트웨어 오류 경로; 빨간 배경 의도|

`screen_frames`는6번 단계 쓰기의 누적 횟수(최대65535)입니다. 실제TV 프레임률이나 정상 픽셀의 증거는 아닙니다. 마지막stage가3~5라도 이전 전송이 있었다면 frames가 양수일 수 있습니다.0~6/255 이외 값도 지우지 않고 남겨 잘못된 코드 실행이나 전송을 구분합니다.

`run_passed=1`과 기존 ROM 오류0도 화면 성공을 의미하지 않습니다. 상태 회수는STOP 뒤, TXT는base 복구 뒤에 기록하며 RUN 중 SD 쓰기를 추가하지 않았습니다. `MENU_PREPARED`와 실제 메뉴 복귀는 별도로 판정합니다.

이번 시험은 정상 영상의 첫 실패 구간을 찾기 위한 제한된 실기 후보입니다. SMB3(J),mapper4/384KiB·패드·오디오 구현과 전체 전기 타이밍 승인은 아직 남아 있습니다.
