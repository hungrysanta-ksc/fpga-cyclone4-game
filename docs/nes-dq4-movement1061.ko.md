# 1061 드래곤 퀘스트 IV 이무르 이동 측정

## 목표

슬롯 1 복원 후 **첫 방향키 입력부터 5.5초** 동안 실제로 공개된 화면을 센다. 이무르에서 같은 동선을 반복해 드래곤 퀘스트 IV의 끊김을 비교하고 배틀토드의 타일 공급 개선과 우선순위를 판단한다.

## 작업내용

DEBUG ZIP의 sd2snes 폴더를 SD에 덮어쓰고 기존 드퀘4 한글판을 선택한다. 퀵메뉴에서 LOAD STATE 슬롯 1을 선택하고, 복귀 후 방향키를 떼고 잠깐 기다린다. 이무르에서 평소처럼 6초 이상 이동한 뒤 EXIT TO MENU로 종료한다. 같은 슬롯을 다시 불러 같은 길을 한 번 더 걷고 네 로그(progress·game-last·frame·stop)의 파일명에 회차를 붙여 보관한다. 중간에 새 상태를 저장하면 슬롯 내용이 바뀐다.

DEBUG의 상세 프레임 파일은 해당 ROM·슬롯에서만 기록한다. 방향 입력 직전까지의 대기는 집계에서 제외한다. FPGA가 마지막 타일 반환·SEAL·화면 공개·최종 ACK를 찍고 ARM이 같은 세대의 첫 유효 ACK, 스크롤, map 변경 행 수와 계획된 타일 바이트를 함께 기록한다. 타임스탬프 한 눈금은 약 0.780ms다. 검사가 끝난 후 메뉴에서 SD에 기록한다. RELEASE는 1060과 같은 실행 파일들이며 무제한 플레이용이다.

## 성과

1060 실기에서 게임 실행·저장·복원·메뉴 복귀가 확인됐다. 1–30초에 398장(13.72 FPS), 30–60초에 511장(17.03 FPS), 55–60초에 99장(19.80 FPS)이 표시됐다. 마지막 5초 유효 표본 74개에서 입력 수신 중앙값은 7.26ms, 입력 완료부터 ARM 유효 ACK까지는 15.59ms였다. 이무르 첫 이동과 동기화한 기록은 1061부터 얻는다.

배틀토드 1059의 마지막 5초는 39장(7.80 FPS), 입력 완료부터 ACK까지 중앙값은 96.33ms였다. 원본 첫 스테이지 프레임 2100에서 바뀐 CHR 그룹은 0·1·2·47·48이었다. 512B 복사 단위를 128B로 줄이는 RTL 시험에서 전송은 1,536→640B다. 8 KiB 미러 전체와 수신 확인·STOP을 대조한다. ARM 캐시에서 1 KiB 페이지 안의 요청 타일 68개 중 실제 쓰기 그룹에 속한 것은 25개다. 차이 43개는 더 세밀하게 무효화할 후보이며 실제 캐시 적중 수와 FPS 이득은 별도 측정 대상이다. 1061 실기판은 드퀘4 계측용으로 배틀토드 실행 경로는 1060과 같다.

## 후속작업

두 이무르 기록을 `python tools/analyze_dq4_movement1061.py 1차.bin 2차.bin`으로 비교한다. 같은 저널인지 확인하고, 5.5초 표시 FPS·공개 간격 95백분위·타일 반환→SEAL·SEAL→공개·공개→ACK를 본다. 동선 차이는 같은 방향·스크롤 좌표·타일 작업량의 표본으로 확인한다.

속도 변경은 배틀토드부터 진행한다. 128B CHR 미러와 복수 변경 그룹의 정확한 캐시 무효화를 각각 적용해 같은 세대에서 마지막 타일 반환·공개·최종 ACK가 함께 앞당겨지는지 검증한 뒤 실기에 반영한다.
