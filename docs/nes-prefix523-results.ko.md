# 523. 닫힌 VRAM 명령의 선행 실행

## 비교 조건

MMC520의 ARM과 입력을 고정하고 65816의 VRAM 전송 시점만 바꿨다. 두 시작 시각 각각에서 905–957을 끊지 않고 실행했다. 첫 두 화면을 제외한 51개 표시 간격과 OBJ 변화가 많은 951–955의 다섯 표시 간격을 따로 계산했다. 같은 시작 시각끼리 최종 표시 ACK를 비교하므로 선행 DMA가 패킷·receipt·credit을 늦춘 비용과 이후 달라진 VBlank·ROM 위상이 모두 들어간다.

실행한 것은 링크된 Cortex-M4 코드와 SysTick, Mesen의 65816 명령 및 PPU DMA다. ARM 명령당 2사이클을 적용했고 SPI 호출 비용은 실기 계측값을 사용했다. ROM 공급은 부팅 중 기록한 허용 구간을 재생했다. SMB3 후반부의 실기 ROM 중재와 메뉴 복귀를 이 두 실행에서 측정할 수는 없다. 실기 기준은 MMC520이며 1–40초와 40–60초의 비교는 다음 보드 로그에서 이어간다.

## 전송과 취소

일반 패킷 처리를 마친 뒤 ACK를 쓰기 전에 기존 명령 목록을 검사한다. 마지막 항목은 연장될 수 있어 보류한다. 앞의 닫힌 항목 중 대상 뱅크가 비활성이고 길이가 2,048B 이하이면 한 건만 허용한다. op7에서도 토큰 receipt를 쓰기 전에 이 검사가 들어간다. 새로운 빔 래치, 9비트 주사선 225–232, VBlank 상태를 확인한다. DMA 전후에 STOP을 서비스하고 동기 DMA 종료 뒤에만 기존 커서를 진전시킨다. BEGIN에서 목록과 커서를 함께 초기화한다. SEAL의 업로드 예산은 새로 계산하고 기존 manifest·독립 검사와 최종 표시 ACK를 그대로 실행한다.

양 뱅크에서 선행 DMA 직전·직후 STOP, 선행 DMA 뒤 잘못된 SEAL을 넣었다. 이전 화면의 VRAM·RGB·표시 일련번호가 보존됐다. 취소로 남은 메모리로 부팅해 cold 전체 행, tile BG·OBJ VRAM, map·HDMA, 최종 ACK를 확인했다. 별도 경계 시험은 두 개의 합법적인 BG 범위로 2,048B 명령을 닫고 빔 검사 진입을 지정된 시각까지 늦췄다. 225/232번 주사선 후반에 허용했을 때 각각 239/246번에서 실제 마지막 PPU 쓰기가 끝났다. 224/233/256번과 stale latch에서 커서는 그대로였다.

## 연속 일정

| 시작 클록 | 첫 두 화면 뒤 평균 (MMC520 → 523) | 밀집 5화면 평균 | 957 최종 ACK |
|---:|---:|---:|---:|
| 3,000,000 | 92.644 → 91.679ms | 126.578 → 126.460ms | 49.928ms 앞당김 |
| 3,178,684 | 92.970 → 91.353ms | 126.572 → 126.458ms | 83.190ms 앞당김 |

두 비교 각각 53개 RGB, 444개 타일 payload, 1,689개 패킷의 내용, 125,488B의 VRAM DMA가 일치했다. 비활성 명령은 42건/4,416B와 44건/4,048B를 앞당겼다. 이 명령들을 발행한 패킷의 load→ACK 시간은 같은 내용의 기준 패킷보다 합계 6.794/6.898ms 길었다. 명령 발행부터 마지막 PPU 쓰기까지 다음 패킷이 이미 도착해 있던 시간은 1.558/1.448ms였다. 이 시간은 패킷 서비스와 겹친다.

| 전체 53화면 | 첫 위상 (MMC520 → 523) | 둘째 위상 (MMC520 → 523) |
|---|---:|---:|
| ARM 명령 | 119,909,246 → 118,598,557 | 120,538,172 → 118,368,893 |
| SysTick 호출 | 519 → 514 | 521 → 513 |
| 총 SPI 바이트 | 543,778 → 540,382 | 545,594 → 539,842 |
| ROM read 배정 / bulk 최대 점유 | 5,616 / 2슬롯으로 동일 | 5,616 / 2슬롯으로 동일 |

SPI 감소의 대부분은 E0 조회 3,200/5,500B 감소다. 출력 E1 전송량은 같다. 65816 관측 스택도 양쪽 11B로 같다. 두 위상에서 첫 화면 이후 모든 PPU DMA의 시작과 마지막 쓰기를 같은 프레임의 VBlank 안에서 확인했다.

**밀집 구간의 제한은 패킷 수락 시점에만 선행 DMA를 시도한 데서 드러났다.** 두 위상 모두 951/953/955에서 각각 256/16/16B, 952/954에서 0B를 앞당겼다. 952에서는 SEAL 이외 패킷 37개, 954에서는 34개를 처리했지만 허용 주사선 225–232에 기록된 해당 패킷 ACK가 두 화면 모두 0개였다. ACK는 빔을 읽은 직후와 정확히 같은 시각은 아니다. 발행이 없었다는 것은 실제 DMA 추적으로 별도 확인했다. 특히 952의 표시 간격은 첫 위상 150.356→150.340ms, 둘째 150.346→150.358ms였다. 밀집 5화면 전체에서 절약한 시간은 각각 0.587/0.571ms여서 VBlank 한 번을 건너뛰는 효과에 미치지 못했다.

**다음 구현**은 닫힌 명령 커서를 유지하면서 큐가 비어 있는 대기 루프에서도 STOP·새 head를 우선 확인한 뒤 선행 전송을 시도한다. 952/954에서 비활성 명령을 실제 발행했는지 먼저 확인한다. 이미 닫힌 범위로도 표시가 다음 VBlank로 넘어갈 때만 수락된 map을 64B 단위로 나누고 나머지 주소와 설정 비용을 센다. 두 위상의 밀집 표시 간격과 최종 ACK가 함께 개선된 뒤 실기 전달을 재개한다.

## Quartus Lite와 메모리

73개 보드 입력을 대조했다. 달라진 파일은 5,120B ROM의 초기값인 `sink-program.hex` 하나다. Cyclone IV EP4CE15F17C8 전체 FIT와 구현·명목 STA를 다시 실행했다.

| 항목 | MMC520 | 523 |
|---|---:|---:|
| LE / 조합 함수 / FF | 15,164 / 14,172 / 8,394 | 동일 |
| RAM / M9K | 264,816비트 / 51 | 동일 |
| 관련 경로 setup / hold | +0.078 / +0.139ns | 동일 |
| 65816 본체 / 본체 여유 | 4,490 / 470B | 4,685 / 275B |
| MCU Flash 점유 / 여유 | 212,992 / 0B | 동일 |

새 WRAM 할당은 없다. 기존 516 생성기의 기본 모드로 이전 본체·ROM·초기값을 바이트 단위로 재생성했다. MCU의 실기 식별자만 바꾼 별도 빌드에서도 785개 함수의 주소·크기·기계어가 일치했다.

## 재현

1. [MMC520 재현 절차](nes-order520-results.ko.md)에서 같은 두 시작 시각의 ARM·oracle·fixture·ROM calendar를 준비한다. [523 생성기](../tools/nes_prefix523.py)로 소비 프로그램을 생성한다.
2. [공동 실행](../tools/test_nes_prefix523_schedule.py)에 같은 ARM, plan, fixture, ROM calendar와 새 client를 전달한다. 시작 클록은 3,000,000과 3,178,684다. [STOP·cold 검사](../tools/check_nes_prefix523.py)와 [빔 경계 시험](../tools/test_nes_prefix523_edges.py)은 MMC520 첫 일정의 실제 패킷을 사용한다.
3. 516 **both** 보드 입력과 동일한 QSF·SDC·소스·ROM 크기에서 새 client의 `sink-program.hex`만 교체한다. Quartus Lite에서 `quartus_sh --flow compile board` 다음 `quartus_sta -t timing506.tcl`을 실행한다.
4. [분석기](../tools/analyze_nes_prefix523.py)에 두 쌍의 일정과 원래·후보 보드, 507 입력 목록 및 guard/edge 결과를 전달한다. 공개 [검증 기록](../analysis/prefix523-verification.json)에 화면별 ACK, 선행 명령별 전송·패킷 대기, 비용과 원자료 해시가 있다.
