# NES166 — 영상 미출력 원인 구분

165에서 소리·메뉴 복귀는 성공했지만 첫 영상이 완성되지 않았다. 이번166은 **동일 FPGA에 수신 단계·취소 이유 기록을 추가한 펌웨어**다. 화면 문제가 해결됐다고 주장하는 시험판은 아니다. 화면이 계속 검정이어도 이번 시험의 목적에 맞는 로그를 얻을 수 있다.

1. ZIP의 `01-GAME166-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. 펌웨어와 `fpga_n166.bi3`, 실행 표식, 게임 경로를 함께 적용한다. FPGA 내용은165와 동일하지만 파일명이 다르다.
2. `NES GAME 166.nh1`를 실행한다. 0바이트 표식이 정상이며 확장자를 바꾸지 않는다. ROM 적재·검증은 기존과 같아 약4분 정도 걸릴 수 있다.
3. 소리가 시작되면 약60초 뒤 메뉴 복귀를 기다린다. 화면이 없으면 버튼 입력이나 영상 촬영은 필요 없다. 전체7분 이상 무반응이면 대기를 끝내고 남은 로그와 상태를 전달한다.
4. `sd2snes/nes-progress-166.txt`와 `sd2snes/nes-game-last-166.txt`, 메뉴 복귀 여부를 전달한다. 마지막 TXT가 없으면 진행 TXT만 전달한다.

RUN 중 SD 쓰기는 추가하지 않았다. 기존처럼 안전하게 멈춘 뒤 최종 로그를 저장한다. 리셋을 눌러 로그를 만들 필요는 없다. 정상 사용 복원용 `02-RESTORE164-SD-ROOT`는 기존164 원본이다. 044/GBC 복원 시험을 반복할 필요는 없다. 세이브 파일·카트리지 별도 SRAM은 건드리지 않는다.

새 로그의 `trace_begins/ends/aborts/commits`는 영상 수신의 시작·완성·취소·승인 횟수다. `trace_first_abort_reason`은 첫 취소 이유, `trace_first_abort_records/bytes`는 취소 당시 받은 정보량이다. 수신 COMMIT은 SNES 표시 완료와 다르므로 실제 표시 성공은 기존 `native_frames`와 함께 판정한다. 분석은 개발 측에서 하므로 사용자가 숫자를 해석할 필요는 없다.
