# 573 · STOP 뒤 첫 generation과 32비트 epoch 배치

**572 START 단독 보드를 개발 기준으로 유지한다.** 연속 샘플링으로 0°C epoch 회귀를 해소했지만 PSRAM 메모리 클록 setup과 ROM_OE에서 회귀했다. 같은 RTL에서 임계 비트의 두 수신 FF만 인접 배치한 경우에도 전체 STA는 악화됐다. 실기 기준은 MMC558이다.

## 언제 epoch를 쓰는가

보드의 STOP·RUN 배선에 맞춰 로컬 RAM, reset 해제, epoch 생산기, 실제 수집기와 표시 lease를 연결했다. RUN 재개 직전부터 NES 상승 에지를 셌다. 처음 가능한 캡처를 유도하기 위해 수집기의 초기화 완료 직후 스캔라인 7·dot 257의 PPU 이벤트를 공급했다.

| RUN 재개 뒤 사건 | NES 에지 |
|---|---:|
| 8,192주소 RAM 초기화와 core reset 해제 완료 | 8,196 |
| 32비트 epoch가 source_ready와 함께 유효 | 8,200 |
| 수집기 초기화 완료 | 16,388 |
| 첫 generation 1과 해당 epoch를 capture lease가 수락 | 16,389 |

두 시작 위상에서 cold, STOP 뒤 동일 ROM 재개, NES 클록이 멈춘 동안 두 번 BEGIN 후 재개를 시험했다. 수락한 epoch는 순서대로 `00c00000`, `00c00000`, `00c00003`였다. 32비트 포화 뒤 BEGIN은 거부됐다. 32개 Gray 비트의 carry는 동작·정지 클록을 나눠 64건 검사했다. 첫 수락까지의 **8,189에지**는 초기화 때의 여유다. 실제 게임에서 매 화면마다 이 시간을 절약할 수 있다는 뜻은 아니다.

## 무엇을 바꿨는가

- **합성 속성만 변경**한 대조군은 첫 단·둘째 단의 동기 제어 입력 사용을 제한하도록 지정했다. 32비트의 실제 FF 위치, slow 0°C 데이터 입력 핀, 원래 제약의 전체 STA 행이 572와 같았다.
- **연속 샘플링**에서는 두 데이터 FF가 STOP 중에도 샘플링할 수 있다. STOP은 2비트 유효 상태를 즉시 지우고 새 NES 에지 두 번을 거쳐야 동기화한 값을 공개한다. 두 번째 에지를 생략한 변이는 reset이 풀리고 ready가 아직 0일 때 이전 값이 보이는 실패를 검출했다. 정상 회로와 572의 네 출력은 두 위상에서 각각 563,030 / 563,626회 대조했다.
- **비트 23 인접 배치**에서는 572 RTL 그대로 MMC558에서 실제 사용한 `FF_X26_Y22_N9`과 `FF_X26_Y22_N7`에 두 수신 FF를 지정했다. SDC·seed는 같고 QSF의 위치 지정 두 개만 달라졌다. 첫 시도는 Quartus가 중괄호를 노드명의 일부로 읽어 위치를 무시했다. 아래 표는 노드명을 고치고 두 FF의 실제 위치를 TimeQuest에서 확인한 재실행 결과다.

572의 송신 FF와 첫 수신 FF는 이미 같은 LAB에 있다(`X20_Y20_N11 → X20_Y20_N17`). 비트 23의 slow 0°C 경로는 첫 FF의 `asdata` 핀을 사용했고, 연속 샘플링에서는 `d` 핀을 사용했다. 32비트 모두 송신 → 첫 단 → 둘째 단을 추적했으며 setup과 hold를 세 코너에서 각각 대조했다.

## 표시 일정과 다음 작업

고장 뒤 E9 수락 0회, STOP을 걸친 부분 ACK 소비 0회, 올바른 ACK 소비 1회를 확인했다. 같은 ARM·SPI·IRQ·ROM 도착 기록으로 65816을 다시 실행했다. 두 위상의 53개 RGB 화면·표시 시각·뱅크 소비 기록이 모두 일치했다. 952·957은 각각 **5 VBlank, 최종 대기 0회**였고, 밀집 평균 간격은 **83.157 / 83.121ms**, 마지막 ACK는 **87,545,284 / 88,254,606 master clocks**였다. 새 실기 FPS는 측정하지 않았다.

다음에는 572에서 개별 비트 위치 탐색을 종료하고, ROM 적재 때 확정된 32비트 identity를 초기화 동안 한 번 전송하는 방식의 비용을 먼저 비교한다. 기존 8,200번째 에지 공개를 유지하려면 core reset 전에도 진행할 전송 소유자와 취소·재시작 절차가 필요하다. 연속 BEGIN, 멈춘 NES 클록, 포화, STOP 뒤 첫 캡처 외에 tile cache와 plan의 첫 사용까지 확인한 뒤 전체 FIT 여부를 결정한다.
