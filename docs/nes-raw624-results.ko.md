# 624 · 922의 표시 마감과 923 첫 ROM 공급

## 921에서 922까지

같은 시작 클록의 622 A와 623 T를 짝지었다. 표의 양수는 T가 늦다는 뜻이다. 921과 922의 마지막 E1은 SEAL이다. 최종 표시 ACK, CRC와 identity를 확인한 ARM의 E0 응답, 출력 함수 반환, EA 완료는 별개 사건으로 기록했다.

| 사건 (T − A, ms) | 위상 1 | 위상 2 |
|---|---:|---:|
| 921 마지막 E1 발행 시작 | −0.085 | +0.893 |
| 921 65816 최종 ACK | −0.010 | +0.265 |
| 921 ARM 출력 함수 반환 | +0.192 | +0.337 |
| 922 SEAL 발행 시작 | +0.364 | +0.169 |
| 922 65816 SEAL 읽기 시작 | +0.344 | +0.127 |
| 922 독립 검사 후 업로드 진입 | +0.343 | +0.127 |
| 922 최종 표시 검사 진입 | +0.022 | +0.061 |
| 922 실제 표시 | +15.239 | +15.278 |

T에서 SEAL 뒤에 남은 VRAM DMA는 두 위상 모두 64+128+96+128+1,536B와 compact raw 64B 세 건이었다. A의 위상 2는 첫 64B가 이미 처리돼 7건, 나머지는 8건이었다. T의 최종 예산 잔량은 800B였지만 빔을 래치한 시점은 247번 선의 수평 클록 276 / 164였다. A는 246번 선의 1,178 / 216에서 래치해 같은 VBlank에 표시했다. 921의 함수 반환 지연 전부가 표시 마감까지 누적되지는 않았다. 922의 마지막 raw 세 건이 두 위상 모두에서 직접 줄일 수 있는 구간이었다.

921의 65816 ACK부터 ARM 함수 반환까지 A가 0.174 / 0.364ms, T가 0.376 / 0.436ms였다. 위상 1에서는 T가 SEAL을 먼저 발행하고 65816 ACK도 먼저 받았지만 ARM이 확인·반환한 시각은 A보다 늦었다. 따라서 ARM의 대기 시간과 실제 표시 시각을 따로 비교했다.

## 65816 변경과 같은 도착 시각 재생

624는 기존 SEAL 독립 검사와 뱅크별 수신 이력으로 만든 6비트 마스크가 정확히 `0x15`일 때 짝수 행 세 건을 건너뛴다. 기존에도 이 세 행에는 DMA를 하지 않았다. 변경점은 행 여섯 개를 순회하는 대신 홀수 행의 WRAM 원본과 VRAM 목적지를 직접 계산해 64B씩 세 번 실행하는 것이다. 각 DMA의 직전에 기존 service와 sticky STOP 검사를 거친다. cold·부분 이력·다른 마스크는 기존 복원기로 간다. 246번 검사선, 큐 및 새 head 우선 처리와 최종 ACK 순서는 공통이다. 6,144B 진단 ROM의 코드 본체가 5,157→5,323B로 늘어 661B가 남았다.

고정 도착 재생에서는 기존 619 소비기를 그대로 실행하다 922의 raw 진입에서만 624의 연결된 기계어를 적용했다. 905부터 진입까지 A는 3,565 / 3,568개, T는 3,568 / 3,566개 이벤트가 원래 기록과 같았다. 실제 DMA의 bank·source·destination·64B 길이와 최종 VRAM을 독립 대조했다. A는 두 위상 모두 92번째 VBlank를 유지하며 해당 ACK가 각각 0.168ms 빨라졌다. T는 두 위상 모두 93→92번째 VBlank로 복귀해 해당 ACK가 15.384 / 15.385ms 빨라졌다.

## 53화면 연속 일정

T ARM에 624를 연결하자 922의 raw 실행 구간이 8,390→4,808 master clocks로 줄었다. 최종 빔 래치는 244 / 243번 선이었고 246번 검사선을 지켰다. 두 위상 모두 923의 첫 BG ROM 응답은 클록 33,928,601→33,571,217로 16.640ms 빨라져 A와 같은 구간을 사용했다.

| 마지막 ACK 비교 (후보 − 대조군, ms) | 위상 1 | 위상 2 |
|---|---:|---:|
| 621 ARM + 624 vs 기존 621 | −49.919 | +16.643 |
| A + 624 vs 622 A | −0.006 | −16.647 |
| T + 624 vs 623 T | −16.634 | −49.932 |
| T + 624 vs 622 A | −0.082 | −16.744 |
| T + 624 vs 621 | −50.010 | −16.733 |

T + 624에서는 두 위상 모두 952·954 표시 간격 4 VBlank, 955의 첫 192B와 마지막 384B map 선행, 957의 tile 두 건과 map 1,152B 동일 VBlank 실행, 최종 추가 대기 0회를 유지했다. 밀집 5화면 합계는 T의 20 / 21→21 / 20 VBlank였다. 위상 1에서 954의 절대 표시가 두 VBlank 빨라진 반면 955는 하나만 빨라져 두 표시 사이가 4→5로 늘었다. 위상 2에서 955 간격은 5→4였다.

A/T 각각의 ARM은 이전 링크와 바이트가 같았다. 두 위상 모두 53장 RGB·map, 출력 작업과 총 VRAM DMA 114,352B가 원래 실행과 일치했다. STOP과 새 head를 각각 또는 동시에 제시했을 때 유휴 DMA 허가가 0이었다. 누락·중복 manifest는 양쪽 뱅크 모두 거부했다. 새 raw 경로의 두 뱅크에서 각 64B DMA 직전 STOP 여섯 건, 기존 복원기의 행·상위 비트면 STOP 두 건, SEAL 예산 계산·최종 ACK 직전 STOP 네 건에서 취소 ACK와 직전 표시를 확인했다.

621 ARM에 624만 붙인 대조군도 922를 두 위상 모두 92번째에 표시했다. 위상 2의 마지막 ACK는 자체 기준보다 16.643ms 늦었다. 기준은 621로 유지하고, 다음 실험은 두 위상 모두에서 마지막 ACK를 앞당긴 T + 624를 사용한다. 위상 1의 955는 SEAL을 212번 선에 읽고 검사 뒤 업로드에 238번 선에 진입했다. 위상 2에서는 각각 146·172번 선이었다. 우선 비교할 것은 이 차이와 첫 DMA의 도착·수락·실행 시각이다.

## 재현과 범위

1. `tools/nes_raw624.py <client>`로 619 coverage 기반의 65816을 생성한다. 621, 622 A, 623 T의 ARM을 각각 그대로 두고 [623 실행 조건](nes-credit623-results.ko.md)의 `tools/test_nes_board611.py`에 새 client를 지정한다. 시작 클록은 3,000,000 / 3,178,684, 세대는 905–957이다.
2. `tools/replay_nes_raw624.py`에 각 기존 trace, 619 `--client`와 624 `--later`를 지정한다. 전체 ROM을 처음부터 바꾼 최초 고정 도착 실험에서는 기존 관측기가 새 실행기의 행 순회를 관측하지 못했다. 최종 재생은 922 진입에 한정하고 실제 DMA 레지스터로 관측한다.
3. `tools/test_nes_map616_edges.py`, `tools/test_nes_seal538_stop.py`, `tools/test_nes_raw624_stop.py`로 STOP·새 head·누락·중복 거부와 행별 취소를 검사한다. 초기 STOP fixture가 907에서 일반 행 루프를 기다렸으나 907은 새 경로를 실행하므로 해당 진입점에서 시험한다.
4. `tools/analyze_nes_raw624.py`로 ARM·SPI·SysTick·2슬롯·65816 및 8부트 프레임 반복 ROM 허가 일정, 53장 RGB·map·VRAM DMA와 양쪽 최종 ACK를 대조한다. 보드 합성·실기 메뉴 복귀·플레이 FPS는 이 진단의 측정 범위 밖이다. [기계 판독 결과](../analysis/raw624-verification.json)
