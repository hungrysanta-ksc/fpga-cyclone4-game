# 709 E1 상태 응답 공유

**E1 응답 공유는 실제 ARM·FPGA에 연결했지만, 시간·배치 조건을 함께 통과하지 못해 채택하지 않았다.** 선택 구성은707D와 기존 ARM·65816이다. Flash와 조회 전송량은 줄었으나 두 위상의 밀집 표시 간격·마지막 ACK가 함께 개선되지 않았다. [전체 검증](../analysis/credit709-verification.json) · [원시 근거](../analysis/credit709-archive.json)

## 구현한 경계

FPGA는 E1에서도 이미 만들고 있던17B 상태 snapshot·CRC8을 기존 MISO 회전 경로로 공개한다. 별도 snapshot·RAM·CDC는 추가하지 않았다. 입력 패킷 CRC16, 실제 SNES 읽기·ACK identity 검사, 수락·retired 카운터 갱신은 그대로다.

응답은 **현재 E1의 SS 해제·수락 이전 상태**다. ARM은 sent/last를 새 패킷으로 갱신하기 전에 이전 accepted·retired·identity를 검증한다. 응답을 현재 패킷 수락이나 최종 표시 완료로 사용하지 않는다. E0와 E1의 parser를 공유하고 room/through에 중복된 최신 identity 검사를 합쳤다. 기존 credit 검사에는 없던 빈 큐 identity 검사도 공통 검사에서 수행한다.19B짜리 최소 E1에는20B 상태 전체가 안 들어가므로 기존 E0 경로를 유지한다.

첫 ARM 후보는20B 이상 E1마다 검사했다. 그 비용이 커서 두 번째는 기존 room 정책에서 다음 전송의 credit 갱신이 필요할 수 있는 pending≥2일 때만 응답을 검증했다. 사용하지 않는 응답으로 credit·진행 상태를 갱신하지 않는다. 사용한 응답은 CRC8·counter 범위·identity 검사를 전부 거친다. 최종 ACK는 여전히 E0에서 실제 완료를 기다린다.

## 조회 감소가 종단 이득으로 남지 않은 이유

192B 패킷의 실제 링크 M4 경계 비용을 분리했다. 이는 callback 모델의 명령 수이며 실기 시간은 아니다.

| 이전 pending | 기존 enqueue+room | 매번 검사 | 선택적 검사 | 별도 SPI |
|---|---:|---:|---:|---|
| 0 | 1,714명령 | 3,200명령 | 1,723명령 | 모두E1 한 번 |
| 2 | 3,193명령 | 3,200명령 | 3,205명령 | 기존E1+E0 → 후보E1 |

여유가 충분한 패킷의 불필요한 검사 비용은1,486→9명령으로 줄었다. 그러나 pending≥2여도 snapshot이 새 credit를 반환하지 않거나 곧바로 필수 소비·최종 ACK 조회가 이어지는 경우가 남는다.53화면 전체에서 선택적 후보는 ARM 명령이 **796,079 /796,305개 증가**했다. CPI2/84MHz 진단 할당으로18.954/18.960ms이며, 줄어든 E0 wire+driver 비용은20.175/23.447ms다. 이를 겹침 없는 순절감이나 실기 시간으로 빼서 계산하지 않는다. 실제 재생에서는 DMA/ROM/VBlank 위치가 달라져 위 종단 결과가 나왔다.

## 독립 검사·STOP·복구 근거

- A/B/C 각각 실제 직렬 SPI 두 속도×두 위상에서 E1 응답27건과 기존48개 경계 검사를 실행했다. 기존 보드와 수락·retired·SNES 제어가 클록 단위로 일치하며 E0 응답도 동일하다. E1은 참조 보드의 **수락 전** 상태로 만든 독립 기대값과 비교했다.
- 최대256B 패킷·4credit·wrap,ACK 작성/공개 중 snapshot,STOP 중 snapshot,19B/20B 경계,잘못된 길이·CRC·identity,중간 RUN 해제를 포함한다. B의 progress→idle receipt 불변조건도 검사했다. 보편적 formal 증명은 아니다.
- 실제 ARM은 매번 검사22건/선택적 검사23건의 CRC·counter·identity·wrap·짧은 응답 fallback·STOP·필수 최종 ACK를 통과했다. 잘못된 응답 뒤 재전송하지 않는다. 사용하지 않은 CRC 손상 응답도 credit를 갱신하지 않는지 확인했다.
- 두 ARM 각각16개 장시간·사용자 종료·STOP·credit wrap·메뉴/base 경계 검사를 통과했다. 실제 보드 메뉴 복귀·장시간 플레이를 새로 시험한 것은 아니다. 새 설치본 없음.

## 다음 순서와 중단 기준

선택 제품은707D와 기존 ARM·65816을 유지한다. E1 응답 공유의 현재 두 ARM 후보와 세 회로 후보를 그대로 재합성하거나 opcode/seed/고정 지연을 변형해 반복하지 않는다.

다음 제한 검토는 **응답이 새 retired를 제시하지 않을 때 CRC 전체 순회를 생략할 수 있는가**다. raw retired는 오직 ‘응답을 검사할 필요가 있는가’의 비신뢰 힌트로만 보고,상태 변경에는 항상 전체 CRC/counter/identity 검사를 요구해야 한다. 현재E1 수락·최종 표시 ACK를 대체하지 않는다. 아직 구현·안전성·절감량이 검증된 후보는 아니다.

1. 실제 E1 snapshot의 retired 변화 횟수와 전체 검사 횟수를 먼저 계측한다. 줄일 수 없는 필수 E0/최종 ACK는 예산에서 제외한다.
2. 검사가 유효한 credit를 반환한 경우만 남겼을 때의 ARM 추가 비용·삭제 조회 예산을 정한다. 이득이 모자라면 E1 조회 후보를 보류하고 큰 출력/DMA 병목으로 돌아간다.
3. 진행 비트의 raw STOP 경계와 snapshot 회전 제어를 포함해 실제로 없앨 조합 제어를 정한다.86LE·1LAB·0M9K 안에 들어가고 기존 제약 STA를 통과할 구조가 없으면 추가 FIT를 진행하지 않는다. A의 timing과 C의 면적을 섞어 통과로 만들지 않는다.
4. 근거가 있는 후보 한 개만 두 위상에 연결한다. 밀집 간격·마지막 ACK 동시 개선과 기존911/951/952/957·7블록·STOP·독립 검사·메뉴 조건을 모두 요구한다.

스페이드 해결은 사용자 실기 확인을 유지한다.707D 배경 CHR 수정의 실기 확인은 남아 있다. 반복 깨짐과stage0 timeout은 별도 관찰이며 속도 개선으로 해결됐다고 가정하지 않는다. 다음 전달 정책은 새 파일명60초/장시간판·RESTORE 제외·5–40초/40–55초 집계다.
