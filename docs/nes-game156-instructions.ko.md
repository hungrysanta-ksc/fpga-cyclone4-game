# NES156 — 음원 채널 차단·버튼 이력 비교

155는 첫 Start 뒤 선택 화면에서 Select를 눌러도 PPU 읽기 기한 오류로 종료됐다.156은 내부 음원 채널 쓰기를 차단해 같은 입력에서 달라지는지 확인한다. 사운드 원인 확정이나 게임 정지 수정 완료를 뜻하지 않는다. 외부 소리 출력은 이전처럼 없다.

## 설치

1. 전원을 끄고 현재 SD의 `firmware.stm`을 별도 백업한다.
2. 개인용 ZIP의 `01-GAME156-SD-ROOT` 내용을 SD 루트에 복사한다.
3. 메뉴에서 **`NES GAME 156.nh1`**을 실행한다. 0바이트 표식이며 확장자는 바꾸지 않는다.

156 MCU·FPGA는65/DF 조합이며 ROM은 `sd2snes/nes/game156.nes`다. 사용자 SMB3(J)가 포함된 개인용 ZIP은 공개하지 않는다.

## 한 번의 시험

- 첫 Start로 선택 화면에 들어간 뒤 버튼을 뗀다.
- **Select를 한 번 누르고 뗀다.** 2PLAYER 화살표로 바뀌는지 또는 메뉴로 종료되는지 확인한다.
- 계속 동작하면 Select를 다시 눌러 1PLAYER로 돌린 뒤, 버튼을 떼고 Start로 진입한다. 진행되면 방향키·A/B로 이동과 점프를 확인한다. 일부러 빠르게 연타할 필요는 없다.
- 이전과 같은 종료라면 영상 없이 TXT 두 개와 누른 순서·메뉴 복귀 여부만 전달해도 된다. 실제 플레이로 진행되면 게임 화면부터 짧게 촬영한다.

로딩 방식은 그대로다.151의 실측 약3분50초는 참고값이며 로딩 영상은 필요 없다. RUN은 최대 약60초, 오류 때 조기 종료한다. 실행 후 총7분이 지나도 복귀하지 않으면 전원을 끄고 남은 로그를 전달한다.7분은 관찰 상한이다.

## 전달할 파일

- `/sd2snes/nes-progress-156.txt`
- `/sd2snes/nes-game-last-156.txt`

최종 TXT에는 기존 오류 주소·PPU 상태와 **최근16건의 버튼 상태 변화**가 추가된다. 예를 들어 `buttons=START|` 다음의 `buttons=NONE`은 게임이 읽은 누름과 해제다. A/B/SELECT/START/UP/DOWN/LEFT/RIGHT의 동시 입력도 기록한다. 로그는 직접 해독하지 않아도 된다.

이력은 게임이 패드8비트를 끝까지 읽은 경우에만 기록한다. 실제 손으로 누른 시각을 직접 측정하지 않으며, 화면 DMA 중 놓친 짧은 입력이나 게임이 읽지 않은 버튼은 없을 수 있다. 시각 단위는 NES 마스터 클록이며 256클록 단위로 내림해 저장한다. 화면 프레임 수나 MCU 밀리초가 아니다. RUN 중에는 SD 쓰기를 하지 않고 오류·STOP 뒤 이력을 회수한다.16건을 넘으면 오래된 항목부터 덮어쓰며 전체 변화 수를 별도로 남긴다. 보조 로그가 잘못되면 `pad_trace_valid=0`으로 표시한다.

음원 차단은 `$4017` 프레임 카운터·레지스터 읽기·OAM DMA·입력 전달·CPU/PPU 클록을 유지한다. 하지만 음원 상태와 DMC 활동이 달라지므로 게임 코드의 실행 경로도 달라질 수 있다. 성공해도 사운드가 완성됐다는 뜻은 아니며 원인을 더 좁힐 근거다. 실패해도 사운드 처리 코드의 ROM 접근 영향까지 배제하지 않는다.

044/GBC·A/B 패턴·동일155 재시험은 필요 없다. 정상 사용으로 돌아갈 때만 전원을 끄고 `02-RESTORE044-SD-ROOT` 내용을 복사한다. 화면 유지·DMA 중 입력 공백·무음·저장 미구현은 계속 미완료다.
