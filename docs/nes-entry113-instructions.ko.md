# NES113 — 메뉴에서 진단으로 넘어가는 구간만 확인

112는 10분 이상 로딩 상태·로그 없음으로 실패했고, 사용자는 복원이 정상이라고 확인했다.113은 그 실패 구간을 좁히기 위한 짧은 진입 시험이다. NES 게임 실행이나80KiB 적재 시험이 아니다.

## 실행

1. 전원을 끈 상태에서 ZIP의 `01-ENTRY-SD-ROOT` 안 내용을 SD 루트에 복사한다. `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`과 루트의 `NES ENTRY 113.nh1`이 들어간다. 표식 파일은0바이트가 정상이다.
2. 메뉴가 나오면 **`NES ENTRY 113.nh1`을 한 번만 실행**한다. 이전 `NES VERIFY 094 80.nh1`은 이번 시험 대상이 아니다.
3. 메뉴로 돌아오는지 관측한다. **60초가 지나도 변화가 없으면 전원을 끈다.** 10분을 다시 기다리거나 리셋 버튼으로 복귀를 시도하지 않는다.60초는 사람의 관측 한도이며 MCU 최악 실행시간 보장이 아니다.
4. 전원을 끈 뒤 `/sd2snes/nes-progress-113.txt`와 `/sd2snes/nes-verify-last-094.txt`를 복사해 전달한다. 두 번째 파일은 이전 시험에서 남은 것일 수 있으므로 새113 로그를 우선한다. 파일이 없거나0바이트라면 그대로 알려준다. 영상은 필요 없다.
5. ZIP의 `02-RESTORE044-SD-ROOT` 안 내용을 SD 루트에 복사해 정상044로 복원한다. 메뉴/GBC 상태를 확인한다.

같은 표식을 반복 실행하면 이번 로그가 덮어써진다. 한 번의 결과만 수집한다. 기존SD 파일을 삭제하거나 포맷하지 않는다.

## 이번에 확인하는 것

정상 메뉴가 남긴 SD 다중 블록 읽기를 CMD12로 종료한 뒤, 진입 로그를 저장하고 CSS 보호 조건을 확인한다. 이후 기존 메뉴 복원 경로를 실행한다. **113 표식에서는 CF86 FPGA 구성·NES 입력 읽기·적재·비교·RUN을 수행하지 않는다.** 메뉴 복원을 위한 SRAM 쓰기는 수행한다.

- `ENTRY_SD_READY`: SD 인계 완료. `entry_transfer=1`이면 진입 시 일반 다중 블록 읽기가 남아 있었고, 검증된 CMD12 종료를 거쳤다.0이면 이미 유휴였다.
- `CSS_CHECK_NEXT` 뒤 기록이 없으면 보호 조건 확인 부근에서 멈춘 후보가 된다. 실제 원인은 추가 분석한다.
- `ENTRY_ONLY_DONE`: 진입 검사 완료.
- `MENU_PREPARED`: 메뉴 준비와 로그 저장 완료. 실제 화면 복귀까지 증명하지는 않으므로 화면 결과를 함께 알려준다.

로그는512바이트 단위라 공백이 많다. 편집하거나 내용을 해석할 필요 없이 파일 그대로 전달하면 된다. 이전094 최종 보고의 `verified=0`은 이번 진입 전용 시험에서 정상이다. 이 시험은 NES 데이터를 검증하지 않는다.

## 한계

로그 저장 이전의 SD 인계 자체가 실패하거나 메뉴에서 진단 함수에 도달하지 못하면 이번에도 파일이 없을 수 있다. 고장 뒤 무리하게 SD 쓰기를 재개하지 않는다. CMD12 응답 CRC·상태·busy 종료를 확인하기 전에는 유휴 상태로 바꾸지 않으며, 진행 중 쓰기·부분 offload는 거절한다.

실제112 실패 원인은 아직 확정되지 않았다. 같은 무로그 중단을 만드는 코드 결함을 재현·수정한 상태이며113 실기로 일치 여부를 확인한다. 전체 NES 구현, SMB3 실행, 외부 전기 조건·공통 원인 고장·8µs 보장은 이번 완료 범위가 아니다.
