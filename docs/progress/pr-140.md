## 목표

MMC502를 유지하면서 전송량과 완료 대기를 줄이고 첫 프레임 이후에도 표시 간격이 개선되는지 확인한다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 보존하고 실제 코드 실행, 조건부 시간 모형, 실기 성능을 구분한다.

## 작업내용

506은 raw 동일색10..256개를 한 record로 전송하고 ARM에서 범위·순서·세대 검증 뒤 최종 배열로 직접 복원한다.2233 ABI로 구형 조합을 거부하며489 SNES 소비기는 그대로 사용한다. 실제 linked M4 runtime/planner/serializer/native service/SysTick과 실제65816의 수신·독립 검사·DMA·receipt·최종 ACK를 공동 일정으로 연결했다. 다음 capture는 COMMIT에서 시작하고 이전 표시 lease는 ACK/EA까지 유지한다.

507은 loader SPI 오류 우선순위를 같은 클록의 비트 식으로 교체해506의 setup 실패를 회복했다. 오류·STOP·status snapshot 공개를 지연하지 않았다.

508은 END 발행과 전체 bulk 소비 대기를 분리했다. packet sequence/BUSY를 잡기 전에 ready bulk·credit을 우선 처리하고, head가 없는 ROM 대기 중 일반 packet 하나를 공급한다. 기존 last-opcode7 의존성은 bulk 발행 counter와 검증된 retired watermark로 대체했다. FPGA의 각 packet ACK 검사, SEAL 앞 전체 drain, 최종 ACK→resident commit→EA는 유지한다. 기존4credit/2bulk bank와 압축 serializer를 재사용한다.

## 성과

- 506 입력 검증: 실제 exporter14정상/2거부와 ARM8span/4CRC·version·PREPARE 거부,raw 도중 STOP 뒤 COMMIT 차단을 통과했다. 같은12개 일정에서 SPI153311→145247B,첫 표시 뒤11간격1263.881→1230.609ms(2.63% 단축)를 확인했다.
- 507 오류 우선순위8192조합/실제SPI268회/64fault bit시점과 mutant 거부를 통과했다. 전체 Lite **15164LE/14172comb/8394FF/264816bits/51M9K**,관련 **setup+0.078ns/hold+0.139ns**다. 전체reset/CDC/IO 승인은 미완료다.
- 508 linked M4 **34개 검사**가 통과했다. mixed ordinary/bulk,16bit wrap,future/stale 완료,bad ACK,중간 STOP,최종 ACK 전 EA 거부,실제 runtime guard·SEAL·resident deadline/IO 실패를 포함한다.
- 같은 시작/ROM위상의12개 최종 RGB가 같고 VRAM DMA36144B/ROM read 배정3280회가 같다.506/507 대비 **첫 표시 뒤11간격1230.609→1147.400ms:6.76% 단축**, **두 초기 표시 뒤10간격981.019→931.110ms:5.09% 단축**이다. 첫905는0.019835ms 느리며 모든 frame의 고유 이득이 같은 것은 아니다.
- SPI145247→140055B(−5192B/3.57%). 906·907·908·909·914·915에서 일반 packet의 실제 선행 공급을 확인했다. 첫 두 frame 이후 추가 VBlank 단축은909·914·915에서 발생한다. 누적 ACK 선행을 frame별 성과로 중복 계산하지 않았다.
- 508 비용은 **FW212992B/Flash0B, BSS18576B(+4), runtime444B(+4), 관측 호출 stack+272B**다. 별도 전역 객체0은 BSS 증가0을 뜻하지 않는다. 첫 ARM01의 Flash4B 초과를 보존하고 중복 service 검사를 합친 ARM02를 선택했다.
- 508 FPGA/SNES는 변경하지 않아507 전체 source SHA를 대조한 뒤 기존 비용을 재사용했다. 새 Quartus 결과로 주장하지 않는다. private15889개 증거 파일은 ZIP 보관 후 전부 SHA 검증했다.

시간은 실제 M4/65816 코드를 실행한 공동 모형의 결과다. CPI·ROM safe-slot 밀도·일부 peripheral 응답은 모형이며 전체 NES/PSRAM RTL·capture 거부율·새 실기 FPS·메뉴 하드웨어 재시험은 아니다. **실기 기준은 MMC502/10.59fps이며60Hz는 미달성**이다. Flash 여유0B라 새 전달본은 만들지 않았다. 505의 고립된 prefix DMA는 첫 frame 이후 이득이 없어 동결했다.

## 후속작업

1. 실제 ROM arbiter 요청/허용/반환 trace를 같은 ARM·SPI·IRQ·65816 일정에 연결해 공급 이득과 ROM 밀도 가정을 구분한다.
2. 기존 진행·완료 제어의 중복을 함께 삭제해 Flash 여유를 회복한다. 독립 검사와 bulk·credit 우선순위를 유지하고 BSS/stack 비용도 비교한다.
3. 초기/연속 일정·STOP·최종 ACK·EA·VBlank·유한 queue/bank를 재검증한 뒤에만 전달 후보를 선정한다. 변경 시 일치한 소스의 전체 보드 비용과 timing을 확인한다.

MMC502와 기존 ZIP을 보존한다. 다음 전달본은 고유 파일명·로그 marker를 사용하고 RESTORE 폴더는 포함하지 않는다. README는 실기 상태 등 유의미한 변화에만 갱신한다. 작은 opcode/seed/위상만 바꾸는 반복은 재개하지 않는다.
