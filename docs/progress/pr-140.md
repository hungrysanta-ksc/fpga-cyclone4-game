## 목표

실기 정상 MMC502를 보존하면서 입력 전송량과 늦은 DMA 공급을 줄인다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 유지하고, 제한 MMC509 전달본으로 실제 첫 레벨의 효과를 확인한다.

## 작업내용

- 같은 raw 값의 묶음을 압축해 FPGA exporter→ARM 단일 복원→기존48965816 경로에 연결했다.
- END 수락 뒤 bulk·credit을 우선하고, ROM 대기에 일반 packet을 한 개씩 공급한다. last-opcode 의존성을 검증된 retired watermark로 대체했다. SEAL drain과 최종 ACK→resident commit→EA는 유지한다.
- loader 오류 공개 시점을 유지하면서 관련 timing을 회복했다. ARM E8 전송·header·CRC의 중복을 합치되 phase별 검사와 오류 우선순위를 보존했다.
- 실제 CPU·PPU·MMC3·ROM의20프레임을 선행 읽기 유무로 비교하고, 기록한 ROM 허용 시각을 같은 ARM·IRQ·65816 일정에 적용했다.
- MMC509의 메뉴·ROM·FPGA·로그 이름을 갱신했다. 기존 base/menu는 그대로 사용하며 게임 ROM·세이브·RESTORE는 포함하지 않았다.

## 성과

- 입력 exporter14정상/2거부, ARM8span/4거부와 loader8192조합·실제SPI268회·64fault시점 검증을 통과했다. 이번 linked ARM34조건과40phase 오류 비교도 통과했다.
- 두 일정 비교에서12개 최종 화면,36144B DMA,3280회 ROM 배정이 같다. 기존 모형에서508의 약5.09% 연속 구간 이득을509가 유지했다.
- 실제 **부팅 ROM 기록을 재생한 모형**의506→509 비교: 첫 표시 이후11간격 **1247.251→1164.043ms(6.67% 단축)**, 초기 두 표시를 제외한10간격 **981.010→931.092ms(5.09% 단축)**. 실제 첫 레벨 부하와 일치한 폐루프 시험이나 실기 FPS는 아니다.
- ROM 선행 읽기2386회에도 CPU942526회/PPU182196회 read, mapper228회와 저장한4개 화면이 같았다. STOP/drain/error 검사도 통과했다.
- ARM은 **FW212956B / Flash 잔여36B / BSS18576B**다.508 대비 Flash36B와 관측 stack24B를 회복했다. 실기502 대비 FW+112B/BSS+4B는 남는다.
- 전체 Lite **15164LE/14172comb/8394FF/51M9K**, 관련 setup+0.078ns/hold+0.139ns는 동일507 소스를 확인해 재사용했다. 새 합성이나 전체 reset/CDC/IO 승인은 아니다.
- 전달용784개 함수가 시험509와 같고 이름만 바뀐다. STM3 CRC·실제 FatFS/프로그래머 전체 바이트·ZIP 무결성 검증을 통과했다. **MMC509는 제한 실기 시험 대기**, 현재 실기 기준은 **MMC502/10.59fps**이며60fps는 미달성이다.

## 후속작업

1. MMC502/509를 같은 첫 레벨·비슷한 동선으로 비교하고509의3개 로그를 받는다. 실행·입력·화면·약60초 메뉴 복귀를 먼저 확인한다.
2. 수신/계획/SEAL·최종 ACK와 초기/연속 표시·capture 오류를 분리해 실제 효과를 판정한다. 다른 장면의 평균이나 중첩 counter를 합산하지 않는다.
3. 남은 본문·framing·DMA 비용으로 A2 예산을 갱신한다. 효과 없는505 prefix DMA와 E8/위상/seed 미세조정은 새 근거 전까지 동결한다. MMC502·기존 백업·GBC/save를 보존하며 README는 유의미한 상태 변화 때만 갱신한다.
