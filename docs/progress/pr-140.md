## 목표

MMC502를 유지하면서 전송량과 데이터 준비 비용을 줄이고 첫 프레임 이후에도 표시 간격이 개선되는지 확인한다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 보존하며 조건부 모형과 실기 성능을 구분한다.

## 작업내용

504에서 실기 비용과 wire 예산을 분리했다.505의 불변 dirty-prefix DMA는 실제65816·STOP·VBlank 기능을 통과했지만 첫 프레임 이후 이득이 없어 동결했다.

506은 raw 동일색10..256개를 한 record로 보내고 ARM에서 범위·순서·세대 검증 후 최종 배열로 직접 복원한다. pixel마다 같은 logical_record를 다시 호출하던 처리를 제거했다. 기존 count/data/repeat 제어를 재사용하고2233 ABI로 구형 조합을 거부한다. 변경되지 않은489 소비기를 사용한다.

실제 linked ARM runtime/planner/serializer/native service/SysTick과 실제65816의 수신·독립 검사·DMA·receipt·최종 ACK를 연결했다. SPI 비용은 실기503 평균을 사용하고 CPI/ROM safe-slot 밀도는 모형으로 명시했다. 입력 COMMIT에서 다음 capture를 시작하되 이전 표시 lease는 ACK/EA까지 보존한다. emulator가 DMA를 원자적으로 실행하며 앞서간 시간이나 미래 ACK를 ARM에 잘못 반영하지 않도록 별도 반례 검사를 추가했다.

507은 loader SPI 오류 우선순위를 같은 클록의 비트별 식으로 바꾸었다. 오류 공개·STOP을 지연하지 않고 기존 status snapshot을 유지한다. 같은 506 ARM 실행에 함수/ROM 모형 관측을 추가해 다음 출력 공급 경계도 추적한다.

## 성과

- 실제 exporter14정상+2거부,ARM8span+4CRC/version/PREPARE 거부가 통과했다. raw run 도중 STOP 뒤 COMMIT을 금지했고 RTL 출력 bytes와 실제 ARM 입력12개를 정확히 연결했다.
- 같은 입력·시작 시각·ROM 위상의12개 연속 비교에서 최종 RGB와 VRAM DMA36,144B가 같았다. SPI153,311→145,247B(−5.26%),첫 BG 발행3.261~3.694ms 선행을 확인했다.
- **첫 프레임 뒤11개 표시 간격 합계1,263.881→1,230.609ms:33.272ms(2.63%) 단축.** 두 bank 초기 채우기 이후10개도33.269ms(3.28%) 줄었다. 모든 프레임이 같은 비율로 빨라지지는 않았고, 큰 추가 이득은911·913의 VBlank 한 주기 단축이었다.
- 506은 FW+8B/Flash140B 남음,새 persistent RAM0. 전체 Lite15198LE/14168comb/8399FF/51M9K. 기준 대비 LE−89는packing 결과이며 comb는33개 늘었다.
- 506의 setup−1.276ns 실패를 507에서 **관련 setup+0.078ns/hold+0.139ns**로 회복했다. 기존 실패 경로 자체는+0.992ns다. 같은 소스의 Lite 전체 배치를 후보당1회 실행했고 seed·SDC 예외를 바꾸지 않았다. 전체 reset/CDC/IO 승인은 별도 미완료다.
- 507은 **15164LE/14172comb/8394FF/51M9K**,506 대비−34LE/+4comb/−5FF다. ARM·SNES는506과 동일하다.
- 오류 선택8192조합과 실제SPI268회,64개 bit시점 fault 주입을 통과했고 우선순위 mutant를 거부했다. 오류의 공개 지연이나 새 상태 저장은 없다.
- 초기 END 모형 오류·RPC 공유 잠금/시작 watchdog·잘못된 DMA/capture 일정·nominal 파일 누락을 분리하고 원본 실패를 남겼다. 506 선택 근거는ARM02/rtl02/joint11·13/board01/analysis03이며,507은test02/trace01/board01/analysis02다.

507의 관측 실행은 같은12개 ACK/RGB·ARM 명령/IRQ/wire와 정확히 같았다. 첫 두 bank 이후10개에서 END→finish 반환 평균8.165ms, 이후 첫 일반 전송까지0.289ms였다. 일반 전송 시작→SEAL은27.275ms이며 순수 CPU 시간이 아니다. 다음 개선 대상은 작은 준비 계산보다 완료 대기와 일반 출력 공급의 겹침이다.

실제 M4/65816 코드를 실행했지만 ROM 경쟁·CPI·일부 peripheral 응답은 모형이다. 전체 NES/PSRAM RTL 공통 시간·새 실기 FPS·메뉴 복귀 시험을 했다는 뜻은 아니다. 실기 기준은 **MMC502/10.59fps**이며 새 전달본은 없다. 전체60Hz는 미달성이다.

## 후속작업

END 수락 뒤 일반 출력을 제한적으로 앞당기는 진행 제어와 bulk 완료 추적을 함께 교체한다. 현재 `complete485`는 마지막 opcode7을 요구하므로 일반 packet을 단순 삽입할 수 없다. 검증된 retired counter의 bulk watermark를 사용하고, 준비된 bulk·credit을 우선하며 일반 packet은 한 번에 하나만 공급한다.

목표 예산은 runtime 구조 추가 최대8B, 새 global0B, Flash 순증 최대140B, FPGA 제어/M9K 추가0이다. 아직 구현 비용이 아니다. 독립 ACK 검사·wrap·STOP·old identity·최종ACK→EA·VBlank와 실제 arbiter trace/연속 일정을 함께 검증한다. 507 loader 변경 자체의 추가 프레임 가속은 주장하지 않는다.

MMC502를 실기 기준으로 유지한다. 다음 전달본은 고유한 파일명을 사용하고 RESTORE 폴더는 포함하지 않는다. 505 prefix/opcode/위상 미세조정이나 seed 반복은 재개하지 않는다.
