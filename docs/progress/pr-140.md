## 목표

PR139에서 실기 확인된 MMC502를 유지하면서 A2의 전송·DMA 비용을 분리하고, 실제로 교체할 실행 경계와 자원 예산을 정한다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 보존한다.

## 작업내용

PR139 merge `46c0cc962397b3e757c838164b70b75fe73090a6`와 head의 master 도달·tree 일치를 확인했다. 새 브랜치에서 502 실기 driver 바이트를 다시 분해하고, 기존65816의 PC 경계를 측정했다. 같은 프로그램·입력·시작 시각에서 픽셀과 모든 최종 ACK masterclock이 원본과 동일했다.

실제502 cold source의 record를 packet 공통 generation으로 표현하는 Python ABI 시제품을 비교했다. 제품 RTL·ARM에는 적용하지 않았다. 전체 이전 입력 RAM, 공통 SPI 설정, 비활성 VRAM 선행 DMA를 비교하고 기존 dirty-list의 열린 tail·payload 완료·VBlank·취소 경계를 명시했다.

## 성과

- 실기 관측 조회 제외5911.51B/표시:16.67ms 예산보다442.76B, 잠정12ms 예산보다1974.01B 많다. 조회만 없애서는 충분하지 않다.
- 실제65816의 과거 연속12개 fixture에서 SEAL→upload 평균2.24ms, upload→최종 ACK23.65ms, upload 중 VBlank 대기1~3회. 새502 실기warm 시간이나 순수 대기시간은 아니다.
- 실제502 cold1개에서는 각각2.17ms/57.68ms, VBlank 대기4회다. 관찰 callback은 원본 픽셀·ACK 시각을 바꾸지 않았다.
- 공통 generation 시제품은332record를 정확히 복원하고5개 반례를 거부했다.17→15packet,3982→3378payloadB. 동일한 최소 transport 할당의 wire 차이는642B/1.957ms이며 실제 제품 가속은 아니다.
- 전체7533B 입력 이력은 M9K 최소7개(8bit구성이면8개)가 필요해 남은5개에 추가할 수 없다. 새 전체 cache는 회수 설계 전까지 기각했다.
- 다음 실행 실험은 기존 dirty-list의 불변 prefix를 비차단 방식으로 비활성 VRAM에 먼저 보내는 경계다. 추가 SNES body≤512B·WRAM≤8B·frame buffer/M9K/ARM 실행코드/FPGA 제어 추가0을 설계할당으로 정했다. 아직 구현 실측이 아니다.

전체60Hz 예산은 아직 통과하지 않았다. 실기는502/10.59fps 그대로이며 새 firmware·Quartus·Questa·설치본은 만들지 않았다.

## 후속작업

packet 완료 뒤의 불변 prefix만 실행하고 append 중인 tail은 보존한다. 현재 VBlank 남은 시간을 확인해 한 DMA가 들어갈 때만 실행하며, 기다리느라 수신을 막지 않는다. SEAL 때 이미 끝낸 prefix를 다시 전송하는 경로를 삭제한다.

STOP 이후 부분 bank 무효화·old active identity·최종 CRC/coverage·semantic 검사·표시 ACK를 실제65816에서 검증한다. 이후 ARM·공유 SPI·IRQ·ROM 전체 일정에서 단순 대기 이동인지 실제 단축인지 판정한다. 입력 ABI의 본문 절감과 전체 예산도 계속 닫아야 한다. 다음 시험판부터 RESTORE 폴더는 포함하지 않는다.
