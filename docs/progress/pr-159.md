## 목표

MMC763을 실기 기준으로 유지한다. 25–30초에 MMC767의 화면당 출력·최종 ACK가 약 8.14ms 늘어난 이유를 찾고, 다음 변경이 실제 표시 시각을 앞당길 조건을 정한다.

## 작업내용

- PR158 병합 `fb7f104`에서 두 성공 회차의 25–30초 bin을 화면 시작 수로 정규화했다. 10ms tick 합으로 구한 구간 평균과 84MHz DWT의 전체 실행 합계를 구분했다.
- 905–957의 기존 캡처는 OBJ 슬롯 범위가 최대 94다. 같은 첫 레벨 캡처를 970까지 연장하고, map 64B 그룹 8개·OBJ 범위 126인 969를 비교 화면으로 골랐다. 969와 보조 표본 961·967에서는 원본 ARM planner의 map_dirty 비트 수를 직전 화면 대비 최종 map 차이와 대조했다. 969의 BG 범위는 147이고 실제 OBJ tile plan은 4개다. 실기 구간의 BG 약 556·OBJ tile plan 평균 7.37/8.41개와 차이가 있어 실제 특정 화면을 식별할 수는 없다.
- 두 배포판의 링크된 ARM과 정적 65816을 리셋부터 같은 입력·시작 위상·SPI 비용·ROM 허가 일정으로 실행했다. 957–970의 압축 입력은 보드 RTL로 생성했다. 957에서 기존 전송 바이트와 일치하는지 검사하고, 새 캡처의 OBJ 캐시는 기록한 PPU fetch로 구성했다. 65816의 수락·DMA·최종 ACK를 직접 기록했다. ARM CPI·IRQ 경계·SPI 드라이버와 ROM 허가 일정은 재생 모델이다.
- MMC767에만 있는 map DMA 대기를 969 한 화면에서만 건너뛰는 대조를 추가했다. 두 실행 모두 직전 968 최종 ACK까지 원본과 일치해야 한다. 65816의 map·타일·CGRAM·OAM·receipt 검사와 VBlank 공개 조건은 그대로 실행한다.

## 후속작업

1. MMC763을 성능 기준으로 유지한다. 다음 25–30초 실기 계측에서 **출력 안의 E0/E8 조회를 진행 유무·사유별로** 세고, SEAL 발행·65816 수락·업로드 시작·최종 ACK의 시각 또는 VBlank 번호를 같은 화면에 묶는다. 실기에서 추가 조회가 어느 DMA나 표시 마감을 실제로 넘기는지 판별한다.
2. 먼저 496B 선행 DMA 기회를 유지한 채 같은 상태를 다시 읽는 E0 조회를 줄이는 후보를 시험한다. E8은 descriptor가 실제로 준비된 시각과 비교한다. 슬롯 반환·DMA 진행·최종 ACK는 각각 기존 독립 검사를 통과해야 한다. STOP과 새 패킷 우선·메뉴 복귀도 유지한다.
3. 후보는 두 시작 위상의 **표시 간격과 최종 ACK**를 함께 비교하고 실기는 기존 5–40초·40–55초 동선으로 판정한다. 중간 성의 PPU 162선 dot 0 읽기 마감은 별도 안정성 항목으로 보존한다.

## 769 조회 간격 시험과 실기 계측

실기 기준은 MMC763이다. MMC767에서 496B를 선행 전송한 969번 화면(map 8그룹, OBJ 범위 126, BG 147)을 같은 ARM·SPI·IRQ·ROM 달력에 재생했다. 769는 큐 반환을 검사하고 map 진행이 없을 때 기존 입력·STOP 서비스 콜백 한 번을 추가한 뒤 E0를 다시 읽는다. 아래 E0는 출력 함수 진입부터 SEAL SPI 발행 전까지이며, quiet는 직전 E0 이후 retired와 map 진행 비트가 모두 같은 횟수다.

| 969 | MMC763 기준 | MMC767 | 769 |
|---|---:|---:|---:|
| 위상 1 E0 전체 / quiet | 18 / 5 | 41 / 25 | 36 / 21 |
| 위상 2 E0 전체 / quiet | 20 / 7 | 42 / 26 | 37 / 21 |

769는 두 위상 모두 전송 100B를 줄였고 선행 496B·SEAL 뒤 786B를 유지했다. 969의 65816 최종 ACK 차이는 MMC767 대비 −120/+240 masterclock, 마지막 970은 +406/−2,714였다. 952–957 평균 표시 간격은 49.914781→49.914750ms / 49.910668→49.907983ms였으며 957 ACK는 0/−346클록이었다. 769는 Flash 212,992B(여유 0)이며 두 위상의 표시 개선 조건을 충족하지 않아 배포 대상에서 제외했다. 각 위상별 66화면의 map·RGB 대조와 최종 ACK를 확인했다. E0/E8 물리 조회에 사유별 계수를 붙이며 추가 SPI78은 최종 ACK와 EA 이후에만 수행한다. 독립적인 VBlank 검증에는 Mesen의 실제 PPU DMA 및 카트리지 쓰기 이벤트를 쓴다. 직접 관측 가능한 다음 병목은 **작업량이 비슷한 화면에서 마지막 유효 진행 뒤 SEAL→첫 DMA가 다음 VBlank로 넘어가는 경우**다. 실기 자료를 받은 뒤 이를 우선 맞춰 본다.
