# PR185 NES 디버그판·배포판과 카트리지 저장 지원

## 목표

FF3와 커비의 실기 비교를 이어가면서 SD에서 선택하는 NES 게임에 빠른 로딩, 수동 종료, 재현 가능한 저장 지점을 제공한다. [PR 185](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/185)

## 작업내용

1054–1058에서 디버그 계측과 배포판 로딩을 분리하고 SRAM 전송·메뉴 복귀, CNROM·AxROM·VRC4·ExROM 실행, 프리렌더 CHR 공급 및 패턴 RAM 미러를 수정했다. 1059에서 세 게임의 매퍼 상태를 체크포인트에 포함하고, 드래곤퀘스트 IV의 1 KiB ExRAM을 별도로 보존한다. 배틀토드에서는 512 B 단위로 패턴 RAM 미러를 갱신한다. 와이와이월드 2는 소비용 CHR-ROM 읽기와 공유 map·OBJ 메모리 구성으로 배치했다.

## 성과

1058 실기에서 와이와이월드 2 첫 스테이지 플레이, 배틀토드 스테이지 표시, 드래곤퀘스트 IV 필드 진입을 확인했다. FF3 1055 배포판의 빠른 시작·저장 및 수동 메뉴 복귀도 확인했다. 1059는 세 보드가 Quartus Lite 전체 FIT·STA를 통과했다. 보드별 최저 slack은 MMC5 +0.157 ns, AxROM +0.143 ns, VRC4 +0.157 ns다. 실제 게임을 실행한 RTL에서 체크포인트 재시작 후 CPU 명령 fetch 64개씩을 대조했고, 최종 release ARM의 파일 왕복은 별도 FAT16 장치 모델에서 검사했다. 배틀토드의 동일 CHR 쓰기에서 미러 전송이 3,072→1,536 B로 줄었다. [실기 수치·설치·조작](../nes-carts1059.ko.md) · [측정·해시](../../analysis/nes-carts1059.json)

## 후속작업

1059에서 세 게임의 같은 슬롯을 SD 메뉴 재실행 뒤 불러와 장면·음악·조작을 확인한다. 배틀토드의 후반 표시 속도와 와이와이월드 2의 소비용 ROM 경로를 먼저 1058과 비교한다. 드래곤퀘스트 IV는 모험의 서를 기록한 뒤 WRITE SRAM과 재실행을 확인한다. 이후 커비·모험도 4의 동일 조건 성능 비교를 재개한다.

1058 입력 보드가 있는 작업 PC에서는 `tools/prepare_cart_state1059.py 7 5 vrc-debug vrc-release`와 `tools/prepare_vrc_state1059.py`로 소스를 생성한다. ARM은 vrc 아래 두 link 트리에서 빌드한다. 보드 5·7은 fit-5·fit-7로 PSRAM과 SRAM 핀을, 보드 21은 fit-21-demand로 PSRAM 핀을 확인한다. 세 test_cart_*1059.ps1을 같은 FLOAT 좌석에서 순차 실행한 뒤 `tools/check_cart_state1059.py vrc`와 `tools/package_cart_state1059.py` 순서로 검증·포장한다.
