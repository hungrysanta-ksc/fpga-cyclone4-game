# PR 170 · 무입력 데모의 map 선행 DMA와 다음 입력 수신

## 목표

모험도 4의 같은 무입력 데모에서 map 전송을 줄인 효과가 실제 화면 공개까지 이어지는지 확인한다. 실기 비교 구간은 오프닝 [1, 30)초와 자동 데모 [30, 60)초다. 재생에서는 두 시작 위상의 오프닝·전환·밀집 장면을 고정하고 표시 간격 합과 마지막 ACK를 함께 비교한다.

## 작업내용

- 862–866에서 수집한 실기 계측과 ARM 후반 패킷 발행 변경을 포함했다. 867–872에서는 sd2snes+의 화면 갱신 방법을 대조하고, 대상 뱅크의 최종 ACK에 근거한 map 열 묶음과 팔레트·DMA 발행 순서를 검증했다. [구조 비교](../nes-reference867-review.ko.md) · [전송 비용](../nes-map868-cost.ko.md) · [오프닝과 전환 회복](../nes-capture871-results.ko.md)
- 873–880에서는 마지막 map의 큐 반환, 비활성 VRAM 쓰기 완료, 다음 스크롤 발행을 구분했다. 같은 값이 같은 PPU 포트와 VRAM 주소로 갔는지 확인하고, 이전 표시의 최종 ACK·EA와 다음 입력 COMMIT 순서를 검사했다. [선행 DMA 대조](../nes-mapwait880-results.ko.md)
- 881–884에서는 전환의 불필요한 E0 조회, OAM 재사용, D1 복원 비용과 ordinary credit 대기를 분리했다. 같은 ARM 바이너리로 962의 수신 조건만 바꾼 대조를 포함했다. [910 캡처](../nes-packed883-results.ko.md) · [962→963 일정](../nes-room884-results.ko.md)
- MMC890은 888 ARM의 판명·로그명을 바꿔 전체 링크하고, 889의 65816 ROM으로 MMC872 보드를 다시 합성한 60초 시험판이다. 기존 SNES·GBC 파일은 MMC872 ZIP의 해시로 대조했다. [설치 안내](../nes-mmc890-trial.ko.md) · [최종 링크·보드·ZIP 검증](../analysis/trial890-package.json)

## 성과

| 모험도 4 무입력 실기 | MMC866 | MMC872 |
|---|---:|---:|
| 오프닝 [1, 30)초 | 519장 · 17.90 FPS | 519장 · 17.90 FPS |
| 데모 [30, 60)초 | 507장 · 16.90 FPS | 523장 · 17.43 FPS |

MMC872는 데모에서 16장을 더 표시했고 60초 뒤 메뉴로 복귀했다. 60 FPS는 계속 개발 목표다. [두 실행의 원본 집계와 작업량](../../analysis/hardware872-results.json)

재생에서 880은 950의 선행 DMA를 회복했고 882는 두 위상의 전환 합을 119 VBlank로 회복했다. 883의 검사 공유 링크는 두 위상 모두 910을 2 VBlank에 표시했다. 884는 같은 바이너리에서 963 첫 D1을 5.56 / 5.55ms 앞당겼지만, 962의 최종 ACK 전에 D1 전송을 마친 블록은 두 경우 모두 13개였다. D2 후속 상태까지 확인한 블록은 884에서 두 위상 모두 12개다. 밀집 60간격은 139 / 139로 같고 마지막 ACK도 두 위상에서 함께 빨라지지 않아 실기 기준은 MMC872로 유지한다. [같은 링크의 발행·수락 시각](../nes-room884-results.ko.md)

885에서 963 두 번째 블록도 테이블 전에 읽었다. 팔레트 반환 시 D2 확인은 3.44ms 빨라졌으나 테이블·SEAL이 0.369ms 밀려 밀집 간격은 그대로였다. [두 위상·같은 ARM 대조](../nes-second885-results.ko.md)

886은 959에서 요구 비트가 없는 단어의 WRAM 읽기를 생략했다. 959에만 적용하면 두 위상 모두 223선에 대기를 시작해 밀집 60간격이 139→138회다. 전체 부팅은 138 / 139회이며 위상 2의 947 캡처가 36클록 늦었다. [정적 ROM과 동일 시각 대조](../nes-coverage886-results.ko.md)

887은 조회가 최종 ACK 직전에 시작해 이전 상태를 받은 두 경우를 재현했다. 48µs 조회를 한 세대에만 적용하면 947·918의 캡처를 각각 한 번 회복했다. 정적 링크의 밀집 간격은 138 / 138회지만 위상 1 마지막 ACK와 오프닝 703 마감이 늦어져 실기 기준을 유지한다. [조회 시각과 전체 부팅 비교](../nes-deadline887-results.ko.md)

888에서 144B 타일 이력 확정을 903→326 ARM 명령으로 줄였다. 947·918의 동일 시각 대조는 모두 한 번 빨라졌지만 정적 링크의 밀집 합은 138 / 139→139 / 138회로 바뀌었다. [함수별 계측과 959 credit 마감](../nes-history888-results.ko.md)

889에서 959 OBJ 검사와 다음 큐 조회 사이의 63클록 차이를 해소했다. 정적 ROM에서 두 위상 모두 밀집 60간격이 138회, 오프닝 703 공개가 231선이었다. 마지막 ACK는 MMC872보다 각각 49.918·49.997ms 빨랐다. 위상 2의 966에는 888에 비해 최종 DMA가 336B 더 남았다. [같은 도착 시각과 정적 ROM 대조](../nes-bulk889-results.ko.md)

### MMC890 실기 부팅

MMC890 실기 1회차는 393,216B 적재·대조와 START 뒤 stage 0에서 44,548회 조회하고 500 tick(5초)에 준비 대기를 종료했다. 표시 0장, ROM 오류 0, STOP·base 복구·메뉴 준비는 성공했다. 첫·마지막 준비 응답 `01400500 → 01580500`은 MMC704 1회차와 같다. MMC872 정상 실행에서도 첫 응답에 `05`가 있었고 25 tick에 stage 3으로 넘어갔다.

2회차는 연속된 512B 레코드 80개가 있고, 마지막은 START 호출 직전인 `DISPLAY_NEXT`(222.450초)다. 이 지점부터 STOP·관측값 확인까지 SD 체크포인트가 없어 실제 정지 위치는 미확정이다. 사용자는 로딩 뒤 오프닝과 음악 없이 검은 화면이 유지됐고 본체 리셋으로 메뉴가 돌아오지 않았고 전원을 껐다 켠 뒤 메뉴가 나타났다고 보고했다. 두 회차 모두 실기 FPS 비교에서 제외한다. [회차별 로그 해시와 판정 근거](../../analysis/hardware890-startup.json)

동봉된 NES BOOT 진단에서도 같은 준비 시간 초과를 확인했다. `DISPLAY_NEXT bytes=2` 뒤 5.010초에 `PROBE_STOPPED bytes=2 total=6`이 기록됐다. 44,507회·500 tick 동안 응답은 일반 1회차와 같은 `01400500 → 01580500`이었고 native 거래는 0건이다. RESET 해제 뒤 빈 큐 응답은 정상이었고 STOP·base 복구와 실제 메뉴 복귀가 모두 성공했다. 2회차 암전의 정확한 위치는 여전히 미확정이다.

MMC872와 MMC890의 Quartus 배치 후 ROM 초기값을 대조했다. RESET 벡터는 둘 다 `$8000`이고, `$00:8024`에서 stage 1을 `$00:7000`에 쓰는 명령까지 첫 39B가 같다. 다음 진단은 이 최초 쓰기보다 앞선 RESET 벡터 읽기·ROM 출력 허가와 쓰기 수락을 구분해야 한다. 현재 로그에는 SNES가 읽은 실제 벡터 데이터나 실행 PC가 없다.

### MMC891 부팅 진단

MMC872·890의 65816은 Mesen에서 모두 640클록에 첫 stage를 썼다. 보드 RTL에서는 벡터가 모두 무구동인 경우와 하위 바이트만 무구동인 경우가 기존 상태 `05`에 함께 들어갔다. MMC891은 두 바이트의 실제 보드 출력, 첫 명령과 stage 쓰기를 구분한다. 7조건 × 4위상, 최종 ARM 링크의 loader·base·메뉴, 전체 FIT·STA를 통과한 891E를 실기용으로 묶었다. 기존 MMC890은 실기 60초 완주 데이터가 없다. [진단 근거와 합성 결과](../nes-boot891-results.ko.md) · [실기 절차](../nes-mmc891-trial.ko.md)

## 후속작업

1. 실기 NES BOOT 891의 `03`을 RAM 초기화 중 RESET 해제로 재현했다. MMC892는 ARM에서 SPI73 active를 확인하고 해제해 네 위상 모두 첫 벡터와 stage 쓰기를 회복했다. Quartus Lite 전체 FIT·STA와 이미지 일치를 확인했다. 다음은 같은 ROM으로 NES BOOT 892의 실기 stage 3·메뉴 복귀를 확인하는 일이다. 60초 완주본이 생기면 MMC872와 비교한다. [실기 판독](../nes-boot891-results.ko.md#nes-boot-891-실기-결과) · [재현·수정·최종 링크](../nes-reset892-results.ko.md)
2. 위상 2의 966에서 최종 DMA에 남은 map 320B·tile 16B의 수락 시각을 직전 VBlank와 비교한다. 기준은 889의 두 위상 연속 재생과 MMC872의 실기 결과다.

### MMC890 재현

1. [889 기준 산출물](../nes-bulk889-results.ko.md#재현)을 만든 뒤 `package_nes_trial890.py prepare`를 실행한다. `build_nes_mmc479_arm.ps1`의 Base는 `nes-history888/link-credit`, Patch와 Out은 각각 `nes-trial890/patch`, `nes-trial890/link-credit`이다.
2. `package_nes_trial890.py board TEMP`로 전체 보드를 합성한다. 최종 링크 재생은 `replay_nes_strip869.py TEMP PHASE WORK 890-final SCENE`에서 PHASE 1·2, SCENE `opening`·`transition`·`dense`를 사용한다. WORK는 `probes/nes-trial890`이다.
3. 최종 ARM의 60초 경계, 두 집계 구간, 입력, retire, 메뉴, base 복귀와 소비기 부팅을 검사한다. `package_nes_trial890.py loader ROM`과 `guards TEMP`를 실행하고, `pack TEMP`로 원본 MMC872 ZIP의 파일 해시와 최종 산출물을 대조해 설치본을 생성한다.
