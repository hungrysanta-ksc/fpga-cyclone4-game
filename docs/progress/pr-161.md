## 목표

MMC763을 실기 기준으로 유지하고, 동일한 작업량에서 직전 표시 ACK부터 SEAL 수락까지 지연이 어디서 생기는지 찾는다.

### 776의 뱅크 준비와 E8 조회

첫 레벨 재생 969는 map 변경 8그룹, OBJ 범위 126, BG 범위 147이었다. 마지막 네 건은 BG 16B(token 158), OBJ 32B(159), OBJ 64B(160), OBJ 32B(161)였다. 수락된 패킷을 원래 시각에 다시 넣어 두 판·두 위상에서 65816의 토큰 쓰기와 0x6050 소비 명령을 기록했다. 각 66화면의 전체 소비 이벤트와 RGB를 원본과 대조했다. 마지막 OBJ의 네 CHR 읽기는 모두 OBJ 캐시에 적중했다.

707D 보드 소스의 staging·토큰 소비·E8 회로 6개 파일을 핀으로 고정했다. 969의 실제 payload와 65816 소비 시각, ARM의 E8 조회 시작을 넣어 슬롯 8의 쓰기 완료, 최종 descriptor가 reader에 보이는 시각, SPI 응답의 CRC·세대·token·주소·길이를 확인했다. 회로 시험 입력은 완성 타일 인터페이스에서 시작한다. ROM·캐시 공급 시각과 SPI 발행은 기존 연속 재생 모델이고, 이 수치는 실기 프로브 측정값이 아니다.

아래는 968 최종 ACK 뒤 경과 시간(ms)이다. 두 쌍 모두 왼쪽 MMC763, 오른쪽 MMC767이다.

MMC767의 마지막 뱅크는 1.019 / 1.461ms 일찍 봉인됐다. 봉인 후 앞선 64B OBJ 반환을 기다리는 시간은 4.595 / 5.169ms 늘었다. reader 공개 뒤 E8 응답 완료까지의 차이는 +0.245 / −0.294ms였다. 세 항목의 합이 +3.822 / +3.413ms다. 65816의 선행 토큰 소비 자극부터 reader 갱신까지 RTL에서 116–125ns가 걸렸다. 두 뱅크가 동시에 봉인된 순간의 STOP은 즉시 공개를 차단했고, 재시작 후 옛 token과 END는 남지 않았다.

MMC767에서는 마지막 map 발행 뒤 ARM이 빈 큐의 실제 DMA 진행을 E0로 확인한 시각이 32.804 / 32.915ms였다. 그 뒤에야 앞선 token 160을 조회하고 E1으로 발행했다. 같은 구간의 map·tile 선행 DMA 496B는 순서대로 192+16+192+32+64B였다. 두 위상 모두 첫 전송은 227선이었다. 당시 순서에서는 920B의 E1 거래가 남아 순수 SPI만 2.804ms였다. 227선의 시작부터 해당 프레임 끝까지 전부 써도 2.223ms다. ARM·검사·DMA 비용을 넣기 전부터 0.581ms 부족하므로, 마지막 조회만 앞당겨 같은 VBlank에 표시할 수 없다.

### 776 발행 후보

- 776A는 map 뒤에 대기 플래그를 세우고 확정 ordinary 준비와 기존 E8 조회를 먼저 수행한다. 처음 본 descriptor는 독립 검사 후 스택에 보유하며, 기존 map 진행 대기를 거친 뒤 E1을 보낸다.
- 776B는 기존 map 대기와 발행 순서를 유지한다. OAM 뒤에 앞선 OBJ receipt를 확인한 경우, 같은 횟수 한도에서 다음 STOP 검사와 E8 조회로 직행한다. 잘못된 CRC·같은 token에 다른 내용·STOP·반복 token 횟수 소진에서 새 E1 발행은 0건이었다.
- 별도로 MMC767의 원래 ELF에서 969의 해당 반환 직후 한 번만 같은 분기를 실행해, 부팅부터 쌓인 위상 변화를 분리한다. 이 분리 시험의 시간은 실제 링크 후보의 시간과 구분한다.

### 777의 969 전송 순서 시험

목표 시각은 968 공개 뒤 두 번째 VBlank의 227선 수평 클록 0으로 고정했다. 기준 MMC767과 두 후보의 링크된 ARM에서 OAM 앞 112B·스크롤·240B 테이블의 마지막 쓰기와 planner 종료 후 값을 기록했다. 일반 발행 시각은 E1 거래, 65816 수락과 반환은 해당 sequence의 head load와 ACK로 측정했다. 프로브를 붙인 기준 재생이 원본과 같은지 66화면 전체의 패킷·소비 이벤트·완료 시각을 대조한다.

- 777A는 기존 map 대기가 실제로 걸리는 warm 화면에서 두 대상 뱅크의 ACK 이력을 검사하고, OAM·스크롤·패딩을 먼저 발행한다. 969에서 각 E1은 135·40·21B로 합계 196B다. 1,100B 패딩은 21B로 전송돼도 65816에서 전체 범위를 채운다. 원래 map 대기 마감과 각 E1의 tile·credit·STOP 중재를 사용한다.
- 777B는 같은 뱅크 이력과 확정된 patch가 있는 warm 화면에서 section 5 전체를 후반 map보다 먼저 보낸다. 스크롤·패딩·raw·테이블 순서와 수신 검사를 유지한다.
- 240B 테이블만 발행하는 대조에서는 원래 ARM이 만든 table 바이트와 세대·뱅크를 사용하고 sequence를 다음 순번으로 맞췄다. 65816은 section 5의 첫 오프셋으로 1,505를 받자 0xE0로 거부했다. 968 화면의 RGB와 마지막 표시 이력은 유지됐다. 현재 ABI에서 독립 검사를 유지하려면 앞 범위를 먼저 수락해야 한다.

## 성과

두 위상 모두 969의 496B 선행 DMA가 유지되는 조건에서는 E8 조회를 당겨도 해당 화면의 최종 ACK와 3 VBlank 표시 간격이 그대로였다. 968까지 같은 실행을 유지한 뒤 969에서만 반환 직후 조회한 경우, 마지막 OBJ의 E8 시작은 양쪽에서 0.130ms 빨라졌다. 970 ACK는 각각 1,850 / 352 masterclock 빨라졌다.

ACK 차이의 기준은 각 위상의 MMC767이며 음수는 더 이른 시각이다. 선행 바이트는 969의 출력 진입부터 SEAL 수락까지 실제 PPU DMA로 전송한 양이다. 부팅부터 바꾼 후보의 ACK 시각에는 이전 세대에서 누적된 차이가 포함된다. 모든 행에서 969는 3 VBlank였고, 각 위상의 66화면에 대해 map·예상 출력·최종 RGB가 같았다. 969 작업량은 실기 25–30초와 가까운 재생 표본이다.

776A의 ARM Flash는 213,056B로 64B 초과했고 BSS가 4B 늘었다. 776B는 212,992B로 한도에 맞으며 BSS는 MMC767과 같다. 두 후보 모두 ARM의 152개 receipt 비트 손상·STOP·최종 ACK·메뉴 복구 검사와 65816의 독립 출력 검사를 통과했다. 776B는 위상 2에서 64B의 선행 DMA를 잃고 밀집 간격이 2.266µs 늘어 실기 펌웨어는 MMC763을 유지한다.

### 777 고정 도착 대조

MMC767의 968 최종 ACK까지 모든 65816 소비 이벤트를 고정했다. 마지막 map 반환이 E0에 보인 뒤 OAM·스크롤·패딩 196B만 먼저 넣고 나머지 거래 도착 시각은 보존했다. 각 선행 패킷에 기존 E8·E0·E1 시간을 배정하고, 그 구간의 원래 E0/D0 조회는 대체했다. ARM 소프트웨어의 추가 비용과 IRQ 효과는 별도 전체 링크에서 계산한다. 두 위상 모두 패딩까지 227선 전에 소비했고 같은 496B가 226–239선에 전송됐다. 969 표시는 그대로 3 VBlank였고 최종 ACK는 12 / 120 masterclock 늦었다. 970 최종 ACK 차이는 0 / +12,088클록이다.

기준의 496B 마지막 PPU 쓰기 뒤 246선 끝까지는 0.396 / 0.362ms였다. 같은 969 수신기의 SEAL 수락→검사 완료·업로드 진입은 1.631 / 1.633ms다. 이 DMA를 원래 시각까지 실행한 뒤에 검사를 시작하는 순서라면, 나머지 전송과 표시 비용을 0으로 놓아도 약 1.24 / 1.27ms가 모자란다. 기존 191B는 SPI만의 필요조건이었다.

### 777 전체 링크와 두 시작 위상

원래 MMC767에서 227선 기준 OAM 원본의 마지막 쓰기는 −13.513 / −13.406ms, scroll은 −13.374 / −13.267ms, table은 −11.717 / −11.612ms였다. 준비 경계에서 읽은 112·21·240B와 실제 발행 payload가 일치했다. 65816이 수락한 시각은 OAM +1.608 / +1.757ms, scroll +3.015 / +3.153ms, table +7.171 / +7.220ms였다. 오류가 없는 E0로 확인한 ordinary 큐의 네 credit과 staging의 두 뱅크는 별도 자원이다. 각 E1 시작 시각의 미반환 개수와 가장 최근 E0의 수락·반환 카운터를 결과 JSON에 남겼다.

777A는 기존 다섯 DMA와 추가 map 384B를 선행했다. SEAL 수락은 목표 246선 끝보다 3.757 / 3.741ms 늦었다(기준 +6.627 / +6.678ms). 968→969 ACK 간격 자체는 0.157 / 0.168ms 줄었으나 969는 양쪽 모두 3 VBlank였다. 부팅부터 누적한 표시 간격에서 위상 1은 960에서 1 VBlank를 잃었다. 위상 2는 909·934·938·960에서 각 1회를 잃고 933에서 1회를 회복했다. 777B는 table을 227선보다 2.445 / 2.647ms 일찍 수락했지만 map이 뒤로 밀렸다. 두 후보는 각 위상에서 66회 최종 ACK와 동일한 map·section 5·RGB를 확인했다.

Flash는 MMC767 212,972B, 777A 213,132B, 777B 213,112B다. 한도 212,992B 대비 A는 140B, B는 120B 초과다. BSS는 세 판 모두 19,796B다. 두 후보에서 ARM receipt 152비트 변조·잘못된 token·STOP·최종 ACK와 메뉴 복구 함수 검사를 통과했다. 선행 패딩 수신 중 STOP을 넣은 65816 시험은 0xE4를 반환했다. STOP 표집 뒤 DMA가 발생하지 않았고, 969의 표시 이력과 최종 ACK는 발행되지 않았으며 968 화면 RGB가 일치했다. 실기 기준은 MMC763으로 유지한다.

## 후속작업

969 표시를 2 VBlank로 줄일 다음 후보는 첫 VBlank에 map offset 1,216부터 공급하는 것이다. MMC767에서 offset 1,024 수락 ACK는 첫 246선 끝보다 0.352 / 0.244ms 앞섰지만 다음 1,216은 5.681 / 5.529ms 늦었다. 첫 VBlank의 448B DMA에 후속 범위를 합칠 수 있는지, 해당 행·BG slot 확정부터 ARM 발행까지 추적한다. 두 번째 VBlank에 남을 DMA와 SEAL 독립 검사 시간을 함께 예산에 넣고, 960·909의 추가 표시 대기도 대조한다. 중간 성 162선 dot 0 프리즈는 별도 과제로 남는다.
