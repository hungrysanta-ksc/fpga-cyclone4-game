## 목표

MMC763을 실기 기준으로 유지하고, 동일한 작업량에서 직전 표시 ACK부터 SEAL 수락까지 지연이 어디서 생기는지 찾는다.

## 작업내용

PR159의 969 재생을 두 시작 위상에서 다시 분석했다. 마지막 32 B OBJ의 세대·token·목적지·길이를 E8 응답과 E1 패킷에서 맞추고 65816의 수락, SEAL 발행·수락·최종 ACK를 연결했다. 두 판의 map 및 최종 RGB 해시가 같다. 시간은 연속 ARM·65816 재생 모델의 ms다.

| 구간 | 위상 1 MMC763 / 767 | 위상 2 MMC763 / 767 |
|---|---:|---:|
| 968 최종 ACK → 마지막 OBJ를 처음 관측한 E8 응답 완료 | 30.867 / 34.689 | 31.389 / 34.803 |
| 해당 E8 응답 → OBJ 발행 | 0.051 / 0.049 | 0.049 / 0.049 |

### 776의 뱅크 준비와 E8 조회

첫 레벨 재생 969는 map 변경 8그룹, OBJ 범위 126, BG 범위 147이었다. 마지막 네 건은 BG 16B(token 158), OBJ 32B(159), OBJ 64B(160), OBJ 32B(161)였다. 수락된 패킷을 원래 시각에 다시 넣어 두 판·두 위상에서 65816의 토큰 쓰기와 0x6050 소비 명령을 기록했다. 각 66화면의 전체 소비 이벤트와 RGB를 원본과 대조했다. 마지막 OBJ의 네 CHR 읽기는 모두 OBJ 캐시에 적중했다.

707D 보드 소스의 staging·토큰 소비·E8 회로 6개 파일을 핀으로 고정했다. 969의 실제 payload와 65816 소비 시각, ARM의 E8 조회 시작을 넣어 슬롯 8의 쓰기 완료, 최종 descriptor가 reader에 보이는 시각, SPI 응답의 CRC·세대·token·주소·길이를 확인했다. 회로 시험 입력은 완성 타일 인터페이스에서 시작한다. ROM·캐시 공급 시각과 SPI 발행은 기존 연속 재생 모델이고, 이 수치는 실기 프로브 측정값이 아니다.

아래는 968 최종 ACK 뒤 경과 시간(ms)이다. 두 쌍 모두 왼쪽 MMC763, 오른쪽 MMC767이다.

| 969 경계 | 위상 1 | 위상 2 |
|---|---:|---:|
| 마지막 OBJ의 마지막 CHR 응답 | 25.015 / 23.985 | 25.046 / 23.666 |
| token 161을 FPGA staging 뱅크에 봉인 | 27.047 / 26.028 | 27.077 / 25.615 |
| ARM이 앞선 token 160의 E8 조회를 시작 | 28.853 / 32.940 | 28.879 / 33.051 |
| token 160을 65816이 반환해 161이 reader에 노출 | 30.427 / 34.003 | 30.458 / 34.165 |
| ARM이 token 161을 확인한 첫 E8 조회 시작 | 30.758 / 34.580 | 31.280 / 34.693 |
| ARM이 token 161을 확인한 E8 응답 완료 | 30.867 / 34.689 | 31.389 / 34.803 |

MMC767의 마지막 뱅크는 1.019 / 1.461ms 일찍 봉인됐다. 봉인 후 앞선 64B OBJ 반환을 기다리는 시간은 4.595 / 5.169ms 늘었다. reader 공개 뒤 E8 응답 완료까지의 차이는 +0.245 / −0.294ms였다. 세 항목의 합이 +3.822 / +3.413ms다. 65816의 선행 토큰 소비 자극부터 reader 갱신까지 RTL에서 116–125ns가 걸렸다. 두 뱅크가 동시에 봉인된 순간의 STOP은 즉시 공개를 차단했고, 재시작 후 옛 token과 END는 남지 않았다.

MMC767에서는 마지막 map 발행 뒤 ARM이 빈 큐의 실제 DMA 진행을 E0로 확인한 시각이 32.804 / 32.915ms였다. 그 뒤에야 앞선 token 160을 조회하고 E1으로 발행했다. 같은 구간의 map·tile 선행 DMA 496B는 순서대로 192+16+192+32+64B였다. 두 위상 모두 첫 전송은 227선이었다. 당시 순서에서는 920B의 E1 거래가 남아 순수 SPI만 2.804ms였다. 227선의 시작부터 해당 프레임 끝까지 전부 써도 2.223ms다. ARM·검사·DMA 비용을 넣기 전부터 0.581ms 부족하므로, 마지막 조회만 앞당겨 같은 VBlank에 표시할 수 없다.

### 발행 후보

- 776A는 map 뒤에 대기 플래그를 세우고 확정 ordinary 준비와 기존 E8 조회를 먼저 수행한다. 처음 본 descriptor는 독립 검사 후 스택에 보유하며, 기존 map 진행 대기를 거친 뒤 E1을 보낸다.
- 776B는 기존 map 대기와 발행 순서를 유지한다. OAM 뒤에 앞선 OBJ receipt를 확인한 경우, 같은 횟수 한도에서 다음 STOP 검사와 E8 조회로 직행한다. 잘못된 CRC·같은 token에 다른 내용·STOP·반복 token 횟수 소진에서 새 E1 발행은 0건이었다.
- 별도로 MMC767의 원래 ELF에서 969의 해당 반환 직후 한 번만 같은 분기를 실행해, 부팅부터 쌓인 위상 변화를 분리한다. 이 분리 시험의 시간은 실제 링크 후보의 시간과 구분한다.

## 성과

두 위상 모두 969의 496B 선행 DMA가 유지되는 조건에서는 E8 조회를 당겨도 해당 화면의 최종 ACK와 3 VBlank 표시 간격이 그대로였다. 968까지 같은 실행을 유지한 뒤 969에서만 반환 직후 조회한 경우, 마지막 OBJ의 E8 시작은 양쪽에서 0.130ms 빨라졌다. 970 ACK는 각각 1,850 / 352 masterclock 빨라졌다.

ACK 차이의 기준은 각 위상의 MMC767이며 음수는 더 이른 시각이다. 선행 바이트는 969의 출력 진입부터 SEAL 수락까지 실제 PPU DMA로 전송한 양이다. 부팅부터 바꾼 후보의 ACK 시각에는 이전 세대에서 누적된 차이가 포함된다. 모든 행에서 969는 3 VBlank였고, 각 위상의 66화면에 대해 map·예상 출력·최종 RGB가 같았다. 969 작업량은 실기 25–30초와 가까운 재생 표본이다.

776A의 ARM Flash는 213,056B로 64B 초과했고 BSS가 4B 늘었다. 776B는 212,992B로 한도에 맞으며 BSS는 MMC767과 같다. 두 후보 모두 ARM의 152개 receipt 비트 손상·STOP·최종 ACK·메뉴 복구 검사와 65816의 독립 출력 검사를 통과했다. 776B는 위상 2에서 64B의 선행 DMA를 잃고 밀집 간격이 2.266µs 늘어 실기 펌웨어는 MMC763을 유지한다.

## 후속작업

969에서 첫 DMA가 시작된 227선보다 먼저 확정된 OAM·scroll·240B 테이블의 준비·E1 발행·65816 수락을 대조한다. 같은 VBlank에 표시하려면 기존 순서에서 920B 중 최소 191B 상당의 SPI 점유를 앞당겨야 한다. 이 하한은 드라이버·수락·검사·표시 마감 비용을 제외하므로, 실제로 수락 가능한 바이트와 남은 시간을 먼저 계산한다. 큐와 staging 뱅크의 소유권을 지키면서 두 위상의 496B DMA, 952–957 표시 간격, 969·970 최종 ACK로 판단한다. 중간 성 162선 dot 0 프리즈는 별도 재현 과제로 유지한다.
