## 목표

MMC524의 수락된 map을 64B 단위로 선행 전송하고, 952·954의 최종 표시가 실제로 한 VBlank 빨라지는지 두 시작 위상에서 검증한다.

## 작업내용

- PR143 병합 `ddaa251`을 원격 master에서 확인하고 분기했다. 65816의 비활성 map 명령에 64B 부분 소비와 tail 제거를 연결했다. DMA 완료 전까지 주소·길이를 보존하고 독립 수신 비트맵과 최종 ACK를 유지했다.
- 기존 232번 제한과 map만 254번까지 허용한 후보를 MMC524와 같은 ARM·SPI·IRQ·2슬롯·ROM 일정에서 각각 53화면씩 비교했다. 양 뱅크의 STOP·head 경합, 중복 행, 누락 참조, cold 복구, 빈 목록에서의 연속 행 재등록과 늦은 주사선 경계를 검증했다.
- 527에서 같은 254 소비기에 ARM 두 후보를 연결했다. 첫 OBJ plan 제출 뒤와 첫 map 행 확정 시점을 각각 시험하고, 동일 클록 패킷 재생·조기 발행 뒤 실패 주입으로 소비·취소를 검증했다.
- 528은 END를 기다리는 기존 E8 조회에서 bulk·E9가 모두 대기할 때 후속 map을 공급했다. 실제 빔 래치와 명령별 PPU DMA 주소·마지막 쓰기를 기록해 대기 원인을 분리했다.
- MMC529는 옛 진단 로더의 강제 링크를 해제하고 메뉴·ROM·FPGA·로그 이름을 교체했다. 새 바이너리로 양 위상의 연속 일정, STOP·VBlank·오류 복구, 표시 카운터 구간을 검증했다.

## 성과

- 254 후보에서 952는 256B/256B, 954는 192B/256B를 먼저 썼다. 두 위상 모두 두 화면의 SEAL 대기 2회와 최종 표시 대기 1회가 유지됐다. 954의 표시 간격은 첫 위상 8→7 VBlank, 둘째 7→8 VBlank였다.
- 밀집 평균은 첫 위상 126.457→123.129ms, 둘째 123.130→126.462ms였다. 마지막 ACK는 각각 0.012ms와 83.174ms 늦었다. 두 후보 모두 전체 보드 15,164 LE·51 M9K, 관련 setup +0.078ns·hold +0.139ns였다. [측정 결과](../nes-map526-results.ko.md)
- 527 행 확정 후보는 952에서 첫 map을 52.3–52.6ms, 954에서 39.1–39.5ms 앞당겼다. 최종 대기는 여전히 1회였다. MMC524 대비 밀집 평균은 126.457→123.129ms 및 123.130→122.856ms, 마지막 ACK는 33.284ms 및 0.023ms 빨라졌다. MCU Flash는 388B 초과다. [ARM 발행·소비·비용](../nes-map527-results.ko.md)
- 528에서 밀집 구간은 113.142/113.150ms, 957 ACK는 527보다 66.549/66.541ms 빨라졌다. 952·954의 표시 간격은 각각 8·7 VBlank로 줄었으나 최종 대기 1회는 유지됐다. Flash는 500B 초과다. [검증 결과](../nes-quiet528-results.ko.md)
- MCU Flash는 213,492→212,248B로 744B의 여유가 생겼다. 528과 모든 표시 ACK 시각과 53개 RGB가 일치했다. 952·954는 각각 8·7 VBlank로 유지됐다. [529 검증·패키지](../nes-flash529-results.ko.md)

## 후속작업

MMC529로 MMC524와 같은 첫 레벨 동선을 플레이하고, 실행·메뉴 복귀 및 1–40초·40–60초 표시율을 세 로그로 비교한다. [실기 시험 순서](../nes-mmc529-trial.ko.md)
