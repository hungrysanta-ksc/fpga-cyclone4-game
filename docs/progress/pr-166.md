# MMC826 데모의 출력과 최종 ACK

## 목표

PR165 머지 커밋 `a6af7af`에서 시작했다. 모험도 4 무입력 실기 기준은 MMC826의 1–30초 17.52 FPS, 30–60초 16.13 FPS다. 후반 출력·최종 ACK 43.27ms 중 다음 표시 마감을 넘기는 원인을 찾는다.

## 작업내용

30–60초의 실기 비용은 프레임 시작 기준 버킷 483건, 평균 43.271ms다. 표시 완료 카운터는 같은 구간에서 484건이다. 이 로그에는 개별 세대의 DMA 시각이 없다. ROM 원본의 약 43초 지점에서 같은 map 1,472B를 보내고 OBJ가 각각 832B·704B인 2576·2580을 골랐다. 같은 원본 여섯 화면씩을 이어서 부팅하고 두 위상에서 MMC826의 SPI 명령별 실측 평균, Cortex-M4 명령당 2클록, 기존 ROM 허가 일정·캐시 응답과 실제 815R 65816 프로그램으로 재생했다.

링크된 ARM의 단계 카운터 시작값과 종료 시각을 읽어 SPI 거래, 큐 head 수락, PPU DMA 시작·마지막 바이트, VBlank 대기 진입·복귀, 화면 공개, 최종 ACK와 맞췄다. SPI 열은 출력 단계 시작부터 SEAL 전송 종료까지이며 E1 외에도 진행 조회와 겹친 입력 거래를 포함한다. 그 사이 ARM 실행·거래 사이 간격은 별도다. SEAL 수락 이전의 선행 DMA는 송신·준비와 겹치므로 중복 합산하지 않는다.

## 성과

두 위상의 MMC826 대조군 재생값이다. 단위는 ms이며 각 열은 같은 시계의 경과 시간이다.

| SEAL 발행까지 SPI 거래 | 10.94 / 10.83 | 14.28 / 14.13 |
| 같은 구간의 ARM 작업·거래 사이 간격 | 5.85 / 5.73 | 7.95 / 8.06 |
| SEAL 전송 종료 → 65816 수락 | 0.19 / 0.24 | 0.36 / 0.19 |

| 수락 뒤 DMA 시작 → 마지막 바이트 | 0.82 / 0.82 | 0.72 / 0.72 |

2576의 SEAL은 261선·257선에 수락됐다. 검사를 마치고 VBlank를 기다리기 시작한 시각은 다음 주사의 34선·30선이었다. 2580은 양 위상 모두 154선에 수락돼 다음 VBlank까지의 대기가 짧았다. 후반 두 장면의 잔여 DMA 자체는 1ms 미만이었다. 2572에서는 65816의 ACK 뒤 ARM 단계 종료까지 약 13ms가 걸렸고 그 사이 다음 입력의 D1·D2·D0가 수행됐다. 출력 단계 시간에는 이처럼 다음 화면에 사용되는 처리도 포함된다.

### 발행 순서와 진행 조회 대조

2580에서 SEAL 전 SPI 중 E0 진행·credit 조회는 7.62 / 7.40ms, E1 출력 데이터는 양 위상 모두 5.20ms였다. END와 독립 검사를 지키고 팔레트 발행 앞의 선택적 DMA 진행 대기만 제거했다. 마지막 OBJ 반환부터 SEAL 수락까지 E0는 47→21 / 44→22회, 경과 시간은 15.27→12.13 / 15.05→12.13ms가 됐다. 그런데 마지막 ACK는 0.114 / 0.105ms 늦었다. 폴링이 줄인 시간을 곧바로 표시 이득으로 환산할 수 없는 직접 대조다.

스크롤·패딩을 긴 map 앞 또는 뒤에 바로 발행한 판, OBJ 묶음의 분할 위치를 바꾼 판, section 5를 팔레트·OAM보다 먼저 보낸 판, 스크롤 채움만 OBJ에 겹친 판, OBJ 공급 후 map을 발행한 판도 각각 따로 링크했다. 같은 사진 여섯 장과 양쪽 시작 시각을 고정했다. 후보는 화면 번호를 참조하지 않고 map·OBJ·credit 상태로 발행 순서를 정한다. OBJ 뒤까지 map을 미룬 판은 213,036B로 Flash 한도도 44B 넘었다.

map 앞 768B 이후에 OBJ 생산을 허용한 판에서는 2576의 일반 출력 이전 DMA가 대상 1,280B 중 576B로 줄었다. 이를 피해 `inherited`에서는 BG 계산을 끝낸 뒤 현재 map이 직전 표시와 같고 반대쪽 뱅크에 긴 갱신이 남아 있을 때만 분할한다. 나머지 map은 실제 큐·타일 진행을 확인하는 기존 발행 경로로 보낸다. 2576·2580 모두 대상 1,280B 선행 DMA를 보존했다. ARM Flash는 212,960B로 32B 여유다. FPGA·65816은 MMC826과 같은 이미지다.

공개와 마지막 ACK의 이득은 0.063 / 0.090ms였다. 긴 map 뒷부분 발행을 ARM 출력 단계 안으로 옮겨 해당 단계 자체는 길어졌다. 2576은 두 위상 모두 5 VBlank이고, 712를 포함하는 오프닝 표본에서 네 표시 간격과 마지막 ACK는 MMC826과 클록까지 같았다. 이 변경의 실기 FPS는 미측정이다.

### 828 실험에서 확인한 map 전송량과 65816 비용

데모 2576·2580의 오른쪽 map 페이지는 각각 23행이었다. ARM은 기존 동일 단어 반복 형식을 먼저 검사하고, 남은 DATA 패킷에서 각 행 끝 46바이트를 모두 검사한다. 한 바이트라도 0이 아니면 해당 패킷을 그대로 보낸다. 압축할 수 있으면 opcode 9·section 2에 행당 18바이트를 담는다. 두 화면 모두 8패킷·1,472B가 8패킷·414B가 됐다. SPI 2.625MHz에서 화면당 순수 전송 시간이 3.224ms 줄어든다.

65816은 큐가 제공하는 실제 길이, 세대·순번, section, 18/36/54B 길이, 64B 행 정렬, 목적지 범위와 coverage를 확인한다. 각 행의 앞 18B를 복사하고 나머지 46B를 0으로 쓴 뒤, 목적지 앞부분을 패킷과 대조하고 뒷부분의 23단어가 모두 0인지 읽어 확인한다. 64B마다 STOP을 검사한 뒤 원래의 패킷 ACK·SEAL·VBlank 표시를 진행한다. 기존 OAM 재사용 명령은 같은 opcode의 section 4로 구분한다.

| 약 43초 데모의 네 표시 간격 | MMC826 위상 1 / 2 | 828 오른쪽 페이지만 압축, 위상 1 / 2 |
|---|---:|---:|
| 화면별 VBlank | 4·3·5·4 / 4·3·5·4 | 4·4·4·6 / 4·5·5·4 |
| 공개 간격 합 | 266.352 / 266.150ms | 299.532 / 299.447ms |
| 2580 최종 ACK, 마스터클록 | 18,923,066 / 18,923,186 | 19,635,970 / 19,638,096 |
| 2576의 map 8패킷 수락부터 개별 ACK까지의 합 | 4.565 / 4.621ms | 12.789 / 12.815ms |
| 2580의 같은 구간 | 4.467 / 4.462ms | 12.816 / 12.762ms |

처음 구현한 단어 루프에서는 네 간격이 두 위상 모두 20 VBlank였다. 18B 블록 복사와 네 단어 단위 0 쓰기·검사로 18 VBlank까지 줄었다. 오른쪽만 갱신하는 프레임에 압축을 제한해 cold와 장면 전환의 혼합 페이지를 원래 형식으로 보낸 판도 18 VBlank였다. 이 판의 복원·독립 재읽기·행별 STOP 확인만 8.915–8.981ms였다. SPI와 소비가 겹치므로 두 시간을 단순 가감해 표시 시각으로 쓰지 않는다. 최종 ACK는 MMC826보다 각각 33.193 / 33.287ms 늦었다.

부팅과 디코더 추가 자체가 끼치는 영향도 분리했다. MMC826 송신기를 새 ROM에 연결하면 두 위상 모두 4·3·5·4 VBlank였고 마지막 ACK 차이는 +120/+398클록(0.006/0.019ms)이었다. 오른쪽 페이지만 압축한 판의 오프닝 표본은 두 위상 모두 원본과 같은 4·4·3·4 VBlank, 오프닝→데모 전환은 8·8·4·3 VBlank였다. 모든 표본의 각 공개 RGB를 원본과 바이트 단위로 대조했다. 이는 무입력 데모에서 선택한 연속 표본의 결과이며 60초 전체 실기 FPS는 MMC826 기록을 유지한다.

ARM Flash는 MMC826 212,944B, 전체 오른쪽 패킷 압축판 212,752B, 오른쪽만 갱신할 때 압축하는 판 212,768B였다(한도 212,992B). BSS는 모두 19,548B였다. 사후 로그의 형식 문자열을 기존 사전에 통합했고, 성공·실패 보고와 크기 제한 결과를 원본과 바이트별로 대조했다. 성공 로그 작성 시 관측 stack이 7,736→7,840B로 증가했다. 최종 65816 프로그램은 6,220B로 풀리며 5,120B ROM 안에 저장한 뒤 27B가 남는다. 기존 FPGA 큐·staging 모델과 보드 인터페이스를 사용한 실험으로, 새 ROM의 보드 FIT·실기 FPS는 측정하지 않았다.

시험 중 압축 목적지를 매번 0xA5로 채운 뒤 실제 WRAM·VRAM과 최종 RGB를 대조했다. 3행 패킷의 첫 행에서 WRAM 끝 바이트를 바꾸면 0xE0, STOP을 걸면 0xE4로 거부하며 이전 공개 화면이 유지됐다. 부분 전송 시점 두 뱅크의 map을 보존해 cold 재부팅 대조에 사용했다. [장면·위상별 시간, 바이너리 해시와 복구 결과](../../analysis/map828-results.json)

### 829 FPGA에서 행 끝을 공급한 결과

MMC826의 815R 65816 ROM을 그대로 사용했다. ARM은 오른쪽 페이지만 갱신할 때 행당 18B를 보낸다. FPGA는 원래 4슬롯 패킷 RAM에 저장하면서 행 끝의 46주소를 건너뛰고, 65816이 읽을 때 원래 DATA 헤더와 64B 행을 제공한다. 2576·2580 각각 map 데이터 1,472B 중 SPI로 보낸 양은 414B다. VRAM에 쓰는 양은 그대로다.

SPI CRC는 실제 수신 바이트를 검사한다. 별도 읽기 커서는 카트리지 버스가 데이터를 구동한 마지막 읽기 박자를 확인하고, 헤더 첫 주소부터 마지막 데이터까지 중복·누락·초과를 검사한다. 패킷 반환 시에는 원본 헤더와 ACK identity까지 대조한다. 저장 credit과 최종 표시 ACK는 기존 순서대로 반환한다. 이 검사의 관측 지점은 카트리지 읽기 포트다. 이후 WRAM·VRAM과 최종 RGB는 원래 65816 재생에서 별도로 대조했다.

| MMC826 | 4·3·5·4 | 4·3·5·4 | 기준 |
| FPGA 복원, 원래 발행 순서 | 4·3·5·4 | 4·4·4·5 | +0.023 / +16.550ms |
| 기존 페이지 이력 조건에서 768B 뒤 OBJ에 공급 기회 | 4·3·5·4 | 4·4·4·4 | −0.084 / −0.067ms |
| 긴 오른쪽 map에서 384B 뒤 OBJ에 공급 기회 | 4·3·6·4 | 4·4·5·4 | +16.571 / +16.560ms |

기존 이력 조건을 쓴 768B 일정의 네 공개 간격 합은 266.267 / 266.101ms였다. 위상 1의 2576은 SEAL을 VBlank 47의 224선에서 수락했지만 1,472B map DMA가 247선에 시작했고 공개는 원본과 같은 VBlank 49였다. 위상 2의 2576 간격이 5→4로 줄어든 것은 직전 2572 공개가 VBlank 44→45로 밀렸기 때문이다. 2576 자체 공개는 VBlank 49로 같고 2580도 양 위상 모두 VBlank 53이다.

Questa에서 실제 SPI 수신, SNES 읽기와 ACK 쓰기로 압축 패킷 256건을 재생했다. CRC·길이·잘못된 identity, 중복·건너뛰기·마지막 바이트 초과, 부분 읽기 뒤 ACK, SEAL이 뒤에 대기한 상태 및 STOP 이후 재개를 검사했다. ROM 클록 허가 일정과 SPI 비용을 사용하는 전체 재생은 RTL에서 확인한 바이트를 실제 ARM·65816에 공급한다. 이 수치는 연속 여섯 화면 표본에서 측정했다. [최종 보드·보호 검사·위상별 계측값](../../analysis/map829-results.json)

같은 EP4CE15·Lite 25.1 전체 보드에서 MMC826은 15,278 LE, 962/963 LAB, 56/56 M9K이며 최악 setup은 +0.497ns다. 압축 포트가 기존 큐에 실제로 들어간 중간판은 15,375 LE, 963 LAB로 FIT했고 전체 STA에서 setup −0.269ns가 남았다. 168MHz 해제 신호에서 84MHz 큐 길이 갱신까지의 경로였다. 잘못 정렬된 행까지 거부하는 최종판은 길이를 빈 슬롯에 선기록하고 CRC·STOP 확인 뒤에만 공개한다. 이 판은 15,293 LE, 56 M9K, **964/963 LAB**로 FIT에 실패해 라우팅 후 STA가 없다. 기존 이력 조건의 ARM 전체 링크는 212,784/212,992B, BSS 19,548B였다. 원래 65816과 같은 바이너리로 오프닝과 장면 전환의 각 여섯 화면, 부분 WRAM cold 복구, ARM 메뉴·base 복구 경로를 대조했다.

### 830 마지막 map 반환과 2576 표시 마감

MMC826의 최종 ARM과 815R 65816을 여섯 화면 연속으로 부팅·재생했다. 동일 코드 재링크 대조군에서도 두 위상의 2572 공개와 2580 최종 ACK가 원본과 클록까지 일치했다. 2576의 마지막 map은 양 위상 모두 VBlank 46의 207선에 반환됐다. 1,472B 단일 DMA는 VBlank 47의 227선에서 시작해 235선 / 236선에 끝났다. 당기려는 공개는 VBlank 49에서 48로의 이동이다. map은 이미 그보다 먼저 끝났다.

실제 발행 변경 중 raw·테이블 3패킷 판은 map 반환을 앞당겼으나 ARM이 E0에서 해당 반환을 처음 본 시각은 0.012 / 0.103ms 늦어졌다. SEAL 수락은 양 위상 222선까지 당겼지만 기존 65816이 독립 검사를 마치고 업로드 경로에 들어간 시각은 249선이었다. 수락부터 이 지점까지 1.717 / 1.715ms가 걸렸다. 팔레트 512B와 OAM 544B는 VBlank 49에 실행됐다. 2572 자체가 한 VBlank 늦어진 후보는 2576 표시 간격만 짧아져도 채택하지 않았다.

선로 시간 대조는 같은 MMC826 바이너리에서 1,472B의 데이터 비트 시간 4.486ms만 제거한다. 큐·헤더·반환과 실제 65816에 전달한 map 바이트는 그대로 검사한다. 양 위상 모두 2572 공개가 동일했고 ARM의 반환 확인도 약 3ms 앞당겨졌지만, 수락된 패킷 사이에서 큐가 비는 시각이 달라져 단일 map DMA 시작은 VBlank 47의 243선이었다. VBlank 48에 끝난 후속 tile은 각각 144B / 304B였고 팔레트·OAM은 여전히 VBlank 49에 남았다. 모든 판정은 SPI 실측 비용과 ROM 허가·IRQ 일정을 사용한 연속 재생 결과다.

완주한 각 후보에서 여섯 화면의 RGB, 여섯 최종 ACK, 2576 map 원본 1,472바이트의 주소·내용·중복 여부를 대조했다. 240B씩 자른 map 패킷은 두 위상 모두 기존 수신기가 0xE0로 거부했다. 전체 map 선행 발행판과 scroll·패딩 결합판에서 마지막 map 발행 뒤 STOP, 잘못된 반환 identity, 잘못된 CRC를 각각 주입해 SEAL 발행 전에 중단하는 것을 확인했다. 두 ARM 링크로 메뉴 해제와 base 복원도 확인했다. ### 831 마지막 OBJ 반환 이후와 SEAL 내부 검사

MMC826의 2576에서 마지막 OBJ 반환→SEAL 수락은 위상 1 / 2에서 6.607 / 6.463ms, 수락→업로드 진입은 1.778 / 1.771ms였다. 앞에서 측정한 1.72ms는 830의 raw·테이블 3패킷 결합판 수치다. 65816은 SEAL에 필요한 타일 비트가 있는 단어만 독립된 대상 뱅크의 수신 비트와 대조하도록 바꿨다. HDMA 세 표는 같은 행의 카운트·모드·값을 뱅크 내부 인덱스로 읽는다. 기존 종료 표식, 합계, 길이, 범위와 STOP 검사는 계속 실행한다.

ARM은 map 발행 직후 bulk 소유권을 다시 확인해 scroll·패딩을 먼저 발행했다. 동일 ARM에 원래 65816과 새 검사기를 각각 연결했다. 표의 마지막 열에서 양수는 MMC826보다 늦은 ACK다.

scroll·패딩 선행과 새 검사기를 결합했을 때 VBlank 48의 243 / 245선에 업로드에 진입했다. 그 VBlank에서 마친 tile DMA는 304 / 144B였다. 팔레트 512B는 VBlank 49의 243 / 244선, OAM 544B는 247 / 248선에 완료됐다. 두 위상 모두 2576은 VBlank 49, 2580은 VBlank 53에 공개됐다.

고정 시각 대조는 실제 MMC826 바이너리로 2572의 최종 ACK까지 실행하고 그 시점에 Mesen의 실행 WRAM에서 바뀐 명령만 교체한다. 큐·비디오 상태와 시계는 이어서 사용한다. 정적 ROM 부팅과 별도 계측이며 독립 검사를 실행한 채 앞 화면의 위상 효과를 제거한다. 56B SEAL은 가운데 필수 비트 112바이트가 모두 0일 때 양 끝 16바이트씩을 보낸다. 전 여섯 화면에서 이를 펼친 168바이트 전체와 RGB를 MMC826과 직접 대조했다. 짧은 형식으로 줄인 시간이 앞 화면의 한 VBlank 지연을 상쇄하지 못했다.

첫 raw 패킷과 후속 두 패킷 사이에 OAM을 넣으면 SEAL을 208 / 211선에 수락하고 231 / 233선에 업로드에 진입했다. VBlank 48에 끝난 tile은 848 / 592B였다. 팔레트·OAM은 VBlank 49에 남았고 2580 공개는 VBlank 54로 한 번 더 늦었다. MMC826은 2580의 map 768B와 704B를 VBlank 51·52에 나눠 전송했지만 이 후보는 1,472B 전체를 VBlank 53에 보냈다. 이 ARM은 Flash 한도보다 8B 크다. 마지막 raw 뒤에 OAM을 보낸 대조는 한도 안에 들었고 네 간격 합은 16 / 16이었다. 짧은 SEAL과 첫 raw 뒤 OAM 발행까지 결합한 판은 2576의 두 소구간을 2.56–2.62ms와 1.23–1.27ms까지 줄였다. 패딩 이력 유무와 위상에 따라 네 간격은 17–18 VBlank, 2580 ACK는 15.86–32.51ms 늦었다. ARM은 213,036B로 한도보다 44B 크다.

두 검사기에서 실제 대상 뱅크의 필수 비트와 두 번째 HDMA 표를 각각 손상시키면 0xE0, STOP에는 0xE4를 반환했다. 56B 형식에서 뒤쪽 OBJ 필수 비트를 지우거나 수락 길이를 54로 바꿔도 0xE0였다. 모든 주입에서 직전 네 번째 화면의 표시 identity가 유지됐다. 최종 ARM들의 메뉴 해제와 base 복원은 실제 ARM 코드를 실행하고 보드 I/O를 모델링해 확인했다. [두 위상별 수락·DMA 완료선·최종 ACK와 보호 검사](../../analysis/seal831-results.json)

### 832 마지막 OBJ 생산 중 section 5 발행

실제 ARM에서 확정된 scroll·raw·HDMA 테이블을 기존 큐로 발행했다. 2572의 공개 클록은 위상 1에서 15,709,676, 위상 2에서 15,709,784다. 앞선 네 화면과 ACK를 그대로 실행한 뒤 ARM의 출력 함수 호출 대상만 바꾸는 대조를 정적 부팅과 따로 실행했다. 원본 함수를 같은 방식으로 다시 링크하면 마지막 ACK까지 원본과 클록이 일치했다. 아래 시간은 모험도 4 여섯 화면의 연속 재생에서 얻었다. ROM 허가와 SPI 시각에는 MMC826 실측 명령 평균을 적용한 모델을 썼다.

|---|---:|---:|---|---:|---:|
| MMC826 | 0 / 0 B | 49 / 49 | 두 위상 모두 768B@51 + 704B@52 | 16 / 16 | 0 / 0 |
| 240B 첫 묶음을 팔레트 사이에 발행 | 0 / 0 B | 49 / 49 | 두 위상 모두 분할 유지 | 16 / 16 | +470 / −120 |
| 세 묶음을 연속 발행하고 831의 검사·복원 단축 적용 | 144 / 304 B | 49 / 49 | 두 위상 모두 분할 유지 | 16 / 16 | +20 / −100 |

연속 발행 후보는 raw 384B와 테이블·길이 249B를 기존 scratch에 모아 240·240·153B로 전송했다. 첫 240B 전송과 마지막 OBJ의 생산 구간이 11,789 / 11,114클록 겹쳤다. 개별 CHR 읽기와 확실하게 겹친 payload 구간은 양쪽 모두 320클록(약 0.015ms)이었다. 중간 대기 전체를 ROM 읽기 절감으로 계산하지 않았다.

패킷은 줄었지만 2576 section 5의 E1 선로 사용량은 459→757B가 됐다. 반복 raw를 일반 데이터에 합치자 PPU가 보낸 raw CHR도 64B씩 3회에서 6회로 늘었다. bulk tile은 원래와 같은 BG 16B·OBJ 832B였다. 831 단축과 결합해도 마지막 OBJ 반환→SEAL 수락은 6.989 / 5.806ms, 수락→업로드 진입은 1.470 / 1.464ms였다. 팔레트 512B와 OAM 544B의 마지막 바이트가 VBlank 49에 남았다. 원래 반복 압축을 유지한 대조는 E1 459B와 raw DMA 192B를 회복했고, 기본 65816에서 OBJ 반환→SEAL은 9.269 / 9.192ms로 늘었다.

완료한 후보는 원본 여섯 화면의 RGB·SEAL과 2576 section 5의 모든 바이트를 대조했다. 테이블 offset 1,505를 앞 범위보다 먼저 보낸 세 후보는 두 위상 모두 65816이 0xE0으로 거부했다. 손상된 HDMA 테이블과 누락된 coverage는 0xE0, STOP은 0xE4로 중단했고 직전 네 화면까지의 표시 이력을 보존했다. ARM의 STOP·CRC·반환 identity 주입과 메뉴 해제·base 복귀도 별도로 확인했다. 이번 후보는 실기 전달 대상으로 선정하지 않았다. [클록·DMA·보호 검사 결과](../../analysis/section832-results.json)

### 833 반복 raw 다섯 범위의 단일 패킷

MMC826 ARM에서 section 5의 384B가 128·64·64·64·64B 범위별로 한 단어의 반복인지 전부 검사한다. 일치하면 다섯 단어를 10B payload로 발행하고, 다른 길이 또는 다른 값은 기존 발행 함수를 사용한다. 65816은 명령·section·offset·길이·예약 필드와 기존 뱅크·순서를 확인한다. 목적지 WRAM을 64B마다 다시 읽어 수신 단어와 대조하고 STOP을 확인한 뒤에만 묶음 ACK를 돌려준다. 원본 여섯 화면의 RGB와 SEAL이 일치했다. 2576의 section 5를 재구성한 1,754B가 모두 같았고, 실제 raw CHR DMA는 VRAM 단어 주소 0x5000·0x5002·0x5020에서 각 64B였다.

2572 공개와 ACK를 MMC826 클록에 고정한 대조다. 각 칸은 위상 1 / 2이며, 마지막 열은 2580 최종 ACK가 기준보다 늦은 시간이다.

|---|---:|---:|---:|---:|---:|
| MMC826 | 5개·105B | 14 / 14 | 39 / 40 | 16 / 16 | 기준 |
| 기존 순서에서 묶음 | 1개·29B | 6 / 5 | 49 / 49 | 16 / 16 | +0.9 / 0.0µs |
| 팔레트 128B 직후 section 5 발행 | 1개·29B | 3 / 3 | 54 / 54 | 16 / 16 | +17.2 / +20.9µs |

세 경우 모두 2580의 map은 VBlank 51에 768B, 52에 704B가 전송됐다. 기존 순서에서 묶으면 raw 패킷 수락→반환의 합은 64,810 / 65,040에서 48,628 / 48,682 master clock으로 줄었다. 마지막 OBJ 반환→SEAL 수락도 6.607 / 6.463ms에서 5.567 / 5.577ms로 줄었다. 그러나 SEAL이 VBlank 48의 244 / 243선에 도착해 독립 검사 뒤 업로드에 진입한 때는 이미 다음 활성 화면 9 / 8선이었다. 2576 팔레트 512B·OAM 544B의 마지막 바이트는 VBlank 49에 기록됐다.

MMC826 보드의 SPI·큐 RTL에 두 위상의 실제 묶음 12개를 보냈다. 각 head의 26B를 읽고 ACK identity 전체를 검사해 E0에 정확히 한 번씩 credit이 반환됨을 확인했다. WRAM 손상·잘못된 offset·길이·예약 필드는 0xE0, 복원 중 STOP은 0xE4로 거부했고 해당 화면 공개는 없었다. ARM 메뉴 해제·base 복귀 검사는 팔레트 128B 뒤 발행하는 전체 링크에서 통과했다. 이 링크의 Flash는 212,792 / 212,992B, 65816 물리 ROM은 5,120B 중 82B 여유다. 고정 시각 비교와 부팅부터 실행한 정적 링크의 결과를 구분해 보관했다. ### 834 마지막 OBJ 반환부터 SEAL 수락까지의 큐·수신기 추적

두 위상에서 실제 ARM이 `through`에 넘긴 반환 번호와 매 E0의 송신·반환 카운터를 기록했다. 같은 클록의 65816 패킷 수락·반환 및 PPU 쓰기와 대조했다. 833의 기존 순서에서 2576의 팔레트는 마지막 OBJ보다 먼저 수락·반환됐다. OAM 마지막 32B도 이미 발행된 상태였고, OBJ 직후 약 0.47ms 만에 반환됐다.

| 2576 마지막 OBJ 반환 → SEAL 수락 | 위상 1 | 위상 2 |
|---|---:|---:|
| MMC826 | 6.607ms | 6.463ms |
| 833 원래 발행 순서 | 5.567ms | 5.577ms |
| 그중 65816이 기존 head를 처리한 시간 | 5.169ms | 5.182ms |
| 그중 패딩 및 384B raw 처리 | 3.761ms | 3.770ms |
| ARM의 SEAL 전송이 끝난 뒤 65816이 수락하기까지 | 2.158ms | 2.254ms |

마지막 두 행은 서로 겹친다. 위상 1에서 ARM은 164번 OBJ의 반환을 확인한 뒤, 165~167번 반환을 확인하며 일반 패킷을 보냈다. 마지막 SEAL은 171번이다. 171번을 기다리는 동안 168번 raw와 169·170번 테이블이 순서대로 처리됐다. 위상 2에서도 같은 head 순서를 확인했다. E0 호출만 없앴을 때 이 구간 전체가 절약된다고 계산할 수 없다.

65816에서 비활성 WRAM의 64B를 수신 단어와 전부 대조한 뒤, 다를 때만 그 행 전체를 다시 쓰고 재검사했다. 이력을 신뢰하거나 STOP 확인 단위를 늘리는 변경은 없다. 처음 사용하는 두 뱅크는 각각 6개 행을 모두 복원했다. 2576의 여섯 행은 이미 일치했다. 행 끝의 한 바이트를 바꾸면 그 행만 복구하고 정상 표시했고, 복구 쓰기 뒤 다시 손상시키면 0xE0, 행 사이 STOP은 0xE4로 중단했다. 기존 순서를 유지하면 OBJ→SEAL은 4.652 / 4.665ms, 공개 간격 합은 16 / 16이다.

스크롤·패딩을 팔레트 128B 직후에 넣는 판, OAM 직전에 넣는 판, BG 계산 직후에 넣는 판을 실제 ARM으로 따로 링크했다. 부팅 위상의 영향을 분리하기 위해 837 부팅부터 2576 최종 ACK까지 동일하게 실행하고 수신기 코드만 교체했다. 두 위상 모두 2576은 VBlank 48, 2580의 704B map DMA는 VBlank 52, 마지막 쓰기는 231선이었다. 이후 246선 끝까지 최대 20,648 / 20,912클록이 남았다. 마지막 section 패킷이 큐 head에 도달한 시각은 이미 마감보다 139,526 / 139,130클록 늦었다. 잔여 OBJ 544B·raw 192B·팔레트 512B·OAM 544B의 첫 DMA 시작부터 마지막 쓰기까지도 21,920 / 21,938클록이 걸렸다. 독립 검사 시간을 전부 가려도 같은 순서로 DMA를 마치기에는 1,272 / 1,026클록이 부족하다. 실제 마지막 쓰기는 VBlank 53의 241선, 표시 간격 합은 16이었다.

데모·오프닝 각 여섯 화면의 RGB와 SEAL을 MMC826과 대조했다. 수락 전 테이블 손상은 최종 전체 검사에서, 수락 후 SEAL의 잘못된 identity와 표시 마스크는 각각 identity 검사와 전체 재검사에서 0xE0로 거부됐다. raw 및 coverage 손상도 0xE0, 한 번 관측한 STOP은 0xE4였고 이후 PPU 쓰기는 없었다. 링크된 ARM의 메뉴 해제·base 복구 시험을 통과했다. 후보 ROM은 5,238B로 보드 한도보다 118B 커서 에뮬레이터 진단에 사용했다. 실기 기준은 MMC826, 후속 재생 기준은 837을 유지한다. ## 후속작업

2580의 마지막 544B OBJ는 2576까지 고정한 두 위상에서 VBlank 52 진입 전 195 / 190선에 이미 수락·반환됐다. 다음에는 704B map과 이 OBJ를 같은 VBlank에 선행 DMA하는 경우와 section 5 후반 패킷을 앞당기는 경우를 분리해 비교한다. map·OBJ의 실제 마지막 쓰기, section 큐 head 수락, 246선과 2580 최종 ACK를 같은 시계로 대조한다. 2576 VBlank 48, 오프닝 245선, STOP·coverage는 계속 보호한다.
