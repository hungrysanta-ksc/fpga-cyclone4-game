## 목표

MMC806에서 중간 성 다음 스테이지의 한 줄에 SNES OAM 항목이 32개를 넘어도 게임과 조작을 이어간다. 직전 표시와 최종 ACK의 의미를 보존한다. PR161 병합 커밋은 `71819b4`다.

## 작업내용

ARM이 입력 END 검사 뒤, D3 수락을 보내기 전에 행별 항목 수를 계산한다. 전체 조각 수와 팔레트 수로 32개 이하가 보장되면 순회를 생략한다. 나머지는 수직 반전, 투명 행을 포함한 8줄 범위, 팔레트 전환에 따른 분할, raw 행을 반영한다. 초과 시 D3 거절을 보내고 해당 세대의 단독 ABORT(6), CRC, 토큰과 D2 반환을 확인해야 다음 입력을 받는다. 출력 BEGIN 이전에 거절하므로 마지막 표시 뱅크와 다음 목적지 뱅크에 쓴 부분 데이터가 없다. 다음 정상 세대는 기존 독립 검사·DMA·최종 ACK 경로를 탄다. game-last에 마지막 초과 행과 확인한 항목 수를 추가했다. 펌웨어 공간을 확보하기 위해 동일한 CRC8 계산을 공유하고 UART 진단 문구를 줄였다.

## 성과

- 두 최종 ARM에서 정상→연속 초과→정상, 16비트 세대·토큰 순환, 32·33개 경계와 두 팔레트의 16·17개 분할을 확인했다. 거절 전후 영상·resident 상태가 바이트 단위로 같았고 실제 runtime step의 대기 중 STOP이 성공했다. 잘못된 COMMIT·세대·거절 사유·추가 바이트·CRC·토큰은 각각 거부됐다.
- 804 보드의 실제 export와 lease RTL을 Questa에서 연결했다. 연속 거절과 ABORT 정체 중 STOP 뒤 다음 정상 세대로 복귀했고 거절한 세대에는 표시 lease가 없었다. 이 시험은 ARM 시험과 별도이며 동일 시각의 전체 보드 하드웨어 재현은 아니다.
- 807·808 모두 최종 링크의 두 부팅 위상에서 실제 65816이 두 화면에 DMA 16,384B와 최종 ACK를 완료했다. 두 번째 ACK는 805 대비 807에서 +14,196 / +126 masterclock, 806 대비 808에서 +0 / +504 masterclock이었다. 속도 이득은 입증되지 않았다. 메뉴·base 복원과 152비트 ACK 손상 검사도 통과했다.
- ARM Flash는 212,988B·212,948B로 각각 4B·44B 남았다. GCC의 준비 함수 정적 스택은 40→280B다. 804 보드·65816·GBC·base·메뉴 파일은 각 기존 판과 해시가 같다. [측정·해시](../../analysis/obj807-results.json) · [설치와 실기 로그](../nes-mmc807-808-trial.ko.md)

### MMC807·808 실기 결과

MMC808은 이전 종료 스테이지를 통과하고 직접 종료했다. 33분 16.61초 동안 42,035장 표시·EA 42,035회, 입력 END 42,037회 중 COMMIT 42,036회·ABORT 1회였다. 139선 33개, ABORT 사유 6, 영상 오류 0이다. 정상 입력도 한 번 더 COMMIT된 상태에서 종료 조합(0x7e, native_result 8)을 받았다. 개별 초과 화면의 시각·스테이지 번호·표시 공백은 기록하지 않는다. MMC807은 1,216장 표시, 60초 제한 종료, 초과 0회다. 두 판 모두 최초 실행 오류·ROM 오류·STOP 오류·전송 실패·CRC 오류가 0이고 base 복원·메뉴 준비 및 실제 메뉴 복귀를 확인했다. 종료 시점의 sink/window 하위 상태는 [원자료 요약](../../analysis/hardware808-results.json)에 보존한다.

| 5–40초 | 625장 · 17.86 fps | 666장 · 19.03 fps | +1.17 fps |

화면당 출력·최종 ACK 평균은 초반 34.48→29.35ms, 후반 34.47→32.74ms다. 초반 dirty map은 14.94→12.15, 후반은 8.70→19.46으로 작업량이 달랐다. 한 실행씩의 관측값이다. 재현은 `tools/analyze_nes_hardware808.py <여섯 로그의 폴더> <결과 JSON>`으로 한다.
