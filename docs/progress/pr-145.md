## 목표

MMC529 실기의 출력·최종 ACK 평균 48.10ms를 분해하고, 같은 작업량에서 952·954의 최종 VBlank 대기를 각각 한 번 줄일 수 있는지 검증한다.

## 작업내용

- PR144 병합 `bbacb9f`를 원격 master에서 확인하고 새 브랜치에서 시작했다. 실제 전달용 ARM과 65816을 두 시작 위상에서 각각 53화면 실행해 출력 호출, 패킷 소유, DMA·제어, 업로드·표시 VBlank 대기를 분리했다.
- 945에서는 입력과 패킷 도착을 고정하고 선행 map 허용선만 좁혀, 64B의 이동이 최종 ACK에 미치는 영향을 대조했다. 952·954는 수락 시각과 빈 큐·빔 구간을 겹쳐 이전 blank에서 처리할 수 있는 명령을 조사했다.
- 532는 실제 ARM이 반환 credit을 확인해 잔여 map을 발행하고, 65816은 수락된 작은 tile을 선택하거나 양쪽 주소가 연속일 때 병합한다. 같은 두 위상에서 ARM 단독, 64B map, 최대 128B map 및 목록 안쪽 tile 선택을 비교했다. 새 패킷·STOP 경합, 독립 수신 검사, 실제 VRAM과 최종 표시를 대조했다.
- MMC533 파일명으로 다시 링크한 ARM과 선택한 소비 ROM을 넣은 전체 보드를 빌드했다. MMC529와 같은 제한 실기 기준으로 STA·복구·표시 로그를 대조했다.

## 성과

- 907–957의 출력 호출은 평균 47.836/47.230ms였다. SEAL load 전은 약 26.24ms, 업로드 blank 대기는 8.65/8.63ms, 최종 blank 대기는 7.96/7.37ms였다. 실기 측정과 재생 범위를 구분했다.
- 945에서 64B 선행을 막자 첫 위상은 최종 대기가 한 번 늘고 ACK가 15.223ms 늦었다. 선행 행이 없던 둘째 위상의 ACK 차이는 −0.009ms였다. 952·954에서는 같은 blank를 사용하려면 각각 최대 6,107/7,899클록을 앞당겨야 한다. [계측 결과](../nes-output531-results.ko.md)
- 작은 tile 우선·128B map 후보가 두 위상 모두 952·954의 최종 대기를 1회에서 0회로 줄였다. 밀집 구간 표시 간격은 113.142/113.150→103.108/103.115ms, 905부터 누적한 957 ACK는 199.669/183.048ms 빨라졌다. 952에서는 기존 잔여 tile 중 16B를 선행 DMA했다. 954의 기존 잔여 map 1,536B는 입력 시작 후 76.815/76.746→61.177/60.977ms에 전부 수락됐다. [후보별 비교](../nes-tile532-results.ko.md)
- 전체 FIT 성공, 관련 setup/hold +0.078/+0.139ns. 전체 STA 57항목은 MMC529와 같고 setup −7.081ns·recovery −8.480ns가 남는다. Flash 여유 572B, STOP·최종 ACK·메뉴 복구 경계 검증 후 MMC533 ZIP을 두 번 동일하게 포장했다. [전달 검증](../nes-trial533-results.ko.md)

## 후속작업

MMC533을 같은 첫 레벨 동선에서 실행해 메뉴 복귀와 세 로그를 확인한다. 1–40초·40–60초 표시 횟수를 MMC529의 461회·232회와 비교한다. [설치 안내](../nes-mmc533-trial.ko.md)
