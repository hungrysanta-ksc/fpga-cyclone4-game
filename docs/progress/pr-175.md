# PR175 · 905 첫 계획 묶음 검증과 MMC955 실기판

## 목표

PR174 병합 커밋 `e62855e`에서 빈 캐시로 시작했다. 952 보드가 일찍 내준 E8 쓰기 허가 한 건을 ARM이 사용했을 때, 113B E9 수락에서 905 첫 화면과 906 입력까지 절약된 시간이 얼마나 남는지 측정한다.

## 작업내용

- 952 보드 RTL, 950 최종 ARM 링크, 같은 65816 ROM, 같은 캡처·ROM 허가 구간을 사용했다. 각 위상의 원래 실행과 첫 E8 응답 한 건만 바꾼 실행을 짝지었다. 바뀐 응답 이전의 ARM 이벤트와 905·906의 모든 E9 바이트를 대조했다.
- 대상 E9는 2.625MHz SPI 속도와 헤더 길이로 계산한 호스트 바이트 도착 시각에 입력했다. 명령 시점의 빈 뱅크, 매 바이트의 쓰기 허가, 마지막 CRC·길이·계획 수와 seal 다음 호스트 에지의 실제 pending을 확인했다. 905·906 타일 공급을 변경된 일정으로 다시 실행하고 각 묶음이 ARM의 타일 발행 전에 준비됐는지, CHR 원본에서 계산한 바이트와 일치하는지 검사했다.
- 같은 ARM에서 SRAM D0·CRC·STOP·base/메뉴 복귀를 재검증했다. 65816에서는 복사 중 STOP, 표시 직전 STOP, 잘못된 descriptor·중복·SEAL을 주입해 이전 화면 보존과 잘못된 최종 ACK 차단을 확인했다.

- MMC955용 설치·로그 이름으로 950 ARM을 최종 링크하고 952 배치 이미지를 패키징했다. 65816 ROM 5,120B를 실제 주소 버스의 읽기 결과 및 합성 ROM 초기값과 대조했다. 두 시작 위상과 두 캐시 조건에서 최종 ARM과 65816을 재생했다.

## 성과

| 952 기준 일정 대비 | 위상 1 | 위상 2 |
|---|---:|---:|
| 905 대상 E9 수락 | 4번째 묶음, 0.255ms 빠름 | 5번째 묶음, 15.040ms 빠름 |
| FPGA의 1,056B BG 준비 | 동일 | 0.256ms 빠름 |
| FPGA의 마지막 736B OBJ 준비 | 동일 | 동일 |
| 65816의 화면 SEAL 수락 | 동일 | 0.072ms 빠름 |
| 905 화면 공개 · 최종 ACK | 동일, 공개 VBlank 28 | 각각 0.017ms 빠름, 공개 VBlank 29 |
| 906 첫 D1 수신 시작 | 동일 | 0.025ms 늦음 |
| 906 마지막 데이터 D2 · COMMIT D2 | 모두 동일 | 데이터 0.104ms 빠름 · COMMIT 0.023ms 늦음 |

두 위상 모두 본문 105B·계획 15개를 수락했다. 위상 1은 바로 다음 E9부터 수락 시각이 원래 일정과 같아졌다. 위상 2는 마지막 E9까지 남은 이득이 0.381ms였고, 마지막 OBJ는 두 실행 모두 9,271,867클록에 준비됐다. ARM의 OBJ 발행이 541클록 늦어졌고 첫 D1도 똑같이 541클록 늦어졌다. 905는 같은 VBlank 안에서 공개선만 235→234로 이동했다. 906 수신 시작과 완료를 함께 앞당기거나 905 표시 간격을 줄인 결과는 얻지 못했다. [절대 시각·응답 수·검사 결과](../../analysis/admission954-results.json)

이 결과는 첫 쓰기 허가의 단독 효과다. 905·906에서 다시 대조한 E8 표본 717개 중 다른 응답 105개가 남았다. 다른 응답은 ARM에 되먹이지 않았다. 905의 두 타일 묶음 1,792B와 906의 일곱 묶음 1,744B는 두 경우 모두 RTL 바이트 검사를 통과했다. 두 위상에서 8장씩 map·팔레트 자료·RGB가 기준과 같았다. 실기 FPS 기준은 MMC925의 오프닝 22.14, 데모 22.23이다.

MMC955의 Flash는 212,980/212,992B다. 기존 캐시에서 여섯 표시 간격 합은 두 위상 모두 13 VBlank, 빈 캐시에서는 모두 14 VBlank였다. 네 조건 모두 입력 17블록·선행 DMA 496B를 유지했다. MMC925와 같은 작업량에서 진단 조회 15회와 8,044B 기록 크기를 확인했다. 원본 ROM 부팅 경로, 변형 ROM 거부, SRAM D0 네 곳, 독립 검사와 STOP·base 복귀도 통과했다. [설치·실기 비교 방법](../nes-mmc955-trial.ko.md) · [최종 링크·보드·ZIP 검증](../../analysis/trial955-package.json)

## 후속작업

1. MMC955로 같은 모험도 4 무입력 데모를 60초 실행하고 메뉴 복귀를 확인한다. 오프닝 1–30초와 데모 30–60초의 공개 장수를 MMC925의 642장·667장과 비교한다.
2. 55–60초에 작업량이 맞는 화면에서 공개 마감을 먼저 놓친 세대를 찾는다. 905의 첫 E9만 앞당기는 변경은 보류하고 남은 E8 차이를 그 세대부터 검증한다.

재현에는 PR174의 952 두 위상 원본 입력과 동일 ROM이 필요하다. 각 위상에 `nes_admission954.py prefix TEMP PHASE`를 실행하고 FLOAT 래퍼에서 `NES_954_MODE=prefix`로 `check_nes_admission954.ps1`을 실행한다. 각 위상에 `nes_admission954.py run TEMP PHASE`를 실행한 뒤 같은 래퍼를 `NES_954_MODE=full`로 실행한다. 별도 결과 폴더에서 `nes_admission954.py safety TEMP`를 실행한 뒤 `analyze_nes_admission954.py TEMP`로 집계한다.
