## 목표

PR157 병합 `a37946e`에서 707D의 실기 효과와 753 ARM·751 정적 ROM의 효과를 구분한다. 같은 보드에서 제한판의 첫 레벨 작업량·표시 수, 장시간판의 BG CHR·스페이드·STOP·메뉴 복귀를 비교한다.

## 작업내용

- A는 MMC704/705 ARM의 설치·로그 이름만 바꾼 763/764와 기존 685/694 표시 ROM이다. B의 766은 753 prefix ARM의 이름만 바꿨다. 765는 같은 753 ARM에 60초 종료·종료 분류와 마지막 통계 bin 보존을 연결했다. B는 동일한 751 ROM·FPGA 이미지 바이트를 사용한다.
- 707D RTL·핀·SDC·seed를 고정하고 763·765용 표시 ROM을 담은 보드를 각각 Quartus Lite로 전체 빌드했다. 764는 이미 검증한 707D SOF다. 766은 765와 같은 BI3에 고유 설치 이름을 사용한다.
- [설치·시험 순서](../nes-mmc763-766-trial.ko.md) · [패키지 검사·재생·해시](../../analysis/trial763-package.json)

## 성과

| 실기판 | 역할 | ARM Flash 여유 | 정적 BSS |
|---|---|---:|---:|
| MMC763 | A 60초 | 8B | 19,544B |
| MMC764 | A 장시간 | 52B | 19,552B |
| MMC765 | B 60초 | 24B | 19,796B |
| MMC766 | B 장시간 | 32B | 19,796B |

세 보드 구성이 모두 15,322/15,408 LE·962/963 LAB·56/56 M9K, 기존 제약 setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns다. 관련 PSRAM·CDC·IO 보고서가 양수이고 전체 외부 IO sign-off 범위는 기존과 같다. 실제 프로그래머 코드와 모델링한 FatFS/장치에서 설치 이미지 전송·디코드를 확인했다. 표시 ROM마다 5,120B 읽기·gap·STOP·정지 클록 reset을 확인했다.

빈 캡처는 기존 화면을 보존하고 단 한 번 폐기한 뒤 다음 정상 세대를 받아야 한다. 707D exporter·lease를 대상으로 두 세대 × 12위상에서 이 순서와 STOP이 통과했다. 이전 643 시험대에는 660에서 추가된 BG 메모리 상위 바이트 입력이 빠져 있었다. 두 바이트의 동일한 ROM 데이터를 공급한 뒤 24조건을 재실행했다. 각 설치판에서 메뉴 표식 4조건·base 복귀와 실패 주입 5조건을 확인했다. 765는 5–40초/40–55초 표시 수와 작업량 bin, tick wrap과 deadline 동시 고장·정상/실패 종료 분류를 확인했다. 초기 60초판은 타임아웃을 오류로 분류하거나 60초 경계의 bin을 지울 수 있어 전달에서 제외했다.

최종 765 ARM과 751 ROM을 부팅해 두 시작 위상에서 각 53장의 map·기대 바이트·RGB가 753 기준과 일치했다. 두 위상에서 951 공개 236선, 952·957의 1,536B map DMA, 957의 최종 대기 0회, 마지막 OBJ 시작 245/246선을 확인했다. 952–957 표시 간격은 여전히 각각 3 VBlank(평균 49.914 / 49.913ms)다. 장시간 753 재생 대비 765의 마지막 ACK는 위상 1에서 357,368클록(약 16.64ms) 늦고 위상 2에서 118클록 빠르다. 60초 종료 처리가 추가된 765의 전 구간 시간이 753과 동일하다고 간주하지 않는다. 766은 검증한 753의 실행 함수 주소·크기·바이트가 동일하다. 실기 성능·안정성 판정은 사용자 로그 대기다.

ZIP은 `WORKSPACE/probes/nes-trial763/trial01/MMC763-766-707D-AB.zip`(2,022,336B, SHA256 `4d6bae72f9c39894e70de93cc16d9055b947a23a9675cd89b1740a9f0e57bff2`)이다. 네 폴더에 분리한 설치·로그 이름을 사용하며 게임 ROM·세이브·RESTORE는 제외했다.

재현 시 `tools/prepare_nes_trial763.py --board <temp>/nes-bg707-board04 --out <work> --patches <patches>`로 준비하고 `tools/build_nes_mmc479_arm.ps1`로 VARIANTS의 각 원본과 patch를 전체 링크한다. 선택 폴더는 `probes/nes-trial763/{linked763,linked764,timed765,linked766}`이다. 보드별 `quartus_sh --flow compile board`와 세 report TCL, 기존 704 image 명령, 613 ROM 버스 및 새 763 capture 시험대를 순차 FLOAT 래퍼로 실행한다. `tools/check_nes_trial763.py`로 각 ARM의 종료 검사, 765/766은 `tools/check_nes_credit753.py --policy prefix --trial <번호>`로 receipt·STOP·최종 ACK 검사를 수행한다. 765는 `tools/run_nes_credit753.ps1`의 prefix 명령을 같은 751 client·ROM 달력으로 실행하되 ARM을 timed765/src로, 출력 경로를 work/timed1·timed2로 바꾼다. 763/764/766 검사는 work/checks번호, 765는 work/selected765, ROM 검사는 work/rom763..765, 빈 캡처 결과는 work/empty2, 이미지 결과는 work/packed763..765에 둔다. 마지막에 `tools/package_nes_trial763.py <work> <새 ZIP> <보고서 JSON>`으로 실제 배포 바이트를 검사한다.

## 후속작업

먼저 763→765의 5–40초·40–55초 최종 표시 수와 map·OBJ 작업량, 764/766의 장시간 로그를 구분해 판정한다. 현재 753 밀집 여섯 표시 창에서 D0+D2를 모두 무료로 만들어도 회수할 수 있는 점유는 22.438 / 22.364ms다. 전체 168.617 / 168.542ms에서 빼면 여전히 약 146.18ms로, 60fps의 100ms를 넘는다. 다음 구조 검토에서는 D1/E1 데이터 왕복을 실제로 얼마나 제거할 수 있는지와 기존 RAM 포트·독립 기대값·STOP 소유권 비용을 함께 산출한다.
