# PR137 — NES487 출력 본문 감사와 compact raw 예산

[GitHub PR137](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/137), 초안·진행 중. [상세 계약](../nes-output487-contract.ko.md) · [검증](../../analysis/output487-verification.json) · [현재 순서](../nes-output487-plan.json).

## 목표

MMC485 플레이 실기의 출력·SEAL 병목을 실제 직렬화 바이트로 분해하고, 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 유지할 다음 전송 절감 구조를 정한다.

## 작업내용

PR136 merge 2d4543ef의 master 도달을 확인하고 새 브랜치에서 진행했다. 실제 linked M4 수신·계획·SEAL을 고정 게임 입력 71개에서 실행해 section별 바이트와 bank 갱신을 계측했다. 필요64B를 넘게 읽던 RLE threshold 탐색을 제한한 후보를 빌드하고 전체 상태·계획·출력 패킷을 대조했다. raw 행/6-plane lossless codec prototype과 반례 검증도 추가했다.

## 성과

- 71개 상태·598개 계획·전체 출력 패킷/독립 확장 table 동일, ACK·token·STOP 등 실제 M4 소유권 12사례 통과.
- 해당 serializer 명령17,275,495→13,767,406(20.31% 감소). Flash+12B/잔여220B, 새 상태·buffer0B. 전송량과 실기 FPS 개선은 아님.
- 고정 입력 모두 raw2행인데 CHR2048B를 전송. 사용 행의6개 plane만 보내는 모델은384B로 원본과 정확히 일치하며 framing 포함1797B/프레임 절감 후보. 실제 ARM/SNES ABI 연결·시간·STOP 검증은 아직 없음.
- 현재 실기는485 대기13.55fps/첫 레벨 플레이 포함8.22fps 그대로다. 새 Quartus·FPGA·설치본은 없고 GBC/save와 정상 원복을 보존한다.

근거: `docs/nes-output487-contract.ko.md`, `analysis/output487-verification.json`, `docs/nes-output487-plan.json`. 즉시 ACK 모델의 명령 계측은 window CRC/E0·IRQ·ROM·실제65816 전체 시간 증명이 아니다. 과거71입력을 실제494플레이 프레임으로 취급하지 않는다.

## 후속작업

1. compact raw 표현을 실제 ARM·65816의 버전/길이/검사/복원과 연결하고 Flash220B·SNES 현재 배치224B와 stack 비용을 측정한다.
2. 실제 queue·공유 SPI·ROM/tile·65816 검사·DMA/VBlank·STOP·최종 ACK를 연결한다.
3. 데이터 절감/SPI 여유를 전체 비용으로 비교한 뒤 D0/source-ready 소유권을 다룬다. MCU_RDY는 현재 external_memory_ready다.
4. 의미 있는 결합 후보 이후 새 번호 전달본으로 같은 장면/입력을 비교한다. 탐색 절감이나 계측만을 위한 실기 재시험은 요청하지 않는다.
