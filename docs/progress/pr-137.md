# PR137 — NES487/488 출력 전송·복원과 전체 비용 검증

[GitHub PR137](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/137), 초안·진행 중. [488 계약](../nes-compact488-contract.ko.md) · [검증](../../analysis/compact488-verification.json) · [다음 순서](../nes-output487-plan.json). 현재 실기는485다.

## 목표

MMC485 플레이의 출력·SEAL 병목을 줄이기 위해 압축 raw를 실제 ARM·65816 복원·독립 검사·DMA에 연결하고, 추가 계산·Flash·RAM·whole Lite 비용과 최종 표시 시간을 함께 판정한다. STOP·최종 ACK·VBlank·메뉴 복귀를 유지한다.

## 작업내용

PR136 merge2d4543ef의 master 도달 뒤 새 브랜치에서487 section 감사와 packet 동일 bounded-scan을 검증했다. 이어4882 paired ABI로 raw1/2행의 low6plane만 전송하고3..7행은 canonical fallback하게 했다. ARM은 expired BG-key384B를 재사용하며 canonical CHR를 보존한다. 실제65816은 비활성 WRAM을 역순 확장한 뒤 기존 검사/2048B DMA/최종 표시를 실행한다. 중간 buffer와 retained cache는 추가하지 않았다.

M4 상태·계획/serializer·window CRC/credit/barrier와65816 픽셀·DMA·STOP를 검증하고, source/ROM/SPI RTL·C·실제65816 첫 표시/STOP/base도 연결했다. program4→8KiB를 실제 보드 ROM bus와 whole Quartus Lite FIT/동일 timing 조건으로 확인했다. 한 Starter FLOAT 좌석을 순차 사용했다.

## 성과

- 기존487 bounded-scan은71개 상태/계획/packet 동일·serializer 명령20.31% 절감이다. 이어488은71개 canonical 상태·598개 계획 동일, ordinary/SEAL E1 **364761→237174B(34.98%)**, raw2 프레임당1797B 절감이다. 실제494개 플레이 입력 재생이나 전체 SPI 감소율은 아니다.
- pack 포함 serializer 명령13767406→6392237(53.57%), 별도 linked window6표본2238692→1551186. 명령 수는 물리 cycle/IRQ 시간과 다르다.
- ARM Flash는485 대비+92B/잔여140B, BSS18572B 동일·새 global0B·SEAL static stack304B 동일. SNES body4233B로 program8KiB가 필요하며 새 persistent/framebuffer0B다.
- 실제6581612프레임의 canonical WRAM/VRAM/RGB/VBlank 최종 ACK,5종 거부·3종 STOP, M4 소유권12사례·sender8벡터·두 bank decoder16벡터 통과. 실제 C/RTL/65816 첫 표시는 raw0이라 raw 검증과 공통 물리 시간 증명으로 합치지 않는다.
- **최종 표시 시간은 거의 동일:** 같은 시작의12프레임823.806394→823.797082ms;4ms 시작 위상 변경에서도0.009312ms 차이. 복원3.83..3.96ms와 VBlank/DMA 일정이 wire 이득을 흡수했다.
- whole Lite FIT15287LE/14081comb/8392FF/51M9K, 기존 대비+33LE/+32comb/+4M9K,121LE/5M9K 여유. **관련 setup−0.101ns 실패**(기존+0.133ns), 최악은 loader check_failed→byte_hold[7]이다. false-path나 seed 재시도는 하지 않았다.

**488은 기능 후보이며 실기 전달은 보류했다.** 새 ZIP/실기 FPS는 없고485 대기13.55fps/첫 레벨 플레이 포함8.22fps가 기준이다. GBC/save·485/482/476/164/467 원복·메뉴 복귀 구현은 보존한다. 전체 reset/CDC/IO·full ARM stack/IRQ·물리 ROM 경쟁 승인은 아직 없다.

## 후속작업

1. loader reset/control fanout을 추적하고 같은 클록의 CRC 실패·STOP·복구를 지킬 실제 제어 변경을 먼저 검증한다.
2. raw 복원과 VRAM DMA를 함께 줄이는 후보를1↔2행/bank/clear 중 STOP/최종 ACK까지 비교한다. 같은 시작의 최종 표시 시간 개선을 먼저 요구하고 실제 code에 맞는 ROM 배치 비용도 비교한다.
3. 선택 구조가 확정된 뒤 한 번의 whole Lite FIT/관련 timing으로 재판정한다. 두 관문을 통과한 뒤 새 번호·marker·로그·원복 전달본으로 같은 장면을 실기 비교한다. 의미 없는 재시험은 요청하지 않는다.
