## 목표

실기 동작한 MMC540의 출력·최종 ACK에서 DMA 실행과 VBlank 대기를 분리하고, 전체 연속 표시 시간이 줄어드는 후보를 검증한다. STOP·독립 검사·메뉴 복귀를 유지하며 다음 전달본에 5–40초·40–55초 완료 집계를 적용한다.

## 작업내용

- PR146 병합과 master tree 일치를 확인하고 새 브랜치에서 시작했다.
- 실제 ARM·SPI·IRQ·2슬롯·65816의 두 시작 위상에서 출력 발행→SEAL head, 검사, 서비스 VBlank 대기, DMA, 나머지 제어를 중복 없이 분리했다.
- raw DMA의 패드 상태 재사용, X/Y 행 진행, 기존 전체 서비스를 유지한 행 진행 대조군을 구현했다. 전송량·독립 검사·STOP 위치·246행 검사선·기존 예산은 유지한다.
- 다음 집계는 [5,40), [40,55), 전체 [5,55)다. 기존 MMC540 ZIP은 바꾸지 않는다.

## 성과

52개 warm 평균의 SEAL 이후 DMA는 약 1.06ms, VBlank 서비스 대기는 약 11.14–11.20ms였다. ARM 출력 진입부터 SEAL head까지 약 26.4ms가 별도로 남는다. 957은 DMA 뒤 246행 검사선을 놓쳐 두 위상 모두 약 15.17ms를 추가 대기한다. 951·952·954는 마지막 대기 0회다. [분리 근거·후보](../nes-dma542-results.ko.md)

패드 상태 재사용 단독은 기능·독립 재생을 통과했으나 마지막 ACK가 33.276 / 16.630ms 늦어져 제외했다. 행 진행 후보는 연속 검증 중이며 새 성능 성과나 실기 전달 승격을 아직 주장하지 않는다. 실기 기준은 MMC540 13.37fps이고 후반 정적 클리어 장면의 영향을 보존한다.

## 후속작업

행 진행 후보의 두 시작 위상·동일 작업량·최종 ACK·첫 BG ROM 구간을 확인한다. 통과한 후보만 5–55초 집계와 메뉴/base 복구, 전체 보드 FIT·관련 timing 및 기존 STA 무회귀에 연결한다. 실패한 후보는 MMC540에 섞지 않는다. 다음 실기 전달은 새 이름을 사용하고 ROM·RESTORE를 제외한다.
