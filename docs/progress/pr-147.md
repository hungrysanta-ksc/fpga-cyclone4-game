## 목표

실기 동작한 MMC540의 출력·최종 ACK에서 DMA 실행과 VBlank 대기를 분리하고, 전체 연속 표시 시간이 줄어드는 후보를 검증한다. STOP·독립 검사·메뉴 복귀를 유지하며 다음 전달본에 5–40초·40–55초 완료 집계를 적용한다.

## 작업내용

- PR146 병합과 master tree 일치를 확인하고 새 브랜치에서 시작했다.
- 실제 ARM·SPI·IRQ·2슬롯·65816의 두 시작 위상에서 출력 발행→SEAL head, 검사, 서비스 VBlank 대기, DMA, 나머지 제어를 중복 없이 분리했다.
- raw DMA의 패드 상태 재사용, X/Y 행 진행, 기존 전체 서비스를 유지한 행 진행 대조군을 구현하고 두 위상씩 검증했다. 이어 map 뒤 기존 완료 확인을 한 번 수행하는 ARM 후보를 집계 변경만 적용한 대조군과 분리해 비교했다.
- BG map 마지막 쓰기 직후 검사된 credit으로 한 묶음을 발행하고, 준비된 tile을 먼저 큐에 넣은 경우 그 뒤에 map을 붙이는 두 ARM 후보를 분리했다. 951·957의 map 발행, 65816 수락, ARM credit 관측과 실제 VBlank 구간을 대조했다.
- 545는 65816의 기존 고정 source DMA를 64B 이상 동일 바이트 short repeat에 연결하고, 각 64B 경계와 마지막 조각 뒤 STOP을 주입했다. 집계 전용 ARM과 두 ROM 시작 위상에서 고정 도착 재생 및 전체 연속 일정을 분리해 비교했다.
- 546은 545의 16B 헤더 복사를 65816 MVN으로 교체해 같은 도착 시각 및 ARM이 후속 발행하는 두 일정에서 비교했다.
- 547은 최종 ACK에 묶인 뱅크별 raw 행 이력과 64B 단위 DMA 생략을 연결했다. 중간 STOP의 실제 부분 VRAM·이력을 이식해 전체 재전송을 확인하고, 서비스 호출 두 방식의 전체 시간을 분리했다.
- 548은 수신 시 독립 검사한 단일 반복 패킷의 값과 전체 행 범위를 뱅크별 최종 ACK에 연결했다. 임의 값 36B와 제한값 6B 기록을 비교하고 부분 수신·쓰기 뒤에는 여섯 행 전체 복원을 검증했다.
- 다음 집계는 [5,40), [40,55), 전체 [5,55)다. 기존 MMC540 ZIP은 바꾸지 않는다.

- 549에서 952의 모든 ROM 요청·grant·응답과 ARM E9·E1, 실제 큐 credit을 한 시간축에 대조하고 첫 BG의 한 행·세 행 묶음과 연속 OBJ 묶음을 각각 연결했다.

- 550은 일반 DMA 명령의 목록 위치와 목적지를 재사용한다. 고정 PUSH, ARM 연속 일정과 실제 CPU 비교값을 분리해 검사하고 MMC551 전체 보드와 전달 ELF를 검증했다.

- MMC551 실기 성공·실패 여섯 로그를 분리했다. 시작 전 실패의 잔존 DWT 통계를 수정하고 일반 mode 표 병합은 별도 ARM 두 위상에서 비교했다.

## 성과

첫 두 화면 이후 51개 평균의 SEAL 이후 DMA는 약 1.05ms, VBlank 서비스 대기는 약 10.88–10.94ms였다. 출력 함수 진입부터 SEAL head까지 약 25.9ms가 별도로 남으며 ARM 계산만의 시간이 아니다. 957은 246행 검사선을 놓쳐 두 위상 모두 약 15.17ms를 추가 대기한다. 원본의 951·952·954는 마지막 대기 0회다. [비용 분리·세 후보](../nes-dma542-results.ko.md)

기존 서비스+X/Y 행 진행은 본문 15B와 전체 53장당 1 VBlank를 두 위상에서 줄였지만 밀집 구간은 30/30 VBlank, 957의 최종 대기 1회 그대로여서 보류했다. 패드 재사용 후보들도 밀집 구간을 개선하지 못했다.

map 뒤 drain은 빈 큐를 확보한 시점이 활성 화면이라 957에서 추가 DMA가 0B였고, 같은 집계 대조군보다 마지막 ACK가 16.646/16.657ms 늦어져 기각했다. Flash +32B(여유 532B), BSS 동일, 추가 E0/SPI/ARM/IRQ까지 계산했다. 집계만 변경해도 한 위상에서 1 VBlank 차이가 나므로 이를 drain 효과와 분리했다. [연속 결과·추가 비용](../nes-drain543-results.ko.md)

542–543에서 10회의 53화면 공동 실행과 독립 재생이 RGB·map/tile·최종 ACK를 통과했다. 후보별 STOP·새 head·독립 검사와 ARM 오류/재시도/메뉴 경계도 통과했다. **새 성능 전달본으로 채택한 후보는 없고 MMC540 13.37fps를 유지한다.** FPGA/SNES가 동일한 ARM 후보는 기존 Lite FIT/STA를 재사용했으며 새 합성·ZIP·실기 성공을 주장하지 않는다.

544의 추가 4회도 53화면과 독립 재생을 통과했다. 최종 ARM 후보는 951에서 두 위상 모두 128B의 선행 map DMA를 추가했다. 같은 집계 대조군보다 53장 마지막 ACK가 33.272/16.645ms 빨랐다. 밀집 951–955는 30→30, 31→30 VBlank로 원본 MMC540의 30/30과 같으며, 957의 마지막 VBlank 대기는 두 위상 모두 1회였다. 951·957의 선행 발행이 실제로 일어났지만 두 위상 공통 승격 조건은 충족하지 못했다. [544 실측·독립 재생](../nes-front544-results.ko.md)

545는 65816 본문 +8B로 951의 194B와 957의 66B를 복원했다. 같은 집계 대조군 대비 두 위상 마지막 ACK가 66.574/66.551ms 빨랐고 첫 두 화면 이후 평균 표시 간격은 양쪽 약 1.305ms 줄었다. 951은 마지막 SEAL 전 VBlank에 map 448B를 더 전송했다. 밀집 합계는 30/30으로 원본 MMC540과 같아 조합 후보로 보존한다. 957 최종 대기는 1/1회다. [545 비용·STOP·표시 비교](../nes-repeat545-results.ko.md)

546은 본문을 5B 줄이고 545보다 53번째 표시 ACK를 16.64/33.29ms 앞당겼다. 957은 여전히 두 위상 모두 248행 h=98에서 빔을 읽어 한 번 더 기다렸으며 밀집 구간은 30/30 VBlank였다. [546 결과와 1,463클록 예산](../nes-header546-results.ko.md)

547은 957에서 같은 네 행을 생략해 두 위상 모두 246행 안에 들어갔다. 53화면에서 11,136B를 줄였지만 밀집 구간은 30/30 VBlank이고 공통 반환 후보의 마지막 ACK는 546보다 18.04/34.69ms 늦었다. [행 이력·복원·전체 비용](../nes-history547-results.ko.md)

548은 384B 원본 재비교를 없애고 warm 수신 기록 및 SEAL 결합을 합해 약 0.275ms로 줄였다. 957의 두 위상 모두 246행 h=624·대기 0회, 마지막 ACK는 546 대비 65.17ms 단축이다. 밀집 합계는 30/30 VBlank로 같아 실기 기준은 MMC540이다. [548 결과와 복구 시험](../nes-receipt548-results.ko.md)

549의 세 행 후보는 밀집 30→29 VBlank와 마지막 ACK 약 33.27ms 단축, 957 대기 0회를 두 위상 모두 달성했다. 연속 OBJ는 952를 6→5, 밀집 합계를 28회로 줄였지만 957 위상 2에서 281클록 늦어 한 번 기다렸다. [549 결과와 판정](../nes-supply549-results.ko.md)

550은 두 시작 위상 모두 952 SEAL 5 VBlank·957 최종 대기 0회를 달성했다. 밀집 표시 간격은 93.212 / 93.215ms이며 549 세 행 대비 마지막 ACK는 0.042 / 16.615ms 빨랐다. 위상 2의 실제 CPU 비교값은 246행이다. MMC551 ZIP 두 개를 독립 생성해 일치를 확인했다. [550 일정·실기 진입 검증](../nes-upload550-results.ko.md)

MMC551 성공 실행은 822회/60.08초(13.68fps), 5–55초는 672회(13.44fps)다. 실패 실행도 ROM 적재·START와 메뉴 복귀는 성공했다. stage 0에서 5초 준비 대기 만료 후 native 전송 0회로 종료했다. 기존 MMC551 성능을 유지하고 밀집 VBlank 수를 줄이지 못한 mode 병합은 제외한다. [552 실기 결과와 비용 대조](../nes-hardware552-results.ko.md)

## 후속작업

957의 마지막 tile ACK 뒤 map 3개의 준비·발행·수락을 추적하고 953 대조에서 회귀가 없는지 확인한다. 자연 재발한 시작 실패는 별도 표본으로 누적한다. 다음 전달 후보에는 미측정 보고 수정과 5–40초·40–55초 완료 집계를 유지한다.
