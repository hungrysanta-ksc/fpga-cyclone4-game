## 목표

MMC509 실기의 출력 43.17ms와 대응하는 65816 실행 구간을 확인하고, 전송량과 최종 표시 시간을 함께 줄일 다음 구현을 고른다.

## 작업내용

PR140 병합을 확인했다. MMC509의 ARM·공유 SPI·IRQ·ROM 일정에서 기록한 8,013개 요청을 동일 시각에 다시 공급하고 실제 65816의 패킷 소비, 독립 검사, PPU DMA, VBlank 대기를 계측했다. 입력 패킷의 공통 generation과 출력 map의 두 바이트 열 압축을 각각 원래 바이트로 복원해 비교했다.

## 성과

- 12개 화면의 픽셀, 최종 ACK 시각과 VRAM DMA 36,144B가 원본과 일치했다. 상태 조회 두 건의 원본 시각이 요청보다 빨랐다. 인과 순서대로 재생한 결과 큐·소비 상태는 같았고 이후 공동 실행기는 이런 조기 응답을 거부한다.
- 후반 10개 화면에서 마지막 END 전송부터 표시 ACK까지 평균 55.82ms였다. 일반 소비 22.66ms, VBlank 대기 20.00ms, PPU DMA 1.18ms였다. 실기 43.17ms는 별도 장면의 ARM 함수 측정이다.
- 같은 입력에서 선형 map 압축은 1,046.8B/표시, 입력 generation 공유는 519.2B/표시를 아꼈다. 합계 1,566B는 2.625MHz에서 4.77ms의 wire 예산이다. 실기 기준은 12.82fps다. [상세 분석](../nes-output511-results.ko.md) · [측정 JSON](../../analysis/output511-verification.json)

## 후속작업

먼저 map을 목표 WRAM에 한 번 복원하는 소비기를 기존 ARM·65816 경로에 연결하고, 공통 generation 입력을 별도로 연결한다. 두 변경을 각각 켜거나 끈 네 경우의 ARM·SPI·IRQ·ROM·VBlank 일정을 비교한다. 독립 검사·STOP·최종 ACK·메뉴 복귀를 유지하고, 후반 표시 간격과 Flash·RAM·FPGA 여유가 확인되는 후보만 실기로 전달한다.
