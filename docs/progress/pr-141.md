## 목표

실기 기준 MMC509에서 입력·출력 바이트를 줄이면 초기 두 화면 이후에도 최종 표시가 빨라지는지 확인한다. 독립 검사, STOP, 최종 ACK, VBlank와 메뉴 복귀를 유지하고 ARM·65816·FPGA 전체 비용으로 판단한다.

## 작업내용

- 511에서 기존 ARM·SPI·IRQ·ROM 일정의 65816 출력 비용을 분리했다. 보존된 상태 조회 두 건의 시각을 바로잡고 조기 응답을 거부하도록 공동 시험기를 수정했다.
- 512에서 ARM map 압축→기존 E1 큐→65816 WRAM 직접 복원과 FPGA D1 generation 공유→ARM 수신 파서를 각각 연결했다. map 빌드의 Flash를 확보하기 위해 종료 로그의 16진수 출력과 중복 CRC 실행 코드를 공유했다.
- 원본·map만·입력만·둘 다 적용한 경우를 동일한 시작 시각과 ROM 캘린더로 실행했다. 원본을 포함한 두 D1 형식의 온전한 응답을 실제 SPI RTL에서 대조했다. 변경 3개 보드는 Quartus Lite로 전체 합성·배치했다.

- 513에서 실제 MMC509 ARM으로 71화면의 map 행을 대상 뱅크와 대조했다. 플래너의 변경 쓰기와 ACK 이력을 기록해 패킷 수를 유지하는 8·16·32B 그룹의 ARM·RAM·전송 예산을 비교했다.

- 514에서 ARM의 8B 변경 마스크를 기존 행 묶음에 연결하고 65816이 대상 뱅크의 공개 이력과 생략 바이트 CRC를 확인한 뒤 부분 DMA를 실행하도록 했다. 원본·공통 코드 대조군·부분 DMA를 같은 12화면 일정에서 실행했다.

|---|---:|---:|---:|---:|---:|
| MMC509 | 93.110ms | 141,259B | 36B | 15,164 | +0.078ns |
| map만 | 108.084ms | 148,543B | 8B | 15,164 | +0.078ns |
| 입력만 | 93.107ms | 136,705B | 28B | 15,252 | −0.317ns |
| 둘 다 | 104.755ms | 141,609B | 0B | 15,252 | −0.317ns |

네 조합 모두 정규화한 396개 패킷의 내용, 12개 RGB 화면, VRAM DMA 36,144B, VBlank 최종 ACK·EA가 일치했다. map 직접 복원·중간 STOP·잘못된 범위 등 11조건과 실제 ARM의 입력·CRC·credit 검사, base-only 복귀 성공 및 오류 4종을 확인했다. 결합은 조회를 뺀 전송을 22,194B 줄였으나 전체 SPI는 350B 늘었다. 같은 192B map에서 일반 DMA 소비는 0.695ms, 압축 복원은 2.429ms였다. 현 실기 기준은 MMC509의 12.82fps다. 513에서 초기 두 화면 이후 전송된 1,763개 행 중 대상 뱅크와 완전히 같은 행은 0개였다. 같은 16비트 워드는 95.38%였다. 8B 그룹으로 **기존 패킷의 앞뒤만 자르면** 후반 69화면에서 평균 502.38B, 전송 환산 1.531ms를 줄일 수 있다. 추가 마스크 192B, 독립 ARM 커널 148B이며 종단 표시 시간은 다음 검증 대상이다. [513 조사](../nes-map513-results.ko.md) · [측정 JSON](../../analysis/map513-verification.json)

514는 원본과 같은 RGB 12장과 VBlank 최종 ACK를 유지했고, 손상·STOP 거절과 두 뱅크 cold 전체 행 복구를 확인했다. 부분 map은 88개 패킷에서 E1·VRAM DMA 각각 4,800B를 줄였지만 후반 평균 표시 간격은 **93.110 → 104.826ms**로 늘었다. 공통 CRC·로그 변경만 쓴 대조군은 91.515ms였다. 부분 map의 65816 소비 시간은 합계 62.222 → 210.717ms였고 E0 조회도 638회 증가했다. 514의 ARM Flash 잔여는 276B, 관측 스택 여유는 2,328B다. Quartus Lite 전체 배치는 원본과 동일한 15,164 LE, M9K 51개, 관련 setup +0.078ns였다. [514 결과](../nes-trim514-results.ko.md) · [측정 JSON](../../analysis/trim514-verification.json)

## 후속작업

MMC509를 실기 기준으로 유지한다. 514의 패킷별 생략 바이트 CRC 재순회는 종료한다. 다음은 최종 ACK 때 확정한 독립 뱅크·행 이력을 재사용하는 방식의 저장·생성·검사·STOP 비용부터 산정한다. 원본과 공통 코드 대조군보다 후반 최종 ACK 간격이 짧아지고 cold 전체 행 복구와 오류 거절을 유지할 때 실기 후보로 삼는다.
