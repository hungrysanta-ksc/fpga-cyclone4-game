## 목표

MMC520 실기에서 적이 많은 장면의 표시 지연을 줄이기 위해, 비활성 VRAM 전송을 앞선 VBlank에 실행하고 두 시작 위상의 최종 표시까지 비교한다.

## 작업내용

- PR142 병합 `9db5fda`에서 분기했다. 522에서 마지막 OBJ receipt 이후의 65816 소비·DMA·VBlank 대기를 분리했고, 523에서 패킷 수락 직전의 선행 DMA를 시험했다. [522 계측](../nes-tail522-results.ko.md) · [523 비교](../nes-prefix523-results.ko.md)
- 524는 큐가 비었을 때 닫힌 명령을 고르고 DMA 시작 직전 STOP과 새 head를 다시 읽는다. 520·523·524의 53화면 연속 일정을 같은 두 시작 시각에서 비교했다.

## 성과

- 952에서 4건·128B, 954에서 2건·160B를 두 위상 모두 실제로 선행 전송했다. 밀집 5화면의 523 대비 평균 개선은 첫 위상 0.003ms, 둘째 3.328ms였다. 53번째 ACK는 523 대비 49.925/99.819ms, MMC520 대비 99.853/183.009ms 빨라졌다.
- 양 뱅크의 STOP·head 충돌, 전송 중 도착, 독립 검사·dirty cold 복구, 최대 2KiB의 VBlank 종료와 53개 RGB를 검증했다. Quartus Lite 전체 보드는 15,164 LE·51 M9K, 관련 setup +0.078ns·hold +0.139ns였다. [524 검증](../nes-idle524-results.ko.md)
- MMC524 실기 실행·메뉴 복귀 정상. 715회/60.08초(11.90fps). MMC520 대비 1–40초 12.08→12.31fps, 40–60초 11.60→11.00fps. 55초 이후에는 표시 40→55회, 최대 간격 180→120ms였다. [실기 분석](../nes-hardware525-results.ko.md)

## 후속작업

MMC524를 기준으로 동일 입력에서 수락된 map의 64B 분할과 최종 표시 검사 도달 시각을 비교한다. STOP·독립 검사·최종 ACK를 유지하면서 952·954가 앞선 VBlank에 실제로 표시되는지를 확인한다.
