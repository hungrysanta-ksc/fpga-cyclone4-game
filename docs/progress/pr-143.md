## 목표

MMC520 실기에서 후반에 길어진 출력 비용을 같은 입력에서 마지막 OBJ 소비, 일반 명령, PPU DMA, VBlank 대기와 표시 ACK로 나눈다.

## 작업내용

- PR142의 master 병합 커밋 `9db5fda`에서 분기했다. MMC520에서 기록한 두 시작 위상의 패킷 도착 시각과 실제 데이터를 같은 65816에 재생했다.
- 토큰 receipt, 큐 head 소비, DMA 시작·마지막 PPU 쓰기, 4,192 예산의 차감·재충전과 명령 목록의 확정 시점을 계측했다.

## 성과

- 각 위상에서 53개 화면의 RGB, 기존 소비 이벤트, 표시 ACK 클록이 모두 일치했다. 밀집 951–955의 마지막 receipt→표시 ACK는 45.58–47.80ms였다.
- 952에서는 VBlank 대기 29.85–29.96ms, SEAL 안 PPU DMA 1.53ms였다. 업로드 예산이 128만큼 부족해 두 번째 blank를 기다렸다. 최종 표시까지 고정 예산으로 담으려면 1,696을 앞당겨야 하고, 앞선 blank에서 닫힌 항목은 1,248만큼 있었다. [522 검증](../nes-tail522-results.ko.md)

## 후속작업

먼저 닫힌 비활성 VRAM 명령의 선행 실행과 기존 최종 beam 검사를 연결한다. 필요하면 수락된 map 일부를 64B 단위로 분리한다. STOP·cold 복구·독립 검사·최종 ACK와 선행 DMA가 지연시킨 패킷까지 포함해 실제 공동 일정에서 비교한다.
