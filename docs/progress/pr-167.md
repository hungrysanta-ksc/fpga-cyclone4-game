# MMC826의 실제 압축 입력과 연속 원본 처리량

## 목표

PR166 머지 커밋 `fb79b39`에서 시작했다. 모험도 4 무입력 실기의 비교 기준은 MMC826의 오프닝 17.52 FPS(1–30초), 데모 16.13 FPS(30–60초)다. 원본 인접 60장을 매초 표시하려면 각 입력 ID가 한 번씩 공개되고 다음 초에 일이 밀리지 않아야 한다.

## 작업내용

- ROM SHA-256은 [MMC826 전달 기록](../../analysis/trial826-package.json)과 대조했다. Mesen에서 입력 없이 3,600프레임을 진행했다. 오프닝 700–759, 장면 전환 1527–1586, 밀집 데모 2560–2619를 선택하고 각각 앞의 두 프레임을 뱅크 준비에 사용했다. 1,557은 실제로 게임이 192선에서 스프라이트를 끄기 시작한 첫 원본 프레임이다. [캡처 시계·원본 ID·RGB·상태 해시](../../analysis/source848-index.json)
- 기존 821 재생기는 exporter가 내보낸 96비트 레코드를 ARM용 일반 map 패킷으로 다시 묶었다. MMC826 보드에서는 같은 레코드가 `nes_native_spi165`의 공유 RAM과 `nes_geometry_sender653`의 압축을 거친다. 822held 보드 소스의 실제 exporter·CDC·SPI를 Starter FLOAT로 실행해 D0 길이, D1 바이트·CRC, D2 반환, D3 준비를 대조했다. 각 D1을 독립 인코더와 비교하고 MMC826 ARM ELF에서 복원한 map·행·OBJ·팔레트·raw와 tile plan을 원래 기대값과 확인했다.
- 동일 시작 위상에서 해당 D1과 준비 클록을 전달했다. 실제 ARM·SysTick 및 65816 프로그램을 실행하고, ROM 허가 일정과 MMC826 실기 평균 SPI 호출 비용을 사용했다. ARM은 명령당 2클록 모델이다. D0–D3·E0–EA에는 명령별 평균을 적용하고, 70·73 상태 관측은 기존 재생과 같이 8B 순수 선로 시간으로 계산했다. 인접 원본 표의 SPI 점유에는 둘 다 들어간다. 거래 점유는 ARM 호출에서 공동 재생이 반환할 때까지로, 바이트만 전송한 시간보다 길 수 있다. 데이터 전송과 조회가 SPI를 점유한 시간만 더했다. ARM 명령 수, 수신기 검사, PPU DMA 시작, VBlank 대기는 별도 관측치로 남겼다. [프레임별·위상별 비용](../../analysis/input848-results.json)

## 성과

### 849에서 최종 표시 대기를 다음 입력 수신에 사용한 결과

MMC826의 E0는 큐와 최종 표시 영수증을 함께 읽는다. 밀집 데모에서 직전과 같은 응답을 돌려준 E0는 시작 위상별로 2,775 / 2,783건이다. SPI 응답의 발행·반환 카운터를 실제 패킷 순번에 붙여 보니, 큐가 가득 찬 동안의 조회는 10.39 / 10.28ms, SEAL이 첫 미반환 패킷일 때는 235.37 / 235.93ms였다. 별도로 65816 측의 명시적인 VBlank 대기와 거래 시간을 교차시키면 177.57 / 178.55ms가 겹쳤다. 두 분류는 일부 같은 시간을 설명한다. SEAL이 맨 앞이고 다음 입력 블록까지 준비돼 있던 반복 조회는 156.03 / 156.14ms였다. [재생별 결과](../../analysis/poll849-results.json)

849에서는 SEAL 전송 성공 직후 다음 원본을 최대 16블록까지 받도록 826 ARM을 다시 링크했다. 원래 이 경로는 앞선 수신으로 남은 예산과 BG·OBJ 개수에 따라 달라졌다. 각 블록의 D1 CRC·D2 토큰 반환과 guard를 그대로 실행하고, 입력이 완료되거나 상태 조회에서 진행이 없으면 루프를 빠져나온다. 다음 D3는 이전 표시의 최종 identity 확인과 EA 해제 뒤에만 허용한다. 모든 재생에서 이 순서를 거래 시각으로 확인했다.

| 인접 원본 구간 | MMC826 → 849 표시 간격 합 (위상 1 / 2, VBlank) | 849 처리 시간 (위상 1 / 2) | 마지막 표시 ACK 단축 (위상 1 / 2) |
|---|---|---|---|
| 오프닝 700–759 | 149 / 149 → **132 / 132** | 2196.00 / 2196.00ms | 282.87 / 282.87ms |
| 밀집 데모 2560–2619 | 150 / 150 → **138 / 139** | 2295.65 / 2312.28ms | 233.20 / 216.57ms |
| 전환 직전 1527–1544 (분리 부팅) | 39 / 39 → 37 / 36 | 615.24 / 598.63ms | 33.30 / 49.91ms |
| 전환 직후 1559–1586 (1557·1558로 뱅크 준비, 분리 부팅) | 61 / 60 → 58 / 58 | 964.64 / 964.64ms | 49.93 / 33.29ms |

표시 간격 합은 두 준비 화면 이후 60개 간격이다. 마지막 ACK는 같은 부팅 시작점부터 측정해 준비 화면의 차이도 포함한다. 데모에서는 준비 이후에만 200.59 / 183.95ms가 줄었다. 두 위상 모두 D1 74,073B·E1 93,898B를 전송했고 준비 화면 포함 VRAM DMA는 70,976B였다. 패킷 발행 순서는 달라질 수 있지만 각 화면의 공개 RGB는 MMC826과 같았다. 밀집 구간의 공유 SPI 점유는 1395.76 / 1396.40ms에서 1311.40 / 1323.17ms로 줄었다. 60장에 쓸 수 있는 1초를 SPI 점유만으로도 넘는다.

SEAL 대기를 더 사용한 대가도 있다. 밀집 구간에서 표시 ACK가 생성된 뒤 ARM이 EA로 해제하기까지 p95가 5.10 / 5.00ms에서 10.79 / 10.77ms로 늘었다. 표시 간격 p95도 여전히 두 위상 모두 약 50.55ms다. 다음 실험에서는 이 반환 지연과 캡처 누락을 함께 비교한다. 16블록을 더 늘리는 실험은 후순위에 둔다.

전체 ARM Flash는 212,944→212,924B로 68B가 남고 BSS는 19,548B다. 12번째 선행 D1에서 STOP과 CRC 손상을 각각 주입했을 때 해당 블록을 D2로 반환하지 않았다. 올바른 CRC에 잘못된 최종 ACK identity를 넣은 경우 오류 8로 거부했다. 세 경우 모두 이후 EA·D3는 0회였다. 같은 ELF의 메뉴 준비·해제와 base 복구 경로도 모델 I/O로 통과했다. 849는 ARM 일정 후보로 보관한다. 보드·65816은 MMC826과 같으며 이번 단계에서 새 Quartus 실행이나 실기 설치본은 만들지 않았다.

### 기존 재생의 교정

같은 원본 여섯 장(2560부터 네 프레임 간격), 같은 ARM·65816과 같은 위상에서 입력 표현과 보드 준비 시각만 교체했다. 2564 공개 직후부터 2580 공개까지 경계에 걸친 SPI는 점유 시간만 나눠 반영했다. 아래 바이트 수는 구간에 완전히 들어온 거래의 합이다.

| 네 표시 간격 | 이전 MMC826 재생 | 보드 D1을 쓴 MMC826 재생 |
|---|---:|---:|
| D1 바이트 | 24,929 | 5,062 |
| E1 바이트 | 11,394 | 11,394 |
| D1·E1 순수 선로 시간 | 110.699 ms | 50.152 ms |
| D0–D3·E0–EA 점유, 위상 1 / 2 | 177.228 / 176.934 ms | 108.849 / 123.529 ms |
| 표시 간격 합, 위상 1 / 2 | 16 / 16 VBlank | 11 / 13 VBlank |

보드 입력으로 바꾸기 전후의 여섯 출력 RGB는 두 위상에서 모두 일치했다. 837도 같은 입력으로 다시 재생하면 12 / 12 VBlank다. 837은 MMC826보다 위상 1에서 한 번 늦고 위상 2에서 한 번 빠르다. PR166의 14,448B 추가 절감 요구를 실제 보드 예산에서 철회한다. 이 차이는 재생 교정 효과이며 실기 FPS 기준은 MMC826을 유지한다.

### 장면 전환의 판정 범위

오프닝과 밀집 데모는 각각 인접 60장이 직전 RGB와 모두 달랐다. 전환은 60장 중 20장에서만 RGB가 달라졌다. 1545–1556은 CHR·nametable fetch와 행 시작 관측이 전혀 없고 원본 RGB는 직전 화면과 같다. 이때 게임의 메모리 상태는 바뀐다. 관측된 12개 ID를 보존하고 전환 전후는 각각 부팅해 측정했다. 따라서 그 두 재생을 더해 전환 1초의 표시 FPS로 발표할 수 없다.

별도로 1544부터 1557까지 collector·exporter RTL을 한 번도 리셋하지 않고 시험했다. 양 끝은 원본 PPU 자극을 주고 가운데 12장은 관측된 검은 RGB, 마스크 0, fetch 없음으로 재생했다. 관측할 수 없는 내부 스크롤 값은 0으로 둔 경계 시험이다. 이전 표시가 끝나지 않았다고 8클록 유지하면 12회 모두 소유권을 보존했고, 해제를 허가하면 각 1회 회수됐다. 중간에는 선로 레코드가 0개, 양 끝은 순서대로 963·1,007개였다. 수신기 공개·ACK가 발생하는 연속 전환은 아직 별도 검증이 필요하다. 분리 부팅한 전환 전 18개 표시 간격은 두 위상 모두 39 VBlank, 전환 후 28개 간격은 61 / 60 VBlank였다.

|---|---:|---:|---:|---:|
| 오프닝 700–759 | 149 / 149 VBlank | 2478.86 / 2479.29 ms | 50.18 / 50.18 ms | 1210.68 / 1211.18 ms |

매 VBlank 원본 하나가 도착하는 조건에 비하면 두 구간 모두 약 1.5초 분량이 밀린다. 여기서는 원본 ID를 순서대로 공급해 어느 ID가 공개됐는지를 검사했다. 실제 보드가 원본을 매번 저장한다고 가정하면 안 된다. 재생의 입력 해제 일정에서 인접 원본 60장을 수용하는 사이에 비어 있는 캡처 기회는 오프닝 116회, 밀집 데모 101회였다. 이 수와 표시 간격 합은 서로 다른 경계에서 센 값이다.

오프닝·밀집 데모에서 최종 ACK는 세대마다 정확히 한 번 도착했고 두 위상에서 출력 RGB가 모두 일치했다. 두 구간 모두 60개 간격 각각에서 표시 RGB가 바뀌었다. 마지막 ACK의 두 위상 master clock은 오프닝 71,797,172 / 71,797,226, 밀집 데모 66,801,114 / 66,800,890이었다. 장면별로 독립 부팅한 절대 시각이다. 세 구간 전체에서 준비 화면을 포함해 검증한 보드 D1은 2,964건이었다.

밀집 데모에서 D1은 두 위상 각각 276.18ms, E1은 343.50ms, E0 상태 조회는 431.29 / 432.18ms를 점유했다. 그중 같은 세대에서 직전 E0와 응답 전체가 같은 조회는 2,775 / 2,783회, 306.65 / 307.53ms였다. 이 시간을 모두 없애도 다음 DMA나 VBlank가 그만큼 빨라진다고 단정할 수 없다. 발생 사유를 추적할 첫 대상이다.

아래는 같은 60장을 두고 어느 데이터가 실제로 같았는지 계산한 상한 비교다. 숫자는 D1·E1 바이트다. 입력은 직전 원본의 같은 위치·길이인 압축 map 블록이 전부 같을 때만 본문을 뺐다. 출력은 대상 뱅크의 마지막 ACK 때 확정한 map과 이번 일반 map 패킷을 4B씩 비교했다. 전체가 맞는 4B만 뺐고 기존 명령 헤더·CRC는 남겼다. 새 이력 명령, bitmap, 독립 검사와 복구 비용은 아직 차감하지 않았다.

| 장면 | 기존 | 입력만 | 출력만 | 둘 다 |
|---|---:|---:|---:|---:|
| 오프닝 | 166,096 | 106,996 | 166,096 | 106,996 |
| 밀집 데모 | 167,971 | 145,176 | 137,491 | 114,696 |

밀집 데모에서 두 후보의 절감 상한은 53,275B, 선로 시간으로 162.36ms다. 현행 조회 정책에서 SPI가 1초를 초과한 약 396ms를 이 두 절감만으로 해소할 수 없다. 오프닝은 입력 map에서 59,100B를 줄일 여지가 있지만 이번 출력 map 비교에서 얻은 절감은 0B였다.

### 850에서 빈 캡처를 지나 첫 데모 화면까지 이어 재생한 결과

원본 1525·1526으로 두 표시 뱅크를 준비하고 1527–1586을 한 번의 ARM·65816 부팅으로 재생했다. 렌더링이 꺼진 1545–1556에서는 원본의 PPU 읽기가 멎는다. 각 ARM과 위상에서 얻은 이전 표시의 소유권 반환(EA) 거래 시작과 끝을 보드의 collector·exporter·lease RTL에 각각 입력했다. 8개 시점 모두 PPU 클록이 계속 진행되는 동안 빈 캡처 12개가 각각 한 번 폐기되고 전송 레코드는 0개였다. 경계 전후의 정상 query·wire는 새로 만든 기준과 일치했다. EA 전달은 거래의 양 끝과 동기화 여유 8클록으로 시험했고, 앞선 ROM reader는 배출 완료 상태로 두었다.

네 재생 모두 캡처 세대는 924→937, 실제 표시 일련번호는 20→21로 이어졌다. 두 표시 사이의 16개 중간 VBlank에서 활성 뱅크 1과 직전 화면의 RGB가 유지됐다. 1557부터 유효 표시가 재개됐고 원본도 1562까지는 검었다. 첫 비흑색 화면은 1563이었다. 준비 화면을 포함한 50장 모두 원본 NES의 224개 표시 행과 SNES 출력의 RGB555 색이 픽셀별로 일치했고 마지막 ACK·EA 이후에 다음 D3가 발행됐다.

| 원본 1527–1586 | MMC826 위상 1 / 2 | 849 위상 1 / 2 |
|---|---:|---:|
| 유효 표시 간격 48개 합 (VBlank) | 123 / 123 | 120 / 120 |
| 표시 간격 p95 (ms) | 50.34 / 50.32 | 49.34 / 49.34 |
| 1544→1557 사이 표시 간격 (VBlank) | 17 / 17 | 17 / 17 |
| 최종 ACK 이후 EA 반환 p95 (ms) | 5.49 / 5.47 | 11.34 / 11.19 |

849의 1586 최종 ACK는 49.91 / 49.93ms 빨랐다. 양쪽 모두 같은 64,034B의 D1을 수신했다. 이 값은 보드에서 얻은 송신기·캐시 결과와 ARM 실행·65816 에뮬레이션을 연결한 일정이다. 실기 기준은 MMC826이다. [위상별 결과와 바이너리 해시](../../analysis/transition850-results.json)

앞선 시험 입력은 7번 줄 dot 257에서 PPU를 구동하기 시작해, 이미 켜진 스프라이트를 그 위치에서 새로 켠 것으로 collector에 전달했다. dot 0부터 신호를 공급하자 50장 모두 인위적인 256B raw 행 하나가 사라졌다. 1544는 256→0B, 1557은 512→256B였다. 실제로 스프라이트가 꺼지는 1557의 경계 행은 보존됐다. 보정 전후의 D1 합계 69,792→64,034B는 시험 입력의 차이이므로 ARM 개선량에서 제외했다.

### 851에서 dot 0으로 보정한 오프닝과 밀집 데모

두 장면 모두 준비 화면 2장과 측정 화면 60장을 연속 공급했다. 총 124장 각각에서 잘못 생겼던 256B raw 행 하나가 사라졌다. 아래 모든 판은 같은 보정 입력, 815R 표시 프로그램, CHR 캐시 적중, ROM 허가 일정과 SPI 호출 비용을 썼다. 849는 SEAL 뒤 입력을 선행 수신한다. 공통 대조군은 849에 재사용 수신기를 링크하고 원래 D1을 보내며, 재사용판은 그 바이너리에 실제 FPGA 송신기가 만든 참조 D1을 보낸다.

|---|---:|---:|---:|---:|---:|---:|
| 오프닝 1 | 134 | 126 | 127 | 121 | 132.777ms | 99.824ms |
| 오프닝 2 | 133 | 127 | 127 | 123 | 99.371ms | 66.707ms |
| 밀집 데모 1 | 139 | 135 | 134 | 133 | 83.207ms | 16.626ms |
| 밀집 데모 2 | 139 | 134 | 133 | 133 | 99.822ms | −0.008ms |

판별 네 열은 60개 표시 간격의 합(VBlank)이다. 마지막 ACK는 같은 위상의 부팅 시각을 기준으로 비교했다. 849는 네 조건 모두 표시와 마지막 ACK를 앞당겼다. 밀집 데모 위상 2에서 849→재사용의 1 VBlank 이득은 기존 D1을 보내는 공통 대조군에서도 나타났다. 참조 D1을 켜자 ACK가 162 master clock 늦어졌다. 밀집 데모 표시 간격 p95는 네 판에서 모두 50.49–50.55ms였고, 849의 ACK→EA p95는 MMC826의 5.07–5.08ms에서 10.62–10.69ms로 늘었다. [세대별 표시 간격·점유·바이너리 해시](../../analysis/comparison851-results.json)

오프닝에서 D1 1,036건 중 720건을 재사용해 106,492→54,592B, 데모에서 1,028건 중 647건을 재사용해 72,693→56,368B가 됐다. D1 블록 수와 블록별 D2 반환은 유지했다. FPGA는 직전 입력과 셀이 모두 같을 때만 본문을 10B 참조로 바꾼다. ARM은 보존한 map에서 세대·범위·CRC를 확인하고 필요한 타일 집합을 다시 만든다. 같은 ARM의 데모 수신 명령은 7,230,570→7,978,046개로 늘었다. 데모 위상 2의 60개 간격 내 공유 SPI 점유는 1,261.80→1,229.64ms까지 줄었지만 같은 표시 마감을 넘었다. 재사용판도 인접 60장에 두 위상 모두 약 2.213초가 걸렸다.

기존 RGB 수거기는 표시가 한 VBlank 간격으로 이어질 때 다음 화면을 읽을 수 있었다. ARM 발행 시각을 고정해 65816을 다시 실행하고, 공개 뒤 첫 번째 완성 화면을 채취했다. 16회 재생의 992개 화면 모두 224행 RGB가 각 NES 원본과 일치했고, 재생 전후의 모든 표시 ACK 클록과 DMA·공개 추적 행이 일치했다. cold·세대 건너뜀·CRC 오류·보존 RAM 손상·부분 수신 뒤 STOP 등을 포함한 오류 10종을 ARM이 거절했고 전체 입력으로 복구했다. FPGA에서도 중간 취소 뒤 이전 참조와 credit이 무효화됐다.

재사용 ARM은 213,016B로 Flash 한도 212,992B를 24B 넘었다. 전체 Quartus Lite FIT에서 직전 셀 이력 15,840비트를 포함한 설계가 M9K 57개를 요구했고 보드에는 56개가 있다. 배치가 종료되어 STA 결과는 없다. 851은 실기 후보에서 제외한다. 실기 기준은 MMC826이다.

### 852에서 대상 뱅크의 마지막 ACK를 사용한 출력 map

dot 0 보정 849의 밀집 데모에서 오른쪽 map의 여러 행은 앞쪽 타일만 바뀌고 뒤쪽 28B는 0을 유지했다. ARM은 뱅크마다 32행 bitmap을 두고, 전송 중에는 작업용 사본을 갱신한다. SEAL의 최종 ACK와 resident commit이 성공해야 그 사본을 공개한다. 두 뱅크의 cold 적재, epoch 변경, 실패 후 reset을 거치는 경로에서는 일반 패킷으로 시작한다. 이전과 현재 모두 0인 꼬리만 생략한다. 압축 명령에는 대상 뱅크의 이전 표시 serial 4B와 행마다 앞쪽 36B가 들어간다. 원래의 64B 행 주소·범위 등록과 VRAM DMA량은 유지한다.

65816은 대상 뱅크가 마지막으로 공개한 32비트 serial, 수신 길이, 확장 길이, 주소·coverage를 검사한다. 앞 36B를 WRAM에 쓴 뒤 선로 원본과 비교하고, 생략한 28B도 WRAM에서 직접 읽어 전부 0인지 확인한다. 첫 소비자는 MVN 명령으로, 두 번째 소비자는 하드웨어 MDMA로 앞부분을 복사한다. 두 소비자 각각에서 cold 참조, 틀린 ACK serial, 길이·범위 오류, 전송한 바이트와 보존한 바이트의 손상을 거절했다. 행 하나의 앞부분을 쓴 뒤 STOP하면 직전 표시가 유지됐고, 취소 시점의 두 WRAM map을 넣어 다시 부팅해도 첫 두 전체 입력의 WRAM·VRAM·RGB가 복구됐다.

ARM 최종 링크는 212,988 / 212,992B(849보다 64B 증가), 정적 RAM은 16B 늘었다. 5,120B 65816 ROM의 패킹 여유는 MVN 22B, MDMA 7B다. 이 비교는 기존 FPGA 데이터 경로에 대해 패킹한 ROM을 재생한 결과이며 별도 보드 FIT·실기 FPS는 측정하지 않았다.

밀집 데모는 준비 화면 2장 뒤 원본 2560–2619의 표시 간격 60개를 합산했다. 마지막 ACK는 같은 부팅 시각에서 원본 2619의 표시 완료까지 재고 849와의 차이를 적었다. 음수면 개선이다.

| 65816 처리 | 간격 합 위상 1 / 2 (VBlank) | 마지막 ACK 차이 위상 1 / 2 (ms) |
|---|---:|---:|
| 849 | 135 / 134 | 기준 |
| MVN 복사 및 검사 | 140 / 138 | +66.570 / +66.557 |
| MDMA 복사 및 검사 | 134 / 134 | −16.627 / +0.005 |
| 같은 MDMA 링크에서 이력 사용 해제 | 133 / 134 | −33.260 / +0.004 |

MDMA에서 이력을 켜면 같은 링크의 일반 패킷 대조군보다 위상 1이 1 VBlank와 16.633ms 늦어지고 위상 2는 간격 동률에 마지막 ACK가 18클록 늦어졌다. 849 대비 위상 1의 개선은 행 꼬리 생략에 귀속할 수 없다.

밀집 데모 두 위상에서 map 패킷 178개 중 174개가 참조를 사용했고, 선로에서 35,894→22,590B(−37.1%)로 줄었다. 확장·DMA 대상은 각각 32,512B였다. 패킷별 SPI 시간의 합은 118.343→77.798ms였다. 반면 65816이 패킷을 꺼낸 뒤 수락 ACK까지의 합은 102.247/102.251→221.788/221.801ms, SPI 전송 완료 뒤 큐에서 기다린 합은 7.983/9.114→356.770/357.942ms였다. 이 값은 병행 실행되는 패킷별 누계다. 주소와 길이를 맞춘 174건 모두 선로와 소비 시간을 합하면 MDMA 후보가 건당 0.292–0.521ms 느렸다.

MDMA의 오프닝 간격은 126/127→127/127, 전환은 120/120→121/121 VBlank였다. 세 구간에서 모든 공개 화면의 224행 RGB가 원본과 일치했고, 빈 캡처 12개를 지나는 동안 직전 뱅크·표시 serial·RGB가 유지됐다. ARM에서도 첫 참조 발행 뒤 STOP과 최종 ACK identity 오류를 각각 주입해 두 뱅크 이력의 공개가 진행되지 않고 후속 EA·D3가 발행되지 않는 것을 확인했다. 비교 기준은 849로 유지한다. [위상별 시간·패킷·오류 주입 원자료](../../analysis/output852-results.json)

## 후속작업

1. dot 0 보정 849를 유지한다. 밀집 데모에서 대상 뱅크가 마지막으로 표시한 map과 달랐던 508행은 모두 16비트 단어 하나씩 바뀌었다. 23개 세대 중 21개에서는 23행의 같은 열이 바뀌었다. 다음 후보는 이 변경을 열 단위 명령으로 묶고, 줄어드는 패킷 수락 횟수와 남는 WRAM 검사 비용을 먼저 비교하는 방식이다. 둘 중 하나의 위상에서만 이득이 나는 후보는 실기판으로 올리지 않는다.
2. 수신기 변경만 적용한 대조군을 계속 둔다. 입력 D1 재사용은 기존 메모리로 이력 비교를 구현하고 밀집 위상 2에서도 독립적인 시간 이득을 보일 근거가 생길 때 다시 검토한다.
3. 두 위상에서 밀집 간격과 최종 ACK가 함께 줄고 오프닝·전환을 보존한 후보만 전체 링크·FIT·STA 확인 후 실기에 보낸다. 실기에서는 같은 무입력 60초의 1–30초·30–60초와 메뉴 복귀를 비교한다.

### 재현

852는 851의 보정 입력과 850의 보정 전환 입력을 그대로 사용한다.

1. `prepare_nes_output852.py arm <probe>/bank-patch`로 849 ARM 소스에서 변경분을 만든다. `build_nes_mmc479_arm.ps1`의 Base는 `nes-poll849/link02`, Patch는 이 디렉터리, Out은 `nes-output852/bank`다. `prepare_nes_output852.py client <probe>/client-board`와 `dma <probe>/client-dma`는 각각 815R에서 MVN 복사판과 MDMA 복사판을 생성한다. 두 판 모두 부트 압축 해제와 전체 바이트 readback을 거친다.
2. `replay_nes_output852.py <temp> <clip> <phase> <policy> 852-bank-<policy>`를 실행한다. clip은 opening·transition·demo, 위상은 1·2, policy는 common·reuse다. common은 같은 ELF의 BEGIN 직전에 승인된 두 행 bitmap을 비워 일반 패킷을 보내게 한다. 두 번째 ROM은 태그를 `852-dma-<policy>`로 바꾸고 `--dma`를 추가한다. 이 ROM은 세 장면의 reuse와 데모의 common을 실행한다. 모든 재생에서 실제 패킷 수락·DMA·표시 ACK, 원본 RGB, D1 크기와 세대 순서를 대조한다.
3. 각 ROM의 `demo` 위상 1 reuse 디렉터리를 대상으로 `guard_nes_output852.py <temp> <run> <probe>/guards-<bank|dma>.json`을 실행한다. 부분 STOP 직후의 두 WRAM map을 새 부팅의 첫 패킷 직전에 주입하고, 두 cold 입력이 참조 없이 각 뱅크 전체와 표시 RGB를 복구하는지 확인한다.
4. 최종 집계 전에 같은 guard 도구를 `<probe>/arm-stop.json --arm stop`, `<probe>/arm-identity.json --arm identity` 출력으로도 실행한다. 세대 914가 첫 참조를 발행한 뒤 ARM에서 STOP 또는 최종 ACK identity 오류를 주입해, 공개된 두 행 이력이 바뀌지 않고 EA·후속 D3가 0건인지 검사한다. `analyze_nes_output852.py <temp> analysis/output852-results.json`이 대조표를 생성한다.
