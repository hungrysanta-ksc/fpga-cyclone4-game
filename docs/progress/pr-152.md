## 목표

MMC613 실기의 출력·최종 ACK 31.63 ms에서 먼저 줄일 구간을 정한다.

## 작업내용

634에서 950이 SEAL 이후 표시 ACK를 기다리는 동안 951 수신·복원 7블록을 배치했다. 기존 30패킷과 633의 여섯 패킷 생략 조건을 같은 두 위상에서 실제 65816 소비 ACK로 대조하고, 625에 제한 수신 callback을 붙여 전체 ARM 링크와 취소 경로를 검사했다. [634 검증](../nes-overlap634-results.ko.md)

633에서 951 팔레트·OAM 후반 여섯 패킷의 준비·전송·소비를 생략한 낙관 일정을 원래 65816에서 재생했다. 대상 뱅크의 바이트, 빈 큐와 map DMA의 시작·종료, 246번 검사선과 최종 ACK를 두 위상에서 대조했다. [633 검증](../nes-bank633-results.ko.md)

632에서 tile 유효 비트맵과 HDMA 형식 검사를 각각 마지막 관련 입력으로 옮겼다. 같은 65816 바이너리의 네 경우를 625의 두 SPI 일정에서 실행하고, 실제 DMA·최종 ACK·중단 후 cold 복구를 대조했다. [632 검증](../nes-seal632-results.ko.md)

631에서 OAM 544B와 HDMA 앞부분 1,121B를 각 한 명령으로 복원하는 65816을 실행했다. OAM만·HDMA만·둘 다 적용한 경우와 대조군을 분리했다. 기존 map 전송을 유지하고 BG 확정 뒤 E0·E8·E1을 반영해 map 두세 개를 앞당겼을 때도 목표 VBlank의 실제 DMA를 추적했다. [631 검증](../nes-tail631-results.ko.md)

630에서 951의 오른쪽 map 24행을 34B literal DMA와 30B 고정값 DMA로 완전히 복원했다. 팔레트·OAM을 먼저 발행하는 경우와 마지막 OBJ 뒤 생산 대기를 모두 제거한 경우를 나눠, 실제 65816이 SEAL을 언제 수락할 수 있는지 두 위상에서 측정했다. [630 검증](../nes-map630-results.ko.md)

629에서 625의 발행 시각과 628의 실제 PUSH 시각을 각각 고정하고, 951에서 바뀐 4B를 쓰는 시간과 생략 데이터를 확인하는 시간을 실제 65816 명령 경계에서 분리했다. 행 단위로 다시 작성한 수신기의 cold·손상·STOP 뒤 전체 복구도 확인했다. [629 검증](../nes-map629-results.ko.md)

628에서 951의 최종 ACK 뱅크 이력을 이용한 4B 변경 전송을 ARM·65816에 연결했다. 별도로 같은 map을 BG 확정 직후 한 패킷 또는 최대 세 패킷까지 보내도록 하고, 두 시작 위상에서 53화면과 STOP·cold 복구를 대조했다. [628 검증](../nes-map628-results.ko.md)

627에서 951의 확정된 raw·HDMA를 남은 map 앞 또는 map 뒤·팔레트 앞으로 옮겼다. 동일 작업량의 53화면에서 ARM 메모리 쓰기·패킹·SPI 발행·65816 수락·표시를 두 위상으로 대조하고, map 순회만 바꾼 대조군도 분리했다. [627 검증](../nes-tail627-results.ko.md)

626에서 955의 두 map 패킷 발행 순서와 65816 부분 DMA 시작 주소를 고정 도착 재생과 실제 연결 실행에서 교차했다. 선행 전송과 SEAL 뒤 전송을 행별로 합산하고, 정확히 1,344B가 수락됐을 때만 허용하는 유휴 DMA도 별도로 시험했다.

625에서 955의 BG ROM 요청·허가부터 map 수락·SEAL·첫 DMA를 추적했다. 같은 65816에서 SEAL 도착만 늦춘 재생과, 같은 ARM 바이너리에서 955의 BG·OBJ 조기 발행 한 번만 우회한 대조군으로 두 효과를 분리했다. 다섯 ARM 후보를 두 시작 위상의 53화면 연속 일정으로 비교했다.

624에서 921 SEAL 발행·ARM 반환, 922 SEAL 수락·잔여 DMA와 빔 래치, 923 첫 ROM 응답을 같은 클록으로 대조했다. 독립 수신 이력으로 확인한 여섯 raw 행 중 세 행만 전송하는 65816 경로를 621·622 A·623 T ARM에 각각 연결하고, 고정 도착 재생으로 922의 효과를 분리했다.

623에서 622 A의 팔레트 압축을 유지하고 세 번째 패킷에 ARM의 실제 소비 ACK 확인을 연결했다. 세 후보와 동일 바이너리 대조군을 두 위상씩 53화면 실행하고, A의 앞선 도착 시각을 보존한 65816 재생으로 957의 효과를 분리했다.

622에서 957의 팔레트 PUSH·수락과 16B·48B tile·1,152B map의 실제 DMA를 대조했다. 621 및 raw 준비 우선 후보 A의 세 번째 팔레트부터 도착을 바꾼 재생을 분리하고, Flash 한도 안의 다섯 ARM을 두 시작 위상씩 53화면 실행했다.

621에서 최종 표시 ACK로 확정된 대상 뱅크 이력에 따라 두 번째 BG 묶음을 발행했다. 같은 ARM 바이너리의 906에서만 조기 발행을 복원한 대조군과 두 위상의 53화면을 비교했다.

620에서 619 검사 단독 65816을 기준으로 확정 BG 묶음의 ARM 조기 발행, 직접 직렬화, map 소비 확인을 네 구성으로 연결했다. 두 위상의 53화면에서 96개 ROM 응답부터 144B의 65816 수락·PPU 쓰기와 절대 마지막 ACK까지 대조했다.

619에서 618의 후반 BG·OBJ 544B를 생산·E1·수락·DMA까지 추적했다. 늦은 tile 허용과 독립 검사 단축을 분리·결합해 두 시작 위상의 53화면과 65816 거부 경계를 비교했다.

618에서 955 OAM 발행 시각과 954 검사 후 DMA를 고정 도착 재생으로 분리한 뒤, ARM 준비 순서·조건부 발행과 65816을 세 가지 구성으로 연결해 두 위상의 53화면을 검증했다.

617에서 BG 계획 중 확정된 다음 map 행을 ARM이 추가로 발행하도록 연결하고, 두 시작 위상에서 65816 수락·실제 VBlank DMA·마지막 ACK를 대조했다.

616에서 수락된 연속 map의 65816 선행 DMA를 최대 1,152 B로 늘렸다. 두 빔 경계 후보를 53화면 연속 일정·고정 도착 대조·STOP/새 head/독립 검사로 검증했다.

MMC577·MMC613의 두 시작 위상에서 같은 세대의 map·OBJ 작업 52쌍을 확인하고, ARM 출력 함수 전체를 SEAL 발행·65816 수락·검사·DMA·VBlank·ACK 복귀로 나눴다.

## 성과

첫 BG map 수락은 약 10 ms 빨라졌다. 입력 중첩만으로 951은 4 / 4회였다. 여섯 출력 패킷도 무료로 재사용하면 3 / 3회, 951 ACK가 625보다 17.057 / 16.979 ms 앞당겨졌다. 최종 업로드 허가는 237 / 238번 선이었고, 화면 공개는 246 / 247번 선이었다. ARM Flash는 120 B 초과했다. [634 결과](../nes-overlap634-results.ko.md)

633은 목표 VBlank에 map 1,152 B DMA를 양쪽 모두 마감 전에 완료했고, 951 최종 ACK가 0.687 / 0.647 ms 빨라졌다. 그러나 SEAL 수락이 246번 검사선보다 3.100 / 3.670 ms 늦어 951 표시는 4 / 4회였다. [633 결과](../nes-bank633-results.ko.md)

632는 두 검사를 함께 앞당겨 업로드 진입을 1.500 / 1.504 ms 줄였다. 마지막 HDMA 자체가 목표 검사선보다 4.796 / 5.559 ms 늦어 951 표시는 4 / 4 VBlank, 951 ACK는 공통 대조군보다 0 / 28 master clock 늦었다. 621을 유지한다. [632 결과](../nes-seal632-results.ko.md)

후반 map 전송은 672B 줄었지만 여덟 패킷의 소비 ACK 합이 약 4.56→6.15ms로 늘었다. 팔레트·OAM을 먼저 보내 OAM이 7.735ms 이상 마감 앞에 도착해도 951은 4 VBlank였다. 기존 수신기에 마지막 OBJ 뒤 모든 명령을 즉시 제공해도 SEAL은 마감보다 1.201 / 1.448ms 늦었다. 두 번째 행 직전 STOP과 중단된 두 뱅크에서의 cold 2화면 복구를 확인했다.

## 후속작업

621을 유지하고 634의 조합에서 무료로 둔 팔레트·OAM 이력 확인을 실제 수신 명령으로 대체한다. 두 위상의 951 표시·최종 ACK, 특히 위상 2의 246번 선 공개 여부를 먼저 확인한다. 조건을 지키는 후보로 END/drain 이후 export, 이전 ACK·EA 뒤 D3, STOP·cold와 952 캡처 중 951 OBJ cache 소유권을 결합한다. ARM Flash 120 B를 회수하고 957까지 연속 검증 후 실기로 간다. 보드 준비는 616B, 실기는 MMC613이다.
