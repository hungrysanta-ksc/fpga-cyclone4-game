## 목표

MMC613 실기의 출력·최종 ACK 31.63 ms에서 먼저 줄일 구간을 정한다.

## 작업내용

619에서 618의 후반 BG·OBJ 544B를 생산·E1·수락·DMA까지 추적했다. 늦은 tile 허용과 독립 검사 단축을 분리·결합해 두 시작 위상의 53화면과 65816 거부 경계를 비교했다.

618에서 955 OAM 발행 시각과 954 검사 후 DMA를 고정 도착 재생으로 분리한 뒤, ARM 준비 순서·조건부 발행과 65816을 세 가지 구성으로 연결해 두 위상의 53화면을 검증했다.

617에서 BG 계획 중 확정된 다음 map 행을 ARM이 추가로 발행하도록 연결하고, 두 시작 위상에서 65816 수락·실제 VBlank DMA·마지막 ACK를 대조했다.

616에서 수락된 연속 map의 65816 선행 DMA를 최대 1,152 B로 늘렸다. 두 빔 경계 후보를 53화면 연속 일정·고정 도착 대조·STOP/새 head/독립 검사로 검증했다.

MMC577·MMC613의 두 시작 위상에서 같은 세대의 map·OBJ 작업 52쌍을 확인하고, ARM 출력 함수 전체를 SEAL 발행·65816 수락·검사·DMA·VBlank·ACK 복귀로 나눴다.

## 성과

619의 검사 단독 후보는 마지막 ACK를 두 위상에서 16.700 / 16.676 ms 앞당겼다. 밀집 합계는 22 / 22→22 / 21 VBlank로, 위상 2에서 955가 한 번 줄었다. 결합 후보는 954 tile 544B 전부를 같은 VBlank에 썼지만 이미 246번 표시 마감을 지났고 위상 1의 마지막 ACK가 33.236 ms 늦어 제외했다. [619 검증](../nes-tile619-results.ko.md)

618의 최종 후보는 955의 첫 map 192B와 마지막 384B를 모두 선행 전송했다. 954는 검사 뒤 같은 VBlank에 두 위상 모두 192B를 썼다. 616B 대비 밀집 평균은 0.032 / 0.007 ms, 마지막 ACK는 50.027 / 33.461 ms 단축됐다. 밀집 합계는 22 / 22 VBlank였다. 6KiB 진단 ROM으로 검증했다. [618 검증](../nes-oam618-results.ko.md)

954·955 모두 첫 VBlank의 map 전송이 64→192B로 늘었다. 마지막 ACK는 49.52 / 16.37 ms 빨라졌지만 밀집 구간은 22 / 22 VBlank였고 업로드 대기는 약 15 ms로 늘어 616B를 유지한다. [617 검증](../nes-map617-results.ko.md)

252번 후보는 MMC613보다 두 시작 위상 모두 952에서 640 B를 일찍 보내 표시 간격을 5→4 VBlank로 줄였다. 밀집 합계는 23→22 VBlank이고 957 최종 대기 0회, 마지막 ACK는 33.608 / 33.499 ms 빨라졌다. [616 검증](../nes-map616-results.ko.md)

MMC613 밀집 5화면의 출력은 평균 39.94 / 40.05 ms이고 SEAL 발행까지 23.57 / 22.69 ms다. 마지막 VBlank 추가 대기는 952에서만 15.05 / 15.04 ms 발생했다. 두 위상에서 246번 검사선까지 0.191 / 0.200 ms가 부족했다. 실기 31.63 ms의 내부 비율은 추적할 수 없으며 같은 작업의 연결 일정 결과를 별도로 기록했다. [분해 결과](../nes-output615-results.ko.md)

## 후속작업

618 ARM과 619 검사 단독 후보를 대조군으로 두고 954의 두 번째 plan 묶음에서 확정된 BG를 먼저 공급한다. 직전 ROM 허용 구간에서 96회분 읽기를 마치려면 첫 요청을 적어도 1.251 / 1.216 ms 앞당겨야 한다. 실제 E9·ROM·E1·65816 수락과 두 위상의 954 표시·마지막 ACK를 함께 검증한다. 952 표시 4 VBlank·955 map 선행·957 최종 대기 0회·246번 검사선·STOP·새 패킷 우선·독립 검사를 유지한다. 보드 준비 기준은 616B, 실기 기준은 MMC613이다.
