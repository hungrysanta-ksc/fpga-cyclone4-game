## 목표

MMC613 실기의 출력·최종 ACK 31.63 ms에서 먼저 줄일 구간을 정한다.

## 작업내용

627에서 951의 확정된 raw·HDMA를 남은 map 앞 또는 map 뒤·팔레트 앞으로 옮겼다. 동일 작업량의 53화면에서 ARM 메모리 쓰기·패킹·SPI 발행·65816 수락·표시를 두 위상으로 대조하고, map 순회만 바꾼 대조군도 분리했다. [627 검증](../nes-tail627-results.ko.md)

626에서 955의 두 map 패킷 발행 순서와 65816 부분 DMA 시작 주소를 고정 도착 재생과 실제 연결 실행에서 교차했다. 선행 전송과 SEAL 뒤 전송을 행별로 합산하고, 정확히 1,344B가 수락됐을 때만 허용하는 유휴 DMA도 별도로 시험했다.

625에서 955의 BG ROM 요청·허가부터 map 수락·SEAL·첫 DMA를 추적했다. 같은 65816에서 SEAL 도착만 늦춘 재생과, 같은 ARM 바이너리에서 955의 BG·OBJ 조기 발행 한 번만 우회한 대조군으로 두 효과를 분리했다. 다섯 ARM 후보를 두 시작 위상의 53화면 연속 일정으로 비교했다.

624에서 921 SEAL 발행·ARM 반환, 922 SEAL 수락·잔여 DMA와 빔 래치, 923 첫 ROM 응답을 같은 클록으로 대조했다. 독립 수신 이력으로 확인한 여섯 raw 행 중 세 행만 전송하는 65816 경로를 621·622 A·623 T ARM에 각각 연결하고, 고정 도착 재생으로 922의 효과를 분리했다.

623에서 622 A의 팔레트 압축을 유지하고 세 번째 패킷에 ARM의 실제 소비 ACK 확인을 연결했다. 세 후보와 동일 바이너리 대조군을 두 위상씩 53화면 실행하고, A의 앞선 도착 시각을 보존한 65816 재생으로 957의 효과를 분리했다.

622에서 957의 팔레트 PUSH·수락과 16B·48B tile·1,152B map의 실제 DMA를 대조했다. 621 및 raw 준비 우선 후보 A의 세 번째 팔레트부터 도착을 바꾼 재생을 분리하고, Flash 한도 안의 다섯 ARM을 두 시작 위상씩 53화면 실행했다.

621에서 최종 표시 ACK로 확정된 대상 뱅크 이력에 따라 두 번째 BG 묶음을 발행했다. 같은 ARM 바이너리의 906에서만 조기 발행을 복원한 대조군과 두 위상의 53화면을 비교했다.

620에서 619 검사 단독 65816을 기준으로 확정 BG 묶음의 ARM 조기 발행, 직접 직렬화, map 소비 확인을 네 구성으로 연결했다. 두 위상의 53화면에서 96개 ROM 응답부터 144B의 65816 수락·PPU 쓰기와 절대 마지막 ACK까지 대조했다.

619에서 618의 후반 BG·OBJ 544B를 생산·E1·수락·DMA까지 추적했다. 늦은 tile 허용과 독립 검사 단축을 분리·결합해 두 시작 위상의 53화면과 65816 거부 경계를 비교했다.

618에서 955 OAM 발행 시각과 954 검사 후 DMA를 고정 도착 재생으로 분리한 뒤, ARM 준비 순서·조건부 발행과 65816을 세 가지 구성으로 연결해 두 위상의 53화면을 검증했다.

617에서 BG 계획 중 확정된 다음 map 행을 ARM이 추가로 발행하도록 연결하고, 두 시작 위상에서 65816 수락·실제 VBlank DMA·마지막 ACK를 대조했다.

616에서 수락된 연속 map의 65816 선행 DMA를 최대 1,152 B로 늘렸다. 두 빔 경계 후보를 53화면 연속 일정·고정 도착 대조·STOP/새 head/독립 검사로 검증했다.

MMC577·MMC613의 두 시작 위상에서 같은 세대의 map·OBJ 작업 52쌍을 확인하고, ARM 출력 함수 전체를 SEAL 발행·65816 수락·검사·DMA·VBlank·ACK 복귀로 나눴다.

## 성과

951의 raw·HDMA는 직전 표시 마감 15.738 / 15.531ms 전에 이미 확정됐다. map 앞으로 옮기자 일곱 패킷이 마감 전에 수락됐지만 팔레트·OAM 519B가 뒤로 밀렸다. 951은 두 위상 모두 4 VBlank이고 957 마지막 ACK는 −0.184 / +0.156ms였다. 동일 뱅크와 대조한 나머지 map 1,536B 중 실제 변경은 56B였다.

626에서 늦은 tile을 map으로 바꾼 뒤 길이를 판정해 두 위상 모두 955의 map 192B를 추가 선행 전송했다. 625 tables-bg 대비 SEAL 뒤 map은 512→320B, 955 ACK는 0.169 / 0.108ms 단축됐다. 밀집 구간은 20 / 20 VBlank였고 마지막 ACK는 −0.006 / +0.173ms였다. STOP·새 head 우선·독립 검사와 957 최종 대기 0회를 통과했다. 기준은 621로 유지한다. [626 검증](../nes-map626-results.ko.md)

625의 tables-bg는 두 위상에서 922를 원래 VBlank에 표시하고 923의 첫 ROM 공급을 유지했다. T + 624 대비 955 간격은 5 / 4→4 / 4, 마지막 ACK는 16.628 / 0.156ms 빨라졌다. 다만 955 후반 map의 선행 DMA가 384→192B로 줄었다. 957 최종 대기는 0회였고 위상 2의 16B tile은 한 VBlank 먼저 실행됐다. 621을 유지한다. [625 검증](../nes-seal625-results.ko.md)

623 T + 624는 두 위상 모두 922를 93→92번째 VBlank로 복구했고, 923 첫 ROM 응답은 16.640ms, 마지막 ACK는 16.634 / 49.932ms 앞당겼다. 622 A 대비 마지막 ACK도 0.082 / 16.744ms 빨랐다. STOP·새 head 우선·독립 검사와 957 최종 대기 0회를 통과했다. 955 표시 간격은 위상 1에서 4→5, 위상 2에서 5→4였다. 기준은 621로 유지한다. [624 검증](../nes-raw624-results.ko.md)

623 T는 두 위상 모두 957의 tile 16B·48B와 map 1,152B를 같은 VBlank에 보냈다. 같은 바이너리에서 957의 ACK는 0.092 / 0.084 ms 빨라졌지만, 전체 마지막 ACK는 622 A보다 16.552 / 33.188 ms 늦었다. 밀집 표시 합계는 21 / 21→20 / 21 VBlank였다. 922의 최종 검사 진입 차이 0.022 / 0.061 ms가 첫 표시 마감을 갈랐다. 621을 유지한다. [623 검증](../nes-credit623-results.ko.md)

622 C와 D는 두 위상 모두 957의 목표 세 DMA를 같은 VBlank에 실행했다. C는 위상 2에서 954 표시가 5회로 늘었고, D는 954 표시 4회를 지켰으나 619 대비 마지막 ACK가 +0.006 / +16.616 ms였다. A는 619 대비 −49.820 / −49.833 ms였으나 957의 작은 tile이 SEAL 뒤에 남았다. 선택적 drain 생략은 위상 1에서 큰 map 선행을 놓쳤다. 621을 유지한다. [622 검증](../nes-palette622-results.ko.md)

621은 906에서 E9 8→7회, 표시 10→9 VBlank, 해당 ACK 15.29 ms 단축의 원인을 분리했다. 952·954 표시 4회와 955 map 선행·957 최종 대기 0회를 유지했다. 전체 마지막 ACK는 619 대비 +0.108 / −49.844 ms였다. 위상 1에서 선행 DMA를 놓친 tile 16B·48B가 SEAL 뒤에 남았다. [621 검증](../nes-bank621-results.ko.md)

620은 두 위상 모두 직전 ROM 구간에서 96회 읽기를 끝냈고, 두 구성에서 954 표시가 5→4 VBlank로 줄었다. 가장 좋은 D는 619 대비 마지막 ACK가 위상 1에서 0.108 ms 늦고 위상 2에서 16.560 ms 빨랐다. 952 표시 4회·955 첫 192B와 마지막 384B 선행·957 최종 대기 0회·STOP·새 패킷 우선·독립 검사·246번 검사선을 확인했다. [620 검증](../nes-bg620-results.ko.md)

619의 검사 단독 후보는 마지막 ACK를 두 위상에서 16.700 / 16.676 ms 앞당겼다. 밀집 합계는 22 / 22→22 / 21 VBlank로, 위상 2에서 955가 한 번 줄었다. 결합 후보는 954 tile 544B 전부를 같은 VBlank에 썼지만 이미 246번 표시 마감을 지났고 위상 1의 마지막 ACK가 33.236 ms 늦어 제외했다. [619 검증](../nes-tile619-results.ko.md)

618의 최종 후보는 955의 첫 map 192B와 마지막 384B를 모두 선행 전송했다. 954는 검사 뒤 같은 VBlank에 두 위상 모두 192B를 썼다. 616B 대비 밀집 평균은 0.032 / 0.007 ms, 마지막 ACK는 50.027 / 33.461 ms 단축됐다. 밀집 합계는 22 / 22 VBlank였다. 6KiB 진단 ROM으로 검증했다. [618 검증](../nes-oam618-results.ko.md)

954·955 모두 첫 VBlank의 map 전송이 64→192B로 늘었다. 마지막 ACK는 49.52 / 16.37 ms 빨라졌지만 밀집 구간은 22 / 22 VBlank였고 업로드 대기는 약 15 ms로 늘어 616B를 유지한다. [617 검증](../nes-map617-results.ko.md)

252번 후보는 MMC613보다 두 시작 위상 모두 952에서 640 B를 일찍 보내 표시 간격을 5→4 VBlank로 줄였다. 밀집 합계는 23→22 VBlank이고 957 최종 대기 0회, 마지막 ACK는 33.608 / 33.499 ms 빨라졌다. [616 검증](../nes-map616-results.ko.md)

MMC613 밀집 5화면의 출력은 평균 39.94 / 40.05 ms이고 SEAL 발행까지 23.57 / 22.69 ms다. 마지막 VBlank 추가 대기는 952에서만 15.05 / 15.04 ms 발생했다. 두 위상에서 246번 검사선까지 0.191 / 0.200 ms가 부족했다. 실기 31.63 ms의 내부 비율은 추적할 수 없으며 같은 작업의 연결 일정 결과를 별도로 기록했다. [분해 결과](../nes-output615-results.ko.md)

## 후속작업

621을 유지하고 625 tables-bg를 시간 대조군으로 쓴다. 951에서 대상 뱅크의 최종 ACK를 근거로 변경된 map 그룹만 전송하는 경우와 BG map 확정 뒤 SPI가 빈 2.871ms에 확정 행을 발행하는 경우를 분리한다. 독립 복원·손상 검사·STOP·cold 전체 복구·새 head 우선을 유지한 실제 ARM·65816 비용을 먼저 측정한다. 두 위상에서 951·밀집 표시와 957 마지막 ACK가 함께 빨라지는지 확인한다. 보드 준비 기준은 616B, 실기 기준은 MMC613이다.
