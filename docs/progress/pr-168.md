# MMC855 무입력 데모의 출력과 최종 ACK

## 목표

PR167 머지 커밋 `db2309d`에서 시작했다. 실기 30–60초 구간의 MMC855 출력·최종 ACK 47.81ms가 어떤 작업을 포함하는지 확인하고, 다음 표시 마감을 앞당길 대상을 정한다.

## 작업내용

- 826·855의 원본 실기 budget 로그에서 5초 버킷을 시작 시각별로 짝지었다. 화면당 mapdirty·OBJ·BG 세 지표에서 두 실행의 상대 차이 중 최댓값이 가장 작은 구간을 골랐다. 분모는 MMC826이다.
- dot 0부터 보정한 무입력 데모 원본 2560–2619를 순서대로 두 위상에서 재생했다. 앞선 두 장은 뱅크 준비에 사용했다. 두 판 모두 MMC855 실기의 명령별 SPI 평균 비용과 같은 ROM 허가 일정을 썼다. 실제 ARM 실행 중 출력 단계 계측 함수의 시작 카운터와 종료 시각, credit 대기 함수의 진입·복귀를 관찰했다. 실제 65816 수신·PPU DMA·표시와 ACK의 순서를 대조했다.
- SEAL 전 SPI, SPI를 뺀 poll 서비스와 남은 ARM 시간, SEAL 전송 완료 후 65816 수락, 수락 뒤 서비스·DMA·VBlank 대기, ARM 최종 확인으로 시간을 한 번씩 계상했다. 큐가 찬 시간과 다음 입력 SPI는 이 시간과 겹칠 수 있어 별도로 기록했다.

## 성과

실기에서 세 작업량 차이의 최댓값이 가장 작았던 구간은 40–45초(2.11%)였다. MMC826 71장과 MMC855 73장의 화면당 BG는 525.59→525.67, OBJ는 24.00→24.01, mapdirty는 4.37→4.27이었다. 수신은 6.76→0.41ms, 계획은 10.00→10.14ms, 출력·최종 ACK는 52.82→56.44ms였다. 출력 시간 증가는 작업량을 맞춰도 관측됐다. 실기의 5초 평균만으로 특정 원본 화면의 마감 사유를 식별할 수는 없다.

같은 원본 60장의 재생에서는 두 판의 map 주소 범위와 map·BG·OBJ 바이트가 전부 일치했다. 아래는 화면당 평균 ms이며 각 칸은 MMC826 → MMC855 순서다.

| 출력 계측 구간 | 위상 1 | 위상 2 |
|---|---:|---:|
| SEAL까지 공유 SPI 점유 | 6.737 → 6.604 | 6.743 → 6.609 |
| credit 조회 함수에서 SPI를 뺀 시간 | 0.543 → 0.777 | 0.545 → 0.783 |
| 나머지 조회 함수에서 SPI를 뺀 시간 | 0.746 → 1.176 | 0.748 → 1.174 |
| 그 밖의 ARM 발행·IRQ 처리 | 1.374 → 1.447 | 1.375 → 1.452 |
| SEAL 전송 완료부터 65816 수락 | 0.109 → 0.099 | 0.113 → 0.105 |
| 65816 검사·설정·표시·ACK 처리 | 2.558 → 2.556 | 2.557 → 2.555 |
| 최종 DMA 전송 | 0.425 → 0.423 | 0.424 → 0.423 |
| 마지막 VBlank 대기 | 6.573 → 6.994 | 6.574 → 7.005 |

출력 계측이 길어진 가장 큰 항목은 65816이 이미 최종 ACK를 기록한 뒤였다. 이 구간에서 다음 입력을 옮긴 SPI 시간만 1.591→4.823ms와 1.551→4.818ms였다. 다음 화면의 작업이 이 경계로 이동한다. 두 위상 모두 실제 표시 간격 합은 139→133 VBlank로 줄었고, 마지막 원본 2619의 ACK도 각각 2,859,110클록과 2,501,572클록 빨라졌다.

큐가 가득 찬 뒤 첫 65816 ACK까지의 시간은 MMC855에서 평균 0.918/0.914ms였고, 거기서 ARM이 반환을 확인하기까지 0.618/0.618ms였다. 이 값은 위 표의 SPI와 ARM 실행에 겹친다.

## 후속작업

첫 대상으로 원본 2616을 선택했다. 두 위상 모두 map 1,472B·BG 16B·OBJ 64B를 처리한다. 마지막 OBJ 반환부터 SEAL 수락까지 2.806ms가 들었다. SEAL은 196/195선에 수락했으나 최종 업로드의 VBlank 대기 루틴에는 225선에 들어와 각각 16.616/16.641ms를 더 기다렸다. 최종 DMA 1,858B의 전송 시간은 두 위상 모두 0.724ms였다.

다음 실험은 마지막 OBJ 반환 뒤 E0 조회와 일반 패킷 발행 순서를 바꿔 독립 검사를 마치고 225선 전에 대기에 진입시키는 것이다. 합격 기준은 두 위상 모두 2616을 3→2 VBlank에 표시하고 60장 간격 합과 마지막 ACK도 같이 줄이는 것이다. 오프닝·전환, STOP·cold 복구·독립 검사·메뉴 복귀를 함께 대조한다.

## 857의 원본 2616 발행 실험

MMC855에서 마지막 OBJ를 반환한 뒤 65816은 section 5의 압축 raw 세 범위(각 64B), 테이블과 길이 정보(240B·9B), SEAL을 차례로 수락했다. 2.806ms 중 공유 SPI 점유는 두 위상 모두 2.290ms였다. 이 구간과 일부라도 겹친 거래는 E1 다섯 번, E0 세 번, E8 한 번, D0 한 번이었다. 225선에서 기록한 수평 클록과 재생에서 관측한 인접 VBlank의 길이로 역산하면 대기 루틴 진입은 시작선보다 약 54µs·16µs 늦었다.

| 후보 | 변경 | 최종 설치용 ARM 크기 | 212,992B 한도 여유 |
|---|---|---:|---:|
| MMC855 | 기준 | 212,984B | 8B |
| 857A | 수락된 OBJ 뒤 section 5 전용 발행 조건 추가 | 213,040B | −48B |
| 857B | 신규·반복 tile descriptor의 완료 처리를 한곳에 두고, 미확인 receipt 뒤 후속 명령을 최대 3개까지 허용 | 212,972B | 20B |
| 857C | 같은 순서의 테이블·길이 249B를 128B·121B로 나눠 첫 패킷을 일찍 공급 | 212,980B | 12B |
| 857D | 실제 receipt를 회수한 직후 E8을 한 번 일찍 조회 | 213,000B | −8B |

857B도 E8의 CRC·token·descriptor 전체 일치, E1의 실제 큐 credit·STOP, SEAL의 완료 확인과 65816 독립 검사를 거친다. 857C는 두 패킷의 경계만 바꾸며 ARM 구조체의 정렬용 바이트를 전송하지 않는다. A·D는 Flash 한도에서 제외했다.

| 원본 2616 | MMC855 위상 1 / 2 | 857B 위상 1 / 2 |
|---|---:|---:|
| 직전 표시부터 마지막 OBJ 반환 | 27.929 / 27.895ms | 27.975 / 28.031ms |
| 마지막 OBJ 반환부터 SEAL 수락 | 2.806 / 2.805ms | 2.421 / 2.421ms |
| SEAL 수락선 | 196 / 195 | 190 / 191 |
| VBlank 대기 진입선 | 225 / 225 | 220 / 221 |
| VBlank 대기 | 16.616 / 16.641ms | 0.326 / 0.269ms |
| 표시 간격 | 3 / 3 VBlank | 2 / 2 VBlank |

위상 1에서 MMC855는 OBJ 반환 뒤 0.758/0.910ms에 두 번째·세 번째 raw 패킷을 발행했다. 857B는 두 패킷을 각각 반환 1.178/0.272ms 전에 발행해 큐에 두었다. 65816에서의 수락은 OBJ 뒤 순서를 지켰고, 이후 240B 테이블 수락도 1.832→1.677ms로 앞당겨졌다.

같은 60장 전체에서 2561과 2616이 각각 1 VBlank 빨라졌고 2617이 1 VBlank 늦어졌다. 두 위상에서 누계는 133→132 VBlank, 마지막 ACK는 각각 16.637/16.626ms 빨라졌다. 2616의 최종 ACK까지 끝난 2617 입력의 D2 반환은 16/16건에서 1/0건으로 줄었다. 총 17건을 완료하는 시각은 직전 ACK 뒤 1.281/1.296ms에서 10.784/10.808ms가 됐다. 다음 화면이 사용할 입력의 준비 시각도 이전 화면의 표시와 함께 보아야 한다.

857C에서는 같은 249B를 같은 순서로 재구성했지만 2616은 3/3 VBlank에 머물렀다. 60장 간격 합은 133/133으로 같고 마지막 ACK는 위상 1에서 0.009ms 빨라지고 위상 2에서 0.019ms 늦어졌다. 패킷 분할 변경은 채택하지 않는다.

오프닝의 간격 합은 MMC855 126/128→857B 127/126 VBlank였다. 최종 ACK가 위상 1에서는 16.508ms 늦고 위상 2에서는 33.452ms 빨랐다. 위상 1에서 원본 703·759가 각각 한 번 늦고 706이 한 번 빨라졌다. 전환은 120/120 VBlank를 유지했고 최종 ACK는 0.017/0.010ms 빨랐다. 빈 캡처 12장의 경계에서 16 VBlank 동안 기존 화면과 뱅크를 보존했다. B는 데모 개선을 재현하는 대조군으로 둔다.

MMC855의 준비 화면을 포함한 62장 중 section 5의 반복 명령(op 4)이 나온 화면은 오프닝 0장, 밀집 데모 62장이었다. E에서는 앞선 명령이 이 형식이고 아직 receipt가 남아 있을 때만 다음 일반 명령을 허용했다. 대상 receipt와 송신 번호 사이 거리가 3 미만이고 STOP 검사를 통과해야 한다. E는 213,036B였다. 같은 동작에서 plan 오류 처리를 모은 F는 213,008B, 출력 오류 처리까지 모은 G는 212,996B로 여전히 4B 초과였다. H는 M4에서 한 번의 little-endian 읽기로 컴파일되는 token 해석을 호출 지점에 넣었다.

857B에서 WRAM 손상은 0xE0, 행 처리 중 STOP은 0xE4로 거부했다. 첫 행만 쓴 시점의 STOP에서 나머지 22행과 표시 뱅크를 보존했고 재시작 후 두 뱅크를 cold 경로로 복구했다. ARM의 STOP 및 최종 ACK identity 오류 주입에서는 해당 세대의 이력, EA, 다음 입력 COMMIT이 공개되지 않았다. 같은 전체 링크에서 메뉴와 base 복귀도 확인했다. 메뉴·base 시험의 프로그래머·입출력은 모델을 사용했다.

857H는 212,980B(여유 12B)로 전체 링크됐다. 신규 발행 조건에 실제로 진입한 세대 913에서 STOP을 넣었을 때 E1·EA·다음 COMMIT이 모두 차단됐다. 독립 WRAM 손상 검사, 부분 STOP·cold 복구, 최종 ACK 오류와 메뉴·base 경로도 통과했다.

| MMC855 → 857H | 위상 1 표시 간격 합 | 위상 2 표시 간격 합 | 마지막 ACK 차이(위상 1 / 2) |
|---|---:|---:|---:|
| 오프닝 | 126→127 | 128→126 | +16.721 / −33.391ms |
| 전환 | 120→120 | 120→120 | −0.017 / −16.663ms |
| 밀집 데모 | 133→133 | 133→133 | −0.005 / +0.007ms |

H도 2616을 두 위상에서 3→2회로 줄였지만 2617에서 2→3회가 되어 60장 이득이 사라졌다. 실기 기준은 MMC855를 유지한다. 다음 비교는 데모 누계에서 이긴 857B를 대조군으로 사용한다. 2617의 입력 준비부터 첫 D1 발행까지는 이미 0.127/0.147ms이고, 입력 준비부터 직전 표시 ACK까지 겹칠 수 있는 시간 자체가 17.120/17.110→0.484/0.480ms가 됐다. 2617 업로드 대기 진입은 VBlank 시작선보다 43/263µs 늦다. 이 화면의 SEAL 수락·검사와 잔여 DMA 준비를 함께 앞당길 여지를 우선 검증하고, 오프닝 위상 1의 703·759를 보호 조건으로 둔다.
