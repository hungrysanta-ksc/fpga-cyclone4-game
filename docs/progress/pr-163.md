## 목표

PR162가 master `71f50d1`에 병합된 시점의 MMC807·808을 실기 기준으로 삼는다. 첫 레벨에서 작업량이 가까운 구간을 찾고, ARM의 SPI 응답 검사 비용을 줄였을 때 연속 표시 간격과 마지막 ACK가 함께 앞당겨지는지 확인한다.

## 작업내용

- 실기 MMC805·807의 5–55초를 5초씩 나눴다. 같은 시간대에서 화면당 변경 map·OBJ·BG가 각각 MMC805 대비 20% 이내인 구간을 골랐다. 20–25초의 평균 출력·최종 ACK는 30.71→30.00ms, 25–30초는 33.23→26.38ms였다. 각 판의 플레이 횟수는 한 번이고 실기 로그의 시간 단위는 10ms다.
- ARM 후보 809는 입력·plan·큐 상태의 CRC-8을 같은 다항식으로 한 바이트씩 계산한다. 매 응답의 전체 검사 범위와 세대·토큰·실제 소비 검사를 유지한다. 60초판과 장시간판을 각각 전체 링크하고, CRC 바이트 전이 256종과 길이 0–246B의 9개 벡터를 두 최종 ARM에서 실행했다.
- 일정 비교에는 60초판을 사용했다. 같은 ROM·입력 905–970·65816·SPI 드라이버 비용·IRQ·ROM 허가 구간을 두고 시작 위상을 바꿔 대조군과 후보를 각각 재생했다. ARM·65816은 링크된 코드를 실행한다. ARM은 CPI 2, ROM 경쟁은 기록한 허가 일정의 반복으로 모델링한다. 실기와 map·OBJ가 비슷한 캡처는 949와 950이다. BG까지 같은 실기 화면은 특정할 수 없다.

## 성과

18B CRC 검사는 1,267→241 ARM 명령, 6B는 427→85 명령이다. Flash는 60초판 212,988→212,956B, 장시간판 212,948→212,916B로 각각 32B 줄었다. 두 링크 모두 152개 ACK 비트 반전, 수신 중 STOP, 연속 OBJ 초과 뒤 정상 복구, 메뉴 복귀 코드 경로를 통과했다.

두 위상 모두 934·940·943이 3→2 VBlank가 됐다. 밀집 구간에서 VBlank가 실제로 줄어든 화면은 위상 2의 970(4→3)이다. 네 재생에서 각 66회 최종 ACK와 map WRAM·VRAM 검사를 완료했다. 같은 위상의 대조군·후보는 66개 화면 모두 기대 map, 실제 map, 표시 RGB가 바이트 단위로 일치했다.

실기와 map·OBJ 작업량이 가까운 949·950에서는 MMC807의 SEAL 이후 업로드 VBlank 대기가 각각 9.50–9.57ms·10.83–10.92ms였고 마지막 표시 대기는 0회였다. 809에서는 각각 11.01–11.18ms·11.93–12.13ms로 늘었다. 검사가 빨라져도 다음 전송 가능 시각까지 조회를 더 자주 하므로, 전체 SPI 전송량은 11,472B·10,432B 늘었다. 동일 화면의 물리 FPS 변화는 미측정이다.

후보는 두 위상에서 951 공개가 248선이었다. 65816이 직전 VBlank에 OAM·section 5 패킷을 소비하는 동안 BG 16B와 map 192+1,344B가 남았다. 위상 1에서 대조군은 227·230·235선에 이 세 DMA를 시작했고, SEAL 뒤 남은 전송량은 690B였다. 후보는 2,242B를 SEAL 뒤에 전송했다. 새 실기판의 246선 공개 조건을 충족하지 못해 실기 기준은 MMC807·808로 유지한다.

## 후속작업

1. 951에서 BG 16B와 map 1,536B를 수락한 뒤, 다음 ordinary 발행이 기존 빈 큐 DMA 기회를 차지하는 시점을 기준판과 맞춘다. 65816의 새 패킷·STOP 우선순위는 보존한다. 두 위상에서 공개 246선 이내를 먼저 확인한다.
2. 959는 후보의 DMA 대기 진입이 가시 구간 3·4선이다. 남은 DMA와 검사를 같은 속도로 수행해 직전 246선까지 검사하려면 보수적으로도 2.045·2.107ms 앞당겨야 한다. 각 줄의 수평 위치와 추가 설정 비용을 제외한 하한이다. 마지막 240B 테이블에서 211개의 0을 모두 생략해도 SPI 데이터 절약은 0.643ms다. 마지막 OBJ 반환과 후속 패킷 발행·수락을 함께 추적해 잔여 DMA를 앞당긴 뒤, 959 표시 3→2회와 951→970 간격·마지막 ACK를 다시 비교한다.
