# PR136 — NES484–486: BG·bulk ACK 연결과 SMB3 플레이 실기 비용

[GitHub PR136](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/136), 병합 완료: `2d4543ef2442bc798bcec128a4a108fdfc4d5287`. 후속은 [PR137](pr-137.md). PR135 merge948a2e9 뒤 새 브랜치에서 진행한다. 현재 MMC485 실기는 대기13.55fps/첫 레벨 플레이 포함8.22fps다. 다른 장면의482와 직접 개선율을 비교하지 않으며 전체 가속은 미입증이다.

## 목표

482의 계획/공급32.32ms를 줄이기 위해 실제 중복 계산과 첫 BG 발행·bulk 소비/ACK 대기를 함께 다룬다. 독립 검사·credit/실제 소비 구분·STOP·최종 ACK·VBlank·메뉴 복귀·정상 원복을 유지하고, 전체 시간으로 판정한다.

## 작업내용

- 484에서 실제 M4/게임71입력을 계측하고 exact-hit의 불필요한 형태 분류와 BG/OBJ40B 중복 초기화를 없앴다.
- 485에서 첫 BG 뒤 E9를 선행 발행하고 emit 기회마다 한 번 E8를 확인한다. bulk를 기존 window에 큐잉한 뒤 descriptor12B/pending을 추적한다. 같은 token을 중복 제출하지 않고 다음 descriptor/finish 전 실제 matching ACK를 drain한다.
- 초기 기능 통과 후보에서 E8 busy-spin을 발견했다. 실제 대기 반복은 기존128µs guard를 재사용하도록 수정하고 다시 M4·RTL/65816을 검증했다. 계산 중 emit에는 이 대기를 넣지 않는다.
- 기존 FPGA482·wire/client ABI를 유지한다. 실제 source/PSRAM/ROM 중재·SPI·65816 DMA/ACK/VBlank/STOP과 전체 픽셀을 확인했다. 모델의 ARM/IRQ 시간 한계도 기록했다.
- 새 메뉴/ROM/FPGA alias/3로그를 MMC485로 갱신하고482/476/164/467 원복을 보존한 개인 비교본을 만들었다. 이번486에서 실제 두 실행을 수신해 현재 문서와 다음 순서를 갱신했다.

## 후속작업

1. 고정 입력에서 source/output/plan 본문과 map/HDMA/OAM/manifest·stale-bank 업로드 원인을 분해한다. map_dirty를 실제 업로드 바이트로 오해하지 않는다.
2. 전체 SEAL48.33ms의 ARM 전송·SPI·65816 수신/독립 검사/DMA/VBlank를 함께 다룬다. 데이터 절감과 검증된 SPI 속도 여유를 비교하되 새 속도는 아직 채택하지 않는다.
3. D0/source 준비 대기를 확인한다. 현재 MCU_RDY는 external_memory_ready이며 source-ready IRQ가 아니다. 역사367 IRQ가 배포됐다고 가정하지 않는다.
4. 의미 있는 변경 후 같은 장면·입력으로 전체 시간을 비교한다. 현재 평균121.60ms/60Hz 격차104.93ms, Flash232B/FPGA154LE 제약과 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 유지한다. capture/p95/NES 속도·full stack/CDC/IO·MMC4/5는 미완료다.
