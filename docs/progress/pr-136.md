# PR136 — NES484: 실제 ARM 계획 절감과 공급 병목 분리

[GitHub PR136](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/136), 초안·진행 중. PR135 merge948a2e9의 master 반영 후 `codex/nes-game-plan-supply-484`에서 시작했다. 현재 실기는 MMC482의14.60fps이며,484는 미실기 ARM 후보다.

## 목표

계획/공급32.32ms의 계산과 대기를 분리하고 실제 중복 작업을 없앤다. 전체60Hz까지의51.82ms 차이를 작은 명령 절감으로 해결했다고 표시하지 않는다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀와 검증된482/476 원복을 유지한다.

## 작업내용

- 실제482 ELF와 기존 게임 입력71개로 함수별 실행 명령을 측정했다. 이전478의 전체 상태와40B 출력 계획까지 대조했다.
- resident exact-hit에서 사용하지 않는 형태 분류를 miss 뒤로 옮기고, BG·OBJ의 중복 memset을 모든 필드의 명시적 할당으로 대체했다. 실제484 ARM 전체 firmware를 빌드했다.
- 현재 allocator 두 버전에 기존 충돌·cold/epoch·세대 wrap·고갈·writer/commit 오류·abort 회귀를 적용했다. 이번에는 resident 인덱스까지 전체 상태를 비교했다.
- 현 E9 append/finish 정책을 실제 계획에 투영하고, 기존480 RTL의 E8 응답23개를 CRC/ABI까지 분류했다. FPGA482는 유지하고 변경 없는 합성을 반복하지 않았다.
- [검증 JSON](../../analysis/game484-planner.json)·[상세 보고](../nes-game484-planner.ko.md)·[관문/예산](../nes-game484-next-plan.json)에 재현 경로와 한계를 남겼다. root README의 실기 수치는 바꾸지 않았다.

## 후속작업

1. **G2B:** 첫 BG 묶음과 op7 bulk in-flight/lease 소유권을 함께 연결한다. 기존 plan buffer/window를 재사용하고 저장 credit·실제 소비/ACK·staging 해제를 구분한다. 미완료 token 중복 발행·STOP 뒤 재개를 막는다.
2. **G2C:** 같은 ROM 위상에서484 ARM+482 RTL+SPI/IRQ/4credit/65816 전체 일정을 비교한다. 추가 E9 framing·E8 검사와 기존 polling 대체 여부, continuous capture를 모두 계산한다.
3. **G3:** 수신17.16ms·SEAL/최종 ACK18.44ms도 포함해60Hz 가능성과 stack/CDC/IO 미완료를 다룬다. 실제 RTL을 바꿀 때만 Lite whole 합성/관련 timing을 갱신한다.
4. **G4:** 전체 경로에서 의미 있는 개선이 검증되면 새 파일명·로그·marker·원복으로 동일 ROM/입력의 실기를 비교한다. 명령 수 계측만 바꾼 전달본을 반복하지 않는다.
