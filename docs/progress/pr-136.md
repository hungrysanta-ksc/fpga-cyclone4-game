# PR136 — NES484–485: ARM 계획 절감과 BG·bulk ACK 소유권 연결

[GitHub PR136](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/136), 초안·진행 중. PR135 merge948a2e9 뒤 새 브랜치에서 진행한다. 현재 실기는 MMC482의14.60fps이며,485의 전체 시간 감소는 미확정이다.

## 목표

482의 계획/공급32.32ms를 줄이기 위해 실제 중복 계산과 첫 BG 발행·bulk 소비/ACK 대기를 함께 다룬다. 독립 검사·credit/실제 소비 구분·STOP·최종 ACK·VBlank·메뉴 복귀·정상 원복을 유지하고, 전체 시간으로 판정한다.

## 작업내용

- 484에서 실제 M4/게임71입력을 계측하고 exact-hit의 불필요한 형태 분류와 BG/OBJ40B 중복 초기화를 없앴다.
- 485에서 첫 BG 뒤 E9를 선행 발행하고 emit 기회마다 한 번 E8를 확인한다. bulk를 기존 window에 큐잉한 뒤 descriptor12B/pending을 추적한다. 같은 token을 중복 제출하지 않고 다음 descriptor/finish 전 실제 matching ACK를 drain한다.
- 초기 기능 통과 후보에서 E8 busy-spin을 발견했다. 실제 대기 반복은 기존128µs guard를 재사용하도록 수정하고 다시 M4·RTL/65816을 검증했다. 계산 중 emit에는 이 대기를 넣지 않는다.
- 기존 FPGA482·wire/client ABI를 유지한다. 실제 source/PSRAM/ROM 중재·SPI·65816 DMA/ACK/VBlank/STOP과 전체 픽셀을 확인했다. 모델의 ARM/IRQ 시간 한계도 기록했다.
- 새 메뉴/ROM/FPGA alias/3로그를 MMC485로 갱신하고482/476/164/467 원복을 보존한 개인 비교본을 만들었다. root README의 실기 수치는 바꾸지 않았다.

기능 결합의 ARM은 C 어댑터이며 M4·IRQ 공통 물리 시계가 아니다. 실제 M4 소유권 시험도 endpoint/DWT는 모델이다. 시뮬레이션 종료 시각·명령 수·줄어든 polling을 실제 전체 시간/FPS로 환산하지 않는다. 원복·FPGA는 기존 바이트와 대조했고 상용 ROM을 새로 포함하지 않았다.

## 후속작업

1. **다음은485 실기 비교(G4→G2C).** 새3TXT로 완료 프레임·수신/계획·공급/SEAL·최종 ACK DWT와 driver/IRQ/ROM·종료 미완료 상태를 함께 비교한다. 사용자가 메뉴 복귀도 확인한다.
2. 같은 ROM만으로 같은 장면이 보장되지는 않는다. 추가 E9/E8·nested quiet 비용을 모두 보고, 지연을 다른 단계로 옮긴 후보나 기능 통과만으로 시간 개선을 승인하지 않는다.
3. 측정 뒤 수신17.16ms/SEAL18.44ms 또는 공급 후속을 정한다. 필요 시 실제 M4/IRQ 공동 시계를 보강한다.60Hz·capture/p95/NES 속도·full stack/CDC/IO는 미완료다.
4. RTL이 실제로 바뀔 때만 Lite whole 합성/관련 timing을 갱신한다. 정상482와 GBC/save·476/164/467 원복을 보존한다.
