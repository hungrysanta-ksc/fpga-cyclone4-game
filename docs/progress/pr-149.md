## 목표

MMC558의 952 표시 간격을 6 VBlank에서 5 VBlank로 줄일 수 있는지 확인한다. 같은 입력과 두 시작 위상에서 밀집 구간과 마지막 ACK를 함께 평가한다.

## 작업내용

PR148 병합을 확인하고 MMC558에서 분기했다. 952의 E9 수락, 슬롯별 ROM 허가, 48B BG 패킷과 마지막 OBJ 소비, 65816 SEAL·DMA·표시를 한 시간축에서 비교했다. 실제 ARM에서 기존 SPI 버퍼를 재사용해 연속 OBJ 슬롯 39–50을 먼저 보내는 후보를 구현했다.

561에서는 기존 ARM 순서를 유지하고 FPGA가 검사를 마친 다음 목적지에서 불연속을 확인하면 완성된 chunk를 일찍 공개하도록 구현했다. 실제 RTL의 읽기·소비·STOP·재시작을 검증하고, M4·SPI·IRQ·ROM·65816 연속 일정과 Quartus Lite 전체 FIT·STA를 비교했다.

562에서는 CHECK와 RUN의 reader 소유권을 분리하고 NES RAM 초기화 완료를 로컬 요청·ready에 연결했다. 같은 seed·제약에서 두 경로의 실제 배치 끝점, 전체 코너, 두 위상의 연속 일정을 다시 대조했다.

563에서는 클록 감시기의 정상 시작 허가와 고장 시 비동기 차단을 분리했다. 참조·메모리 클록을 세 시점에서 멈춰 읽기 취소와 공통 reset 후 복구를 검증했고, 배치된 주소 전체의 setup과 동기화 첫 단의 토글 도착을 실제 캡처 에지에 맞춰 비교했다.

564에서는 SPI 인자 바이트의 일곱 번째 비트에서 쓰기 허가를 저장했다. 두 위상의 차등 RTL 시험에서 256가지 인자와 SS 중단·오류·CHECK·START·STOP을 검증하고 전체 보드와 53화면 재생을 대조했다.

565에서는 ROM_OE의 중복 선택과 host 취소 reset의 해제 경로를 바꿨다. PSRAM 핀 출력·데이터 샘플의 배치 예산과, core reset 전후 같은 물리 뱅크를 쓰는 실제 RTL의 준비·읽기·소비 시각을 따로 검증했다.

566에서는 MMC558 ARM의 RESET 구동·피드백과 STOP·다음 START 명령을 실행했다. 두 위상에서 실제 65816의 마지막 OBJ 읽기와 토큰 쓰기에 취소를 주입하고 버스 쓰기를 565 RTL에 재생했다.

567에서는 기록·준비 ACK 양쪽의 mailbox에 로컬 reset 해제를 적용하고, 수신 완료만 바꾼 대조군과 전체 보드·클록 정지·표시 일정을 비교했다.

## 성과

슬롯 39의 첫 ROM 허가는 두 위상 모두 약 83→50ms로 앞당겼으나, 마지막 개별 슬롯 34가 같은 83ms 구간까지 기다렸다. 952는 6 VBlank, 951–955 합계는 26 VBlank 그대로였다. 957 마지막 ACK는 각각 0.011ms 늦어지고 0.018ms 빨라졌다. 두 일정 모두 53화면의 RGB·타일·map과 독립 재생이 일치했고 952·954·957의 최종 대기는 0회였다. Flash는 104B 늘어 한도를 20B 초과했다. 실기 기준은 MMC558을 유지한다. [두 위상 결과](../nes-supply560-results.ko.md) · [검증 데이터](../../analysis/supply560-verification.json)

561의 조기 공개는 두 위상에서 모두 952 표시를 6→5 VBlank, 밀집 합계를 26→25 VBlank로 줄였다. 53번째 화면의 마지막 ACK도 82.989 / 33.501ms 빨라졌다. 두 위상 모두 53개 RGB와 소비·표시 검사를 통과했다. 전체 FIT는 15,256 LE로 성공했으나 기존 음수 STA 항목 6개가 악화되어 실기 전달을 보류했다. [561 비교와 다음 경로](../nes-close561-results.ko.md) · [검증 데이터](../../analysis/close561-verification.json)

562에서 loader phase→request toggle과 init_done→reader memory reset 경로를 제거했다. RTL에서 전체 384KiB 적재와 읽기 중 STOP·재시작을 검증했다. 위상별 965개 reader 이벤트가 561과 일치했다. 53화면의 표시·ACK도 양쪽 위상에서 같고 전체 FIT는 15,213 LE로 43개 줄었다. MMC558 대비 메모리 setup·recovery 등 기존 음수 항목 7개가 악화되어 실기판은 MMC558을 유지한다. [562 결과](../nes-owner562-results.ko.md) · [검증 데이터](../../analysis/owner562-verification.json)

563은 두 위상 모두 한쪽 클록 정지 시 차단됐고, 클록만 복원했을 때는 재가동되지 않았다. 서로 다른 코너의 극값을 조합한 RUN 주소 캡처 여유는 9.280ns다. 53화면 재생은 일치했다. MMC558보다 악화된 기존 음수 STA 항목은 7→3개로 줄었으나 168MHz SPI 수신의 대상 setup이 −0.333ns여서 전달은 보류했다. [563 전체 결과](../nes-guard563-results.ko.md) · [검증 데이터](../../analysis/guard563-verification.json)

564는 168MHz 수신의 직접 경로를 제거해 대상 setup이 −0.333→+0.415ns로 개선됐다. 두 위상의 53화면 재생은 같았다. FIT는 15,223 LE지만 MMC558 대비 악화된 음수 STA 항목이 3→10개로 늘어 실기 전달은 보류했다. [564 결과](../nes-arg564-results.ko.md) · [검증 데이터](../../analysis/arg564-verification.json)

565는 85°C의 조건부 PSRAM 읽기 여유를 1.624→3.920ns로 늘리고 ROM_OE 핀 제약을 통과했다. 뱅크 쓰기 준비는 host 2에지 늦어졌지만 시험의 첫 chunk 공개는 255번째 에지로 같았다. 564·565 모두 세대가 바뀐 뒤 이전 토큰 1의 ACK 전체를 다시 쓰면 새 데이터를 읽기 전에도 반환됨을 재현했다. 실기에서 관측된 실패는 아니다. MMC558 대비 악화된 음수 STA 항목은 10→5개로 줄었고 실기 기준은 MMC558을 유지한다. [565 결과](../nes-reuse565-results.ko.md) · [검증 데이터](../../analysis/reuse565-verification.json)

566의 정상 취소 8건에서 이전 토큰이 새 뱅크를 반환한 경우는 0건이었다. RESET 핀이 해제 상태로 고정되면 ARM은 STOP 전송 전에 차단했다. FPGA만 재시작한 대조군 2건은 읽지 않은 뱅크를 반환했다. MMC558의 정상 재시작에는 새 토큰 필드를 추가하지 않는다. [566 결과](../nes-drain566-results.ko.md) · [검증 데이터](../../analysis/drain566-verification.json)

567의 양방향 후보는 두 원격 reset setup 경로를 제거했다. 전체 최악 setup은 −7.286→−5.931ns, MMC558보다 악화된 전체 STA 항목은 5→1개다. 두 위상 53개 화면과 마지막 ACK는 565와 같았다. loader 대상 setup −0.024ns와 slow 0°C NES setup 회귀 0.034ns가 남아 실기 기준은 MMC558이다. [567 결과](../nes-mailbox567-results.ko.md) · [검증 데이터](../../analysis/mailbox567-verification.json)

## 후속작업

567 양방향 후보에서 CHECK 실패가 loader의 END 거부 상태에 도달하는 경로를 먼저 줄인다. STOP 우선·WRITE/HOLD 완료를 확인하고, epoch Gray 버스의 0°C 캡처와 전체 FIT·STA·OE 여유·두 위상의 952·957 표시 및 마지막 ACK를 재검증한다.
