## 목표

MMC558의 952 표시 간격을 6 VBlank에서 5 VBlank로 줄일 수 있는지 확인한다. 같은 입력과 두 시작 위상에서 밀집 구간과 마지막 ACK를 함께 평가한다.

## 작업내용

PR148 병합을 확인하고 MMC558에서 분기했다. 952의 E9 수락, 슬롯별 ROM 허가, 48B BG 패킷과 마지막 OBJ 소비, 65816 SEAL·DMA·표시를 한 시간축에서 비교했다. 실제 ARM에서 기존 SPI 버퍼를 재사용해 연속 OBJ 슬롯 39–50을 먼저 보내는 후보를 구현했다.

561에서는 기존 ARM 순서를 유지하고 FPGA가 검사를 마친 다음 목적지에서 불연속을 확인하면 완성된 chunk를 일찍 공개하도록 구현했다. 실제 RTL의 읽기·소비·STOP·재시작을 검증하고, M4·SPI·IRQ·ROM·65816 연속 일정과 Quartus Lite 전체 FIT·STA를 비교했다.

562에서는 CHECK와 RUN의 reader 소유권을 분리하고 NES RAM 초기화 완료를 로컬 요청·ready에 연결했다. 같은 seed·제약에서 두 경로의 실제 배치 끝점, 전체 코너, 두 위상의 연속 일정을 다시 대조했다.

563에서는 클록 감시기의 정상 시작 허가와 고장 시 비동기 차단을 분리했다. 참조·메모리 클록을 세 시점에서 멈춰 읽기 취소와 공통 reset 후 복구를 검증했고, 배치된 주소 전체의 setup과 동기화 첫 단의 토글 도착을 실제 캡처 에지에 맞춰 비교했다.

564에서는 SPI 인자 바이트의 일곱 번째 비트에서 쓰기 허가를 저장했다. 두 위상의 차등 RTL 시험에서 256가지 인자와 SS 중단·오류·CHECK·START·STOP을 검증하고 전체 보드와 53화면 재생을 대조했다.

565에서는 ROM_OE의 중복 선택과 host 취소 reset의 해제 경로를 바꿨다. PSRAM 핀 출력·데이터 샘플의 배치 예산과, core reset 전후 같은 물리 뱅크를 쓰는 실제 RTL의 준비·읽기·소비 시각을 따로 검증했다.

566에서는 MMC558 ARM의 RESET 구동·피드백과 STOP·다음 START 명령을 실행했다. 두 위상에서 실제 65816의 마지막 OBJ 읽기와 토큰 쓰기에 취소를 주입하고 버스 쓰기를 565 RTL에 재생했다.

567에서는 기록·준비 ACK 양쪽의 mailbox에 로컬 reset 해제를 적용하고, 수신 완료만 바꾼 대조군과 전체 보드·클록 정지·표시 일정을 비교했다.

568에서는 loader 거부 레지스터 하나 또는 네 개를 현재 phase로 대체한 후보와, 레지스터를 유지하고 CHECK 실패 선택만 옮긴 후보를 분리했다. 명령 판정·STOP 쓰기 완료, epoch 32비트의 실제 배치 경로와 두 위상의 표시 일정을 비교했다.

569에서는 16비트 plan descriptor를 디코더 WAIT에서 직접 캡처해 mailbox의 중간 수신 저장을 제거했다. 567과 568 A 두 loader에서 클록별 소유권·STOP·슬롯 재사용과 전체 보드 비용을 분리 비교했다.

570에서는 168MHz 메모리 시작 허가를 로컬에서 동기화하고, NES 고장이 마지막 에지에 올라온 경우 plan·SPI·타일 뱅크가 언제 차단되는지 다섯 보드에서 비교했다. E9 마지막 SS의 수락과 다음 E8 응답, 두 클록 정지 중 버스 해제와 부분 토큰 취소까지 검증했다.

571에서 SNES DATA·OE·DIR까지의 추가 경로를 추적하고 aperture reset, 읽기 허가, 최상위 소유자 선택을 각각 구현했다. 정지한 클록에서의 실제 핀 선택식·두 슬롯·STOP·최종 ACK를 시험하고 세 보드의 전체 FIT·STA를 비교했다.

572에서는 loader START와 168MHz 메모리 시작·고장 차단을 분리해 네 보드를 합성했다. 실제 SPI 수신·고장 중 PSRAM·두 슬롯·최종 ACK와 두 위상 65816 재생을 대조했다.

573에서 실제 RAM·수집기 초기화와 STOP 뒤 첫 generation 수락을 연결했다. 32개 Gray 비트의 두 동기화 단을 추적하고, 합성 속성·연속 샘플링·비트 23 인접 배치를 같은 SDC와 seed로 비교했다.

574에서는 RAM 초기화 중 32비트 identity를 request/ACK로 한 번 인계했다. 모든 중간 비트 취소와 실제 첫 capture/cache/plan을 검증하고 같은 seed·제약의 전체 보드 비용을 비교했다.

## 성과

## 후속작업

572 START 단독을 유지하고 epoch 국소 배치·직렬화 FIT 반복을 종료한다. 실제 top의 클록·CDC 첫 단·reset 해제와 초기 소비자의 소유권을 분류해 RTL 결함과 제약 오류를 구분한다. 제약 변경은 endpoint별 근거를 갖춘 뒤 MMC558/572를 동일 조건으로 비교하고 기존 raw STA를 보존한다. STOP·두 슬롯·첫 capture/cache/plan과 952·957·마지막 ACK를 유지하며 전체 gate와 실기 기준은 자동으로 완화하지 않는다.
