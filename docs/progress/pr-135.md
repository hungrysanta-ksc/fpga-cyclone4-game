# PR135 — NES476–482: 수신 개선·MMC3 시작 진단과 실기 전달본

[GitHub PR135](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/135). 열림.476 성공 실기는 평균23.84fps다.480 공동 기능/픽셀·ACK/STOP 검사는 통과했지만 실제 게임은 SNES 표시 시작에서 실패했다. ROM·전체 적재/검증·START와 STOP·메뉴 복귀는 정상이다.481 기각을 보존하고482의 준비 조건과 새 제한 진단 전달본까지 완료했다. 물리 시작 복구와 게임 FPS/60fps는 미확정이다.

## 목표

NROM476의 수신·CRC 비용을 줄이고 독립 검사·STOP·최종 ACK·메뉴 복귀를 유지한다. 문양의 대표성을 판정해 실제 MMC3 게임 진입과 전체 예산을 검증한다. MMC480 실기에서 드러난 SNES 표시 시작 실패는 ROM/적재·실행·표시 경계로 분리하고, 미확인 상태를 새 설치본의 성공으로 표시하지 않는다.

## 성과

- 고정 cold 이동 SPI replay116거래/10D1/1800payloadB에서 M4 명령506568→309481, **38.9063% 감소**. 전체 복원 상태와 TX가 같다.
- native CRC3byte 입력16777216조합·bitmap25094건, M4 정상/8fault의 동일 상태·실패 뒤 추가 SPI 차단을 통과했다.
- 실제476 native ARM C·기존 NES/source RTL·Mesen65816 연결에서30ACK/4144VRAM bytes/1commit·독립 막대 mask·최종ACK/EA·run136 STOP을 통과했다.
- ARM text+28B, data/BSS·관련 static stack 동일. Flash 파일 후미352B. FPGA66input 재해시·동일471 bitstream이며 불변 Quartus 재합성을 하지 않았다.
- 실기477:60.07초/1432표시로 평균23.84fps.474의23.59fps 대비+1.06%이지만 정상 구간은 약24fps로 유지됐다. 수신15.65ms로 감소, SEAL/소비/최종ACK19.58ms로 증가해 대부분 상쇄됐다. CPU 명령39% 절감을 FPS 향상으로 쓰지 않는다.
- CRC/driver/abort0, START·STOP/base/menu 정상. 마지막 프레임의4packet은 deadline 취소됐고 표시로 세지 않았다.
- OBJ0/warm mapdirty0/BG27/28group 재사용 장면이라 실제 게임을 대표하지 않는다.30/60fps·실제 SMB3/MMC3·연속 capture 무손실/p95·전체 CDC/IO·MMC4/5는 미완료다.

- 게임 기록71개에서 활성 canonical·전체 receiver/video/resident·40B plans가474/476간 동일하다. 수신 절감 중앙48.22%, 계획 중앙799681명령은 문양 warm의4.63배다. host encoder/peer 완료 모델이므로 실제 게임 SPI/IRQ/FPS 증거가 아니다.
