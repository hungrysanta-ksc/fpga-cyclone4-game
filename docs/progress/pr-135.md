# PR135 — NES476–478: 실기 판정·게임 입력 검증과 MMC3 배치

[GitHub PR135](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/135). 초안·열림이며476 실기477까지 확인했다. 478에서 게임 기록71개·MMC3 배치까지 확인했으며 실제 게임 부팅/60fps는 미완료다. PR134 merge `93bb8f715914da12d46f1d5c8262d6e8b10d3362`의 master 도달을 확인하고 새 브랜치에서 시작했다.

## 목표

PR134가 master에 반영된 것을 확인하고 현재 PC의 실기474/475를 기준으로 개발을 재개한다. 수신·CRC/record 비용부터 줄이며 독립 검사·STOP·최종 ACK·메뉴 복귀를 유지한다. 문양 실기의 대표성을 판정하고, 실제 게임 입력과 MMC3 전체 보드 예산을 확인해 게임 진입 순서를 정한다.

- 새 파일명·476 marker·직전474/471·164/467 원복을 묶은 NROM476-RECEIVE 전달본을 만들고 사용자 실기3TXT를 독립 재분석했다.
- 시험 대표성을 점검했다. 실제 loader/cart가 NROM 전용인 점을 확인하고 문양 회귀와 실제 MMC3/SMB3 진입을 별도 관문으로 정했다.
- 478에서 동결 SMB3 기록71개를 현재474/476 M4의2232 모델 입력으로 비교하고, 기존 MMC3 cart를 현재471 보드에 복원해 전체 Lite MAP/FIT·관련 timing을 확인했다.

- 고정 cold 이동 SPI replay116거래/10D1/1800payloadB에서 M4 명령506568→309481, **38.9063% 감소**. 전체 복원 상태와 TX가 같다.

- 실제476 native ARM C·기존 NES/source RTL·Mesen65816 연결에서30ACK/4144VRAM bytes/1commit·독립 막대 mask·최종ACK/EA·run136 STOP을 통과했다.

- 실기477:60.07초/1432표시로 평균23.84fps.474의23.59fps 대비+1.06%이지만 정상 구간은 약24fps로 유지됐다. 수신15.65ms로 감소, SEAL/소비/최종ACK19.58ms로 증가해 대부분 상쇄됐다. CPU 명령39% 절감을 FPS 향상으로 쓰지 않는다.

## 후속작업

- NROM과 구분되는 새 MMC3 profile와 정확 SMB3 header/크기/CRC·PRG/CHR 배치를 ARM loader/readback/START/STOP/base에 묶는다. 기존 검사를 단순 해제하지 않는다.
- 실제 MMC3 core/source/query·bank/IRQ·입력 중 ROM 경쟁과 display lease를 연결한다.71개 host-encoded 재생으로 실제 core/FPGA 경로 관문을 대체하지 않는다.
- paired65816 게임 프레임의 DMA·독립 검사·최종ACK/EA·observer·STOP/base/menu와 같은 source의 비용/timing을 확인한다.142LE 여유는 좁고 full CDC/IO는 미승인이다.
- 관문 통과한 게임 조합만 새 marker/원복과 전달하고 월드맵·1-1·sprite/상태창·CHR·음악/효과음·입력·capture cadence를 측정한다. 현재 실제 게임 firmware/bitstream/ZIP는 없다.
- 문양은 회귀로 유지한다. 문양60fps를 게임 진입의 선행 조건으로 두거나 같은 입력의 소규모 최적화만 반복하지 않는다.
