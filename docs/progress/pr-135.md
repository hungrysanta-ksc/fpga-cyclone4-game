# PR135 — NES476: 수신 절감·24fps 실기 판정과 게임 검증 계획

[GitHub PR135](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/135). 초안·열림이며476 실기477까지 확인했다. 실제 게임/60fps는 미완료다. PR134 merge `93bb8f715914da12d46f1d5c8262d6e8b10d3362`의 master 도달을 확인하고 새 브랜치에서 시작했다.

## 목표

PR134가 master에 반영된 것을 확인하고 현재 PC의 실기474/475를 기준으로 개발을 재개한다. 수신·CRC/record 비용부터 줄이며 독립 검사·STOP·최종 ACK·메뉴 복귀를 유지한다.

## 작업내용

- 실제474 ELF/firmware의 poll/prepare를 기록 SPI로 재생해 함수·소스 라인별 명령을 측정했다.
- 동일 CRC16 byte 식과 required bitmap의 sparse tag 열거로 nes_native165.c만 교체했다. wire2232·단일 복원·geometry/count/512상한·POP/retire·FPGA471·65816은 유지했다.
- 실제 ARM 빌드, CRC/bitmap 전수·경계, M4 오류/실패 freeze, native C→RTL→65816 표시/최종ACK/STOP을 검증했다.
- 새 파일명·476 marker·직전474/471·164/467 원복을 묶은 NROM476-RECEIVE 전달본을 만들고 사용자 실기3TXT를 독립 재분석했다.
- 시험 대표성을 점검했다. 실제 loader/cart가 NROM 전용인 점을 확인하고 문양 회귀와 실제 MMC3/SMB3 진입을 별도 관문으로 정했다.
- README는 의미 있는 진척·정정 때만 갱신하고 PR은 이 네 항목을 계속 유지하도록 기록했다. PC 이전 작업은 우선하지 않는다.

- 고정 cold 이동 SPI replay116거래/10D1/1800payloadB에서 M4 명령506568→309481, **38.9063% 감소**. 전체 복원 상태와 TX가 같다.
- native CRC3byte 입력16777216조합·bitmap25094건, M4 정상/8fault의 동일 상태·실패 뒤 추가 SPI 차단을 통과했다.

## 후속작업

- 문양은 경로·CRC·STOP 회귀로 유지한다. 이 문양60fps를 게임 진입의 선행 조건으로 두거나 같은 이름만 바꾼 설치를 반복하지 않는다.
- 기존 SMB3의 BG/OBJ·split·bank/tag 대표 입력을 현재 ARM/ABI와 비교한다. 기록 replay와 실제 게임 실기를 구분한다.
- 실제 MMC3/WRAM/IRQ·loader/PSRAM 배치·source/query/lease·입력 중 ROM 경쟁의 교체 경계를 고정하고 전체 Lite 비용을 판정한다. 기존227의 SMB3 성공이나 옛 MAP 차이를 새 조합 FIT로 승계하지 않는다.
- 구동 가능할 때 같은 조합의 SMB3 월드맵·1-1 이동·sprite/상태창·CHR 변경·음악/효과음과 capture cadence·누락/반복·입력·STOP/최종ACK/base/menu를 검증한다. 아직 새 MMC3 구현/게임 설치본은 없다.
- 해당 문양의 평균30fps까지8.615ms,60Hz까지25.282ms가 남는다. 이 수치와 CPU 명령 개선을 일반 게임 예산/FPS로 확장하지 않는다.
