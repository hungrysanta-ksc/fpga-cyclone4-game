## 목표

MMC705 첫 실행의 배경 CHR 마감 오류를 수정하고 같은 map·OBJ 작업량의 속도 최적화를 재개한다. 스페이드 해결은 사용자 실기 확인으로 인정한다. 반복 화면 깨짐·stage0 timeout은 관찰 항목으로 보존하며 이번 성능 작업의 선결 조건으로 삼지 않는다.

## 작업내용

PR156 병합 `4ee65ac300c3b5eca73848bd0b408c1bc63b6800`에서 새 브랜치를 만들었다. 실제 T65 원본 ROM 명령과 PSRAM 경쟁으로 렌더 시작 및 `$2007` 읽기 종료 뒤의 BG 요청 지연을 재현했다. 선택707D는 PPU 한 파일에서 기존 주소 경로와 fine-Y 증가·mask를 공유해 다음 읽기를 앞당긴다. CPU/PPU 클록·mapper commit·우선순위·실제 주소 독립 검사·deadline·STOP/ACK는 유지했다.

367개 경계 조건, fine-Y/copy/wrap 3,072조건, 기존 sprite·중간 STOP, 두 위상106화면을 검증하고 전체 Quartus Lite FIT·STA를 확인했다. 원시 실패·중간 후보·생산 patch를 보존하고 재현 도구와 다음 비용표를 추가했다.

708에서 후반 scroll+패딩 선행,짧은 scroll 단독 선행,전송 버퍼 중복 초기화 제거를 각각 실제 링크 ARM·65816의 두 위상106화면에서 비교했다. 조건부 발행은 전체 Flash 단계에서 기각했다. 별도 credit 조회와 소비·최종 ACK 조회 비용도 분리했다.

## 성과

- 실제 T65의 `$2007` 읽기에서 실기 오류 문맥 `e30143c2c221e161`과 PPU 상태 `60b9880005858586` 전체 일치. 기존 각3위상6실패 → 수정0실패. 렌더 시작 경계도 수정했다. 물리 실행의 직전 이력이 없어 두 재현 중 유일 원인까지 확정하지 않는다.
- 선택D: **15,322 LE / 962 LAB / 56 M9K**, 기존703B 대비 −26 LE/−1 LAB, FF·RAM 동일. setup/hold/recovery/removal **+0.362/+0.145/+1.594/+0.483ns**. 제약·pin·seed 변경 없음; 개별 reader/ROM출력 경로도 양수.
- 두 위상 표시·마지막 ACK는703B와 클록 단위 동일. 951공개245/236선,952표시3VBlank,957최종대기0회 유지. ARM Flash/RAM·65816 ROM 증가0.
- 실제 CPU/PSRAM 경계 시험과 링크 ARM·65816 일정 재생은 별도 증명이다. 전체 FPGA 동시 실행·실기 오류 해결·FPS 개선을 주장하지 않는다. 외부IO 전체 sign-off 미완료. 새 설치본 없음.

## 후속작업

707D와 기존 ARM·65816을 유지한다. 다음은 기존 E1 응답에 기존 E0 snapshot/CRC를 함께 실어 **중복 credit 조회만** 줄일 경계와 삭제 예산부터 검증한다.951 enqueue 내부 조회는5/6회·100/120B·0.545/0.654ms이며 이는 현재 비용이지 절감 보장이 아니다. snapshot은 현재 E1 수락 이전 상태이므로 이전 accepted/retired·identity를 검사하고,짧은 E1·full/stale 응답은E0 fallback을 유지한다. 소비 완료·최종 표시 ACK는 생략하지 않는다.

정상판8B/장시간판52B Flash와86LE/1LAB/0M9K 예산 안에서 기존 검사·응답 제어를 공유해야 한다. 두 위상에서 동일 작업량·독립 검사·STOP·최종 ACK·메뉴 복귀,911마감·951공개≤246·952표시3회·957최종대기0회·7블록 선행수신을 유지하고 밀집 간격과 마지막 ACK가 함께 개선돼야 채택한다. 같은 후반 순서 변경/초기화 미세조정은 새 근거 전까지 반복하지 않는다. 다음 전달은 고유 이름의60초/장시간판이며 RESTORE는 제외한다.
