## 목표

조사한 NES 헤더와 카트리지 배선의 호환성을 한 PR에서 확장한다. SD에서 사용자가 선택한 ROM의 메모리 구성으로 보드를 결정하고, 대표 게임의 부팅·표시·IRQ·소리·저장·재실행·STOP·메뉴 복귀를 각 배선에서 확인한다. 검증 기준과 원자료는 [기존 조사](../nes-cartridge-compatibility-plan.ko.md)에 둔다.

## 작업내용

PR186이 병합된 master `3322565e`에서 시작했다. 첫 변경은 실제 디버그·배포 로더의 SD 선택과 재검사에서 같은 iNES/NES 2.0 판독기를 사용하는 것이다. NES 2.0의 12비트 매퍼·서브매퍼, 두 가지 ROM 크기 표기, RAM/NVRAM 필드, 512B trainer의 위치, 추가 데이터, 미러링·기종·타이밍·장치를 분리한다. 구형 헤더의 정확한 DiskDude! 서명만 별도로 처리한다.

## 성과

| 범위 | 현재 근거 | 완료에 필요한 다음 검증 |
|---|---|---|
| iNES·NES 2.0 | 두 ARM 최종 링크 각각 50건 통과. 모아이군의 지수형·DiskDude! 헤더 두 종류에서 실제 배포판 ARM과 FatFS로 128블록씩 적재하고 메뉴 복귀 확인 | 보드별 수용 가능한 메모리·배선 조합과 실기 실행 대조 |
| NROM·UxROM·CNROM·AxROM | 모아이군·테트리스·배틀토드의 기존 개별 구성 실기 | 용량·미러링·버스 충돌 조합과 모든 뱅크, 게임 실행 |
| MMC1, SXROM | 1064 젤다 1·2 실기 실행·로드. 1065 젤다 2 타이틀 캡처와 FF1&2의 512KiB PRG·32KiB 배터리 RAM, CPU 복원·전체 FIT·STA 통과 | 1065 실기에서 타이틀과 FF1·FF2 개별 저장·재실행 확인 |
| MMC3·191·192 | 커비·모험도 4·FF3의 개별 구성 실기 | 용량 확장, MOTHER·메탈 맥스 혼합 CHR의 쓰기/캐시와 IRQ |
| MMC5·VRC4·VRC6a | 드퀘4·와이와이2 기존 구성 실기 | MMC5 제한 조건 판별, 악마성 전설 IRQ·펄스 2개·톱니파·상태 복원 |
| 특수 형식·환경 | 헤더 있는 UNIF·FDS 시그니처 및 카트리지의 특수 기종·타이밍·장치 요구 식별 | UNIF 보드명/청크, FDS 디스크·BIOS, VS·PlayChoice·확장 기종, PAL·Dendy·주변기기 실행 지원을 각각 추적 |

1064에서 지수형 크기 바이트 256가지, trainer 뒤 PRG/CHR 오프셋과 절단 경계를 독립적으로 검사했다. 젤다 1·2는 각각 실제 배포판 ARM을 FatFS·모델 주변장치와 실행해 512페이지씩 확인하고 STOP·base·메뉴 복귀까지 검사했다. 새 ARM에서 배터리 8,192B와 퀵세이브 21,264B를 저장한 뒤 FAT 볼륨을 다시 열어 전체 바이트를 대조했다. [ARM 검증 결과](../../analysis/nes-headers1064.json)

Questa에서 두 젤다의 원본 PRG로 CPU를 구동해 매퍼 쓰기 45회·15회를 관측했다. 2,658워드를 저장하고 리셋·복원한 뒤 매퍼 레지스터와 다음 64회 CPU 명령 읽기를 대조했다. 별도 로더 시험은 실제 RTL에 262,144바이트를 공급해 START와 STOP을 확인했다. 512KiB용으로 남아 있던 마지막 바이트 판정과, 합성에서 상수 0이 된 주소 18번 비트의 제약 두 줄을 수정했다. Quartus Lite 전체 FIT은 15,005/15,408 LE, 953 LAB, 56 M9K이며 STA 57개 그룹의 최저 여유는 +0.173ns다. [보드 및 설치본 결과](../../analysis/nes-mmc1-board1064.json) · [1064 실기 시험 방법](../nes-mmc1-1064.ko.md)

1064 젤다 2 로그에서 ROM 적재·START·메뉴 복귀가 성공했다. 첫 화면이 흰 원인은 원본 CPU·PPU를 실행한 RTL로 재현했다. 19번째 캡처부터 OBJ 조각이 128개를 넘었다. 1065에서는 양쪽 패턴 바이트가 모두 0인 행을 제외하고, 화면 중간 PPU 주소 쓰기가 발생한 한 줄은 합성 픽셀로 보존한다. 기준 타이틀의 OBJ 조각은 138개에서 85개로 줄었고, RTL에서 각 불투명 행의 타일·위치·우선순위·뒤집기를 대조했다. 같은 캡처를 최종 디버그·배포 ARM에서 재생해 OBJ 85개와 화면 분할선 256픽셀의 출력 계획을 확인했다.

FF1&2는 MMC1 SXROM 보드에서 PPU A12와 CHR 뱅크 출력으로 PRG의 상·하위 256KiB와 배터리 RAM 뱅크 네 개를 선택한다. 양쪽 게임 선택 후의 매퍼 쓰기와 주소 핀, 리셋 뒤 32KiB 전체와 CPU 읽기 64회, ARM·FatFS의 저장 복원을 검사했다. 전체 Quartus Lite FIT·STA는 젤다 보드 14,948 LE·최저 +0.133ns, SXROM 15,032 LE·최저 +0.145ns다. [1065 검증 기록](../../analysis/nes-mmc1-1065.json) · [실기 확인 방법](../nes-mmc1-1065.ko.md)

## 후속작업

1. 정상·오염·절단·큰 크기·trainer·추가 ROM 시험과 기존 여섯 실행 경로 회귀를 유지한다. trainer를 수용할 때는 PRG 시작 위치와 CPU `$7000–$71FF` 초기화까지 확인한다.
2. 1065 DEBUG에서 젤다 2 무입력 오프닝과 이전 슬롯을 확인한다. FF1&2에서는 두 게임의 배터리 기록을 각각 남기고 SD 메뉴 복귀와 재실행 후 다시 읽는다. 단순 보드·혼합 CHR·VRC6a와 특수 형식은 위 표에서 이어간다.
3. 각 보드의 전체 Quartus Lite FIT·STA와 대표 실기 결과를 기록하고 DEBUG·RELEASE를 함께 준비한다. 추가 게임에서 재현되는 스크롤·스프라이트 부하 장면은 별도 성능 비교용으로 남긴다.
