## 목표

[감사499 계획](../nes-audit499-plan.json)의 A1부터 진행한다. 실기493과 같은 fetch01/04/06 거부를 재현하고, 정상 렌더링 전환에서 정확한 raw 행을 보존하면서 수집을 복구한다. 독립 검사·STOP·최종 ACK·VBlank·메뉴/GBC/save 경계를 유지한다.

## 작업내용

500에서 실제493 PPU/수집기로 오류를 재현했다.501은493 보드70입력 중 planes/frame 두 파일만 교체했다. PPUMASK 전환의 현재/다음 행은 기존 raw 저장소로 보존하며, 완전한 행·identity·세대·완료 통지를 요구한다. 실제 ROM의 주소/DATA/byte·plane lane 검사는 유지하고, raw 행에서 PPU load 이름과 정상 ROM 주소의plane 불일치를 구분한다.

실제PPU 한 개에 기존/후보 planes를 함께 연결했다. raw 픽셀은별도 post-CE 관측기와 비교하고, raw 밖 native 이벤트는 개수·순서·64bit 내용을 비교했다. 고장/STOP 반례를 단일Questa FLOAT좌석으로 순차 실행하고 같은RTL을 Quartus Lite 전체보드에 연결했다. [계약](../nes-capture501-contract.ko.md) · [검증](../../analysis/capture501-verification.json).

## 후속작업

A1 전체는미완료다. 불필요한세번째raw행을줄이는소유권범위와현재compact/full CHR전송을실제source→ARM→65816에연결해비교한다. 필요한행을강제로누락하거나검사를완화하지않는다. 압축·SPI/credit/IRQ·DMA·최종ACK 비용까지확인하고그결과와잔여100LE를A2 구조예산에반영한다. 단독status/FSM 최적화·498승격·새실기전달로건너뛰지않는다.
