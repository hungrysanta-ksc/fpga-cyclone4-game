## 목표

감사499의 A1에 따라 정상 PPUMASK 중단·재개의 fetch 거부를 복구하고, 필요한 픽셀과 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 보존한다. 수집 회복의 추가 raw 비용을 실제 배포 ARM·65816 경로로 확인한 뒤60fps 구조 예산에 반영한다.

## 작업내용

500에서 실제493 PPU/수집기로 fetch01/04/06을 재현했다.501은 행 identity·세대·완전한 raw coverage 뒤에만 렌더링 전환의 불완전 fetch를 복구한다.502는 visible 전환과 다음 행 fetch 전환의 소유권을 구분해 불필요한 세 번째 raw 행을 제거했다. 필요한4행과 기존 용량/주소/DATA/ROM/STOP 검사는 유지한다.

같은 PPU 입력의 실제 source record를493 ARM 수신·planner·serializer에 넣고, 결과 패킷을 실제493 65816 검사·DMA·표시에 연결했다. 기존 bulk 묶음 규칙을 적용하고 두 시작 위상을 비교했다. 같은RTL을 Quartus Lite 전체 보드에 연결했다. [502 계약](../nes-capture502-contract.ko.md) · [검증](../../analysis/capture502-verification.json). [501 근거](../../analysis/capture501-verification.json)는 별도로 보존한다.

## 성과

- 정상33조건/반례12종 통과. raw15,360픽셀·native241,956이벤트 일치. 기존27조건 중10조건에서 raw3→2; 필요한4행은 모두 보존한다.500의기존9거부 회복을 유지했다.
- 고정 cold 장면의 실제493 ARM 실행: 수신 SPI −330B, 출력 E1 −1797B, 수신/계획/serializer 명령 수 각각 −27,380/−33,816/−109,029. Flash/static RAM 추가0.
- 실제65816의 최종 RGB가501/502에서 동일하고 독립 검사·DMA·VBlank·최종ACK 통과. 같은 시작 위상별 ACK 단축은0.20347ms/16.82504ms다. VBlank 때문에 전송 감소와 표시 단축이 일대일 대응하지 않는다.
- Lite15,287LE/14,135comb/8,399FF/264,816bit/51M9K,잔여121LE.501 대비−21LE/+2comb이므로 제어 삭제 성과로 계산하지 않는다. 관련setup+.353ns/hold+.142ns,seed/제약 변경없음.
- 한 cold fixture와 모델 transport/ROM/ACK endpoint다. 실제 공유 ARM·IRQ·ROM 공통 일정, 연속 게임/실기 STOP·메뉴·FPS 재검증은 남았다. 실기4939.57fps/원복/README는 유지하며 이번에는 새ZIP이 없다.

## 후속작업

제한된 수집·소비 gate를 통과했으므로 다음은502 수정만 분리한 고유 파일명 실기 전달본과493 복구본을 준비한다. 같은 장면에서 수집 거부·표시 간격·메뉴 복귀를 확인한 뒤 A2의 전체 전송/DMA 예산을 갱신한다. 같은 bounded 시험·FIT 반복이나 미선정498/status/FSM 변경으로 우회하지 않는다. 실제 공유 SPI 설정·IRQ·ROM 대기·VBlank를 분리 계측하며, 물리 결과 전까지 A1 전체완료/60fps/지속가속으로 표시하지 않는다.
