## 목표

[PR150](pr-150.md)의 수정 계획에 따라 MMC577을 고정하고 전체 비용과 실제 교체 범위를 확인한다. R1 감사를 마감하고 R2에서 입력 좌표·출력 이력·SPI 호출을 함께 줄일 구조와 검사·자원 예산을 검증한다.

## 작업내용

PR150 병합 `588fa177` 확인 후 `codex/nes-whole-budget-580`에서 FPGA 입력 75개와 ARM 파일 414개를 고정했다. ARM558/577 함수 792개와 CPU 재생의 동일성을 확인하고 104간격을 비중첩 항으로 분해했다. 581에서는 53개 입력, 106개 D1 경계, 3378개 E1 발행·수락·ACK와 대상 뱅크 복원을 대조했다.

마지막 D2의 start 로그가 다음 capture 시각으로 덮어써지는 시험 도구 오류를 수정했다. 원본과 누락 시각은 보존했으며 제품 실행 시계는 바꾸지 않았다.

582의 section/block·map/row·stale 재사용 예산에 이어 583에서 33칸 행의 ±1칸 재사용, 독립 M4 복원 커널, 50B 진행 응답을 검증했다. 584는 실제 MMC577 ARM의 수신·runtime·window·plan 일곱 파일을 교체하고 전체 링크했다. D0/D2/E0/E8을 제거한 공통 진행 응답, source 4packet ring, output 4credit 포화, 오류 뒤 늦은 완료 차단을 제한된 M4 실행으로 확인했다. 기존 record 압축은 유지했고 583 codec은 합치지 않았다.

## 성과

실기 기준은 MMC577 **13.95fps / 5–55초 13.86fps**, Flash 84B·LE 148개·M9K 5개 여유다. 기존 907–957 ACK 평균 70.477/71.125ms와 밀집 951–955 평균 83.157/83.121ms는 재분석한 모델이며 새 성능 결과가 아니다.

입력 map 1914B는 기존 평균 2571.88B로 포장됐고 출력 map은 96.8% 같은 바이트여도 전체 동일 packet은 0개였다. 583 행 재사용의 literal word는 951 749→23, 954 755→75, 957 754→31개다. M4 독립 커널은 248B/stack104B이며 1537행과 17개 거절을 통과했다. 공통 응답 참조는 정상 6·거절 20조건을 통과했다. 조회 3회 가정의 C안 I/O 10.507/10.517ms는 달성 시간이 아니다.

**584 transport 단독 후보는 채택하지 않았다.**

| 제한된 951/954 시험 | MMC577 | 584 |
|---|---:|---:|
| SPI 호출 | 86–120회 | 57–71회 |
| 같은 사례 대비 전송량 | 기준 | +841–919B |
| 전체 펌웨어 | 212908B | 213352B |
| 배포 한도 대비 | 84B 여유 | 360B 초과 |
| BSS / 시험 관측 stack 증가 | 기준 | +84B / +256B |

입력 전체와 각 7개 실제 plan을 쓴 4개 대조 사례, 포화 검사, 오류·STOP·최종 ACK·driver 한도 관련 18개 거절을 통과했다. 새 형식의 255/256B payload는 기존 259B driver 한도에 맞지 않아 일반 호환성도 확보하지 못했다. 정상 시험 최대 전송은 259B다.

소비·표시 허가는 endpoint 모델이다. 실제 IRQ·ROM·65816·2슬롯·VBlank·메뉴를 새로 검증한 결과가 아니다. 현재 577은 표시 ACK/EA 뒤 다음 입력 poll을 실행한다는 점도 확인했다. 과거 입력 선행 수신을 현재 기능으로 가정하지 않는다. 제품 FW·RTL·SDC·README는 유지했으며 새 FIT·전체 게임 시뮬레이션·실기 ZIP은 없다.

585에서 기존 packet1434B·응답 adapter166B를 교체하되 의미검사1112B·required-tag68B는 유지하도록 범위를 고정했다. rowkernel248B와584 초과360B를 빼면 **남은 새 코드 상한은992B**다. 실제 순삭제가 아니며 다음 링크 시험의 중단 기준이다.

전체8948B 이력 복사는 실제 RAM 간격에 들어가지 않는다. 기존 prefix·2297B raw shadow·140B stale mask·259B RX·8B scratch의 정렬 예약은2708B이고 caller/IRQ/identity/손상검사 전2144B가 남는다. 참조 밀집 구간의 순 전송 생략은675B로 exact 전체 이력707.2B의 대부분을 유지했다. 다만 planner 초기화를 바꿔야 하며 **stale mask만으로 은행 RAM 손상을 검출하지 못하는 반례**도 확인했다. 독립 검사를 대체하지 않는다.

E9 cut1–5에서 52B in-place RX 확대가 미발행 suffix를 훼손했다. 별도RX와 기존4B trailer 보존을 함께 유지할 경계를 정했다. 585는 새 펌웨어·FPGA·표시 시간 개선 결과가 아니다.

**586 결합안도 채택하지 않았다.** 최종213852B로577 대비+944B, 배포 한도860B 초과다. 출력 history/planner/retained-bank 손상검사 코드는 아직 추가하지 않았으므로 그 확장을 중단했다. 53개 연속 입력,parser 거절15조건,실제 수신/출력4slice,전송/취소18조건,API 인자3조건,E9 suffix7조건과4credit 포화를 통과했다. BSS18940B,관측 slice stack832B이며 전체 IRQ stack 증명은 아니다.

공통 응답 직접 소비는584 대비 plan98B를 줄였지만 native652B 증가가 이를 넘었다. 새 section 수락 뒤 기존 `logical_record` 제어가 남는 비용을 확인했다. 이는 독립 검사를 지우거나 전체 구조의 불가능성을 선언할 근거가 아니다. 두 시작 위상·FPGA·실기 표시 성능을 새로 검증하지 않았다.

## 후속작업

R1은 결측을 명시하고 마감했다. 물리 capture/NES 진행/입력 지연,밀집 ROM·실제 MCU 사이클,대표 장면과 clean-clone 전체 실행은 미완료다.

다음 R2는 **검사 소유권 결정**이다. 기존 encoded BEGIN/record 제어를 실제 삭제하고 section 수락·값별 의미/required-tag·canonical CRC를 하나의 실행기로 만들 수 있는지 모든 유지 검사를 대응시킨다. 기존 의미검사1112B 전체를 무료 절감으로 세거나 새 parser 아래 옛 controller를 그대로 남기는 안은 제외한다.

source expected 생산·output history/독립 손상검사·실제 stack·wire/조회·FPGA 자원까지 맞출 근거가 없으면 C의 역할/지원 범위를 재선택한다. 584/586의 같은 adapter 조합·padding/opcode/poll/로그 축소·불변 FIT는 반복하지 않는다. source input-COMMIT base와 표시 ACK bank history를 구분하고 old EA→new COMMIT·STOP·늦은 완료 차단을 유지한다. R3는 미선정이며 MMC577·VBlank·메뉴 복귀·GBC/save를 보존한다.
