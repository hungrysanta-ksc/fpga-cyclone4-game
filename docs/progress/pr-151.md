## 목표

[PR150](pr-150.md)의 수정 계획에 따라 MMC577을 고정하고, 60Hz를 위한 전체 전송·실행 비용과 실제 교체 범위를 확인한다. 국소 개선을 새 성능으로 합산하지 않고 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 유지한다.

## 성과

실기 제품은 **MMC577: 13.95fps /5–55초13.86fps** 그대로다. 이번 PR에서 새 실기 성능을 얻었다고 주장하지 않는다. 제품 여유는 Flash84B·148LE·5M9K다.

| 후보 | 전체 ARM 이미지 | 한도 대비 | 판정 |
|---|---:|---:|---|
|MMC577|212908B|84B 여유|제품 유지|
|584 공통 응답|213352B|360B 초과|단독 후보 보류|
|586 section+응답+RX|213852B|860B 초과|이력 확장 중단|

586은53입력·15parser 거절·4수신/출력slice·18전송/취소·3API·7E9 suffix·4credit 포화를 통과했다. 하지만 source 기대 CRC와 소비/표시 허가는 모델이며 실제 IRQ·ROM·65816·2슬롯·VBlank·메뉴를 새로 검증한 결과가 아니다. 공통 응답의 plan98B/runtime30B 감소보다 native652B 증가가 컸다. BSS18940B·관측 stack832B는 전체 IRQ 최대치 증명이 아니다.

**587의 중요한 수정:** 고정 FPGA 6파일의 해시·top 연결은 입력 **256B 단일 sealed block+96bit mailbox**를 가리킨다. 584/586의 입력4packet ring은 시험 모델이다. 그 생산 시간·credit 여유를 실제 보드에 승계하지 않도록 과거 결과 문서와 현재 계획을 보완했다. host의 압축 packet CRC와 새 canonical CRC도 구분했다.

실제586 ELF의 값455개·수락 경계4조건·control22조건이 독립 참조와 일치했다. query 재읽기2반례에서는 모든 응답을 CRC에 넣으면 중복되며 실제 인덱스 전진 값만 넣어야 함을 확인했다. 기존 실행기1136B를 전부 지우고 대체를0B로 가정해도276B만 남는다. 의미 검사·출력 이력·손상 검사는 무료 삭제가 아니므로 현재 결합안의 선택 근거는 부족하다.

RAM은 shared RX를 중복 과금하지 않고 shadow/mask/scratch2448B를 더하면 caller/IRQ/독립 검사 전2124B가 남는다. 실제 최대 stack·새 source CRC/port/CDC·전체 LE 비용은 미확정이다. 새 FW/RTL/FIT/설치 ZIP과 README 제품 상태 변경은 없다.

## 후속작업

R1은 결측을 명시하고 마감했다. 물리 capture/NES 진행/입력 지연·밀집 ROM·실제 MCU 사이클·대표 장면·clean-clone 전체 실행은 미완료다.

다음 R2는 **MMC577 실제 입력 생산기와 ARM 직접 section 실행기를 함께 바꿀 순삭제·포트·cycle 예산**이다. 기존 D0/D1/D2/D3 및 출력 실행을 기준으로 유지하고586 section/row 형식을 사용한다. source export/mailbox/host 제어의 실제 삭제, 단일 block backpressure, query 인덱스 전진 CRC, 취소 drain, ARM 순 링크 비용을 함께 계산한다. source가 빠진 ARM 단독 통과를 선택 근거로 삼지 않는다.

전체 C의 공통 응답·출력 history 확장은 보류한다. 입력 단독을60Hz 달성안으로 부르지 않고 남는 출력 시간을 전체 비용표에 환원한다. 근거 있는 상한 뒤에만 한 번의 bounded prototype을 진행하며 R3는 미선정이다. adapter/padding/opcode/poll/로그 축소와 불변 FIT 반복은 재개하지 않는다. source COMMIT base와 표시 ACK bank 이력, STOP·최종 ACK·VBlank·메뉴·GBC/save를 보존한다.
