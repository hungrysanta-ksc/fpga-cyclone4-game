## 목표

[PR150](pr-150.md)의 수정 계획에 따라 MMC577을 고정하고 전체 비용과 실제 교체 범위를 확인한다. R1 감사를 마감하고, R2에서 입력 좌표·출력 이력·SPI 호출을 함께 줄일 구조와 검사·자원 예산을 검증한다.

## 작업내용

PR150 병합 `588fa177` 확인 후 `codex/nes-whole-budget-580`에서 FPGA 입력 75개와 ARM 파일 414개를 고정했다. ARM558/577 함수 792개와 561/576 CPU 재생의 동일성을 확인하고, 104간격을 8개 비중첩 항으로 분해했다. 581에서는 53개 입력, 106개 D1 경계, 3378개 E1 발행·수락·ACK와 대상 뱅크 복원을 대조했다.

마지막 D2의 start 로그가 다음 capture 시각으로 덮어써지는 시험 도구 오류를 수정했다. 원본 106건과 누락 시각을 보존했으며 제품 실행 시계는 바꾸지 않았다.

582에서 section block, map/row base, 8B map stale, nonmap 범위 재사용의 세 가지 예산을 비교했다. 583에서는 같은 33칸 행의 ±1칸 재사용으로 대량 변경을 설명하고, 독립 M4 복원 커널과 50B 공통 진행 응답 참조 검사를 작성했다. 고정 FETCH와 가변 2단계 수신의 padding·추가 제출·마지막 confirm·조회 비용도 계산했다.

## 성과

기존 907–957 ACK 평균 70.477/71.125ms, 밀집 951–955 평균 83.157/83.121ms를 재분석했다. 952·957 최종 대기 0회와 마지막 ACK는 그대로이며 새 성능 결과가 아니다. 실기 MMC577의 13.95fps, 5–55초 13.86fps와 Flash 84B·LE 148개·M9K 5개 여유를 유지한다.

입력 map은 기존 1914B가 평균 2571.88B로 포장됐고, 출력 map의 96.8%가 같아도 전체 동일 packet은 0개였다. 583의 행 재사용으로 전송할 map word는 951에서 749→23개, 954에서 755→75개, 957에서 754→31개로 줄었다. 같은 582 호출식의 밀집 입력은 1500.2→946.6B다. **전송량 개선이며 실기 FPS 개선은 아니다.**

M4 명령 실행으로 1537행, 정상 경계 6조건, 원자적 거절 17조건을 통과했다. 커널은 248B, stack은 104B이며 제품 펌웨어에는 연결하지 않았다. 기존 여유가 84B이므로 커널만으로도 최소 164B의 기존 코드 삭제가 필요하다. 새 parser와 응답 비용은 별도다. 공통 응답은 Python 정상 6조건·거절 20조건의 참조 검사이며, 실제 RTL·CDC·STOP 검증은 아니다.

가변 2단계 수신과 공통 응답을 쓴 C안의 밀집 직렬 I/O는 10.507/10.517ms, 954는 11.589/11.638ms다. 그러나 **별도 조회 3회와 source BUSY 0회를 가정한 민감도**다. 기존 조회 수를 유지하면 36.994/36.880ms다. 이력 검사·생산자 저장, 실제 ARM·ROM·IRQ·65816·DMA·VBlank, 순 Flash·LE 비용이 남아 R3 후보로 선정하지 않았다. 제품 FW·RTL·SDC, README, 새 FIT·전체 시뮬레이션·ZIP은 변경하지 않았다.

## 후속작업

R1은 결측을 명시하고 마감했다. 물리 capture·NES 진행·입력 지연, 밀집 ROM·실제 MCU 사이클, 대표 장면, clean-clone 전체 실행은 미완료다. 같은 자료 감사와 전체 FIT를 반복하지 않는다.

다음 R2 gate는 **실제 577 ARM 문맥의 제한된 transport 교체 시험**이다. 951/954의 source-ready, 유한 queue, 실제 소비·plan 진행과 IRQ를 연결해 ACK+FETCH·공통 응답이 실제로 삭제하는 D0/D2/E0/E8 호출 수와 전체 링크의 순 Flash·stack·RAM을 확인한다. 기존 호출을 남긴 채 응답만 추가하거나 조회 3회 가정을 실측으로 취급하지 않는다.

source COMMIT의 base와 최종 표시 ACK의 bank 이력을 분리하되, 기존 old EA→new COMMIT 조건과 STOP·늦은 완료 응답 차단을 유지한다. C의 유지 데이터 독립 검사·생산자 이력이 예산에 들어가지 않으면 C를 버리고 역할·지원 범위를 재검토한다. 행 codec·packet/poll 크기의 작은 변형은 반복하지 않는다. 검증된 전체 예산을 확보한 뒤 한 후보만 R3로 진행하며 STOP·독립 검사·최종 ACK·VBlank·메뉴 복귀·GBC/save를 보존한다.
