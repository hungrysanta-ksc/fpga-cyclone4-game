## 목표

[PR150](pr-150.md)의 수정 계획에 따라 MMC577을 고정하고, 다음 구현 전에 전체 시간·전송량·선택 소스와 미측정 경계를 확인한다. 현재 범위는 R1이며 제품 성능 후보를 새로 구현하지 않는다.

## 작업내용

PR150 병합588fa177 확인 후 `codex/nes-whole-budget-580`에서 FPGA 입력75개·ARM 파일414개를 고정했다. ARM558/577 함수792개와 기존561/최신576 CPU 재생의 동일성을 확인하고 두 위상의104간격을8개 비중첩 구간으로 분리했다. 이어581에서 sealed53개 입력의section별 변경량,106D1패킷 경계,3378E1 publish/load/ACK와 대상 뱅크 map/palette/OAM을 대조했다.

## 성과

907–957 평균 ACK 간격70.477/71.125ms, SEAL 뒤DMA0.993/0.996ms, 출력 진입→SEAL 수락21.632/21.669ms다. 밀집951–955 표시 간격83.157/83.121ms,952·957 최종 대기0회와 마지막 ACK는 기존과 같다. 이 숫자는 기존 모델/CPU 재생의 재분석이며 물리 출력36.366ms의 직접 분해나 새 성능 향상이 아니다.

입력 map은 1914B가 평균 2571.88B로 포장되고, 출력 map의 약96.8%가 대상 뱅크와 같지만 전체 동일 패킷은0개다. 동일 입력 record/출력 packet을 생략하고 재포장까지 비용 없이 가정해도 밀집4118.8/4122B(12.553/12.562ms)로 잠정12ms를 넘는다. 새 skip/base/CRC·조회/gap 이전의 산술이며 실행 ABI/시간 이득이 아니다.

## 후속작업

R1은 기존 자료 분석과 제한 조사로 결측을 명시하고 마감했다. 물리 capture/NES 진행/입력 지연·밀집 ROM/실제 ARM 사이클·대표 장면·clean-clone 전체 실행은 계속 미완료다. 같은 분석을 반복하지 않는다.

다음 R2에서는 입력 section/block와 map 소비 ABI를 함께 바꿀 전송·전체 일정·실제 코드 삭제·Flash/LE/RAM/포트/STOP·cold 복구 예산을 비교한다. 함수 전체 크기를 삭제 이득으로 합산하지 않으며 현재 순삭제는0B다. 514/515의 생략 바이트 재순회·국소 DMA/poll 최적화는 재개하지 않는다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀·GBC/save를 유지한다.
