## 목표

[PR150](pr-150.md)의 수정 계획에 따라 MMC577을 고정하고, 60Hz를 위한 전체 전송·실행 비용과 실제 교체 범위를 확인한다. 국소 개선을 새 성능으로 합산하지 않고 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀를 유지한다.

## 작업내용

- PR150 병합 `588fa177` 확인 후 새 브랜치에서 FPGA 입력75개·ARM 파일414개를 고정했다. 580–581에서104표시 간격,53입력,106D1경계,3378E1 발행·수락·ACK를 대조했다. 마지막D2 시작 로그의 덮어쓰기 오류를 수정했다.
- 582–583에서 section/row 재사용·출력 stale 이력·공통 진행 응답의 참조 비용을 비교했다. 실제 M4 행 복원 커널과 입력/출력 소유권 경계를 검증했다.
- 584–586에서 실제 전체 ARM 링크와 제한된 M4 실행으로 공통 응답·section 복원·canonical CRC·shared RX를 연결했다. 이력 확장 전에 Flash 한도를 적용했고 예산 초과 후보는 채택하지 않았다.
- 587에서 기존 record 실행기의 유지 검사를 직접 section 수락·값 의미·META/END/COMMIT·취소 경계에 대응시켰다. 고정 보드의 실제 source 연결과 CRC 소유자를 확인했다.
- 588에서는 기존 D0–D3를 유지한 source base/scratch·단일 block 참조를53입력에 연결하고 in-place 행 교체·STOP/COMMIT/epoch8조건을 검증했다. 실제FIT·ARM object에서 교체 상한을 계산했다.

## 성과

실기 제품은 **MMC577: 13.95fps /5–55초13.86fps** 그대로다. 이번 PR에서 새 실기 성능을 얻었다고 주장하지 않는다. 제품 여유는 Flash84B·148LE·5M9K다.

| 후보 | 전체 ARM 이미지 | 한도 대비 | 판정 |
|---|---:|---:|---|
|MMC577|212908B|84B 여유|제품 유지|
|584 공통 응답|213352B|360B 초과|단독 후보 보류|
|586 section+응답+RX|213852B|860B 초과|이력 확장 중단|

586은53입력·15parser 거절·4수신/출력slice·18전송/취소·3API·7E9 suffix·4credit 포화를 통과했다. 하지만 source 기대 CRC와 소비/표시 허가는 모델이며 실제 IRQ·ROM·65816·2슬롯·VBlank·메뉴를 새로 검증한 결과가 아니다. 공통 응답의 plan98B/runtime30B 감소보다 native652B 증가가 컸다. BSS18940B·관측 stack832B는 전체 IRQ 최대치 증명이 아니다.

**587의 중요한 수정:** 고정 FPGA 6파일의 해시·top 연결은 입력 **256B 단일 sealed block+96bit mailbox**를 가리킨다. 584/586의 입력4packet ring은 시험 모델이다. 그 생산 시간·credit 여유를 실제 보드에 승계하지 않도록 과거 결과 문서와 현재 계획을 보완했다. host의 압축 packet CRC와 새 canonical CRC도 구분했다.

실제586 ELF의 값455개·수락 경계4조건·control22조건이 독립 참조와 일치했다. query 재읽기2반례에서는 모든 응답을 CRC에 넣으면 중복되며 실제 인덱스 전진 값만 넣어야 함을 확인했다. 기존 실행기1136B를 전부 지우고 대체를0B로 가정해도276B만 남는다. 의미 검사·출력 이력·손상 검사는 무료 삭제가 아니므로 현재 결합안의 선택 근거는 부족하다.

586의 이력 확장 가정에서 shared RX를 중복 과금하지 않고 shadow/mask/scratch2448B를 더하면 caller/IRQ/독립 검사 전2124B가 남는다. 전체 최대 stack과보드비용은 미확정이다. 선택 제품FW/RTL/SDC·설치ZIP·README 상태는 유지했다. 589의새 원형RTL·localMAP 결과는 아래에서 별도로 판정한다.

588의 source RAM 참조는586과 정확히 같은 block·packet을 생산했다. 밀집 구간의 입력 wire+driver는14.066→4.156ms로 줄 가능성이 있지만 실제 source 계산·ARM 검사·BUSY·IRQ/ROM을 연결한 개선치가 아니다. 기존 비입력 일정은두위상59.983/59.989ms여서 입력만으로60Hz를 달성하지 못한다.

교체 영역의 기존FIT는1433LE이며 여유148을 포함한 상한1581LE, 추가 source RAM 예산3M9K다. ARM은 기존packet1434+logical1112+여유84를 합친2630B가 직접 실행기 산술 상한이다. 이 수치는 실제 절감·새FIT/링크 통과가 아니다. ROM 본문·바이너리·RESTORE를 추가하지 않았다.

**589도 회로 비용으로 채택하지 않았다.** 실제53입력282packet이586과 정확히 일치하고 STOP·클록정지·잘못된POP/세대8조건을 통과했다. 하지만 같은 경계LiteMAP은1668→4014LE(+2346), 조합1311→3517(+2206),FF794→1370으로 늘었다. source RAM은M9K로 정상 추론됐다. 동적 복귀·주소/폭 선택을 갖는 source 주state는FSM으로 추출되지 않았다. 속성 변경만으로 비용이 해결된다는 증거는 없다.

예정한 중단 기준에 따라 ARM 직접 실행기 결합·전체FIT/STA·새ZIP은 진행하지 않았다. 테스트의 source/SPI tick은 ARM·IRQ·ROM·65816 표시 시간이 아니므로 새FPS로 환산하지 않는다. 최초MAP 기준의timeout을 실제보드33554432에 맞춰 reference만 재실행했고 candidate는 재사용했다. 최종 선택은test02/map02/analysis02다.

590의 8B 행CRC32+양끝·ARM same/shift 판정·묶음요청은 dense 입력I/O14.066→6.775ms, warm13.294→6.520ms의 조건부 여유를 보였다. cold13.223→12.353ms, full-map repair는 추가8.716ms다. 실제577 M4의 CRC32함수20B·기존표1024B를 재사용할 수 있어 새 표를 과금할 필요는 없다. 53입력의 map복원·20참조보호조건은 통과했지만 새 ARM전체링크·RTL·MAP·표시시간을 검증한 것은 아니다. 기존 nonmap 검사를 유지하므로 logical1112B 전체 삭제를 예산에 넣지 않았다. 제품의 실제 순삭제·새 실기개선은 아직 없다.

**591은 첫 ARM Flash gate에서 탈락했다.** 최종214760B로 기준보다1852B 증가하고 한도를1768B 초과한다. packet1434→2724B,logical1112→960B,new request320B가 주요 비용이다. BSS는같고 receiver/caller stack은40B 늘었다. 추가표 없이 기존CRC32를 재사용해도 전체예산에 들어오지 않았다. ARM 기능53입력/18조건은 통과했지만 FPGA 구현·Quartus Lite MAP·두 시작 위상·첫BG/마지막ACK 결합은 이 비용 실패로 실행하지 않았다.

590의 dense6.775ms에는 행 검사 뒤 MAP_ACCEPT 왕복과 추가phase D0가 빠져 있었다. 실제 ARM 호출을 반영한 I/O는7.121ms다. CPI2 입력 민감도는 warm20.186→15.866ms,dense21.162→16.241ms이지만 cold20.089→21.609ms로 회귀한다. 실제 MCU cycle·IRQ·ROM·표시 시간으로 해석하지 않는다. 최종 ACK/EA는 기존runtime을 유지했고 수신 시험의 consumed 호출은 fixture다. 새로운 회로 절감·실기 성능은 없다.

## 후속작업

591의 혼합phase parser에 FPGA나adapter를 더 붙이는 작업은 중단한다. 다음은 기존 record/nonmap과 새 phase/identity/완료 제어를 하나의 수신 문법으로 대체할 실제 삭제표와 전체Flash 상한을 먼저 확정하는 일이다. 완성펌웨어212992B 이하가 기준이며, 유지해야 할 의미검사1112B나request320B를 무료삭제로 취급하지 않는다. MAP_ACCEPT/repair·실제phase D0 비용을 반드시 포함한다.

구체적인 삭제 예산이 없으면 새 원형을 만들지 않고 지원 범위·코드 배치 선택으로 되돌린다. 589범용source·591혼합parser의 opcode/CRC/helper/poll/seed 미세조정은 재개하지 않는다. 독립검사·STOP·sourceCOMMIT/최종표시ACK·EA·VBlank·메뉴·GBC/save를 유지한다. 물리capture/NES진행/입력지연·대표장면·clean-clone 결측과 비입력dense59.983/59.989ms는 미해결이다. MMC577·README·ZIP은 유지하며 R3는 미선정이다.
