## 목표

MMC666을 기준으로 같은 map·OBJ 작업량에서 출력·최종 ACK를 ARM 발행·65816 수락·검사·DMA·VBlank 대기로 나누고, 독립 검사·STOP·캡처 회복·메뉴 복귀를 유지하며 두 시작 위상의 밀집 간격과 마지막 ACK를 함께 줄일 후보를 검증한다.

sd2snes+에서 이미 반영한 기능과 남은 직접 공급 구조를 구분해 후속 순서와 전체 비용 판정을 보완한다.

## 성과

실기 DWT 26.84ms를 모델 비율로 임의 분할하지 않았다. 같은 warm 52개 재생에서는 출력 28.910/28.931ms 중 ARM SEAL 발행까지 15.690/15.703ms, 업로드 VBlank 대기 9.255/9.480ms였다. 밀집 구간 마지막 추가 대기는 이미 0회다.

탐색은 실제 밀집 입력에서 CPI2 기준 약 0.75→0.14–0.18ms로 줄었으나, linear의 마지막 ACK는 +0.215/−0.214ms로 두 위상 동시 개선에 실패했다. map 선행 DMA 기회가 달라진 것이 함께 관측됐다. drain은 밀집 평균을 0.043/0.046ms 줄였지만 911의 검사 후 업로드 진입이 214→221/223번 선으로 늦어져 VBlank를 한 번 더 기다렸고 마지막 ACK는 16.849/16.640ms 늦어졌다. 두 후보 모두 기각하고 MMC666을 유지한다.

독립 출력 대조와 STOP·최종 ACK·메뉴/base 경계는 통과했다. Flash 여유는 MMC666 496B, linear 480B, drain 448B이며 data/BSS는 동일하다. 회로 추가 비용은 없고 전체 15,324 LE·962 LAB·56 M9K 및 기존 양의 STA를 유지한다. 실기 FPS 개선·새 합성 성공·새 설치본을 주장하지 않는다.

sd2snes+의 CHR 변환·2B 공급은 반영됐지만 FPGA→SNES map 공급은 별도 조사에 머물렀음을 확인했다. 표시 중 WRAM DMA 자체는 이미 있다. 공개 구현의16KiB mailbox 추가나 표시 전 ACK를 채택하지 않고, 기존4KiB bulk·1KiB packet 저장의 대체 가능성과 변환 비용을 먼저 따지는 계획으로 보완했다. 669는 소스·산출물 식별과 계획 검토만 수행했다.

## 후속작업

673 예산에 따라 957의 준비된 BG를 먼저 묶어 보내는 비용을 제한 검증한다. 최소 0.881ms의 이전 ROM 창 여유 안에 E8/E9·decode·16회 읽기를 포함하고 추가 거래 비용을 확인한다. 954는 마지막 BG 계산을 최소 2.641ms와 실제 전송/읽기 비용만큼 앞당길 의존성을 따로 조사한다. 그 뒤 검증된 immutable ordinary의 선행 발행과 결합해 두 위상 전체 일정을 비교한다. 현재 ROM 시각을 유지하는 ordinary-only·credit-only와 672 선택기 단독, 671 CRC 미세조정은 보류한다. 마감 예산 통과 후 제품 변경·전체 FIT·전달로 진행한다.

일괄 drain·단독 탐색·659 직접 PSRAM DMA 반복은 보류한다. 911의 기존 발행 마감, 951 공개선·952 3 VBlank 이하·957 추가 대기0회와 독립 검사·STOP·캡처 회복·메뉴 복귀, 두 위상의 밀집 간격·마지막 ACK 동시 개선을 유지한다. 불가능하면 비용 근거를 남기고 기존 병합 계획으로 복귀한다. 지속60fps·외부 IO 전체 sign-off는 미완료다.
