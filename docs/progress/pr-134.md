# PR134 — 실기 NROM 20% 개선과 멀티 코어 현황·인계 정리

[GitHub PR134](https://github.com/hungrysanta-ksc/fpga-cyclone4-game/pull/134). master에93bb8f715914da12d46f1d5c8262d6e8b10d3362로 병합됐다. 아래는 당시 정리/중지 시점의 기록이며, 사용자 재개 이후의 현재 작업은 [PR135](pr-135.md)를 따른다.

## 목표

sd2snes Cyclone IV 멀티 코어 확장의 NES 경로에서 실기 동작한 구성을 유지하며 입력 전송·ARM 처리 비용을 줄인다. 독립 검사·STOP·최종 ACK·메뉴 복귀를 유지하고 지속60fps를 목표로 하되 제한 NROM 성과를 NES 지원 완료로 표시하지 않는다.

사용자 요청으로 성능 개발은 중지했으며, 마지막 작업은 PR 양식과 저장소의 현재 상태·진척·재개 안내 정리다.

- PR131–133 회고와 실제 설치 경로의 비용을 분석했다.
- FPGA457 기반 입력 압축·ARM 단일 복원471, 같은 프레임 BG 계획 재사용·무진행 E0 quiet·계측 수정474를 구현했다.
- 실제 M4·독립 renderer·FPGA/65816 연결·취소/복구 회귀와 두 회차 실기475를 연결했다.
- 루트 README를 멀티 코어 목표·현재 코어 상태·진입 링크로 정리했다. PR별 기록을 progress 폴더로 분리하고 기존 원문은 archive에 보존했다.
- 오래된 AGENTS·NES 인계·코어 등록부와 문서 색인을 현재474/475 기준으로 맞췄다. PR template·운영 규칙·기록을 같은 네 항목으로 통일했다.
- 다른 PC의 읽기 순서·환경·로컬 원본 의존성과 재현 한계를 명시했다. 이 정리에서 runtime/bitstream·설치본·원시 실기는 변경하거나 다시 실행하지 않았다.

## 성과

- 같은 이동 장면471 평균19.61fps →474 평균23.59fps(+20.29%). 두 회차 모두60.07초/1417표시로 재현됐고 정상 구간은 약24fps다.
- 계획·준비13.63→6.09/6.07ms, CRC/driver 오류0, STOP·base 복구·메뉴 복귀 정상.
- FPGA는471 bitstream 그대로14740LE/13672comb/8063FF/185824bits. ARM+928text/+84BSS, Flash 파일 후미380B. 전체 CDC/IO와 지속60Hz/capture 무손실·일반 NES/MMC4/5는 미완료다.
- 완료 코어는 GB/GBC G13C44/0.9.0이며 NES는 개발 중이다. 현재 판단과 다음 순서는 채팅 없이 저장소의 짧은 진입 문서에서 파악할 수 있게 했다.
- 깨끗한 clone의 NES474 전체 재빌드는 아직 별도 로컬 source/tool/fixture에 의존한다. 이식성 한계를 숨기거나 누락 원본을 새 PASS로 대체하지 않는다.

## 후속작업

- 성능 개발은 사용자 재개 지시까지 중지한다. 이번 작업에서 새 후보·합성·전달본을 만들지 않는다.
- 재개 시474를 기준으로 남은 수신·CRC·record 비용과 이미 존재하는 capture/export·SEAL/최종ACK 일정을 먼저 분리한다. 다음 capture 중첩을 새 기능으로 재계산하지 않는다.
- 평균30fps까지9.06ms/표시,60Hz까지25.73ms/표시가 남았다. 같은 장면·같은 전체 보드 비용과 복구 조건으로 판정한다.
- 다른 PC의 실제 빌드 전에는 [로컬 입력/경로 의존성](../../cores/nes/REPRODUCING.ko.md)을 복구·일반화한다. GBC·기존 원복물과 라이선스/개인 자산 분리는 유지한다.
- 새 PR은 같은 네 항목으로 기록하고 루트 README에는 현재 상태만 갱신한다. 새 버전의 문서/링크 검사는 전용 검사기로 확인한다.
