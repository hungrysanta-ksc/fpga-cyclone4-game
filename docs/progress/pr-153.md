## 목표

MMC643 출력·최종 ACK 실측 29.51 ms의 계측 경계를 확인하고, 같은 map·OBJ 작업에서 어느 구간을 먼저 줄일지 정한다.

## 작업내용

651에서 955의 마지막 BG·OBJ 공급, E8 상태 조회, 타일 제출·수락과 큐 credit 반환을 같은 시계로 대조했다. 실제 ARM이 검증된 E8의 plan credit을 타일 제출 후 END 발행에 쓰도록 연결했다. [두 위상과 오류 주입 결과](../nes-end651-results.ko.md)

650에서 648의 954 SEAL 발행 마감을 고정하고 955 첫 7블록의 SPI·ARM CRC·복원·반환 확인을 분리했다. 같은 token 경계의 압축 형식과 실제 ARM 수신기를 세 일정으로 검증했다. [블록별 비용·표시 결과](../nes-geometry650-results.ko.md)

649에서 큐 credit 반환, section 5 발행 완료, END 확인 뒤 타일 슬롯 보존의 세 시점에 실제 ARM 입력 수신을 연결했다. 두 시작 위상의 53화면과 보드 RTL의 세대·token 경계를 확인했다. [입력·표시 일정 비교](../nes-receive649-results.ko.md)

648에서 테이블·SEAL의 ARM 마지막 쓰기, 슬롯 반환 ACK·E0 관측, SPI 발행·65816 수락을 대조했다. 고정 테이블 꼬리를 묶고 SEAL을 FIFO에 선행 발행한 ARM으로 두 시작 위상과 보드 FIFO 오류·STOP·메뉴 복귀를 검증했다. [측정과 재현](../nes-tail648-results.ko.md)

647에서 65816이 대상 뱅크의 최종 ACK 이력으로 1,100 B 패딩을 재사용하도록 구현했다. 같은 ARM과 두 시작 시각에서 개별 ACK부터 957 표시까지 대조하고 부분 STOP·양쪽 뱅크 복구를 실행했다. [분해·복구·비교](../nes-pad647-results.ko.md)

646에서 실제 MMC643 ARM의 OAM·CGRAM·HDMA 마지막 쓰기를 측정하고, END 대기의 연속 OAM 발행과 기존 명령을 사용한 HDMA 패딩 압축을 각각 두 시작 위상에서 실행했다. [분리 실험](../nes-tail646-results.ko.md)

PR152의 master 병합 9e53907을 기준으로 네 연속 일정의 52세대 작업 서명, 실제 ARM 함수 798개, 65816 ROM을 대조했다. SEAL 발행 전후·수락·DMA·업로드 및 마지막 VBlank 대기를 분리하고 후반 패킷이 기존 SPI 빈 구간에 들어가는지 검사했다. [분석·재현](../nes-output645-results.ko.md)

## 성과

651 grant는 905–957 연속 일정에서 954·955 모두 두 위상에서 3 VBlank에 표시했다. 955 END→출력은 10.717 / 12.023→6.967 / 6.965 ms, 밀집 평균은 MMC643의 59.834 / 59.870→53.286 / 53.283 ms였다. 957 최종 대기 0회, 마지막 ACK는 MMC643보다 82.961 / 82.787 ms 빨랐다. 648 대비 954 SEAL 여유는 직전 표시 기준 146 / 11 µs다. 전체 링크는 Flash 한도보다 324 B 크다.

650 packed는 1,758→495 B로 줄여 첫 7블록 비용을 9.116 / 8.902→4.187 / 4.187 ms로 낮췄다. 954 마감과 3 VBlank를 양쪽에서 지켰고, 955는 3 / 4회였다. MMC643 대비 밀집 평균 53.279 / 56.457 ms, 마지막 ACK 83.024 / 83.152 ms 단축이었다. 입력 7개 중 5개씩만 이전 ACK 전에 확인했고 실기 전달은 보류한다.

649는 세 후보 모두 954 최종 ACK 전 955 입력 7블록을 검증·반환했다. END 후보의 준비→첫 D1은 648의 13.236 / 13.117→3.571 / 4.402 ms였으나, 954·955는 모두 4 VBlank였고 밀집 합은 21 / 21회였다. 실기 기준은 MMC643이다.

648은 SEAL 조립→SPI 시작을 1.061 / 0.782→0.048 / 0.048 ms로 줄였다. 954는 4→3 VBlank, 955는 4회였다. 957 마지막 ACK는 16.25 / 32.73 ms 앞당겼으나 951 공개선은 247 / 248이었다. 954 ACK 전 955 입력 수신이 7 / 7→2 / 3블록으로 줄어 후보 채택은 보류했다.

647은 955 패딩 수락→ACK를 1.50→0.37 ms로 줄였다. 955는 두 위상 모두 4 VBlank였고 위상 1의 954는 4→5회, 위상 2의 951 공개선은 245→247이었다. 957 최종 추가 대기 0회를 유지했으나 밀집 표시 개선 기준에 미달해 실기 전달은 보류했다.

955 OAM 수락은 약 11.5–11.8 ms 앞당겼고 전송량 후보는 별도로 58 B를 절약했다. 두 후보 모두 955 표시 간격 4→3 VBlank와 밀집 간격·957 마지막 ACK 동시 단축에는 미달했다. 빈 캡처·STOP·메뉴 복귀 경계를 확인했고 실기 기준은 MMC643을 유지한다.

밀집 951–955에서 출력 진입→SEAL 발행은 18.83–20.00 ms, 업로드 VBlank 대기는 6.89–7.45 ms, 최종 추가 대기는 0회였다. 955는 1.70–2.04 ms가 직전 업로드 구간과의 시각 차이다. planner 완료 후에는 예비 credit을 둔 가장 긴 빈 SPI 구간이 0.175 ms여서 첫 0.461 ms 명령을 기존 순서로 옮길 수 없었다. 29.51 ms는 실기 평균이며 위 구간 값은 연결 일정의 측정이다.

## 후속작업

651 grant에서 ARM Flash를 최소 324 B 줄이고 650 압축 송신기를 실제 FPGA에 연결한다. 패킷 준비 지연·공유 포트 경쟁을 포함해 같은 두 일정을 재실행하고, 특히 위상 2의 954 SEAL 여유 11 µs를 다시 확인한다. 시간·Flash·Quartus Lite 전체 FIT·STA와 복구 검사를 통과한 뒤 실기 전달을 판단한다.
