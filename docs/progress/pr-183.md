# PR183 · FF3 1051 실기 회고와 다음 게임 선택 기준

## 목표

60 FPS에서는 새 화면 하나에 약 16.7ms를 쓸 수 있다. FF3 1051이 어느 종류의 작업을 줄였는지, 그 원인을 더 일찍 찾아낼 수 있었는지 평가하고 다음 비교 순서를 정했다.

## 작업내용

FF3 1050과 1051의 마지막 표시 세션, 프레임 파일 헤더, 세대별 입력 기록을 대조했다. 과거 1049의 마을·필드 원본 쓰기 추적과 ARM이 실제 발행한 명령을 같은 프레임 번호로 다시 맞췄다. 비공정은 같은 저장 슬롯에서 정지와 오른쪽 비행을 따로 재생했다. [실기 카운터·로그 해시·1049 재대조](../../analysis/ff3-1051-hardware.json) · [1051 구현·장면별 재생 검증](../nes-ff3-airship1051.ko.md)

## 성과

| 마지막 표시 세션 | 1050 | 1051 |
|---|---:|---:|
| 표시 완료 | 3,895장 | 5,864장 |
| 퀵메뉴 포함 경과 | 283.44초 | 393.60초 |
| 평균 표시 FPS | 13.74 | 14.90 |
| 55–60초 표시 카운터 / 세대별 기록 | 75장 / 62건 | 0장 / 0건 |

1051은 정상 실행됐고 사용자는 마을과 필드의 개선을 확인했다. STOP·base 복구·메뉴 준비도 로그에 남았다. 1051 진행 로그에는 31.58초와 393.60초의 두 표시 구간이 있으며 마지막 보고서의 5,864장은 뒤 구간에 대응한다. 세션 평균의 관측 차이는 +1.16 FPS(+8.4%)다. 동선·메뉴 시간이 달라 마을이나 비공정의 가속률로 쓸 수 없다. 1051의 샘플 누락 카운터는 0/0이고 수신 임시 슬롯에는 마지막 두 세대가 남았다. 55–60초 고정 창에 유효 표본이 없는 이유와 최종 ACK 단축량은 이 파일로 확정할 수 없다.

**비공정 없이도 조사에 착수할 수 있었다.** 1049의 마을 705–708과 필드 1020–1023은 모두 화면당 CHR 쓰기 2회, 변경 페이지 마스크 1이었다. 두 출력 뱅크가 채워진 뒤에도 마을은 타일 명령 46개, 필드는 55~59개를 발행했다. 이 수치에는 스크롤로 새로 보인 타일도 포함되므로 과잉 전송의 정확한 개수는 당시 자료만으로 정할 수 없었다. 그래도 물리 쓰기 주소와 다시 요구한 태그의 교집합을 측정할 근거는 충분했다.

1048의 페이지 추적은 전체 타일 이력을 버리던 문제를 완화했다. 1049는 ARM의 반복 계산을 줄이는 실험이어서 출력량이 그대로인지 검사했다. 이때 그대로 남은 전송량을 다음 병목으로 계량하지 않았다. 1050 계획에는 이미 변경 페이지 안에서 실제로 다시 요구한 타일을 세는 항목이 있었다. 비공정 슬롯의 가치는 정지·이동을 쉽게 반복하면서 이 가설을 검증한 데 있다. [1048 페이지 단위 결과](../nes-ff3-walk1048.ko.md) · [1049 ARM 비용](../nes-ff3-scroll1049.ko.md) · [1050 후속 계획](../nes-ff3-1050.ko.md)

1051은 물리 쓰기가 128B 한 범위에 모인 경우에만 그 범위의 타일을 무효화한다. 비행 표본에서는 기존 페이지 안의 BG 타일 47개 중 5개가 그 범위에 있었다. 따뜻한 두 뱅크에서 비행 6장의 계획된 타일 DMA는 82.9%, 마을과 필드 각 4장은 75.5%, 84.2% 줄었다. 같은 비행 6장의 ARM 계획 명령 수 감소는 0.4%였다. 원래 화면을 잘 보존하면서 줄일 수 있는 전송과 화면 전체의 계산 비용이 따로 남는다는 뜻이다. CHR ROM 게임에는 이번 RAM 쓰기 무효화 자체의 이득을 예상할 근거가 없다.

## 후속작업

1. **다음 측정은 FF3에서 닫는다.** 같은 슬롯과 입력으로 정지→비행, 마을→필드 동선을 재생한다. LOAD 후 플레이 재개를 기준으로 창을 열고 표본 유무를 먼저 확인한다. 두 판의 계측량을 맞춰 반복하고, 표시 FPS와 표시 간격의 중앙값·상위 5% 지연, VBlank를 추가로 기다린 화면 비율을 함께 남긴다. 변경 타일·무효화 타일·실제 재공급량과 입력 완료·마지막 타일 반환·SEAL·공개·최종 ACK를 같은 세대로 맞춘다. 회차 차이가 후보 간 차이와 비슷하면 효과 판정을 유보한다.
2. **새 병목은 여러 게임에서 찾고, 수정 하나는 고정 장면에서 검증한다.** FF3는 CHR RAM 갱신과 스크롤을, 커비는 CHR ROM 공급·OBJ 뱅크 반환을, 모험도 4는 map 전송·DMA·표시 마감을 대표한다. 커비와 모험도는 무입력 데모의 1–30초와 30–60초를 각자의 실기 기준과 비교한다. 세 게임의 FPS를 한 평균으로 합치지 않는다. [두 게임의 캐시 대조](../nes-cross1022-results.ko.md) · [커비에서 실측한 입력·ROM 대기](pr-181.md)
3. **다른 게임으로 넘어가는 시점은 남은 지연이 결정한다.** FF3에서 같은 동선의 공개·ACK 이득과 복구가 확인되면 이번 CHR RAM 수정을 기준으로 고정한다. 다음 후보는 장면에서 마감을 놓치는 빈도와 회수 가능한 VBlank 수로 고른다. 공통 ARM 계획이나 출력 경로가 유력하면 커비 또는 모험도에서도 같은 원인이 있는지 먼저 확인한다. 바이트·명령 감소가 공개 마감에 영향을 주지 않으면 그 장면의 미세 조정을 보류한다. 현재 세 게임에서 드러나지 않는 부하가 필요할 때 이카리 3·요괴도중기 등의 무입력 데모를 추가한다. 공통 경로 변경에는 기존 장면의 회귀와 STOP·LOAD·메뉴 복귀도 확인한다.
