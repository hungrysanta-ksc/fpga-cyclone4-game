# 모험도 4 오프닝·데모 표시 FPS 집계

## 목표

같은 ROM을 60초 동안 무입력으로 실행했을 때 오프닝 위주 구간과 스테이지 데모 구간의 표시 속도를 각각 비교한다.

## 작업내용

PR164가 머지된 `1f9563b`에서 분기했다. 로컬에서 검증했던 MMC820–825 소스 생성기·재생 도구·실기 분석을 먼저 보존했다. MMC826은 MMC825의 ARM 최종 링크 소스에서 판 식별자, 표시 완료 카운터의 경계와 로그 필드만 바꾼다. 같은 FPGA 이미지와 815R 표시 ROM을 사용한다.

ARM의 10ms 타이머에서 표시 완료가 100–2999틱이면 첫 카운터, 3000–5999틱이면 둘째 카운터를 올린다. 두 수치를 `display_1_30_60`로 출력한다. 호스트 비교기는 구간이 다른 두 로그의 FPS 차분 계산을 거부한다.

## 성과

최종 ARM 이미지에서 1초·30초·60초 전후의 누계, 미완료 프레임 제외와 리셋을 확인했다. Flash는 MMC825와 같은 212,944B이며 여유는 48B다. 5초 단위 작업량 로그는 처리 시작 시각으로 배정되므로 30초 전후의 표시 완료 횟수를 역산할 수 없다.

두 시작 위상의 초반·후반 재생에서 표시 간격과 마지막 ACK 클록이 모두 MMC825와 일치했다. 전환 구간의 여섯 화면도 두 위상에서 RGB·map·독립 검사 결과와 ACK를 확인했다. STOP·CRC·identity 오류 주입, 정상 ROM 수락·손상 ROM 거부, base 및 메뉴 복귀를 검증했다.

## 후속작업

MMC826을 실기에서 무입력으로 실행해 오프닝→데모 전환과 메뉴 복귀를 확인하고, 완료 횟수를 29초·30초로 각각 나눈 값을 새 대조군으로 보존한다. 이후 속도 변경판에서 같은 두 구간을 별도로 비교한다. [설치·로그 회수](../nes-mmc826-trial.ko.md)

다시 검증할 때는 `prepare_nes_windows826.py`와 `build_nes_mmc479_arm.ps1`로 최종 링크를 만든다. `check_nes_windows518.py --layout demo`로 카운터 경계를 실행하고, `run_nes_output823.py 826`과 `replay_nes_demo825.py 826`으로 초반·후반 및 전환을 재생한다. STOP·CRC·identity 거부와 타이머·메뉴·base 복원을 확인한 뒤 `package_nes_trial824.py --edition 826`으로 묶는다. 세부 결과는 [최종 링크 검증 기록](../../analysis/trial826-package.json)에 보존한다.
