# NES107 다음 구현과 필요한 보드 근거

이 문서는 설치·분해·고장 주입 지시가 아니다. 실기 없이 확인할 수 있는 구현과 보드 자료/계측 없이는 확인할 수 없는 항목을 구분한다. 현재 설치 및 실기 시작은 false다.

## 다음 구현: 진단 중 HSE 고장 종료

CSS/NMI를 HSE 고장 후 추가 IO를 막는 경로로 구현·검증한다. 독립8µs 보호라는 이름을 붙이지 않는다. 해당 지연을 입증하지 못하면 E2는 계속 미결이다.

1. RESET/USB 보호와 nCONFIG GPIO 소유권을 확보한 진단 세션에서만 활성화한다. CSS 이전 상태, 활성화·정상 종료 시점, 다른 NMI 원인을 명시한다. 일반 부팅/GBC를 전역 변경하지 않는다.
2. HSE 고장 시 일반 UART/printf/SD/FatFS/타이머 대기 함수에 들어가지 않는다. 진단 fault를 고정하고 RESET·USB 보호, nCONFIG LOW 및 필요한 직접 GPIO 종료를 수행한다. 재시도·fault 초기화·자동 base/menu 재구성 없이 종료 상태를 유지한다. nCONFIG LOW로 RAM 데이터와 설정을 잃을 수 있으므로 메뉴 복귀를 약속하지 않는다.
3. NMI의 RCC 상태 처리를 검사하고 HSI 전환 뒤84MHz 전제의 delay·통신을 재개하지 않는다. 기존 fault 관찰 함수의 호출 그래프를 그대로 NMI에 넣지 말고 재진입·부수효과를 먼저 검토한다.
4. 실제 C의 host MMIO 검증으로 진단 활성/비활성, CSS 원인/다른 NMI, 기존 fault, IRQ 차단, tick 정지, 정상 종료를 구분한다. 최종 ARM의 실제 vector·진입·직접 store를 확인한다. host 이벤트 지연을 MCU 시간으로 보고하지 않는다.
5. 생산 소스가 바뀌면 새 ARM 및 관련 회귀를 수행한다. FPGA RTL이 같으면 기존086 fit/097 ASM을 재사용한다. 이후 필요한 경우에만105 쌍의 변경 역할을 갱신한다.

CSS는 HSE 감지 경로다. HSE가 정상인 채 두 FPGA 감시 클록이 정지하는 경우, CPU/버스 정지, 공급 전압 상실은 이 구현의 보호 범위로 선언하지 않는다. TIM1 break 지원이라는 문구만으로 현재 보드에 CE 차단 배선이 있다고 가정하지 않는다.

## E2: 차단 상한을 위한 별도 결과

`이미 경과한 CE LOW + 고장 감지 + 종료 요청 전달 + nCONFIG→패드 해제 + CE의 유효 HIGH 도달 < tCEM(8µs)`를 최악값으로 충족해야8µs 보호를 주장할 수 있다. 일부 항목이 미지수이면 합계는 미확정이다.093의 Q 이후 지연23.699ns만 이 식 전체에 넣지 않는다. 공급 전압 상실처럼 임계값 자체가 유효하지 않은 상태는 별도 고장 범위로 정의한다.

- 감지 경로가 어떤 발진기·전원·버스를 필요로 하는지 도식화한다. HSE 단독 상실과 FPGA 내부 정지, 두 클록 정지, 전원 상실을 구분한다.
- nCONFIG LOW가 실제 FPGA에 도달한 시점, 출력 high-Z 시점, CE가 RAM VIH를 넘은 시점의 근거를 분리한다. 풀업 저항·부하·누설 최악값 없이는 RC 상승 상한을 정하지 않는다.
- 필요한 회로 정보/계측이 없으면 결과를 미결로 보고한다. 무제한 보호 대신 제한 실험을 택할 때는 제외 고장과 남는 데이터 손실·복구 제약을 명시적으로 판단해야 한다. 현 문서는 그 선택을 대신 승인하지 않는다.

## 진행을 반복시키지 않는 기준

다음 작업은 위 CSS/NMI 구현 또는 새 보드 근거가 있어야 한다. 동일한 부품 조회·일반 웹 검색·104 재빌드·105 재포장·106 예산 재계산으로107을 반복하지 않는다. 관측600초는 사람의 종료 한도이며8µs 차단이나SD flush 보장이 아니다. 실기 패키지가 나올 때는 새 TXT·실제 메뉴 복귀·정확044 복원을 각각 판정한다.
