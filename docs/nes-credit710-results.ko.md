# 710 E1 무변경 응답 검사 생략

## 목표

707D·기존 ARM·65816을 대조군으로 유지하고, 새 credit가 없는 E1 응답의 CRC 순회를 줄인다. 상태를 실제 갱신할 때의 전체 검사, STOP·최종 ACK·메뉴 복귀, 두 위상의911/951/952/957 표시 조건은 유지한다. [검증 JSON](../analysis/credit710-verification.json) · [원시 근거](../analysis/credit710-archive.json)

## 작업내용

ARM은 E1 길이≥20B·기존 pending≥2일 때 응답의 raw retired 두 바이트를 먼저 본다. 기존 retired와 같으면 **응답 자체를 사용하지 않는다**. 이 값은 credit를 승인하는 값이 아니라 검사를 건너뛰는 비신뢰 힌트다. 값이 다르면 기존 CRC8·F7·flags·accepted/retired 범위·최신 identity 검사를 모두 통과해야 credit를 갱신한다. `status_flags`와 `ack_status`도 모든 검사 이후에만 공개하도록 옮겼다. 손상 응답은 error만 래치하며 잘못된 상태·credit를 공개하지 않는다.

E1 snapshot은 현재 패킷 수락 이전 상태이며 현재 E1 수락이나 최종 표시 ACK를 대신하지 않는다. 19B 짧은 패킷, credit가 모자란 경우, 소비·최종 ACK 경계에는 기존 E0를 유지한다. 같은 retired의 손상 응답은 건너뛸 수 있지만 credit는 늘지 않으며 다음 필수 E0는 생략하지 않는다. STOP guard도 유지한다.

회로는709의 E1 공유·단일 snapshot 회전을 기반으로 **136비트 snapshot의 reset 제어를 삭제**했다. command/count/MISO는 기존처럼 reset된다. 모든 새 명령이 snapshot 전 바이트를 덮어쓴 뒤에만 응답을 공개하므로, 비공개 저장값의 초기화만 없앤다. raw STOP·progress 자격·수락·retire·ACK 독립 검사·입력CRC16은 그대로다. 새 RAM·CDC·FF는 추가하지 않았다. seed·핀·클록·제약은 변경하지 않고 후보 하나만 전체 합성했다.

실제 링크 ARM/65816은 같은905–957 작업량, SPI/IRQ·ROM 달력, 두 시작 위상에서 재생했다. 읽기 전용 관찰로 E1 snapshot과 실제 `response709` 진입을 기록했다. 이 관찰은 타깃 실행·비용을 건너뛰지 않는다. 생성자에서 먼저 실행되는 초기 E0 한 번은 hook 관찰 이전이므로 별도 표시했다. FPGA 직렬/ACK/STOP 시험은 별도로 수행했으며 전체 NES/PSRAM/CPU 동시 시뮬레이션은 아니다.

## 성과

**검사 생략과 FIT/STA는 성공했지만 밀집 표시 간격이 개선되지 않아 미채택이다. 선택 구성은707D·기존 ARM·65816을 유지한다.**

|---|---:|---:|
| 전체 E1 | 1,277 | 1,277 |

| 같은 retired라 추가 생략 | **260** | **258** |
| 실제 전체 CRC/counter/identity 검사 | 556 | 560 |

192B 패킷에서 새 credit가 없을 때 enqueue+room은709의4,576→**3,190명령**으로 줄었다(원본3,189). E0 fallback은 유지하므로 기존보다1명령 많다. 새 credit가 실제 있으면 기존3,193(E1+E0)→710의3,209(E1만)로, 버스 거래를 ARM 검사로 치환한다. credit가 필요 없는 경우는1,714→1,723명령이다. 이 값은 링크 M4 callback 경계 명령 수이며 실기 사이클 측정이 아니다.

위상1 마지막 ACK의 약1VBlank 이득은 **cold906이8→7VBlank로 줄어든 효과**다. 밀집 구간 자체의 추가 VBlank 단축이 아니다. 위상2는 표시 VBlank 수 변화가 없다. 두 위상 모두951–957은3VBlank이며952 표시3회·957 최종대기0회·951 공개245/236선·911 마감·7블록 선행 수신·두 슬롯을 유지했다. map/OBJ 작업량·최종 출력 바이트·tile 이미지·독립 검사·최종 ACK는 대조군과 같다.

53화면 전체의 추가 ARM 명령은204,325/676,404개다. CPI2/84MHz 진단 할당은4.865/16.105ms, E0 wire+driver 감소는23.883/19.630ms다. 이 둘을 단순 차감해 실기 순이득으로 주장하지 않는다. 위상·ROM 허용 구간·반복 polling과 DMA 일정이 달라지며, 실제 종단 결과가 위 표다.

밀집 출력·최종ACK 내부 구간은위상1 25.941→25.414ms,위상2 25.882→25.622ms로 줄었지만 화면 간격으로 이어지지 않았다. 710에서 첫 E1→SEAL 발행은16.507/17.127ms, upload 대기는4.665/4.432ms, 최종 추가 VBlank 대기는0회다. 이 구간들은 해당 재생의 실행 구간이며 실기 평균에 비율로 대입하지 않는다.

Quartus Lite 전체 FIT·STA는통과했다. setup/hold/recovery/removal은 **+0.381/+0.145/+1.412/+0.483ns**다.709A의setup−0.269ns 문제는 이 후보에서 없어졌다.707D보다 setup은+0.019ns, recovery는−0.182ns로 여유가 줄지만 양수다. 한도 통과와 회로 절감은 다르다. LE/LAB는 증가했고 LAB/M9K 여유는0이다. 외부IO 미제약 포트·클록 집계는 기준과 같으며 전체IO sign-off 완료를 뜻하지 않는다.

검사 근거:

- 실제 ARM40건: CRC·flags·counter·identity·wrap·짧은 응답 fallback·필수 최종ACK·손상 후 재전송 차단, 같은 hint 손상·새 hint 거절 시 상태 불변, 거짓 동일 hint 뒤 E0 복구, 생략 응답 뒤 STOP까지 통과했다.
- 실제 ARM 종료·통계·메뉴/base 경계16건을 통과했다. 실제 장시간 보드 플레이나 메뉴 재시험은 아니다.
- FPGA 두 SPI속도×두 위상에서 각 E1 43건·기존/확장72개 검사를 통과했다. 기존 보드와 수락/retired/SNES 제어가 클록 단위로 같고 E0 응답이 같으며 E1은 수락 전 참조 snapshot과 일치한다.
- 각 RTL 실행에8개 명령/CRC/응답 중간 reset 조건을 추가했다. reset 동안 stale snapshot 비공개, credit 초기화, 다음 E0/E1 전체 복구를 확인했다. 최대256B·4credit·ACK 중첩·STOP·RUN 해제도 유지했다. 보편적 formal 증명은 아니다.

## 후속작업

710을 그대로 재합성하거나 raw hint의 조건·고정 지연·seed만 바꿔 반복하지 않는다. **E1 조회 절감은 구현·안전성·전체 비용 검증까지 마쳤으나 현재 밀집 표시 병목을 줄이지 못한 후보**로 보존한다. 작은 조합 함수 감소를 실제 LE/LAB 감소라고 해석하지 않는다.

다음 속도 작업은707D·기존 ARM·65816에서 같은 작업량의 마지막 수락 패킷과 선행 DMA 가능한 VBlank를 다시 맞춘다. 첫 E1→SEAL 발행과 upload 대기를 분리해, ‘어느 패킷을 얼마나 일찍 수락하면 표시가 실제 한 VBlank 앞당겨지는가’를 두 위상에서 먼저 확정한다. 이전 기각된 일괄 map drain·발행 순서·고정 대기를 근거 없이 반복하지 않는다. 필수 검사·STOP·최종 ACK는 절감 예산에서 제외한다. 임계선까지 이동할 예산이 없으면 E1 미세조정보다 전송량·준비/소비 구조 변경을 검토한다.

707D 배경 CHR의 실기 확인은남아 있다. 스페이드는 사용자 실기 해결을 유지한다. 반복깨짐·stage0 timeout은별도관찰이며 속도개선으로 해결됐다고 가정하지 않는다. 새설치본은 만들지 않았다. 이후 전달 정책은새 파일명60초/장시간판·RESTORE 제외·5–40초/40–55초 집계다.

재현은 `prepare_nes_credit710.py`(기준SHA검증·patch),기존479 전체ARM 빌더,`check_nes_credit710_arm.py`와693 종료검사,`check_nes_credit710_rtl.py`(Starter FLOAT1좌석),`test_nes_credit710.py`,`analyze_nes_credit710.py` 순서다. `archive_nes_credit710.py`는전체 보드82개입력·원시FIT/STA·패치·ELF/firmware·재생로그를 해시 검증한다. 원본게임ROM·PRG/CHR·라이선스는 Git/ZIP에 넣지 않는다. clean clone 재현에는 문서화된 기존 private 입력/캡처 보관본이 여전히 필요하다.

첫 observer는 import순서로 실행 전 실패했고,첫 guard 확장은 through 인자 순서 오류가 있었다. 첫 분석은 생성자 E0가 hook 설치 전임을 누락했다. 타깃 코드 변경 없이 시험/관찰 집계만 수정했고 중간 결과·실패 설명을 보존했다. 제품이나 라이선스 실패가 아니다.
