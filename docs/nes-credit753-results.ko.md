# 753 · 957 입력과 직전 표시 credit의 시간

752의 `mapobj` ARM, 707D 보드 인터페이스와 751 `sharedfast` 정적 ROM을 기준으로 삼았다. 모든 후보는 ARM 전체 링크 후 같은 ROM을 리셋부터 실행했다. 시작 시각은 7,288,416 / 7,467,100 마스터클록이다. E8 마감은 같은 위상의 749 SPI 시작·종료, OBJ 마감은 해당 map과 같은 VBlank의 256선 이내 MDMAEN 쓰기로 판정했다. 밀집 시간은 951 공개부터 957 공개까지 여섯 간격의 평균이며 최종 ACK는 957의 65816 실제 쓰기 시각이다.

## 5,906클록의 내역

위상 1의 957 source 시작부터 planner 진입까지 749는 386,069클록, 752는 391,975클록이었다. 아래는 실제 SPI 시작·종료와 ARM 콜백 경계를 겹침 없이 분할한 값이다. D1 종료에서 D2 시작까지에는 입력 CRC, 복원, POP 준비와 해당 구간에 들어온 IRQ가 포함된다.

| 752 − 749 | 마스터클록 |
|---|---:|
| D1 수신 17회 | 0 |
| D1 종료 → D2 시작, 17블록 합계 | −45.000 |
| D2 반환·D0 상태 조회의 SPI 거래 | 0 |
| E0 거래 1회 추가 | +2,342.222 |
| 최종 ACK 조회 사이의 입력 없는 대기 콜백 | +2,782.841 |
| 나머지 ARM 응답 검사·호출 경계·IRQ | +825.852 |
| 합계 | **+5,905.915** |

추가 조회는 **956의 소비 완료**를 기다리던 중 발생했다. 752 위상 1의 E0는 그 ACK 쓰기 456클록 전에 시작했고 1,886클록 뒤에 끝났지만 스냅숏의 retired 값은 1,251이었다. ACK 뒤 5,450클록에 시작한 다음 E0에서 1,252를 확인했다. 749는 ACK 뒤 2,137클록에 시작한 E0에서 같은 값을 확인했다. 이 구간의 E0 횟수는 11→12회, 위상 2는 12→12회다. 위상 2에서는 957 입력 시작부터 planner까지의 총시간 차이가 1클록 미만이었다.

## ARM 변경

- `ready`는 7블록을 받았고 SEAL E0에 변화가 없을 때, 앞선 D2 이후 D0에서 준비를 확인한 블록 하나를 복원한다. 다음 E0를 받기 전에는 더 읽지 않는다. `geometry`는 map을 복원하는 구간에 한정하고, `one`은 최초 묶음 이후 추가 블록을 한 번만 허용한다.
- `large`는 확인된 다음 payload가 128B 이상일 때만 그 E0 대기를 빌린다. `objburst`는 사용 이력이 있는 대상 뱅크에서, 마지막으로 확인한 OBJ descriptor가 128B 이상이면 처음부터 8블록까지 허용한다.
- `prefix`는 warm 뱅크의 최초 묶음이 끝나는 시점에만 준비된 128B 이상 payload를 한 블록 더 읽는다. `prefixcrc`는 여기에 SEAL E0 전체 CRC의 바이트 단위 계산을 결합한다.
- `inputcrc`와 `sealcrc`는 기존 7블록과 조회 소유권을 그대로 두고 각각 입력 헤더·상태 CRC 또는 SEAL E0의 전체 CRC 계산만 바꾼 대조군이다.

모든 수신은 기존 D1 CRC·token 검사와 D2/D0 반환 확인을 거친다. 다음 화면의 D3 COMMIT, 이전 화면의 최종 ACK와 EA는 기존 장벽을 따른다. 공유 SPI·IRQ·ROM 비용은 이전 보드 기록을 적용한 시뮬레이션이며, 새 실기 FPS 측정은 없다.

## 선택한 8블록 후보

`prefix`는 원래 7번째 블록의 D2/D0를 확인한 순간, ① 이전 화면이 이미 SEAL 단계이고 ② 대상 뱅크에 재사용 이력이 있으며 ③ 검증된 다음 source head가 준비됐고 payload가 128B 이상일 때 그 한 블록을 마저 읽는다. STOP을 확인한 뒤 원래 E0 경로로 돌아간다. 957의 여덟 번째 D1은 131B(128B payload)였다. 루프가 매 quiet E0마다 새로운 입력을 계속 꺼내지 않는다. CRC·token 검사는 기존 루틴을 사용했다.

두 위상에서 D1 17회·총 1,772B와 D2·D0의 전송량은 같았다. 위상 1에서 E0 세 거래가 7,027클록, 최종 대기 콜백이 8,349클록 줄었다. 복원→POP 준비 구간은 90클록 늘었고 나머지 ARM·거래 경계가 2,465클록 줄었다. 956 화면은 위상 1에서 749보다 한 VBlank 일찍 공개됐다. 이를 보정한 뒤에도 E8이 빨랐다. 952–957의 개별 표시 간격은 양쪽 모두 3 VBlank다. 951은 236선에 공개했고 957의 최종 대기는 0회였다. Flash는 212,960B로 32B가 남는다.

`sealcrc`도 독립적으로 모든 마감을 통과했다. 다음 단계에는 두 위상에서 OBJ 시작이 246선으로 일치하고 956 공개 뒤 E8 여유가 1ms 이상인 `prefix`를 사용한다. 957 최종 ACK만 752와 비교하면 `prefix`는 위상 1에서 357,368클록 빨랐고 위상 2에서 464클록 늦었다.

## 7블록 유지 대조군

`sealcrc`는 752의 `mapobj`에 SEAL 대기 중 E0의 CRC-8/ATM만 바이트 단위 동치식으로 교체했다. 등록된 18B 전체와 최종 identity를 검사한다. 입력은 두 위상 모두 첫 7블록·D1 총 17회(1,772B 전송)를 유지했다. ARM 전체 이미지는 212,956B로 36B가 남는다. BSS는 19,796B로 같고 5,120B 정적 ROM에는 61B가 남는다.

956의 공개 프레임 번호는 두 위상 모두 749와 같았다. 952·957에서 각각 1,536B를 나눔 없이 SEAL 수락 전에 보냈고, 957에서는 48B BG → map → 288B OBJ가 같은 VBlank 안에 끝났다. 951은 양쪽 236선 공개, 952–957의 개별 표시 간격은 모두 3 VBlank, 957 최종 대기는 0회였다.

위상 1에서 이전 최종 ACK의 E0는 752와 같은 12회였다. 빨라진 부분은 각 응답을 검증한 뒤 다음 일을 시작하는 ARM 경로다. 같은 수신 구간에서 SPI 거래 및 D1→D2 준비 비용은 그대로였고, ARM·IRQ·거래 경계의 잔여 비용이 6,429클록 줄었다. 위상 2에서는 조회가 12→13회로 늘어 E0와 대기에 약 5,125클록을 더 썼고 ARM·경계 비용이 6,095클록 줄었다. 최종 ACK 절대 시각은 752 `mapobj`보다 **134 / 120클록 늦다**. 이번 채택 조건인 727 대비 개선은 두 위상 모두 유지했다.

## 보호 조건과 재현

각 실행에서 53회 표시, 2슬롯 한도, map WRAM→VRAM과 727의 화면 RGB를 확인했다. 패킷은 프레임 내 발행 순번을 제외하고 opcode·범위·payload·중복 횟수를 비교했다. OBJ가 다음 VBlank로 밀린 경우에는 256보다 작은 선 번호도 탈락시켰다. 908·911은 2 VBlank 이내, 951 공개는 246선 이내, 952는 3 VBlank 이내, 957의 최종 대기는 0회로 판정했다.

`prefix`와 `sealcrc`의 ARM에서 기존 deadline·취소 17건, 독립 receipt 9건, 페이지 전환 8건, map·OAM 조건 6건, 첫 입력 묶음 6건, 최종 E0 응답 152개 단일 비트 오류 거부 및 wrap, 메뉴·base 복구 5경로·표식 4건을 확인했다. `prefix`는 별도로 126/132B, cold/첫 뱅크와 warm 이력의 수신 한도도 확인했다. 두 후보의 동일 정적 ROM에서 957의 288B OBJ 직전·도중 STOP, 새 패킷 삽입, stale receipt까지 두 위상에 주입했다. STOP과 stale은 956 화면을 보존하고 957 최종 ACK를 차단했다. DMA 중 STOP은 시작한 DMA 한 건을 끝낸 뒤 차단했고, 새 패킷은 다음 DMA보다 먼저 수락했다. 보드 RTL과 정적 ROM은 752와 동일하다.

1. [ARM 소스 생성기](../tools/prepare_nes_credit753.py)에 `../probes/nes-credit752/arm-mapobj ../probes/nes-credit753/patch-K --policy K`를 전달한다. [전체 링크](../tools/build_nes_mmc479_arm.ps1)의 Base는 같은 752 ARM, Patch는 생성한 폴더, Out은 새 `../probes/nes-credit753/arm-K`의 절대 경로다. 752 ARM·751 정적 ROM·749/727 대조군의 준비는 [752 재현 안내](nes-credit752-results.ko.md)를 따른다.
