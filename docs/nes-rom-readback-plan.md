# NES 물리 ROM 읽기 검증 후속 설계

SPDX-License-Identifier: MIT.

이 문서는057 이후의 **미구현 설계**다. 물리 메모리를 검사했다고 표시하지 않는다. 057 공동 진단 fit는954/963LAB이므로 검증용 CRC32 회로·두 번째 PSRAM 제어기를 바로 추가하지 않고 기존052 읽기 제어기와 STM32의 계산을 재사용하는 경로부터 평가한다.

## 확인한 기존 경계

- 053 `nes_rom_boot`는 RUN일 때만 읽기 핀을 선택한다.052 reader의 reset도 `!run_enable` 및 코어 초기화의 `read_reset`에 묶여 있다. 따라서 MCU에서 단순히 읽기 명령만 추가해도 실행 전 readback이 되는 구조가 아니다.
- 054 SPI 프레임은8바이트이며 응답은 명령 수신 때의 snapshot이다. CS 상승 뒤 명령이 반영되므로 새 READ도 응답 완료를 따로 확인해야 한다. 프로토콜 버전과 상태 해석 변경은056 MCU와 구분해야 한다.
- 057은 로더가 승인한 `chr32` 레지스터 하나를 길이와 코어 CHR mask에 연결한다. 검증할 논리 길이도 이 설정을 사용해야 한다. 명령 인자 latch를 승인된 형상으로 사용하면 거부된 BEGIN으로 설정이 바뀐다.

## 우선 평가할 구현

END가 승인된 뒤에도 코어·패킷·로컬 RAM 소비자를 reset에 둔다. 기존 reader를 별도 CHECK 소유권으로 잠시 열고, MCU가 논리 바이트 주소별 데이터를 받아 승인된 SD 진단과 비교한다. 논리0..FFFF는 PRG,10000 이후는 물리200000 이후 CHR로 변환한다. 이때 쓰기 제어기·CHECK·RUN은 PSRAM 핀의 상호 배타적인 소유자여야 한다.

MCU는 입력 파일 검증과 별도로 **물리 경로가 반환한 바이트**를 비교/CRC 계산한다. END나 입력 CRC만으로 검증 성공을 기록하지 않는다. 전체 길이가 일치하고 모든 응답의 주소·데이터·완료 상태가 확인된 경우에만 후속 RUN 진입을 허용한다. 보안 인증 기능은 아니다.

READ 명령/응답에는 단일 outstanding 요청, 명시적 busy/완료, 요청 주소 tag가 필요하다. 명령 프레임의 offset 레지스터는 다음 STATUS 수신 중 덮어써질 수 있으므로, 이를 CDC payload 보관소로 그대로 쓰지 않는다. 요청/응답은 ack까지 안정적으로 유지하고 두 클록 사이의 제어 동기화·리셋 취소 계약을 정한다. 기존 byte/상태8바이트 프레임을 유지할지와 구체적인 opcode는 자원 실험에서 확정한다.

CHECK 완료 후 진행 중 읽기를 비우고 reader 양쪽 도메인을 공통 reset으로 초기화한다. 그다음 기존 RUN 및049 scrub 경로로 전환한다. CHECK 동안 코어 reset과 reader reset은 구분해야 하지만, 오류·STOP·재설정 시에는 reader 양쪽을 함께 취소해야 한다. 독립 도메인 reset이나 상태가 남은 채 RUN으로 전환하는 방식은 사용하지 않는다.

## 필요한 검증

1. 실제 write pin으로 채운80/96KiB를 CHECK 읽기로 전부 검사한다. 저장된 한 바이트·chip/lane·CHR 주소 상위 비트를 각각 손상시켜 MCU가 RUN 전에 거부하는지 확인한다.
2. busy 중 새 READ/BEGIN/DATA, 오래된 완료 응답, 주소 tag 불일치, 응답 없음, CS 절단, STOP/PLL loss/common reset을 검사한다. 오류 복구 중에도 쓰기 펄스 유지와 데이터 핀 충돌 금지를 확인한다.
3. 실제 새 MCU GPIO 파형을 새 RTL에 재생하고, 호스트 모형만 통과한 상태와 구분한다. 기존044 식별/복구와056 USB IRQ·GPIO 소유권·기본 FPGA 실패 보호를 유지한다.
4. **첫 통합부터 공동 map/fit**로954LAB 기준과 비교한다. 독립 모듈 LE 합산으로 남은9LAB에 들어간다고 판단하지 않는다. 초과하면 동등성 근거가 있는 기존 회로 최적화가 먼저다.
5. 검증 통과 후 실제 코어8프레임/전체 이벤트를 회귀한다. 읽기 검증 시간이 추가되는 것과 RUN 이후 프레임/개별 메모리 읽기 마감은 구분한다. 이후 보드 클록/소비자/전체 핀·PLL fit/STA를 완료한 후보만 실기에 전달한다.

현재250kHz에서 DATA+STATUS 한 쌍은 최소556µs/바이트다. readback도 같은 요청/응답 비용을 쓴다면80KiB 약45.5초,96KiB 약54.7초가 적재 시간에 추가될 수 있다. 이는 처리량 추정이며 구현 측정이 아니다. 처음에는 명확한 진행·중단 결과를 갖춘 진단을 우선하고, 더 긴 burst 응답은 별도 프로토콜·메모리 소유권 검증 후 최적화한다.
