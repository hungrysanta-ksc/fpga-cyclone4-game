# 592: nonmap·요청·완료 제어의 교체 예산

제품은 MMC577을 유지한다. [591](nes-roles591-results.ko.md)의 실제 M4 바이너리를 같은 53개 입력으로 다시 실행했다. cold 병목은 찾았지만, Flash와 시간을 함께 통과한 새 바이너리는 없다. 근거는 [실행별 명령 수·링크 크기·한도](../analysis/boundary592-verification.json)다.

## 실제로 교체할 코드와 남겨야 할 일

| 591 링크 경계 | 기존 | 교체 후 상한 | 필요한 순삭제 | 새 경계가 맡는 일 |
|---|---:|---:|---:|---|
| packet | 2,724 B | 1,434 B | 1,290 B | BEGIN·요약·행과 nonmap을 하나의 phase/ordinal cursor로 진행. nonmap은 구형 record의 kind/index/generation 재해석 대신 절 단위 typed block 사용 |
| logical_record | 960 B | 622 B | 338 B | 복원과 함께 개수·범위·필수 tile·CRC 검사. phase 종료와 입력 완료는 한 소유자가 판정 |
| request / poll / PREPARE | 320 + 568 + 224 B | 972 B | 140 B | 하나의 상태 전이에서 요청·재요청·응답 identity·완료를 관리. D0/D1/D2/D3/D4와 승인 순서는 유지 |
| **합계** | **4,796 B** | **3,028 B** | **1,768 B** | 새 표·보조 함수·정렬이 다른 곳에서 늘면 그만큼 상한을 더 낮춘다 |

첫 상한은 577 packet의 실제 크기, 셋째는 실제 요청 320 B와 577 poll/PREPARE 652 B의 합이다. 가운데 622 B는 잔여 예산이며 구현 크기 추정이 아니다. 577에서 대응하는 네 함수만 해도 3,198 B였다. 즉, 원래보다 기능이 늘어난 상태에서 그보다 170 B 더 작아져야 한다. 591 packet 안의 old record/raster 귀속분은 728+68 B뿐이고, 그 안에도 새 코드가 계속 해야 하는 일이 있다. 591의 request/poll/PREPARE를 그대로 쓰면 나머지 둘의 합은 1,916 B 이하여야 한다. DWARF 줄 귀속을 실제 삭제로 세지 않는다. 확인된 제품 순삭제는 **0 B**다. 최종 판정은 214,760 B인 전체 링크가 **212,992 B 이하**인지다.

## cold 905의 시간 예산

cold에서 기존 591은 377,344명령이다. 957개 map 값에 대한 일반 의미처리 74,646명령, canonical 처리 37,323명령, 1,914 B map CRC 재순회 19,147명령이 **서로 겹치지 않는 131,116명령**이다. 호출된 필수 tile 검사의 본체 비용을 이 수치에 더해 절감으로 잡지 않았다. cold에서는 재사용 행 요약 digest를 호출하지 않으므로 그 함수를 줄여도 이 프레임은 빨라지지 않는다.

후보는 수신값과 재사용값 모두를 **확정될 순서의 실제 map 값**으로 순회하면서 15비트 값·행 범위·coverage·필수 tile을 검사하고 독립 CRC를 한 번만 누적하는 것이다. 예상 CRC와 일치할 때만 그 누산값으로 nonmap canonical CRC를 이어간다. 요약 fingerprint를 독립 CRC 대신 쓰지 않는다.

별도로 nonmap은 기존 literal/repeat/raster-linear 선택과 블록 경계를 유지하고 절·모드·개수를 3 B로 한 번만 기록했다. cold의 nonmap 본문은 588→517 B, 해당 단계의 패킷 수는 4→4다. 새 소스 선행 읽기나 추가 병합 이득은 넣지 않았다. 53개 입력의 nonmap 복원·이어 계산한 전체 CRC가 일치했고, 필수 tile tag/종류 5,255쌍도 기존 ARM 결과와 같았다. 잘림·누락·중복·순서·길이·모드·범위 오류 등 8개 참조 입력을 거부했다. 이것은 새 FPGA 송신기나 실제 ARM decoder의 검증은 아니다.

| cold 입력, 84 MHz 가정 | 577 | 591 | 새 문법 조건부 예산 |
|---|---:|---:|---:|
| I/O 시간 | 13.223 ms | 12.625 ms | 12.408 ms |
| CPI 2 입력 시간 | 20.089 ms | 21.609 ms | 577과 같아지려면 591보다 **54,767명령 이상** 절감 |
| CPI 1에서 필요한 절감 | 기준 | 기존 wire면 38,743명령 | 새 wire면 20,567명령 |

71 B 절감은 약 0.216 ms로, CPI 2 회귀 1.520 ms를 단독으로 상쇄하지 못한다. 기존 wire를 유지하면 63,855명령을 줄여야 한다. 새 문법을 쓰고 다른 작업량이 같다면 map의 세 경로는 **131,116→76,349명령 이하**(값당 79.78명령)여야 한다. 새 decoder·임시 상태·복구 등에서 늘어난 명령은 별도로 차감한다. 두 번의 CRC를 모두 없앨 수는 없다. warm/dense 입력의 조건부 I/O는 각각 6.481/6.859 ms다. 모든 D4 요청·MAP_ACCEPT/REPAIR와 단계 간 D0를 포함한다. 이 값들은 실측 MCU cycle·ROM 경합·첫 BG·최종 표시 시간이 아니다.

## 검사와 공개 경계

- 동일 epoch/serial/generation/token, 단계·순번·정확한 길이와 wire CRC를 확인한다. packet D2는 수신 credit만 돌려준다. 행 전송 D2 뒤 MAP_ACCEPT 또는 REPAIR가 결정되기 전에는 nonmap으로 넘어가지 않는다.
- 필수 tag와 map 상태는 CRC 및 coverage가 맞을 때까지 비공개다. 기존 bitmap을 임시용으로 쓸 수 있는 조건은 계획/IRQ가 미확정 값을 읽지 않는 것이다. REPAIR 때 cursor·CRC·seen·임시 tag를 폐기하고 전체 map으로 다시 계산한다. 초기화·재요청 시간을 예산에 포함한다.
- cold·STOP·부분 전송은 미확정 입력과 그 재사용 권한을 무효화하고 다음 입력은 전체 행으로 복구한다. source base는 확인된 COMMIT 응답 뒤에만 갱신한다. 표시 bank 이력은 독립 검사와 VBlank 표시 뒤의 최종 ACK에서만 갱신하고 이후 EA를 허용한다. STOP이나 입력 완료가 최종 표시 ACK를 대신하지 않는다. 이번 단계에서 새 실행기의 STOP·최종 ACK·메뉴 동작을 시험했다고 간주하지 않는다.

## 다음 단일 판정

같은 ARM 전체 링크에서 위 다섯 함수를 실제로 대체하고, 전체 Flash 한도와 cold 905 입력 예산을 **동시에** 통과하는지 한 번 검증한다. retained 표·library·stack/IRQ·repair·cold 복구를 따로 계상한다. 어느 한쪽이라도 실패하면 이 문법에 FPGA를 덧붙이지 않고 코드 배치·지원 범위를 다시 검토한다. 둘 다 통과해야 FPGA 고정 행 공급/CRC·STOP 및 실제 독립 검사·최종 ACK·메뉴 복구, Quartus Lite 전체 비용과 두 시작 위상의 첫 BG~마지막 ACK 비교로 넘어간다. 60 fps 판정이나 실기 전달본은 없다.
