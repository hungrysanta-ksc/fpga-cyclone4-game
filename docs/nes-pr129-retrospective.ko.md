# PR129 회고와 머지 후 작업 계획

2026-10-19. PR129의 NES248–255 검토를 마무리하고 다음 목표를 전체 구현 가능성 판정으로 전환한다. 검토 기준은 cdb64745c823b7eed9b127f8da8baa4670ad12e2다. 이 문서와 [실행 계획](nes-pr129-next-plan.json)이 과거 NEXT 지시보다 우선한다. 과거 측정·실패·미검증 범위는 그대로 보존한다.

## 회고

ARM 화면 계획 / FPGA map 해석·검증 / SNES DMA·표시는 유망한 역할 분담이지만 아직 제품 구현으로 선정하지 않았다. 이번 PR에서 source 구조, 단계별 RAM, CRC·인증서 문맥, query 선행 읽기와 receipt·소비 제어의 실제 비용을 확인했다.

| 확인한 성과 | 해석의 한계 |
|---|---|
| NES255 동일 기능 경계 MAP 3414→3362LE, 1046→985FF, RAM49152bits 동일 | 전체 보드490LE·40LAB 부족에서52LE를 뺄 수 없다 |
| warm 입력 평균 약0.060074ms 개선, 출력74..152cycles 감소 | 실제 ARM·출력 SPI parser·SNES 실행을 포함한 시간이 아니다 |
| 기준/후보 각각71프레임·28오류 검사, 후보8부분 CRC 갱신 통과 | 소비 sink는 모델 메모리이며 실제 bank/token·표시 ACK는 미연결이다 |
| RAM 수명·취소·부분 수락과 선행 읽기를 함께 검증 | fullFIT/STA·fullRUN/IRQ·실기60fps는 미검증이다 |

주된 반성점은 부분 회로를 줄이는 동안 실제 연결에 필요한 제어가 비교 경계 밖에 남았다는 것이다. source의 절약에 receipt·인증서·어댑터 비용이 추가됐고, 공유 RAM으로 메모리를 줄여도 논리가 줄지는 않았다. query 통합은 선행 읽기를 없애 시간을 늘렸으며255에서 이를 복원했다. 따라서 FF 감소, RAM instance 감소, 독립 MAP 차이를 전체 이득으로 대신하지 않는다.

조건부 최대15.995909ms는 ARM32000cycles·parser8cycles/byte·SNES setup500 및 검사 제거 가정을 포함한다. setup1000이면16.857285ms로 예산을 넘는다. 스트레스 공급 시간을 추가한 수치도 실제 성능의 상·하한이 아니다. 다음 단계에서는 수십μs의 추가 국소 절약보다 이 미측정 비용을 실제 실행으로 확인하는 일을 우선한다.

## 다음 목표와 순서

목표는 **같은 ARM/FPGA/SNES 구성으로 전체 회로와 연속 표시의 프레임 예산을 함께 만족할 수 있는지 판정하는 것**이다. NES255는 검증 후보로 유지하며 채택을 미리 결정하지 않는다.

1. **R0 — 교체 경계와 비용표 고정.** source/query, 출력 SPI head/READ/ACK, parser, receipt, bank/token 및 최종 표시 제어에 대해 제거·유지·추가할 실제 모듈과 소유자를 명시한다. tail CRC·fresh scroll·OAM·H2도 포함한다. 공유 RAM 포트/단계 수명, 클록/CDC, 패킷 분할과 큐 credit를 함께 기록한다. 같은 프레임의 비용을 실측·모델·미확인으로 구분하고 중첩은 의존성과 실제 자원 소유권으로 입증한다. 미확인 비용을0으로 두거나 parent/child MAP을 중복 합산하지 않는다.
2. **R1 — 부담이 큰 프레임의 실제 연결.** 952/954/955/962/963/968/970을 시작 집합으로 사용하되255 자료와 실제 경로에서 더 나쁜 프레임이 나오면 추가한다. ARM N5 복원·계획·인증서·전송, 출력 SPI parser/큐, 실제 SNES setup·남은 검사·DMA·poll·VBlank를 연결해 측정한다. 입력 COMMITTED, typed consume, final display ACK/capture lease retire를 분리한다. 테스트벤치 sink나 과거 SNES 시간만으로 연결 완료라 하지 않는다. MCU 계측이 없으면 그 항목은 미확인으로 남기고 통과 처리하지 않는다.
3. **R2 — 같은 후보의 전체 자원·시간 판정.** R0/R1에서 비용 근거가 성립하면 최소 통합 후보로 전체 MAP/FIT와 필요한 STA/CDC/IO를 확인한다. 같은 소스 해시의 ARM fullRUN/IRQ·메모리, FPGA, SNES로71프레임과 취소·재시작·부분 소비·raw2→0 양 bank 전환을 검사한다. STOP/세대/lease 및 최종 표시 소유권을 유지한다. 처음 전체 자원 검사가 실패하면 실패 원인을 기록하고 구조적 변경 근거가 있을 때만 다시 실행한다.
4. **R3 — 실기 연속 표시 확인.** R2 통과 후 SMB3 첫 레벨 연속 스크롤에서 실제 표시 간격·최대 공백·capture-to-display age를 측정하고 사운드·유지/동시 입력·메뉴 복귀를 확인한다. cold/장면 전환은 연속 스크롤과 별도 보고한다.

R0/R1은 가능성 검증이며 P2 제품 후보 선정과 다르다. R2 통과 전에는 전체 회수·설치 가능·60fps 달성을 선언하지 않는다. 기준16.666667ms는 명목60Hz 예산이다. 실제 NTSC 표시 주기와 VBlank/DMA 마감도 확인하며 평균만 맞추거나 프레임 버리기·게임 감속으로 통과시키지 않는다. FPGA의 LE/LAB/M9K와 mapper·배선·타이밍 여유, ARM의 기존 메모리/스택 게이트를 같은 구성으로 확인한다. 임의의 여유율이나 ROM4KiB 제한을 새로 만들지 않는다.

## 중단·재계획 기준

실제 시간 초과나 전체 면적 부족이 남고, 이를 줄일 구체적인 기존 제어 대체/전송량 감소 근거가 없으면 후보 채택을 보류하고 전송 표현과 역할 분담을 다시 비교한다. 작은 FSM·카운터·ROM/opcode·seed 조정과 FIT 반복으로 다음 목표를 대체하지 않는다. 한 후보의 실패를 전체 역할 분담의 불가능으로 확대하지 않으며, 부족한 비용과 실패 프레임을 근거로 다음 결정을 내린다.

## 머지 및 재개 계약

이 PR의 마지막 변경은 회고·계획·인계 문서다. 새 RTL/ARM/SNES 구현, 합성·시뮬레이션·실기 시험은 추가하지 않는다. PR129는 검토/머지를 기다리고 여기서 작업을 멈춘다.

머지 후 재개할 때 GitHub의 merged 상태와 실제 merge SHA를 확인하고 origin/master를 갱신한다. 그 merge SHA가 master에 포함됐는지 확인한 뒤 깨끗한 master 기준의 새 codex/ 브랜치와 새 PR에서 R0부터 시작한다. PR129의 기존 브랜치에 후속 구현을 쌓지 않는다. 진행 중인 사용자 변경은 보존한다. 본 계획은 자동 머지나 주기적 확인 작업을 요청하지 않는다.
