# MMC903 · 모험도 4 마지막 타일 실기 계측

MMC897에서 간헐적으로 마지막 타일 수락이 늦어지는 구간을 측정한다. MMC901의 55–60초 표본에서 마지막 타일의 65816 수락이 비교 화면보다 23.56ms 늦었다. MMC903은 같은 타일의 FPGA 준비부터 65816 수락까지를 한 화면의 기록으로 남긴다.

## 한 번 실행하는 방법

1. 전원을 끄고 ZIP 안의 `MMC903-ADVENTURE-60SEC-SD-ROOT` 폴더 **내용물**을 SD 루트에 복사한다.
2. MMC901에서 사용한 일본판 모험도 4 ROM을 `sd2snes/nes/mmc903.nes`로 복사한다.
3. 메뉴에서 `NES MMC3 903.nh1`을 선택한다. 60초 동안 입력 없이 오프닝과 플레이 데모를 보고 자동 메뉴 복귀를 확인한다.
4. 메뉴 복귀 뒤 SD의 `sd2snes`에서 `nes-frame-mmc903.bin`, `nes-budget-mmc903.txt`, `nes-progress-mmc903.txt`, `nes-game-last-mmc903.txt`를 보관한다. BIN은 55–60초의 개별 화면, budget은 전체 오프닝과 데모의 표시 수를 담는다.

기본 실행 한 번이면 된다. 추가 대조가 필요할 때만 로그를 복사한 뒤 `NES-DIAG`의 EARLY(30–35초), LATE(55–60초) 또는 CONTROL(55–60초, SPI 계측 조회 생략)을 사용한다. 같은 설치본의 네 로그는 다음 실행 때 덮어쓴다.

## 기록을 읽는 방법

`tools/read_nes_tile903.py nes-frame-mmc903.bin`은 이전 화면 공개를 기준으로 아래 시각을 복원한다. 같은 화면에서 마지막으로 소비한 타일의 세대·종류·32비트 token을 ARM의 12B descriptor와 대조한다. 시간 단위는 6.10µs이고 같은 단위 안에 든 이벤트의 순서에는 1틱 오차가 있다.

| 구간 | 구분할 대기 |
|---|---|
| FPGA 뱅크 쓰기 완료 → 그 뱅크가 읽기 선두에 등장 | 앞선 타일이 읽기 뱅크를 차지한 시간 |
| 읽기 선두 → 최초 유효 E8 스냅샷 | ARM이 해당 타일을 조회할 때까지의 시간 |
| E8 스냅샷 → E1 타일 opcode 도착 | E8 응답 나머지 바이트, ARM 준비와 공유 SPI 대기 |
| E1 opcode → 65816의 첫 헤더 읽기 | 나머지 패킷 전송과 큐에서 소비되기까지의 시간 |
| 첫 헤더 읽기 → 화면 공개 | 해당 타일 수락 뒤 남은 출력 전체 |

E8은 FPGA가 첫 명령 바이트를 받은 시각이고 E1은 두 번째 바이트를 받은 시각이다. 개별 DMA 완료와 ROM 허가 시각은 이 기록에서 분해할 수 없다. ARM의 입력 완료와 첫 유효 최종 ACK 확인은 별도 시계이므로 조회 시간만큼 오차 범위를 둔다. 타일이 없는 화면, 이력 누락, 버퍼 포화는 구분한다. 실기 비교 시에는 세대 번호가 달라질 수 있으므로 뱅크·map·BG·OBJ 작업량이 연속해서 일치하는 화면을 대응시킨다.

출시 링크 재생에서 MMC901 대비 30–35초 표본의 여섯 표시 간격 합은 두 시작 위상 모두 14 VBlank, 55–60초 표본은 모두 13 VBlank였다. 뒤 구간의 마지막 ACK 클록과 네 조건의 RGB도 일치했다. 재생에서 ROM 허가와 큐는 모델로 처리하며, 두 뱅크의 실제 전환과 반복 E8은 별도 RTL 시험으로 확인했다.
