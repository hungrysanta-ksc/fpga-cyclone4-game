# NES165 로더 명령 차단과 SPI 응답 직렬화

PR108의 FPGA 구현을 계속한 결과다. **실제 클록 setup이 아직 미달이므로 실기 설치판은 아니다.** [검증 수치](../analysis/retire165-verification.json)와 [현재 인계](../cores/nes/HANDOFF.ko.md)를 함께 본다. 기존 CHECK 배치의 입력61개 중3개만 바뀌었고 나머지58개는 바이트 단위로 같다.

## 작업 목표와 의미

전체 영상 경로가 FPGA 안에 들어간 뒤 남은 로더·SPI 제어 지연을 줄여 실기용 영상 전송 구현으로 이어가는 작업이다. 디버그 항목 추가나 새 게임 기능 구현이 아니다. 실제 게임용 MCU 수신·변환·ACK 연결은 아직 남아 있다. 설치164의 사운드·입력·STOP·메뉴 경로와 카트리지 세이브 SRAM은 그대로다.

## 채택한 변경

- 로더의4개 명령에 각각 붙었던 공통 CHECK 오류 차단을 로더 입력으로 전달하고, 명령 충돌 판정 뒤에 한 번 적용했다. 일반 명령 수락 조건과 STOP·진행 중 쓰기 종료 우선순위는 같다.
- SPI 응답의56비트 스냅샷을 매 비트마다 큰 선택기로 읽던 구조를 순서대로 시프트하는 구조로 바꿨다. 스냅샷을 잡는 시점과 MISO가 바뀌는 하강 edge, MCU가 읽는 상승 edge는 같다. 내부 스냅샷 표현만 달라지고 SPI식별6B·명령 완료 시점은 유지한다.
- 원본GBC·기존NES 소스는 수정하지 않고 재현 도구가 진단용 입력을 생성한다. 선택은 **retire165 map02/reproduce02, variant=serial**이다. map03은 선택하지 않는다.

## 검증과 한계

로더는 차단0/1을 포함한52,224개 한 단계 상태에서 출력·다음 상태·데이터·타이머가 이전 구현과 일치했다. 잘못된 차단 조건은 음성 대조시험에서 검출됐다. 전체393216바이트를 다시 쓰는 시험은 아니다.

SPI 응답은256프레임·15,680비트·1,347,840메모리 클록 경계에서 외부 출력이 일치했다. 프레임 도중 상태가 바뀌어도 처음 캡처한 응답을 유지하며 짧거나 긴 프레임도 비교했다. 잘못된 응답 비트는 검출됐다. 별도로 실제SPI 경로98검사,8쓰기,6CHECK읽기,6오류조건·19비트 ACK 경계·finish/START를 통과했다. 이 결과는 새 SMB3 전체 부팅이나 MCU 통합 시험을 뜻하지 않는다.

선택 배치는35/56M9K,8329레지스터,197104메모리비트,1PLL,122실제핀·0가상핀이다. 합성 추정 LE와 실제 FIT LE를 혼동하지 않는다. LAB 여유는0이다. NES setup+5.344ns,host+0.021ns,board+124.038ns,hold 최저+0.159ns다. 메모리 클록은5.952ns이며 `boot.check_failed -> control.check_next[15]`가−0.217ns다.

기존 구현 SDC의5.5ns CHECK·5.3ns 배치 목표는 그대로 유지했다. 그 조건에서−0.426ns라는 실패도 보존했다. 별도 STA는 핀으로 고정한155의 순수 클록 SDC를 재사용했으며, 새FIT·클록 변경·false path·multicycle 추가 없이367개 소스/설정/배선 DB가 그대로임을 검사했다. 추가 목표와 실제 클록은 서로 다른 수치이며 어느 쪽도 전체 타이밍 통과로 표시하지 않는다. 혼합 도메인 raw setup−15.982ns와 외부 입력54·출력57미제약 포트는 IO/CDC 미완료로 남는다.

기각한 map03은19비트 모든 증가값524288개와오류우선순위262144개, 합계786432개 비교·오류 차단 누락 음성대조·실제SPI경로를 통과했다. 그러나 카운터 피드백이 증가 조건을 거쳐 XOR로 돌아가는 배선 경로가 길어졌다. 기능 동등성만으로 채택하지 않는다. 해당 실험과 원시 결과는 남긴다.

## 재현·증거 관리

`nes_retire165.py --variant serial`로 선택 입력을 생성하고 `check_nes_retire165.py`로 기준58개 입력 보존·선택3개 변환·실행RTL·재생성·FIT/STA를 대조한다. 이전 실행의 생성기 해시를 새 생성기 해시로 덮어쓰지 않는다. 실행된 로더/SPI 본문을 직접 비교해 재사용하고 옛 생성기 복사본도 보존한다. map03의 초기 선언 위치 수정 전 입력은 실행하지 않았고, 첫STA 상대경로 실행 실패는 별도 로그로 남겼다. 실제 기능 실패나 라이선스 오류로 분류하지 않는다.

## 다음 작업

1. 선택map02의 실제 CHECK 오류→카운터 경로를 먼저 수정한다. 고정된 pending명령·헤더·본문 조건을 기존 캡처 edge에서 미리 분류하는 방법을 검토하되, 동적인 하드 오류 우선순위와 명령 완료 edge는 유지한다. 이 방법은 아직 구현하지 않았다. map03의 긴 피드백 구조나 근거 없는 속성/refit 반복은 피한다.
2. host+0.021ns와963/963LAB도 동시에 확인한다. 다른 클록 경로 악화나 리소스 초과를 놓치지 않는다. 실제 클록을 완화해 통과시키지 않는다.
3. 필요한 외부IO·영상CDC 계약을 확인한 뒤 MCU 수신·변환·ACK와 기존 사운드·입력·STOP·실제시간 처리를 연결하고 전체 링크·중첩스택을 확인한다. 최소 안전 조건을 충족하면 SMB3(J) 첫 레벨 실기로 간다. 무변경 전체 쓰기·OAM·A/B·044 복원을 다시 반복하지 않는다.

**미완료:** 실제 클록 타이밍, 외부IO/CDC, MCU 통합, 새SD 패키지와 실제 게임 화면 검증. 이번 결과로60fps나 정상 플레이를 주장하지 않는다.
