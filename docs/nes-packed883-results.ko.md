# 883 · 최종 E0 조회와 다음 입력의 캡처 마감

실기 기준은 MMC872이고 구현 대조군은 882의 단일 BG·SEAL 직접 작성 링크다. 두 위상에서 같은 입력, ROM 허가표, 65816과 보드를 사용했다. ARM은 전체 링크를 처음부터 실행했다. 모든 시간은 결합 재생의 마스터 클록이다.

## 907에서 놓친 ACK가 910 캡처에 미친 영향

밀집 위상 2의 881에서는 907의 65816 최종 ACK가 15,700,554클록, 다음 E0 시작이 15,700,572클록이었다. ARM이 18클록 차이로 갱신된 상태를 읽었다. 882에서는 ACK가 15,700,658클록인데 E0는 15,700,442클록에 이미 시작했다. 216클록 뒤 거래 중에 ACK가 갱신돼도 응답은 시작할 때의 이전 큐 상태다. 다음 E0는 15,705,223클록에 시작했다.

그 결과 882의 907 EA 발행이 881보다 4,651클록 늦어졌다. 908의 첫 일반 출력도 4,652클록, SEAL 발행도 4,578클록 늦었다. 마지막 입력 묶음 뒤 ARM이 유효 E0를 받은 시점에도 같은 4,578클록 차이가 남았다. 908의 유효 E0부터 909의 마지막 D2까지는 두 링크 모두 13,022클록이었다. 910을 직전 입력 시작선에서 캡처하려면 위상 2의 909 D2를 16,438,928클록까지 마쳐야 한다.

동일 바이너리 대조에서 앞선 SPI 1,387건과 입력·표시 순서를 고정하고 907의 조회 휴지만 여섯 번 없앴다. 909 D2는 16,442,574→16,439,850클록으로 2,724클록 빨라졌다. 여전히 마감보다 922클록 늦어 910은 같은 VBlank 51에 표시됐다. 이 대조는 907에서 비롯된 지연을 분리한다. 전체 링크에는 다른 세대의 조회 및 입력 수신 위상 변화도 포함된다.

## ARM 변경과 비용

- `--ack`는 다음 입력이 COMPLETE이고 SEAL만 기다릴 때 96µs 휴지를 없앤다. 각 E0의 SPI 전송, guard, CRC, 큐 순번, 최종 identity 확인을 모두 실행한다. 기존 poll_limit도 적용한다.
- `--shared`는 기존 수신기의 행·팔레트 검사 함수를 유지한다. 이미 수신한 D1에서 해당 바이트를 직접 읽고, 타일 요구 비트는 기존 바이트에 OR한다. META_END에서는 little-endian Cortex-M4의 같은 4바이트를 memcpy로 읽어 유효 비트를 순회한다. STOP·D2·COMMIT 순서는 공통이다.
- 행·팔레트 검사를 묶음당 한 번 실행하는 별도 링크와, 입력 바이트에서 직접 처리하는 링크도 비교했다. 전자는 밀집 두 위상을 실행했다. 후자는 Flash 한도와 실제 입력 블록 단위 검증까지 진행했다.

| 909의 COMMIT 전 데이터 16블록 | 전체 ARM Flash | 수신기 실행 명령 수 |
|---|---:|---:|
| 882 직접 SEAL | 212,988B | 80,378 |
| 묶음당 검사 | 213,136B | 62,715 |
| 독립된 wire 바이트 처리 | 213,088B | 58,341 |
| 기존 검사 공유 | 212,960B | 73,715 |
| E0 휴지만 제거 | 212,988B | 수신기 코드 동일 |

각 블록 후 수신기 전체 상태가 네 수신기 링크에서 일치했다. 실제 행·팔레트 패킷 세 개의 각 8개 위치에 잘못된 바이트를 넣은 24회에서도 거부와 오류 발생 전까지 기록한 상태가 일치했다. 중간 상태를 초기화하고 전체 입력을 다시 적용해 같은 결과를 확인했다. 명령 수는 SPI까지 포함한 전체 표시 시간과 별도로 측정했다.

## 963 입력 공급

기존 검사를 공유한 후보의 밀집 위상 1에서는 962가 882와 같은 VBlank 170에 표시됐지만 963이 172→173으로 밀렸다. 두 링크에서 963 입력 준비는 모두 60,365,184클록이다. 첫 D1 발행은 60,370,142→60,591,135클록으로 220,993클록(10.29ms) 늦었다. 후보는 962의 259B 테이블과 187B SEAL을 발행한 뒤 다음 입력을 읽었다. 963의 SEAL 수락은 171·163선→171·213선, 업로드 진입은 171·189선→172·238선이었다. 다음 실험은 962의 후반 출력을 유지하면서 입력이 준비된 첫 credit에서 963 D1을 허용할 수 있는지 확인한다.
