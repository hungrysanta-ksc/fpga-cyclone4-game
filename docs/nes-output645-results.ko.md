# MMC643 출력·최종 ACK 비용과 955 발행 일정

**첫 실험은 955의 SEAL 발행 앞단이다.** 955는 같은 map 11패킷·OBJ 448 B를 처리할 때 마지막 map 또는 tile 발행 뒤에도 8.82–8.89 ms가 걸려 SEAL을 발행했다. 수락 후 검사가 끝나고 남은 DMA를 실행하려면 업로드용 VBlank를 14.60–14.93 ms 기다렸다. 그 뒤 화면을 공개하려고 추가로 기다린 VBlank는 네 조건 모두 0회였다.

## 실기와 비교 일정

실기 MMC643에서 Cortex-M4가 `nes_sink212_seal` 호출을 둘러싸고 센 값은 84 MHz에서 2,855,238,911클록, 완료 1,152회다. 평균은 **29.506 ms**다. 여기에는 IRQ와 대기가 들어간다. EA 반환은 호출 이후다. 실기 세 로그에 화면별 map·OBJ 내용, 65816 수락, DMA, 빔 시각이 없어 실측 평균의 내부 시간을 직접 복원할 수 없다. [실기 근거](../analysis/hardware644-mmc643.json)

대신 두 부팅 조건 × 두 시작 위상의 기존 905–957 연속 추적을 다시 분해했다. 선정한 638과 MMC643 ELF에서 함수 798개의 주소·크기·기계어가 일치하고, 65816 ROM 해시가 같다. 네 추적에서 906–957의 52개 세대 각각에 대해 map·OBJ 목적지·길이·payload·중복 횟수·OBJ plan 슬롯 순서의 해시가 615 분석 당시 MMC613 대조와도 일치했다. 905는 cold forced blank이고, 906은 두 번째 초기 화면이므로 아래 warm 평균에서는 둘 다 제외했다. CPI 2, 실기 기반 SPI 서비스 시간, SysTick과 ROM 공급 달력을 포함한 **유효 캡처 일정**이다. 643의 거부→회복 구간이 실기 평균에서 차지한 시간은 별도 미측정이다.

## 시간이 쓰인 곳

단위는 ms/화면이다. 각 칸은 네 조건별 평균의 최솟값–최댓값이다. 한 세대·조건 안에서는 각 구간 합이 출력 진입부터 ARM 복귀까지의 경과 시간과 일치한다. 열의 양 끝값이 서로 다른 실행에서 나올 수 있다.

| 측정 경계 | warm 907–957 | 밀집 951–955 |
|---|---:|---:|
| ARM 출력 진입 → SEAL 발행 완료 | 16.60–16.70 | 18.83–20.00 |
| SEAL 발행 → 65816 수락 | 0.033–0.046 | 0.014–0.062 |
| 65816 수락 → 업로드 진입 검사 완료 | 1.63 | 1.62 |
| 업로드 중 VBlank 대기 | 7.43–7.59 | 6.89–7.45 |
| 수락 후 실제 DMA 시작 → 마지막 바이트 합 | 0.54–0.56 | 0.66–0.79 |
| 나머지 설정·표시·제어 | 1.11–1.12 | 1.19–1.21 |
| 마지막 표시용 VBlank 추가 대기 | 0.60–0.89 | 0 |
| 최종 ACK → ARM 출력 함수 복귀 | 0.49–0.56 | 0.50–0.68 |
| **전체** | **28.58–28.95** | **30.29–31.11** |

SEAL 전 일반 패킷의 65816 수락·소비와 비활성 뱅크 선행 DMA는 ARM 발행 구간과 겹친다. 그 구간을 순수 ARM 계산 비용으로 해석하면 안 된다. SEAL 뒤에는 DMA가 검사·대기 구간과 겹치지 않는지 이벤트로 확인했다. warm에서는 51화면 중 마지막 표시 추가 대기가 2–3회 있었다. 밀집 구간에서 이를 줄여 얻을 시간은 0이다. [원시 추적 핀·화면별 상세 비용](../analysis/output645-verification.json)

## 955를 먼저 볼 이유

| 세대 | map 패킷 / OBJ B | 업로드 VBlank 대기 | 직전 225번 선의 같은 실행 위치에 맞출 선행량 |
|---|---:|---:|---:|
| 952 | 10 / 512 | 2.90–4.35 ms | 12.29–13.74 ms |
| 954 | 12 / 384 | 13.77–13.92 ms | 2.72–2.87 ms |
| **955** | **11 / 448** | **14.60–14.93 ms** | **1.70–2.04 ms** |
| 957 | 11 / 288 | 14.49–14.68 ms | 1.96–2.14 ms |

선행량은 한 NTSC 프레임의 클록 수에서 실제 `wait169` 진입→225번 선 복귀 시간을 뺀 **정렬 목표**다. 그만큼 발행을 당겼을 때 앞선 DMA가 시간을 흡수할 수도 있다. 실제로 한 VBlank를 얻으려면 검사·빔·잔여 credit을 통과한 표시와 마지막 ACK가 함께 당겨져야 한다. 957은 회귀 대조로 남긴다.

955의 마지막 map/tile 뒤에는 OAM·팔레트의 뱅크 이력을 확인하는 명령 1개와 section 5의 스크롤·raw·HDMA 명령 9개가 있다. 열 거래의 기존 E1 서비스 합 2.637 ms가 발행 구간 8.82–8.89 ms 안에 들어간다. 끝부분을 별도로 보면 마지막 일반 ACK부터 SEAL 수락까지는 0.95–1.03 ms다.

두 슬롯, 기존 SPI 거래와 반환 순서를 고정하고 일반 큐에 예비 credit 하나를 남기는 조건으로 선행 전송 기회를 셌다. planner가 성공해 END 함수에 들어간 시점부터 마지막 map/tile까지 955에는 3.59–4.08 ms의 빈 SPI 시간이 있다. 하지만 **가장 긴 연속 구간은 0.171–0.175 ms**이고 첫 명령은 0.461 ms다. 기존 순서로 들어갈 수 있는 선두 패킷은 0개다. 순서를 자유롭게 바꿔도 개별 길이가 들어갈 수 있는 명령들의 E1 시간 합은 최대 0.57–0.74 ms다. 이 상한은 ARM 준비, 추가 수락·소비, credit 반환 지연을 공짜로 두었으며 실측 절감량은 아니다. 954에서도 첫 명령을 넣을 연속 구간이 없었다.

따라서 다음에는 955에서 **OAM·팔레트 이력과 section 5 데이터가 실제 확정되는 ARM 시각**을 먼저 찍는다. 확정 후 첫 명령을 받아줄 연속 SPI 구간을 만들 수 있는지, 또는 후반부 전송·복원 자체를 줄이는 편이 나은지 분리 비교한다. 단순히 남는 작은 구간으로 패킷 순서만 바꾸는 실험은 우선순위에서 뺀다. 954는 같은 후반 열 명령을 가진 두 번째 대조다. 밀집 표시 간격과 957 마지막 ACK가 두 위상 모두 개선되는지 보고, 951 공개선·952 4 VBlank·957 최종 대기 0회와 MMC643의 빈 캡처 회복·STOP·메뉴 복귀를 지킨다.
