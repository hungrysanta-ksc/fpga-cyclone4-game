# FF3 1047 전투 실기판

SD 루트에 ZIP의 `sd2snes` 폴더를 덮어쓴 뒤 전원을 껐다 켜고, 파일 목록에서 기존 FF3 한글판 `.nes`를 선택한다. 기존 배터리 세이브와 퀵세이브를 그대로 읽는다.

1. 전투 중에 저장한 슬롯은 **L+R+START → STATE SLOT 1 → LOAD STATE**로 불러온다. A로 공격과 대상을 확정하고, 아군이 앞으로 나올 때와 명중 이펙트가 뜰 때 움직임을 확인한다. 같은 슬롯을 다시 불러오면 같은 위치에서 비교할 수 있다.
2. 전투 진입 효과는 필드에서 아래로 이동해 조우할 때 확인한다. 전투 슬롯을 보존하려면 필드 시험에서 새로 저장할 때 다른 슬롯을 선택한다.
3. **L+R+START → EXIT TO MENU**로 종료한다. 이번 로그는 `nes-progress-ff31047.txt`, `nes-game-last-ff31047.txt`, `nes-frame-ff31047.bin`이다.

## 전투 진입 효과

한글판 ROM CRC32 `4be84aa7`와 슬롯 1의 이전 복사본(저장 순번 3)을 대조했다. 필드에서 이동하면 참조 재생의 435–498번째 프레임에 PPUMASK가 `1f`와 `1e` 사이를 32번 왕복한다. 이전 보드는 회색조를 일반 타일로 표현할 수 없어 원본 픽셀 보관을 요청했다. 보관할 수 있는 7행을 넘으면 그 화면 전체를 버렸다.

1047은 일반 행의 BG·OBJ 팔레트 32색을 기록할 때 NES 회색조 마스크 `$30`을 적용한다. 화면 중간에 표시 설정이 바뀌는 행은 기존 원본 픽셀 검사로 처리한다. 한글판에서 추출한 64프레임의 마스크와 팔레트를 합성에 사용한 RTL에 입력하고, 각 화면의 224행 수락과 32개 출력 색상, 최종 ARM이 만드는 SNES CGRAM의 위치를 검사한다.

## 공격 애니메이션

슬롯 1의 새 복사본(저장 순번 4)에서 A를 10프레임마다 3프레임씩 눌렀다. 첫 580프레임 중 530프레임은 타일 원본(CHR RAM)에 쓰기가 없었다. 510–574번째 프레임에는 원본 화면에서 움직임이 관측된 6프레임 모두 타일 원본이 그대로였다. 움직임은 화면의 배치나 팔레트만 바뀌어도 생긴다.

1046은 CHR RAM 게임에서 매 화면 대상 VRAM 뱅크의 타일 기록을 비웠다. 1047은 FPGA가 직전 정상 회수 이후 CHR 쓰기 유무를 추적하고, CRC 검사 대상인 기존 입력 헤더 한 비트로 ARM에 알린다. ARM은 원본이 그대로이고 대상 뱅크·타일 정의가 일치할 때만 전송을 생략한다. 실제 쓰기가 있으면 양쪽 뱅크의 기록을 지운다. 첫 화면, STOP, 불러오기, 실패한 표시 뒤에도 확인되지 않은 타일을 재사용하지 않는다.

## 검증 범위

전투 슬롯에서 시작한 보드 RTL의 캡처를 1046·1047 최종 ARM 링크에 같은 순서로 공급한다. 매 캡처를 처리한 경우와 세 번째 캡처마다 처리한 경우를 대조한다. 건너뛴 동안의 CHR 쓰기도 반영한다. 표시 map·OAM·팔레트·HDMA·원본 픽셀용 타일과, 실제로 화면에서 참조하는 VRAM 슬롯의 타일 정의를 대조한다. 측정한 양은 타일 DMA 바이트와 전송 계획의 레코드 바이트다. 1046 실기 마지막 실행 구간은 DISPLAY_NEXT부터 DISPLAY_STOPPED까지 55.32초에 최종 표시 332회였다. 약 6.00 FPS에는 재시작과 메뉴 처리 시간도 들어 있다. 공격 애니메이션만의 FPS는 같은 슬롯에서 다시 측정해야 한다. 집계와 배포물의 SHA-256은 [검증 결과](../analysis/ff3-battle1047.json)에 있다.

같은 전투 슬롯에서 A 입력을 반복한 보드 RTL 65프레임 중 첫 캡처가 완성된 시점부터 64개 화면을 대조했다. 두 버전의 표시 데이터와 참조 타일 정의가 모든 화면에서 일치했다.

| ARM에 공급한 캡처 | 타일 전송 명령 1046 → 1047 | 타일 DMA 바이트 1046 → 1047 | 계획 레코드 바이트 1046 → 1047 |
|---|---:|---:|---:|
| 연속 64개 | 5,780 → 703 | 92,640 → 11,280 (87.8% 감소) | 40,214 → 4,667 |
| 세 번째마다 1개, 총 22개 | 1,983 → 477 | 31,776 → 7,664 (75.9% 감소) | 13,796 → 3,253 |

Quartus Lite로 보드 전체를 배치·배선하고 STA 57항목을 확인했다. 실기판은 15,213/15,408 LE를 사용하며 최소 여유는 +0.172ns다. ARM 설치 이미지는 212,928/212,992B다.

이전 실기판의 슬롯 재시작과 보스 방 전환 검증은 [1046 기록](nes-ff3-play1046.ko.md)에 있다.
