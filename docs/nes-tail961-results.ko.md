# 961 · 마지막 544B OBJ의 ROM 대기와 다음 화면의 공급 마감

## 목표

960의 빈 캐시에서 907→908 공개에 걸리는 3 VBlank 중 한 번을 줄이고, 그 이득이 여섯 표시 간격과 912 최종 ACK까지 이어지는지 확인한다. 실기 FPS 기준판은 MMC955다.

## 작업내용

- 세대 908의 FPGA 내부 토큰 3을 ARM 토큰 13·OBJ 슬롯 39·544B와 연결했다. 물리 CHR 요청, ROM 허가, 태그가 붙은 응답, FPGA 공개, 첫 유효 E8 스냅샷, ARM 송신, 65816 수락·반환을 같은 마스터 클록으로 대조했다.
- 후보는 빈 캡처에서 페이지 끝의 짝수 타일에 행 마스크 `0x7f`가 수락될 때 다음 페이지의 첫 두 타일을 기존 행 캐시로 미리 읽는다. 마지막 CHR 페이지에서는 주소가 돌아가지 않도록 막았다. 실제 게임 세대나 고정 태그 번호를 조건으로 사용하지 않는다. 보류된 프로그램 읽기와 실제 tile 읽기가 우선이다.
- MMC955 ARM과 960의 정적 65816 ROM으로 905–912를 처음부터 재생했다. 두 위상의 907→908→909에서 실제 ROM 허가를 적용하고 세대 간 RTL 행 RAM을 넘겼다. 모델과 보드 RTL에서 E8가 달랐던 시각은 실제 응답의 토큰·플래그·CRC를 ARM에 전달하고 바뀐 일정을 다시 검증했다.

## 성과

| 빈 캐시 측정 | 위상 1 | 위상 2 |
|---|---:|---:|
| 960에서 태그 6256 행 0의 요청→ROM 허가 | 11.542ms | 11.665ms |
| 960에서 마지막 OBJ 공개→첫 유효 E8 | 0.110ms | 0.113ms |
| 961에서 마지막 OBJ가 준비된 시각의 개선 | 10.247ms | 10.372ms |
| 65816이 마지막 OBJ를 읽기 시작한 주사선, 960→961 | 255→103 | 256→102 |
| 908 공개 VBlank, 960→961 | 39→38 | 40→39 |
| 909 공개 VBlank, 960→961 | 42→42 | 43→43 |
| 실제 E8를 반영한 912 최종 ACK 차이, 961−960 | +4.94µs | −7.73µs |

907의 유휴 ROM 구간에서 6256·6257의 16개 행을 실제로 읽었다. 908의 해당 타일 공급에 필요한 전면 요청 15개가 사라졌다. 908은 두 위상 모두 한 VBlank 먼저 공개됐다. 909에서 태그 3074 행 0은 요청 시각이 앞당겨져도 두 보드 모두 같은 ROM 허가를 받았다. 이 태그가 들어 있는 첫 E9 묶음은 후보에서 직전 허가보다 2.751·2.835ms 늦게 확정됐다. 따라서 908→909가 3회에서 4회로 늘었다.

기존 캐시의 여섯 간격은 13회, 빈 캐시는 14회다. 8개 화면의 픽셀과 VRAM DMA 총 22,512B를 대조했다. 911 공개 전 입력 17블록 및 빈 캐시 912의 SEAL 전 496B 전송을 확인했다. 세대 908의 잘못된 SEAL 및 처리 중 STOP은 각각 `0xe0`·`0xe4`로 끝났고 이전 화면 907이 보존됐다. 보드 시험에서 잘못된 행 응답, STOP과 물리 응답의 중첩, 캐시 무효화 뒤 바뀐 ROM 데이터도 확인했다. 같은 ARM으로 메뉴 종료·base 복구를 재생했다.

Quartus Lite 전체 MAP·FIT·ASM·STA에서 960→961은 15,247→15,201 LE, 961→962 LAB, M9K 56→56, RAM 320,616비트였다. 최소 setup 여유는 +0.579→+0.330ns다. 후보의 hold·recovery·removal·최소 펄스폭 여유는 각각 +0.168·+1.593·+0.480·+2.626ns다.

## 후속작업

905–908에서 수락된 E9에는 인접 태그 3072–3075가 한 번도 없었다. 네 태그는 두 위상 모두 909의 첫 묶음에서 처음 등장했다. 다음에는 909의 입력 복원과 ARM planner에서 3074의 주소·행 마스크가 처음 확정되는 시각을 직전 ROM 허가와 비교한다. 먼저 확정된다면 앞당긴 실제 발행으로 기존 타일 공급과의 경쟁까지 재생한다. 채택 조건은 908 조기 공개를 유지하면서 두 위상에서 여섯 표시 간격과 912 최종 ACK가 함께 줄어드는 것이다.

재현 순서는 `tools/nes_tail961.py`의 `board`·`fit`, 두 위상의 `run`·`fixtures`, 단일 FLOAT 래퍼에서 `tools/check_nes_tail961.ps1`의 control·pair, 그리고 `wire`·`fixtures`와 동일 RTL 재생이다. 960 대조군의 두 번째 피드백은 `wire --recheck`와 `NES_WIRE961=2`를 사용한다. 오류 주입은 두 위상 각각 `guards`로 실행한다. 수치와 보고서 해시는 [검증 결과](../analysis/tail961-results.json)에 있다.
