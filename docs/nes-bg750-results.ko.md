# 750 · 749의 E8 시각에서 48B BG → 1,536B map → 288B OBJ 전송

## 시험 조건

707D 보드, 749의 마지막 map 페이지 앞에서 E8을 조회하는 ARM 전체 링크, 694의 부팅 ROM을 사용했다. 957의 마지막 OBJ가 수신기에 도착한 시점에 시험용 65816 코드를 WRAM에 연결했다. E8 이전의 부팅·표시 이력과 952의 선행 DMA를 같은 조건으로 비교하기 위한 계측 방법이다. 세대 번호와 절대 시각은 시험 코드 연결 시점에만 사용한다. 실행기가 DMA를 허가할 때는 수락된 descriptor, 실제 전송 길이, 큐, STOP과 빔 위치를 확인한다.

먼저 749 ARM이 실제로 보냈던 모든 패킷의 바이트와 도착 시각을 고정했다. 그다음 실제 ARM·65816을 함께 실행해 957의 map 완료 공개와 credit 반환이 이후 SPI 발행을 바꿀 수 있게 했다. 실제 보드 플레이 시간은 측정하지 않았다.

## 같은 패킷 시각에서의 원인 분리

아래는 두 위상에서 각각 연속 905–957을 실행한 결과다. 밀집 간격은 951 공개부터 957 공개까지 여섯 간격의 평균이고, 음수 변화는 727보다 빠름을 뜻한다. DMA 시작선은 완료 통지와 구분해 채널 0의 실제 MDMAEN 쓰기에서 기록했다.

| 65816 동작 | OBJ 시작선 1 / 2 | 밀집 간격 변화 µs 1 / 2 | 957 최종 ACK 변화 클록 1 / 2 |
|---|---|---:|---:|
| 749 수신기 | 다음 226 / 다음 226 | +13.968 / +8.241 | +1,296 / +1,062 |
| 48B BG 우선 | 다음 225 / 다음 225 | +6.689 / +1.956 | +398 / +252 |
| BG 우선과 일반 선택기의 288B 허가 | 다음 225 / 256 | +5.820 / −20.766 | +246 / −2,676 |
| 긴 map 완료 후 다음 OBJ 연결 | 258 H120 / 255 H1302 | −18.578 / −19.850 | −2,898 / −2,558 |
| map 완료 분기에서 같은 채널 설정 재사용 | 258 H52 / 255 H1250 | −19.447 / −20.766 | −3,010 / −2,676 |
| 48B 완료 뒤 map tail 선택까지 단축 | **257 H1352 / 255 H1100** | **−20.378 / −20.766** | **−3,130 / −2,676** |

마지막 후보는 직전 48B DMA가 끝나면 STOP과 새 head를 확인한 후 남아 있는 map tail을 조회한다. 1,536B map을 마치면 기존 완료 비트를 한 번 공개한다. 수락된 큐의 첫 항목이 실제 288B OBJ임을 확인하고 채널 0의 전송 모드·VRAM 포트·source bank를 재사용한다. 새 source·VRAM 목적지·288B 길이를 설정하고 VBlank, 새로 래치한 9비트 수직선, 저장·실시간 STOP과 새 패킷을 확인한 뒤 동기 DMA를 시작한다.

## ARM 반환을 연결한 연속 실행

| 957 사건 | 위상 1 | 위상 2 |
|---|---:|---:|
| E8 시작 / 응답 완료 (마스터클록) | 65,199,630 / 65,201,973 | 65,558,861 / 65,561,204 |
| BG 48B MDMAEN → 마지막 쓰기 | 244선 H140 → 244선 | 241선 H1252 → 242선 |
| map 1,536B MDMAEN → 마지막 쓰기 | 247선 H10 → 256선 | 244선 H1122 → 254선 |
| OBJ 288B MDMAEN → 마지막 쓰기 | 257선 H1352 → 259선 | 255선 H1100 → 257선 |
| 258선 시작까지의 여유 | 12클록 | 2,992클록 |
| 밀집 표시 간격 (727 → 750) | 49.932319 → 49.914781ms | 49.932304 → 49.911537ms |
| 957 최종 ACK (727 → 750, 마스터클록) | 65,725,518 → 65,722,754 | 66,082,774 → 66,080,098 |

두 위상의 ARM E8 시작·응답 시각과 descriptor 응답 바이트가 각각 749와 일치했다. 위상 1은 되먹임을 연결하자 뒤쪽 4개 패킷의 발행이 8,067–8,068클록 늦어져, 고정 발행 재생보다 최종 ACK 이득이 366클록 줄었다. 위상 2는 고정 재생과 전체 65816 이벤트 시각이 일치했다. 두 위상 모두 952–957의 각 표시는 여전히 3 VBlank 간격이다. 이번 이득은 같은 VBlank 안에서 공개와 ACK가 앞당겨진 시간이다.

## 보호 조건과 ROM

- 두 위상에서 952·957의 1,536B를 분할 없이 선행 전송했다. map 빔 래치는 245 / 243선으로 기존 248선 마감을 통과했다. 908·911은 2 VBlank, 951 공개는 236선, 952는 3 VBlank, 957 최종 대기는 0회였다. 53개 화면의 RGB와 수락 바이트별 VRAM 검사, 최종 ACK를 대조했다.
- 두 위상에서 OBJ 허가 직전에 STOP을 넣으면 OBJ 전송은 0B였다. 첫 PPU 쓰기 중 STOP이면 이미 시작한 288B만 마쳤다. 두 경우 모두 956 화면을 보존하고 957 최종 ACK를 차단했다. 잘못된 OAM 표시 이력도 상태 0xE0으로 거부했다. OBJ 허가 직전 실제 다음 패킷을 공개하면 두 위상 모두 OBJ DMA보다 먼저 section 4 OAM을 읽었다. 같은 ARM 바이너리의 메뉴·base 복귀 5경로와 파일명 표식 4조건도 검사했다.
- ARM은 212,784B로 208B가 남는다. 65816 실행 본문은 6,185B로 WRAM 본문 영역 안에 들어간다. 기존 694의 512B 비압축 prefix로 패킹하면 5,120B 물리 ROM에서 **107B 초과**다. 허용되는 모든 짝수 prefix의 최단 압축 길이를 비교해도 최선은 52B prefix, **39B 초과**였다. 707D RTL 변경이 없어 새 보드 합성은 수행하지 않았다.

## 다음 작업

750의 BG·map·OBJ 전송 순서를 유지하면서 65816의 기존 descriptor 선택과 채널 설정을 공유해 ROM을 줄인다. 694와 같은 부팅 prefix에서 107B를 회수하거나 더 짧은 prefix로 최소 39B를 줄인 뒤, 정적 ROM으로 처음부터 부팅해 E8 시각과 257선 여유, 두 위상의 밀집 간격·최종 ACK를 다시 검증한다. 같은 53화면 밖에서 12클록의 여유가 유지되는지는 별도 확인이 필요하다.

## 재현

[고정 발행 재생 및 수신기 코드](../tools/replay_nes_bg750.py)를 `--trace <temp>/nes-obj749-pageN --client <694 client01> --mesen <Mesen.exe> --out <temp>/nes-bg750-<variant>N-trace --variant <variant>`로 실행한다. N은 1·2이고 variant는 표 순서대로 `control`, `bg`, `full`, `chain`, `compact`, `tail`이다. `tail`에서 `--mode stop --inject before|during`, `--mode trace --inject head`, `--mode stale`가 오류 주입 시험이다. 출력 폴더의 마지막 부분은 각각 `stopbefore`, `stopduring`, `tracehead`, `stalenone`이다.

[연속 공동 실행](../tools/run_nes_bg750.ps1)에 `-Phase 1|2 -Game <실제 ROM> -TraceRoot <temp>`를 전달한다. [메뉴 검사](../tools/check_nes_menu533.py)에 749 page의 `src`, `--trial 690`, `--out <temp>/nes-bg750-menu.json`을 전달한다. [검증 코드](../tools/analyze_nes_bg750.py)의 `--temp`, `--client`, `--out`으로 수치, ROM 용량과 보호 조건을 다시 확인할 수 있다. [결과와 해시](../analysis/bg750-verification.json)

공동 실행에 오류를 주입할 때는 같은 명령의 입력을 `nes-bg750-liveN`으로 바꾸고 출력 폴더의 `tailN`을 `coupledN`으로 바꾼다.
