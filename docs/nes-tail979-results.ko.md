# 911의 마지막 OBJ 반환과 section 5·SEAL 일정

## 목표

978 returned의 909 선행 DMA와 910 입력 캡처를 기준으로, 911의 마지막 OBJ 뱅크 반환부터 SEAL 수락까지 어디서 시간이 드는지 측정했다. 합격 기준은 스크롤 선행·908 공개·독립 검사·STOP을 유지하고 두 위상 모두 911을 직전 VBlank에 표시하며 912 최종 ACK도 앞당기는 것이다.

## 작업내용

두 시작 위상에서 905–912를 연속 실행했다. ARM 전체 링크, 65816 명령과 DMA는 실행했고 FPGA 타일 공급·공유 SPI·IRQ는 978과 같은 모델을 썼다. 각 패킷의 ARM 발행·전송 완료·65816 로드·반환과 911의 token 30 뱅크 반환을 같은 마스터 클록으로 연결했다.

978의 201B·240B section 5 패킷을 팔레트·OAM 앞으로 옮긴 ARM, 거기서 OAM을 팔레트보다 먼저 보내는 ARM을 각각 시험했다. 별도로 실제 planner에서 OBJ와 첫 팔레트가 확정된 prefix 콜백으로 OAM을 옮겼고, 96B 팔레트 범위도 함께 옮기는 경우를 분리했다. prefix는 해당 경로로 발행한 경우에만 원래 위치에서 생략한다. Flash에 맞춘 prefix 후보에서는 planner 입구가 이미 초기화하는 OAM의 두 번째 초기화를 제거했다. 같은 초기화만 제거한 링크를 대조군으로 사용했다.

## 성과

### 마지막 OBJ 반환 이후의 비용

시작은 384B OBJ의 실제 token 30 반환, 끝은 65816의 SEAL 수락이다. SPI 점유는 두 시각 안에 걸치는 거래 시간만 잘라 합쳤다. 큐 대기·65816 작업은 같은 시간에 겹쳐 실행된다.

| 978 returned, ms | 위상 1 | 위상 2 |
|---|---:|---:|
| 마지막 OBJ 반환 → SEAL 수락 | 4.480 | 4.362 |
| E1 패킷 전송 | 3.171 | 3.187 |
| E0 상태·credit 조회 | 0.546 | 0.480 |
| E8 조회 | 0.109 | 0.109 |
| D0 입력 상태 조회 | 0.086 | 0.074 |
| SPI 거래 밖에서 경과한 시간 | 0.567 | 0.512 |

| 패킷 | 전송 시간 (ms) | 도착 후 65816 로드까지 (ms) | 로드 후 복원·검사·반환까지 (ms) |
|---|---:|---:|---:|
| section 5 첫 201B | 0.720 / 0.720 | 1.003 / 1.058 | 0.359 / 0.356 |
| section 5 뒤 240B | 0.839 / 0.839 | 0.369 / 0.421 | 0.370 / 0.370 |

위상 1에서는 첫 201B가 도착한 뒤 이전 OAM 반복 채우기와 상위 속성 패킷이 큐를 점유했다. 뒤 240B가 도착했을 때도 첫 201B의 처리가 남았다. CPU와 SPI 시간을 단순 합산하면 중복된다.

### ARM 연속 실행

표의 슬래시는 위상 1 / 위상 2다. 양수 ACK 변화는 978보다 늦음을 뜻한다.

| ARM | Flash (B) | 911 표시 간격 | 밀집 여섯 간격 | 912 ACK 변화 (ms) |
|---|---:|---:|---:|---:|
| 978 returned | 212,992 | 2 / 2 | 13 / 13 | 기준 |
| section 5 먼저 | 212,936 | 2 / 2 | 14 / 14 | +16.991 / +33.622 |
| section 5와 OAM 먼저 | 212,936 | 2 / 2 | 13 / 14 | 0.000 / +33.292 |
| 중복 OAM 초기화만 제거 | 212,976 | 2 / 2 | 13 / 13 | +0.010 / +0.018 |
| prefix에서 OAM 발행 | 212,980 | 2 / 2 | 13 / 13 | +0.010 / +0.023 |
| prefix에서 팔레트 96B와 OAM 발행 | 212,980 | 2 / 2 | 13 / 13 | +0.004 / +0.007 |

마지막 후보는 908을 양쪽 모두 VBlank 38의 245선에 공개하고 910 캡처를 회복한 상태를 유지했다. 다만 909의 선행 DMA는 592 / 624B로 978의 624 / 624B에 미달했고 911의 SEAL 수락도 978의 240 / 241선에서 245 / 246선으로 늦어졌다. 실행한 다섯 후보 모두 여덟 RGB 화면, map 패킷의 범위·값, E9 레코드가 기준과 일치했다. 마지막 후보에 잘못된 SEAL·STOP을 각각 주입했을 때 0xE0·0xE4로 종료하고 910의 마지막 정상 화면을 보존했다. Flash를 8–20B 초과한 변형은 링크 크기만 기록했다.

### VBlank 44에 들어가는 실제 DMA

978의 패킷 도착을 그대로 두고 마지막 SEAL만 늦춰 큐를 비운 65816 대조군에서 두 위상 모두 BG 16B, OBJ 32B와 384B를 VBlank 44에 보냈다. tile 432B를 옮겨도 raw 192B·팔레트 512B·OAM 544B는 VBlank 45에 전송됐다. 911 공개는 VBlank 45의 244선에서 240선으로 이동했다. 반대로 마지막 OBJ 패킷 이후의 E1을 실제 전송 길이와 큐 credit만 지키고 연속 발행한 대조군에서도 SEAL 수락은 234 / 237선, 공개는 VBlank 45였다.

타일의 원래 ARM 관측 시각을 유지하며 BEGIN 이후의 다른 패킷까지 가능한 즉시 발행한 소비자 대조군도 VBlank 45였다. 마지막 OBJ 하나의 관측만 1ms 당겨도 결과가 같았다. 세 타일 모두 1ms 당긴 경우에는 VBlank 44에서 432B를 DMA했지만 공개는 VBlank 45였다. 2ms 조건에서는 위상 2만 VBlank 44의 245선 공개에 성공했다. 위상 1은 224선에 새 VBlank 대기 함수에 진입해 VBlank 45에서 반환했다. 이 비교는 저장된 실제 타일·패킷을 사용한 65816 민감도 실험이다. 변경된 ARM이 더 빨리 타일을 생산했다는 뜻으로 사용할 수 없다.

세 타일의 관측을 모두 3ms 앞당긴 대조군에서는 SEAL을 183 / 184선에 수락하고 업로드에 204 / 205선에 진입했다. 두 위상 모두 VBlank 44의 244선에 911을 공개했다. 3ms는 시험한 값 중 양쪽에서 성공한 값이다. 일반 E1 패킷의 준비와 공유 버스 경쟁도 낙관적으로 둔 단일 화면 실험이므로 최소 요구 시간이나 연속 실행의 912 ACK 개선으로 환산할 수 없다.

## 후속작업

개발 기준은 978 returned, 실기 기준은 MMC966으로 유지한다. 978의 911 planner 진입에서 E9 발행까지 약 6.06ms가 걸리고, E9 수락 후 첫 BG를 ARM에서 관측하기까지는 두 위상 모두 약 0.007ms다. 다음에는 첫 BG와 첫 OBJ가 확정되는 시각부터 마지막 OBJ가 확정될 때까지를 나누고, 기존 E9 한 묶음과 앞부분만 먼저 발행하는 경우의 ARM 계산·SPI 거래·FPGA 수락 비용을 함께 비교한다. 908 공개·909의 624B·910 캡처가 유지되는 실제 연속 일정에서 판정한다.
