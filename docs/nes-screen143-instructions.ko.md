# NES143 — 단색·직접 타일·ROM 전송·NES 화면 비교

**판정 기준을 정정합니다. 기존 진단 ROM의 정상 기준 화면도 잡음처럼 촘촘한 무늬입니다.** 141/142의 사진 외형만으로 정상 영상 실패를 확정했던 판단은 철회합니다. 실행 로그와 기준 그림을 함께 비교해야 합니다. 이번 시험은 분명한 단색·큰 타일을 먼저 표시해 경로를 나눕니다.

## 복사와 실행

1. 전원을 끄고 기존 SD 파일을 별도 보관합니다.
2. ZIP의 **01-SCREEN143-SD-ROOT 안의 내용**을 SD 최상위에 복사합니다. `sd2snes/firmware.stm`, `fpga_n143.bi3`, `nes/screen143.nes`를 함께 적용합니다.
3. **NES SCREEN 143.nh1**을 한 번 실행합니다. 이 선택 파일은0바이트가 정상입니다. 확장자를 바꾸지 않습니다.
4. 기존 보호 조건을 유지하므로 적재·대조에 약9분이 걸립니다. 이후 아래 순서를 표시하고, 표시 시작부터 약30초 뒤 자동 메뉴 복귀하는 것이 목표입니다. 전체 관찰 기준은 **최대10분**입니다.

같은142 시험이나044/GBC 복원 반복은 하지 않습니다. ZIP의02-RESTORE044-SD-ROOT는 필요할 때 쓰는 기존 복원본입니다. 장치 분해·PC 연결·LED 확인은 필요 없습니다.

## 기대 화면 — ZIP의 EXPECTED-SCREENS.png와 비교

|순서|화면|확인하는 경로|
|---|---|---|
|A, 약3초|화면 전체가 파란 단색|배경색과 표시 설정. 타일·패킷 전송을 사용하지 않음|
|B, 약3초|왼쪽 빨강, 오른쪽 청록|SNES CPU가 직접 만든 타일·타일맵·팔레트|
|C, 약3초|빨강·청록 계열의 매우 촘촘한 반복 무늬|B의 맵·팔레트를 유지하고 그림 타일만 기존 ROM DMA로 교체|
|D, 남은 시간|검정·흰색·붉은색·푸른색 계열의 잡음 같은 무늬|기존 NES 패킷→WRAM→VRAM 경로. **이 외형 자체는 정상 기준에도 있음**|

A~C는 각각180번의 수직 귀선을 기다립니다. TV 방식에 따라 약3~3.6초입니다. D로 넘어갈 때 파란 대기 화면이 잠깐 보일 수 있습니다. CRT의 색 번짐·확대·카메라 대각선 띠 때문에 PNG와 사진의 픽셀 단위 비교는 하지 않습니다. 무음은 오디오 미구현 상태에서 예상됩니다.

이번에는 **A가 깨끗한 파랑인지, B가 명확한 좌우 두 색인지**가 가장 중요한 관찰입니다. C/D의 촘촘한 무늬는 참고 이미지와 전체 형태를 비교합니다. 자동 메뉴 복귀도 별도로 확인합니다.

## 회수할 결과

- `sd2snes/nes-progress-143.txt`
- `sd2snes/nes-screen-last-143.txt`
- A/B/C/D 중 관찰한 단계와 자동 메뉴 복귀 여부

가능하면 표시 구간 약30~40초만 촬영해 주세요. 필수는 아니며, 전체9분 대기는 촬영할 필요가 없습니다. 실행 후 약8분20초부터 준비하면 표시 구간을 놓칠 가능성이 줄어듭니다.10분이 지나도 복귀하지 않으면 전원을 끄고 남은 로그를 회수합니다.

## 로그의 범위

`screen_phase_mask`의 비트1/2/4/8은 A/B/C/D 단계가 MCU에서 관측됐다는 뜻이며 모두 관측되면15입니다. `screen_stage`는 A=49/B=50/C=51/D 대기=52, D 전송 후=99입니다. 전송 중 기존4~6 또는 오류255가 마지막 값일 수도 있습니다. `screen_frames`는 D의 소프트웨어 전송 완료 횟수이며 실제 정상 TV 프레임 수가 아닙니다.

이번 FPGA의 회로·배치와SPI 프로토콜은142 그대로여서 식별은5E/D9를 유지합니다. **143은 새 ROM 내용·펌웨어·파일명 조합으로 구분**합니다. 과거 파일을 혼합하지 않습니다. RUN 중 추가한 것은 읽기 전용 상태 관측이며 SD 쓰기는STOP 이후에만 수행합니다. `MENU_PREPARED`는 실제 메뉴 표시의 증거가 아닙니다.

이번 시험으로 A/B가 정상이고 C/D가 기준과 비슷하다면, 잡음형 진단 이미지 자체를 고장으로 다루던 가설부터 수정합니다. A/B부터 틀리거나 특정 단계에서 기준과 분명히 달라지면 해당 경계만 수정합니다. 게임·패드·오디오 정상 동작 판정은 별도입니다.
