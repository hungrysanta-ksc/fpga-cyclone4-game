# 623 · 세 번째 팔레트 발행 시점의 큐 소비 확인

**621을 유지한다.** 작은 BG가 있는 화면으로 소비 확인을 제한한 T는 957의 tile 16B·48B와 map 1,152B를 두 위상 모두 같은 VBlank에 썼다. 그러나 622 A보다 마지막 ACK가 16.552 / 33.188 ms 늦었다. 두 위상에서 처음 한 VBlank를 잃은 화면은 922였다.

## ARM이 실제로 알 수 있는 상태

622 A의 957에서 앞 두 팔레트 패킷은 오프셋 0의 32B와 오프셋 32의 96B 반복값이다. 세 번째는 오프셋 128의 232B DATA다. 위상 1에서 세 번째 E1 발행을 시작했을 때 ARM의 미회수 credit은 둘이었고, 두 번째 패킷의 실제 65816 소비 완료까지 0.268 ms가 남아 있었다. 기존 status는 최신 소비 ACK를 알려주지만, SNES가 유휴 VBlank에서 어떤 DMA를 시작했는지까지 알려주지는 않는다.

623은 A의 기존 `span`이 고른 DATA/RLE 경계를 사용한다. 새 코드가 보는 것은 현재 팔레트 오프셋, 직전 전송의 section, 미회수 credit 두 개, 선택적으로 이미 발행한 BG 크기다. 해당 패킷의 원래 plan/bulk 우선 처리를 마친 다음 큐의 소비 완료를 확인하고 E1을 보낸다. 기존 SPI status의 CRC·accepted/retired 범위·빈 큐 마지막 ACK identity 검사를 그대로 거친다. 이후 새 head 우선, STOP, SEAL과 최종 표시 ACK는 동일한 65816이 처리한다.

| 링크 통과 구성 | 세 번째 발행 조건과 동작 | ARM Flash |
|---|---|---:|
| R · drain-report | 위 조건에서 두 번째 팔레트까지 소비 완료를 한 번 확인 | 212,968B |
| S · snapshots | 같은 경계에서 빈 큐와 마지막 ACK를 네 번 확인 | 212,980B |
| T · small-snapshots | 총 BG 발행량이 32–64B일 때만 S 적용 | 212,988B |

네 번의 확인은 새 패킷을 발행하지 않고 SNES가 유휴 선택기를 돌릴 시간을 주는 실험이다. 같은 ACK가 네 번 반환돼도 DMA가 완료됐다고 간주하지 않는다. 어느 구성도 957의 프레임 번호·빔 위치·미래의 map DMA 시각을 참조하지 않는다.

## Flash와 검사 비용

전체 Flash 한도는 212,992B다. 보고서 boot·plan 헤더를 한 번에 출력한 첫 drain 링크는 213,016B로 24B 초과했다. 작은 BG와 단일 OBJ 공급을 구분하고 소비 확인 뒤 128µs의 STOP 확인 대기를 네 번 넣은 후보는 213,100B, 진단 출력 함수를 공유해도 213,052B였다. 이 두 quiet 이미지는 연속 일정에서 제외했다.

R/S/T는 진단 보고의 범위 확인과 `vsnprintf` 호출을 공유했다. 기존 622 A와 각 링크의 실제 ARM 함수를 실행해 샘플 비용 보고 유무, 서로 다른 진단 필드값, 공간 부족·정확한 길이·종단 문자·경계 밖 쓰기를 대조했다. 18개 버퍼 조건에서 반환값과 버퍼 해시가 일치했다. BSS는 18,592B이고, 보고 함수 시험에서 관찰한 스택 쓰기는 168→192B였다. 이는 게임 실행 전체의 최대 스택 측정값과 별개다.

실제 queue writer에 957의 512B 팔레트를 넣어 순번이 65,534에서 0으로 넘어가는 상황과 소비 지연을 확인했다. CRC 오류·잘못된 수락 개수·빈 큐의 잘못된 마지막 identity·소비 대기 중 STOP·빈 큐가 된 직후 STOP에서 오프셋 128 이후 패킷은 발행되지 않았다. 정상 수신 바이트는 원래 팔레트와 일치했다.

## 두 시작 위상의 연속 표시

각 쌍은 위상 1 / 2 순서다. 밀집 합계는 951–955 다섯 표시 간격이고, 마지막 ACK는 동일 시작 클록에서 957까지의 절대 시각이다.

| ARM | 밀집 합계 (VBlank) | 957 목표 세 DMA가 같은 VBlank | 마지막 ACK 차이 vs 622 A (ms) | vs 619 (ms) | vs 621 (ms) |
|---|---:|---|---:|---:|---:|
| 622 A | 21 / 21 | 실패 / 실패 | 기준 | −49.820 / −49.833 | −49.928 / +0.011 |
| R | 21 / 21 | 성공 / 실패 | +49.838 / +49.810 | +0.018 / −0.023 | −0.090 / +49.820 |
| S | 21 / 21 | 성공 / 성공 | +49.843 / +33.188 | +0.024 / −16.645 | −0.084 / +33.199 |
| T | 20 / 21 | 성공 / 성공 | +16.552 / +33.188 | −33.268 / −16.645 | −33.376 / +33.199 |

R은 위상 1에서 955의 마지막 384B map 선행도 놓쳤다. S와 T는 906 표시 9회, 952·954 표시 각 4회, 954 첫 ROM 구간 96회 읽기, 955의 첫 192B·마지막 384B map 선행과 957 최종 대기 0회를 유지했다. 세 후보 모두 두 위상의 53장 RGB·map, 일반 출력 내용, VRAM DMA 바이트와 ROM 작업량을 A와 대조했다. T에서 STOP·새 head 동시 도착과 각각의 우선 처리, 누락·중복 거부, 검사 직전·최종 ACK 직전 STOP도 통과했다. 추가 보드 합성이나 실기 메뉴 복귀 시험은 수행하지 않았다. 보드 준비 기준은 616B, 마지막 실기 기준은 MMC613이다.

**957 자체의 이득은 약 0.09 ms였다.** 동일한 T 바이너리에서 957의 네 번의 소비 확인 호출만 우회했다. 두 번째 팔레트 PUSH까지 11,909 / 11,944개 이벤트가 각각 동일했다. 호출을 실행하면 선행 tile이 0→64B가 되고 마지막 ACK는 0.092 / 0.084 ms 앞당겨졌다. 957 표시 간격은 두 위상 모두 4 VBlank였다. 별도 고정 도착 재생에서 A의 첫 두 PUSH를 정확히 유지하고 T에서 실측한 세 번째 PUSH 지연 1.041 / 0.978 ms만 이후 패킷에 적용해도 tile 16B·48B와 map 1,152B가 226·229·232번 선에서 시작했고 ACK가 0.075 / 0.091 ms 앞당겨졌다. 이 재생은 A의 앞선 일정을 보존했을 때의 65816 결과다.

**전체 일정에서 처음 줄여야 할 곳은 922의 표시 마감이다.** T의 첫 ROM 응답 시각은 두 위상 모두 922에서 A와 같았다. 최종 표시 검사 진입은 A보다 0.022 / 0.061 ms 늦었고, 실제 표시는 15.239 / 15.278 ms 늦었다. A는 92번째 VBlank 안에서 표시했지만 T는 93번째에 표시했다. 뒤이어 923의 첫 ROM 공급이 두 위상 모두 16.640 ms 밀려 표시 누계 차이가 2 VBlank가 됐다. 위상 1은 955에서 한 번을 만회했다. T의 53화면 전체 SPI 비용도 A보다 1,676 / 2,736B 늘었다.

다음은 621과 622 A를 대조군으로 두고, 921 후반의 마지막 발행·반환부터 922의 SEAL 수락·잔여 DMA·246번 검사까지 같은 도착 시각으로 분리한다. 922를 같은 VBlank에 복구한 뒤 923의 첫 ROM 허가와 957 절대 ACK까지 재검증한다. 957의 status 반복 횟수 조정은 보류한다.
