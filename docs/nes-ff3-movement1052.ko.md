# FF3 비공정 이동 계측판 1052·1053

1052는 1050의 1KiB 페이지 무효화, 1053은 1051의 128B 범위 무효화를 실행한다. 두 판에 같은 FPGA 관측기와 같은 65816 프로그램이 들어간다. 원래 설치본에 계측을 추가했으므로 비교 결과는 이 두 판 사이에서 해석한다.

## 실기 순서

1. 1052 ZIP의 `sd2snes` 폴더를 SD 루트에 병합하고 평소 쓰던 FF3 `.nes`를 선택한다.
2. L+R+START → LOAD STATE에서 이전에 제공한 비공정 슬롯 1을 선택하고 방향키를 뗀다. 양쪽 판 모두 같은 저장 파일을 사용한다. 원래 파일의 ROM CRC는 `4be84aa7`, 슬롯 일련번호는 13이다.
3. 비공정 화면이 뜬 뒤 약 1초간 정지하고 오른쪽만 5초 이상 계속 누른다. 첫 방향 입력 뒤 약 4초간 공개되는 모든 화면을 기록한다. L+R+START → EXIT TO MENU로 종료한다.
4. SD의 `nes-frame-ff31052.bin`, `nes-progress-ff31052.txt`, `nes-game-last-ff31052.txt`를 보관한다. 1053 ZIP으로 교체해 같은 순서를 반복한다. 파일명의 숫자는 1053이다. 반복 시험 시 같은 판의 로그가 덮어써지므로 회차별로 복사한다.

## 시간과 끊김의 판정

- FPGA 84MHz 클록 65,536개당 한 눈금(약 0.780ms)이다. 각 화면에서 실제 마지막 타일 뱅크 반환, 65816의 첫 SEAL 헤더 읽기, SEAL 뒤 첫 INIDISP 쓰기, 검사된 최종 ACK의 큐 은퇴 시각을 기록한다. 타일이 없는 화면에는 반환 유효 비트를 세우지 않는다. 첫 방향 입력은 호스트 패드 비트가 중립에서 방향 입력으로 바뀐 시각이다.
- ARM은 검증된 최종 E0를 처음 확인한 사이클과 세대, 배경 스크롤 좌표 및 BG·OBJ 수를 남긴다. 스크롤 좌표는 화면 중간 112행의 값이다. 두 판에 같은 화면당 16B SPI 조회를 추가한다. 플레이 중 SD 쓰기는 없다.
- 저장 슬롯·ROM CRC·저장 일련번호·본문 CRC가 일치하는 두 결과만 비교한다. 최초 이동부터 연속 공개의 FPS, 공개 간격 중앙 경향과 p95·최대, 공개 사이에 지난 VBlank 수의 분포, 타일 반환→SEAL→공개→최종 ACK를 함께 본다. VBlank 횟수는 NTSC 공개 간격에서 환산하며 오차가 4ms 이상이면 미분류로 남긴다. SEAL→공개에는 독립 검사와 DMA 실행도 들어간다. 이 구간 전체를 순수 VBlank 유휴 시간으로 계산할 수 없다.
- `python tools/compare_ff3_movement1052.py <1052.bin> <1053.bin> --rows`로 세대별 값을 출력한다. 서로 다른 캡처 세대 번호가 같은 장면을 뜻하지 않으므로 스크롤 위치와 방향도 대조한다. 공통 좌표가 없는 구간은 동선 단위 결과로만 해석한다.
- 이 계측판에서는 칩 공간을 확보하기 위해 SPI 71·72·74·75의 선택형 최초 ROM 요청/PPU 상세 스냅샷을 미수집으로 표시한다. 기본 ROM 고장 코드, 실행 샘플 수, 독립 검사, STOP 및 메뉴 복귀 경로는 유지한다.

FF3 실측을 받은 뒤 커비와 모험도 4의 무입력 60초를 같은 ROM·동선 기준으로 대조한다. CHR ROM 게임에는 FF3의 CHR RAM 무효화 이득이 직접 적용되지 않으므로, 공통 계획·타일 반환·공개 경로에서 이득이 재현되는지 별도로 판정한다.
