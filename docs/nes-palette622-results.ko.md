# 622 · 957의 팔레트 발행과 작은 BG tile 선행 DMA

**실제 ARM에서 두 시작 위상 모두 957의 16B·48B tile과 1,152B map을 같은 VBlank에 전송했다.** 다만 그 결과와 954 표시 4회, 955 map 선행, 양쪽 마지막 ACK 단축을 한꺼번에 달성한 구성은 없었다. 621을 유지하고 A의 전체 일정과 C·D의 957 전송 결과를 분리해 보존한다.

## 957에서 어느 패킷이 DMA와 겹쳤는가

621의 위상 1에서 BG 16B·48B는 각각 마스터 클록 83,534,922 / 83,696,818에 이미 65816 수락을 마쳤다. 앞 VBlank에는 세 번째 팔레트 패킷(오프셋 128, 232B)이 222번 라인에 큐의 선두로 올라와 228번까지 소비됐고, 네 번째(오프셋 360, 반복값 152B)는 228–236번을 차지했다. 그 뒤 map 1,152B는 239번에 DMA를 시작했지만 두 tile은 SEAL 뒤로 넘어갔다.

같은 621의 실제 패킷을 65816에 다시 공급해 다른 요인을 분리했다. 957의 세 번째 팔레트 PUSH부터 뒤쪽 도착 시각을 통째로 22,603 / 22,305 마스터 클록 늦췄다. 이는 원래 map DMA가 시작된 직후까지 큐의 선두를 비우기 위한 재생 조건이다. 그 전 10,318 / 10,315개 이벤트와 최종 RGB 53장은 각각 기준과 일치했다. 두 위상 모두 tile 16B는 226번, 48B는 229번, map 1,152B는 232번 라인에 DMA를 시작했다. 621 대비 마지막 ACK는 2,322 / 2,092클록 빨랐다. 위상 1은 이 두 DMA를 되찾아도 619와 동률이었다.

raw 준비를 팔레트 앞으로 옮긴 A에도 같은 분리 시험을 적용했다. 957의 앞쪽 10,309 / 10,316개 이벤트를 유지하고 세 번째 PUSH부터 1.054 / 1.049 ms 늦추니 226·229·232번 라인의 세 DMA가 다시 나타났다. 마지막 ACK는 A의 실제 ARM 일정보다 0.098 / 0.096 ms, 621보다 50.026 / 0.085 ms 빨랐다. 이 값은 외부에서 도착 시각을 바꾼 65816 재생 결과다. 실제 ARM 구성의 성과는 아래 연속 일정으로 별도 판정한다.

## 실제 ARM 구성

모두 621에서 출발하며 같은 619 검사 단독 65816을 사용한다. 기존 E0 소비 확인, 두 번의 128µs STOP 확인 대기, raw 준비와 팔레트 발행의 순서를 바꿨다. A–D의 E0와 두 대기는 기존 긴 map 조건에서 실행한다. raw 압축 준비는 기존 patch 수 조건에서 실행한다.

| 구성 | map 발행 뒤 ARM 처리 순서 | 전체 Flash |
|---|---|---:|
| 621 | E0 소비 확인 → 팔레트 → raw 준비 → 대기 → OAM | 212,952B |
| A · after-pack | E0 → raw 준비 → 팔레트 → 대기 → OAM | 212,960B |
| B · after-pause | E0 → raw 준비 → 대기 → 팔레트 → OAM | 212,960B |
| C · advance | 팔레트 → E0 → raw 준비 → 대기 → OAM | 212,956B |
| D · split | E0 → 팔레트 첫 128B → raw 준비 → 대기 → 팔레트 나머지 384B → OAM | 212,980B |
| E · credit-only | A와 같은 순서. OBJ 발행을 시작했고 발행한 BG가 16–64B이면 선택적인 E0 소비 대기를 건너뛴다 | 212,968B |

모두 BSS는 18,592B다. D는 두 구간을 각각 기존 DATA·반복값 선택기와 큐 credit 검사를 거쳐 보낸다. 분할점을 걸치는 반복값, 비반복, 전체 동일 단어 세 입력에서 실제 ARM이 발행한 패킷을 복원해 512B 전체를 비교했다. E는 기존 BG·OBJ 발행 카운터를 사용한다. 해당 카운터는 DMA 완료 권한을 주지 않으며, 개별 패킷 credit·CRC·최종 ACK는 기존 소유자가 계속 확인한다. 0/1/4/5단위와 OBJ 발행 전후의 ARM 분기·STOP을 분리 검사했다.

BG가 작을 때 C, 그 밖에는 A를 선택하는 구현도 전체 링크했다. 단순 분기와 공통 두 단계 구현이 각각 213,020B(+28B), 기존 span/OAM 비용 계산까지 공유한 구현은 213,028B(+36B)였다. 세 이미지는 Flash 예산에서 제외해 연속 일정 수치가 없다. E는 기존 선택적 대기 한 곳만 조정해 24B 여유로 링크했다.

## 두 시작 위상의 53화면 결과

각 칸은 위상 1 / 위상 2다. 마지막 ACK는 동일 시작 클록에서 잰 957의 절대 시각 차이이며 음수가 단축이다. 957의 tile 선행량은 두 목표 tile 총 64B 중 SEAL 전에 PPU로 보낸 바이트다.

| 구성 | 957 tile 선행(B) | 957 map 1,152B 선행 | 954 표시(VBlank) | 951–955 합계(VBlank) | 마지막 ACK 차이, 619 대비(ms) | 621 대비(ms) |
|---|---:|---|---:|---:|---:|---:|
| 621 | 0 / 0 | 양쪽 | 4 / 4 | 21 / 21 | +0.108 / −49.844 | 기준 |
| A | 0 / 0 | 양쪽 | 4 / 4 | 21 / 21 | −49.820 / −49.833 | −49.928 / +0.011 |
| B | 16 / 0 | 양쪽 | 4 / 4 | 21 / 20 | +0.066 / −33.200 | −0.042 / +16.643 |
| C | 64 / 64 | 양쪽, tile과 같은 VBlank | 4 / 5 | 21 / 21 | −0.153 / −0.283 | −0.261 / +49.560 |
| D | 64 / 64 | 양쪽, tile과 같은 VBlank | 4 / 4 | 21 / 21 | +0.006 / +16.616 | −0.102 / +66.460 |
| E | 64 / 64 | 위상 2만, tile과 같은 VBlank | 4 / 4 | 21 / 21 | +0.512 / −49.918 | +0.404 / −0.074 |

A는 956을 표시할 때 이미 619보다 49.912 / 49.917 ms 빨랐다. 957 단독으로는 직전 표시부터 ACK까지 66.418 / 66.449 ms로, 621의 66.424 / 66.402 ms와 비슷했다. C는 957 자체가 66.205 / 66.056 ms로 가장 빨랐지만 위상 2에서 954의 한 VBlank를 되돌렸다. D는 기존 표시 조건과 957의 세 DMA를 모두 유지했지만 956에서 이미 619보다 0.016 / 16.669 ms 늦었다. E에서 보조 drain을 생략하자 위상 1은 두 tile을 먼저 보낸 대신 큰 map DMA를 놓쳤다.

모든 실제 후보에서 906 표시 9회, 952 표시 4회, 954 BG ROM 96회 선행, 957 최종 대기 0회를 확인했다. 955의 첫 192B와 마지막 384B map 선행은 B의 위상 1에서만 마지막 384B를 놓쳤다. 각 실행에서 53장 RGB·map·일반 명령·tile 내용과 VRAM DMA 합계 114,352B는 기준과 일치했다. ARM의 STOP 발행 중단, 공통 65816에서 새 head·STOP 우선과 양쪽 뱅크의 누락·중복 거부, 최종 ACK 직전 STOP을 통과했다. 246번 검사선과 FPGA·65816 바이너리를 유지했다. 이번 단계에서는 보드 재합성·실기 메뉴 복귀·플레이 FPS를 다시 측정하지 않았다.

다음 비교는 **A의 첫 두 팔레트 패킷과 앞선 전체 일정을 보존한 채 세 번째 패킷의 발행 기회만 조정하는 것**이다. A의 원래 512B span 분할을 유지하고 다음 패킷의 오프셋 및 현재 소비·credit 상태를 확인한다. 재생에 사용한 미래 map DMA 시각을 실제 ARM의 판단에 사용하지 않는다. 956 표시 시각부터 따로 대조하고, 957의 세 DMA와 양쪽 절대 마지막 ACK를 함께 판정한다.
