# 602. 다음 D1을 언제 시작할 수 있는가

MMC577의 한 슬롯에서는 현재 블록을 복원하는 동안 다음 블록을 읽을 수 없다. D2를 짧게 한 ARM과 FPGA에서는 952·954 모두 실제 SPI 핀에서 60 B를 줄였다. 두 번째 슬롯과 자율 전송까지 무료로 가정한 표시 전 시간 이득은 4.802/4.763 ms다. 두 장면 모두 한 주기 안에 표시할 수 없어 실기 기준을 MMC577로 유지한다. [블록별 시각·시험 결과](../analysis/overlap602-verification.json) · [601 비교 기준](nes-snoop601-results.ko.md)

## 누가 블록을 소유하는가

MMC577과 600의 블록별 generation 공유 형식에서 952·954 전 블록을 두 번씩 SPI 핀으로 읽었다. D2 전 두 번째 D1은 길이·본문·CRC까지 첫 D1과 같았고 token과 sealed가 유지됐으며 다음 record의 ready는 내려가 있었다. 진단용 두 번째 읽기는 성능 집계에서 제외했다. 실제 ARM은 D1 CRC를 확인하고 packet 함수에서 세대·토큰·범위·내용을 복원한 다음 D2를 보낸다. FPGA가 CS 종료에서 슬롯을 반환하고 나면 ARM은 D0 응답의 CRC와 token+1로 반환을 확인한다. 두 번째 ARM 버퍼만 추가해도 FPGA에는 다음 블록이 없다.

| 연결 ARM · 세대 | 수신 전체 | D1 반환→복원 함수 진입 합계 | 복원 함수 실행 합계 | 다음 D1과 겹칠 수 있는 복원 상한 |
|---|---:|---:|---:|---:|
| MMC577 · 952 | 21.190 ms | 0.738 ms | 5.177 ms | 4.539 ms |
| MMC577 · 954 | 21.142 ms | 0.736 ms | 5.168 ms | 4.503 ms |
| 600 공유 형식 · 952 | 19.124 ms | 0.622 ms | 5.164 ms | 4.377 ms |
| 600 공유 형식 · 954 | 19.089 ms | 0.620 ms | 5.156 ms | 4.338 ms |
| 4 B D2 · 952 / 954 | 18.699 / 18.664 ms | 0.622 / 0.620 ms | 5.164 / 5.156 ms | 4.377 / 4.338 ms |

연결 ELF에서 SPI 호출, 복원 함수 진입·복귀, D2, 확인 D0를 계측했다. 시간은 준비된 생산자, 84 MHz·CPI 2와 기존 opcode별 평균 드라이버 시간으로 환산했다. 새 4 B D2에도 같은 D2 드라이버 비용을 부과했다. 예를 들어 MMC577의 952 첫 블록은 독립 실행에서 입력 시작 후 D1 반환 0.929, 복원 시작 0.983, 복원 끝 1.352, D2 반환 1.437, D0 확인 1.532 ms였다. IRQ·다른 SPI 작업이 있는 기존 공동 일정에서는 첫 D1 완료 1.084, D2 발행 1.521, D2 완료 1.596, D0 확인 1.694 ms였다. 전 블록의 두 위상 시각을 별도로 기록했다. 원래 trace에서 마지막 COMMIT의 D2 시작 표식은 완료 시각보다 늦어 해당 칸을 비웠다. 그 블록의 반환·확인 시각과 독립 ARM 호출 시각은 유효하다.

중첩 상한은 각 보통 블록에서 복원 함수 실행과 다음 D1의 실제 wire 중 짧은 값을 취했다. END 다음 COMMIT은 D3 준비 이후에만 열었다. 이 상한에는 이미 봉인된 두 번째 생산 슬롯, 독립 RX 버퍼, 현재 token을 retire하지 않는 별도 읽기 명령과 자율 SPI가 필요하다. 다음 길이 조회, 슬롯 채우기, DMA 설정·중재, STOP 때 선행 결과 폐기 비용을 0으로 뒀다. 현재 공유 SPI에서 동시에 두 거래가 진행된다고 계산하지 않았다. 이 상한을 실기 이득으로 계상하지 않는다.

## 보호를 유지하며 실제 줄어든 바이트

600의 15개 블록마다 D2를 8 B에서 4 B로 줄였다. 새 명령은 opcode·16비트 token·CRC8을 담고, FPGA는 D1을 끝까지 읽었고 CS 종료 시 정확히 4 B인 경우에만 반환한다. 이후 D0의 상태·CRC8·token+1 확인은 유지했다. 고정 인자·보수·꼬리 필드를 생략하고 반환 결과는 다음 D0에서 확인한다. FPGA와 연결 ARM은 동일 payload와 원래 geometry·raw를 재현했다. 송신 핀 시험과 ARM 실행은 각각 수행했고, ARM의 SPI 콜백에는 같은 D2 형식과 입력 패킷을 적용했다.

- 핀에서 952는 3,300→3,240 B, 954는 3,292→3,232 B였다. 원본 MMC577과 공유 형식, 짧은 D2 모두 D1 재읽기 시험을 통과했다. 잘못된 token·CRC와 3/5 B D2는 유효한 D1 뒤에도 슬롯을 해제하지 않았다.
- 연결 ARM은 D1 CRC 오류 뒤 POP 차단, 부분 입력의 ABORT 뒤 늦은 COMMIT, 잘못된 세대·token 및 D2 유실 뒤 D0 확인 실패를 검사했다. 정상 최종 표시 ACK만 집계하고 잘못된 ACK에서 EA를 막았으며, EA 시점 STOP을 검사했다. 최종 ACK runtime 시험은 출력 주변장치 모델을 사용했다.
- 4 B D2 전체 링크는 **212,996 B**로 Flash 한도를 4 B 초과했다. 제품 전체 FIT·STA, 실기 FPS, 메뉴 복귀는 새로 측정하지 않았다. 첫 Questa 작업 디렉터리는 한글 경로의 work DB 생성에서 실패했고 동일 시험을 영문 경로와 단일 FLOAT에서 완료했다.

## 두 시작 위상의 표시 기한

60 Hz SPI 한도는 5,468.75 B다. 600에서 확인한 최소 credit·최종 retire 조회를 포함하면 952는 5,515→**5,455 B**로 47 B 절감 목표를 통과하고, 954는 5,588→**5,528 B**로 120 B 목표까지 60 B가 더 필요하다. 비교 기준에는 8 B map 후보가 포함돼 있으며 전체 링크에 그 후보를 추가한 비용은 미포함이다. 4 B D2만으로 빨라진 시간은 두 장면 모두 0.425 ms다.

| 세대 · 위상 | 601 표시 전 버스 완료 | 4 B D2 + 복원 중 다음 D1 상한 | 16.667 ms까지 추가 단축 | 같은 ROM 허용 구간의 낙관 표시 간격 |
|---|---:|---:|---:|---:|
| 952 · 1 | 26.613 ms | 21.810 ms | 5.144 ms | 31.481 ms |
| 952 · 2 | 26.764 ms | 21.962 ms | 5.295 ms | 31.443 ms |
| 954 · 1 | 27.017 ms | 22.254 ms | 5.587 ms | 31.894 ms |
| 954 · 2 | 26.985 ms | 22.223 ms | 5.556 ms | 31.900 ms |

이전 표시와 이번 입력 시작은 601과 같게 고정했다. 8프레임 부팅 ROM의 실제 grant 기록에 208/272 요청을 다시 배치한 경우와, 601처럼 전부 캐시 적중한 경우가 같은 VBlank에 도달했다. 같은 시각까지의 실제 65816 검사·DMA나 새 최종 ACK까지 통합한 측정은 아니다.

**다음 판정은 표시 전에 반드시 버스를 건너는 본문이다.** 위 4 B D2 형식에서 수신 CPU와 드라이버 비용을 모두 0으로 둬도 이전 표시→버스 완료가 17.046/17.197 ms 및 17.461/17.429 ms다. 고정 시작에서 두 위상을 모두 맞추려면 이상적인 wire만으로도 952에서 추가 175 B, 954에서 261 B를 표시 전에 없애거나 안전하게 이동해야 한다. 실제 중첩 상한에는 위 표의 5.144–5.587 ms가 남는다. 다음에는 D1/E1/E9의 본문을 실제 소비 기한과 값의 출처로 대응시켜, 어느 바이트를 한 번만 보내거나 이전 화면의 버스 여유로 옮길 수 있는지 확인한다. 시작 위상·이전 EA·STOP·최종 표시 ACK의 소유권을 동시에 만족하는 후보가 나오기 전까지 두 슬롯 통합과 짧은 D2의 Flash 튜닝은 보류한다.

## 재현

`tools/check_nes_overlap602_spi.py`에 600 probe와 delta231/test07, 영문 출력 경로와 Questa bin을 지정하고 FLOAT 래퍼에서 실행한다. `tools/prepare_nes_overlap602.py`로 600 ARM 프로젝트의 사본을 만들고 `tools/build_nes_trial577.ps1`로 링크한다. `tools/check_nes_overlap602.py --help`의 입력은 577 ARM, 600 probe, 새 ARM, 602 핀 결과, delta231/test07, 561 두 위상 및 509 ROM calendar다. 공개 결과에는 원본 ROM이나 SPI payload가 없다.
