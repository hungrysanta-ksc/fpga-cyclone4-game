# MMC931 · 세대 912의 CHR 태그 6265와 다음 OBJ의 ROM 대기

실기 기준은 MMC925다. MMC925 ARM·65816 최종 링크를 실행하고 세대 905–912의 E9 전송을 동일 ROM 허가 일정에서 재생했다. 태그 6265의 행 0–2를 일찍 읽으면 32B OBJ(token 37)는 약 10.9ms 먼저 준비된다. 496B 선행 DMA를 보존한 경우에는 다음 128B OBJ(token 38)의 첫 ROM 허가가 늦어져 두 위상 모두 표시 간격 합이 그대로였다.

## 행이 확정되는 시각

세대 912 첫 E9의 14번째 레코드가 슬롯 108에 마스크 `F8`을 전달한다. 두 번째 E9의 두 번째 레코드 `81 90 03 63 00 79 18 07`이 같은 태그의 슬롯 99와 행 0–2를 확정한다. 같은 묶음의 여섯 번째 레코드는 슬롯 113에 마스크 `E0`을 전달한다. 아래 수락 시각은 패킷 전체 CRC16·CRC8 및 끝 표식을 확인한 경계다. 단위는 NTSC 마스터클록이며 E9 수락은 가장 가까운 정수로 표시했다.

| MMC925 빈 캐시 | 위상 1 | 위상 2 |
|---|---:|---:|
| 첫 E9 수락 | 16,985,790 | 17,344,512 |
| 두 번째 E9 수락 | 17,023,436 | 17,382,158 |
| 기존 선행 읽기에서 행 3 허가 | 17,137,440 | 17,494,800 |
| 주 디코더가 두 번째 묶음 검사 시작 | 17,199,162 | 17,557,954 |
| 행 0 일반 요청 → 허가 | 17,223,135 → 17,489,748 | 17,581,887 → 17,847,108 |
| 행 0 대기 | 12.414ms | 12.349ms |

두 위상 모두 행 3을 읽는 시점에 두 번째 E9도 이미 수락됐다. 기존 보조 판독기가 대기 중인 묶음에서 먼저 볼 수 있는 레코드는 첫 번째뿐이다. 두 번째 레코드의 확정된 마스크를 이때 사용하면 같은 ROM 허가 구간에서 행 0–2도 읽을 수 있다.

## 표시까지의 비용

좁은 후보는 가장 최근에 수락한 E9의 두 번째 레코드 하나만 보관한다고 가정했다. 적중한 태그의 두 바이트짜리 행이 이미 공급 중이고, 그 레코드에서 지시한 추가 행이 있을 때만 정상 요청 뒤의 유휴 허가를 사용한다. 세대나 태그 번호를 조건으로 사용하지 않았다. 이전 묶음들도 보관하는 대조군과 최근 하나만 보관하는 후보는 네 조건에서 같은 결과가 나왔다. 넓은 후보는 E9 수락 뒤 모든 레코드를 보조 판독기에 노출하고, CDC 8클록과 레코드당 판독 20클록을 부과했다.

| 세대 912 · 위상 1 / 2 | MMC925 | 최근 두 번째 레코드 | 전체 묶음 조기 판독 |
|---|---:|---:|---:|
| 빈 캐시 밀집 여섯 간격 합 (VBlank) | 16 / 16 | 16 / 16 | 15 / 15 |
| 빈 캐시 최종 ACK 단축 (ms) | 기준 | 0.060 / 0.031 | 16.258 / 16.252 |
| 빈 캐시 SEAL 전 DMA (B) | 496 / 496 | 528 / 528 | 0 / 0 |
| 그중 MMC925와 주소가 같은 바이트 | 496 / 496 | 496 / 496 | 0 / 0 |
| 기존 캐시 여섯 간격 합 (VBlank) | 13 / 13 | 13 / 13 | 13 / 13 |
| 기존 캐시 최종 ACK 단축 (ms) | 기준 | 0 / 0 | 0 / 0 |

좁은 후보에서 token 37은 10.918 / 10.929ms 일찍 준비됐다. 다른 37개 타일 묶음의 준비 시각은 모두 MMC925와 같거나 빨랐다. 다음 token 38에서 태그 3081 행 0이 ROM 허가를 10.895 / 10.906ms 기다려 token 38 준비의 순이득은 0.010 / 0.009ms였다. 912 공개는 두 위상 모두 기존 VBlank의 242선에서 241선으로 이동했다. 기존 캐시는 세대 912에서 이 ROM 공급이 필요하지 않았다.

넓은 후보는 두 위상 모두 912를 한 VBlank 앞의 248선에 공개했다. 선행 DMA로 보내던 496B 전부가 SEAL 뒤로 이동했고, 다른 타일 묶음 4 / 5개의 준비도 늦어졌다. 이 결과로 실기판을 교체하지 않는다. 다음 비교에서는 3081 행 0의 확정 시점과 같은 허가 구간 내 자리부터 대조하고, 496B를 보내는 여섯 DMA의 실제 뱅크 반환과 SEAL 시점을 같이 본다.

## 보호 조건과 재현

* 910의 마지막 D2와 가장 가까운 캡처선 차이는 기존 캐시에서 −120 / −499클록으로 유지됐다. 빈 캐시에서는 같은 캡처선에 대해 MMC925의 +84,731 / +85,752클록이 좁은 후보에서 +50,086 / +51,062클록으로 줄었다. 두 값 모두 원래 캡처선 뒤이며 추가 캡처 손실은 없었다.
* 기존·빈 캐시와 두 시작 위상에서 대조군 SPI 이벤트가 MMC925와 일치했다. 각 재생의 여덟 화면에서 RGB·타일·map·팔레트·section 5와 작업량이 같았고, ROM 허가 중복도 없었다.
* 새로 당겨진 세 행의 실제 허가 시각으로 위상당 24개 STOP 경계를 모델에서 검사했다. 취소 시 행과 소유권을 폐기하고 이미 허가된 물리 요청은 응답까지 포트를 점유했다. 같은 번호의 세대로 재시작해도 취소된 행은 재사용되지 않았다.
* 65816에서 손상 descriptor·중복·잘못된 SEAL 거부와 복사·표시·OBJ 마지막 바이트 STOP을 다시 실행했다. 동일한 ARM 해시에서 SRAM D0 네 곳, 손상 CRC 거부, 타이머·base·메뉴 복귀 증거를 대조했다. FPGA 공급은 공유 포트 일정 모델로 검증했다. 새 보드 RTL·FIT·STA와 새 실기 FPS는 측정하지 않았다.
