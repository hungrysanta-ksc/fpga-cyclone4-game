# 1002 · 912 마지막 OBJ 반환과 일반 출력의 SPI 중첩

## 목표

978에서 세대 912의 마지막 128B OBJ(token 38)가 뱅크를 반환하기 전에 팔레트·OAM·section 5를 발행할 수 있는 양을 구한다. 두 시작 위상 모두 VBlank 46 시작 전에 그룹을 준비하고 246선 안에 공개해 최종 ACK를 앞당기는 것이 목표다.

## 작업내용

두 위상에서 978 ARM을 실행해 바이트별 마지막 쓰기를 기록했다. 912의 원본 영상 버퍼와 실제 전송 패킷을 바이트 단위로 대조했다. ARM의 FPGA 조회 결과는 실제 E8 응답의 세대·토큰으로 찾고, 물리 반환은 65816이 해당 토큰을 소비한 시각으로 잡았다. 계측 전후 SPI 이벤트·타일 생산·65816 실행 기록·계획 기록의 SHA-256이 일치했다.

다음 표의 0은 **각 위상에서 마지막 OBJ가 물리 뱅크를 반환한 시각**이다. 음수는 반환 전이다. 팔레트·OAM은 각각 첫 패킷이며 section 5는 기존 201B·240B 묶음이다. SPI 발행은 거래 시작이다.

| 978 패킷 | 원본 확정 위상 1 / 2 (ms) | 조립 완료 위상 1 / 2 (ms) | SPI 발행 위상 1 / 2 (ms) |
|---|---:|---:|---:|
| 첫 팔레트 | −9.289 / −9.299 | 별도 계측 없음 | −1.715 / −1.724 |
| 첫 OAM | −9.325 / −9.334 | 별도 계측 없음 | +1.076 / +1.067 |
| section 5 · 201B | −9.109 / −9.119 | +2.049 / +2.040 | +2.104 / +2.095 |
| section 5 · 240B | −9.096 / −9.105 | +2.053 / +2.043 | +3.011 / +3.002 |

마지막 OBJ의 FPGA 준비는 16,373,281 / 16,373,185클록, 실제 유효 E8 응답 종료는 16,437,576 / 16,437,289클록, 뱅크 반환은 16,453,858 / 16,453,770클록이었다. VBlank 46 시작은 16,388,372클록이다. 최초 유효 응답까지 2.994 / 2.985ms가 걸렸다. 생산 모델이 타일을 처음 관측한 시각과 ARM이 토큰을 읽은 시각을 구분했다.

## 성과

**현재 두 슬롯·패킷 형식에서 SPI 중첩은 늘었지만 VBlank 46 공개와 최종 ACK 개선을 함께 얻지 못했다.** 기존 거래의 빈 구간에 패킷을 온전히 넣을 수 있는지 각 section 순서를 보존하는 부분집합 검색으로 확인했다. 원래 일반 E1을 재배치하되 나머지 SPI 거래를 고정하면 1,038B 중 VBlank 46 시작 전 들어가는 최대치는 두 위상 모두 72B, 원래 마지막 OBJ 반환 전 최대치는 243B다. 이는 credit·65816 소비를 무료로 놓은 전송 상한이다. 1,038B는 팔레트·OAM·section 5 후반 9개 패킷의 SPI 헤더 포함 크기다.

65816 재생은 BEGIN과 911까지의 일정을 고정했다. 912에서 두 슬롯, 실제 수락·복사·반환·STOP, 같은 뱅크의 선행 토큰 반환, 타일 생산 비용을 반영했다. E0·E8 재배치 후보에서는 978의 나머지 SPI 점유를 유지하고 필요한 상태 조회와 타일 조회 거래 시간을 다시 지불했다. section 5는 원본 확정 시 송신 데이터를 즉시 사용할 수 있다고 가정해 중간 조립 비용을 유리하게 잡았다. 바뀐 발행 순서는 송신기 재생 실험이며 새 ARM 펌웨어 전체 링크의 측정값은 없다.

| 912 발행 조건 | OBJ 반환 전 완료한 일반 SPI | 그룹 준비가 VB46 시작을 넘긴 시간, 위상 1 / 2 | 공개 위상 1 / 2 | 최종 ACK 변화, 위상 1 / 2 |
|---|---:|---:|---|---:|
| 978 | 72B | 9.446 / 9.444ms | VB47 242 / 242선 | 기준 |
| 준비된 타일 우선 | 538B | 6.483 / 6.483ms | VB47 248 / 248선 | 0.378 / 0.380ms 지연 |
| 준비된 일반 패킷 우선 | 1,038B | 6.310 / 6.303ms | VB47 246 / 245선 | 0.242 / 0.239ms 지연 |
| 일반 패킷 우선 + 1001 DMA 사전 설정 | 1,038B | 6.205 / 6.199ms | VB47 244 / 244선 | 0.151 / 0.149ms 지연 |

일반 패킷 우선에서는 일반 SPI 3.612ms 전부가 마지막 OBJ 반환 전에 끝났다. 그러나 마지막 OBJ 반환 자체가 978보다 1.348 / 1.345ms 늦어졌다. 타일 우선에서는 반대로 마지막 OBJ가 약 2.23ms 먼저 반환됐지만 그룹 준비와 공개는 목표 VBlank를 놓쳤다. 기존 E0·E8 점유를 그대로 예약하고 필요한 추가 조회도 청구한 보수적 대조군은 두 위상 모두 VB48에 공개됐다. 그 대조군에서는 section 5 발행을 조립 완료 시각에서 원본 확정 시각으로 옮겨도 실제로 쓸 수 있는 SPI 구간이 같았다.

**수신 비용.** 978과 타일 우선 후보의 성공 경로에서 패킷별 CPU 사이클과 WRAM 명령 인출을 계측했다. 6클록/사이클에 WRAM 명령 바이트당 최소 2클록을 더하고 패킷마다 64클록을 차감했다. 첫 E9에서 타일 8개가 모두 준비되고 SPI·credit·그룹 설정 비용이 0이라고 놓아도, 시험한 두 경로의 짧은 비용을 취한 기존 section 순서 모델에서 업로드 진입은 VBlank 시작보다 24,758 / 24,470클록(1.153 / 1.139ms) 늦다. 이 값은 계측한 명령 경로와 section 순서에서의 수신 예산이다. section 안의 순서까지 자유롭게 놓으면 같은 계산에서 6,632 / 6,920클록이 남으므로 다른 수신 ABI까지 불가능하다고 단정할 수 없다.

908 공개 시각·909 선행 DMA 624B와 910 입력 일정이 보존됐다. 정상 재생의 905–912 RGB를 978과 대조했고, 손상된 SEAL과 STOP은 912 공개·최종 ACK를 막고 직전 911 화면을 유지했다. [위상별 원본 시각·실제 발행 순서·검사 결과](../analysis/overlap1002-results.json)

## 후속작업

978을 유지한다. 다음 후보는 912의 첫 OAM 152B와 뒤의 반복 OAM 360B(op 8) 수신 경로다. 반복 OAM의 관측 수신 비용만 최소 약 22,336클록이므로, 원본을 유지하면서 복원·검사를 앞선 시점에 처리하거나 다른 타일 소비와 겹칠 여지를 먼저 계측한다. 1.14ms는 SPI 등을 무료로 둔 부족분이다. 실제 두 슬롯·SPI 일정을 다시 연결한 뒤 VB46 시작 전 그룹 준비와 최종 ACK를 함께 판정한다.

재현은 978 캡처와 1001 근거 자료가 있는 TEMP에서 위상 1·2 각각 아래 순서로 진행한다.

1. `tools/nes_ready999.py TEMP PHASE --generation 912`로 ARM 쓰기를 수집한다.
2. `tools/nes_overlap1002.py TEMP PHASE MODE`에서 joined·source·arb·tail·free를 실행한다. reference·arb는 별도로 `--audit`을 붙여 수신 사이클을 센다. arb에는 `--fault bad_seal` 및 `--fault stop_decode`를 각각 적용한다.
3. arb·tail에서 `--stage`로 1001의 DMA 사전 설정도 결합하고, tail에서는 같은 두 fault를 각각 재생한다.
4. `tools/check_nes_overlap1002.py TEMP analysis/overlap1002-results.json`으로 바이트·일정·보호 조건과 수신 비용을 검증한다.
