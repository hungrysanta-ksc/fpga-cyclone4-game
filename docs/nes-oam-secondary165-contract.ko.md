# NES165 secondary OAM 저장 제어와 전체 배치 성공

같은 PR108의 후속 결과다. [이전 주소 범위 최적화](nes-oam-port165-contract.ko.md)의 964/963 LAB 초과를 해결하여 **전체 FPGA 배치·배선이 완료**되었다. 타이밍은 아직 실패하므로 실기 설치 파일은 만들지 않았다. 설치164와 원본 GBC, 카트리지 세이브 SRAM은 그대로 보존한다.

## 변경과 작업 의미

secondary OAM의 각 바이트를 초기화할 때 데이터 8비트 전체를 리셋하는 대신, 바이트별 유효 비트만 지우고 읽기에서 무효 바이트를 `FF`로 반환한다. 실제 데이터를 쓰는 같은 클록에서 유효 비트를 설정한다. 행 복사도 무효 원본이면 `FF`를 복사한다. reset/clear는 유효 비트에 대해 쓰기보다 우선한다. 숨겨진 데이터가 무효 상태에서 바뀌어도 소비자에게 노출되지 않는다.

쓰기 조건을 바이트별로 분리해 레지스터의 리셋·제어 구성을 단순하게 했다. 새로운 RAM 블록으로 옮긴 작업은 아니며 클록, CE, 외부 읽기 지연과 CPU/PPU 소비 시점은 바꾸지 않았다. extra sprite 경로도 기능을 유지한다. 보드에 연결되지 않은 부분은 기존과 같이 합성에서 제거된다.

이번에는 논리 수 자체가 줄어서 성공한 것이 아니다. 이전 후보보다 조합 논리는 70개, 레지스터는 32개 늘었지만 실제 LAB 배치가 가능해졌다. 이 결과는 **연속 화면을 위한 native 영상 경로가 전체 게임 코어와 같은 FPGA에 들어갈 수 있음**을 보여준다. 실기 게임의 연속 표시 성공을 의미하지는 않는다.

## 선택 결과

선택은 `map03/reproduce`이며 기준은 board03 + AREA + 이전 주소 수정이다. 생성 입력 59개는 그대로이고 `rtl/ppu.sv`, AREA 설정을 적용한 `board.qsf`만 원래 board03과 다르다. 재생성 입력은 선택 후보와 바이트 단위로 일치한다.

| 항목 | 이전 range map02 | 이번 secondary map03 |
|---|---:|---:|
| MAP 조합 논리 | 13,928 | 13,998 |
| 레지스터 | 8,284 | 8,316 |
| 실제 FIT LE | 14,983 (실패 중간값) | 15,052 / 15,408 |
| 실제 LAB | 964 / 963, 실패 | 963 / 963, 성공 |
| M9K | 35 | 35 / 56 |

새 후보 MAP 추정 LE는 19,421이며 실제 배치 LE와 혼동하지 않는다. 메모리 197,104비트, 실제 핀122/가상핀0, PLL1이다. Fitter의 첫 내부 라우팅 시도에서 net 하나가 실패했지만 자동 재시도로 최종 성공했다. 원시 로그를 보존했다. LAB는 모두 사용하므로 후속 논리 추가의 여유를 보장하지 않는다.

## 변경 경계 검증

- 기존 banked OAM과 216,362 edge 비교: 행 복사2,426회, CPU 쓰기3,111회, save-state 쓰기10,473회, 충돌2,012회. primary256/secondary64바이트, 상태, 출력, native 관측값이 일치했다.
- 유효 비트 시험: extra row0..15 중 허용8/거부8, 총1,024바이트 비교. 무효 저장소에 일부러 `37`을 넣어도 `FF`가 유지되며 새 쓰기에서만 데이터가 보였다.
- 잘못된 valid 갱신을 넣은 음성 대조는 row0/byte32에서 검출했다.
- 이 검증은 실행한 시나리오의 비교이며 모든 입력에 대한 형식 증명이나 새 SMB3 전체 부팅 시험은 아니다. 기존 board/SPI 시험의 stub 코어 범위와 전체 코어 합성을 구분한다.

`map01`의 단순 쓰기 분리는 조합 논리13,939로 개선되지 않아 채택하지 않았다. `map02/test02`는 상수 주소 함수가 참조하는 전역 메모리 변경을 시뮬레이터가 갱신하지 않아 36ns에서 비교에 실패했다. 최종 `map03`은 모든 읽기를 명시적 메모리·valid 피연산자의 삼항식으로 바꿨고 비교를 통과했다. 실패 원본도 남겼다.

## 같은 배치의 타이밍과 미완료 범위

기존 SDC를 그대로 적용한 3 corner의 같은 클록 경로 보고서198행을 확인했다. 각 클록별 최소 setup은 NES +8.479ns, host84 +1.937ns, board8 +119.620ns, **memory168 −1.218ns**이다. 최소 hold는 +0.155ns다.

실패 경로는 `reader|check_response_address[15]` → `control|check_next[7]`이며 CHECK 응답 비교에서 다음 주소 갱신까지 7단 논리를 지난다. 보고서의 max-delay 목표는 **5.500ns**다. 더 느슨한 목표로 바꾸어 통과 처리하지 않았다. nominal 주기만 적용한 별도 재분석은 하지 않았으므로 그 결과를 주장하지 않는다.

혼합 도메인 setup 최저 −12.396ns, 미제약 입력54/출력57포트도 남아 있다. 같은 클록 hold 통과가 CDC·외부 IO 승인이라는 뜻은 아니다. 예전 배치의 타이밍 승인을 새 배치에 그대로 적용하지 않는다.

## 다음 작업

1. 선택 map03의 실제 CHECK 응답 비교·상태/주소 갱신 경로를 줄인다. 이미 끝난 OAM 실험이나 무변경 부팅 시험을 반복하지 않는다. 응답의 유효성·주소·오류 판정 및 명령 완료 순서는 보존한다.
2. 변경 경계 시험과 새 배치의 setup/hold, 필요한 PSRAM/SPI/SNES IO·CDC 조건을 확인한다. SDC 완화나 세이브 SRAM 전용으로 해결하지 않는다.
3. MCU RUN 수신·변환·ACK를 기존 사운드/입력/STOP/경과시간에 연결하고 전체 firmware link와 중첩 stack을 확인한다.
4. 최소 안정성 확보 후 SMB3(J) 첫 레벨에서 화면·사운드·조작을 검증한다. 반복 A/B 표시나 동일044 복원 시험을 선행 조건으로 늘리지 않는다.
