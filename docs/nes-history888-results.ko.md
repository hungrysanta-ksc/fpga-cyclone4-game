# 888 · 표시 ACK 뒤의 뱅크 이력 확정 비용

## 변경과 비교 조건

886에서는 ARM이 유효한 E0 응답을 받은 뒤 144B의 타일 수신 비트맵을 대상 뱅크 이력에 1B씩 OR한다. 888은 같은 주소 범위를 32비트 단위로 병합한다. 배열의 실제 오프셋은 2,560과 2,992이고 두 뱅크의 간격은 144B다. C 코드는 고정 크기 `memcpy`로 접근하고 전체 ARM 링크는 정렬된 word load·OR·store를 사용한다. serial·generation·대상 뱅크·실제 표시 검사에 성공한 뒤에만 병합에 진입한다. 대기 주기·SPI 명령·65816 ROM·FPGA에는 변경이 없다.

양쪽 뱅크에서 전체·빈·혼합 비트맵과 7개 거부 조건을 실행했다. 20조건 모두 원래 함수와 반환값 및 보호 영역 포함 6,064B가 일치했다. 성공마다 대상 뱅크의 모든 바이트가 독립 계산한 OR 값과 같고 반대 뱅크의 값도 보존됐다. 링크된 함수의 성공 경로는 903→326명령, Flash는 212,960→212,956B로 줄었다(여유 36B). BSS는 20,908B다.

밀집 945와 오프닝 916의 최종 ACK가 다음 입력과 947·918 캡처를 좌우한다. 세 가지 재생을 사용했다. 첫째는 계측을 추가한 886 부팅이다. 둘째는 886 부팅에서 해당 세대의 병합 함수만 한 번 교체한 인과 대조다. 기존·후보 ELF에서 함수와 외부 abort 분기 목적 주소가 같음을 확인하고 직전·해당 표시 집계에서 교체·복원한다. 셋째는 새 ARM 링크로 처음부터 실행한 전체 일정이다. 세대 번호 조건은 진단 대조에만 들어간다. 실기 기준은 MMC872다.

## 같은 E0 응답에서 출발한 결과

위상 2에서 유효 E0의 완료 시각은 밀집 46,802,218클록, 오프닝 26,063,359클록으로 한 세대 대조에서 원본과 같았다. 아래는 E0 거래 완료부터 EA 거래 시작까지의 겹치지 않는 구간이다.

| ARM 구간 (마스터클록) | 밀집 945, 886 → 888 | 오프닝 916, 886 → 888 |
|---|---:|---:|
| 유효 E0 완료부터 뱅크 확정 함수 진입 | 392 → 392 | 361 → 361 |
| 타일 수신 이력 확정 | 461 → 166 | 462 → 167 |
| map 이력과 다음 호출 준비 | 11 → 11 | 10 → 10 |
| 팔레트·OAM 이력 확정 | 5 → 5 | 284 → 284 |
| 런타임 확인·집계, 표시 통계, retire 호출 준비 | 67 → 67 | 63 → 63 |
| retire 진입부터 EA 발행 | 113 → 113 | 113 → 113 |
| **합계** | **1,049 → 754** | **1,293 → 998** |

두 경우 모두 295클록(13.74µs)을 줄였다. 947의 마지막 D2 여유가 −36→+259클록, 918은 −254→+41클록이 되어 각각 한 VBlank 먼저 캡처·표시했다. 이후 일정까지 포함하면 단일 세대 교체의 위상 2 밀집 합은 139→140회, 오프닝은 122→121회다.

## 정적 링크로 부팅한 결과

| 지표 (위상 1 / 위상 2) | 886 | 888 |
|---|---:|---:|
| 밀집 60개 표시 간격 합 | 138 / 139 | 139 / 138 |
| 밀집 마지막 65816 ACK (마스터클록) | 63,944,966 / 64,659,938 | 64,303,004 / 64,302,572 |
| 밀집 E0 거래 수 | 3,135 / 3,244 | 3,235 / 3,133 |
| 오프닝 60간격 합 | 121 / 122 | 121 / 122 |
| 오프닝 703 공개 (VBlank·선) | 59·231 / 59·231 | 59·231 / 59·249 |
| 전환 간격 합 | 119 / 119 | 119 / 119 |

위상 2의 밀집 947은 목표 캡처선보다 1,552클록 먼저 D2를 반환해 VBlank 135에 공개했다(886은 136). 반면 오프닝 918에서는 앞선 출력의 유효 E0 확인이 744클록 늦어져 295클록을 절감하고도 캡처선을 703클록 넘겼다. 918 공개는 두 링크 모두 VBlank 78이었다.

두 위상의 959 선행 map DMA는 768B의 WRAM 원본 주소·VRAM 주소·PPU 포트·값·순서가 모두 같았다. 위상 1에서 타일 offset 416의 수락 완료가 두 번째 E0 조회 시작보다 63클록 늦었다. 886에서는 같은 조회가 완료보다 1,380클록 늦어 새 credit을 바로 읽었다. 888에서는 세 번째 조회에서 credit을 확인해 다음 타일 offset 512까지의 발행 간격이 5,439클록 늘었다. 이후 SEAL 발행도 886보다 7,536클록 늦었다. 959의 VBlank 대기 진입선이 219→226선으로 넘어가 위상 1의 마지막 ACK가 16.67ms 늦었다. 위상 2 마지막 ACK는 16.64ms 빨랐다.

888은 실기판 채택을 보류한다. 다음은 위상 1의 959에서 offset 416의 65816 수락 완료와 ARM의 큐 조회를 맞추는 시험이다. 일반 조회 주기와 독립 검사를 유지하면서 offset 512와 SEAL의 발행을 회복하고, 위상 2의 947 캡처·오프닝 703 공개선 및 918 캡처를 함께 확인한다.

## 재현

두 위상에서 활성 RGB와 map, 밀집 세대별 작업량, 최종 ACK·EA·COMMIT 순서를 대조했다. ARM retire 19조건, 65816 수신·STOP·cold 재시작 12조건, ARM 메뉴 복귀 경로를 통과했다. 888의 실기 FPS는 미측정이다.

1. `prepare_nes_history888.py`와 `build_nes_mmc479_arm.ps1`로 883 공유 ARM 소스에서 전체 후보를 링크한다. 65816은 886 정적 ROM을 사용한다. `guard_nes_history888.py`로 두 링크의 병합 결과와 명령 수를 비교한다.
2. `replay_nes_history888.py TEMP PHASE SCENE`으로 dense·opening·transition을 두 위상에서 실행한다. 밀집·오프닝의 위상 2는 각각 `--reference`와 `--local`도 실행한다. 링크된 ARM과 65816을 같은 캡처·ROM 허가표·SPI 비용 모델에서 실행한다. 클록은 콘솔 실측값과 구분한다.
3. `test_nes_mapwait880.py TEMP PHASE --generation 959 --audit 888-word`로 비활성 VRAM 선행 쓰기를 기록한다. 메뉴 및 retire 가드, 65816 소비·STOP·cold 재시작을 검사하고 `check_nes_history888.py TEMP analysis/history888-results.json`으로 활성 RGB·map·표시·최종 ACK를 대조한다. [측정 결과](../analysis/history888-results.json)
