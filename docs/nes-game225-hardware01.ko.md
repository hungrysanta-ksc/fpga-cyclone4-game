# NES225 실기: 실행 정상, 스크롤 성능 개선은 미달

PR123의225 시험 결과다. **60.07초 실행·사운드·메뉴 복귀는 정상이나, 스크롤 성능 개선 성공으로 채택하지 않는다.** 사용자는 정지 화면의 확실한 개선과 스크롤 화면의 악화 의심을 보고했다. 녹음 잡음은 사용자 요청대로 분석에서 제외했다. 화면 처리의 일부 비용이 줄었지만 전체 갱신 비용은 충분히 줄지 않았다.

## 실행과 종료

ROM393216B 로드·비교, START/RUN/STOP/base 복원 통과. DISPLAY_NEXT231080ms부터 DISPLAY_STOPPED291150ms까지60070ms, MENU_PREPARED294390ms다. 영상63–64초에 카트리지 메뉴도 확인했다.

BEGIN402/COMMIT401/ABORT0, 마지막 표시generation668/59960ms, 다음669는 미완료다. 패킷11320개 모두 retire됐다. ROM/run/sink/video/window/plan 오류와 실패 전송은0이다. `native_result=1`은 기존60초 deadline이고 `native_receiver_error=24`는 다음D2에서 callback 실패 또는 status 거부를 함께 나타낸다. 실제 transfer 전후 guard가 최초deadline을 보존하므로 종료 경계와 일치한다. 별도의ACK 손상으로 단정하지 않는다.

`screen_error=169`/`spc_init_status_hex=a9`는 SPC 초기화 결과이며 화면 오류가 아니다. `screen_frames=0`은 untrusted telemetry로 사용하지 않는다. 사용자 사운드 정상 보고와 unmute 확인을 기록했다. 입력 trace111은 변경된8bit 읽기 수이며 물리 버튼111회라는 뜻이 아니다. 이번 사용자 보고만으로 입력 유지 품질을 새롭게 인증하지 않는다.

## 확인된 비용 이동과 아직 모르는 원인

1. **맵 계열 비용 감소는 관측됐으나 실제 맵 전송 반감은 입증되지 않았다.** mapdirty/완료는17.82%, E1/완료는8.42% 줄었다. mapdirty는 직전 표시 대비64B블록이고, 비활성bank에 실제 올린 누적union과 다르다. E1도 맵 전용이 아니라OAM/CGRAM/HDMA/BEGIN/SEAL/descriptor를 포함한다. 합성192프레임의49.44% 맵 전송 감소를 실기 전체로 확대하지 않는다.
2. **타일 생성·완료 처리 쪽 부담이 늘었다.** 계획/완료+19.06%, 출력B/완료+26.40%, E8/완료+43.90%다. 총E8은35968→49893회. E8에는credit·descriptor·END·retire/rearm 조회가 포함되므로 이것을PSRAM miss 수나순수대기시간으로 부르면 안 된다.
3. **플래너 함수 자체가 느려졌다는 증거는 없다.** 내부 누적은13.54→12.80초, 완료당도32.55→31.92ms다. 전체 계획 구간이 커진 부분은 그 바깥6.56→8.66초에 있다. 실제 호출 순서는resident BEGIN→sink BEGIN→planner→plan finish다. 따라서BEGIN, 남은계획 flush, 타일chunk 전달·END대기, 서비스 호출이 조사 대상이다. 이 차이를FPGA 단독 지연이나finish만의시간이라고 단정하지 않는다.
4. **입력 수신과 전체 재계산도 여전히 크다.** D1은완료당0.87% 감소에 그쳐 순수wire만17.76ms다. 계측된공유SPI 전체는54.21ms/완료로16.67ms보다 크다. 현재 반복되는표현과미완료분의관측평균이며NES의불변대역폭 하한은 아니다. E8 polling만 없애는 것으로60fps가 되지는 않는다.

225는맵 위치/HOFS와화면밖셀 보존을 바꿨고타일키·할당·FPGA·SNES 소비기는223과 같다. 동일입력에서계획타일이증가하는지현재로그로재현할수는없다. 영상의서로다른진행범위, 표시generation 선택시점 변화, tile/row-alt/mask의working set이후보이며**원인 확정은 아니다**. 화면밖맵 보존이반복word압축효율에영향을줄수있지만맵전용실기byte집계가없어역시가설이다. 무조건buffer확대나새FPGA FIT부터시작할근거는없다.

## 다음 작업과 작업 의미

이번 결과 기록은 **60fps를 위한 스크롤 최적화의 합격 기준을 바로잡는 작업**이다. 정지장면개선·합성맵절감만으로완료처리하지않는다. 새펌웨어/FIT/배포ZIP은만들지않았다.

다음 구현은실제스크롤의새타일처리와BEGIN/finish/bulk drain을우선검토하고, 전체geometry수신·재계산·64B맵갱신을함께16.67ms예산에넣는다. 기존자료에동일스크롤geometry/state가있다면223/225에같이재생해중복생성·bank재업로드를먼저분리한다. 이번3TXT로그입력은복원할수없다. 필요시다음성능변경에제한된phase/plan-kind/dirty-union계측만동반하며계측만의실기반복이나새FIT루프를앞세우지않는다.

source epoch/physical CHR/row-alt/mask/두bank기준/최종displayACK를보존한다. ACK제거·중간타일생략·타임아웃완화는성능대책이아니다. ARM여유1912B와FPGA159LE/2LAB/9M9K를구별해지키고저장SRAM/GBC164를건드리지않는다. 같은225/044를다시시험할필요는없다. 최소경계검증후실제첫레벨스크롤에서검증한다.
