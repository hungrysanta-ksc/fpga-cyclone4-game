# 870 · map 선행 DMA 완료와 첫 팔레트 발행

**밀집 데모 후속 기준은 870G, 실기 비교 기준은 MMC866이다.** 870G는 밀집 60개 간격을 두 위상 모두 141 VBlank로 줄이고 마지막 ACK도 앞당겼다. 936에서는 1,472B map과 나머지 업로드를 같은 VBlank에 끝냈다. 오프닝 703은 회복했으나 오프닝 전체와 장면 전환에는 추가 대기가 남았다. [870G 최종 링크와 세 장면 검증](../analysis/progress870-g.json)

| 같은 시작 위상의 측정값 | MMC866 | 869 | 870E | 870F | 870G |
|---|---:|---:|---:|---:|---:|
| 936 표시 간격, 위상 1 / 2 | 3 / 3 | 5 / 5 | 3 / 3 | 3 / 3 | 2 / 2 |
| 밀집 60개 간격 합, 위상 1 / 2 | 145 / 144 | 144 / 146 | 146 / 143 | 143 / 144 | 141 / 141 |
| 밀집 마지막 ACK 차이, 위상 1 / 2 | 기준 | −16.64 / +33.29ms | +16.65 / −16.65ms | −33.27 / 0.00ms | −66.55 / −49.92ms |

G에서는 압축 map이 마지막으로 발행됐거나 같은 세대의 DMA 완료를 확인했으면 팔레트 앞의 별도 대기를 건너뛴다. 기존 일반 패킷 경로가 준비된 tile과 큐 credit을 확인하며, tile 생산자가 map 반환을 확인하는 경로를 그대로 사용한다. 936에서 65816의 map 검사·반환은 두 위상 각각 261선과 0선이었다. ARM은 팔레트를 큐에 미리 넣었고 65816은 map 반환 직후 0선과 1선에 팔레트를 수락했다. SEAL은 두 위상 모두 167선에 수락했다. 그다음 VBlank 226선부터 1,472B map을 전송하고 245선에서 공개 가능 여부를 검사한 뒤 255선에 화면을 공개했다. 세대 번호와 주사선 번호는 펌웨어 발행 조건에 사용하지 않는다.

E와 F는 별도의 1,472B 선행 DMA를 살리면서 936을 3회로 복구했다. F는 같은 세대의 완료가 확인된 경우 팔레트 중간의 추가 조회도 생략했다. 위상 2에서 F의 60개 간격과 마지막 ACK는 MMC866과 같았다. G에서는 팔레트 전용 대기를 생략해 팔레트와 OBJ를 겹쳐 준비할 수 있었다. 그 결과 936의 표시용 VBlank에 필요한 데이터가 모두 갖춰졌다. 세 후보 모두 밀집 map E1 거래량은 69,213→40,158B였고 op10은 19회였다. [870E](../analysis/progress870-e.json) · [870F](../analysis/progress870-f.json) · [870G](../analysis/progress870-g.json)

G는 ARM Flash 212,972/212,992B, 869 소비기 ROM 여유 17B, 세 장면 중 최저 관측 스택 여유 492B다. 같은 입력으로 각 후보 348장의 활성 영상이 세대별로 MMC866과 일치했다. 오프닝 703은 두 위상 모두 VBlank 59·231선이다. 오프닝 60개 간격은 126→127 / 126→127, 전환 48개 간격은 119→120 / 119→121이었다. 다음 작업은 G의 밀집 이득을 유지하며 오프닝 759까지 처음 놓친 마감과 전환의 첫 추가 대기에서 캡처 준비, map 반환과 SEAL을 대조하는 것이다. 보드 RTL·65816은 869와 동일하며 새 실기 시험은 수행하지 않았다.

## 936에서 확인한 원인

869의 65816은 두 위상 모두 1,472B를 비활성 VRAM으로 전송했다. 물리 map DMA가 끝난 뒤 ARM이 받은 E0 응답 두 개에는 진행 비트가 있었다. 두 응답의 큐 발행·반환 카운터가 일치했고 CRC, op10, epoch·serial·sequence·generation, ACK 꼬리가 유효했다. 이후 OBJ 패킷이 마지막 패킷이 되면서 E0가 가리키는 대상도 바뀌었다. ARM은 마지막 OBJ 반환 뒤 첫 팔레트를 보내기까지 조회 121회를 사용했다. 이 시점에는 이미 끝난 map 전송에서 새 진행 비트를 받을 수 없었다.

생산자 변경은 유효한 strip 반환과 물리 진행을 함께 확인했을 때만 해당 화면의 완료 비트를 기록한다. BEGIN과 cold reset에서 비트를 지운다. E는 strip이 마지막 패킷이거나 완료 이력이 있을 때 이미 확정한 팔레트를 기존 ordinary credit 경로로 보낸다. OBJ와 팔레트는 별도 목적지를 쓰며 같은 큐에서 각각 수락·반환된다. SEAL은 기존 FINAL 경로에서 모든 tile 반환을 기다리고 65816은 독립 검사와 표시 후 최종 ACK를 발행한다.

| 세대 936 | 869 위상 1 / 2 | 870E 위상 1 / 2 |
|---|---:|---:|
| 마지막 OBJ 반환을 기준으로 한 첫 팔레트 SPI 시작 | +16.22 / +16.23ms | −4.52 / −4.47ms |
| SEAL 수락 VBlank·선 | 111·204 / 113·204 | 110·156 / 111·154 |
| 공개 VBlank·선 | 113·240 / 115·240 | 111·244 / 112·244 |
| 직전 공개부터 표시 간격 | 5 / 5 VBlank | 3 / 3 VBlank |

음수는 팔레트 발행과 남은 OBJ 처리가 겹친 시간이다. 두 위상의 첫 팔레트 SPI 시작 절대 시각은 각각 452,354클록과 809,392클록 앞당겨졌다. 절대 시각에는 앞선 화면 일정 변화도 포함된다. [SPI 응답·DMA·표시 시각](../analysis/progress870-e.json)

## 대조군과 복구

A는 큐 공통 반환 함수에 완료 기억을 넣어 Flash를 12B 초과했다. B는 tile 생산자의 기존 map 반환 경로에 완료 기억을 넣었다. B에서 마지막 OBJ 뒤 팔레트 전 E0는 두 위상 모두 121→1회로 줄었지만 SEAL 수락이 해당 VBlank의 227/226선 부근에 걸려 936은 4 VBlank였다. C는 세로로 같은 행을 저장하는 이력 형식을 단순화했다. 저장 시 0부터 센 3·4·5행이 실제로 같은지 128B를 확인하고, 모양이 다르면 이력을 무효화하고 일반 map 경로로 보낸다. D는 FINAL 진입 전 한 번만 완료 여부를 판단했기 때문에 FINAL 안에서 뒤늦게 관측한 진행을 놓쳤다. [대조군의 실제 링크와 마지막 ACK](../analysis/progress870-controls.json)

검증은 고정된 dot 0 입력, 보정된 SPI 비용, CPI 2의 실제 ARM 명령, Mesen에서 실행한 정적 65816 ROM을 사용한다. 각 최종 후보에서 오프닝 62장·전환 50장·밀집 62장을 두 위상으로 재생하고 화면마다 활성 영상과 공개 후 ACK를 MMC866과 대조한다. 밀집 간격 합은 첫 두 장 이후의 60개 간격이다. 독립 검사에는 잘못된 기준 세대, 잘못된 범위, 생략 열과 전송 열의 WRAM 손상, 부분 쓰기 뒤 STOP과 양쪽 뱅크의 cold 복원을 포함했다. 메뉴 복귀는 같은 링크의 ARM 복귀 함수에서 정상 해제와 실패 시 해제 차단을 검사했다. 이 시험으로 실기 FPS를 산출하지 않는다.

ARM 단독 응답 주입에서는 정상 op10을 수락했고 CRC 오류, 다른 generation, 아직 남은 큐에 설정된 진행 비트, SEAL을 대신 반환한 경우와 STOP은 모두 거부했다. 다음 BEGIN과 cold reset은 이전 화면의 완료 비트를 지웠다. 65816 독립 검사의 범위는 869와 같다. 같은 위치의 두 WRAM 뱅크가 동시에 같은 값으로 손상되는 경우는 이 비교로 판별할 수 없다.
