# NES165 적재 길이 비교 구조 개선

165 영상 경로 진척: 적재 길이 비교와 STOP 상태 판정을 개선하는 세 후보를 검증했습니다. 전체 타이밍 개선을 확인하지 못해 채택하지 않았습니다. 선택 구현 phaseguard165/map01/reproduce01의 기존 최악 setup−0.083ns를 유지합니다. 마지막 후보 15042LE/960LAB/35M9K, 실제 클록 setup-0.410ns. 외부IO·CDC·MCU와 실기는 미완료, 설치164·세이브 SRAM 보존, 새SD 없음.

[검증 수치](../analysis/length165-verification.json) · [현재 인계](../cores/nes/HANDOFF.ko.md).

## 변경 근거와 범위

phaseguard165/map01의 적재 바이트 수→pending_counter_clear 경로는−0.083ns였고 비교4단과 명령 자격 결합2단으로 이어졌다. 새 후보는19비트 길이와24비트 offset 비교를11개의 작은 비교 묶음으로 나누고4/4/3개의 결과를 결합한다. keep 속성은 중간 조합 논리 경계를 보존한다. 새 레지스터나 클록 지연 없이 기존의 두 불일치 판정과 하나의 일치 판정을 같은 비교 결과에 연결한다. 실시간 loaded_bytes를 같은 저장 클록에서 읽으며, SPI 프레임 전송 중 적재 길이가 변할 수 있는 조건을 보존한다.

첫 후보 map01은 `keep = "true"` 표기를 사용했고, 보고서에서 기존과 같은6단/−0.083ns 경로로 나왔다. 두 번째 map02는 [Quartus 공식 예제](https://docs.altera.com/r/docs/683283/18.1/design-compilation-user-guide-quartus-prime-standard-edition/keep-combinational-node/implement-as-output-of-logic-cell?contentId=4ZtpsWy4RIS0OK2_DXmxcg)의 `keep = 1`로 두 속성만 바꿨다. 이것은 새로운 기능 지연이나 레지스터 추가가 아니다. 실제 경계 보존 여부는 배치 보고서로 확인하며 속성 문자열만으로 성공을 주장하지 않는다.

**후속 구현 규칙:** 이 Quartus Standard 환경의 Verilog 조합 논리 보존에는 공식 표기인 `(* keep = 1 *)`를 사용한다. 소스 표기만으로 적용을 단정하지 말고 MAP 보고서에서 대상 노드의 IGNORE_LCELL_BUFFERS/REMOVE_REDUNDANT_LOGIC_CELLS 설정과 배치 경로의 노드명을 확인한다. 이번 map02는11개 pair와3개 group 노드에 두 설정이off로 적용됐다. map01의문자열 표기에는 해당 설정 행이 없었다. 기존 동결 근거나 다른 속성을 일괄 변경하지 않는다.

지난 STOP 저장 레지스터 분리 후보를 재시도하지 않았다. map01/02는 SPI RTL만 바꿨다. map03은 map02에서 로더의 IDLE/READY/RECEIVE/RUN 상태 전이 중 중복 명령 충돌 판정을 상태별로 정리했다. STOP+VALID만 동시에 들어오는 경우는 충돌이 아니라는 기존 계약을 유지했다. 오류·데이터·타이머 처리 블록과 WRITE/HOLD/SETUP/RELEASE 전이는 그대로다. CHECK 요청 태그·응답 검사·ACK, 지역 리셋 해제4개 QSF 설정, 클록과SDC도 보존했다. 각 단계에서 직전 후보와60개 배치 입력이 같고, map03은 최초 기준과59개가 같다. 세 후보 모두 독립 재생성 결과와 바이트가 같다.

## 기능 검증

- 저장·처리393741조건: 전체 명령 코드/헤더 오류/주소 구역/인수 조합 및 길이 경계7개×offset의24비트 반전과 일치 조건×3명령을 확인했다. 저장 후 live length를 바꾸어도 기존 회로와 같은 처리 결과였다.
- 실제 SPI·boot·READ16 연결에서1026691클록,100읽기/7ACK/19잘못된 응답/72중단/2겹침을 통과했다. READY·적재 길이 일부를 주입한 시험이며 전체 ROM 적재·게임 실행·MCU/SNES 시험은 아니다.
- 상위 비교 묶음을 누락한 잘못된 후보가 검출됐다. map01/02의 로더는 바이트가 같은 이전 회로 근거를 재사용했다. map03의 변경된 로더는294912조건/1056연속 시나리오를 새로 통과했고, 잘못된 STOP 처리도 음성 대조군으로 검출했다.
- map02 기능 근거는 두 keep 속성만 정규화하면 실행된map01 RTL과 일치하는지 검증해 재사용했다. map02에서 새 Questa 실행을 주장하지 않는다. 배치·타이밍과 지역 리셋 해제 경로는 새로 검사했다.
- map03의 SPI는map02와 바이트가 같다. SPI 연결 시험과 새 로더 동등성 시험을 결합해 판단했으며, 변경된 두 모듈을 함께 실행하는 추가 연결 시험이나 전체 게임 실행을 했다는 뜻은 아니다.
- 새 배치의 지역 리셋 해제4레지스터, 첫 단계fanout1,12개 setup/hold 경로를 확인했다.

## 배치 결과

|항목|결과|
|---|---:|
|LE / LAB / M9K|15042 / 960 / 35|
|실제 클록 최악 setup|-0.410ns|
|실제 클록 최소 hold|+0.146ns|
|적재 길이→카운터 초기화 최소 setup|+0.444ns|
|STOP→로더 상태 최소 setup|-0.115ns|

실제4클록·3조건 setup/hold 통과 여부는 **False**다. map01(15039LE/960LAB)은 기존과 같은−0.083ns였다. map02(15029LE/963LAB)는 numeric keep 적용으로 길이 비교가5단/+0.258ns가 됐지만 STOP→state가−1.010ns로 악화됐다. map03(15042LE/960LAB)은 상태별 명령 판정으로 STOP→state를−0.115ns로 회복했고 길이 비교는+0.444ns였으나 check_failed→check_next[17]가−0.410ns로 최악이 됐다. 세 후보 모두 기존 전체 최악−0.083ns보다 좋지 않아 채택하지 않았다. 숫자 keep의 적용과 특정 경로 개선은 확인했지만 전체 타이밍 해결이나 프레임 속도 개선을 달성했다는 뜻은 아니다. map03 검사기의 설명문만 잘못 상속된 것을 수정하고 같은 결과를 재검증했으며, 수정 전 검사기·결과도 별도 보존했다. 기능 및 배치 재실행은 하지 않았다.

실제 클록과 더 엄격한 추가 배치 목표는 구분한다. 외부 입력54개/출력57개 미제약, 혼합 클록·전체 reset/CDC·MTBF 및 MCU 실행 연결은 미완료다. FIT나 내부 클록 통과만으로 전체 실기 설치·60fps를 승인하지 않는다.

## 다음 작업과 의미

선택 phaseguard165/map01을 기준으로 진행한다. 이번 numeric keep의 비교 경계 효과와 map03의 상태별 판정은 실험 근거로만 재사용한다. 다음에는 check_failed의 CHECK 카운터·상태·오류 처리 팬아웃과 START/STOP 우선순위를 함께 읽고, 명령 완료 시점과 오류 대응을 바꾸지 않는 공통 자격 신호/다음 상태 구조를 설계한 뒤 변경 경계 동등성 시험과 한 번의 배치로 평가한다. 같은 세 후보의 무변경 재배치, 이전 STOP 저장 레지스터 분리, 클록 완화·false path 추가는 반복하지 않는다. 내부 타이밍 통과 후 필요한 외부IO/CDC와 E6/version2 상태73·E5 관측70, E0/F6 수신·변환 ACK 및 사운드·입력·STOP·경과시간 MCU 연결을 마무리해 SMB3 첫 레벨 실기로 간다. 불필요한 전체 ROM 쓰기와044 복원 반복은 생략한다.

연속 화면을 위한 FPGA 조합 논리·배선 속도 개선 작업이다. 설치164의 사운드·입력·메뉴와 세이브 SRAM을 보존하며 필요한 연결 후 SMB3 첫 레벨 실기로 간다.

## 공개 도구 이름 정정

공개 전 해시 검사에서 새 시험 도구가 이전 predecode165의 `test_nes_length165.py`와 이름이 겹친 것을 검출했다. 이전 도구는 원본 바이트로 복원했고, 이번 도구는 `test_nes_balancedlength165.py`로 분리했다. 실행 당시 도구·결과·동결 manifest는 바꾸지 않았다. 새 검사기는 명시적인 이름/호출 정규화로 실행 당시 해시와 대조하며, 실제 실행한 두 시험 회로와 생성 결과가 같은지도 확인했다. 이 정정은 기능 시험이나 배치를 다시 실행했다는 뜻이 아니다.
