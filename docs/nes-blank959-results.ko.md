# 959 · 세대 906의 남은 VBlank와 다음 입력

## 목표

MMC955에서 세대 906의 SEAL을 받은 뒤 이미 열린 VBlank에 비활성 뱅크의 map을 전송할 수 있는지 확인한다. 같은 입력과 빈 캐시 두 시작 위상에서 906 공개, 906→912 여섯 표시 간격의 합, 912 최종 ACK를 비교한다. [958의 대조군](nes-ready958-results.ko.md)

## 작업내용

65816이 지금 보낼 수 있는 DMA 하나를 고르는 시점과 전체 묶음의 소요 시간을 계산한 직후를 따로 계측했다. 905부터 시작한 ARM·65816 공동 실행에서는 먼저 906 SEAL까지 대조군과 같은 시각·실행 경로를 유지하고 WRAM에서 해당 분기만 바꿨다. 별도로 실제 ROM에 들어간 후보는 압축 로더부터 부팅해 같은 입력을 실행했다. ARM 송신기는 MMC955의 SRAM 경로를 사용했다.

- 길이 한도만 384→1,920B로 넓힌 대조군은 단일 DMA 허용선을 252→240선으로 당겼다. 위상 1은 검사할 때 VBlank 전이어서 기회를 놓쳤고, 위상 2는 238선에 시작해 249선에 끝났다.
- 기존 소량 DMA 조건을 보존한 후보는 묶음 계산 직후 빔 위치와 STOP을 다시 읽고, 240선까지 승인된 map 하나만 추가로 허용했다. 같은 SEAL에서 위상 1은 227→239선, 위상 2는 240→252선에 1,920B 전송을 끝냈다. 압축 본문 4,871B, 로더 209B, 벡터 64B로 총 5,144B였다.
- 분기를 재사용한 정적 ROM 후보는 같은 계산 뒤 기존 단일 DMA 검사로 돌아간다. 총 5,117/5,120B다. 두 위상에서 952 보드 RTL의 E8 응답을 실제 ARM 코드에 되먹여 다시 실행하고 일곱 번째 E9의 75B 본문과 수락을 확인했다.

## 성과

각 셀은 **위상 1 / 위상 2** 순서다. 최종 ACK 변화는 같은 위상의 MMC955 ARM·65816과 906의 RTL 응답을 반영한 958 대조군 대비이며, 음수가 빠르다.

| 후보 | 906 공개 VBlank 번호 | 여섯 표시 간격 합 (VBlank) | 912 최종 ACK 변화 (ms) | 911 공개 전 912 입력 D2 반환 수 |
|---|---:|---:|---:|---:|
| MMC955 대조군 | 35 / 36 | 14 / 15 | 기준 | 17 / 0 |
| 길이 한도 변경 | 35 / 35 | 15 / 15 | +17.009 / −16.626 | 0 / 0 |
| 기존 소량 경로 + 두 번째 검사, 동일 SEAL에서 실행 | 34 / 35 | 14 / 14 | −16.644 / −33.633 | 17 / 17 |
| 분기 재사용, 동일 SEAL에서 실행 | 34 / 35 | 15 / 15 | +0.377 / −16.608 | 0 / 0 |
| 분기 재사용, 정적 ROM 부팅·906 RTL 응답 반영 | 34 / 35 | 15 / 15 | +0.364 / −16.608 | 0 / 0 |

정적 ROM은 906의 1,920B를 228→240선과 240→252선에 끝냈고 두 화면 모두 255선에 공개했다. 246선 검사는 마지막 업로드를 *시작*할 때 적용한다. 이 후보에서 911 SEAL 수락은 171선·170선이었고 다음 입력의 D2는 공개 전에 하나도 돌아오지 않았다. 기존 소량 DMA를 보존한 경우에는 10선·14선에 수락해 17개가 모두 돌아왔다. 앞쪽 화면이 한 번 일찍 떠도 후속 입력 여유를 잃으면 마지막 ACK까지 이득이 이어지지 않았다. [위상별 SPI·DMA·공개·ACK 측정값](../analysis/blank959-results.json)

각 대조는 세대 905–912의 RGB 8장과 VRAM DMA 22,512B를 확인했다. 화면이 켜진 뒤 각 SEAL의 DMA 첫 쓰기와 마지막 쓰기가 같은 VBlank 안에 있었다. 두 후보·두 위상에 각각 세 가지 오류를 주입했다. DMA 선택 직전 STOP은 전송 0B, 마지막 바이트에서 들어온 STOP은 진행 중인 1,920B만 완료했다. 두 경우 모두 906 공개·최종 ACK 없이 905 화면이 유지됐다. 잘못된 SEAL identity도 거부했다. MMC955 ARM의 메뉴 복귀 경로와 base 재설정은 재생에서 확인했다.

RTL 응답 대조 범위는 905를 거쳐 도달한 **906**이다. 906의 최종 E8 비교는 위상별 173회·172회 모두 일치했다. 905 자체는 129회 중 60회, 161회 중 59회에서 모델과 RTL의 E8 상태가 달랐다. 여섯 간격은 빈 캐시 재생 결과다. 실기 기준과 60초 FPS는 MMC955 측정값을 사용한다.

## 후속작업

960에서 기존 소량 DMA 경로를 그대로 정적 ROM에 넣고, 17블록 선행 수신과 두 위상의 최종 ACK를 재검증했다. [960 정적 부팅·전체 보드 결과](nes-blank960-results.ko.md)

기존 소량 DMA 허용 및 911 공개 전 17블록 수신을 보존하는 후보에서 압축 ROM을 **24B 이상** 줄인다. 전체 ROM을 부팅한 뒤 두 위상의 906 선행 전송, 911 입력, 여섯 표시 간격, 912 최종 ACK를 다시 측정한다. 위상별 결과가 함께 개선되는지 확인한 뒤 실기 전달 여부를 결정한다.

재현은 958과 같은 두 위상의 자료에서 `tools/nes_blank959.py prepare TEMP`로 시작한다. `--retry ordered`는 정적 ROM 생성과 `static` 실행에 사용하고, `seal`은 옵션 없음·`--retry`·`--retry ordered` 세 가지로 비교한다. 정적 ROM의 `static → credit → closed` 단계마다 두 ARM 재생 뒤 기존 FLOAT 래퍼로 `tools/check_nes_ready958.ps1`을 실행한다. `NES_959_RTL`은 각각 `959orderedstatic`, `959orderedcredit`, `959orderedclosed`이고 `NES_958_RTL`은 각각 `closed`, `credit`, `closed`다. `tools/check_nes_blank959.py TEMP --phase N --guard before|after|identity`를 각 위상과 두 후보(`--retry` 유무)에서 실행한 후 같은 스크립트를 `TEMP`만 주어 집계한다.
