# 713 두 페이지 행 완료·map/tile 공동 발행의 실제 ARM 검증

## 목표

707D·기존65816을 유지하고712의 두 페이지 행 완료와 공동 발행을 실제 ARM에 연결한다. 교체1,116B·추가RAM4B 이내에서 독립 검사·STOP·최종ACK·메뉴와 기존 표시 조건을 유지하며,두 위상의951 이후 연속 표시와957 마지막ACK가 함께 개선되는지 판정한다. [검증 JSON](../analysis/rows713-verification.json) · [보관 근거](../analysis/rows713-archive.json)

## 작업내용

**A:** 기존 `nes_sink527_early`를 삭제했다. planner는 공통 행 완료 지점에서 완료한 논리행 수를 공개하고,`map527`이 두 물리 페이지의 cursor와 완료 한도 안에서 최대192B를 선택한다. 기존 E8/E9·tile receipt·4credit·STOP 검사와 `drive554`/`nes_plan200_progress`를 재사용하며,기존 quiet callback을 END 이전의 확정 행에도 연결했다. 새 wire ABI·packet buffer·collector 재읽기·FPGA 상태는 없다. 이미 발행한 바이트의 후속 변경과 중복 발행을 실제 ARM 메모리/함수 hook으로 차단했다.

**B:** A의952 회귀를 추적한 뒤 첫 새 BG plan이 실제 발행된 `plan.early`까지 map 선행을 보류했다. 모든 BG 행이 완료되면 새 BG가 없는 화면도 진행한다. 세대 번호·시작 위상·고정 시간에 따른 분기는 없다. 정상60초판과 장시간판을 각각 원본에서 생성해 전체 링크했다. 정상판의60초 종료·장시간판의종료/정지시계 보호는 그대로다.

실제 ARM/65816,동일 시작 시각 두 위상,CPI2/84MHz·SPI2.625Mbps·실측 driver 배분·IRQ·credit·2bulk·반복 ROM 허용 달력을 실행했다. A는106화면,B는 위상2의53화면을 끝까지 통과했고,B 위상1은918 검사에서 중단됐다. 실제 게임 NES/PSRAM 전체 RTL 공동 시뮬레이션이나 실기 FPS가 아니다.

### B 위상1의 독립 주사선 검사

겉으로는 pipe 종료 예외였지만 원인은 기존 CPU 시험의 주사선 assertion이다. 조건을 그대로 두고 값만 추가한905–918 재현에서 **packet 기록과 CPU 사건 CSV가 원실패와 SHA256까지 같다.**

```text
g=918 saved=253/0/69 current=254/198/69 elapsed=1562 bytes=448 length=448
```

`$2137` 관측 시점253선·h0에서 허용 상한252선을 벗어났고,448B DMA 요청은254선·h198에서 발생했다. 이 기록만으로 VBlank 밖 VRAM 쓰기나 실기 타일 깨짐의 원인이라고 단정하지 않는다. 정확한 latch 값/주사선 경계의 관계는 추가 확인 대상이다. 그러나 **현재 요구한 독립 판정은 실패**했으므로 상한을253으로 늘리거나 검사를 끄고 성능을 집계하지 않았다.917까지만 완료했으며951 이후/957ACK는 추정하지 않는다.

### 안전·기존 보드 경계

A/B 각각 실제 링크 ARM의9개 frontier/credit/준비된tile/CRC/STOP/모호한E1/reset/전체4096B 복구 검사와16개 long-session·사용자 종료·최종ACK 분리 검사를 통과했다. B는 첫BG 이전 차단/이후 허가/새BG없는완료화면7조건도 별도 확인했다(이 검사는 map 실행기를 계수 stub으로 대체하며 전송 검사는 별도9조건에서 실행). 정상·오류 메뉴 준비/해제5조건씩을 실행했다. 새 패킷 순서를 이용한65816 STOP4조건·사용자 종료2조건씩에서 이전 표시 보존과 종료 후 DMA/ACK 중단을 확인했다. base 복구5조건은A 실제 링크에서 실행했고,B는 같은 변경 없는 cleanup 소스를 승계한다. 실물 메뉴 복귀를 새로 확인한 것은 아니다.

707D RTL·SDC·65816 이미지가 같아 전체 FIT/STA는 기존15,322LE·962LAB·56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계한다. 새 합성은 하지 않았다. 외부IO 전체 sign-off와707D 배경CHR 실기 확인은 계속 미완료다. B의 통합 주사선 실패를 단위 안전 검사 통과로 덮지 않는다.

## 후속작업

두 후보와 모든 실패를 보존하고 제품에는 채택하지 않는다. **행이 완성됐다는 사실만으로 SPI를 쓰게 하는 정책,첫BG 한 개만 기다리는 정책은 이번 근거로 보류한다.** 같은3행 주기·페이지 교대·고정 지연 변형을 반복하지 않는다.

다음 경계는952/954에서 **필요한 BG plan 묶음이 발행되고 실제 ROM 공급을 시작할 때까지의 생산 경로와,이미 수락한 map의 DMA 연속 범위**다. 새 발행을 넣기 전에 이 두 마감이 보존되는 비용을 함께 지급해야 한다. B의918 관측 경계는 별도 최소 재현으로 latch 값과 실제 완료선을 분리하되 기존65816/검사 조건을 임의로 완화하지 않는다. 이후 후보도 두 위상에서911/951/952/957·7블록·STOP·독립검사·최종ACK를 유지하면서952–957 합계18VBlank와밀집평균·957ACK를 모두 줄여야 한다.

재현은 `prepare_nes_rows713.py`로694/704 각각에서 patch를 만들고 `build_nes_mmc479_arm.ps1`로 전체 링크한다. `--first-bg`가B다. 실제 재생은 `test_nes_rows713.py`,B 실패의 같은 시각 진단은 `diagnose_nes_rows713.py`이며 원래707D 인자/시작7288416·7467100을 사용한다. 보관 `probe/replay.ps1`·`replayb.ps1`·`diagnose.ps1`에 전체 명령이 있다. `analyze_nes_rows713.py`와`finalize_nes_rows713.py`가 비용·판정을 재생성한다. 원본 게임 ROM·라이선스는 Git/근거ZIP에 넣지 않는다. 새 설치본·RESTORE는 만들지 않는다.
