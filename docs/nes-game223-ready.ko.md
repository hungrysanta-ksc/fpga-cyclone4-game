# NES223 geometry 전송 개선 실기 시험

223의 배경 묶음 전송과224 단계의 로더 타이밍 수정을 함께 넣은 시험판이다. 파일 이름과 로그 번호는 **223**이다. 기존222와 섞어 설치하지 않는다. 최종 ZIP은 `release01/result.json`의 모든 gate를 통과한 경우에만 생성된다.

## 설치와 실행

1. 본체 전원을 끄고 ZIP의 `01-GAME223-SD-ROOT` 내용물을 SD 루트에 복사한다. `firmware.stm`과 `fpga_n223.bi3`를 반드시 함께 교체한다. 폴더 자체를 루트 아래에 넣는 것이 아니라 그 안의 내용을 복사한다.
2. `NES GAME 223.nh1`을 실행한다. ROM은 기존과 같은 Super Mario Bros 3 (J)다. 이번 변경은 게임 중 화면 자료 전송량을 줄이며 초기 ROM 로딩 시간 단축을 목표로 하지 않는다.
3. 첫 레벨 숫자1 타일에서 A로 진입한다. 오른쪽+B를 유지하고 A를 반복해 스크롤한다. 적이나 장애물 때문에 연속 플레이가 어렵다면 가능한 구간만 시도한다.
4. 실제 게임 실행 구간은 기존처럼 약60초 후 메뉴로 돌아오는 설정이다. 소리·조작·메뉴 복귀와 첫 레벨 스크롤 개선 여부를 확인한다. 메뉴 복귀 전에는 SD를 빼지 않는다.
5. 전원을 끈 뒤 아래3파일을 전달한다. 이전 파일이 있으면 시험 전 별도로 보관해 이번 결과와 섞이지 않게 한다.

- `nes-progress-223.txt`
- `nes-game-last-223.txt`
- `nes-budget-223.txt`

영상은 첫 레벨 스크롤과 시간 대응이 필요할 때 도움이 되지만 이번 시험의 필수 조건은 아니다. 정상044/164 복원 반복 시험은 요구하지 않는다. 기존과 다른 멈춤이 있다면 멈춘 장면과 소리·조작 지속 여부를 함께 알려주면 된다.

## 판단 범위

합성 geometry 부하에서 payload가6780→3612B로 감소했으나 실제 SMB3 화면 전체의 압축률이나60fps를 보장하는 수치는 아니다. 첫 레벨 스크롤에서 표시 완료 수·receive/plan/seal 시간·D1 payload 변화와 체감을 함께 확인한다. 서로 다른 플레이 결과를 통제된 FPS 비교로 부르지 않는다.

입력·사운드·시작222·인덱스221·60초 제한과 저장SRAM 사용 정책은 그대로다. `02-RESTORE164-SD-ROOT`는 필요할 때 쓰는 이전 복원본이며, 이번 시험을 위해 복원 시험을 반복할 필요는 없다. 미래 scroll-aware map 개선과 전체16.67ms 예산 검증은 계속 남아 있다.
