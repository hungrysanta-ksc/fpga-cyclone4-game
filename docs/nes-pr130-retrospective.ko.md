# PR130 회고 — NES256–298

2026-10-22. 구현 기준 c0a68362e3c6fa1cb3d336bc69c4445e0ebdb3ca, PR 시작 master 2978f04aef65987c615d62ca54576e68fc946637.
이 회고는 기존 증거를 재계산한다. 새 RTL·ARM·65816 실행이나 합성이 아니다.

## 판단

ARM 계획 / FPGA 해석·독립 검사 / SNES DMA·표시라는 역할 분담은 유효한 작업 가설이다. 실제 producer와 소비 완료를 연결하며 얻은 전송·메모리 절감은 보존할 가치가 있다. 그러나 이 구성이 현재 보드에서 60fps로 동작한다는 결론은 아직 없다. PR130은 **통합 검증과 비용 발견의 성과가 크지만, 시간과 회로를 동시에 해결한 제품 구현은 아니다.**

후반의 작은 FSM·cursor·완료 중계 통합은 중단하고 데이터 표현, 해석 횟수, 주소 선택, ROM 공급 일정을 함께 비교해야 한다. 독립 검사를 없애는 것은 해결안이 아니다. 공통 실행기298은 실제로 구현했으나 host에서 없앤 회로 대부분이 validator와 선택 제어로 옮겨졌다.

## 검증에서 전진한 부분과 남은 부분

시작256의 packet→staging→DMA→receipt→최종ACK 경계는257 이후 실제65816 slice, 일반/typed 중재, 4credit, token/bank 재사용, 공유 RAM, STOP 및 최종 표시 ACK로 구체화됐다. ARM serializer에 이어 native planner·일반 명령·manifest 생산과 IRQ/ROM 경쟁도 연결했다. 최신298은 새6개 live 일정과42개 RTL 오류 검사를 통과했고, 동일 ARM ELF의 native71 등은 재사용임을 명시했다.

다만 **native71 producer 성공과 최종 통합 일정71프레임 성공은 다르다.** 최신 경로의 heavy7/전체71 일정, 전체 live65816, fullRUN·실제 MCU 사이클/WCET, 최종 보드 glue/CDC/IO/FIT/STA, 실물 지속 스크롤·음향·입력은 미완료다. PR129의 조건부15.996ms와 최신17.468ms는 포함 비용이 달라 순수 회귀 비교가 아니다. R0 완료, R1 부분 완료, R2/R3 미완료로 평가한다.

## 수정할 개발 방식

1. 목표를 ‘다음 제어를 합치기’에서 **현재 전체2275comb와 제한907 최소0.802ms를 동시에 해소할 구조의 근거 확보**로 바꾼다. host+validator3427만으로 해결하려면1152 이하, 고정 출력 경계4837만으로 해결하려면2562 이하가 필요하다. 각각66.4%/47.0% 감소여서20개 단위 미세 통합은 충분하지 않다.
2. 먼저 protocol·descriptor·manifest를 몇 번 해석하는지, 압축 cursor와 확장 cursor가 언제 동시에 필요한지, RAM 포트/CDC/CRC 관측이 실제로 어떤 mux를 요구하는지 표로 고정한다. 유지할 검사와 지울 제어, 새 제어를 모두 예산에 넣는다. ARM 이동도 SPI·SRAM·실행 비용을 함께 계산한다.
3. 정상/제한 ROM 위상을 고정한289·297·298 비교 기준을 유지한다. 개선 프레임 하나나 직전 실패 후보만 기준으로 삼지 않는다. ROM 창 경계 민감도와 초기 채움 정책도 함께 다룬다.
4. 구조 후보가 목표 규모의 절감 근거를 못 내면 FSM/seed/FIT 반복을 하지 않는다. 역할 분담 자체, 출력 표현 또는 대상 하드웨어의 적합성을 재검토한다. 하드웨어 변경·구매를 자동 실행하지 않는다.
5. 근거가 선 후보만 동일 입력 live3→heavy7/71→전체CPU/fullRUN→matching whole FIT/STA→실물로 확장한다. 매 단계에서 새 실행과 재사용 증거를 구분한다.

PR130은 회고 전43커밋/498파일로 커졌다. 최신 단계만 설명하는 PR 본문을 전체 성과·회귀·미해결 게이트로 교체한다. 실험 기록과 실패는 보존하되 production227/GBC164/saveSRAM 승격은 하지 않는다. 이번 작업은 문서·증거 정리로 마무리하며 자동 merge하지 않는다. 다음 구체 목표와 중단 조건은 [후속 계획](nes-pr130-next-plan.json)에 둔다.
