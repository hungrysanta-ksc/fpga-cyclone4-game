# NES227 실기 시험: 스프라이트 반복 데이터 전송 감소

226에서 스크롤 개선이 확인됐지만 수신·전송 비용이 크게 남았다. 227은 스프라이트 목록(OAM)의 끝부분에 동일한4바이트 패턴이 반복될 때 그 패턴과 길이만 보내고 SNES에서 원래 내용 전체를 복원한다. 숨겨진 스프라이트가 많을 때 특히 적용된다. 모든 바이트를 비교한 뒤 사용하므로 스프라이트를 생략하거나 FPS를 낮추는 변경은 아니다.

## 설치와 실행

1. 전원을 끄고 ZIP의 **01-GAME227-SD-ROOT 안의 내용**을 SD 루트에 복사한다.
2. 이번 **firmware.stm과 fpga_n227.bi3를 함께 사용**한다. FPGA 배선은 같지만 내부 SNES 소비기 ROM이 바뀌었으므로226 파일과 섞지 않는다.
3. 메뉴에서 **NES GAME 227.nh1** 실행 → 플레이어 선택 → 월드맵 숫자1 타일에서 A로 첫 레벨 진입.
4. 오른쪽+B를 유지하면서 A를 반복해 스크롤한다. 적·마리오가 정상으로 보이는지, 스크롤 끊김·소리·조작을 확인한다. 약60초 후 메뉴 복귀도 확인한다.

## 전달할 결과

- nes-progress-227.txt
- nes-game-last-227.txt
- nes-budget-227.txt
- 가능하면 첫 게임 화면부터 메뉴 복귀까지 영상. 스크롤 구간 체감과 소리·조작·메뉴 상태.

budget_schema=226은 같은23필드 형식을 유지한다는 의미다. 파일명이227이면 정상이다. 로딩 경로와60초 제한은 기존과 같다. 같은226/044 재시험은 필요하지 않으며 복원 폴더는 필요할 때만 사용한다.

## 예상 범위

동일한 합성30프레임에서 메타데이터 패킷 바이트가104753→88733(-15.29%), 그중 스크롤16프레임은58768→50288(-14.43%)였다. 이는 전체전송량이나 실기 FPS 개선율이 아니다. 실제65816 복원 뒤 모든 OAM544바이트와 기준 화면1835520픽셀이 같았으며 새영역RAM은 사용하지 않는다.

반복 복원 자체의 SNES 처리 비용도 있으므로 실기에서 순효과를 확인해야 한다. 이번만으로60fps에 도달한다고 예상하지 않는다. 실제 개선이 없으면 반복 압축을 계속 확장하기보다 남은 수신·메타데이터·타일 완료 경로를 우선한다.
