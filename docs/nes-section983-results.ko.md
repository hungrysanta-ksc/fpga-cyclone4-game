# 911의 section 5 확정·발행·raw 선행 DMA 기회

## 목표

978 returned에서 201B와 240B의 ARM 원본 확정, 패킷 조립, 발행, 65816 수락을 분리한다. 첫 패킷에 담긴 raw 192B가 직전 VBlank에 실제로 소비 가능한지 확인하고, 마지막 패킷을 먼저 보냈을 때 SEAL·공개·912 최종 ACK까지 앞당겨지는지 판정한다.

## 작업내용

같은 905–912 무입력 캡처로 위상별 ARM 전체 링크와 65816을 연속 실행했다. ARM 원본의 마지막 쓰기는 한 행의 CHR 32타일 × 3개 평면 쌍 × 2B, 테이블의 앞 9B·뒤 234B, 길이 6B를 각각 추적했다. SEAL 생산 함수 진입 때 재구성한 441B는 실제 SPI payload와 일치했다. 계측을 켜도 978의 ARM 이벤트·생산 기록·65816 일정·입력 레코드는 두 위상 모두 바이트 단위로 일치했다.

후보는 한 행이고 스크롤·패딩이 이미 발행됐으며 OAM 재사용이 아닌 경우에 적용했다. 첫 후보는 팔레트 뒤 201B→OAM→240B, 두 번째는 팔레트 뒤 201B→240B→OAM 순서다. 원래 순서는 팔레트 뒤 OAM→201B→240B다. 65816 ROM과 FPGA는 공통이다. ARM·65816은 실행했고 SPI·IRQ·ROM 경쟁은 기존 모델을 사용했다.

## 성과

### 978의 준비 시간과 공유 SPI

|---|---:|---:|
| 201B 원본 확정 → 발행 | 4.199 | 4.324 |
| 그중 선행 E1 / E0 / E8 점유 | 2.160 / 0.765 / 0.328 | 2.160 / 0.874 / 0.328 |
| SPI 밖에서 경과한 시간 | 0.946 | 0.962 |
| 240B 원본 확정 → 발행 | 5.093 | 5.217 |
| 그중 선행 E1 / E0 / E8 점유 | 2.881 / 0.874 / 0.328 | 2.881 / 0.983 / 0.328 |
| SPI 밖에서 경과한 시간 | 1.010 | 1.026 |

위 두 구간은 서로 겹친다. 최종 송신 버퍼의 마지막 쓰기부터 발행까지는 201B가 0.055ms, 240B가 0.958ms였다. 첫 패킷의 실제 SPI 거래만 0.720ms를 차지했다. 원본이 준비된 뒤에도 선행 패킷과 조회가 공유 버스를 사용하고 있었다.

### 발행 순서와 공개

표는 978 대비 부팅부터 잰 절대 시각 변화다. 앞 값이 위상 1, 뒤 값이 위상 2이며 음수가 단축이다. 수락은 65816의 패킷 로드, 반환은 복원·수신 처리가 끝난 ACK다.

| 변경 | 201B 수락 (ms) | 240B 반환 (ms) | SEAL 진입 (ms) | 909 선행 DMA (B) | 밀집 여섯 간격 | 912 최종 ACK (ms) |
|---|---:|---:|---:|---:|---:|---:|
| 978 | 기준 | 기준 | 기준 | 624 / 624 | 13 / 13 | 기준 |
| 201B만 OAM 앞으로 | −2.111 / −2.360 | +0.446 / +0.202 | +0.255 / +0.204 | 592 / 592 | 13 / 13 | +0.004 / +0.024 |
| 201B·240B 모두 OAM 앞으로 | +8.124 / −2.293 | +8.641 / −1.772 | +12.110 / +1.760 | 464 / 464 | 14 / 13 | +17.005 / +0.008 |

두 패킷을 옮긴 위상 2에서는 240B 반환을 **1.772ms** 당겨도 뒤에 남은 OAM이 공개를 막았다. 위상 1은 910 캡처를 0.035ms 놓쳐 911 자체의 공급이 늦어졌다. 세 실행 모두 911은 VBlank 45에 공개됐고 직전 표시부터의 간격은 2회였다.

### raw 192B의 사용 가능 시각

같은 65816 ROM을 다시 재생해 두 패킷 반환 시 대상 뱅크와 표시 뱅크가 다름을 확인하고, 실제 WRAM에서 201B·240B 전부를 패킷 원본과 대조했다. 이후 246선 마감까지 새 패킷이 없을 때의 실제 큐 조회를 기록했다.

- 978 위상 1에서는 235선에 한 번, 다음 패킷 도착까지 735클록이 남은 조회가 있었다. DMA 설정·STOP 검사 비용을 0으로 두고 새 패킷 도착 전 시작한 64B DMA가 끝까지 실행된다고 해도 최대 128B다. 위상 2에서는 가능한 조회가 없었다.
- 201B를 OAM 앞으로 옮기자 데이터를 일찍 수락했지만 **두 위상 모두 목표 VBlank에 빈 큐 조회가 0회**였다. 두 패킷을 함께 옮긴 후보도 같았다. 세 실행 모두 기존 ROM은 SEAL 뒤 raw 64B 세 번을 수행했다. 128B는 고정 일정에서의 낙관적 상한이며 실제 선행 전송량은 0B다.

각 후보는 Flash 213,044B로 한도를 52B 초과했다. 두 위상에서 여덟 RGB 화면과 map 값·plan 레코드를 대조했다. 두 후보 모두 STOP·불량 SEAL 주입에서 각각 0xE4·0xE0로 종료하고 910 화면을 보존했다. 링크된 ARM 메뉴 복귀 분기도 확인했다. 실기 기준 MMC966과 개발 기준 978을 유지한다.

## 후속작업

같은 순서 변경을 반복하기보다 이 장면에서 실제로 버스를 차지한 두 거래를 한 번으로 줄일 수 있는지 시험한다. 911의 raw 세 평면은 각각 하나의 16비트 값이 32번 반복됐다. 길이 81B인 HDMA 테이블 셋은 각각 21B만 사용했다. 길이 6B, raw 대표값 6B, 테이블 63B로 총 75B를 만든 뒤 원래 441B로 복원해 일치함을 확인했다. 현행 19B 거래 오버헤드를 가정하면 479→94B이고 2.625MHz에서 선로 시간 약 1.173ms를 줄일 수 있다. 이는 911 표본의 소프트웨어 왕복 검사와 전송 예산이다.

실제 후보에서는 ARM이 반복 패턴·테이블 패딩을 확인하고, 조건이 어긋나면 원래 두 패킷으로 복구해야 한다. 65816의 WRAM 복원·독립 검사·credit 반환까지 비용에 포함한다. 기존 982에서 구한 마감과 909 선행 624B·910 캡처를 모두 대조한 뒤 채택 여부를 정한다. [클록·패킷·복구 검사 결과](../analysis/section983-results.json)
