# 118 — 동일116 펌웨어의 전체80KiB 복구 시험

116의 짧은 복구 시험은 메뉴 복귀까지 성공했다. 이번에는 같은 펌웨어로 적재·전체 읽기 비교 뒤에도 복구되는지 확인한다. 패키지 번호는118, 펌웨어는116, 실행 표식 이름은094를 유지한다. 새 펌웨어 빌드는 없다.

## 실행 순서

1. 기존 `nes-progress-116.txt`와 `nes-verify-last-094.txt`를 PC에 보관한다. 새 실행이 같은 이름의 로그를 덮어쓴다. 이전 최종094 로그를 새 결과로 오인하지 않도록, 보관한 뒤 SD의 기존 최종094 파일만 삭제한다. SD를 포맷하지 않는다.
2. 전원이 꺼진 상태에서 `01-FULL80-SD-ROOT` 안 내용을 SD 루트에 덮어쓴다. 동일116 펌웨어·FPGA·메뉴와 정확한 자체 시험 데이터 `sd2snes/nes/fine_x.nes`가 들어 있다. 이 파일은 상용 게임이 아니다.
3. 메뉴에서 **`NES VERIFY 094 80.nh1`을 한 번 실행**한다. 0바이트 표식이 정상이다. `NES BASE 116.nh1`, ENTRY113, 96KiB 표식, fine_x.nes 자체를 실행하지 않는다.
4. 이전 전체80KiB 실측은 적재 약196초, 비교·STOP까지 약487초였다. 로딩 화면이 계속될 수 있다. **표식 선택 후 최대10분(600초)**까지 관찰하고, 메뉴가 돌아오면 추가 시험 없이 전원을 끈다. 10분에도 복귀하지 않으면 전원을 끈다. 리셋 버튼이나 반복 실행은 사용하지 않는다. 이는 관측 한도이며 완료 시간 보장이 아니다.
5. `/sd2snes/nes-progress-116.txt`와 새 `/sd2snes/nes-verify-last-094.txt`를 전달하고 메뉴 복귀 여부를 알려준다. 파일이 없거나0바이트여도 그 결과를 그대로 전달한다. 영상은 필요 없다.
6. 정상 사용 전 `02-RESTORE044-SD-ROOT` 내용을 SD 루트에 덮어써서044로 복원한다. 이번 복원 결과도 실제 확인한 범위만 알려준다.

## 확인할 결과

진행 로그는 OPEN_INPUT/VALIDATE/LOAD/CHECK → STOP_DONE → BASE_FILE_OPENED/STREAM_END/DONE_HIGH/TOKEN_RESULT/BASE_DONE → MENU_PREPARED 순서를 기대한다. 이번에는 `loaded_bytes=81920`, `compared_bytes=81920`, `verified=1`, `end_accepted=1`, `stop_ok=1`, `base_restored=1`, `safe_to_reload=1`, 오류0이 전체 성공 조건이다. `start_sent=0`을 유지한다.

짧은 BASE 시험의 `verified=0`은 정상이었지만 이번 전체 시험에서는 성공이 아니다. `menu_state=PREPARED_RESET_HELD`는 화면 복귀 전에 저장하는 값이므로 실제 메뉴 복귀 여부를 별도로 확인한다. 보고서에는 실행 고유번호가 없어 이전 파일 보관·구분이 필요하다.

## 다음 판단

전체 경로가 성공하면 제한80KiB 진단의 통합 복구를 통과로 기록한다. 실패하면 새 기본FPGA 세부 기록으로 마지막 완료 지점을 좁힌다. 공유고장 뒤에는 추가SD 기록을 강행하지 않으므로 마지막 줄이 정확한 고장 명령이라고 단정하지 않는다.

이번 시험은 NES 게임 실행이나384KiB SMB3/mapper4 지원 시험이 아니다. 기존113 실패의 원인이 수정됐다는 가정도 하지 않는다. E1/E2 전기·공통원인 조건과8µs 보장 미완료 상태는 유지한다.
