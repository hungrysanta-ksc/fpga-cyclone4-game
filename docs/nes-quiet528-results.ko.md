# 528. END 대기 중 후속 map 공급과 246번 표시 검사선

## 구현과 검증 조건

527의 행 확정 ARM과 526의 254번 주사선 소비기를 대조군으로 삼았다. 첫 map 패킷은 기존 위치에서 발행한다. 528은 resident 준비가 성공한 뒤 최종 plan 묶음과 END를 비우는 동안에만 후속 행을 공급한다. E8 응답의 CRC·개수·descriptor 검사와 bulk 처리를 마친 뒤, E9를 발행할 수 있으면 E9를 먼저 보낸다. 둘 다 대기 중이고 기존 네 개 큐 슬롯 중 점유가 두 개 이하일 때만 다음 확정 map 패킷 하나를 보낸다. 별도 E8 조회는 추가하지 않는다.

기존 DATA/RLE, 최대 세 행 묶음, 65816의 64B DMA를 사용한다. enqueue에 성공해야 커서를 옮기고, END 수락 후에는 나머지만 SEAL에서 보낸다. STOP, 응답 오류나 전송 결과가 불명확한 경우에는 화면 처리를 중단한다. [후보 생성기](../tools/prepare_nes_quiet528.py)

두 위상의 905–957 연속 일정에서 링크된 Cortex-M4와 Mesen의 65816을 실행했다. ARM CPI 2, 2.625MHz 공유 SPI, 기록된 전송 비용·ROM 허용 구간과 SysTick 모델은 527과 같다. 보드의 60초 실측은 MMC524가 최신이다. [실기 결과](nes-hardware525-results.ko.md)

## SEAL에서 기다리는 비용

각 DMA 시작과 마지막 PPU 쓰기, 최종 표시 여부를 판단하는 실제 $2137 읽기에서 마스터클록과 빔 좌표를 기록했다. 246번 행 끝까지 현재 VBlank를 재사용할 수 있으므로, 아래 지연은 **247번 행 시작부터 실제 빔 읽기까지**의 클록이다. 240번 짧은 주사선까지 반영해 DMA 사이의 경과 클록을 대조했다.

|---|---|---|---:|---:|
| 952 | 384→1,152B / 384→1,152B | 64 + 512 + 768 + 384 = 1,728B | 6,796 / 7,098클록 | 6,106 / 5,594클록 |
| 954 | 320→384B / 384→384B | 176 + 384 + 1,536 + 384 = 2,480B | 8,226 / 7,860클록 | 7,898 / 7,536클록 |

두 위상 모두 53화면 중 6화면에서 END 수락 전 후속 map 18패킷을 보냈다. 952는 5패킷(실제 E1 1,055B), 954는 3패킷(377B)이었다. 952의 SEAL은 640B 줄었지만 BG·OBJ 전송이 잘게 남아 최종 표시 전 DMA 명령이 11→14개로 늘었다. 첫 위상의 첫 DMA 시작부터 빔 검사까지, DMA 시작→마지막 쓰기의 합은 19,826→14,664클록, 각 마지막 쓰기→다음 DMA 또는 빔 검사의 합은 15,596→19,798클록이었다. 954에서는 선행 map이 늘어도 BG 잔량이 늘어 SEAL의 전송량이 2,384/2,320→2,480B가 됐다.

두 화면의 마지막 여섯 명령은 raw 그래픽의 하위 비트플레인을 복원하는 64B strided DMA였다. 이 여섯 명령의 첫 시작부터 빔 검사까지 약 11,000클록이 걸렸다. 동일 뱅크의 두 화면 전 최종 표시와 바이트를 대조하면 여섯 블록 중 세 블록이 그대로였고 952는 4B, 954는 5B가 달랐다. 이 비교는 캡처 분석이다. 528의 독립 검사·DMA 비용에는 여섯 명령이 모두 포함됐다.

527 대비 952는 두 위상 모두 9→8 VBlank(133.128 / 133.112ms), 954는 8→7 VBlank(115.236 / 115.256ms)였다. 957의 ACK도 66.549/66.541ms 빨랐다. 각 표시의 SEAL 전체 대기 2회와 최종 표시 대기 1회는 남았다. 954의 입력 시작 기준 마지막 OBJ ROM 응답은 0.027/0.191ms 늦었다. 528의 SPI는 529,574/527,894B, SysTick은 499/496회, ROM 배정은 5,616회, 최대 bulk 점유는 2슬롯이었다.

**후속작업.** 두 위상에서 얻은 연속 표시 개선을 실기로 비교할 수 있도록 528의 ARM Flash 500B를 회수하는 작업을 먼저 한다. 크기를 줄인 바이너리로 두 일정을 다시 실행하고, 통과하면 MMC524와 같은 동선의 1–40초·40–60초와 메뉴 복귀를 확인한다. 246번 대기 해소는 별도 목표다. 다음 후보는 SEAL 앞의 비활성 뱅크 raw DMA와 작은 tile 명령을 대상으로 하고, raw 이력 유효성·수신 완료·STOP 검사를 포함해 5,594–7,898클록을 회수할 수 있는지 측정한다.

## 비용과 안전성

공유 FPGA와 65816 이미지는 527과 같다. 보드 SOF를 해시로 대조했으며 기존 Quartus Lite 전체 비용은 15,164 LE, 51 M9K, 관련 setup +0.078ns·hold +0.139ns다. ARM Flash는 213,380→213,492B로 112B 늘어 한도를 500B 초과했고 BSS는 18,588→18,592B다.

링크된 ARM에서 후속 행 진행, 빈 마스크, E9 우선, 16비트 랩에서 큐 3건 양보, bulk 우선, 잘못된 E8 CRC, E8 뒤 STOP, 후속 map 발행 뒤 STOP, E1 응답 불명확을 검증했다. 기존 40개 응답 회귀도 통과했다. 두 후보의 패킷 내용·개수, 뱅크별 map 발행 순서, tile 내용, VRAM DMA 총량과 53개 RGB를 대조했다. 두 위상 각각에서 도착한 패킷만으로 65816을 독립 재생해 전체 소비 이벤트의 클록·RGB·SEAL DMA와 빔 좌표가 일치하는지도 확인했다. 메뉴 복귀는 기존 MMC524 실기 기록을 유지한다.
