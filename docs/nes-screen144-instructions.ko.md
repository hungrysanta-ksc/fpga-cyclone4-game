# NES144 — 읽을 수 있는 NES 그림 확인

143에서 단색·직접 타일·ROM 타일·기존 진단 화면의 표시와 자동 메뉴 복귀를 확인했습니다. 이번에는 무작위 CHR 타일만 큰 글자와 테두리로 바꾸고, 기존 NES 프로그램과 전송 경로를 유지합니다. 단색 A/B/C 비교는 반복하지 않습니다.

## 실행

1. 전원을 끄고 기존 SD 파일을 별도 보관합니다.
2. ZIP의 `01-SCREEN144-SD-ROOT` 안의 내용을 SD 최상위에 복사합니다. 펌웨어·FPGA·NES 진단 이미지를 함께 적용합니다.
3. `NES SCREEN 144.nh1`을 한 번 실행합니다. 선택 파일은 0바이트가 정상이고 확장자는 바꾸지 않습니다.
4. 기존과 같은 약 9분 적재·대조 후, 약 30초 동안 진단 그림을 표시하고 자동으로 메뉴에 돌아오는 것이 목표입니다. 전체 관찰 기준은 최대 10분입니다.

## 기대 화면

ZIP의 `EXPECTED-SCREENS.png`가 기준입니다. **큰 `NES 144` 글자와 테두리가 세로로 반복**되고, 오른쪽의 **A/B 글자와 일부 색상이 바뀌는 두 그림**이 있습니다. 두 그림은 NES 프로그램이 바꾸는 MMC3 CHR 뱅크에 해당합니다. 실제 전송이 프레임을 건너뛸 수 있으므로 매번 규칙적으로 A/B가 번갈아 보인다고 보증하지는 않습니다.

이번에는 글자를 읽을 수 있는지, 테두리가 유지되는지, A/B 중 어떤 그림이 보이는지를 확인해 주세요. 처음 파란 대기 화면이 잠깐 보일 수 있습니다. 무음은 정상이며 패드 입력은 아직 연결하지 않았습니다. CRT 색 번짐과 카메라 대각선 띠는 판정에서 제외합니다.

## 전달할 결과

- `sd2snes/nes-progress-144.txt`
- `sd2snes/nes-screen-last-144.txt`
- 글자가 읽혔는지, A/B 중 무엇을 봤는지, 자동 메뉴 복귀 여부

가능하면 화면 표시 구간 30~40초만 촬영해 주세요. 전체 적재 대기는 촬영할 필요가 없습니다. 10분이 지나도 복귀하지 않으면 종료하고 남은 로그를 회수합니다. 같은 143이나 044/GBC 복원 재시험은 필요 없습니다. ZIP의 기존 복원본은 필요할 때만 사용합니다.

## 로그와 판정 범위

143에서 실제 A/B/C 화면과 단계 비트 기록이 일치하지 않았습니다. 이번에는 `screen_telemetry_trusted=0`을 명시하고 원시 stage/mask/frame 값을 참고용으로 보존합니다. 이 표식만으로 화면 실패나 정상 프레임 수를 확정하지 않습니다. 실제 그림과 ROM/RUN/STOP 오류, 메뉴 복귀를 함께 확인합니다.

FPGA 회로·배치·프로토콜은 같아 ID 5E/D9를 유지합니다. 새로운 144 파일 조합과 엄격한 진단 ROM CRC로 구분합니다. RUN 중 SD 쓰기는 추가하지 않았습니다. 이번 통과는 진단 그림의 경로 확인이며 SMB3 게임 구동·패드·오디오 완료를 뜻하지 않습니다.
