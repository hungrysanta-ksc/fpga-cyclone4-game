# NES728 실제 DMA 완료와 OBJ 발행 경계

## 목표

727의 인접 map 발행·384B 연속 DMA·BG ROM 마감을 유지하면서,953에서 이미 수락된 map과 후속 OBJ의 발행을 실제 DMA 진행·credit에 맞춘다. Flash 한도,STOP·새 패킷 우선·독립 검사·최종 ACK·메뉴 경계와951/911/952/957을 보호하고 두 위상의952–957 표시 간격·957 마지막 ACK를 함께 비교한다.

## 작업내용

ARM은719의 SEAL 대기와 tile 인계의 중복 진행 검사를 `nes_sink728_map_wait`로 합쳤다. warm bank 이력이 있고 마지막 수락 section이 map일 때만 적용한다. BG에는 기존 한 번의 입력 서비스 기회를 주고,OBJ에는 기존719의 ACK 시각 기반 만료 조건과 poll 한도를 적용한다. 실제 E0의 CRC·identity·credit 검사를 거치며,기다리는 동안 기존 bounded 입력 callback을 실행한다. 만료·시계 부재·오래된 시각에서는 진행 신호를 기다리지 않는다. 이 시각 추정은 ARM 발행 허가이며65816의 실제 VBlank·DMA 안전 검사를 대체하지 않는다.

OBJ descriptor는 submit 성공 전까지 현재 호출의 소유이고,수락 후 기존 실제 소비 receipt를 기다린다. STOP/CRC/identity 실패 시 OBJ 발행을 중단한다. 새로운 고정 지연·세대/위상별 분기·persistent RAM은 없다.

- A: 공유 함수의 single/반복 분기를 그대로 둔 첫 구현. 정상 Flash213016B로24B 초과하여 전체 일정 시험 전에 기각했다.
- B: loop 시계 조건과 오류 소유권을 통합해24B를 회수했다. ARM만 변경하고 원래65816을 유지한다.
- C: B ARM에 실제65816 완료 공개를 연결한다. 기존 E0 bit8은 ‘map DMA 한 번 완료’이므로 이미1이어도 남은 map이 있을 수 있었다. 이를 ‘현재 수락된 DMA 작업 큐가 실제 retire 뒤 비었음’으로 좁혔다. 기존 source 분류의 저장·stack·복원을 제거하고 기존 head/tail 비교로 바꿨다. 새 포트·FPGA 상태·WRAM·packet은 없고,진행은 새 packet/ACK/STOP으로 소실될 수 있는 advisory다. 최종 표시 ACK는 별도다.

같은727의 두 시작 시각7288416/7467100,ROM 위상0,CPI2/84MHz,실제 링크 M4·Mesen65816과 기존 공유SPI/IRQ·ROM 허가 달력으로 비교한다. 전체 NES/PSRAM RTL 동시실행이나 실기 FPS가 아니다. 입력7블록,동일 map·tile·plan·픽셀,실제 수락·DMA·최종 ACK를 검사한다.

## 성과

**구현·자원·안전 조건은 통과했지만 전체 시간 동시 개선은 실패했다. B/C를 모두 미채택으로 보존하고 선택707D·기존 ARM/65816을 유지한다.** B/C 각106화면,총212화면의 map·tile·plan·픽셀과 최종 ACK가 일치했다. 각 실행114352B의 VRAM DMA를 완료했다.

|장시간 전체 Flash|212948B|212948B|
|같은 함수 경계(상한4700B)|4696B|4696B|

전체 Flash를 같게 유지한 것은 poll416→382B,SEAL1336→1202B의 중복을168B 공유 함수로 대체한 결과다. 정상판 Flash 여유0B·장시간44B다. C의 전개 body6020B/물리 ROM5120B는 같고,압축 길이는4230→4226B다. C는 원래 DMA stack2B를 제거했다.

추가 정적 RAM은 없지만 C의 ARM 관측 stack low는 위상1에서 `0x2000f814→0x2000f7f0`로36B 더 깊어졌다. 위상2는 동일하다. 이는 callback 중첩 비용이며 최대 stack의 형식적 보장은 아니다. `.data1048B/.ahbram8992B/.bss19548B(정상)·19556B(장시간)`는 유지했다.

B에서953 map 선행은 두 위상832B로 회복했다. 하지만727 대비952–957 평균은+0.001909/+0.004811ms,957 마지막 ACK는+0.011454/+0.015551ms다. 양쪽18VBlank 그대로이고 보호 조건은 통과했다. **국소 map DMA 회복을 전체 처리 시간 개선으로 판정하지 않는다.**

위상2의953은 빨라져도954가+0.171437ms 늦어져 마지막 ACK는 같다. 위상1은955가−0.095450ms지만956이+0.110442ms로 이득을 소비한다. 명령 감소나 한 화면의 빠른 공개만으로 지속 성능을 주장하지 않는다.

952의384B 및 후속1536B map DMA,956/957의 선행 map1024/2048B를 유지했다. 953 BG ROM 허가 구간은169/169·170/170 그대로다. 951 공개246선 이내·911 표시2회·952 표시3회·957 최종 대기0회·입력7블록과 기존908/934/940/943 개선을 모두 유지했다.

정상/장시간 실제 링크의 새 handoff14조건씩,기존 수락·마감·STOP/credit/소유권·메뉴 경계를 검사했다. C는 packed reset6020B 복원 및4종 손상 거부,실제65816의23개 DMA/beam/부분 retire/새 packet/STOP/독립 coverage/최종 ACK 취소,종료 후 DMA·ACK 금지를 검사했다. 실제 보드에서 메뉴를 새로 실행한 시험은 아니다.

B는707D의 RTL·ROM·SDC를 변경하지 않아 기존 전체 Lite FIT15322LE·962/963LAB·56/56M9K,setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns의 기록 범위를 승계한다. C는 RTL·SDC는 같아도 ROM 내용이 바뀌므로 해당 FIT/STA를 새 이미지의 통과로 간주하지 않는다. 두 위상 시간 게이트 실패로 C의 새 전체 FIT/STA는 실행하지 않았다. 외부IO 승인 확대나 회로 절감 주장도 없다.

### 다음 병목의 실제 예산

C의953 마지막 tile 소비 ACK는 직전 표시부터37.528/37.555ms,SEAL 수락은42.642/42.751ms다. 이전 VBlank의246선 끝까지 허용하는 낙관적 상한과 비교해도 tile ACK는 최소3.707/3.731ms,SEAL 수락은 최소8.821/8.927ms 늦다. 이는 실제 이전 frame의 관측 clock/line에 최대1364clock/선을 적용한 상한이며,수평 위치·짧은 선·남은 검사/DMA 비용을 유리하게 제외했다. 추가 검사와 DMA까지 포함한 충분조건이나 전역 최소 개선량은 아니다.

따라서832B map 선행을 회복한 뒤 ‘진행 bit를 더 오래 기다리기’로 VBlank를 줄일 수 있다는 근거는 없다. 늦은 tile 소비와 그 뒤 약5.1ms의 ordinary/SEAL 경로를 함께 줄여야 한다. 동일 시작 시각의 두 위상과 후속 화면을 계속 대조해야 한다.

## 후속작업

1. 선택707D·기존 ARM/65816과727 자원 통과 후보,723C 시간 대조군을 유지한다. B/C는 미채택 연구 결과다. 현재 경계의 E0 기다림·poll 수·고정 지연 미세 조정은 반복하지 않는다.
2. 다음은953 마지막 OBJ의 데이터/ROM 준비·발행·credit·소비를 분해하고,그 뒤 ordinary/SEAL 약5.1ms와 겹칠 수 있는 생산·전송을 찾는다. 목표 예산은 이전246선까지 tile 최소3.7ms·SEAL 최소8.8ms 부족이다. 아직 삭제 가능한 코드나 실현 가능한 가속으로 계산하지 않는다.
3. 952의384B 연속 DMA와 BG ROM 구간,951/911/952/957·7블록을 보호한다. 952–957·기존951–955·개별 간격·마지막 ACK를 분리해 두 위상에서 판정한다. Flash 여유0B·같은 함수 경계 여유4B·새 정적RAM0B를 유지하며,ARM stack36B 증가도 비용에 포함한다. C ROM30B 여유는 미채택 후보의 수치다.
4. 새 설치본은 없다. 다음 실기 전달은60초/장시간판·새 파일명·RESTORE 제외·5–40초/40–55초 비교를 유지한다.
