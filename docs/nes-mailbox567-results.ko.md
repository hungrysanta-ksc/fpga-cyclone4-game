# 567 · 기록·준비 ACK mailbox의 reset 경로

**다음 설계의 기준은 양방향 로컬 해제 후보 B, 실기 기준은 MMC558이다.** 565에서 나빠진 전체 STA 5항목 중 4항목이 MMC558 기준을 회복했다. 수신·송신 mailbox에 걸리던 코어 reset의 직접 setup 경로는 모두 사라졌다. 실기 전달에는 loader의 대상 setup −0.024ns와 NES 도메인의 코너 회귀 0.034ns가 남는다. [전체 보드·재생·기능 시험 결과](../analysis/mailbox567-verification.json)

## 실제로 바꾼 경로

565는 기록을 NES에서 84MHz host로 96비트씩 넘기고, 준비 ACK는 반대 방향으로 17비트씩 돌려준다. `src_ready`와 `dst_valid`에는 공통 reset과 각 클록의 해제 플립플롭이 함께 들어갔다. 소비자에게 보이는 포트 식을 내부 수락·완료에도 쓰면서 원격 reset이 데이터 레지스터의 다음 상태를 선택하게 됐다.

- **A · 수신 완료만 분리.** 수신기가 이미 로컬 해제·상대 준비를 확인한 블록 안에서 `valid && dst_ready`로 완료한다. 85°C에서 기록 mailbox의 `valid`에 도착하는 최악 setup은 −7.286→+5.598ns가 됐다. 반면 준비 ACK 송신기의 `held`에는 reset이 계속 들어가 −8.090ns가 됐다.
- **B · 양쪽 포트를 로컬 해제로 구동.** 보드에서 쓰던 mailbox206의 RTL을 기존 165 인스턴스 이름으로 사용했다. reset을 걸면 두 해제 체인이 비동기로 클리어되어 클록이 멈춰도 포트가 닫힌다. 재개는 양쪽 클록의 해제 및 상대 준비 확인 뒤에만 허용한다. 기록 `valid`와 준비 ACK `held`를 대상으로 시작·끝 레지스터의 존재를 별도 확인한 뒤 setup 경로를 조회했다. 두 직접 경로 모두 세 코너에서 0개였다. 85°C 기록 `valid`의 남은 최악 경로는 host 내부에서 시작하며 +6.623ns다.

중간 시도에서 인스턴스 타입까지 206으로 바꾸자 Quartus가 DAC reset 레지스터를 다른 이름으로 병합해 기존 CDC 제약이 정확한 끝점을 찾지 못했다. 해당 FIT 실패를 보존했다. B는 합성 계층 이름을 유지하며 MMC558의 QSF·배치 SDC·CDC SDC·명목 SDC를 그대로 쓴다.

## STOP과 표시 일정

기준·후보에 같은 데이터를 주고 매 클록에서 포트와 수신 바이트를 비교했다. 96비트·17비트 각각 두 위상에서 시험했다. 한 폭·위상당 단어 81개 중 33개를 전달하고 48개를 reset으로 취소했다. 송신·수신 클록을 각각 또는 동시에 멈춘 뒤 짧은 reset을 걸었다. 이미 공개된 단어의 수락 직전·직후, 데이터 캡처 도중, 장시간 backpressure까지 포함했다. B의 네 조합에서 데이터 손상·중복 전달·취소 뒤 오반환은 0건이었다.

기존 ARM·SPI·IRQ·ROM 일정의 패킷 도착 시각을 고정하고 실제 65816을 다시 실행했다. 위상별 53개 RGB 화면, 전체 이벤트 9,464 / 9,462개, 타일 읽기·반환 기록이 565와 일치했다. 952 표시 간격은 위상별 83.362 / 83.240ms, 957은 83.657 / 83.405ms였다. 모두 직전 표시에서 5 VBlank, 최종 준비 뒤 추가 대기 0회였다. 밀집 5화면 평균은 83.157 / 83.121ms, 마지막 ACK는 87,545,284 / 88,254,606 master clocks였다. 이 단계는 변경된 mailbox의 클록별 동작과 고정 입력의 소비 일정을 분리 검증했다. ARM 프레임 루프나 물리 메뉴 복귀를 새로 실행하지 않았다.

## 다음 작업 순서

1. B에서 `check_failed → loader.reject_state[2]`의 168MHz 경로를 줄인다. 명령 거부, WRITE/HOLD 완료, STOP 우선순위를 기준과 대조한 뒤 두 STA 뷰에서 −0.024ns가 회복되는지 확인한다.
2. slow 0°C NES의 남은 회귀는 `source_epoch207.gray[1] → epoch_meta[1]`이다. MMC558의 −4.586ns에 비해 B는 −4.620ns다. epoch 변경과 독립 수락 조건에서 전 비트의 도착 및 캡처를 확인한다.
3. 같은 보드에서 원래 OE 제약과 PSRAM 예산, 전체 FIT·STA, 두 시작 위상의 952·957과 마지막 ACK를 재확인한 뒤 실기 인계를 판단한다.

## 재현

`prepare_nes_mailbox567.py --base <MMC558 보드> --out <경로>`로 A를 생성한다. B에는 `--local-ports`를 추가한다. 두 보드 모두 Quartus Lite 전체 compile과 `timing506.tcl`을 실행한다. 565와 후보에서 `report_nes_mailbox567.tcl`, 후보에서 `report_nes_{pins565,arg564,owner562}.tcl` 보고서를 생성한다. Windows에서는 Tcl을 짧은 보드 경로에 복사해 실행한다. 기존 Starter FLOAT wrapper에서 `check_nes_mailbox567.py`로 각 후보를 기준과 비교한다. `replay_nes_close561.py --all-banks`로 562 두 입력을 재생한 뒤 `analyze_nes_mailbox567.py`로 원본 해시·표시 시각·전체 보드 결과를 대조한다.
