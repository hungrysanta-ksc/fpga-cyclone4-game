# NES177 — 화면 정지 경계 관측과 다음 전송 개선

PR110의 176 회고를 이어 **실기에서 마지막 COMMIT 뒤 무엇이 다음 화면을 막는지 구분할 최소 관측**을 적용했다. 새 177 시험 패키지를 준비했다. 화면 정지 해결·연속 60fps는 미완료이며, 실기 결과로 수정할 경계를 결정한다.

## 완료한 변경

174 FPGA의 기존 96비트 history 중 하위 22비트만 교체했다. 상위 74비트(주사선·dot·상태·ROM 주소), 16표본 RAM, 표본 수집 시점, STOP 보존 방식은 그대로다. 기존 PPU 주소 필드는 이 시험에서 하위 상태 묶음으로 대체되므로 174 해석기를 사용하지 않는다.

| 하위 비트 | 의미 |
| --- | --- |
| 21:18 | 177 표식 `6` |
| 17:14 | exporter 상태: IDLE부터 DRAIN까지 기존 12상태 |
| 13:10 | frame_owned / 원본 geometry_valid / initialized / active |
| 9:6 | fill busy / done / idle / abort |
| 5:0 | arbiter_fault / tx_valid / tx_ready / host_valid / host_ready / release |

`nes_native_export165.sv`는 기존 상태의 출력 포트만 추가했고 `nes_live_joint.sv`는 위 관측선을 연결했다. 나머지 빌드 입력 59개는 174와 동일하다. 로더·SPI·타임아웃·코어 우선권·실제 해제 제어를 변경하지 않았다. MCU는 세 소스의 시험 번호·파일명·로그 표지만 변경했고 실행 제어와 history wire version 1을 재사용한다. 보고서 표지는 `LAST16_BOUNDARY177_LOW22`다.

**기록은 STOP/fault에 가까운 마지막 16 NES 클록이다. 첫 정지 순간이나 16프레임의 사건 기록이 아니다.** 하나의 표본만으로 영구 정지를 확정하지 않고 기존 세대·BEGIN/COMMIT/ACK·ROM 오류·시간 기록과 함께 해석한다. raw geometry와 중재기 오류를 적용한 허용 조건을 혼동하지 않는다.

## 검증 결과와 한계

| 검증 | 결과 |

| 동일 입력 재생성 및 변경 범위 | 61개 입력 일치, 출력 전용 2개 변경·59개 보존 |

| 자원 | 15,062LE / 962LAB / 36M9K |
| 더 엄격한 구현 여유 예산 | −0.061ns, 미통과 값을 그대로 공개 |

| 전체 ARM 링크와 RUN/IRQ 보수적 상한 | static 26,564B / foreground 37,312B / IRQ 508B / 잔여 1,040B |
| 실제 최대 길이 TXT formatter | 3,925 / 4,096B |
| 패키지 | mapped SNES ROM 4,096B 일치, RBF 압축 왕복 일치, ROM·메뉴·164 복원 바이트 보존 |

실제 클록 검사는 174와 같은 기준이며 클록/예외를 완화하지 않았다. 엄격한 구현 여유 예산 통과나 전체 IO/CDC/MTBF 승인을 주장하지 않는다. 조건부 IO는 기존 PCB·수신 허용치를 전제로 한 경계 검사다. 기존 24개 비동기 reset 관련 음수 보고도 별도 유지한다. 해제 시험은 합성된 정상 BG 입력과 기존 수집기 4개를 사용하며 실제 CPU·공유 PSRAM·fill/export·SPI·SNES 전체를 재현한 시험이 아니다.

첫 ARM 빌드의 오래된 최종 검사기 실패와 sandbox 검사 실행 실패는 원본 로그로 보존했다. 이미 검증한 builder 및 허용된 host 실행으로 후속 검사를 완료했다. 실패를 새 펌웨어 결함이나 새 라이선스 요구로 해석하지 않는다.

## 실기 결과 이후 분기

1. 177 두 TXT와 화면·사운드·입력·메뉴 복귀 보고를 받는다. 같은 화면이면 영상 재촬영·174 재시험·044 복원 검증은 요구하지 않는다.
2. raw geometry가 없고 owned도 없다면 수집기 결합/초기화/거부 조건을 좁힌다. owned가 남거나 exporter DRAIN·fill busy가 지속된다면 소비 완료→해제·배수 경계를 좁힌다. arbiter_fault가 있으면 해당 소유권/응답 오류를 조사한다. 174의 ABORT0과 모순되는 단정은 피한다.
3. geometry와 owned가 있어도 BEGIN이 없다면 최종 허용 조건·exporter·호스트 backpressure를 함께 본다. 표본 창이 짧거나 모순되면 원인을 확정하지 않는다. 광범위 로그나 무관한 로더 FIT 반복으로 되돌아가지 않는다.
4. 특정 경계 수정은 필수 회귀 후 SMB3로 확인한다. 완전 정지뿐 아니라 처음부터 뚝뚝 끊기는 표시 간격도 합격 조건이다.

## 속도 개선의 다음 구현 단위 — 아직 설계 단계

176의 2개 도입부 화면에서 5,493B 중 변경 20B였던 결과는 전송량 축소 여지를 보여준다. 일반 플레이 성능이나 구현 완료 증거가 아니다. 첫 단계는 지속 패턴 캐시 전체를 한 번에 만들기보다 **패턴 전송을 유지한 채 map/OAM/CGRAM/HDMA 변경 범위를 앞단에서 만드는 것**이다. 이미 구현한 SNES 변경분 DMA는 재사용한다.

현재 174 변환기는 매번 plan 전체를 지우며 OAM 앞 240B를 BG 묶음, CGRAM 앞 224B를 OBJ 묶음의 임시 공간으로 쓴다. 따라서 단순히 memset을 지우거나 이전 테이블을 그대로 남기면 기준 화면이 깨진다. 수신기 `required[2048]`은 수신 검증 후 COMMITTED 상태에서는 읽지 않으므로, 그 기간에 이전 OAM 544B + CGRAM 512B = 1,056B를 저장하는 방안을 검토한다. 남는 992B는 제한된 dirty metadata 후보 공간이다. 이것은 **소스 사용 수명 확인에 근거한 설계 제안이며 아직 union/API·오류 경로·스택 검증을 구현한 것이 아니다.**

다음 구현 조건:

- MCU: 현재 COMMIT 이후, 이전 plan을 덮기 전에 필요한 기준 테이블을 보존한다. map/HDMA는 이전 값과 비교하고 덮어쓰되 미사용 map 셀과 짧아진 HDMA 꼬리도 처리한다. `consumed` 후 다음 BEGIN에서 수신기 초기화가 일어나므로 재사용 영역을 그 뒤까지 참조하지 않는다.
- SNES: 교대 WRAM 수신 버퍼는 직전 표시 화면과 같다고 가정할 수 없다. 새 BEGIN에 `base_generation`과 `target_generation`을 명시하고 확정된 화면의 테이블을 물려받는 계약이 필요하다. MCU만 전송을 생략하는 수정은 금지한다.
- 확정: 일치하는 최종 표시 ACK 뒤에만 기준 세대를 전진시킨다. 실패·잘못된 세대·확정 여부 불명은 base를 무효화하고 전체 재동기화한다. 활성 VRAM 패턴을 조기 덮어쓰지 않는다.
- 검증: 초기 전체 화면, 무변경, map 변경, OAM/CGRAM/HDMA 변경, 교대 버퍼 두 세대, 실패 후 재동기화로 제한한다. 추가 MCU 전체 화면·세이브 SRAM 없이 실제 링크의 여유를 다시 확인한다.
- 계측: 생산·수신·변환 계산·패턴 전송·테이블 전송·폴링·SNES 복사/비교/표시 ACK를 분리한다. WRAM 기준 복사와 전체 비교 비용도 포함한다. build38.3ms는 패턴 staging까지 포함하므로 순수 CPU 시간이라고 쓰지 않는다.

그 뒤에도 직렬 경로가 약 16.7ms를 넘으면 FPGA→SNES 카트리지 버스 DMA 직접 경로를 비교한다. SPI 속도나 타임아웃만 올려 목표를 달성했다고 보고하지 않는다. 우선순위는 **연속 AV → 장기 실행 및 오류/리셋 로그 → 입력 유지**다.
