# NES146 — 느린 갱신에서 연속 갱신으로

145의 긴 검정·고정 그림과 메뉴 복귀는 실기 통과했습니다. 이번에는 같은 NES 그림을 사용하면서 긴 검정을 없애고 갱신 간격을 줄입니다. 실기 표시 성공은 아직 확인하지 않았습니다.

## 실행

1. 전원을 끄고 교체할 SD 파일을 별도 보관합니다.
2. ZIP의 `01-SCREEN146-SD-ROOT` 안의 내용을 SD 최상위에 복사합니다. `sd2snes/firmware.stm`, `fpga_n146.bi3`, `nes/screen146.nes`와 동봉된 base/menu를 함께 적용합니다.
3. **`NES SCREEN 146.nh1`**을 한 번 실행합니다. 이 선택 파일은 0바이트가 정상이며 확장자를 바꾸지 않습니다.
4. 적재·전량 대조는 기존과 같이 약9분입니다. 이후 명목60초 표시하고 자동 메뉴 복귀합니다. 실행부터 최대11분, 표시 시작부터 최대90초를 관찰 기준으로 삼습니다. 넘으면 전원을 끄고 남은 두 TXT를 회수해 주세요.

## 촬영과 기대 화면

대기 전체는 찍지 않아도 됩니다. 실행 약8분30초 뒤 촬영을 준비해 **그림 표시 시작부터 메뉴 복귀까지** TV 전체를 연속 촬영해 주세요. 가능하면60fps로 촬영하되 기존 촬영 설정도 괜찮습니다.

- 처음 파란 대기 화면이 잠깐 나올 수 있습니다.
- 처음12개 받은 그림은 각각30 TV프레임 고정합니다. NTSC 기준 약0.5초씩으로, 수신 대기를 제외하면 약6초 구간입니다.
- 이후에는 받은 그림을2 TV프레임만 고정하고 다음 그림을 받습니다. NTSC 기준 최소 약33ms의 고정 대기이며 **실제 수신·표시가30fps라는 뜻은 아닙니다.** 실제 갱신 간격은 수신 시간에도 좌우됩니다.
- 145의 약1.5초 검정·약3초 그림 반복은 없습니다. 정상 전송은 수직 블랭크 안에 끝나며, 전송이 늦으면 화면을 끈 채 다음 블랭크까지 기다립니다. 반복적인 검정·깜빡임이 보이면 중요한 결과이므로 그대로 촬영해 주세요.

글자는 **`NES 144` 그대로**입니다. ROM·그림을 재사용하고 실행 표식·펌웨어·로그만146으로 바꿨습니다. 세로로 반복되는 글자·색상 막대가 원래 그림이며 무음·패드 입력 없음도 정상입니다. A/B가 반드시 번갈아 나타나지는 않습니다. 카메라/CRT 대각선 밝기 띠는 제외합니다.

느린 첫 구간과 이후 구간을 비교해 **위아래 A/B 혼합, 글자 일부씩 갱신, 반복 검정이나 정지**가 생기는지 봐 주세요. 영상과 두 로그를 보내면 분석할 수 있으므로 별도로 FPS를 세지 않아도 됩니다.

## 전달할 결과

- 표시 시작부터 메뉴까지 연속 영상
- `sd2snes/nes-progress-146.txt`
- `sd2snes/nes-screen-last-146.txt`
- 자동 메뉴 복귀 여부

한 번의 적재로 두 속도를 시험합니다. 같은146 재실행이나 변하지 않은044/GBC 복원 시험은 요구하지 않습니다. `02-RESTORE044-SD-ROOT`는 필요할 때 쓰는 기존 복원본입니다. 교체·복원은 전원을 끈 상태에서 합니다.

## 남은 범위

약9분은 NES 고유 요구 시간이 아니라 현재 바이트별 GPIO SPI 적재·전량 대조 비용입니다. 이번에는 표시 경로만 변경했으며 로딩 단축은 별도 미완료입니다. 검증 완료 START·RUN 중 SD쓰기 금지·오류 차단·STOP·메뉴 복귀를 유지합니다. `screen_telemetry_trusted=0`인 화면 관측값으로 실제 FPS나 화면 성공을 판단하지 않습니다. SMB3·입력·오디오·게임용 갱신 속도는 아직 완료되지 않았습니다.
