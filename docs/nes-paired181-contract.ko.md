# NES181 — 압축 송수신 전체 ARM 통합과 작업 메모리 수명

## 작업 의미

FPGA→MCU의 1813 수신기와 MCU→SNES의 1815 송신기를 전체 ARM 펌웨어에 함께 넣었다. 각각의 함수만 빌드했을 때는 드러나지 않았던 스택 여유 부족을 수정했다. 실기 패키지를 만들기 위한 MCU 측 통합 조건이며, FPGA 타이밍 통과나 실제 60fps 달성을 뜻하지 않는다.

## 변경과 메모리 계약

`tools/nes_paired181.py`는 board181의 검증된 전체 ARM 입력을 해시 검사한 뒤 복사한다. receiver1813, sink1815, converter의 작업 공간 수명만 바꾼다. 기존 펌웨어·완료 증거·배포180을 덮어쓰지 않는다. 비교용 `--baseline-stack`은 새 송수신기와 이전 converter 스택을 조합한다.

기존 converter는 OBJ 검증용 `rank_used[224]`와 `evaluation[224]`를 스택에 두었다. BG 배치와 마지막 동기식 패턴 콜백이 반환하면 `bg_keys[1024]`는 더 이상 읽히지 않으므로, 그 앞448바이트를 초기화해 두 배열로 재사용한다. OBJ 키는 별도 필드에 유지한다. 이후 raw CHR/HDMA 생성 단계는 자신의 전체 영역을 다시 초기화한다.

- 콜백은 입력 포인터를 보관하지 않으며 ACK까지 동기식으로 처리한다. BG 콜백이 끝나기 전에는 키 메모리를 재사용하지 않는다.
- 실패한 후보는 유효 화면으로 공개하지 않는다. 다음 build는 plan 전체를 다시 초기화한다.
- 일반 장면의 build 이후 BG 키448바이트는 더 이상 원래 키를 담지 않는다. 이를 다음 프레임 차분 캐시나 강제 세이브 상태로 사용하면 안 된다.
- 수신기18,064바이트, 영상 작업 공간15,888바이트와 ABI는 그대로다. 별도 프레임 버퍼·힙·카트리지 세이브 SRAM은 추가하지 않는다.

## 전체 ARM 결과

같은 ARM GNU13.3 컴파일러와 기존 플랫폼 검토를 사용했다. `packet_wire`로 옮겨진 간접 콜백 간선을 명시하고, 실제 링크된 `span`·수신 poll·서비스·장애 처리까지 RUN 그래프에 포함했다. ISR은 SysTick/TIM2/NMI와 각 확장 하드웨어 프레임을 보수적으로 예약한다. 라이브러리8개·플랫폼5개의 명령/피연산자는 기존 검토와 재배치 후 동등함을 확인했다.

| 항목 | 기존 board181 | 새 송수신, 이전 작업 공간 | 작업 공간 재사용 적용 |
|---|---:|---:|---:|
| static RAM |26,564|26,564|26,564|
| RUN 외 사용 가능 RAM |38,860|38,860|38,860|
| foreground 상한 |37,320|37,408|36,968|
| IRQ 예약 |508|508|508|
| 남는 여유 |1,032|944, 기준 실패|1,384, 기준 통과|

기준1,024바이트를 낮추지 않았다. converter의 컴파일러 보고 스택은696→256바이트로 줄었다. 재사용 배열448바이트와 실제 함수 스택 절감440바이트가 다른 것은 레지스터/정렬 등 컴파일 결과를 그대로 집계했기 때문이다. 새 펌웨어 크기200,412바이트, SHA256 `cf16e9c124a20ab0e25e9f0d0646d8dfd33f706300b8df600318e3020bcc5d1c`는 **컴파일 검증용**이다. 설치 가능한 새 FPGA와의 쌍은 아직 없다.

이는 정적 호출 그래프 상한이며 실기 high-water 측정이나 모든 메뉴/GBC 경로의 재증명이 아니다. 계획상 목표였던 ARM 여유4KiB에는 여전히 못 미친다.

## 필요한 경계만 검증

`test_nes_paired181.py`는 실제1813 수신기→converter→1815 송신기를 연결한다. 패킷 ACK는 이 시험에서 모의 값이다. 이전 converter와 재사용 converter를 각각 실행하여0/1/7 raw 행, 두 표시 마스크와 raw 위치 변경 등5장면·61검사를 비교했다.

출력 BG/OBJ 패턴, map, CGRAM, OAM, HDMA, raw bundle과 plan을 비교했다. 일반 장면의 **수명이 끝난 BG 키448바이트만** plan 비교에서 제외하며, 송신 데이터는 전부 일치해야 한다. raw 장면의 plan은 전체가 일치한다. guard 바이트·중복 OBJ·최대 rank7/마지막 부근 행의 충돌·잘못된 수신 상태·콜백 실패·SEAL 거부·복구도 검사한다. 같은 작업 공간을 반복 사용한다.

새 수신기/송신기 C는 packed181/stream181의 검증된 생성 결과와 동일하다. 변경 없는 1815 실제65816/WRAM/PPU 검사는 재사용하며, 이번에 새로 실기나 SNES 전체 시험을 수행했다고 집계하지 않는다. 다른 fixture 사이의 전송 시간 모델을 더해 실측 종단 시간을 만들지 않는다.

실패 기록도 보존한다. check01은 샌드박스 WinError623으로 도구 실행 실패, check02는 위944바이트로 실제 기준 실패다. test01은 하네스의 `-Werror=misleading-indentation` 컴파일 실패였으며 중괄호 수정 후 새 test02에서 통과했다. SELECT는 **arm02/check03/test02**다.

## 다음 작업

작은 codec 개선을 반복하기보다 FPGA의 관련 PLL RUN/STOP 활성화와 응답 ACK 소유권 경계를 정리한다. 즉시 버스 취소와 미완료 ACK 무효화를 유지하면서 실제 전체 경로의 타이밍을 확보해야 한다. 마지막 replyjoin181 전체 FIT는 setup−1.408ns로 미채택이며 이 ARM 변경은 그 실패를 해결하지 않는다. 같은 PLL 경로를 false path 처리하지 않는다.

이후 변경된 경계의 최소 검사와 통합 FIT/IO를 통과하면 paired181 ARM·stream1815 SNES를 사용해 SMB3 숫자1 타일→A 실기로 간다. 1813 exporter와 SPI의 extended kind7 처리도 FPGA에 함께 반영해야 한다. 이전1811 FPGA를 새1813 MCU와 섞지 않는다. 1815 SNES ROM 또한 일치해야 한다.

60fps 기준은 유지한다. 현재 raw7 장면은 송신 최소 모델만 약22.15ms이고, 단일 capture lease/수신→변환→송신 직렬 경로도 남아 있다. 향후 target-bank 차분·수집 겹침은 저장 위치/기준 세대/포트/취소 수명을 먼저 정의한다. 추가16KiB ARM plan이나 세이브 SRAM을 임시 버퍼로 쓰지 않는다. 실기 화면 정지 해소와 실제 표시 주기 달성을 별도로 판정하고, 정상 영상·사운드 이후 장시간 실행/오류·리셋 로그, 그 다음 입력 유지 품질을 확인한다.

증거: `analysis/paired181-verification.json`, 로컬 `probes/nes-paired181/progress.json`. 완료 archive와 source-after-run 스냅샷은 불변이다.
