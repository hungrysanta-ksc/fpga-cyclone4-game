# NES226 실기 시험: 배경 계산량 감소

> 실기 결과 추가: 첫 레벨 스크롤 개선과 소리·메뉴 복귀가 확인됐다. 60.06초452display, 계획 계산7.17초. 60fps는 미달이다. [결과와 다음 작업](nes-game226-hardware01.ko.md)이 아래 배포 당시 시험 안내보다 우선하며 같은226 재시험은 필요하지 않다.

225에서 정지 화면은 개선됐지만 스크롤 성능은 미달이었다. 이번226은 일반 배경 타일의 줄 위치·예외 검색을 반복하던 CPU 계산을 줄였다. 화면에 올리는 타일 내용과 순서는 유지한다. FPGA·SNES 소비기, 사운드·입력, 60초 시험 제한은225와 같다. **실제 스크롤 성능 개선과60fps는 아직 미확인이다.**

## 설치·실행

1. 전원을 끄고 ZIP의 `01-GAME226-SD-ROOT` 안의 내용을 SD 루트에 복사한다. 폴더 자체를 넣지 않는다. 이번 `firmware.stm`과 `fpga_n226.bi3`, `game226.nes`, 실행 파일을 함께 사용한다.
2. 메뉴에서 `NES GAME 226.nh1`을 실행한다. 초기 로딩 경로는 변경하지 않았다.
3. 플레이어 선택 → 월드맵 숫자1 타일 → A로 첫 레벨에 진입한다. 오른쪽+B를 유지하고 A를 반복해 스크롤한다. 가능한 범위에서 잠시 왼쪽 이동도 확인한다.
4. 게임 화면 시작 후 약60초가 지나면 메뉴로 돌아온다. 정지 화면보다 **첫 레벨의 스크롤 중 끊김**을 우선 확인한다.

## 전달할 결과

- `/sd2snes/nes-progress-226.txt`
- `/sd2snes/nes-game-last-226.txt`
- `/sd2snes/nes-budget-226.txt`
- 스크롤의 끊김, 타일 깨짐 여부, 소리·조작·메뉴 복귀 상태.

가능하면 게임 화면부터 메뉴 복귀까지 영상도 남긴다. 완전히 같은 조작을 재현할 필요는 없다. 예산 로그의 schema226에는 BEGIN과 타일 완료 대기 시간이 추가됐다. startup222/boot214/plan215 번호는 각 기록 형식의 기존 버전이다.

같은225/044 재시험이나 매번 복원 시험은 필요하지 않다. `02-RESTORE164-SD-ROOT`는 필요할 때 사용할 기존 복원 파일이다. 저장SRAM을 새로 사용하지 않았다.

## 확인된 범위

실제 C1,939개 합성 프레임에서225와 타일 계획·전체 출력 데이터·캐시·두bank 상태가 바이트 단위로 같았다. 예외가 첫 열에 있는 경우도 포함했고 기존11개 거부 경계, 잘못된 최적화2개 음성 대조, 실제 RUN9프레임/6개 실패 경계가 통과했다. 이전225의 실제65816 소비기 검증은 출력 동등성과 소비기 소스 동일성을 근거로 재사용했다.

ARM209476B/static28116/RUN35008/IRQ508, 여유1792B. 새 시간필드96B를 포함한 값이다. 로그 최대3521B/4096B 검증. FPGA 재배선·새 FIT·ROM 조립은 하지 않았다. 계산 횟수 감소는 실제 FPS 증가율이 아니며, 수신·타일 생성·전송 완료 대기 비용은 남아 있다.
