# MMC907에서 마지막 OBJ가 ROM 허가를 기다리는 시간

실기 기준은 MMC907을 유지한다. 확정된 OBJ 행을 먼저 읽는 후보는 빈 캐시 두 위상에서 여섯 표시 간격 합을 20→17 VBlank로 줄였다. 기존 캐시는 두 위상 모두 15회였고, 빈 캐시에서 기존 선행 DMA의 일부가 SEAL 뒤로 옮겨갔다.

## 마지막 240B 수락 이후

모험도 4 캡처 3436에 해당하는 재생 세대 912를 비교했다. 시작은 65816의 마지막 240B 수락, 끝은 FPGA 모형의 마지막 OBJ descriptor 공개다. 두 타일 뱅크가 차 있어도 다음 ROM 읽기는 진행될 수 있다. 아래에서는 타일 읽기가 끝났는데 결과를 쓸 뱅크가 없어 실제 소비 token 반환을 기다린 시간만 뱅크 대기로 셌다. 시작 전에 발행한 ROM 요청은 240B 수락 뒤의 시간만 합산했다.

| 빈 캐시의 경과 시간 (ms) | 위상 1 | 위상 2 |
|---|---:|---:|
| OBJ 요청→ROM 허가 | 26.926 | 26.829 |
| 허가→읽기 응답 | 0.022 | 0.022 |
| 타일 뱅크 반환 대기 | 0.670 | 0.706 |
| 나머지 생산·공개 | 0.170 | 0.170 |
| **합계** | **27.788** | **27.727** |

93회 읽기 중 두 건이 대부분을 차지했다. token 35의 CHR 오프셋 `0x0C010`은 직전 허가보다 1.289 / 1.343ms 늦게 요청됐다. 이 요청은 240B 수락 시 이미 대기 중이었고 이후 10.939 / 10.884ms를 기다렸다. token 38의 `0x18790`은 직전 허가보다 0.282 / 0.318ms 늦어 15.560 / 15.524ms를 기다렸다. 기존 캐시에서는 이 세대의 OBJ backing 읽기가 0회였고 마지막 OBJ가 240B 수락보다 5.367 / 5.288ms 먼저 준비됐다.

## 기존 캐시와 빈 캐시 대조

**행 재사용**은 캡처 캐시 두 조회가 모두 실패한 뒤 읽었던 두 평면을 다시 사용한다. 16개 인덱스 × 8행에 물리 태그를 확인하며 세대가 바뀌면 비운다. **선행 읽기**는 CRC를 통과한 E9에서 복사한 short OBJ 기록을 사용한다. 해당 세대에서 첫 실제 OBJ miss가 생긴 뒤에만 동작하고, 각 묶음의 첫 CHECK 이후 기록당 20클록의 순회 비용을 부과했다. 세대당 최대 16개 태그·128개 행 쌍을 보관한다. 기존 캡처 적중이 우선이며, 모든 물리 요청은 같은 CPU·PPU 허가 달력을 공유한다. 데이터에 256B가 들고 태그·유효 상태·행 요청과 plan 복사 공간이 추가된다.

| 캐시·위상 | 여섯 간격 합 MMC907 / 행 재사용 / 선행 읽기 (VBlank) | 행 재사용 최종 ACK 차이 | 선행 읽기 최종 ACK 차이 |
|---|---|---:|---:|
| 기존 1 | 15 / 15 / 15 | −0.007ms | −0.007ms |
| 기존 2 | 15 / 15 / 15 | 0 | 0 |
| 빈 캐시 1 | 20 / 20 / 17 | +0.016ms | −49.735ms |
| 빈 캐시 2 | 20 / 19 / 17 | −16.650ms | −49.739ms |

선행 읽기는 세대 912에서 실제 소비자가 직접 기다리는 OBJ 허가를 123→34회로 줄이고 87회를 먼저 요청했다. 240B 수락 이후에는 직접 허가가 93→12회였고, 마지막 OBJ 공개까지 11.502 / 11.511ms가 걸렸다. 빈 캐시 여덟 화면의 전체 물리 읽기는 1,585→1,629회, 기존 캐시는 1,093→1,312회였다. 빈 캐시의 ARM 첫 유효 E0도 49.490 / 49.827ms 빨라졌다.

기존 캐시는 선행 DMA 범위가 보존됐다. 빈 캐시는 두 위상 모두 세대 909에서 기존 720B 중 32B, 세대 912에서 기존 496B 중 320B(288B+32B)가 SEAL 뒤로 이동했다. 모든 캡처의 RGB와 ordinary·tile 각각의 패킷 내용과 순서, 최종 identity·CRC는 일치했다. 위상 1에서 세대 912의 실제 공개는 VBlank 54→51이었다.

## 검증 범위와 다음 작업

같은 MMC907 ARM 최종 링크(212,820B)와 65816 ROM을 사용했다. 원본과 관측만 추가한 대조군의 결과가 일치했다. SRAM D0 송신 네 곳, 잘못된 CRC의 반환 거부, 타이머 STOP, base 복구·메뉴 반환을 ARM 경로에서 재검사했다. 선행 읽기 모형에서는 허가부터 응답 직후까지 STOP을 주입해 이전 행·peer·대기열을 무효화하고 같은 세대로 재시작해도 물리 응답이 끝나야 포트를 다시 쓰는지 확인했다.

ROM 허가는 부팅 코어에서 측정한 8개 구간을 반복한 달력이다. ARM과 65816은 실제 코드를 실행하지만 타일 공급은 모형이며, 타일 소비 데이터는 기존 캡처 fixture를 쓴다. 새 reader RTL의 메모리 포트·STOP CDC·Quartus FIT와 실기 FPS는 미검증이다. 다음 비교에서는 세대 912의 288B·32B 소비와 SEAL 수락을 같은 시계에 놓고 빈 캐시의 496B 선행 DMA를 회복할 수 있는지 먼저 확인한다. 기존 캐시는 OBJ가 이미 준비된 뒤의 240B 수락→SEAL→공개 경로를 따로 본다.
