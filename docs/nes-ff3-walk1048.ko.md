# FF3 1048 마을·필드 실기판

SD 루트에 설치 ZIP의 `sd2snes` 폴더를 덮어쓰고 전원을 껐다 켠다. 기존 FF3 한글판을 선택한 뒤 **L+R+START → STATE SLOT 1 → LOAD STATE**로 마을을 불러온다. 1047에서 저장한 순번 8의 슬롯을 그대로 쓴다. 아래로 걸어서 마을 출구를 지나 필드에서도 계속 걸으면 두 장소의 스크롤과 첫 전투 전환을 비교할 수 있다. **EXIT TO MENU**로 끝내면 `nes-progress-ff31048.txt`, `nes-game-last-ff31048.txt`, `nes-frame-ff31048.bin`이 남는다.

1047은 CHR RAM 한 곳에만 써도 양쪽 VRAM 뱅크의 일반 타일 이력을 모두 버렸다. 1048은 FPGA에서 1KiB 페이지 8개의 쓰기를 추적하고 수신 헤더에 포함한다. ARM은 변경된 페이지의 BG·OBJ 타일만 두 뱅크에서 무효화한다. ACK와 동시에 쓴 페이지는 다음 캡처에 포함되고, 잘못된 세대의 ACK나 폐기된 캡처는 변경 이력을 지울 수 없다. ARM은 한 화면에서 같은 일반 BG 태그를 다시 만나면 앞에서 확정한 슬롯을 재사용한다. 예외 타일은 원래 행별 검사를 거친다.

## 1047과 같은 입력으로 비교한 결과

| 구간 | 비교한 화면 | 타일 DMA 바이트 | ARM 계획 함수 실행 명령 수 |
|---|---:|---:|---:|
| 마을 | 11 | 10,736 → 7,568 | 2,941,981 → 1,773,437 |
| 필드 | 4 | 4,672 → 3,840 | 1,377,272 → 814,018 |

마을은 슬롯을 복원한 NES 코어의 캡처를 사용했다. 필드는 같은 슬롯에서 아래로 걷는 원본 게임의 224–227번째 화면을 기록하고 그 PPU 읽기와 레지스터 값을 보드의 캡처 RTL에 재생했다. 각 구간은 양쪽 출력 뱅크가 비어 있는 상태에서 시작했다. 두 최종 ARM 링크가 만든 map·OAM·CGRAM·HDMA·사용 타일 정의는 15장 모두 일치했다. 타일 DMA 바이트는 계획된 전송량이며, 명령 수는 계획 함수를 실제 ARM 명령어로 재생해 센 값이다. 실기에서의 SPI 대기와 VBlank를 포함한 표시 FPS는 1048 시험에서 측정한다.

Quartus Lite 전체 FIT는 15,290/15,408 LE, 963/963 LAB, 56/56 M9K다. STA 검사 57개의 최소 여유는 +0.139ns다. ARM Flash는 212,960/212,992B다. 8개 페이지, ACK와 쓰기의 동시 발생, 잘못된 세대, STOP 뒤 cold 복구, 64프레임의 전투 점멸, ARM의 저장 파일 입출력과 메뉴 복귀 경로를 검사했다.
