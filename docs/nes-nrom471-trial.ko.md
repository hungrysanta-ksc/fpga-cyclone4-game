# NROM471 설치·비교 시험

이번 전달본은 실제457 경로에 입력 압축과 ARM 단일 복원을 넣은 후보다. 기본 ROM은 **가로로 이동하는 세로 막대**이며 A를 누르면 붉은색, 놓으면 파란색으로 돌아온다. 소리는 합격 조건이 아니다. 약60초 RUN 뒤 자동 STOP과 메뉴 복귀를 확인한다. 적재·독립 readback 시간은 RUN 시간과 별도이며 기존처럼 몇 분 걸릴 수 있다.

## 설치

1. 전원을 끄고 기존 SD와 저장 자료를 PC에 백업한다.
2. `01-NROM471-MOVING-SD-ROOT` 안의 내용을 SD 루트에 복사한다. **firmware.stm과 fpga_nrom471.bi3를 함께 사용한다.** 입력 형식2232라 이전467 파일과 섞으면 안 된다.
3. 메뉴의 **NES NROM 471.nh1**을 실행한다. 이전227 항목은 이번 시험 항목이 아니다.
4. 막대 이동을 관찰하고 A를2초 누름→놓음을 몇 번 반복한다. 자동 메뉴 복귀와 같은 항목의 재실행 여부를 기록한다. 오류나 정지가 있으면 마지막 화면·경과 시간을 남긴다. BLOCKED_RESET_HELD 보호를 해제해 강제 재진입하지 않는다.

## 가져올 파일

각 실행 직후 아래 세 파일을 SD에서 PC로 복사한다.

- sd2snes/nes-progress-nrom471.txt
- sd2snes/nes-game-last-nrom471.txt
- sd2snes/nes-budget-nrom471.txt

가능하면 실행부터 메뉴 복귀까지 영상도 부탁한다. 반복 실행하면 같은471 파일이 갱신되므로, PC에 `moving-1`, `moving-2`처럼 폴더를 나눠 보관한다. 다음 전달 번호에서는 marker·로그 이름도 함께 바뀐다.

## 기존15fps와 같은 장면으로 비교하려면

기본 이동 장면은 기존 정적 화면과 부하가 다르다. 직접 속도 비교를 위해 `03-STATIC-COMPARE-SD-ROOT`에 **기존428 ROM과 바이트 동일한 기준 장면**을 별도로 넣었다. 이 폴더의 ROM만 SD에 덮어쓰면 새 ARM/FPGA로 기존 정적 장면을 실행한다. 실행 항목과 로그 이름은471이다. 먼저 이동 장면 로그를 PC에 보관한 다음 기준 장면을 실행하고 `static-1` 폴더에 세 로그를 저장한다. 이동 장면으로 돌아가려면01 폴더의 ROM을 다시 복사한다. 전체 firmware/FPGA를 다시 교체할 필요는 없다.

cost 로그의 `cost_scene_crc32_hex`와 manifest의 scene CRC로 장면을 구분한다. 이번 ROM은 둘 다 자체 제작물이다. 같은 장면 비교가 끝나기 전에는 움직이는 장면의 수치를 과거 정적15fps와 단순 비율로 비교하지 않는다.

## 로그에서 추가된 정보

10ms 기존 통계와 함께 opcode별 호출 수·바이트·cycle 합·최대값, 수신/계획/SEAL의 cycle 합을 기록한다. observer/screen의 직접 SPI도 포함한다. `cost_counter_available=0`이면 cycle 값으로 시간을 계산하지 않는다. cycle 합은 상·하32bit로 기록하며 phase와 opcode 시간은 서로 중첩된다. 둘을 더하면 중복 계산이다. CRC 오류와 deadline 등으로 D1 전송이 취소된 횟수도 구분한다. SD 기록은 RUN 뒤 안전한 base 복구 경로에서 수행한다.

## 복원

전원을 끄고 `02-RESTORE467-SD-ROOT` 내용을 SD 루트에 복사하면 지난 실기에서 동작한467 조합으로 돌아간다. 이때 실행 항목은 **NES GAME 227.nh1**이다. 보존164 기본 구성이 필요하면 `04-RESTORE164-SD-ROOT`를 사용하거나 설치 전 백업을 복원한다. 상용 게임 ROM과 저장 파일은 전달본에 포함하지 않았으며 SD를 포맷할 필요는 없다.

## 이번 결과의 범위

정적 기준에서 payload5764→1926B,25→10블록, 실제 M4 packet 해석 명령309514→270899를 확인했다. 이는 전체 FPS 개선율이 아니다. 새 실기 FPS·누락·전체 처리 시간은 이번 로그로 측정한다. 60fps 달성은 아직 확인하지 않았다.

최종 Lite FIT14740LE/13672comb/8063FF/185824 RAM bits. 실제 클록 기준 setup+0.081ns/hold+0.143ns지만 강화 배치 예산에−0.036ns가 남고 raw reset/CDC·미제약IO도 완전히 닫히지 않았다. 기존과 같은 제한 진단 시험용이며 장시간 안정성·전체 전기적 보증을 뜻하지 않는다. STOP·최종ACK·표시·클록 중단 및 base 복구의 기능/모델 회귀 결과는 기술 문서에 기록했다.
