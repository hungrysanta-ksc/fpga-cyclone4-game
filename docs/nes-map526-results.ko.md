# 526. 수락된 map 행의 64B 선행 전송

## 구현과 비교 조건

PR143의 병합 커밋 `ddaa251`과 실기 MMC524에서 분기했다. 524는 닫힌 명령만 먼저 보냈다. 526은 패킷 처리가 끝나 큐가 비었을 때 마지막 명령이 비활성 map이면 이미 수락된 맨 앞 64B를 우선한다. 마지막 명령이 tile이면 기존 큐 커서의 닫힌 명령을 선택한다. 열린 tile은 계속 보류한다.

각 DMA 직전에 STOP과 새 head를 다시 읽는다. 동기 DMA가 끝나면 부분 map 명령의 WRAM 주소와 VRAM 주소를 각각 64만큼 올리고 잔여 길이를 줄인다. 마지막 64B를 마친 tail은 제거한다. 미처리 항목이 하나도 남지 않았으면 목록 끝과 커서를 함께 초기화해 다음 패킷이 은퇴한 항목을 연장할 수 없게 했다. 기존 수신 행·뱅크별 유효성 비트맵은 그대로 유지하며 SEAL과 최종 표시는 기존 독립 검사를 통과해야 한다.

두 후보를 같은 905–957 입력과 두 시작 시각에 각각 실행했다. **232**는 MMC524의 기존 DMA 허용선을 사용한다. **254**는 64B map에 한해 254번 주사선까지 허용한다. 두 후보 모두 tile 허용선은 232번이고 최종 표시 검사선은 246번이다.

## 실제 표시와 대기

**판정.** 254 후보에서는 두 위상의 두 대상 화면 모두 map을 먼저 썼다. 952와 954는 여전히 SEAL에서 VBlank를 두 번 기다렸고, 그중 한 번은 최종 표시 단계였다. 954의 이전 표시부터 실제 PPU 공개까지의 간격은 첫 위상에서 한 주기 줄고 둘째에서 한 주기 늘었다. 최종 대기를 제거한 결과로 볼 수 없다. MMC524를 실기 기준으로 유지한다.

| 3,000,000 | 952 | 4행·256B | 254 → 253 | 9 → 9 VBlank (149.746 → 149.752ms) |

| 3,178,684 | 954 | 4행·256B | 256 → 254 | 7 → 8 VBlank (116.468 → 133.117ms) |

232 후보는 다른 화면에서 총 57/54행을 선행 전송했지만 952·954에서는 두 위상 모두 0행이었다. 254 후보는 전 구간에서 188/182행을 먼저 썼다. 952에서 최종 표시 준비 전 SEAL의 PPU DMA는 두 위상 모두 2,752→2,496B였다. 954에서는 2,704→2,512/2,448B였다. 모든 대상에서 최종 표시의 246번 검사선을 넘겼다.

각 위상에서 세 경로의 53개 RGB, 444개 타일 데이터, 1,689개 패킷 내용, 125,488B의 VRAM DMA가 일치했다. ROM read 배정은 5,616회, bulk 최대 점유는 2슬롯이었다. 254 후보는 첫 화면 후 PPU DMA 수가 689→868/861회로 늘었다. SPI 바이트는 첫 위상 536,646→536,586B, 둘째 532,410→538,446B였다. SysTick은 각각 509→509회와 503→511회였다. 마지막 ACK는 행 분할의 추가 설정, head 지연, 조회 횟수와 이후의 ROM·VBlank 위상 변화까지 포함한다.

**다음 비교.** 254 후보에서 첫 map 패킷이 큐에 도착하기 전에 952에서는 이미 네 번, 954에서는 두 번의 idle DMA가 실행됐다. 첫 idle 발행에서 첫 map 패킷 도착까지의 간격은 두 위상 각각 952에서 21.13/21.33ms, 954에서 2.68/2.79ms였다. 다음에는 ARM이 첫 map 범위를 안전하게 확정할 수 있는 시각과 실제 SPI 발행 시각을 분리해 측정한다. 이미 쓰이는 tile 공급·credit을 늦추지 않고 더 이른 blank에 map을 보낼 수 있는지 먼저 확인한다.

## 기능·회로 검증

실행 도중 각 선행 map이 이미 ACK된 DATA/RLE 패킷의 64B 행인지, 올바른 대상 뱅크에 한 번만 쓰였는지 추적했다. 실제 DMA 종료 직후 그 행의 VRAM 64바이트를 독립 map 원본과 비교했다. 전체 표시 때는 map WRAM·VRAM, HDMA, RGB, 최종 ACK를 검증했다. ARM·공유 SPI·SysTick과 2슬롯을 포함한다. 처리 시간은 ARM 명령당 2사이클과 부팅 중 기록한 ROM 허용 구간을 적용한 공동 시뮬레이션 결과다.

두 후보 각각 두 뱅크에서 DMA 직전 head와 STOP의 단독·동시 도착, 첫 PPU 쓰기 뒤 head·STOP, dirty cold 복구를 검증했다. 거절 때 이전 화면과 표시 identity를 보존했다. 192B 이상인 tail이 줄어드는 경우와 마지막 64B tail이 빠지는 경우를 따로 시험했다. 이미 보낸 map 행을 다시 수신하면 중복 비트맵이 거절한다. 초기화하지 않은 패턴을 참조하는 SEAL도 기존 bitmap 검사에서 거절됐다. 254번 후반까지 기다린 진단 ROM은 실제 PPU 쓰기를 255번에 시작해 256번에 마쳤다. 255·256번에 검사한 map과 233번에 검사한 tile은 발행되지 않았다.

Quartus Lite 전체 FIT·STA에서 두 후보와 MMC524 모두 15,164 LE, 14,172개 조합 함수, 8,394 FF, 264,816 RAM 비트와 51 M9K였다. 관련 경로 구현·명목 setup +0.078ns, hold +0.139ns도 같았다. 73개 보드 입력 중 소비 ROM 초기값만 달랐다. 65816 본체는 4,715B에서 4,811B(232) / 4,825B(254)로 늘었고 새 WRAM 할당은 없었다. MMC524와 각 후보에서 본체·초기값·실행 ROM·레이블을 바이트 단위로 재생성했다.

## 재현

1. [MMC524 재현 절차](nes-idle524-results.ko.md)의 ARM·plan·fixture·ROM 허용 일정을 준비한다. [526 생성기](../tools/nes_map526.py)를 기본 모드와 `--late-map`으로 각각 실행한다.
2. [공동 일정](../tools/test_nes_map526_schedule.py)에 같은 입력을 전달하고 시작 클록 3,000,000과 3,178,684에서 각각 53개 화면을 실행한다. [중재·독립 검사](../tools/test_nes_map526_priority.py)는 MMC524의 첫 위상 패킷을 사용한다. 254 후보에는 `--late-map`을 전달한다.
3. MMC524 보드에서 `sink-program.hex`만 바꾸고 Quartus Lite 전체 FIT와 `timing506.tcl`을 실행한다. [분석기](../tools/analyze_nes_map526.py)는 MMC524의 저장된 해시와 실행 조건, 각 후보의 실제 ROM·보드 입력을 대조한다. [기계 판독 결과](../analysis/map526-verification.json)
