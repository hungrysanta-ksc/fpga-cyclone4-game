## 전환 941과 밀집 950

ARM은 두 페이지 map 발행 뒤 마지막 credit 응답을 검사한다. 첫 페이지의 dirty 행이 0행부터 연속이면 여기서 스크롤을 발행한다. 중간에 빈 행이 있으면 기존과 같이 최대 96회까지 DMA 진행을 확인한다. 행 비트맵은 대기 예산을 고르는 데만 쓰인다. 완료 판정은 기존 CRC와 identity 검사를 거친 응답이 담당한다.

같은 바이너리에서 연속 행의 조회 한도를 96으로 되돌린 대조군과 비교했다. 두 위상 모두 SPI가 처음 달라진 곳은 941이다. 마지막 credit 뒤 95회, 1,900B의 E0 조회가 사라졌고 첫 스크롤 발행까지 259,881 / 259,882클록 걸리던 구간이 611 / 611클록으로 줄었다. SEAL 수락은 VBlank 118의 82 / 81선에서 VBlank 117의 154 / 153선으로, 공개는 119에서 118로 앞당겨졌다.

950은 두 위상 모두 직전 VBlank에 1,472B와 추가 64B를 전송했다. 첫 1,472B의 WRAM 주소, VRAM 목적지, PPU 포트 순서와 바이트 값은 종전 192+192+1,088B 전송과 일치했다. 950 공개와 밀집 마지막 ACK는 880 END와 클록 단위까지 일치했다. 952는 양쪽 모두 241선에 공개됐다.

## 남은 한 VBlank

- **전환 952**에서만 MMC872보다 표시 간격이 길었다(1→2회). 캡처 준비는 같고 planner 진입은 881이 3,066 / 4,165클록 빨랐다. MMC872는 BG 뒤 OAM 재사용 명령부터 발행하고 section 5 두 패킷을 보냈다. 881은 이 두 패킷 뒤에 OAM을 발행했다. SEAL 수락은 32,154 / 31,954클록(약 1.50 / 1.49ms) 늦어졌고 업로드 진입은 212 / 215선에서 235 / 238선으로 밀렸다. 다음 시험은 **map 패킷이 없는 화면에서 OAM을 먼저 발행**해 실제 개선량을 분리한다. 밀집 데모의 952는 다른 입력이다.
- **오프닝 위상 1**은 내부 세대 906에서 처음 표시를 놓쳤다. 1,808B BG 묶음의 생산 시각은 MMC872보다 346,032클록 늦고 ARM이 확인한 E8 완료는 349,715클록 늦었다. 생산 뒤 조회만 단축해 회복할 수 있는 양은 제한적이다. 다음은 128B E9 plan 발행과 마지막 BG 읽기의 ROM 허가 구간을 대조한다.
- **오프닝 위상 2**는 첫 세대 905에서 늦었다. 같은 BG 묶음의 생산 차이는 2,832클록이다. MMC872는 VBlank 36에 2,688B와 768B를 DMA하고 37에 잔여 832B·팔레트·OAM을 마쳤다. 881은 36에 768B, 37에 3,520B를 보내면서 512B 팔레트와 544B OAM이 38로 넘어갔다. 이 위상은 map 수락과 tile 사이의 순서, DMA 분할을 우선 확인한다.

## 검증과 재현

ARM Flash는 212,964 / 212,992B다. MMC872 보드와 65816을 사용했다. 두 위상에서 총 348장의 활성 RGB·map과 세대별 최종 ACK → EA → 재무장 → 다음 COMMIT 순서를 검사했다. ARM의 연속 행 credit 응답 5조건·불연속 행 10조건, 65816의 잘못된 범위·cold·부분 전송·STOP·재시작 12조건 및 ARM 메뉴 복귀 경로가 통과했다. 모든 시간은 실제 ARM·65816 바이너리와 기록 기반 ROM 경쟁을 결합한 재생에서 얻었다. 이번 판의 실기 FPS는 미측정이다.

1. `prepare_nes_mapgate881.py`에 880 END의 `link-credit/src`와 새 patch 경로를 준다. `build_nes_mmc479_arm.ps1`로 전체 링크를 만들고 같은 `client02`를 사용한다.
2. `replay_nes_table877.py TEMP PHASE WORK 881-range CLIP`으로 opening, transition, dense를 각각 실행한다. `replay_nes_mapgate881_control.py TEMP PHASE WORK`는 같은 링크의 전환 대조군이다.
3. 880의 ARM·메뉴·65816 가드를 새 링크와 881-range 패킷으로 실행한다. `guard_nes_scroll874.py`의 연속 행은 `--rows 0x7fffff`, 불연속 행은 `--rows 0x27fffff --progress-reads 96`이다. `test_nes_mapwait880.py TEMP PHASE --audit 881-range`로 PPU 쓰기를 채집한다.
4. `check_nes_mapgate881.py TEMP WORK analysis/mapgate881-results.json`으로 비교한다. [클록·패킷·DMA·검사 결과](../analysis/mapgate881-results.json)
