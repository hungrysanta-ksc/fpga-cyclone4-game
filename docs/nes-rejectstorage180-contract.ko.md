# NES180 — 기록 저장 공간 재사용 결과와 관측 범위 축소

두 구조 변경 후보 모두 기능 검증을 통과했지만 FPGA 채택 기준을 통과하지 못했다. 배포178을 유지하며 새 펌웨어·FPGA·ZIP은 배포하지 않는다. 첫 레벨 영상 정지와 약60fps 목표는 아직 미완료다.

| --- | --- | --- | --- |
| 기존 history RAM 출력으로 직전 오류 비교 | 실제 SPI 사건 기록·복구·취소·STOP·fault, 연속20쓰기와 RAM 읽기 지연, 무효 피드백 주입 통과 | 15,024 LE / 962 LAB / 36 M9K, 실제 클록 setup −0.227ns / hold +0.157ns | 미채택 |

RAM 후보의 합성 레지스터는 기존180 map02의8,458개에서8,438개로, 문맥 공유 후보는8,407개로 줄었다. RAM 사용량은205,568비트로 같았다. 그러나 레지스터 수 감소가 LAB 수·배선·타이밍 개선을 보장하지 않았다. 문맥 공유에서 추가되는 선택 논리와 연결을 함께 고려해야 한다. 그 선택 논리만이 967 LAB의 유일 원인이라고 단정하지는 않는다.

## 문맥 공유 후보의 규칙

기존 `first_ppu154[63:0]`는 `context_valid=0`일 때에만 기록기의 임시 상태로 쓴다. armed/owned-seen/first-seen/previous-bad 네 비트, 직전 오류25비트, 최초 관측 위치26비트를 배치한다. 새 observer `reg` 선언은 없고 별도 witness 인스턴스를 제거한다. 기존 history RAM·SPI 규격2·MCU는 유지한다.

첫 ROM 오류는 임시 기록보다 우선한다. 같은 클록에 기존64비트 PPU 문맥 전체를 저장하고 `context_valid`를 세우며 history를 동결한다. 오류 이후에는 새로운 프레임/오류 입력으로 문맥을 덮지 않는다. STOP과 오류가 같은 클록에 발생해도 원래 오류가 우선이다. `first_context`의 ROM 주소 문맥은 변경하지 않는다.

유효한 오류 문맥의 바이트는 기존과 같지만, **valid=0인 문맥의 payload는 이제 미정 값**이다. 이를0으로 보장하거나 유효한 기록으로 해석하면 안 된다. 이 계약 차이도 배포되지 않은 후보에만 해당한다. SPI74/75의 유효 문맥 값을 실제 테스트벤치에서 확인했다.

## 검증 범위와 보존

전체 후보 SV를 컴파일하고 실제 observer SPI를 통해 검증했다. 두 후보의 source 생성 재현과 변경 파일 제한, 관측기가 NES와 같은 클록에서 동작하는 점, 기존 게임 제어 경로 및4096바이트 SNES ROM MIF 보존을 확인했다. 모델 통과는 실기 표시 개선이나60fps의 증거가 아니다.

각 구조 후보에 FIT를 한 번씩 실행했다. 문맥 공유의 첫 실행 명령은 Windows PowerShell의 stderr 처리 때문에 MAP 시작 중 중단됐고, PowerShell7로 같은 입력을 실행했다. 이는 배치 seed 변경이나 추가 FIT가 아니다. 원래 오류 로그도 보존한다. 문맥 공유에는 유효한 배치가 없어 타이밍 수치를 만들지 않았으며, 두 후보 모두 조건부 IO·ASM·CPF·ZIP 단계로 진행하지 않았다.

기존 MCU180 ARM02의1,413개 소스와198,012바이트 실행 파일을 해시로 확인했다. ARM 여유1,040바이트, C 판독15경우·디코더4벡터, 최대 TXT3,920/4,096바이트는 기존 결과 재사용이며 새 시험으로 세지 않는다. GBC·세이브 SRAM·164 복구 및 배포178을 변경하지 않았다.

## 다음 작업 결정

여기서 ROM 로더 미세 조정·seed 변경·동일 입력 FIT 반복을 하지 않는다. 일반적인 사건 변경 기록에 필요한 직전 오류25비트와 최초 위치26비트를 모두 유지하려던 범위를 줄인다.

다음 후보는 **유효 geometry 뒤 첫 거부와 다음 정상 회복**만 기록하는 최소 상태를 우선 검토한다. 확정 오류 벡터와 수집 개수는 그 순간 기존 history RAM으로 직접 보내고, 중복 비교용 오류 벡터·최초 line/dot 저장은 제거한다. 거부가 이어지는 동안 오류 종류가 바뀌는 사건은 놓칠 수 있으며 최초 오류 위치도 얻지 못한다는 한계를 명시한다. 기존 규격의 위치로 오인하지 않도록 descriptor/MCU/디코더 규격을 함께 정한다. 아직 구현·승인된 후보는 아니다.

이 축소 기록으로 필요한 판단이 가능한지는 먼저179의 실제 ROM 전환 근거와 대조한다. 최소 기능·자원·타이밍 통과 뒤 숫자1 타일→A 실기로 진행한다. 목적은 fetch/compact/raster 중 실기에서 남은 거부 주체를 확인하는 것이다. 이후 공통 렌더링 중단·재개와 누락 fetch 표현을 구현한다. 화면 정지 해소와 별도로 앞단 차분/base-generation/최종ACK를 통한 약60fps 개선도 유지한다. 같은178·044 재시험이나 무입력 긴 부팅 모델은 요청하지 않는다.
