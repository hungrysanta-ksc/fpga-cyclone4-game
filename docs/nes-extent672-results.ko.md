# 672 수락된 map 범위·DMA 선택과 후속 발행 검증

**기능과 보호 조건은 통과했으나 두 위상의 종단 시간 동시 개선에 실패했다. MMC666을 유지한다.** 후반 VBlank에서 더 큰 수락 범위를 먼저 보내면 실제 선행 DMA는 증가하지만, 늦은 tile·ordinary·SEAL 수락 때문에 표시 VBlank는 줄지 않았다. 후보의 전체 FIT/STA·실기 ZIP은 진행하지 않는다.

## 구현과 비교 경계

MMC666 ARM과665 FPGA는 그대로 두었다. 65816의233–252번 선 선택 코드49B를 대체하고80B helper를 추가했다. 앞쪽 명령과 마지막 map descriptor의 이미 수락된 길이를 비교해 최대1152B를 고른다. 같은 전송 길이에서는 기존 선택을 유지하되, tail 원래 길이가1152B보다 크면 상한 동률에서도 tail을 선택한다. 232번 선까지의 작은 tile/기존 head 우선, fresh beam 검사, STOP·새 패킷 재확인, 동기 DMA 완료 후 descriptor 갱신은 그대로다. 수신·검사·DMA·최종 ACK 본체 바이트가 변경 범위 밖에서 정확히 같은지 확인했다.

단순 길이별 모델 대신 실제 링크 ARM·65816을 두 시작 시각7288416/7467100에서53개씩 실행했다. CPI2·실제 SysTick 코드의 경계 dispatch·공유 SPI·반복 ROM 허용 달력은 기존과 같다. map·OBJ 작업량과 canonical 출력 바이트,106개 최종 map/화면을 독립 대조했다. 원본665 재생의 ARM은664 all 명칭이지만 MMC666과798개 함수 주소·크기·코드가 같고,668의 새 MMC666 대조군은53개 최종 ACK 시각까지 원본과 일치했다. 시험판 문자열 때문에 firmware hash는 서로 다르므로 전체 hash가 같다고 주장하지 않는다.

실기26.84ms를 이 재생의 비율로 나누지 않는다. 새 FPGA 동시 실행·물리 FPS·새 실기 메뉴 복귀 시험은 아니다. 원본 ROM 경쟁은 측정 달력 모델이며 전체 PSRAM RTL 경쟁 검증을 대체하지 않는다.

## 수락 범위와 발행 시각의 대조

위상2의954 원본은238번 선에 offset896의128B를 선택했다. 같은 시각 offset2048부터1152B가 이미 수락돼 있었다. 이어251번 선에 offset1600의64B를 보냈지만, 큰 범위는 후속 패킷 때문에 다음 실행으로 남았다. 후보는241번 선에 offset2048의1152B를 실제 DMA했다. 이 한 구간에서 작은128+64B 대신1152B를 보내 선행량이960B 늘었다. 독립 coverage와 실제 VRAM 바이트도 일치했다.

그러나 마지막 OBJ 및 section5 ordinary 수락이 뒤따른다. MMC666 위상1에서954 마지막 ROM 응답은 직전 표시 후36.111ms, 마지막 OBJ의 준비/발행 시작/수락/ACK는37.875/37.889/38.033/38.987ms다. 이어1100B 패딩은39.022–40.518ms,240B 테이블은42.427–42.801ms에 소비되고 SEAL 수락은43.155ms다. 957은 마지막 ROM 응답33.751ms, 마지막 OBJ ACK36.749ms, SEAL 수락41.069ms다. 이 준비·수락 값은 JSON의 실제 ARM/65816 사건에서 얻었으며 데이터가 그보다 앞서 의미상 확정됐다는 증명은 아니다.

현재 표시보다 한 번 앞선 VBlank **끝**과 비교해도, 원본954 SEAL 수락은 두 위상 최소8.814/8.719ms 늦고957은6.562/7.226ms 늦다. 마지막 tile ACK도954는4.646/4.551ms,957은2.241/2.360ms 늦다. 수평 위치가 없는 window trace에는 VBlank 끝을 최대 한 주사선 늦게 잡는 보수적 상한을 사용했다. 따라서 이 수치는 부족 시간의 하한이며 검사·남은 DMA 시간까지 포함한 충분 예산이 아니다. 246번 공개선을 요구하면 더 앞당겨야 한다.

**선행 map DMA 확대만으로3→2 VBlank를 만들 수 없는 이유가 확인됐다.** 957의 마지막 추가 대기0회는 모든 업로드 대기가 사라졌다는 뜻이 아니다. 두 위상에서 더 큰 범위를 고르는 선택기만 반복하거나 주사선 제한을 늦추지 않는다.

## 안전·복구 검사

- 106개 연속 화면에서 실제 수신/독립 검사/VRAM/최종 ACK와 두 bulk 슬롯 상한을 통과했다. 911 SEAL 수락은189→186/187선, 검사 후 진입은214→212선이다. 951 공개≤246,952 표시3회,957 최종 대기0회를 유지했다.
- 실제 cold 패킷 순서를 바꿔 작은 앞쪽 map과 큰 뒤쪽 map이 함께 존재하게 했다. 뒤쪽1152B 전송, 범위 축소/retire, 새 패킷 우선, STOP+새 패킷 동시 도착, DMA 도중 STOP을 검사했다. 실행 중 DMA는 끝내고 후속 packet ACK 없이 quiet로 들어가 이전 표시 뱅크를 유지했다.
- partial DMA·STOP의 실제 WRAM/VRAM 상태에서 cold 재시작해905/906 전체 화면을 다시 복원했다. 두 뱅크의 SEAL 준비/최종 ACK 직전 STOP4조건을 확인했다.
- 기존 head 경계8조건은252/253선의 허용/차단과 누락·중복 coverage 거부를 포함한다. 252선 수평1146에서 MDMA를 시작한 경우와252선 수평1162에서 beam을 읽은 경우를 별도로 시험했다. 후자의 마지막 VRAM write는261선 수평428로 VBlank 안이며 STOP 뒤 새 head ACK는0이다. 모든 대기 정렬은 fixture만 변경하고 실제 진입 시 원본 CPU 프로그램 전체를 대조했다.
- 캡처 회복·ARM 메뉴/base 경로와 보드 HDL은 변경하지 않았다. 이 부분은 기존 MMC666 근거를 유지한다. 후보의 새 실기 메뉴 복귀 성공으로 확대 해석하지 않는다.

## 자원과 채택 판정

ARM Flash212496B/여유496B, data10040/BSS19544B는 동일하다. 새 runtime 버퍼는 없고 helper의 임시 stack2B는 복귀 전에 해제된다. 연속 재생의 관측 SNES stack 최대는 원본/후보 모두11B다. WRAM body는5792→5872B(한도5984B), 기존49B 자리는 점프와0으로 대체해 압축 후 물리 ROM 여유는11→42B다. 이것은5120B ROM 형식의 용량 확인이며 새 회로 합성 결과가 아니다.

MMC666 선택 보드는15324LE·962LAB·56M9K, setup+0.511/hold+0.149/recovery+1.828/removal+0.393ns다. 후보는 ROM 내용이 바뀌므로 채택하려면 ROM을 포함한 전체 Lite FIT/STA가 필요하지만, 이번 시간 게이트 실패로 실행하지 않았다. 새 회로 절감·전체STA 통과·실기 성능을 주장하지 않는다. 원래 선택본과 ZIP은 변경하지 않았다.

## 다음 한 단계

MMC666에서954·957의 **마지막 BG/OBJ 생산 가능 시각과 ordinary 내용 확정 시각**을 먼저 분리한다. 현재 준비 함수가 호출된 시각을 데이터 확정 시각으로 간주하지 않는다. ROM 응답→plan/bulk credit→tile 발행·수락, section5 원본 확정→packet 준비→SPI/queue 수락의 의존성을 연결하고, 두 경로를 함께 앞당겼을 때 이전 VBlank의246선까지 갈 수 있는 하한/필요 절감량을 먼저 계산한다.

일괄 drain,672 선택 순서의 상수 변형,검사선 완화,671 SNES CRC/변환 루프 미세조정은 보류한다. 새 일정은911 마감·951 공개선·952≤3회·957 최종대기0회·STOP·독립검사·최종ACK·메뉴 복귀와 두 위상 전체 개선이 확인돼야 구현/전체 FIT/실기로 진행한다. 이번 결과로 DMA 선택기의 개선 여지가 모두 소진됐다고 일반화하지 않는다.
