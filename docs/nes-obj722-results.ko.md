# NES722 Flash 회복·DMA 진행 기반 OBJ 조회

## 목표

721D의 Flash4B 초과를 없애고,719의 map 연속DMA·951 공개·911 표시 조건을 유지한다. 같은 작업량과 두 시작 위상에서952–957 표시 간격과957 마지막ACK를 함께 비교한다.

## 작업내용

722C는721D의 실제DMA 진행bit·현재sent==retired 조건과전체12B token 검사를 유지한다. E9의 중복CRC16 비트 순회를 삭제하고 E1에서 이미 사용 중인 `crc_xmodem_block(0xffff, payload, length)`를 호출한다. 다항식0x1021·seed0xffff·검사 범위·CRC 저장 순서는 같다. 기존 테이블·어셈블리·헤더는 변경하지 않았으며 새 테이블 비용은 없다.

실제 수정은 `nes_plan_service200.c` 한 파일이다.719 planner/sink/runtime/window,707D RTL·SDC,기존65816을 유지한다. 조회 성공의 flags 공개도 한 곳으로 묶었지만 컴파일 결과만으로 그 부분의 절감을 주장하지 않는다. 대기 상수·주사선·세대별 예외는 바꾸지 않았다. 진행bit는 모든map 완료나 표시 허가가 아니며,새E1 뒤counter가 다르면 이전bit로OBJ 조회를 앞당기지 않는다.

기존 CRC 어셈블리는 양수 길이를 요구한다. 실제E9 record는 모두 비어 있지 않으며 count0의flush는 호출 전에 반환한다. 새 linked ARM 시험은1–240B 모든 길이를 독립 비트 CRC와 비교하고 빈flush가SPI를 발행하지 않음을 검사한다. 실제 E9 endpoint도 각 패킷의CRC16/CRC8·count·generation을 독립 검사한다.

실제 링크M4·65816,기존CPI2/84MHz·SPI/IRQ 비용모델·같은ROM 달력과 시작7288416/7467100을 사용한다. 전체보드RTL 동시실행·물리IO·실기FPS를 새로 증명하는 시험은 아니다.

## 성과

**Flash 초과와 map 연속 DMA 회귀는 해소했지만, 두 위상의 표시 간격·마지막 ACK 동시 개선에는 실패했다.** 722C는 기능·자원 검증 후보로 보존하고, 선택본은707D·기존ARM/65816을 유지한다. 새 설치본은 만들지 않았다.

## 후속작업

1. **Flash4B 문제는 종료한다.** CRC 공유와719 map우선·721D의오래된진행정보차단을검증된후보로보존한다. 같은분기표현·CRC미세조정·대기상수반복은재개하지않는다. 제품선택은동시시간개선까지보류한다.
2.953은OBJ계획수락23.515/23.524ms부터첫읽기33.730/33.770ms까지10.214/10.246ms가남는다. 마지막BG ROM 응답은앞당겨지지않았다. **BG의직전ROM허용마감과두bulk뱅크소유권**을함께맞춰야하며,이대기전체를ARM계산이나외부ROM읽기비용으로간주하지않는다.
3.956은OBJ계획수락23.744/23.719ms직후읽기를시작하지만마지막응답36.832/36.824ms,마지막tile ACK40.428/40.426ms,SEAL43.487/43.485ms다. 후속bulk수락·map DMA·ordinary공급을함께앞당길경계가필요하다. 이번OBJ읽기80건과953의112건은`OBJ_capture`캐시이며PSRAM경쟁으로잘못분류하지않는다.
4.한회차앞246선말미를낙관마감으로잡아도953 SEAL은최소9.605/9.717ms,956은9.654/9.653ms앞당겨야한다. 이후검사·DMA비용을0으로둔하한이며시간을보장하는예산이아니다. **map연속발행을깨지않는BG선행계획·bulk소유권해제구조**를먼저검토하고,이규모의여유를만들근거가있을때만다음구현을진행한다. 준비된OBJ즉시삽입은721A의회귀근거로계속기각한다.

다음후보도두위상952–957합계18회미만·밀집평균·마지막ACK동시개선과911/951/952/957·7블록·독립검사·STOP·메뉴복귀를같은바이너리에서확인한다. 새전달은새파일명의60초/장시간판·RESTORE제외·5–40초/40–55초집계정책을유지한다.
