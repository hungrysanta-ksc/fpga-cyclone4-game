# FF3 저장 SPI와 스프라이트 RAM의 전체 보드 비용 (1042)

Quartus Lite 25.1의 EP4CE15F17C8 전체 FIT에서 1041 대비 623 LE와 39 LAB를 줄였다. 선택한 보드는 15,468 LE와 976 LAB를 요구한다. 장치 한도는 15,408 LE와 963 LAB다. 배치 실패로 배선 후 STA, SD 재선택부터 같은 장면 복원까지의 실기 검증, 설치본 생성은 남아 있다.

| 전체 보드 | LE | 필요 LAB | M9K | 확인한 변경 |
|---|---:|---:|---:|---|
| 1041 | 16,091 | 1,015 | 56 | 이전 FF3 후보 |
| 1042 owner | 16,042 | 1,012 | 56 | SPI의 중복 워드·인덱스 보관 제거 |
| cursor | 15,906 | 1,009 | 56 | 저장 파일 워드 위치에서 RAM 주소 생성 |
| oam | 15,974 | 1,007 | 55 | 기본 OAM과 반복 스프라이트 판정의 읽기 포트 공유, 시각 기록 RAM 배치 |
| **secondary-final** | **15,468** | **976** | **56** | 보조 OAM 하위 32바이트를 두 포트 M9K에 배치 |
| extra | 15,456 | 978 | 56 | 상위 32바이트까지 RAM 사용, 시각 기록을 논리로 이동 |
| rowvalid | 15,470 | 977 | 56 | 상위 OAM 행 단위 유효 표시와 바이트 지우기 |
| shared-extra | 15,528 | 981 | 56 | 기본 OAM의 여유 주소에 상위 보조 행을 복제하고 유휴 포트로 읽기 |

두 방향 32비트 OAM 포트에서 행 복사도 담당한 별도 후보는 M9K 59개가 필요했다. SPI 복원 워드를 바이트 단위로 공유한 후보도 1,011–1,015 LAB를 요구했다. 다음 비교의 기준은 `secondary-final`이다.

## 저장과 복원

코어가 응답을 받을 때까지 파일 워드와 주소를 유지한다. SPI는 응답 시작 때 상태를 고정한다. 프레임 도중 준비된 다음 워드는 다음 응답에서 공개한다. 전체 프레임 길이·CRC·방향·워드 인덱스·데이터 에코가 맞아야 저장 워드를 반환한다. 복원 데이터는 전체 프레임을 수락한 뒤에만 코어로 넘어간다. 워드 번호와 영역 안의 하위 바이트 위치에서 실제 RAM 주소를 생성한다.

실제 SPI와 VHDL 순회기를 연결해 저장 2,658워드 및 복원 2,658워드를 대조했다. 지연 응답 중 데이터 안정성, 다른 인덱스, 잘못된 에코와 CRC, 부분 응답을 검사했다. 사용자 FF3 ROM을 실행한 별도 혼합 언어 시험에서는 일곱 부분 복원 위치에서 STOP 후 cold 재시작을 확인했다. 전체 복원 후 배터리 8,192바이트, 재개한 CPU 명령 인출 64회와 두 프레임의 표시 픽셀 122,880개가 연속 실행과 일치했다. 호스트 파일 시험은 손상된 최신 사본의 이전 세대 복구, 슬롯·ROM 분리, CRC 및 워드 순서 오류 격리를 확인했다.

## OAM 포트와 다음 작업

1041과 1042의 OAM을 같은 입력으로 179,208도트 구동했다. CPU 주소 변경 43,334회, 스프라이트 반복 확인 914회, 추가 스프라이트 8개 행의 읽기를 포함한다. 저장 상태에서 재개하는 경계도 따로 만들어 평가 쓰기와 복사가 같은 주소와 서로 다른 주소에 동시에 발생하는 경우를 각각 한 번 확인했다. PPU 출력과 독립 대조값이 일치했다.

PPU가 기본 OAM 바이트를 가져오는 도트와 스프라이트 반복을 판정하는 도트에서 같은 읽기 포트를 쓴다. 남은 메모리에 보조 OAM 하위 32바이트를 두었다. PPU 활성 에지에서 평가 쓰기와 행 복사 요청을 잡고 다음 하강 에지에 기록한다. 같은 주소에 쓰기가 겹치면 기존 평가 쓰기가 이긴다. 다음 활성 에지 전 유휴 클록에서 두 읽기 주소를 다시 샘플한다. 상위 32바이트의 추가 스프라이트와 기존 유효 비트 처리는 유지한다.

다음 면적 검토는 56개 M9K를 모두 사용하는 이 후보에서 출발한다. 배치 전 보고서상 저장 SPI는 조합 함수 279개, RAM 선택기는 216개, 화면 계측은 269개다. 호스트가 화면을 정지하고 큐를 비운 뒤 저장 SPI를 사용하는 구간과 실행 중 계측 응답을 내보내는 구간에서 실제로 겹치는 직렬화·응답 저장을 먼저 계측한다. 클록 경계와 실행 중 조회를 포함한 소유권을 확인한 뒤 전체 FIT로 절감량을 판정한다. 배치 후에는 보조 OAM의 상승→하강 및 하강→상승 경로를 포함해 STA를 확인한다. 이후 메뉴의 일반 저장과 강제 저장·불러오기, SD에서 FF3 재선택·같은 장면 복귀 순서로 검증한다.

재현 도구는 `tools/prepare_ff3_display1037.py`, `tools/fit_ff3_display1037.ps1`, `tools/check_ff3_display1037.ps1`, `tools/check_ff3_checkpoint_rtl.ps1`, `tools/check_nes_savefile1036.py`다. 원본 보고서와 기능 로그는 작업 루트의 `probes/nes-ff3-1042/`에 있다. 소스에서 다시 생성한 보드 입력 99개가 `lite-secondary-final` 합성 입력과 바이트 단위로 일치했다.
