# NES172 표시 프로그램 시작 계약

실기 결과 추가: NES172 실기에서 표시 준비와 14회 표시 완료 응답을 통과했지만 이후 화면이 멈췄다. 버튼·스테이지 음악은 계속 반응했고 정상 약60초 한도로 메뉴에 복귀했다. BEGIN/END/COMMIT 각14, ABORT0, 마지막 generation27이다.170의 수집 시간 초과와 달리 다음 BEGIN이 수신되지 않은 경계이며, 연속 화면 목표는 미달성이다. [분석과 다음 작업](nes-game172-hardware01.ko.md). 아래 내용은 배포 당시 계약·안내로 보존하며 같은172 재시험은 요청하지 않는다.

171의 첫 BEGIN은 정상 CRC의 F6/flags01 상태로65536회 응답을 기다리다 종료됐다. FPGA의 요청 보관은 확인됐지만 SNES의 부팅·복사·요청 읽기·ACK 게시 중 정확한 실패 위치는 미확정이다.172는 이 경계를 구분하고 준비되지 않은 소비자에 첫 패킷을 보내지 않도록 한다. 근본 원인 수정 완료나 연속 화면 성공을 주장하지 않는다.

## 구현

- SNES ROM은 초기 레지스터 설정 뒤 `$7000=1`을 기록한다. 기존 MVN으로3163바이트를 WRAM7E:2000에 복사하고, 원본00:8100과 모든 바이트를 비교한다. 불일치하면 `$7000=E1`을 기록하고 MCU가 정지·메뉴 복귀를 수행할 때까지 대기한다. 잘못 복사된 코드를 실행하지 않는다. ROM 자체의 물리 읽기 일관성까지 증명하는 검사는 아니다.
- 정상 복사 후 기존 WRAM 진입 기록2와 SPC 초기화를 거쳐, 메타데이터 초기화가 끝나면3을 기록한다.3은 첫 패킷 수신 준비이며 TV 표시 완료가 아니다. SPC 실패는 기존대로 오류를 기록하고 영상 준비를 계속한다.
- MCU는 기존 상태/ROM 오류 감시를 유지하면서3을 기다린다. 최대500틱(5초) 또는65536회이며 클록 정지에도 유한하게 종료한다. E1은 즉시 실패한다. 기존 오류를 보존하고 없으면 `run_first_error=6`, `native_result=2(SERVICE)`를 기록한다. 준비된 뒤부터 기존60초 실행 한도를 시작한다. 자동 재시도·대기 한도 증가·CRC 완화는 없다.
- 새 영구 버퍼가 없으며 준비 검사 함수는 `noinline`이다. 초기 인라인 빌드는 스택 여유1008바이트로 기준에 미달하여 미채택했다. 최종 ARM02는 기존과 같은 RUN37320+IRQ508, 여유1024바이트다.

172 펌웨어와172 ROM을 함께 사용한다. 이전169 ROM은 준비 단계3을 기록하지 않아 혼용하면 준비 대기로 종료된다. FPGA SPI 프로토콜·ID74·171 FIFO·CPU/PPU 우선권·PSRAM 감시·SNES 표시 알고리즘은 유지한다. ROM MIF만 갱신하여 기존171 배치/배선/타이밍65개 파일이 동일하다. 새 MAP/FIT/STA는 실행하지 않았고 기존 조건부 IO/CDC 한계도 그대로다. 별도 세이브 SRAM/GBC/164는 변경하지 않는다.

## 검증과 한계

- 실제65816: 정상1→2→3 및 첫 BEGIN ACK, 첫/끝 복사 바이트 오류1→E1·ACK 차단, SPC 초기화 실패 후 영상 준비 지속4경우 통과.
- 실제 C 준비 검사: 즉시/지연 준비, 틱 순환, 복사 불일치, 서비스/상태 오류, 틱 정지 상한, 단계1/2 정지9경우 통과.
- 실제65816/C 표시 연결:6회 표시·270ACK, 대형 갱신6개 청크를 포함해 기존169 픽셀 기준과 일치했다. 기존 기준은 재사용했고 SPI/실제 보드/FPS 검증이 아니다.
- 최종 ELF·RUN/IRQ·13개 기존 라이브러리/플랫폼 함수 대조와 최대 TXT4020/4096바이트 통과. ROM MIF4096바이트·패키지 압축 왕복·원본 ROM/164 복원 파일 해시 보존 확인.
- 첫 에뮬레이터 실행은 Unicode 경로에서 결과 없이 끝났으며 ASCII 경로로 재실행했다. 두 번째 실행의 잘못된 client 경로, 샌드박스 SUBST/DLL 실패와 초기 스택 기준 실패는 비공개 근거에 보존한다. 이를 RTL·라이선스 장애나 실기 실패 원인으로 해석하지 않는다.

실기에서 단계0이면 reset 해제/ROM 읽기 경계,1/E1이면 복사 경계,2이면 WRAM 초기화,3 이후 실패면 패킷/ACK 경계로 우선순위를 정한다. 단계 기록 자체의 버스 수신 문제도 가능하므로 단독 원인 확정은 피한다. 같은171·044 재시험 없이 [172 실기 안내](nes-game172-ready.ko.md)에 따라 실제 SMB3 결과를 받는다. 연속 AV 후 장기 실행·오류/본체 리셋 로그, 마지막으로 입력 유지를 확인한다.
