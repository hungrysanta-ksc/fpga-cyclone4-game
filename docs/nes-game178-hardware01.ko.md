# NES178 실기 — 월드맵 표시 성공, 레벨 정지 뒤 월드맵에서 회복

사용자는 월드맵 진입에 성공했고, 첫 레벨에 들어가자 영상이 정지했다고 보고했다. 이후 게임 오버로 월드맵에 돌아오자 영상이 다시 움직였다. **178의 표시 설정 수정으로 진행 가능한 장면은 늘었지만, 레벨의 지속 영상은 아직 실패다.** 같은 종류의 표현 제약이 더 남아 있을 가능성이 높으며, 실제 원인이 여러 개인지는 아직 확인하지 못했다.

## 이번 로그에서 확인한 사실

| 항목 | 값과 의미 |
| --- | --- |
| BEGIN / END / producer COMMIT | 각각70회 |
| SNES 표시 완료 |69회, 마지막 generation1793 |
| 마지막 표시 완료 시간 | RUN 시작 후59.65초 |
| DISPLAY 구간 |60.05초; 결과DEADLINE1 |
| ABORT / ROM / receiver / video 오류 |0 |
| 마지막 미완료 전송 | generation1794, serial70, DATA/MAP offset1440,240바이트 |
| 마지막 sink 상태 | error2, ACK 미수신, io09/POLL_TRANSFER·시도1회 |
| 종료 절차 | STOP·기본 FPGA 복구 성공; 메뉴 준비는 실행295.53초 |

177은 마지막 표시가12.48초였지만178은 종료 직전까지 표시 완료가 있었다. 장면·입력 순서가 다르므로 횟수 증가를 속도 향상으로 판단하지 않는다. 사용자 관찰과 합치면 **영상 경로가 영구적으로 멎었다기보다 특정 장면에서 출력할 수 있는 후보가 없어지고, 장면이 바뀌면 회복하는 경우**를 우선 조사할 근거다. 로그에는 장면 이름별 표시 타임라인이 없어69회 중 어느 화면이 언제 표시됐는지까지 확정하지 않는다.

`native_sink_error=2`를 레벨 정지 원인으로 바로 해석하면 안 된다. 실행의 최초 결과는DEADLINE1이며, 전송 래퍼는 실제 SPI 전후의 시간 검사에서도 false를 반환한다. 마지막 DATA 준비 도중 한 번의 poll에서 이 값이 남았고 ACK는 수신하지 않았다. **마지막 오류는60초 종료의 후속 상태와 일치하며 CRC 오류·잘못된 ACK의 증거가 아니다.** `sink_trace_ack_hex=0...`도 실제로 받은0바이트 ACK가 아닌 미수신 자리값이다.

`screen_error=169`는SPC 초기화A9이고, `screen_frames=0`은 신뢰하지 않는 과거 계측이다. 이번 메시지는 게임 내부 월드맵 복귀를 확인한 것이며 SNES 메뉴의 실제 화면 복귀와 사운드 정상 여부를 별도로 명시한 것은 아니다. 로그에서 확인한 메뉴 준비와 사용자 눈으로 본 메뉴를 구분한다.

## 마지막16클록의 해석

모두 scanline6/dot251~254, exporter VALUE, owned1/raw geometry_valid1/initialized1이다. tx와 host는 valid1/ready0이고 fill_busy·fill_abort·arbiter_fault는0이다. 이는 종료 시점에 다음 유효 후보와 전송 데이터를 보유한 상태이며, MCU가 앞 후보를 SNES에 전달하는 동안에도 나올 수 있다. **레벨에서 정지하기 시작한 순간의 표본도, 전송 교착의 증명도 아니다.** 마지막59.65초 표시 완료와 함께 읽어야 한다.

## 아직 구분하지 못한 조건

- **표시 설정·변경 시점:** 178은 한 프레임 전체1e/18만 허용한다. 다른 mask, 화면 위아래 사이의 변경, 한 주사선 도중의 변경은 별도 조건이다.
- **장면 표현:** 팔레트 시점·backdrop 변경, 스크롤·CHR 패턴 분할, 객체·타일 예외·묶음 개수가 수집기의 표현 범위를 벗어날 수 있다.
- **수집 완료·결합:** 장면 전환 뒤 불완전한 행이나 plane pair 등으로 후보가 계속 거부될 수도 있다.

이것들은 코드에 실제 존재하는 제한이지만 **이번 레벨에서 무엇이 걸렸다는 증거는 아니다.** ABORT0/MCU video_error0만으로 모든 수집 후보가 정상이라고 할 수 없다. BEGIN 전에 거부한 후보는 이 값들에 포함되지 않는다. 렌더링이 복잡하다는 이유만으로 전송량 초과나 MMC3 IRQ 오류라고 단정하지 않는다.

속도 문제도 그대로 남아 있다. 누적 build/pattern staging4,140ms, 성공한 seal/ACK10,550ms, 수신·폴링43,890ms다. 마지막70번째 후보는 build 뒤 seal의 DATA 전송 중 종료돼 집계 경계가 서로 다르다. 이를 단순히 같은69프레임 비용으로 평균 내거나69/60을TV FPS로 삼지 않는다. 이전의 초기 끊김과 약60fps 목표는 계속 미완료다.

## 다음 작업

1. 모델에 **현재178 수집기**를 적용하고 정상 직렬 입력으로 월드맵→첫 레벨까지 진행한다. 앞선100프레임 재현은 플레이어 선택까지만이므로 레벨 지원 근거로 재사용하지 않는다. 이미 통과한 무입력 도입부만 다시 검사하지 않는다.
2. 레벨의 최초 거부 후보에 대해 generation·실제 mask와 행간 변경, fetch/compact/raster 오류, 묶음·객체·예외·팔레트 개수를 한 번에 대조한다. 그 뒤 정상 후보가 다시 만들어지는 경계까지 본다. 하나씩 허용 비트를 추측해 실기판을 반복하지 않는다.
3. 모델에서 재현되지 않을 때만 이 최초 거부 경계의 최소 정보가 유지되도록 기존 종료 로그 관측을 보완한다. 마지막16클록을 최초 실패 기록으로 오인하지 않는다. 원인을 확인한 뒤 해당 표현만 수정하고 SMB3로 돌아간다.
4. 앞단 테이블 차분·기준세대·최종ACK 기반 성능 개선은 별도 목표로 유지한다. 영상 정지만 해소했다고 연속 AV를 완료 처리하지 않는다.
