# MMC907 후반 두 화면의 OBJ 준비와 최종 ACK

MMC905와 MMC907의 모험도 4 무입력 실기 기록을 시작 tick, 표시 뱅크, BG·OBJ·변경 map 수, 타일·묶음 수, 마지막 OBJ의 크기와 offset으로 짝지었다. 두 쌍에서 마지막 OBJ 준비 이후의 시간이 모두 늘었다. 전체 시간의 방향을 가른 것은 첫 타일 계획(E9)부터 마지막 OBJ 준비까지의 시간이었다.

| 실기 시각과 세대 (905 → 907) | BG / OBJ / 변경 map | 입력 완료 → 첫 E9 (ms) | 첫 E9 → 마지막 OBJ 준비 (ms) | 마지막 OBJ 준비 → ARM 유효 최종 ACK (ms) | 입력 완료 → ARM 유효 최종 ACK (ms) |
|---|---|---|---|---|---|
| 56.30초 · 1073 → 1209 | 529 / 18 / 7 | 10.654–11.580 → 10.655–11.581 | 26.526 → 29.257 | 11.916–12.855 → 20.498–21.437 | 50.036 → 61.349 |
| 57.67초 · 1090 → 1232 | 528 / 10 / 5 | 8.942–9.868 → 17.512–18.438 | 44.861 → 19.505 | 11.526–12.465 → 20.498–21.437 | 66.267 → 58.453 |

56.30초는 뱅크 0, 6타일·4묶음, 마지막 OBJ 64B다. 57.67초는 뱅크 1, 9타일·3묶음, 마지막 OBJ 32B다. 둘 다 마지막 offset은 288이다. 57.67초에 입력 완료부터 E9까지 8.57ms 늘어난 배경은 이전 화면과의 중첩이다. MMC907은 이전 화면의 유효 ACK가 오기 7.973–9.070ms 전에 다음 입력을 끝냈다. 이전 ACK부터 첫 E9까지는 두 판 모두 8.990–9.929ms였다. 이전 ACK부터 현재 ACK까지는 65.768–66.865ms에서 49.384–50.481ms로 줄었다. 56.30초에는 이 간격이 49.384–50.481ms에서 60.696–61.794ms로 늘었다.

두 실기판은 FPGA의 첫 E9·마지막 OBJ 준비·조회 시각 및 ARM의 입력 완료·유효 최종 ACK 경과 시간을 기록했다. 표의 범위에는 FPGA 시계의 양자화와 SPI 조회 폭을 반영했다. 55–60초에 마지막 OBJ와 양의 공급 시간이 기록된 65개·78개 표본 전체의 OBJ 준비 후 ACK까지 중앙값 범위도 11.526–12.849ms에서 20.498–21.437ms로 이동했다. 서로 다른 실행의 표본 분포이므로 같은 화면끼리 비교한 값은 위 두 행이다.

## DMA와 VBlank를 식별할 수 있는 범위

MMC905·907 BIN에는 이 두 세대의 PPU DMA 시작·종료, 표시 VBlank 번호, 65816이 ACK를 쓴 시각이 없다. ARM이 확인한 ACK는 65816 공개 이후다. 따라서 약 9ms 중 몇 ms가 실제 VBlank 대기였는지는 이 두 BIN만으로 확정할 수 없다.

다른 실기 계측판인 MMC901에서 같은 뱅크와 같은 BG·OBJ·map 수인 가까운 표본을 찾았다. 직전 화면 공개를 0으로 두면 56.32초는 SEAL 32.018ms, 마지막 DMA 종료 49.786ms, 공개 49.902ms, 65816 ACK 50.036ms였다. 57.58초는 각각 33.451, 49.652, 49.774, 49.908ms였다. 둘 다 세 번째 VBlank에 공개했다. 이 판도 첫 DMA 시각은 기록하지 않았다.

MMC907 최종 링크와 65816 코드를 같은 시계로 재생해 잔여 DMA 구간을 따로 측정했다. 이 재생의 마지막 화면은 게임 캡처 3436이고 위 두 실기 세대와 다르다. 기존 캐시에서 두 위상은 마지막 OBJ 준비 → SEAL 수락 6.011 / 6.006ms, SEAL → 첫 잔여 DMA 6.977 / 6.920ms, 첫 DMA 시작 → 마지막 PPU 쓰기 1.279 / 1.279ms였다. 1,888B를 전송했고 마지막 쓰기 → 공개 약 0.123ms, 공개 → 65816 ACK 약 0.135ms였다. 두 위상 모두 SEAL을 받은 뒤 다음 VBlank의 225선에 DMA를 시작해 245선에 마지막 바이트를 썼다. OBJ 캐시를 비운 조건에서는 SEAL → DMA가 11.672 / 11.644ms, 실제 전송 구간은 0.941 / 0.943ms였다. ROM 허가와 SPI는 모형이고 ARM 명령·65816 명령·PPU 쓰기는 재생에서 관측했다.

## 처리 비용을 줄인 세 가지 변경

같은 MMC907 링크를 기준으로 ARM 변경을 각각 적용했다. 독립 수신 검사와 표시 ROM은 공통이다.

- 팔레트·OAM의 2바이트 반복 탐색에서 이미 제외한 시작 위치를 다시 훑는 비용을 없앴다. 링크된 함수가 기록된 고유 payload 100개에서 실행한 명령 수가 421,714 → 91,779로 줄었다. 56개 경계 입력을 추가해 반환 경계의 일치도 확인했다. 이 수치는 화면별 빈도로 가중하지 않은 함수 단독 합계다.
- SEAL 뒤 다음 입력을 한 블록 처리하면 유효 E0를 먼저 확인했다. SRAM 재생에서는 기존 대기 E0 응답 하나의 순서만 옮기고 SPI 거래와 응답의 전체 바이트가 같은지 검사했다.
- section 5의 첫 192B가 64B 단위로 각각 정확히 반복되는 경우, 원래 수신기가 검사하는 고정값 쓰기 세 건으로 보냈다. 나머지 9B와 테이블 240B는 그대로 전송했다. 여덟 화면의 RGB와 세대별 section 5의 복원 바이트 및 쓰기 범위를 대조했다.

각 최종 링크의 Flash는 순서대로 212,824 / 212,836 / 212,916B이며 한도는 212,992B다. 세 링크 모두 SRAM D0 송신 네 경로, 정상 입력과 CRC 오류 처리, 제한 시간 STOP, base 복구와 메뉴 반환 경로를 통과했다. 실기 STOP·메뉴 복귀 기준은 사용자가 확인한 MMC907이다.

| 최종 링크 | 기존 캐시 여섯 표시 간격 합 · 위상 1 / 2 | 마지막 65816 ACK 차이 (ms) | 빈 OBJ 캐시 간격 합 | 마지막 65816 ACK 차이 (ms) |
|---|---|---|---|---|
| MMC907 | 15 / 15 | 기준 | 20 / 20 | 기준 |
| 반복 탐색 한 번 | 15 / 15 | +0.023 / +0.026 | 20 / 20 | +0.016 / −0.006 |
| E0 조기 확인 | 15 / 15 | −0.003 / +0.006 | 20 / 20 | 0.000 / −0.018 |
| 고정값 쓰기 세 건 | 14 / 14 | −0.018 / +0.007 | 20 / 20 | +16.650 / +16.630 |

고정값 쓰기는 여덟 화면의 E1 전송을 1,032B 줄였지만 기존 캐시에서는 간격 집계의 첫 화면이 한 VBlank 늦어졌다. 마지막 표시는 두 위상 모두 원래 VBlank였다. 빈 캐시에서는 마지막 표시까지 한 VBlank 늦어졌다. 마지막 재생 화면에서 section 5 수락 건수가 4→7로 늘었고 기존 캐시의 SEAL은 0.354 / 0.381ms 늦어졌다. E0 조기 확인으로 기존 캐시의 ARM 유효 응답은 0.233 / 0.096ms 빨라졌지만 표시 시각을 결정하는 VBlank는 그대로였다.

실기 기준은 MMC907을 유지한다. 다음 절감 대상은 마지막 OBJ가 준비된 뒤에야 시작되는 확정 출력의 수락과 SEAL이다. 기존 캐시 기준 마지막 재생 화면의 SEAL 수락은 115 / 116선으로 이미 직전 VBlank가 끝난 뒤다. 확정된 section 5 준비와 기존 패킷 발행을 마지막 OBJ 공급과 겹칠 때 큐 credit과 선행 DMA가 밀리는지 같은 시작 시각에서 비교해야 한다. 실기 판정에는 같은 세대의 OBJ token, SEAL, DMA 시작·마지막 쓰기, 표시, 65816 ACK와 ARM 유효 E0가 함께 필요하다. 중간 간격 합과 함께 동일 시작 기준 첫 표시와 마지막 ACK를 비교한다.

## 재현 경로

`tools/nes_tail908.py patch`로 MMC907 원본 해시를 확인하고 독립 패치 세 개를 생성한다. 기존 MMC907 전체 링크 절차로 각 패치를 링크한 뒤 같은 도구의 `guards <linear|ack|fill> <게임 ROM>`과 `replay <임시 경로> <1|2>`를 실행한다. 기본 재생은 반복 탐색 변경이고 `--ack` 또는 `--fill`로 나머지를 선택한다. 각 위상에서 기존 캐시와 `--cold`를 모두 실행한다. `tools/analyze_nes_tail908.py <실기 로그 폴더> <재생 경로> <결과 JSON>`이 MMC901·903·905·907 기록, 최종 링크 증거, 같은 세대의 E0 identity·CRC, RGB·section 5를 함께 대조한다.
