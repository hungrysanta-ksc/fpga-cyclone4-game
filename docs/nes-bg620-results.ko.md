# 620 · 두 번째 BG plan의 발행부터 954 표시까지

**954의 표시는 두 시작 위상 모두 5→4 VBlank로 줄었다.** 전체 일정에서 가장 좋은 후보 D의 마지막 ACK는 619 대비 위상 1에서 0.108 ms 늦고 위상 2에서 16.560 ms 빨랐다. 양쪽의 마지막 ACK 단축을 채택 조건으로 두었으므로 619를 비교 기준으로 유지한다.

## 53화면 연속 결과

각 칸은 위상 1 / 위상 2 순이다. 밀집 합계는 951–955 다섯 표시 간격을 더했다. 마지막 ACK는 같은 시작 클록의 957 절대 시각을 비교하며, 양수는 지연이다.

| 구성 | 직전 ROM 구간의 읽기 수(목표 96) | 954 표시 간격(VBlank) | 밀집 합계(VBlank) | 마지막 ACK 차이(ms) |
|---|---:|---:|---:|---:|
| 619 검사 단독 | 0 / 0 | 5 / 5 | 22 / 21 | 기준 |
| A · BG 7개 발행 | 96 / 96 | 5 / 5 | 21 / 21 | +49.983 / +33.278 |
| B · BG 6개와 1개 분리 | 96 / 96 | 5 / 4 | 21 / 20 | +33.297 / 0.000 |
| C · BG 7개와 직접 직렬화 | 96 / 96 | 4 / 4 | 21 / 21 | +16.657 / +33.800 |
| D · C와 map 소비 확인 | 96 / 96 | 4 / 4 | 21 / 21 | +0.108 / −16.560 |

### 954에서 확보한 시간

953을 표시한 시점부터 잰 시각이다. E9는 두 번째 묶음의 전송 완료이고, DMA 완료는 144B BG에 대한 PPU의 마지막 쓰기다.

| 경계 | 619 (ms) | D (ms) |
|---|---:|---:|
| ARM 두 번째 E9 완료 | 34.762 / 34.562 | 31.969 / 32.186 |
| 96번째 ROM 응답 | 49.728 / 49.733 | 33.227 / 33.233 |
| 65816의 BG 144B 수락 | 51.324 / 51.317 | 37.819 / 37.732 |
| BG 144B DMA 완료 | 81.442 / 65.995 | 64.832 / 48.592 |

7개를 일찍 보낸 A에서는 tile DMA가 빨라도 954 표시가 그대로였다. 새 map·팔레트 패킷이 먼저 수락되면서 map은 192B만 선행했고, 최종 빔 확인은 양쪽 모두 248번 라인에 도착했다. C와 D에서는 map 1,344B를 선행하면서 246번 검사선을 지키고도 954를 한 VBlank 일찍 표시했다.

### 남은 비용과 다음 비교

D의 위상 1에서는 953 표시까지 이미 기준보다 한 VBlank 늦었다. 954에서 이를 만회해 두 구성 모두 223번째 VBlank에 표시했다. 957도 같은 236번째 VBlank에 도착했지만 D의 SEAL 수락은 11라인 늦었고, 최종 표시 경로 진입은 2,316 마스터 클록 늦었다. 그 뒤 ACK까지 걸린 클록 수는 정확히 같았다. 위상 2에서는 955가 4→5 VBlank로 늘어 954의 한 번 절약을 상쇄했지만, 앞서 확보한 시간 덕에 957 ACK는 한 VBlank 일찍 끝났다.

다음 비교는 **906에서 두 위상 모두 추가된 한 VBlank**를 먼저 분리한다. 906에서 조기 발행은 E9 묶음을 7회에서 8회로 늘렸고 954에서는 3회를 유지했다. 이미 확인된 대상 뱅크 이력으로 첫 채움과 재사용을 구분할 수 있는지 살펴보고, 첫 채움에서는 기존 발행을 유지한 구성과 D를 같은 두 시작 시각에서 비교한다. 957에서는 SEAL 수락부터 최종 표시 경로 진입까지를 따로 추적한다. 954 표시 4회와 955 map 선행을 유지하고 957의 최종 대기·마지막 ACK를 모두 대조한다.

모든 후보에서 952 표시 간격 4회, 955 첫 map 192B·마지막 map 384B 선행, 957 최종 대기 0회를 확인했다. 위상별 53화면의 RGB·map, 타일·일반 출력 내용, VRAM DMA 114,352B가 기준과 일치했다. 두 뱅크의 누락·중복 거부, 새 패킷·STOP 우선, SEAL 검사·최종 표시 경계의 STOP도 통과했다. 이번 수치는 연결 시뮬레이션 결과다. FPGA·65816 변경이 없어 Quartus 재합성은 생략했고, 실기 메뉴 복귀와 플레이 속도는 MMC613에서 마지막으로 확인했다.

## 비교 조건

기준은 618 ARM03과 **619 검사 단독 65816**의 조합이다. 이 기준에서 954의 여섯 BG slot(126–131)에 필요한 96회 읽기는 두 위상 모두 첫 BG가 사용한 ROM 구간을 놓쳤다. 해당 구간에 96회분을 확보하려면 첫 요청이 최소 1.421 / 1.216 ms 빨라져야 했다. 이전 1.251 ms는 618의 65816을 사용한 위상 1 수치다.

ARM A는 첫 E9가 수락된 warm 프레임에서 다음 BG 7개가 확정되면 즉시 발행한다. ARM B는 6개에서 먼저 발행하고, 다음 BG 하나가 확정되면 후속 E9로 넘긴다. 954에서는 앞의 6개가 96회 읽기를 시작하고 뒤의 BG slot 122가 앞의 연속 tile(144B)을 닫는다. 어느 후보도 세대 번호나 미래 OBJ를 참조하지 않는다. 기존 2슬롯의 E8 응답·STOP guard·CRC를 통과한 뒤 E9가 성공해야 ARM이 버퍼를 반환한다. cold의 첫 묶음, 기존 map·OAM 발행 조건과 65816 코드는 유지했다.

후보 C는 A의 7개 발행을 유지하면서 compact plan의 직렬화를 앞당긴다. 65816과 E9 양식을 그대로 사용하고, ARM이 입력 범위·행·대체 태그를 검사한 뒤 compact/긴 형식 중 실제 전송할 쪽의 바이트만 만든다. 구·신 C 인코더 대조 28,160건에서 반환 길이와 전송 바이트가 일치했다. 잘못된 입력 25,531건, 짧은 BG·OBJ·END/zero와 16–32B 확장형을 포함한다. 후보 D는 C에서 오른쪽 페이지 첫 19행 이상이 연속인 map을 보낸 뒤, 기존 E0 소비 완료를 확인하고 팔레트를 발행한다. map과 tile이 같은 VBlank를 사용할 때 큐를 비워 65816에 선행 DMA 기회를 주는 실험이다. OAM 전의 기존 대기는 별도로 유지한다.

ARM 전체 링크는 A/B 212,976B, C 212,904B, D 212,928B다. 모두 212,992B 한도 안이며 BSS는 18,592B다. 연속된 진단 보고 헤더 두 개를 한 번의 출력 호출로 합쳤다. 실제 ARM에서 서로 다른 진단 필드값을 사용해 이전 보고서와 전체 바이트, 부족한 버퍼·정확한 길이에서의 반환값, 경계 밖 쓰기를 대조했다. C와 D의 첫 빌드에서 각각 이전 helper의 미사용 선언과 drain 헤더 누락을 컴파일러가 검출했다. 선언을 정리한 arm04와 arm06을 링크해 검증했다. RTL과 65816 ROM은 기존 바이너리 구성을 사용했다.

## 재현

1. `tools/prepare_nes_bg620.py`에 618 arm03을 주고 기본(A, arm01), `--split`(B, arm02), `--direct`(C, arm04), `--direct --map-drain`(D, arm06)으로 생성한다. 각각 `tools/build_nes_trial577.ps1`로 전체 링크한다.
2. `tools/test_nes_board611.py`를 [619와 같은 조건](nes-tile619-results.ko.md)에서 실행한다. 65816은 `nes-tile619/coverage`, 시작 클록은 3,000,000 / 3,178,684다. ARM 명령, SPI, SysTick, 두 슬롯, 65816과 PPU를 연결한다. ROM 허가는 부트 8프레임에서 얻은 중재 기록을 반복 사용한다.
3. `tools/check_nes_bg620.py`에 기준·후보 ARM의 src와 `--count 7`(B만 6)을 준다. D에는 `--drain`도 준다. `tools/check_nes_bg620_codec.py`는 기준·C 헤더를 별개로 컴파일해 같은 입력을 대조한다. 후보별 trace에서 `tools/test_nes_map616_edges.py`와 `tools/test_nes_seal538_stop.py`를 실행한다. `tools/analyze_nes_bg620.py`로 96개 주소와 허가, 144B의 E1·수락·PPU 마지막 쓰기, 53개 map·화면, 표시 간격과 최종 ACK를 대조한다.
