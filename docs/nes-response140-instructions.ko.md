# NES140 — ROM 읽기 완료 응답 수정 시험

139에서 CPU가 필요한 시점까지 ROM 응답이 도착하지 않는 상태를 확보했습니다.140은 읽기 완료를 알리는 시점을 한 메모리 클록 앞당긴 수정 후보입니다. **PSRAM을 실제로 읽는 시간과 읽은 뒤 핀을 유지하는 시간은 그대로입니다.** 모델에서 오류 재현·수정 효과를 확인했으며, 실기 화면 성공 여부는 이번 시험으로 확인합니다.

## 복사와 실행

1. 전원을 끄고 현재 SD의 `sd2snes/firmware.stm`, `fpga_base.bi3`, `m3nu.bin`을 별도 보관합니다.
2. ZIP의 **`01-SCREEN140-SD-ROOT` 안의 내용**을 SD 최상위에 복사합니다. 펌웨어·`fpga_n140.bi3`·`nes/screen140.nes`를 함께 적용합니다.
3. 메뉴에서 **`NES SCREEN 140.nh1`**을 한 번 실행합니다. 이 선택 파일은 **0바이트가 정상**입니다. 확장자를 바꾸거나 이전139 선택 파일을 실행하지 않습니다.
4. 메뉴로 돌아오면 전원을 끄고 아래 두 TXT를 회수합니다.
5. **`02-RESTORE044-SD-ROOT` 안의 내용**을 SD 최상위에 덮어써 복원하고 메뉴·기존 GBC 동작을 확인합니다.

## 시간과 관찰

앞의80KiB 적재·전체 대조는 유지합니다. 이전139은 표시 시작까지 약8분45초가 걸렸습니다. 정상이라면 그 뒤 **약10초간 진단 화면을 표시하고 메뉴로 복귀**하는 것이 목표입니다. 입력·소리는 아직 시험하지 않습니다.

전체 실행은 **최대10분**을 관찰 기준으로 삼습니다. 그때까지 복귀하지 않으면 전원을 끄고 남은 로그를 회수한 뒤044로 복원합니다. 리셋 버튼으로 복귀를 시도하거나 같은 시험을 연속 반복하지 않습니다. 오류가 나면139처럼 표시 대기를 일찍 끝내므로 화면이 잠깐 보이거나 보이지 않을 수 있습니다.

이번에는 **화면이 보이면 사진 한 장이나 짧은 영상**이 정상 패턴 여부를 판단하는 데 도움이 됩니다. 보이지 않거나 촬영하지 못했다면 두 로그와 관찰 내용만 보내도 됩니다. 약9분의 전체 과정을 촬영할 필요는 없습니다.

## 전달할 결과

- `sd2snes/nes-progress-140.txt`
- `sd2snes/nes-screen-last-140.txt`
- 화면 표시·깨짐·정지 여부, 메뉴 복귀 여부
- 044 복원 후 메뉴·GBC 동작 여부

`run_passed=1`은 CPU 읽기 활동과 STOP 검사 통과이며, 화면 정상 여부의 자동 판정은 아닙니다. 오류 시에는139와 같은 최초 주소·대기 상태와 실행/종료 오류 구분을 기록합니다. RUN 중에는 SD에 쓰지 않고 정상 복귀 경로에서 저장합니다. 최종 TXT가 없거나0바이트면 그 사실과 진행 TXT를 알려주세요.

## 범위

같은 진단 ROM으로 응답 경계 수정의 효과를 확인하는 제한 시험입니다. SMB3(J)·패드·오디오 완료가 아닙니다. 보드 지연은 실측하지 않았으며, 기존 E1/E2·8µs·양클록 정지CE9µs 미보장·MTBF·source-lock 보류4건은 유지합니다. 카트리지 분해·LED 확인·PC 직접 연결·SD 포맷은 필요 없습니다.
