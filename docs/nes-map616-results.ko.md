# MMC616 후보의 952 map 선행 DMA

## 640 B가 남은 이유

MMC613에서 952의 첫 번째 유휴 VBlank에는 목적지 0xAB80의 map 데이터가 아직 수락되지 않았다. 다음 VBlank 시작 시 10행 중 7행(448 B)이 준비됐고, 그 안에서 나머지 3행도 수락됐다. 마지막 map 패킷 ACK는 BEGIN ACK 뒤 24.920 / 25.219 ms였다. 두 위상 모두 큐가 빈 250번 라인에서 65816이 연속한 1,152 B 중 앞 512 B(오프셋 2432부터)만 보냈다. 같은 descriptor의 나머지 640 B(2944부터)가 SEAL 뒤에 남았다.

## 65816 변경과 경계 검사

후보는 수락이 끝난 연속 map descriptor 하나에서 최대 1,152 B까지 보낸다. 비활성 뱅크·실제 잔여 길이를 확인하고 MDMAEN 직전에 STOP과 새 패킷을 검사한다. 후보 A는 map 빔 샘플의 마지막 허용 라인을 254에서 251로 당겼다. tile 시작 제한은 232, 최종 표시 검사선은 246이다. 실제로 전송한 뒤에만 descriptor를 줄인다. ARM과 FPGA 제어를 수정할 필요는 없었다. 65816 본체는 4,949 B, 내장 프로그램은 5,120 B로 MMC613과 같다. 기준 프로그램을 다시 생성해 기존 ROM과 바이트가 일치하는지 확인했다.

실제 65816 명령을 실행한 경계 시험에서 251번 라인에 허용한 최대 map 전송은 252번 라인에 쓰기를 시작해 259번 라인에 끝났다. 첫 쓰기부터 마지막 쓰기까지 9,488 master clock이었다. 전송 중 도착한 STOP은 마지막 쓰기 뒤에 처리했고, 시작 직전의 새 패킷과 STOP은 전송을 막았다. 252번 라인의 map은 거절했다. 두 뱅크에서 missing·duplicate 입력을 각각 거절하고 직전 화면을 보존했다. 초기 907 fault 시험은 앞에 있는 tile을 map으로 간주하는 시험 조건에서 중단됐다. 기존 map-first fixture로 주입 대상을 지정한 뒤 네 조건을 통과했다.

## 두 번째 위상의 차이

251번까지 허용한 A는 위상 1에서 목표 640 B 전체를 선행 전송했다. 위상 2에서는 첫 VBlank에 준비된 map이 없었고, 다음 VBlank 초반에는 작은 tile 48 B를 우선했다. 마지막 map은 236번 라인에서 수락했다. 큐가 빈 뒤 selector에 들어간 시점은 251번이었지만 실제 빔 검사에서 252번을 읽어 1,152 B가 대기했다. 53화면 독립 재생에서 CPU 이벤트 10,458개가 원래 기록과 일치했다. 최초 재생은 palette fill 관측점의 차이로 이벤트 수 대조에 실패해, 원래 일정의 palette 관측기를 적용하고 전체 이벤트를 다시 확인했다.

후보 B는 이 빔 샘플을 받아들이도록 마지막 허용 라인을 252로 정했다. 253번에서는 거절한다. 같은 도착 시각 대조에서는 A로 951까지 실행한 다음 952에서만 WRAM의 상한 비교 즉시값 한 바이트를 B 값으로 바꿨다. 두 위상 모두 그 전 CPU 이벤트 9,197개가 일치했다. 위상 1은 이미 250번에 발행해 결과가 같았고, 위상 2에서는 253번에 실제 DMA가 시작돼 952 ACK가 15.84 ms 빨라졌다. 이 값은 발행 시각을 고정한 952 한 화면의 효과다.

B의 최대 전송 경계 시험은 252번 라인의 앞·뒤 수평 위치에서 각각 실행했다. 늦은 샘플(H=1272)에서 첫 쓰기는 254번, 마지막 쓰기는 261번 라인이었다. 샘플부터 마지막 쓰기까지 11,028 master clock이 걸렸다. 최종 표시 검사선 246번과 STOP·새 패킷 우선 검사는 A와 B에서 같다.


## 53화면 연속 실행

표의 순서는 시작 위상 1 / 2다. 고정 도착 시각 실험과 별도로, 각 후보를 905부터 957까지 실제 ARM610·65816 프로그램으로 실행해 SPI/IRQ·두 bulk 슬롯·반복 ROM 캘린더와 화면 간 위상 변화를 포함했다.

| 지표 | MMC613 | A · 251번 | B · 252번 |
|---|---:|---:|---:|
| 952 목표 640 B 중 선행 처리 B | 0 / 0 | 640 / 0 | **640 / 640** |
| 952 최종 대기 횟수 | 1 / 1 | 0 / 0 | **0 / 0** |
| 952 표시 간격(VBlank) | 5 / 5 | 4 / 5 | **4 / 4** |
| 951–955 표시 간격 합(VBlank) | 23 / 23 | 22 / 23 | **22 / 22** |
| 951–955 평균 표시 간격(ms) | 76.53 / 76.47 | 73.19 / 76.52 | **73.15 / 73.14** |
| 957 최종 대기 횟수 | 0 / 0 | 0 / 0 | **0 / 0** |
| 957 마지막 ACK 시각 차이(ms) | 기준 | −33.524 / −0.209 | **−33.608 / −33.499** |
| 첫 두 화면 이후 평균 간격(ms) | 69.52 / 69.49 | 69.16 / 69.49 | **69.16 / 68.84** |

A의 위상 2는 대기가 업로드 도중으로 이동해 표시가 여전히 5 VBlank 걸렸다. B는 두 위상 모두 동일한 map 640 B가 SEAL 이후 목록에서 사라졌고 952 빔 검사가 250→245번 라인으로 이동했다. 이전 화면부터 마지막 ACK까지 누적되는 일정에서는 957의 절감량이 952 한 화면의 절감량과 달라진다.

모든 53화면에서 이전 구성과 화면 픽셀, map·tile 출력이 일치했다. VRAM DMA는 114,352 B, BG 캐시 적중 48회·OBJ 캡처 적중 1,200회를 유지했다. B의 warm DMA 565 / 564건은 첫 쓰기부터 마지막 쓰기까지 같은 VBlank 안에 있었다. 954의 팔레트·OAM·HDMA 수락 직후 STOP 주입 세 건도 0xe4를 반환하고 직전 953 화면을 보존했다. 이전 EA부터 다음 동일 뱅크 캡처 시작까지의 최소 간격은 32.73 / 32.84 ms였다.

## 다음 순서와 재현

252번 후보 B를 다음 일정 비교의 기준으로 선택한다. 954·955의 표시는 여전히 두 위상 모두 5 VBlank이고, 업로드 대기는 각각 14.63 / 14.13 ms와 14.25 / 14.28 ms다. 다음은 확정 map의 E1 발행·65816 수락·선행 DMA를 마지막 사용 가능한 VBlank에 맞추는 일이다. 952의 4 VBlank·957 최종 대기 0회와 마지막 ACK를 대조한다. 실기 기준은 MMC613의 5–55초 15.66fps다. 이번 측정 범위는 연결 일정과 65816 동작 시험까지이며, 새 내장 ROM의 보드 FIT·STA와 실기 메뉴 복귀는 전달본 단계에 남는다.

1. `tools/nes_map616.py`를 마지막 라인 251·252로 각각 실행한다. 로컬 프로그램은 `probes/nes-map616/client01`과 `client02`다.
2. `tools/test_nes_board611.py --keep-run`을 두 시작 클록 3000000·3178684에 실행한다. 610 arm06/src, 231 test07, 519 fixture02, 538 plans01, 489 audit01, 601 trace01/stim.tsv, 509 rom03, hardware503-mmc502 드라이버 모델을 사용했다. 65816 독립 검사는 `tools/test_nes_map616_edges.py`로 실행한다.
3. `tools/replay_nes_quiet608.py --generation 952`로 A의 위상 2에서 selector 이벤트를 대조한다. `tools/replay_nes_map616.py`는 각 A의 패킷 도착 시각을 유지한 채 952에서만 B의 비교 즉시값을 적용한다.
4. `tools/analyze_nes_map616.py`에 기존 611 추적과 새 두 위상, 프로그램, 경계 시험을 전달한다. B는 `--prefix nes-map616-beam --fixed-prefix nes-map616-isolate`를 사용했다. [251번 후보 결과](../analysis/map616-verification.json) · [252번 후보와 분리 시험](../analysis/map616-beam-verification.json)
