# MMC872 밀집 데모에서 한 VBlank를 넘긴 원인

실기 기준은 MMC872다. 모험도 4 무입력 35–40초의 출력·최종 ACK 비용은 MMC866 61.00ms/장, MMC872 59.30ms/장이었다. 시작 기준 표본 수는 70장과 71장이고, 평균 BG는 512.86/512.82, OBJ는 29.83/25.28, dirty map 행은 4.90/4.54였다. 이 실기 집계만으로 개별 DMA 시각을 복원할 수 없어 원본 2120–2364에서 4장 간격으로 뽑은 입력으로 링크를 각각 재생했다. 첫 두 화면으로 뱅크를 준비했다. 세 링크 모두 밀집 62장의 BG·OBJ·dirty 행 수, 완성 map, 유효 화면 픽셀이 일치했다. [구간별 실기 집계와 재생 결과](../analysis/word873-results.json)

## 950번 화면에서 밀린 작업

원본 2300에 해당하는 950번의 작업량은 BG 521, OBJ 99, dirty 행 23이다. 아래는 MMC872의 연속 일정이다. VBlank 번호는 225선에서 증가하고, 261선 뒤 0선으로 돌아가도 그 번호를 유지한다.

| 시점 | 위상 1 | 위상 2 |
|---|---|---|
| 마지막 map 반환 | VBlank 142 · 250선 | 143 · 245선 |
| 마지막 tile 준비 → 첫 유효 E8 | 0.169ms | 0.115ms |
| 마지막 tile 반환 | 142 · 54선 | 143 · 51선 |
| SEAL 수락 → 업로드 진입 | 142 · 83→109선 | 143 · 80→106선 |
| 마지막 검사 진입 | 143 · 248선 | 144 · 249선 |
| 팔레트 2B·OAM 112B 전송 후 공개 | 144 · 229선 | 145 · 229선 |

마지막 map 반환 순간에는 다음 스크롤 21B가 이미 큐에 있었다. 65816은 새 패킷을 먼저 처리해 그 공백에 map DMA를 시작할 수 없었다. 이어지는 VBlank에 map 1,088+64+1,472B와 tile·raw DMA가 몰렸다. 두 위상 모두 246선 검사 마감을 넘겨 마지막 114B만 다음 VBlank에 보냈다. 다른 화면에서도 같은 원인을 가정하면 안 된다. 940에는 map 패킷이 없고 SEAL 수락이 230/231선, 업로드 진입이 양쪽 255선이다. 947에서는 1,472B map을 먼저 보냈고 SEAL 수락이 247/249선이었다.

## 복원 연산 단축과 발행 순서의 분리 시험

**65816 복원 변경.** 873은 2B 단어를 64B마다 한 번 읽어 비활성 WRAM에 순서대로 쓴다. 밀집 60장에서 두 값이 다른 반복 map 패킷은 네 화면에 두 개씩 있었다. 950의 offset 2,240·2,432에 들어가는 두 패킷의 합산 수락→반환 시간이 두 위상 모두 약 3.24→2.71ms로 줄었다. SEAL 수락은 0.28/0.19ms 빨라졌지만 950 표시 간격은 여전히 4/4 VBlank였다.

| MMC872 → 873 복원 변경, 연속 재생 | 위상 1 | 위상 2 |
|---|---:|---:|
| 오프닝 60개 표시 간격 합 | 125→126 | 124→125 |
| 전환 48개 표시 간격 합 | 119→119 | 119→119 |
| 밀집 60개 표시 간격 합 | 141→140 | 141→141 |
| 밀집 마지막 ACK 단축 | 16.64ms | 0.22ms |

오프닝 703은 양쪽 59번 VBlank의 231선을 지켰고 759는 176→177로 밀렸다. ARM Flash 212,956B(36B 여유)를 재사용했고 65816 ROM 여유는 17→9B다. 기존 12개 검사와 반복 단어의 64B·128B 지점 STOP, 양 뱅크 cold 복구, 부팅 복원·손상 거부를 통과했다. 취소 직후 쓴 접두부, 쓰지 않은 꼬리, 활성 뱅크, 이전 화면 유지까지 대조했다. 메뉴 복귀에 쓰는 ARM은 해시가 같은 MMC872의 검증 결과를 사용했다. 후보 보드 합성과 후보 실기 시험은 수행하지 않았다.

**스크롤 발행 시각 변경.** 별도의 65816 시험에서 950번 마지막 map 반환 시각에 스크롤 SPI 거래를 시작한다고 두고 원래 거래 시간을 모두 부과했다. 후속 패킷을 같은 양만큼 늦춰 순서·간격·내용을 유지했다. 대조군은 원래 결합 재생과 949·950 공개 시각 및 950 최종 ACK 클록이 일치했다.

| 두 위상 결과 | MMC872 원본 ROM | 873 복원 변경 ROM |
|---|---|---|
| 스크롤 이후 패킷 지연 | 1.272/1.218ms | 1.184/1.146ms |
| 직전 VBlank의 1,088B map DMA 시작선 | 252/248 | 242/244 |
| 950 표시 간격 | 4→3 / 4→3 | 4→3 / 4→3 |
| 950 공개선 | 양쪽 246선 | 양쪽 246선 |
| 950 최종 ACK 단축 | 15.54/15.55ms | 15.55/15.55ms |

이 시험은 950까지의 패킷 시각을 고정했다. ARM의 반환 확인 거래와 그에 따른 차기 입력·tile 일정 변화는 다음 결합 재생에 포함해야 한다. 873 복원 단독판은 채택하지 않는다. 다음 후보는 MMC872 ARM이 마지막 큰 map의 반환을 기존 credit 응답에서 확인하는 동안 첫 스크롤 발행을 보류해, 이미 수락한 map을 65816이 선행 전송하도록 하는 방식이다. 두 위상에서 950의 1,088B 선행 전송, 밀집 60개 간격 합과 마지막 ACK, 오프닝 703·759와 전환 119회를 함께 판정한다. 반복 E0 조회 비용도 포함한다.

## 재현

1. MMC872의 최종 링크 자료를 준비한다. 새 작업 디렉터리에 같은 `link-credit`과 `menu869.json`을 사용하고, `tools/prepare_nes_word873.py BASE/client02 WORK/client02`로 후보 ROM을 만든다. 해시가 고정된 MMC872 ROM을 입력으로 받는다.
2. `tools/replay_nes_strip869.py TEMP PHASE WORK 873-word CLIP`으로 두 위상에서 `dense`, `opening`, `transition`을 재생한다. 대조 태그는 `866-on`, `872-final`이다.
3. `tools/check_nes_strip869.py guards TEMP WORK 873-word WORK/guards.json`과 `tools/guard_nes_word873.py TEMP TEMP/nes-tile821-demo-jointmirror-p1-873-word WORK/client02 WORK/word-guards.json`을 실행한다. `tools/check_nes_longrun694_boot.py`에 기준·후보 client02와 Mesen 경로를 지정해 `TEMP/nes-word873-boot`에 기록한다.
4. `tools/test_nes_word873_idle.py TEMP PHASE DELAY --tag TAG`를 양 위상, DELAY 0·1, 두 태그 `872-final`·`873-word`로 실행한다. `tools/analyze_nes_word873.py TEMP WORK DOWNLOADS analysis/word873-results.json`이 실기 로그, 픽셀·작업량 대조, 일정, 검사 결과를 결합한다.
