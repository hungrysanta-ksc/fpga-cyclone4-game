# MMC1023 커비 교차 게임 기준판

MMC1012의 일반 실행·계측·65816 경로를 유지하고, 일본판 별의 커비의 512 KiB PRG와 256 KiB CHR에 맞춰 주소 폭을 확장했다. MMC1022에서 비교한 OBJ 캐시 배치·조회 순서 실험은 기준판에서 껐다(`POLICY=0`, `REMEMBER=0`). 모험도 4의 실기 기준은 MMC1012다.

## 화면 검증

원본 Mesen에서 입력 없이 3,600 프레임을 실행하고 아래 네 장의 PPU 읽기와 RGB 출력을 채집했다. 해당 읽기를 보드의 캡처·내보내기·SPI 회로에서 재생하고, D1 블록별 CRC를 확인한 뒤 최종 ARM 링크에서 복원·계획·E9 직렬화를 실행했다. 같은 E9를 보드의 decoder와 tile205에 넣고 ROM 주소별 응답과 타일 출력 바이트를 기록했다. 이 바이트를 실제 ARM의 map·OAM·CGRAM·HDMA 데이터로 조합해 원본의 표시 영역 256×224와 15비트 색으로 비교했다. SNES 전기 신호나 실기 60초 전 장면을 검증하는 시험은 별도로 남는다.

## 비용과 복구

- EP4CE15F17C8 전체 배치에서 15,309/15,408 LE, 963/963 LAB, 53/56 M9K를 사용했다. 생산 경로가 호출하지 않는 tile-query 종류 6의 조회 메모리를 제거했다. 일반 캡처·수신 범위 검사와 타일의 응답 주소·세대 검사는 유지했다.
- 기존 bundled-data 제약을 새 page mailbox 비트와 물리 ROM 주소 비트까지 확장했다. Quartus Lite 25.1의 57개 STA 요약 항목에서 최소 slack은 +0.161ns, TNS는 모두 0이었다. 새로 활성화된 ROM_ADDR[16]의 최장 배선 지연은 11.402ns였다. 70ns PSRAM·PCB 왕복 4ns 가정에서 새 주소 비트 여유는 9.086ns, 주소 전체는 5.372ns, CE/OE는 4.050ns다. 일반 STA의 외부 입출력 미제약 항목은 남아 있다.
- ARM은 16,384개 BG 태그를 2 KiB 비트맵으로 기록하고, META_END에서 이미 받은 OBJ를 정렬된 필요 타일 목록에 합친다. 실험판 파일명으로 링크한 Flash는 212,980/212,992B다. 기존 하위 뱅크 첫 화면을 새 wire 형식으로 바꾼 제어 시험에서 최종 ACK·EA 뒤 STOP, 지연된 입력, 손상된 CRC를 확인했다. IRQ를 포함한 최저 스택과 정적 데이터 사이에 1,080B가 남았다.
- 커비 원본은 끝까지 CRC를 확인한 뒤 로더가 수락했고, 마지막 바이트를 뒤집은 경우 거부했다. 최종 ARM의 60초 타이머 경계, base 복구, 메뉴 준비·해제, 보드 프로그램 바이트의 BI3 왕복도 통과했다.

## 재현과 다음 측정

MMC1022의 로더 링크와 MMC1012의 보드 소스에서 `prepare_nes_kirby1023.py`의 `arm`, `board`를 실행한다. `check_nes_kirby1023.py capture`로 원본 입력을 채집하고 FLOAT 래퍼로 `check_nes_kirby1023.ps1`, `check_nes_kirby1023_ingress.ps1`을 순서대로 실행한다. 최종 ARM 링크로 `verify_nes_kirby1023_arm.py`를 실행한 후 `check_nes_kirby1023_tiles.ps1`로 계획을 재생한다. `check_nes_kirby1023_release.py`의 guards·run·base를 실행하고, 전체 FIT·STA와 report_nes_kirby1023_io.tcl의 핀 지연 결과, 변환된 보드를 `package_nes_kirby1023.py`로 확인한다.

무입력 60초 실기 두 회차의 1–30초와 30–60초 공개 FPS를 따로 기록한다. 회차 간 차이를 남겨 이후 커비 최적화의 변화량과 비교한다. 후보를 고정한 다음 모험도 4에서도 같은 전후 시험을 반복한다. [설치·로그 보존 방법](nes-mmc1023-trial.ko.md) · [패키지와 검증 수치](../analysis/trial1023-package.json)
