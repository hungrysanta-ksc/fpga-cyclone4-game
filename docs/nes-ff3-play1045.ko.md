# FF3 1045 실기 시험

기존 SD 카드에 설치본 안의 `sd2snes` 폴더를 병합한다. 같은 이름의 설치 파일은 덮어쓰고 기존 `sd2snes/nesstate/` 폴더는 그대로 둔다. 게임과 저장 파일은 설치본에 포함하지 않는다.

1. 파일 선택 메뉴에서 1044 때 사용한 한글판 FF3의 `.nes`를 선택한다. 입력하기 전에 음악과 함께 오프닝 화면이 보이는지 확인한다.
2. **L+R+START → STATE SLOT 1 → LOAD STATE**를 선택한다. 기존 부하 지점으로 돌아오면 몇 걸음 이동해 화면 갱신과 입력 반응을 확인한다. 이 지점을 다시 확인할 때는 **SAVE STATE**를 누를 필요가 없다. LOAD는 ROM 전체를 다시 대조하므로 바로 화면이 바뀌지 않을 수 있다.
3. **L+R+START → EXIT TO MENU**로 나간다. `nes-progress-ff31045.txt`, `nes-game-last-ff31045.txt`와 생성된 `nes-frame-ff31045.bin`이 이번 판의 로그다.

1044와 저장 형식이 같다. 이 ROM의 `4be84aa7-80000-0a.nsv`는 일반 배터리 세이브이고, `4be84aa7-80000-1a.nsv`는 장면 저장 슬롯 1의 사본이다. 슬롯 안에서는 두 사본을 번갈아 기록한다. ROM 파일 이름을 바꿔도 내용이 같으면 같은 슬롯을 사용한다.

게임 자체의 저장 내용을 SD에 기록하려면 **WRITE SRAM**을 선택한다. 다른 장면을 보관하려면 **STATE SLOT**에서 2–4번 중 하나를 고른 뒤 **SAVE STATE**를 누른다. **RESUME GAME** 또는 **B**로 플레이를 재개한다. 게임 내 세이브와 장면 저장은 각각 별도의 파일에 기록된다.

같은 판을 여러 번 실행하면 같은 이름의 로그를 다시 사용한다. 불러오기 뒤의 끊김을 비교할 때에는 슬롯 1을 불러와 잠시 플레이하고 **EXIT TO MENU**로 종료한 다음, 같은 ROM을 다시 선택하기 전에 이번 로그를 복사해 두면 된다.

## 1044 실기 기록과 1045 검증 범위

| 증상 | 재현 및 변경 |
| --- | --- |
| 재실행 직후 슬롯 1을 불러오면 메뉴로 복귀 | 1044의 마지막 기록은 표시 0장, 오류 5, ROM 오류 0, STOP·base 복구 성공이었다. 실기 슬롯의 헤더와 본문 CRC가 일치했다. 최종 ARM 실행 파일에서 같은 슬롯으로 오류 5를 재현했다. 1045는 유효 슬롯으로 재시작하는 동안 첫 표시 여부를 종료 실패로 처리하지 않는다. 복원된 21,264바이트를 슬롯 본문과 대조했다. |
| 시작 지점의 끊김 | 슬롯 1을 보드 RTL에 복원했을 때 1044는 소량의 CHR 쓰기에도 8 KiB 전체를 다시 복사해 연속 여섯 번 캡처 시작선을 놓쳤다. 1045는 변경된 1 KiB 페이지만 갱신해 같은 여섯 번 모두 캡처를 시작할 수 있었다. 복사 중 재변경·세대 불일치·STOP 뒤 전체 복사를 검사했다. |
| 오프닝 음악만 재생 | FF3는 배경만 출력하고 왼쪽 8픽셀의 배경을 허용한다. 기존 수집기는 이 조합을 raw 행으로 처리해 한도를 넘겼다. 1045는 스프라이트가 꺼진 동안 왼쪽 스프라이트 마스크를 행 채택 조건에서 제외한다. 같은 ROM의 콜드 부팅에서 17번째 인덱스의 첫 다색 화면이 일반 행으로 승인됐다. |

캡처 수는 NES 수집기 단독 시험값이다. ARM·65816 전송과 TV 표시까지 포함한 1045 실기 FPS는 별도 측정이 필요하다.
