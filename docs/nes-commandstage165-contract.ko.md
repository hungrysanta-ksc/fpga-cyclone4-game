# NES165 명령 캡처·판정·실행 분리

## 목표와 판단

165 영상 경로 진척: 실제164 MCU의 SPI 전송 간격을 확인하고 명령 캡처·판정·실행을3단계로 분리했습니다. FPGA1클록 추가, 두 후보의 기능·실제SPI 상태 응답 검증 통과. map01은 길이→원인 +0.672ns/원인→오류 +2.970ns/원인→카운터 자격 +2.628ns를 확보했지만 응답 주소→load_data -0.332ns가 남았다. map02는 데이터 선준비로 쓰기 허용 경로와 분리했다. 마지막 결과 15009LE/962LAB/35M9K, 전체 최악 -0.204ns; check_request_tag[6] → load_begin. 선택 phaseguard165/map01/reproduce01, 내부 실제클록 통과=False. 전체IO/CDC·MCU 연결·실기는 미완료, 새SD 없음.

작은 조합식을 반복 배치하는 대신 SPI 명령 완료 계약을 명시적으로 바꿨다. 기존 SS 캡처 다음1클록 실행에서 **캡처 C0 → 판정 C1 → 실행 C2**로 변경했다. 168MHz 기준 추가5.95ns다. 클록 주기·SDC·false path·multicycle 예외는 변경하지 않았다. 같은 클록 동등성이라고 주장하지 않는다.

## 실제 MCU 근거와 외부 계약

설치164의 동결된 MCU 소스와 manifest를 확인했다. `nes_rom_spi_transfer`는 `nes_game149_transfer`에 위임한다. 실제 엔진은84MHz PCLK2/32의 mode0 SPI1(2.625MHz), RXNE → TXE/!BSY 완료 확인, SS 해제 후2µs 대기, 다음 전송 준비 중2µs 대기, SS 활성 후 첫 SCK까지2µs 대기를 요청한다. `wait_us` → `delay_us` → 진단 모드의 `nes_return_delay`와 TIM2 설정까지 추적했다. 정상 경로에 큐·재시도는 없다. 실패 경로는 SS를 해제하고 기존 fail-stop으로 간다. 이 결과는 소스/모델 검증이며 실기 신호를 계측한 결과가 아니다.

외부 계약은 SS high 최소2µs, SS 활성 후 SCK까지2µs,2.625MHz 이하를 그대로 유지한다. 동기화 후 C2에 출력되고 로더는 다음 클록에 소비한다. 정상 명령 지연은 이 간격보다 훨씬 작지만, 이는 비동기 입력 전체 MTBF/IO 승인과 다르다. CHECK READ 응답은 기존 ready/busy/done 상태를 폴링한 뒤 실제 바이트를 대조하고 ACK하며, 고정 대기로 응답을 추정하지 않는다.

두 대기 단계에서 hard fault9, 잘못된/소유자 없는 응답7, SS 재활성1의 기존 우선순위로 fault를 잠근다. 한 클록만 겹친 SS도 이후 정상으로 돌아왔다고 명령을 살리지 않는다. reset은 큐와 모든 실행 펄스를 비운다. STOP도 같은 C2에 실행되며 기존 WRITE/HOLD 배출·오류 처리를 변경하지 않는다. 새 STOP 프레임으로 이미 대기 중인 명령을 덮어쓰는 큐는 없다.

기존 명령0x60..0x6a와 CRC/보수/A5 프레임은 유지한다. 응답 식별자만 실험용 **0x74**로 분리했다. 설치164의0x6b 검사와 호환된다고 주장하지 않는다. 향후 MCU는 정확한 새 식별자와 지연 계약을 명시적으로 채택해야 한다. E6/version2 상태73·E5 관측70·F6 패킷은 별개의 기존 계약이며 이번 변경에서 그대로다. 새 설치 펌웨어는 만들지 않았다.

map01은 판정/오류 인코딩/카운터 clear·ACK 자격을 C1에 계산한다. 모든 동적 자격은 종전처럼 SS 캡처 시점에 평가한다. map02는 DATA payload를 C1에 미리 준비하고 C2의 `load_valid`만 최종 오류 차단으로 허용한다. **load_valid=0일 때 load_data 변화는 허용**한다. 실제 로더는 accepted_load_valid 분기에서만 byte_hold에 소비하며 이 로더·상위 배선은 바이트 단위로 불변이다. 거부된 명령에 쓰기 펄스가 발생해서는 안 된다.

## 검증과 결과

각 후보는393,741개 캡처 조건을 기준 구현의 거래 결과와 비교했다. 기준 구현 실행 뒤 상태를 보관하고 후보만1클록 더 전진시킨 비교로, 같은 edge 비교가 아니다. 캡처 뒤 live length 변경, 오류 코드 우선순위와 실행 펄스, 각 대기 단계의 hard fault/응답/한 클록 SS/reset 등120개 경계를 확인했다. map02의 payload 비교는 valid일 때만 수행한다.

각 후보의 실제 SPI+boot+READ16 연결 시험은219개 프레임의 MISO 식별자, BEGIN/DATA/STATUS/STOP 이후 상태 응답,100회 읽기·7ACK·19주소 손상·72취소·2우선순위 충돌을 확인했다. SCK2.625MHz, SS high/setup2µs 모델이다. 일부 로더 READY/count와 CHECK counter를 주입하며 전체 ROM 적재·게임·MCU 실행은 아니다. 변하지 않은 로더의294,912조건/1,056시퀀스 근거는 재사용했다.

첫 test01은 잘못된 회로에서도 다음 클록까지 SS low가 남아 대조 시험이 실패를 검출하지 못했다. test02에서 단1클록 SS 겹침으로 수정해 잘못된 회로의 명령 유출을 검출했다. test03은 실제 wire 응답219개를 추가한 map01 최종 시험, test04는 map02 최종 시험이다. 최초 로그·실행 소스도 보존했고, test02 실행 소스는 기록된 hash와 일치한다. 라이선스 오류가 아니다.

## 다음 작업과 의미

선택 phaseguard165/map01은 유지한다. 명령3단계의 외부 지연 허용 가능성은 확인됐으므로 같은 MCU 간격 조사를 반복하지 않는다. 다음은 실제 잔여 경로 check_request_tag[6] → load_begin (-0.204ns)의7단 LUT 경로를 기준으로 C1에서 명령별 실행 허용 비트를 각각 등록하고 C2의 공통 오류 차단 뒤 최종 명령 재디코딩3단을 제거하는 후보 한 개를 검증한다. 오류 우선순위를 다음 클록으로 미루거나 응답 검사를 생략하지 않는다. 같은 두 후보의 무변경 배치나 작은 조합식 탐색은 반복하지 않는다. 실험 SPI 식별자74는 아직 설치용으로 승인하지 않았다. 후속 MCU는 기존6b를 묵인하지 말고 정확한 후보 식별자를 확인하고 SS high/setup 2µs 계약을 유지해야 한다. E6/version2 상태73·E5 관측70·E0/F6 수신/변환/ACK, 사운드·입력·STOP·경과시간, full-link/stack을 연결한 뒤 SMB3(J) 첫 레벨 실기로 간다. 설치164·GBC·세이브 SRAM 보존; 새SD 없음; 전체 ROM 쓰기·A/B·044 반복 생략.

연속 게임 화면을 위한 FPGA 제어 처리 구조를 개선하는 작업이다. 디버그 표시 항목을 늘리는 작업이 아니다. 변경 경계만 검증하고 최소 연결 조건을 갖춘 뒤 SMB3 실기로 판단한다.
