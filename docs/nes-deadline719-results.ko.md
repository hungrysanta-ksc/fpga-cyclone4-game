# 719 — ACK 기준의 DMA 대기 제한: 951·911 동시 회복, 밀집 속도 조건 미달

## 목표

716B의 descriptor 계산 절감과 717의 패딩 drain 제거를 보존하면서, map DMA를 기다려도 ordinary·SEAL 마감을 놓치지 않는 발행 조건을 실제 ARM에 연결한다. 두 시작 위상에서 951 공개 ≤246선, 911 표시 2 VBlank, 952 표시 3회, 957 최종 대기 0회와 독립 검사·STOP·최종 ACK·메뉴 복귀를 함께 검사한다.

**판정: 보호조건과 Flash는 통과했으나 밀집 간격·마지막 ACK의 동시 개선은 실패했다.** 선택 구성은 707D·기존 694/704 ARM·기존 694 65816으로 유지한다. 719는 조건부 대기의 검증 후보로 보존하며 설치본을 만들지 않는다.

## 작업내용

717에서 911과 951은 마지막 map 뒤에 **같은 10개 패킷·E1 거래 874B**를 보낸다. map ACK→SEAL 수락은 911이 5.160/5.308ms, 951이 6.057/6.059ms다. 패킷 개수나 크기만으로 두 장면의 대기 허용 여부를 구분할 수 없다. 718B의 무조건 DMA 진행 대기는 951을 회복하면서 911을 2→3 VBlank로 늦췄다.

719는 다음 경계를 교체했다.

- 독립 검사를 통과한 최종 표시 ACK 직후 DWT 시각을 4B로 저장한다. 중간 receipt나 DMA 진행으로 갱신하지 않으며 공통 reset에서 지운다.
- 재사용 뱅크의 마지막 head가 map이고 DWT가 유효할 때만 대기를 검토한다. 직전 ACK 이후 경과 시간을 NTSC 주기 약 16.639ms로 나누고, 현재 주기에 ordinary 꼬리 예산 8ms가 남아 있으면 곧바로 발행한다. 이 예산을 이미 놓쳤다면 다음 예측 경계까지만 실제 DMA 진행을 기다린다.
- 모든 반복은 기존 E0 CRC·counter·identity 검사와 STOP callback을 거친다. 실제 DMA 진행을 받거나 시간/poll 한도가 끝나면 발행으로 돌아간다. 시간 만료를 DMA 완료·표시 ACK·오류로 조작하지 않는다. 빈 입력은 credit을 쓰거나 새 COMMIT을 허용하지 않는다.
- cold, 카운터 미사용, 약 0.799초 이상 지난 ACK는 예측 대기를 사용하지 않는다. DWT 순환을 unsigned 차로 처리하고, 카운터가 멈춰도 기존 poll 한도로 끝난다.
- 기존 map-mask 기반 꼬리 drain과 팔레트의 고정 두 번 pause를 대체한다. 716B에서 네 화면의 단축에 기여한 OAM 경계 반복 drain은 그대로 남긴다. 716B planner/resident와 717 plan service는 바이트 그대로 보존한다.

**8ms는 재생에서 관측한 꼬리 비용에 여유를 둔 발행 예산이며 WCET 증명이 아니다.** 특정 generation·시작 위상·fixture 번호를 사용하지 않지만, 직전 ACK 시각도 실제 beam 시각은 아니다. 이전 공개선은 236–247선으로 달랐고 CPU ACK→ARM 출력 복귀에도 약 0.197–0.284ms가 있었다. E0 bit 3은 DMA 진행 이력이며 현재 DMA 허가나 예약된 SEAL 슬롯이 아니다. 따라서 이 예측식만으로 일반 게임 장면의 마감을 보장한다고 주장하지 않는다.

## 성과

실제 링크한 장시간 ARM과 기존 65816으로 **53화면×두 위상, 106화면**을 완료했다. 같은 map·tile·plan 바이트와 53화면의 픽셀을 717과 대조했다. SPI·IRQ·credit·ROM 달력과 VBlank를 포함하되, CPI2 모델 및 반복된 ROM 허용 구간을 사용하는 재생이며 실기 FPS나 전체 NES/PSRAM RTL 공동 실행은 아니다. 60초판은 전체 링크와 별도 경계·메뉴 검사를 수행했다.

### 빈 조회와 남은 공급 병목

951의 reason-4 callback은 10/11회, 합계 1.017/1.121ms였고 새 입력 블록은 0개였다. 953은 24회·2.440ms, 956은 21회·약 2.136ms를 썼지만 역시 모두 빈 입력이었다. 전체 SPI는 원본보다 **2,952/3,032B 증가**했다. E0는 740/1,000B 줄었지만 D0가 4,424/4,664B 늘었고 다른 거래 감소를 초과했다. 유효 입력 복원과 겹친 비용으로 간주하지 않는다.

953 SEAL은 직전 표시 후 43.439/43.437ms, 956은 43.565/43.280ms에 수락됐다. 파싱·검사·DMA를 모두 0으로 놓고 이전 VBlank의 246선 끝까지 표시할 수 있다고 가정해도, 수락을 각각 **최소 9.635/9.692ms, 9.734/9.448ms** 더 당겨야 한다. 빈 조회 약 2ms만 없애서 한 회차를 줄인다고 볼 수 없다.

953의 마지막 BG 발행은 23.574/23.534ms이고 ROM 응답은 33.789/33.734ms까지 밀린다. 956은 BG ROM이 이미 17.283/17.295ms에 끝나지만 마지막 tile ACK는 40.507/40.220ms다. **956의 OBJ 읽기 80회는 `OBJ_capture` 캐시 공급이며 새로운 외부 PSRAM 읽기가 아니다.** OBJ plan은 23.807/23.838ms에 수락됐는데 캐시의 마지막 응답은 36.912/36.696ms다. 오래된 `obj_rom_*` 계측 이름만 보고 이 간격 전체를 ROM 경쟁으로 부르지 않는다. 실제 bulk 뱅크 해제·생산 재개·map/ordinary 소비 연결을 다음에 대조해야 한다.

|---|---:|---:|---:|

seal 함수는 1,344→1,336B이며 packet/기존 wait 함수와 공동 map/plan 경계 1,108B는 그대로다. 원본 ARM 대비 전체 Flash는 8B 증가한다. 관측 최대 stack은 두 위상 모두 원본과 같았으나 WCET/최악 stack 상한 증명은 아니다. 60초판 파일명 변경 등 추가 작업도 별도 링크 예산이 필요하다.

새 발행 경계 17조건을 두 판본에서 각각 실행했다. 대기 만료·STOP·잘못된 credit/final ACK·cold·DWT 사용 불가/정지/순환·공통 reset을 포함한다. 장시간판에서 기존 slot 18, bulk 정책 24, plan 7, 입력 credit 9, runtime 16조건을 통과했고 두 판본의 메뉴 준비/해제 5조건과 marker 4조건을 검사했다. 후보 패킷으로 실제 65816 STOP 4조건을 통과했다. 변경 없는 65816의 종료 service 12조건은 718 근거를 승계한다. 이는 새 실물 메뉴 복귀 시험이 아니다.

보드/SDC/65816 변경은 없다. 707D 전체 Lite FIT 15,322LE·962/963LAB·56/56M9K와 기존 제약 setup/hold/recovery/removal +0.362/+0.145/+1.594/+0.483ns를 승계하며 새 Quartus 실행은 하지 않았다. 외부 IO sign-off 범위도 확대하지 않는다.

초기 링크의 Flash 초과와 중간 소스/바이너리를 보존했다. 대기 반복의 poll/시간 조건을 합쳤고, 오래된 ACK 배제 한도를 1초보다 보수적인 2^26 cycle로 바꿔 최종 한도를 맞췄다. 메뉴 시험의 `--trial690` 인자 오류와 60초판에 장시간판 marker690을 적용한 실패는 각각 `--trial 690`·실제 marker704로 수정했다. 최초 분석의 초기 generation0에 표시가 없던 오류도 905–957의 완료 구간으로 제한해 고쳤다. 타깃 검사나 성공 기대값을 완화하지 않았다.

## 후속작업

1. **707D·기존 ARM·65816 선택을 유지한다.** 716B·717 절감과 719의 951/911 동시 회복 경계는 재사용 후보로 보존한다. 이번 설치본은 없다.
2. 8ms/주기 나머지 상수의 반복 조정은 중단한다. 다음에는 953의 BG 생산→E9→이전 ROM 허용 구간과 956의 OBJ capture 공급→bulk 뱅크 해제→실제 소비를 분리해 위의 최소 9.45–9.73ms 부족분을 줄일 구조를 검토한다. 신규 캐시나 ROM 경쟁 제거를 입증 없이 이득으로 계산하지 않는다.
3. 현재 DMA 가능 여부를 새로 공개해야 한다면 기존 E0 이력과 혼동하지 않고 identity·만료·STOP·새 패킷 우선 경계 및 ARM/65816/FPGA 교체 예산부터 확정한다. ARM Flash 여유 0B, FPGA 1LAB/0M9K를 추가 코드·회로의 여유로 취급하지 않는다.
4. 두 위상에서 951≤246선·911 2회·952 3회·957 최종 대기0·7블록과 기존 네 화면의 계산 절감을 유지한다. 밀집 평균/952–957 회차/마지막 ACK를 함께 개선한 후에만 새 실기 전달을 검토한다. 전달 시 60초판·장시간판/새 파일명, RESTORE 제외, 5–40초·40–55초 비교 정책을 유지한다.
