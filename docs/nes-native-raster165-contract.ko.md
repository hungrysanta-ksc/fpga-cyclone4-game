# 165 행별 표시 상태와 팔레트 묶음

목적은 CHR 캐시의 그림을 SNES에서 어느 위치·색상으로 표시할지 전달하는 경로를 만드는 것이다. 픽셀 전체 복사를 대체하기 위한 구현이며, 새 진단 화면이나 실기 시험판은 아니다. [검증 결과](../analysis/native-raster165-verification.json) · [앞선 실제 PPU 연결](nes-native-tap165-contract.ko.md).

## 구현한 경계

동결164를 복사한 뒤 실제 PPU의 현재 Loopy `v`, 임시 `t`, fine X, 지연된 BG/OBJ 패턴 선택·스프라이트 크기, 표시 마스크와 팔레트32색을 관측 포트로 노출한다. 팔레트는 실제 `PaletteRam` 배열에서 읽고 `$3F10/$14/$18/$1C` 별칭을 적용한다. CPU 쓰기를 별도로 흉내 내지 않으므로 리셋/세이브상태 복원과 원본의 팔레트 corruption 변경도 반영된다. `$2006` 지연 적용과 `$2007`의 실제 주소 증가도 관측한다.

기존 캐시 생성기를 재사용하는 새 생성기는 추가 부분의 역변환으로 원본 바이트 보존을 검사한다. `NES → nes_probe → nes_live_joint` 관측 배선과 `nes_native_raster165` 연결을 생성한다. 전체 보드 연결부는 **컴파일만 했으며 실행하지 않았다.** 게임·ROM 서비스·기존 CHR 캐시에는 새로운 요청이나 대기 신호를 추가하지 않는다.

NES 클록에서 다음 상태 묶음을 만든다.

- 기존 화면과 같은 NES8~231행, 각 dot1에서224개 행 상태를 수집한다. dot/행 번호는 원본 PPU 기준이며 SNES 좌표가 아니다.
- 행마다56비트: `[14:0] v`, `[29:15] t`, `[32:30] fine X`, `[35:33] {OBJ크기,BG패턴,OBJ패턴}`, `[43:36] 표시마스크`, `[48:44] 팔레트 번호`, 나머지0.
- **v/t는 원시 Loopy 값이다.** 프리페치 때문에 이미 진행된 가로 주소를 그대로 SNES 스크롤로 쓰면 안 된다. 실제 fetch/타일맵 좌표와 연결하는 단계가 남았다.
- 이전 행과 팔레트가 달라지면 새 버전을 최대32개까지 기록한다. 같은 과거 팔레트가 재등장해도 새 버전으로 세며, 고유 팔레트 전체를 검색하는 캐시는 아니다.
- 팔레트192비트를 먼저 래치한 뒤32 NES클록 동안 색상당1바이트로 저장한다. 직렬 저장 중 원본 팔레트가 바뀌어도 같은 버전 안에서 섞이지 않는다.
- 232행 dot1에서 봉인한다. 호스트가 아닌 **같은 NES 클록** 조회만 지원한다. 소유 중에는 다음 화면의 상태가 덮어쓰지 않으며 release/reset은 조회도 취소한다. 세대 번호는16비트 순환값이며 영구 고유 ID가 아니다.

상태 데이터 크기는 행1568바이트+팔레트32~1024바이트, 합계1600~2592바이트다. 헤더·CHR·타일맵·OAM·전송 비용은 제외한 수치다. 실제 합성 RAM/LAB 배치나 SNES 수직공백 예산을 통과했다는 뜻이 아니다. 현재56/56M9K 설계에 추가한 실기 빌드는 만들지 않았다.

## 유효성의 의미

`owned`는 수집 종료, `valid`는 **이 상태 묶음의 제한된 형식 검사 통과**다. 화면 전체 준비 신호로 사용할 수 없다. CHR 완성/물리 뱅크 버전·맵/OAM·MMC3 분할·PPU 픽셀 파이프라인까지 일치한다는 의미가 아니다.

| 오류 비트 | 거부 조건 |
|---|---|
| 0 | 누락/반복/순서 불일치 행, 끝까지224행 미수집 |
| 1 | 팔레트 직렬 저장 중 다음 버전 요구, 종료 시 복사 미완료 |
| 2 | 팔레트 버전32개 초과 |
| 3 | 가시 행 내부 dot2~256에서 팔레트/fine X/패턴/마스크 변경 |
| 4 | 가시 dot1~256의 PPU 설정·스크롤/데이터 접근 또는 지연 주소 적용 |
| 5 | 원본 ROM 서비스 오류 |

행 중간 효과를 행 시작 상태 하나로 잘못 표현하지 않도록 보수적으로 거부한다. ROM 오류는 PPU CE가 멈춰도 다음 NES클록에 실패 상태로 종료한다. 게임 클록까지 완전히 멈춘 경우의 별도 정지·리셋 처리는 상위 시스템 책임이다. 오류 없는 임의 클록 정지에 대한 자체 타임아웃은 없다.

## 실행한 검사

선택 test05: **1336검사, 합성9프레임, 오류8시나리오 통과**.224행 및32팔레트×32색 전수 조회, 소유 중 불변, 범위 밖 조회, 소유 전 조회, CE 정지, 해제/리셋 취소, 다음 세대 덮어쓰기, 팔레트 초과/복사 충돌/행 누락/행 내부 변경/소스 오류를 확인했다. 실제 `PaletteRam` 쓰기·별칭·corruption을 실행했고 실제 PPU 레지스터를 시드한 관측 포트와 지연 주소 적용도 확인했다. **이 테스트는 SMB3 게임 실행이 아니다.** 앞선 실제 부팅20프레임/CHR 캐시 검증은 변경하지 않고 재사용한다.

컴파일 오류·경고0, 시뮬레이션 오류0/경고39. 그중36개는 시험에서 사용하지 않는 실제 PPU 출력 포트,3개는 원본 PPU 내부 포트 폭/미연결 경고다. 입력 포트를 시험에 맞게 임의로 생략해 동작을 증명한 것은 아니다. 새 부모 연결부는 컴파일 범위다.

attempt01/02는 PaletteRam 선언의 줄바꿈을 생성기가 잘못 가정해 시뮬레이션 전에 실패했다. test03은 초기1320검사 통과. test04는 행 누락 때 fine X/표시 상태도 바뀌는 합성 자극인데 오류를 행 누락 하나만 기대한 검사 실패다. 최종 test05는 두 오류를 정확히 기대하며, ROM 오류 즉시 종료와 추가 경계 검사까지 포함한다. 모든 시도는 별도로 보존한다.

## 다음 실기 연결

1. 실제 OAM/타일맵과 BG/OBJ 필요 타일을 같은 프레임 기준으로 연결한다. 이미 구현한 팔레트·행 상태를 다시 만들지 않는다. 행 내부 거부가 목표 게임의 필요한 분할을 막는지 실제 fetch와 함께 확인한다.
2. 필요한 부분 CHR 보충과 한 논리 슬롯의 여러 물리 뱅크 사용을 처리한다. 캐시 lease와 이번 state lease는 아직 독립이므로 상위 프레임 게시 조건으로 묶어야 한다. 임의 host 신호를 NES 입력에 직접 연결하지 않는다.
3. host CDC/소유권과 SNES 맵·OAM·팔레트·CHR 소비를 연결하고 기존38M9K 픽셀 버퍼를 대체한다. 최소 변경 경계 검사와 자원/타이밍 확인 후 실제 SMB3 이동·점프·스크롤로 평가한다.

실기 설치 후보164, 사운드·STOP·메뉴 복귀는 유지한다. 부드러운 화면 목표는 미완료이고 새165 패키지는 없다. 정상 영상·사운드 다음60초 제한 해제/오류·본체 리셋 안전 로그, 이어 장시간 입력 유지 순서는 그대로다. 범용 모든 매퍼/별도 진단 확대를 새 선행조건으로 만들지 않는다.
