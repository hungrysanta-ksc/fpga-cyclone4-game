# NES725 수락된 map DMA와 bulk 소비 순서 검증

## 목표

723C의 BG ROM 마감과 map 연속 DMA를 유지하면서, 실제65816이 검증한 bulk 명령을 보유하는 동안 앞서 수락된 map을 DMA한다. Flash·ROM 한도, STOP·독립 검사·최종 ACK·메뉴 경계와951·911·952·957 조건을 지키고 두 시작 위상의952–957 표시 간격·마지막 ACK를 함께 줄이는지 확인한다.

## 작업내용

A는 bulk header·generation·token·범위 검증 후 payload 수신 전에 기존 prefix DMA를 한 번 실행한다. B는 bulk payload 소비·receipt 기록 뒤 packet ACK 전에 실행하며, DMA 대상을 이전에 수락된 map으로 제한한다. 새 head를 검사하기 전 DMA하는 방식이 아니다. 현재 검증한 head를 그대로 보유하고, idle 경로의 새 패킷 우선권은 유지한다.

기존 transaction word `$1228`의 bit1을 호출 중에만 소유권으로 사용한다. open=1→3→1이며 원래 완료·STOP 경로로 돌아가기 전에 복구한다. prefix의 비활성 뱅크 검사, 실제 VBlank 위치 확인, 동기 DMA 완료 후 cursor 갱신을 재사용한다. STOP은 DMA 전에 확인하고 진행 중 발생하면 해당 DMA 완료 직후 처리한다. packet 수락·bulk 소비·최종 표시 ACK를 합치지 않았다. 새 지속 RAM·ARM 코드·SPI 명령은 없다.

B의 첫 구현은 방금 복사했으나 packet ACK가 아직 없는 tile까지 기존 selector가 고를 수 있었다. 두 위상 모두 독립 수락 이력 검사가 `tile not accepted`로 중단했다. 검사를 완화하지 않고, 최종 B에서는 소유권 호출 중 map source만 허용했다. 일반 idle tile 처리는 그대로다. 중간 실패와 수정 전 바이너리를 보존했다.

실제723C 링크 ARM과 후보65816을 실행하고, 같은 map·tile·plan·픽셀을 비교했다. 시작 시각7288416/7467100, CPI2/84MHz, 공유SPI·IRQ·기존 ROM 허가 달력은723과 같다. 후보별53화면×2위상, 총212화면을 완료했다. 이는 실제 명령 실행을 포함한 모델 비교이며 전체 NES/PSRAM RTL 동시실행·실기 FPS·물리 메뉴 복귀 증명은 아니다.

## 성과

**두 후보 모두 자원·독립 검사·보호 조건은 통과했지만 종단 성능 기준에는 실패했다. 선택본707D·기존 ARM/65816과723C 시간 비교 기준을 유지한다.**

두 후보 모두951 공개236선·3VBlank,911 표시2VBlank,952 표시3VBlank,957 최종 대기0회,다음 입력7블록,908/934/940/943 표시2VBlank를 유지했다. 952/956/957 선행 map1920/1024/2048B와953 첫 BG→마지막 BG의 동일 ROM 허가 구간도 보존했다.

### 추가 소비 기회를 열어도 수락된 map이 부족했다

A에서 새 소유권 경로의 실제 DMA는 위상1의946/947 각192B, 위상2의946/947 각192B 및956의128B였다. B는 위상1의917/946/947, 위상2의946/947에서만 실제 DMA를 실행했다. B의952–957에서는 새 경로로 추가 map DMA가 한 번도 일어나지 않았다.

각 bulk 진입 시 이전 packet ACK로 수락된 map byte 집합에서 실제 완료된 map DMA를 뺀 결과를 함께 기록했다. B의952/953/955/956/957에서는 모든 bulk 진입 시 남은 수락 map이0B다. 954의후속 bulk 세 번에는192B가 남지만 이미 활성 화면 구간(수락16–78선)에 들어가 DMA할 수 없다. 따라서 이 일정에서는 **bulk가 보유한 head 때문에 충분한 map을 DMA하지 못하는 상황이 주된 병목이 아니다.** 아직 수락되지 않은 map을 소비 순서 변경만으로 전송할 수는 없다.

실행할 map이 없는 호출도 비용이 든다. B는 보통54–77µs, 새 작은 tile을 선택했다가 map-only 조건으로 거절하는 경우 약162–164µs를 소비했다. 이 비용까지 전부 포함했으며 새 selector를 더 붙여 개선으로 주장하지 않았다. A 위상2의956에서128B를 앞당긴 경우에도 전체 선행량과 표시 회차는 그대로다.

ARM은723C 정상/장시간 ELF·firmware hash가 그대로이며 재링크하지 않았다. 정상 여유0B·장시간44B,공동 코드 경계4698B/한도4700B를 유지한다. ROM 여유 증감은 압축 결과를 포함하며 body 삭제로 계산하지 않는다. 기존 idle selector를 공유했지만 순삭제는 없고 body49/71B가 추가됐다.

새 CPU 소유권 시험 A14/B15조건은 실제 beam·DMA·VRAM, inactive/cold 거절, 새 head 우선, DMA 전·중 STOP과 cursor 완료를 확인했다. B에서는252선 수평1128클록의 마지막 위치 확인 뒤1152B가254선에 시작해261선 안에 끝났고, 진행 중 STOP은 완료 직후 처리했다. 방금 소비한 tile의 조기 DMA 거절도 확인했다. 별도 후보별 manifest/descriptor 오류8조건,최종 표시 전후 STOP4조건,사용자 종료 경계2조건,정상 복원·ROM 손상 거절4조건을 통과했다. 기존 ARM 메뉴·cold·credit 검사는 동일 바이너리의723 근거를 승계한다. 실제 SD/menu 하드웨어 재시험은 하지 않았다.

중간 검증기에서 owned DMA를 무조건 packet 외부로 한정했던 조건을 수정했다. 실제 소유권 진입/복귀 구간을 먼저 증명한 다음에만 op7의 VRAM DMA를 집계한다. 원래 수락 바이트 집합·inactive bank·내용·VBlank·완료 검사는 유지했다. 늦은 주사선 fixture는 준비 코드가 이미 목표선을 지난 사례를 발견해 다음 프레임부터 정렬하도록 수정했고, 실패 원본을 보존했다.

RTL·SDC는 바꾸지 않았다. 707D의15,322LE·962/963LAB·56/56M9K 및 기존 STA 근거는 변경 없는 회로의 참고치다. **새 ROM 내용에 대한 전체 FIT·STA는 실행하지 않았다.** 시간 채택 기준에서 탈락했으므로 새 보드 통과·회로 절감·외부IO 승인 확대를 주장하지 않는다.

## 후속작업

1. 725A/B를 선택본에 적용하지 않는다. bulk 앞/뒤에 무조건 DMA 조회를 추가하는 실험과 pack prefix 조정만으로 시간 이득을 만드는 튜닝은 종료한다. B0의 미수락 tile 허용도 재사용하지 않는다.
2. 723C 일정에서 목표 VBlank 직전 확정된 map의 생산→ARM 발행→65816 ACK를 실제 완료 DMA와 연결한다. 수락된 backlog가0인 원인을 생산 미완료와 공유SPI/credit 대기로 나누고, 기존 BG 묶음의 ROM 마감을 지키며 map을 먼저 수락할 수 있는 정확한 범위·필요 시간을 산정한다. 이미 실패한 무조건 OBJ 우선·행별 즉시 flush를 반복하지 않는다.
3. 바뀔 경계는 ARM의기존 `packet_wire`·`wait634`·SEAL 발행과65816의기존 수락/idle 진행 제어다. 단순 추가 호출 대신 교체할 명령을 먼저 특정한다. ARM 전체Flash212992B·같은 경계4700B·추가 지속RAM0B,원래65816 물리ROM 여유26B,FPGA86LE·1LAB·0M9K를 예산으로 둔다. 이번에 입증한 회수량은0B다. 미채택724의64B나725A의압축 여유를 무료 예산으로 합치지 않는다.
4. 두 시작 위상에서952–957 합계18VBlank 미만·밀집 평균·957 마지막ACK 동시 개선, 기존 보호 조건·STOP·독립 검사·최종ACK·메뉴 경계를 다시 채택 기준으로 쓴다. 새65816 후보는 복원 부팅 시간도 함께 비교한다. 통과한 뒤에만 새ROM을 포함한 전체Lite FIT·STA와 실기 전달을 진행한다.
