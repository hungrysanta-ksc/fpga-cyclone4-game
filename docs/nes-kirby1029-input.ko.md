# 커비 43.61초에서 처음 늦어진 입력 경계

이전 화면 공개를 각 회차의 0으로 잡고, 마지막 입력 D2를 ARM이 D0로 확인한 시각부터 첫 E9, 마지막 타일 공개, SEAL 수락까지 다시 맞췄다. MMC1025 1차와 MMC1028 두 회차는 BG 649·OBJ 17·변경 map 0·타일 11개·3묶음으로 일치한다. MMC1025 2차는 1타일·1묶음이어서 이 화면의 대조에서 제외했다.

| 실기 측정 (ms) | MMC1025 1차 | MMC1028 1차 | MMC1028 2차 |
|---|---:|---:|---:|
| 직전 공개 → 입력 완료 표시 | −0.16 ~ +1.47 | +7.05 ~ +8.68 | +7.70 ~ +9.34 |
| 입력 완료 표시 → FPGA 첫 E9 | 9.06–10.70 | 8.87–10.51 | 9.00–10.63 |
| 직전 공개 → FPGA 첫 E9 | 10.53 | 17.55 | 18.33 |
| 첫 E9 → 마지막 타일 공개 | 12.09 | 12.48 | 12.48 |
| 마지막 타일 공개 → SEAL 수락 | 3.51 | 3.51 | 3.12 |
| SEAL 수락 → 화면 공개 | 7.41 | 15.99 | 15.60 |

입력 완료 표시는 마지막 소스 블록의 CRC·복원 및 D2 뒤 D0의 다음 token 확인을 마친 ARM 호출이다. 32B 헤더 조회는 ARM 기록 시작·종료 사이에 FPGA에서 일어난다. FPGA의 직전 공개→조회와 ARM의 입력 완료→기록 시작을 빼고, 조회 소요와 양쪽 타이머의 양자화를 포함해 범위를 계산했다. 두 판의 FPGA 클록 절대값을 직접 빼지 않는다. 1차끼리 비교하면 이 시점에 이미 5.58–8.84ms의 상대 지연이 있다. 직전 공개 자체의 위상, 첫 데이터가 준비된 시각, ARM이 읽기 시작한 시각, 블록 사이의 서비스 공백은 이 범위 안에 함께 들어간다.

같은 400ms 구간에서 다섯 작업량이 일치하고 최종 ACK 간격이 한 VBlank 늘어난 표본에서도 확인했다. MMC1025 1차와 MMC1028 1·2차의 7/7쌍과 6/6쌍은 입력 완료 지연 하한이 양수다. MMC1025 2차를 기준으로는 4/7쌍과 5/7쌍이다. 네 조합은 각각 같은 원본 회차를 재사용한다. [입력 시각과 비교 표본](../analysis/kirby1029-boundary.json)

## 동일한 ARM으로 두 FPGA 비교

MMC1029는 MMC1025의 FPGA, MMC1030은 MMC1028의 FPGA 산출물을 그대로 사용한다. 두 ARM 이미지의 실행 payload는 파일명 숫자와 로그 헤더의 판 번호만 바꾸면 바이트 단위로 일치한다. 양쪽 모두 지난 55–60초 일반 출력 패킷 추적을 교체해, 30–60초의 동일한 화면 표본에 수신 세대와 다음 값을 기록한다.

- 첫 D1 호출부터 마지막으로 확인된 D2/D0까지 흐른 ARM 클록
- 유효 D1 거래 누계, CRC·원본 복원 누계, D2 송신과 후속 D0 확인 누계
- 위 세 누계를 제외한 블록 사이 시간, 수락 블록 수와 실제 입력 바이트 수

첫 D1 전에 대기한 시간에는 FPGA가 제공할 데이터가 아직 없던 경우와 ARM이 바빠 첫 요청을 보내지 못한 경우가 모두 포함된다. 블록 사이 시간에는 상태 조회·타 작업·계측 코드도 포함된다. 새 SPI 명령은 없으며, 이미 쓰던 8KiB 메뉴 scratch와 75회의 32B 헤더 조회를 재사용한다. 입력은 완료된 두 세대와 묶어 보관하고 독립 검사된 화면 헤더로만 해석한다. 시간 구간 계산은 32비트 ARM 카운터 wrap을 처리한다. 두 판의 인과 대조는 동일한 새 계측끼리 수행한다. 계측 코드가 달라진 과거 판의 FPS는 참고값이다.

먼저 각 한 회씩 무입력으로 실행한다. 작업량과 입력 바이트가 맞는 화면에서 첫 D1이 이미 늦은지, D1 이후의 거래·복원·블록 사이 시간이 길어졌는지부터 나눈다. 목표는 해당 화면의 다음 VBlank 대기를 줄이는 것이다. [계측 제어판](nes-mmc1029-trial.ko.md) · [선행 읽기판](nes-mmc1030-trial.ko.md)

양쪽 최종 링크는 각 212,656B이며 Flash 여유는 336B다. 실제 ARM 코드를 실행한 SPI 재생에서 앞선 세대 905와 다음 세대 906의 소스 입력을 각각 16블록·1,681B로 확인했다. 1,247회 빈 상태 응답을 삽입해도 집계가 같고, 첫 D1의 CRC를 손상시키면 완료 기록은 0개였다. 계측 단독 시험에는 32비트 카운터 wrap, 두 세대 인계와 reset, 확정된 행 복사를 포함했다. SRAM D0, 최종 ACK·EA, 타이머 STOP, base 복구와 메뉴 해제도 두 링크에서 검증했다. FPGA는 각 원본 실기판과 BI3 해시가 같다. [MMC1029 검증](../analysis/trial1029-package.json) · [MMC1030 검증](../analysis/trial1030-package.json)

## 실기 대조 결과

커비 무입력 각 한 회에서 MMC1029는 1–30초·30–60초에 780·828장(26.90·27.60 FPS), MMC1030은 809·861장(27.90·28.70 FPS)을 공개했다. 두 판 모두 실행·60초 STOP·base 및 메뉴 복귀에 성공했다. 후반 프레임 시작 기준 출력·최종 ACK 비용은 25.50→24.03ms였다.

같은 400ms 구간에서 BG·OBJ·map·타일·묶음 수가 일치한 43쌍 중 입력 블록·바이트 수도 같은 30쌍을 대조했다. MMC1030의 공개와 최종 ACK는 5쌍이 한 VBlank 빨랐고 25쌍은 같은 VBlank였다. 5쌍 모두 직전 공개를 기준으로 첫 D1을 일찍 시작했다. 33.23초에는 16블록·1,657B의 수신 소요가 소수 셋째 자리까지 같아도 첫 D1이 약 10.78–14.04ms 먼저였다. 42.82–42.83초에는 블록 사이 공백이 4.52ms 늘어도 일찍 시작해 직전 공개 기준으로 입력 완료가 앞섰다. 제시한 첫 D1 시각은 입력 완료 표시 범위에서 실측 수신 소요를 뺀 추정이며 마지막 D0 뒤 계측 처리 오차가 있다. 다음 대조는 첫 유효 D0 응답과 D1을 이전 세대 출력 및 공유 SPI 점유와 맞춰, 입력이 일찍 준비됐는지 ARM이 일찍 읽었는지 구분한다.

43.6초에는 두 판 모두 17블록·1,790B지만 출력 타일은 5개와 11개였다. 2 VBlank에 각각 공개됐으며 이 화면은 같은 출력 작업량 대조에서 제외했다. 표본은 1029가 75/75, 1030이 74/75개 유효하다. 1030의 50.83초에는 직전 공개 타임스탬프 0xffcc와 SEAL 0x0034 사이에서 계측 카운터가 돌아 판독기가 헤더를 제외했다.

사용자는 간헐적인 순간 화면 깨짐을 보고했다. 판과 발생 시각은 특정되지 않았다. 양쪽 모두 전송 실패·캡처 중단·실행 ROM 오류·native video 오류는 0이었다. 최초 종료 사유는 두 판 모두 60초 타이머였고, 1030은 D2 송신·응답 확인 단계의 수신 상태 24도 남겼다. 이 값에는 화면별 시각이 없고 BIN에는 표시 픽셀이 없어 깨짐과 연결할 수 없다. 다음 자연 발생 시 판 번호와 경과 초 또는 짧은 영상으로 같은 장면의 map·CHR·DMA 및 원본 표시를 대조한다. 실기 성능 기준은 MMC1024를 유지한다.
