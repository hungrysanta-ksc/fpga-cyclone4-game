# 568 · loader 명령 거부와 epoch 수신

**실기판은 MMC558, 다음 설계 기준은 567의 양방향 mailbox 보드로 유지한다.** 세 후보 모두 CHECK·STOP 기능은 통과했다. A는 목표 setup을 회복했지만 보드에 새 hold 위반이 생겼다.

기준은 567의 양방향 mailbox 보드다. 이 보드의 168MHz 대상 setup은 −0.024ns였고 최악 경로는 CHECK 실패 래치에서 END 거부 레지스터까지였다. 기존 one-hot `phase`와 거부 레지스터는 같은 에지에서 함께 갱신된다. 한쪽에서 다른 쪽의 값을 구해도 명령을 받는 에지가 같다는 점을 이용했다.

- **A · END만 교체.** DATA를 거부하는 IDLE·READY·RUN에 SETUP·WRITE·HOLD·RELEASE를 더하면 END의 상태별 거부 조건이 된다. 기존 DATA 거부 레지스터를 재사용해 END 전용 레지스터 하나를 삭제했다.
- **B · 전체 교체.** BEGIN·START·END·DATA를 거부하는 조건을 모두 현재 phase에서 구한다. 네 거부 레지스터를 없애고 기존의 명령 충돌·잔여 바이트·sticky fault 검사를 유지했다. 기존 phase 레지스터와 오류 처리는 사용한다.
- **C · CHECK 실패의 최종 선택.** 네 거부 레지스터를 유지한다. WRITE·HOLD는 항상 END 거부를 유지하고, 나머지 phase에서는 차단된 명령과 정상 명령의 다음 END 판정을 각각 계산한 뒤 CHECK 실패로 선택한다. fault·STOP·terminal의 우선순위는 두 경우 모두 보존한다. 세 후보의 전체 보드를 같은 기기·seed·SDC에서 각각 한 번 합성했다.

## 같은 에지에서의 명령 수락과 쓰기 완료

567과 각 후보를 함께 실행했다. 16개 phase 인코딩과 모든 phase가 0인 경우, 다섯 명령 비트의 32개 조합, CHECK 차단·기존 fault·최종 byte·최종 cycle의 16개 조합으로 후보당 8,704건을 구성했다. 각 경우에 다음 에지의 명령과 CHECK 차단을 뒤집어 두 에지를 추적했다. 명령별 거부 판정, sticky fault·오류 코드, 주소·길이·PSRAM 제어 핀을 대조했다. A·B에서 END 검사에 timed phase를 누락한 대조군과 C에서 CHECK 차단 선택을 없앤 대조군은 모두 검출됐다.

실제 boot·loader·reader와 70ns 핀 RAM 모델을 연결했다. 이미 WE가 내려간 상태에서 잘못된 CHECK 요청으로 실패를 래치한 뒤 STOP과 모든 적재 명령을 같이 걸었다. 기준과 세 후보 모두 오류 코드 6을 내고 진행 중이던 쓰기 한 번을 완료했다. WE 펄스는 386.880ns였고, 핀 해제 후 새로운 쓰기나 RUN 허가는 없었다. reset 후 오류와 적재량은 0이었다. 두 위상의 정상 읽기 960개와 STOP·재시작을 포함한 수락·응답 이벤트 1,930개도 동일했다. 이 핀 시험은 처음·마지막 바이트를 써서 적재 경계를 검사하고 중간 RAM은 패턴으로 초기화했다.

epoch 시험은 각 비트가 전환되기 직전의 serial을 설정한 뒤 실제 BEGIN으로 Gray 코드가 한 비트만 바뀌는지 확인했다. 32비트 각각 NES 클록이 도는 경우와 멈춘 경우를 실행했다. 64건 모두 클록 재개·안정화 후 새 ID를 수락했고 loader fault를 걸면 즉시 수락을 차단했다. 코너별 배치 보고서는 모든 `gray[i] → epoch_meta[i] → epoch_sync[i]`의 실제 시작·끝 비트를 검증한다. 첫 단의 raw setup과 다음 NES 에지의 setup은 별도로 기록했다. 핀 실측·준안정성 측정은 이번 시험 범위 밖이다.

대상 setup·hold는 배치·명목 두 뷰에서 같은 결과였다. A·B에서 원래 END 레지스터로 가는 경로는 사라졌다. A의 새 hold 위반은 85°C의 `plan_batch206.control.held[14] → received[14]`였다. B의 대상 최악은 loader phase에서 적재량으로 옮겨갔다. C는 85°C `check_failed → reject_state[2]` 자체를 −0.024→+0.319ns로 바꿨지만 SPI 수신기의 `byte_count[0] → snapshot[48]`가 −0.925ns가 됐다. 세 후보 모두 물리 기준의 미제약 집계는 늘지 않았다. 제약 예외를 추가하지 않았다.

A·B는 0°C epoch 첫 단의 최악 slack이 좋아졌고, C는 나빠졌다. 세 후보의 두 번째 동기화 단은 모든 비트·코너에서 +41.450ns 이상이다. 첫 단 비동기 도착과 두 번째 단의 여유를 합산해 원래 보드 STA 회귀를 면제하지 않았다.

## 연속 표시 일정

두 기존 ARM·SPI·IRQ·ROM 도착 일정에서 실제 65816을 다시 실행했다. 각 53개 RGB 화면, 타일 소비 기록, 표시·ACK 이벤트 9,464 / 9,462개가 567과 같았다. 952·957은 두 위상 모두 직전 표시부터 5 VBlank, 최종 준비 뒤 추가 대기 0회였다. 밀집 5화면 평균은 83.157 / 83.121ms, 마지막 ACK는 87,545,284 / 88,254,606 master clocks였다. 이 수치는 고정 입력에서 loader 변경과 소비 일정을 분리한 결과다.
