# NES165 첫 구현: 수동 CHR 관측 캐시

PR107의 조사/형식 프로토타입에 이어, **정상 수신한 CHR 바이트를 재사용하는 출력용 RTL 부품**을 구현했다. [RTL](../src/nes/diagnostic/nes_native_chr165.sv), [시험](../tests/nes-functional/native_chr165_tb.sv), [실행 도구](../tools/test_nes_native_chr165.py), [결과](../analysis/native-chr165-verification.json).

현164의 실제 PPU/PSRAM/SNES 버스에 아직 연결하지 않았다. 게임 실행·호스트 클록 경계·합성/배치·실기 개선 검증이 아니며 설치 가능한165 패키지는 없다. 이번에는 작은 부품을 독립 검증했고 기존164 동결 소스는 바꾸지 않았다.

## 데이터 공급 결정

기본 공급원은 PPU가 **실제로 샘플하는 정상 CHR-ROM 응답**이다. 새 ROM 요청이나 CPU/PPU 대기 출력을 만들지 않는다. 기존164 `nes_live_joint`에는 `tap_ce && ppumem_read`, 현재 `ppumem_addr`, `rom_ppu_valid`, `external_ppu_data`가 있고, `rtl/nes.v` 내부 `chr_addr`가 매퍼 적용 전 PPU 주소다. 연결할 때 마지막 주소도 명시적으로 밖으로 전달해야 한다. `out_ppumem_addr`는 한 클록 지연된 디버그 레지스터이므로 샘플 데이터와 묶어 쓰지 않는다. 이 연결은 이번에 구현/시험한 범위가 아니다.

**수동 관측만으로 모든 타일이 완성되는 것은 아니다.** 화면 경계에서 잘린 스프라이트나 사용하지 않은 패턴 행은 PPU가 전부 읽지 않을 수 있다. 새 네이티브 화면을 제출하기 전에 필요한 타일 집합과 캐시의 물리 태그/완성 마스크를 대조한다. 빠진 바이트의 적재 시 준비 또는 별도 보충 읽기 경로를 구현해야 한다. 보충 읽기를 현재 PSRAM 중재의 무제한 새 요청으로 넣거나, 타임아웃을 늘려 CPU/PPU 기한을 숨기지 않는다. 이 경로가 없으면 해당 표시 후보는 준비 미완료다.

## 부품 계약

| 항목 | 동작 |
|---|---|
| 캐시 슬롯 | 논리 CHR 주소13비트의 상위9비트로512슬롯, 각16바이트. 완전 연관/LRU 캐시가 아닌 현재 논리 창의 미러 |
| 태그 | 매퍼 적용 후 물리 주소의 상위18비트. 뱅크가 바뀌면 같은 슬롯의16비트 완성 마스크를 다시 시작 |
| 허용 입력 | 정상 응답 표시가 있는 샘플, 물리200000–21FFFF(SMB3 CHR128KiB), 논리/물리 주소의 타일 내 오프셋 일치 |
| 보존 영역 | 데이터8192바이트와 메타데이터512×34비트. 실제 M9K/LAB 수는 미측정 |
| 초기화 | 리셋 뒤512클록 동안 메타데이터를 순차 소거. RAM 내용에 비동기 리셋을 걸지 않으며 초기화 전 입력/조회는 사용하지 않음 |
| 소유권 | freeze는 새 입력보다 우선한다. 이전 메타데이터 쓰기를 끝내고 owned를 올린 뒤 내용이 고정됨. owned 동안 들어오는 샘플은 캐시만 갱신하지 않음; 게임 실행을 멈추는 신호 없음 |
| 조회 | 논리 슬롯과 기대 물리 태그를 함께 요청.16바이트가 모두 유효할 때만 hit. 틀린 태그/불완전 타일/범위 밖 BG 오프셋은 hit0/data0 |
| 형식 | BG2bpp16바이트는 두 비트플레인을 행마다 교차 배치. OBJ4bpp32바이트의 상위 두 플레인은0이지만, 완성된 일치 타일에 대해서만 성공 응답 |
| 해제/리셋 | release는 진행 중 조회를 취소하고 캐시 갱신을 재개. 리셋은 소유권/응답을 폐기하고 마스크 재소거 |

입력/조회/소유권 모두 **같은 NES 클록**을 전제로 한다. SNES 호스트 신호를 이 포트에 직접 넣으면 안 된다. 호스트 CDC와 프레임 단위 소유권 연결은 다음 단계다. 캐시 태그는 ROM 재적재를 나타내지 않으므로 게임 변경/새 ROM 세션에서는 반드시 리셋해야 한다. CHR-RAM/다른 매퍼/같은 물리 주소 데이터 변경의 일반적 지원은 승인하지 않았다.

연속 입력의 메타데이터 read-modify-write에는 직전 쓰기 우회가 있다. 동일 슬롯의 바이트가 연달아 와도 앞 바이트의 유효 표시를 잃지 않는다. 조회와 관측 메타데이터 읽기는 소유권에 따라 하나의 읽기 포트로 나눈다. 실제 RAM 추론/타이밍을 통과했다고는 주장하지 않는다.

## 이번 검사

기존 Starter FLOAT 래퍼로 Questa를 한 번 실행했다. 실제 SMB3 CHR131072바이트를16개의8KiB 논리 창으로 순차 공급하고, 모든8192타일의 BG16/OBJ32바이트를 원래 ROM 비트플레인과 대조했다. 입력 시점은 시험벤치가 만든 연속 샘플이며 실제 PPU/CPU 명령 실행이 아니다.

401432조회 검사 통과, 그중 음성 조건 집계8218. 정상 전체 입력 외에 다른 물리 뱅크 태그, 불완전 타일, 유효하지 않은 응답, CIRAM 주소, 잘못된 바이트 오프셋, BG 범위 초과, 소유 중 쓰기 차단, freeze 직전 마지막 쓰기 완료, 해제 중 응답 취소, 재설정 뒤 기존 데이터 거부를 포함한다. 음성 집계는 조건별 카운터이며 모두 독립 실행 케이스라는 뜻은 아니다. 시뮬레이션 오류/경고0. 게임 바이트와 라이선스/서버 로그는 Git에 넣지 않았다.

## 다음 최소 연결

1. 실제 PPU 샘플의 논리/물리 주소·응답을 묶어 연결한다. 추가 관측 출력이 CPU/PPU/매퍼/ROM 서비스 동작을 바꾸지 않는 경계를 확인한다.
2. 실제 배경·스프라이트가 필요로 하는 타일 집합, 팔레트/OAM/행별 스크롤 묶음을 만들고 캐시 미완성/은행 전환 시 부족 데이터를 해결한다. 캐시 일부만 찬 상태를 화면 준비 완료로 표시하지 않는다.
3. 호스트 CDC·동결된 세대 전달·SNES 소비를 연결한다. 현재56M9K에 캐시를 덧붙이지 않고38M9K 픽셀 경로의 대체 자원으로 배치한다. 40KiB VRAM/5632바이트 청크 초안은 실제 패킷과 DMA로 다시 확인한다.
4. 최소 변경 검사 후 실제 SMB3 이동·점프·스크롤로 간다. 기존 사운드/메뉴 복귀를 보존하며, 부품 식별·044/GBC·무변경 전체 적재·모든 매퍼 진단을 반복하지 않는다.
