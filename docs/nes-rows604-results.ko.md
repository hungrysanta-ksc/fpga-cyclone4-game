# 604 · D1 행 압축과 첫 BG의 ROM 마감

**952·954 모두 D1 행 압축으로 입력 SPI가 278 B 줄었다. 첫 BG 계획도 약 1.668 ms 일찍 발행됐지만 두 시작 위상 모두 첫 ROM 허용 시각이 같았다.** 실기 기준은 MMC577이다. 비교 대조군은 MMC577에서 D1 블록 내 generation을 공유하도록 바꾼 600이다.

## 측정한 경계

MMC577 보드의 실제 NES exporter, 96비트 정방향·17비트 역방향 클록 교차 mailbox, 600의 단일 sealed 슬롯과 8 B D2를 사용했다. 604는 묶을 수 있는 동안 행을 모으고 불연속 값에서 기존 레코드를 내보낸 뒤 그 값만 다시 조회한다. 새 D1 버전은 구간 시작값과 개수를 전송한다. M4는 generation, 수신 단계, 앞선 map 완료, 목적지 행 개수와 구간 마지막 값의 map 범위를 쓰기 전에 검사한다.

952·954의 입력은 해시로 고정했다. 직전 표시 뱅크는 MMC577의 링크된 계획기로 905부터 순서대로 재구성하고 성공 ACK를 가정해 commit했다. 각각 같은 이력을 대조군과 후보의 링크된 M4에 주입했다. D0–D3는 Questa의 실제 RTL SPI 핀에서 실행했고 복원된 여섯 geometry 배열과 raw 전체를 원본과 비교했다. 시간에는 M4 명령 수 × CPI 2, 84 MHz, 공유 SPI 2.625 MHz, 명령별 드라이버 평균을 사용했다. 출력 credit·소비·최종 ACK는 모델이다. ROM 시각은 561의 동일 입력 시작과 첫 E9 이후 decode 간격에 509의 부팅 코어 grant 기록을 다시 적용한 값이다. 이 실행에서 실물 IRQ·65816·최종 VBlank는 계측하지 않았다.

## 입력과 첫 BG

| 세대 · 위상 | 실제 입력 SPI 대조→604 | 첫 BG 계획 완료 대조→604 | 첫 ROM 허용, 양쪽 동일 | 직전 ROM 구간의 마지막 기회까지 더 필요한 단축 |
|---|---:|---:|---:|---:|
| 952 · 1 | 3,212→2,934 B | 27.918→26.250 ms | 32.280 ms | 9.818 ms |
| 952 · 2 | 3,212→2,934 B | 27.918→26.250 ms | 32.091 ms | 10.007 ms |
| 954 · 1 | 3,204→2,926 B | 27.578→25.910 ms | 32.502 ms | 9.257 ms |
| 954 · 2 | 3,204→2,926 B | 27.578→25.910 ms | 32.538 ms | 9.220 ms |

시각의 원점은 해당 입력 시작이다. 224행을 네 구간으로 묶어 행 레코드는 280→16 B, D1은 15→14블록이 됐다. 첫 블록 봉인은 양쪽 모두 27.49–27.52 µs이고 짝별 차이는 최대 24 ns다. 행 조회는 224→227회다. 두 경로가 발행한 첫 E9는 32 B이며 페이로드 해시가 일치했다.

실제 차이 278 B는 D1에서 270 B, D2에서 8 B다. D0는 양쪽에서 모두 21회여서 줄지 않았다. 603이 가정한 블록당 D0 한 회 절감을 빼면 8 B D2의 예상 286 B와 일치한다. 603의 282 B 수치는 4 B D2를 전제했다. 600의 최소 출력 조회·8 B map 가정에 이번 실제 입력을 대입하면 952에서 5,253 B, 954에서 5,326 B다. 한 프레임의 5,468.75 B에는 들어가지만, 출력과 실제 ROM·VBlank 대기를 포함한 60 Hz를 달성했다는 뜻은 아니다.

## 검사와 비용

- 연결된 M4는 두 입력·두 위상에서 모델 최종 표시 ACK를 확인한 뒤 EA를 보냈다. 잘못된 최종 ACK에서는 EA가 없었고, EA에서 STOP이 걸리면 다음 입력용 idle로 넘어가지 않았다. D1 CRC 오류에서 POP을 차단했고 잘못된 generation·token, 행 개수·시작값·마지막 map 범위, abort 뒤 늦은 COMMIT을 거부했다.
- 실제 RTL에서 진행 중인 행의 값 상위 비트 오류와 lease 취소를 각각 유발했다. 두 경우 모두 COMMIT 전에 ABORT를 보냈고 reset 뒤 sealed 슬롯·token·lease가 해제됐다. 별도 M4 시험에서 합법적인 231·0 교대 224행도 18블록에 나눠 복원·commit했다. 구간이 전부 끊기면 행 레코드만 896 B여서 이 형식의 절감은 입력에 따라 달라진다.
- ARM 전체 링크는 **212,916→213,104 B**, 한도 212,992 B보다 112 B 크다. ELF data 10,040 B와 bss 18,592 B는 양쪽이 같다. Quartus Lite의 동일 exporter 단독 MAP은 **868→903 LE**, FF 240, 메모리 0 bit다. 전체 보드 FIT·STA와 실기 메뉴 복귀는 이번 후보로 실행하지 않았다.

## 다음 순서

직전 ROM 구간에서 **한 번이라도 읽으려면** 첫 E9를 입력 시작 후 952에서 16.242–16.432 ms, 954에서 16.654–16.690 ms까지 마쳐야 한다. 다음은 현재 입력에서 그 E9에 들어가는 BG tag와 slot이 각각 처음 확정되는 D1 레코드를 찾는 일이다. 수신→commit→계획→E9를 분해하고, 앞서 확정된 값만 임시로 읽어 두는 방식이 실제 SPI·ROM 비용을 내고도 마감을 지키는지 판정한다. 잘못된 D1·취소·STOP에서 임시 결과가 표시 뱅크로 넘어가면 기각한다. 첫 읽기 뒤에 남은 tile·OBJ·DMA·표시 ACK도 별도로 통과해야 한다. Flash 단독 조정과 설치본 제작은 이 마감 판단 뒤로 둔다.
