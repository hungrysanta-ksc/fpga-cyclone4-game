# NES167 — 그래픽 수집 대기 처리 수정 시험

**배포 보류:** 기능 검증은 통과했으나 FPGA 타이밍 기준이 아직 미달이다. 현재167 실기 ZIP은 없다. 아래는 타이밍·외부 연결 지연 검증 후 패키지에 넣을 예정인 절차이며, 지금166 파일을 이름만 바꿔 실행하지 않는다.

166은 화면을 완성하기 전에 그래픽 수집을 계속 취소했다.167은 메모리 사용권·전송 소비를 기다리는 정상 대기와 실제 읽기 응답 오류를 구분한다. 전체 작업 상한과 안전 정지는 유지한다. **화면 복구·속도 개선의 최종 판정은 이번 실기 결과로 한다.**

1. ZIP의 `01-GAME167-SD-ROOT` **안의 내용**을 SD 루트에 복사한다. 이번에는 펌웨어와 FPGA가 모두 바뀌므로 함께 적용한다.
2. `NES GAME 167.nh1`를 실행한다. 0바이트 표식이 정상이며 확장자를 바꾸지 않는다. ROM 적재·검증은 기존과 같아 약4분 정도 걸릴 수 있다.
3. 화면이 나오면 스타트→선택→월드맵→첫 레벨 진입을 시도한다. 화면의 움직임과 소리가 담긴20~30초 영상이 있으면 도움이 된다. 계속 검정이면 촬영·조작은 필요 없다.
4. 소리/게임 실행 시작 후 약60초 뒤 자동 메뉴 복귀를 기다린다. 실행 표식 선택 후 전체7분 이상 무반응이면 대기를 끝내고 상태를 전달한다.
5. `sd2snes/nes-progress-167.txt`, `sd2snes/nes-game-last-167.txt`, 화면·소리·메뉴 복귀 여부를 전달한다. 마지막 TXT가 없으면 진행 TXT만 전달한다.

RUN 중 SD 기록은 하지 않으며 안전 정지 후 최종 TXT를 쓴다. 별도 리셋이나044/GBC 복원 재시험은 필요 없다. 동봉 `02-RESTORE164-SD-ROOT`는 기존164 복원용이며 세이브 파일·카트리지 별도 SRAM은 영상 공간으로 사용하지 않는다.

개발 기록:167의 취소 이유 바이트는 하위4비트가 기존 export 이유, 상위4비트가 fill 세부 오류다. 예를 들어52(0x34)는 export4/fill3,68(0x44)는 export4/fill4다. 사용자에게 숫자 해석을 요구하지 않는다. `native_frames`가 SNES 표시 완료 수이며 COMMIT 횟수만으로 화면 정상·60fps를 판정하지 않는다.
