# NES185 입력 후보 — 자동 패드 읽기 경계에서 잘못된 해제 방지

## 원인과 수정

배포184의 실제 SNES1815 `service_pad`는 VBlank=1, auto-read busy=0이면 JOY1 두 바이트를 즉시 읽어 FPGA로 보낸다. VBlank 시작과 자동 패드 읽기 시작 사이에는 작은 간격이 있다. 그 간격에 busy=0을 확인한 뒤, JOY1을 읽을 때는 자동 수집이 진행 중일 수 있다. 누름이 잠깐0이나 부분값으로 바뀌면 게임에는 해제와 재누름처럼 보일 수 있다.

[Mesen 자동 읽기 구현](https://github.com/SourMesen/Mesen2/blob/master/Core/SNES/InternalRegisters.cpp)의 `ProcessAutoJoypad`는 수집 중 레지스터를 지우고 순차 shift한다. 실제 하드웨어 시험 자료도 이 코드 주석에서 연결한다. [SNESdev 컨트롤러 문서](https://snes.nesdev.org/wiki/Controller_reading)에도 VBlank 진입 직후 busy 검사만으로 완료를 판단하는 경계 문제가 설명되어 있다. 2026-10-15 확인. 에뮬레이터 결과와 사용자 실기의 모든 증상이 동일 원인이라는 최종 판정은 아직 아니다.

후보 `tools/nes_pad185.py`는 화면 활성 구간이면서 busy=0일 때 JOY1을16bit로 읽어 스택에 보관하고, 상태를 다시 검사한 뒤만 기존6002/6003에 게시한다. 읽는 도중 VBlank로 넘어가면 후보를 버리고 이전 누름을 유지한다. 한 활성 구간당 한 번 게시하며 STOP 검사는 매번 유지한다. 기다리는 루프·연타 억제·debounce·버튼 edge 변환은 없다. 실제 해제도 다음 정상 표본으로 전달한다.

프로토콜1815·DATA 큐·FPGA/MCU 코드·화면 처리 방식은 그대로다. 원래 수집 여부 byte1238을 재사용하고, 임시 스택2B만 더 쓴다. 본문3643→3659B, 제한3776B 이내이며 compact ROM4096B다. 후보 생성은 기존 source generator를 조합하며 역사적184 생성물이나 archive를 고치지 않는다.

## 확인 범위

- 동일한 실제 SNES 코드에서 240fields 동안 무입력, A+B+아래+왼쪽 유지, START+SELECT 유지, 오른쪽 유지를 반복. 컨트롤러는 명시적으로 SnesController로 설정하고 자동 읽기 레지스터는 주입하지 않았다.
- 전환 주변과 boot를 제외한 동일186표본: 배포184는78개 잘못된 값, 후보는0개. 전체 게시237/238회와 원본 각 commit timestamp/value를 보존했다. 186개 통과는 물리 패드/FPGA CDC의 완전 검증이 아니다.
- 실제 C 송신기+184 큐의 held-file 모델+실제65816 후보: 정상7화면219ACK, 복사 중STOP61ACK, 긴 반복 중STOP27ACK. 550656픽셀 이전 기대값과 동일, STOP 뒤 후속 패킷 비공개, 반복64B마다 service 보장. 합성 JOY register를 사용한 이 결합 검사는 위의 실제 자동 읽기 검사와 증거 범위가 다르다.
- 이 후보로 새 RTL 이벤트 재생이나 FIT는 하지 않았다. 큐RTL과 프로토콜은 불변이며 이미 통과한184 근거를 유지한다. 새 ROM ASM/패키지/실기 승인 또는60fps 개선을 주장하지 않는다.

초기 실패도 보존: old01 샌드박스 프로세스 종료, old02 한글 Lua 출력 경로에서 파일 생성 실패, old03 컨트롤러 미설정으로 모든 값0인 잘못된 fixture. old03의 결과를 결함 재현 근거로 쓰지 않는다. 최종 old04/new01은 명시적 controller 설정 및 실제 누름값이 도달했는지 검사를 추가했다. 선택 source hash와 fixture raw는 검증JSON/manifest에 남긴다.

## 다음 작업

입력 후보는 다음 화면 성능 변경과 함께 최소 결합검사 및 새 ROM 패키지를 거쳐 실기에 전달한다. 단독 패드 시험판을 위해 사용자의 수분 로딩을 다시 요구하지 않는다. 새 패키지 전까지 배포184는 변경되지 않았으며, 해당 ZIP에 이 수정이 포함되었다고 안내하면 안 된다.

목표는 입력을 덜 받는 것이 아니라 오래 누름을 유지하고 짧은 실제 해제를 구분하는 것이다. 향후 아래 방향 유지/짧은 연속 탭/대시+점프를 실기에서 확인한다. 약60fps, 장기 세션, mapper 확장 작업은 계속 미완료다.
