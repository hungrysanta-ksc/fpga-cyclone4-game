# 998 · 907 OBJ 주소가 확정되는 입력 블록과 연속 표시

## 목표

978에서 907의 448B OBJ가 906 표시 대기 중 어느 입력 블록부터 ROM 허가를 쓸 수 있는지 확인한다. 907·908 공개, 909의 선행 DMA 624B, 910 캡처, 여섯 표시 간격과 912 최종 ACK로 채택 여부를 판정한다.

## 작업내용

모험도 4 원본 캡처의 3416번째 화면을 사용했다. 978에서 공유 포트가 실제로 수락한 물리 주소를 큐에서 항목을 꺼내기 직전에 기록했다. 기준 재실행의 ARM SPI 이벤트·65816 이벤트·타일 준비·ROM 허가 기록은 원본과 바이트 단위로 일치한다. 첫 번째 허가 대기는 위상별 5.128 / 5.061ms다.

첫 실수요 주소는 0x196F0(태그 6511의 0행)이다. 미스는 태그 6511의 0–5행, 태그 3138·3139의 0–7행으로 총 22행이다. 모두 907의 14번째 D2가 끝난 시점에 이미 입력 블록에서 물리 태그와 행 마스크를 얻을 수 있었다. 원본 PPU의 OBJ fetch 주소와 양쪽 비트플레인의 값을 ROM과 대조했다. 뒤에 들어오는 mapper 설정을 예측할 필요가 없었다.

공동 시뮬레이션에서는 ARM·65816 바이너리를 그대로 실행하고 공급 모델만 바꿨다. 906의 SEAL을 발행한 뒤 907의 D2로 반환된 블록에서 읽은 OBJ 순서대로 기존 행 RAM의 인덱스에 채웠다. 907 입력 소유권 전환 때 그 저장소를 보존하는 조건을 모델에 넣었다. 14·15번째 블록 전체에서 읽은 것은 96행이다. 첫 허가는 12,129,252클록, 마지막 응답은 12,134,429클록으로 모두 906 공개 전이다. 인접 태그를 포함한 경우도 마지막 응답이 12,135,557클록으로 두 위상 모두 공개 전에 끝났다. 새 행마다 실제 ROM 허가와 양쪽 바이트를 부과하고, 일반·기존 선행 요청과 같은 허가를 중복 사용하는 일이 없는지 확인했다. 주소·세대 관측과 소유권 전환은 모델이며 새 RTL의 회로·타이밍 측정은 수행하지 않았다.

907에서 기존 선행 경로는 태그 6256·6257의 16행도 채워 두었다. 907의 OBJ 준비가 빨라지면서 이 작업이 사라졌고, 908에서 실수요 읽기가 14회 생겼다. 907 입력의 태그·마스크에 기존 `next_pair` 규칙을 적용해 16행을 같이 읽자 908 공개가 회복됐다. 별도로 907 OBJ 실수요에만 ROM 허가 대기를 없앤 대조군도 96행 후보와 같은 OBJ 준비·907 공개·912 ACK를 보였다.

두 선행 후보 모두 448B OBJ의 65816 반환을 VBlank 35의 246선 종료보다 2.313 / 2.247ms 앞당겨 끝냈다. 하지만 끝에서 두 번째 map(offset 1,152)의 반환부터 이미 0.290 / 0.267ms 늦었고, 마지막 map(offset 1,344)은 0.825 / 0.805ms 늦었다. 이후 팔레트·OAM·section 5 반환을 거쳐 SEAL 수락은 5.975 / 5.953ms, 독립 검사 뒤 업로드 진입은 7.441 / 7.418ms 늦었다. 따라서 공급 개선만으로 직전 VBlank에 공개할 수 없었다.

905–912 여덟 화면은 모든 비교군에서 978과 동일했다. 두 위상에서 907 SEAL 손상은 0xE0, STOP은 0xE4로 끝났고 907의 최종 ACK가 차단돼 906 화면이 보존됐다. 별도의 모델 검사에서 D2 전에는 행을 사용하지 않고, 응답 전·저장 후 STOP 모두 다음 입력으로 행을 넘기지 않음을 확인했다. 실기 메뉴 복귀와 신규 RTL FIT·STA는 미검증이다. [클록·수락 순서·DMA·오류 주입 결과](../analysis/grant998-results.json)

## 후속작업

978을 유지한다. 907 마지막 두 map과 팔레트·OAM·section 5의 실제 준비 시각으로, 전송을 완전히 겹쳐도 VBlank 35에서 독립 검사와 잔여 DMA가 끝날 수 있는지부터 계산한다. 그 하한이 마감을 넘으면 907 발행 순서의 미세 조정을 종료하고, 908 공개·909 선행 624B·910 캡처를 지키면서 실제 표시 한 번을 줄일 수 있는 세대를 고른다.

재현은 `tools/nes_grant998.py`에 작업 임시 경로·위상 1 또는 2를 전달한다. 기본 주소 추적과 `--ideal`, `--early`, `--companion`을 각각 실행한다. STOP·SEAL 대조는 `check_nes_output970.replay`를 `998prefix`의 907 패킷에 `fixed` 모드로 적용한다. `tools/check_nes_grant998.py TEMP ROM OUT`이 원본 물리 주소·양쪽 바이트·기존 재생 일치·보호 조건·오류 주입 결과를 대조한다.
