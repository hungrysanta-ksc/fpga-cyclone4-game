# SDREPORT083 화면·저장 관측 시험

이번 파일은 **실기 첫 관측용 진단 펌웨어**다. NES 게임 실행용이 아니다. 이전 검은 화면/0바이트의 원인을 고쳤다고 확정하지 않았다. SD 명령을 보내기 전에 화면 표식을 먼저 보여 주어 실패 범위를 좁힌다. 실제 TV 가독성과 저장 성공은 이번 실행으로 확인한다.

## 복사할 파일

`FXPAK-SDREPORT083-TRIAL.zip`을 PC에서 풀면 `test`, `restore`, 안내문과 해시 목록이 나온다. 두 폴더를 한꺼번에 SD에 복사하지 않는다.

| 용도 | ZIP 안의 파일 | SD의 대상 | 크기 / SHA256 |
| --- | --- | --- | --- |
| 이번 시험 | `test/sd2snes/firmware.stm` | `/sd2snes/firmware.stm` | 132552바이트 / `60d5ffcf283bdd1a69a62d8baac3f4f1dfad06c2562888c55e0491968663d91b` |
| 시험 후 정상044 복원 | `restore/sd2snes/firmware.stm` | 같은 위치 | 169056바이트 / `1c3b40a3459d24114cb4d91ee9d861d1a08025a670ef25317ef489092203693b` |

복원 파일은 사용자가 제공한 마지막 정상044 파일과 전체 해시가 같다. `firmware.stm.bak-hwTest`로 받았던 HW002 성공 펌웨어는 별도 파일이며 이번 복원용에 넣지 않았다. 없는 `firmware.before-sdinfo072.stm`을 찾을 필요가 없다.

## 실행 순서

1. 콘솔 전원을 끄고 SD를 꺼낸다. 게임·세이브를 포함한 SD 독립 백업을 보관한다. 현재 진단용 firmware를 정상044 백업 위에 덮어쓰지 않는다.
2. `test/sd2snes/firmware.stm` 하나를 SD의 `/sd2snes/firmware.stm`으로 복사한다. 기본 FPGA, `m3nu.bin`, 게임, 세이브는 교체하지 않는다. 이번 패키지는 해당 파일을 포함하지 않는다.
3. TV 전체 화면이 보이도록 **전원을 켜기 직전부터 영상**을 촬영한다. 파일 브라우저에서 진단 파일을 선택할 필요 없이 펌웨어 시작 시 자동 실행된다. 기판 분해, 카트리지 LED, PC USB 연결은 필요 없다.
4. `SDREPORT083 STORAGE TEST`와 아래 표식들을 확인한다. 최종 결과가 나오면 촬영하고 전원을 끈다. 최종 결과가 없으면 전원을 켠 뒤 **90초까지 관측하고 전원을 끈다**. 이는 사용자 관측 종료 기준이며 CPU/클록 고장까지 자동 종료시킨다는 뜻은 아니다. 자동 메뉴 복귀는 하지 않는다.
5. SD 루트의 새 `HW083000.TXT`–`HW083999.TXT` 중 이번 파일과 영상을 전달한다. 0바이트도 그대로 전달하고, 파일이 없으면 없다고 알려준다. 예전 HW002/HW005 등의 파일은 이번 결과로 대신하지 않는다. 같은 실패를 여러 번 반복할 필요 없다.
6. 전원이 꺼진 상태에서 `restore/sd2snes/firmware.stm`을 같은 SD 위치로 복사한다. 정상 메뉴가 뜨는지와 GBC 실행 결과를 확인한다. 복원 파일의 해시 확인과 실제 정상 복귀 확인은 별개다.

## 정상 순서와 결과 해석

| 마지막으로 읽힌 화면 | 그 뒤 시도하는 일 / 해석 |
| --- | --- |
| 083 표식이 전혀 없음 | 펌웨어 적용·MCU 시작·mini 준비·초기 표시 범위부터 확인. SD 저장 실패로 단정하지 않음 |
| `STEP 1A INIT SD` (1초) | SD 초기화. 아직 TXT 만들기를 시도하지 않음 |
| `STEP 1B MOUNT FAT` (1초) | 초기화 성공 후 첫 FatFS mount. 아직 TXT 만들기 전 |
| `STEP 2 CREATE TXT` (0.5초) | 새 이름으로 파일 생성 |
| `STEP 3 WRITE CONTENT` (0.5초) | 256바이트 단위 내용 쓰기 |
| `STEP 4 SYNC` (0.5초) | 데이터·FAT·디렉터리 반영 |
| `STEP 5 CLOSE WRITE` / `STEP 6 OPEN READ` | 쓰기 닫기 / 재읽기 열기, 각각0.5초 |
| `STEP 7 VERIFY BYTES` / `STEP 8 CLOSE READ` | 크기·전체 내용 비교 / 읽기 닫기, 각각0.5초 |
| `TXT SAVED + READBACK OK`, `Save code: 0` | 펌웨어의 저장·전체 재읽기 검사 성공. 파일3072바이트와 영상을 함께 회수 |
| `TXT SAVE FAILED`, `Save code: 2`–`7` | 파일시스템 또는 내용 검사 실패. 표시된 코드·파일명·파일 그대로 회수 |

표시 뒤 RESET을 다시 유지하는 구간에서는 화면이 꺼지거나 바뀔 수 있다. 마지막 정지 사진보다 전체 영상이 필요하다. 마지막 표식은 **다음 작업을 예고한 기록**이며 정확한 전기적 오류 코드나 그 작업이 끝났다는 증거는 아니다. 표식의 SRAM 비교 및 대기만으로 TV가 읽을 수 있다고 보장하지 않는다.

저장 코드2=파일생성 실패,3=1000개 이름 모두 사용 중,4=쓰기 실패/짧은 쓰기,5=sync 실패,6=쓰기 close 실패,7=재열기·크기·내용·읽기 close 실패다. 공유 SD/SPI/timer 고장에서는 추가 화면/SD 접근을 막으므로 최종 실패 문구가 없을 수 있다. 파일이3072바이트여도 최종 readback 성공 화면과 동일한 의미는 아니다.

화면 대기 합계는 모델 기준5.5초다. 초기 부팅·SD IO 시간은 별도이며 실물 소요 시간은 미측정이다. runtime의 부팅/초기화 구간60초·100만poll, writer 진입 후10초·10000poll 제한과 하위 타이머 제한을 유지한다. MCU 전원·clock·CIC 시작까지 이 제한이 적용되는 것은 아니다.

## 패키지 범위

새 코드679검사·실제1초 타이머5검사·인과대조4 및 ARM 호출 순서/파일 해시 확인을 통과했다. 기본 mini 비트스트림과 native SD 코드는 이전 고정 입력을 유지한다. 첫 실기 결과를 받기 전에는 저장 문제 해결이나 NES/CF68 실기 통과로 기록하지 않는다. CF68 FPGA 쌍은 설치하지 않는다.

대응 소스는 별도 `FXPAK-SDREPORT083-SOURCE.zip`이다. 공개 저장소에는 도구·가이드·검증 요약을 올리고 바이너리/개인 원본은 넣지 않는다. 완전한 TV 실패 지점·전압·클록 원인이 아니라 **첫 SD 접근 전후의 관측 범위와 저장 결과**를 확인하는 시험이다.
