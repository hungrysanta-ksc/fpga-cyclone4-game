# 756 · 957의 OBJ 준비 중 map 발행과 955 표시 이력

## 목표

753의 연속 일정에서 두 가지를 분리했다. 첫째는 BG map 확정 후 OBJ 준비 때 마지막 페이지 발행을 시도하는 ARM 일정이다. 둘째는 955의 대상 뱅크 최종 ACK를 근거로 957의 변경된 4B 그룹만 보내는 명령이다. 합격 조건은 양 위상에서 첫 VBlank 248선 끝까지 마지막 map 반환, 957 표시 2 VBlank, 952·957 각각 SEAL 전 1,536B 연속 DMA, 같은 blank에서 BG→map→OBJ, 749 E8 마감·OBJ 256선 시작, 밀집 평균과 957 마지막 ACK 동시 개선이다. ARM Flash 상한은 212,992B다.

## 작업내용

753과 같은 707D FPGA 증거·공유 SPI·IRQ·ROM 달력·시작 클록 두 개를 사용했다. ARM 전체 링크를 명령 단위로 실행하고, 정적 ROM 리셋부터 Mesen의 65816과 동기화했다. ARM 명령 시간은 CPI 2, SPI 드라이버 시간은 실측 보정이다. 원본을 같은 harness에서 다시 실행해 패킷·CPU 표시·DMA·ACK 클록 일치를 확인했다. 각 실행에서 905–957의 53개 RGB·map 이미지, 논리 패킷과 독립 map 복원 결과를 원본과 맞췄다.

- **OBJ 중 발행**. BG를 확정하고 OBJ 우선순위 8개를 처리하는 사이에 기존 map 커서·tile 우선권을 지키면서 발행을 시도했다. 별도 후보는 로컬 credit이 오래됐을 때 실제 E0의 CRC·identity를 검사해 반환된 슬롯을 확인한 뒤 발행한다. 전송은 기존 동기식 SPI를 사용한다.
- **변경 그룹**. 매 최종 표시 ACK 뒤 ARM이 해당 뱅크의 2,048–3,583 바이트를 RLE 이력으로 확정한다. 이력이 없거나 한도를 넘으면 전체 범위를 보낸다. 65816은 자신의 뱅크·최종 표시 serial, payload 길이, 복원한 전체 범위의 두 합계를 독립적으로 검사한다. STOP은 64B 단위로 처리한다. 955→957의 8개 마스크에 순서대로 3·5·5·3·3·5·6·4개 그룹이 설정됐다.
- **결합**. 기존 credit으로 OBJ 사이에 시도하는 일정과 변경 그룹 명령을 함께 연결했다. 추가로 753의 957 패킷 도착 시각만 모두 3.57ms 앞당긴 수신기 재생을 별도로 수행했다.

## 성과

| 후보 | Flash B | 마지막 map의 248선 초과 ms | 957 표시 VBlank | 밀집 평균 ms | 마지막 ACK 차이 ms |
|---|---:|---:|---:|---:|---:|
| 753 | 212,960 | 14.646 / 14.932 | 3 / 3 | 49.910 / 49.912 | 0.000 / 0.000 |
| OBJ 중 발행 시도 | 213,028 | 14.964 / 14.935 | 3 / 3 | 49.911 / 49.910 | 33.284 / -0.016 |
| OBJ 중 반환 credit 확인 후 발행 | 213,060 | 13.838 / 13.643 | 3 / 3 | 49.937 / 49.936 | 16.793 / 0.143 |
| 변경 그룹만 | 213,756 | 28.370 / 28.386 | 5 / 5 | 60.896 / 60.894 | 498.751 / 482.095 |
| 발행 시도 + 변경 그룹 | 213,824 | 28.379 / 28.211 | 5 / 5 | 60.894 / 60.896 | 515.385 / 498.735 |

표의 각 쌍은 위상 1 / 2다. 248선 초과는 956 공개 후 첫 blank에서 249선이 시작되는 시각을 수평 클록으로 복원한 값이다. 불확실성은 최대 4클록이다. 밀집은 951 공개부터 957 공개까지 여섯 간격의 평균이고, 마지막 ACK 차이는 같은 위상의 753 대비 리셋 기준 누적 차이다. 이 결과는 연속 시뮬레이션이다.

753에서 마지막 페이지의 첫 발행 함수에 들어가기까지 3.566 / 3.566ms, 실제 E1 전송 시작까지 5.459 / 5.461ms가 걸렸다. 3.57ms의 시작점은 BG 완료 콜백에서 돌아와 OBJ용 OAM을 지우는 시점이다. 이보다 앞선 **BG 완료 콜백 진입**에서도 이미 248선 끝을 0.257 / 0.523ms 지났다. 콜백의 마지막 map 쓰기 관측은 0.256 / 0.522ms 초과였다. 이 값은 4KiB map의 마지막 쓰기다. 개별 192B 범위가 각각 그때 확정됐다는 뜻으로 사용할 수 없다. 실제로 957 패킷 전부의 도착을 3.57ms 앞당긴 재생에서도 SEAL 수락은 3.622 / 3.547ms 빨라졌으나 표시는 3 / 3 VBlank였다.

OBJ 준비 중 기존 credit으로는 8번 모두 미반환 카운터가 4여서 map을 발행하지 못했다. E0로 실제 반환을 확인하자 두 위상 모두 OBJ 준비 중 192B 두 패킷을 발행했다. BG 동결 표식부터 첫 제출은 3.566→0.320ms, 첫 E1 시작은 약 5.46→0.370ms가 됐다. 하지만 952와 957 모두 선행 DMA가 384B와 1,152B로 쪼개졌다. 957의 E8도 749 마감보다 164,347 / 158,900클록 늦었고, 최종 ACK는 원본보다 16.793 / 0.143ms 늦었다. 결합 후보에는 기존 credit 정책을 사용했다.

변경 그룹 방식은 8개 E1의 실제 전송을 **1,688→400B**로 줄였다. 400B에는 변경 데이터 136B, 마스크 48B, 뱅크 이력 serial·두 검사합 64B, 패킷 헤더·SPI 프레이밍 152B가 들어간다. SPI 점유는 약 5.543→1.617ms로 줄었다. 반면 8개 패킷의 **65816 수락→ACK 합계가 약 4.60→19.15ms**로 늘었다. 생략한 그룹도 비활성 WRAM에서 읽어 두 합계를 갱신한다. SPI·수신기는 병행하므로 이 시간을 직렬로 더해 표시 시간을 계산하지 않았다. 변경 그룹 단독과 결합 후보는 양 위상 모두 952·957 대상 1,536B의 SEAL 전 DMA가 0B였고 957의 최종 대기는 한 번이었다.

### 안전 경로와 용량

- 실제 링크의 ARM에서 정상·STOP·잘못된 credit·receipt·최종 ACK·메뉴 복귀 함수 경로를 확인했다. 변경 그룹 encoder에서 60개 조합, 부적합 RLE·오래된 serial의 전체 패킷 복귀, 부분 발행 실패·reset에서 양쪽 이력 무효화를 확인했다.
- 65816에서 957의 이전 serial 변조·검사합 손상·생략된 WRAM 바이트 손상을 각각 주입했다. 셋 모두 오류 0xE0에 956 화면을 유지했다. 첫 64B 복원 뒤 STOP을 넣으면 0xE4, 52개 커밋으로 끝났다. 중단 당시 두 뱅크의 WRAM·VRAM 16,384B를 넣고 cold 부팅해 905·906 이미지와 486개 이벤트가 원본과 일치했다. 양 위상에서 957의 128B 선행 DMA 직전 새 head를 제공하면 65816이 새 head를 먼저 수락하고 53개 최종 ACK를 마쳤다.
- 880B/뱅크 초기 시도는 ARM stack이 workspace와 8B 겹쳐 중단됐다. 700B/뱅크로 좁힌 링크는 통과했고 관측 최소 stack 간격은 68B였다. BSS 19,796→21,212B. 변경 그룹 ARM 이미지는 213,756B, 결합은 213,824B다. 확장 65816 코드 6,528B는 기존 WRAM 예약보다 128B 크고, 압축 저장에 필요한 5,278B는 보드 ROM보다 158B 크다. 시간 진단은 확장 ROM 공간에서 수행했다. FPGA RTL 변경·신규 FIT·실기 설치본은 없다.

## 후속작업

753을 유지한다. 다음 실험은 957의 마지막 페이지 여덟 범위 각각에 대해 **마지막으로 값이 바뀐 시각**, slot 확정, 기존 큐의 실제 반환을 같은 시간축에 놓는다. 이미 내용이 확정된 범위를 BG 완료 콜백 전에 발행할 수 있는지 먼저 확인한다. 이때 952·957의 1,536B 연속 DMA와 후속 OBJ를 기준으로 잡는다. 변경 그룹 수신기는 생략 데이터를 다시 순회하는 19.15ms 비용을 실제로 대체할 독립 검사 경로가 확보될 때 다시 검토한다.

## 재현

1. `tools/prepare_nes_window756.py`에 753 prefix의 src, 새 overlay 경로, 모드 overlap·refresh·deltapage·bothpage를 전달한다. `tools/build_nes_mmc479_arm.ps1`에 같은 base와 overlay를 주어 전체 링크한다. 초기 stack 실패는 delta·both 모드다.
2. `tools/build_nes_window756.py`에 751 sharedfast, 635 client04, 새 client 디렉터리를 순서대로 전달한다. 각 ARM 모드와 control을 `tools/run_nes_window756.ps1 -Variant K -Phase N -Game <ROM>`으로 양 위상에서 실행한다.
3. `tools/check_nes_window756_arm.py`로 각 ARM을 검사한다. 변경 그룹 모드에는 `--delta`를 지정한다. deltapage 위상 1 trace에서 `tools/check_nes_window756.py`의 identity·checksum·retained·partial(재부팅 포함)을 실행한다. 양 위상 head 재생은 `tools/check_nes_static751.py --fault head --source 20800 --size 128`를 사용한다. 이상적 스케줄 대조는 `tools/replay_nes_deadline711.py --mode all --generation 957 --through 957 --advance-us 3570`를 753의 양 위상에 적용한다.
4. 출력 디렉터리의 이름 규칙과 합격 판정은 `tools/analyze_nes_window756.py`에 있다. `--temp <trace-root> --probe ../probes/nes-window756 --out analysis/window756-verification.json`으로 원시 기록에서 결과를 다시 계산한다.
