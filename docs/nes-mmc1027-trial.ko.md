# MMC1027 커비 무입력 60초 실기 시험

1. ZIP 안의 `MMC1027-KIRBY-60SEC-SD-ROOT` 폴더 내용을 SD 루트에 복사한다. MMC1024·1025에서 사용한 일본판 커비 ROM을 `sd2snes/nes/mmc1027.nes`로 복사한다.
2. 전원을 켜고 **NES MMC3 1027.nh1**을 선택한다. 기존 실기에서 초기 적재에는 약 7분 25초가 걸렸다. 오프닝이 시작되면 입력 없이 60초 자동 종료와 메뉴 복귀를 기다린다.
3. SD의 `sd2snes`에 있는 다음 네 파일을 PC의 1차 폴더에 복사한다. 같은 전원 시작 조건으로 한 번 더 실행하고 2차 폴더에 보관한다. 중단된 경우에는 다시 시작하기 전에 생성된 로그를 보관한다.

- `nes-progress-mmc1027.txt`
- `nes-budget-mmc1027.txt`
- `nes-game-last-mmc1027.txt`
- `nes-frame-mmc1027.bin`

표시 FPS는 1–30초와 30–60초를 따로 집계한다. 커비 성능 기준은 MMC1024이며, 같은 계측량의 비교 대상은 MMC1025다. 이번에는 출력 일정과 캐시 정책을 그대로 두고 각 표본의 기존 32바이트 응답 안에 FPGA 사건 시각을 넣었다.

마지막 연속 슬롯 묶음의 첫 계획 수락, 그 묶음의 첫 소비용 CHR 요청·허가, 마지막 타일 완료, bulk END 수락, 마지막 writer 공개, 반환된 마지막 토큰을 담은 첫 E8 스냅샷을 읽을 수 있다. 55–60초의 두 상세 표본에는 기존 ARM 패킷·credit 기록도 있다. E8 스냅샷은 FPGA가 응답을 만든 시각이며 ARM에서 CRC 확인이 끝난 시각은 이후다.

시각 한 눈금은 약 0.390ms다. 8비트 시간의 순환을 유일하게 풀 수 없거나 사건 순서가 맞지 않는 표본은 구간 계산에서 제외한다. 첫 요청 이후의 개별 행 허가는 집계하지 않는다. 2KiB 용량 때문에 연속 슬롯이 여러 뱅크로 나뉘면 계획 시작 시각은 그 연속 슬롯 전체의 시작을 가리킨다. [MMC1025에서 확인한 지연 구간](nes-kirby1026-boundaries.ko.md)
