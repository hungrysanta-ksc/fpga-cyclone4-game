# 911 타일 432B와 마지막 OAM·테이블 반환

## 목표

978의 908 공개, 909 선행 DMA 624B와 910 캡처 여유를 보존하면서 911을 VBlank 44의 246선 끝까지 표시하고 912 최종 ACK를 앞당길 수 있는지 확인했다.

## 작업내용

978과 985의 240B 반환 대조군에 대해, 같은 입력으로 905부터 912까지 전체 ARM 링크와 Mesen 65816을 두 시작 위상에서 실행했다. ARM 후보는 확정된 OAM 앞 176B를 먼저 발행하고, 큐 대기를 생략하거나 201B 뒤 또는 240B 뒤에 배치했다. 별도 대조군에서는 OAM 상위 32B만 리터럴로 보냈다. 65816 후보는 원래 압축 형식을 유지하며 두 반복 값이 같고 section 4·offset 512·길이 32일 때 기존 고정 소스 DMA로 대상 WRAM을 채웠다. 같은 65816을 978 ARM과 985 ARM에 각각 연결했다.

SPI 발행, 큐 도착, 65816 수락·반환, SEAL 검사 진입, 각 DMA의 시작과 마지막 바이트, 공개, 최종 ACK를 추적했다. 32B WRAM 전송은 VRAM 선행 전송량에서 제외했다. 905–912의 RGB, map 바이트와 타일 plan을 978과 대조하고 OAM 반복·리터럴의 복원 바이트도 비교했다. 새 WRAM DMA를 인식하지 못했던 초기 계측은 판정에서 제외했다. 최종 계측은 해당 명령에서 고정 소스와 실제 목적지의 32B를 확인한다.

## 성과

보호 조건을 모두 지킨 고정 소스 DMA + 240B 반환 대기의 측정값이다. 음수는 978보다 빠른 시각을 뜻한다.

| 항목 | 위상 1 | 위상 2 |
|---|---:|---:|
| 908 공개 (VBlank·선) | 38·245 | 38·245 |
| 909 선행 DMA | 624B | 624B |
| 910 캡처 여유 | 0.214ms | 0.200ms |
| 911 타일 16+32+384B 완료 (VBlank·선) | 44·243 | 44·242 |
| 마지막 OAM 반환 변화 | −0.055ms | −0.358ms |
| 마지막 240B 테이블 반환 변화 | −0.052ms | −0.347ms |
| SEAL 검사 진입 변화 | +0.820ms | +0.657ms |
| SEAL 검사 진입 (VBlank·선) | 44·253 | 44·251 |
| 911 공개 (VBlank·선) | 45·240 | 45·240 |
| 911 표시 간격 / 밀집 여섯 간격 합 | 2 / 13회 | 2 / 13회 |
| 912 최종 ACK 변화 | +0.010ms | +0.023ms |

OAM 앞 176B를 먼저 보내면 해당 반환은 3.043 / 3.247ms 빨라졌다. 201B 뒤에 큐를 비운 경우 마지막 OAM 반환은 0.151 / 0.108ms 늦었고, 마지막 테이블 반환도 1.299 / 1.411ms 늦었다. 위상 1에서 909 선행량은 592B로 줄었다. 32B 리터럴은 위상 2에서 마지막 OAM을 0.441ms 앞당겼지만 위상 1의 908 공개가 한 VBlank 늦어졌다.

**246선 마감은 검사와 DMA를 언제 실행할 수 있는지가 결정한다.** 225선 시작부터 246선 끝까지 1.397ms다. 978에서 SEAL 진입부터 독립 검사 후 업로드 진입까지 1.306 / 1.308ms가 걸렸다. 타일 432B와 잔여 raw 192B·팔레트 512B·OAM 544B의 순수 DMA만 최소 0.626ms다. 타일 DMA 뒤 검사를 시작하는 현 순서에서는 225선에 즉시 시작하고 설정·공개 비용을 0으로 잡아도 0.534 / 0.536ms가 부족하다. 이번 후보에서 raw·팔레트·OAM은 실제로 VBlank 45의 238선에 끝났다.

고정 소스 + 큐 대기 진단판의 ARM은 213,040B로 Flash 한도를 48B 넘고, 65816 로더·압축 본문·벡터는 5,134B로 보드 ROM 한도를 14B 넘었다. 정상 경로와 손상 SEAL·검사 중 STOP을 분리해 재생하고 실패 시 직전 910 화면 보존을 대조했다. 메뉴 경로는 ARM 소스의 정상 해제와 실패 시 해제 차단을 시험했다. 실기 설치본은 만들지 않았다. [실행별 시각과 가드 결과](../analysis/oam988-results.json)

## 후속작업

978을 기준으로 검사에서 이미 수락한 불변 범위에 해당하는 일과 마지막 바이트·identity·coverage가 확정되어야 하는 일을 분리한다. 타일 DMA 전 또는 앞 VBlank에서 실제로 끝낼 수 있는 검사량을 먼저 계측한다. 0.54ms 이상을 옮긴 뒤에도 설정·공개 시간이 남는지 확인하고, 늦은 WRAM 쓰기·부분 수신·STOP 주입으로 검사 결과 무효화를 확인한다. 이후 같은 두 위상의 911 공개와 912 최종 ACK를 다시 판정한다.
