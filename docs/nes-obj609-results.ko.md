# 609 · 현재 캡처에서 OBJ를 공급한 연속 일정

실기 기준은 MMC577이다. 비교에는 608의 팔레트 DMA만 적용한 65816과 607의 전체 ARM을 사용했다. 608에서 마감 뒤에 남았던 952의 슬롯 40–50, 954의 슬롯 60–70을 mapper가 확정한 물리 CHR 주소·행·plane으로 복원했다. 각 장면의 96 B는 서로 다른 주소다.

## 두 캡처가 같은 포트를 사용할 때

OBJ PPU strobe에 나타난 주소·값만 수집한다. 각 뱅크는 128라인 × 16 B이며 물리 tile tag와 바이트별 유효 비트를 보관한다. 인덱스 충돌로 tag가 바뀌면 다른 lane의 유효 비트도 지운다. 캡처 시작 때 해당 뱅크의 디렉터리 128개를 비우고, 캡처 종료 뒤 전체 16비트 generation이 맞을 때만 읽는다. 두 뱅크를 번갈아 써서 다음 캡처가 이전 출력의 조회와 겹칠 수 있다. bulk 출력의 두 슬롯과 별도의 저장소다.

- PPU 쓰기를 우선한다. strobe가 디렉터리를 읽고 다음 클록에 데이터를 확정할 때 조회가 같은 읽기 포트를 사용한다. 새 캡처가 쓰는 동안 이전 세대를 읽도록 만든 3,072회 경합을 검사했다. 이 수치는 의도적으로 충돌시킨 RTL 시험의 횟수다.
- Questa에서 53캡처의 OBJ 표본 8,416회와 조회 1,328회를 재생해 1,200회 적중과 128회 miss를 독립 fixture와 대조했다. STOP, 미확정 쓰기, 세대 불일치, 다른 세대의 release, 시작 시 clear 미완료, 불변 ROM 자격 상실을 검사했다. 최종 회로는 클록 사이에서 끝난 STOP 펄스도 응답을 차단하고, 재개할 때 이전 소유권을 먼저 지운다.
- ARM·65816 연속 실행에서는 수락한 E9의 실제 순서로 주소를 만들고 각 적중 값을 독립 tile payload와 대조했다. OBJ 조회에는 적중·miss 모두 8 master clock을 청구했다. miss는 그 뒤의 실제 허가 기록을 기다린다. BG는 기존 일정대로 읽는다. ROM 허가 시각은 보드 부팅 기록 8구간의 주기적 재생이며, 첫 레벨의 실시간 ROM 중재는 별도 검증 대상이다. cold 905는 선행 캡처가 이미 완료된 상태에서 시작한다.

## Quartus Lite 비용

ARM 바이너리는 대조군과 같은 212,976 B로 Flash 16 B가 남는다. 65816 본체도 팔레트 단독 대조군과 같은 4,949 B다. 추가 저장은 FPGA 안의 두 캡처 뱅크가 부담한다. ARM·65816의 Flash·RAM 증가분은 0 B다.

| 같은 EP4CE15 대상 단독 MAP | LE | 조합 논리 | FF | RAM bit |
|---|---:|---:|---:|---:|
| 별도 읽기 포트 | 264 | 183 | 97 | 44,032 |
| 공유 읽기 포트와 짧은 STOP 보존 | 229 | 160 | 86 | 38,400 |

첫 합성에서는 256×22 디렉터리가 두 번 추론됐다. 공유 후 데이터 4,096×8과 디렉터리 256×22가 하나씩 남는다. 각각 M9K 4개와 1개에 해당하는 크기다. 기준 보드에는 148 LE·M9K 5개가 남았다. 단순 추가의 LE 예산 차이는 81개이며, 이는 전체 보드 FIT에서 산출한 부족분이 아니다. 기존 576 보드 FIT의 `nes_chr_cache192`는 337 LE·234 FF를 사용한다. 그 안에는 한 줄 캐시 외에도 물리 주소·세대 응답 확인, ROM 오류 처리와 취소가 포함된다. 601의 한 줄 캐시 대조에서는 53세대 48회 적중했고 952·954에서는 각각 0회였다. 337 LE 전체를 삭제 여유로 계상하지 않았다.

## 두 위상의 전체 처리 결과

두 위상 모두 53화면의 RGB·114,352 B VRAM DMA·최종 ACK가 대조군과 일치했다. OBJ 1,328회 중 1,200회를 저장소에서 공급해 전체 ROM 경로의 요청은 5,616→4,416회다. 이전 캡처 조회와 다음 캡처가 시간상 겹친 요청은 위상별 402 / 402회이며, 모든 조회가 해당 캡처의 종료 이후였다. 같은 물리 뱅크가 다시 시작되기까지 이전 EA 뒤 최소 32.631 / 32.810 ms가 남았다. 실제 bulk 점유는 최대 2, E0의 sent/retired는 모든 거래를 실제 PUSH·ACK 시각과 대조해 최대 4개다.

지연됐던 96 B는 952에서 캡처 시작 9.449 ms, 954에서 9.322 ms부터 모두 남아 있었다. 두 위상의 실제 조회보다 충분히 앞섰다. 아래 차이는 608 팔레트 단독 대비이며 음수는 단축이다.

## 빨라진 ROM 응답이 표시를 늦춘 경로

952는 SEAL 전 DMA가 8건·2,048 B에서 2건·528 B로 줄었다. 나머지 1,520 B가 SEAL 처리로 넘어가 마지막 DMA는 6건·640 B에서 12건·2,160 B가 됐다. 최종 검사 위치는 두 위상 모두 236→248번 선, 남은 credit은 2,496→400 B였으며 246번 검사선을 넘어 한 번 더 기다렸다. 954도 선행 DMA가 1,936→1,104 B로 줄고 SEAL 처리가 736→1,568 B로 늘었다. 따라서 OBJ 응답만 앞당기는 것으로 최종 표시 조건을 만족하지 못했다.

다음은 952에서 SEAL 전 어느 VBlank에 큐가 비지 않았는지를 실제 ARM 발행·credit 반환·65816 수락으로 확인하고, 필요한 일반 명령을 앞당기거나 발행 묶음 사이에 DMA 시간을 확보하는 방식이다. STOP·새 패킷 우선과 246번 검사선은 유지한다. 동시에 기존 한 줄 CHR 캐시의 miss·오류·취소 제어를 함께 대체할 예산을 정한다. 이번에는 별도 포트 264 LE와 공유 포트/짧은 STOP 229 LE까지 측정했으며 보드 통합 FIT·STA·실기 전달은 진행하지 않았다.
