# NES737 · 마지막 map DMA 중 OBJ와 section 5의 SPI 발행

**727을 유지한다.** 세 후보 모두 두 위상의 map DMA 마감은 회복했으나 952–957 평균 표시 간격과 957 최종 ACK를 함께 줄이지 못했다.

727의 두 시작 클록 7,288,416 / 7,467,100에서 905–957을 연속 재생했다. 각 후보는 먼저 잔여 map을 전부 발행한다. 해당 map의 독립 검사·소비 ACK와 빈 큐를 확인한 E0 진행 응답이 도착하고, 미발행 OBJ가 연속된 한 구간이며 patch가 있으면 기존 중재 경로로 scroll·패딩을 공급한다. 나뉜 OBJ·cold·마감 만료는 scroll·패딩의 기존 발행 순서를 따르고, 수신 오류는 기존 실패 경로로 돌아간다. E0는 DMA 진행을 알리며 화면 공개는 여전히 최종 SEAL·ACK가 맡는다.

- A는 기존 raw 계산 위치를 유지했다.
- B는 한 OBJ 구간에서만 raw를 map 소비 대기 중 미리 준비했다.
- C는 기존 raw 순회를 map 발행 직후로 옮겼다. 짧은 patch는 한 번만 변환하고 긴 patch는 원본을 사용한다.

## map 수락 마감과 957의 후속 발행

두 map 열은 직전 화면 공개를 맞춘 뒤 727의 1,536B DMA 시작에서 후보의 마지막 map ACK를 뺀 **여유 시간**이다. 나머지 열은 각 실행의 직전 화면 공개부터 잰 시각이다. 240B 테이블은 헤더 등 19B를 포함해 259B SPI 거래 하나로 전송했다.

## 자원과 검증 범위

| 후보 | 60초판 Flash B | 장시간판 Flash B | 60초판 여유 B |
| --- | --- | --- | --- |
| A | 212,876 | 212,832 | 116 |
| B | 213,020 | 212,976 | -28 |
| C | 212,900 | 212,856 | 92 |

각 후보는 727과 같은 정적 RAM 및 문맥 크기를 사용한다. 여섯 링크 각각에서 발행·오류 경계 16조건과 section 5 원본 독립 복원 5조건을 실행했다. 각 후보의 정상판·장시간판 메뉴 경로와 STOP·credit·최종 ACK 검사를 확인했다. 각 위상 53장, 총 318장의 픽셀과 map·tile·section 5 복원 바이트, 팔레트·OAM 명령 및 plan을 대조했다. 957의 패딩 64B와 1,088B에서 STOP을 주입한 6회 모두 0xE4, 이전 52개 세대만 커밋, 직전 화면 RGB 유지였다.

링크된 M4와 65816의 실행 결과이며 SPI·IRQ·ROM 경쟁은 기존 재생 모델을 사용했다. 동일한 707D FPGA와 65816을 사용했다. 신규 FIT·STA·실기 FPS 측정은 수행하지 않았다.

## 다음에 줄일 비용

727도 이미 957의 map DMA 중 OBJ와 OAM을 발행했다. 이번에는 OAM 대신 scroll을 이 구간에 넣어 scroll·패딩을 앞당겼지만 뒤로 간 OAM을 소비하고 테이블을 수락해야 SEAL이 가능했다. C에서 scroll ACK는 0.817 / 0.609ms 앞당겼고 SEAL 수락은 위상 1에서 0.102ms 앞당겼지만 위상 2에서는 0.202ms 늦어졌다.

각 뱅크의 직전 최종 ACK까지 보낸 데이터를 복원해 비교했다. 밀집 951–957의 일곱 화면 모두 같은 뱅크의 이전 화면과 비교해 1,100B 패딩·240B 테이블·9B 꼬리에서 달라진 바이트는 0개였다. 957의 1,754B 중 차이는 scroll 2B·raw 3B였다. 727에서 이 세대의 section 5는 E1 여덟 건으로 약 2.081ms의 SPI와 약 4.16ms의 65816 소비를 점유했다. 두 자원은 일부 병행하며 이 값을 절감량으로 더할 수 없다.

다음에는 최종 ACK부터 해당 뱅크의 재사용까지 65816 WRAM 쓰기를 추적한다. 유지가 확인된 범위에 한해 독립 검산·이력 보관·메시지·cold/STOP/부분 실패 후 전체 복원까지 계상한 뒤 변경분 전송을 시험한다. 이번 바이트 비교는 송신 이미지의 동일성을 확인한 것이며 WRAM 보존 자체는 후속 검증 대상이다.
