# NES172 — 표시 프로그램 준비 확인 후 SMB3 실행

171은 첫 표시 요청이 FPGA에 보관된 뒤 SNES 응답 없이 종료됐다.172는 ROM 진입·WRAM 복사 검증·표시 준비 완료를 구분하고, 준비 완료 후에만 첫 화면 데이터를 보낸다. 근본 원인이나 연속 화면 문제가 해결됐다고 확정한 시험판은 아니다.

1. `NES172-SMB3-BOOT-READY.zip`의 `01-GAME172-SD-ROOT` 내용을 SD 루트에 덮어쓴다. 펌웨어와 FPGA를 함께 적용한다.
2. 메뉴에서 `NES GAME 172.nh1`을 실행한다. ROM 적재·비교 시간은 기존과 같아 약4분 정도 걸릴 수 있다.
3. 표시 준비는 별도 최대 약5초(65536회 상한도 적용) 기다린다. 준비 실패 시 화면 없이 메뉴로 복귀할 수 있다. 준비되면 기존처럼 약60초 게임을 실행한다.
4. 첫 화면 이후 지속 갱신·소리·메뉴 복귀 여부와 아래 두 파일을 전달한다. 같은 무화면이면 영상은 필요 없다. 화면이 움직이면20~30초 영상이면 충분하다.

- `sd2snes/nes-progress-172.txt`
- `sd2snes/nes-game-last-172.txt`

메뉴 실행부터6분이 지나도 복귀하지 않으면 전원을 끄고 로그를 복사한다. 이는 관찰 상한이며 성공·정확한 벽시계 보증이 아니다. 정상 복원은 필요할 때 `02-RESTORE164-SD-ROOT`를 사용하며, 같은044 복원 시험을 반복할 필요는 없다.

`screen_stage`는0=진입 미확인,1=ROM에서 복사·검증 중,225(E1)=복사 비교 불일치,2=WRAM/SPC 초기화,3=표시 준비 완료다.3은 TV 표시 성공 증명이 아니다. 준비 실패는 `run_first_error=6`이며 기존 오류가 있으면 그 값을 보존한다. `screen_error`는 기존 SPC 결과 용도로 유지된다. 시작 전 실패에서는 음악이나 버튼 시험이 불필요하다.

171 FIFO·PSRAM 우선권·사운드·169 표시 방식·세이브 SRAM 보호는 유지한다. 실행 중 SD 쓰기는 없고 정지·메뉴 복구 뒤 로그를 쓴다.
