# NES735 · 957의 마지막 OBJ 소비와 SEAL 수락

## 727의 마감

957에서 마지막 OBJ의 소비 ACK부터 65816이 SEAL 헤더를 읽기 시작할 때까지 727은 **5.441 / 5.265ms**, 734B는 **5.439 / 5.519ms**가 걸렸다. 아래에서 슬래시 앞뒤는 시작 시각 7,288,416 / 7,467,100 master clock을 뜻한다.

| 727의 같은 구간에서 점유한 시간 | 위상 1 | 위상 2 |
|---|---:|---:|
| ARM 호출자 준비·범위 계산 | 0.829ms | 0.829ms |
| 패킷 작성·enqueue·barrier의 버스 밖 실행 | 0.475ms | 0.475ms |
| 입력 callback·plan 진행·소비 확인의 버스 밖 실행 | 0.538ms | 0.414ms |
| E1 패킷 SPI | 2.700ms | 2.700ms |
| E0 credit·상태 조회 SPI (각 6회) | 0.654ms | 0.654ms |
| E8 producer·D0 입력 조회 SPI | 0.183ms | 0.183ms |
| SEAL 전송 완료 후 65816 수락까지 | 0.061ms | 0.010ms |
| **합계** | **5.441ms** | **5.265ms** |

버스 밖 실행은 관측된 함수 경계 안에서 SPI와 중첩 호출을 제외한 경과 시간으로, 모델의 IRQ·서비스 비용을 포함한다. 한쪽 프로세서의 전용 명령 실행 시간으로 환산할 수 없다. 같은 구간을 65816에서 분해하면 ordinary 헤더 검사·복원·receipt 처리 **4.555 / 4.554ms**, 다음 패킷이 아직 큐에 없어 기다린 시간 **0.490 / 0.416ms**, 준비된 head를 읽기까지 **0.397 / 0.295ms**다. E0의 여섯 번 조회는 모두 큐가 빈 구간 밖에서 끝났다. 큐가 비어 실제로 기다린 E1 시간은 0.317 / 0.366ms였다. 한편 SEAL 자체의 헤더·의미·coverage 검사 **1.628 / 1.633ms**는 SEAL 수락 **후**에 걸렸다. 독립 검사를 제거 가능한 SPI 시간에 더하면 이중 계산이 된다.

727의 마지막 OBJ ACK는 **260 / 259선**이었다. 그 ACK가 왔을 때 해당 VBlank의 246선 끝을 이미 **0.826–0.889 / 0.762–0.826ms** 지났다. 수평 위치의 불확실성을 한 줄로 묶은 범위다. SEAL 헤더 수락만 그 선 안으로 당기는 데에도 **6.267–6.330 / 6.027–6.091ms**가 필요하다. VBlank 끝까지 써도 마지막 OBJ ACK 뒤 남은 시간은 최대 **0.127 / 0.191ms**로, 관측된 SEAL 검사만으로도 초과한다.

## 구현과 독립 검사

727의 ARM 발행 순서에 733의 240→2B 패딩 상수 축소를 적용했다. A는 긴 짝수 길이의 section 5 패딩과 바로 뒤 raw CHR의 선행 영점 워드를 한 op5로 발행한다. 전송 경계를 확장하기 전에 실제 두 바이트 값을 읽고 연속 길이를 확인한다. 957에서는 1,100B + 66B가 1,166B 한 명령이 되고, 다음 literal은 원래의 offset 1187에서 시작한다. raw 전체가 0이면 바로 다음 테이블로 진행한다. 홀수 패딩과 비영점 시작은 기존 전송 경계를 유지한다.

B는 A의 병합을 **이번 화면에서 실제 OBJ를 발행했고 대상 뱅크의 팔레트·OAM 재사용 명령이 성립한 경우**에 적용한다. cold와 map 위주의 화면에서 발행 순서 변화가 누적되는 효과를 분리하기 위한 후보다. 두 후보 모두 기존 순차 offset·CRC·coverage·credit·새 패킷 우선과 최종 ACK 경로를 사용한다. FPGA 707D와 65816 프로그램은 같다.

각 후보에서 전체 링크한 ARM을 사용해 짧은 패딩 240개 길이, compact와 2,048B canonical raw, 홀수·짝수 패딩, 0/1/2바이트, 끝까지 0인 raw, 테이블 앞뒤와 마지막 ACK 거절을 검사했다. 65816에서 실제 병합 명령의 **64B 뒤**와 **1,152B 뒤**에 각각 STOP을 걸었다. 두 번째 위치는 종전 패딩 끝을 넘는다. 두 경우 모두 완료한 바이트만 바뀌고 나머지 WRAM과 직전 표시가 보존되며, 오류 ACK는 0xE4다. A의 906과 B의 907에서 각각 두 경우를 재현했다. 별도 ARM 검사에서 STOP·credit 오류·최종 identity, 60초판·장시간판 메뉴 및 base 복구를 확인했다.

초기 경계 시험에는 planner가 만들 수 없는 880B scroll fixture가 있었다. 727도 거절하는 입력임을 확인했고, 실제 5바이트 record와 끝 1바이트로 만들어지는 871/876/881B로 경계를 검사했다. 초기 STOP fixture는 한글 경로를 JSON escape로 Lua에 넣어 실행되지 않았다. 동일 ROM과 패킷을 ASCII 경로에 놓고 두 중단 위치를 확인했다.

## 두 시작 위상의 연속 일정

905–957의 같은 53개 화면을 후보별로 두 번 재생했다. ARM과 65816은 실제 링크한 바이너리를 실행했고, 84MHz ARM의 CPI 2와 SPI·IRQ·반복 ROM 허가는 기존 모델을 사용했다. 네 재생에서 원본 section 5 전체 바이트, map·tile 목적지와 값, plan 순서, 최종 픽셀과 화면당 최종 ACK를 확인했다. 아래 Δ는 727 대비 변화다.

| 결과 (위상 1 / 위상 2) | A · 연속 영점 병합 | B · 재사용 가능한 OBJ 뒤에서 병합 |
|---|---:|---:|
| 957 OBJ ACK → SEAL 수락 | 4.855 / 5.024ms | 5.111 / 5.195ms |
| 952–957 평균 표시 간격 Δ | +0.000807 / +0.005106ms | +0.006689 / +0.003632ms |
| 951–955 밀집 평균 Δ | -0.014955 / -0.003166ms | -0.001229 / -0.004060ms |
| 957 마지막 ACK Δ | -16.644944 / +0.011733ms | +0.018531 / +0.015551ms |
| 952–957 표시 VBlank 합계 Δ | +0 / +0회 | +0 / +0회 |

두 후보 모두 952/957의 **1,536B 연속 map DMA**, 952 표시 3 VBlank와 957 최종 대기 0회를 유지했다. 957 표시 간격 자체는 양쪽 모두 3 VBlank였다.

- **A**는 956의 마지막 384B를 후속 OBJ보다 먼저 DMA했다. 선행 map/tile은 두 위상 모두 1,024B/64B로 727과 같았다. 위상 1에서 924·933이 각각 한 VBlank 빨라지고 934가 한 번 늦어져, 957 ACK에 앞 구간의 한 VBlank 이득이 남았다. 위상 2에서는 953의 BG가 다음 ROM 구간으로 밀렸다.
- **B**는 두 위상에서 953을 포함한 다음 BG 공급 마감과 934의 2 VBlank를 회복했다. 위상 1에서 956 마지막 384B를 후속 OBJ 전에 전송하지 못해 선행 map이 640B로 줄었다. 위상 2는 1,024B였다. tile 선행은 양쪽 모두 64B로, 734B가 확보한 128B에는 미달했다.

957의 영점 구간은 기존 두 명령이 18회와 2회에 나누어 수행하던 DMA를 19회에 마쳤다. 65816의 ordinary 검사·복원·ACK 점유는 A에서 4.175 / 4.174ms로 줄었다.

A의 정상판 Flash는 212,808B, 장시간판은 212,764B다. B의 정상판 Flash는 212,828B, 장시간판은 212,784B다. 두 후보 모두 212,992B 한도에 들어왔으며 733의 패딩 상수 절감 238B를 유지했다. 전체 정상판은 733보다 A가 16B, B가 36B 크다. 정적 RAM은 양쪽 모두 기존과 같고, FPGA와 65816이 같아 707D의 Quartus Lite FIT·STA 근거를 사용했다. 이번 기록에는 새 실기 FPS나 물리 메뉴 시험이 포함되지 않는다.

**채택 판정은 미달이다.** 707D·기존 ARM·65816과 연구 대조군 727을 유지한다.

## 다음에 줄일 시간

727에서 planner가 확정한 HDMA·테이블은 마지막 OBJ ACK보다 **11.442 / 11.315ms** 앞서 준비됐다. 이 사이에 SPI가 비는 시간은 **2.159 / 2.216ms**지만 각각 40 / 38개 구간에 흩어져 있고, 가장 긴 한 구간도 두 위상 모두 **0.166ms**다. 240B 테이블의 실제 E1 거래는 약 **0.839ms**여서 기존 거래를 그대로 빈 구간에 끼우기는 어렵다. 다음 비교에서는 이전 VBlank의 **마지막 OBJ 수락·소비 마감**을 기준으로, 이미 확정된 section 5를 순차 offset에 따라 scroll·패딩부터 먼저 소비시키고, 테이블의 온전한 SPI 거래를 확보하려면 어느 기존 발행을 옮겨야 하는지 검증한다. 956의 마지막 map과 952/957의 1,536B map이 실제로 DMA된 구간과 다음 BG 허가는 별도로 보호한다.
