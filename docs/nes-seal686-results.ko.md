# 686: SEAL 뒤 입력 소유권을 먼저 넘기기

686은 SEAL 성공 뒤 첫 E0 전에 입력을 시작하도록 소유권을 옮겨 진입 대기를154.389→4.810µs로 줄였다. 두 위상 모두7블록 마감을+1.305946/+0.171500ms로 회복하고957 마지막384B 선행·952 표시3회·957 최종대기0회·보호조건을 유지했다. MMC666 대비 마지막ACK는−0.188944/−0.385896ms지만 밀집 평균은+0.062596/−0.047082ms여서 동시 개선은 미달이다. 위상1의955 마지막map이253선에수락돼1152B 선행 DMA를 놓쳤으므로 MMC666을 유지한다.

## 실제로 바꾼 경계

685에서는 성공한SEAL 전송 뒤에도 첫20B E0의 SPI·CRC·credit 처리를 마친 후 입력poll이 시작됐다. 이번에는 `nes_window184_barrier`가 SEAL 전송 성공 직후 기존reason3 callback으로 입력 소유권을 넘긴다. callback은 이전COMMITTED를 소비 완료 처리하고 최대7블록의D1·CRC·D2/D0 반환 확인을 수행한다. 일반 출력credit 대기와새패킷 우선권은 바꾸지 않는다.

범용SPI `transfer`의SEAL opcode 검사·예산 재설정을 삭제하고 SEAL 전용 경계의 기존 재설정에 합쳤다. send 실패나STOP이면 입력으로 진입하지 않는다. 입력이 끝나도 기존E0 CRC·sent/retired·generation/serial·마지막ACK identity·magic 검사가 통과해야barrier가 반환된다. 입력 수신은 새COMMIT·EA·표시ACK를 대신하지 않는다.

## 위상1의 새 병목

955의 마지막map3392/192B가685에서는65013604에수락을시작하고65025724(251선)에ACK됐다. 실제beam은65027374의252선h402였고1152B DMA가65029180(253선)에시작해65038704(260선)에끝났다.

686에서는같은패킷의시작65016706,ACK65028794(253선)로ACK가3070masterclocks(142.944µs)늦었다. 이미기존252선 admission을넘어추가DMA가없었고,955 선행map1472→320B,최종map384→1536B가됐다.955표시는685의241선에서249선으로늦어졌다. 최종reveal차이는10864클록(약0.506ms)다. 마지막BG6개 ROM응답시각은같았으므로 ROM 전체 공급이 늦어졌다고 단정하지 않는다.

이후956/957에서 다시 따라잡아957 마지막ACK는두위상모두MMC666보다빠르지만,요청한밀집평균까지함께개선한것은아니다. 수락마감을회복해야하며DMA허용선·246검사선을늘려통과시키지않는다.

## 독립 검사·복구와 비용

- 새SEAL/입력/최종ACK 경계23개: 정상·pending·빈입력·완료입력,send실패,SEAL전후STOP,READ뒤STOP,CRC/POP실패,틀린ACK CRC/identity/magic·미래retire·fault·끝나지않는ACK,7블록한도·3블록뒤STOP·중간CRC·cache손상을검증했다.
- 기존수신/credit56개, BG/map33개, 메뉴/base5개·marker4개를 새ELF로 통과했다. 이전685의65816 beam·새패킷·STOP·cold·최종ACK 취소 검사는CPU hash가동일함을묶어유지했다. 새실기시험은아니다.
- 첫E0를수신뒤로옮긴대가로출력status fault 확인도그뒤에온다. 전체재생에서SEAL종료→첫E0의관측최대는위상1 4.397136ms/위상2 4.180761ms다. 이는관측값이며일반WCET가아니다. 각입력거래의STOP/CRC/POP검사와최종ACK이전COMMIT금지는그대로유지된다.
- 전체ARM Flash212952B/free40B로685보다36B절감했다. data10040B/BSS19544B,새정적RAM0B다. wait634 stack40B,barrier24B,through32B,transfer32B,poll560B다.154개C/H를생성기로재현했고7개DWARF구조체는685와동일하다.
- 65816은685와바이트동일: body5984B/free0,packed5120B/free13. 새RTL·DMA기계어변경은없다.685의비선점DMA STOP응답관측최악약0.725ms도그대로유지한다.

전체 시간 조건이 미달이므로 새 Quartus Lite MAP/FIT/STA·설치본은 만들지 않았다. RTL과65816은685와 동일하지만 기존 MMC666 보드 FIT/STA를 이 후보의 통과 근거로 옮기지 않는다. 실기 기준·제품 파일은MMC666 그대로다.

## 다음 순서

686의 SEAL 소유권·7블록 수신과685의957 마지막384B 선행 DMA를 유지한다. 다음은 위상1의955 마지막map3392/192B 발행→수락→ACK를 기존65025724(251선) 마감과 대조한다. 686의65028794(253선)는3070클록/142.944µs 늦고1152B 선행 DMA를 놓쳤다. 첫BG의ROM허용창, map행 확정·발행·credit·후속tile 순서를 묶어 기존 실제 수락 마감 회복에 필요한 비용을 정한다. 154µs E0를 되돌리거나 ACK를 늦춰7블록을 맞추지 않는다. 248/252 DMA 허용선과246 표시 검사선, STOP·새패킷 우선·독립검사·최종ACK·메뉴복귀를 유지한다. 두 위상 모두7블록·952 표시3회·957최종대기0회·밀집평균·마지막ACK를 함께 통과한 뒤에만 전체Lite FIT/STA·새전달로 간다. 고정지연·위상상수·DMA크기 탐색은 하지 않는다.
