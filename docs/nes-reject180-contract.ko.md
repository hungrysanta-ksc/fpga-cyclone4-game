# NES180 — 첫 레벨 영상 거부·회복 기록

NES179에서 확인한 행중 렌더링 중단·재개 외에 실제 보드의 fetch/compact 오류가 함께 발생하는지 확인하기 위한 후보이다. **기능 검증은 통과했지만 최종 타이밍 실패로 미채택이며, 새 실기 ZIP은 없다.** 배포178을 유지한다. 영상 표현과 전송 속도는 수정하지 않는다. 기존 종료 직전16클록 기록을 원인 변화·회복 기록으로 교체하는 후보 결과는 `analysis/reject180-verification.json`을 기준으로 한다.

## 기록하는 사건

- 첫 유효 geometry 프레임 이후부터 기록한다. 이는 수집기 수용이며 SNES 표시 완료가 아니다.
- 잘못된 프레임의 첫 소유권 확정 시, 직전이 정상이거나 최종25비트 오류 벡터가 달라졌을 때 REJECT를 남긴다.
- 거부 다음에 유효 프레임이 오면 RECOVERY를 한 번 남긴다. 이후 같은 정상 프레임은 기록하지 않는다.
- 같은 오류 벡터의 반복은 행·dot·mask·개수가 달라도 생략한다. 최근16사건이 남으며 이전 사건은 순환 덮어쓴다. 이것은 모든 프레임의 기록이나 전역 최초 오류 보존이 아니다.
- 최초 관측 오류 위치는 현재 프레임에서 live 오류를 처음 읽은 NES 클록이다. 원래 CPU 쓰기/실패 fetch의 정확한 시각은 아니며, 출력은 보통 등록된 오류보다 한 클록 뒤에서 관측한다.
- 오류 코드와 개수는 소유권 확정 시 값이다. 조기 실패로 먼저 확정된 경우 이후 다른 수집기의 오류까지 모두 포함한다고 보지 않는다.

기존16×96비트 RAM과 명령77/A0–BF를 재사용한다. 정상 수집·거부·release·전송·사운드·입력 경로는 이 관측 결과를 읽지 않는다. 별도 SRAM, 두 번째 프레임버퍼, 실행 중 SD 쓰기 없이 STOP 뒤 기존 로그에 저장한다. ROM 최초 오류 전용 관측과 버튼 기록은 유지한다. STOP과 최초 ROM fault는 ring을 보존하며, fault와 같은 클록에 사건이 없으면 가짜 표본을 만들지 않는다.

## 형식

명령77 descriptor의 마지막 바이트만1→2로 변경한다. 폭96·페이지 구성1·최대16개는 동일하다. MCU는 버전2만 수용하며 잘못된 보조 기록은 STOP·기본 FPGA 복원·메뉴 준비를 막지 않는다. 로그 식별자는 `LAST16_REJECT180_V2`다. 예전 `LAST16_BOUNDARY177_LOW22` 해석기로 읽지 않는다.

96비트의 상위부터 순서는 다음과 같다.

| 필드 | 비트 | 의미 |
|---|---:|---|
| kind | 2 | 1=REJECT, 2=RECOVERY |
| generation | 8 | 하위8비트, modulo256; 절대 프레임 번호 아님 |
| errors | 25 | ROM1/raster8/compact8/fetch8 |
| first line / dot / mask | 9/9/8 | 최초 오류 관측 위치; 없으면511/511/0; 회복 사건에서는 무시 |
| rows / groups | 8/6 | 소유권 확정 때 행·묶음 수 |
| objects / exceptions | 8/8 | 확정 때 객체·예외 수 |
| palettes | 5 | 31에서 포화; 정상 수용 상한은2 |

`tools/decode_nes_reject180.py`는 형식·유효 플래그·사건 순서를 검사하고 fetch/compact/raster를 분리한다. 입력 파일은 종료 로그다. ACK 개수·generation 차이·사건 수로 실제 TV FPS를 계산하지 않는다.

## 검증 및 다음 판단

실제 SPI를 통해 최초 위치와 최종 개수의 조합, 오류 반복 생략, 종류 변경, 회복, 취소, 같은 클록의 오류/소유권 확정,16개 초과 순환, STOP 보존, fault 동시 기록/무사건 동결을 검증한다. 기존 수집기의 해제14위치/42검사도 유지한다. 실제 C 판독 함수15경우와 독립 decoder4경우, 최대 길이 formatter, 전체 ARM 링크·스택 검사를 수행한다.

첫 후보는 위치와 mask도 오류 변화 비교에 포함했지만964 LAB이 필요해963 LAB 기기에 배치하지 못했다. 두 번째 후보는 비교 상태를25비트 오류로 한정하고 회복 위치용 mux를 제거했다. 이는 기록 범위의 명시적 축소이며 게임 허용 조건 변경이나 임의 배치 seed 반복이 아니다. 원본 실패 자료는 보존한다.

두 번째 후보는15,043 LE/963 LAB/36 M9K로 배치는 성공했지만 실제 클록 setup −0.092ns로 실패했다. 위반은 기존 ROM reader `chip`→control `check_enable` 경로이며 관측 NES 클록 자체의 최소 setup은+6.654ns다. 관측 추가에 따른 전체 배치 영향이므로 해당 경로의 기능 오류가 새로 증명된 것은 아니다. hold 최소+0.127ns, 추가 목표 예산도−0.092ns다. 실패 후보의 조건부 IO/ASM/압축/ZIP은 진행하지 않았다.

MCU 전체 링크는198,012바이트, static RAM26,564바이트, RUN bound37,312/IRQ508/남은 여유1,040바이트다. 최대 TXT는3,920/4,096바이트다. MCU만178 FPGA와 섞어 배포하지 않는다. `arm01` 생성은 버전 치환 문자열이두곳에 있어 중단됐고, 정확히 history descriptor에 한정한 `arm02`가 최종이다. 테스트01은 중첩 소스 복사 경로,02는 공유 컴파일 단위 누락으로 실패했다. 테스트03은 첫 후보 PASS,04는 축소 규격에서 같은 오류를 새 사건으로 기대한 fixture 실패,05가 축소 후보 PASS다. 원본 실패도 보존했다.

다음에는 관측용 first-position/previous-error 상태를 별도 FF로 더 늘리는 대신 기존 history RAM의 기록·읽기 경계를 활용해 중복 상태를 줄이는 설계를 먼저 검토한다. 새 지연·STOP/fault 동시성·실제 프레임 간격을 명시하고 작은 검증을 통과시킨 뒤에만 필요한 한 번의 배치를 수행한다. **이전 ROM 로더 미세 조정, seed 변경, 같은 회로 FIT 반복으로 돌아가지 않는다.** 이 방식이 전체 코어 여유 안에 들어가지 않으면 기록 범위를 줄이는 대안을 선택하고 이유를 남긴다.

배포 승인 뒤 실기에서는 월드맵의 **숫자1 타일로 이동한 뒤 A**로 진입한다. raster08/48만 있는지, compact82나 fetch 오류·용량 제한이 함께 있는지 확인하여 렌더링 중단·재개의 공통 표현을 구현한다. 지금은 같은178/044 재시험을 요청하지 않는다. 고정193행·ROM 이름 예외·검사 제거로 우회하지 않는다. 차분/base-generation/최종ACK를 통한 실제 약60fps 전송 개선도 유지한다. 진단만으로 영상 정지·속도가 해결됐다고 계산하지 않는다.
