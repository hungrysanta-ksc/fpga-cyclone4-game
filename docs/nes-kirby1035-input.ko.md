# MMC1035 커비 첫 블록 공급과 둘째 타일 뱅크

## MMC1034에서 확인한 지연

두 실기 BIN의 59.70초 표본은 BG 666·OBJ 16·변경 map 0·15타일·4묶음·마지막 OBJ 96B(오프셋 416)·입력 17블록 1,849B가 일치한다. 타일 태그 전체와 캐시 이력은 수집하지 않았다. 시각 원점은 각 세대의 직전 화면 공개, FPGA 한 눈금은 0.390095ms다. [기존 실기 원본 해시와 해독 결과](../analysis/kirby1034-hardware.json)

| 사건 | 1차 세대 1693 | 2차 세대 1558 |
|---|---:|---:|
| 첫 블록 준비 | −16.14∼−13.68ms | −2.26∼+0.20ms |
| 첫 D1 호출 | −15.36∼−13.72ms | −1.87∼−0.22ms |
| 마지막 데이터 D2 확인 | −2.69∼−1.04ms | +9.71∼+11.35ms |
| 첫 반환→마지막 묶음 시작 | 13눈금 | 25눈금 |
| 마지막 묶음 시작→둘째 반환 | 2눈금 | 2눈금 |
| SEAL 수락 | 37.06ms | 51.49ms |
| 공개 / 최종 ACK | 49.93 / 49.93ms | 65.93 / 66.32ms |

첫 블록 준비 격차는 11.42∼16.34ms다. 느린 쪽도 준비 뒤 첫 D1까지 0.39ms 미만이다. 둘째 뱅크까지의 추가 12눈금(4.68ms)은 마지막 묶음의 첫 plan을 받기 전에 이미 나타났다. MMC1034에는 둘째 뱅크의 생산 완료 시각, 물리 캡처 시작과 직전 버퍼 해제 시각이 빠져 있어 이 증가분을 생산자나 소비자에게 배분할 수 없다.

## 발행 변경과 대조

실제 MMC1034 보드의 새 캡처 시작 조건은 PPU 7선 dot 257에서 이전 소유권이 해제되어 있는 것이다. 캡처를 끝내고 독립된 geometry RAM이 유효해져도, 이전 세대의 표시 소유권이 남아 있으면 exporter는 이전 타일 plan의 END 수락을 기다렸다. MMC1035는 이미 유효한 geometry를 위한 임시 전송을 그 앞에서 시작한다. 시작 순간 ROM reader의 drain 조건, 기존 세대의 타일 뱅크와 표시 소유권, EA 뒤의 D3 COMMIT, 폐기·오류 경로는 기존 신호로 확인한다.

커비 3570 캡처의 원래 query 값에서 exporter·두 CDC mailbox·압축기·SPI를 구동했다. 18블록의 응답과 CRC 총 1,980B를 원본과 대조했다. geometry를 먼저 확정하고 이전 plan을 11.42ms 또는 16.34ms 열어 둔 두 조건에서 첫 블록은 각각 11.419ms, 16.339ms 앞당겨졌다. 같은 만큼 캡처를 늦춘 대조군과 plan 대기를 없앤 대조군은 차이가 0이었다. 대기 길이는 실기 구간의 양 끝을 사용한 시험 입력이다. 과거 두 세대의 plan 종료 시각을 재현한 값으로 해석할 수 없다. 첫 블록 STOP, EA 전 D3 거부, 정상 COMMIT을 함께 시험했다.

15타일·4묶음·마지막 OBJ 96B의 구조 대조에서는 둘째 뱅크 게시 전 ROM 공급을 늦추자 첫 반환→생산 완료가 2,757→5,886 host 클록, 생산 완료→반환은 1클록이었다. 소비를 늦추자 생산 완료까지는 2,757클록, 반환까지는 1→801클록이었다. 이 대조는 생성한 태그와 중간 묶음 길이를 쓰며 소비 지연을 외부에서 부여한다. 실제 65816 명령별 시간과 두 회차의 4.68ms 원인 배분은 실기 계측 대상이다. [대조 시험과 보드 검증](../analysis/trial1035-package.json)

## 계측과 실기 판정

- 첫 세 D2의 기존 응답 공간에 첫 블록 준비→D1, 직전 collector 해제→캡처 시작, 캡처 시작→첫 블록 준비를 담는다. SPI 거래를 추가하지 않는다. ARM은 데이터와 CRC, D2 상태와 다음 토큰을 확인한 뒤에만 저장한다. 127은 포화 또는 관측 누락이므로 시각 복원에서 제외한다.
- 별도로 직전 COMMIT 블록의 D2 응답과 다음 BEGIN의 첫 D1을 ARM 시계에서 연결한다. 연속 토큰과 저장 가능 시간을 확인하고 512 ARM 사이클 단위로 저장한다. 이 값은 공유 SPI 입력 버퍼의 반환을 ARM이 확인한 시각이다. collector 해제는 NES 도메인의 별도 사건이다.
- 같은 세대에서 FPGA writer 전환과 토큰 검사를 통과한 65816 뱅크 반환을 네 묶음까지 기록한다. 둘째 뱅크가 먼저 완성됐다면 첫 반환 이후의 생산 대기는 0으로 잡는다. 게시 뒤 반환까지는 ARM 조회·발행과 65816 소비를 포함한다.
- 기본 캐시·65816 ROM과 STOP·메뉴 복귀 경로를 유지했다. 초기 후보는 966/963 LAB로 FIT에 실패했다. 기존 E9 수락·마지막 묶음 관측 자리를 뱅크 게시 시각으로 교체하고 시간 눈금을 공유한 전달본은 15,323 LE, 963 LAB, 55 M9K다. 전체 STA 57항목의 최소 여유는 +0.128ns, ARM Flash는 212,880B로 112B 남는다.
- 실기 채택 조건은 같은 입력·출력 작업량에서 공개 4→3 VBlank와 직전 공개→최종 ACK 단축이 함께 관측되는 것이다. 무입력 두 번의 같은 구간 표본 수와 1–30초·30–60초 FPS도 함께 기록한다. 부팅·종료 화면은 사용자가 확인한다. [실기 절차](nes-mmc1035-trial.ko.md)

보드 생성은 `tools/prepare_nes_input_times1035.py`, ARM은 같은 스크립트의 `--arm`을 사용한다. 경계 대조는 `tools/check_nes_kirby1035.ps1`과 `tools/check_nes_banks1035.ps1`을 Starter FLOAT 래퍼로 실행한다. 최종 링크 검사는 `tools/check_nes_return1035.py`, 패키지 검증은 `tools/package_nes_kirby1035.py`, BIN 해독은 `tools/read_nes_kirby1034.py --edition 1035 <BIN>`이다.
