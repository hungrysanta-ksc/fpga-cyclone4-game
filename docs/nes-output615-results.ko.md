# MMC613 출력·최종 ACK 비용 분해

## 목표

[실기 973화면](nes-hardware614-results.ko.md)의 출력·최종 ACK 평균은 31.63 ms다. ARM의 계측 범위는 `nes_sink212_seal` 호출 전후로, EA와 다음 입력은 그 뒤에 온다. 실기 로그에는 화면별 작업과 SNES의 수락·DMA·빔 시각이 없어 31.63 ms의 내부 비율은 미확정이다.

## 작업내용

MMC577과 MMC613 구성에 대응하는 기존 연속 추적을 각 두 시작 위상에서 읽었다. 613은 611 후보의 ARM·65816 일정을 사용한다. [613 전달본 검증](nes-trial613-results.ko.md)에 프로그램과 ARM 함수의 대응 근거가 있다. 각 추적의 여섯 입력 파일 해시를 기존 결과와 대조했다. 906–957의 52개 세대마다 map 주소·길이·payload와 OBJ bulk 목적지·길이·바이트·계획 슬롯 순서를 네 실행에서 맞췄다. 처음 두 화면을 제외한 907–957 및 밀집 951–955를 별도 집계했다.

첫 E1 전 준비부터 SEAL 패킷 발행, 65816 큐 load, 검사, DMA 시작부터 마지막 바이트, VBlank 대기, ACK 후 ARM 복귀까지 중복 없이 합산했다. 모든 세대에서 합이 ARM 함수 경과와 일치한다. SEAL 전 65816의 일반 패킷 처리는 ARM 발행과 겹친다. 아래 표에서 DMA와 VBlank 시간은 SEAL 수락 뒤에만 해당한다. IRQ·ROM 중재와 폴링을 포함하는 기존 연결 일정이며, 대기 중 수행하는 검사·폴링은 대기 구간에 포함된다.

- 밀집 5화면의 MMC577 대조군은 42.07 / 42.07 ms다. 반면 907–957 전체 평균은 577의 33.12 / 33.82 ms에서 613의 36.86 / 36.82 ms로 늘었다. SEAL 전 발행은 짧아졌지만 업로드 대기가 약 10 ms로 늘었고 마지막 대기는 51화면 중 7회씩이었다. 실기 5–55초 표시율과 추적의 함수 평균은 각각 다른 집단·측정 범위를 가진다.
- **952**는 두 위상에서 map 10패킷·OBJ 512 B였다. 최종 검사선은 250번 라인 H=10 / 212였고 잔여 credit은 208 B였다. 246번 라인 끝까지 오려면 같은 DMA 구성에서 빔 검사를 최소 4,103 / 4,305 master clock(0.191 / 0.200 ms) 당겨야 한다. 이 한 번의 실패로 15.05 / 15.04 ms를 기다린다. 이는 마지막 빔 검사 시각의 필요조건이다. 앞단 발행만 그만큼 당겨도 앞선 업로드 대기가 이를 흡수할 수 있다. 구체적인 후보는 목적지 0xAB80의 640 B map이다. 이 명령부터 다음 raw 명령까지 두 위상에서 5,962 / 5,914클록이 걸려 필요한 4,103 / 4,305클록보다 길다. 여러 선행 DMA로 나눌 때의 추가 설정·중재와 이전 VBlank의 실제 여유는 다음 검증에 포함한다. 그 뒤 raw 64 B DMA 세 번은 유지한다.
- **954·955**는 두 위상 모두 마지막 추가 대기 0회지만 업로드 VBlank까지 14.21–14.61 ms가 남는다. 954의 map 12패킷이 SEAL 전 E1 거래에서 6.84 ms, 65816 수락부터 해당 ACK까지 합계 6.11 ms를 쓴다. 두 시계는 겹친다. SEAL 자체의 큐 수락은 0.03–0.06 ms 수준이다. map 패킷을 먼저 수락해 이전 안전한 DMA 구간을 쓸 수 있는지가 발행 순서 평가 기준이다.
- 957의 마지막 추가 대기는 두 위상 모두 0회다. 실제 실기에서 같은 세대가 어느 시각에 나왔는지는 식별할 수 없다.

## 후속작업

먼저 952에서 이미 검증된 비활성 뱅크 작업을 이전 안전한 DMA 구간에 옮겨 두 위상 모두 마지막 빔 검사를 246번 라인 안으로 돌릴 수 있는지 시험한다. raw 전송 조건·독립 검사를 보존하고, 이동할 수 있는 map·tile 작업부터 대조한다. 그다음 954·955는 확정된 map의 ARM 발행·65816 수락을 다음 업로드 VBlank에 맞춘다. STOP·새 패킷 우선·최종 ACK·메뉴 복귀와 957 대기 0회를 유지하고, 밀집 표시 간격·마지막 ACK가 함께 앞당겨지는 후보만 채택한다. MMC613의 Flash·M9K 여유는 0이다.
