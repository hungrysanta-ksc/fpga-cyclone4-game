# NES165 상태 직접 저장과 ROM 읽기 캡처 분리

## 목표와 구현

165 영상 경로 진척: 로더 상태를 직접 저장하고 ROM 읽기의 데이터 캡처 허용을 분리했습니다. 실제 내부4클록·3조건의 setup/hold가 모두 통과했다. 최악 setup+0.094ns, hold+0.120ns,15010LE/959LAB/35M9K이며 다음 연결 작업의 기준으로 채택한다. 선택 directstate165/map01/reproduce01. 외부IO·영상CDC/reset·MCU 연결·실기는 미완료이며 새SD는 없습니다.

[직전 UPDATE 후보](nes-update165-contract.ko.md)의 SPI와 카운터 개선을 실험 기반으로 사용한다. 채택 기준은 여전히 phaseguard−0.083ns다. 로더·ROM 읽기2개만 변경하고 나머지59개 구현 입력은 보존했다.

- 로더는 숫자 상태→해석→다음 상태 인코딩의 피드백 대신 상태별 비트를 직접 갱신한다. 단순 ONE_HOT 합성 옵션 변경이 아니다. 외부 핀을 구동하는 조건도 상태 비트를 직접 참조한다.
- RTL은16개 숫자 상태를 각각 한 비트로 표현한다.9..15 미사용 상태의 유지/오류 전이는 기존과 같으며, 숫자 state는 시험 비교용 wire다. 초기화 이후 한 비트만 켜지는 불변식을 검증했다. 여러 비트가 동시에 손상되는 경우는 기존 숫자 상태와 동등하다고 주장하지 않는다. 합성은 도달하지 않거나 출력에 기여하지 않는 비트를 제거할 수 있으므로 실제 레지스터 개수를 별도로 확인한다.
- ROM 읽기는 다음 클록의 ACTIVE·종료 조건을 정확히 예측해 같은 클록에 두 개의 capture 허용 레지스터를 갱신한다. 각각4비트의 데이터를 받는다. preserve/dont_merge와 실제 배치 결과를 함께 확인하며, 읽기 데이터 샘플·CE/OE·HOLD·ACK 시점은 바꾸지 않는다.
- 직전 후보의 terminal·명령 종류·C0/C1/C2·ID0x74는 그대로다. 외부 명령 지연, 클록, SDC, false path, multicycle, 핀, PSRAM 쓰기 시간은 변경하지 않는다. 설치164/GBC 및 카트리지 세이브 SRAM은 보존한다.

## 검증 범위와 실행 이력

로더294,912조건/1,056쓰기·명령·STOP·reset 시퀀스에서 모든16개 숫자 상태의 동작을 비교했다. 직접 주입하는 fixture에서는 후보의 one-hot 비트와 양쪽 terminal을 일치시킨다. 잘못된 STOP 배출과 미사용 상태 소거도 검출했다.

ROM 읽기는 READ_CYCLES1/2/3/16, CHECK/RUN 두 소유자, 서로 다른 클록 위상에서120읽기/126취소/5클록정지 reset을 비교했다. capture 허용이 현재 ACTIVE·read_last와 일치하는 불변식과 잘못된 예측 회로를 검증했다. 추가로 실제70ns PSRAM 모델의16위상 핀/CDC/reset 시험을 수행하고,110ns 지연 및 HOLD 제거 대조 시험도 검출했다. 이는 실기 전기적 타이밍과 전체 CDC 승인에 해당하지 않는다.

새 로더·읽기를 실제 SPI/boot에 연결한219wire/1,125,909클록/100READ·7ACK·19주소오류·72취소·2충돌 시험을 통과했다. 변경 없는 SPI 단위393,741거래/120경계와 MCU 간격은 이전 근거를 재사용했다. 전체 ROM 적재·MCU 게임 루프·실기 게임은 새로 실행하지 않았다.

loader01은 fixture가 dut.state뿐 아니라 refdut.state까지 치환해 참조 모듈의 phase를 찾지 못했다. 식별자 경계를 고친 loader02가 통과했다. joint01은 시험용 baseline_check165 모듈이 컴파일 목록에서 빠져 실패했고, 검증된 참조 소스를 추가한 joint02가 통과했다. 모두 시험 구성 오류이며 map01 RTL은 바뀌지 않았다. 처음 실행한 스크립트·실패 로그를 보존했다. reader01과pins01은 통과한 그대로 사용했다. 라이선스 실패가 아니며 FPGA 전체 배치는 한 번만 했다.

기존 commandpulse 분석은 숫자 state 레지스터가 없어 STOP 경로 검색에서 중단됐다. 실패 로그를 보존하고 실제 phase/capture 레지스터를 대상으로 새 보고서를 생성했다. analyze02는 동일한 배치 DB의 보고서만 생성했으며 추가 FIT가 아니다.

## 다음 작업과 의미

선택 기준을 directstate165/map01/reproduce01로 변경한다. 양수 여유를 더 늘리기 위한 미세 논리·seed·무변경 refit는 중단한다. 먼저 동일 배치에서 외부54입력/57출력과 혼합 클록 경로를 PSRAM70ns/SNES/MCU-SPI/영상 mailbox/reset으로 분류하고 기존 보드 근거를 재사용할 수 있는 범위를 확인한다. 실제 새 경계의 요청/응답 데이터 안정성·ACK 소유권·공통 reset/STOP 회수 및 필요한 지연 제약을 점검한다. 그 다음 MCU에 실험 SPI0x74와 E6/version2 상태73·E5관측70·E0/F6 패킷 수신/변환/SNES ACK를 연결하고, 기존 사운드·입력·경과시간·STOP 서비스를 유지한다. full-link/stack과 최소 변경 경계 검증 후 SMB3(J) 첫 레벨 실기 패키지로 넘어간다. 새로운 일반 진단체계나 전체 ROM/A-B/044 반복을 선행 조건으로 추가하지 않는다. 변경으로 배치가 달라질 때만 해당 완성 후보의 전체 타이밍을 다시 확인한다. 내부 통과만으로60fps·실기 안전성·장시간 입력 유지를 완료 처리하지 않는다. 설치164/GBC/세이브 SRAM은 보존한다.

연속 게임 화면을 위한 FPGA 제어 회로 구현이다. 최소 조건을 갖추면 SMB3(J) 첫 레벨 실기로 넘어간다. 완료된 원자료·검증 pin·finalizer는 변경하지 않는다.
