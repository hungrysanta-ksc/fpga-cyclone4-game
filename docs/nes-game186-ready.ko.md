# NES186 복사 요청 묶음 실기 시험

185에서 잘 동작한 사운드·입력 유지 수정을 유지하고, 같은 타일맵을 복사하는 요청을64→256바이트 단위로 묶었다. 전체 map이 같으면64개 요청이16개로 줄어든다. 아직60fps 완성판은 아니며 초기 ROM 로딩과 약60초 플레이 제한은 같다.

## 실행

1. 현재 SD 파일을 백업한 뒤 ZIP의 `01-GAME186-SD-ROOT` **안의 내용**을 SD 최상위에 복사한다. `firmware.stm`과 `fpga_n186.bi3`는 반드시 함께 교체한다.185 파일과 섞지 않는다.
2. 메뉴에서 `NES GAME 186.nh1`을 실행한다. 스타트로 플레이어 선택·월드맵에 들어가 숫자 **1** 타일에서 **A**로 첫 레벨에 진입한다.
3. 첫 레벨의 끊김이185보다 줄었는지, 음악과 조작이 유지되는지 확인한다. 가능하면20~30초 영상을 촬영한다. 입력만을 위한 별도 반복 시험은 필요 없다.
4. 약60초 후 실제 파일 메뉴 복귀 여부와 아래 두 로그를 알려준다.

- `sd2snes/nes-progress-186.txt`
- `sd2snes/nes-game-last-186.txt`

첫 게임 화면 이후90초가 지나도 복귀하지 않으면 더 기다리지 말고 증상과 남은 로그를 알려준다. 화면만 멈춘 경우 소리·버튼 반응도 함께 기록하면 된다. 같은044 복원 시험은 반복하지 않아도 된다. `02-RESTORE164-SD-ROOT`는 필요할 때만 사용한다.

`sink_window_schema=184`는 기존 큐 규격을 그대로 사용한다는 뜻이다. 전송·소비 패킷 수는 프레임 수가 아니다. 세이브 SRAM은 작업 공간으로 사용하지 않으며, 로그는 종료·기본 코어 복원 뒤 기록한다.
