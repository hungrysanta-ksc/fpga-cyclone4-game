# MMC502 — 수집 오류 수정 실기 확인본

이번에는 실제 슈퍼마리오3로 확인한다. 정상 렌더링 중단·재개를 전체 프레임 오류로 처리하던 수집기를 수정하고, 불필요한 세 번째 raw 행을 줄였다. ARM·65816 실행 코드는 정상493과 같으며 ARM의 메뉴/ROM/FPGA/로그 이름만502로 변경했다. 독립 검사·STOP·최종 ACK·VBlank·메뉴 복귀는 유지한다. **502의 실기 성능과 메뉴 복귀는 이번 시험으로 확인할 항목이며,60fps 달성판은 아니다.**

## 비교 순서

가능하면 **493 한 번 → 502 한 번**, 같은 동선으로 비교한다. 현재493이 설치돼 있으면 먼저 기준 실행을 할 수 있다. 두 번 모두 같은 첫 레벨에 비슷한 시점에 진입하고, 비슷하게 오른쪽으로 이동·점프한 뒤 약60초의 자동 메뉴 복귀까지 확인한다. 한쪽은 메뉴 대기, 다른 쪽은 플레이한 결과를 성능 개선율로 비교하지 않는다.

493 실행 뒤 기존 `nes-progress-mmc493.txt`, `nes-budget-mmc493.txt`, `nes-game-last-mmc493.txt`를 먼저 보존한다. 기준 실행을 추가하기 어렵다면502 한 번의 실행·입력·표시·메뉴 결과부터 확인해도 된다. 그 경우 지속 가속 판정은 보류한다.

## 502 설치

1. 전원을 끄고 기존 SD·세이브를 보존한다. ZIP의 **`01-MMC502-SD-ROOT` 안의 내용물 전체**를 SD 루트에 복사한다. 폴더 자체를 넣지 않는다. 새 `firmware.stm`과 `fpga_mmc502.bi3`를 함께 적용한다.
2. 이전에 정상 실행한 원본 `mmc493.nes`를 **`sd2snes/nes/mmc502.nes`**로 복사한다. 이름만 바꾸며 ROM을 개조하지 않는다. 원래480/482/485/489의 같은 ROM도 가능하다. 상용 ROM은 ZIP에 포함하지 않았다.
3. **`NES MMC3 502.nh1`**을 선택한다. 게임 로드, 첫 레벨의 입력·화면, 약60초 뒤 메뉴 복귀를 확인한다. 자동 복귀 방식과 시간은493과 같다.

ROM은393232바이트, CRC32 `5a04eed7`, SHA256 `dbb1cb5e18b091ca9101b1c2f5a5d6bdbeaa4a30ae1a504251310f6765cabb49`인 기존 원본이다. 별도 문양 NES 파일로 교체하지 않는다.

## 보내줄 결과

- `sd2snes/nes-progress-mmc502.txt`
- `sd2snes/nes-budget-mmc502.txt`
- `sd2snes/nes-game-last-mmc502.txt`

화면/입력/메뉴 복귀 결과와 첫 레벨 진입 여부를 함께 알려준다.493을 같은 동선으로 실행했다면493의3개 로그도 함께 보존한다. 반복 실행은 같은 이름의 로그를 덮으므로 실행별로 따로 복사하거나 `-1차`, `-2차`를 붙여 보존한다. 영상은 화면 깨짐이나 멈춤이 보일 때 도움이 된다. SD를 작업 PC에 연결할 필요는 없다.

새 바이너리·로그 이름은 모두502이므로493 로그와 구분된다. 로그의 `candidate=NES-MMC502`, FPGA profile `7b`, status3, client ABI4891을 분석에서 대조한다. 현재 계측으로 IRQ 시간이나 ROM 대기만을 완전히 분리할 수는 없다. 기존 DWT 단계/실제 최종 표시와 capture 오류 기록을 함께 판단하며, 모델 명령 수를 실기 FPS로 바꾸지 않는다.

## 493 복구

전원을 끄고 **`02-RESTORE493-SD-ROOT` 안의 내용물 전체**를 SD 루트에 복사한다. 기존 `sd2snes/nes/mmc493.nes`와 **`NES MMC3 493.nh1`**을 사용한다. 펌웨어·FPGA·base/menu 파일은 기존493 전달본과 byte/hash가 같다.03=489,04=485,05=482,06=476,07=164,08=467 복구본도 보존했다. 사용자 세이브 파일은 포함하지 않아 덮어쓰지 않는다.

## 제작 근거와 범위

502 정상33조건/반례12종과 실제source→493 ARM→493 65816의 고정 장면 비교를 통과했다. 최종 화면은 같고, 모델 입력 SPI330B/출력1797B가 줄었다. 전체Lite 합성15,287LE/51M9K,잔여121LE·관련setup+.353/hold+.142ns다. 이번 전달은 같은 합성 결과를 재사용하며 새 기능이나498 실험을 섞지 않았다.

전달용 ARM781개 함수의 주소·크기·명령은493과 동일하다. Flash 잔여148B/추가global RAM0B다. 실제 FatFS/프로그래머가 새BI3를 원래RBF510,856바이트로 복원하는 것도 검사했다. GPIO/DONE은 모델이며 새 보드 설치 성공을 뜻하지 않는다. 전체 reset/CDC/외부IO·IRQ최대stack과MMC4/5 일반화는 미완료다. 이번 로그를 받은 뒤 수집 거부·표시 간격을 평가하고 A2 전송/DMA 구조 예산을 갱신한다.
