# NES167 실기 결과 — 첫 화면 표시 후 응답 검사 오류로 조기 종료

사용자는 첫 화면이 약1~2초 보이고 메뉴로 돌아왔다고 보고했다. 소리가 나는 장면까지 진행하지 못했다. **새 영상 경로의 첫 출력은 확인했지만, 연속 플레이는 아직 실패다.**

| 항목 | 결과 |
| --- | --- |
| ROM 적재·비교 | 393216바이트, verified1 / run_rom_error0 |
| 영상 수신 | BEGIN8 / END8 / COMMIT8 / ABORT0 |
| SNES 표시 완료 ACK | 7회, 마지막 성공 세대22 |
| 다음 수신 영상 | 세대24, 표시 처리에서 종료 |
| 종료 원인 | native_result5(DISPLAY), native_sink_error3(응답 내용 검사 실패) |
| STOP·복구 | stop_ok1 / base_restored1 / safe_to_reload1, 사용자 메뉴 복귀 확인 |
| 사운드 | SPC A9·unmute1, 실제 소리 미확인 |

진행 기록0~99는 연속이다. DISPLAY_NEXT231450ms→DISPLAY_STOPPED234990ms로 표시 처리 구간은 **3540ms**다. 초기 준비·정지도 포함하므로 화면이 실제 보인 시간이나 FPS는 아니다. 약60초 만료가 아니라 오류로 종료했다. 전체 MENU_PREPARED는238100ms다. 모두 펌웨어 tick이며 외부 시계로 실측한 값은 아니다.

## 오류를 해석한 근거

`nes_native_runtime165.c`는 프레임 변환·전송·SEAL 표시 응답 확인을 끝내고 guard까지 통과한 뒤에만 frames를 올린다. 따라서7회는 수신 프레임 수가 아니라 표시 완료 응답까지 확인한 횟수다. 모든 NES 프레임이 전송됐거나60fps라는 뜻은 아니다. 166의 BEGIN383/ABORT383·표시0회에서 벗어났다. 이번 관측 동안 fill ABORT는 없었지만 모든 장면의 fill 안정성까지 증명하지는 않는다.

`nes_native_sink165.c`의 오류3은 transport exchange가 성공한 뒤 ACK의 상태·명령·순번·세션·세대·서명 중 하나가 기대값과 달랐다는 뜻이다. `nes_sink_spi165.c`는 F6 식별·CRC·상태를 검사하므로 단순한 통신 무응답/시간 만료와 다르다. SNES가 정상 형식으로 오류를 돌려줘도 같은3이 된다. **SNES 거절과 응답 식별값 불일치를 현재 로그만으로 구분할 수 없다.** 실패한 명령이 BEGIN/DATA/SEAL 중 어느 것인지도 기록되지 않았다.

SNES 클라이언트에는 E0(패킷 검증), E1(비교 입력), E2(32개 DMA 명령 초과), E3(전송 예산 초과), E4(STOP) 응답이 있다. 실제 화면이 변하면서 명령 수·5000 예산 제한에 걸렸을 가능성과 순번·세대·응답 소유권 문제를 먼저 대조한다. **어느 코드가 실제 발생했는지는 미확정**이며 상한 증대나 ACK 검사 제거로 우회하지 않는다.

run_error4는 MCU의 표시 실패 요약이다. ROM 오류나 버튼 문제로 해석하지 않는다. screen_error169는 SPC A9이며 screen_frames0은 신뢰하지 않는 구형 화면 계수다. 버튼 기록은 NONE 한 번뿐이어서 입력 품질은 판정할 수 없다. PPU 최근16클록은 ROM fault context가 없으므로 이를 단독으로 PPU 고장 증거로 쓰지 않는다.

## 다음 작업

실패한8번째 영상의 SNES 패킷 응답 검사를 우선 조사한다. 기존 성공7회/마지막세대22·수신세대24를 기준으로 연속 프레임의 변경량·32개 DMA 명령 상한·5000 전송 예산·길이/순번/세대 소유권을 최소 재현한다. sink 오류3만으로 SNES 거절(E0~E4)과 응답 토큰/서명 불일치를 구분할 수 없으므로 실패 패킷의 op/section/offset/length, 기대 토큰 및 실제12바이트 ACK를 안전 정지 후 기존 TXT에 기록하는 최소 보강을 우선한다. 응답 검사를 끄거나 상한을 무조건 늘리지 않는다. 필요한 수정 뒤 SMB3 실기로 복귀하며 같은167·044·무변경 FIT를 반복하지 않는다. 이후 연속 AV→장기 플레이/오류·본체 리셋 로그→입력 유지 순서를 유지한다.

이번 변경은 결과·소스 대조·다음 계획의 기록이며 새 시험판은 만들지 않았다. 추가 영상이나 같은167 재시험은 현재 필요하지 않다. 원본 로그는 비공개 작업 폴더에 바이트 그대로 보존했다. [로그 해시·전체 필드·소스 해시](../analysis/game167-hardware01-verification.json). 기존 구현·배포·완료된 검증 기록은 수정하지 않는다.
